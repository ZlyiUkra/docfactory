# Плани вивчення React і NestJS

## Узгоджена пропозиція

Три плани — React, NestJS, Next.js — стають однією родиною для одного учня: React-розробника рівня мідл, який
іде у фулстек. Порядок проходження: React (шлях мідла) → NestJS → Next.js, по черзі. Через усі три проходить
один проєкт: SPA, що отримує бекенд на NestJS, а потім переїжджає на Next.js. Кожна тема має одного власника, інші
плани на нього посилаються. Обидва плани переписано в докладному форматі плану Next.js: кожен день пояснений від
знайомого до нового, з вправою по кроках і способом перевірити себе.

## Межі та обмеження

- React — поточна лінія 19.3; NestJS — 12 (стабільна, `latest` 12.1.1 від 2026-09-28).
- Назви глав — точні назви документів корпусів; усе поза корпусами позначено.

## Зауваження, що вціліли

- [підтверджено] Межа корпусу в плані React застаріла: для бібліотек екосистеми є примірники (nitpicker,
  best-practices, pragmatist).
- [підтверджено] Старт React-проєкту — `Build a React app from Scratch`, не `Creating a React App` (nitpicker,
  best-practices).
- [підтверджено] React Compiler стабільний; «useMemo майже завжди зайвий» хибне (performance, nitpicker).
- [підтверджено] Дані — через лоадери маршрутів, щоб уникнути водоспаду (best-practices).
- [підтверджено] Порядок ланцюга запиту NestJS хибний; однаковий в 11 і 12 (nitpicker).
- [підтверджено] Шість назв глав NestJS не існують у 12; Prisma 7 потребує особливого налаштування (nitpicker,
  pragmatist).
- [підтверджено] NestJS: права на конкретний запис, хеш пароля у відповіді, модель токена — блокери (security).
- [підтверджено] Навантажувальні заміри й кеш у NestJS; профілювання й віртуалізація в React (performance).
- [підтверджено] Дублі з планом Next.js і фаза 6 React: прибрати, вправи фронтенд-боку перенести в NestJS
  (pragmatist після допиту).
- [підтверджено] Zod через Standard Schema у NestJS 12 (best-practices; OpenAPI без пакетів — умовно, див. нижче).

## Позначене допитувачем

- [слабке] «zod ≥ 4.2 дає OpenAPI без пакетів» — у корпусі zod підтвердження не знайдено; у плані NestJS написано
  умовно, із запасним шляхом `standardSchemaConverter`.
- [слабке] «Prisma 3 дні» — після допиту 4 дні.
- [слабке] «Фаза 6 React уся є деінде» — три з п'яти вправ губилися; перенесено в NestJS.
- [слабке] Вразливості React 2025 як мотив латок для SPA — стосуються лише Server Components.
- [суперечить security] `SameSite=Strict` між різними сайтами — розв'язано: проксі Vite у розробці, той самий
  сайт у продакшні, BFF (Next.js) для різних сайтів.

## Свідомо не робимо

- WebSockets, GraphQL, мікросервіси в NestJS — лише «знати, що існує».
- Паралельне проходження планів.
