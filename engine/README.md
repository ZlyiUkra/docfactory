# engine — родове ядро фабрики

Спільний код, незалежний від домену. Що тут лежить:

- `sources.py` — схема `sources.json` і білий список: дозвіл рахується з оголошення (`url`, `expand: chapters`,
  `within`), шляхи порівнюються нормалізованими; поле `frozen` позначає знімок на закріпленому тезі чи коміті, якого
  звірка й оновлення не питають, доки його не назвуть;
- `net.py` — єдиний мережевий шлюз: кожне звернення і кожен перехід редиректу проходять той самий білий список;
- `readers/` — реєстр читачів: `toc`, `page`, `rfc`, `report`, `ldml`, `pdf` для специфікацій і `llms`, `mdblog`,
  `nextdata`, `gatsby`, `gatsby-blog`, `ghdocs`, `changelog`, `ghreleases`, `mdpage`, `ghcommit` для сайтів
  документації; `_markup.py` —
  їхнє спільне зведення markdown, HTML і дерева Next.js до тексту корпусу. Новий домен додає свій модуль із
  `@register("ім'я")` — модулі теки імпортуються самі, ядро не змінюється;
- `refresh.py` — оновлювач корпусу: тягне лише задеклароване, між зверненнями тримає паузу (`pause_sec` у
  `config.json` примірника), на 429 і 503 чекає й повторює, пише атомарно через тимчасовий файл; `--missing`
  докачує лише відсутні файли;
- `status.py` — звірка «що змінилося нагорі»: нове, змінене, сироти і «невідомо» для джерел, які не відповіли;
  з іменами звіряє лише названі джерела;
- `manifest.py` — паспорт корпусу `corpus/index.json`: суми тексту, якими звірка відрізняє «змінилося» від
  «те саме».

Запускається кроками `./df <домен> …` з кореня фабрики; дані домену код бере зі змінної `DF_INSTANCE_DIR`
(її виставляє `df`), а не з розташування самого коду. Доменне — записи джерел і корпус — живе в
`instances/<домен>/`.

Загальний устрій — у [../README.md](../README.md), проведення апдейту корпусу — в [../UPDATE.md](../UPDATE.md).
