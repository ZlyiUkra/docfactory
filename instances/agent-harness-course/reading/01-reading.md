### Початок файла: опис формату й імпорти

```python
"""Тонкий слой над LLM-провайдерами. Только стандартная библиотека Python.

Внутренний формат сообщений (нейтральный, похож на OpenAI):
    {"role": "system" | "user" | "assistant" | "tool",
     "content": str,
     "tool_calls": [{"id": str, "name": str, "arguments": dict}],   # только у assistant
     "tool_call_id": str}                                            # только у tool
"""
from __future__ import annotations

import json
import os
import urllib.error
import urllib.request
from dataclasses import dataclass, field
from typing import Callable, Iterator
```

Фрагмент скорочено: у файлі опис ще перелічує трьох провайдерів.

**Опис у потрійних лапках.** Текст у `"""` на початку файла називається **докстрингом** (docstring, «рядок
документації»). Це справжній рядок, а не коментар, і Python зберігає його як опис файла. У JavaScript найближче до
цього коментар `/** */`. Такий самий рядок може стояти на початку класу чи функції. Звичайні коментарі в Python
починаються з `#`.

**Що тут найважливіше.** Це опис нейтрального формату, на якому побудовано весь файл. Повідомлення є словником із
чотирма можливими полями. `tool_calls` буває лише у `assistant`, а `tool_call_id` лише у `tool`. Він пов'язує
результат із викликом, бо модель може попросити кілька інструментів одразу. Слова «только стандартная библиотека»
означають, що файл використовує лише те, що входить до самого Python. Це як код без жодного пакета npm.

**Імпорти.**

| Рядок | Те саме в JavaScript | Навіщо тут |
|-------|----------------------|------------|
| `import json` | `import * as json from "json"` | перетворювати дані на JSON і назад; замість `JSON.stringify` і `JSON.parse` |
| `import os` | `process` у Node | читати змінні оточення |
| `import urllib.request` | `fetch` | надсилати HTTP-запити |
| `import urllib.error` | немає прямого аналога | класи помилок HTTP |
| `from dataclasses import dataclass, field` | `import { dataclass, field } from "dataclasses"` | коротке оголошення класів даних |
| `from typing import Callable, Iterator` | типи TypeScript | назви типів для анотацій |

**Рядок `from __future__ import annotations`.** Він просить Python не обчислювати типи під час запуску, а зберігати їх
як текст. Записи на кшталт `name: str` називаються **анотаціями типів**. Вони схожі на TypeScript, але Python під час
роботи їх не перевіряє, і компілятора, який би це зробив, тут немає. Тому `ToolCall(id=5, ...)` не викличе жодної
помилки, хоча в анотації написано `str`.

### `ToolCall`

```python
@dataclass
class ToolCall:
    id: str
    name: str
    arguments: dict
```

Цей клас описує одне прохання моделі виконати інструмент: номер виклику, назву інструмента й аргументи у вигляді вже
розібраного словника. **Словник** (dict) у Python є аналогом простого об'єкта JavaScript.

**Що таке `@dataclass`.** Запис `@щось` над класом чи функцією називається **декоратором**. Це функція, яка отримує
клас і повертає його зміненим. Той самий синтаксис є в TypeScript і в NestJS. Декоратор `@dataclass` читає поля класу
й сам дописує конструктор, текстове подання й порівняння. На TypeScript це було б приблизно так:

```ts
class ToolCall {
  constructor(public id: string, public name: string, public arguments: Record<string, unknown>) {}
}
```

Викликати можна двома способами: `ToolCall("c1", "add", {"a": 1})` або `ToolCall(id="c1", name="add", arguments={"a":
1})`. Ключове слово `new` у Python не потрібне. Звертання `call.name` простіше за `call["name"]`, а помилка в назві
поля відразу дасть виняток, тому код поза `llm.py` працює з класами, а не зі словниками.

### `Reply`

```python
@dataclass
class Reply:
    text: str = ""
    tool_calls: list[ToolCall] = field(default_factory=list)
    input_tokens: int = 0
    output_tokens: int = 0
    stop_reason: str = "end"
```

Це відповідь моделі в нейтральному форматі. Кожне поле має значення за замовчуванням, тому в уроках можна писати
коротко: `Reply("Привіт")`. Порядок полів важливий, бо обидва клієнти створюють `Reply` позиційно: `Reply(text, calls,
вхід, вихід, причина)`.

**Навіщо `field(default_factory=list)`.** Здавалося б, можна написати `tool_calls: list = []`. У Python значення за
замовчуванням обчислюється один раз, під час оголошення класу, тому всі об'єкти отримали б той самий список, і запис в
одному об'єкті з'явився б в усіх інших. Декоратор `@dataclass` забороняє такий запис і видає помилку `ValueError`.
Функція `field(default_factory=list)` каже: для кожного нового об'єкта виклич `list()` і створи новий порожній список.
У JavaScript такої проблеми немає, бо поля класу обчислюються для кожного об'єкта окремо.

**Значення `"end"`.** Це значення за замовчуванням для `stop_reason`. Його отримують записані відповіді сценарної
моделі. Справжні клієнти записують сюди значення провайдера без перекладу.

```python
    def as_message(self) -> dict:
        msg: dict = {"role": "assistant", "content": self.text}
        if self.tool_calls:
            msg["tool_calls"] = [
                {"id": c.id, "name": c.name, "arguments": c.arguments} for c in self.tool_calls
            ]
        return msg
```

Цей метод перетворює відповідь на повідомлення для історії. Цикл агента викликає його, щоб дописати відповідь моделі в
`messages`.

- `def` оголошує функцію чи метод. Блоки в Python позначають відступами, а не фігурними дужками.
- `self` є аналогом `this`, але його треба явно вказувати першим параметром кожного методу. Під час виклику
  `reply.as_message()` Python передає його сам.
- `-> dict` означає тип результату, як `: Record<string, unknown>` у TypeScript.
- `if self.tool_calls:` спрацьовує, лише якщо список не порожній. **Тут Python відрізняється від JavaScript:**
  порожній список, порожній словник і порожній рядок є хибними значеннями, а в JavaScript `[]` і `{}` істинні. Це
  правило трапляється в цьому файлі постійно.
- Запис у квадратних дужках називається **списковим виразом** (list comprehension). `[f(c) for c in items]` — це те
  саме, що `items.map(c => f(c))`.

**Чого немає в результаті.** Токени й причина зупинки не потрапляють в історію, бо моделі вони не потрібні. Поле
`tool_calls` зовсім відсутнє, якщо викликів немає, бо нейтральний формат каже, що воно потрібне лише тоді, коли
виклики є. Історія складається зі словників, а не класів, тому її легко записати у файл як JSON, що й робить модуль 4.

**Спробуй передбачити.** Що поверне `Reply("Думаю", [ToolCall("c1", "add", {"a": 1})]).as_message()`?

### `LLMError`

```python
class LLMError(RuntimeError):
    pass
```

Це власний тип помилки. Запис `class LLMError(RuntimeError)` означає успадкування, як `class LLMError extends Error` у
JavaScript. Помилки в Python називаються **винятками** (exceptions). Слово `pass` означає порожнє тіло: Python вимагає
щонайменше одну інструкцію після двокрапки, а порожні дужки `{}` тут неможливі.

Навіщо окремий тип: щоб код міг перехопити лише помилки роботи з моделлю, написавши `except LLMError:`, і не
перехопити випадково щось інше. У коді курсу цього поки ніхто не робить, тому такий виняток зупиняє всю програму.

### `LLM`

```python
class LLM:
    """Базовый интерфейс. Харнесу всё равно, какой провайдер внутри."""

    name = "base"

    def complete(self, system: str, messages: list[dict], tools: list[dict] | None = None,
                 max_tokens: int = 1024) -> Reply:
        raise NotImplementedError

    def stream_text(self, system: str, messages: list[dict], max_tokens: int = 1024) -> Iterator[str]:
        """По умолчанию — «стрим» одним куском. Провайдеры переопределяют."""
        yield self.complete(system, messages, None, max_tokens).text
```

Це базовий клас. Цикл агента знає лише про нього, тому будь-який провайдер, що має ці методи, підходить без змін у
циклі.

- `name = "base"` є **атрибутом класу**: спільним значенням, яке нащадки перевизначають. Уроки читають його як
  `llm.name`, щоб показати, хто відповідає. У JavaScript найближче до цього поле `static`, але в Python воно доступне
  й через об'єкт.
- Сигнатура `complete` на TypeScript виглядала б так: `complete(system: string, messages: Msg[], tools: Tool[] | null
  = null, maxTokens = 1024): Reply`. `None` у Python є аналогом `null`.
- `max_tokens` за замовчуванням дорівнює 1024. Таке саме значення використовує й цикл `run_agent`. Для коротких кроків
  цього вистачає, а для інструмента, який записує великий файл, може не вистачити.
- `raise NotImplementedError` видає виняток, як `throw` у JavaScript. Це спосіб сказати, що нащадок мусить написати
  цей метод сам. Помилка з'явиться під час виклику, а не під час компіляції, як у TypeScript із ключовим словом
  `abstract`.

**Що таке `yield`.** Функція з `yield` є **генератором**, як `function*` у JavaScript. Зірочка в Python не потрібна:
сам `yield` у тілі робить функцію генератором. Виклик такої функції ще не виконує її тіло, а лише повертає об'єкт,
який можна перебирати циклом `for`. Кожен `yield` віддає одне значення й зупиняє функцію до наступного кроку. Тип
`Iterator[str]` означає послідовність рядків.

Базовий `stream_text` віддає всю відповідь одним шматком. Завдяки цьому код, що читає потік, працює навіть із
провайдером, який потокового режиму не написав.

**Спробуй передбачити.** Чи буде помилка в рядку `g = LLM().stream_text("", [])`, адже `complete` у базовому класі
видає виняток?

<details><summary>Відповідь</summary>

У цьому рядку помилки не буде, бо виклик генератора не запускає його тіло. Виняток з'явиться під час першого кроку
перебору, наприклад у `next(g)` чи `for chunk in g`.

</details>

### `ScriptedLLM`

Сценарна модель видає заздалегідь записані відповіді. На ній працюють усі уроки й тести без ключа. Опис класу з файла
тут пропущено, бо його зміст подано нижче.

```python
class ScriptedLLM(LLM):
    name = "scripted"

    def __init__(self, script: list[Reply] | Callable[[str, list[dict], list[dict] | None], Reply]):
        self.script = script
        self.calls: list[dict] = []  # что модель «видела» — удобно проверять в тестах
```

`__init__` є конструктором, як `constructor` у JavaScript. Сценарій може бути одним із двох типів. На TypeScript це
`Reply[] | ((system: string, messages: Msg[], tools: Tool[] | null) => Reply)`. Список зручний для простих випадків, а
функція потрібна, коли відповідь залежить від вмісту історії. Поле `calls` зберігає все, що модель «бачила».

```python
    def complete(self, system, messages, tools=None, max_tokens=1024):
        self.calls.append({"system": system, "messages": [dict(m) for m in messages], "tools": tools})
        if callable(self.script):
            reply = self.script(system, messages, tools)
        else:
            if not self.script:
                raise LLMError("ScriptedLLM: сценарий закончился")
            reply = self.script.pop(0)
        # грубая оценка токенов, чтобы демо счётчиков тоже работали
        reply.input_tokens = reply.input_tokens or approx_tokens(system) + sum(approx_tokens(json.dumps(m, ensure_ascii=False)) for m in messages)
        reply.output_tokens = reply.output_tokens or approx_tokens(reply.text) + 20 * len(reply.tool_calls)
        return reply
```

Рядок за рядком:

- **`self.calls.append(...)`.** `append` є аналогом `push`. Запис `[dict(m) for m in messages]` створює новий список
  із копіями кожного повідомлення, як `messages.map(m => ({...m}))`. Копія потрібна, бо цикл змінює той самий список
  далі, і без неї запис показав би пізніший стан, а не те, що модель бачила на цьому кроці. Копія неглибока, тому
  вкладений список `tool_calls` лишається спільним.
- **`callable(self.script)`.** Перевіряє, чи це функція, як `typeof script === "function"`.
- **`if not self.script:`.** Порожній список хибний, тому умова спрацює, коли записані відповіді закінчилися. Тест
  одразу побачить, що цикл зробив зайвий виклик.
- **`self.script.pop(0)`.** Забирає перший елемент, як `shift()`. Він змінює переданий список, тому той самий список
  не можна використати для другого запуску.
- **Рядки з токенами.** Оператор `or` працює як `||` у JavaScript: повертає перше істинне значення, а `0` є хибним.
  Якщо в записаній відповіді токени вказано явно, вони лишаються. Інакше код їх оцінює. Оператор `or` виконується
  після `+`, тому читати треба так: `reply.input_tokens or (оцінка system + оцінка повідомлень)`.
- **`sum(... for m in messages)`.** Вираз у дужках без квадратних дужок називається **генераторним виразом**: це те
  саме, що списковий вираз, але значення обчислюються по одному. Весь рядок відповідає `messages.map(...).reduce((a,
  b) => a + b, 0)`.
- **`json.dumps(m, ensure_ascii=False)`.** Перетворює повідомлення на рядок JSON, як `JSON.stringify`. Без
  `ensure_ascii=False` кирилиця стала б послідовностями `Ч`, по 6 символів на букву, і оцінка вийшла б у кілька разів
  завищеною.
- **`20 * len(reply.tool_calls)`.** Умовні 20 токенів на кожен виклик. `len(x)` є аналогом `x.length`.

**Крайні випадки.** Описи інструментів в оцінку не входять. Аргумент `max_tokens` ігнорується, тому сценарна модель не
вміє сама обрізати відповідь: щоб перевірити таку ситуацію, запиши `Reply("...", stop_reason="max_tokens")`. Метод
змінює сам об'єкт відповіді, тому якщо функція-сценарій щоразу повертає той самий об'єкт, числа токенів лишаться від
першого виклику.

```python
    def stream_text(self, system, messages, max_tokens=1024):
        text = self.complete(system, messages, None, max_tokens).text
        for word in text.split(" "):
            yield word + " "
```

Цей метод імітує потоковий режим: бере наступну відповідь сценарію й віддає її по словах. Саме тому в уроці
`01_hello_llm.py` записано дві відповіді: першу забирає `complete`, другу — `stream_text`. Після останнього слова теж
додається пробіл, тому склеєний результат закінчується пробілом.

**Спробуй передбачити.** Сценарій містить дві відповіді. Програма викликає `complete` тричі. Що станеться? Що поверне
`Reply("ok", input_tokens=100)` після виклику `complete`?

<details><summary>Відповідь</summary>

Третій виклик видасть `LLMError("ScriptedLLM: сценарий закончился")`. У другому випадку `input_tokens` лишиться 100,
бо значення вже задане, а `output_tokens` стане 1: у тексті два символи, `2 // 4` дає 0, але `approx_tokens` повертає
щонайменше 1.

</details>

### `approx_tokens`

```python
def approx_tokens(text: str) -> int:
    """Эвристика «символы / 4». Для русского текста занижает (~в 1.5–2 раза), но для бюджета ок."""
    return max(1, len(text) // 4) if text else 0
```

Функція приблизно оцінює кількість токенів без звернення до провайдера. **Евристика** означає грубе правило, яке
зазвичай дає прийнятний результат.

- `A if умова else B` є тернарним оператором, як `умова ? A : B`. Порядок інший: спершу значення, потім умова.
- `//` є цілочисельним діленням, як `Math.floor(a / b)`.
- `max(1, ...)` гарантує, що непорожній текст не дасть 0 токенів.

Опис попереджає, що для російського тексту оцінка занижена в 1,5–2 рази. Лекція 0 пояснює причину: російський токен
коротший за чотири символи. Цю оцінку використовує не лише сценарна модель: у модулі 3 функції з `harness/context.py`
на ній вирішують, чи час скорочувати історію. Для російської історії це означає, що справжня кількість токенів буде
більшою, ніж показує оцінка.

**Спробуй передбачити.** Що поверне функція для `""`, `"abc"` і `"abcdefghi"`?

<details><summary>Відповідь</summary>

0, 1 і 2. Порожній рядок хибний, тому результат 0. У другому випадку `3 // 4` дає 0, а `max` піднімає його до 1. У
третьому `9 // 4` дає 2.

</details>

### `_post`

```python
def _post(url: str, headers: dict, body: dict, timeout: int = 120):
    req = urllib.request.Request(url, data=json.dumps(body).encode(), method="POST",
                                 headers={"content-type": "application/json", **headers})
    try:
        return urllib.request.urlopen(req, timeout=timeout)
    except urllib.error.HTTPError as e:
        detail = e.read().decode(errors="replace")[:500]
        raise LLMError(f"HTTP {e.code} от {url}: {detail}") from e
```

Усі HTTP-запити файла проходять через цю функцію. Підкреслення на початку назви є домовленістю, що функція внутрішня.
Python цього не забороняє, на відміну від `#` у класах JavaScript.

- **`json.dumps(body).encode()`.** Перетворює словник на рядок JSON, а рядок на байти, бо `urllib` надсилає лише
  байти. У JavaScript `fetch` робить другий крок сам. Кирилиця тут запишеться як `Ч`, але це коректний JSON, і сервер
  розбере його правильно.
- **`headers={..., **headers}`.** Запис `**` у словнику розгортає інший словник, як `{...headers}` у JavaScript.
  Пізніші ключі перекривають попередні.
- **`urlopen(req, timeout=timeout)`.** Надсилає запит і повертає відповідь, ще не читаючи її тіла. Саме тому та сама
  функція підходить і для потокового режиму. `timeout=120` означає найбільше очікування окремої операції з мережею в
  секундах, а не всієї відповіді.
- **`try` і `except ... as e`.** Це `try` і `catch (e)`, причому `except` перехоплює лише вказаний тип. **Головна
  відмінність від `fetch`:** `fetch` повертає відповідь навіть із кодом 500 і лише ставить `response.ok = false`, а
  `urlopen` на кодах 4xx і 5xx сам видає виняток `HTTPError`.
- **`e.read().decode(errors="replace")[:500]`.** Читає тіло відповіді з помилкою, де провайдер пояснює причину.
  `errors="replace"` замінює некоректні байти спеціальним символом, а не видає нову помилку. Запис `[:500]` є
  **зрізом** (slice), як `.slice(0, 500)`: він обмежує текст, щоб довга HTML-сторінка проксі не заповнила журнал.
- **`f"HTTP {e.code} от {url}: {detail}"`.** Рядок із префіксом `f` є шаблонним рядком, як `` `HTTP ${code}` `` у
  JavaScript.
- **`raise ... from e`.** Зберігає початкову помилку як причину, як `new Error(msg, { cause: e })`.

**Що зламається й чого тут немає.**

- Повторів немає: перша відповідь 429 чи 5xx одразу дає `LLMError`. Це практика модуля, і дописувати її зручно саме
  тут, бо лише тут доступне число `e.code`. Далі код помилки лишається тільки всередині тексту.
- `except` ловить лише випадок, коли сервер відповів кодом помилки. Якщо з'єднання немає або час очікування вичерпано,
  вийде інший виняток, не `LLMError`.
- Заголовок `retry-after` не читається, хоча він доступний як `e.headers.get("retry-after")`.

**Спробуй передбачити.** Ollama не запущена, а програма викликає `llm.complete(...)`. Який виняток ти побачиш?

<details><summary>Відповідь</summary>

`urllib.error.URLError`, а не `LLMError`. З'єднання не встановилося, тому коду відповіді немає. `HTTPError` є нащадком
`URLError`, тому `except urllib.error.URLError` перехопив би обидва випадки, а `except urllib.error.HTTPError`
перехоплює лише один.

</details>

### `OpenAICompatLLM`

Цей клас працює з будь-яким сервером, який приймає формат OpenAI: сама OpenAI, OpenRouter, DeepSeek, Ollama, LM
Studio, vLLM. Вони відрізняються лише адресою, ключем і назвою моделі.

```python
class OpenAICompatLLM(LLM):
    name = "openai-compatible"

    def __init__(self, model: str, api_key: str = "", base_url: str = "https://api.openai.com/v1"):
        self.model, self.api_key, self.base_url = model, api_key, base_url.rstrip("/")

    def _headers(self):
        return {"authorization": f"Bearer {self.api_key}"} if self.api_key else {}
```

- Перший рядок конструктора присвоює три поля одразу, як деструктуризація в JavaScript: `[a, b, c] = [x, y, z]`.
- `base_url.rstrip("/")` прибирає косу риску в кінці, щоб адреса не вийшла з двома косими рисками, як у
  `.../v1//chat/completions`.
- `_headers` не додає заголовка без ключа, бо локальній Ollama ключ не потрібен.

**Метод `_to_wire`: переклад історії у формат OpenAI.**

```python
    @staticmethod
    def _to_wire(system: str, messages: list[dict]) -> list[dict]:
        out = [{"role": "system", "content": system}] if system else []
        for m in messages:
            if m["role"] == "assistant" and m.get("tool_calls"):
                out.append({
                    "role": "assistant", "content": m.get("content") or None,
                    "tool_calls": [{"id": c["id"], "type": "function",
                                    "function": {"name": c["name"], "arguments": json.dumps(c["arguments"], ensure_ascii=False)}}
                                   for c in m["tool_calls"]],
                })
            elif m["role"] == "tool":
                out.append({"role": "tool", "tool_call_id": m["tool_call_id"], "content": m["content"]})
            else:
                out.append({"role": m["role"], "content": m["content"]})
        return out
```

- `@staticmethod` є аналогом `static`: методу не потрібен `self`, тому тести можуть викликати його без створення
  об'єкта.
- Системний промпт стає першим повідомленням, якщо він не порожній.
- `m["role"]` і `m.get("tool_calls")` різняться. Запис у квадратних дужках видає виняток `KeyError`, якщо ключа немає,
  а в JavaScript там було б `undefined`. Метод `.get` у такому разі повертає `None`.
- `elif` є скороченням `else if`, а `and` є аналогом `&&`.
- **Перша гілка.** Повідомлення моделі з викликами. `m.get("content") or None` перетворює порожній рядок на `null`.
  OpenAI очікує аргументи як рядок із JSON, тому `json.dumps` перетворює словник на рядок. Тут `ensure_ascii=False`
  особливо важливий, бо цей рядок читає сама модель: вона має бачити `Київ`, а не `Київ`.
- **Друга гілка.** Результат інструмента майже без змін.
- **Третя гілка.** Усе інше передається як є.

**Метод `complete`: запит і переклад відповіді.**

```python
    def complete(self, system, messages, tools=None, max_tokens=1024):
        body = {"model": self.model, "max_tokens": max_tokens, "messages": self._to_wire(system, messages)}
        if tools:
            body["tools"] = [{"type": "function", "function": t} for t in tools]
        with _post(f"{self.base_url}/chat/completions", self._headers(), body) as r:
            data = json.load(r)
        choice = data["choices"][0]
        msg = choice["message"]
        calls = []
        for c in msg.get("tool_calls") or []:
            try:
                args = json.loads(c["function"].get("arguments") or "{}")
            except json.JSONDecodeError:
                args = {"__invalid_json__": c["function"].get("arguments")}
            calls.append(ToolCall(c["id"], c["function"]["name"], args))
        usage = data.get("usage") or {}
        return Reply(msg.get("content") or "", calls, usage.get("prompt_tokens", 0),
                     usage.get("completion_tokens", 0), choice.get("finish_reason") or "end")
```

- `body["tools"]` загортає кожен опис інструмента в об'єкт із `type: "function"`, бо внутрішній опис має поля `name`,
  `description` і `parameters`, а OpenAI хоче їх усередині `function`.
- **`with ... as r:`** гарантує закриття з'єднання, навіть якщо всередині сталася помилка. Це як `try { ... } finally
  { r.close() }`. Змінна `data` доступна й після блоку, бо блоки `with` і `if` у Python не створюють окремої області
  видимості.
- `json.load(r)` читає все тіло відповіді й розбирає JSON. Функція `load` працює з потоком, а `loads` (буква `s` від
  string) з рядком.
- `data["choices"][0]` бере перший варіант, бо формат OpenAI повертає масив варіантів відповіді.
- `msg.get("tool_calls") or []` дає порожній список, якщо ключа немає або він дорівнює `null`.
- **Блок `try`.** OpenAI надсилає аргументи рядком, і офіційна бібліотека OpenAI попереджає, що модель не завжди пише
  коректний JSON. Якщо `json.loads` не може його розібрати, код кладе сирий рядок у спеціальний аргумент
  `__invalid_json__`, і програма працює далі. Потім функція `validate_args` із `harness/tools.py` бачить цей аргумент
  і повертає текст помилки, який модель отримає як результат інструмента. Так модель може виправитися сама.
- `or "{}"` обробляє випадок, коли аргументів немає зовсім: вийде порожній словник.
- `data.get("usage") or {}` враховує сервери, які не надсилають `usage`. Тоді токени будуть нулями, і ціна вийде
  нульовою, хоча це не так.
- Останній рядок заповнює `Reply` у порядку оголошення полів. `finish_reason` записується без перекладу, тому там буде
  `stop`, `length` або `tool_calls`, а не `end_turn`, `max_tokens` чи `tool_use`.

**Спробуй передбачити.** Модель обірвалася, і в полі `arguments` лежить `{"path": "no`. Що буде в
`ToolCall.arguments`? А якщо там порожній рядок?

<details><summary>Відповідь</summary>

У першому випадку `{"__invalid_json__": '{"path": "no'}`. У другому порожній рядок хибний, тому `or` підставить
`"{}"`, і вийде порожній словник `{}`. Тоді `validate_args` повідомить про відсутній обов'язковий аргумент, якщо такий
є в інструмента.

</details>

**Застереження про `max_tokens`.** Офіційна бібліотека OpenAI позначає це поле застарілим на користь
`max_completion_tokens` і каже, що моделі серії o його не приймають. Ollama це поле підтримує.

**Метод `stream_text`: читання потоку.**

```python
    def stream_text(self, system, messages, max_tokens=1024):
        body = {"model": self.model, "max_tokens": max_tokens, "stream": True,
                "messages": self._to_wire(system, messages)}
        with _post(f"{self.base_url}/chat/completions", self._headers(), body) as r:
            for raw in r:  # Server-Sent Events: строки вида "data: {...}"
                line = raw.decode().strip()
                if not line.startswith("data:"):
                    continue
                payload = line[5:].strip()
                if payload == "[DONE]":
                    break
                delta = json.loads(payload)["choices"][0].get("delta", {})
                if delta.get("content"):
                    yield delta["content"]
```

- `"stream": True` вмикає потоковий режим. Python пише `True`, `False` і `None` з великої літери.
- `for raw in r` перебирає рядки відповіді, поки вона надходить. Кожен `raw` є байтами. Читання цілими рядками зручне
  ще й тим, що символ кирилиці не розірветься між двома шматками, як це може статися з `getReader` у JavaScript без
  `TextDecoder` із параметром `stream: true`.
- `.strip()` прибирає пробіли й символи нового рядка з обох боків, як `.trim()`.
- `continue` і `break` працюють так само, як у JavaScript.
- `line[5:]` є зрізом від п'ятого символу до кінця: `.slice(5)`.
- `.get("delta", {})` повертає порожній словник, якщо ключа немає.
- `if delta.get("content"):` пропускає порожні шматки: не кожна подія містить текст.

Формат потоку показано в лекції. Цей метод не передає інструментів, не читає `usage` і не бачить причини зупинки.
OpenAI надсилає токени в потоці лише за окремим запитом через `stream_options`, а код курсу такого запиту не робить.

### `AnthropicLLM`

```python
class AnthropicLLM(LLM):
    name = "anthropic"
    URL = "https://api.anthropic.com/v1/messages"

    def __init__(self, model: str, api_key: str):
        self.model, self.api_key = model, api_key

    def _headers(self):
        return {"x-api-key": self.api_key, "anthropic-version": "2023-06-01"}
```

Адреса тут стала. Anthropic чекає ключ у заголовку `x-api-key`, а заголовок `anthropic-version` вказує версію API, за
якою сервер будує відповідь.

**Метод `_to_wire`: переклад історії у формат Anthropic.** Цей метод не приймає `system`, бо в Anthropic системний
промпт не є повідомленням.

```python
    @staticmethod
    def _to_wire(messages: list[dict]) -> list[dict]:
        out: list[dict] = []
        for m in messages:
            if m["role"] == "assistant":
                blocks = [{"type": "text", "text": m["content"]}] if m.get("content") else []
                blocks += [{"type": "tool_use", "id": c["id"], "name": c["name"], "input": c["arguments"]}
                           for c in m.get("tool_calls", [])]
                out.append({"role": "assistant", "content": blocks or [{"type": "text", "text": "…"}]})
            elif m["role"] == "tool":
                block = {"type": "tool_result", "tool_use_id": m["tool_call_id"], "content": m["content"]}
                # результаты инструментов идут в user-сообщении; подряд идущие склеиваем
                if out and out[-1]["role"] == "user" and isinstance(out[-1]["content"], list) \
                        and out[-1]["content"] and out[-1]["content"][0].get("type") == "tool_result":
                    out[-1]["content"].append(block)
                else:
                    out.append({"role": "user", "content": [block]})
            else:
                out.append({"role": "user", "content": m["content"]})
        return out
```

**Гілка `assistant`.** В Anthropic вміст є списком блоків різних типів.

- Текстовий блок з'являється, лише якщо текст не порожній.
- `blocks += [...]` дописує елементи, як `blocks.push(...items)`.
- `c["arguments"]` передається як об'єкт, а не рядок, бо поле `input` в Anthropic є об'єктом.
- `blocks or [{"type": "text", "text": "…"}]` спрацьовує, коли повідомлення зовсім порожнє: немає ні тексту, ні
  викликів. Anthropic відхиляє повідомлення без вмісту, тому код підставляє символ «…». Модель побачить його в історії
  як власну відповідь.

**Гілка `tool`.** Це найскладніше місце файла. Результат стає блоком `tool_result` у повідомленні `user`. Довга умова
перевіряє, чи попереднє повідомлення вже містить результати інструментів:

| Перевірка | Навіщо |
|-----------|--------|
| `out` | Список не порожній: інакше `out[-1]` видасть виняток `IndexError` |
| `out[-1]["role"] == "user"` | Останнє повідомлення від людини. `out[-1]` є аналогом `out.at(-1)` |
| `isinstance(out[-1]["content"], list)` | Вміст є списком блоків, а не звичайним рядком. `isinstance` схожий на `instanceof` |
| `out[-1]["content"]` | Список блоків не порожній: інакше `[0]` видасть виняток |
| `out[-1]["content"][0].get("type") == "tool_result"` | Перший блок є результатом інструмента |

Якщо все так, новий блок дописується до того самого повідомлення, а якщо ні, створюється нове. Зворотна коса риска `\`
в кінці рядка означає, що вираз продовжується на наступному рядку.

Навіщо склеювати: коли модель просила кілька інструментів одразу, усі результати відповідають на одне її повідомлення.
Документація Anthropic вимагає, щоб результати йшли одразу після повідомлення з викликами й щоб у повідомленні `user`
блоки `tool_result` стояли першими. Звичайне повідомлення людини має вміст-рядок, тому воно ніколи не склеїться з
результатами.

**Гілка `else`.** Усе інше стає повідомленням `user`. Отже, повідомлення з роллю `system` усередині `messages`
непомітно стало б повідомленням людини. У коді курсу таких повідомлень немає, бо системний промпт завжди йде окремим
аргументом. У клієнті для OpenAI така роль збереглася б. Це невелика відмінність між двома клієнтами, яку варто знати,
якщо ти колись покладеш `system` в історію.

**Спробуй передбачити.** В історії є `{"role": "assistant", "content": ""}` без викликів. Що вийде в обох клієнтів?

<details><summary>Відповідь</summary>

В `AnthropicLLM`: `{"role": "assistant", "content": [{"type": "text", "text": "…"}]}`. В `OpenAICompatLLM` умова
першої гілки не виконається, бо викликів немає, тому спрацює третя гілка: `{"role": "assistant", "content": ""}`.

**Метод `complete`.**

```python
    def complete(self, system, messages, tools=None, max_tokens=1024):
        body = {"model": self.model, "max_tokens": max_tokens, "messages": self._to_wire(messages)}
        if system:
            body["system"] = system
        if tools:
            body["tools"] = [{"name": t["name"], "description": t["description"],
                              "input_schema": t["parameters"]} for t in tools]
        with _post(self.URL, self._headers(), body) as r:
            data = json.load(r)
        text = "".join(b["text"] for b in data["content"] if b["type"] == "text")
        calls = [ToolCall(b["id"], b["name"], b["input"]) for b in data["content"] if b["type"] == "tool_use"]
        u = data.get("usage", {})
        return Reply(text, calls, u.get("input_tokens", 0), u.get("output_tokens", 0), data.get("stop_reason", "end"))
```

- `system` стає окремим полем тіла запиту.
- У описах інструментів `parameters` перейменовується на `input_schema`.
- `"".join(... for b in ... if ...)` бере лише текстові блоки й склеює їх. Це те саме, що `.filter(b => b.type ===
  "text").map(b => b.text).join("")`. Умова `if` у кінці виразу працює як `filter`.
- `calls` збирає блоки `tool_use`. На відміну від OpenAI, `b["input"]` уже є об'єктом, тому блоку `try` тут немає й
  розбирати нічого.
- `stop_reason` записується без перекладу. Значення можуть бути такі: `end_turn`, `max_tokens`, `tool_use`,
  `stop_sequence`, `refusal` та інші.

**Що тут втрачається.**

- Усі інші типи блоків ігноруються, зокрема блоки міркувань `thinking`. Нові моделі Anthropic міркують без окремого
  налаштування, а документація вимагає повертати такі блоки разом із результатами інструментів. Метод `_to_wire` будує
  лише блоки `text` і `tool_use`, тому цю вимогу код курсу не виконує. Якщо у своєму агенті використаєш таку модель з
  інструментами, перевір сторінку про міркування в примірнику `anthropic-api`.
- Якщо відповідь обрізано посеред виклику, документація радить повторити запит із більшим `max_tokens`. Код цього
  випадку окремо не обробляє: поле `input` піде в `ToolCall` таким, яким прийшло. Функція `validate_args` помітить
  відсутній обов'язковий аргумент, але обрізаного значення не помітить.
- Якщо ввімкнути кешування, `input_tokens` не міститиме токенів із кешу, і підрахунок ціни доведеться розширити.

**Метод `stream_text`.**

```python
    def stream_text(self, system, messages, max_tokens=1024):
        body = {"model": self.model, "max_tokens": max_tokens, "stream": True,
                "messages": self._to_wire(messages), **({"system": system} if system else {})}
        with _post(self.URL, self._headers(), body) as r:
            for raw in r:
                line = raw.decode().strip()
                if line.startswith("data:"):
                    ev = json.loads(line[5:])
                    if ev.get("type") == "content_block_delta" and ev["delta"].get("type") == "text_delta":
                        yield ev["delta"]["text"]
```

Запис `**({"system": system} if system else {})` додає поле лише за умови, як `...(system ? { system } : {})` у
JavaScript. Потік Anthropic виглядає так:

```text
event: content_block_delta
data: {"type": "content_block_delta", "index": 0, "delta": {"type": "text_delta", "text": "При"}}

event: message_stop
data: {"type": "message_stop"}
```

Рядки `event:` код пропускає, бо тип події є й усередині JSON у полі `type`. Ось усі події потоку й що з ними робить
код:

| Подія | Що в ній | Що робить код |
|-------|----------|---------------|
| `message_start` | Початок повідомлення й лічильник вхідних токенів | пропускає |
| `content_block_start`, `content_block_stop` | Початок і кінець блоку | пропускає |
| `content_block_delta` із `text_delta` | Шматок тексту | віддає через `yield` |
| `content_block_delta` інших типів | Шматок аргументів чи міркувань | пропускає |
| `message_delta` | Причина зупинки й токени | пропускає |
| `message_stop` | Кінець повідомлення | пропускає, цикл завершиться, коли сервер закриє відповідь |
| `ping` | Службова подія без змісту | пропускає |
| `error` | Помилка після коду 200, наприклад `overloaded_error` | пропускає, **і це справжня проблема** |

Остання подія найважливіша. Якщо провайдер перевантажиться посеред відповіді, він надішле подію `error`, а код її не
помітить. Людина побачить відповідь, що обірвалася без жодної помилки. У своєму агенті перевіряй `ev.get("type") ==
"error"` і видавай виняток.

### `from_env`

```python
def from_env(fallback: LLM | None = None) -> LLM:
    provider = os.environ.get("LLM_PROVIDER", "mock").lower()
    model = os.environ.get("LLM_MODEL", "")
    if provider == "mock":
        if fallback is None:
            raise LLMError("Нет сценария для mock-режима. Задай LLM_PROVIDER=openai|anthropic и LLM_MODEL.")
        return fallback
    if not model:
        raise LLMError("Задай LLM_MODEL — актуальные id смотри в документации провайдера.")
    if provider == "openai":
        return OpenAICompatLLM(model, os.environ.get("LLM_API_KEY", ""),
                               os.environ.get("LLM_BASE_URL", "https://api.openai.com/v1"))
    if provider == "anthropic":
        key = os.environ.get("LLM_API_KEY") or os.environ.get("ANTHROPIC_API_KEY", "")
        return AnthropicLLM(model, key)
    raise LLMError(f"Неизвестный LLM_PROVIDER={provider}")
```

Тут пропущено опис функції, який є у файлі, бо нижче він поданий таблицею. Функція `from_env` є **фабрикою**, тобто
функція, яка вирішує, який об'єкт створити.

- `os.environ.get("LLM_PROVIDER", "mock")` є аналогом `process.env.LLM_PROVIDER ?? "mock"`. Метод `.lower()` дозволяє
  написати `OPENAI` великими літерами.
- `fallback` є запасною сценарною моделлю. Її передає кожен урок зі своїм сценарієм, тому сам `from_env` нічого про
  сценарії не знає.
- `fallback is None` перевіряє саме на `None`, як `fallback === null`.
- `LLM_API_KEY` має перевагу над `ANTHROPIC_API_KEY`, бо оператор `or` бере перше непорожнє значення.

| `LLM_PROVIDER` | `LLM_MODEL` | Результат |
|----------------|-------------|-----------|
| не задано або `mock` | неважливо | `fallback`, а якщо його немає, `LLMError` |
| `openai` або `anthropic` | порожньо | `LLMError` із проханням задати модель |
| `openai` | задано | `OpenAICompatLLM` |
| `anthropic` | задано | `AnthropicLLM` |
| інше значення | задано | `LLMError` про невідомого провайдера |
| інше значення | порожньо | `LLMError` із проханням задати модель, бо ця перевірка стоїть раніше |

**Крайні випадки.** Наявність ключа тут не перевіряється. Якщо ключа немає, помилка з'явиться лише під час першого
запиту: відповідь 401 стане `LLMError`. Ще одна небезпека: якщо ти раніше виконав `export LLM_PROVIDER=anthropic`, то
всі наступні запуски в цьому вікні термінала йтимуть до платного провайдера, а не до сценарної моделі. Перед першим
запуском перевір змінні командою `env | grep LLM_PROVIDER`. Значення ключа нікуди не копіюй і не показуй.

**Спробуй передбачити.** Задано `LLM_PROVIDER=openai`, а `LLM_MODEL` і `LLM_API_KEY` порожні. Що станеться?

<details><summary>Відповідь</summary>

`from_env` видасть `LLMError("Задай LLM_MODEL — ...")`, бо перевірка моделі стоїть перед створенням клієнта. Ключ ця
функція не перевіряє взагалі, тому без `LLM_MODEL` справа до нього не дійде.

</details>

### Що перенести у свій `llm.py`

- Нейтральний формат і переклад лише всередині класів провайдерів.
- Сценарну модель із записом викликів у `calls`.
- Перетворення помилки розбору JSON на текст для моделі замість аварійного завершення.
- Те, чого в коді курсу немає: повтори, зведення причин зупинки до спільних слів, перевірку події `error` у потоці.
