# Оновлення корпусу algorithms

Книжки, статті й курси MIT не міняються. Оновлення — це здебільшого нова книжка чи стаття, або новий коміт cp-algorithms.

Правило: **нічого не видаляється.** Лише `vectors` прибирає точки своєї колекції, чиїх фрагментів уже немає в корпусі.

1. Поверніть тексти за [README, розділ «Корпус лише локально»](README.md#корпус-лише-локально).
2. Нова книжка з файлу: покладіть PDF у `instances/algorithms/raw/local/` під коротким іменем латиницею і допишіть джерело в
   `sources.json` за зразком сусідніх: читач `pdf-outline`, поля `file`, `url` (сторінка видавця), `title`, `depth` (до якої
   глибини закладок різати книжку на документи), `skip` (такий самий, як у сусідів: він відкидає покажчики) і `frozen: true`.
   Книжка лише сканом: спершу розпізнайте її скриптом з README (розділ «Як читаються файли»), потім джерело `ocr-pages` з полями
   `folder` і `page_titles`.
3. Новий коміт cp-algorithms чи algorithmica: візьміть SHA коміту і впишіть його в `url` джерела замість старого.
4. Оновіть примірник:

```
./df algorithms refresh <id джерела>
./df algorithms manifest
./df algorithms vectors
./df algorithms smoke
./df algorithms quality
```

5. Запишіть нове число фрагментів у `checks.json`, зробіть новий архів і звірте його з диском. Лише тоді видаляйте тексти з теки
   та попередній архів.

Усі джерела позначено `frozen`, тому `refresh` без імен їх не чіпає: джерело треба називати за id. Якщо читач змінився,
перебудовують усі джерела цього читача: `refresh` з їхніми id. Старі файли з іншими іменами `refresh` сам не видаляє, їх
прибирають вручну перед `manifest`.

Якщо з WSL не відповідає github.com чи api.github.com, а з Windows відповідає, WSL не дістає до адреси, яку повернув DNS. 10.11.2026
це обійшли двома рядками в `/etc/hosts` з іншими адресами GitHub (`140.82.121.6 api.github.com`, `140.82.121.4 github.com`). Ці
рядки треба прибрати, коли збирання закінчено: адреси GitHub із часом змінюються.
