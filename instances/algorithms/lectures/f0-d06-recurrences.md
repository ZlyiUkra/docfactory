# Лекція. День 6. Рекурентні співвідношення

Ця лекція вчить рахувати час рекурсивних алгоритмів. Читання займе близько 60 хвилин. Числа в таблицях порахувала
програма в Node 24.22, і під кожною таблицею сказано, як саме.

Учора кількість викликів рекурсивної функції ми рахували програмою або на око, малюючи дерево викликів. Для циклів
день 2 дав точний спосіб: порахувати, скільки разів виконується кожен рядок, і скласти. Для рекурсії такий самий
точний спосіб — записати час функції рівнянням, у якому час для входу `n` виражено через час для менших входів, і
розв'язати це рівняння.

**Після лекції ви зможете пояснити:**

- як за кодом рекурсивної функції записати рекурентне співвідношення для її часу;
- як розв'язати співвідношення розгортанням і деревом рекурсії;
- які три ситуації бувають у дереві рекурсії і чому відповідь визначає найбільший рівень;
- як застосовувати головну теорему і коли вона не застосовна;
- як довести вгадану відповідь методом підстановки і де в ньому легко помилитися;
- чому кількість і розмір підзадач важать більше, ніж робота кожного виклику.

## Два схожі рівняння

MCS порівнює дві рекурсивні процедури. Перша — вежі Ханоя з учорашньої лекції: щоб перенести `n` дисків, вона двічі
переносить `n − 1` дисків і робить один хід. Друга — сортування злиттям: щоб відсортувати `n` чисел, вона двічі сортує
половину і зливає половини, роблячи не більше `n − 1` порівнянь. Запишемо їхні витрати:

```
Вежі Ханоя:          T(n) = 2T(n − 1) + 1
Сортування злиттям:  T(n) = 2T(n/2) + n − 1
```

Обидві процедури розбивають задачу на дві підзадачі і додають трохи роботи. Перша додає лише один крок, друга — майже
`n`. Здається, що перша має бути швидшою. Порахуємо для `n = 64`. Вежі Ханоя роблять `2⁶⁴ − 1 = 18 446 744 073 709 551
615` ходів, понад `10¹⁹`. Сортування злиттям 64 чисел робить не більше `64 · 6 − 64 + 1 = 321` порівняння. Різниця у
п'ятдесят сім квадрильйонів разів.

Вирішила не робота кожного виклику, а **розмір підзадач**: `n − 1` проти `n/2`. Ця лекція вчить бачити такі речі за
рівнянням, не рахуючи всіх викликів.

## Що таке рекурентне співвідношення

**Рекурентне співвідношення** — рівняння, яке описує функцію через її ж значення на менших аргументах. Як і рекурсивна
функція, воно має **базові випадки**, де значення дано прямо, і **рекурсивні випадки**, де значення виражено через
менші. Erickson зауважує просту річ: якщо переписати співвідношення як рекурсивну функцію, розв'язок — це те, що ця
функція обчислює.

Для аналізу алгоритмів нас цікавить не саме рівняння, а **замкнена форма**: вираз без самопосилання, такий як `2ⁿ − 1`
чи `n log₂ n`. Зазвичай досить асимптотичної відповіді на кшталт `Θ(n log n)`.

### Як записати співвідношення за кодом

Правило просте: час виклику на вході розміру `n` дорівнює сумі часу рекурсивних викликів і часу всієї іншої роботи
цього виклику.

| Що робить функція | Співвідношення |
|-------------------|----------------|
| робить стале число дій і один виклик на вході, меншому на 1 | `T(n) = T(n − 1) + Θ(1)` |
| проходить весь вхід і робить один виклик на вході, меншому на 1 | `T(n) = T(n − 1) + Θ(n)` |
| ділить вхід навпіл, робить два виклики на половинах, потім проходить увесь вхід | `T(n) = 2T(n/2) + Θ(n)` |
| ділить навпіл, робить три виклики на половинах і проходить увесь вхід | `T(n) = 3T(n/2) + Θ(n)` |

Друге співвідношення описує, наприклад, сортування вставками, записане рекурсивно: відсортувати перші `n − 1`
елементів, а потім вставити останній, пройшовши в найгіршому випадку весь масив. Третє описує сортування злиттям.
Четверте — множення Карацуби, яке план розбирає у фазі 4.

Базовий випадок для асимптотики майже не важить. CLRS домовляється вважати `T(n) = Θ(1)` для всіх `n`, менших за
деякий поріг, і не писати цього щоразу. MCS пояснює чому: якщо найнижча операція займає вдвічі більше часу, весь час
зросте не більше ніж удвічі, а такий множник `Θ` і так ховає.

Так само для асимптотики не важать округлення. Насправді масив непарної довжини ділиться на `⌊n/2⌋` і `⌈n/2⌉`, а не на
дві рівні половини, але і CLRS, і MCS, і Erickson показують, що відповідь від цього не змінюється. Тому округлення
зазвичай не пишуть, а `n` для зручності вважають степенем двійки.

## Метод 1: розгортання

Найпряміший спосіб — підставляти рівняння саме в себе, поки не проступить закономірність. MCS називає це «plug and
chug», тобто «підстав і спрости». Розв'яжемо співвідношення з другого рядка таблиці, `T(n) = T(n − 1) + n` з базою
`T(0) = 0`:

```
T(n) = T(n − 1) + n
     = T(n − 2) + (n − 1) + n
     = T(n − 3) + (n − 2) + (n − 1) + n
     = …
     = T(0) + 1 + 2 + … + n
     = n(n + 1)/2
```

Відповідь `Θ(n²)`. Програма порахувала точні значення: `T(10) = 55`, `T(100) = 5050`, `T(1000) = 500 500`, і всі вони
дорівнюють `n(n + 1)/2`. Це та сама сума з дня 2, і вона пояснює, чому сортування вставками квадратичне: одна
підзадача, менша лише на одиницю, і лінійна робота на кожному кроці.

Розгортання дає здогадку, а не доведення: «і так далі» між третім і передостаннім рядком треба довести індукцією.
Erickson у конспекті розгортає так рівняння веж Ханоя і сортування злиттям, а потім доводить знайдену закономірність
індукцією за кількістю розгортань.

## Метод 2: дерево рекурсії

Розгортання незручне, коли рекурсивних викликів кілька. Тоді малюють **дерево рекурсії**. Кожен вузол дерева — одна
підзадача, а значення вузла — робота цієї підзадачі **без** рекурсивних викликів. Час усього алгоритму дорівнює сумі
значень усіх вузлів. Erickson радить на практиці малювати перші два-три рівні дерева, а потім рахувати суму **по
рівнях**.

Для рівняння `T(n) = aT(n/b) + f(n)` дерево влаштоване так:

- на глибині `i` лежить `aⁱ` вузлів, бо кожен вузол має `a` нащадків;
- кожен вузол глибини `i` розв'язує задачу розміру `n/bⁱ` і має значення `f(n/bⁱ)`;
- дерево закінчується, коли розмір доходить до 1, тобто на глибині `L = log_b n`;
- листків `a^L = a^(log_b n) = n^(log_b a)`.

Остання рівність не очевидна, тому перевірмо її на числах. Для `a = 3`, `b = 4` і `n = 4¹⁰` листків `3¹⁰ = 59 049`, а
`n^(log₄ 3) = (4¹⁰)^0,7925 ≈ 59 049`. Обидва вирази рахують одне: скільки разів по `a` можна розгалузитися за `log_b
n` рівнів.

### Приклад: `T(n) = 3T(n/2) + n`

Розпишемо дерево по рівнях:

| Глибина | Вузлів | Розмір кожного | Робота кожного | Робота рівня |
|---------|--------|----------------|----------------|--------------|
| 0 | 1 | `n` | `n` | `n` |
| 1 | 3 | `n/2` | `n/2` | `(3/2) · n` |
| 2 | 9 | `n/4` | `n/4` | `(3/2)² · n` |
| `i` | `3ⁱ` | `n/2ⁱ` | `n/2ⁱ` | `(3/2)ⁱ · n` |
| `log₂ n` (листки) | `3^(log₂ n) = n^(log₂ 3)` | 1 | 1 | `n^(log₂ 3)` |

Робота рівнів росте: кожен рівень у півтора раза дорожчий за попередній. Це **зростаюча геометрична прогресія**, а
сума такої прогресії з точністю до сталого множника дорівнює її найбільшому члену, тобто останньому. Останній рівень —
листки, їх `n^(log₂ 3)`. Отже, `T(n) = Θ(n^(log₂ 3)) ≈ Θ(n^1,585)`.

Програма обчислила `T(n)` точно за рівнянням з базою `T(1) = 1` і поділила на `n^(log₂ 3)`:

```
n        3T(n/2)+n   n^log2(3)   відношення
2^4               211           81      2.605
2^8             19171         6561      2.922
2^12          1586131       531441      2.985
2^16        129009091     43046721      2.997
2^20      10458256051   3486784401      2.999
```

Відношення прямує до сталої 3. Це і означає `Θ(n^(log₂ 3))`: функція з часом поводиться як `n^(log₂ 3)`, помножене на
сталу. Точна замкнена форма тут `3 · n^(log₂ 3) − 2n`, але для висновку про швидкість вона не потрібна.

### Приклад: `T(n) = 2T(n/2) + n²`

| Глибина | Вузлів | Робота кожного | Робота рівня |
|---------|--------|----------------|--------------|
| 0 | 1 | `n²` | `n²` |
| 1 | 2 | `(n/2)²` | `n²/2` |
| 2 | 4 | `(n/4)²` | `n²/4` |
| `i` | `2ⁱ` | `(n/2ⁱ)²` | `n²/2ⁱ` |

Тепер робота рівнів **спадає** вдвічі на кожному рівні. Сума спадної геометричної прогресії теж дорівнює її
найбільшому члену з точністю до сталої, а найбільший член тут перший, корінь. Отже, `T(n) = Θ(n²)`: майже вся робота
виконується на верхньому рівні. Програма підтвердила: відношення `T(n)/n²` дорівнює 1,938 для `n = 16` і далі 1,996,
2,000, 2,000. Точна форма `2n² − n`.

### Три ситуації

Erickson зводить усе до трьох випадків суми по рівнях:

| Робота рівнів | Чим визначається сума | Відповідь |
|---------------|-----------------------|-----------|
| спадає геометрично | коренем | `T(n) = Θ(f(n))` |
| однакова на всіх рівнях | кількістю рівнів | `T(n) = Θ(f(n) · log n)` |
| росте геометрично | листками | `T(n) = Θ(n^(log_b a))` |

Чому сума геометричної прогресії дорівнює найбільшому члену з точністю до сталої? Якщо кожен член щонайменше в `r > 1`
разів менший за наступний, то всі члени, крім найбільшого, разом не перевищують найбільший, помножений на `1/(r − 1)`.
Для прогресії зі знаменником 3/2 решта членів не більша за подвоєний останній. Сталий множник `Θ` ховає.

Середній рядок — випадок сортування злиттям: два вузли розміру `n/2` разом роблять стільки ж, скільки один вузол
розміру `n`, тож кожен з `log₂ n` рівнів коштує `n`. Звідси `Θ(n log n)`. Дерево для `n = 16`, яке практика дня
просить намалювати, показує це наочно.

### Нерівне дерево

Дерево рекурсії працює і тоді, коли підзадачі різного розміру. CLRS розбирає `T(n) = T(n/3) + T(2n/3) + n`. Ліва гілка
щоразу зменшує задачу втричі, права — лише в півтора раза, тому листки лежать на різній глибині. Але на кожному
повному рівні розміри підзадач разом дають `n`, бо `n/3 + 2n/3 = n`. Рівнів не більше `log_{3/2} n`, тобто `Θ(log n)`.
Отже, `T(n) = O(n log n)`.

Програма обчислила цю функцію з округленням униз і поділила на `n log₂ n`: 0,976 для тисячі, 1,010 для десяти тисяч,
1,029 для ста тисяч і мільйона. Відношення стабілізується, тобто відповідь справді `Θ(n log n)`.

CLRS у цьому прикладі показує ще одну пастку. Здається, що листків не більше, ніж у повному двійковому дереві такої
самої висоти, а це `2^(log_{3/2} n) = n^(log_{3/2} 2) ≈ n^1,71`. Ця оцінка правдива, але дуже груба: вона більша за `n
log n` і зіпсувала б відповідь. Насправді листків `Θ(n)`, і книжка доводить це окремим рівнянням для кількості
листків. Висновок: верхня межа, яка правдива, ще не обов'язково корисна.

## Метод 3: головна теорема

Більшість рівнянь вигляду `T(n) = aT(n/b) + f(n)` розв'язуються одразу **головною теоремою** (master theorem). Вона
формалізує три ситуації дерева рекурсії. CLRS називає функцію `f(n)` **рушійною** (driving function), а функцію
`n^(log_b a)`, тобто кількість листків, — **вододільною** (watershed function). Теорема порівнює їх.

Умови: `a > 0` і `b > 1` — сталі. Тоді:

| Випадок | Умова | Відповідь | Що в дереві |
|---------|-------|-----------|-------------|
| 1 | `f(n) = O(n^(log_b a − ε))` для деякого `ε > 0` | `Θ(n^(log_b a))` | переважають листки |
| 2 | `f(n) = Θ(n^(log_b a) · lgᵏ n)` для деякого `k ≥ 0` | `Θ(n^(log_b a) · lg^(k+1) n)` | рівні приблизно однакові |
| 3 | `f(n) = Ω(n^(log_b a + ε))` для деякого `ε > 0` і `a·f(n/b) ≤ c·f(n)` для деякого `c < 1` | `Θ(f(n))` | переважає корінь |

Запис `lgᵏ n` означає `(log₂ n)ᵏ`. Найчастіше в другому випадку `k = 0`, і тоді умова — просто `f(n) = Θ(n^(log_b
a))`, а відповідь `Θ(n^(log_b a) · lg n)`. Формулювання з довільним `k` — особливість 4-го видання CLRS. У старших
книжках і в Bae другий випадок записано лише для `k = 0`.

Два технічні слова в умовах важать багато.

**«Поліноміально».** У першому і третьому випадках однієї різниці в швидкості росту замало: `f(n)` має відрізнятися
від `n^(log_b a)` у `n^ε` разів для деякого сталого `ε > 0`. Різниця в логарифм разів недостатня.

**Умова регулярності** в третьому випадку, `a·f(n/b) ≤ c·f(n)` з `c < 1`, означає, що робота всіх нащадків вузла разом
строго менша за роботу самого вузла. Тоді робота рівнів справді спадає геометрично. Для звичайних функцій на кшталт
`n²` чи `n lg n` вона виконується сама.

### Як застосовувати

Порядок дій завжди той самий: знайти `a`, `b` і `f(n)`; обчислити `log_b a`; порівняти `f(n)` з `n^(log_b a)`; вибрати
випадок. Кілька прикладів із CLRS і MCS, жоден з яких не збігається із завданнями практики:

| Рівняння | `n^(log_b a)` | Порівняння | Випадок | Відповідь |
|----------|---------------|------------|---------|-----------|
| `9T(n/3) + n` | `n²` | `n` менше в `n¹` разів | 1 | `Θ(n²)` |
| `3T(n/2) + n` | `n^1,585` | `n` менше в `n^0,585` разів | 1 | `Θ(n^(log₂ 3))` |
| `7T(n/2) + n²` | `n^2,807` | `n²` менше в `n^0,8` разів | 1 | `Θ(n^(lg 7))`, алгоритм Штрассена |
| `T(2n/3) + 1` | `n⁰ = 1` | рівні | 2, `k = 0` | `Θ(lg n)` |
| `2T(n/2) + n lg n` | `n` | більше в `lg n` разів | 2, `k = 1` | `Θ(n lg² n)` |
| `3T(n/4) + n lg n` | `n^0,793` | більше приблизно в `n^0,2` разів | 3 | `Θ(n lg n)` |
| `2T(n/2) + n²` | `n` | більше в `n` разів | 3 | `Θ(n²)` |

Для рядка `2T(n/2) + n lg n` програма поділила точне значення на `n lg² n` і отримала 0,578, 0,535, 0,523, 0,517 для
`n = 2⁸, 2¹⁶, 2²⁴, 2³²`. Відношення повільно наближається до 1/2, тобто відповідь справді `Θ(n lg² n)`.

### Коли теорема мовчить

**Розмір підзадачі зменшується відніманням, а не діленням.** `T(n) = T(n − 1) + n` не має вигляду `aT(n/b) + f(n)`:
тут немає `b > 1`, у скільки разів зменшується задача. Відповідь `Θ(n²)` дає сума, як у методі розгортання. Спроба
вставити таке рівняння в теорему — пастка, про яку попереджає план.

**Рушійна функція потрапляє в щілину між випадками.** CLRS наводить `T(n) = 2T(n/2) + n/lg n`. Вододільна функція `n`,
і `n/lg n` менша за неї, але лише в `lg n` разів, а не в `n^ε`. Перший випадок не годиться, бо різниця не
поліноміальна. Другий теж, бо тут `k = −1`, а потрібно `k ≥ 0`. Відповідь, `Θ(n lg lg n)`, Erickson отримує деревом
рекурсії через гармонічні числа. Програма поділила точне значення на `n lg lg n` і отримала 0,739, 0,720, 0,715, 0,712
— відношення стабілізується.

**Підзадачі різного розміру.** `T(n) = T(n/3) + T(2n/3) + n` теж не має потрібного вигляду. Для таких рівнянь є
загальніший метод Акри–Бацці, про який пишуть і CLRS, і MCS, і Erickson, але він потребує інтегралів, і в плані він не
потрібен. Дерева рекурсії зазвичай досить.

### Версія Erickson

Erickson формулює головну теорему простіше, через порівняння роботи кореня з роботою його нащадків:

- якщо `a·f(n/b) = κ·f(n)` для сталої `κ < 1`, то `T(n) = Θ(f(n))`;
- якщо `a·f(n/b) = K·f(n)` для сталої `K > 1`, то `T(n) = Θ(n^(log_b a))`;
- якщо `a·f(n/b) = f(n)`, то `T(n) = Θ(f(n) · log n)`.

Тобто: порахуйте роботу першого рівня під коренем і порівняйте з роботою кореня. Якщо нащадки разом роблять менше —
переважає корінь, більше — листки, стільки ж — усі рівні однакові. Ця версія вужча за CLRS, бо вимагає точної
рівності, а не асимптотичної, але її легко запам'ятати і вона годиться для більшості рівнянь, де `f(n)` — степінь `n`.

## Метод 4: підстановка

Дерево рекурсії дає здогадку. Довести її можна **методом підстановки**: припустити, що відповідь має вигляд `T(n) ≤
c·g(n)`, підставити це припущення в праву частину рівняння як гіпотезу індукції і перевірити, що ліва частина теж не
більша за `c·g(n)`. Erickson називає вгадування й перевірку індукцією «остаточним методом»: він працює для будь-якого
рівняння, а звідки взялася здогадка, неважливо.

Приклад із CLRS. Доведемо, що `T(n) = 3T(n/4) + cn²` має розв'язок `T(n) ≤ dn²` для достатньо великого `d`:

```
T(n) = 3T(n/4) + cn²
     ≤ 3d(n/4)² + cn²         за гіпотезою індукції для n/4
     = (3/16)dn² + cn²
     ≤ dn²                    якщо d ≥ (16/13)c
```

Остання нерівність рівносильна `cn² ≤ (13/16)dn²`, тобто `d ≥ (16/13)c ≈ 1,23c`. Отже, `T(n) = O(n²)`.

### Пастка: стала, яка росте

Головне правило підстановки: доводити треба **точно те саме** твердження зі **сталою, яка не змінюється**. Ось хибне
«доведення», що `T(n) = 2T(n/2) + n` має розв'язок `O(n)`:

```
T(n) = 2T(n/2) + n
     ≤ 2c(n/2) + n            «за гіпотезою T(n/2) ≤ c·n/2»
     = cn + n
     = O(n)                   ← помилка
```

Помилка в останньому рядку. Треба було довести `T(n) ≤ cn` з тією самою сталою `c`, а отримали `T(n) ≤ (c + 1)n`.
Стала зросла на 1, і на наступному рівні зросте ще на 1. Після `log n` рівнів «стала» стане `c + log n`, а це вже не
стала. Справжня відповідь, як ви знаєте, `Θ(n log n)`. Писати `O(…)` всередині ланцюжка нерівностей у доведенні
підстановкою небезпечно саме тому, що `O` ховає зміну сталої.

MCS показує протилежну пастку в розділі «The Upper Bound Trap». Розв'язок рівняння веж Ханоя — `2ⁿ − 1`. Спроба
довести «простішу» межу `T(n) ≤ 2ⁿ` проваливається: з гіпотези `T(n − 1) ≤ 2ⁿ⁻¹` виходить лише `T(n) ≤ 2ⁿ + 1`. Слабша
межа виявилася важчою для доведення, ніж точна. Як і в день 4, гіпотеза індукції мусить бути досить сильною.

## Відчуття рекурентних співвідношень

MCS завершує главу правилами, які варто тримати в голові, коли бачите рекурсивний алгоритм:

| Рівняння | Розв'язок | Що змінилося порівняно з попереднім |
|----------|-----------|--------------------------------------|
| `T(n) = 2T(n − 1) + 1` | `≈ 2ⁿ` | вежі Ханоя |
| `T(n) = 2T(n − 1) + n` | `≈ 2 · 2ⁿ` | роботи на виклик стало в `n` разів більше, а відповідь лише подвоїлася |
| `T(n) = T(n − 1) + T(n − 2)` | `≈ 1,618ⁿ` | одна підзадача менша на 2, а не на 1, і основа експоненти впала з 2 до 1,618 |
| `T(n) = 3T(n − 1) + 1` | `Θ(3ⁿ)` | третя підзадача підняла основу до 3 |
| `T(n) = 2T(n/2) + n − 1` | `≈ n log n` | підзадачі вдвічі менші, і експонента зникла |

Висновок MCS: швидкість рекурсивного алгоритму визначають **кількість і розмір підзадач**, а не робота одного виклику
і не базовий випадок. Якщо підзадачі менші на сталу (`n − 1`, `n − 2`), розв'язок майже завжди експоненційний. Якщо
підзадачі менші в сталу кількість разів (`n/2`, `n/3`), розв'язок зазвичай обмежений многочленом.

Кількість підзадач теж важить. Для рівняння `T(n) = aT(n/2) + n − 1` MCS показує: при `a < 2` відповідь `Θ(n)`, при `a
= 2` — `Θ(n log n)`, при `a > 2` — `Θ(n^(log₂ a))`. Перехід від `a = 1,99` до `a = 2,01` змінює саму форму відповіді.

## Як це звучить на співбесіді

BCtCI вважає, що головної теореми на співбесідах не питають, і радить метод BAD з учорашньої лекції. На практиці
корисно знати напам'ять кілька рівнянь і відповідей, бо вони покривають більшість задач:

| Рівняння | Відповідь | Де трапляється |
|----------|-----------|----------------|
| `T(n) = T(n/2) + O(n)` | `O(n)` | вибір k-го елемента в середньому |
| `T(n) = 2T(n/2) + O(n)` | `O(n log n)` | сортування злиттям, швидке сортування в середньому |
| `T(n) = T(n − 1) + O(1)` | `O(n)` | рекурсивний прохід списком |
| `T(n) = T(n − 1) + O(n)` | `O(n²)` | швидке сортування в найгіршому випадку, вставки рекурсивно |
| `T(n) = 2T(n − 1) + O(1)` | `O(2ⁿ)` | вежі Ханоя, перебір підмножин |

Ще два рівняння з цього набору, `T(n) = T(n/2) + O(1)` для бінарного пошуку і `T(n) = 2T(n/2) + O(1)` для обходу
збалансованого дерева, — завдання сьогоднішньої практики, тому виведіть їх самі, а не запам'ятовуйте. Коли пояснюєте
відповідь інтерв'юеру, назвіть, скільки підзадач, якого розміру і скільки роботи поза рекурсією. Цих трьох чисел
досить, щоб інтерв'юер побачив ваше міркування.

## Типові хибні уявлення

**«Головна теорема розв'язує будь-яке рекурсивне рівняння».** Лише рівняння вигляду `aT(n/b) + f(n)` з однаковими
підзадачами, які менші в `b > 1` разів, і з `f(n)` не в щілині між випадками. `T(n − 1)`, підзадачі різного розміру і
`n/lg n` вона не бере.

**«`n − 1` і `n/2` — майже те саме, бо обидва менші за `n`».** Перше дає експоненту там, де друге дає многочлен.
Різниця між вежами Ханоя і сортуванням злиттям для 64 елементів — `10¹⁹` проти 321.

**«Більше роботи на виклик — набагато повільніше».** Перехід від `+1` до `+n` у вежах Ханоя лише подвоїв відповідь.
Розмір і кількість підзадач важать більше.

**«Базовий випадок визначає відповідь».** Для рівнянь «поділи на частини» базовий випадок змінює лише сталий множник.
Виняток, який MCS згадує окремо, — рівняння, де без бази все дорівнювало б нулю, як `T(n) = 2T(n/2)` з `T(1) = 0`.

**«Якщо нерівність `T(n) ≤ cn + n` правдива, то `T(n) = O(n)`».** У методі підстановки стала мусить лишатися тією
самою. `cn + n` — це `(c + 1)n`, і доведення розвалюється.

**«Округлення `⌊n/2⌋` і `⌈n/2⌉` змінюють відповідь».** Для рівнянь «поділи на частини» не змінюють, це доводять і
CLRS, і MCS, і Erickson. Тому `n` вважають степенем `b`.

## Перевірте себе

**1. Розв'яжіть головною теоремою `T(n) = 9T(n/3) + n²`.**

<details><summary>Відповідь</summary>

`a = 9`, `b = 3`, `log₃ 9 = 2`, вододільна функція `n²`. Рушійна функція `n²` дорівнює їй, тобто другий випадок з `k =
0`. Відповідь `Θ(n² lg n)`. Дерево рекурсії підтверджує: на глибині `i` лежить `9ⁱ` вузлів по `(n/3ⁱ)²`, тобто кожен
рівень коштує `n²`, а рівнів `log₃ n`.

</details>

**2. Розв'яжіть `T(n) = T(n/2) + n`.**

<details><summary>Відповідь</summary>

`a = 1`, `b = 2`, `log₂ 1 = 0`, вододільна функція `n⁰ = 1`. Рушійна `n` більша в `n¹` разів, і регулярність
виконується: `1 · (n/2) ≤ (1/2) · n`. Третій випадок, `Θ(n)`. Деревом: це шлях `n + n/2 + n/4 + … < 2n`, спадна
прогресія, і переважає корінь.

</details>

**3. Чому головна теорема не розв'язує `T(n) = T(n − 1) + 1`, і яка відповідь?**

<details><summary>Відповідь</summary>

Задача зменшується відніманням одиниці, а не діленням на `b > 1`, тому рівняння не має вигляду `aT(n/b) + f(n)`.
Розгортання дає `T(n) = T(0) + n`, тобто `Θ(n)`.

</details>

**4. Розв'яжіть `T(n) = 8T(n/2) + n²` і поясніть деревом, чому переважають листки.**

<details><summary>Відповідь</summary>

`log₂ 8 = 3`, вододільна функція `n³`, а рушійна `n²` менша в `n` разів. Перший випадок, `Θ(n³)`. На глибині `i`
лежить `8ⁱ` вузлів по `(n/2ⁱ)²`, тобто робота рівня `8ⁱ · n²/4ⁱ = 2ⁱ · n²`. Вона подвоюється з кожним рівнем, і
найбільший член прогресії — останній рівень, листки, яких `n³`.

</details>

**5. Студент «довів», що `T(n) = 2T(n/2) + n` дорівнює `O(n)`, бо `T(n) ≤ 2c(n/2) + n = cn + n = O(n)`. Де помилка?**

<details><summary>Відповідь</summary>

Гіпотеза індукції була `T(k) ≤ ck` з конкретною сталою `c`, і для `n` треба довести `T(n) ≤ cn` з тією самою `c`.
Вийшло `T(n) ≤ (c + 1)n`, тобто стала зросла. Запис `= O(n)` у кінці приховує цю зміну. Справжня відповідь `Θ(n log
n)`.

</details>

**6. Алгоритм ділить задачу на 4 частини вчетверо меншого розміру і робить `n` кроків поза рекурсією. Інший ділить на
5 частин учетверо меншого розміру з тими самими `n` кроками. Наскільки різниться їхній час?**

<details><summary>Відповідь</summary>

Перший: `4T(n/4) + n`, `log₄ 4 = 1`, другий випадок, `Θ(n log n)`. Другий: `5T(n/4) + n`, `log₄ 5 ≈ 1,16`, рушійна
функція `n` поліноміально менша, перший випадок, `Θ(n^1,16)`. Одна додаткова підзадача змінила клас: `n^1,16` росте
швидше за `n log n`. Це правило MCS про кількість підзадач.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| рекурентне співвідношення | рівняння, що описує функцію через її значення на менших аргументах |
| замкнена форма | вираз для функції без самопосилання і без «…» |
| розгортання | підстановка рівняння в саме себе, поки не проступить закономірність |
| дерево рекурсії | дерево, де вузол — підзадача, а значення вузла — її робота без рекурсивних викликів |
| робота рівня | сума значень усіх вузлів однієї глибини |
| геометрична прогресія | послідовність, у якій кожен член у ту саму кількість разів більший чи менший за попередній |
| головна теорема | правило, що розв'язує `T(n) = aT(n/b) + f(n)` порівнянням `f(n)` з `n^(log_b a)` |
| рушійна функція | `f(n)`, робота виклику поза рекурсією |
| вододільна функція | `n^(log_b a)`, кількість листків дерева рекурсії |
| умова регулярності | вимога третього випадку: нащадки разом роблять строго менше, ніж їхній батько |
| метод підстановки | доведення вгаданої відповіді індукцією, де гіпотезу підставляють у праву частину рівняння |
| `lg n` | логарифм за основою 2, як у CLRS |
| `lgᵏ n` | `(lg n)ᵏ`, логарифм у степені `k` |
| гармонічне число `Hₙ` | `1 + 1/2 + … + 1/n`, приблизно `ln n` |
