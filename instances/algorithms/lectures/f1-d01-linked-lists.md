# Лекція. Фаза 1, день 1. Зв'язні списки

Ця лекція пояснює зв'язний список: структуру, у якій елементи лежать не підряд, а кожен знає, де лежить наступний.
Читання займе близько 55 хвилин. Під прикладами коду стоїть справжній вивід з Node 24.22 і Vitest 5.1.

У фазі 0 ви бачили, що масив швидкий, бо лежить у пам'яті суцільно, і що вставка на початок масиву дорога з тієї самої
причини: усі елементи доводиться зсувати. Зв'язний список робить навпаки. Він відмовляється від суцільності, і завдяки
цьому вставка в будь-яке місце, до якого ви вже дійшли, коштує кілька кроків. Сьогодні з'ясуємо, що саме ви за це
платите, і навчимося працювати з посиланнями так, щоб не губити вузли.

**Після лекції ви зможете пояснити:**

- з чого складається зв'язний список і чим однозв'язний відрізняється від двозв'язного;
- які операції в списку коштують сталий час, а які — лінійний, і чому;
- чому порядок присвоєнь посилань важливий і як неправильний порядок губить решту списку;
- навіщо потрібен вузол-сторож і як він прибирає особливі випадки з коду;
- як два вказівники з різною швидкістю знаходять середину списку, цикл і початок циклу;
- чому в JavaScript список рідко швидший за масив, хоча за асимптотикою деякі його операції кращі.

## Стрічка, у якій нове стає першим

Розробник пише стрічку новин: кожна нова подія має з'являтися зверху. Найпростіший код кладе подію на початок масиву
методом `unshift`. Програма нижче порівнює його з однозв'язним списком, який кладе новий вузол перед головою. Сам
список описано в наступному розділі, а тут важливі лише числа. Кожен вимір — медіана п'яти запусків:

```ts
// Вставка n елементів на початок: масив з unshift і список з pushFront.
for (const n of [25_000, 50_000, 100_000, 200_000]) {
  const a = time(() => { const xs: number[] = []; for (let i = 0; i < n; i++) xs.unshift(i); });
  const l = time(() => { const xs = new SinglyLinkedList<number>(); for (let i = 0; i < n; i++) xs.pushFront(i); });
  console.log(`n = ${n}: unshift ${a.toFixed(1)} мс, pushFront ${l.toFixed(2)} мс`);
}
```

```
n = 25000: unshift 43.1 мс, pushFront 0.63 мс
n = 50000: unshift 204.6 мс, pushFront 0.36 мс
n = 100000: unshift 1253.7 мс, pushFront 5.76 мс
n = 200000: unshift 5393.9 мс, pushFront 10.22 мс
```

Коли кількість подій подвоюється, час `unshift` зростає в чотири-шість разів, тобто квадратично. Причина та сама, що з
`shift` у розборі читання дня 7: специфікація ECMA-262 описує `unshift` як зсув кожного наявного елемента на одну
позицію вправо. Вставка з номером `k` зсуває `k` елементів, і разом виходить `0 + 1 + … + (n − 1) = n(n − 1)/2`
зсувів. Список вставляє новий вузол на початок за три присвоєння, хоч би яким довгим він був. Час списку росте
лінійно; дрібні стрибки в його числах дає прибиральник сміття, який час від часу зупиняє програму.

Але за це є ціна. Інша програма поклала мільйон чисел у масив і в список і виміряла пам'ять:

```
масив:  10.4 байта на елемент
список: 40.0 байта на елемент
```

У масиві ціле число займає одну комірку, а надлишок понад 8 байтів — це запас місткості з учорашньої лекції. У списку
кожне число живе в окремому об'єкті-вузлі, і цей об'єкт тримає службові поля рушія, значення і посилання на наступний
вузол. Виходить учетверо більше пам'яті. До того ж у лекції дня 7 ви бачили, що прохід по списку з мільйона вузлів у
2,3 раза повільніший за прохід по масиву, навіть коли вузли створено підряд, і у 82 рази повільніший, коли вузли
розкидано по пам'яті. Тож список не «кращий за масив». Він дешевий для одних операцій і дорогий для інших, і далі ми
розберемо, для яких саме.

## Вузол, голова і хвіст

**Вузол** — це маленький об'єкт із двома полями: значенням і посиланням на наступний вузол. Посилання в останньому
вузлі дорівнює `null`: це означає, що далі вузлів немає. Список зберігає посилання на перший вузол, який називають
**головою** (head). Решту вузлів можна знайти лише одним способом: іти від голови по посиланнях, крок за кроком.

```
 head                                tail
  │                                   │
  ▼                                   ▼
┌───┬───┐    ┌───┬───┐    ┌───┬───┐    ┌───┬──────┐
│ 9 │ ●─┼───►│16 │ ●─┼───►│ 4 │ ●─┼───►│ 1 │ null │
└───┴───┘    └───┴───┘    └───┴───┘    └───┴──────┘
```

Такий список називають **однозв'язним**, бо кожен вузол знає лише наступного сусіда. У **двозв'язному** списку вузол
має ще й поле `prev` з посиланням на попередній вузол. Тоді по списку можна йти в обидва боки, а вузол можна вирізати,
знаючи лише його самого.

Ось однозв'язний список, який зберігає голову, **хвіст** (tail, останній вузол) і кількість вузлів. Хвіст потрібен,
щоб додавати в кінець без проходу через увесь список:

```ts
// Однозв'язний список з головою, хвостом і лічильником розміру.
export class ListNode<T> {
  value: T;
  next: ListNode<T> | null = null;
  constructor(value: T) {
    this.value = value;
  }
}

export class SinglyLinkedList<T> {
  head: ListNode<T> | null = null;
  tail: ListNode<T> | null = null;
  size = 0;

  pushFront(value: T): void {
    const node = new ListNode(value);
    node.next = this.head;          // спершу новий вузол показує на стару голову
    this.head = node;               // і лише потім голова переходить на новий вузол
    if (this.tail === null) this.tail = node;   // особливий випадок: список був порожній
    this.size++;
  }

  pushBack(value: T): void {
    const node = new ListNode(value);
    if (this.tail === null) this.head = node;   // особливий випадок: список був порожній
    else this.tail.next = node;
    this.tail = node;
    this.size++;
  }

  popFront(): T | undefined {
    if (this.head === null) return undefined;   // особливий випадок: порожній список
    const value = this.head.value;
    this.head = this.head.next;
    if (this.head === null) this.tail = null;   // особливий випадок: забрали останній вузол
    this.size--;
    return value;
  }

  // Вузол з номером i: прохід від голови, i кроків.
  at(i: number): ListNode<T> | null {
    let node = this.head;
    for (let k = 0; k < i && node !== null; k++) node = node.next;
    return node;
  }

  toArray(): T[] {
    const out: T[] = [];
    for (let node = this.head; node !== null; node = node.next) out.push(node.value);
    return out;
  }
}
```

Тип `ListNode<T> | null` означає «вузол або нічого». Режим `strict` у TypeScript змушує перевіряти `null` перед тим,
як читати поле: рядок `this.tail.next = node` компілюється лише тому, що гілка `else` виконується тоді, коли
`this.tail` не `null`. Це та сама дисципліна, яку BCtCI радить на співбесіді: перед кожним `.next` питати себе, чи
змінна точно не порожня.

**Чому поле `value` записано окремим рядком.** TypeScript дозволяє скоротити клас до `constructor(public value: T)
{}`. Проте Node 24 запускає файли `.ts`, лише вирізаючи з них типи, а таке скорочення — не тип, а код, який створює
поле. Перша версія цього файлу з таким скороченням впала з помилкою `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX: TypeScript
parameter property is not supported in strip-only mode`. Документація TypeScript перелічує всі такі конструкції в
описі параметра `erasableSyntaxOnly`: з ним компілятор попередить про них ще до запуску.

## Що коштує дешево, а що дорого

Список дешевий там, де ви вже стоїте на потрібному вузлі, і дорогий там, де до вузла треба дійти.

**Дійти до вузла з номером `i`** можна лише проходом від голови: метод `at(i)` робить `i` кроків, тобто `Θ(i)`. У
масиві той самий доступ коштує один крок, бо адресу комірки обчислюють множенням. Двозв'язний список Morin трохи
кращий: він іде від ближчого кінця, тож робить `min(i, n − i)` кроків. Для вузла посередині це все одно `n/2`.

**Вставити вузол після вузла, який у вас уже є,** — два присвоєння, сталий час. Вставити перед ним в однозв'язному
списку так само дешево не вийде, бо вузол не знає свого попередника.

**Видалити вузол.** У двозв'язному списку вузол знає обох сусідів, тож досить, щоб сусіди показували один на одного в
обхід нього: сталий час. В однозв'язному списку треба змінити поле `next` попередника, а попередника можна знайти лише
проходом від голови. Тому видалення за посиланням на вузол коштує `Θ(n)`. Саме це просить довести вправа 10.2-1 CLRS.
З тієї самої причини однозв'язний список не вміє швидко видаляти з кінця: хвіст відомий, але щоб зробити хвостом
передостанній вузол, його треба знайти.

| Операція | Масив | Однозв'язний список з хвостом | Двозв'язний список |
|----------|-------|-------------------------------|--------------------|
| доступ за номером `i` | `O(1)` | `Θ(i)` | `Θ(min(i, n − i))` |
| вставка на початок | `Θ(n)` | `O(1)` | `O(1)` |
| вставка в кінець | `O(1)` амортизовано | `O(1)` | `O(1)` |
| видалення з початку | `Θ(n)` | `O(1)` | `O(1)` |
| видалення з кінця | `O(1)` | `Θ(n)` | `O(1)` |
| вставка після відомого вузла | `Θ(n)` | `O(1)` | `O(1)` |
| видалення відомого вузла | `Θ(n)` | `Θ(n)` | `O(1)` |
| пошук значення | `Θ(n)` | `Θ(n)` | `Θ(n)` |

Слова «відомого вузла» тут головні. Майже кожне «`O(1)`» у стовпцях списків передбачає, що посилання на потрібний
вузол у вас уже є. Якщо ж вузол треба спершу знайти за значенням чи номером, до сталої вартості додається лінійний
пошук. Тому список виграє в задачах, де посилання на вузли зберігаються окремо: наприклад, хеш-таблиця тримає
посилання на вузли, а список тримає їхній порядок. Так влаштований кеш LRU, до якого план дійде у фазі 5.

## Порядок присвоєнь

Вставимо вузол зі значенням 4 після першого вузла списку `1 → 2 → 3`. Треба змінити два посилання: новий вузол має
показувати на вузол 2, а вузол 1 — на новий вузол. Програма робить це у двох порядках:

```ts
// Вставка вузла 4 після першого вузла списку 1 → 2 → 3: правильний і неправильний порядок присвоєнь.
const a = new ListNode(4);
a.next = good.head!.next;     // 1) новий вузол показує на 2
good.head!.next = a;          // 2) вузол 1 показує на новий
console.log("правильно:  ", firstValues(good, 6).join(" → "));

const b = new ListNode(4);
bad.head!.next = b;           // 1) вузол 1 показує на новий — посилання на 2 втрачено
b.next = bad.head!.next;      // 2) новий показує... сам на себе
console.log("неправильно:", firstValues(bad, 6).join(" → "), "…");
```

```
правильно:   1 → 4 → 2 → 3
неправильно: 1 → 4 → 4 → 4 → 4 → 4 …
```

Знак `!` після `good.head` каже компілятору: «я знаю, що тут не `null`». Перевірки під час виконання він не додає.
Функція `firstValues` бере не більше шести значень від голови, і зараз стане зрозуміло, навіщо це обмеження.

У неправильному порядку перше присвоєння перезаписує єдине посилання на вузол 2. Після нього вузли 2 і 3 недосяжні:
жодна змінна і жоден вузол на них не показують, і прибиральник сміття згодом їх звільнить. Друге присвоєння читає
`bad.head.next`, але там уже лежить сам новий вузол, тож вузол 4 починає показувати на себе. Список замкнувся в
**цикл**. Перша версія програми друкувала неправильний список методом `toArray`, і той не зупинився: він 5,8 секунди
додавав четвірки в масив, з'їв майже 3 ГБ пам'яті і впав з `RangeError: Invalid array length`, коли масив перевищив
найбільшу дозволену довжину.

Правило, яке з цього випливає: **перш ніж перезаписати посилання, переконайтеся, що вузол, на який воно показує,
досяжний іншим шляхом**. Найчастіше для цього досить спершу заповнити поля нового вузла, а потім змінювати старі. Або
запам'ятати потрібний вузол у локальній змінній.

Те саме правило керує розворотом списку на місці, який ви напишете в практиці. Розворот іде від голови, і в кожен
момент список поділено на дві частини: уже розвернуту, на голову якої показує `prev`, і ще не розвернуту, на голову
якої показує `cur`. Щоб перевернути посилання вузла `cur`, доведеться перезаписати `cur.next`, а це єдиний шлях до
решти нерозвернутої частини. Тому спершу її треба зберегти. Перевірити розворот варто трьома способами: на порожньому
списку, на списку з одного вузла і на списку з трьох вузлів, малюючи стан `prev` і `cur` після кожного кроку.

## Особливі випадки і вузол-сторож

Порахуйте в класі `SinglyLinkedList` рядки з коментарем «особливий випадок»: їх чотири на три короткі методи. Кожен
такий рядок — місце для помилки. Тест нижче перевіряє, що список працює після того, як його спорожнили:

```ts
import { describe, expect, it } from "vitest";
import { SinglyLinkedList } from "./slist.ts";

describe("SinglyLinkedList", () => {
  it("після спорожнення список знову працює", () => {
    const xs = new SinglyLinkedList<string>();
    xs.pushBack("a");
    expect(xs.popFront()).toBe("a");     // список знову порожній
    xs.pushBack("b");
    xs.pushBack("c");
    expect(xs.toArray()).toEqual(["b", "c"]);
    expect(xs.size).toBe(2);
  });
});
```

З повним класом тест проходить. А тепер приберемо з `popFront` рядок `if (this.head === null) this.tail = null`:

```
 FAIL  src/f1d1/slist.test.ts > SinglyLinkedList > після спорожнення список знову працює
AssertionError: expected [] to deeply equal [ 'b', 'c' ]

- Expected
+ Received

- [
-   "b",
-   "c",
- ]
+ []
```

Після `popFront` голова стала `null`, а хвіст лишився показувати на вже вилучений вузол `a`. Тому `pushBack("b")`
бачить непорожній хвіст і прикріплює `b` до вилученого вузла, а голову не чіпає. Список здається порожнім, хоча `size`
дорівнює 2. Помилка тиха: програма не падає, вона просто губить дані.

**Вузол-сторож** (sentinel, у Morin — dummy) прибирає такі випадки. Це додатковий вузол без значення, який завжди є в
списку. У двозв'язному списку його замикають у коло: поле `next` сторожа показує на перший справжній вузол, поле
`prev` — на останній, а перший і останній вузли показують назад на сторожа. Порожній список складається з одного
сторожа, який показує сам на себе в обидва боки:

```
порожній список:               список a, b, c:

   ┌──────────┐                  ┌───────────────────────────────────────┐
   ▼          │                  ▼                                       │
 [сторож] ────┘                [сторож] ⇄ [a] ⇄ [b] ⇄ [c] ⇄ (знову сторож)┘
 next = prev = сам сторож      next сторожа = a, prev сторожа = c
```

Тепер у кожного справжнього вузла завжди є і попередник, і наступник, жоден із них не `null`. Голова списку — це
`sentinel.next`, хвіст — `sentinel.prev`. Вставка на початок стає вставкою після сторожа, вставка в кінець — вставкою
перед сторожем, і обидві виконує та сама процедура «вставити після вузла». Видалення будь-якого вузла теж пишеться
однаково, бо сусіди є завжди. CLRS показує, що процедура видалення зі сторожем займає два рядки, а без нього — п'ять,
з двома перевірками на `NIL`.

Ціна сторожа — один зайвий вузол на кожен список. CLRS попереджає, що коли програма тримає тисячі крихітних списків,
ця пам'ять стає помітною, і радить ставити сторожа лише там, де він справді спрощує код.

CLRS показує ще один прийом зі сторожем. Звичайний пошук значення робить у кожному кроці дві перевірки: чи не дійшли
ми до кінця і чи не знайшли значення. Якщо перед пошуком записати шукане значення у сам сторож, пошук гарантовано
зупиниться, і перевірка кінця стає непотрібною. Наприкінці лишається з'ясувати одне: зупинилися ми на справжньому
вузлі чи на сторожі. Асимптотика не змінюється, але кожен крок стає дешевшим.

## Два вказівники з різною швидкістю

Деякі задачі про списки розв'язуються двома вказівниками, що йдуть від голови з різною швидкістю: повільний робить
один крок, швидкий — два.

**Середина списку.** Коли швидкий вказівник доходить до кінця, повільний пройшов рівно половину шляху і стоїть
посередині. Для списку `10 → 20 → 30 → 40 → 50` повільний проходить 10, 20, 30, а швидкий — 10, 30, 50. Швидкому далі
йти нікуди, і повільний стоїть на 30. Знадобився один прохід, і довжину списку рахувати не довелося.

**Цикл.** Ви вже бачили, як помилка в порядку присвоєнь замикає список у коло. Для такого списку звичайний прохід до
`null` ніколи не закінчиться. Простий спосіб помітити цикл — складати відвідані вузли в `Set` і зупинитися, коли вузол
трапився вдруге. Це працює, але потребує пам'яті на кожен вузол. **Алгоритм Флойда** (його ще називають «черепаха і
заєць») обходиться двома змінними. Якщо циклу немає, швидкий вказівник дійде до `null`. Якщо цикл є, обидва вказівники
врешті потраплять у нього, і там швидкий наздожене повільного.

Розберемо приклад. Список має вузли з номерами від 0 до 7. Від вузла 0 до вузла 3 веде «хвіст» з трьох кроків, а вузли
3, 4, 5, 6, 7 утворюють коло: вузол 7 показує назад на вузол 3. Позначимо довжину хвоста `a = 3`, довжину кола `L =
5`.

```
0 → 1 → 2 → 3 → 4 → 5
            ↑       ↓
            7   ←   6
```

| Крок | Повільний | Швидкий | Скільки кроків швидкому до повільного по колу |
|------|-----------|---------|-----------------------------------------------|
| 0 | 0 | 0 | обидва ще не в колі |
| 1 | 1 | 2 | повільний ще не в колі |
| 2 | 2 | 4 | повільний ще не в колі |
| 3 | 3 | 6 | 2 (6 → 7 → 3) |
| 4 | 4 | 3 | 1 (3 → 4) |
| 5 | 5 | 5 | 0, зустрілися |

Чому зустріч неминуча: коли обидва в колі, кожен крок швидкий підходить до повільного на 1, бо робить на один крок
більше. Відстань між ними по колу менша за `L`, отже, вона дійде до нуля не пізніше ніж за `L` кроків. Перестрибнути
повільного швидкий не може: щоб перестрибнути, відстань мала б зменшитися на 2 за раз. Повільний входить у коло за `a`
кроків, тож зустріч настає менш ніж за `a + L` кроків. Перевірка всіма довжинами хвоста й кола до 30 це підтвердила.

**Початок циклу.** Найдивовижніша частина алгоритму: після зустрічі поставте один вказівник на голову, другий лиште в
точці зустрічі і рухайте обидва по одному кроку. Вони зустрінуться саме на першому вузлі кола. У прикладі: перший іде
0, 1, 2, 3, другий іде з точки зустрічі 5, 6, 7, 3. Через `a = 3` кроки обидва на вузлі 3.

Чому так. Нехай точка зустрічі лежить на `b` кроків після початку кола; у прикладі `b = 2`, від вузла 3 до вузла 5.
Повільний пройшов до зустрічі `a + b` кроків. Швидкий пройшов удвічі більше, `2(a + b)`, але він стоїть у тій самій
точці, тобто пройшов той самий шлях плюс кілька повних кіл: `2(a + b) = a + b + kL`. Звідси `a + b = kL`, тобто `a =
kL − b`. У прикладі `3 = 1 · 5 − 2`. Вказівник, що стоїть за `b` кроків після початку кола і робить ще `a = kL − b`
кроків, проходить `k` повних кіл без останніх `b` кроків, тобто зупиняється рівно на початку кола. А вказівник з
голови за ті самі `a` кроків теж доходить до початку кола. Тому вони там і зустрічаються.

Код алгоритму ви напишете в практиці. Перевіряйте його на списках, де циклу немає, де вузол показує сам на себе (`a =
0`, `L = 1`) і де весь список — одне коло (`a = 0`).

## Списки в мовах

У стандартній бібліотеці JavaScript зв'язного списку немає. Масив покриває більшість потреб, а там, де потрібна швидка
вставка за посиланням, список пишуть самі. Go має пакет `container/list`, і його документація описує тип `List` як
двозв'язний список, нульове значення якого вже готове до роботи. Python має `collections.deque`. Документація Python
пише, що доступ за номером у ньому коштує `O(1)` на кінцях і сповільнюється до `O(n)` посередині, і радить для
швидкого доступу за номером звичайний список. Python-список, попри назву, — це динамічний масив з учорашньої лекції, а
не зв'язний список.

## Для співбесіди

| Питання | Коротка відповідь |
|---------|-------------------|
| Коли список кращий за масив? | Коли треба часто вставляти й видаляти вузли, посилання на які вже є, особливо на початку чи посередині. Доступ за номером і прохід у масиві швидші. |
| Чому видалення з кінця однозв'язного списку `Θ(n)`, хоча хвіст відомий? | Новим хвостом стає передостанній вузол, а знайти його можна лише проходом від голови. |
| Навіщо вузол-сторож? | Щоб у кожного справжнього вузла завжди були сусіди і код не мав окремих гілок для порожнього списку, голови і хвоста. |
| Як знайти середину за один прохід? | Два вказівники: повільний на крок, швидкий на два. Коли швидкий дійшов до кінця, повільний посередині. |
| Як виявити цикл за `O(1)` пам'яті? | Алгоритм Флойда: швидкий і повільний вказівники зустрінуться, якщо цикл є, і швидкий дійде до `null`, якщо немає. |
| Яка пам'ять у рекурсивного проходу списку? | `O(n)` на стек викликів. BCtCI радить для списків ітеративний прохід з `O(1)` пам'яті. |

## Типові помилки

**«Вставка в список коштує `O(1)`».** Лише якщо посилання на місце вставки вже є. Вставка на позицію з номером `i` —
це спершу прохід на `i` кроків, тобто `Θ(i)`.

**Перезаписати посилання до того, як збережено вузол, на який воно показує.** Ви бачили наслідок: решта списку
недосяжна, а список може замкнутися в коло.

**Забути про хвіст.** Коли видаляють останній вузол, `tail` теж треба оновити. Тест «спорожнити і знову додати» ловить
цю помилку одразу.

**Звертатися до `.next.next` без перевірки.** Якщо `node.next` дорівнює `null`, то `node.next.next` кидає `TypeError`.
Режим `strict` у TypeScript підсвітить таке місце, якщо не глушити його знаком `!`.

**Вважати, що список у JavaScript швидший за масив для всього, де «вставка дешева».** Вимір показав учетверо більше
пам'яті на елемент, а лекція дня 7 — повільніший прохід. Список виграє лише там, де масив робить зсуви.

## Практика

Працюйте в тому самому проєкті, що й у фазі 0. Відповіді в лекції немає: прийоми показано на однозв'язному списку і на
середині списку, а завдання стосуються двозв'язного списку зі сторожем, розвороту і циклів.

**1. `DoublyLinkedList<T>` із вузлом-сторожем.** Методи `pushFront`, `pushBack`, `remove(node)` і `toArray`. Методи
`pushFront` і `pushBack` повертають створений вузол, щоб потім його можна було видалити. Перш ніж писати код,
намалюйте порожній список і список з одного вузла і випишіть, на що показують усі поля `prev` і `next`. Мета: жоден
метод не має окремої гілки для порожнього списку. Якщо гілка з'являється, подумайте, яку вставку можна виразити через
«вставити після вузла».

**2. Розворот однозв'язного списку на місці.** Функція отримує голову і повертає нову голову, нових вузлів не створює.
До запуску випишіть на папері стан `prev` і `cur` після кожного кроку для списку `1 → 2 → 3`.

**3. Пошук циклу.** Функція `hasCycle(head)` за алгоритмом Флойда, а потім `cycleStart(head)`, що повертає перший
вузол циклу або `null`. Для тестів напишіть допоміжну функцію, яка будує список з хвостом довжини `a` і колом довжини
`L`.

**4. Тести.** Порожній список, один вузол, видалення першого, останнього і єдиного вузла. Для розвороту — порожній
список, один вузол, три вузли. Для циклу — без циклу, вузол, що показує сам на себе, і список, що весь є колом.

**5. Вимір.** Перед запуском передбачте, у скільки разів зміниться час, коли `n` подвоюється. Потім повторіть вимір
`unshift` проти `pushFront` для свого двозв'язного списку і запишіть числа в `MEASUREMENTS.md`.

**6. Журнал.** Один рядок у `JOURNAL.md`: що стало зрозумілим і що ні.

## Перевірте себе

**1. Однозв'язний список має голову і хвіст. Які з операцій «додати в кінець», «видалити з кінця», «видалити з
початку» коштують сталий час?**

<details><summary>Відповідь</summary>

Додати в кінець і видалити з початку. Додавання в кінець змінює `tail.next` і `tail`. Видалення з початку переносить
голову на наступний вузол. Видалення з кінця вимагає зробити хвостом передостанній вузол, а його можна знайти лише
проходом від голови, тож воно коштує `Θ(n)`.

</details>

**2. Що надрукує програма і чому?**

```ts
const xs = new SinglyLinkedList<number>();
xs.pushBack(1);
xs.pushBack(2);
const second = xs.at(1)!;
xs.head!.next = null;
console.log(xs.toArray(), second.value);
```

<details><summary>Відповідь</summary>

Вона надрукує `[ 1 ] 2`. Присвоєння `xs.head.next = null` відрізало вузол 2 від списку, тому `toArray` бачить лише
вузол 1. Сам вузол 2 не зник, бо на нього досі показує змінна `second`, і його значення читається. Проте список тепер
суперечливий: `tail` усе ще показує на вузол 2, а `size` дорівнює 2.

</details>

**3. Навіщо в двозв'язному списку зі сторожем потрібне коло, а не просто сторож на початку?**

<details><summary>Відповідь</summary>

Сторож на початку прибирає особливий випадок лише для голови. Останній вузол мав би `next = null`, і видалення
останнього вузла чи вставка в кінець усе ще потребували б перевірок. Коли `prev` сторожа показує на останній вузол, а
`next` останнього — на сторожа, кожен справжній вузол має обох сусідів. Тоді вставка й видалення пишуться однаково для
будь-якого місця.

</details>

**4. У списку хвіст до кола має довжину 2, а коло — довжину 3. Через скільки кроків зустрінуться вказівники Флойда, і
скільки кроків займе друга фаза?**

<details><summary>Відповідь</summary>

Пронумеруємо вузли 0, 1, 2, 3, 4, де вузол 4 показує на вузол 2. Після кроку 1 повільний на 1, швидкий на 2. Після
кроку 2 повільний на 2, швидкий на 4. Після кроку 3 повільний на 3, швидкий на 3: зустріч на третьому кроці, `b = 1`.
Друга фаза займає `a = 2` кроки: перший вказівник іде 0 → 1 → 2, другий іде 3 → 4 → 2. Перевірка формулою: `a = kL − b
= 3 − 1 = 2`.

</details>

**5. Нехай швидкий вказівник робить три кроки замість двох. Чи знайде перша фаза цикл? А чи знайде друга фаза його
початок?**

<details><summary>Відповідь</summary>

Перша фаза знайде. Після `t` кроків повільний пройшов `t` вузлів, а швидкий `3t`, тобто на `2t` більше. Візьміть `t`,
кратне `L` і не менше за `a`: обидва вказівники вже в колі, а різниця `2t` — ціла кількість кіл, тож вони стоять на
одному вузлі. Отже, зустріч настане, хоча, можливо, не в тій точці, що з кроком 2.

Друга фаза може не спрацювати. Її доказ спирався на те, що швидкий пройшов рівно вдвічі більше: `2(a + b) = a + b +
kL`. З кроком 3 виходить `3(a + b) = a + b + kL`, тобто `2(a + b) = kL`, і `a` вже не обов'язково дорівнює цілій
кількості кіл без `b` кроків. Приклад: хвіст `a = 2`, коло `L = 4`, вузли від 0 до 5, вузол 5 показує на вузол 2.
Вказівники зустрічаються на вузлі 2 після другого кроку. Друга фаза ставить перший вказівник на вузол 0, а другий
лишає на вузлі 2. Через два кроки перший приходить на вузол 2, а другий уже пішов на вузол 4, і далі вони кружляють
колом, не зустрічаючись.

</details>

**6. Видалити вузол однозв'язного списку, маючи посилання лише на нього, — `Θ(n)`. Є відомий трюк: скопіювати в нього
значення наступного вузла і видалити наступний. Коли трюк не працює і чим він небезпечний?**

<details><summary>Відповідь</summary>

Трюк не працює для останнього вузла: наступного немає, і копіювати нічого. Небезпечний він тому, що змінює не той
вузол, який просили видалити. Якщо інша частина програми тримає посилання на наступний вузол, після трюку це посилання
показує на вузол, якого в списку вже немає, а значення, яке вона там шукала, переїхало в інший об'єкт. Так само
ламається хвіст: якщо видалили передостанній вузол, `tail` треба переставити.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| вузол | об'єкт зі значенням і посиланням на сусіда чи сусідів |
| зв'язний список | послідовність вузлів, у якій порядок задають посилання, а не розміщення в пам'яті |
| однозв'язний список | кожен вузол знає лише наступний вузол |
| двозв'язний список | кожен вузол знає і наступний, і попередній вузол |
| голова | перший вузол списку |
| хвіст | останній вузол списку |
| вузол-сторож, dummy, sentinel | додатковий вузол без значення, що завжди є в списку і прибирає особливі випадки |
| кільцевий список | список, у якому останній вузол показує на перший |
| цикл у списку | ситуація, коли прохід за посиланнями повертається до вже відвіданого вузла і ніколи не доходить до `null` |
| алгоритм Флойда, «черепаха і заєць» | пошук циклу двома вказівниками, що рухаються з різною швидкістю |
| недосяжний вузол | вузол, на який не показує жодна змінна і жоден інший вузол |
| `!` у TypeScript | твердження для компілятора, що значення не `null` і не `undefined`; перевірки під час виконання не додає |
