# Лекція. Фаза 1, день 8. Швидке сортування

Ця лекція пояснює quicksort: сортування, яке розбиває масив навколо опорного елемента і обходиться без допоміжного
масиву. Читання займе близько 50 хвилин. Під прикладами коду стоїть справжній вивід з Node 24.22.

Учора сортування злиттям гарантувало `n log n` порівнянь, але платило за це допоміжним масивом. Сьогодні з'ясуємо, як
quicksort переносить усю роботу з кроку «поєднати» на крок «розділити», чому зазвичай він швидкий, і чому на
відсортованому масиві він раптом стає квадратичним.

**Після лекції ви зможете пояснити:**

- як quicksort застосовує «розділяй і володарюй» і чому йому не потрібне злиття;
- що таке розбиття навколо опорного елемента і який інваріант воно тримає;
- чим розбиття Ломуто відрізняється від розбиття Гоара;
- чому quicksort робить у середньому близько `1,39 n log₂ n` порівнянь, а в найгіршому — `n²/2`;
- чому відсортований масив з опорним першим елементом — найгірший вхід і чим це загрожує стеку викликів;
- де розбиття трапляється поза сортуванням.

## Розділяй і володарюй навпаки

Erickson пише, що quicksort придумав Тоні Гоар у 1959 році, а опублікував у 1961-му. Як і сортування злиттям, це
«розділяй і володарюй», але робота розподілена навпаки:

| Крок | Сортування злиттям | Quicksort |
|------|--------------------|-----------|
| розділити | тривіально: навпіл | уся робота: розбиття навколо опорного елемента |
| володарювати | дві рекурсії | дві рекурсії |
| поєднати | уся робота: злиття | нічого |

CLRS описує три кроки так. **Розділити**: переставити елементи ділянки так, щоб ліворуч від опорного елемента (pivot)
стояли не більші за нього, а праворуч — не менші. Опорний елемент стає на своє остаточне місце. **Володарювати**:
відсортувати рекурсивно ліву і праву частини. **Поєднати**: нічого робити не треба, бо кожен елемент лівої частини вже
не більший за кожен елемент правої.

Erickson показує це на тих самих літерах, що й для злиття:

```
вхід:            S O R T I N G E X A M P L
опорний — P:     S O R T I N G E X A M P L
розбиття:        A G O E I N L M   P   T X S R
ліва частина:    A E G I L M N O   P   T X S R
права частина:   A E G I L M N O   P   R S T X
```

Bhargava пояснює те саме на маленьких масивах і доводить правильність індукцією: масиви з 0 і 1 елемента вже
відсортовані; якщо quicksort правильно сортує всі масиви, коротші за `n`, то після розбиття обидві частини коротші за
`n`, тож рекурсія сортує їх правильно, а разом з опорним елементом посередині виходить відсортований масив.

## Розбиття

Розбиття — найважливіша частина quicksort і корисна операція сама по собі. Вона переставляє масив так, щоб спершу йшли
всі елементи з певною властивістю, а потім усі інші, за один прохід і без допоміжного масиву.

Ось розбиття за довільною умовою двома вказівниками, що йдуть назустріч. Лівий шукає елемент, якому місце праворуч,
правий — елемент, якому місце ліворуч, і вони міняються місцями:

```ts
// Розбиття за умовою двома вказівниками назустріч: спершу елементи, для яких pred правдивий.
// Повертає межу: pred правдивий на [0, межа) і хибний на [межа, n). Порядок усередині частин не зберігається.
export function partitionBy<T>(xs: T[], pred: (x: T) => boolean): number {
  let i = 0, j = xs.length - 1;
  while (true) {
    while (i <= j && pred(xs[i]!)) i++;        // ліворуч лишаємо ті, що вже на місці
    while (i <= j && !pred(xs[j]!)) j--;       // праворуч — так само
    if (i >= j) return i;
    [xs[i], xs[j]] = [xs[j]!, xs[i]!];          // xs[i] має бути праворуч, xs[j] — ліворуч: міняємо
    i++; j--;
  }
}

type Task = { title: string; overdue: boolean };
const tasks: Task[] = [
  { title: "звіт", overdue: false }, { title: "лист", overdue: true }, { title: "код", overdue: false },
  { title: "дзвінок", overdue: true }, { title: "тест", overdue: true }, { title: "реліз", overdue: false },
];
const border = partitionBy(tasks, (t) => t.overdue);
console.log(`прострочених ${border}:`, tasks.map((t) => (t.overdue ? "!" : "") + t.title).join(", "));

const nums = [7, 2, 9, 4, 1, 8, 3, 6, 5];
const b = partitionBy(nums, (x) => x < 5);
console.log(`менших за 5: ${b}; масив: ${nums.join(" ")}`);
```

```
прострочених 3: !тест, !лист, !дзвінок, код, звіт, реліз
менших за 5: 4; масив: 3 2 1 4 9 8 7 6 5
```

Прострочені завдання опинилися попереду, решта — позаду, і на це пішов один прохід. Порядок усередині частин змінився:
«тест» стрибнув на початок, бо помінявся місцями зі «звітом». Розбиття двома вказівниками не стабільне, і quicksort,
що на ньому стоїть, теж нестабільний.

Інваріант цього циклу легко записати: усе ліворуч від `i` задовольняє умову, усе праворуч від `j` — ні. Кожен прохід
або просуває `i`, або зсуває `j`, або міняє пару і робить обидва, тож ділянка між ними зменшується, і цикл
закінчується.

Розбиття знадобиться не лише в сортуванні: у день 12 воно знаходитиме `k`-тий елемент без повного сортування, а у фазі
4 стане одним з прийомів двох вказівників.

### Ломуто і Гоар

Для quicksort умова розбиття — «менший за опорний елемент». Книжки дають два способи.

**Розбиття Ломуто** — те, що в CLRS і Erickson. Обидві книжки беруть опорним останній елемент. Один вказівник `j` іде
зліва направо через усю ділянку, а другий, `i`, позначає кінець «малої» частини. Коли `j` знаходить елемент, не
більший за опорний, `i` збільшується, і елементи `i` та `j` міняються місцями. Наприкінці опорний елемент стає одразу
за малою частиною. CLRS записує інваріант трьома областями:

```
 p          i                j                r
 [ ≤ x ... ≤ x ][ > x ... > x ][ ще не бачені ... ][ x ]
```

- позиції від `p` до `i` містять елементи, не більші за опорний `x`;
- позиції від `i + 1` до `j − 1` містять елементи, більші за `x`;
- позиція `r` містить сам `x`.

Цикл робить рівно `n − 1` порівнянь для ділянки з `n` елементів, по одному на кожен елемент, крім опорного.

**Розбиття Гоара** — оригінальне, двома вказівниками назустріч, як `partitionBy` вище. Воно робить менше обмінів, бо
міняє лише ті пари, де обидва елементи стоять не на своєму боці, а Ломуто міняє кожен малий елемент, навіть якщо той
уже на місці. Erickson попереджає про ціну: розбиття Гоара — «one of the places off-by-one errors go to die».
Sedgewick показує, як не дати вказівникам вийти за межі масиву, коли опорний елемент найменший чи найбільший.

У практиці дня ви напишете розбиття Ломуто з опорним **першим** елементом, а не останнім, тож формули CLRS доведеться
дзеркально переробити.

## Скільки порівнянь

Нехай опорний елемент після розбиття стає на місце `r` серед `n` елементів. Тоді ліва частина має `r − 1` елемент,
права — `n − r`, і кількість порівнянь

```
C(n) = (n − 1) + C(r − 1) + C(n − r).
```

Усе залежить від того, де опиниться опорний елемент. Програма нижче рахує три випадки за формулами, нічого не
сортуючи:

```ts
// Кількість порівнянь quicksort з розбиттям Ломуто (n − 1 порівняння на розбиття ділянки з n елементів):
// найгірший випадок, середній для випадкового порядку і найкращий, коли опорний щоразу посередині.
function harmonic(n: number): number { let h = 0; for (let k = 1; k <= n; k++) h += 1 / k; return h; }
const best = new Map<number, number>();
function B(n: number): number {
  if (n <= 1) return 0;
  if (!best.has(n)) best.set(n, n - 1 + B(Math.floor((n - 1) / 2)) + B(Math.ceil((n - 1) / 2)));
  return best.get(n)!;
}
for (const n of [500, 1000, 2000, 4000]) {
  const worst = n * (n - 1) / 2;
  const avg = 2 * (n + 1) * harmonic(n) - 4 * n;            // точне середнє для випадкової перестановки
  console.log(`n = ${String(n).padStart(4)}: найкращий ${String(B(n)).padStart(6)}, середній ${avg.toFixed(0).padStart(6)},` +
    ` найгірший ${String(worst).padStart(8)}; 1.39·n·log₂n = ${(1.39 * n * Math.log2(n)).toFixed(0)}`);
}
```

```
n =  500: найкращий   3498, середній   4806, найгірший   124750; 1.39·n·log₂n = 6231
n = 1000: найкращий   7987, середній  10986, найгірший   499500; 1.39·n·log₂n = 13852
n = 2000: найкращий  17964, середній  24730, найгірший  1999000; 1.39·n·log₂n = 30485
n = 4000: найкращий  39917, середній  54989, найгірший  7998000; 1.39·n·log₂n = 66530
```

**Найгірший випадок.** Якщо опорний елемент щоразу найменший чи найбільший, одна частина порожня, а друга має `n − 1`
елемент. Тоді `C(n) = (n − 1) + C(n − 1)`, і разом `(n − 1) + (n − 2) + … + 1 = n(n − 1)/2`: для 2000 елементів майже
два мільйони, як у сортування вибором. CLRS підкреслює іронію: так стається саме тоді, коли масив уже відсортований, а
сортування вставками на ньому лінійне.

**Найкращий випадок.** Якщо опорний елемент щоразу медіана, частини рівні, і `C(n) ≈ 2C(n/2) + n` — та сама рекурсія,
що в сортування злиттям, з розв'язком `n log₂ n`.

**Середній випадок.** Якщо всі порядки вхідного масиву однаково ймовірні, середня кількість порівнянь дорівнює `2(n +
1)Hₙ − 4n`, де `Hₙ = 1 + 1/2 + … + 1/n ≈ ln n` — гармонічне число. Головний член — `2n ln n ≈ 1,39 n log₂ n`.
Sedgewick формулює це як твердження K і зауважує, що середнє лише на 39 % більше за найкращий випадок. Останній
стовпець показує, що головний член для таких `n` ще помітно більший за точне значення: формула має від'ємний доданок
`−4n`, який на малих `n` важить.

**Чому середній ближчий до найкращого.** CLRS пояснює це розбиттям у пропорції 9 до 1. Здавалося б, воно дуже
незбалансоване, але дерево рекурсії все одно має глибину `log_{10/9} n = Θ(log n)`, а кожен рівень коштує не більше
`n`. Тож навіть такі розбиття дають `O(n log n)`, лише з більшою сталою. Те саме для пропорції 99 до 1. Погане
розбиття шкодить лише тоді, коли воно погане **щоразу**. На випадковому вході гарні й погані розбиття чергуються, і
погане розбиття, за яким іде гарне, коштує не більше за одне гарне, помножене на сталу.

## Найгірший вхід — найзвичайніший

З опорним першим елементом відсортований масив дає найгірший випадок: перший елемент найменший, усе інше йде праворуч,
і так на кожному рівні. Те саме із зворотним масивом. Erickson зауважує, що евристика «медіана з трьох» (взяти медіану
першого, середнього й останнього елементів) рятує на відсортованих масивах, але можна побудувати вхід, де вона щоразу
вибирає другий найменший елемент, і час знову квадратичний.

Квадратичний час — не єдина біда. CLRS звертає увагу на пам'ять: quicksort сортує на місці, але кожен рекурсивний
виклик займає місце на стеку, і в найгіршому випадку глибина рекурсії — `n`. У лекції дня 5 фази 0 стек Node 24
витримав близько 9765 вкладених викликів простої функції. Отже, quicksort з опорним першим елементом на відсортованому
масиві з кількох десятків тисяч елементів не просто працюватиме повільно, а впаде з `RangeError: Maximum call stack
size exceeded`. Sedgewick формулює це в твердженні L: «not only that the time required will be quadratic but also that
the space required to handle the recursion will be linear».

Два виправлення розбирає наступний день. Перше — **випадковий опорний елемент** або, як у Sedgewick, перемішування
масиву перед сортуванням: тоді жоден конкретний вхід не буде поганим, лише невдале везіння. Друге — рекурсія лише в
меншу частину, а більша обробляється циклом: тоді глибина не більша за `log₂ n`, хоч би якими були розбиття.

**Однакові ключі.** Вправа 7.2-2 CLRS питає, що буде, якщо всі елементи однакові. Розбиття Ломуто відправляє їх усі в
ліву частину, бо умова `≤ x` правдива для кожного, і quicksort знову квадратичний. Виправлення — розбиття на три
частини, теж у дні 9.

## Покращення Sedgewick

Sedgewick називає quicksort «fragile»: у ньому легко помилитися так, що він стане квадратичним, і в літературі описано
багато таких випадків. Тому до базового алгоритму додають:

- **Перемикання на вставки** для коротких ділянок, від 5 до 15 елементів, як у сортуванні злиттям учора. Sedgewick
  повідомляє, що такі покращення разом дають 20–30 % виграшу.
- **Медіану з трьох** як опорний елемент.
- **Розбиття на три частини** (Dijkstra, задача голландського прапора): менші, рівні й більші за опорний. Тоді
  однакові ключі не сортуються повторно.

Сучасні бібліотеки йдуть далі. Документація Go 1.19 повідомляє, що пакет `sort` переписано на **pattern-defeating
quicksort**, який швидший у кількох поширених випадках. V8 до версії 7.0 використовував quicksort для
`Array.prototype.sort`, а потім, за статтею «Getting things sorted in V8», перейшов на Timsort, зокрема через його
стабільність.

## Злиття проти quicksort

| | Сортування злиттям | Quicksort |
|---|--------------------|-----------|
| порівняння в найгіршому випадку | `n log₂ n` | `n²/2` |
| порівняння в середньому | близько `n log₂ n` | близько `1,39 n log₂ n` |
| додаткова пам'ять | `Θ(n)` масив + `Θ(log n)` стек | `Θ(log n)` стек у середньому, `Θ(n)` у найгіршому |
| стабільність | так | ні |
| де робота | у злитті | у розбитті |
| на практиці | бібліотеки для об'єктів, зовнішнє сортування, списки | бібліотеки для чисел у пам'яті |

Quicksort робить більше порівнянь у середньому, але часто швидший на практиці: CLRS пише, що сталі множники в його
`Θ(n log n)` малі, а Sedgewick — що його внутрішній цикл коротший, ніж у більшості сортувань. До того ж він не копіює
елементи в допоміжний масив і назад.

## Для співбесіди

| Питання | Коротка відповідь |
|---------|-------------------|
| Як працює quicksort? | Вибрати опорний елемент, розбити масив на менші й більші, рекурсивно відсортувати обидві частини. |
| Скільки він коштує? | `Θ(n log n)` у середньому, `Θ(n²)` у найгіршому; пам'ять `Θ(log n)` у середньому, `Θ(n)` у найгіршому. |
| Коли трапляється найгірший випадок? | Коли опорний елемент щоразу найменший чи найбільший; з першим чи останнім опорним — на відсортованому і зворотному масиві. |
| Як від нього захиститися? | Випадковий опорний елемент або перемішування; медіана з трьох; рекурсія в меншу частину; розбиття на три частини для повторів. |
| Чим Ломуто відрізняється від Гоара? | Ломуто простіше, один вказівник іде зліва направо; Гоар — два вказівники назустріч, менше обмінів, легше помилитися. |
| Чи стабільний quicksort? | Ні: розбиття міняє місцями далекі елементи. |

## Типові помилки

**Брати опорним перший елемент і сортувати дані, що прийшли вже впорядкованими.** Час квадратичний, а стек
переповнюється.

**Вважати рекурсію quicksort неглибокою.** У найгіршому випадку глибина `n`, і стек Node 24 вміщує лише кілька тисяч
кадрів.

**Створювати нові масиви на кожному розбитті.** Код Bhargava так робить заради ясності: `less` і `greater` — нові
масиви. Sedgewick попереджає, що новачок, який створює допоміжний масив на кожному розбитті, «would drastically slow
down the sort».

**Помилитися на одиницю в розбитті Гоара.** Вказівники мають зупинятися на елементах, рівних опорному, і не виходити
за межі ділянки.

**Забути, що quicksort нестабільний.** Для сортування за кількома ключами кількома проходами він не годиться.

## Практика

Працюйте в тому самому проєкті. Відповіді в лекції немає: розбиття показано для іншої задачі, а розбиття Ломуто з
опорним першим елементом ви пишете самі.

**1. `quickSort(xs)`** з розбиттям Ломуто, опорним **першим** елементом ділянки і лічильником порівнянь. Перш ніж
писати, намалюйте три області інваріанта для опорного першого елемента: де тепер опорний, де мала частина, де велика,
де ще не бачені.

**2. Інваріант словами.** Запишіть у коментарі над розбиттям, що правдиве перед кожною ітерацією циклу, і перевірте,
що кожен рядок циклу це зберігає.

**3. Вимір.** Порахуйте порівняння на випадковому і на відсортованому масиві з 2000 елементів. Перед запуском випишіть
з таблиці лекції, що має вийти.

**4. Стек.** Запустіть сортування на відсортованому масиві з 20 000 елементів. Що сталося і чому? Запишіть
повідомлення про помилку в журнал.

**5. Тести.** Порожній масив, один елемент, два елементи в обох порядках, масив з однакових елементів, масив з

## Перевірте себе

**1. Розбийте `[5, 3, 8, 1, 9, 2]` розбиттям Ломуто з опорним останнім елементом, як у CLRS. Де опиниться опорний
елемент?**

<details><summary>Відповідь</summary>

Опорний `x = 2`. `j` іде по 5, 3, 8, 1, 9: не більший за 2 лише 1. Коли `j` доходить до 1 (позиція 3), `i` стає 0, і
елементи на позиціях 0 і 3 міняються: `[1, 3, 8, 5, 9, 2]`. Наприкінці опорний міняється з елементом на позиції `i + 1
= 1`: `[1, 2, 8, 5, 9, 3]`. Опорний 2 стоїть на позиції 1, ліворуч `1`, праворуч `8, 5, 9, 3`. Порівнянь 5, тобто `n −
1`.

</details>

**2. Скільки порівнянь зробить quicksort з опорним останнім елементом на масиві `[1, 2, 3, 4, 5]`?**

<details><summary>Відповідь</summary>

Опорний щоразу найбільший, права частина порожня, ліва має на один елемент менше. Порівнянь `4 + 3 + 2 + 1 = 10 = 5 ·
4/2`. Найгірший випадок.

</details>

**3. Чому розбиття 9 до 1 на кожному рівні все одно дає `O(n log n)`?**

<details><summary>Відповідь</summary>

Кожен рівень дерева рекурсії розбиває ділянки, що разом містять не більше `n` елементів, тож коштує не більше `n`
порівнянь. Найдовша гілка зменшує розмір у `10/9` разів на рівень, тож дерево має глибину `log_{10/9} n ≈ 21,9 log₁₀
n` рівнів, тобто `Θ(log n)`. Разом `O(n log n)` з більшою сталою, ніж для рівних половин.

</details>

**4. Чому quicksort нестабільний, навіть якщо розбиття Ломуто проходить масив зліва направо?**

<details><summary>Відповідь</summary>

Обмін `A[i] ↔ A[j]` переносить елемент з позиції `i + 1`, першої в «великій» частині, на позицію `j`, далеко праворуч.
Між ними можуть стояти рівні йому елементи, і він перестрибує через них. До того ж останній обмін переносить опорний
елемент через усю велику частину. Приклад: `[2a, 2b, 1]` з опорним 1 — після розбиття `[1, 2b, 2a]`.

</details>

**5. Масив з мільйона однакових чисел. Скільки порівнянь зробить quicksort з розбиттям Ломуто і чому?**

<details><summary>Відповідь</summary>

Умова `A[j] ≤ x` правдива для кожного елемента, тож усі йдуть у ліву частину, і опорний стає останнім. Права частина
порожня, ліва має `n − 1` елемент. Це найгірший випадок: `n(n − 1)/2 ≈ 5 · 10¹¹` порівнянь, до того ж глибина рекурсії
мільйон, і стек переповниться значно раніше. Розбиття на три частини відправило б усі рівні в середню частину, яку не
треба сортувати далі.

</details>

**6. Чому сортування злиттям гарантує `n log n`, а quicksort ні, хоча обидва ділять масив і рекурсивно сортують
частини?**

<details><summary>Відповідь</summary>

Сортування злиттям ділить навпіл за позицією, а не за значеннями, тож частини завжди рівні, і дерево рекурсії завжди
має висоту `log₂ n`. Quicksort ділить за значенням опорного елемента, і розміри частин залежать від того, яким за
величиною він виявився. Якщо щоразу найменшим, дерево стає ланцюжком висоти `n`. Ціна гарантії злиття — допоміжний
масив і копіювання.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| опорний елемент, pivot | елемент, навколо якого розбивають масив |
| розбиття | перестановка, після якої елементи з певною властивістю стоять перед усіма іншими |
| розбиття Ломуто | розбиття одним вказівником зліва направо з межею малої частини |
| розбиття Гоара | розбиття двома вказівниками назустріч |
| медіана з трьох | вибір опорного як медіани першого, середнього й останнього елементів |
| розбиття на три частини | розбиття на менші, рівні й більші за опорний; задача голландського прапора |
| гармонічне число `Hₙ` | сума `1 + 1/2 + … + 1/n`, приблизно `ln n` |
| pattern-defeating quicksort | варіант quicksort, що розпізнає погані для себе входи і змінює стратегію; стоїть у Go |
