# Лекція. Фаза 2, день 3. Ліволосі червоно-чорні дерева

Ця лекція пояснює ліволосе червоно-чорне дерево: звичайне двійкове дерево пошуку, яке кольорами посилань записує 2-3
дерево і тому має гарантовано логарифмічну висоту. Читання займе близько 50 хвилин. Під прикладами коду стоїть
справжній вивід з Node 24.22.

Учора ви бачили, що 2-3 дерево тримає всі листки на одній глибині, але програмувати його напряму незручно: два види
вузлів, масиви ключів, перетворення одного вузла в інший. Сьогодні з'ясуємо, як записати те саме дерево звичайними
двійковими вузлами, додавши до кожного посилання один біт кольору. Пошук від цього не зміниться зовсім, а вставка
отримає три короткі перевірки.

**Після лекції ви зможете пояснити:**

- як 3-вузол записують двома двійковими вузлами з червоним посиланням між ними;
- які три правила задають ліволосе червоно-чорне дерево і чому воно точно відповідає 2-3 дереву;
- що роблять лівий поворот, правий поворот і зміна кольорів і чому вони не ламають порядок ключів і чорний баланс;
- як три перевірки після рекурсивного виклику виконують розщеплення 2-3 дерева;
- чому висота такого дерева не більша за `2 log₂ n` і чому на практиці вона ближча до `log₂ n`.

## 3-вузол як два двійкові вузли

Sedgewick починає з простої думки. Звичайне дерево пошуку складається з самих 2-вузлів. Щоб записати 3-вузол, досить
узяти два 2-вузли і позначити посилання між ними як особливе. Таке посилання він називає **червоним**. Усі інші
посилання — **чорні**: вони з'єднують вузли 2-3 дерева між собою, а червоні склеюють два двійкові вузли в один
3-вузол.

Червоне посилання домовляються завжди спрямовувати ліворуч: менший ключ 3-вузла стає лівою дитиною більшого. Звідси
назва **ліволосе** (left-leaning) червоно-чорне дерево, скорочено LLRB.

```
3-вузол 2-3 дерева:                     той самий вузол у LLRB:

      [ 20   27 ]                                 27
     /     |     \                              //  \
 менші   між 20   більші                       20    більші за 27
 за 20   і 27     за 27                       /  \
                                          менші   між 20
                                          за 20   і 27
```

Подвійна риска `//` тут позначає червоне посилання. Перевірте порядок: усе, що менше за 20, лежить ліворуч від 20; усе
між 20 і 27 — праворуч від 20, але ліворуч від 27; усе більше за 27 — праворуч від 27. Це звичайне дерево пошуку. Тому
Sedgewick наголошує на головній перевазі: пошук у червоно-чорному дереві — це пошук з дня 1 без жодної зміни. Він не
дивиться на кольори взагалі.

**Де зберігати колір.** На кожен вузол, крім кореня, вказує рівно одне посилання — від батька. Тому колір посилання
зберігають у вузлі, на який воно вказує: поле `red` означає «посилання від батька до мене червоне». Коли кажуть
«червоний вузол», мають на увазі саме колір посилання до нього. Порожні посилання за домовленістю чорні, а корінь
завжди чорний, бо посилання згори в нього немає.

## Три правила

Sedgewick дає й інше, рівносильне визначення. Червоно-чорне дерево пошуку в його книжці — це дерево пошуку з червоними
і чорними посиланнями, у якому виконуються три правила:

1. червоні посилання ведуть ліворуч;
2. жоден вузол не має двох червоних посилань, тобто ні двох червоних дітей, ні червоної дитини під червоним посиланням
   згори;
3. **ідеальний чорний баланс**: кожен шлях від кореня до порожнього посилання має однакову кількість чорних посилань.

**Чому це саме 2-3 дерево.** Намалюйте червоні посилання горизонтально, щоб два вузли 3-вузла стояли поруч на одному
рівні. Тоді всі порожні посилання опиняться на однаковій відстані від кореня, бо кожен рівень тепер — один рівень
чорних посилань. А якщо стиснути кожну пару вузлів, з'єднаних червоним посиланням, в один вузол, вийде 2-3 дерево.
Правило 2 гарантує, що стискати доведеться не більше двох вузлів разом, тобто не виникне 4-вузлів. Правило 1 гарантує,
що кожен 3-вузол записано одним способом. Тому Sedgewick говорить про **взаємно однозначну відповідність**: кожному
2-3 дереву відповідає рівно одне ліволосе червоно-чорне дерево, і навпаки.

Ось дерево, яке вчора вийшло з дев'яти вставок, і його запис у LLRB:

```
2-3 дерево:                                   LLRB:

            [ 50 ]                                    50
          /        \                                /    \
    [ 20  27 ]      [ 90 ]                        27      90
    /   |   \       /    \                      //  \    /  \
 [10] [25] [30]  [80]   [95]                   20    30 80   95
                                              /  \
                                             10   25
```

Єдиний 3-вузол `[20 27]` став вузлом 27 з червоною лівою дитиною 20. Порахуйте чорні посилання від кореня до порожніх
посилань під кожним листком: шлях до 10 — `50→27` чорне, `27→20` червоне, `20→10` чорне, і ще порожнє посилання під
10. Шлях до 95 — `50→90`, `90→95` і порожнє. В обох по три чорних посилання.

## Повороти

Під час вставки правила 1 і 2 можуть на мить порушитися. Їх виправляють **поворотами**. Лівий поворот бере вузол `h`,
у якого праве посилання червоне, і робить коренем цієї пари його праву дитину `x`. Ключі, що лежали між `h` і `x`,
тобто ліве піддерево `x`, переходять у праве піддерево `h`. Правий поворот робить те саме дзеркально.

```ts
// Три операції ліволосого червоно-чорного дерева. Колір зберігається у вузлі:
// red = true означає, що червоне посилання веде від батька до цього вузла.
type Node = { key: number; left: Node | null; right: Node | null; red: boolean };
const n = (key: number, red: boolean, left: Node | null = null, right: Node | null = null): Node =>
  ({ key, left, right, red });

function rotateLeft(h: Node): Node {        // праве червоне посилання стає лівим
  const x = h.right!;
  h.right = x.left;                         // ключі між h і x переходять під h
  x.left = h;
  x.red = h.red;                            // x займає місце h і забирає колір посилання згори
  h.red = true;                             // h тепер висить під x на червоному посиланні
  return x;
}
function rotateRight(h: Node): Node {       // дзеркально: ліве червоне посилання стає правим
  const x = h.left!;
  h.left = x.right;
  x.right = h;
  x.red = h.red;
  h.red = true;
  return x;
}
function flipColors(h: Node): void {        // розщеплення 4-вузла: середній ключ іде до батька
  h.red = true;
  h.left!.red = false;
  h.right!.red = false;
}
// Запис дерева: ключ, зірочка — червоне посилання згори, у дужках ліве і праве піддерева.
const show = (x: Node | null): string =>
  x === null ? "·" : !x.left && !x.right ? `${x.key}${x.red ? "*" : ""}`
    : `${x.key}${x.red ? "*" : ""}(${show(x.left)} ${show(x.right)})`;

let t = n(20, false, n(10, false), n(30, true, n(25, false), n(40, false)));
console.log("праве червоне:     ", show(t), " → ", show(rotateLeft(t)));

t = n(30, false, n(20, true, n(10, true)), n(40, false));
console.log("два червоні ліворуч:", show(t), " → ", show(rotateRight(t)));

t = n(20, false, n(10, true), n(30, true));
const before = show(t); flipColors(t);
console.log("4-вузол:           ", before, " → ", show(t));

function rotateLeftWithoutColors(h: Node): Node {   // пастка дня: повернути, а кольори забути
  const x = h.right!;
  h.right = x.left;
  x.left = h;
  return x;
}
t = n(20, false, n(10, false), n(30, true, n(25, false), n(40, false)));
console.log("поворот без кольорів:", show(t), " → ", show(rotateLeftWithoutColors(t)));
```

```
праве червоне:      20(10 30*(25 40))  →  30(20*(10 25) 40)
два червоні ліворуч: 30(20*(10* ·) 40)  →  20(10* 30*(· 40))
4-вузол:            20(10* 30*)  →  20*(10 30)
поворот без кольорів: 20(10 30*(25 40))  →  30*(20(10 25) 40)
```

У записі `30*(25 40)` ключ 30 має зірочку, бо посилання до нього червоне, а в дужках — його ліва і права дитини.
Крапка позначає порожнє посилання.

**Перший рядок.** До повороту 3-вузол `[20 30]` записано неправильно: червоне посилання веде праворуч. Після лівого
повороту коренем пари став 30, 20 висить під ним на червоному посиланні ліворуч, а ключ 25, який лежав між 20 і 30,
перейшов з-під 30 під 20 праворуч. Порядок не змінився: симетричний обхід і до, і після дає `10 20 25 30 40`.

**Чому поворот не ламає чорний баланс.** Поворот лише міняє, який з двох вузлів 3-вузла стоїть вище. Обидва вузли були
з'єднані червоним посиланням і лишилися з'єднаними червоним. Нагору, до батька, веде посилання того самого кольору, що
й раніше: рядок `x.red = h.red` передає колір верхньому вузлу. Тому кожен шлях проходить ту саму кількість чорних
посилань.

**Другий рядок.** Два червоні посилання ліворуч підряд: 30, під ним 20, під ним 10. Це тимчасовий 4-вузол `[10 20
30]`, записаний «драбиною». Правий поворот у 30 робить коренем середній ключ 20, і обидва червоні посилання тепер
ведуть від 20 до 10 і до 30. Так 4-вузол стає збалансованим.

## Зміна кольорів

Збалансований 4-вузол — вузол з двома червоними дітьми — порушує правило 2. Його виправляє **зміна кольорів** (color
flip): обидві діти стають чорними, а посилання до самого вузла — червоним. Третій рядок виводу показує саме це:
`20(10* 30*)` став `20*(10 30)`.

Подивіться, що це означає для 2-3 дерева. Раніше 10, 20 і 30 були одним тимчасовим 4-вузлом. Тепер 10 і 30 — окремі
2-вузли, бо до них ведуть чорні посилання. А 20 приєднався червоним посиланням до свого батька, тобто піднявся в
батьківський вузол. Це рівно те розщеплення, яке вчора виконувала 2-3 вставка: крайні ключі розходяться, середній іде
до батька. Sedgewick підкреслює, що зміна кольорів, як і поворот, — локальне перетворення, яке зберігає ідеальний
чорний баланс: на кожному шляху через 20 одне червоне посилання стало чорним, а одне чорне — червоним.

Після зміни кольорів червоне посилання до 20 може порушити правила вже вище, у батька. Але для батька це виглядає так
само, ніби до нього щойно приєднали новий червоний вузол. Тому ті самі перевірки, повторені на кожному рівні вгору,
доведуть справу до кінця.

**Корінь.** Якщо зміна кольорів зробила червоним корінь, його фарбують у чорний. Червоний корінь означав би, що він
частина 3-вузла, а батька в нього немає. Sedgewick помічає, що саме в цей момент чорна висота всього дерева зростає на
1. Це розщеплення кореня 2-3 дерева, і дерево, як і вчора, росте вгору.

## Вставка

Вставка в LLRB — це вставка з дня 1, до якої додано дві речі.

**Новий вузол завжди червоний.** Він приєднується до батька червоним посиланням, тобто вливається в батьківський вузол
2-3 дерева, а не створює новий рівень унизу. Чорна висота від цього не змінюється. Це те саме правило, що й учора:
ключ кладуть у наявний лист.

**На шляху вгору — три перевірки.** Вставка рекурсивна, як `put` у Sedgewick з дня 1: функція спускається до
порожнього посилання, вішає там новий вузол, а потім, повертаючись з кожного рекурсивного виклику, перевіряє поточний
вузол `h`. Перевірки йдуть одна за одною в такому порядку:

1. якщо права дитина червона, а ліва — ні, виконати лівий поворот;
2. якщо ліва дитина червона і її ліва дитина теж червона, виконати правий поворот;
3. якщо обидві дитини червоні, змінити кольори.

Після повернення з верхнього виклику корінь фарбують у чорний.

Ці три перевірки покривають усі випадки, які розбирає Sedgewick.

| Куди потрапив новий червоний вузол | Що роблять | Що це в 2-3 дереві |
|------------------------------------|------------|--------------------|
| ліворуч від 2-вузла | нічого | 2-вузол став 3-вузлом |
| праворуч від 2-вузла | лівий поворот | 2-вузол став 3-вузлом, записаним правильно |
| праворуч від 3-вузла, більший за обидва ключі | зміна кольорів | 4-вузол розщепився |
| ліворуч від 3-вузла, менший за обидва ключі | правий поворот, зміна кольорів | 4-вузол-«драбину» вирівняли і розщепили |
| між ключами 3-вузла | лівий поворот унизу, правий поворот угорі, зміна кольорів | 4-вузол вирівняли двома поворотами і розщепили |

Отже, кожна вставка робить нуль, один або два повороти і одну зміну кольорів на кожному рівні, куди дійшло
розщеплення. Порядок перевірок важливий. Перша перевірка обслуговує два різні випадки: і 3-вузол, що нахилився не
туди, і нижнє посилання 4-вузла, коли новий ключ потрапив між двома ключами. Після неї друга бачить уже «драбину» з
двох лівих червоних посилань, а третя — збалансований 4-вузол.

**Дрібний приклад.** Вставимо в порожнє дерево 10, 30, 20. Після 10 і 30 маємо 30 з червоною лівою дитиною 10: вставка
30 праворуч від 10 дала праве червоне посилання, і лівий поворот у 10 його виправив. Двадцять потрапляє між 10 і 30,
тобто праворуч від 10. У вузлі 10 праве посилання червоне, а ліве ні, тож лівий поворот робить 20 вищим за 10. У вузлі
30 тепер два червоні посилання ліворуч підряд: 30, 20, 10, тож правий поворот робить 20 вищим за 30. У вузлі 20 обидві
дитини червоні, тож кольори змінюються. Корінь 20 фарбують у чорний. Вийшло дерево 20 з чорними дітьми 10 і 30, і з
ним 2-3 дерево висоти 1: корінь розщепився.

## Траса: ті самі ключі, що вчора

Вставимо ті самі дев'ять ключів, що вчора вставляли в 2-3 дерево. Права колонка показує, що відбувається у 2-3 дереві,
і її можна звірити з учорашньою трасою.

| Ключ | Операції на шляху вгору | Дерево LLRB після вставки | 2-3 дерево |
|------|-------------------------|---------------------------|------------|
| 50 | — | `50` | `[50]` |
| 20 | — | `50(20* ·)` | `[20 50]` |
| 80 | зміна кольорів у 50 | `50(20 80)` | корінь розщепився |
| 10 | — | `50(20(10* ·) 80)` | `[10 20]` |
| 30 | зміна кольорів у 20 | `50(20*(10 30) 80)` | лист розщепився, 20 піднявся в корінь `[20 50]` |
| 90 | лівий поворот у 80 | `50(20*(10 30) 90(80* ·))` | `[80 90]` |
| 95 | зміна кольорів у 90, зміна кольорів у 50 | `50(20(10 30) 90(80 95))` | лист і корінь розщепились |
| 25 | — | `50(20(10 30(25* ·)) 90(80 95))` | `[25 30]` |
| 27 | лівий поворот у 25, правий у 30, зміна кольорів у 27, лівий поворот у 20 | `50(27(20*(10 25) 30) 90(80 95))` | лист розщепився, 27 піднявся до 20: `[20 27]` |

Найдовший рядок — вставка 27. Двадцять сім потрапило праворуч від 25, тобто між 25 і 30, у 3-вузол `[25 30]`. Лівий
поворот у 25 і правий у 30 вирівняли 4-вузол `[25 27 30]` з 27 нагорі, а зміна кольорів у 27 розщепила його: 27
піднявся до батька 20 червоним посиланням. Але це посилання вело праворуч від 20, тож на наступному рівні вгору перша
перевірка знову зробила лівий поворот, уже у 20. Вийшов вузол 27 з червоною лівою дитиною 20: 3-вузол `[20 27]`, як
учора.

## Пастка: поворот без кольорів

Останній рядок виводу з розділу про повороти показує пастку дня. Функція `rotateLeftWithoutColors` переставила вузли,
але кольори залишила там, де вони були. До повороту дерево `20(10 30*(25 40))` було правильним записом 3-вузла `[20
30]`, хоча й з посиланням не в той бік. Після повороту вийшло `30*(20(10 25) 40)`.

Порахуйте чорні посилання від 30. Шлях до порожнього посилання під 10: `30→20` чорне, `20→10` чорне, порожнє під 10 —
три. Шлях до порожнього посилання під 40: `30→40` чорне і порожнє під 40 — два. Чорний баланс зламано. Крім того, 30
тепер червоний, хоча стоїть нагорі пари. Дерево перестало відповідати жодному 2-3 дереву. Ключі при цьому лишилися
впорядкованими, тож пошук ще працюватиме, і помилку легко не помітити, доки висота не почне рости. Саме тому практика
просить метод `check()`, який після кожної вставки перевіряє всі три правила.

## Висота: не більша за `2 log₂ n`

Sedgewick доводить твердження G: висота червоно-чорного дерева з `n` вузлами не більша за `2 lg n`. Міркування таке.
Порахуємо на шляху від кореня вниз лише посилання між вузлами, без порожнього в кінці. Чорних серед них на кожному
шляху до листка однаково, нехай `b`. Кожне чорне посилання — це крок на рівень нижче у 2-3 дереві, тож `b` дорівнює
висоті 2-3 дерева, а вона, як ви бачили вчора, не більша за `log₂ n`. Червоних посилань підряд не буває, тож між двома
червоними завжди стоїть чорне, і червоних на шляху щонайбільше на одне більше, ніж чорних. Отже, жоден шлях не довший
за `2b + 1`, тобто приблизно за `2 log₂ n`.

Найгірший випадок Sedgewick описує так: 2-3 дерево з самих 2-вузлів, крім найлівішого шляху, де всі вузли — 3-вузли.
Тоді шлях по лівих посиланнях від кореня вдвічі довший за решту. Стаття 2008 року дає ту саму картину словами: усі
вузли чорні, крім одного шляху, де червоні й чорні чергуються.

Межа обережна. Sedgewick пише, що в експериментах і на звичайних даних пошук у червоно-чорному дереві з `n` вузлами в
середньому робить близько `1,00 lg n − 0,5` порівнянь, тобто майже стільки, скільки в ідеально збалансованому дереві.
Для `FrequencyCounter` з учорашнього читання шляхи пошуку виявилися приблизно на 40 % коротшими, ніж у звичайному
дереві пошуку. Стаття 2008 року додає ще одне спостереження: висота дерева з випадкових ключів близька до `2 ln n`.
Автор підкреслює, що це лише гіпотеза з експериментів, а математичну модель, яка пояснювала б поведінку червоно-чорних
дерев на випадкових ключах, він називає однією з відкритих задач аналізу алгоритмів.

Практика перевірить межу на відсортованих ключах. План очікує висоту 9 для тисячі ключів, хоча межа `2 log₂ 1000` дає
майже 20, а звичайне дерево з дня 1 мало висоту 999.

## Що дає червоно-чорне дерево поза вставкою

**Пошук безкоштовний.** Метод `get` не дивиться на кольори, тож баланс не додає пошуку жодної роботи. Sedgewick
пояснює, чому це важливо: ключ вставляють один раз, а шукають багато разів.

**Впорядковані операції працюють без змін.** Мінімум, максимум, `floor`, `ceiling`, `rank`, `select` і пошук проміжку
з дня 1 працюють з деревом пошуку і не потребують кольорів. Sedgewick формулює твердження I: у червоно-чорному дереві
всі ці операції, а також вставка і видалення, коштують логарифмічний час у найгіршому випадку.

**Видалення складніше.** Sedgewick відкладає його у вправи, а стаття 2008 року дає повну реалізацію приблизно на 30
рядків. Ідея — під час спуску позичати ключі в сусідів, щоб пошук ніколи не закінчився в 2-вузлі, бо з 2-вузла ключ не
прибереш без зміни висоти. До видалення план дійде в день 5.

**Варіант 2-3-4 дерева.** Стаття і книжка показують, що 2-3-4 дерево, у якому 4-вузли можуть лишатися в дереві,
виходить з того самого коду переміщенням одного рядка: зміну кольорів роблять не після рекурсивного виклику, а перед
ним, на шляху вниз. Тоді кожен 4-вузол на шляху розщеплюється заздалегідь.

**Історія.** Стаття нагадує, що червоно-чорні дерева запропонували Гібас і Седжвік у 1978 році. Вимогу, щоб 3-вузли
завжди хилилися в один бік, раніше використав Андерссон, а повороти на шляху вгору — сам Седжвік у попередніх книжках.
Поєднання цих ідей і дало ліволосе дерево, коротке настільки, що вставка відрізняється від звичайного дерева пошуку
трьома рядками.

## Для співбесіди

| Питання | Коротка відповідь |
|---------|-------------------|
| Що таке червоно-чорне дерево? | Двійкове дерево пошуку, в якому червоні посилання склеюють вузли в 3-вузли 2-3 дерева; кожен шлях має однакову кількість чорних посилань. |
| Яка висота? | Не більша за `2 log₂ n`: червоних посилань на шляху не більше, ніж чорних. |
| Чому новий вузол червоний? | Він вливається в наявний вузол 2-3 дерева і не змінює чорної висоти. |
| Що робить зміна кольорів? | Розщеплює 4-вузол: діти стають чорними, а середній ключ піднімається до батька червоним посиланням. |
| Чи сповільнює баланс пошук? | Ні: пошук не дивиться на кольори. |
| Чим LLRB простіше за класичне червоно-чорне дерево? | 3-вузли записуються одним способом, тож випадків удвічі менше, і вставка — це три перевірки на шляху вгору. |

## Типові помилки

**Повертати вузли, не переносячи кольори.** Це пастка дня, і вивід вище показує, що з неї виходить: зламаний чорний
баланс при правильному порядку ключів.

**Забувати присвоїти результат повороту.** Поворот повертає новий корінь піддерева. Якщо написати `rotateLeft(h)`
замість `h = rotateLeft(h)`, батько і далі вказуватиме на старий вузол, який тепер стоїть нижче.

**Міняти порядок трьох перевірок.** Якщо змінити кольори раніше за повороти, «драбина» з двох лівих червоних посилань
не встигне вирівнятися, і розщеплення піде не так.

**Забувати пофарбувати корінь у чорний.** Тоді після зміни кольорів у корені правило 2 порушиться на наступній
вставці, коли під червоним коренем з'явиться червона дитина.

**Робити новий вузол чорним.** Чорний новий вузол подовжує один шлях на чорне посилання і ламає чорний баланс.

**Вважати, що червоний вузол — це властивість самого вузла.** Колір у вузлі описує посилання від батька. Після
повороту він мусить переїхати разом із місцем вузла в дереві.

## Практика

Працюйте в проєкті `algo-lab`. Повороти і зміну кольорів лекція показала кодом, а вставку — правилами і таблицею, тож
метод вставки ви пишете самі.

**1. `LLRB<K, V>`** з компаратором у конструкторі і методами `get`, `set`, `height` і `check`. Метод `check` перевіряє
три речі: ключі впорядковані, жоден вузол не має двох червоних посилань і немає правого червоного посилання, і кожен
шлях від кореня до порожнього посилання має однакову кількість чорних посилань.

**2. Вимір.** Вставте 1…1000 по порядку і виміряйте висоту. Потім вставте 1000…1 у зворотному порядку. Передбачте
обидва числа до запуску і поясніть різницю, якщо вона буде.

**3. Тести.** Викликайте `check()` після кожної вставки у випадковій послідовності ключів. Окремо перевірте вставку
наявного ключа: вона мусить замінити значення і не змінити дерево.

**4. Відповідність.** Візьміть дерево з 15 ключів, вставлених у будь-якому порядку, намалюйте його з горизонтальними
червоними посиланнями і стисніть пари в 3-вузли. Перевірте, що вийшло 2-3 дерево з однаковою глибиною листків.

**5. Журнал.** Один рядок у `JOURNAL.md` і висоти з пункту 2 у `MEASUREMENTS.md`.

## Перевірте себе

**1. Перетворіть на LLRB 2-3 дерево з коренем `[40]`, його дітьми `[20 30]` і `[60]` та листками `[10]`, `[25]`,
`[35]`, `[50]`, `[70]`.**

<details><summary>Відповідь</summary>

Корінь 40 лишається чорним. 3-вузол `[20 30]` стає вузлом 30 з червоною лівою дитиною 20. Під 20 ліворуч 10, праворуч
25; під 30 праворуч 35. Під 60 ліворуч 50, праворуч 70. У записі лекції: `40(30(20*(10 25) 35) 60(50 70))`. На кожному
шляху три чорні посилання, рахуючи порожнє.

</details>

**2. В останнє дерево траси вставили 26. Які операції відбудуться?**

<details><summary>Відповідь</summary>

Двадцять шість іде від 50 ліворуч до 27, ліворуч до 20, праворуч до 25 і стає правою червоною дитиною 25. У вузлі 25
праве посилання червоне, а ліве ні, тож лівий поворот: 26 стає вище, 25 — його червона ліва дитина. Більше нічого: у
20 немає двох червоних дітей, у 27 немає двох червоних посилань ліворуч підряд, бо 20 червоний, а його ліва дитина 10
чорна. У 2-3 дереві лист `[25]` став `[25 26]`.

</details>

**3. Чому новий вузол приєднують червоним посиланням, а не чорним?**

<details><summary>Відповідь</summary>

Чорне посилання вниз додало б один чорний крок до шляхів, що проходять через новий вузол, і лише до них. Чорний баланс
зламався б, а виправити його локально неможливо. Червоне посилання не змінює чорної висоти: новий ключ просто
вливається в наявний вузол 2-3 дерева. Порушення, які воно може створити, — праве червоне посилання чи два червоні
підряд — виправляються поворотами і зміною кольорів.

</details>

**4. Чому зміна кольорів не змінює кількості чорних посилань на жодному шляху?**

<details><summary>Відповідь</summary>

Шлях, що проходить через вузол `h` зі зміною кольорів, іде далі або в ліву, або в праву дитину. До зміни посилання до
`h` було чорним, а до дитини — червоним. Після зміни посилання до `h` червоне, а до дитини — чорне. На кожному такому
шляху одне чорне стало червоним, а одне червоне — чорним, тож чорних стільки ж. Шляхи, що не проходять через `h`,
зміна не зачіпає.

</details>

**5. Межа `2 log₂ n` для тисячі ключів — близько 20. Чому відсортовані ключі дають висоту лише 9?**

<details><summary>Відповідь</summary>

Межа описує найгірший випадок, коли один шлях складається з чергування червоних і чорних посилань. Відсортовані ключі
в 2-3 дереві дають майже самі 2-вузли, як показав учорашній вимір: висота 8 і лише шість 3-вузлів на правому краю. У
LLRB такі вузли дають лише поодинокі червоні посилання, тож висота LLRB лише трохи більша за висоту 2-3 дерева.

</details>

**6. Чому червоно-чорне дерево шукає не повільніше за звичайне дерево пошуку, хоча зберігає кольори?**

<details><summary>Відповідь</summary>

Пошук порівнює ключі і йде ліворуч чи праворуч, як у дні 1, і ніколи не читає поле кольору. Кольори потрібні лише
вставці і видаленню. Водночас дерево збалансоване, тож шлях пошуку коротший, ніж у звичайному дереві на тих самих
даних.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| червоне посилання | посилання, що склеює два двійкові вузли в один 3-вузол 2-3 дерева |
| чорне посилання | звичайне посилання між вузлами 2-3 дерева |
| ліволосе червоно-чорне дерево, LLRB | червоно-чорне дерево, де червоні посилання завжди ведуть ліворуч |
| ідеальний чорний баланс | однакова кількість чорних посилань на кожному шляху від кореня до порожнього посилання |
| лівий поворот | перетворення, що робить праву дитину коренем пари і переносить ключі між ними під старий корінь |
| правий поворот | дзеркальне перетворення для лівої дитини |
| зміна кольорів, color flip | діти вузла стають чорними, а посилання до вузла — червоним; розщеплення 4-вузла |
