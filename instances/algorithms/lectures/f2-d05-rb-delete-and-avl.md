# Лекція. Фаза 2, день 5. Видалення з червоно-чорного дерева і AVL-дерева

Ця лекція пояснює дві речі. Перша — як CLRS видаляє вузол з червоно-чорного дерева і відновлює властивості через
«зайве чорне». Друга — AVL-дерево, найстаріше збалансоване дерево, яке тримає баланс іншим правилом: висотами
піддерев. Читання займе близько 60 хвилин. Під прикладами коду стоїть справжній вивід з Node 24.22.

Учора ви бачили вставку в червоно-чорне дерево: новий червоний вузол ламав щонайбільше одну властивість, а виправлення
робило не більше двох поворотів. Сьогодні з'ясуємо, чому видалення складніше, який вузол насправді виходить з дерева,
і чим AVL-дерево платить за те, що воно нижче.

**Після лекції ви зможете пояснити:**

- чому видалення чорного вузла ламає чорний баланс і що таке «зайве чорне»;
- який вузол фізично виходить з дерева в `RB-DELETE` і чому вирішує саме його колір;
- чотири випадки `RB-DELETE-FIXUP` і чому видалення робить не більше трьох поворотів;
- правило AVL-дерева і чому його висота не більша за приблизно `1,44 log₂ n`;
- як AVL-дерево відновлює баланс одинарним або подвійним поворотом;
- чим AVL-дерево і червоно-чорне дерево відрізняються на практиці.

## Чому видалення складніше

Усі джерела цього тижня сходяться в одному. CLRS пише, що видалити вузол з червоно-чорного дерева складніше, ніж
вставити. Sedgewick відкладає видалення у вправи. Його стаття 2008 року зауважує, що промислові реалізації видалення
займають понад сто рядків. Morin пише, що видалення — найскладніша операція в усіх відомих варіантах червоно-чорних
дерев.

Причина ось у чому. Вставка додавала червоний вузол на місце чорного сторожа, і кількість чорних вузлів на шляхах не
змінювалась. Видалення може прибрати з шляху чорний вузол. Тоді всі шляхи через це місце стають на один чорний вузол
коротшими, і властивість 5 ламається вже не в одному місці, а для всіх предків.

## Хто насправді виходить з дерева

`RB-DELETE` побудовано на видаленні з дня 1. Якщо в вузла `z` не більше однієї дитини, він виходить з дерева сам, а
його дитина стає на його місце. Якщо дітей дві, на місце `z` переїжджає його наступний `y`, найлівіший вузол правого
піддерева, а на старе місце `y` стає права дитина `y`. Процедура використовує такі позначення:

- `z` — вузол, ключ якого видаляють;
- `y` — вузол, який залишає своє місце: сам `z`, якщо дітей не більше однієї, або наступний за `z`, якщо дві;
- `x` — вузол, який стає на старе місце `y`; якщо там нікого немає, це сторож `T.nil`.

Найважливіша деталь: коли `y` переїжджає на місце `z`, він **бере колір `z`** (рядок 20). Тому біля місця `z` нічого
не змінюється, а колір, який справді зникає з дерева, — це **початковий колір `y`**. Процедура запам'ятовує його у
змінній `y-original-color` і викликає виправлення лише тоді, коли цей колір чорний.

Програма нижче бере підсумкове дерево вчорашньої траси і для кількох ключів показує, хто виходить і чи потрібне
виправлення. Вона повторює лише ту частину `RB-DELETE`, яка вибирає `y` і `x`.

```ts
// Який вузол фізично виходить з дерева, коли RB-DELETE видаляє ключ z (рядки 1–11 процедури).
// Дерево — підсумок траси дня 4: 50B(20R(10B 27B(25R 30R)) 90B(80R 95R)).
type Node = { key: number; red: boolean; left: Node | null; right: Node | null };
const n = (key: number, red: boolean, left: Node | null = null, right: Node | null = null): Node =>
  ({ key, red, left, right });
const root = n(50, false,
  n(20, true, n(10, false), n(27, false, n(25, true), n(30, true))),
  n(90, false, n(80, true), n(95, true)));

function find(x: Node | null, key: number): Node {
  while (x !== null && x.key !== key) x = key < x.key ? x.left : x.right;
  return x!;
}
const color = (x: Node | null) => (x === null ? "сторож" : x.red ? "червоний" : "чорний");

for (const key of [10, 20, 27, 50, 90]) {
  const z = find(root, key);
  let y = z;                                          // рядок 1: y = z, якщо дітей не більше однієї
  if (z.left !== null && z.right !== null) {          // рядок 9: інакше y — наступний за z
    y = z.right;
    while (y.left !== null) y = y.left;
  }
  const x = z.left === null || y !== z ? y.right : z.left;   // хто стане на місце y
  const moved = y === z ? "вузол виходить з дерева сам" : `на його місце переїжджає ${y.key} і бере його колір`;
  console.log(`видаляємо ${key} (${color(z)}): ${moved}; зникає ${color(y)} вузол на місці ${y.key},` +
    ` туди стає ${x === null ? "сторож" : x.key}; RB-DELETE-FIXUP ${y.red ? "не потрібен" : "потрібен"}`);
}
```

```
видаляємо 10 (чорний): вузол виходить з дерева сам; зникає чорний вузол на місці 10, туди стає сторож; RB-DELETE-FIXUP потрібен
видаляємо 20 (червоний): на його місце переїжджає 25 і бере його колір; зникає червоний вузол на місці 25, туди стає сторож; RB-DELETE-FIXUP не потрібен
видаляємо 27 (чорний): на його місце переїжджає 30 і бере його колір; зникає червоний вузол на місці 30, туди стає сторож; RB-DELETE-FIXUP не потрібен
видаляємо 50 (чорний): на його місце переїжджає 80 і бере його колір; зникає червоний вузол на місці 80, туди стає сторож; RB-DELETE-FIXUP не потрібен
видаляємо 90 (чорний): на його місце переїжджає 95 і бере його колір; зникає червоний вузол на місці 95, туди стає сторож; RB-DELETE-FIXUP не потрібен
```

Подивіться на рядок про корінь 50. Видаляють чорний ключ, але виправлення не потрібне. Вісімдесят переїжджає в корінь
і фарбується в чорний, як був 50, а з дерева зникає лише старе місце 80, яке було червоним. Кількість чорних вузлів на
шляхах не змінилась. Навпаки, якби програма дивилася на колір `z`, вона запустила б виправлення там, де його не треба,
і зламала б дерево. Це і є пастка дня з плану: колір треба брати в того вузла, який справді вийшов зі свого місця.

**Чому червоний `y` нічого не ламає.** CLRS дає три причини. Чорні висоти не змінились, бо зник червоний вузол. Два
червоні вузли не стали сусідами: якщо `y` був червоним, його батько і дитина чорні, тож дитина, ставши на його місце,
опиниться під чорним батьком. Корінь лишився чорним, бо червоний вузол не міг бути коренем.

**Дрібниця з великими наслідками.** Процедура `RB-TRANSPLANT` відрізняється від `TRANSPLANT` з дня 1 тим, що присвоює
`v.p = u.p` завжди, навіть коли `v` — сторож. А рядок 16 записує `x.p = y` на випадок, коли `x` — сторож. Звичайно
батько сторожа нікого не цікавить, але виправлення після видалення починає роботу саме з `x.p`. Тому сторож мусить на
мить «знати», де він стоїть.

## Зайве чорне

Якщо зник чорний вузол, кожен шлях через місце `y` втратив один чорний вузол. CLRS пропонує уявити, що чорнота
зниклого вузла перейшла на `x`, який став на його місце. Тоді `x` несе **зайве чорне** і рахується на шляхах двічі.
Властивість 5 знову виконується, але тепер порушена властивість 1: `x` не червоний і не чорний. Якщо його поле кольору
червоне, CLRS називає його **червоно-чорним** вузлом, і він рахується як один чорний. Якщо чорне — **двічі чорним**, і
він рахується як два. Зайве чорне позначає не поле кольору, а сам вказівник `x`.

Цикл `RB-DELETE-FIXUP` переносить зайве чорне вгору, доки не станеться одне з трьох:

1. `x` вказує на червоно-чорний вузол — тоді досить пофарбувати його в звичайний чорний (рядок 44);
2. `x` дійшов до кореня — тоді зайве чорне просто зникає: воно додає по одному чорному вузлу до всіх шляхів одразу;
3. повороти і перефарбування позбулися зайвого чорного на місці, і цикл виходить.

## Чотири випадки

CLRS розбирає випадок, коли `x` — ліва дитина свого батька. Правий випадок дзеркальний. Брата `x` позначають `w`. Він
точно не сторож: інакше на шляху від батька до сторожа-брата було б менше чорних вузлів, ніж до двічі чорного `x`.
Позначимо батька `B`, брата `D`, лівого і правого племінників — дітей `D` — `C` і `E`.

**Випадок 1: брат червоний.** Тоді батько і обидва племінники чорні. Брат і батько міняються кольорами, і робиться
лівий поворот у батька. Тепер новим братом `x` став один із колишніх племінників, а він чорний. Випадок 1 нічого не
виправляє сам, він лише переводить ситуацію у випадки 2, 3 або 4.

```
       B(чорний)                           D(чорний)
      /         \                         /         \
   x(A)        D(червоний)     →      B(червоний)    E
              /   \                   /    \
             C     E                x(A)    C  ← новий брат, чорний
```

**Випадок 2: брат чорний, обидва племінники чорні.** Брат фарбується в червоний, а `x` піднімається на батька: `x =
x.p`. CLRS пояснює це так: з `x` і з брата знімають по одному чорному, а батько бере зайве чорне на себе. Поворотів
немає. Якщо батько був червоним, він тепер червоно-чорний, і цикл закінчиться при наступній перевірці. Саме так буде,
коли у випадок 2 потрапили з випадку 1, бо там батько щойно став червоним.

**Випадок 3: брат чорний, лівий племінник червоний, правий чорний.** Брат і лівий племінник міняються кольорами, і
робиться правий поворот у брата. Тепер новий брат чорний і має червону праву дитину. Це випадок 4.

**Випадок 4: брат чорний, правий племінник червоний.** Брат бере колір батька, батько і правий племінник фарбуються в
чорний, і робиться лівий поворот у батька. Брат піднімається на місце батька, батько опускається до `x` і забирає
зайве чорне собі, а правий племінник, ставши чорним, відшкодовує втрату на правому боці. Зайве чорне зникає, і `x`
встановлюється на корінь, щоб цикл закінчився.

```
       B(колір c)                            D(колір c)
      /         \                           /         \
   x(A)        D(чорний)      →        B(чорний)     E(чорний)
              /   \                    /    \
             C    E(червоний)        x(A)    C
```

**Через 2-3-4 дерево.** Двічі чорний `x` — це вузол 2-4 дерева, який лишився без ключа, як у видаленні Morin з дня 2.
Випадок 2 — це злиття: брат був 2-вузлом, ключа позичити не можна, тож брат зливається з батьком, і проблема
піднімається на рівень вище. Morin називає відповідну операцію в своєму дереві `pull_black`. Випадки 3 і 4 — це
позичання: у брата є зайвий ключ, червоний племінник, і повороти передають його на бік `x`. Випадок 1 лише переписує
3-вузол батька іншим способом, щоб братом `x` став справжній сусід у 2-4 дереві.

**Скільки це коштує.** CLRS підсумовує: лише у випадку 2 цикл може повторитися, і тоді `x` піднімається вгору без
поворотів, щонайбільше `O(lg n)` разів. Випадки 1, 3 і 4 закінчують цикл після сталої кількості перефарбувань і не
більш ніж трьох поворотів: випадок 1 може перейти у випадок 3, а той — у випадок 4, по одному повороту на кожен. Отже,
видалення коштує `O(lg n)` і робить не більше трьох поворотів.

## AVL-дерево: баланс за висотами

AVL-дерево — найстаріше збалансоване дерево. Курс MIT називає його першою запропонованою схемою балансу, а Knuth
розповідає, що його відкрили в 1962 році математики Г. М. Адельсон-Вельський і Є. М. Ландіс. Назва складена з перших
літер їхніх прізвищ.

Правило AVL-дерева просте: у кожному вузлі висоти лівого і правого піддерев різняться не більше ніж на одиницю. Курс
MIT називає різницю «висота правого піддерева мінус висота лівого» **перекосом** (skew) вузла. Вузол збалансований за
висотою, якщо його перекіс −1, 0 або 1. Grokking називає те саме число **коефіцієнтом балансу**.

**Чому висота логарифмічна.** Курс MIT доводить це через найменшу кількість вузлів `F(h)` у дереві висоти `h`, де
кожен вузол збалансований. Найбідніше таке дерево має в корені одне піддерево висоти `h − 1` і друге висоти `h − 2`, і
кожне з них теж найбідніше. Звідси `F(h) = F(h − 1) + F(h − 2) + 1` при `F(0) = 1`, `F(1) = 2`. Це майже числа
Фібоначчі, які ростуть приблизно як `φ^h`, де `φ ≈ 1,618` — золотий перетин. MIT дає грубу оцінку: `F(h) ≥ 2F(h − 2)`,
тож `F(h) ≥ 2^(h/2)`, і висота не більша за `2 log₂ n`. Knuth доводить точну межу в теоремі A: висота AVL-дерева з `n`
внутрішніми вузлами лежить між `lg(n + 1)` і `1,4405 lg(n + 2) − 0,3277`. Він підсумовує це так: шляхи пошуку в
AVL-дереві ніколи не довші за оптимальні більш ніж на 45 %. Grokking пояснює те саме простіше: у AVL-дереві логарифм
береться не за основою 2, а за основою `φ`.

Порахуємо найбільшу можливу висоту за цими правилами і порівняємо з межею червоно-чорного дерева:

```ts
// Найбільша можлива висота дерева з n ключами для трьох правил балансу.
// AVL: найменше вузлів у дереві висоти h — N(h) = N(h − 1) + N(h − 2) + 1, як числа Фібоначчі.
// Межа Knuth для AVL: 1,4405·lg(n + 2) − 0,3277.
// Червоно-чорне: лема 13.1 CLRS, h ≤ 2 lg(n + 1). Досконале дерево: ⌊lg n⌋.
function avlMaxHeight(n: number): number {
  let prev = 1, cur = 2, h = 1;                       // N(0) = 1, N(1) = 2
  if (n < 2) return 0;
  while (true) {
    const next = cur + prev + 1;                      // N(h + 1)
    if (next > n) return h;                           // дерево висоти h + 1 вже не вміщується в n вузлів
    prev = cur; cur = next; h++;
  }
}
for (const n of [1_000, 1_000_000, 1_000_000_000]) {
  const lg = Math.log2(n);
  console.log(`n = ${n}: досконале ${Math.floor(lg)}, AVL не вище ${avlMaxHeight(n)}` +
    ` (межа Knuth ${(1.4405 * Math.log2(n + 2) - 0.3277).toFixed(1)}), червоно-чорне не вище ${Math.floor(2 * Math.log2(n + 1))}`);
}
```

```
n = 1000: досконале 9, AVL не вище 13 (межа Knuth 14.0), червоно-чорне не вище 19
n = 1000000: досконале 19, AVL не вище 27 (межа Knuth 28.4), червоно-чорне не вище 39
n = 1000000000: досконале 29, AVL не вище 41 (межа Knuth 42.7), червоно-чорне не вище 59
```

Найгірше AVL-дерево з мільярдом ключів має висоту 41, а найгірше червоно-чорне дозволене висоти 59. Обидва числа —
межі для найгіршого випадку. На звичайних даних обидва дерева значно нижчі, і практика порівняє їх на мільйоні
випадкових ключів.

### Як AVL-дерево відновлює баланс

**Висота у вузлі.** Щоб знати перекіс, треба знати висоти піддерев, а рахувати їх обходом надто дорого. Курс MIT
пропонує доповнити кожен вузол полем з висотою його піддерева, як у дні 1 доповнювали вузол розміром піддерева. Висоту
вузла обчислюють зі збережених висот дітей: найбільша з двох плюс один. Після кожної вставки чи видалення висоти
оновлюють на шляху від зміненого місця до кореня, а після повороту — у двох переставлених вузлах, спершу в нижньому,
потім у верхньому.

**Локальне перебалансування.** Нехай вузол `B` має перекіс 2, тобто його праве піддерево на два рівні вище за ліве, а
все нижче за `B` уже збалансоване. Курс MIT розбирає три випадки за перекосом правої дитини `F`:

| Перекіс `F` | Що робити | Як це називають |
|-------------|-----------|-----------------|
| 0 або 1 | лівий поворот у `B` | одинарний поворот |
| −1 | правий поворот у `F`, потім лівий поворот у `B` | подвійний поворот |

Після цього `B` знову збалансований. Перекіс −2 обробляють дзеркально. Bae у своїй книжці називає ці випадки «LL»,
«RR», «LR» і «RL» за тим, з якого боку і в якому порядку піддерево стало задовгим.

**Вставка і видалення.** Після вставки або видалення висоти змінюються лише в предків зміненого місця. Цикл іде від
нього вгору і перебалансовує найнижчого предка з перекосом ±2. Курс MIT і Knuth розрізняють два випадки:

- після **вставки** досить одного перебалансування, одинарного чи подвійного, бо воно повертає піддереву ту висоту,
  яка була до вставки, і вище нічого не змінюється. Knuth пише, що вставка ніколи не потребує більше одного такого
  кроку;
- після **видалення** перебалансування може зменшити висоту піддерева, і тоді новий перекіс може з'явитися вище. Knuth
  пише, що видалення може потребувати до `log N` поворотів, хоча в експериментах їх у середньому близько 0,21 на
  видалення.

**Траса.** Вставимо 10, 20, 30, 40, 50, 25 у порожнє AVL-дерево. Запис дерева той самий, що в попередні дні, але без
кольорів.

| Ключ | Що відбувається | Дерево |
|------|-----------------|--------|
| 10 | — | `10` |
| 20 | перекіс 10 став 1, це дозволено | `10(· 20)` |
| 30 | перекіс 10 став 2, перекіс 20 дорівнює 1: лівий поворот у 10 | `20(10 30)` |
| 40 | перекоси 30 і 20 по 1 | `20(10 30(· 40))` |
| 50 | перекіс 30 став 2, перекіс 40 дорівнює 1: лівий поворот у 30 | `20(10 40(30 50))` |
| 25 | перекіс 20 став 2, а перекіс 40 дорівнює −1, бо 25 потрапило ліворуч від 40: подвійний поворот — правий у 40, лівий у 20 | `30(20(10 25) 40(· 50))` |

Ключі 10…50 ішли по порядку, і звичайне дерево пошуку стало б ланцюжком. AVL-дерево після кожного кроку тримає висоту
не більшу за 2.

## AVL-дерево і червоно-чорне дерево

| | AVL-дерево | Червоно-чорне дерево CLRS |
|---|---|---|
| Правило | висоти піддерев різняться не більше ніж на 1 | п'ять властивостей кольорів |
| Висота в найгіршому випадку | `≈ 1,44 lg n` | `2 lg(n + 1)` |
| Що зберігає вузол | висоту піддерева; Knuth зауважує, що досить двох бітів на перекіс | один біт кольору |
| Повороти при вставці | одне перебалансування: до двох поворотів | до двох поворотів |
| Повороти при видаленні | до `O(log n)` | до трьох |
| Амортизована робота на виправлення | Morin: сталої гарантії немає | Morin: стала |

З таблиці видно, де кожне дерево виграє. AVL-дерево нижче, тож у найгіршому випадку пошук у ньому коротший.
Червоно-чорне дерево обмежує кількість поворотів на кожну зміну. Morin, пояснюючи, чому червоно-чорні дерева стоять у
Java Collections Framework, кількох реалізаціях STL C++ і ядрі Linux, серед причин називає саме сталу амортизовану
кількість поворотів. Яке з двох краще для конкретної програми, залежить від того, чого в ній більше: пошуків чи змін.
Практика дня поміряє обидва дерева на тих самих ключах.

## Для співбесіди

| Питання | Коротка відповідь |
|---------|-------------------|
| Чому видалення з червоно-чорного дерева складніше за вставку? | Зникнення чорного вузла робить коротшими всі шляхи через нього; виправлення мусить переносити «зайве чорне» вгору або позбуватися його поворотами. |
| Чий колір вирішує, чи потрібне виправлення? | Вузла `y`, що залишає своє місце: самого `z` або його наступного. |
| Скільки поворотів робить видалення? | Не більше трьох; перефарбувань може бути `O(lg n)`. |
| Що таке AVL-дерево? | Дерево пошуку, у кожному вузлі якого висоти піддерев різняться не більше ніж на одиницю. |
| Яка висота AVL-дерева? | Не більша за `≈ 1,44 lg n`: найбідніші AVL-дерева будуються як числа Фібоначчі. |
| Коли потрібен подвійний поворот? | Коли піддерево стало задовгим «зсередини»: перекіс вузла 2, а перекіс його правої дитини −1, або дзеркально. |

## Типові помилки

**Брати колір видаленого ключа, а не вузла, що вийшов зі свого місця.** Це пастка дня, і вивід вище показує ціну
помилки: видалення чорного кореня 50 не потребує виправлення, бо зникає червоне місце 80.

**Не записувати батька сторожа.** Якщо `x` — сторож, рядок 16 `RB-DELETE` і рядок 6 `RB-TRANSPLANT` записують йому
батька. Без цього `RB-DELETE-FIXUP` піде від `x.p` не туди.

**Робити поворот у випадку 2.** У випадку «брат чорний, обидва племінники чорні» поворотів немає: брат червоніє, а
зайве чорне піднімається до батька.

**Оновлювати висоти після повороту в неправильному порядку.** У AVL-дереві після повороту спершу оновлюють висоту
вузла, що опустився, бо він тепер дитина, а потім вузла, що піднявся. Навпаки — і верхній вузол порахує висоту зі
старого значення.

**Видаляти з AVL-дерева без перебалансування.** У книжці Bae видалення, за словами автора, відрізняється від
звичайного лише оновленням висот, а перебалансування в ньому немає. Після кількох видалень правило AVL перестає
виконуватися.

**Плутати одинарний і подвійний поворот.** Одинарний поворот виправляє піддерево, яке задовге «ззовні». Якщо воно
задовге «зсередини», одинарний поворот лише перекине перекіс на інший бік.

## Перевірте себе

**1. Видаліть 10 з дерева `50B(20R(10B 27B(25R 30R)) 90B(80R 95R))`. Який випадок `RB-DELETE-FIXUP` спрацює і що
вийде?**

<details><summary>Відповідь</summary>

Десять чорне і не має дітей, тож воно виходить само, а на його місце стає сторож `x` із зайвим чорним. Батько `x` —
червоний 20, брат — чорний 27, правий племінник 30 червоний. Це випадок 4: 27 бере колір батька, тобто стає червоним,
20 і 30 фарбуються в чорний, лівий поворот у 20. Результат: `50B(27R(20B(· 25R) 30B) 90B(80R 95R))`. Один поворот.

</details>

**2. Чому, потрапивши у випадок 2 з випадку 1, цикл одразу закінчується?**

<details><summary>Відповідь</summary>

Випадок 1 фарбує батька `x` у червоний. Випадок 2 переносить зайве чорне на батька: `x = x.p`. Новий `x` червоний,
тобто червоно-чорний, а цикл працює лише поки `x` чорний. Тож перевірка циклу не проходить, і рядок 44 фарбує новий
`x` у звичайний чорний.

</details>

**3. Чому видалення з червоно-чорного дерева робить не більше трьох поворотів, хоча цикл може повторюватися `O(lg n)`
разів?**

<details><summary>Відповідь</summary>

Повторюється лише випадок 2, а він не робить поворотів. Будь-який випадок з поворотом закінчує цикл: випадок 4 —
одразу; випадок 3 — переходом у випадок 4; випадок 1 — переходом у випадок 2 з червоним батьком, що закінчує цикл, або
у випадки 3 чи 4. Найдовший ланцюжок — 1, 3, 4, по одному повороту на кожен.

</details>

**4. В AVL-дерево `30(20(10 25) 40(· 50))` вставили 27, а потім 26. Що станеться?**

<details><summary>Відповідь</summary>

Двадцять сім стає правою дитиною 25. Перекіс 25 дорівнює 1, 20 — теж 1, 30 — −1, усе дозволено, поворотів немає.
Двадцять шість іде праворуч від 25 і ліворуч від 27. Тепер перекіс 25 дорівнює 2, а перекіс його правої дитини 27
дорівнює −1: піддерево задовге «зсередини». Подвійний поворот: правий у 27, потім лівий у 25. Вийде `30(20(10 26(25
27)) 40(· 50))`.

</details>

**5. Скільки вузлів щонайменше в AVL-дереві висоти 4?**

<details><summary>Відповідь</summary>

За формулою `F(h) = F(h − 1) + F(h − 2) + 1`: `F(0) = 1`, `F(1) = 2`, `F(2) = 4`, `F(3) = 7`, `F(4) = 12`. Knuth
наводить саме такий приклад: дерево Фібоначчі з 12 внутрішніми вузлами, яке він називає деревом висоти 5, бо рахує ще
рівень зовнішніх вузлів.

</details>

**6. AVL-дерево нижче за червоно-чорне. Чому ж бібліотеки, які називає Morin, обирають червоно-чорне?**

<details><summary>Відповідь</summary>

Різниця у висоті — сталий множник: `1,44 lg n` проти `2 lg n` у найгіршому випадку, а на звичайних даних обидва дерева
мають висоту, близьку до `lg n`. Зате червоно-чорне дерево обмежує повороти на кожну зміну, до двох при вставці і до
трьох при видаленні, а Morin доводить, що сумарна робота виправлень для його варіанта амортизовано стала на операцію.
AVL-дерево може робити `O(log n)` поворотів на одне видалення, і такої амортизованої гарантії Morin для нього не має.
Бібліотека не знає, чого буде більше в програмі, пошуків чи змін, і вибирає дерево з передбачуванішою вартістю змін.

</details>
