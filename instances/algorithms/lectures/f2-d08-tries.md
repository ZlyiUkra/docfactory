# Лекція. Фаза 2, день 8. Префіксні дерева

Ця лекція пояснює дерево, у якому ключ — рядок, і шлях від кореня читає цей рядок по одному символу. Таке дерево
називають префіксним деревом, або trie. Читання займе близько 45 хвилин. Під прикладами коду стоїть справжній вивід з
Node 24.22.

Усі дерева попередніх днів порівнювали ключі цілком: «менше», «більше», «дорівнює». Порівняти два довгі рядки коштує
стільки кроків, скільки в них спільних перших символів. Префіксне дерево ніколи не порівнює ключі цілком. Воно
дивиться на один символ за раз і саме тому вміє те, чого не вміє жодне дерево з попередніх днів: швидко знаходити всі
слова, що починаються з заданих літер.

**Після лекції ви зможете пояснити:**

- як побудоване префіксне дерево і де в ньому «лежать» слова;
- чому пошук слова довжини `m` проходить не більше `m + 1` вузлів, хоч би скільки слів було в дереві;
- чому невдалий пошук зазвичай зупиняється після кількох вузлів;
- скільки пам'яті займає дерево і чому таблиця на весь алфавіт у кожному вузлі — погана ідея;
- як трійкове дерево пошуку і стиснення ланцюжків зменшують пам'ять;
- як двійкове префіксне дерево Morin зберігає цілі числа.

## Навіщо шукати за префіксом

Коли ви набираєте в рядку пошуку «алг», сайт пропонує «алгоритм», «алгебра», «алгоритми сортування». Це запит «усі
слова з цим початком». Маршрутизатор вебфреймворку робить те саме з адресою: шлях `/api/users/42` він розбирає по
частинах і йде від `api` до `users`. Мережевий маршрутизатор шукає для адреси пакета найдовший відомий префікс.

Хеш-таблиця з фази 1 знаходить слово миттєво, але не вміє відповісти «які слова починаються з `алг`»: однакові початки
в ній розкидані по різних кошиках. Відсортований масив уміє, але кожне нове слово треба вставляти посередині, зсуваючи
решту. Префіксне дерево робить обидві речі.

## Як побудоване префіксне дерево

Sedgewick пише, що назву trie запропонував Edward Fredkin 1960 року: це частина слова retrieval, «вибірка». Вимовляють
його як англійське «try», щоб не плутати з tree.

Будова така. Кожне слово записане шляхом від кореня. Перший символ слова вибирає перехід з кореня, другий — перехід з
наступного вузла, і так далі. Слова зі спільним початком мають спільну частину шляху. Вузол, на якому закінчується
слово, має позначку «тут закінчується слово». Позначка потрібна, бо одне слово може бути початком іншого: Laaksonen
наводить приклад THE і THERE, і без позначки дерево не знало б, що THE — теж слово.

Sedgewick підкреслює незвичну річ: самих рядків у дереві немає. Вузол не знає, яке слово йому відповідає. Слово — це
шлях, а символи записані лише на переходах.

Програма нижче будує дерево для речення, яке використовує Sedgewick: «she sells sea shells by the sea shore». Переходи
зберігаються в `Map`, тож дерево приймає будь-які символи. Метод `shape` записує форму дерева рядком: після символу
переходу в дужках ідуть переходи з наступного вузла, а зірочка позначає кінець слова.

```ts
// Вузол префіксного дерева: переходи за символом у Map і позначка «тут закінчується слово».
class TrieNode {
  next = new Map<string, TrieNode>();
  isWord = false;
}

class Trie {
  root = new TrieNode();
  nodes = 1; // корінь

  insert(word: string): void {
    let x = this.root;
    for (const ch of word) { // for...of іде за символами Unicode, а не за половинками UTF-16
      let child = x.next.get(ch);
      if (!child) {
        child = new TrieNode();
        x.next.set(ch, child);
        this.nodes++;
      }
      x = child;
    }
    x.isWord = true;
  }

  // Повертає, чи є слово, і скільки вузлів пройдено до відповіді.
  has(word: string): { found: boolean; visited: number } {
    let x = this.root;
    let visited = 1;
    for (const ch of word) {
      const child = x.next.get(ch);
      if (!child) return { found: false, visited };
      x = child;
      visited++;
    }
    return { found: x.isWord, visited };
  }

  // Рядок, що описує форму дерева: символи переходів у порядку сортування, «*» — кінець слова.
  shape(x: TrieNode = this.root): string {
    const parts = [...x.next.keys()].sort().map((ch) => ch + this.shape(x.next.get(ch)!));
    return (x.isWord ? "*" : "") + (parts.length ? `(${parts.join(" ")})` : "");
  }
}

const words = "she sells sea shells by the sea shore".split(" ");
const a = new Trie();
for (const w of words) a.insert(w);
const b = new Trie();
for (const w of [...words].reverse()) b.insert(w);

console.log("nodes:", a.nodes, " letters in all words:", words.join("").length);
console.log("shape:", a.shape());
console.log("same shape for reversed order:", a.shape() === b.shape());
for (const q of ["shells", "she", "shell", "shore", "shop", "zebra"]) console.log(q.padEnd(7), a.has(q));
```

```
nodes: 20  letters in all words: 30
shape: (b(y*) s(e(a* l(l(s*))) h(e*(l(l(s*))) o(r(e*)))) t(h(e*)))
same shape for reversed order: true
shells  { found: true, visited: 7 }
she     { found: true, visited: 4 }
shell   { found: false, visited: 6 }
shore   { found: true, visited: 6 }
shop    { found: false, visited: 4 }
zebra   { found: false, visited: 1 }
```

Що видно з виводу:

- **Вузлів менше, ніж літер.** У восьми словах 30 літер, а вузлів 20, разом з коренем. Спільні початки зберігаються
  один раз: `she`, `shells` і `shore` ділять вузли `s` і `h`, а слово `sea` трапляється двічі і не займає нового
  місця.
- **Форма не залежить від порядку вставки.** Ті самі слова в оберненому порядку дали те саме дерево. Sedgewick
  доводить це як твердження F і зауважує, що для всіх попередніх дерев пошуку форма залежала від порядку. Treap з дня
  6 досягав незалежності випадковістю, а префіксне дерево — самою будовою.
- **Знайдене слово коштує свою довжину плюс один вузол.** `shells` — 6 літер, 7 вузлів: корінь і по вузлу на літеру.
  Це твердження G у Sedgewick: пошук і вставка звертаються не більше ніж до `m + 1` вузлів для слова довжини `m`.
- **Шлях може існувати, а слова — ні.** Для `shell` дерево пройшло 6 вузлів, але останній не має позначки, бо `shell`
  є лише початком `shells`.
- **Невдалий пошук часто закінчується рано.** `zebra` зупинився в корені, бо з кореня немає переходу `z`. `shop`
  дійшов до `sho` і не знайшов переходу `p`.

## Чому невдалий пошук такий дешевий

Знайдене слово завжди коштує його довжину: інакше не можна переконатися, що всі символи збігаються. Невдалий пошук
зупиняється на першому символі, якого немає. Sedgewick доводить твердження H: якщо `N` ключів — випадкові рядки з
алфавіту з `R` символів, невдалий пошук у середньому оглядає близько `log_R N` вузлів. Довжина ключів не важить.

Пояснення на пальцях. На першому рівні під коренем є щонайбільше `R` різних символів. На глибині `t` різних префіксів
щонайбільше `R^t`. Поки `R^t` набагато менше за `N`, майже всі можливі префікси вже зайняті, і пошук іде далі. Коли
`R^t` перевищує `N`, більшість префіксів порожні, і пошук зупиняється. Межа між цими станами — саме `t ≈ log_R N`.

Перевіримо на випадкових словах з восьми латинських літер, `R = 26`.

```ts
// Вузол префіксного дерева: переходи за символом у Map і позначка «тут закінчується слово».
class TrieNode {
  next = new Map<string, TrieNode>();
  isWord = false;
}

class Trie {
  root = new TrieNode();
  nodes = 1; // корінь

  insert(word: string): void {
    let x = this.root;
    for (const ch of word) { // for...of іде за символами Unicode, а не за половинками UTF-16
      let child = x.next.get(ch);
      if (!child) {
        child = new TrieNode();
        x.next.set(ch, child);
        this.nodes++;
      }
      x = child;
    }
    x.isWord = true;
  }

  // Повертає, чи є слово, і скільки вузлів пройдено до відповіді.
  has(word: string): { found: boolean; visited: number } {
    let x = this.root;
    let visited = 1;
    for (const ch of word) {
      const child = x.next.get(ch);
      if (!child) return { found: false, visited };
      x = child;
      visited++;
    }
    return { found: x.isWord, visited };
  }
}

// mulberry32: стале зерно лише для того, щоб вивід лекції повторювався.
function mulberry32(seed: number): () => number {
  let s = seed >>> 0;
  return () => {
    s = (s + 0x6d2b79f5) >>> 0;
    let t = s;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

const random = mulberry32(5);
const randomWord = (len: number) =>
  Array.from({ length: len }, () => String.fromCharCode(97 + Math.floor(random() * 26))).join("");

for (const n of [1_000, 10_000, 100_000]) {
  const trie = new Trie();
  for (let i = 0; i < n; i++) trie.insert(randomWord(8));
  let visited = 0;
  let misses = 0;
  for (let i = 0; i < 10_000; i++) {
    const r = trie.has(randomWord(8));
    if (!r.found) { visited += r.visited; misses++; }
  }
  console.log(`n=${n}`.padEnd(9), `miss visits ${(visited / misses).toFixed(2)}`,
    ` log26(n) = ${(Math.log(n) / Math.log(26)).toFixed(2)}`, ` nodes ${trie.nodes} of ${8 * n + 1} possible`);
}
```

```
n=1000    miss visits 2.83  log26(n) = 2.12  nodes 6523 of 8001 possible
n=10000   miss visits 3.45  log26(n) = 2.83  nodes 58249 of 80001 possible
n=100000  miss visits 4.20  log26(n) = 3.53  nodes 507471 of 800001 possible
```

Що видно:

- **Кількість відвіданих вузлів росте як логарифм за основою 26.** Від тисячі до ста тисяч слів вона зросла з 2,8 до
  4,2, приблизно на 0,7 за кожне множення на десять: `log₂₆ 10 ≈ 0,71`. Лічильник рахує ще й корінь, тому числа трохи
  більші за `log₂₆ n`.
- **Довжина слів у виводі не з'являється.** Усі слова мають по 8 літер, але невдалий пошук проходить у середньому
  чотири вузли. Sedgewick пише, що в дереві з мільйона випадкових ключів невдалий пошук оглядає три-чотири вузли, хай
  то номери машин із 7 символів чи рахунки з 20 цифр.
- **Пам'ять велика.** Сто тисяч слів дали понад п'ятсот тисяч вузлів. Спільних початків у випадкових словах мало, і
  хвости слів займають по вузлу на літеру.

Справжні слова не випадкові: у них багато спільних початків, тому вузлів відносно менше, а пошук іде трохи глибше.
Sedgewick визнає, що модель випадкових рядків наближена, але пише, що на практиці дерева поводяться приблизно так.

## Пам'ять

Пошук швидкий, а пам'ять — головна ціна. Sedgewick у своєму коді тримає в кожному вузлі масив на `R = 256` посилань,
по одному на кожен можливий символ. Твердження I: посилань у такому дереві від `RN` до `RNw`, де `w` — середня довжина
ключа. Його таблиця показує, що мільйон адрес сайтів довжиною 28 символів вимагає близько 4 мільярдів посилань.

Висновок Sedgewick прямий: не використовуйте таке дерево для великої кількості довгих ключів з великого алфавіту.
Звідси три способи зменшити пам'ять.

**1. Зберігати лише наявні переходи.** Замість масиву на весь алфавіт вузол тримає хеш-таблицю чи `Map` лише з тими
символами, які справді трапилися. Так зроблено в коді цієї лекції. Bae робить так само звичайним об'єктом JavaScript.

**2. Трійкове дерево пошуку.** Sedgewick описує вузол з одним символом і трьома посиланнями: на менші символи, на
рівні і на більші. Набір переходів одного вузла префіксного дерева тут записаний маленьким деревом пошуку з дня 1.
Пам'ять — три посилання на вузол, від `3N` до `3Nw`, зате невдалий пошук робить близько `ln N` порівнянь символів
замість `log_R N`. Sedgewick радить трійкове дерево для великих алфавітів, зокрема для рядків Unicode. Його форма, на
відміну від звичайного префіксного дерева, залежить від порядку вставки, бо кожен вузол — дерево пошуку.

**3. Стиснення ланцюжків.** Довгі слова закінчуються довгими «хвостами», де кожен вузол має одну дитину. Sedgewick
називає це однобічним розгалуженням і показує на прикладі `shells` і `shellfish`: спільний ланцюжок `shell` і два
окремі хвости. Ланцюжок вузлів з однією дитиною можна замінити одним ребром з цілим рядком. Таке стиснене дерево
називають radix-деревом; Sedgewick лишає його у вправах 5.2.11 і 5.2.12.

## Пастка: масив на 26 літер

Найпростіша реалізація з підручника — масив на 26 комірок, індекс — код літери мінус код `a`. Вона працює, поки текст
складається лише з малих латинських літер. Програма нижче вставляє в таке дерево чотири слова і збирає всі слова
перебором 26 комірок, як збирає ключі `collect` у Sedgewick.

```ts
// Пастка: вузол з масивом на 26 латинських літер, індекс — код символу мінус код «a».
class Node26 {
  next: (Node26 | undefined)[] = new Array(26);
  isWord = false;
}

const root = new Node26();
function insert(word: string): void {
  let x = root;
  for (const ch of word) {
    const i = ch.charCodeAt(0) - 97;
    x = x.next[i] ??= new Node26();
  }
  x.isWord = true;
}

// Збирає всі слова, перебираючи 26 комірок кожного вузла, як Sedgewick перебирає R комірок.
function collect(x: Node26, prefix: string, out: string[]): void {
  if (x.isWord) out.push(prefix);
  for (let i = 0; i < 26; i++) {
    const child = x.next[i];
    if (child) collect(child, prefix + String.fromCharCode(97 + i), out);
  }
}

for (const w of ["kyiv", "київ", "café", "Paris"]) insert(w);
const out: string[] = [];
collect(root, "", out);
console.log("collected:", out);
console.log("root array length:", root.next.length);
console.log("index of 'к':", "к".charCodeAt(0) - 97, " index of 'P':", "P".charCodeAt(0) - 97);
console.log("slots for every Unicode code point:", 0x110000, " MB at 8 bytes each:", (0x110000 * 8 / 2 ** 20).toFixed(1));
```

```
collected: [ 'kyiv' ]
root array length: 986
index of 'к': 985  index of 'P': -17
slots for every Unicode code point: 1114112  MB at 8 bytes each: 8.5
```

Розбір:

- **Зібрано одне слово з чотирьох.** `київ`, `café` і `Paris` вставилися, але перебір 26 комірок їх не бачить. Пошук
  `has`, написаний з тією самою арифметикою індексів, знайшов би їх, тож помилка проявляється лише в запитах за
  префіксом. Це найгірший вид помилки: тести на латиниці проходять.
- **Масив кореня виріс до 986 комірок.** Код літери `к` — 1082, мінус 97 дає 985. JavaScript не падає на індексі поза
  масивом, а розширює масив. Java у Sedgewick кинула б виняток.
- **Велика `P` дала індекс −17.** Від'ємний індекс у JavaScript перетворюється на звичайну властивість об'єкта з ім'ям
  `"-17"`. Вона не є елементом масиву, і жоден перебір індексів її не знайде.
- **Масив на весь Unicode неможливий.** Кодових точок 1 114 112. Навіть по 8 байтів на посилання це 8,5 МБ на кожен
  вузол, а вузлів — сотні тисяч.

Висновок: для довільного тексту переходи зберігають у `Map`, як у першій програмі, і проходять рядок `for...of`, який
видає символи Unicode цілком. `charAt` і доступ за індексом повертають половинки UTF-16, і емодзі чи рідкісний
ієрогліф розпадеться на два переходи.

## Двійкове префіксне дерево для чисел

Morin застосовує ту саму ідею до цілих чисел. `BinaryTrie` зберігає числа з `w` бітів. Алфавіт — дві «літери», 0 і 1,
а слово — двійковий запис числа від старшого біта. Шлях іде ліворуч на нулі і праворуч на одиниці, всі листки на
глибині `w`. Morin показує дерево з `w = 4` і числами 3, 9, 12 і 13, тобто `0011`, `1001`, `1100` і `1101`.

Таке дерево вміє більше, ніж «є чи немає». Листки з'єднано в двозв'язний список, а вузол, якому бракує однієї дитини,
має посилання `jump` на найменший чи найбільший листок свого піддерева. Тоді пошук числа, якого немає, за `O(w)`
кроків знаходить найближче більше число. Вартість не залежить від кількості чисел, лише від їхньої довжини в бітах.
Morin будує на цьому структури `XFastTrie` і `YFastTrie`, які план не просить читати.

| Питання | Коротка відповідь |
|---------|-------------------|
| Що таке префіксне дерево? | Дерево, де шлях від кореня записує рядок по символу, а вузол позначено, якщо на ньому закінчується слово. |
| Скільки коштує пошук? | `O(m)` для слова довжини `m`, незалежно від кількості слів; невдалий пошук зазвичай зупиняється за `log_R N` вузлів. |
| Як знайти всі слова з префіксом? | Пройти шлях префікса, а потім обійти піддерево під ним. |
| Чим погане префіксне дерево? | Пам'яттю: масив на весь алфавіт у кожному вузлі дає `R` посилань на вузол. |
| Як зменшити пам'ять? | `Map` лише з наявними переходами, трійкове дерево пошуку, стиснення ланцюжків з однією дитиною. |
| Чому не хеш-таблиця? | Хеш-таблиця не вміє шукати за префіксом і не тримає ключі впорядкованими. |

## Типові помилки

**Масив на 26 літер для довільного тексту.** Це пастка дня. Вивід вище показав, що код не падає, а мовчки губить
слова.

**Забути позначку кінця слова.** Без неї дерево зі словами `shells` вважатиме словом і `shell`, і `she`, і навіть `s`.

**Видаляти слово разом з вузлами, які потрібні іншим словам.** Після видалення `shells` вузол `shell` треба прибрати,
лише якщо він не має інших дітей і сам не є кінцем слова. Sedgewick і Bae видаляють вузли знизу вгору лише за цієї
умови.

**Ходити рядком через `charAt` чи індекс.** Символи поза основною площиною Unicode займають два елементи UTF-16 і
розпадаються на два переходи.

**Збирати всі слова з префіксом, коли потрібні перші десять.** Обхід піддерева можна зупинити, щойно знайдено потрібну
кількість. Інакше запит «a» в словнику на сто тисяч слів пройде пів дерева.

## Практика

Працюйте в проєкті `algo-lab`. Лекція показала вставку і пошук, а збирання слів за префіксом ви пишете самі.

**1. `Trie`** з методами `insert`, `has` і `withPrefix(prefix, limit)`. Переходи — у `Map`, рядок — через `for...of`.
`withPrefix` повертає не більше `limit` слів у порядку, у якому їх видає обхід, і зупиняється, щойно набрала `limit`.

**2. Словник.** Заповніть дерево словником на 100 000 слів. Порахуйте вузли і порівняйте з сумарною кількістю літер.

**3. Порівняння.** Виміряйте час `withPrefix(prefix, 10)` і фільтрації масиву через `startsWith` для префіксів
довжиною 1, 2 і 3 літери. Порівняйте пам'ять дерева з пам'яттю масиву через `process.memoryUsage().heapUsed`.
Передбачте до запуску, хто виграє за часом і хто за пам'яттю.

**4. Тести.** Порожнє дерево; слово, яке є початком іншого; повторна вставка; кирилиця і емодзі; префікс, з якого не
починається жодне слово; `limit` більший за кількість знайдених слів.

**5. Журнал.** Один рядок у `JOURNAL.md` і числа з пунктів 2 і 3 у `MEASUREMENTS.md`.

## Перевірте себе

**1. У дереві лежать слова `car`, `cart`, `care` і `dog`. Скільки в ньому вузлів разом з коренем?**

<details><summary>Відповідь</summary>

Корінь; `c`, `a`, `r` — спільні для трьох слів; `t` і `e` під `r`; `d`, `o`, `g`. Разом `1 + 3 + 2 + 3 = 9`. Позначку
кінця слова мають вузли `r`, `t`, `e` і `g`.

</details>

**2. Чому форма префіксного дерева не залежить від порядку вставки, а форма трійкового дерева пошуку залежить?**

<details><summary>Відповідь</summary>

У префіксному дереві кожен вузол визначається своїм префіксом: вузол для `sh` існує тоді і лише тоді, коли якесь слово
починається з `sh`. Порядок вставки на це не впливає. У трійковому дереві переходи одного вузла записані деревом
пошуку з дня 1, а форма дерева пошуку залежить від порядку вставки.

</details>

**3. Пошук слова з 20 літер у дереві на мільйон слів. Скільки вузлів він пройде, якщо слово є, і приблизно скільки,
якщо його немає?**

<details><summary>Відповідь</summary>

Якщо слово є, 21 вузол: корінь і по вузлу на літеру. Якщо немає, то для випадкових слів з латиниці близько `log₂₆ 10⁶
≈ 4,2` вузли плюс корінь. Невдалий пошук не залежить від довжини слова, бо зупиняється на першому відсутньому
переході.

</details>

**4. Чому `has` у програмі з масивом на 26 комірок знаходить слово `київ`, а `collect` — ні?**

<details><summary>Відповідь</summary>

`insert` і `has` обчислюють індекс однаково, `код − 97`, тому `has` іде тим самим шляхом, що й вставка, і знаходить
вузол. `collect` перебирає лише індекси від 0 до 25 і не заходить у комірку 985, де лежить перехід `к`. Дві частини
коду по-різному уявляють, де можуть лежати переходи.

</details>

**5. Скільки кроків займає пошук найближчого більшого числа в `BinaryTrie` Morin для 32-бітних чисел?**

<details><summary>Відповідь</summary>

`O(w)`, тобто близько 32 кроків вниз деревом, плюс один перехід за `jump` і, можливо, один крок списком листків. Число
збережених значень на це не впливає. Збалансоване дерево пошуку для мільйона чисел зробило б близько `log₂ 10⁶ ≈ 20`
кроків, тож для малої кількості довгих ключів двійкове префіксне дерево не обов'язково швидше.

</details>

**6. Що повертає `longestPrefixOf("shellsort")` у Sedgewick для ключів зі старту лекції і чому?**

<details><summary>Відповідь</summary>

`shells`. Метод іде шляхом рядка і запам'ятовує останній вузол з позначкою слова. На шляху `s-h-e-l-l-s-o` позначені
`she` і `shells`, а переходу `o` після `shells` немає, тож пошук зупиняється, і найдовший знайдений ключ — `shells`.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| префіксне дерево, trie | дерево, у якому шлях від кореня записує рядок по символу |
| префікс | початок рядка, наприклад `sh` для `shells` |
| позначка кінця слова | ознака вузла, на якому закінчується ключ, а не лише його префікс |
| алфавіт, `R` | набір можливих символів і їхня кількість |
| `R`-арне дерево | префіксне дерево, вузол якого тримає масив на всі `R` символів |
| трійкове дерево пошуку | префіксне дерево, у якому переходи вузла записані деревом пошуку з посиланнями «менше», «рівно», «більше» |
| однобічне розгалуження | ланцюжок вузлів з однією дитиною |
| radix-дерево | префіксне дерево, у якому ланцюжки з однією дитиною стиснуто в одне ребро з рядком |
| `BinaryTrie` | двійкове префіксне дерево Morin для цілих чисел з `w` бітів |
