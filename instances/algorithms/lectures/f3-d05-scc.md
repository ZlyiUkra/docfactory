# Лекція. Фаза 3, день 5. Сильно зв'язні компоненти

Учора топологічне сортування впорядковувало граф без циклів, а на графі з циклом лише казало, що цикл є. Сьогодні
цикли перестають заважати. Кожну групу вершин, які досяжні одна з одної, стискають в одну вершину, і граф стає
ациклічним. Такі групи називають сильно зв'язними компонентами. Читання займе близько 45 хвилин. Під прикладом коду
стоїть справжній вивід з Node 24.22.

**Після лекції ви зможете пояснити:**

- що таке сильно зв'язна компонента і граф компонент;
- чому граф компонент завжди ациклічний;
- як алгоритм Косараджу знаходить усі компоненти двома обходами в глибину;
- чому другий обхід іде розвернутим графом і бере вершини за спаданням часу виходу;
- що ламається, якщо взяти інший порядок.

## Взаємна досяжність

В орієнтованому графі з вершини `u` може бути шлях до `v`, а назад шляху може не бути. Erickson називає дві вершини
сильно зв'язаними, якщо кожна досяжна з іншої. Ця ознака поводиться як рівність: вершина зв'язана сама з собою, ознака
симетрична, і якщо `a` зв'язана з `b`, а `b` з `c`, то `a` зв'язана з `c`. Тому вершини розпадаються на групи, що не
перетинаються. Кожна група — сильно зв'язна компонента, найбільша множина вершин, у якій з кожної вершини є шлях до
кожної.

Erickson називає два крайні випадки. Граф сильно зв'язний, якщо компонента одна. Граф ациклічний тоді й лише тоді,
коли кожна компонента складається з однієї вершини.

Уявіть файли проєкту, що імпортують один одного. Якщо `a.ts` імпортує `b.ts`, `b.ts` імпортує `c.ts`, а `c.ts`
імпортує `a.ts`, ці три файли утворюють кругову залежність. Їх неможливо зібрати по одному в порядку залежностей, бо
кожен чекає на інший. Такі три файли — одна компонента. Пункт 3 практики шукає саме такі групи у вашому проєкті.

## Граф компонент

Стисніть кожну компоненту в одну вершину. Ребро між двома новими вершинами проведіть, якщо в початковому графі є хоч
одне ребро з першої компоненти в другу. Вийде граф компонент. CLRS позначає його `G^SCC`, cp-algorithms називає
конденсацією.

Граф компонент завжди ациклічний. Cp-algorithms доводить це так. Якби в ньому був цикл через кілька компонент, то з
кожної з них можна було б дійти до кожної іншої по колу. Тоді всі вони разом були б однією компонентою, а не кількома.
Отже, граф компонент можна топологічно впорядкувати вчорашнім способом.

### Приклад

Граф з 7 вершин і 10 ребер:

```
0 → 1   1 → 2   2 → 0          (цикл 0, 1, 2)
3 → 4   4 → 5   5 → 3          (цикл 3, 4, 5)
0 → 3   2 → 3   5 → 6   1 → 6  (ребра між циклами і до вершини 6)
```

Програма нижче знаходить компоненти прямо за означенням: рахує, хто кого досягає, і об'єднує вершини, що досяжні одна
з одної. Цей спосіб повільний, але очевидно правильний, тому годиться як еталон для тестів на малих графах.

```ts
// Компоненти за означенням: u і v в одній компоненті, якщо u досяжна з v і v досяжна з u.
// Досяжність рахуємо найпростіше: поки щось змінюється, кожне ребро u → v додає до reach[u] усе з reach[v].
// Це повільно, зате очевидно правильно, і годиться як еталон для тестів на малих графах.
type Edge = [number, number];

function reachability(n: number, edges: Edge[]): boolean[][] {
  const reach = Array.from({ length: n }, (_, u) => Array.from({ length: n }, (_, v) => u === v));
  let changed = true;
  let rounds = 0;
  while (changed) {
    changed = false;
    rounds++;
    for (const [u, v] of edges)
      for (let w = 0; w < n; w++)
        if (reach[v][w] && !reach[u][w]) { reach[u][w] = true; changed = true; }
  }
  console.log("rounds until nothing changed:", rounds);
  return reach;
}

function componentsByDefinition(n: number, edges: Edge[]): number[] {
  const reach = reachability(n, edges);
  const comp = new Array<number>(n).fill(-1);
  let count = 0;
  for (let u = 0; u < n; u++) {
    if (comp[u] !== -1) continue;
    for (let v = 0; v < n; v++) if (reach[u][v] && reach[v][u]) comp[v] = count; // взаємна досяжність
    count++;
  }
  return comp;
}

// Граф з лекції: два цикли і окрема вершина.
const edges: Edge[] = [[0, 1], [1, 2], [2, 0], [0, 3], [2, 3], [3, 4], [4, 5], [5, 3], [5, 6], [1, 6]];
const comp = componentsByDefinition(7, edges);
console.log("component of each vertex:", comp.join(" "));

// Граф компонент: ребро між різними компонентами, без повторів.
const condensed = new Set<string>();
for (const [u, v] of edges) if (comp[u] !== comp[v]) condensed.add(`${comp[u]} -> ${comp[v]}`);
console.log("edges between components:", [...condensed].join(", "), " (from", edges.filter(([u, v]) => comp[u] !== comp[v]).length, "edges of G)");
```

```
rounds until nothing changed: 5
component of each vertex: 0 0 0 1 1 1 2
edges between components: 0 -> 1, 1 -> 2, 0 -> 2  (from 4 edges of G)
```

Що видно:

- **Три компоненти.** Компонента 0 — вершини 0, 1, 2. Компонента 1 — вершини 3, 4, 5. Компонента 2 — вершина 6.
- **Граф компонент має 3 ребра, хоча між компонентами йде 4 ребра графа.** Ребра `0 → 3` і `2 → 3` обидва ведуть з
  компоненти 0 в компоненту 1 і дають одне ребро графа компонент. CLRS у вправі 20.5-5 прямо вимагає, щоб між двома
  компонентами було не більше одного ребра.
- **Граф компонент ациклічний.** Його порядок `0, 1, 2`: спершу цикл 0, 1, 2, потім цикл 3, 4, 5, потім вершина 6.
- **Еталон дорогий.** Кожен раунд проходить усі ребра для кожної вершини, а раундів може бути до `V`. Це `O(V²E)`.
  Erickson описує трохи кращий прямий спосіб: компонента вершини `v` — це перетин множини вершин, досяжних з `v`, і
  множини вершин, з яких досяжна `v`. Але для всіх компонент він теж коштує `O(VE)`.

## Головна властивість часу виходу

Алгоритм Косараджу спирається на час виходу з учорашнього і позавчорашнього днів. Запустіть пошук у глибину з
обгорткою на всьому графі і для кожної компоненти візьміть найбільший час виходу її вершин. CLRS доводить у лемі
20.14: якщо в графі є ребро з компоненти `C′` у компоненту `C`, то найбільший час виходу `C′` більший, ніж у `C`.

Чому так. Можливі два випадки.

- **Обхід спершу увійшов у `C′`.** У цю мить усі вершини обох компонент білі. З першої вершини `C′` є білий шлях до
  кожної вершини `C′` і, через ребро, до кожної вершини `C`. За теоремою про білий шлях усі вони стануть нащадками
  цієї вершини, і з неї обхід вийде останнім.
- **Обхід спершу увійшов у `C`.** З `C` не можна дійти до `C′`, інакше дві компоненти були б однією. Тому обхід вийде
  з усієї `C`, не торкнувшись `C′`, і в `C′` увійде пізніше.

Отже, ребра графа компонент ведуть від компонент з більшим часом виходу до компонент з меншим. Вершина з найбільшим
часом виходу в усьому графі лежить у компоненті, в яку не входить жодне ребро з інших компонент. Erickson називає таку
компоненту джерелом графа компонент.

## Алгоритм Косараджу

Якщо запустити обхід з вершини компоненти-джерела у звичайному графі, він вийде за межі компоненти: з джерела ребра
ведуть в інші компоненти. Тут допомагає розвернутий граф, у якому кожне ребро `u → v` замінено на `v → u`. CLRS пише,
що в розвернутого графа ті самі компоненти, бо взаємна досяжність від розвороту не змінюється. А граф компонент теж
розвертається, тож джерело стає стоком, з якого жодне ребро не виходить. Обхід розвернутого графа з вершини стоку
відвідає рівно свою компоненту.

Звідси алгоритм у трьох кроках, як у CLRS:

1. Пошук у глибину з обгорткою на графі `G`, записати час виходу кожної вершини.
2. Побудувати розвернутий граф `G^T`. Це коштує `Θ(V + E)`.
3. Пошук у глибину з обгорткою на `G^T`, але обгортка перебирає вершини за спаданням часу виходу з кроку 1. Кожне
   дерево цього обходу — одна компонента.

Після першої компоненти обгортка бере наступну ще не відвідану вершину з найбільшим часом виходу. Вона лежить у
компоненті, з якої в `G^T` ребра ведуть лише в уже знайдені компоненти, тож обхід знову не виходить за межі своєї
компоненти. CLRS доводить це індукцією за кількістю знайдених дерев у теоремі 20.16. Обидва обходи і розворот коштують
`O(V + E)`.

Erickson пише той самий алгоритм у дзеркальному вигляді: перший обхід іде розвернутим графом, другий — звичайним.
Обидва варіанти правильні з тієї самої причини. Cp-algorithms і Erickson згадують, що алгоритм знайшли незалежно
Kosaraju і Sharir. Erickson уточнює роки: Kosaraju у 1978 році, але не опублікував, а Sharir — у 1981.

### Обхід вручну

Перший обхід графа з прикладу, сусіди за зростанням:

```
вхід 0, вхід 1, вхід 2, вхід 3, вхід 4, вхід 5, вхід 6,
вихід 6, вихід 5, вихід 4, вихід 3, вихід 2, вихід 1, вихід 0
```

Обхід пішов ланцюжком `0 → 1 → 2 → 3 → 4 → 5 → 6`, бо в кожної вершини перший білий сусід веде далі. Порядок виходу:
`6, 5, 4, 3, 2, 1, 0`. За спаданням часу виходу: `0, 1, 2, 3, 4, 5, 6`.

Розвернутий граф, сусіди за зростанням:

```
0: [2]   1: [0]   2: [1]   3: [0, 2, 5]   4: [3]   5: [4]   6: [1, 5]
```

Другий обхід:

| Обгортка бере | Обхід відвідує | Що зупиняє | Компонента |
|---|---|---|---|
| 0 | 0, 2, 1 | з 1 ребро лише до 0, вже відвіданої | `{0, 1, 2}` |
| 1, 2 | — | уже відвідані | — |
| 3 | 3, 5, 4 | ребра з 3 до 0 і 2 ведуть у знайдену компоненту | `{3, 4, 5}` |
| 4, 5 | — | уже відвідані | — |
| 6 | 6 | ребра до 1 і 5 ведуть у знайдені компоненти | `{6}` |

Обхід і таблицю перевірено програмою. Компоненти збіглися з еталоном. Зверніть увагу на рядок вершини 3: у
розвернутому графі з неї є ребра до 0 і 2, але ці вершини вже відвідані. Саме порядок обходу гарантує, що компонента,
куди ведуть такі ребра, вже знайдена.

CLRS додає корисний наслідок: другий обхід знаходить компоненти в топологічному порядку графа компонент. Тут це `{0,
1, 2}`, `{3, 4, 5}`, `{6}`, тобто той самий порядок, що й у висновку програми.

## Пастка: не той порядок у другому обході

Другий обхід мусить брати вершини за спаданням часу виходу. Інший порядок може злити кілька компонент в одну.

**Порядок входу замість порядку виходу.** Найменший приклад — дві вершини і одне ребро `1 → 0`. Компонент дві: `{0}` і
`{1}`. Перший обхід входить у 0, виходить з 0, потім входить у 1 і виходить з 1. За спаданням часу виходу: `1, 0`. У
розвернутому графі ребро `0 → 1`. Другий обхід з 1 нікуди не йде, і компонента `{1}`. Потім з 0: вершина 1 вже
відвідана, компонента `{0}`. Правильно.

Тепер візьміть порядок входу: `0, 1`. Другий обхід почне з 0 і пройде розвернутим ребром до 1. Вийде одна компонента
`{0, 1}`, хоча з 0 до 1 у початковому графі шляху немає. На графі з прикладу лекції порядок входу випадково збігся з
порядком виходу навпаки, і помилка не проявилася б. Це ще одна причина перевіряти реалізацію еталоном на багатьох
випадкових графах.

**Зростання часу виходу замість спадання.** На графі з прикладу другий обхід почав би з вершини 6. У розвернутому
графі з 6 є ребра до 1 і 5, а звідти досяжне все. Усі сім вершин злилися б в одну компоненту. CLRS у вправі 20.5-3
пропонує подумати про схожу зміну професора Бекона: другий обхід іде не розвернутим, а звичайним графом за зростанням
часу виходу.

## Типові помилки

**Не той порядок у другому обході.** Це пастка дня: порядок входу чи зростання часу виходу зливає компоненти.

**Другий обхід звичайним графом.** Без розвороту обхід з компоненти-джерела відвідає все, куди з неї ведуть ребра.

**Скидати лічильник часу між запусками обгортки.** Cp-algorithms наголошує, що лічильник не скидають: час виходу
мусить порівнюватися між різними деревами першого обходу.

**Повторні ребра в графі компонент.** Кілька ребер між тими самими компонентами треба звести до одного, як вимагає
вправа 20.5-5 CLRS.

**Вважати кожну компоненту циклом.** Компонента з однієї вершини без петлі — не кругова залежність. Для пункту 3
практики шукайте компоненти з кількох вершин і вершини з ребром самі в себе.

**Рекурсія на великому графі.** Обидва обходи мають ту саму межу глибини, що й у дні 3.

самі.

еталоном за означенням на сотнях малих випадкових графів.

## Перевірте себе

**1. Граф: `0 → 1`, `1 → 0`, `1 → 2`, `2 → 3`, `3 → 2`. Які компоненти і який граф компонент?**

<details><summary>Відповідь</summary>

Компоненти `{0, 1}` і `{2, 3}`. Граф компонент має одне ребро, з `{0, 1}` у `{2, 3}`, бо ребро `1 → 2` йде між ними, а
назад ребер немає. Це перевірка з плану: два цикли, з'єднані одним ребром.

</details>

**2. Як може змінитися кількість компонент, якщо додати одне ребро?**

<details><summary>Відповідь</summary>

Вона може лишитися тією самою або зменшитися, але не збільшитися. Нове ребро не руйнує жодного шляху, тож вершини, що
були взаємно досяжні, такими й лишаються. Якщо ребро замикає цикл через кілька компонент, усі компоненти на цьому
циклі зливаються в одну. Це вправа 20.5-1 CLRS.

</details>

**3. Чому в графі без циклів кожна вершина — окрема компонента?**

<details><summary>Відповідь</summary>

Якби дві різні вершини `u` і `v` були в одній компоненті, існували б шляхи `u ⇝ v` і `v ⇝ u`. Разом вони утворюють
цикл. У графі без циклів такого немає.

</details>

**4. Скільки разів алгоритм Косараджу проходить кожне ребро?**

<details><summary>Відповідь</summary>

Тричі: перший обхід розглядає його в `G`, побудова `G^T` записує його розвернутим, другий обхід розглядає його в
`G^T`. Кожне з трьох проходжень коштує `O(1)`, тому разом `O(V + E)`.

</details>

**5. Чому вершина з найбільшим часом виходу першого обходу лежить у компоненті, в яку не входять ребра з інших
компонент?**

<details><summary>Відповідь</summary>

За лемою 20.14 CLRS ребро з компоненти `C′` у компоненту `C` означає, що найбільший час виходу `C′` більший, ніж у
`C`. Якби в компоненту цієї вершини входило ребро з іншої компоненти, та інша мала б ще більший час виходу, а більшого
немає.

</details>

**6. У розвернутому графі з прикладу є ребро `3 → 0`. Чому другий обхід, почавши з вершини 3, не пішов до 0?**

<details><summary>Відповідь</summary>

Вершину 0 вже відвідав перший запуск другого обходу, і вона належить знайденій компоненті `{0, 1, 2}`. Обхід не
заходить у відвідані вершини. Порядок за спаданням часу виходу гарантує, що кожне ребро розвернутого графа, яке
виходить з поточної компоненти, веде в уже знайдену компоненту.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| сильно зв'язні вершини | вершини, кожна з яких досяжна з іншої |
| сильно зв'язна компонента | найбільша множина вершин, де кожна досяжна з кожної |
| граф компонент, конденсація | граф, у якому кожна компонента стала однією вершиною |
| розвернутий граф `G^T` | той самий граф з усіма ребрами в протилежному напрямку |
| джерело, стік | вершина, в яку не входить жодне ребро; вершина, з якої не виходить жодне ребро |
| алгоритм Косараджу | два обходи в глибину: на `G` для часу виходу і на `G^T` у порядку спадання цього часу |
