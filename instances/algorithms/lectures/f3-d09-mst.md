## Кістякове дерево

Конспект MIT 6.046J нагадує: дерево — зв'язний граф без циклів. Кістякове дерево графа — набір його ребер, що з'єднує
всі вершини і не має циклів. У дереві з `V` вершинами рівно `V − 1` ребро. Менше ребер не з'єднає всіх вершин, а
більше неминуче утворить цикл.

Мінімальне кістякове дерево зв'язного неорієнтованого графа з вагами — кістякове дерево з найменшою сумою ваг. Ваги
можуть бути будь-якими, навіть від'ємними: Erickson прямо це дозволяє. На відміну від найкоротших шляхів, від'ємні
ваги тут нічого не ламають.

Перебрати всі кістякові дерева не вийде. Конспект MIT показує, що їх буває експоненційно багато. Програма нижче
перебирає їх для трьох малих графів, щоб побачити, скільки їх і скільки серед них мінімальних.

```ts
// Еталон перебором: перебрати всі набори з V − 1 ребер, залишити ті, що не мають циклу (це кістякові дерева),
// і знайти найменшу суму ваг. Годиться лише для малих графів: наборів стає дуже багато.
type Edge = [number, number, number]; // [u, v, вага]

function* combinations<T>(items: T[], k: number, start = 0, picked: T[] = []): Generator<T[]> {
  if (picked.length === k) { yield picked; return; }
  for (let i = start; i < items.length; i++) yield* combinations(items, k, i + 1, [...picked, items[i]]);
}

function isSpanningTree(n: number, edges: Edge[]): boolean {
  const parent = Array.from({ length: n }, (_, i) => i);
  const find = (x: number): number => (parent[x] === x ? x : find(parent[x]));
  for (const [u, v] of edges) {
    const a = find(u), b = find(v);
    if (a === b) return false; // ребро замикає цикл
    parent[a] = b;
  }
  return true; // V − 1 ребро без циклу з'єднують усі V вершин
}

function survey(name: string, n: number, edges: Edge[]): void {
  let trees = 0, best = Infinity, bestCount = 0;
  for (const set of combinations(edges, n - 1)) {
    if (!isSpanningTree(n, set)) continue;
    trees++;
    const w = set.reduce((s, [, , c]) => s + c, 0);
    if (w < best) { best = w; bestCount = 1; } else if (w === best) bestCount++;
  }
  console.log(`${name}: V=${n} E=${edges.length}  spanning trees=${trees}  min weight=${best}  minimum trees=${bestCount}`);
}

const lecture: Edge[] = [[0, 1, 4], [0, 2, 3], [1, 2, 1], [1, 3, 2], [2, 3, 4], [3, 4, 2], [4, 5, 6], [3, 5, 5], [2, 4, 7]];
survey("lecture graph", 6, lecture);

const square: Edge[] = [[0, 1, 1], [1, 2, 1], [2, 3, 1], [3, 0, 1]]; // квадрат з однаковими вагами
survey("square, equal weights", 4, square);

const k5: Edge[] = [];
for (let u = 0; u < 5; u++) for (let v = u + 1; v < 5; v++) k5.push([u, v, 1 + ((u * 7 + v * 3) % 4)]);
survey("K5, weights 1..4", 5, k5);
```

```
lecture graph: V=6 E=9  spanning trees=55  min weight=13  minimum trees=1
square, equal weights: V=4 E=4  spanning trees=4  min weight=3  minimum trees=4
K5, weights 1..4: V=5 E=10  spanning trees=125  min weight=6  minimum trees=2
```

Що видно:

- **Граф з 6 вершин і 9 ребер має 55 кістякових дерев.** Повний граф з 5 вершин — уже 125. Для тисяч вершин перебір
  неможливий.
- **Мінімальне дерево графа з лекції одне, вагою 13.** Його знайдуть обидва алгоритми нижче.
- **Квадрат з однаковими вагами має 4 мінімальні дерева.** Кожне з них — квадрат без одного ребра, і всі важать 3.
  Erickson пише саме про це: якщо всі ваги однакові, мінімальне кожне кістякове дерево.
- **Повний граф з 5 вершин має 2 мінімальні дерева однакової ваги 6.** Тому пункт 3 практики порівнює суму ваг і
  кількість ребер, а не самі набори ребер.

Erickson доводить, що мінімальне дерево єдине, якщо всі ваги різні. Навпаки — не обов'язково: граф з повторами ваг теж
може мати єдине мінімальне дерево, як граф з лекції, де дві ваги 2 і дві ваги 4.

## Розріз і безпечне ребро

Обидва алгоритми спираються на одну властивість. Поділіть вершини графа на дві групи, `S` і решту. Такий поділ
називають розрізом. Ребро перетинає розріз, якщо його кінці в різних групах. Найлегше з таких ребер CLRS називає
легким ребром розрізу.

**Властивість розрізу.** Легке ребро будь-якого розрізу входить у якесь мінімальне кістякове дерево. CLRS доводить це
в теоремі 21.1, конспект MIT — у лемі 2, Erickson приписує це спостереження Приму. Доведення через обмін:

1. Візьміть мінімальне дерево `T`, у якому немає легкого ребра `e = u–v`.
2. У `T` є шлях від `u` до `v`. Кінці `e` лежать по різні боки розрізу, тож на цьому шляху є ребро `e′`, яке теж
   перетинає розріз.
3. Заберіть з `T` ребро `e′` і додайте `e`. Вийде знову кістякове дерево.
4. Його вага `w(T) − w(e′) + w(e)`. Оскільки `e` найлегше серед ребер розрізу, `w(e) ≤ w(e′)`, і нове дерево не важче
   за `T`. Отже, воно теж мінімальне, і в ньому є `e`.

CLRS будує на цьому загальний жадібний алгоритм: тримати набір ребер `A`, який лежить у якомусь мінімальному дереві, і
додавати по одному безпечному ребру, тобто такому, що після нього `A` теж лежить у якомусь мінімальному дереві.
Erickson називає це «єдиним алгоритмом мінімального кістякового дерева»: майже всі відомі алгоритми — його варіанти.
Вони відрізняються лише тим, який розріз беруть.

## Алгоритм Крускала

Крускал бере ребра за зростанням ваги. Ребро беруть, якщо його кінці лежать у різних деревах поточного лісу, і
пропускають, якщо кінці вже з'єднані, бо тоді ребро замкнуло б цикл. Чому взяте ребро безпечне: розріз «дерево одного
кінця проти решти» ребра лісу не перетинають, а це ребро — найлегше з тих, що його перетинають, бо всі легші вже
розглянуто.

Перевірку «чи в одному дереві» робить union-find з дня 10 фази 2: `find` для обох кінців, `union`, якщо ребро взяли.

Обхід вручну на графі з програми:

| Ребро | Вага | Дія | Чому |
|---|---|---|---|
| `1–2` | 1 | взяти | 1 і 2 в різних деревах |
| `1–3` | 2 | взяти | |
| `3–4` | 2 | взяти | |
| `0–2` | 3 | взяти | |
| `0–1` | 4 | пропустити | 0 і 1 уже з'єднані через 2 |
| `2–3` | 4 | пропустити | 2 і 3 уже з'єднані через 1 |
| `3–5` | 5 | взяти | |
| `4–5` | 6 | пропустити | |
| `2–4` | 7 | пропустити | |

Взято 5 ребер, тобто `V − 1`, вага `1 + 2 + 2 + 3 + 5 = 13`. Таблицю перевірено програмою. Cp-algorithms радить
зупинитися, щойно взято `V − 1` ребро: решту ребер можна не переглядати.

**Вартість.** Сортування ребер коштує `O(E log E)`. Операції union-find з об'єднанням за рангом і стисненням шляху
коштують майже сталу величину на операцію, `O(α(V))` у середньому за серію. CLRS підсумовує: сортування переважає, і
разом `O(E log E) = O(E log V)`, бо `E < V²`. Конспект MIT додає: якщо ваги — цілі числа з невеликого діапазону,
сортування можна зробити за `O(E)`, і тоді Крускал швидший за Прима.

Erickson розповідає історію. Kruskal описав алгоритм у 1956 році, після того як побачив переклад праці Borůvka і
вирішив, що вона «unnecessarily elaborate». Borůvka описав перший алгоритм мінімального дерева ще в 1926 році.

## Алгоритм Прима

Прим вирощує одне дерево. Він починає з однієї вершини і щоразу додає найлегше ребро, що з'єднує дерево з вершиною
поза ним. Розріз тут — «дерево проти решти», і додане ребро — легке ребро цього розрізу.

Будова майже така сама, як у Дейкстри. Купа зберігає вершини поза деревом, а ключ вершини — вага найлегшого ребра від
неї до дерева. CLRS наголошує на різниці: Дейкстра ставить ключем довжину всього шляху від джерела, `dist[u] + w`, а
Прим — вагу одного ребра, `w`.

Як і вчора, без операції «зменшити ключ» можна класти в купу нові записи і пропускати застарілі. Обхід вручну з
вершини 0, у купі ребра, що виходять з дерева:

| Дістали з купи | Дія | Дерево після кроку |
|---|---|---|
| `0–2` (3) | додати 2 | `{0, 2}` |
| `2–1` (1) | додати 1 | `{0, 1, 2}` |
| `1–3` (2) | додати 3 | `{0, 1, 2, 3}` |
| `3–4` (2) | додати 4 | `{0, 1, 2, 3, 4}` |
| `0–1` (4) | застаріле: 1 уже в дереві | |
| `2–3` (4) | застаріле | |
| `3–5` (5) | додати 5 | усі 6 вершин |
| `4–5` (6), `2–4` (7) | застарілі | |

Ті самі 5 ребер і вага 13, але в іншому порядку. Таблицю перевірено програмою.

**Вартість.** Із двійковою купою `O(E log V)`, як у Крускала. З масивом і переглядом усіх вершин `O(V²)`, що краще для
щільного графа; CLRS пропонує це у вправі 21.2-2. З купою Фібоначчі `O(E + V log V)`. Erickson додає, що на практиці
купа Фібоначчі рідко швидша за двійкову, хіба що граф дуже великий і щільний.

Erickson розповідає й про ім'я. Першим цей алгоритм описав Vojtěch Jarník у листі до Borůvka в 1929 році, а Prim
знайшов його знову в 1957, Dijkstra — у 1958. Тому Erickson називає його алгоритмом Ярника.

## Пастка: незв'язний граф

Мінімальне кістякове дерево існує лише для зв'язного графа. Що буде на незв'язному?

Приберіть з графа лекції ребра `3–5` і `4–5`. Вершина 5 стала окремою.

- **Прим з вершини 0** додасть вершини 2, 1, 3, 4 і зупиниться, бо купа спорожніє. Вийде дерево з 5 вершин і 4 ребер.
  Вершина 5 просто не з'явиться, і алгоритм нічого про це не скаже.
- **Крускал** візьме ті самі 4 ребра і пройде весь список. Результат — ліс з двох дерев: дерево з 5 вершин і окрема
  вершина 5. Він дасть мінімальне кістякове дерево кожної частини, тобто мінімальний кістяковий ліс.

В обох випадках ребер менше за `V − 1`. Ця перевірка і ловить пастку: після алгоритму порівняйте кількість ребер з `V
− 1`. Якщо менше, граф незв'язний, і дерева для нього немає.

## Для співбесіди

| Питання | Коротка відповідь |
|---------|-------------------|
| Що таке мінімальне кістякове дерево? | Набір ребер, що з'єднує всі вершини без циклів і має найменшу суму ваг. |
| Скільки в ньому ребер? | `V − 1`. |
| На чому тримаються алгоритми? | Легке ребро будь-якого розрізу входить у якесь мінімальне дерево. |
| Як працює Крускал? | Ребра за зростанням ваги; брати, якщо не замикає цикл; перевірка — union-find. |
| Як працює Прим? | Вирощувати дерево, щоразу додаючи найлегше ребро з дерева назовні; купа. |
| Скільки коштують? | Обидва `O(E log V)`; Прим з масивом `O(V²)`. |
| Чи єдине дерево? | Якщо всі ваги різні — так; інакше їх може бути кілька, але вага в усіх однакова. |
| Чим Прим відрізняється від Дейкстри? | Ключ — вага одного ребра, а не довжина шляху від джерела. |

## Типові помилки

**Прим на незв'язному графі.** Це пастка дня: дерево охоплює лише частину вершин, а помилки немає.

**Плутати ключ Прима з ключем Дейкстри.** Якщо записати `dist[u] + w`, вийде дерево найкоротших шляхів, а не
мінімальне кістякове дерево. Вони різні.

**Порівнювати набори ребер у тестах.** Якщо ваги повторюються, правильні реалізації можуть дати різні дерева.
Порівнюйте вагу і кількість ребер.

**Застосовувати до орієнтованого графа.** Обидва алгоритми — для неорієнтованих графів. Для орієнтованих задача інша.

**Union-find без прийомів.** Без об'єднання за рангом і стиснення шляху `find` може коштувати `O(V)`, як показала фаза
2.

## Перевірте себе

**1. Граф: `a–b` (1), `b–c` (2), `a–c` (3), `c–d` (1). Знайдіть мінімальне кістякове дерево Крускалом.**

<details><summary>Відповідь</summary>

За зростанням: `a–b` (1) взяти, `c–d` (1) взяти, `b–c` (2) взяти, `a–c` (3) пропустити, бо `a` і `c` вже з'єднані
через `b`. Дерево `a–b`, `c–d`, `b–c` вагою 4.

</details>

**2. Чи входить найлегше ребро всього графа в якесь мінімальне дерево?**

<details><summary>Відповідь</summary>

Так. Візьміть розріз «один кінець цього ребра проти решти». Ребро перетинає розріз і легше за всі інші ребра графа,
тож і за ті, що перетинають розріз. За властивістю розрізу воно входить у якесь мінімальне дерево. Це вправа 21.1-1
CLRS.

</details>

**3. Чи може найважче ребро графа входити в мінімальне дерево?**

<details><summary>Відповідь</summary>

Так, якщо без нього граф розпадається. Наприклад, у ланцюжку `a–b` (1), `b–c` (100) ребро вагою 100 — єдиний зв'язок з
`c`, і воно в дереві. Але найважче ребро будь-якого циклу можна не брати: CLRS доводить це у вправі 21.1-5.

</details>

**4. Чому від'ємні ваги не ламають Крускала і Прима, хоча ламають Дейкстру?**

<details><summary>Відповідь</summary>

Обидва алгоритми лише порівнюють ваги окремих ребер, а не суми вздовж шляху. Доведення властивості розрізу теж
порівнює два ребра, `w(e) ≤ w(e′)`, і від знака ваг не залежить. Якщо додати до всіх ваг одне число, кожне кістякове
дерево подорожчає на `(V − 1)` разів це число, і найлегше лишиться найлегшим.

</details>

**5. Граф щільний: 3000 вершин і 4 мільйони ребер. Який алгоритм швидший?**

<details><summary>Відповідь</summary>

Прим з масивом: `O(V²) = 9 · 10⁶` кроків. Крускалу треба відсортувати 4 мільйони ребер, `O(E log E)`, близько `9 ·
10⁷`. Прим з двійковою купою дав би `O(E log V)`, теж близько `5 · 10⁷`.

</details>

**6. Конспект MIT каже, що найшвидший відомий алгоритм мінімального дерева працює за очікуваний `O(V + E)`. Чому
Крускал і Прим досі потрібні?**

<details><summary>Відповідь</summary>

Той алгоритм (Karger, Klein, Tarjan, 1993) випадковий і складний. Крускал і Прим прості, детерміновані і на практиці
досить швидкі: `O(E log V)` відрізняється від лінійного часу лише логарифмом.

</details>
