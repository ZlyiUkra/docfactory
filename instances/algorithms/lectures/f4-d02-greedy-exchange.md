# Лекція. Фаза 4, день 2. Жадібні алгоритми й аргумент обміну

Касир дає решту 30 копійок. Він не перебирає варіанти: бере найбільшу монету, яка вміщується в суму, потім знову
найбільшу для залишку, і так до кінця. Для одних наборів монет це дає найменшу кількість монет. Для інших той самий
спосіб видає зайві. Спосіб «бери найкраще зараз і не передумуй» називають жадібним алгоритмом. Він найпростіший з усіх
прийомів цієї фази і найпідступніший: неправильний жадібний алгоритм виглядає так само переконливо, як правильний.
Сьогодні ви навчитеся відрізняти один від другого. Читання займе близько 45 хвилин. Під кожним прикладом коду стоїть
справжній вивід з Node 24.22.

**Після лекції ви зможете пояснити:**

- що таке жадібний алгоритм і чим він відрізняється від перебору;
- чому жадібний вибір буває неправильним, на прикладі монет;
- яке жадібне правило розв'язує задачу про вибір заявок;
- як працює доказ «жадібний іде попереду»;
- як працює аргумент обміну;
- як за секунди знайти контрприклад до неправильного жадібного правила.

## Що таке жадібний алгоритм

Жадібні алгоритми розв'язують оптимізаційні задачі. Так називають задачі, де серед багатьох можливих розв'язків треба
знайти найкращий: найкоротший, найдешевший, найбільший. Найкращий розв'язок називають оптимальним.

Розв'язок оптимізаційної задачі зазвичай складається з низки виборів. Щоб дати решту, треба вибрати першу монету,
потім другу, і так далі. Перебір пробує всі можливі низки виборів і порівнює результати. Жадібний алгоритм робить
інакше. CLRS описує його одним реченням: на кожному кроці він робить вибір, який виглядає найкращим у цю мить.
Зроблений вибір він уже ніколи не переглядає.

Книжка Beyond Cracking the Coding Interview, далі BCtCI, порівнює жадібний алгоритм з дитиною за обідом, яка починає з
найсмачнішого і не думає, що буде далі.

З цього випливають і сила, і слабкість прийому. Жадібний алгоритм швидкий, бо не повертається назад: зазвичай він
сортує вхідні дані за однією ознакою і проходить по них один раз, тому працює за `O(n log n)`. І він ризикований, бо
найкращий вибір зараз може зіпсувати все, що буде потім.

## Монети: жадібність, яка помиляється

Задача: набрати задану суму найменшою кількістю монет. Монет кожного номіналу скільки завгодно. Жадібне правило
очевидне: щоразу брати найбільшу монету, яка ще вміщується.

Візьмемо монети 1, 3 і 4 і суму 6. Жадібне правило бере 4, і залишається 2. Монета 3 вже не вміщується, тому далі
йдуть дві монети по 1. Разом три монети: 4 + 1 + 1. А найкраще — дві монети: 3 + 3. Перший вибір виглядав найкращим і
зіпсував решту.

Наступна програма порівнює жадібне правило з повним перебором для трьох наборів монет і для всіх сум від 1 до 30.

```ts
// Жадібний спосіб: щоразу брати найбільшу монету, яка ще вміщується в залишок.
// У кожному наборі є монета 1, тому залишок завжди можна добрати до кінця.
function greedyCoins(coins: number[], amount: number): number[] {
  const fromLargest = [...coins].sort((a, b) => b - a);
  const taken: number[] = [];
  let rest = amount;
  for (const coin of fromLargest) {
    while (rest >= coin) {
      taken.push(coin);
      rest -= coin;
    }
  }
  return taken;
}

// Повний перебір: спробувати кожну монету першою, решту суми набрати так само,
// і з усіх варіантів залишити найкоротший. Цей спосіб не може помилитися, але він повільний.
function bestCoins(coins: number[], amount: number): number[] {
  if (amount === 0) {
    return [];
  }
  let best: number[] = new Array<number>(amount).fill(1); // найгірший варіант: самі одиниці
  for (const coin of coins) {
    if (coin <= amount) {
      const candidate = [coin, ...bestCoins(coins, amount - coin)];
      if (candidate.length < best.length) {
        best = candidate;
      }
    }
  }
  return best;
}

for (const coins of [[1, 3, 4], [1, 5, 10, 25], [1, 10, 25]]) {
  const failures: string[] = [];
  for (let amount = 1; amount <= 30; amount += 1) {
    const greedy = greedyCoins(coins, amount);
    const best = bestCoins(coins, amount);
    if (greedy.length > best.length) {
      failures.push(`${amount}: жадібно ${greedy.join('+')}, найкраще ${best.join('+')}`);
    }
  }
  console.log(`монети ${coins.join(', ')}: жадібний спосіб програв на ${failures.length} сумах із 30`);
  for (const line of failures.slice(0, 3)) {
    console.log(`  ${line}`);
  }
}
```

```
монети 1, 3, 4: жадібний спосіб програв на 7 сумах із 30
  6: жадібно 4+1+1, найкраще 3+3
  10: жадібно 4+4+1+1, найкраще 3+3+4
  14: жадібно 4+4+4+1+1, найкраще 3+3+4+4
монети 1, 5, 10, 25: жадібний спосіб програв на 0 сумах із 30
монети 1, 10, 25: жадібний спосіб програв на 1 сумах із 30
  30: жадібно 25+1+1+1+1+1, найкраще 10+10+10
```

Що видно у виводі.

**З монетами 1, 3 і 4 жадібне правило помиляється на 7 сумах із 30.** Перша така сума — 6, і це приклад, розібраний
вище. На решті 23 сум правило дає правильну відповідь. Якби ви перевірили його на сумах 1, 2, 3, 4 і 5, помилки ви б
не побачили.

**З монетами 1, 5, 10 і 25 помилок немає.** Це набір, з яким жадібний касир має рацію на всіх перевірених сумах.

**Досить прибрати одну монету, і правило ламається.** Без монети 5 суму 30 жадібне правило набирає шістьма монетами, а
три монети по 10 дають її трьома.

**Практичний висновок:** правильність жадібного правила залежить від задачі і навіть від вхідних даних, а не від того,
наскільки розумним воно здається. Тому жадібний алгоритм завжди потребує одного з двох: доказу, що він правильний, або
контрприкладу, що він неправильний. Приклад з монетами 1, 3 і 4 запишіть у `PATTERNS.md` як застереження.

Функція `bestCoins` робить повний перебір і працює дуже повільно: для великих сум кількість її викликів росте
експоненційно. У день 4 цієї фази ви навчитеся робити такий перебір швидким.

## Задача про вибір заявок

Тепер задача, де жадібне правило працює. Є одна кімната для зустрічей. На день подано дев'ять заявок, і кожна має час
початку і час кінця. Дві зустрічі не можуть іти в кімнаті одночасно. Треба задовольнити якнайбільше заявок.

| Заявка | Початок | Кінець |
|--------|---------|--------|
| 1 | 9 | 11 |
| 2 | 10 | 12 |
| 3 | 11 | 13 |
| 4 | 10 | 14 |
| 5 | 12 | 15 |
| 6 | 13 | 16 |
| 7 | 14 | 17 |
| 8 | 16 | 18 |
| 9 | 15 | 18 |

Дві заявки називають сумісними, якщо їхні проміжки часу не перетинаються. У цій лекції зустріч займає кімнату від
свого початку включно до кінця, не включаючи сам кінець. Тому заявка 1, яка закінчується об 11, сумісна із заявкою 3,
яка об 11 починається. Так означує задачу CLRS. Перш ніж писати код, завжди з'ясовуйте, чи дозволено проміжкам
торкатися: джерела цього дня домовляються по-різному, і розбір читання про це розповідає.

Kleinberg і Tardos описують загальну схему жадібного розв'язку. Вибираємо першу заявку за якимось простим правилом.
Викидаємо всі заявки, несумісні з нею. З решти вибираємо наступну за тим самим правилом. Повторюємо, доки заявки не
закінчаться. Усе питання в тому, яке правило взяти. Автори називають чотири природні правила:

- брати заявку, яка починається найраніше;
- брати найкоротшу заявку;
- брати заявку, яка перетинається з найменшою кількістю інших;
- брати заявку, яка закінчується найраніше.

Три перші правила неправильні, хоча кожне звучить розумно. Контрприклади до них ви знайдете самі в практиці. Правильне
четверте: брати заявку, яка закінчується найраніше. Задум простий: що раніше звільниться кімната, то більше часу
лишиться на решту заявок.

Виконаємо це правило вручну. Заявки в таблиці вже впорядковано за часом кінця.

| Крок | Кімната вільна з | Перша заявка, що починається не раніше | Вибрано | Кімната вільна з |
|------|------------------|----------------------------------------|---------|------------------|
| 1 | 9 | заявка 1, з 9 до 11 | 1 | 11 |
| 2 | 11 | заявка 3, з 11 до 13 | 3 | 13 |
| 3 | 13 | заявка 6, з 13 до 16 | 6 | 16 |
| 4 | 16 | заявка 8, з 16 до 18 | 8 | 18 |

Жадібне правило вибрало чотири заявки: 1, 3, 6 і 8. Заявки 2 і 4 відпали, бо починаються о 10, коли кімната ще
зайнята. Заявка 5 відпала, бо починається о 12. Заявки 7 і 9 починаються раніше, ніж закінчується заявка 6.

Алгоритм виходить коротким: відсортувати заявки за часом кінця і пройти по них один раз, пам'ятаючи, коли звільняється
кімната. Сортування коштує `O(n log n)`, прохід коштує `O(n)`.

Чотири заявки — це справді найбільше можливе? Для дев'яти заявок це можна перевірити перебором. Але перебір не скаже,
чи правило спрацює на будь-якому іншому наборі. Це може сказати лише доказ. Нижче їх два, і обидва варто знати, бо на
них стоять докази майже всіх жадібних алгоритмів.

## Доказ перший: жадібний іде попереду

Цей доказ наводять Kleinberg і Tardos. Його задум: порівнювати жадібний розклад з будь-яким іншим крок за кроком і
показати, що на кожному кроці жадібний розклад не відстає.

Візьмемо для порівняння інший розклад із сумісних заявок: 2, 5 і 9. Запишемо часи кінця заявок обох розкладів у
порядку, в якому зустрічі відбуваються.

| Номер зустрічі в розкладі | Жадібний розклад закінчує | Інший розклад закінчує |
|---------------------------|---------------------------|------------------------|
| перша | об 11 (заявка 1) | о 12 (заявка 2) |
| друга | о 13 (заявка 3) | о 15 (заявка 5) |
| третя | о 16 (заявка 6) | о 18 (заявка 9) |
| четверта | о 18 (заявка 8) | немає |

Перша зустріч жадібного розкладу закінчується не пізніше за першу зустріч іншого. Друга не пізніше за другу. Третя не
пізніше за третю. Це і є точний зміст слів «жадібний іде попереду»: зустріч з кожним номером у жадібному розкладі
закінчується не пізніше, ніж зустріч з тим самим номером у будь-якому іншому розкладі.

Чому так буде завжди, а не лише в цьому прикладі? Міркування йде індукцією за номером зустрічі.

- **Перша зустріч.** Жадібне правило бере заявку з найранішим кінцем серед усіх. Отже, перша зустріч будь-якого іншого
  розкладу закінчується не раніше.
- **Наступна зустріч.** Нехай для попереднього номера твердження вже правильне: жадібний розклад звільнив кімнату не
  пізніше за інший. Наступна заявка іншого розкладу починається після того, як інший розклад звільнив кімнату. Отже,
  вона починається і після того, як кімнату звільнив жадібний розклад. Тому жадібне правило могло б узяти саме її.
  Воно бере заявку з найранішим кінцем серед доступних, тож його вибір закінчується не пізніше.

Лишилося показати, що інший розклад не може мати більше зустрічей. Припустімо, що в жадібному розкладі `k` зустрічей,
а в іншому більше. Зустріч з номером `k` у жадібному розкладі закінчується не пізніше, ніж в іншому. Тоді зустріч з
номером `k + 1` іншого розкладу починається після того, як жадібний розклад звільнив кімнату востаннє. Ця заявка
сумісна з усім, що вибрало жадібне правило, тому воно мусило б узяти ще й її. Але воно зупинилося, тобто вільних
заявок не лишалося. Вийшла суперечність. Отже, жоден розклад не має більше зустрічей, ніж жадібний.

Зверніть увагу на одну тонкість, яку підкреслюють автори. Доказ не каже, що жадібний розклад є єдиним найкращим.
Найкращих розкладів може бути кілька. Доказ каже лише, що в жадібному розкладі стільки ж зустрічей, скільки в
найкращому.

## Доказ другий: аргумент обміну

Другий доказ тієї самої задачі наводять CLRS і Erickson. Його задум інший: узяти будь-який розклад і крок за кроком
перетворити його на жадібний, щоразу міняючи одну заявку. Якщо жодна заміна не зменшує кількість зустрічей, то
початковий розклад не міг бути кращим за жадібний.

Перетворимо розклад із заявок 2, 5 і 9.

| Крок | Розклад | Що міняємо | Чому розклад лишається сумісним |
|------|---------|------------|---------------------------------|
| початок | 2, 5, 9 | | |
| 1 | 1, 5, 9 | заявку 2 на заявку 1 | заявка 1 закінчується об 11, раніше за заявку 2, тому наступній заявці 5 вона не заважає |
| 2 | 1, 3, 9 | заявку 5 на заявку 3 | серед заявок, що починаються не раніше 11, заявка 3 закінчується найраніше, о 13 |
| 3 | 1, 3, 6 | заявку 9 на заявку 6 | серед заявок, що починаються не раніше 13, заявка 6 закінчується найраніше, о 16 |

Після трьох замін у розкладі, як і раніше, три зустрічі, але тепер це перші три вибори жадібного правила. Жадібне
правило додає до них ще заявку 8. Отже, розклад 2, 5, 9 не був найкращим.

Головна частина доказу — одна заміна. CLRS формулює її теоремою: заявка з найранішим кінцем завжди входить у якийсь
найкращий розклад. Доказ займає три речення. Візьмемо найкращий розклад і його першу зустріч. Якщо це не заявка з
найранішим кінцем, замінимо першу зустріч на неї. Нова заявка закінчується не пізніше за стару, тому з рештою розкладу
вона сумісна, а кількість зустрічей не змінилася.

Далі те саме міркування повторюють для заявок, які лишилися після першого вибору, і так до кінця. Erickson описує
загальну схему аргументу обміну трьома кроками:

1. Припустити, що є оптимальний розв'язок, який відрізняється від жадібного.
2. Знайти першу відмінність між ними.
3. Показати, що в цьому місці вибір оптимального розв'язку можна замінити на жадібний вибір і розв'язок не стане
   гіршим.

Звідси за індукцією випливає, що якийсь оптимальний розв'язок збігається з жадібним.

Назви двох прийомів доказу: «жадібний іде попереду», англійською greedy stays ahead, і аргумент обміну, англійською
exchange argument.

## Аргумент обміну на іншій задачі: найменше запізнення

Щоб побачити аргумент обміну в роботі ще раз, візьмемо задачу з розділу 4.2 Kleinberg і Tardos. Вона схожа на
попередню, але влаштована інакше.

Є одна машина і кілька робіт. Кожна робота має тривалість і термін, до якого її бажано закінчити. Машина виконує
роботи одну за одною, починаючи з моменту 0. Виконати треба всі роботи, тому вибирати доводиться не «які», а «в якому
порядку». Якщо робота закінчилася пізніше за свій термін, різницю називають її запізненням. Якщо робота встигла, її
запізнення дорівнює 0. Мета: зробити найбільше із запізнень якомога меншим.

Автори розглядають три жадібні правила, і кожне лише сортує роботи:

- найкоротша робота першою, щоб швидко позбутися дрібниць;
- першою та робота, в якої найменший запас часу, тобто найменша різниця між терміном і тривалістю;
- першою та робота, в якої найраніший термін.

Котре з них правильне? Замість гадати, запитаймо в програми. Вона складає 5000 випадкових малих наборів робіт. Для
кожного набору вона знаходить найкращу відповідь повним перебором усіх порядків і порівнює з нею відповідь кожного
правила.

```ts
// Робота має тривалість і термін. Усі роботи виконує одна машина, одну за одною, без пауз.
interface Job {
  length: number;
  deadline: number;
}

// Найбільше запізнення розкладу. Машина починає в момент 0.
// Запізнення роботи — це на скільки пізніше за термін вона закінчилась; якщо встигла, то 0.
function maxLateness(order: Job[]): number {
  let time = 0;
  let worst = 0;
  for (const job of order) {
    time += job.length;
    worst = Math.max(worst, time - job.deadline);
  }
  return worst;
}

// Три жадібні правила. Кожне лише сортує роботи за однією ознакою.
const rules: [string, (a: Job, b: Job) => number][] = [
  ['найкоротша робота першою', (a, b) => a.length - b.length],
  ['найменший запас часу першим', (a, b) => a.deadline - a.length - (b.deadline - b.length)],
  ['найраніший термін першим', (a, b) => a.deadline - b.deadline],
];

// Повний перебір: скласти всі можливі порядки робіт і взяти найменше з найбільших запізнень.
function bruteForce(jobs: Job[]): number {
  let best = Infinity;
  const order: Job[] = [];
  const used = new Array<boolean>(jobs.length).fill(false);
  function extend(): void {
    if (order.length === jobs.length) {
      best = Math.min(best, maxLateness(order));
      return;
    }
    for (let i = 0; i < jobs.length; i += 1) {
      if (!used[i]) {
        used[i] = true;
        order.push(jobs[i]);
        extend();
        order.pop();
        used[i] = false;
      }
    }
  }
  extend();
  return best;
}

// Генератор mulberry32: з одного початкового числа щоразу виходить та сама послідовність.
let state = 2026;
function random(): number {
  state = (state + 0x6d2b79f5) | 0;
  let t = Math.imul(state ^ (state >>> 15), 1 | state);
  t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
  return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
}
function randomInt(low: number, high: number): number {
  return low + Math.floor(random() * (high - low + 1));
}

const show = (jobs: Job[]): string => jobs.map((job) => `(${job.length}, ${job.deadline})`).join(' ');

const start = performance.now();
const tests = 5000;
const failures = rules.map(() => 0);
const firstFailure = rules.map(() => 0);
const smallest: (Job[] | null)[] = rules.map(() => null);

for (let test = 1; test <= tests; test += 1) {
  const count = randomInt(2, 6); // від двох до шести робіт
  const jobs: Job[] = Array.from({ length: count }, () => ({
    length: randomInt(1, 5), //    тривалість від 1 до 5
    deadline: randomInt(1, 12), // термін від 1 до 12
  }));
  const best = bruteForce(jobs);
  rules.forEach(([, compare], r) => {
    if (maxLateness([...jobs].sort(compare)) > best) {
      failures[r] += 1;
      if (firstFailure[r] === 0) {
        firstFailure[r] = test;
      }
      const current = smallest[r];
      if (current === null || jobs.length < current.length) {
        smallest[r] = jobs;
      }
    }
  });
}

rules.forEach(([name, compare], r) => {
  console.log(`${name}: помилок ${failures[r]} з ${tests}`);
  const jobs = smallest[r];
  if (jobs !== null) {
    const greedyOrder = [...jobs].sort(compare);
    console.log(`  перша помилка на тесті ${firstFailure[r]}; найменший контрприклад: ${show(jobs)}`);
    console.log(
      `  правило ставить ${show(greedyOrder)}, запізнення ${maxLateness(greedyOrder)}; найкраще ${bruteForce(jobs)}`,
    );
  }
});
console.log(`час усієї перевірки: ${(performance.now() - start).toFixed(0)} мс`);
```

  перша помилка на тесті 1; найменший контрприклад: (1, 8) (2, 2)
  правило ставить (1, 8) (2, 2), запізнення 1; найкраще 0
найменший запас часу першим: помилок 1159 з 5000
  перша помилка на тесті 3; найменший контрприклад: (2, 5) (5, 7)
  правило ставить (5, 7) (2, 5), запізнення 2; найкраще 0
найраніший термін першим: помилок 0 з 5000
час усієї перевірки: 154 мс

Що видно у виводі.

**Правило «найкоротша робота першою» помилилося на 3456 наборах із 5000.** Найменший контрприклад має дві роботи:
перша триває 1 і має термін 8, друга триває 2 і має термін 2. Правило ставить коротку роботу першою, тому друга
закінчується в момент 3 і запізнюється на 1. У зворотному порядку друга закінчується в момент 2, перша в момент 3, і
ніхто не запізнюється. Правило взагалі не дивиться на терміни, тому й помиляється так часто.

**Правило «найменший запас часу першим» помилилося на 1159 наборах із 5000.** Найменший контрприклад: робота з
тривалістю 2 і терміном 5 та робота з тривалістю 5 і терміном 7. Запас часу першої дорівнює 3, другої 2, тому правило
починає з другої. Вона закінчується в момент 5, а перша в момент 7, із запізненням 2. У зворотному порядку перша
закінчується в момент 2, друга в момент 7, і запізнень немає.

**Правило «найраніший термін першим» не помилилося жодного разу.** Саме його Kleinberg і Tardos називають правильним.

**Уся перевірка тривала 154 мс.** Перші помилки двох неправильних правил програма знайшла на першому і на третьому
наборі.

**Практичний висновок:** друге правило дає правильну відповідь на 77 зі 100 випадкових наборів. Якщо перевірити його
вручну на трьох-чотирьох прикладах, цілком можна не натрапити на жодну помилку і повірити, що воно правильне.
Програма, яка порівнює правило з повним перебором на тисячах малих входів, знаходить помилку за частку секунди і ще й
показує найменший контрприклад.

### Чому найраніший термін правильний

Нуль помилок на 5000 наборів — це сильне свідчення, але не доказ. Доказ дає аргумент обміну, і тут він навіть
наочніший, ніж для заявок.

Назвемо інверсією пару робіт, які стоять у розкладі в «неправильному» порядку: робота з пізнішим терміном іде раніше
за роботу з ранішим терміном. Розклад за правилом найранішого терміну не має інверсій. Доказ показує, що будь-який
найкращий розклад можна позбавити інверсій, не погіршивши його.

Якщо в розкладі є інверсія, то є й дві сусідні роботи, які її утворюють. Поміняємо їх місцями і подивимося на
контрприклад з виводу. У порядку «робота з терміном 7, потім робота з терміном 5» є інверсія.

| | Робота з тривалістю 5 і терміном 7 | Робота з тривалістю 2 і терміном 5 | Найбільше запізнення |
|---|---|---|---|
| до обміну | закінчується в момент 5, запізнення 0 | закінчується в момент 7, запізнення 2 | 2 |
| після обміну | закінчується в момент 7, запізнення 0 | закінчується в момент 2, запізнення 0 | 0 |

Чому обмін сусідів ніколи не шкодить? Простежимо за кожною роботою.

- Усі інші роботи закінчуються тоді ж, коли й раніше, бо дві сусідні роботи разом займають той самий відрізок часу.
- Робота з ранішим терміном тепер закінчується раніше, тому її запізнення не зросло.
- Робота з пізнішим терміном тепер закінчується пізніше: у той момент, коли до обміну закінчувалася її сусідка. Але її
  термін пізніший, ніж у сусідки. Тому її нове запізнення не більше, ніж було в сусідки до обміну.

Отже, після обміну найбільше запізнення не зросло, а інверсій стало на одну менше. Повторюючи обміни, з будь-якого
найкращого розкладу отримуємо розклад без інверсій, і він не гірший. Kleinberg і Tardos окремо показують, що всі
розклади без інверсій і без пауз мають однакове найбільше запізнення. Розклад за найранішим терміном — один з них,
тому він найкращий.

## Пастка: повірити правилу після кількох прикладів

Це головна пастка дня, і вивід обох програм її показує. Жадібне правило для монет 1, 3 і 4 правильне на 23 сумах із
30. Правило найменшого запасу часу правильне на 77 відсотках наборів. Кілька вдалих прикладів нічого не доводять.

BCtCI називає найчастішою помилкою на співбесіді саме це: кандидат застосовує жадібний алгоритм і не помічає, що той
не завжди дає найкращу відповідь.

Надійний спосіб перевірки складається з чотирьох частин, і всі вони є у другій програмі лекції:

1. **Жадібний розв'язок.** Те правило, яке ви перевіряєте.
2. **Повний перебір.** Повільний розв'язок, який не може помилитися, бо пробує все. Він має бути написаний окремо і
   якомога простіше.
3. **Генератор малих випадкових входів.** Малих, бо перебір на великих входах не закінчиться, і бо малий контрприклад
   легко зрозуміти.
4. **Порівняння.** Тисячі входів, на кожному дві відповіді, і друк найменшого входу, де вони різняться.

BCtCI радить те саме про контрприклади: шукайте найпростіший і найменший, бо він показує, де саме міркування хибне.

Перевірка має межу. Якщо вона знайшла розбіжність, правило точно неправильне. Якщо не знайшла, правило, найпевніше,
правильне, але доводить це лише один із двох доказів: «жадібний іде попереду» або аргумент обміну.

## Коли жадібність працює: дві властивості

CLRS називає дві властивості задачі, які разом роблять жадібний алгоритм правильним.

**Властивість жадібного вибору.** Найкращий розв'язок усієї задачі можна скласти, роблячи найкращий вибір на кожному
кроці. Саме це доводить аргумент обміну: жадібний вибір завжди входить у якийсь оптимальний розв'язок.

**Оптимальна підструктура.** Після першого вибору лишається менша задача того самого виду, і найкращий розв'язок усієї
задачі містить найкращий розв'язок цієї меншої задачі. Після вибору заявки 1 лишається задача про заявки, що
починаються не раніше 11.

CLRS показує різницю на двох задачах про рюкзак. Злодій несе рюкзак, який витримує 50 фунтів. Є три речі.

| Річ | Вага, фунтів | Ціна, доларів | Ціна за фунт |
|-----|--------------|---------------|--------------|
| 1 | 10 | 60 | 6 |
| 2 | 20 | 100 | 5 |
| 3 | 30 | 120 | 4 |

Жадібне правило: брати спершу те, що найдорожче за фунт.

У першій задачі речі можна ділити, як золотий пісок. Правило бере всю річ 1, всю річ 2 і на 20 фунтів, що лишилися,
дві третини речі 3. Разом 60 + 100 + 80 = 240 доларів, і це найкраще можливе.

У другій задачі речі неподільні, як злитки. Правило бере річ 1 і річ 2, разом 30 фунтів і 160 доларів. Річ 3 уже не
вміщується, і 20 фунтів місця пропадають. А найкращий вибір — речі 2 і 3: рівно 50 фунтів і 220 доларів. Жадібне
правило програло, бо порожнє місце в рюкзаку знижує справжню ціну за фунт усього вантажу.

Задача про неподільні речі не має властивості жадібного вибору. Її розв'язують динамічним програмуванням, і до неї ви
дійдете в день 6.

## Як упізнати задачу на цей прийом

Сьогодні у файлі `PATTERNS.md` з'являється другий запис. Ось ознаки, які варто туди перенести своїми словами.

- **Задача оптимізаційна.** Треба знайти найбільше, найменше, найдешевше.
- **Розв'язок будується низкою виборів.** І є проста ознака, за якою можна впорядкувати кандидатів: кінець, термін,
  ціна за одиницю.
- **Зроблений вибір не доводиться переглядати.** Після нього лишається менша задача того самого виду.
- **Жадібний вибір можна обґрунтувати.** Або він «іде попереду», або будь-який інший вибір можна замінити на нього без
  втрат.

Порядок роботи:

1. Придумайте правило і запишіть його одним реченням.
2. Спробуйте його зламати: шукайте малий контрприклад руками і порівнянням з повним перебором.
3. Якщо правило встояло, доведіть його одним із двох способів.
4. Якщо правило зламалося і кращого не видно, це ознака, що задача потребує динамічного програмування або перебору.

Жадібні алгоритми ви вже писали, хоча так їх не називали. Алгоритми Прима і Крускала з дня 9 фази 3 на кожному кроці
беруть найлегше ребро, яке ще годиться, і ніколи не передумують.

## Типові помилки

**Повірити правилу, бо воно пройшло кілька прикладів.** Це пастка дня. Неправильне правило може бути правильним на
більшості входів.

**Сортувати заявки за початком, а не за кінцем.** Обидва порядки виглядають природно, і код відрізняється одним
словом.

**Не з'ясувати, чи можна проміжкам торкатися.** Від цього залежить, який знак стоїть у порівнянні: «не менше» чи
«строго більше». Помилка проявляється лише на заявках, де кінець однієї дорівнює початку іншої.

**Доводити, що кожен крок «найкращий зараз».** Це правда для будь-якого жадібного правила, зокрема й для
неправильного. Доказ мусить порівнювати жадібний розв'язок з довільним оптимальним.

**Вважати, що жадібний розв'язок єдиний найкращий.** Найкращих розв'язків буває кілька. Доводять, що жадібний не
гірший за них, а не що він збігається з кожним.

**Переносити правило на трохи змінену задачу.** Якщо кожна заявка має ціну і треба набрати найбільшу суму цін, правило
найранішого кінця вже не працює. Kleinberg і Tardos називають цю задачу зваженим вибором заявок, а BCtCI радить
розв'язувати її динамічним програмуванням.

**Перевіряти жадібний алгоритм ним самим.** Якщо перебір і жадібний розв'язок користуються однією спільною функцією з
помилкою, вони помиляться однаково, і порівняння нічого не покаже.

## Практика

**1. Вибір заявок за найранішим кінцем.** Функція отримує масив заявок з часом початку і кінця і повертає вибрані
заявки. Спершу вирішіть і запишіть у коментарі, чи вважаються сумісними заявки, які торкаються.

**2. Повний перебір.** Друга функція перебирає всі підмножини заявок, відкидає ті, де є несумісна пара, і повертає
найбільший розмір. Для 15 заявок підмножин 32 768.

**3. Порівняння.** Згенеруйте кілька тисяч випадкових наборів, у кожному від 1 до 15 заявок, і порівняйте кількість
заявок у двох відповідях. До запуску запишіть, скільки розбіжностей ви очікуєте.

**4. Три інші правила.** Напишіть правила «найкоротша заявка», «найраніший початок» і «найменше перетинів» за
загальною схемою: вибрати заявку за правилом, викинути несумісні з нею, повторити. Знайдіть для кожного правила
контрприклад тією самою перевіркою і надрукуйте найменший. Намалюйте кожен контрприклад на папері й поясніть одним
реченням, чому правило на ньому помиляється.

**5. Тести.** Порожній набір. Одна заявка. Дві заявки, які торкаються. Дві однакові заявки. Заявка, що лежить цілком
усередині іншої.

**6. Записи.** Один рядок у `JOURNAL.md`. У `PATTERNS.md` — запис про жадібні алгоритми з ознаками і порядком роботи
та приклад з монетами 1, 3 і 4 як застереження.

**Підказка до пункту 4.** Контрприклади до двох перших правил трапляються часто. Контрприклад до правила «найменше
перетинів» рідкісний: Kleinberg і Tardos пишуть, що придумати його помітно важче. У перевірці, зробленій для цієї
лекції, на 3000 наборів до 15 заявок він трапився один раз. Якщо ваш пошук нічого не знайшов, збільште кількість
наборів.

**Як перевірити себе.** Найраніший кінець збігся з перебором на всіх наборах. Для трьох інших правил знайдено
контрприклади. Приклад з монетами записано в `PATTERNS.md`.

## Перевірте себе

**1. Монети 1, 5 і 12. Знайдіть суму, на якій жадібне правило бере більше монет, ніж треба.**

<details><summary>Відповідь</summary>

Сума 15. Жадібне правило бере 12 і потім три монети по 1, разом чотири монети. Три монети по 5 дають ту саму суму.
Найменша така сума саме 15: для сум до 11 монети 12 немає серед кандидатів, а для сум 12, 13 і 14 жадібний набір
найкращий.

</details>

**2. Заявки: з 1 до 4, з 3 до 5, з 0 до 6, з 5 до 7, з 6 до 8. Які заявки вибере правило найранішого кінця, якщо
заявкам дозволено торкатися?**

<details><summary>Відповідь</summary>

Заявки вже впорядковано за кінцем: 4, 5, 6, 7, 8. Правило бере першу, з 1 до 4. Заявка з 3 до 5 починається раніше 4 і
відпадає. Заявка з 0 до 6 теж. Заявка з 5 до 7 починається після 4, її беремо. Заявка з 6 до 8 починається раніше 7 і
відпадає. Вибрано дві заявки: з 1 до 4 і з 5 до 7.

</details>

**3. У доказі «жадібний іде попереду» де саме використано те, що правило бере заявку з найранішим кінцем, а не якусь
іншу?**

<details><summary>Відповідь</summary>

У двох місцях. На першому кроці: перша жадібна заявка закінчується найраніше серед усіх, тому не пізніше за першу
заявку іншого розкладу. На кожному наступному кроці: наступна заявка іншого розкладу доступна жадібному правилу, а
воно бере з доступних ту, що закінчується найраніше, тому не відстає. Якби правило брало, наприклад, найкоротшу
заявку, друге твердження вже не було б правильним.

</details>

**4. Три роботи: тривалість 3 і термін 4, тривалість 2 і термін 6, тривалість 4 і термін 5. Який порядок дає найменше
найбільше запізнення і яке воно?**

<details><summary>Відповідь</summary>

Порядок за найранішим терміном: спершу термін 4, потім термін 5, потім термін 6. Перша робота закінчується в момент 3
і встигає. Друга закінчується в момент 7 при терміні 5 і запізнюється на 2. Третя закінчується в момент 9 при терміні
6 і запізнюється на 3. Найбільше запізнення дорівнює 3. Меншим воно бути не може: усі три роботи разом тривають 9,
тому остання в будь-якому порядку закінчується в момент 9, а найпізніший термін дорівнює 6.

</details>

**5. Жадібне правило збіглося з повним перебором на 10 000 випадкових наборів. Чи доведено, що воно правильне?**

<details><summary>Відповідь</summary>

Ні. Це сильне свідчення, але не доказ. Контрприклад може бути рідкісним або мати форму, якої генератор не створює:
наприклад, він потребує більше елементів, ніж генератор дозволяє. У перевірці, зробленій для цієї лекції, правило
«найменше перетинів» помилилося на одному наборі з 3000. Доказом є лише міркування, яке охоплює всі входи: «жадібний
іде попереду» або аргумент обміну.

</details>

**6. Чому рюкзак, де речі можна ділити, розв'язується жадібно, а рюкзак з неподільними речами — ні?**

<details><summary>Відповідь</summary>

Коли речі можна ділити, рюкзак завжди заповнюється повністю, і кожен фунт місця зайнятий найдорожчим з того, що
лишилося. Замінити будь-який фунт вантажу на інший означає взяти щось не дорожче. Коли речі неподільні, найдорожча за
фунт річ може зайняти місце так, що решта не вміститься, і частина рюкзака лишиться порожньою. У прикладі CLRS
жадібний вибір дає 160 доларів і 20 фунтів порожнього місця, а найкращий вибір дає 220 доларів.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| оптимізаційна задача | задача, де серед багатьох розв'язків шукають найкращий |
| оптимальний розв'язок | найкращий з можливих розв'язків; їх може бути кілька |
| жадібний алгоритм | алгоритм, який на кожному кроці робить найкращий зараз вибір і не переглядає його |
| жадібне правило | ознака, за якою жадібний алгоритм робить вибір |
| сумісні заявки | заявки, проміжки часу яких не перетинаються |
| жадібний іде попереду | доказ: після кожного кроку жадібний розв'язок не гірший за будь-який інший |
| аргумент обміну | доказ: оптимальний розв'язок перетворюють на жадібний замінами, які його не погіршують |
| інверсія | пара робіт, де робота з пізнішим терміном стоїть раніше за роботу з ранішим |
| контрприклад | вхід, на якому алгоритм дає неправильну відповідь |
| властивість жадібного вибору | найкращий розв'язок можна скласти з найкращих виборів на кожному кроці |
| оптимальна підструктура | найкращий розв'язок задачі містить найкращі розв'язки менших задач |
