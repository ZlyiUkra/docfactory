## Задачі з відповіддю «так» чи «ні»

Теорія цього дня говорить лише про задачі розпізнавання. Так називають задачі, відповідь на які — «так» або «ні».
Конспект MIT 6.006 дає приклади:

- чи є в графі шлях від `s` до `t` вагою не більше `d`;
- чи є в графі від'ємний цикл;
- чи можна вибрати з набору цілих чисел кілька так, щоб їхня сума дорівнювала `S`.

Багато звичних задач просять не «так» чи «ні», а найкраще значення: найкоротший шлях, найдешевший маршрут. Таку задачу
перетворюють на задачу розпізнавання, додавши межу. Grokking робить це із задачею комівояжера: замість «знайдіть
найкоротший маршрут» питають «чи є маршрут довжиною 5?». CLRS так само перетворює найкоротший шлях на задачу PATH: чи
є шлях від `u` до `v` не більше ніж з `k` ребер.

Навіщо це спрощення? Задачі з відповіддю «так» чи «ні» легко порівнювати між собою, і далі ви побачите як.

## Клас P: задачі, які розв'язуються швидко

Erickson називає найменшу вимогу до «ефективного» алгоритму: його час обмежений многочленом від розміру входу, тобто
`O(n^c)` для якоїсь сталої `c`. Такий час називають поліноміальним. Клас P — це всі задачі розпізнавання, які
розв'язуються за поліноміальний час.

Майже все, що ви писали в цьому плані, лежить у P: сортування за `O(n log n)`, пошук у ширину за `O(V + E)`, алгоритм
Дейкстри, мінімальне кістякове дерево, максимальний потік.

Чому межею обрано саме многочлен, а не, скажімо, `n³`? CLRS називає три причини:

1. Задачі, для яких знайшли поліноміальний алгоритм, на практиці рідко потребують многочлена високого степеня. Щойно
   з'являється перший поліноміальний алгоритм, за ним зазвичай приходять швидші.
2. Поліноміальність не залежить від моделі комп'ютера: що поліноміальне на одній розумній моделі, те поліноміальне й
   на іншій.
3. Многочлени добре поєднуються. Якщо вихід одного поліноміального алгоритму подати на вхід іншого, разом вийде знову
   поліноміальний алгоритм.

Третя причина знадобиться, коли дійдемо до зведень.

**Розмір входу — це довжина запису, а не величина чисел.** CLRS пояснює це на прикладі. Нехай єдиний вхід алгоритму —
число `k`, і алгоритм працює `Θ(k)` кроків. Число `k` у двійковому записі займає близько `log k` бітів. Тому відносно
довжини входу `n` такий алгоритм робить `2^n` кроків, і він експоненційний. Через це алгоритм для рюкзака з дня 6 фази
4, час якого залежить від місткості рюкзака, називають псевдополіноміальним, а не поліноміальним.

## Клас NP: задачі, де відповідь «так» легко перевірити

Конспект MIT означує клас NP через перевірку. Задача лежить у NP, якщо для неї є алгоритм перевірки з такими
властивостями:

- він отримує вхід задачі і ще один рядок, який називають сертифікатом; довжина сертифіката поліноміальна від довжини
  входу;
- він завжди працює поліноміальний час;
- якщо правильна відповідь «так», то існує сертифікат, на якому перевірка скаже «так»;
- якщо правильна відповідь «ні», то перевірка скаже «ні» на будь-якому сертифікаті.

Сертифікат — це доказ того, що відповідь «так». Зазвичай це сам розв'язок. Ось рядки з таблиці конспекту MIT:

| Задача | Сертифікат | Що робить перевірка |
|--------|------------|---------------------|
| шлях від `s` до `t` вагою не більше `d` | сам шлях | додає ваги ребер шляху і порівнює з `d` |
| від'ємний цикл | сам цикл | додає ваги ребер циклу і порівнює з нулем |
| сума підмножини | вибрані числа | додає їх і порівнює з `S` |

Три речі про NP плутають найчастіше.

**NP не означає «не поліноміальний».** Конспект MIT розшифровує назву: «Nondeterministic Polynomial Time», тобто
недетермінований поліноміальний час. Що означає слово «недетермінований», для цієї лекції не важливо.

**Кожна задача з P лежить і в NP.** Конспект MIT пояснює: перевірка може не дивитися на сертифікат і просто розв'язати
задачу сама. Тож пошук у ширину чи сортування теж «у NP». Питання не в тому, чи задача в NP, а в тому, чи лежить вона
ще й у P.

**Перевіряють лише відповідь «так».** Щоб довести, що сума 9 досяжна, досить показати числа. А як коротко довести, що
жодна підмножина не дає потрібної суми? Означення цього не вимагає. Erickson називає клас задач, де легко перевірити
відповідь «ні», словом co-NP, і зауважує, що ніхто не знає, чи збігається він з NP.

Конспект MIT додає оцінку згори: будь-яку задачу з NP можна розв'язати за експоненційний час, якщо перебрати всі
можливі сертифікати і кожен перевірити. Саме це робить програма нижче для задачі про суму підмножини.

```ts
// Задача про суму підмножини: чи можна вибрати з чисел кілька так, щоб їхня сума дорівнювала target?

// Перевірка. Сертифікат — номери вибраних чисел. Перевірка проходить список один раз.
function verify(numbers: number[], target: number, chosen: number[]): boolean {
  const seen = new Set<number>();
  let sum = 0;
  for (const i of chosen) {
    if (!Number.isInteger(i) || i < 0 || i >= numbers.length || seen.has(i)) return false; // чужий номер або повтор
    seen.add(i);
    sum += numbers[i];
  }
  return sum === target;
}

// Пошук перебором. Кожен біт числа mask каже, чи взято число з таким номером, тому підмножин 2^n.
// Повертає сертифікат і кількість переглянутих підмножин.
function solve(numbers: number[], target: number): { chosen: number[] | null; checked: number } {
  const n = numbers.length;
  for (let mask = 0; mask < 1 << n; mask++) {
    let sum = 0;
    for (let i = 0; i < n; i++) if (mask & (1 << i)) sum += numbers[i];
    if (sum === target) return { chosen: [...Array(n).keys()].filter((i) => mask & (1 << i)), checked: mask + 1 };
  }
  return { chosen: null, checked: 1 << n };
}

// Генератор випадкових чисел mulberry32: рахує в цілих 32-бітних числах і щоразу дає той самий ряд.
let state = 2026;
function rnd(): number {
  state = (state + 0x6d2b79f5) | 0;
  let x = Math.imul(state ^ (state >>> 15), 1 | state);
  x = (x + Math.imul(x ^ (x >>> 7), 61 | x)) ^ x;
  return ((x ^ (x >>> 14)) >>> 0) / 4294967296;
}

// Малий приклад.
const small = [3, 34, 4, 12, 5, 2];
const found = solve(small, 9);
console.log("small: chosen", found.chosen, "checked", found.checked, "verified", verify(small, 9, found.chosen!));
console.log("small: wrong certificate [0, 1] verified", verify(small, 9, [0, 1]));

// Найгірший випадок для перебору: відповіді немає. Усі числа парні, а потрібна сума непарна.
for (const n of [16, 20, 24]) {
  const numbers = Array.from({ length: n }, () => 2 * (1 + Math.floor(rnd() * 1_000_000)));
  const start = performance.now();
  const result = solve(numbers, 1_000_001);
  const ms = performance.now() - start;
  const answer = result.chosen === null ? "no" : "yes";
  console.log(`n=${n}: answer ${answer}, subsets checked ${result.checked}, ${ms.toFixed(0)} ms`);
}

// Скільки коштує перевірка готового сертифіката для 24 чисел: середнє за мільйон перевірок.
const numbers24 = Array.from({ length: 24 }, () => 1 + Math.floor(rnd() * 1_000_000));
const half = [...Array(12).keys()];
const target24 = half.reduce((sum, i) => sum + numbers24[i], 0);
const start = performance.now();
let accepted = 0;
for (let r = 0; r < 1_000_000; r++) if (verify(numbers24, target24, half)) accepted++;
const microseconds = (performance.now() - start) / 1_000_000 * 1000;
console.log(`verify n=24: accepted ${accepted} of 1000000, ${microseconds.toFixed(2)} microseconds each`);

// Зведення. Задача про поділ: чи можна поділити числа на дві купки з однаковою сумою?
// Перетворюємо вхід задачі про поділ на вхід задачі про суму підмножини з тією самою відповіддю.
function partitionToSubsetSum(numbers: number[]): { numbers: number[]; target: number } {
  const total = numbers.reduce((a, b) => a + b, 0);
  // Непарну суму поділити навпіл не можна. Тоді даємо вхід, для якого відповідь теж «ні».
  if (total % 2 === 1) return { numbers: [], target: 1 };
  return { numbers, target: total / 2 };
}
// Недбале зведення: забуло про непарну загальну суму.
function sloppyReduction(numbers: number[]): { numbers: number[]; target: number } {
  return { numbers, target: Math.floor(numbers.reduce((a, b) => a + b, 0) / 2) };
}
// Незалежний розв'язувач задачі про поділ: кожне число кладемо в ліву або в праву купку.
function canPartition(numbers: number[], i = 0, left = 0, right = 0): boolean {
  if (i === numbers.length) return left === right;
  const x = numbers[i];
  return canPartition(numbers, i + 1, left + x, right) || canPartition(numbers, i + 1, left, right + x);
}

let agree = 0, yes = 0, sloppyWrong = 0;
for (let t = 0; t < 2000; t++) {
  const numbers = Array.from({ length: 1 + Math.floor(rnd() * 10) }, () => 1 + Math.floor(rnd() * 20));
  const expected = canPartition(numbers);
  const viaReduction = partitionToSubsetSum(numbers);
  const viaSloppy = sloppyReduction(numbers);
  if ((solve(viaReduction.numbers, viaReduction.target).chosen !== null) === expected) agree++;
  if ((solve(viaSloppy.numbers, viaSloppy.target).chosen !== null) !== expected) sloppyWrong++;
  if (expected) yes++;
}
console.log(`reduction: ${agree} of 2000 answers agree (yes ${yes}, no ${2000 - yes})`);
console.log(`sloppy reduction: ${sloppyWrong} of 2000 answers differ`);
```

```

small: wrong certificate [0, 1] verified false
n=16: answer no, subsets checked 65536, 6 ms
n=20: answer no, subsets checked 1048576, 67 ms
n=24: answer no, subsets checked 16777216, 1160 ms
verify n=24: accepted 1000000 of 1000000, 0.34 microseconds each
reduction: 2000 of 2000 answers agree (yes 520, no 1480)
sloppy reduction: 625 of 2000 answers differ
```

Перші шість рядків виводу — про перевірку і пошук. Останні два стосуються зведення, до них повернемося нижче.

- **Малий приклад.** Серед чисел 3, 34, 4, 12, 5, 2 перебір знайшов суму 9: числа з номерами 2 і 4, тобто 4 і 5.
  Перевірка цей сертифікат прийняла, а сертифікат з номерами 0 і 1, тобто 3 і 34, відхилила.
- **Перебір росте у 16 разів на кожні чотири числа.** Підмножин 65 536, потім 1 048 576, потім 16 777 216. Час: 6
  мілісекунд, 67 і 1160. Ще чотири числа дали б близько 20 секунд. Якщо зріст лишиться таким самим, 40 чисел заберуть
  близько півтори доби, а 50 чисел — близько п'яти років.
- **Перевірка коштує третину мікросекунди.** Для тих самих 24 чисел пошук тривав понад секунду, а перевірка готової
  відповіді — 0,34 мікросекунди. Різниця — понад три мільйони разів.

У найгіршому випадку ми взяли парні числа і непарну суму. Людина одразу бачить з парності, що відповідь «ні». Перебір
про парність не знає, і тому такий вхід гарантовано змушує його пройти всі підмножини.

Числа часу залежать від машини, але зріст буде тим самим.

Чесне застереження. Для суми підмножини перебір — не єдиний шлях. Динамічне програмування з фази 4 розв'язує її за
час, пропорційний добутку кількості чисел на потрібну суму. Але цей час залежить від величини суми, а не від довжини
її запису, тож це знову псевдополіноміальний алгоритм. Конспект MIT називає такі задачі «weakly NP-complete». Для
чисел завдовжки сто цифр таблиця динамічного програмування не вміститься в жоден комп'ютер.

## Чи дорівнює P класу NP

Ми знаємо, що P лежить усередині NP. Чи є в NP задачі, яких немає в P, тобто такі, де перевірити легко, а швидко
розв'язати неможливо? Цього ніхто не знає. Це питання називають «P проти NP».

Майже всі дослідники вважають, що P не дорівнює NP. Erickson пише, що твердження «P ≠ NP» розумно приймати як закон
природи: його підтверджує величезний досвід, але математичного доведення немає. Інститут Клея обіцяє за розв'язання
мільйон доларів, це одна з семи «задач тисячоліття».

Для практики важить не саме питання, а його наслідок. Є задачі, про які доведено: якщо хоч одну з них розв'язати за
поліноміальний час, то P дорівнює NP. Знайти швидкий алгоритм для такої задачі означало б спростувати те, у що вірять
майже всі. Щоб пояснити, що це за задачі, потрібні ще два поняття: задача SAT і зведення.

## SAT: задача про здійсненність формули

Grokking пояснює її на замовленні піци. Четверо друзів мають побажання:

- Елейн хоче пепероні;
- Джеррі хоче пепероні або ковбаски;
- Крамер хоче оливки або цибулю;
- Джордж не хоче цибулі.

Чи є піца, яка влаштує всіх? Запишемо побажання формулою з чотирма змінними, кожна з яких каже, чи є начинка в піці:

`(пепероні) і (пепероні або ковбаски) і (оливки або цибуля) і (не цибуля)`

Задача SAT питає: чи можна дати змінним значення «так» і «ні» так, щоб уся формула стала істинною? Тут можна: пепероні
й оливки є, цибулі немає. Якщо такі значення існують, формулу називають здійсненною. Назва SAT — скорочення від
англійського «satisfiability».

Три слова, без яких про SAT не поговорити:

- **Змінна** — те, що може бути «так» або «ні»: `цибуля`.
- **Літерал** — змінна або її заперечення: `цибуля`, `не цибуля`.
- **Диз'юнкт** — кілька літералів, з'єднаних словом «або»: `(оливки або цибуля)`. Диз'юнкт істинний, коли істинний
  хоча б один його літерал.

Формула в нашому прикладі — це диз'юнкти, з'єднані словом «і». Вона істинна, коли істинний кожен диз'юнкт. У програмі
літерал зручно записувати числом зі знаком: `3` означає третю змінну, а `−3` її заперечення. Тоді диз'юнкт — це масив
чисел, а формула — масив диз'юнктів.

Багато побутових умов легко перекласти на диз'юнкти. Наприклад, умова «з трьох людей `a`, `b`, `c` чергує рівно один»
— це чотири диз'юнкти:

- `(a або b або c)` — хоча б один чергує;
- `(не a або не b)`, `(не a або не c)`, `(не b або не c)` — жодні двоє не чергують разом.

**SAT лежить у NP.** Сертифікат — значення всіх змінних. Перевірка підставляє їх у формулу і обчислює кожен диз'юнкт.
Grokking показує це на формулі з трьома начинками: перевірити готові значення швидше, ніж знайти їх.

**Розв'язати SAT можна перебором.** Grokking рахує: з `n` начинками можливих піц `2^n`. Перебрати їх усі — це таблиця
істинності. Швидшого алгоритму, який працює для будь-якої формули, ніхто не знає.

Grokking додає, що SAT — перша задача, про яку довели NP-повноту, і сталося це 1971 року. Що означає це слово, стане
ясно після наступного розділу.

## Зведення: одна задача через іншу

Зведення задачі A до задачі B — це швидке перетворення будь-якого входу задачі A на вхід задачі B з тією самою
відповіддю. «Швидке» означає поліноміальний час. «З тією самою відповіддю» означає дві речі: вхід з відповіддю «так»
стає входом з відповіддю «так», а вхід з відповіддю «ні» стає входом з відповіддю «ні».

Erickson зауважує, що ви робите зведення роками, тільки називаєте їх підпрограмами чи службовими функціями. Конспект
MIT дає приклади з фази 3. Найкоротший шлях у графі без ваг зводиться до найкоротшого шляху з вагами: досить дати
кожному ребру вагу 1. Найдовший шлях зводиться до найкоротшого: досить змінити знак кожної ваги.

Програма вище містить ще одне зведення. Задача про поділ питає: чи можна поділити набір чисел на дві купки з однаковою
сумою? Функція `partitionToSubsetSum` перетворює її вхід на вхід задачі про суму підмножини:

- якщо загальна сума парна, числа лишаються ті самі, а потрібна сума дорівнює половині загальної;
- якщо загальна сума непарна, поділити не можна, і функція повертає вхід, для якого відповідь теж «ні»: порожній набір
  і суму 1.

Чому відповіді збігаються? Якщо числа діляться на дві рівні купки, то одна з купок — це підмножина із сумою в половину
загальної. І навпаки: якщо є підмножина із сумою в половину загальної, то решта чисел дає другу половину.

Передостанній рядок виводу підтверджує це на 2000 випадкових наборах: відповіді збіглися на всіх, і серед них було 520
«так» і 1480 «ні». Порівнювали з незалежним розв'язувачем, який розкладає числа по двох купках і про суму підмножини
нічого не знає.

Останній рядок показує, чому перевіряти треба обидві відповіді. Недбале зведення забуло про непарну суму і просто
округлює половину вниз. Воно помилилося на 625 наборах з 2000. Набір з чисел 1 і 2 має суму 3, і поділити його не
можна. Але недбале зведення просить підмножину із сумою 1, і така є. Відповідь «ні» перетворилася на «так». Про цю
помилку докладно розповість день 2.

**Що дає зведення.** Позначимо «A зводиться до B» як `A ≤ B`. Конспект MIT читає цей знак так: B не легша за A. Звідси
два висновки, і вони дивляться в різні боки.

1. **Якщо B легка, то й A легка.** Щоб розв'язати A, перетворіть вхід і запустіть алгоритм для B. Це лема 34.3 CLRS:
   якщо `A ≤ B` і B лежить у P, то й A лежить у P. Тут і потрібна третя причина з розділу про P: поліноміальне
   перетворення разом з поліноміальним алгоритмом дають поліноміальний алгоритм.
2. **Якщо A важка, то й B важка.** Це те саме твердження, прочитане навпаки. Якби B розв'язувалася швидко, то за
   першим висновком швидко розв'язувалася б і A.

## NP-важкі і NP-повні задачі

Тепер можна дати означення, заради яких написано лекцію.

Задача **NP-важка**, якщо до неї зводиться кожна задача з NP. Така задача не легша за жодну задачу з NP. Erickson
формулює наслідок: якщо NP-важку задачу можна розв'язати за поліноміальний час, то P дорівнює NP.

Задача **NP-повна**, якщо вона NP-важка і сама лежить у NP. NP-повні задачі — найважчі серед задач класу NP.

Теорема 34.4 CLRS каже: якщо хоч одна NP-повна задача розв'язується за поліноміальний час, то P дорівнює NP, і тоді
швидко розв'язуються всі задачі з NP. І навпаки: якщо P не дорівнює NP, то жодна NP-повна задача швидкого алгоритму не
має. CLRS додає, що за десятиліття досліджень поліноміального алгоритму не знайшли для жодної з них. Erickson пише, що
NP-повних задач відомо буквально тисячі.

Erickson пояснює це порівнянням. Назвати задачу NP-важкою — те саме, що сказати: «Якщо в мене є собака, то вона вільно
розмовляє англійською». Ви не знаєте, чи є в нього собака. Але ви певні, що собаки, яка розмовляє, у нього немає.
Отже, собаки немає взагалі. Так само, якщо задача NP-важка, не варто вірити, що для неї є поліноміальний алгоритм.

Ось кілька NP-повних задач зі списку конспекту MIT:

- SAT;
- сума підмножини;
- найдовший простий шлях у графі;
- задача комівояжера у формі «чи є маршрут вартістю не більше `d`»;
- розфарбування графа у три кольори, хоча розфарбування у два кольори лежить у P, і ви розв'язували його пошуком у
  ширину в дні 2 фази 3;
- судоку, «Сапер» і більшість головоломок.

**Звідки взялася перша така задача.** Щоб довести, що задача NP-важка, треба показати зведення до неї від кожної
задачі з NP. Для першої задачі це довелося зробити напряму. Erickson називає авторів: теорему опублікував Стівен Кук у
1971 році і незалежно Леонід Левін у 1973. У CLRS і Erickson першою задачею є здійсненність схеми з логічних
елементів, а до SAT від неї вже зводять. Ідею доведення CLRS описує так: роботу будь-якого алгоритму перевірки можна
розгорнути у схему з логічних елементів, по одній копії схеми комп'ютера на кожен крок.

**Як доводять NP-повноту нової задачі.** Після першої задачі все простіше. Erickson радить витатуювати правило на
руці: щоб довести, що задача A NP-важка, зведіть до A якусь відому NP-важку задачу. Тоді до A зводиться і кожна задача
з NP: спершу до відомої задачі, а від неї до A.

## Пастка: зведення не в той бік

Erickson попереджає, що зведення для доведення важкості йде не в той бік, якого чекає більшість людей. Природно
думати: «моя задача важка, бо я звів її до SAT». Це помилка.

Зведення вашої задачі до SAT каже: SAT не легша за вашу задачу. Про вашу задачу воно каже лише те, що її можна
розв'язати програмою для SAT. До SAT зводиться кожна задача з NP, зокрема й легкі. Розфарбування у два кольори теж
можна звести до SAT, а воно розв'язується пошуком у ширину за лінійний час.

Щоб довести, що ваша задача важка, треба звести відому важку задачу до вашої. Запам'ятати допомагає знак: `A ≤ B`
означає «B не легша за A», і важкість переходить від лівої задачі до правої.

Приклад із сьогоднішньої програми. Ми звели поділ до суми підмножини. Це каже: сума підмножини не легша за поділ. Чи
важкий сам поділ, з цього зведення дізнатися не можна.

У практиці ви зведете розфарбування мапи у три кольори до SAT. Це корисне зведення: воно дає спосіб розв'язати
розфарбування. Але важкості розфарбування воно не доводить.

## Що робити, коли задача виявилася NP-повною

Це не вирок, а зміна запитання. Замість «як розв'язати точно і швидко» питайте «чим можна поступитися»:

- **Розміром.** У вимірі лекції перебір для 20 чисел тривав 67 мілісекунд. Якщо входи завжди малі, перебору досить.
- **Загальністю.** Окремі випадки бувають легкими: розфарбування у два кольори, сума підмножини з малими числами.
- **Точністю.** День 3 цієї фази показує алгоритми, що дають відповідь, гарантовано близьку до найкращої.
- **Гарантією часу.** Перебір з поверненням з фази 4 на багатьох справжніх входах працює швидко, хоч у найгіршому
  випадку він експоненційний.

| Питання | Коротка відповідь |
|---------|-------------------|
| Що таке P? | Задачі розпізнавання, які розв'язуються за поліноміальний час. |
| Що таке NP? | Задачі розпізнавання, де відповідь «так» можна перевірити за поліноміальний час за допомогою сертифіката. |
| Чи означає NP «не поліноміальний»? | Ні. Кожна задача з P лежить у NP. |
| Що таке зведення A до B? | Поліноміальне перетворення входів A на входи B з тією самою відповіддю. |
| Що з нього випливає? | B не легша за A: швидкий алгоритм для B дає швидкий алгоритм для A. |
| Що таке NP-важка задача? | До неї зводиться кожна задача з NP. |
| Що таке NP-повна задача? | NP-важка задача, яка сама лежить у NP. |
| Як довести, що моя задача NP-важка? | Звести до неї відому NP-важку задачу. |
| Чи відомо, що P ≠ NP? | Ні, але майже всі так вважають. |
| Що робити з NP-повною задачею? | Поступитися розміром, загальністю, точністю або гарантією часу. |

## Типові помилки

**Зводити не в той бік.** Це пастка дня: зведення вашої задачі до SAT не доводить, що ваша задача важка.

**Читати NP як «не поліноміальний».** Сортування теж лежить у NP.

**Плутати «NP-важка» і «NP-повна».** NP-повна задача мусить сама лежати в NP. NP-важка задача може й не лежати в NP.
Приклад з конспекту MIT — задача про шахи «чи може гравець гарантовано виграти з цієї позиції»: до неї зводиться кожна
задача з NP, але чи лежить вона сама в NP, невідомо.

**Вважати NP-повну задачу нерозв'язною.** Її можна розв'язати перебором, і для малих входів це нормально. Невідомо
лише, чи є алгоритм, швидкий на всіх входах.

**Рахувати час від величини числа, а не від довжини запису.** Алгоритм, який робить `k` кроків для числа `k`,
експоненційний відносно довжини входу.

**Вважати, що відповідь «ні» перевірити так само легко.** Означення NP говорить лише про сертифікат для відповіді
«так».

**Перевіряти зведення лише на входах з відповіддю «так».** Недбале зведення з програми лекції на таких входах не
помиляється жодного разу. Усі його 625 помилок — на входах з відповіддю «ні».

## Практика

Працюйте в проєкті `algo-lab`. Лекція показала перевірку, перебір і зведення на задачах про суму підмножини і про
поділ. Те саме для SAT і розфарбування ви пишете самі.

**1. Перевірка для SAT.** Функція отримує формулу, записану як масив диз'юнктів, і значення всіх змінних. Вона
повертає, чи істинна формула. Час має бути лінійним від довжини формули.

**2. Перебір для SAT.** Функція перебирає всі значення змінних і повертає перший набір, на якому формула істинна, або
`null`. Виміряйте час на формулах з 15, 20 і 25 змінними, для яких відповіді немає. До запуску запишіть, у скільки
разів, на вашу думку, 25 змінних довші за 15.

**3. Зведення.** Зведіть задачу про розфарбування мапи у три кольори до SAT. Вирішіть, що означає кожна змінна і які
диз'юнкти потрібні. Розв'яжіть перебором мапу з п'яти-шести областей і перекладіть знайдені значення змінних назад у
кольори.

**4. Тести.** Формула з піцою з лекції здійсненна. Формула `(x) і (не x)` нездійсненна. Трикутник з трьох областей
розфарбовується у три кольори. Чотири області, кожна з яких межує з усіма іншими, не розфарбовуються. Перевірте
зведення на випадкових малих мапах проти незалежного перебору розфарбувань, окремо для відповідей «так» і «ні».

**5. Журнал.** Один рядок у `JOURNAL.md` і три числа часу з пункту 2 у `MEASUREMENTS.md`.

## Перевірте себе

**1. Задача: чи є в графі простий шлях щонайменше з `k` ребер? Назвіть сертифікат і перевірку. Чи доводить це, що
задача важка?**

<details><summary>Відповідь</summary>

Сертифікат — сам шлях, тобто список вершин. Перевірка дивиться, що вершини не повторюються, що кожні дві сусідні
вершини списку з'єднані ребром і що ребер не менше ніж `k`. Це лінійний час, тож задача лежить у NP. Про важкість це
нічого не каже: у NP лежать і всі легкі задачі. Те, що ця задача NP-повна, доводять окремо, зведенням до неї.

</details>

**2. Перебір для суми підмножини з 24 числами працював 1160 мілісекунд. Оцініть час для 34 чисел.**

<details><summary>Відповідь</summary>

Десять нових чисел збільшують кількість підмножин у `2^10 = 1024` рази. Кожну підмножину тепер додають з 34 чисел
замість 24, це ще приблизно в півтора раза довше. Разом близько 1160 мс × 1024 × 1,4, тобто приблизно 28 хвилин.

</details>

**3. Ви звели свою задачу X до задачі про найкоротший шлях. Що ви дізналися про X?**

<details><summary>Відповідь</summary>

Що X легка. Найкоротший шлях лежить у P, а зведення `X ≤ найкоротший шлях` каже, що найкоротший шлях не легший за X.
Отже, X теж розв'язується за поліноміальний час: перетворіть вхід і запустіть Дейкстру. Це перший із двох висновків
про зведення.

</details>

**4. Колега каже: «Моя задача NP-важка, бо я звів її до SAT». Що не так?**

<details><summary>Відповідь</summary>

Напрямок. Зведення його задачі до SAT каже лише, що SAT не легша за його задачу і що його задачу можна розв'язати
програмою для SAT. До SAT зводиться кожна задача з NP, зокрема й легкі. Щоб довести важкість, треба звести SAT або
іншу відому NP-важку задачу до його задачі.

</details>

**5. Чому з того, що кожна задача з P лежить у NP, не випливає, що P дорівнює NP?**

<details><summary>Відповідь</summary>

Це лише половина рівності: P лежить усередині NP. Для рівності треба ще, щоб кожна задача з NP лежала в P, тобто щоб
усе, що швидко перевіряється, швидко й розв'язувалося. Цього ніхто не довів і не спростував.

</details>

**6. Запишіть диз'юнктами умову «з двох серверів `a` і `b` працює рівно один».**

<details><summary>Відповідь</summary>

Два диз'юнкти: `(a або b)` — хоча б один працює, і `(не a або не b)` — обидва разом не працюють. Перевірка: якщо
працює лише `a`, обидва диз'юнкти істинні. Якщо працюють обидва, другий хибний. Якщо не працює жоден, перший хибний.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| задача розпізнавання | задача з відповіддю «так» або «ні» |
| поліноміальний час | час, обмежений многочленом від довжини входу |
| клас P | задачі розпізнавання, які розв'язуються за поліноміальний час |
| сертифікат | доказ відповіді «так», який можна перевірити за поліноміальний час |
| клас NP | задачі розпізнавання, для яких є сертифікат і поліноміальна перевірка |
| зведення A до B | поліноміальне перетворення входів A на входи B з тією самою відповіддю |
| NP-важка задача | задача, до якої зводиться кожна задача з NP |
| NP-повна задача | NP-важка задача, яка лежить у NP |
| SAT | задача про те, чи можна зробити логічну формулу істинною |
| літерал | змінна або її заперечення |
| диз'юнкт | кілька літералів, з'єднаних словом «або» |
