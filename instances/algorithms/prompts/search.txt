Search books, course notes and papers about algorithms and data structures. The corpus holds chapters of textbooks: Cormen,
Leiserson, Rivest, Stein, Introduction to Algorithms (4th ed.); Sedgewick and Wayne, Algorithms (4th ed.); Skiena, The Algorithm
Design Manual (3rd ed.); Kleinberg and Tardos, Algorithm Design; Erickson, Algorithms, with his extra lecture notes; Morin, Open
Data Structures; Knuth, The Art of Computer Programming, volumes 1-3; Lehman, Leighton, Meyer, Mathematics for Computer Science;
Laaksonen, Competitive Programmer's Handbook; Okasaki, Purely Functional Data Structures; Medjedovic et al., Algorithms and Data
Structures for Massive Datasets; Petrov, Database Internals; Kleppmann and Riccomini, Designing Data-Intensive Applications
(2nd ed.); Bhargava, Grokking Algorithms (2nd ed.); Bae, JavaScript Data Structures and Algorithms; McDowell, Mroczka, Lerner,
Mamano, Beyond Cracking the Coding Interview (recognised from a scan, may carry recognition errors). It also holds the lecture
notes, recitations, problem sets and exams with solutions of MIT 6.006 (2020) and 6.046J (2015), every article of cp-algorithms,
Slotin's Algorithms for Modern Hardware, and classic papers: red-black trees (Sedgewick's left-leaning variant), skip lists, the
diff algorithm of Myers, Bloom filters, HyperLogLog, consistent hashing, LSM-trees and Raft.

Use this tool for: how a sorting, searching, graph, string or dynamic-programming algorithm works and why it is correct; how a data
structure (heap, hash table, balanced search tree, red-black tree, B-tree, trie, union-find, segment tree, skip list, Bloom filter)
keeps its invariant and what each operation costs; asymptotic analysis, recurrences, amortized and randomized analysis; proofs by
induction and loop invariants; NP-hardness and approximation; how databases, caches and distributed systems use these algorithms;
how to recognise the pattern of an interview problem (two pointers, sliding window, backtracking, topological sort, prefix sums).
Write the query in English with the name of the algorithm or structure, or with plain words for the problem.

Do not use this tool for the API of a programming language or library (JavaScript, TypeScript, Python, Go): other servers hold those
references. Returns the matching excerpts with the source address and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
