### `Ignoring Floors and Ceilings Is Okay, Honest`

Справжнє рівняння сортування злиттям — `T(n) = T(⌈n/2⌉) + T(⌊n/2⌋) + O(n)`, бо масив непарної довжини не ділиться на
рівні половини. На сервері дроби з прикладу «що означає відсортувати 42½ чи 17⅞ елементів» стали числами «42 12» і «17
78». Erickson прибирає округлення **перетворенням області визначення**: спершу переоцінює `T(n) ≤ 2T(n/2 + 1) + n`, а
потім вводить нову функцію `S(n) = T(n + α)` зі сталою `α`, для якої рівняння вже без округлень. Головне для плану:
для асимптотики округлення не важать, і цей прийом показує чому. Деталі перетворення можна пропустити.

### `2 The Ultimate Method: Guess and Confirm`

Головна думка: є лише один безвідмовний спосіб розв'язати будь-яке співвідношення — **вгадати відповідь і довести її
індукцією**. Звідки взялася здогадка, неважливо: від однокурсника, з підручника, з інтернету. Якщо доведення не
виходить, провал підказує, як виправити здогадку.

| Підрозділ | Що в ньому |
|-----------|-----------|
| `2.1 Tower of Hanoi` | `T(n) = 2T(n − 1) + 1`, `T(0) = 0`. Перші значення 0, 1, 3, 7, 15, 31, 63 підказують `2ⁿ − 1`, і індукція це підтверджує. Потім той самий результат отримано розгортанням: після `k` підстановок `T(n) = 2ᵏ T(n − k) + (2ᵏ − 1)`, і при `k = n` маємо відповідь |
| `2.2 Fibonacci numbers` | Здогадка `Fₙ ≤ α · cⁿ` вимагає `c² − c − 1 ≥ 0`, звідки найменше `c = φ = (1 + √5)/2 ≈ 1,618`. Бази дають `Fₙ ≤ φⁿ⁻¹`. Для нижньої межі треба відкинути базу `F₀ = 0` і взяти `F₂ = 1`, звідки `Fₙ ≥ φⁿ⁻²` для `n ≥ 1`. Разом `Fₙ = Θ(φⁿ)`. Це пояснює число 1,618 з лекції дня 5 |
| `2.3 Mergesort` | псевдокод сортування злиттям і процедури злиття. Спрощене рівняння `T(n) = 2T(n/2) + n` з `T(1) = 1` розгортанням дає `T(n) = 2ᵏ T(n/2ᵏ) + kn`, а при `k = log₂ n` — `T(n) = n log₂ n + n`. Це точна формула для завдання 3 практики, тому, якщо ви ще не передбачили її самі, спершу спробуйте |
| `2.4 An uglier divide-and-conquer example` | `T(n) = √n · T(√n) + n`. Erickson по черзі пробує `n lg n`, `n`, `n√lg n` і `n lg lg n`. Перші три провалюються або на верхній, або на нижній межі, а для `n lg lg n` доведення проходить в обидва боки зі сталими `a ≥ 1` і `b ≤ 1`. Підказка Erickson: якщо доведення працює для **будь-якої** сталої, навіть як завгодно малої, межа, мабуть, неточна; якщо доведення накладає умову на сталу, ви, мабуть, знайшли правильну відповідь |

### `3 Divide and Conquer Recurrences (Recursion Trees)`

Той самий метод, що в книжці, з більшою кількістю прикладів. Усі вони варті прочитання, бо показують, як дерево
рекурсії працює там, де головна теорема мовчить.

| Рівняння | Що каже дерево | Відповідь |
|----------|----------------|-----------|
| `2T(n/2) + n` | усі рівні рівні | `Θ(n log n)` |
| `T(3n/4) + n` | шлях зі спадними значеннями | `Θ(n)` |
| `3T(n/2) + n` | рівні ростуть у 3/2 раза, переважають листки | `Θ(n^(log₂ 3))` |
| `2T(n/2) + n/lg n` | рівень `i` коштує `n/(lg n − i)`, сума — гармонічне число | `Θ(n lg lg n)` |
| `4T(n/2) + n lg n` | сума `n² · Σ j/2ʲ`, а `Σ j/2ʲ = 2` | `Θ(n²)` |
| `√n · T(√n) + n` | кожен рівень коштує `n`, рівнів `lg lg n` | `Θ(n lg lg n)` |
| `T(3n/4) + T(n/4) + n` | повні рівні коштують `n`, листки між глибинами `log₄ n` і `log_{4/3} n` | `Θ(n log n)` |
| `T(n/5) + T(7n/10) + n` | повні рівні спадають: `n`, `9n/10`, `81n/100`, … | `Θ(n)`, детермінований вибір k-го елемента |
| `T(n/2) + T(n/4) + 1` | рівні ростуть, межі `√n` і `n` | цими засобами точніше не знайти |

Рядок `4T(n/2) + n lg n` не збігається з `4T(n/2) + n` з практики, але міркування схоже, тож не підглядайте, поки не
розв'яжете своє.

Наприкінці розділу Erickson формулює головну теорему через порівняння `a·f(n/b)` з `f(n)`. Лекція переказує цю версію.
Erickson визнає, що багатьом, і йому самому, легше користуватися деревом рекурсії, ніж пам'ятати формулювання теореми.

**Що з текстом на сервері.** Більшість формул, набраних окремими рядками, на сервері пропали: самі рівняння, суми,

### `An illustrative example`

Рівняння прикладу — `T(n) = 3T(n/4) + Θ(n²)`, на сервері воно загубилося після слів «the recurrence». Для дерева
книжка бере `cn²` замість `Θ(n²)`, де `c` — стала з `Θ`, і вважає `n` степенем 4.

| Крок | Відновлена формула |
|------|--------------------|
| розмір вузла на глибині `i` | `n/4ⁱ`, і дерево закінчується при `i = log₄ n` |
| вузлів на глибині `i` | `3ⁱ` |
| робота рівня `i` | `3ⁱ · c(n/4ⁱ)² = (3/16)ⁱ · cn²` |
| листків (пропущено після «contains») | `3^(log₄ n) = n^(log₄ 3)` |
| робота листків (пропущено після «total leaf cost of») | `Θ(n^(log₄ 3))` |
| сума (пропущено після «for the entire tree») | `T(n) = Σ (3/16)ⁱ cn² + Θ(n^(log₄ 3)) < cn² / (1 − 3/16) + Θ(n^(log₄ 3)) = (16/13)cn² + Θ(n^(log₄ 3)) = O(n²)` |

Число `log₄ 3 ≈ 0,7925`, тож листки дають менше, ніж корінь. Робота рівнів спадає в `16/3` раза, і переважає корінь.
Книжка додає: оскільки корінь сам коштує `Θ(n²)`, межа `O(n²)` не може бути грубішою, ніж треба, отже, вона точна.

Далі підстановка, у якій на сервері пропав середній вираз: `3d(n/4)² + cn² = (3/16)dn² + cn² ≤ dn²`, що виконується
для `d ≥ (16/13)c`. Лекція наводить цей ланцюжок повністю. Абзац про сталі `c` і `d` важливий: `c` дано, бо вона
прихована в `Θ`, а `d` ми вибираємо самі, і вона може залежати від `c`.

### Головне рівняння і теорема 4.1

Рівняння, яке на сервері пропало після «of the form», — **головне співвідношення** (master recurrence):

```
T(n) = aT(n/b) + f(n)
```

де `a > 0` і `b > 1` — сталі, а `f(n)` — **рушійна функція**. Воно описує алгоритм, який ділить задачу розміру `n` на
`a` підзадач розміру `n/b` і витрачає `f(n)` на поділ і збирання відповіді. Приклад книжки: алгоритм Штрассена
множення матриць з `a = 7`, `b = 2`, `f(n) = Θ(n²)`.

Тонкість формулювання 4-го видання: запис `aT(n/b)` насправді означає `a′T(⌊n/b⌋) + a″T(⌈n/b⌉)` з `a′ + a″ = a`. Тобто
теорема сама бере до уваги округлення, і писати їх не треба.

Три випадки, які на сервері зникли після слів «such that» і «then»:

| Випадок | Умова | Відповідь |
|---------|-------|-----------|
| 1 | `f(n) = O(n^(log_b a − ϵ))` для деякої сталої `ϵ > 0` | `T(n) = Θ(n^(log_b a))` |
| 2 | `f(n) = Θ(n^(log_b a) · lgᵏ n)` для деякої сталої `k ≥ 0` | `T(n) = Θ(n^(log_b a) · lg^(k+1) n)` |
| 3 | `f(n) = Ω(n^(log_b a + ϵ))` для деякої сталої `ϵ > 0` і `a·f(n/b) ≤ c·f(n)` для сталої `c < 1` і всіх досить великих `n` | `T(n) = Θ(f(n))` |

Функція `n^(log_b a)`, назва якої на сервері є («watershed function»), а сама формула ні, — **вододільна функція**.

| Що написано | Що це означає |
|-------------|---------------|
| Випадок 1: вододільна функція росте **поліноміально** швидше за рушійну. Робота рівнів дерева росте геометрично від кореня до листків, і листки переважають. | Відповідь — кількість листків. |
| Випадок 2: обидві функції ростуть майже однаково, рушійна швидша лише в `lgᵏ n` разів. Кожен рівень коштує приблизно `n^(log_b a) lgᵏ n`, а рівнів `Θ(lg n)`. | Найчастіше `k = 0`, і тоді відповідь `Θ(n^(log_b a) lg n)`. |
| Випадок 3: рушійна функція росте поліноміально швидше, і виконується умова регулярності. Робота рівнів спадає, переважає корінь. | Умова регулярності виконується для більшості многочленних функцій; вправа 4.5-5 показує функцію, для якої ні. |
| Різниця має бути поліноміальною, хоч і маленькою. `T(n) = 4T(n/2) + n^1,99`: вододільна функція `n²`, рушійна менша в `n^0,01` разів, тож випадок 1 з `ϵ = 0,01`. | `ϵ` може бути як завгодно малим, але сталим. |

### `Using the master method`

Приклади книжки з відновленими вододільними функціями:

| Рівняння | Вододільна функція | Випадок | Відповідь |
|----------|--------------------|---------|-----------|
| `9T(n/3) + n` | `n^(log₃ 9) = n²` | 1, `f(n) = O(n^(2 − ϵ))` для `ϵ ≤ 1` | `Θ(n²)` |
| `T(2n/3) + 1` | `n^(log_{3/2} 1) = n⁰ = 1` | 2, `f(n) = Θ(1)` | `Θ(lg n)` |
| `3T(n/4) + n lg n` | `n^(log₄ 3) ≈ n^0,793` | 3, `ϵ` до приблизно 0,2; регулярність: `3(n/4)lg(n/4) ≤ (3/4)n lg n` | `Θ(n lg n)` |
| `2T(n/2) + n lg n` | `n^(log₂ 2) = n` | 2, `f(n) = Θ(n lg n)`, тобто `k = 1` | `Θ(n lg² n)` |
| `2T(n/2) + Θ(n)`, сортування злиттям | `n` | 2 | `Θ(n lg n)` |
| `8T(n/2) + Θ(1)`, просте рекурсивне множення матриць | `n³` | 1 | `Θ(n³)` |
| `7T(n/2) + Θ(n²)`, Штрассен | `n^(lg 7)`, `lg 7 ≈ 2,807` | 1, `ϵ = 0,8` | `Θ(n^(lg 7))` |

Рядок `2T(n/2) + n lg n` у старих виданнях і в багатьох конспектах вважають прикладом, де головна теорема не працює,
бо там другий випадок формулюють лише для `k = 0`. Четверте видання CLRS його покриває.

### `When the master method doesn't apply`

| Що написано | Що це означає |
|-------------|---------------|
| Рушійну і вододільну функції може бути неможливо порівняти: одна то більша, то менша на нескінченній кількості `n`. | Для алгоритмів таке рідкість. |
| Є **щілина** між випадками 1 і 2: рушійна менша, але не поліноміально. І щілина між 2 і 3: рушійна більша більш ніж у степінь логарифма разів, але не поліноміально. | Також теорема мовчить, якщо не виконано регулярність. |
| Приклад щілини: `2T(n/2) + n/lg n`. `n/lg n = o(n)`, але лише в логарифм разів. Для випадку 1 потрібно `n^ϵ`, а `lg n = o(n^ϵ)`. Для випадку 2 тут `k = −1`, а треба `k ≥ 0`. | Відповідь, `Θ(n lg lg n)`, просять показати у вправі 4.6-3. Лекція і конспект Erickson отримують її деревом рекурсії. |
| Попри це, теорема покриває переважну більшість рівнянь, які трапляються на практиці. | |

  У пунктах b і c функції на сервері загубилися, їх видно лише в PDF.

  рекурсивних викликів і витрачати `Θ(n²)` на решту. Яке найбільше ціле `a` ще дає швидший алгоритм?

### `22.1 The Towers of Hanoi`

| Що написано | Що це означає |
|-------------|---------------|
| Найпростіший спосіб — вгадати й перевірити індукцією. Значення 1, 3, 7, 15, 31, 63 підказують `Tₙ = 2ⁿ − 1`. | Те саме, що в Erickson, але з базою `T₁ = 1`. |
| Структура рекурентного співвідношення повторює структуру доведення індукцією: база спирається на перший рядок співвідношення, крок — на другий. | Тому перевіряти розв'язки індукцією зручно. |
| Для 64 дисків ченцям потрібно понад 18 мільярдів мільярдів ходів. | `2⁶⁴ − 1 ≈ 1,8 · 10¹⁹`. |

**`22.1.1 The Upper Bound Trap`.** Спроба довести «простішу» межу `Tₙ ≤ 2ⁿ` провалюється: з гіпотези виходить лише `Tₙ
≤ 2ⁿ + 1`. Знак `6` на сервері тут означає `≰`. Книжка називає цей крок «аварією потяга в полум'ї». Висновок: як і в
дні 4, гіпотеза мусить бути досить сильною, і точна відповідь доводиться легше за грубішу.

**`22.1.2 Plug and Chug`.** Розгортання: підставити, спростити, повторити, поки не проступить закономірність. Потім
перевірити закономірність ще одним кроком і підставити базу.

### `22.2 Merge Sort`

| Що написано | Що це означає |
|-------------|---------------|
| Приклад злиття списків `5, 7, 10, 23` і `2, 6, 8, 9`: щоразу виводиться менший з двох перших елементів. | Таблиця з підкресленнями на сервері злиплася в один рядок. |
| `Tₙ` — найбільша кількість **порівнянь** для `n` чисел, `n` — степінь двійки. `T₁ = 0`, `Tₙ = 2T(n/2) + n − 1`. | Злиття `n` чисел робить не більше `n − 1` порівнянь: після кожного порівняння виводиться хоча б одне число, а останнє виводиться без порівняння. |
| Перші значення: 0, 1, 5, 17, 49. Закономірності не видно, тож вгадування не допомагає. | Тому книжка розгортає. |
| Розгортання дає `Tₙ = 2ᵏ T(n/2ᵏ) + kn − 2ᵏ + 1`, а при `k = log n` — `Tₙ = n log n − n + 1`. | Таблиця перевірки: для `n = 1, 2, 4, 8, 16` формула дає 0, 1, 5, 17, 49. |

Зверніть увагу: це рівняння не те саме, що `T(n) = 2T(n/2) + n` з практики. Тут база 0 і доданок `n − 1`, тому і точна
формула інша, хоча асимптотика та сама.

### `22.3 Linear Recurrences`

Метод розв'язання співвідношень на кшталт Фібоначчі через характеристичне рівняння. Для плану не потрібен, можна
пропустити. Підсумок методу стоїть у врізці «Short Guide to Solving Linear Recurrences» на початку розділу 22.4.

### `22.4 Divide-and-Conquer Recurrences`

| Що написано | Що це означає |
|-------------|---------------|
| Загальний вигляд `T(n) = Σ aᵢ T(bᵢ n) + g(n)`, де `0 < bᵢ < 1`. | **Інший звичай запису:** MCS множить на `bᵢ < 1`, а CLRS ділить на `b > 1`. `T(n/2)` у CLRS — це `T(bn)` з `b = 1/2` у MCS. |
| **Формула Акри–Бацці:** `T(n) = Θ(nᵖ (1 + ∫₁ⁿ g(u)/u^(p+1) du))`, де `p` задовольняє `Σ aᵢ bᵢᵖ = 1`. | Формула на сервері: `‚ np 1C Z n 1 g.u/ upC1 du`. Інтеграли для плану не потрібні. |
| Для сортування злиттям `2(1/2)ᵖ = 1` дає `p = 1`, і інтеграл дає `Θ(n log n)`. | Та сама відповідь. |
| «Страшне» рівняння `2T(n/2) + (8/9)T(3n/4) + n²`: `p = 2`, бо `2 · 1/4 + (8/9) · 9/16 = 1/2 + 1/2 = 1`, відповідь `Θ(n² log n)`. | Приклад, де підзадачі різного розміру. |
| Асимптотика не залежить від базового випадку і від округлень. | Виняток — рівняння, яке без бази дорівнює нулю, як `T(n) = 2T(n/2)` з `T(1) = 0`. |

### `22.5 A Feel for Recurrences`

Найкорисніший розділ глави для плану. Лекція переказує його таблицею «Відчуття рекурентних співвідношень». Головні
думки:

- вежі Ханоя і сортування злиттям мають схожі рівняння, але для 64 елементів різниця — понад `10¹⁹` ходів проти
  кількох сотень порівнянь;
- менший розмір підзадач важить набагато більше, ніж менша робота на виклик;
- лінійні співвідношення з підзадачами, меншими на сталу, зазвичай дають експоненту, а співвідношення «поділи на

## Запитання до читання

**1. Вправа CLRS 4.4-1 a і b: які відповіді для `T(n) = T(n/2) + n³` і `T(n) = 4T(n/3) + n`?**

<details><summary>Відповідь</summary>

a. Дерево — шлях, робота рівнів `n³`, `n³/8`, `n³/64`, … спадає у 8 разів, переважає корінь: `Θ(n³)`. Головна теорема:
`log₂ 1 = 0`, рушійна функція `n³` поліноміально більша, регулярність `(n/2)³ = n³/8`, третій випадок.

b. На глибині `i` лежить `4ⁱ` вузлів по `n/3ⁱ`, робота рівня `(4/3)ⁱ n` росте, переважають листки, яких `4^(log₃ n) =
n^(log₃ 4) ≈ n^1,26`. Відповідь `Θ(n^(log₃ 4))`, перший випадок теореми.

</details>

**2. Вправа CLRS 4.5-1 a, d, e: розв'яжіть `T(n) = 2T(n/4) + g(n)` для `g(n) = 1`, `n` і `n²`.**

<details><summary>Відповідь</summary>

Вододільна функція `n^(log₄ 2) = n^(1/2) = √n`. Для `g = 1` рушійна менша поліноміально, перший випадок, `Θ(√n)`. Для
`g = n` рушійна більша в `√n` разів, регулярність `2 · n/4 = n/2`, третій випадок, `Θ(n)`. Для `g = n²` теж третій
випадок, регулярність `2(n/4)² = n²/8`, `Θ(n²)`.

</details>

**3. Вправа CLRS 4.5-2: яке найбільше ціле `a` дає професорові Цезарю алгоритм, швидший за Штрассена?**

<details><summary>Відповідь</summary>

Рівняння `T(n) = aT(n/4) + Θ(n²)`. Поки `log₄ a > 2`, тобто `a > 16`, працює перший випадок і час `Θ(n^(log₄ a))`. Він
швидший за `Θ(n^(lg 7))`, якщо `log₄ a < lg 7`, тобто `a < 4^(lg 7) = 2^(2 lg 7) = 7² = 49`. Найбільше ціле `a = 48`.

</details>

**4. Чому Erickson у прикладі `√n · T(√n) + n` вважає підозрілим доведення, яке працює для будь-якої сталої `a`?**

<details><summary>Відповідь</summary>

Якщо верхня межа `T(n) ≤ a · g(n)` доводиться для як завгодно малої `a`, то `T(n)` насправді росте повільніше за
`g(n)`, і межа неточна. Для `g(n) = n lg n` так і вийшло: правильна відповідь `Θ(n lg lg n)` менша. Коли доведення
вимагає умови на сталу, як `a ≥ 1` для `n lg lg n`, межа зазвичай точна.

</details>

**5. Чому в MCS кількість порівнянь сортування злиттям `n log n − n + 1`, а Erickson для «того самого» алгоритму
отримує `n log₂ n + n`?**

<details><summary>Відповідь</summary>

Рівняння різні. MCS рахує лише порівняння: `T₁ = 0` і `n − 1` порівнянь на злиття. Erickson рахує спрощену роботу:
`T(1) = 1` і `n` кроків на злиття. Різна база і різний доданок змінюють молодші доданки точної формули, але старший
доданок `n log n` однаковий, тому асимптотика та сама. Це приклад того, що база й дрібні відмінності в роботі на
рівень не змінюють `Θ`.

</details>

**6. Прочитайте рядок MCS з тексту сервера: `TnD2Tn=2Cn1`.**

<details><summary>Відповідь</summary>

`D` — `=`, `=` між `n` і `2` — це коса риска ділення, `C` — `+`, а мінус між `n` і `1` зник. Отже, `Tₙ = 2T(n/2) + n −
1`: рівняння кількості порівнянь сортування злиттям.

</details>
