### 2.3.1 Метод «розділяй і володарюй»

| Що написано | Що це означає |
|-------------|---------------|
| Сортування вставками — **інкрементний** метод: на кожному кроці відсортована частина довшає на один елемент. Тепер — інший підхід, «divide-and-conquer». | — |
| Три кроки: **divide** — розділити на менші задачі того самого виду; **conquer** — розв'язати їх рекурсивно; **combine** — поєднати розв'язки. | Три кроки з лекції. |
| Сортування злиттям ділить `A[p : r]` у середині `q` на `A[p : q]` (`⌈n/2⌉` елементів) і `A[q + 1 : r]` (`⌊n/2⌋` елементів). Рекурсія зупиняється на одному елементі. | У CLRS ліва половина на один елемент довша, якщо `n` непарне. |
| Злиття на картах: дві стопки сорочкою донизу, найменша карта згори; щоразу брати меншу з двох верхніх. Кількість кроків — від `n/2` до `n`, тож злиття займає `Θ(n)`. | — |
| `MERGE(A, p, q, r)` копіює `A[p : q]` у новий масив `L`, а `A[q + 1 : r]` у `R`, потім зливає назад в `A[p : r]`, беручи `L[i]`, коли `L[i] ≤ R[j]`. Після основного циклу два окремі цикли дописують залишок `L` чи `R`. | Знак `≤` — стабільність. |

Ключовий фрагмент `MERGE`, відновлений з тексту сервера:

```
12  while i < nL and j < nR
13      if L[i] ≤ R[j]
14          A[k] = L[i]
15          i = i + 1
16      else A[k] = R[j]
17          j = j + 1
18      k = k + 1
19  // одну з частин вичерпано: дописати решту іншої
20  while i < nL  …  A[k] = L[i] …
24  while j < nR  …  A[k] = R[j] …
```

### 2.3.2 Аналіз

| Що написано | Що це означає |
|-------------|---------------|
| Час алгоритму «розділяй і володарюй» описують **рекурентним співвідношенням**. Якщо задача ділиться на `a` задач розміру `n/b`, а ділення й поєднання коштують `D(n)` і `C(n)`, то `T(n) = aT(n/b) + D(n) + C(n)`. | Загублене співвідношення (2.3). |
| Для сортування злиттям `a = b = 2`, `D(n) = Θ(1)`, `C(n) = Θ(n)`, тож `T(n) = 2T(n/2) + Θ(n)`, а з явними сталими — `T(n) = 2T(n/2) + c₂n` при `n > 1` і `c₁` при `n = 1`. | Співвідношення (2.4). |
| Дерево рекурсії (рисунок 2.5): на рівні `i` згори `2ⁱ` вузлів по `c₂(n/2ⁱ)`, тобто `c₂n` на рівень. Подвоєння кількості вузлів і половинення вартості кожного взаємно знищуються. | — |
| Рівнів `lg n + 1`, нижній коштує `c₁n`. Разом `c₂ n lg n + c₁n = Θ(n lg n)`. | `lg` у CLRS — логарифм за основою 2. |
| Число рівнів доведено неформальною індукцією: дерево з `2^(i+1)` листками на один рівень вище за дерево з `2ⁱ`. | — |

**Вправи і задачі.** 2.3-1 — простежити сортування `⟨3, 41, 52, 26, 38, 57, 9, 49⟩`. 2.3-3 — сформулювати інваріант
циклу злиття і довести його коректність. 2.3-4 — довести індукцією, що `T(n) = n lg n` для степенів двійки. 2.3-7 — чи

**Увага: злиття Erickson нестабільне.** Процедура `Merge` у рисунку 1.6 бере елемент з лівої половини лише тоді, коли

такого злиття змінять порядок. CLRS (`L[i] ≤ R[j]`), Sedgewick і Skiena (`<=`) беруть ліву половину, і їхнє злиття
стабільне. У практиці дня потрібна саме стабільна версія.

## Sedgewick, Wayne, Algorithms — `2.2 Mergesort`

**Де читати:** розділ 2.2 четвертого видання. На сервері знаки шрифту зіпсовано: `/H11349` означає `≤`, `/H11350` —
`≥`, `/H11001` — `+`, `/H11002` — мінус; `⎣N/2⎦` і `⎡N/2⎤` — округлення вниз і вгору. Рядки з розрідженими літерами —
заголовки абзаців.

**Якщо часу мало,** прочитайте `Abstract in-place merge`, `Top-down mergesort` до твердження G і `Bottom-up
mergesort`.

| Що написано | Що це означає |
|-------------|---------------|
| **Abstract in-place merge**: метод `merge(a, lo, mid, hi)` копіює `a[lo..hi]` у допоміжний масив `aux` і зливає назад в `a`. Чотири умови: ліва вичерпана — брати праву; права вичерпана — ліву; `aux[j] < aux[i]` — праву; інакше — ліву. | Ліва береться при рівних, тож злиття стабільне. |
| **Top-down mergesort** (алгоритм 2.4): `aux` створюється один раз у публічному `sort` і передається в рекурсивний `sort(a, lo, hi)`. | Саме це просить перший пункт практики. |
| Твердження F: від `½ N lg N` до `N lg N` порівнянь для будь-якого масиву довжини `N`. Доказ: `C(N) ≤ C(⌊N/2⌋) + C(⌈N/2⌉) + N` і `C(N) ≥ C(⌊N/2⌋) + C(⌈N/2⌉) + ⌊N/2⌋`. | Верхня межа Sedgewick грубіша на одиницю на кожне злиття: `N` замість `N − 1`. |
| Розв'язок для `N = 2ⁿ`: поділити `C(2ⁿ) = 2C(2ⁿ⁻¹) + 2ⁿ` на `2ⁿ`, отримати `C(2ⁿ)/2ⁿ = C(2ⁿ⁻¹)/2ⁿ⁻¹ + 1` і повторити `n` разів: `C(N) = N lg N`. | Прийом «поділити на `2ⁿ`» — розгортання з дня 6 фази 0. |
| Твердження G: не більше `6N lg N` звернень до масиву: на кожне злиття `2N` на копіювання, `2N` на повернення і до `2N` на порівняння. | — |
| Сортування злиттям дає змогу сортувати мільйони елементів, а елементарні методи — ні. | — |

**Три покращення.**

| Що написано | Що це означає |
|-------------|---------------|
| **Use insertion sort for small subarrays**: перемкнення на вставки для шматків до 15 елементів прискорює типову реалізацію на 10–15 %. | Те саме пропонує задача 2-1 CLRS. |
| **Test whether the array is already in order**: якщо `a[mid] ≤ a[mid + 1]`, злиття пропустити. Тоді сортування відсортованого масиву лінійне. | Запитання 6 лекції. |
| **Eliminate the copy to the auxiliary array**: міняти ролі `a` і `aux` на кожному рівні рекурсії. Це прибирає час копіювання, але не пам'ять. | — |

**Bottom-up mergesort.** Більшість злиттів у рекурсивному варіанті зливають крихітні шматки, тож можна зробити всі
злиття довжини 1 за один прохід, потім усі злиття довжини 2 і так далі. Твердження H: ті самі межі, що для
рекурсивного варіанта, і для `N`, що є степенем двійки, ті самі порівняння в іншому порядку. Sedgewick радить цей
варіант для зв'язних списків: він переставляє посилання і не потребує допоміжного масиву.

**Складність сортування.** Твердження I: жодне сортування порівняннями не може гарантувати менше ніж `lg(N!) ~ N lg N`
порівнянь; доказ — через двійкове дерево порівнянь з `N!` листками. Твердження J: сортування злиттям асимптотично
оптимальне. Sedgewick одразу застерігає, що теорія має межі: сортування злиттям не оптимальне за пам'яттю; найгірший
випадок може бути малоймовірним на практиці; крім порівнянь, важать інші операції, як звернення до масиву; а деякі
дані можна сортувати взагалі без порівнянь. Останнє план розбере в день 11.

У вправах наприкінці розділу трапляється примітка «The resulting sort is not stable» до варіанта злиття, який вправа
просить написати. Це нагадування, що стабільність залежить від деталей злиття, а не від самої ідеї.

## Перевірте себе

**1. CLRS ділить ділянку з 7 елементів на 4 і 3, а Skiena — на 4 і 3 чи на 3 і 4? Чи впливає це на результат?**

<details><summary>Відповідь</summary>

CLRS кладе в ліву частину `⌈n/2⌉ = 4` елементи. Skiena ділить у `middle = (low + high)/2` з цілочисельним діленням і
бере ліву частину `low…middle`: для `low = 0`, `high = 6` це `0…3`, тобто теж 4 елементи. На результат сортування це
не впливає, а кількість порівнянь може трохи відрізнятися для різних способів поділу, бо різні шматки зливаються.

</details>

**2. Чому Skiena пише, що найдорожчий рівень дерева — верхній?**

<details><summary>Відповідь</summary>

На рівні `k` злиття роблять не більше `n − 2ᵏ` порівнянь, бо кожне з `2ᵏ` злиттів заощаджує одне порівняння порівняно
з довжиною. Що нижче рівень, то більше злиттів і більша економія. Верхній рівень має одне злиття і робить до `n − 1`
порівнянь, найбільше з усіх.

</details>

**3. Знайдіть два записи з однаковим ключем, які злиття Erickson поставить у неправильному порядку.**

<details><summary>Відповідь</summary>

Нехай ліва половина `[(1, "a")]`, права `[(1, "b")]`, порівнюється лише число. Перший крок: `A[i] < A[j]` — це `1 <
1`, хибно, тож процедура бере правий елемент `(1, "b")`. Потім ліва частина йде як залишок. Результат `[(1, "b"), (1,
"a")]`, хоча у вході `"a"` стояв лівіше. Зі знаком `≤` результат був би `[(1, "a"), (1, "b")]`.

</details>

**4. Чому верхня межа Sedgewick `N lg N`, а лекція дає `N lg N − N + 1`?**

<details><summary>Відповідь</summary>

Sedgewick оцінює злиття `N` порівняннями, бо так простіше розв'язати співвідношення діленням на `2ⁿ`. Насправді злиття
робить не більше `N − 1`. Різниця в одиницю на кожне злиття, а злиттів `N − 1`, тож точна межа на `N − 1` менша: `N lg
N − (N − 1)`. Для асимптотики `~N lg N` ця різниця не важлива.

</details>

**5. Задача 2-1 CLRS: шматки довжини `k` сортують вставками, а потім зливають. Скільки це коштує, і яке найбільше `k`
не погіршує асимптотику?**

<details><summary>Відповідь</summary>

`n/k` шматків по `Θ(k²)` на вставки — разом `Θ(nk)`. Злиття `n/k` шматків займає `lg(n/k)` рівнів по `Θ(n)` — разом
`Θ(n lg(n/k))`. Загалом `Θ(nk + n lg(n/k))`. Це лишається `Θ(n lg n)`, поки `k = O(lg n)`. На практиці `k` вибирають
вимірами, як 15 у Sedgewick, бо важать сталі множники.

</details>

**6. Чому Sedgewick радить для зв'язних списків варіант знизу вгору, а не рекурсивний?**

<details><summary>Відповідь</summary>

Рекурсивний варіант мусить ділити список навпіл, а для цього треба дійти до середини, тобто пройти половину списку на
кожному рівні. Варіант знизу вгору нічого не ділить: він іде по списку, зливає сусідні шматки довжини 1, потім 2,
потім 4, просто переставляючи посилання. Допоміжний масив не потрібен ні тут, ні там, але варіант знизу вгору
простіший і не потребує стека рекурсії.

</details>
