## Cormen, Leiserson, Rivest, Stein, Introduction to Algorithms — `9.2 Selection in expected linear time`

**Де читати:** розділ 9.2 четвертого видання. Псевдокод злитий з коментарями; рисунки 9.1 і 9.2 відсутні, а деякі
позначення в доведенні загубилися.

```
RANDOMIZED-SELECT(A, p, r, i)
1   if p == r
2       return A[p]                       // при p == r може бути лише i = 1
3   q = RANDOMIZED-PARTITION(A, p, r)
4   k = q − p + 1
5   if i == k
6       return A[q]                       // опорний і є відповіддю
7   elseif i < k
8       return RANDOMIZED-SELECT(A, p, q − 1, i)
9   else return RANDOMIZED-SELECT(A, q + 1, r, i − k)
```

| Що написано | Що це означає |
|-------------|---------------|
| `RANDOMIZED-SELECT` повертає `i`-тий найменший елемент `A[p : r]`. `k` — кількість елементів нижньої частини плюс опорний. | Номер `i − k` у рядку 9 — та сама зміна номера, про яку попереджає лекція. |
| Найгірший час `Θ(n²)`, навіть для мінімуму, якщо щоразу розбивати навколо найбільшого. | — |
| Інтуїція: якщо опорний завжди в середній половині, лишається не більше `3/4`, і `T(n) = T(3n/4) + Θ(n) = Θ(n)` за випадком 3 головної теореми. Випадковий опорний потрапляє в середню половину з імовірністю близько 1/2 — це випробування Бернуллі. | — |
| Розбиття називають **helpful**, якщо після нього в грі лишається не більше `3/4` елементів. Лема 9.1: розбиття корисне з імовірністю щонайменше 1/2. | Середню половину CLRS визначає точно: усі, крім `⌈n/4⌉ − 1` найменших і стількох само найбільших. |
| Теорема 9.2: на масиві з різних елементів очікуваний час — `Θ(n)`. Доведення ділить послідовність розбиттів на **покоління**: кожне починається корисним розбиттям, тож розмір після `k` поколінь не більший за `(3/4)ᵏ n`, а очікувана довжина покоління — не більше 2. | Рисунок 9.2 на сервері відсутній. Сума `Σ 2 (3/4)ᵏ n = 8n` дає `O(n)`. |

**Вправи.** 9.2-1 — довести, що рекурсія ніколи не йде в порожній масив. 9.2-2 — ітеративна версія. 9.2-3 — побудувати
найгіршу послідовність розбиттів для мінімуму масиву `⟨2, 3, 0, 5, 7, 9, 1, 8, 6, 4⟩`.

## Erickson, Algorithms — `1.8 Linear-Time Selection`

**Де читати:** розділ 1.8 глави 1, позначений сердечком як необов'язковий. Документ на сервері починається з кінця
попереднього розділу про доменні перетворення. Псевдокод `MomSelect` з назвами в капітелі на сервері виглядає як
`M/e.sc/d.sc/i.sc/a.sc/n.sc…`: це `MedianOfFive` і `MomSelect`.

| Що написано | Що це означає |
|-------------|---------------|
| Перший лінійний алгоритм знайшли Блум, Флойд, Пратт, Рівест і Тарʼян на початку 1970-х. Він є варіантом quickselect, який Гоар описав у 1961 році на тій самій сторінці, де опублікував quicksort. | — |
| Quickselect, або «one-armed quicksort»: розбиття, потім рекурсія лише в одну частину. Його правильність не залежить від вибору опорного. | — |
| Навіть заради медіани алгоритм мусить розв'язувати загальну задачу вибору: медіана масиву майже ніколи не медіана частини. | — |
| Найгірший випадок `T(n) ≤ max_{0 ≤ 𝓁 ≤ n − 1} T(𝓁) + O(n) = O(n²)`. Якщо опорний добрий, тобто `𝓁 ≤ αn` для `α < 1`, то `T(n) ≤ T(αn) + O(n) = O(n)`. | — |
| «So now all we need is an Approximate Median Fairy». І вона — «the Recursion Fairy in disguise»: групи по 5, медіана кожної перебором, рекурсивна медіана цих медіан як опорний. | `mom` — median of medians. |
| `mom` більша приблизно за `n/10` медіан груп, кожна з яких більша за два елементи групи, тож `mom` більша щонайменше за `3n/10` елементів і менша щонайменше за стільки ж. Друга рекурсія — не більше `7n/10`. | — |
| Рисунок-сітка `5 × ⌈n/5⌉`: якщо уявити кожен стовпець відсортованим, а стовпці впорядкованими за медіанами, `mom` — найближче до центру сітки. «The algorithm does not actually do this!» | — |
| `T(n) ≤ T(n/5) + T(7n/10) + O(n)`: кожен рівень дерева рекурсії коштує не більше `9/10` попереднього, тож `O(n)`. «Hooray! Thanks, Mom!» | Рисунок 1.13 на сервері — рядок дробів `n 7n/10 49n/100 7n/50 n/5 …`. |
| **Sanity checking**: 5 — найменший непарний розмір групи з експоненційним спаданням. З групами по 3 `T(n) ≤ T(n/3) + T(2n/3) + O(n) = O(n log n)`, «no faster than sorting». | — |
| Медіана п'яти — не більше 6 порівнянь, розбиття після рекурсії — лише `2n/5` додаткових, бо `3n/10` з кожного боку вже відомі. `T(n) ≤ T(n/5) + T(7n/10) + 8n/5`, звідки `T(n) ≤ 16n` порівнянь. | На сервері `8n5 ∑ 910i` означає `(8n/5) · Σ (9/10)^i = (8n/5) · 10 = 16n`. |
| На практиці медіана медіан повільніша навіть за сортування для помірно великих масивів. «The right way to choose the pivot element in practice is to choose it uniformly at random». Тоді для медіани в середньому не більше `4n` порівнянь. | Лекція рахує точніше: `3,39n`. |

## Cormen, Leiserson, Rivest, Stein, Introduction to Algorithms — `9.3 Selection in worst-case linear time`

**Де читати:** розділ 9.3 четвертого видання. Четверте видання дає версію `SELECT`, що працює на місці: групи
складаються з елементів через крок `g`, а не з сусідніх. Псевдокод на сервері злитий; рисунок 9.3 відсутній.

| Що написано | Що це означає |
|-------------|---------------|
| `SELECT` гарантує `Θ(n)` у найгіршому випадку; алгоритм «remarkable and theoretically interesting», але «not nearly as practical as RANDOMIZED-SELECT. It is mostly of theoretical interest». | Те саме, що каже Erickson. |
| Групи по 5 займають стовпці: перший стовпець — `A[p]`, `A[p + g]`, `A[p + 2g]`, `A[p + 3g]`, `A[p + 4g]`, де `g = (r − p + 1)/5`. Кожен стовпець сортують, медіани опиняються в середньому рядку, і рекурсивно знаходять медіану медіан. | Розміщення стовпцями дозволяє обійтися без окремого масиву медіан. |
| Рисунок 9.3: елементи на синьому тлі гарантовано не більші за опорний `x`, на жовтому — не менші; кожна область має щонайменше `3g/2` елементів. Тому рекурсія отримує не більше `7n/10`. | Той самий аргумент, що в Erickson. |
| Рекурентне співвідношення `T(n) ≤ T(n/5) + T(7n/10) + Θ(n)` має розв'язок `Θ(n)`, бо `1/5 + 7/10 < 1`. | — |

**Вправи і задачі.** 9.3-1 — групи по 7 теж дають лінійний час. Одна з вправ просить використати `SELECT` як
підпрограму, щоб quicksort працював `O(n lg n)` у найгіршому випадку. Задача 9-1 — три способи знайти `i` найбільших у
відсортованому порядку: сортування; купа і `i` вилучень; вибір, розбиття і сортування лише `i` найбільших. Задача 9-2
— спрощений `RANDOMIZED-SELECT` без перевірки `i == k`. Остання задача розділу уточнює Erickson: для груп по 3 відома
лише верхня оцінка `O(n log n)`, і невідомо, чи вона точна для самого алгоритму. Алгоритм `SELECT3` повторює ідею груп
по 3 ще раз на середній групі медіан і так гарантує `O(n)`.

**Примітки до глави.** Лінійний у найгіршому випадку алгоритм — від Блума, Флойда, Пратта, Рівеста і Тарʼяна; швидка
рандомізована версія — від Гоара; Флойд і Рівест покращили її, вибираючи опорний рекурсивно з малої вибірки.

## Перевірте себе

**1. Чому в рядку 9 `RANDOMIZED-SELECT` шукає `i − k`-тий, а не `i`-тий?**

<details><summary>Відповідь</summary>

`k` елементів — уся нижня частина разом з опорним — менші за кожен елемент верхньої частини. Тож `i`-тий найменший у
всій ділянці, якщо він у верхній частині, має там номер `i − k`: перед ним у верхній частині стоїть `i − k − 1`
елементів, а ще `k` залишилися знизу.

</details>

**2. Чому CLRS вважає розбиття корисним з імовірністю щонайменше 1/2?**

<details><summary>Відповідь</summary>

Розбиття корисне, якщо опорний потрапив у середню половину значень: тоді і нижня, і верхня частини не більші за `3/4`
ділянки. Середня половина містить приблизно половину елементів, а опорний вибирається рівноймовірно серед усіх. Звідси
ймовірність близько 1/2; CLRS акуратно доводить нижню межу 1/2 з урахуванням округлень.

</details>

**3. Erickson отримує `16n` порівнянь для медіани медіан. Звідки `8n/5` у рекурентному співвідношенні?**

<details><summary>Відповідь</summary>

Медіана кожної групи з п'яти коштує не більше 6 порівнянь, а груп `n/5`: разом `6n/5`. Після того як опорний знайдено,
`3n/10` елементів уже відомо як менші, а `3n/10` — як більші, тож розбиття порівнює з опорним лише решту, `2n/5`
елементів. `6n/5 + 2n/5 = 8n/5`.

</details>

**4. Чому 5 — найменший непарний розмір групи, що працює?**

<details><summary>Відповідь</summary>

Для груп розміру `g` пошук опорного рекурсивно обробляє `n/g` медіан, а гарантована частка з кожного боку — половина
груп по `(g + 1)/2` елементів, тобто близько `n/4 + n/(4g)`. Рекурсія після розбиття отримує решту, близько `3n/4 −
n/(4g)`. Сума `n/g + 3n/4 − n/(4g) = 3n/4 + 3n/(4g)` менша за `n` лише при `g > 3`. Для `g = 3` вона дорівнює `n`, і
час `O(n log n)`; для `g = 5` — `9n/10`.

</details>

**5. Задача 9-1 CLRS: як найшвидше знайти `i` найбільших у відсортованому порядку для `i` набагато меншого за `n`?**

<details><summary>Відповідь</summary>

Третій спосіб: вибрати `(n − i + 1)`-тий найменший елемент за `O(n)`, розбити навколо нього за `O(n)` і відсортувати
лише `i` найбільших за `O(i log i)`. Разом `O(n + i log i)`. Сортування всього коштує `O(n log n)`, а купа з `i`
вилученнями — `O(n + i log n)`.

</details>

**6. Код cp-algorithms приймає вектор за значенням. Яку пастку з плану це закриває?**

<details><summary>Відповідь</summary>

Передача за значенням у C++ робить копію, і функція переставляє елементи копії, а не масиву викликача. Це той самий
захист, що `slice()` і тип `readonly` у лекції: вибір не перемішує чужі дані. Ціна — `Θ(n)` пам'яті і часу на копію.

</details>
