## Python — модуль `collections`: `deque` і `defaultdict`

**Де читати:** документ `cpython--py-doc-library-collections-55017249` у примірнику `python`, сторінка
`docs.python.org/3.15/library/collections.html`. Записи розділів про `deque` і `defaultdict` однакові для версій
3.13–3.15. Потрібні розділи «`deque` objects» і «`defaultdict` objects».

| Що написано | Що це означає |
|-------------|---------------|
| Дека узагальнює стек і чергу; назва вимовляється «deck» і означає «double-ended queue». | Двобічна черга. |
| Додавати й забирати можна з обох боків «with approximately the same O(1) performance in either direction». | Для пошуку в ширину досить `append` і `popleft`. |
| Списки оптимізовано для операцій сталої довжини; `pop(0)` і `insert(0, v)` коштують `O(n)` через переміщення даних у пам'яті. | Пастка дня, прямо в документації. |
| `popleft()` на порожній деці кидає `IndexError`. | Тому цикл пишуть `while queue:`. |
| Доступ за номером коштує `O(1)` біля кінців і `O(n)` у середині; «For fast random access, use lists instead». | Дека не заміняє масив. |
| Параметр `maxlen` обмежує довжину: зайві елементи випадають з протилежного кінця. | Для пошуку в ширину не потрібен; корисний для «останніх N подій». |
| `defaultdict` для відсутнього ключа викликає `default_factory`, вставляє результат у словник і повертає його. | Чому читання `graph["d"]` у лекції створило вершину. |
| Метод `__missing__` викликається лише для звертання у квадратних дужках; `dict.get` поверне `None`. | Чому `get` у лекції нічого не створив. |
| Приклад: `defaultdict(list)` групує пари «ключ — значення» у словник списків; це простіше і швидше, ніж `dict.setdefault`. | Це і є побудова списків суміжності: ключ — вершина, значення — сусід. |

Підручник Python каже про чергу те саме коротше. Розділ «Using Lists as Queues» документа `Data Structures` пояснює,
що забирати з початку списку повільно, бо всі інші елементи зсуваються на одне місце, і показує чергу на `deque` з
п'ятьма іменами.

## Python — модуль `sys`: `getrecursionlimit` і `setrecursionlimit`

**Де читати:** документ `cpython--py-doc-library-sys-2307968c` у примірнику `python`, сторінка
`docs.python.org/3.15/library/sys.html`. Запис про `setrecursionlimit` однаковий для версій 3.5–3.15. Виняток
`RecursionError` описано в документі `Built-in Exceptions`, розділ «Concrete exceptions».

| Що написано | Що це означає |
|-------------|---------------|
| Межа рекурсії — це найбільша глибина стека інтерпретатора Python. | Рахуються всі вкладені виклики, а не лише рекурсивні. |
| Межа не дає нескінченній рекурсії переповнити стек C і обвалити Python. | Навіщо межа взагалі існує. |
| Найвища можлива межа залежить від платформи; «a too-high limit can lead to a crash». | Чому лекція радить явний стек, а не підняття межі. |
| Якщо нова межа нижча за поточну глибину, `setrecursionlimit` кидає `RecursionError`. | Межу не можна опустити нижче місця, де ви вже є. |
| `RecursionError` походить від `RuntimeError`; з'явився у версії 3.5, раніше кидали сам `RuntimeError`. | Тому старий код ловить `RuntimeError`. |

Числа 1000 в описах цих двох функцій немає. Його показує перший рядок виводу програми лекції.

## Go — `package container/heap`

**Де читати:** документ `std--container-heap-8dced8b5` у примірнику `go`, сторінка `pkg.go.dev/container/heap` для Go
1.27. Цю сторінку ви читали в дні 13 фази 1. Сьогодні потрібні приклад `PriorityQueue` у розділі «Overview» і функція
`Fix`.

| Що написано | Що це означає |
|-------------|---------------|
| Купа — дерево, у якому кожен вузол найменший у своєму піддереві; найменший елемент лежить під номером 0. | Мінімальна купа, як ваша `MinHeap`. |
| Щоб отримати пріоритетну чергу, порядок у методі `Less` задають за «(negative) priority». | `Pop` віддає найменший за `Less`; щоб першим ішов найбільший пріоритет, порівняння перевертають. |
| Приклад `PriorityQueue`: запис має поля `value`, `priority` та `index`; метод `Swap` оновлює `index` обох записів. | Запис завжди знає свій номер у купі. |
| Метод `update` змінює пріоритет і викликає `heap.Fix(pq, item.index)`. | Справжнє зменшення ключа для Дейкстри. |
| `Fix` коштує `O(log n)` і дешевший, ніж `Remove` і наступний `Push`. | — |
| `Init` коштує `O(n)`; `Pop` рівносильний `Remove(h, 0)`. | Дейкстра починає з одного запису, тому `Init` їй не потрібен. |
| Приклад друкує `05:orange 04:pear 03:banana 02:apple`. | Від найбільшого пріоритету до найменшого, бо `Less` порівнює через `>`. |

## Go 101 — «Arrays, Slices and Maps in Go»

**Де читати:** документ `go101--pages-fundamentals-container-html-96385604` у примірнику `learning-go`, стаття Тапіра
Ліу на сайті Go 101. У дні 13 фази 1 ви читали розділи про внутрішню будову зрізу, `append` і обхід. Сьогодні потрібні
розділи «Simple Overview of Container Types and Values» і «Derive Slices From Arrays and Slices».

| Що написано | Що це означає |
|-------------|---------------|
| Доступ до елемента масиву, зрізу й мапи коштує `O(1)`, але доступ до мапи «generally… several times slower». | У вимірі лекції обхід графа в мапі був повільніший в 11 разів. |
| Переваги мапи: ключ будь-якого порівнюваного типу; менше пам'яті, коли більшість елементів нульові. | Мапа доречна для вершин-рядків і рідкісних великих номерів. |
| Зріз, виведений з іншого зрізу, лежить «on the same memory segment». | Чому `q = q[1:]` нічого не копіює. |
| Форма `base[low : high]` рівносильна `base[low : high : cap(base)]`. | Місткість нового зрізу рахується від `low` до кінця пам'яті; тому в лекції вона стала 3 замість 4. |
| Індекси обмежені місткістю, а не довжиною: `low <= high <= cap(base)`. | Зріз можна «продовжити» в межах місткості. |
| «Kind-of memory leaking»: функція повертає `s[50:60]` зі зрізу місткістю 100, і половина виділеної пам'яті марнується. | Те саме відбувається з чергою через `q = q[1:]`, доки зріз не переїде в нову пам'ять. |

## Перевірте себе

**1. Документація каже, що доступ до середини деки коштує `O(n)`. Чому це не заважає пошуку в ширину?**

<details><summary>Відповідь</summary>

Пошук у ширину ніколи не звертається до середини черги. Він лише додає в один кінець через `append` і забирає з
другого через `popleft`, а обидві операції коштують `O(1)`.

</details>

**2. Чому `graph[v]` у `defaultdict` створює вершину, а `graph.get(v)` ні?**

<details><summary>Відповідь</summary>

Значення за замовчуванням створює метод `__missing__`. Документація каже, що його викликає лише звертання у квадратних
дужках. Метод `get` працює, як у звичайному словнику: повертає `None` або другий аргумент і словника не змінює.

</details>

**3. У прикладі `PriorityQueue` метод `Less` повертає `pq[i].priority > pq[j].priority`. Що змінити для Дейкстри?**

<details><summary>Відповідь</summary>

Знак. Функція `heap.Pop` віддає запис, найменший за `Less`. У прикладі «найменшим» оголошено запис із найбільшим
пріоритетом, тому він виходить першим. Дейкстрі першою потрібна вершина з найменшою відстанню, тож `Less` має
повертати `pq[i].dist < pq[j].dist`.

</details>

**4. Go 101 показує функцію, що повертає `s[50:60]` зі зрізу завдовжки 10 і місткістю 100. Чому це не помилка і що тут
марнується?**

<details><summary>Відповідь</summary>

Індекси у виразі зрізу обмежені місткістю, а не довжиною, тому 50 і 60 дозволені. Новий зріз дивиться на елементи з
50-го і має місткість 50. Перші 50 місць виділеної пам'яті вже ніхто не використає, але звільнити їх не можна, доки
живе повернутий зріз. Go 101 називає це «kind-of memory leaking».

</details>
