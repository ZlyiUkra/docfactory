Search the documentation of amqp-connection-manager -- the Node.js library that wraps amqplib with automatic
reconnection to RabbitMQ, the second half (with amqplib) of the RabbitMQ transport of NestJS microservices (repository
jwalton/node-amqp-connection-manager, package amqp-connection-manager on npm). The corpus holds the README of every
stable version from 1.0 to 5.0 -- the README is the whole documentation of the package: `connect` with a list of
broker URLs, `findServers`, heartbeats and reconnection timing, the `AmqpConnectionManager` events (`connect`,
`disconnect`, `connectFailed`, `blocked`, `unblocked`), `createChannel` with `setup` functions that re-run after every
reconnect, the `ChannelWrapper` with `publish`, `sendToQueue`, `ack`, `nack`, `addSetup`, `removeSetup`,
`waitForConnect`, confirm channels and the in-memory queue of messages sent while the broker is unreachable --; the
GitHub release notes of every stable version; and the npm registry history of the package (date of every version,
dist-tags, dependencies, the Node.js requirement). Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about amqp-connection-manager as it describes itself -- how to connect with failover,
what happens to messages published while disconnected, how setup functions declare queues again after a reconnect,
what an option of `connect`, `createChannel` or `publish` does and its default, which events to listen to -- and above
all history and compatibility: since which version an option exists, what changed between versions (the release notes
list features, fixes and breaking changes), which Node.js and amqplib a version requires, and when every version came
out.

Do not call this for amqplib itself (the channel methods, `assertQueue` options), RabbitMQ (queue types, policies,
clustering), the NestJS RabbitMQ transport or @golevelup/nestjs-rabbitmq: their documentation is not here -- these pages
only show how this library wraps them -- and the search will return excerpts that merely mention them, with
confident-looking titles.

`version` narrows the search to one release line. The library carries plain numbers: a line of one number keeps every
document of that major ("4" keeps 4.0.0 to 4.1.15), two numbers keep a minor ("4.1"), three an exact version
("5.0.1"). Leave `version` empty to search everything, including text that carries no version. Every excerpt comes
back with `versions`: each version whose documents contain this exact text, newest first -- a README that stayed the
same across versions is returned once, with all of them listed, so the list itself shows from which to which version
the documentation said exactly this.

Write the query in English, with the names the documentation itself uses ("connect", "AmqpConnectionManager",
"createChannel", "ChannelWrapper", "setup", "addSetup", "publish", "sendToQueue", "waitForConnect", "findServers",
"heartbeatIntervalInSeconds", "reconnectTimeInSeconds", "confirm", "json", "disconnect", "connectFailed", "blocked"),
not in the user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike --
and the word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація amqp-connection-manager". Identifiers, option names and titles stay in English, spelled exactly
as the documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an
excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
