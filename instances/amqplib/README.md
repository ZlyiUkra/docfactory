# amqplib — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про amqplib — клієнт AMQP 0-9-1 для Node.js, яким працюють з RabbitMQ
(репозиторій amqp-node/amqplib, сайт amqp-node.github.io/amqplib, пакет amqplib на npm) — за документацією всіх
стабільних версій: сторінки сайту на час кожної мінорної версії, README кожної версії, журнал змін та історія версій у
реєстрі npm. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані
домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Примірник — другий у родині RabbitMQ: сервер окремо (`rabbitmq`), кожен клієнт Node окремо, як у родинах Redis, Mongo і
Kafka. Далі в родині — `amqp-connection-manager` і `@golevelup/nestjs-rabbitmq`.

amqplib — найпоширеніший клієнт RabbitMQ для Node.js (близько 1,9 млн завантажень за тиждень до 25.10.2026): з'єднання,
канали, черги й обмінники, публікація, споживання, підтвердження, prefetch, канали з підтвердженнями (confirm
channels), обидва API — проміси й колбеки. На ньому стоїть транспорт RabbitMQ мікросервісів NestJS. Лінія 0.10 була
чинною з 2022 до 1.0.0 (березень 2026) і досі має близько 64 % завантажень, лінія 2 (найновіша 2.2.0 від 28.09.2026) —
близько 22 %.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df amqplib <крок>`.

## Версії

Версія — номер випуску. Сторінки сайту несуть останню латку мінорної версії, за якої сайт був саме таким: береться
останній коміт `gh-pages` перед першим випуском наступної мінорної (для 2.2 — голова гілки). Де сайт не змінювався кілька
мінорних поспіль, коміт стоїть під найновішою з них: 0.7.1 для 0.5–0.7, 1.2.0 для 1.0–1.2, 2.2.0 для 2.0–2.2. Фільтр
`version` бере мажор (`"2"`), мінор (`"0.10"`) або точну версію (`"0.10.9"`). На питання «як це зробити зараз» промпт
велить шукати для 0.10 і для 2 — обидві лінії в ходу. Сторінка, що не змінилася між версіями, — один документ з усіма
ними, тож перелік версій уривка сам показує, відколи й доки документація казала саме це.

## Родина RabbitMQ: піднімати разом

Цей примірник — частина родини RabbitMQ: сам брокер і три бібліотеки для Node.js. Питання про клієнта впирається в
поведінку брокера (підтвердження, prefetch, dead lettering, типи черг), а питання про модуль NestJS — у те, що роблять
під ним amqplib і amqp-connection-manager. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї
теки перелічує всі чотири сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `rabbitmq` | `rabbitmq-docs` | 8890 | сам RabbitMQ 3.11–4.4: типи черг, обмінники, підтвердження, кластер, `rabbitmq.conf`, нотатки релізів |
| `amqplib` | `amqplib-docs` | 8891 | клієнт amqplib для Node.js (на ньому транспорт RMQ NestJS) |
| `amqp-connection-manager` | `amqp-connection-manager-docs` | 8892 | перепідключення поверх amqplib, друга половина транспорту RMQ NestJS |
| `golevelup-nestjs-rabbitmq` | `golevelup-nestjs-rabbitmq-docs` | 8893 | модуль NestJS `@golevelup/nestjs-rabbitmq` з `@RabbitSubscribe` і `@RabbitRPC` |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/amqplib-corpus-2026-10-25.tar.gz` (88 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\amqplib-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/amqplib/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/amqplib-corpus-РРРР-ММ-ДД.tar.gz -C instances/amqplib corpus raw
find instances/amqplib/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/amqplib/raw
gzip -9 -c instances/amqplib/index/passages.json > instances/amqplib/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/amqplib-corpus-2026-10-25.tar.gz -C instances/amqplib
./df amqplib smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/amqplib/index/passages.json.gz`,
далі `./df amqplib vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df amqplib …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df amqplib sources --why   # перелік джерел і білий список
./df amqplib refresh         # завантажити все задеклароване (близько хвилини)
./df amqplib manifest        # оновити паспорт
./df amqplib setup           # Qdrant чи пошук лише по словах
./df amqplib vectors         # залити корпус у docs-amqplib
./df amqplib smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df amqplib serve          # порт 8891
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8891/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user amqplib-docs http://127.0.0.1:8891/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `amqplib-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
