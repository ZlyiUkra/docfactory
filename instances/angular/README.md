# angular — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Angular — фреймворк Google для вебзастосунків (компоненти й шаблони,
сигнали, впровадження залежностей, маршрутизатор, форми, HttpClient, рендеринг на сервері, тестування, CLI), а також
про AngularJS 1.x, Angular Material і CDK. Документація — кожної стабільної мінорної лінії: Angular 2.0–22.2
(67 ліній), AngularJS 1.0 і 1.2–1.8, Material і CDK 5.0–22.2. Джерела — офіційні сайти angular.dev, angular.io усіх
мажорів, v2.angular.io і code.angularjs.org, репозиторії angular/angular, angular/components, angular/angular-cli,
angular/angular.js і angular/material2-docs-content, пакети й реєстр npm; лише англійською й лише стабільні версії.
Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену.
Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Angular за десять років змінив форму кілька разів, і код однієї лінії на іншій часто не працює. 2.0 (15.09.2016)
переписав AngularJS з нуля; 4.0 перейшов на теку `packages/` і пропустив номер 3; 9.0 зробив типовим компілятор Ivy;
14–17 принесли окремі (standalone) компоненти, сигнали й вбудований потік керування (`@if`, `@for`, `@defer`), а
19.0 зробив standalone типовим; 20–22 — беззонне виявлення змін, `resource`, сигнальні форми. Сайт кожного мажора
показує лише свою останню мінорну, а сайти v12–v17.angular.io сторінок довідника API (core, common, router, forms)
уже не віддають зовсім. Тож відповідь мусить знати версію, а версії мусять бути всі.

**Що є що.** **Компонент** — клас із декоратором `@Component` і шаблоном. **Сигнал** — значення, що сповіщає
залежних про зміну (`signal`, `computed`, `effect`, `linkedSignal`). **Впровадження залежностей** (DI) — Angular сам
створює й передає сервіси (`inject`, `providers`, `InjectionToken`). **NgModule** — давній спосіб групувати
оголошення; **standalone**-компонент імпортує залежності сам. **Точка входу** — підшлях пакета (`@angular/core`,
`@angular/common/http`, `@angular/core/testing`). **AngularJS** — перша, зовсім інша версія фреймворку (`$scope`,
контролери, директиви); тут вона — лінія версій «1». **Material** — набір компонентів Material Design, **CDK** —
базові будівельні блоки без вигляду (overlay, drag and drop, virtual scroll).

## Звідки документація

- **Посібники з тегів.** Читач `ghdocs-history` з полем `ng_docs` бере markdown `aio/content` і `adev/src/content` на
  останньому патчі кожної мінорної. Код прикладів на сайті не записаний у сторінці: `<code-example path region>`
  (aio) і `<docs-code path visibleRegion>` (adev) лише посилаються на файл прикладу. Читач підставляє його з того
  самого тегу за областями `#docregion`, як генератор сайту; розмітка `<docs-step>`, `<docs-callout>`, `{@link}`
  стає текстом. Посібники 4.0 писали шляхи за розкладкою репозиторію angular.io (`toh-pt5/ts/…`, `cb-…`), а на
  тегах 4.0 тексти прикладів у angular/angular ще не лежали: файл береться з найближчого тегу, де він є (15 таких
  підстановок, усі в 4.0–4.1, одна — з angular.io), і рядок над кодом каже, з якого тегу код.
- **Довідник API з коду** (`ng-api-history`). Перелік символів і чисті оголошення — з золотих файлів перевірки
  публічного API (`tools/public_api_guard` у 2.x–8.x, `goldens/public-api` з 9.0), опис, примітки до використання й
  описи членів — з JSDoc файлів типів тарбола npm тієї самої версії (`@angular/router` 2.x має власну нумерацію 3.x).
  Приклади `{@example шлях region}` — код області з `packages/examples` (у 2.x `modules/@angular/examples`) того
  самого тегу; опис `NG_VALIDATORS` 2.x–4.0 посилається на файл, якого немає ніде, і це так і сказано.
- **Сайти.** angular.dev v18–v22 (`adev-html`): текст — з кешу стану сторінки, бо у v18–v19 вкладки «Description» і
  «Usage Notes» намальовані лише там; перелік — обхід посилань від `/api` і `/cli`. angular.io v4–v17 — `aio-json`;
  посібники цих сайтів не беруться (вони є з тегів), лише згенеровані сторінки API і CLI. v2.angular.io — `ng2-site`,
  AngularJS — `angularjs-docs` (шматки `partials/*.html` застосунку документації).
- **Material і CDK.** Зібраний HTML сайту з репозиторію `material2-docs-content`: гілка на кожну мінорну 6.4–22.2 і
  найновіший знімок-тег 5.0, 5.1, 5.2; для 5.0–6.3 — ще й markdown оглядів із тегів angular/components.
- **npm.** Реєстр 12 пакетів; README @angular/cli і `angular` — з репозиторію на кожній версії; README @angular/core,
  common, router, forms, platform-browser, compiler, animations, material і cdk є лише в пакеті — береться з тарбола
  останнього патча кожної мінорної (588 тарболів, 32 неповторні тексти).

## Межі, про які треба пам'ятати

- Посібники Angular 2.0–2.3 недосяжні: тексти 2.x жили в репозиторії angular.io без тегів, шаблонами Jade. Є сайт
  v2.angular.io (2.4.10) і довідник API з коду кожної мінорної 2.0–2.4.
- Довідника API Material 6.0–6.3 немає: стабільних знімків docs-content для цих ліній не існує.
- Сторінки сайтів — один знімок на мажор (остання мінорна); версії інших мінорних — з тегів і довідника з коду.
- Нотатки релізів GitHub angular/angular і angular/components не беруться: їх складено з того самого журналу змін.
- Передрелізів (next, rc, beta), RxJS, NgRx, Nx, Ionic, AngularFire та інших сторонніх бібліотек тут немає; RxJS має
  свій примірник `rxjs`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/angular-corpus-2026-10-28-examples.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\angular-corpus-2026-10-28-examples.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів
немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/angular/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/angular-corpus-РРРР-ММ-ДД.tar.gz -C instances/angular corpus raw
find instances/angular/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/angular/raw
gzip -9 -c instances/angular/index/passages.json > instances/angular/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/angular-corpus-2026-10-28-examples.tar.gz -C instances/angular
./df angular smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/angular/index/passages.json.gz`, далі
`./df angular vectors` заллє колекцію Qdrant (близько хвилини на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df angular …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/angular/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df angular sources --why   # перелік джерел і білий список
./df angular refresh         # усе задеклароване: близько 5 годин мережею (паузи 0,1 с)
./df angular manifest        # оновити паспорт
./df angular setup           # Qdrant чи пошук лише по словах
./df angular vectors         # залити корпус у docs-angular
./df angular smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df angular serve          # порт 8927
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8927/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user angular-docs http://127.0.0.1:8927/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `angular-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
