Search the Angular documentation -- every stable minor line of Angular 2.x to 22.x, AngularJS 1.x, Angular
Material and the CDK, and the Angular CLI -- and return the matching excerpts with the versions each one belongs
to. What is here: the guides, tutorials, error reference and extended diagnostics of angular.dev
(adev/src/content of every stable minor tag 17.0 to 22.2) and of angular.io (aio/content of every stable minor
tag 4.0 to 17.3), with the code of their examples filled in from the same tag; the API reference and the CLI
reference of every major site (v4.angular.io to v17.angular.io, v18.angular.dev to v21.angular.dev and
angular.dev for 22): every class, decorator, function, directive, pipe, interface, type, injection token and
CLI command with its options; the old site v2.angular.io (Angular 2.4: guides, cookbook, tutorial, API); the
AngularJS documentation of 1.0, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7 and 1.8 (code.angularjs.org: guide, tutorial, the
API of every module, directive, service and filter, the error reference); Angular Material and the CDK (the API
reference, the overview of every component and the guides of every minor line 6.4 to 22.2, the markdown
overviews of 5.0 to 6.3); the old Angular CLI documentation (docs/documentation of 1.0 to 8.3); the changelogs
of angular/angular (2.0 to 22.2), angular/components, angular/angular-cli (12.0 onward, and the GitHub release
notes before that) and angular/angular.js; the README of every repository tag; and the npm registry history of
@angular/core, common, router, forms, platform-browser, compiler, animations, ssr, cli, material, cdk and
angular (AngularJS): versions, dates, dist-tags, peer dependencies and Node and TypeScript requirements.

Call this when a question is about Angular itself: components, templates and control flow (@if, @for, @switch,
@defer), signals (signal, computed, effect, linkedSignal, resource, httpResource, input, output, model,
viewChild, toSignal), change detection and zoneless, dependency injection (inject, providers, InjectionToken,
hierarchical injectors), directives and pipes, NgModules and standalone components, the router (routes, guards,
resolvers, lazy loading, RouterLink, withComponentInputBinding), forms (reactive forms, template-driven forms,
signal forms, validators), HttpClient and interceptors, server-side rendering and hydration (@angular/ssr),
testing (TestBed, ComponentFixture, harnesses), animations, i18n, the compiler and its error codes (NG0100,
NG8001 and the rest), the CLI (ng new, generate, build, serve, test, update, angular.json, builders and
schematics), Angular Material and the CDK (components, theming, overlay, drag and drop, virtual scroll, a11y,
component harnesses), AngularJS 1.x ($scope, controllers, directives, services, $http, ngRoute, components,
$compile) -- and history: since which version an API exists, when it was deprecated and what replaces it, what
changed in a release, how to migrate between versions, which TypeScript and Node versions a release needs.
Example query: "linkedSignal computation previous".

Do not call this for RxJS operators themselves, NgRx, Nx, Ionic, AngularFire, PrimeNG or other third-party
libraries, for TypeScript or JavaScript language questions, or for prereleases (next, rc) of any package:
their documentation is not here, and the search will return Angular excerpts that merely mention them, with
confident-looking titles.

`version` narrows the search to one release line: "22" keeps every 22.x document, "17" every 17.x, "1" is
AngularJS (1.0 to 1.8); leave it empty to search everything. Material and the CDK share the Angular major
numbers. Documents of the Angular CLI 1.x carry the version "cli-1.x" so they do not mix with AngularJS 1.x.
Every excerpt comes back with `versions`: each version whose documents contain this exact text, newest first,
so the list itself shows from which to which version the documentation said exactly this. The API reference
is one snapshot per major (the last minor of each line); guides are here for every minor line.

Write the query in English, with the names Angular itself uses ("provideRouter", "ChangeDetectionStrategy",
"withFetch", "HttpInterceptorFn", "MatDialog", "CdkDrag", "$compile"), not in the user's own words. Everything
here is English -- the excerpts, the word index and the meaning index alike -- and the word index keeps only
latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing
at all and comes back with `found: 0`. When the user asks in another language, translate the question into
Angular terms first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if
the excerpts say so; and how it stands in the current version. Every point names the version and the document
it rests on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian,
write as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the
Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call
this set of documents "корпус" -- say "документація Angular". Identifiers, option names and titles stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional, see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry
`truncated: true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Angular 22 and 21 are the newest stable lines and together carry well over half
of the weekly downloads of @angular/core (22 a little more than 21); 20 about an eighth; every older line a few
percent. Search with `version` "22" for a question about how to do something, and when the 21 way differs,
search "21" as well and give both. If the user names a version, or their code shows one (NgModule-only setup,
`*ngIf` and `*ngFor` without the built-in control flow -> 16 or older; standalone components without
`standalone: true` -> 19 or newer; `$scope`, `angular.module` or `ng-controller` -> AngularJS, version "1"),
search that line. Search without `version` when the question is about history, or when the line gave nothing.
Every answer says which version it is for; when the user did not name one, answer for Angular 22 and say so
("for Angular 22; in 21 ..."). When the excerpts behind a statement come only from older versions, name those
versions instead of presenting the text as current.
