Search the Anthropic API documentation, in English: the Claude Developer Platform at platform.claude.com/docs
(formerly docs.anthropic.com) and the official SDKs. The set holds the whole English site: models (the models
overview, a page for every model -- Haiku 5.5, Haiku 4.5, Sonnet, Opus, Fable, Mythos -- with model IDs on every
platform, context window, max output, pricing, knowledge cutoff; choosing a model, migration guides, model IDs
and aliases, deprecations), pricing, rate limits and service tiers, errors, versioning and beta headers, the
Messages API (streaming, stop reasons, extended and adaptive thinking, effort, prompt caching, batch processing,
token counting, files, PDF and vision, citations, structured outputs, context windows and compaction), tool use
and server tools (web search, web fetch, code execution, bash, text editor, computer use, memory), MCP, Agent
Skills, Managed Agents, the Admin API, cloud platforms (Amazon Bedrock, Google Cloud Vertex AI, Microsoft
Foundry, Claude Platform on AWS), prompt engineering, release notes and system prompts, and the API reference
as HTTP, as Python SDK methods and as TypeScript SDK methods. Besides the site: for every stable release the
README, api.md, helpers and migration pages of the TypeScript, Python, Go, Ruby and C# SDKs and of the ant CLI,
with their GitHub release notes; the source code of the newest TypeScript and Python SDK with examples; the
version tables and READMEs of @anthropic-ai/sdk, bedrock-sdk, vertex-sdk, foundry-sdk, aws-sdk and
google-cloud-sdk on npm and of anthropic on PyPI; and the claude-cookbooks notebooks. Returns the matching
excerpts with the versions each one belongs to.

Call this when a question is about calling Claude models through the API: which model ID to use (claude-haiku-5-5,
claude-haiku-4-5-20251001, claude-sonnet-5-5, claude-opus-5-5), what a model costs per MTok, its context window
and max output, rate limits (RPM, ITPM, OTPM) and 429 or 529 errors, max_tokens, temperature, system, stop_sequences,
stream, thinking and effort, tool_choice and tool definitions, cache_control and cache pricing, the Message
Batches API, count_tokens, the Files API, structured outputs (output_format, strict tools), anthropic-version and
anthropic-beta headers, retries and timeouts in an SDK, how client.messages.create, messages.stream, the tool
runner and batches work in Python or TypeScript, and what changed between SDK versions. Example query:
"claude-haiku-5-5 pricing context window".

Do not call this for Claude Code (the CLI coding agent, its settings and hooks), the Claude apps (claude.ai,
desktop, mobile), the Claude Agent SDK packages, or other model providers (OpenAI, Gemini, Ollama).

Write the query in English, with the names the documentation uses (max_tokens, cache_control, tool_use,
stop_reason, message_batches, claude-haiku-5-5, anthropic-beta). Everything here is English, and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing and comes back with `found: 0`. When the user asks in another language, translate the question
into API terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "потокова видача", "кешування
промпту", "вікно контексту". Never call this set of documents "корпус" -- say "документація API Anthropic".
Parameter, header, model, method and type names stay in English, spelled exactly as the documentation spells
them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says. Prices, limits and model IDs change: quote them from the excerpt,
never from memory.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. The site pages and the cookbooks carry no version: they are the current state.
SDK documents carry versions named after their SDK: "typescript-0.135.0" (@anthropic-ai/sdk),
"python-1.15.0" (anthropic on PyPI), "go-1.82.0", "ruby-1.80.0", "csharp-12.1.0", "cli-1.42.0",
"bedrock-sdk-0.35.0", "vertex-sdk-0.21.0", "foundry-sdk-0.6.0", "aws-sdk-0.8.0", "google-cloud-sdk-0.1.0". When the
user names an SDK version, pass its line into `version` ("python-1.15", "typescript-0.135"); never put it into the
query text. Without a version, answer for the current site and the newest SDK release and say so.
