# arch — примірник фабрики docfactory

Цей примірник зібрав документацію arch і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. arch — це бібліотека Python Кевіна Шеппарда для моделей волатильності й фінансової економетрики. Волатильність —
це міра того, наскільки сильно коливається ціна. Вона не стала: після різкого руху ринок зазвичай лишається неспокійним ще
якийсь час. Моделі родини GARCH описують саме це і дають прогноз волатильності на наступні дні.

Для торгового бота тут найважливіші такі речі:

- модель волатильності: функція `arch_model` збирає модель із трьох частин — середнього (`Constant`, `AR`, `HAR`),
  волатильності (`GARCH`, `EGARCH`, `GJR`, `FIGARCH`) і розподілу похибок (`normal`, `t`, `skewt`, `ged`); метод `fit` оцінює її;
- прогноз: `forecast` з `horizon` дає прогноз дисперсії на кілька кроків уперед аналітично, симуляцією чи бутстрепом;
  посібник показує ковзні прогнози (`last_obs`, `first_obs`) і розрахунок Value-at-Risk, тобто збитку, який за день
  перевищується лише з малою ймовірністю;
- бутстреп часових рядів (`StationaryBootstrap`, `CircularBlockBootstrap`): перевибірка блоками, що зберігає залежність між
  сусідніми днями;
- перевірка стратегій без самообману: тести `SPA`, `StepM` і `MCS` кажуть, чи краща стратегія справді краща за еталон, а не
  виграла випадково серед багатьох спроб;
- тести одиничного кореня (`ADF`, `DFGLS`, `PhillipsPerron`, `KPSS`) і коінтеграції (`engle_granger`, `phillips_ouliaris`):
  чи стаціонарний ряд і чи рухаються дві валютні пари разом у довгому періоді.

## Скільки цього

Усього 1318 документів і 4702 фрагменти. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Сторінка з
однаковим текстом у кількох версіях лежить одним документом із переліком цих версій. Сторінка, що змінювалася, лежить кількома
документами, по одному на кожен варіант тексту.

| Що | Версії | Документів |
|---|---|---|
| сайт bashtage.github.io/arch: посібник, зошити з прикладами, довідник API, зміни кожної версії | 9.0 | 1067 |
| код бібліотеки, поділений на класи й функції | останній тег кожної мажорної лінії: 4.19, 5.6, 6.3, 7.2, 8.0, 9.0 | 155 |
| нотатки релізів GitHub | усі релізи, які GitHub публікує | 50 |
| записи PyPI | усі сталі версії 1.0–9.0 та опис пакета | 46 |

Мітка версії має вигляд `arch-9.0`. Префікс потрібен, щоб версії arch не збігалися з версіями інших бібліотек, коли сервери
працюють разом.

**Де є прогалини, хоч ми й брали всі версії.**

- Сайт публікує лише поточну версію 9.0 і розробницьку `devel`; `devel` не взято. Старші мажорні лінії представлені кодом: довідник
  API сайту збирається з рядків документації цього коду, тож опис параметрів кожної лінії в корпусі є. Зміни кожної версії
  описано на сторінці змін сайту.
- З коду не взято тести, дані-приклади, таблиці критичних значень і код сумісності.

Замір `quality` на 14.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 4 із 10: словами без назв моделей пошук часто знаходить сусідню сторінку.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df arch <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт | `bashtage.github.io/arch/` | `sphinx-html` |
| код `arch/` | теги репозиторію `bashtage/arch` | `ghcode-history` |
| нотатки релізів | релізи GitHub `bashtage/arch` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/arch/json` | `pypi-versions` |

**Поля читача для сайту.** `param_types: true` ставить « : » між назвою параметра й типом у довіднику, і пошук за назвою параметра
знаходить сторінку. `min_chars: 25` пропускає в корпус короткі сторінки методів з одним рядком опису.

Завантаження всього примірника зайняло близько 20 хвилин.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df arch serve
```

Порт — `8988`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user arch-docs http://127.0.0.1:8988/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `arch-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/arch-corpus-2026-11-14.tar.gz` (1318 текстів, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\arch-corpus-2026-11-14.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/arch/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/arch-corpus-РРРР-ММ-ДД.tar.gz -C instances/arch corpus raw
find instances/arch/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/arch/raw
gzip -9 -c instances/arch/index/passages.json > instances/arch/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/arch-corpus-2026-11-14.tar.gz -C instances/arch
./df arch smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
