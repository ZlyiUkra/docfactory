# argocd — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Argo CD — декларативний інструмент безперервної доставки GitOps
для Kubernetes (сайт argo-cd.readthedocs.io, репозиторій argoproj/argo-cd), а також про те, що ставлять поруч із ним:
офіційний Helm-чарт `argo-cd` (argoproj/argo-helm, Artifact Hub), Argo CD Image Updater і argocd-vault-plugin. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

GitOps — підхід, де бажаний стан кластера лежить у Git, а контролер у самому кластері звіряє з ним живі ресурси й
доводить їх до записаного. Argo CD — такий контролер: ресурс `Application` каже, з якого репозиторію, теки й ревізії
брати маніфести (звичайні YAML, Helm, Kustomize, Jsonnet) і в який кластер їх викотити; `syncPolicy` вмикає
автоматичну синхронізацію, `selfHeal` повертає ручні правки, `prune` прибирає зайве, sync waves і hooks задають
порядок, `ApplicationSet` породжує застосунки за шаблоном для багатьох кластерів чи тек. У плані Next.js
(фулстек-родина) — у розділі «знати, що існує» й у «Що далі»: викот «з репозиторію».

Супутні проєкти взято за статистикою використання (26.10.2026): argocd-vault-plugin — 11,5 млн завантажень бінарника
з релізів GitHub, Image Updater — 1,05 млн завантажень образу з Docker Hub і 1,7 тис. зірок. Не взято Autopilot
(61 тис. завантажень, розробка сповільнилася), argocd-operator (статистики завантажень немає) і архівні окремі
ApplicationSet та Notifications — з 2.3 вони частина Argo CD і описані на його сайті.

бо назву плагіна несе майже кожен його реліз. Запити «як модель» для цих двох випадків записано так, як їх пише
модель за цими підказками.

Чого немає. Вихідний код (Go) і тести, пререлізи (`-rc`), Kubernetes, Helm, Kustomize, Vault, Argo Rollouts, Argo
Workflows і Argo Events як окремі проєкти, argocd-operator, Autopilot.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df argocd <крок>`.

## Версії

Сторінки й README несуть версію тегу, з якого взяті (`3.5.6`), релізи й журнал — версію релізу. Номери чарту
(3.0–9.x) збігаються з номерами Argo CD, тож супутні версії записано з префіксом: `chart-9.1.0`, `image-updater-1.4.0`,
`avp-1.18.1`. Фільтр `version` бере мажор (`"3"`), мінор (`"2.14"`) або точну версію (`"3.5.6"`); голе число лишає
лише Argo CD, `"chart-9"` — лінію чарту, `"avp-1"` — argocd-vault-plugin 1.x. Реєстру із завантаженнями в Argo CD
немає; проєкт підтримує три найновіші мінорні (на 26.10.2026 — 3.5, 3.4 і 3.3), тож промпт відповідає для 3.x, для
чарту — для лінії chart-9.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/argocd-corpus-2026-10-26.tar.gz` (4588 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows
`C:\Distr\argocd-corpus-2026-10-26.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/argocd/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/argocd-corpus-РРРР-ММ-ДД.tar.gz -C instances/argocd corpus raw
find instances/argocd/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/argocd/raw
gzip -9 -c instances/argocd/index/passages.json > instances/argocd/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/argocd-corpus-2026-10-26.tar.gz -C instances/argocd
./df argocd smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати; їхні
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/argocd/index/passages.json.gz`; далі
`./df argocd vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df argocd …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df argocd sources --why   # перелік джерел і білий список
./df argocd refresh         # завантажити все задеклароване (близько 45 хвилин)
./df argocd manifest        # оновити паспорт
./df argocd setup           # Qdrant чи пошук лише по словах
./df argocd vectors         # залити корпус у docs-argocd
./df argocd smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df argocd serve          # порт 8907
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8907/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user argocd-docs http://127.0.0.1:8907/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `argocd-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
