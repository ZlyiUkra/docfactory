Search the documentation of Argo CD -- the declarative GitOps continuous delivery tool for Kubernetes (site
argo-cd.readthedocs.io, repository argoproj/argo-cd) and of what is used together with it: the official Helm chart
`argo-cd` (repository argoproj/argo-helm, Artifact Hub), Argo CD Image Updater (argoproj-labs/argocd-image-updater)
and argocd-vault-plugin (argoproj-labs/argocd-vault-plugin). The corpus holds every page of the Argo CD site as it
stood at the last tag of every minor, 0.1 to 3.5: getting started, the core concepts, the user guide (Applications,
tools -- Helm, Kustomize, Jsonnet, plain directories, Config Management Plugins; tracking strategies, private
repositories, sync options, sync phases and waves, resource hooks, `ignoreDifferences`, automated sync, self-heal and
pruning, projects, multiple sources, the `argocd` CLI with every command and flag), the operator manual
(installation, high availability, declarative setup, `argocd-cm`, `argocd-rbac-cm`, user management, SSO with Dex
and OIDC, RBAC, security, TLS, cluster bootstrapping, ApplicationSet with every generator, Notifications with every
service, metrics, health checks, resource actions, upgrading between versions), the developer and contributor guides,
and the README. It also holds the README of the Helm chart `argo-cd` with its table of values at the last tag of every
chart minor (3.0 to 9.x; versions written "chart-9.1.0"), the CHANGELOG of Argo CD (to 2.4.8), the stable GitHub
releases of Argo CD, the documentation and releases of Image Updater (versions "image-updater-1.4.0") and of
argocd-vault-plugin (versions "avp-1.18.1"). Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about Argo CD as it describes itself -- how to define an Application or an AppProject,
how to sync, prune, self-heal, order resources with sync waves and hooks, ignore differences, deploy Helm or
Kustomize sources, generate Applications with ApplicationSet, configure SSO, RBAC, notifications, high availability,
install or upgrade with the Helm chart and which values it takes, update images automatically with Image Updater,
inject secrets from Vault and other backends with argocd-vault-plugin -- and history: since which version a field,
flag or feature exists, what changed between versions (the upgrading guides list it).

Do not call this for Kubernetes, Helm, Kustomize, Vault, Argo Rollouts, Argo Workflows or Argo Events as their own
projects: their documentation is not here -- these pages only show how Argo CD is used with them -- and the search
will return excerpts that merely mention them, with confident-looking titles. The Go source code is not here either.

`version` narrows the search to one release line: a line of one number keeps every document of that major of Argo
CD ("3" keeps 3.x), two numbers keep a minor ("2.14"), three an exact version ("3.5.6"); the chart, Image Updater
and argocd-vault-plugin carry a prefix ("chart-9", "image-updater-1", "avp-1.18"), so a bare number keeps only Argo
CD. Pages unchanged across versions carry all of them. Every excerpt comes back with `versions`: each version whose
documents contain this exact text, newest first.

"argocd-cm", "argocd-rbac-cm", "argocd app sync", "argocd login", "SSO", "Dex", "RBAC", "health check", "resource
hooks", "Notifications", "Config Management Plugin", "repo server", "values.yaml", "image-updater.argoproj.io",

user's own words. Two cases where the obvious query misses: an ApplicationSet generator has
its own page titled by its name -- search "Cluster generator", "Git generator", "Matrix generator", not
"ApplicationSet" plus the generator, which every generator page repeats; for argocd-vault-plugin search its
annotations and placeholder syntax ("avp.kubernetes.io/path", "<placeholder>", "<path:...#key>", "AVP_TYPE"), not
the name "argocd-vault-plugin", which nearly every one of its release notes carries. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin
script matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the
question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація Argo CD". Identifiers, parameters and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Argo CD has no package registry with download counts; the project supports the
three newest minors (3.5.6 is the newest, then 3.4 and 3.3). Answer for 3.x: search without `version` first, then
with "3" if 2.x pages crowd the results; when the user names their version, search that line. For the Helm chart
answer for the newest chart line ("chart-9"), for Image Updater -- "image-updater-1", for argocd-vault-plugin --
"avp-1". Every answer says which version it is for.
