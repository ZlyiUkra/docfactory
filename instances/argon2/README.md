# argon2 — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про хешування паролів Argon2 у Node.js — за документацією двох пакетів
npm усіх стабільних версій: `argon2` (node-argon2, прив'язка до еталонної реалізації на C) і `@node-rs/argon2`
(прив'язка на Rust із готовими збірками під платформи), — а також еталонної реалізації P-H-C/phc-winner-argon2 і
специфікації алгоритму. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі
дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Argon2 — переможець конкурсу Password Hashing Competition і рекомендоване хешування паролів. У фабриці вже є сам
стандарт (RFC 9106, примірник `webstandards`) і поради OWASP щодо параметрів (примірник `owasp`), але не бібліотеки,
якими його викликають з Node.js: які опції в `hash()`, що змінилося між версіями, яка версія працює з яким Node.
Пакетів два, і вони роблять одне й те саме з різним API, тож обидва тут — щоб можна було вибрати будь-який.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, правила `redact` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад (з `pypdf` для специфікації).

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df argon2 <крок>`.

Разом із цим примірником додано два читачі:

- **`ghwiki-page`** (`engine/readers/ghwiki.py`) — сторінка вікі GitHub. Назвою сторінки GitHub показує ім'я файла
  (дефіси стають пробілами), а в самому тексті заголовка немає, тож `mdfile` таку сторінку відкидав як «без назви».
  Підкреслені заголовки («`hashLength`» і рядок «-----» під ним) читач переписує в «## …», інакше сторінка Options
  лягла б одним розділом замість розділу на кожну опцію.
- **`changelog-conventional`** (`engine/readers/changelogconventional.py`) — журнал, який пише lerna з
  conventional-changelog: `# [2.2.0](<порівняння>) (<дата>)` для мінорних і мажорних версій, `## [2.0.2](…)`
  для латок і голе `# 1.0.0 (<дата>)` для першої. Жоден наявний читач не бачить номера-посилання на обох рівнях.

Особливості корпусу:

- **Сайту немає.** Домашня сторінка `argon2` веде на npm, `@node-rs/argon2` — на репозиторій. Документація обох —
  README, типи й нотатки релізів; у `argon2` ще вікі.
- **Опції в двох місцях.** У `argon2` значення за замовчуванням і пояснення опцій — у вікі (поточний стан, без версій)
  і в типах (по версіях: `const defaults` — 0.15–0.31, `const limits` — 0.15–0.41); у `@node-rs/argon2` — у
  коментарях JSDoc типів і в розділі API README. Типові параметри пакетів різні: `argon2` — m=65536, t=3, p=4;
  `@node-rs/argon2` — m=19456, t=2, p=1.
- **Вимога до Node (`engines`)** записана в документах реєстру npm, у версії, де вона змінилася («engine changed»):
  `argon2` 0.6 — Node 4, 0.17 — 6, 0.20 — 8, 0.26.1 — 10, 0.28.0 — 12, 0.28.7 — 14, 0.40 — 16.17; `@node-rs/argon2` —
  Node 10 від першої версії.
- **Журнал `@node-rs/argon2` неповний:** записів 2.0.0, 2.0.1, 2.2.1 і 2.2.2 у ньому немає, вони лише в релізах GitHub.
  Частина релізів, навпаки, порожня («No release notes.») — їхній зміст у журналі.
- **Специфікація — PDF.** Розділи впізнаються за номером і назвою («3.4 Compression function G»), номери сторінок
  викидаються. Лігатури PDF («ﬁ», «ﬀ») правило `redact` у `config.json` замінює звичайними літерами, інакше слова
  «specification» чи «tradeoff» пошук у специфікації не знаходив би. Версії документ не несе: «1.3» алгоритму збіглася б
  із лінією 1.3 `@node-rs/argon2` у фільтрі версій.
- **Фільтр версії один на обидва пакети:** лінії `argon2` — 0.x («0.45»), `@node-rs/argon2` — 1.x і 2.x («2»), релізи
  еталонної реалізації — дати («20190702»). Вікі, журнал еталонної реалізації та специфікація без версії знаходяться
  лише пошуком без `version`.
- **Версія за замовчуванням.** Найпопулярніші версії `argon2` за завантаженнями — 0.44.0 і 0.45.1, майже нарівно, тож
  відповідь іде для обох; для `@node-rs/argon2` — лінія 2.
- **Назва README еталонної реалізації.** Файл починається голим заголовком «Argon2», тож у назві документа перед ним
  стоїть «phc-winner-argon2 README» (поле `title_prefix` у `sources.json`) — інакше у видачі було б просто «Argon2».
- **Документ — неповторний текст.** Версії, де файл не змінився, ділять один документ; у рядку `# версія:` стоять усі.

## Межі, про які треба пам'ятати

Документації `node:crypto` (там `crypto.argon2` з Node 24.7 — примірник `nodejs`), RFC 9106 (примірник `webstandards`),
порад OWASP щодо параметрів (примірник `owasp`), bcrypt, scrypt і фреймворків тут немає. Код бібліотек — ні C, ні Rust,
ні JavaScript — не входить, лише документація. Сторінка man утиліти командного рядка еталонної реалізації не береться:
її прапорці описано в README. Інші пакети Argon2 (`argon2-browser`, `hash-wasm`, `@phc/argon2`) не беруться.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/argon2-corpus-2026-10-09-titles.tar.gz` (222 тексти і паспорт). В
історії git текстів немає ніде. Архів лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/argon2-corpus-2026-10-09-titles.tar.gz -C instances/argon2
./df argon2 smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/argon2/index/passages.json           # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/argon2-corpus-РРРР-ММ-ДД.tar.gz -C instances/argon2 corpus
find instances/argon2/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/argon2/index/passages.json > instances/argon2/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/argon2/index/passages.json.gz`, далі
`./df argon2 vectors` заллє колекцію Qdrant (близько хвилини).

## Установка venv

```
cd instances/argon2
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY

```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df argon2 sources --why   # перелік джерел і білий список
./df argon2 refresh         # завантажити все задеклароване (близько 10 хвилин)
./df argon2 manifest        # оновити паспорт
./df argon2 setup           # Qdrant чи пошук лише по словах
./df argon2 vectors         # залити корпус у docs-argon2
./df argon2 smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df argon2 serve          # порт 8814
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8814/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user argon2-docs http://127.0.0.1:8814/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `argon2-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
