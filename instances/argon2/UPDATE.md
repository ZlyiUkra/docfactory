# Оновлення корпусу argon2

Перелік версій тут не оголошується руками: читачі беруть його з опису пакетів у реєстрі npm
(`https://registry.npmjs.org/argon2` і `https://registry.npmjs.org/@node-rs%2Fargon2`), тож нова версія потрапляє в
корпус сама, коли вийде в npm. Релізи беруться з GitHub (`ranisalt/node-argon2` і `napi-rs/node-rs`), журнал змін
`@node-rs/argon2` — з гілки `main` монорепозиторію `napi-rs/node-rs`, вікі — з `ranisalt/node-argon2.wiki`, еталонна
реалізація — з `P-H-C/phc-winner-argon2`.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df argon2 check                 # чи змінилося щось нагорі за джерелом
./df argon2 refresh               # повне перезавантаження, близько 10 хвилин
./df argon2 manifest
./df argon2 vectors
./df argon2 smoke
# Ctrl+C у терміналі з serve, і знову: ./df argon2 serve
```

`refresh` повний, не `--missing`: у документі стоять усі версії, де текст був таким, тож нова версія змінює й старі
документи (README, що не змінився, дописує нову версію в рядок `# версія:`).

Якщо вийшла нова лінія (для `argon2` — нова мінорна 0.x чи стабільна 1.0, для `@node-rs/argon2` — нова мажорна):

- у `prompts/search.txt` (абзац «Which package and version to search first» і перелік вимог до Node) та
  `prompts/agent.txt` замінити поточну лінію на нову, а версії за замовчуванням звірити з числом завантажень
  (`https://api.npmjs.org/versions/argon2/last-week`): відповідь іде для найпопулярнішої версії, а коли дві
  майже рівні — для обох;
- у `checks.json`, у десятці `quality_model`, замінити лінію там, де питання про поточну поведінку, і звірити цілі.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) не обов'язковий, але без нього звернення до API GitHub (релізи двох
репозиторіїв, дерева шести релізів еталонної реалізації) ідуть годинними вікнами по 60.

Журнал змін `@node-rs/argon2` пише lerna з conventional-changelog («# [2.2.0](…) (2026-08-29)»), його читає
`changelog-conventional`; якщо формат зміниться, `refresh` зупиниться з повідомленням «жодного заголовка версії», і
читача треба поправити.

Специфікацію Argon2 (PDF) читає `pdf-paper`: заголовки розділів — за виразом `heading` у `sources.json`, номери
сторінок викидає `skip_lines`. Лігатури PDF («ﬁ», «ﬀ») правило `redact` у `config.json` замінює звичайними літерами —
без цього слова «specification» чи «tradeoff» у тексті не знаходилися б пошуком.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df argon2 quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
