Return the full text of one excerpt of the Astro documentation by its identifier,
together with the document it belongs to, every version whose documents contain this
text, the URL it was taken from and the date the text was fetched from that URL -- so
a quotation can be checked against the source even a year later.

Call this after `search_docs` when the excerpt you need came back cut at 600
characters, or when the exact wording matters -- a configuration option, a breaking
change, an upgrade step or a deprecation notice quoted half-way is how a wrong answer
starts. Configuration especially: option names, defaults and their nesting are the
part a summary gets wrong. The same holds for a catalog entry: the name of a package
and the address it lives at are worth quoting exactly, not from memory.

Do not guess identifiers: they are not URLs, not chapter names and cannot be assembled
by hand. Every identifier this tool accepts comes from the `id` field of a
`search_docs` result.

The text comes back in English, as the documentation is written. Answer the user in
their own language, and follow the same rules as for `search_docs`: keep identifiers
and titles in English, use Ukrainian words for Ukrainian prose, and name the version
and the document you read.
