# auth — примірник фабрики docfactory

Тридцять сьомий примірник фабрики: захищений MCP-сервер, що відповідає на питання про Better Auth і NextAuth.js /
Auth.js. Тут документація Better Auth кожної мінорної версії від 0.0 до 1.7, NextAuth.js кожної мінорної від 1.1 до
4.24, Auth.js (NextAuth.js v5) на кожній беті від 5.0.0-beta.4 до 5.0.0-beta.32 і довідник API authjs.dev. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

Вхід, сесії й облікові записи в застосунках на Next.js майже завжди беруть з бібліотеки, і це одна з двох: Auth.js
(колишній NextAuth.js) або Better Auth; документація Auth.js сама має посібник переходу на Better Auth. Обидві
змінюються швидко: у v5 NextAuth.js змінились імпорти, конфігурація й спосіб узяти сесію (`auth()` замість
`getServerSession`), а Better Auth випускає мінорну версію кожні кілька місяців з новими плагінами й опціями. Проєкт
клієнта може стояти на будь-якій із них — на слабкій машині й на старому Node це часто стара версія, — тож тут зібрано
всі версії, документацію яких можна дістати.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

Разом 2 640 документів; фрагментів в індексі — 16 597 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук. Документ — це одна редакція сторінки: сторінка, що не мінялася від 1.4
до 1.7, — один документ з чотирма версіями, а змінена — кілька. Однаковий текст розділу в різних редакціях зливається
в один фрагмент зі списком версій: у NextAuth.js 46 711 копій розділів по всіх версіях дали 3 940 фрагментів, у Better
Auth 15 112 — 6 005. Довідник authjs.dev — 6 652 фрагменти: TypeDoc робить окремий розділ на кожну властивість
кожного типу.

Замір `quality`: перша десятка (питання своїми словами) — по словах 6 із 10, за змістом 6, разом 9; друга, «як модель»
(назви плагінів, функцій і опцій, з версією, як велить промпт), — 10 із 10. Заміряно сітку `max_per_doc` 0–3 на
`fusion_depth` 0, 60, 120 і 200: найкраще 1 і 60, вони й стоять. З глибиною 120 і більше «як модель» падало до 6:
дрібні розділи довідника authjs.dev (окремий розділ на кожну властивість типу) є в обох списках, що зливаються, і
витісняли потрібні сторінки. З `max_per_doc` 2 випадала сторінка 2FA — інші документи займали по два місця з п'яти.

**Повнота видачі.** На 20 пробних словах (`session`, `jwt`, `organization`, `passkey`…) видача на 5 результатів
повна. На 10 — інколи коротша (`organization` — 6, `passkey` — 8): серед 60 кандидатів менше різних сторінок, а з
кожної береться одна.

**Що пропускає пошук своїми словами.** «Увійти відбитком пальця чи обличчям» (passkey, WebAuthn): ні по словах, ні за
змістом. З назвою (`passkey plugin`), як велить промпт, пошук знаходить потрібне.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження); `.mcp.json` — запис
  HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df auth <крок>`.

Білий список — `api.github.com`, `raw.githubusercontent.com` (у кожного джерела — лише його тека на його тегах) і
`authjs.dev/reference/`. Посилання у відповідях ведуть на файл на GitHub на тезі тієї версії, з якої текст: сайти
better-auth.com і authjs.dev показують лише найновішу документацію, і посилання туди для тексту 1.2 вело б на інший
текст. Довідник — на сторінку authjs.dev.

Особливості, які варто знати:

- **Версія — мінорна, знімок — останній патч.** Для кожної мінорної береться тег її останнього патча (`v1.6.33`,
  `next-auth@4.24.15`). Де тегів немає (NextAuth.js 1.x, документація 4.0–4.2 в окремому репозиторії), знімок — коміт
  гілки на мить виходу останнього патча в npm: коміт «перед наступною мінорною» вже містив би опис її нових
  можливостей. NextAuth.js 1.0 немає ні в історії репозиторію (вона починається після 1.1.0), ні в реєстрі.
- **Зміст у властивостях компонентів.** Better Auth пише метод і шлях ендпоінта атрибутами
  `<APIMethod path="/sign-in/email" method="POST">`, опції — об'єктом для `<TypeTable>`, поля таблиць бази — масивом
  для `<DatabaseTable>`. Звичайний розбір MDX бере лише текст між тегами, а `export` викидає як код, тож ні
  ендпоінтів, ні опцій, ні схем у корпусі не було б. Поле `jsx_props` читача `ghdocs-history` розгортає їх у
  текст: рядок «Endpoint: `POST /two-factor/enable` (requires a session).», списки «- `minPasswordLength` (number,
  default: 8) — …» і «- `userId` (string, foreign key, references `user.id`) — …».
- **Вкладки фреймворків.** Auth.js показує той самий приклад окремими вкладками для Next.js, SvelteKit, Qwik і
  Express. Поле `component_labels` ставить над кожним блоком підпис «Next.js:», «SvelteKit:» — інакше чотири блоки
  коду йшли б поспіль без назв.
- **Виноски Docusaurus** (`:::tip`, `:::note`) у документації 2.x–4.x і ранніх бет v5 стають підписом «Tip:», «Note:»
  (поле `admonitions`).
- **Ключі сторінок.** Та сама сторінка в різних епохах лежала в різних теках (`www/docs`, `docs`, `docs/docs`,
  `docs/pages`). Поле `slug_rewrite` у `config.json` зводить їх до одного імені (`next-auth-configuration-options`,
  `better-auth-plugins-2fa`), щоб однаковий текст різних версій зливався.
- **Назви 24 сторінок довідника** — такі, як їх дав TypeDoc: `adapters`, `types`, `jwt`; пакет видно з імені
  документа (`reference-nextjs-adapters`).

## Версії у відповіді

Мітка — бібліотека й номер: `better-auth-1.7` … `better-auth-0.0`, `next-auth-4.24` … `next-auth-1.1`,
`next-auth-5.0.0-beta.32` … `next-auth-5.0.0-beta.4`; довідник authjs.dev — `next-auth-5.0.0-beta.32`. Назва в мітці
не дає сплутати Better Auth 1.2 з NextAuth.js 1.2. Фільтр бере лінію чи мінорну: `better-auth-1` — уся 1.x,
`next-auth-4.10` — лише 4.10, `next-auth-5` — усі бети v5.

Без названої версії відповідь — для Better Auth 1.7 і 1.6 (на 07.10.2026 вони мають 42% і 47% завантажень за тиждень)
і для NextAuth.js окремо v5 і v4 (52% і 48%): у них різні імпорти, конфігурація й спосіб узяти сесію.

## Межі, про які треба пам'ятати

Тут немає патчів окремими версіями (у межах мінорної API не змінюється, а текст між патчами різниться правками), бет і
canary Better Auth, журналів змін, документації інших продуктів автентифікації (Clerk і Supabase Auth — у своїх
примірниках, Lucia, Passport, Firebase Auth — ніде) і самих протоколів OAuth 2.0 та OpenID Connect (тексти RFC — у
примірнику `webstandards`). Довідник authjs.dev — лише поточне видання: старіших сайт не публікує.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку, як у express: у `corpus/` лежить лише паспорт `index.json`, а сервер
підіймається з кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає
повний текст кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/auth-corpus-2026-10-07.tar.gz` (2,1 МБ, 2 640 текстів і паспорт;
перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде.
Архів лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/auth/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/auth-corpus-РРРР-ММ-ДД.tar.gz -C instances/auth corpus
find instances/auth/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/auth/index/passages.json > instances/auth/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/auth-corpus-РРРР-ММ-ДД.tar.gz -C instances/auth
./df auth smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/auth/index/passages.json.gz`, далі
`./df auth vectors` заллє колекцію Qdrant (близько 15 хвилин).

## Установка venv

```
cd instances/auth
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

```
./df auth sources --why   # перелік джерел і білий список
./df auth refresh         # завантажити все задеклароване (~60 хвилин)
./df auth manifest        # оновити паспорт
./df auth setup           # Qdrant чи пошук лише по словах
./df auth vectors         # залити корпус у docs-auth (~15 хвилин)
./df auth smoke           # перевірки
```

Дерев тегів тут понад сотню, тож без `GITHUB_TOKEN` у `.env` анонімного ліміту GitHub API (60 звернень на годину) не
вистачить. Тексти йдуть з raw.githubusercontent.com, що до ліміту не рахується. Обірваний `refresh` продовжується з
`--missing`.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd /mnt/c/Projects/fwdays/docfactory
./df auth serve             # порт 8797
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8797/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user auth-docs http://127.0.0.1:8797/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `auth-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
