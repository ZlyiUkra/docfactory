# backtesting — примірник фабрики docfactory

Цей примірник зібрав документацію двох бібліотек Python для тестування торгової стратегії на історії й віддає її через сервер MCP, щоб
модель відповідала з текстів бібліотек, а не з пам'яті. Тестування на історії (backtesting) — це прогін стратегії по минулих цінах:
програма свічка за свічкою вирішує, чи відкрити угоду, де поставити стоп-лос і тейк-профіт, коли закрити, а наприкінці рахує прибуток,
просідання й інші показники. Так ще до живої торгівлі видно, чи має стратегія перевагу.

- **Backtesting.py** (пакет `backtesting`) — бібліотека з подієвою моделлю: метод `next()` стратегії викликається на кожній свічці,
  а угоду відкривають `self.buy(sl=..., tp=...)`. Довідник API на kernc.github.io збирається з рядків документації коду, тому тут
  лежить сам код, поділений на класи й функції, і приклади-посібники (Quick Start, оптимізація параметрів з тепловою картою, кілька
  таймфреймів, бібліотека стратегій, торгівля з машинним навчанням).
- **vectorbt** (відкрита версія) — бібліотека з векторною моделлю: тисячі варіантів стратегії рахуються одразу над масивами сигналів.
  `Portfolio.from_signals` приймає стоп-лос і тейк-профіт параметрами `sl_stop` і `tp_stop`, а записи угод дають win rate, profit
  factor, expectancy і SQN. Довідник на vectorbt.dev теж збирається з коду.

Примірник зібрано під проєкт торгового робота для валютних пар зі співвідношенням ризику до прибутку 1:3. Тестер самого MetaTrader
лежить у примірниках `mql5` і `mql4`, теорія чесного тестування — у примірнику `quant-trading`.

## Скільки цього

змінювався між версіями, лежить кількома документами, а однакові фрагменти пошук зливає й показує з переліком версій.

Мітки версій мають префікс бібліотеки: `backtesting-0.6`, `vectorbt-1.2`. Тегів vectorbt між 0.21 і 0.28 у репозиторії немає, тож
цих ліній у корпусі теж немає. Код малювання графіків Backtesting.py не взято.

знаходять потрібне 10 із 10, запити своїми словами — 7 із 10. Фільтр версії працює після відбору найкращих збігів усіх
версій, тому на загальне слово («Portfolio») стара лінія vectorbt може не дати жодного фрагмента: у такому разі запит
треба уточнити назвою методу чи параметра.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df backtesting <крок>`.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df backtesting serve
```

Порт — `8979`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user backtesting-docs http://127.0.0.1:8979/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `backtesting-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/backtesting-corpus-2026-11-14.tar.gz` (тексти, паспорт і сховище сирого `raw/`; перед
видаленням текстів архів звірено з диском) і в копії на диску Windows `C:\Distr\backtesting-corpus-2026-11-14.tar.gz` (звірено за
SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/backtesting/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/backtesting-corpus-РРРР-ММ-ДД.tar.gz -C instances/backtesting corpus raw
find instances/backtesting/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/backtesting/raw
gzip -9 -c instances/backtesting/index/passages.json > instances/backtesting/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів (і його копію в `C:\Distr`), а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/backtesting-corpus-2026-11-14.tar.gz -C instances/backtesting
./df backtesting smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
