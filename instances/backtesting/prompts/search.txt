Search the documentation of two Python libraries that test a trading strategy on historical prices: Backtesting.py
(package `backtesting`) and the open-source vectorbt. The corpus holds: the code of Backtesting.py at the last patch of
every minor line 0.1-0.6 split into classes and functions, because its API reference is generated from these docstrings
(Backtest with run, optimize and plot, Strategy with init, next, buy and sell, Order, Trade, Position, the statistics,
and lib: crossover, resample_apply, SignalStrategy, TrailingStrategy, FractionalBacktest, MultiBacktest), its guide
examples (Quick Start, parameter heatmap and optimization, multiple time frames, the strategies library, trading with
machine learning), its README, the page about alternative libraries and its change log; the code of vectorbt 0.20-1.2
split into classes and functions (Portfolio.from_signals with sl_stop and tp_stop, Portfolio.from_orders, the trade and
position records with win rate, profit factor, expectancy and SQN, signals, indicators, returns statistics), the pages of
vectorbt.dev and the vectorbt release notes.

Use this tool for: how to place a stop-loss and a take-profit on an order (`sl=`, `tp=` in `Strategy.buy`, `sl_stop`,
`tp_stop` in `from_signals`), how commission, spread and margin are applied, how to optimise parameters without fooling
yourself, walk-forward retraining of a machine learning model inside a backtest, what each statistic means, and what
changed between versions. Write the query in English with the class, method or parameter name, such as
`Strategy.buy`, `Backtest.optimize`, `from_signals` or `sl_stop`. Give a version in the filter when the answer depends
on it.

Do not use it for the MetaTrader strategy tester (it belongs to the MQL5 and MQL4 servers), for indicator formulas (the
technical indicators server holds TA-Lib, pandas-ta-classic and ta) or for the theory of testing strategies (the
quant-trading server holds the books). Returns the matching excerpts with the versions each one applies to, the source
address and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. The newest lines are Backtesting.py 0.6 (`backtesting-0.6`) and vectorbt 1.2
(`vectorbt-1.2`). Search without `version` first; when the user names a version, search that line. Every answer says
which library and which version it is for: parameter names and defaults changed between lines.
