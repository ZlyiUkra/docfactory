# binance-spot — примірник фабрики docfactory

Сорок перший примірник фабрики: захищений MCP-сервер, що відповідає на питання про API споту біржі Binance — як
отримати ринкові дані (ціни, свічки, книгу заявок), як працюють потоки WebSocket і їхні ліміти, як підписати запит,
які є ордери й правила біржі, що означає код помилки і що в API змінилося. Джерело — офіційний репозиторій
документації `binance/binance-spot-api-docs`, лише англійські файли. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

На ринкових даних Binance стоять модулі «список монет» і «живі ціни» в планах навчання React і NestJS, а також
факультатив «крипта»: REST без ключа для свічок і книги заявок, потоки WebSocket для живих цін. Правила, без яких
такий модуль ламається, — у цій документації і ніде більше: з'єднання з потоком живе не довше 24 годин, нових
з'єднань — не більше 300 за п'ять хвилин з однієї адреси, свічок за запит — не більше 1000, а локальну книгу заявок
треба синхронізувати за окремою процедурою. Ці числа Binance міняє, і журнал змін каже, коли саме, — тож потрібен
поточний текст, а не пам'ять моделі.

**Що таке спот.** Спот — звичайна купівля й продаж монети за іншу монету з негайною поставкою, на противагу
ф'ючерсам і маржинальній торгівлі. **Ринкові дані** — публічна частина API: ціни, угоди, свічки, книга заявок;
ключ для них не потрібен. **Потік** (stream) — з'єднання WebSocket, яким біржа сама надсилає зміни.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

Разом 24 документи; фрагментів в індексі — 1 042 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук.

Замір `quality`: перша десятка (питання своїми словами) — по словах 5 із 10, за змістом 6, разом 7; друга, «як
модель» (назви ендпойнтів, потоків, полів і кодів помилок, як велить промпт), — 10 із 10. Своїми словами слабше, ніж
в інших примірниках, і це властивість самої документації: вона довідникова, написана назвами ендпойнтів і полів, а
«свічки», «обрив через добу» чи «годинник комп'ютера» в ній так не звуться; довідки FAQ із заголовками «How can I…»
перехоплюють такі питання по словах. Модель пише запит назвами документації — так велить опис інструмента. Поле
`max_per_doc: 1` (не більше одного фрагмента з документа у видачі) дало найкраще «разом»: на 0, 2 і 3 — 5, 5 і 5;
«як модель» — 10 на всіх.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (тут не потрібен: усе йде з
  raw.githubusercontent.com); `.mcp.json` — запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df binance-spot <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| 24 файли markdown | `https://raw.githubusercontent.com/binance/binance-spot-api-docs/master/<файл>` | `mdfile` |

Білий список — рівно ці 24 адреси, кожна своїм джерелом. Посилання у відповідях ведуть на файл на GitHub із якорем
розділу (`https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md`): сайт
developers.binance.com на автоматичні запити відповідає кодом 202, а його адреси не збігаються з іменами файлів.

Особливості, які варто знати:

- **Зміст doctoc вирізається.** П'ять великих файлів (REST, WebSocket API, потоки, потік даних користувача, фільтри)
  починаються згенерованим змістом — списком назв усіх розділів. Лишений у тексті, він відгукувався б у пошуку на
  назву будь-якого ендпойнта. Поле `cut_doctoc` читача `mdfile` прибирає його.
- **Огорожа коду в пункті списку.** У журналі змін приклади коду подекуди починаються просто з пункту списку
  («* ```json»). Без правки межа коду губилася, і понад вісімдесят записів журналу злипалися в один фрагмент. Поле
  `list_fences` знімає маркер пункту перед такою огорожею.
- **Журнал змін — один документ.** Записи йдуть за датами («### 2026-09-18»), а не за версіями; фрагмент — запис
  дня або його підрозділ («2025-08-12 › WebSocket API»).
- **Із тестової мережі — лише журнал змін.** Решта документації `testnet/` майже повторює основну, і пошук видавав
  би кожен розділ двічі. Журнал корисний тим, що нові можливості з'являються там раніше.
- **Із FIX і SBE — лише короткі довідки.** `fix-api.md` і схеми XML не беруться: це протоколи для професійної
  торгівлі, планам навчання вони не потрібні.

## Версії у відповіді

Версій у документації немає: вона описує API як він є зараз, а журнал змін — його історія за датами. Фільтр
`version` у цього примірника вимкнено. Коли ліміт, вага запиту чи поле могли змінитися, відповідь називає дату
запису журналу; журнал тестової мережі стосується лише тестової мережі.

## Межі, про які треба пам'ятати

Тут немає ф'ючерсів, маржі, гаманця, суб-акаунтів та інших продуктів Binance (вони — лише на
developers.binance.com), повного довідника FIX API, схем SBE, бібліотек-конекторів, китайських перекладів і
демо-режиму. Сам протокол WebSocket і браузерний `WebSocket` — у примірниках `webstandards` і `mdn`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/binance-spot-corpus-2026-10-08.tar.gz` (171 КБ, 24 тексти й паспорт;
перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде.
Архів лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/binance-spot/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/binance-spot-corpus-РРРР-ММ-ДД.tar.gz -C instances/binance-spot corpus
find instances/binance-spot/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/binance-spot/index/passages.json > instances/binance-spot/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/binance-spot-corpus-РРРР-ММ-ДД.tar.gz -C instances/binance-spot
./df binance-spot smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/binance-spot/index/passages.json.gz`,
далі `./df binance-spot vectors` заллє колекцію Qdrant (кілька хвилин).

## Установка venv

```
cd instances/binance-spot
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # якщо потрібен крок ask, впишіть ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

```
./df binance-spot sources --why   # перелік джерел і білий список
./df binance-spot refresh         # завантажити все задеклароване (~1 хвилина)
./df binance-spot manifest        # оновити паспорт
./df binance-spot setup           # Qdrant чи пошук лише по словах
./df binance-spot vectors         # залити корпус у docs-binance-spot (кілька хвилин)
./df binance-spot smoke           # перевірки
```

**Новий файл у репозиторії** (нова довідка в `faqs/`) сам не з'явиться: білий список — поіменний. Його дописують
окремим джерелом `mdfile` за зразком сусідніх довідок.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd /mnt/c/Projects/fwdays/docfactory
./df binance-spot serve       # порт 8801
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8801/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user binance-spot-docs http://127.0.0.1:8801/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `binance-spot-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію
Claude Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і
«Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
