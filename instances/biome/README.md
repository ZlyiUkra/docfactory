# biome — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Biome — набір інструментів для вебпроєктів від biomejs:
форматувальник, лінтер із правилами для JavaScript, TypeScript, JSX, JSON, CSS, GraphQL, HTML і Markdown, асист із
діями над кодом (сортування імпортів тощо), CLI, сервер мови для редакторів і плагіни GritQL. Джерела — сайт
biomejs.dev (до квітня 2024 — тека `website/` репозиторію biomejs/biome, далі — репозиторій biomejs/website), журнали
змін репозиторію biomejs/biome і реєстр npm, лише англійською й лише стабільні версії. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

Biome замінює в проєкті пару ESLint і Prettier одним швидким інструментом і рухається швидко: майже щомісяця виходить
мінорна версія з новими правилами, а Biome 2.0 (червень 2025) переробив конфігурацію — `files.include` і
`files.ignore` стали одним `files.includes`, сортування імпортів переїхало з окремого `organizeImports` в асист,
частина правил змінила групи й типову суворість, з'явилися домени правил, вкладені конфігурації й плагіни. Тож потрібен
текст документації тієї версії, з якою працюєш, а не пам'ять моделі.

**Що є що.** **Форматувальник** переписує код за єдиним стилем (відступи, лапки, ширина рядка), як Prettier.
**Лінтер** шукає помилки й погані звички за **правилами** (`noUnusedVariables`, `useExhaustiveDependencies`); правила
поділено на **групи** (`correctness`, `suspicious`, `style`, `a11y`, `nursery` для нових і ще не сталих), частина з
них **рекомендована** — увімкнена без налаштувань. Правило може мати **виправлення**: безпечне застосовує
`--write`, небезпечне — лише `--write --unsafe`. **Асист** — дії над кодом без діагностики помилки (сортування
імпортів, ключів, атрибутів). **Домен** — набір правил для бібліотеки чи середовища (React, Next.js, тести), що
вмикається сам, коли бібліотека є в залежностях. Налаштування лежать у `biome.json` (чи `biome.jsonc`); `biome check`
запускає форматувальник, лінтер і асист разом, `biome ci` — те саме для конвеєра, без запису змін.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

Разом 9 326 документів; фрагментів в індексі — 18 059 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук. Документ сторінки — неповторна редакція: сторінка разом із тим, що вона
вставляє, і в рядку `# версія:` стоять усі версії, де вона була саме такою. Однаковий текст різних версій лягає одним
фрагментом з усіма цими версіями, тож 6 823 редакції сторінок правил дають лише 11 870 фрагментів.

Замір `quality`: перша десятка (питання своїми словами, без версії) — по словах 6 із 10, за змістом 6, разом 7; друга,
«як модель» (назви правил, ключів і команд, як велить промпт), — 10 із 10 з першого заміру. Промахи першої десятки —
сусідні правила й сторінки (на «змінні, які оголосили й не читають» приходять `noUnassignedVariables` і `useConst`, на
«різні налаштування для тестів» — налаштування розширення редактора), а не помилки розбору. Ціль питання про
сортування імпортів доповнено сторінкою `analyzer/import-sorting` Biome 1: у 1.x сортування описувала саме вона.
`max_per_doc` 1, 2 і 3 піднімає першу десятку до 7 лише за змістом, але забирає одне влучання «як модель»
(`files.includes`: довідник конфігурації — одна сторінка з сотнями розділів), тож не ввімкнений.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, родини джерел (`families`), спільний
  ключ сторінок трьох схем шляхів сайту (`slug_rewrite`), глибина лінії версій і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (дерева комітів); `.mcp.json` — запис HTTP-сервера для
  Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df biome <крок>`.

**Сайт не має версій, але має знімки на день випуску.** Реєстр npm дає 107 стабільних версій `@biomejs/biome`, від
0.1.2 (серпень 2023, перші випуски після відгалуження від Rome) до 2.5.15 (30.09.2026); нічні збірки
(`-nightly.…`) і бети 2.0 не беруться. До квітня 2024 сайт жив у теці `website/` основного репозиторію, тож знімок
версії — коміт її релізу (`gitHead` у реєстрі npm, для 2.0.1 і 2.0.2 — тег чи коміт «ci: release»). З 8 квітня 2024
сайт — окремий репозиторій biomejs/website, і знімок версії — стан гілки `main` на момент її випуску: останній коміт
перед першою синхронізацією («chore(ci): synchronize to `…`») з комітом biomejs/biome, якого в релізі немає. Сторінки
правил, довідник CLI й конфігурації генеруються з коду й синхронізуються автоматично ще до релізу; знімок «перед
наступною версією», як у drizzle чи prisma, ніс би вже правила наступної (так 2.1.4 показувала б правила 2.2.0).
У шапці документа стоїть файл на GitHub на тому коміті: живий сайт показує лише найновішу версію. Посилання у
відповідях ведуть на github.com, www.npmjs.com, registry.npmjs.org і biomejs.dev.

Особливості, які варто знати:

- **Три схеми шляхів.** До жовтня 2023 сторінки лежали в `website/src/pages` (правило — `lint/rules/noUnusedVariables.md`,
  назвою в camelCase), далі — у `website/src/content/docs` (правило — `linter/rules/no-unused-variables.md`), з квітня
  2024 — у `src/content/docs` окремого репозиторію, з серпня 2026 англійські сторінки — у теці `en/`, а правило, що є в
  кількох мовах, — тека зі сторінкою на мову (`linter/rules/no-unused-variables/javascript.mdx`). 257 правил
  `slug_rewrite` у `config.json` зводять усе це до одного ключа: сторінка правила JavaScript (чи єдиної мови правила)
  стає тим самим документом, що й раніше; сторінки інших мов того самого правила лишаються окремими. Правила
  виведено зіставленням назв; ключ розділу ніде не спільний для двох різних сторінок однієї версії, а для різних
  джерел — лише для двох періодів сайту, оголошених однією родиною (`families`).
- **Компоненти сайту.** Сторінки — MDX для Astro Starlight. Поле `biome_mdx` (модуль `_biomemdx`) робить із виводу
  діагностики правил (сирий `<pre>` у Biome 1, рядок `<Fragment set:html={…}>` з серпня 2024) блок тексту, де видно
  повідомлення («⚠ This variable a is unused.»), з іконок таблиць правил — підписи («[This rule is recommended]»), з
  компонентів команд (`PackageManagerBiomeCommand`, `PackageManagerCommand`) і налаштувань редактора (`EditorAction`)
  — код для npm, pnpm, yarn, bun, deno, VS Code і Zed за шаблоном файла компонента того самого знімка (шаблон мінявся:
  `npx @biomejs/biome …` → `npx biome …`), зі згенерованих `.astro` — число правил і переліки рекомендованих правил і
  груп, із вкладок Starlight — підписи. Шматки `.md`/`.mdx` (типова конфігурація, приклади діагностики) розкриває
  `_astromdx`, виноски `:::note` — поле `admonitions`. Сторінки, що беруть номер найновішої версії на час збирання
  сайту (`getLatestVersion`: адреса схеми, посилання на двійковий файл), дістають найновішу версію свого документа, і
  Biome 1 та Biome 2 — окремими документами.
- **Лише англійська.** Переклади (ja, zh-CN, pt-BR, es, fr, pl, ru, uk) не беруться; також сторінка 404 і сторінки
  журналу змін сайту — журнали змін беруться з репозиторію, версія на документ.
- **Сторінка з розміткою, зламаною в самому джерелі.** Сторінка правила `useFencedCodeLanguage` для Markdown
  (2.5.x) вкладає огорожі коду одна в одну без різної довжини, і на ній лишається сирий вивід діагностики; так само
  виглядає вона й на сайті.

## Версії у відповіді

Фільтр `version` бере лінію з двох чисел (`version_line_depth` 2): `"2.5"` — усе 2.5.x, `"1.9"` — усе 1.9.x,
`"0.2"` — перші випуски. Без фільтра сторінка, що є в кількох версіях, показується один раз — найновішою редакцією.
Журнали змін мають версію свого випуску.

Без названої версії промпт велить відповідати для двох найпопулярніших стабільних ліній за завантаженнями npm (тиждень
до 13.10.2026): Biome 2 (2.5.15 — 2,4 млн) і Biome 1 (1.9.4 — 1,5 млн), а де вони різняться — для обох.

## Межі, про які треба пам'ятати

Тут немає нічних збірок і бет 2.0, попередника Rome, ESLint і Prettier поза сторінками порівняння й переходу (є
окремий примірник `eslint`), самих мов JavaScript, TypeScript і CSS (є `mdn`, `typescript`), редакторів як таких,
фреймворків. Розширення редакторів (biome-vscode, biome-zed, biome-intellij) описано сторінками сайту, власних
журналів змін розширень тут немає.

## Сховище сирого

Під час оновлення примірник тримає ще й сирі відповіді — у теці `raw/`, поза git (сховище ввімкнене за
замовчуванням). Правка читача тоді не вимагає нового завантаження: `./df biome build` збирає тексти зі сховища без
мережі. Попередні версії файлів не видаляються, а переїжджають у `raw/_old/<день>/`. Між оновленнями сховище, як і
тексти, лежить лише в архіві: серверу воно не потрібне. Устрій — у [../../UPDATE.md](../../UPDATE.md), розділ про
`refresh`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/biome-corpus-2026-10-13.tar.gz` (9 326 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде.
Архів лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/biome/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/biome-corpus-РРРР-ММ-ДД.tar.gz -C instances/biome corpus raw
find instances/biome/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/biome/raw
gzip -9 -c instances/biome/index/passages.json > instances/biome/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/biome-corpus-РРРР-ММ-ДД.tar.gz -C instances/biome
./df biome smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/biome/index/passages.json.gz`, далі
`./df biome vectors` заллє колекцію Qdrant (близько 45 хвилин).

## Установка venv

```
cd instances/biome
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # ANTHROPIC_API_KEY — для кроку ask; GITHUB_TOKEN — для репозиторіїв
cd ../..
```

## Збирання корпусу

```
./df biome sources --why   # перелік джерел і білий список
./df biome refresh         # завантажити все задеклароване (~80 хвилин: 107 дерев, ~8 800 файлів, пауза 0,3 с)
./df biome build           # перезібрати тексти зі сховища сирого, без мережі (після правки читача)
./df biome manifest        # оновити паспорт
./df biome setup           # Qdrant чи пошук лише по словах
./df biome vectors         # залити корпус у docs-biome (~45 хвилин)
./df biome smoke           # перевірки
```

Як оновлювати після нових версій — у [UPDATE.md](UPDATE.md).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df biome serve       # порт 8832
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8832/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user biome-docs http://127.0.0.1:8832/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт. Інший
шлях — запис `.mcp.json` цієї теки: Claude Code, відкритий у ній, побачить сервер сам.

**3. Перевірити.** `/mcp` — має бути `biome-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Якщо порт 8832 зайнятий, `serve` падає з «address already in use»: значить,
сервер уже піднято в іншому терміналі. Решта — scope запису — так само, як у
[README примірника nestjs](../nestjs/README.md#спосіб-б--сервер-під-claude-code-http).
