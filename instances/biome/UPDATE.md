# Оновлення корпусу biome

Дві різні роботи: звичайне оновлення, коли вийшли нові стабільні версії Biome, і збирання з нуля. Порядок усередині
кожної важливіший за самі команди.

Головне правило: **оновлювач тягне лише оголошене.** Дерева й файли репозиторіїв — лише тих комітів, що перелічені в
полі `tags` джерел `site` і `site-v1`, і лише в межах `within`; журнали змін — лише з адрес джерел `changelog` і
`changelog-v1`; версії — з реєстру npm. Нова версія сама в документацію не потрапить, доки коміт сайту не дописано в
`tags`.

Друге правило: **лише стабільні версії.** У `tags` — тільки стабільні випуски, без нічних збірок
(`1.9.5-nightly.81fdedb`) і бет (`2.0.0-beta.6`); поле `skip_versions` джерела `npm-biome` відкидає все з дефісом за
номером.

Третє правило: **версія сайту — стан гілки `main` biomejs/website на момент випуску.** Сторінки правил, довідник CLI
й конфігурації генеруються з коду biomejs/biome і синхронізуються в сайт комітами «chore(ci): synchronize to
`<коміт biome>`» ще до релізу. Тож знімок версії — останній коміт `main` (за ланцюжком перших батьків) перед першою
синхронізацією, яка вже несе коміт biome, що в реліз не ввійшов (`git merge-base --is-ancestor <коміт> <gitHead
версії>` не проходить), і до публікації наступної версії. `gitHead` версії — у реєстрі npm; якщо його немає, — тег
`@biomejs/biome@X.Y.Z` чи коміт «ci: release» перед публікацією.

Четверте правило: **нова версія змінює й старі документи.** Документ сторінки — неповторна редакція, а в рядку
`# версія:` стоять усі версії, де вона була саме такою. Тож після нових комітів джерело перезаписується цілком
(`refresh site`), а не докачується (`--missing`).

П'яте правило: **нічого не видаляється.** Ані `refresh`, ані `build`, ані `manifest` нічого не стирають самі;
`vectors` прибирає лише точки власної колекції, чиїх фрагментів у корпусі вже немає. Редакції сторінок, що після
правки читача дістали нове ім'я, лишаються в `corpus/` старими файлами — їх переносять убік вручну.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед будь-якою роботою нижче тексти й сховище сирого розпаковують, а після неї —
пакують і виносять знову; обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## 1. Вийшла нова стабільна версія

**Крок 1. Знайти версію.** Стабільні версії, час публікації й `gitHead` — у реєстрі npm
(`https://registry.npmjs.org/@biomejs/biome`, поля `time` і `versions.<версія>.gitHead`).

**Крок 2. Знімок сайту.** У голому клоні biomejs/website і частковому клоні biomejs/biome (`git clone --bare
--filter=blob:none`) за третім правилом знайти коміт `main`, що описує нову версію, і дописати на початок поля `tags`
джерела `site`: `"<повний SHA>": "2.5.16"`. Якщо сайт між двома версіями не мінявся, обидві стають в один ключ:
`"<SHA>": "2.5.17, 2.5.16"`.

**Крок 3. Журнал змін.** Адресу джерела `changelog` перевести на `gitHead` нової версії:
`https://raw.githubusercontent.com/biomejs/biome/<gitHead>/packages/%40biomejs/biome/CHANGELOG.md`.

**Крок 4. Завантажити.**

```
./df biome sources --why
./df biome refresh site changelog npm-biome
./df biome manifest
./df biome vectors
./df biome smoke
# Ctrl+C у терміналі з serve, і знову: ./df biome serve
```

Названий `refresh` інших джерел не чіпає зовсім. Джерела `site-v1` і `changelog-v1` застиглі: Biome 1 більше не
випускається.

**Крок 5. Ключі сторінок.** Якщо сайт знову переклав файли (як у серпні 2026, коли англійські сторінки переїхали в
`en/`, а правила кількох мов — у теки зі сторінкою на мову), до `slug_rewrite` у `config.json` дописують правила, що
зводять нові шляхи до ключа `src-content-docs-…`. Правильність перевіряють в `index/passages.json`: ключ розділу (`slug`
і `section`) не спільний для двох різних сторінок однієї версії і спільний для різних джерел лише в межах родини
(`families`).

**Крок 6. Промпти.** Версії за замовчуванням (найпопулярніші за завантаженнями npm:
`https://api.npmjs.org/versions/@biomejs%2Fbiome/last-week`) записано в `prompts/search.txt` (абзац «Every answer says
which version…») і `prompts/agent.txt`; межі версій — ще й у `prompts/loaded.txt`, `prompts/search.txt`,
`prompts/agent.txt` («від 0.1.2 до 2.5.15»), у `title` джерел і в README.

## 2. Вийшов Biome 3

Знімки сайту тривають у тому самому джерелі `site`, якщо сайт лишається в репозиторії biomejs/website; лінія версій
у промптах і README — «3.x» поруч із «2.x». Журнал змін 3.x — нове джерело за зразком `changelog` з власним
`name_prefix` (`biome-v3`), id якого дописують у родину `changelog` поля `families`.

## 3. Сайт змінив розмітку

Якщо в тексті з'явилися службові рядки MDX (теги компонентів `<…>`, `set:html`, `{…}`, рядки `import`), правиться
модуль `engine/readers/_biomemdx.py`. Правка читача не вимагає нового завантаження: `./df biome build site` збирає
тексти зі сховища сирого. Виняток — вставка файла, якого читач досі не брав: його в сховищі ще немає, тож потрібен
`refresh` джерела.

Корпус не комітиться: після оновлення пишуть новий архів і знову виносять тексти й сховище (README, розділ «Архівний
режим»), а в git ідуть лише паспорт і кеш. Старий архів видаляють, коли новий звірено з диском.

Якщо `smoke` скаржиться на число фрагментів — це наслідок того, що документація підросла. Нове число записують у
`checks.json` полем `expected_passages`, а в `expected_note` — коли й чому його знято.

## 4. Збирання з нуля

**Крок 1. Токен.** Покладіть `GITHUB_TOKEN=…` у `.env` цієї теки: без нього 107 дерев ішли б годинними вікнами по 60
звернень.

**Крок 2. Два прогони паралельно**, окремими процесами (пауза до хоста — у кожного своя):

```
PYTHONUNBUFFERED=1 setsid nohup ./df biome refresh site > refresh-site.log 2>&1 < /dev/null &
PYTHONUNBUFFERED=1 setsid nohup ./df biome refresh site-v1 changelog changelog-v1 npm-biome > refresh-rest.log 2>&1 < /dev/null &
```

Перший — близько 80 хвилин: дерево кожного з 81 коміту сайту через API GitHub і кожен неповторний файл (сторінка,
файл компонента) один раз із raw.githubusercontent.com, з паузою 0,3 с. Другий — близько 15 хвилин. Обірваний прогін
продовжують `./df biome refresh <джерело, де зупинився>`, далі `refresh --missing`.

**Крок 3.** `manifest`, `vectors` (~45 хвилин), `smoke`, `quality`; далі — архів і винесення текстів.

Очікуваних збоїв `refresh` немає.
