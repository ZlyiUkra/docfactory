# bun — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Bun за його документацією: bun.com/docs (runtime, `bunfig.toml`,
сумісність із Node.js, Web API, `Bun.serve`, `Bun.file`, `Bun.spawn`, `bun:sqlite`, SQL, Redis, S3, FFI, shell `Bun.$`;
менеджер пакетів `bun install`, робочі простори, каталоги, `bunx`; збирач `bun build`, плагіни, виконувані файли
`--compile`; тести `bun test`; `bun lint` і його правила; посібники) на кожен сталий патч 1.0.0–1.4.4 і останній патч
кожної мінорної 0.1–0.8, довідник API з файлів типів `packages/bun-types` на ті самі версії, релізи GitHub, записи npm
пакетів `bun`, `bun-types` і `@types/bun`, теги образу Docker `oven/bun` і всі дописи блогу bun.com. Код спільний і
лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій
фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Bun — середовище виконання JavaScript і TypeScript з вбудованими менеджером пакетів, збирачем і тестами, яке
розглядають як заміну Node.js (поряд із Deno, примірник `deno`). Нові можливості Bun виходять і в патчах: гілка 1.1 мала
46 патчів, і чимало API з'явилося саме в них. Тому тут кожен сталий патч, щоб відповідати, з якої версії що працює.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df bun <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| документація | `oven-sh/bun`, тека `docs/` (без `docs/snippets/`), `.md` до 1.3.1, `.mdx` (Mintlify) далі | `ghdocs-history` |
| довідник API | `oven-sh/bun`, `packages/bun-types/**/*.d.ts` | `ghcode-history-dts` |
| релізи | GitHub API релізів `oven-sh/bun`, теги `bun-v…` без передрелізів | `ghreleases-stable` |
| блог | `bun.com/sitemap.xml`, адреси `/blog/`; текст — HTML допису до `</article>` | `sitemap-html` |
| повні нотатки | п'ять адрес `bun.com/blog/release-notes/` | `html-list` |
| npm | `registry.npmjs.org/bun`, `bun-types`, `@types/bun` | `npm-versions` |
| Docker | `hub.docker.com/v2/namespaces/oven/repositories/bun/tags` | `dockerhub-tags` |

**Документація.** Сайт bun.com/docs збирається з теки `docs/` самого репозиторію Bun, тож теги `bun-v…` дають її стан
на кожну версію. Тека двічі міняла будову: до 1.3.1 — `docs/cli/`, `docs/api/`, `docs/install/` (markdown), далі —
`docs/runtime/`, `docs/pm/`, `docs/bundler/`, `docs/test/` (MDX Mintlify); з 1.4 додалися правила `bun lint` (1 051
сторінка). Однакові тексти різних тегів зливаються в один документ з усіма версіями.

**Блог.** Кожен допис про випуск сайт тримає двічі — `/blog/bun-v1.1.27` і `/blog/release-notes/bun-v1.1.27`, дослівно
однакові. Тека `/blog/release-notes/` відкинута полем `exclude`; п'ять повних нотаток великих випусків, яких під
`/blog/` немає, бере окреме джерело.

**Docker.** Реєстр Docker Hub без токена протоколу OCI не віддає (401), а дзеркало mirror.gcr.io тримає лише частину
тегів. Читач `dockerhub-tags` зроблено для цього примірника: він читає відкритий API hub.docker.com і дає огляд образу
(варіанти, плаваючі теги з версією, на яку кожен указує зараз, лінії) і документ на кожну лінію (версії з варіантами,
дата публікації, архітектури).

## Версії

`version: "1"` бере всі документи 1.x, `"1.2"` — мінорну з усіма її патчами, `"1.2.5"` — один патч; 0.x — `"0.8"` тощо.
Документи Docker несуть лінію (`"1.4"`), блог версії не має.

Без версії поточна документація стоїть попереду: поле `demote` у `config.json` опускає на десять місць старі теки
документації (`docs/cli/`, `docs/api/`, `docs/install/`, `docs/ecosystem/`, `docs/dev/`), блог і релізи GitHub. Інакше
на запит «як зробити» першими йшли нотатки до випусків і сторінки 1.0–1.3. З `version` чи номером випуску в запиті вони
знаходяться як і раніше.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/bun-corpus-2026-10-31.tar.gz` (4 753 тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\bun-corpus-2026-10-31.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/bun/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/bun-corpus-РРРР-ММ-ДД.tar.gz -C instances/bun corpus raw
find instances/bun/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/bun/raw
gzip -9 -c instances/bun/index/passages.json > instances/bun/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/bun-corpus-2026-10-31.tar.gz -C instances/bun
./df bun smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/bun/index/passages.json.gz`.
Далі `./df bun vectors` заллє колекцію Qdrant: менше хвилини на відеокарті, довше на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df bun …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df bun sources --why   # перелік джерел і білий список
./df bun refresh         # завантажити все задеклароване (близько 45 хвилин: 270 дерев тегів і 3 857 текстів)
./df bun manifest        # оновити паспорт
./df bun setup           # Qdrant чи пошук лише по словах
./df bun vectors         # залити корпус у docs-bun
./df bun smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df bun serve          # порт 8939
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8939/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user bun-docs http://127.0.0.1:8939/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `bun-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
