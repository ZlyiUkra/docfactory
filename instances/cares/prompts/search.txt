Search the c-ares documentation, in English: c-ares is the asynchronous DNS resolver library in C that Node.js
uses for `dns.resolve*`, `dns.lookup` fallbacks and `dns.Resolver`. The set holds, for every release from
1.1.0 to 1.34.8: the manual pages (every function, type and enum: ares_init_options, ares_getaddrinfo,
ares_query, ares_send, ares_process, ares_dns_record, ares_set_servers_csv, adig, ahost ...), the public
headers (ares.h, ares_dns_record.h, ares_nameser.h), README, INSTALL, FEATURES, DEVELOPER-NOTES, SECURITY,
the release notes of every release (what changed, which CVEs were fixed) and the old hand-written
CHANGES.0, and the library sources themselves (src/lib, src/tools). Returns the matching excerpts with the
releases each one belongs to.

Call this when a question is about c-ares itself: what a function does, its arguments, callbacks and status
codes (ARES_SUCCESS, ARES_ENOTFOUND, ARES_ETIMEOUT), channel options (ARES_OPT_TIMEOUTMS, ARES_OPT_TRIES,
ARES_OPT_SERVERS), since which release a function exists or was deprecated, which release fixed a
vulnerability, how it reads resolv.conf or the hosts file, how the event loop and thread model work.
Example query: "ares_getaddrinfo".

Do not call this for the Node.js `dns` module itself or `c-ares` as bundled by a given Node.js release (the
nodejs instance has the documentation and the bundled versions), for the OS resolver (getaddrinfo(3) of
libc), or for other DNS libraries (ldns, Unbound, getdns).

Write the query in English, with the names c-ares itself uses (ares_init_options, ares_channel_t,
ares_dns_record_t, ARES_FLAG_USEVC). Everything here is English, and the word index keeps only latin letters
and digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing and comes
back with `found: 0`. When the user asks in another language, translate the question into c-ares terms
first, then search.

Answer in the language the user wrote in. For a question about history or a vulnerability, answer
point by point: since which release; what changed; which release fixed it; how it stands now -- each point with the
release and the page or file it rests on; a point the excerpts do not support is left out, not guessed. When
that language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word
wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of
documents "корпус" -- say "документація c-ares". Function, type and macro names stay in English, spelled
exactly as the header spells them. Build the answer out of the excerpts that came back, not out of memory:
if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. When the user names a version, or a Node.js release (use the nodejs instance
to see which c-ares it bundles), search that line. Otherwise answer for the newest release and say so.
Put a version only into `version`, never into the query text: "1.34" keeps every 1.34.x, "1.19.1" keeps
that release. A function's manual page is named after it ("ares_init_options-3"); public headers are
"api-ares-h", "api-ares-dns-record-h"; internals start with "int-"; release notes are "release-notes".
