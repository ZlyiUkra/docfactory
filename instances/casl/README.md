# casl — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про CASL — ізоморфну бібліотеку авторизації JavaScript (монорепозиторій
stalniy/casl, сайт casl.js.org) — за документацією всіх її стабільних версій: сайт v4–v7 і старий сайт v1–v3, README
кожної версії семи пакетів `@casl/*` і старого пакета `casl`, журнали змін, приклади stalniy/casl-examples та історія
версій у реєстрі npm. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі
дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

CASL описує права за атрибутами (ABAC, attribute based access control): правило каже, яку дію (`read`, `update`)
користувач може виконати над якою сутністю (subject), з якими умовами мовою запитів MongoDB (`{ authorId: user.id }`)
і над якими полями. Правила будують `defineAbility` чи `AbilityBuilder`, перевіряють `ability.can(...)` або
`ForbiddenError.from(ability).throwUnlessCan(...)`; ті самі правила стають умовою запиту до бази (`accessibleBy` для
Mongoose і Prisma) і їдуть у браузер (`packRules`), де обгортки для React, Vue й Angular ховають кнопки. Документація
NestJS має главу про CASL, але лише як приклад інтеграції; у плані NestJS (фулстек-родина) це авторизація на рівні
атрибутів запису.

За шість мажорних ліній змінилося багато: у 2.0 бібліотеку розділено на пакети `@casl/*`, у 4.0 `Ability` розділено
на базовий `PureAbility` і налаштований `Ability` та додано помічник `subject`, у лінії 6 правила створює
`createMongoAbility`, у 7.0 `PureAbility` перейменовано на `Ability` без типових опцій, а `rulesToQuery` замінено на
`rulesToCondition`. Сайт кожної лінії, журнал кожного пакета
й вимоги до React, Vue, Angular, Mongoose і Prisma зібрано в одному місці, з номером версії біля кожного уривка.

збирався сайт тієї лінії. Сторінки пакетів (`package/casl-react` тощо) не беруться: на нових тегах це рядок
`@include: packages/casl-react/README.md`, на старих — копія README, а README кожної версії вже є з npm.

Журнали змін пишуть заголовки версій трьома способами (semantic-release — `# [@casl/react-v1.0.4](…)`, lerna —
`# 5.0.0 (посилання) (дата)`, release-please — `## [7.0.2](…) (дата)`), тож їх читає `changelog-regex` з виразом, що
розуміє всі три. 21 запис журналів — лише заголовок без жодного рядка (оновлення залежностей); їх пропускає поле `skip`.
`@casl/aurelia` з гілки `main` вилучено, тож її журнал береться з тегу `@casl/aurelia@1.3.2`. Релізи GitHub
(release-please, понад сотню) дублюють текст журналів і не беруться.

Чого немає. Документації React, Vue, Angular, Aurelia, Mongoose, Prisma, MongoDB, Express і NestJS: сторінки CASL і
приклади лише показують, як CASL до них під'єднується. Коду й типів пакетів: довідка API на сайті описує кожну функцію.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df casl <крок>`.

## Версії

`@casl/ability` і старий `casl` мають версії без префікса: лінії 0–1 — старий пакет `casl`, 2–7 — `@casl/ability`;
сторінки сайту мають версію тегу `@casl/ability`, з якого взято. Решта пакетів — з префіксом: `react-5`, `vue-2`,
`angular-9`, `aurelia-1`, `mongoose-8`, `prisma-2`. Фільтр `version` бере мажор (`"6"`, `"react-5"`), мінор (`"6.8"`)
або точну версію (`"6.8.1"`). Без названої версії промпт велить шукати для лінії 6 — на неї за тиждень до 24.10.2026
припадало близько 70 % завантажень `@casl/ability`, на лінію 7 (7.0.0 від 21.05.2026, 7.0.2 від 15.10.2026) близько
26 %; де 7.x відрізняється (журнал 7.0.0), модель згадує й її. Для обгорток: `@casl/react` — лінії 5 (43 %) і 7 (29 %),
відповідь для обох; `@casl/vue` — 2 (63 %); `@casl/angular` — 9 (52 %); `@casl/mongoose` — 8 (48 %); `@casl/prisma` —
2 (55 %) і 1 (45 %), відповідь для обох. Сторінка, що не змінилася між версіями, — один документ з усіма ними, тож
перелік версій уривка сам показує, відколи й доки документація казала саме це.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/casl-corpus-2026-10-24.tar.gz` (575 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\casl-corpus-2026-10-24.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/casl/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/casl-corpus-РРРР-ММ-ДД.tar.gz -C instances/casl corpus raw
find instances/casl/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/casl/raw
gzip -9 -c instances/casl/index/passages.json > instances/casl/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/casl-corpus-2026-10-24.tar.gz -C instances/casl
./df casl smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/casl/index/passages.json.gz`,
далі `./df casl vectors` заллє колекцію Qdrant (секунди на відеокарті, менше хвилини на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df casl …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df casl sources --why   # перелік джерел і білий список
./df casl refresh         # завантажити все задеклароване (близько 22 хвилин)
./df casl manifest        # оновити паспорт
./df casl setup           # Qdrant чи пошук лише по словах
./df casl vectors         # залити корпус у docs-casl
./df casl smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df casl serve          # порт 8882
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8882/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user casl-docs http://127.0.0.1:8882/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `casl-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
