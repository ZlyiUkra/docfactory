Search the Certbot documentation -- the eff-certbot.readthedocs.io site as it stood at every
stable release of Certbot, the pages of every certbot-dns-* plugin at every release, the
changelog, and the PyPI history of certbot, acme, certbot-apache, certbot-nginx and the DNS
plugins -- and return the matching excerpts with the versions each one belongs to. Certbot is
the ACME client by EFF that obtains and renews Let's Encrypt certificates: the commands (run,
certonly, renew, certificates, revoke, delete, reconfigure, register, update_account, enhance),
the authenticator and installer plugins (apache, nginx, webroot, standalone, manual, the DNS
plugins for Cloudflare, Route 53, DigitalOcean, Google, Linode, OVH, RFC 2136 and others),
http-01 and dns-01 challenges, wildcard certificates, automated renewal and the renewal
configuration files, pre/post/deploy hooks, the cli.ini configuration file, key types (RSA,
ECDSA), staging and dry runs, log rotation, lock files, where certificates live
(/etc/letsencrypt/live), installation (snap, pip, Docker, OS packages) and every command-line flag
of `certbot --help all`.

Call this when a question is about Certbot itself -- a command, a flag and its default, a plugin
and its credentials file, renewal and hooks, a file under /etc/letsencrypt -- and above all
history and compatibility: since which version a flag or plugin exists, what changed between
majors (0.x -> 1 -> 2 -> 3 -> 4 -> 5), which Python versions each release runs on (the
`requires_python` of each version is written in the PyPI documents), and which library versions a
plugin needs. Example query: "certbot requires Python".

Do not call this for the Let's Encrypt service itself (rate limits, chains, the ACME protocol), for
Apache, nginx or a DNS provider beyond what the Certbot pages say, or for other ACME clients
(acme.sh, lego, cert-manager): their documentation is not here, and the search will return Certbot
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "5" keeps every 5.x document, "2.11" keeps
2.11.x; leave it empty to search everything. Every excerpt comes back with `versions`: each
version whose documents contain this exact text, newest first -- text that stayed the same
across versions is returned once, with all of them listed, so the list itself shows from which
to which version the documentation said exactly this.

Write the query in English, with the names Certbot itself uses ("certonly", "--webroot-path",
"--deploy-hook", "--preferred-challenges", "renew", "dns-cloudflare", "cli.ini"), not in the
user's own words. Everything here is English -- the excerpts, the word index and the meaning index
alike -- and the word index keeps only latin letters and digits, so a query written in Ukrainian,
Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When
the user asks in another language, translate the question into Certbot terms first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists; what changed in later versions;
what prompted the change, if the excerpts say so; and how it stands in the current version. Every
point names the version and the document it rests on; a point the excerpts do not support is left
out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація Certbot". Identifiers, flags and titles stay in English, spelled
exactly as the documentation spells them. Build the answer out of the excerpts that came back,
not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see below. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the
query had to appear in the text, so a query phrased in other words than the documentation uses
may miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase
had a chance.

Which version to search first. For a question about how to do something today, pass `version`
"5"; if the user runs Certbot from an OS package (Debian, Ubuntu, RHEL ship older lines), the line
to name is the one installed there. Search without `version` when the question is about history,
or when the line gave nothing. Every answer says which version it is for; when the user did not
name one, answer for 5.x and say so ("for Certbot 5.x"). When the excerpts behind a statement come
only from older versions, name those versions instead of presenting the text as current.
