# chrome-extensions — примірник фабрики docfactory

Цей примірник зібрав документацію розширень Chrome і віддає її через сервер MCP, щоб модель відповідала з текстів, а не з пам'яті.
Розширення Chrome — це невелика програма на HTML, CSS і JavaScript, яку браузер завантажує поруч зі сторінками. Файл `manifest.json`
каже браузерові, що в розширенні є і які дозволи воно просить. Фонова частина розширення — service worker: браузер запускає його на
подію й зупиняє, коли той довго нічого не робить. Скрипт вмісту (content script) працює всередині відкритої сторінки й бачить її
DOM, а з фоновою частиною обмінюється повідомленнями. Решту можливостей розширення бере з API `chrome.*`: вкладки, сховище, мережеві
правила, бічна панель тощо. Нинішня версія платформи — Manifest V3. Попередню, Manifest V2, Chrome вимикає.

## Скільки цього

Усього 943 документи й 8925 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат.

| Що | Документів |
|---|---|
| посібники з розширень Manifest V3: основи, service worker, повідомлення, дозволи, інтерфейс, перехід з MV2 | 89 |
| довідник API `chrome.*` і `manifest.json` з дозволами й версією Chrome, у якій API з'явилося | 121 |
| старі сторінки Manifest V2, разом із довідником API MV2 | 147 |
| Chrome Web Store: публікація, оновлення, панель розробника, правила програми | 86 |
| файли коду офіційних прикладів `chrome-extensions-samples`: `manifest.json`, service worker, скрипти, README | 500 |

Версій у сайту немає: він показує поточний стан. Версію Chrome, з якої працює API, сторінка довідника пише у своєму тексті.

**Чого тут немає.** Записів блогу Chrome про розширення: у sitemap вони лежать разом з усім блогом, і окремо їх не виділити. Сторінок
`.html` з прикладів: це здебільшого розмітка, а запобіжник читача коду відкидає HTML на місці тексту. Архівних прикладів MV2 (тека
`_archive`). Розширень Firefox і Safari.

Замір `quality` на 08.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 9 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df chrome-extensions <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сторінки `developer.chrome.com/docs/extensions/` і `/docs/webstore/` | sitemap сайту, текст — markdown-двійник сторінки (`.md.txt`) | `devsite-md` |
| код прикладів | теки `functional-samples/` і `api-samples/` гілки `main` репозиторію `GoogleChrome/chrome-extensions-samples` | `ghcode` |

Сайт developer.chrome.com, як і web.dev, віддає кожну сторінку чистим markdown за адресою з «.md.txt». Тексти сайту Google публікує на
умовах CC BY 4.0, а код прикладів — Apache-2.0. Тому корпус можна тримати в архіві, як в інших примірників, а не лише на цій машині.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df chrome-extensions serve
```

Порт — `8960`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user chrome-extensions-docs http://127.0.0.1:8960/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/chrome-extensions-corpus-2026-11-08.tar.gz` (943 тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\chrome-extensions-corpus-2026-11-08.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/chrome-extensions/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/chrome-extensions-corpus-РРРР-ММ-ДД.tar.gz -C instances/chrome-extensions corpus raw
find instances/chrome-extensions/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/chrome-extensions/raw
gzip -9 -c instances/chrome-extensions/index/passages.json > instances/chrome-extensions/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/chrome-extensions-corpus-2026-11-08.tar.gz -C instances/chrome-extensions
./df chrome-extensions smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
