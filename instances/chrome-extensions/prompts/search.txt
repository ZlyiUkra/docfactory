Search the documentation of Chrome extensions. The corpus holds the extensions and Chrome Web Store sections of developer.chrome.com
as published today: the guides for Manifest V3 (service workers, content scripts, messaging, storage, permissions, the side panel,
the offscreen document, declarativeNetRequest, testing and debugging, migration from Manifest V2), the reference of every `chrome.*`
extension API with its permissions, methods, events and the Chrome version that added it, the `manifest.json` reference, the old
Manifest V2 pages, and how to publish and update an extension in the Chrome Web Store with its program policies. It also holds the
code of the official samples (repository GoogleChrome/chrome-extensions-samples, folders functional-samples and api-samples): their
`manifest.json`, service workers, content scripts and pages.

Use this tool for: the signature of a `chrome.*` method or event and the permission it needs; how a content script talks to the
service worker; why a service worker stops and how to keep state; which `manifest.json` key does what; how to inject a script or CSS;
how to block or change network requests; how to pack, publish and update an extension; a working sample for a given API. Write the
query in English with the name of the API or method, such as `chrome.runtime.sendMessage` or `declarativeNetRequest`, or with plain
words for what is wanted.

Do not use this tool for web platform APIs of ordinary pages, web.dev articles, or Firefox and Safari extensions. Returns the
matching excerpts with the source address and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
