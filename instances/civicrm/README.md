# civicrm — примірник фабрики docfactory

Цей примірник зібрав документацію CiviCRM і віддає її через сервер MCP, щоб модель відповідала з її текстів, а не з пам'яті. CiviCRM — це відкрита система для
неприбуткових організацій: контакти, членство, внески, події й розсилки. Її порівнюють із власною розробкою, коли вирішують, чи писати систему для асоціації самому.

## Скільки цього

Усього 1439 документів і 12 843 фрагменти. Фрагмент — це шматок документа, який пошук повертає як окремий результат.

| Що | Документів |
|---|---|
| посібник розробника, `docs.civicrm.org/dev` | 372 |
| посібник користувача, `docs.civicrm.org/user` | 170 |
| посібник адміністратора і встановлення | 89 |
| документація близько 95 розширень і навчальних матеріалів | близько 530 |
| журнал випусків кожної версії, `release-notes/` у civicrm-core | 279 |
| запис Packagist про `civicrm/civicrm-core`, усі версії | 1 |

**Версії.** Сайт документації не має версій: адреса `/user/en/4.7/` віддає те саме, що `/latest/`. Тому посібники описують поточний випуск, а що змінилося в старшій версії,
показує лише журнал випусків. Це означає, що «усі мажорні й мінорні» тут є тільки в журналі й у записі Packagist.

Замір `quality` на 03.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а запити своїми словами лише 3 із 10. Модель зазвичай питає назвами, тож
про це сказано в промпті.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df civicrm <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| посібники й розширення | `docs.civicrm.org/*/en/latest/` | `html-query` |
| журнал випусків | `release-notes/` у `civicrm/civicrm-core` | `ghdocs-history` |
| реєстр | Packagist, `civicrm/civicrm-core` | `pkg-registry` |

Карти сайту 32 книг вказують на `http://localhost:8000` або містять `None`, зокрема в посібнику розробника. Тому їхні сторінки записано в поле `pages` джерела. Книг `googlegroups` і
`mercadopago` немає: їхні адреси відповідають 404.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df civicrm serve
```

Порт — `8950`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user civicrm-docs http://127.0.0.1:8950/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `civicrm-docs` з інструментами `search_docs` і `read_section`. Якщо сервер позначено як недоступний, перевірте, чи працює
`serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів (`index/passages.json`) і колекції Qdrant.

**Де тексти.** В архіві `~/archives/docfactory/civicrm-corpus-2026-11-03.tar.gz` (1439 текстів, паспорт і сховище сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із
диском) і в копії на диску Windows `C:\Distr\civicrm-corpus-2026-11-03.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/civicrm/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/civicrm-corpus-РРРР-ММ-ДД.tar.gz -C instances/civicrm corpus raw
find instances/civicrm/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/civicrm/raw
gzip -9 -c instances/civicrm/index/passages.json > instances/civicrm/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/civicrm-corpus-2026-11-03.tar.gz -C instances/civicrm
./df civicrm smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким потрібні тексти, пропускаються («корпус в архіві»).
