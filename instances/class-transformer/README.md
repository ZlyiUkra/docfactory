# class-transformer — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про пакет npm `class-transformer` (перетворення простих об'єктів у
екземпляри класів і назад декораторами для TypeScript і JavaScript, репозиторій typestack/class-transformer) — за
документацією усіх його стабільних версій: README кожної версії, теки `docs` репозиторію, журналу змін та історії
версій у реєстрі npm.
Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

`class-transformer` — пара до `class-validator` (той самий автор, та сама організація TypeStack): вхід з мережі — проста
структура JSON, а перевіряти й обробляти треба екземпляр класу. `plainToInstance()` будує такий екземпляр, `@Type()`
вчить його вкладених класів, `@Exclude()` і `@Expose()` вирішують, що потрапить у відповідь, `@Transform()` змінює
значення. У NestJS він працює під `ValidationPipe` (опція `transform: true`) і під `ClassSerializerInterceptor`, тож у
плані NestJS стоїть поруч із class-validator. Пакет живе у версіях 0.x, і між ними були зміни, що ламають код: у 0.3.2
обробник `@Transform` отримує не три аргументи, а один об'єкт `{ value, key, obj, type }`, у 0.4.1 функції
`plainToClass`, `classToPlain` і `classToClass` отримали нові імена `plainToInstance`, `instanceToPlain` і
`instanceToInstance` (разом з виправленням відмови в обслуговуванні через спеціально зроблене тіло запиту), а у 0.5.1
старі імена повернули. README усіх версій досі називає функції старими іменами; нові імена є лише в журналі змін. Усе
це записано в README, журналі змін і реєстрі, розкиданих між npm і GitHub, — тут воно в одному місці й з номером версії
біля кожного уривка.

Офіційного сайту в пакета немає: поле `homepage` у npm веде на репозиторій GitHub. Тому примірник складається з пакета
npm і репозиторію.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, правила `redact` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише для
  завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df class-transformer <крок>`.

## Версії

Версія — номер випуску. Фільтр `version` бере лінію з двох чисел (`"0.5"`) або точну версію (`"0.4.1"`): мажор усюди
нульовий, тому лінією є мінор. Без названої версії промпт велить шукати для лінії 0.5: остання версія 0.5.1 мала близько
97 % завантажень за тиждень до 20.10.2026 (0.4.0 — 1,4 %, 0.3.1 — 0,6 %).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/class-transformer-corpus-2026-10-20.tar.gz` (31 текст, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде.
Архів лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/class-transformer/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/class-transformer-corpus-РРРР-ММ-ДД.tar.gz -C instances/class-transformer corpus raw
find instances/class-transformer/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/class-transformer/raw
gzip -9 -c instances/class-transformer/index/passages.json > instances/class-transformer/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/class-transformer-corpus-2026-10-20.tar.gz -C instances/class-transformer
./df class-transformer smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/class-transformer/index/passages.json.gz`,
далі `./df class-transformer vectors` заллє колекцію Qdrant (близько секунди на відеокарті, хвилина на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df class-transformer …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df class-transformer sources --why   # перелік джерел і білий список
./df class-transformer refresh         # завантажити все задеклароване (близько хвилини)
./df class-transformer manifest        # оновити паспорт
./df class-transformer setup           # Qdrant чи пошук лише по словах
./df class-transformer vectors         # залити корпус у docs-class-transformer
./df class-transformer smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df class-transformer serve          # порт 8875
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8875/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user class-transformer-docs http://127.0.0.1:8875/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `class-transformer-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
