Search the class-transformer documentation -- the README of every stable version of the npm package
`class-transformer` (decorator-based transformation, serialization and deserialization between plain
objects and class instances for TypeScript and JavaScript, from the TypeStack organisation), the pages of
its `docs` folder on GitHub, the changelog and the npm registry history of the package -- and return the
matching excerpts with the versions each one belongs to.

Call this when a question is about class-transformer as it describes itself -- plainToInstance() and its
older name plainToClass(), instanceToPlain() and classToPlain(), instanceToInstance() and classToClass(),
plainToClassFromExist(), serialize(), deserialize(), deserializeArray(), the decorators @Type, @Expose,
@Exclude, @Transform, @TransformClassToPlain, @TransformClassToClass, @TransformPlainToClass, the options of
a transformation (strategy "excludeAll" or "exposeAll", excludeExtraneousValues, excludePrefixes, groups,
version, ignoreDecorators, enableImplicitConversion, enableCircularCheck, exposeDefaultValues,
exposeUnsetFields, targetMaps), nested objects and arrays, Set and Map, polymorphism through a
`discriminator`, exposing getters and methods, renaming properties, skipping properties by operation
(`toClassOnly`, `toPlainOnly`), groups, since/until versions of a property, date strings to Date objects,
generics, implicit type conversion, circular references, the parameters of the @Transform handler (value,
key, obj, type, options), the requirement for `reflect-metadata` and the TypeScript options
`experimentalDecorators` and `emitDecoratorMetadata` -- and above all history and compatibility: since which
version a function, decorator or option exists, what changed between versions, what the breaking changes were
(0.2.0, 0.2.2 and 0.2.3, 0.3.2 with the new signature of the @Transform handler, 0.4.1 with the renamed
functions and the fixed denial of service, 0.5.1 that brought the old names back), which versions are
deprecated (0.2.1 and 0.2.2), and when every version came out.

Do not call this for class-validator (validate, @IsString, ValidationPipe options and the like), for the NestJS
ValidationPipe and its `transform` option, for plain-to-class mappers such as AutoMapper or
class-transformer-validator, for JSON Schema, Zod or any other validation library, nor for TypeScript
decorators in general: their documentation is not here, and the search will return excerpts that merely
mention them, with confident-looking titles.

`version` narrows the search to one release line. The package is numbered 0.x: the lines are 0.1, 0.2, 0.3, 0.4
and 0.5 (21 stable versions, 0.1.0 to 0.5.1). "0.5" keeps every 0.5.x document, "0.4.1" one exact version.
There was never a 1.0. The versions 0.1.0-beta.1 to 0.1.0-beta.10 are not stable releases: only the registry
lists them. Versions below 0.1.0 appear nowhere. Leave `version` empty to search everything, including text
that carries no version. Every excerpt comes back with `versions`: each version whose documents contain this
exact text, newest first -- text that stayed the same across versions is returned once, with all of them
listed, so the list itself shows from which to which version the documentation said exactly this.

Write the query in English, with the names the documentation itself uses ("plainToClass", "classToPlain",
"Expose", "Exclude", "Transform", "excludeExtraneousValues", "enableImplicitConversion", "groups"), not in the
user's own words. The README of every version still uses the old function names plainToClass, classToPlain and
classToClass; the new names plainToInstance, instanceToPlain and instanceToInstance appear in the changelog
(0.4.1), so search for both. Everything here is English -- the excerpts, the word index and the meaning index
alike -- and the word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any
other non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in another
language, translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it
rests on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as
a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word
wherever one exists -- "уривок", not "ексерпт"; "перетворення", "декоратор", "застарілий". Never call this set
of documents "корпус" -- say "документація class-transformer". Identifiers, decorator names and titles stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came back,
not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the whole
thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means
a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. 0.5.1 is the newest version and takes about 97 % of weekly downloads (0.4.0 about
1.4 %, 0.3.1 about 0.6 %), so pass `version` "0.5" for how things are done today and name the version in the
answer. Search without `version` when the question is about history, or when the line gave nothing. Every answer
says which version it is for; when the excerpts behind a statement come only from older versions, name those
versions instead of presenting the text as current.
