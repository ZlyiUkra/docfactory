# class-validator — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про пакет npm `class-validator` (валідація класів декораторами для
TypeScript і JavaScript, репозиторій typestack/class-validator) — за документацією усіх його стабільних версій: README
кожної версії, теки `docs` репозиторію, журналу змін, релізів GitHub та історії версій у реєстрі npm.
Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

`class-validator` — стандартний спосіб описати правила перевірки даних класом: кожну властивість прикрашають
декораторами (`@IsString()`, `@IsEmail()`, `@Length()`…), а функція `validate()` повертає перелік порушень. Саме його
бере `ValidationPipe` у NestJS, тож у навчальних планах NestJS і Next.js він зустрічається в кожному місці, де дані
надходять ззовні. Пакет живе у версіях 0.x, і між ними були зміни, що ламають код: у 0.12.0 з класу `Validator`
прибрано методи перевірки (заради tree shaking), у 0.14.0 параметр `forbidUnknownValues` став типово увімкненим (об'єкт
без жодного декоратора тепер не проходить перевірку), у 0.15.1 функція `@IsIBAN` дістала аргумент `options`. Усе це
записано в README, журналі змін і релізах, розкиданих між npm і GitHub, — тут воно в одному місці й з номером версії біля
кожного уривка.

Офіційного сайту в пакета немає: поле `homepage` у npm веде на репозиторій GitHub. Тому примірник складається з пакета
npm і репозиторію.

Разом 85 документів; фрагментів в індексі — 278 (`expected_passages` у `checks.json`). Чотири реліз-документи
(v0.13.0, v0.13.1, v0.13.2, v0.14.0) у самому GitHub порожні: у корпусі лише їхня шапка, фрагментів вони не дають.
Замір `quality`: по словах 5 із 11, за змістом 4, разом 6, «як модель» 10 із 11.

**Відома слабкість.** Розділ README «Validation decorators» — одна таблиця на близько 30 000 символів (усі декоратори
підряд, без порожніх рядків), і рушій ріже розділи лише по порожніх рядках, тож це один фрагмент. Пошук по словах його
розбавляє (довжина), пошук за змістом бачить лише початок таблиці, тому запит «які декоратори перевіряють e-mail,
телефон, URL» не піднімає цей розділ у п'ятірку, і саме він дає єдиний промах «як модель». Промпт радить шукати
«validation decorators» з іменами декораторів, але стійко це не лікує; повний текст таблиці `read_section` віддає за
`id` `class-validator-markdown#validation-decorators`.

Чому немає коду й тестів: їх не просили, а документація пакета (README, `docs`, журнал, релізи) відповідає на питання
про те, що викликати й що змінилося. Код версій можна додати окремим джерелом `ghcode-history`, як у примірнику `passport`.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, правила `redact` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише для
  завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df class-validator <крок>`.

## Версії

Версія — номер випуску. Фільтр `version` бере лінію з двох чисел (`"0.14"`) або точну версію (`"0.14.4"`): мажор усюди
нульовий, тому лінією є мінор. Без названої версії промпт велить шукати для лінії 0.14 — на неї за тиждень до 20.10.2026
припадало близько 72 % завантажень (0.14.4 — 32 %, 0.14.3 — 17 %, 0.14.1 — 10 %, 0.14.2 — 8 %, 0.14.0 — 5 %), а 0.15.1,
найновіша, мала близько 25 % — і згадувати 0.15, де вона відрізняється (опція `validateIf` у кожного валідатора,
аргумент `options` в `@IsIBAN`, нові `@IsISO31661Numeric` і `@IsISO6391`, більше версій `@IsUUID`).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/class-validator-corpus-2026-10-20.tar.gz` (85 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде.
Архів лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/class-validator/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/class-validator-corpus-РРРР-ММ-ДД.tar.gz -C instances/class-validator corpus raw
find instances/class-validator/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/class-validator/raw
gzip -9 -c instances/class-validator/index/passages.json > instances/class-validator/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/class-validator-corpus-2026-10-20.tar.gz -C instances/class-validator
./df class-validator smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/class-validator/index/passages.json.gz`,
далі `./df class-validator vectors` заллє колекцію Qdrant (близько секунди на відеокарті, хвилина на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df class-validator …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df class-validator sources --why   # перелік джерел і білий список
./df class-validator refresh         # завантажити все задеклароване (близько хвилини)
./df class-validator manifest        # оновити паспорт
./df class-validator setup           # Qdrant чи пошук лише по словах
./df class-validator vectors         # залити корпус у docs-class-validator
./df class-validator smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df class-validator serve          # порт 8874
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8874/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user class-validator-docs http://127.0.0.1:8874/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `class-validator-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
