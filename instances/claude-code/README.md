# claude-code — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Claude Code — агента Anthropic для програмування в терміналі, IDE,
застосунку для комп'ютера й браузері: налаштування й дозволи, `CLAUDE.md` і пам'ять, скіли, субагенти, хуки, MCP,
плагіни й маркетплейси, моди, довідник CLI, команд і змінних оточення, Agent SDK, GitHub Actions. Документація —
сайт code.claude.com/docs англійською цілком, журнал змін Claude Code за версіями, Agent SDK для TypeScript і Python,
claude-code-action, офіційні скіли й плагіни Anthropic і довідник спільноти Claude Code Handbook російською. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Інструмент для роботи з самим Claude Code: що означає налаштування, яка подія хука що отримує, як підключити
MCP-сервер для всіх проєктів, які поля приймає `SKILL.md`, що змінилося у версії — за документацією, а не з
пам'яті моделі. Claude Code виходить майже щодня (на 27.10.2026 — 2.1.312), і разом із ним міняються налаштування,
команди й події, тож сторінки сайту лежать знімком, а журнал змін — по документу на кожну версію. Примірник
`anthropic-api` (порт 8860) про це не знає: він тримає документацію API Anthropic, сторінок Claude Code там немає.

Довідник sfrangulov/claude-code-handbook-ru — обов'язкове джерело за рішенням користувача: розділ Harness
(«обв'язка» — скіли, субагенти, хуки, моди, MCP і `CLAUDE.md` разом як конвеєр), каталог 1400+ інструментів
спільноти, поради команди Claude Code, шаблони `CLAUDE.md`. Ліцензія CC0.

Разом 1 716 записів паспорта, 16 757 фрагментів (`expected_passages` у `checks.json`) із 1 712 документів. Довгі
таблиці сайту (змінні оточення — 133 КБ, команди, налаштування, прапорці CLI, помилки) поділено на фрагменти з цілих
рядків полем `split_long_tables`. Вектори на відеокарті — пів хвилини.

Замір `quality`: по словах 4 із 10, за змістом 3, разом 4, «як модель» 10 із 10. Цілі доповнено справжніми
відповідями: таблиця полів frontmatter усіх файлів у сторінці про теку `.claude` і розділ про рішення `PreToolUse`.
Промахи першої десятки — питання своїми словами, на які в документації кілька правильних відповідей у різних
місцях: «зробити зовнішній сервер інструментів доступним у кожному проєкті» знаходить сторінку MCP в Agent SDK, а не
рівень `user` у Claude Code. `max_per_doc` і `fusion_depth` не ставились.

Чого немає:

- Перекладів сайту, російського зокрема: лише англійська редакція (`within` джерела `site`).
- Документації Claude Tag (Claude у Slack). Сайт Claude Code посилається на неї, але сторінка `claude-tag`
  переадресовує на claude.com/docs — це вже інший сайт і окремий продукт на 79 сторінок, його немає в білому
  списку. Через це `refresh` джерела `site` щоразу показує один збій.
- Файла типів модів `mods/types/claude-code.d.ts` (517 КБ) і коду вбудованих модів: читач коду лишав файл типів
  одним фрагментом. API модів описують сторінки сайту `plugins/mods/*`.
- Релізів GitHub: вони повторюють `CHANGELOG.md`. README пакета `@anthropic-ai/claude-code` у реєстрі npm порожній.
- Сторінок, на які посилається довідник sfrangulov (Habr, блоги, репозиторії з каталогу): береться лише текст
  самого репозиторію.

## Довідник російською: кирилиця в пошуку

Індекс слів фабрики бере лише латиницю й цифри, а модель векторів (`bge-small`) англійська, тож російський текст
довідника без особливого поля був би невидимим. Поле `cyrillic_words: true` у `config.json` робить кирилицю
літерами слів, а кириличні заголовки транслітерує в ключах розділів (`Как устроен автономный конвейер` →
`kak-ustroen-avtonomnyy-konveyer`), щоб різні розділи не злипалися в один. Запит без жодного латинського слова
шукається лише по словах, без векторів.

Отже, офіційна документація шукається англійським запитом, а пояснення довідника — російським («обвязка конвейер
субагенты»). Український запит знаходить довідник лише там, де слово пишеться однаково обома мовами. Опис
інструмента (`prompts/search.txt`) каже про це моделі, і там же: довідник — спільнота, а не Anthropic, і коли він
розходиться з сайтом, правий сайт.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус (20 джерел). Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df claude-code <крок>`.

## Версії

Сторінки сайту, знімки репозиторіїв, скіли, плагіни й довідник версій не мають — це поточний стан. Записи журналу
змін і рядки npm Claude Code несуть голу версію (`2.1.312`), Agent SDK — свою з префіксом (`agent-sdk-ts-0.3.312`,
`agent-sdk-py-0.2.174`), claude-code-action — `action-1.0.264` і `action-0.0.63`. Фільтр `version` приймає лінію
(`"2.1"`, `"agent-sdk-ts-0.3"`, `"action-1.0"`) або один випуск (`"2.1.312"`).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/claude-code-corpus-2026-10-27-tables.tar.gz` (1 716 текстів, паспорт і
сховище сирого `raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\claude-code-corpus-2026-10-27-tables.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/claude-code/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/claude-code-corpus-РРРР-ММ-ДД.tar.gz -C instances/claude-code corpus raw
find instances/claude-code/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/claude-code/raw
gzip -9 -c instances/claude-code/index/passages.json > instances/claude-code/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/claude-code-corpus-2026-10-27-tables.tar.gz -C instances/claude-code
./df claude-code smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/claude-code/index/passages.json.gz`.
Далі `./df claude-code vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df claude-code …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df claude-code sources --why   # перелік джерел і білий список
./df claude-code refresh         # завантажити все задеклароване (кілька хвилин)
./df claude-code manifest        # оновити паспорт
./df claude-code setup           # Qdrant чи пошук лише по словах
./df claude-code vectors         # залити корпус у docs-claude-code
./df claude-code smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df claude-code serve          # порт 8926
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8926/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user claude-code-docs http://127.0.0.1:8926/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `claude-code-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
