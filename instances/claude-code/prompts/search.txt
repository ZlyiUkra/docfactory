Call this when a question is about using, configuring or extending Claude Code or the Agent SDK: settings.json
keys and their scopes, permission rules and modes, CLAUDE.md and rules files, skills and SKILL.md frontmatter,
subagents, hook events (PreToolUse, PostToolUse, Stop, SessionStart and the rest), matchers, exit codes and JSON
output, MCP servers (claude mcp add, scopes, .mcp.json), plugins, marketplaces and mods, slash commands, CLI flags
(claude -p, --resume, --model), environment variables, sandboxing, IDE integrations, headless and CI use, Bedrock,
Vertex and Foundry, costs and usage limits, the Agent SDK (query(), options, hooks, custom tools, sessions),
claude-code-action inputs, Claude Tag in Slack (setup, connections, commands), or what changed in a given Claude
Code version. Example query: "PreToolUse hook matcher exit code 2".

Do not call this for the Anthropic API itself (Messages API, model IDs, pricing per MTok, SDKs of the API), for
the Claude apps outside Claude Code and Claude Tag (claude.ai chats, Cowork, Office agents), or for other coding
agents (Codex, Gemini CLI, Cursor).

Write the query in English, with the names the documentation uses (settings.json, permissions.allow, PreToolUse,
SKILL.md, subagent_type, claude mcp add, CLAUDE_CODE_USE_BEDROCK, --dangerously-skip-permissions). The official
documentation is English, and so is the meaning index: a question asked in another language is translated into
Claude Code terms first. The handbook is the one exception: it is written in Russian, and its prose is found only
by Russian words (the word index here keeps Cyrillic too, and a query with no latin word is searched by words
only, without the meaning index). When the handbook's commentary matters -- harness, orchestration, methodologies,
tips, the catalogue descriptions -- search a second time in Russian ("обвязка конвейер субагенты"). Ukrainian
words match the handbook only where they happen to be spelled as in Russian.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its version
and the page it rests on; a point the excerpts do not support is left out, not guessed. When that language is
Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "налаштування", "дозвіл", "вікно контексту", "субагент". Never call this set of documents
"корпус" -- say "документація Claude Code". Setting, flag, event, command, tool and type names stay in English,
spelled exactly as the documentation spells them. The handbook is a community guide, not Anthropic's
documentation: say so when an answer rests on it, and where it disagrees with the official site, the site wins.
Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of
it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional.
The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the
`id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase had a
chance.

Which version to answer for. The site pages, Claude Tag, the repository snapshots, the skills, the plugins and the
handbook carry no version: they are the current state. Claude Code changelog entries and npm rows carry the plain
version ("2.1.312"); the Agent SDK carries its own: "agent-sdk-ts-0.3.312" (@anthropic-ai/claude-agent-sdk),
"agent-sdk-py-0.2.174" (claude-agent-sdk on PyPI); claude-code-action carries "action-1.0.264" and
"action-0.0.63". When the user names a version, pass it into `version` -- a line ("2.1", "agent-sdk-ts-0.3",
"action-1.0") or one release ("2.1.312"); never put it into the query text. Without a version, answer for the
current documentation and say so.
