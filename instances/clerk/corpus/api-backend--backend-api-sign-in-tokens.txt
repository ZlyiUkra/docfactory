# Backend API: Sign-in Tokens
# джерело: https://clerk.com/docs/reference/backend-api
# отримано: 2026-09-25

Sign-in tokens are JWTs that can be used to sign in to an application without specifying any credentials.
A sign-in token can be used at most once and they can be consumed from the Frontend API using the `ticket` strategy.

## POST /sign_in_tokens

Create sign-in token

Creates a new sign-in token and associates it with the given user.
By default, sign-in tokens expire in 30 days.
You can optionally supply a different duration in seconds using the `expires_in_seconds` property.

Request body (application/json):

- `user_id` `string`, required: The ID of the user that can use the newly created sign in token
- `org_id` `string`: The ID of the organization to activate when the user signs in. Organizations must be enabled for the instance, and the user must be a member of the organization.
- `expires_in_seconds` `integer`: Optional parameter to specify the life duration of the sign in token in seconds. By default, the duration is 30 days.

Responses:

- `200`: Success
- `403`: Authorization invalid
- `404`: Resource not found
- `422`: Invalid request parameters

## POST /sign_in_tokens/{sign_in_token_id}/revoke

Revoke the given sign-in token

Revokes a pending sign-in token

Parameters:

- `sign_in_token_id` (path, required) `string`: The ID of the sign-in token to be revoked

Responses:

- `200`: Success
- `400`: Request was not successful
- `404`: Resource not found
