# Frontend API: Checkouts
# джерело: https://clerk.com/docs/reference/frontend-api
# отримано: 2026-09-25

Used to interact with the checkout flow.

## POST /v1/me/billing/checkouts

Create billing checkout

Creates a new billing checkout for the current user.

Request body (application/x-www-form-urlencoded):

- `plan_id` `string`, required: The ID of the plan to checkout
- `plan_period` `string, one of month, annual`, required: The billing period for the plan
- `org_id` `string`: Organization ID (if creating org checkout)
- `payment_method_id` `string`: Payment method ID to use

Responses:

- `200`: Returns a commerce checkout.
- `400`: Request was not successful
- `401`: Authentication invalid
- `403`: Request was not successful
- `409`: Request was not successful
- `422`: Invalid request parameters

## GET /v1/me/billing/checkouts/{checkoutID}

Get billing checkout

Returns a billing checkout for the current user.

Parameters:

- `checkoutID` (path, required) `string`: The ID of the checkout

Responses:

- `200`: Returns a commerce checkout.
- `400`: Request was not successful
- `401`: Authentication invalid
- `404`: Resource not found
- `410`: Request was not successful

## PATCH /v1/me/billing/checkouts/{checkoutID}

Update billing checkout

Applies or removes a promo code on an in-progress billing checkout for the current user.
A non-blank promo_code applies the code; a blank value clears it.

Parameters:

- `checkoutID` (path, required) `string`: The ID of the checkout to update

Request body (application/x-www-form-urlencoded):

- `promo_code` `string`, required: The promo code to apply to this checkout. Send a blank value to clear the currently applied promo code.

Responses:

- `200`: Returns a commerce checkout.
- `400`: Request was not successful
- `401`: Authentication invalid
- `404`: Resource not found
- `409`: Request was not successful
- `422`: Invalid request parameters

## PATCH /v1/me/billing/checkouts/{checkoutID}/confirm

Confirm billing checkout

Confirms a billing checkout for the current user.

Parameters:

- `checkoutID` (path, required) `string`: The ID of the checkout to confirm

Request body (application/x-www-form-urlencoded):

- `payment_method_id` `string`: The ID of the payment method to use for this checkout
- `gateway` `string`: The payment gateway to use (e.g., stripe)
- `payment_token` `string`: A payment token for processing the payment
- `use_test_card` `boolean`: Whether to use a test card for payment processing

Responses:

- `200`: Returns a commerce checkout.
- `400`: Request was not successful
- `401`: Authentication invalid
- `404`: Resource not found
- `409`: Request was not successful
- `422`: Invalid request parameters
