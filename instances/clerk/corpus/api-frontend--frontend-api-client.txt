Used to interact with the Client Object.

## GET /v1/client

Get Current Client

Returns the current client that is present either in the browser cookies or authorization header.

Security: DevBrowser

Responses:

- `200`: Returns the current session object.
- `400`: Request was not successful
- `401`: Request was not successful
- `403`: Request was not successful

## GET /v1/client/handshake

Generate and return a new session token for a given client.

When the authentication status cannot be determined from the current session token, we initiate a handshake to refresh the token and send it back to the application. Called in server environments.

Parameters:

- `Clerk-Proxy-Url` (header) `string`: The URL of the proxy
- `Clerk-Secret-Key` (header) `string`: The secret key of the proxy
- `redirect_url` (query) `string`: The URL to redirect back to after the handshake
- `format` (query) `string, one of nonce, token`: The supported format of the handshake payload.
- `organization_id` (query) `string`: The organization ID or slug to attempt to set as active for the session. If this param is present but has no value, the personal account will be set as active. If the organization cannot be set as active (because it does not exist, or the user is not a member), the active organization for the session will not change.
- `satellite_fapi` (query) `string`: The Frontend API of the satellite domain

Responses:

- `307`: Redirect
- `400`: Request was not successful
- `403`: Request was not successful
- `404`: Request was not successful
- `422`: Request was not successful
- `500`: Request was not successful

## GET /v1/agents/tasks

Create session from agent task

Creates a new session directly from an agent task without requiring navigation to the sign-in page.
Agent tasks are single-use tokens created via the Backend API that bypass MFA requirements.

The endpoint returns a redirect with a handshake cookie containing all session cookies,
enabling cookie sync to the app domain in a single step. This is useful for browser
automation tools (Puppeteer, Playwright) that need cookies on the application domain.

Security: DevBrowser

Parameters:

- `ticket` (query, required) `string`: The agent task ticket value obtained from the Backend API.

Responses:

- `307`: Redirect to the `redirect_url` specified when the agent task was created. Before redirecting, the URL is validated: - Must be a valid absolute URL with an `https` scheme in production. In development instances, `http` is also permitted. - The URL's domain must belong to one of the instance's associated domains (primary or satellite). In production, the handshake payload is set as a cookie. In development, the handshake payload is passed as a query parameter.
- `400`: Request was not successful
- `403`: Request was not successful
- `404`: Request was not successful
- `422`: Request was not successful
- `500`: Request was not successful
