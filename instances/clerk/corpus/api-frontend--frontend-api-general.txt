# Frontend API: general
# джерело: https://clerk.com/docs/reference/frontend-api

## GET /v1/account_portal

Get account portal

Get users account portal

Responses:

- `200`: Returns the account portal.
- `400`: Request was not successful
- `401`: Request was not successful
- `404`: Request was not successful

## GET /v1/proxy-health

Get Proxy Health

Use this endpoint to check the validity of a proxy configuration for a domain.
Pass the instance ID and domain ID as query parameters.

Parameters:

- `domain_id` (query, required) `string`: The ID of the domain
- `Clerk-Proxy-Url` (header, required) `string`: The URL of the proxy
- `Clerk-Secret-Key` (header, required) `string`: The secret key of the proxy
- `X-Forwarded-For` (header, required) `string`: The IP address of the client

Responses:

- `200`: Configuration is valid
- `400`: Request was not successful
- `503`: Configuration is invalid or service is unavailable

## GET /v1/client/sync

Sync clients across multiple domains

Start the syncing process between a satellite and primary domain.

Parameters:

- `link_domain` (query) `string`: The satellite domain which should be synced with its primary.
- `redirect_url` (query) `string`: The URL to redirect to after the syncing process has been completed.

Responses:

- `307`: Redirect
- `400`: Request was not successful
- `403`: Request was not successful
- `422`: Request was not successful

## GET /v1/client/link

Link clients across multiple domains

Complete a syncing process between a satellite and primary domains by linking their clients.

Parameters:

- `__clerk_token` (query) `string`: The token generated from a sync request.

Responses:

- `307`: Redirect
- `400`: Request was not successful
- `403`: Request was not successful
- `422`: Request was not successful

## POST /v1/dev_browser/set_first_party_cookie

Post Dev Browser init set cookie

post dev_browser/set_first_party_cookie

Responses:

- `200`: A cookie for the dev browser was set.

## GET /v1/dev_browser/init

Initialize dev browser for development and staging instances

get dev_browser/init

Parameters:

- `origin` (query) `string`: The origin of the request

Responses:

- `200`: Successfully initialized the dev browser.
- `400`: Request was not successful
- `500`: Request was not successful

## GET /v1/clear-site-data

Set the Clear-Site-Data header

Clear browsing data (cookies, storage, cache) associated with the requesting website

Responses:

- `200`: The Clear-Site-Data header was set with wildcard value.
