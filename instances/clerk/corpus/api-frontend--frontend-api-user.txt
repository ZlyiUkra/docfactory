# Frontend API: User
# джерело: https://clerk.com/docs/reference/frontend-api
# отримано: 2026-09-25

Used to interact with the properties of the current user.

## GET /v1/me

Get User

Returns all attributes of the current user.

Responses:

- `200`: Returns the response for Session wrapped User object.
- `401`: Request was not successful
- `403`: Request was not successful
- `404`: Request was not successful

## PATCH /v1/me

Update User

Update the current user with the given attributes.

`unsafe_metadata` is not accepted on this endpoint as of API version 2026-05-12.
Use `PATCH /v1/me/metadata` to update `unsafe_metadata`.

Request body (application/x-www-form-urlencoded):

- `username` `string`
- `first_name` `string`
- `last_name` `string`
- `primary_email_address_id` `string`
- `primary_phone_number_id` `string`
- `primary_web3_wallet_id` `string`

Responses:

- `200`: Returns the response for Session wrapped User object.
- `400`: Request was not successful
- `401`: Request was not successful
- `403`: Request was not successful
- `404`: Request was not successful
- `422`: Request was not successful

## PATCH /v1/me/metadata

Merge and update the current user's metadata

Update the current user's metadata attributes by merging existing values with the provided parameters.

This endpoint behaves differently than the *Update User* endpoint.
Metadata values will not be replaced entirely.
Instead, a deep merge will be performed.
Deep means that any nested JSON objects will be merged as well.

You can remove metadata keys at any level by setting their value to `null`.

Only `unsafe_metadata` can be updated through the Frontend API. `public_metadata` and `private_metadata` must be modified through the Backend API.

Request body (application/x-www-form-urlencoded):

- `unsafe_metadata` `string`, required: A stringified JSON object containing the unsafe metadata patch to merge into the current user's `unsafe_metadata`. Existing keys are deep-merged; keys at any level with `null` values are removed.

Responses:

- `200`: Returns the response for Session wrapped User object.
- `400`: Request was not successful
- `401`: Request was not successful
- `403`: Request was not successful
- `404`: Request was not successful
- `422`: Request was not successful
