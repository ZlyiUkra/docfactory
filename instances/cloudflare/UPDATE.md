# Оновлення корпусу cloudflare

Сайт версій не має: кожен `refresh` бере його поточний стан, і змінена сторінка не затирає збереженої — стара відповідь
переїжджає в `raw/_old/<день>/`. README пакетів читаються з реєстру npm щоразу заново (нові версії додаються самі),
журнали змін — з гілки main workers-sdk.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df cloudflare check                 # чи змінилося щось нагорі за джерелом
./df cloudflare refresh               # повне перезавантаження (близько півтори години)
./df cloudflare refresh npm-readme-wrangler changelog-wrangler   # лише пакети
./df cloudflare manifest
./df cloudflare vectors
./df cloudflare smoke
# Ctrl+C у терміналі з serve, і знову: ./df cloudflare serve
```

Перерваний повний прогін продовжують командою `refresh <джерело, де зупинився>`, а потім `refresh --missing`.

**Що перевірити після оновлення.**

- Сторінка, що зникла з sitemap, лишається в корпусі (нічого не видаляється). Щоб прибрати її, файл видаляють руками
  разом із записом паспорта — лише за рішенням людини.
- Якщо `refresh` пише «Сторінка не схожа на документ» чи «у шапці YAML немає title», сайт змінив розмітку markdown:
  звірити одну сторінку (`curl -H 'Accept: text/markdown' <адреса>`) з виразами `drop` і `exclude` джерела `site`.
- Якщо пакет переїхав у workers-sdk в іншу теку (як `vitest-pool-workers` → `packages/vitest-plugin/`), журнал змін
  дає 404: виправити адресу джерела `changelog-…`.
- Нова мажорна `wrangler` (на 31.10.2026 найновіша — 4.156.0): замінити `"4"` у `prompts/search.txt`, `prompts/agent.txt`
  і `version_probe` у `checks.json`.

Якщо `smoke` скаржиться на число фрагментів, корпус підріс. Нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df cloudflare quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
