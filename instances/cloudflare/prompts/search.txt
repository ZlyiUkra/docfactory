Search the Cloudflare documentation and return the matching excerpts with the versions each one belongs to.
What is here: every page of developers.cloudflare.com as a current snapshot -- the developer platform (Workers and
its runtime APIs, bindings, Wrangler commands and configuration, Pages, R2, D1, Workers KV, Durable Objects, Queues,
Workflows, Workers AI, Vectorize, Hyperdrive, AI Gateway, Agents, Containers, Browser Rendering, Images, Stream,
Realtime, Email), application performance and security (DNS, cache and CDN, rules and the ruleset engine, SSL/TLS,
WAF, DDoS protection, bots, Turnstile, load balancing), Cloudflare One and Zero Trust (Access, Gateway, Tunnel, WARP),
network services (Magic Transit, Spectrum), analytics, logs, fundamentals, learning paths, reference architectures
and the changelog posts; the README of every stable version of wrangler, @cloudflare/workers-types, miniflare,
create-cloudflare (C3) and @cloudflare/vitest-pool-workers, and of @cloudflare/vitest-plugin, its successor under a new name since 1.x; the changelogs of wrangler, miniflare, create-cloudflare
and @cloudflare/vitest-pool-workers from the workers-sdk repository.

Call this when a question is about Cloudflare: writing, configuring, testing and deploying Workers (fetch handler,
bindings, environment variables and secrets, compatibility dates and flags, `wrangler.jsonc` / `wrangler.toml`,
wrangler commands), the storage and compute products and their limits and pricing, local development with
miniflare and the Vitest integration (`@cloudflare/vitest-plugin`, `cloudflareTest`), Pages and static assets, DNS records and zones, caching and rules, SSL certificates, WAF and
bot settings, Zero Trust policies, Tunnel, and history: since which wrangler version a command or flag exists, what
changed in a release, when a product announcement appeared in the changelog.

Do not call this for other clouds or hosting platforms (AWS, Vercel, Netlify), for frameworks themselves (Hono,
Astro, Next.js, Remix) beyond how they deploy to Cloudflare, for Node.js or Web API semantics in general, or for
JavaScript or TypeScript language questions: their documentation is not here, and the search will return Cloudflare
excerpts that merely mention them, with confident-looking titles.

The site carries no version: its pages describe Cloudflare as of the day they were fetched. `version` narrows the
search to one release line of a package: "4" keeps every wrangler 4.x README and changelog entry; the other
packages carry their own numbering with a prefix, so they never mix with wrangler: "miniflare-4",
"create-cloudflare-2", "vitest-pool-workers-0", "vitest-plugin-1", "workers-types-4"; the
changelog of the Vitest integration keeps the "vitest-pool-workers-" prefix for its 1.x entries too. Leave it empty to search everything, the site
included. Every excerpt comes back with `versions`: each version whose documents contain this exact text, newest
first, so the list itself shows from which to which version a README said exactly this.

Write the query in English, with the names Cloudflare itself uses ("wrangler deploy", "compatibility_date",
"Durable Objects alarms", "R2 presigned URLs", "D1 migrations", "KV limits", "cloudflared tunnel", "Access
policies", "cache rules"), not in the user's own words. Everything here is English -- the excerpts, the word index
and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written in
Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the
user asks in another language, translate the question into Cloudflare terms first, then search.

Answer in the language the user wrote in. When the question is about the history of a wrangler command or option,
answer point by point: since which version it exists; what changed in later versions; what prompted the change, if
the excerpts say so; and how it stands now. Every point names the version and the document it rests on; a point
the excerpts do not support is left out, not guessed. Limits and prices are quoted as the page states them, as of
the date it was fetched. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents "корпус" -- say "документація
Cloudflare". Identifiers, command names, keys and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read
the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated:
true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.
