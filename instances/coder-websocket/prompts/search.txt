Search the documentation of coder/websocket (github.com/coder/websocket, formerly nhooyr.io/websocket), a minimal
idiomatic WebSocket library for Go built on net/http and context: the README and the example READMEs at every minor
release 0.1 ... 1.8 (features, comparison with gorilla/websocket and gobwas/ws, the chat and echo examples); the
package reference from pkg.go.dev for 1.8 at github.com/coder/websocket and for 1.0 ... 1.8 at the old path
nhooyr.io/websocket -- Accept, AcceptOptions (OriginPatterns, InsecureSkipVerify, Subprotocols, CompressionMode),
Dial, DialOptions, Conn (Read, Write, Reader, Writer, Ping, Close, CloseNow, CloseRead, SetReadLimit, Subprotocol),
MessageType, StatusCode (StatusNormalClosure, StatusGoingAway, StatusPolicyViolation, StatusInternalError),
CloseError, CloseStatus, NetConn, wsjson (Read, Write) -- with examples; the code of the examples (a chat with a hub,
a buffered channel per subscriber and dropping slow clients; an echo server with rate limiting) and example_test.go;
and the GitHub release notes. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about a WebSocket server or client in Go with this library: accepting a connection in an
http.Handler, the Origin check and cross-site WebSocket hijacking, reading and writing messages with a context, JSON
messages, ping and pong, close codes and close handshakes, read limits, concurrent writes, closing reads when a
connection only writes, broadcasting to many clients, slow subscribers, testing with httptest, and moving from
nhooyr.io/websocket to github.com/coder/websocket.

Do not call this for the WebSocket protocol itself (RFC 6455 -- the standards documentation), for the browser
WebSocket API, for gorilla/websocket, gobwas/ws or socket.io, or for other languages: their documentation is not here,
and the search will return excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release: "1.8", "1.7" or an exact version. Every excerpt comes back with
`versions`: each release whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("websocket.Accept", "AcceptOptions",
"OriginPatterns", "InsecureSkipVerify", "websocket.Dial", "Conn.Read", "Conn.Write", "wsjson.Write", "Ping",
"CloseRead", "SetReadLimit", "StatusNormalClosure", "StatusPolicyViolation", "CloseStatus", "MessageText",
"MessageBinary", "concurrent writes", "chat example", "subscriber", "NetConn", "CompressionMode"), not in the user's
own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question into the
terms of the documentation first, then search.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "з'єднання", "повідомлення", "код закриття", "рукостискання". Never call this set of documents "корпус" --
say "документація coder/websocket". Identifiers and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. coder/websocket 1.8.15 is the newest release; the import path changed from
nhooyr.io/websocket to github.com/coder/websocket in 1.8.12. Search without `version` first; every answer says which
import path and release it is for.
