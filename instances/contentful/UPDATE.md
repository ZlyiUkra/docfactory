# Оновлення корпусу contentful

Сайт береться таким, яким він є в день завантаження: contentful.com/developers/docs версій не має. README й файли
документації репозиторіїв беруться з закріплених комітів: джерело `<префікс>-repo` кожного репозиторію тримає в полі
`tags` коміт останнього тегу кожної мінорної. Релізи GitHub і реєстр npm беруться щоразу заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

**Сайт.** Переліку сторінок contentful.com не віддає (llms.txt і sitemap за перевіркою Vercel), тож читач `mdcrawl`
обходить посилання між markdown-двійниками сторінок, починаючи з адрес поля `pages` джерела `contentful-site`. Нова
сторінка, на яку ще ніхто не посилається, обходом не знайдеться: її адресу (без «.md») дописують у `pages`. Стара
адреса, що тепер віддає заглушку «Page Not Found», нічого не ламає — заглушка документом не стає.

**Нова версія пакета.** Новий патч наявної мінорної — замінити в полі `tags` джерела `<префікс>-repo` коміт і версію
її рядка; нова мінорна — новий рядок нагорі `tags` (від найновішого). Коміт тегу дає
`https://api.github.com/repos/contentful/<репозиторій>/git/ref/tags/<тег>` (для анотованого тегу — ще один крок через
`git/tags/<sha>`) або `git ls-remote --tags https://github.com/contentful/<репозиторій>` (рядок `^{}` — коміт
анотованого тегу). Імена тегів різні: `vX.Y.Z` у більшості репозиторіїв, `@contentful/rich-text-types@X.Y.Z` у
rich-text, `@contentful/live-preview@X.Y.Z` у live-preview, `@contentful/create-contentful-app@X.Y.Z` у
create-contentful-app, `mcp-server@X.Y.Z` у contentful-mcp-server.

```
./df contentful check                 # чи змінилося щось нагорі за джерелом
./df contentful refresh               # повне перезавантаження, близько 30 хвилин
./df contentful manifest
./df contentful vectors
./df contentful smoke
# Ctrl+C у терміналі з serve, і знову: ./df contentful serve
```

Якщо змінилося співвідношення завантажень ліній чи найновіша версія пакета в npm — у `prompts/search.txt` (абзац
«Which version to search first») і `prompts/agent.txt` замінити лінії й числа.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df contentful quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
