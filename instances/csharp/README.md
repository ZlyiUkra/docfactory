# csharp — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про мову C# — і лише про мову: ключові слова, оператори, інструкції,
шаблони, типи, перетворення, правила розв'язання перевантажень, повідомлення компілятора, що нового в кожній версії,
що каже стандарт і специфікація можливості, що зламав компілятор чергового випуску. Документація англійською, усі
стабільні версії мови: сторінки learn.microsoft.com/dotnet/csharp на день виходу кожної версії C# 7.0–14 і чинний
сайт; стандарт ECMA-334 усіх видань — 1–4 (PDF Ecma, C# 1.0 і 2.0), 5–7 (dotnet/csharpstandard, C# 5, 6, 7.0–7.3) і
чернетки комітету для C# 8–14; специфікація C# 6 від Microsoft; специфікації можливостей C# 6.0–14.0
(dotnet/csharplang); документація компілятора Roslyn і критичні зміни компілятора C# у .NET 5–10. Код спільний і лежить
у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

**Документація мови C# є лише в цьому примірнику.** Примірник `dotnet` тримає платформу: .NET, бібліотеку базових
класів, довідник API, CLI `dotnet`, випуски; примірники `aspnetcore`, `entityframework`, `testcontainers-dotnet` —
свої фреймворки. Так сказано й в описі інструмента пошуку, який бачить модель: питання про `HttpClient` чи
`dotnet publish` сюди не йдуть.

## Навіщо окремий примірник

Мова живе довше за платформу й незалежно від неї: та сама C# 12 працює в .NET 8 і в Unity, стандарт ECMA-334 не знає
слова «.NET», а специфікації можливостей пишуть про компілятор, не про runtime. У примірнику `dotnet` сторінки C# були
однією з двадцяти тек серед 274 тисяч документів платформи, і видачу забирали WCF, WinForms і довідник API. Тут
довідник мови, стандарт і специфікації стоять поруч, нумерація версій — лише C#, а запит без версії відповідає для
C# 14.

Знімки сайту беруться в день виходу кожної версії мови, а не з тижневим відступом після випуску .NET, як у `dotnet`:
C# 7.0 (07.03.2017, Visual Studio 2017), 7.1 (14.08.2017), 7.2 (04.12.2017), 7.3 (07.05.2018), 8.0 (23.09.2019,
.NET Core 3.0), 9.0 (10.11.2020, .NET 5), 10 (08.11.2021), 11 (08.11.2022), 12 (14.11.2023), 13 (12.11.2024),
14 (11.11.2025, .NET 10). Репозиторій dotnet/docs веде теку `docs/csharp/` з липня 2016, тож C# 6 має лише
специфікацію Microsoft і 6-те видання стандарту, а 1.0 і 2.0 — лише видання ECMA.

словами — змістові, не від браку даних: цілі в корпусі є, і запити назвами знаходять їх усі; видачу розбавляють
розділи «See also» та дрібні підрозділи специфікацій (однакові «Summary», «Motivation», «Drawbacks» у кожній).
`smoke` — усі перевірки пройдено. Сервер перечитує `config.json` на старті, тож `serve` треба перезапустити.

Чого немає. Решти сайту learn.microsoft.com/dotnet (ядро .NET, довідник API, F#, Visual Basic, .NET Framework): це
примірник `dotnet`. Нотаток засідань команди мови (`meetings/` у dotnet/csharplang, понад тисячу файлів з 2016 року):
шум у видачі переважив би користь. Пропозицій, що не вийшли (`proposals/inactive`, `rejected`, `discriminated-unions`,
корінь `proposals/`), і прев'ю C# 15 (`proposals/csharp-15.0`, сторінка `whats-new/csharp-15.md`): лише стабільні
версії. Критичних змін компіляторів Visual Basic і Razor: це не C#. 33 сторінки знімка 7.0 і одна знімка 8.0 — порожні
заглушки того часу (`generics.md`, `interfaces.md`, how-to LINQ, `whats-new/index.md`): тіло нульової довжини, читач
їх не бере.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується (46 джерел), і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, родини джерел, профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише для
  завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df csharp <крок>`.

Нових читачів не додавалося; читач `pdf` дістав два поля, без яких усе лишається, як було: `headings: "markdown"`
(для примірника з `sections: "markdown"`: нумерований заголовок стає заголовком markdown, а номер глави з крапкою —
«1. Scope» у старих виданнях — теж заголовок) і `line_numbers: true` (PDF 1-го видання друкує на полі номер кожного
рядка, і pypdf приклеює його до кінця рядка — «8.6 Statements7»; номери на сторінці йдуть підряд від 1, тож знімається
лише число, що дорівнює наступному очікуваному, а «is 1» у тексті лишається). Розриви й злипання слів у тексті PDF
(«inter change», «namedWriteLocations») — з самих файлів, читач їх не лагодить.

Знімки сайту обмежено текою `docs/csharp/` виразом `exclude` з негативним випередженням (`^docs/(?!csharp/)`):
читач `docfx` читає шапки лише цих сторінок, тож `xref` на статтю поза текою лишається ім'ям `uid`, а посилання на
тип API розгортається, як і раніше, без шапок. Сховище сирого засіяно з голого клону dotnet/docs: усі текстові файли
кожного з 12 комітів (237 тисяч записів, 1,5 ГБ), бо вставки й приклади коду читач бере з будь-якого місця набору.

## Версії

Нумерація — лише C#, у кожному шарі: сторінки сайту несуть версію мови на день знімка (`7.0`, `7.1`, `7.2`, `7.3`,
`8.0` … `14.0`; чинна `main` — `14.0`), видання стандарту — версію мови, яку описують (`1.0` — видання 1 і 2, `2.0` —
3 і 4, `5.0`, `6.0`, `7.3` — 7-ме видання вкриває C# 7.0–7.3, чернетки `8.0`–`14.0`), специфікації можливостей —
свою версію, критичні зміни компілятора — версію C#, що вийшла з тим .NET (`9.0` = .NET 5 … `14.0` = .NET 10).
Документація Roslyn версії не має. Глибина лінії версії — 2 (`version_line_depth`): `"7.3"` — окрема лінія, `"7"` бере
всі 7.x, `"12"` чи `"12.0"` — увесь C# 12 в усіх шарах; текст, що не мінявся між версіями, несе їх усі. Без названої
версії промпт велить відповідати для C# 14 і казати це.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/csharp-corpus-2026-10-22.tar.gz` (18 933 тексти, паспорт і сховище
сирого `raw/`; перед видаленням текстів перелік і розміри файлів звірено з диском). В історії git текстів немає ніде.
Копія архіву — `C:\Distr\csharp-corpus-2026-10-22.tar.gz` (звірена за SHA-256; опис — у
`C:\Distr\docfactory-corpus-archives.txt`). Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/csharp/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/csharp-corpus-РРРР-ММ-ДД.tar.gz -C instances/csharp corpus raw
find instances/csharp/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/csharp/raw
gzip -9 -c instances/csharp/index/passages.json > instances/csharp/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/csharp-corpus-2026-10-22.tar.gz -C instances/csharp
./df csharp smoke
```

**Що перестає працювати.** `check`, `refresh`, `build` і `manifest` читають файли, і без текстів їм нема з чим
працювати. Дві перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/csharp/index/passages.json.gz`,
далі `./df csharp vectors` заллє колекцію Qdrant (півтори хвилини на відеокарті, близько двох годин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df csharp …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df csharp sources --why                 # перелік джерел і білий список
./df csharp build site-7-0 … site-main    # знімки сайту зі сховища сирого, без мережі, пів хвилини
./df csharp refresh <решта джерел>        # GitHub і PDF мережею, близько 6 хвилин
./df csharp manifest                      # паспорт
./df csharp setup                         # Qdrant чи пошук лише по словах
./df csharp vectors                       # залити корпус у docs-csharp
./df csharp smoke                         # перевірки
```

Знімки сайту не беруть мережею (`refresh site-*`): на кожну з ~1 500 сторінок знімка читач робив би звернення з
паузою, хоч усі тексти лежать у сховищі; для них — `build`. Коли сховище треба засіяти наново (новий знімок):
`git clone --bare https://github.com/dotnet/docs.git` і
`.venvs/gpu/bin/python tools/seed_git_store.py --instance csharp --clone dotnet/docs=<шлях до клону>`.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df csharp serve          # порт 8878
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8878/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user csharp-docs http://127.0.0.1:8878/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `csharp-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
