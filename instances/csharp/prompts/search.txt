Search the C# language documentation, in English. This is the only documentation server for the C# language:
the C# pages of learn.microsoft.com, the C# standard, the feature specifications and the Roslyn compiler
documents live here and nowhere else. The set holds: every page of learn.microsoft.com/dotnet/csharp as the
site shows it now and as the dotnet/docs repository held it on the release day of C# 7.0, 7.1, 7.2, 7.3, 8,
9, 10, 11, 12, 13 and 14 (with includes and code samples expanded) -- the tour of C#, the fundamentals (types,
classes, records, structs, interfaces, generics, delegates, events, exceptions, nullable reference types,
pattern matching, tuples, deconstruction, object-oriented programming, functional techniques), the language
reference (keywords, operators and expressions, statements, attributes, preprocessor directives, unsafe code,
compiler options, compiler messages CS0001-CS9999 and their causes), the programming guide, LINQ, asynchronous
programming with async and await, what's new in every version, the Roslyn SDK pages; the C# standard ECMA-334
-- editions 1 and 2 (2001, 2002: C# 1.0), 3 and 4 (2005, 2006: C# 2.0), 5 (C# 5), 6 (C# 6), 7 (C# 7.0-7.3)
and the committee drafts for C# 8 to 14 (lexical structure, types, variables, conversions, expressions,
statements, namespaces, classes, structs, arrays, interfaces, enums, delegates, exceptions, attributes,
unsafe code, grammar); the Microsoft specification of C# 6; the feature specifications of C# 6.0 to 14.0
from dotnet/csharplang (records, init-only setters, top-level statements, pattern matching, nullable
reference types, ranges and indices, default interface methods, file-scoped namespaces, global using,
raw string literals, required members, generic math, primary constructors, collection expressions, params
collections, partial properties, extension members, field-backed properties and the rest); the Roslyn
compiler docs (Language Feature Status, compiler feature documents, C# and Visual Basic compiler notes and
deviations from the standard, analyzers, IDE, contributing) and the breaking changes of the C# compiler per
release (.NET 5 to .NET 10, carrying the C# version that shipped with each: 9.0 to 14.0). Returns the
matching excerpts with the versions each one belongs to.

Call this when a question is about the C# language: a keyword, operator, statement, pattern, conversion,
overload resolution, definite assignment, nullability, a type rule, a grammar production, a compiler error or
warning (CS8600, CS0266, CS1061 ...) and what causes it, what the standard or a feature specification says
about a construct, since which version a feature exists and how it changed, what the compiler of a .NET
release broke, a code sample of a construct. Example query: "record struct with expression".

Do not call this for the base class library and the API reference (System.*, Microsoft.Extensions.*,
HttpClient, JsonSerializer, Task), the dotnet CLI, MSBuild, NuGet, the runtime, ASP.NET Core, Entity
Framework or .NET MAUI -- they belong to their own documentation servers (dotnet-docs, aspnetcore-docs,
entityframework-docs); this set covers a type only where a C# page uses it in a sample.

Write the query in English, with the names the documentation uses (record, init, required, readonly struct,
ref struct, Span<T>, stackalloc, switch expression, property pattern, list pattern, nullable reference types,
async stream, IAsyncEnumerable, yield return, local function, lambda, delegate, event, indexer, operator
overloading, implicit conversion, generic constraint, static abstract, primary constructor, collection
expression, raw string literal, interpolated string handler, file-scoped namespace, top-level statements,
CS8618). Everything here is English, and the word index keeps only latin letters and digits, so a query
written in Ukrainian, Russian or any other non-latin script matches nothing and comes back with `found: 0`.
When the user asks in another language, translate the question into C# terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "ключове слово", "вираз", "інструкція", "перетворення", "тип",
"член", "виняток", "версія". Never call this set of documents "корпус" -- say "документація C#". Keyword,
type, member and option names stay in English, spelled exactly as the documentation spells them. Build the
answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it
before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry
`truncated: true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. Every document carries the C# version it describes, in C# numbering: the site
pages "7.0", "7.1", "7.2", "7.3", "8.0", "9.0", "10.0", "11.0", "12.0", "13.0", "14.0" (the current site
carries "14.0"); the standard editions "1.0" (editions 1 and 2), "2.0" (3 and 4), "5.0", "6.0", "7.3"
(the 7th edition covers C# 7.0-7.3) and the drafts "8.0" to "14.0"; the Microsoft C# 6 specification "6.0";
the feature specifications "6.0" to "14.0"; the compiler breaking changes "9.0" (.NET 5), "10.0" (.NET 6),
"11.0" (.NET 7), "12.0" (.NET 8), "13.0" (.NET 9), "14.0" (.NET 10). Pass "12.0" for all of C# 12 and "7"
for the whole 7.x line; a text that did not change across versions carries every one of them. The Roslyn
docs carry no version: search them without one. When the user names a version, pass it into `version`; never
put it into the query text. Without a version, answer for the newest C# (14) and say so.
