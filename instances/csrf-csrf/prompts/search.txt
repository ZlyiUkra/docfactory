Search the csrf-csrf documentation -- the npm package `csrf-csrf` (stateless CSRF protection for Express by the signed
Double Submit Cookie pattern: the token is an HMAC of the session identifier and a random value, one copy goes into a
cookie, the other comes back in a header or the body; repository Psifi-Solutions/csrf-csrf). The package has no
documentation site: its README is the documentation, and the corpus holds the README of every stable version from
1.0.0 to 4.0.3 (background, getting started with doubleCsrf, sessions, asynchronous use, the configuration --
`getSecret`, `getSessionIdentifier`, `cookieName`, `cookieOptions`, `messageDelimiter`, `csrfTokenDelimiter`,
`getCsrfTokenFromRequest`, `hmacAlgorithm`, `ignoredMethods`, `size`, `errorConfig`, `skipCsrfProtection` -- and the
utilities `doubleCsrfProtection`, `generateCsrfToken`, `invalidCsrfTokenError`, `validateRequest`); the README of the
main branch, newer than 4.0.3, with the configuration examples corrected; the FAQ (what a CSRF attack is, whether CSRF
protection and this package are needed, unauthenticated routes such as login, httpOnly, choosing the secret, why the
token must not be read from the cookie, troubleshooting "ForbiddenError: invalid csrf token"); UPGRADING.md, the guide
from 3.x to 4.x; the changelog of every version from 3.0.0 to 4.0.3; the examples of the repository -- `complete`
(Express, cookie-parser, an HTML form) and `react` (an Express backend in TypeScript with express-session, helmet and
cors, and a React client with React Query that fetches the token and sends it with every request); and the npm
registry history (date of every version, dist-tags, dependencies, the Node.js requirement). Returns the matching
excerpts with the versions each one belongs to.

Call this when a question is about csrf-csrf as it describes itself -- how to set up `doubleCsrf`, what each option
does and its default (the cookie `__Host-psifi.x-csrf-token`, `ignoredMethods` GET, HEAD and OPTIONS, `size` 32,
`hmacAlgorithm` sha256), how a client gets the token with `generateCsrfToken` and sends it back in the
`x-csrf-token` header, how the session identifier binds the token to a session, what to do without sessions, how to
protect only some routes or skip the check, how to handle `invalidCsrfTokenError` -- and above all history and
compatibility: since which version an option or a function exists, what changed between versions (generateToken
became generateCsrfToken, getTokenFromRequest became getCsrfTokenFromRequest, getSessionIdentifier became required,
`signed` was removed in 4.0.0), and when every version came out.

or cors, for NestJS, nor for CSRF theory in general beyond what the FAQ says: their documentation is not here -- the
README and the examples only show how csrf-csrf is wired into them -- and the search will return excerpts that merely
mention them, with confident-looking titles.

`version` narrows the search to one release line. The package is numbered 1.x to 4.x (30 stable versions, 1.0.0 to
4.0.3): a line of one number keeps every document of that major ("4" keeps 4.0.0 to 4.0.3, "3" keeps 3.0.0 to
3.2.2), two numbers keep a minor ("3.2"), three an exact version ("3.2.2"). Leave `version` empty to search
everything, including text that carries no version. Every excerpt comes back with `versions`: each version whose
documents contain this exact text, newest first -- a README that stayed the same across versions is returned once,
with all of them listed, so the list itself shows from which to which version the documentation said exactly this.
