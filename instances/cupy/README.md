# cupy — примірник фабрики docfactory

Цей примірник зібрав документацію бібліотеки CuPy і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. CuPy — це бібліотека масивів для Python, яка повторює інтерфейс NumPy, але рахує на відеокарті. Масив `cupy.ndarray` лежить
у пам'яті відеокарти, а функції з тими самими назвами, що в NumPy (`cupy.sum`, `cupy.dot` тощо), виконуються там само. Дані між
пам'яттю комп'ютера і пам'яттю відеокарти треба переносити явно, і саме це перенесення найчастіше робить код повільним. Коли
готових функцій не вистачає, CuPy дає написати власне ядро — маленьку програму, яку відеокарта виконує паралельно для кожного
елемента масиву.

## Скільки цього

Усього 5193 документи і 8561 фрагмент. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Одна сторінка, що
змінювалася між версіями, лежить кількома документами, а однакові розділи пошук зливає й показує з переліком версій.

| Що | Версії | Документів |
|---|---|---|
| сайт docs.cupy.dev: посібник користувача, навчальні сторінки, встановлення, перехід між версіями, довідник кожної функції `cupy`, `cupyx`, `cupyx.scipy` і `cupy.cuda` | останній випуск кожного мажора: 14.2.0, 13.6.0, 12.3.0, 11.6.0, 10.6.0, 9.6.0, 8.6.0, 7.8.0, 6.7.0, 5.4.0, 4.5.0, 2.5.0, 1.0.3 | 5069 |
| нотатки релізів GitHub | усі стабільні теги 1.0.0–14.2.0 | 87 |
| записи PyPI | усі мажорні лінії та опис пакета | 37 |

Мітка версії має вигляд `cupy-14`. Префікс потрібен, щоб версії CuPy не збігалися з версіями інших бібліотек, коли сервери працюють
разом.

**Де є прогалини, хоч ми й брали всі мажори.**

- Сайт не публікує теки версії 3: адреси `v3.x.x` відповідають «404». Про CuPy 3 є лише нотатки релізів.
- Близько 440 сторінок довідника мають лише заголовок і підпис функції, без жодного пояснення. Здебільшого це обгортки над
  функціями CUDA Runtime, наприклад `cupy.cuda.runtime.malloc(size_t size) → intptr_t`. Такий текст коротший за звичайну межу
  в 200 символів, і читач відкинув би його як порожню сторінку. Проте підпис каже, що функція є і які аргументи вона бере, тому для
  джерела `cupy-docs` межу знижено до 30 символів (поле `min_chars`). Відкинуто лише дві сторінки навігації, на яких немає нічого,
  крім посилань.

Замір `quality` на 09.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 7 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df cupy <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт документації | `docs.cupy.dev/en/v*/` | `sphinx-html` |
| нотатки релізів | релізи GitHub `cupy/cupy` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/cupy/json` | `pypi-versions` |

**Чому обхід сайту довгий.** Сайт розміщено на Read the Docs. Коли програма звертається до нього частіше ніж раз на секунду, сайт
відповідає «429 Too Many Requests» і на якийсь час перестає віддавати сторінки. Тому в `config.json` стоїть `pause_sec: 1.0`: між
двома зверненнями програма чекає секунду. З такою паузою обхід усіх 13 версій, а це близько 9400 сторінок, триває приблизно 4 години.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df cupy serve
```

Порт — `8962`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user cupy-docs http://127.0.0.1:8962/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `cupy-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/cupy-corpus-2026-11-09-signatures.tar.gz` (5193 тексти, паспорт і сховище сирого `raw/`; перед
видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows `C:\Distr\cupy-corpus-2026-11-09-signatures.tar.gz`
(звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/cupy/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/cupy-corpus-РРРР-ММ-ДД.tar.gz -C instances/cupy corpus raw
find instances/cupy/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/cupy/raw
gzip -9 -c instances/cupy/index/passages.json > instances/cupy/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/cupy-corpus-2026-11-09-signatures.tar.gz -C instances/cupy
./df cupy smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
