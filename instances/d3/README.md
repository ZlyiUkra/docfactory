# d3 — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про D3 — бібліотеку візуалізації даних (виділення й приєднання даних,
переходи, шкали, осі, фігури, ієрархії, сили, географічні проєкції, масиви й статистика, кольори й інтерполятори,
формати, час, завантаження даних, масштабування, перетягування, пензель, хорди, контури, Делоне й Вороний).
Документація — на кожен стабільний реліз d3 і кожного його модуля, від D3 3.x до 7.9. Джерела — репозиторії d3/d3,
d3/d3-3.x-api-reference і 42 репозиторії модулів організації d3, пакети й реєстр npm, зошити Observable команди D3;
лише англійською. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі
дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

D3 двічі міняв саме устроєння API. D3 4.0 (2016) розібрав бібліотеку на три десятки модулів (`d3-scale`,
`d3-selection`…) і перейменував майже все: `d3.scale.linear` став `d3.scaleLinear`, `d3.svg.axis` — `d3.axisBottom`,
`d3.layout.force` — `d3.forceSimulation`. D3 5 перейшов на проміси (`d3.csv` повертає Promise), D3 6 передає подію
слухачеві аргументом замість `d3.event`, D3 7 — лише модулі ES. Довідник жив у різних місцях: у 3.x — вікі репозиторію
d3/d3, у 4.0–7.8 — README кожного модуля, з 2023 року — сайт d3js.org. Код D3 3 досі трапляється в старих прикладах
(2 % завантажень), тож відповідь мусить знати, до якої версії вона.

**Що є що.** **Виділення** (selection) — набір елементів DOM, до яких застосовують атрибути й дані; **приєднання**
(join) — зіставлення масиву даних з елементами: що додати (enter), що оновити (update), що прибрати (exit); **шкала**
(scale) — функція з області даних у видиму величину (пікселі, колір); **зошит Observable** — сторінка
observablehq.com з комірок тексту й коду, де D3 тримає галерею прикладів.

## Звідки документація

- **Сайт d3js.org** (VitePress) живе в теці `docs/` репозиторію d3/d3 з червня 2023 року, тегів не має: читач
  `ghsite-dated-vue` бере знімок на мить перед кожним наступним релізом d3 (7.8.5 і 7.9.0). Розбір розмітки той самий,
  що й для vuejs.org: контейнери `:::tip`, блоки `<script setup>` і живі графіки (`<PlotRender>`, `<ColorRamp>`)
  знімаються, якорі `{#scaleLinear}` теж.
- **README модулів.** До появи сайту довідником D3 був README кожного модуля, тож `npm-readme` бере його з тегу
  кожної стабільної версії. Модулі мають власну нумерацію, і версії їхніх документів несуть ім'я модуля префіксом
  (`d3-scale-4.0.2`, `d3-array-3.2.4`), інакше фільтр «3» змішав би їх із D3 3. Сюди ж — чотири модулі, вилучені з
  пакета d3 (`d3-collection`, `d3-queue`, `d3-request`, `d3-voronoi`), і вісім модулів поза пакетом
  (`d3-geo-projection`, `d3-sankey`, `d3-hexbin`, `d3-tile`, `d3-geo-polygon`, `d3-selection-multi`, `d3-require`,
  `d3-hsv`).
- **Довідник 3.x.** Вікі d3/d3 GitHub вимкнено; її сторінки перенесено в репозиторій d3/d3-3.x-api-reference, звідки
  їх бере `ghdocs`. Сторінки вікі без заголовка «# …», тож назва документа — ім'я файла (`SVG-Axes.md`).
- **Зошити Observable** — новий читач `observable-collections` (`engine/readers/observable.py`): перелік збірок
  `@d3`, зошити кожної збірки й кілька зошитів поза збірками, на які посилається d3js.org (поле `notebooks`). Текст
  комірок лишається markdown, код стає огорожею ```js. Зошит без версії, а рядок «Collections:» називає збірки, куди
  він входить.

## Родина D3: піднімати разом

Цей примірник — частина родини D3: сама бібліотека D3 і Observable Plot, бібліотека графіків тієї ж команди,
побудована на D3. Plot бере в D3 шкали, фігури, проєкції й формати, тож питання про графік Plot часто закінчується в
модулі D3 — і навпаки. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує обидва
сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `d3` | `d3-docs` | 8933 | D3 3.x–7.9: d3js.org, довідник 3.x, README 42 модулів на кожну версію, зошити Observable команди D3 |
| `observable-plot` | `observable-plot-docs` | 8934 | Observable Plot 0.1–0.6.17: сайт Plot з тегу кожного релізу 0.6, README, журнали, зошити про Plot |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
кореневому README.md, розділ «Родини примірників».

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/d3-corpus-2026-10-29.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\d3-corpus-2026-10-29.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів немає
ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/d3/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/d3-corpus-РРРР-ММ-ДД.tar.gz -C instances/d3 corpus raw
find instances/d3/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/d3/raw
gzip -9 -c instances/d3/index/passages.json > instances/d3/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/d3-corpus-2026-10-29.tar.gz -C instances/d3
./df d3 smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/d3/index/passages.json.gz`, далі
`./df d3 vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df d3 …` бере спільне середовище з кореня репозиторію (`.venvs/cpu` або
`.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/d3/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df d3 sources --why                   # перелік джерел і білий список
./df d3 refresh                         # усе незакріплене: близько 20 хвилин мережею (паузи 0,1 с)
./df d3 refresh api-reference-3x changes   # закріплені джерела — лише названими
./df d3 manifest                        # оновити паспорт
./df d3 setup                           # Qdrant чи пошук лише по словах
./df d3 vectors                         # залити корпус у docs-d3
./df d3 smoke                           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df d3 serve              # порт 8933
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8933/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user d3-docs http://127.0.0.1:8933/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `d3-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
