Search the D3 documentation and return the matching excerpts with the versions each one belongs to. What is
here: d3js.org (repository d3/d3, folder docs) at every stable release of d3 since 7.8.5 -- every module page:
selections and joins, transitions, scales, axes, shapes (lines, areas, arcs, pies, stacks, curves, links,
symbols), hierarchies (tree, cluster, treemap, pack, partition, stratify), forces, geographic projections and
paths, arrays (group, rollup, bin, bisect, ticks, statistics), colors and interpolators, formats, time intervals
and time formats, DSV and fetch, zoom, drag, brush, chords, contours, Delaunay and Voronoi, quadtrees, random,
dispatch, timers; the D3 3.x API reference (the former wiki: d3.layout, d3.svg, d3.scale.linear and the rest of
the 3.x API, and "Upgrading to 3.0"); the README of every stable version of d3 and of each module -- before 2023
the README of a module was its whole API reference, so these carry the reference of d3 4.0 to 7.8 --
including the modules removed from d3 (d3-collection, d3-queue, d3-request, d3-voronoi) and the modules outside
the d3 bundle (d3-geo-projection, d3-sankey, d3-hexbin, d3-tile, d3-geo-polygon, d3-selection-multi,
d3-require, d3-hsv); API.md of every d3 release since 4.0 (the index of the whole API) and CHANGES.md (what
changed in 4.0, 5.0, 6.0 and 7.0); the GitHub release notes and the npm registry history (versions, dates,
dependencies) of all these packages; the Observable notebooks of the D3 team, without a version -- the gallery
of charts, Learn D3, Let's Make a Bar Chart and the examples of every module, with their full code.

Call this when a question is about D3: d3.select and selectAll, selection.join, data, enter and exit, attr and
style, transitions and easing, scales (scaleLinear, scaleTime, scaleBand, scaleOrdinal, scaleSequential and
the rest), axes, d3.line, d3.area, d3.arc, d3.pie, d3.stack, curves, d3.hierarchy and its layouts,
d3.forceSimulation, d3.geoPath and projections, d3.group and d3.rollup, d3.bin, d3.extent, d3.format,
d3.timeFormat, d3.csv and d3.json, d3.zoom, d3.drag, d3.brush, d3.Delaunay, d3.contours, color schemes; the
3.x API (d3.layout.force, d3.svg.axis, d3.scale.linear); migrating between major versions (3 to 4 renamed most
of the API, 5 moved to promises, 6 passed the event to listeners, 7 became ES modules only) -- and history: since
which version a function exists, what changed in a release, how to migrate.

Do not call this for Observable Plot, Vega, Chart.js, ECharts or other charting libraries, for React, Vue,
Svelte or other frameworks that render D3 charts, for SVG, Canvas or CSS themselves, for TopoJSON or for
JavaScript language questions: their documentation is not here, and the search will return D3 excerpts that
merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "7.9" keeps every 7.9.x document of d3, "7" every 7.x, "3.5"
the last D3 3 line; leave it empty to search everything. The modules carry their own numbering with the module
name as a prefix, so they never mix with d3: "d3-scale-4", "d3-array-3.2", "d3-sankey-0.12". Every excerpt
comes back with `versions`: each version whose documents contain this exact text, newest first, so the list
itself shows from which to which version the documentation said exactly this.

Write the query in English, with the names D3 itself uses ("scaleBand", "selection.join", "forceManyBody",
"geoAlbersUsa", "d3.svg.line"), not in the user's own words. Everything here is English -- the excerpts, the
word index and the meaning index alike -- and the word index keeps only latin letters and digits, so a query
written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with
`found: 0`. When the user asks in another language, translate the question into D3 terms first, then search.

Answer in the language the user wrote in. When the question is about a function's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it
rests on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write
as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word
wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of
documents "корпус" -- say "документація D3". Identifiers, option names and titles stay in English, spelled
exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out of
memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated:
true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. D3 7 carries about 95% of the weekly downloads, D3 3 about 2%, D3 5 about 2%.
Search with `version` "7.9" for a question about how to do something. If the user names a version or writes
D3 3 code (d3.scale.linear, d3.svg.axis, d3.layout), search "3.5"; for D3 4 to 6 code search that line. Search
without `version` when the question is about a module's own release (its versions carry a prefix), about an
example or a chart type (the notebooks have no version), or when the line gave nothing. Every answer says which
version it is for; when the user did not name one, answer for D3 7.9 and say so. When the excerpts behind a
statement come only from older versions, name those versions instead of presenting the text as current.
