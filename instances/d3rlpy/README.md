# d3rlpy — примірник фабрики docfactory

Цей примірник зібрав документацію d3rlpy і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті.

d3rlpy — бібліотека для Python на PyTorch для навчання з підкріпленням на записаній історії (offline reinforcement learning).
Звичайний агент учиться, пробуючи дії в середовищі. Тут середовища під час навчання немає: є лише набір уже записаних переходів,
тобто спостережень, дій, винагород і позначок кінця епізоду. Агент мусить вивести з них добру політику, не маючи змоги перевірити
дію, якої в записах не було. Тому алгоритми цієї бібліотеки (CQL, IQL, TD3+BC та інші) навмисно обережні з діями, яких у даних
мало. Так описується навчання на історичних котируваннях: ринок не можна «переграти» з іншою дією.

Набір даних збирають у `MDPDataset` або `ReplayBuffer`. Алгоритм створюють із його налаштувань, наприклад
`CQLConfig().create(device="cuda:0")`, і навчають методом `fit`. Навчену політику оцінюють без середовища класом `FQE`, зберігають
і вивантажують у TorchScript чи ONNX методом `save_policy`. Метод `fit_online` дозволяє довчити агента вже в живому середовищі.

## Скільки цього

Усього 1 036 документів і 4 317 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Сторінка з
однаковим текстом у кількох лініях лежить одним документом із переліком цих ліній.

| Що | Версії | Документів |
|---|---|---|
| сайт d3rlpy.readthedocs.io: встановлення, перші кроки, підручники, довідник API зі сторінкою кожного алгоритму й класу, командний рядок, поради | останній патч кожної з 19 мінорних ліній 0.2–2.8 | 966 |
| нотатки релізів GitHub `takuseno/d3rlpy` | усі стабільні теги | 34 |
| записи PyPI пакета `d3rlpy` з README | усі стабільні версії | 36 |

Мітка версії — мінорна лінія: `2.8`, `1.1`, `0.9`.

**Про номери старих версій.** До 1.0 бібліотека нумерувала випуски двома числами: `0.90` і `0.91` — це лінія 0.9, `0.22` і `0.23` —
лінія 0.2. Сайт узято з останнього випуску кожної лінії: `v0.91`, `v0.80`, `v0.70`, `v0.61`, `v0.51`, `v0.41`, `v0.32`, `v0.23`.

**Де є прогалини.**

- Лінії 0.1 на сайті немає: про неї є лише запис PyPI.
- Версія 2.0 переписала API: налаштування з методом `create`, `ReplayBuffer` замість старого буфера, оцінювачі (`evaluators`)
  замість функцій `scorer`. Тому відповідь про API залежить від версії, і в запиті варто її називати.
- Сторінки `_modules/` (вихідний код, на який ведуть посилання «[source]») не взято: це код, а не документація.
- Зошити Jupyter із прикладами лежать у репозиторії бібліотеки, і в корпус вони не входять.

Замір `quality` на 12.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає
саме так. Запити своїми словами знаходять потрібне 8 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df d3rlpy <крок>`.

хвилини. Підсумок джерела читач друкує лише наприкінці обходу.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df d3rlpy serve
```

Порт — `8974`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user d3rlpy-docs http://127.0.0.1:8974/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `d3rlpy-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Родина «Навчання з підкріпленням»: піднімати разом

Цей примірник — частина родини «Навчання з підкріпленням»: теорія і три бібліотеки, якими її застосовують. Питання про те, чому
агент не вчиться, починається в документації алгоритму Stable-Baselines3, а закінчується в теорії або в описі середовища
Gymnasium. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує всі чотири сервери:
підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `reinforcement-learning` | `reinforcement-learning-docs` | 8971 | теорія: книжки, курси й статті про навчання з підкріпленням і бандитів, торгове середовище, навчання на записаній історії |
| `gymnasium` | `gymnasium-docs` | 8972 | Gymnasium 0.26–1.4: інтерфейс середовища, простори, обгортки, векторні середовища |
| `d3rlpy` | `d3rlpy-docs` | 8974 | Stable-Baselines3 0.11–2.9, sb3-contrib і RL Zoo: готові алгоритми, колбеки, векторні середовища |
| `d3rlpy` | `d3rlpy-docs` | 8974 | d3rlpy 0.2–2.8: навчання на записаній історії без живого середовища (CQL, IQL, Decision Transformer) |

Усі чотири одним терміналом:

```
cd ~/Projects/docfactory && tools/up.sh reinforcement-learning gymnasium d3rlpy d3rlpy
```

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
кореневому README.md, розділ «Родини примірників».

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/d3rlpy-corpus-2026-11-12.tar.gz` (1 036 текстів, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\d3rlpy-corpus-2026-11-12.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/d3rlpy/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/d3rlpy-corpus-РРРР-ММ-ДД.tar.gz -C instances/d3rlpy corpus raw
find instances/d3rlpy/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/d3rlpy/raw
gzip -9 -c instances/d3rlpy/index/passages.json > instances/d3rlpy/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/d3rlpy-corpus-2026-11-12.tar.gz -C instances/d3rlpy
./df d3rlpy smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
