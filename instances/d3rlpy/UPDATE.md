# Оновлення корпусу d3rlpy

Корпус живе нагорі: сайт d3rlpy.readthedocs.io, релізи GitHub `takuseno/d3rlpy` і реєстр PyPI. Теки вже вийшлих версій
на сайті не змінюються, а нова лінія потребує правки `sources.json`.

Правило: **нічого не видаляється.** Ані `refresh`, ані `manifest` нічого не видаляють. Лише `vectors` прибирає точки своєї колекції,
чиїх фрагментів у корпусі вже немає.

**Спершу — повернути тексти.** Корпус примірника в архіві, а `check`, `refresh` і `manifest` читають файли. Тому перед роботою нижче
тексти розпаковують, а після неї виносять знову: обидві дії описано в
[README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df d3rlpy refresh <id джерела>   # лише те, що змінилося
./df d3rlpy manifest
./df d3rlpy vectors
./df d3rlpy smoke
# Ctrl+C у терміналі з serve, і знову: ./df d3rlpy serve
```

Що міняти, коли вийшов новий випуск:

- **Нова лінія чи новий патч (наприклад 2.9.0).** У поле `versions` джерела `docs` запишіть теку
  першою (`"v2.9.0"`), а в `version_labels` — що вона означає лінію (`"v2.9.0": "2.10"`). Новий патч наявної лінії замінює в обох
  полях попередній патч цієї лінії. Перед записом перевірте, що стартова сторінка теки відповідає «200».
- Релізи GitHub і PyPI підтягуються самі.

**Лише один процес.** Read the Docs відповідає «429», коли запитів забагато. Сайт оновлюють одним процесом `refresh` з паузою в
секунду (`pause_sec: 1.0`). Обхід звертається до кожної сторінки, навіть коли вона вже є в сховищі сирого, тому повне оновлення
сайту триває близько 45 хвилин; запускають його у фоні (`setsid nohup … &`). Сторінку, пропущену через збій мережі,
довантажує `./df d3rlpy refresh --missing <id джерела>`.

Якщо `smoke` скаржиться на число фрагментів, корпус підріс: нове число записують в `expected_passages`, а в `expected_note` — коли й
чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу треба виконати `./df d3rlpy quality --show`, переглянути запити зі знаком «-» і перевірити, чи
справді відповідь змінилася. Ціль розширюють лише тоді, коли знайдена сторінка справді відповідає на запит.
