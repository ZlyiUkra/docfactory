Search the documentation of d3rlpy, the Python library for offline deep reinforcement learning: it trains an agent from
a fixed dataset of recorded transitions (observations, actions, rewards, episode ends) without interacting with an
environment, and can also fine-tune online. The corpus holds the d3rlpy.readthedocs.io site at the last patch of every
minor line 0.2-2.8 (installation, getting started, the tutorials, the API reference with a page for every algorithm
and class, the command line, tips), the GitHub release notes and the PyPI records.

Use this tool for: building a dataset (`MDPDataset`, `ReplayBuffer`, `create_fifo_replay_buffer`, `terminals` against
`timeouts`), the algorithms and their configs (`CQLConfig`, `DiscreteCQLConfig`, `IQLConfig`, `TD3PlusBCConfig`,
`BCConfig`, `AWACConfig`, `DQNConfig`, `SACConfig`, `DecisionTransformerConfig`, `create(device=...)`), training with
`fit` (`n_steps`, `n_steps_per_epoch`, `evaluators`) and `fit_online`, evaluators and metrics (`TDErrorEvaluator`,
`EnvironmentEvaluator`, `InitialStateValueEstimationEvaluator`), off-policy evaluation (`FQE`, `DiscreteFQE`),
preprocessing (`StandardObservationScaler`, `MinMaxActionScaler`, reward scalers), Q-function and encoder factories,
`predict`, `save_model`, `load_learnable`, `save_policy` (TorchScript and ONNX), the `d3rlpy` command line, and what
changed between versions. Write the query in English, with the name of the class, function or parameter, such as
`CQLConfig conservative_weight` or `MDPDataset timeouts`. Give a version in the filter when the answer depends on it:
2.0 rewrote the API (configs with `create`, `ReplayBuffer`, evaluators instead of scorers).

Do not use it for the theory of offline reinforcement learning, for Gymnasium, Stable-Baselines3 or PyTorch: other
servers hold them. Returns the matching excerpts with the versions each one applies to, the source address and the
fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
