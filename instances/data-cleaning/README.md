# data-cleaning — примірник фабрики docfactory

Цей примірник зібрав документацію трьох бібліотек Python і віддає її через сервер MCP, щоб модель відповідала з їхніх текстів, а не з
пам'яті. Бібліотека pandas читає й об'єднує таблиці. Бібліотека openpyxl читає й пише файли Excel. Бібліотека RapidFuzz порівнює
рядки, які схожі, але не однакові, і так допомагає знаходити дублікати записів. Разом вони потрібні для однієї задачі: прочитати
кілька файлів Excel, очистити дані й знайти людей, записаних двічі.

## Скільки цього

Усього 18 093 документи і 31 198 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Одна сторінка, що
змінювалася між версіями, лежить кількома документами, а однакові розділи пошук зливає й показує з переліком версій.

| Що | Лінії | Документів |
|---|---|---|
| pandas: посібник, початок роботи, whatsnew із репозиторію | 34 мінорні лінії 0.4–3.1 | 1489 |
| pandas: довідник API із сайту | 7 ліній 1.5–3.1 | 14 656 |
| pandas: записи PyPI | усі стабільні версії | 29 |
| openpyxl: документація із сайту | 5 ліній 2.4–3.1 | 1743 |
| openpyxl: записи PyPI | усі стабільні версії | 29 |
| RapidFuzz: документація з репозиторію | 44 лінії 0.12–3.14 | 69 |
| RapidFuzz: сайт, поточна версія | 3.14 | 21 |
| RapidFuzz: записи PyPI | усі стабільні версії | 57 |

**Де є прогалини, хоч ми й брали всі лінії.** Деяких текстів уже ніде не публікують.

- Сайт pandas віддає лише лінії 1.5–3.1. Довідник API створюється з коду, тому для старіших ліній його тексту немає, є лише посібник.
- Для ліній pandas 0.1–0.3 у репозиторії немає тегів, тож про них є лише записи PyPI.
- Сайт openpyxl віддає лише лінії 2.4–3.1. Про лінії 1.1–2.3 є лише записи PyPI з README.
- Для 12 найстаріших ліній RapidFuzz немає тегів, тож про них є лише записи PyPI.

Замір `quality` на 03.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме так.
Запити своїми словами знаходять потрібне лише 3 із 10. Цей замір занижує результат: сторінки довідника API не мають підрозділів, тож вони не
можуть бути ціллю запиту, хоча часто й відповідають на нього. Проте довідник API і справді заглушує посібник на запитах без термінів.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить поруч і в
  git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df data-cleaning <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| тексти pandas | `doc/source` у тегах `pandas-dev/pandas` | `ghdocs-history` |
| довідник API pandas | `pandas.pydata.org/pandas-docs/version/*/reference/` | `sphinx-html` |
| документація openpyxl | `openpyxl.readthedocs.io/en/*/` | `sphinx-html` |
| тексти RapidFuzz | `docs` у тегах `rapidfuzz/RapidFuzz` | `ghdocs-history` |
| сайт RapidFuzz | `rapidfuzz.github.io/RapidFuzz/` | `html-pages` |
| записи всіх трьох | `pypi.org/pypi/*/json` | `pypi-versions` |

Читач `sphinx-html` отримав поле `min_chars`: сторінка атрибута в довіднику pandas має один рядок опису, і без цього поля вона вважалася порожньою.
Лишилося 615 сторінок, де опису зовсім немає, вони в корпус не входять.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df data-cleaning serve
```

Порт — `8949`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user data-cleaning-docs http://127.0.0.1:8949/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `data-cleaning-docs` з інструментами `search_docs` і `read_section`. Якщо сервер позначено як
недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів (`index/passages.json`) і колекції
Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/data-cleaning-corpus-2026-11-03.tar.gz` (18 093 тексти, паспорт і сховище сирого `raw/`; перед видаленням
текстів розпакований окремо й звірений із диском) і в копії на диску Windows `C:\Distr\data-cleaning-corpus-2026-11-03.tar.gz` (звірено за SHA-256). В
історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/data-cleaning/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/data-cleaning-corpus-РРРР-ММ-ДД.tar.gz -C instances/data-cleaning corpus raw
find instances/data-cleaning/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/data-cleaning/raw
gzip -9 -c instances/data-cleaning/index/passages.json > instances/data-cleaning/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів звірено з диском. Тоді
ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/data-cleaning-corpus-2026-11-03.tar.gz -C instances/data-cleaning
./df data-cleaning smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким потрібні тексти,
пропускаються («корпус в архіві»).
