# devops-core-course — примірник фабрики docfactory

Захищений MCP-сервер для вивчення курсу DevOps Engineering: Core Practices
([inno-devops-labs/DevOps-Core-Course](https://github.com/inno-devops-labs/DevOps-Core-Course)): один власний
вебсервіс за шістнадцять тижнів проходить шлях від контейнера й CI через Terraform, Ansible і спостережуваність до
Kubernetes, GitOps і поступової доставки. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`;
ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

План вивчення — у [LEARNING.md](LEARNING.md). Він є четвертим етапом лінії Linux → Docker → Kubernetes.

## Навіщо

Сервер — довідка під час лабораторних: «що вимагає завдання 4 лабораторної 13», «чому pull кращий за push», «навіщо
потрібен remote state», «чим canary відрізняється від blue-green», «що рахує критерій прийняття лабораторної 14».
Відповідь будується з уривків курсу, а кожен уривок має адресу файла.

Це **курс, а не довідник інструментів**. Параметри Kubernetes, Helm, Argo CD чи Prometheus шукають у їхніх власних
примірниках.

Промпт сервера вмикає й **режим наставника**: коли людина працює над лабораторною, він не видає готового маніфеста чи
ролі без прохання, а називає лабораторну, завдання й лекцію та ставить наступне запитання. Коли просять пояснити
механізм, пояснює повністю.

## Нагадування: що зібрати перед лабораторними

Цим інструментам курсу бракує власного примірника. Рішення таке: збирати кожен, коли дійде черга до його лабораторної,
а не наперед.

| Перед лабораторною | Зібрати примірник |
|--------------------|-------------------|
| 4 | Terraform і OpenTofu, Pulumi |
| 5–6 | Ansible |
| 7 | Grafana Alloy |
| 11 | OpenBao, External Secrets Operator |
| 14 | Argo Rollouts |
| 18 | Nix |

Те саме знає сервер: нагадування стоїть в описі інструмента (`prompts/search.txt`, `prompts/loaded.txt`), тож
наставник скаже про це сам, коли ти дійдеш до такої лабораторної. Коли примірник зібрано, його прибирають звідси
([UPDATE.md](UPDATE.md#коли-примірник-інструмента-зібрано)).

## Версії

Тегів у курсі немає, тому видання позначені номером за датою:

| Версія | Що це | Коміт |
|--------|-------|-------|
| `2026.7` | гілка `master` від 02.07.2026, інструменти закріплені на травень 2026 | `61c0e34` |
| `2026.4` | видання `s26` від 15.04.2026 | `f5c458b` |

Лекції двох видань нумеровані по-різному, тому однакова тема там лежить у різних розділах і не згортається в один.
Промпт велить передавати `version: "2026.7"`, а старше видання брати лише тоді, коли питають про нього чи про зміни.
Гілку `s25` не взято: там лише короткі лабораторні без лекцій.

## Що не входить

Документація самих інструментів. Частина її є в інших примірниках (`docker`, `github-actions`, `kubernetes`, `argocd`,
`loki`, `prometheus`, `grafana`, `cloudflare`). Terraform і OpenTofu, Pulumi, Ansible, OpenBao, External Secrets
Operator, Argo Rollouts, Grafana Alloy і Nix примірника поки не мають: їх збирають окремо, коли дійде черга до
відповідних лабораторних.

## Корпус лише локально

У репозиторії курсу **немає ліцензії**, тож читати текст можна, а перевидавати не можна. Тому **корпус та індекс у git
не потрапляють** (`corpus/` і `index/` у `.gitignore`), у git лежать лише налаштування примірника. З тієї ж причини
промпт велить переказувати своїми словами, цитувати коротко й давати адресу файла.

**Де тексти.** Корпус в архіві від самого початку: `~/archives/docfactory/devops-core-course-corpus-2026-11-02.tar.gz`
(82 тексти, паспорт і сховище сирого `raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і
копія на диску Windows `C:\Distr\devops-core-course-corpus-2026-11-02.tar.gz` (звірено за SHA-256). Сервер
підіймається з кешу фрагментів `index/passages.json` (лише на цій машині) і колекції Qdrant.

**Як повернути тексти** — перед оновленням корпусу:

```
tar -xzf ~/archives/docfactory/devops-core-course-corpus-2026-11-02.tar.gz -C instances/devops-core-course
./df devops-core-course smoke
```

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
tar -czf ~/archives/docfactory/devops-core-course-corpus-РРРР-ММ-ДД.tar.gz -C instances/devops-core-course corpus raw
find instances/devops-core-course/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/devops-core-course/raw
```

Тексти видаляють лише тоді, коли архів звірено з диском. Тоді ж видаляють попередній архів і виправляють назву в цьому
розділі. `check`, `refresh` і `manifest` без текстів працювати не можуть; `smoke` пропускає їхні перевірки з позначкою
«корпус в архіві». **На іншій машині** кешу немає: тексти повертають з архіву, далі `vectors`.

## Як запустити

```
./df devops-core-course serve
```

Порт `8943`, сервер `devops-core-course-docs`, адреса `http://127.0.0.1:8943/mcp`, інструменти `search_docs` і
`read_section`. Запис у клієнті MCP:

```
claude mcp add --transport http --scope user devops-core-course-docs http://127.0.0.1:8943/mcp
```

Приклад питання власному агенту фабрики:

```
./df devops-core-course ask "Why does pull beat push in GitOps?"
```
