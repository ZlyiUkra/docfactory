### Розділ 1. Проблема до DevOps: слайди 5–9

| Що написано в курсі | Що це означає |
|---------------------|---------------|
| Dev і Ops із протилежними цілями | Одних цінують за швидкість змін, інших за відсутність аварій. Конфлікт виникає через оцінювання праці, а не через поганих людей |
| Wall of Confusion | Образ «стіни нерозуміння»: розробники перекидають код адміністраторам, а провину за поломку отримують ті, хто його запускає |
| Manual Release Hell | Випуск буває рідко, його роблять вручну за списком кроків, часто на вихідних і без способу скасувати |
| blame culture | Після аварії спершу шукають винного. Тому люди ховають помилки, а організація нічого не вчить |
| postmortem | Письмовий розбір аварії: що сталося й що змінити. Слово blameless означає «без пошуку винного» |
| MTTR | Mean time to recovery, середній час до відновлення роботи після аварії |
| firefighting | Дослівно «гасіння пожеж»: команда весь час реагує на аварії й не встигає запобігати новим |

Числа на слайдах 7 і 9 ілюструють масштаб. Перед тим як посилатися на них деінде, перевір джерело: курс наводить їх
без посилань на конкретні сторінки.

### Розділ 2. Що таке DevOps: слайди 10–14

Слайд 11 розбиває хибні уявлення, а наша лекція докладно розглядає два з них. Далі йдуть дві моделі, які варто знати
за назвами, бо вони часто трапляються в статтях.

**Three Ways (слайд 12), три напрями роботи:**

- **Flow** означає швидкий рух зміни від розробки до реального середовища. Приклад: автоматичний конвеєр.
- **Feedback** означає швидкий рух інформації назад: метрики й сповіщення кажуть розробникам, що сталося.
- **Continual Learning** означає безпечне експериментування й розбір помилок.

**CAMS (слайд 13), чотири складові.** Абревіатура складається з Culture (культура), Automation (автоматизація),
Measurement (вимірювання) і Sharing (спільні знання). Варіант CALMS додає Lean, тобто усунення зайвої роботи.

Незнайомі слова в цих слайдах:

| Вираз | Що це означає |
|-------|---------------|
| trunk-based development | Усі часто вливають маленькі зміни в одну основну гілку замість довгоживучих гілок |
| error budget | Допустима кількість збоїв за період. Поки її не вичерпано, команда може ризикувати новими випусками |
| chaos engineering | Навмисні поломки в контрольованих умовах, щоб перевірити, чи система витримує збій |
| toil | Одноманітна ручна робота, яку можна автоматизувати |
| you build it, you run it | Хто написав сервіс, той і відповідає за його роботу, зокрема вночі |

### Розділ 3. Гра в технічного директора: слайди 15–19

Курс розігрує чотири аварії вигаданої компанії FlowStart. Наша лекція зводить їх в одну таблицю, а тут важливо
побачити деталі кожної.

**Сценарій 1, слайд 16: випуск без перевірок.** Хтось у п'ятницю ввечері відправив код без тестів, і вхід зламався на
чотири години. Ліки: зміни проходять тести й перегляд до злиття. Звідси лабораторна 3.

**Сценарій 2, слайд 17: неповторний сервер.** Сервер два роки налаштовувала вручну одна людина, а тепер вона
звільнилася. Тут з'являється вислів **pets vs. cattle**: «домашні улюбленці проти стада». Улюбленця лікують, а стадо
замінюють новими однаковими одиницями. Це аналогія, де улюбленець відповідає серверу з унікальними налаштуваннями, а
стадо — однаковим серверам, створеним за описом. Приклад коду мовою Terraform читати поки не потрібно, він повернеться
в лабораторній 4.

**Сценарій 3, слайд 18: пароль у коді.** Курс показує різницю між самим значенням секрету і посиланням на нього. Назви
gitleaks і trufflehog — це сканери, що шукають секрети в коді перед комітом. OpenBao — це відкрите відгалуження Vault,
яке побачиш у лабораторній 11.

**Сценарій 4, слайд 19: робота наосліп.** Тут вводиться **спостережуваність** (observability): здатність зрозуміти, що
відбувається всередині системи, за даними, які вона видає. Курс називає три види даних: журнали кажуть, що сталося,
метрики кажуть, скільки й наскільки швидко, а трасування каже, де саме в ланцюжку сервісів витрачено час.

### Завдання 1.1. Вибір фреймворку

**Що вимагає.** Вибрати один із трьох фреймворків і в `docs/LAB01.md` обґрунтувати вибір абзацом і таблицею. У таблиці
мають бути щонайменше обсяг залежностей, підтримка асинхронної роботи, автоматична документація API та складність
навчання.

**Незнайомі слова.** **Фреймворк** — це бібліотека, що бере на себе розбір HTTP-запитів і вибір обробника, як Express
у Node.js. **Асинхронна підтримка** означає, що під час очікування одного запиту процес може обробляти інші.
**OpenAPI** — це формат машиночитного опису API, а FastAPI будує його автоматично. Django курс сам називає надмірним
для цього завдання.

**Де спотикаються.** Зміна фреймворку посеред роботи коштує часу, тому вибери одразу. Для наступних лабораторних
важить лише те, чи зможеш ти пояснити свій вибір.

### Завдання 1.2. Шлях `/`

**Що вимагає.** Відповідь JSON із п'ятьма верхніми ключами: `service` (про сервіс і фреймворк), `system` (про машину),
`runtime` (час роботи й поточний час), `request` (про поточний запит), `endpoints` (перелік шляхів). Точний перелік
полів кожного ключа дивись у лабораторній, бо лабораторна 3 перевірятиме саме верхні ключі.

**Що знадобиться з Python:**

| Модуль | Для чого | Аналог, який ти вже знаєш |
|--------|----------|---------------------------|
| `platform` | Назва системи, архітектура, версія Python | `process.platform`, `process.arch` у Node.js |
| `socket` | Ім'я машини | `os.hostname()` у Node.js |
| `os` | Кількість процесорів і змінні оточення | `os.cpus()`, `process.env` |
| `datetime` | Поточний час і різниця часу | `Date` |

**Пастка з часом.** У Python значення часу буває з часовим поясом (aware) або без нього (naive). Відняти одне від
іншого не можна: Python видасть `TypeError`. У JavaScript такої помилки немає, бо `Date` завжди зберігає абсолютну
мить, тому ця пастка для тебе нова. Правило лабораторної: скрізь використовуй час із поясом UTC. Початок роботи
запам'ятовується один раз під час імпорту файла, а `uptime_seconds` рахується від нього.

**ISO 8601** — це стандартний текстовий запис дати й часу, наприклад `2026-05-28T12:30:00+00:00`.

**Доступ до запиту** залежить від фреймворку, і лабораторна наводить потрібні атрибути в підказках.

**Де спотикаються.** Якщо відповідь виглядає дивно, наприклад має префікс `b'...'`, ти повернув рядок чи байти замість
структури даних. Спершу зроби `/health`, а `/` нарощуй частинами.

**Неточність у курсі.** Лабораторна радить не повертати з Flask звичайний словник і вимагає `jsonify`. Це застаріла
порада: [документація Flask 3.1](https://flask.palletsprojects.com/en/stable/quickstart/#apis-with-json) каже, що
словник чи список автоматично стає відповіддю JSON. Обидва способи працюють.

### Завдання 1.3. Шлях `/health`

**Що вимагає.** Відповідь із трьома полями (стан, мітка часу, час роботи) і кодом 200. Без звернень до баз чи
зовнішніх сервісів. Причину пояснює наша лекція.

**Де спотикаються.** Лабораторна не називає значення поля `status`, але тест лабораторної 3 очікує точне значення
`"healthy"`. Постав його вже зараз.

### Завдання 1.4. Змінні оточення

**Що вимагає.** Читати адресу, порт і режим налагодження зі змінних оточення зі значеннями за замовчуванням, які
названо в лабораторній. Сервіс має запускатися без змін коду за всіма трьома командами з тексту завдання.

**Запис `PORT=8080 python app.py`** задає змінну лише для цієї однієї команди. Це можливість оболонки bash, а не
Python, тому так само можна запускати й програму на Node.js.

**Де спотикаються.** Порт із оточення є рядком, тому потрібне перетворення на число. Перетворення режиму налагодження
на логічне значення пояснює лекція. Лабораторна також попереджає: на macOS порт 5000 часто зайнятий службою AirPlay,
тому `curl` може отримати відповідь від неї, а не від твого сервісу.

### Завдання 1.5. Обробники помилок і журнал

**Що вимагає.** Помилки 404 і 500 мають повертати JSON, а не сторінку HTML. Журнал пишеться через стандартний модуль
`logging` на рівні INFO, з часом і рівнем у форматі. Функцію `print()` лабораторна забороняє.

**Незнайомі слова.** **Обробник помилки** (error handler) — це функція, яку фреймворк викликає замість звичайного
обробника, коли сталася помилка. **Рівень журналу** показує важливість запису: INFO означає звичайну подію, а ERROR
означає помилку.

**Де спотикаються.** Лабораторна правильно застерігає про код відповіді. [Документація
Flask](https://flask.palletsprojects.com/en/stable/errorhandling/) підтверджує: код відповіді не встановлюється сам за
кодом обробника, тому його треба вказати явно. Якщо цього не зробити, клієнт отримає 200 із текстом про помилку, а
проба в лабораторній 9 вважатиме сервіс здоровим.

Обробник 500 у режимі налагодження не спрацьовує: Flask покаже свій налагоджувач. Тому перевіряй цей обробник у
звичайному режимі.

### Завдання 1.6. Докази

**Доказом вважаються** такі речі у `docs/LAB01.md`:

- повна відповідь `/` зі справжнім іменем твоєї машини й часом роботи;
- відповідь `/health`;
- код 404 на неіснуючий шлях;
- відповідь сервісу, запущеного на іншому порту;
- таблиця порівняння фреймворків;
- два-три речення про найбільшу складність і її розв'язання.

**Незнайомі слова в командах доказів.** Програма `curl` надсилає HTTP-запит із командного рядка. Програма `jq` гарно
виводить JSON і вибирає поля з нього. Прапорець `-w "HTTP %{http_code}\n"` наказує `curl` вивести код відповіді. Самі
команди наведено в лабораторній, бо це готовий інструмент перевірки, а не частина відповіді.

### Завдання 2.1. README

**Що вимагає.** README сервісу з шістьма розділами: огляд, вимоги, встановлення, запуск, таблиця шляхів, таблиця
змінних оточення. Лабораторна просить більше команд і менше слів. Читачем цього файла буде людина, яка запускає сервіс
уперше, тому перевір свої команди в новому терміналі.

### Завдання 2.2. Порядок у коді

**Що вимагає.** Три речі: точне закріплення фреймворку в `requirements.txt`, файл `.gitignore` для кешів Python,
оточень і файлів редактора, а також згруповані імпорти за стилем PEP 8.

**Незнайомі слова.** **PEP 8** — це загальноприйнятий стиль коду Python, як правила Prettier і ESLint разом. **Exact
patch** означає, що вказано всі три числа версії. Каталог `__pycache__` містить скомпільовані файли Python, і в
репозиторії їм не місце.

### Бонус. Той самий сервіс компільованою мовою

**Що вимагає.** Ті самі два шляхи й той самий формат JSON мовою Go, Rust, Java чи C#. Лабораторна радить Go. Потрібні
також README і файл опису збірки, а звіт доповнюється порівнянням розміру.

**Навіщо.** Компільована мова дає один готовий двійковий файл, тому бонус лабораторної 2 зможе показати образ у
десятки разів менший.

**Незнайомі слова.** **Статичний двійковий файл** містить усе потрібне й не вимагає бібліотек системи. **Struct tags**
у Go, записи на кшталт `json:"hostname"`, задають назву поля в JSON. **Wire-compatible** означає, що відповідь
збігається формою, тому ті самі запити працюють проти обох сервісів.

**Доказ.** Обидві програми відповідають на ті самі запити, а звіт містить рядок із розміром. Вимірюй однаково: тека
`venv` для Python проти двійкового файла для іншої мови.

**Де шукати зразок.** Для порівняння будови можна подивитися на `plumbing/health/main.go`: це маленький сервіс курсу
мовою Go. Він не є розв'язком, бо його поля інші.
