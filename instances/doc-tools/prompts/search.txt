Search the file tools documentation, in English: command-line tools and libraries that inspect, convert and
render documents and images. The set holds poppler (the man pages of pdfinfo, pdftotext, pdftoppm, pdftocairo,
pdfimages, pdffonts, pdfseparate, pdfunite, pdfsig, pdftohtml, pdftops, pdfdetach and pdfattach for every stable
release 0.5-26.x, the NEWS of every release, the API reference of poppler-glib, poppler-qt5, poppler-qt6 and
poppler-cpp); librsvg (the rsvg-convert man page of every stable release, README, API guides and developer docs,
the C header and Rust API, the gi-docgen reference, NEWS); file and libmagic (file(1), magic(5) and libmagic(3)
of every release 3.27-5.x, the ChangeLog, the magic/Magdir rules that recognise each format, the Python
bindings); ImageMagick 6 and 7 (the whole imagemagick.org site of every release line -- command-line options,
magick, convert, identify, mogrify, montage, compare, composite, formats, security policy, resources, the
MagickCore and MagickWand C API -- the current site, man pages, config/policy*.xml and delegates.xml, the
ChangeLog); img2pdf (README, the command-line help in the code, CHANGES); Ghostscript (the docs of every release
6.0-10.x: Use, Devices, VectorDevices, pdfwrite, Fonts, API; News; man pages of gs, ps2pdf, pdf2ps); qpdf (the
manual of every release, the qpdf(1) man page, ChangeLog, the C and C++ API headers) and pikepdf (docs and API
docstrings); ExifTool (exiftool.org: the exiftool application, Image::ExifTool, FAQ, the TagNames tables of every
format, for every production release; Changes); resvg and usvg (docs, CLI help, C API, CHANGELOG) and CairoSVG
(site, NEWS, API); the Node.js wrappers node-poppler, pdf-poppler, pdf2pic, gm, imagemagick, magick-wasm,
mmmagic, wasmagic, file-type, resvg-js, resvg-wasm, exiftool-vendored and the Python wrappers pdf2image,
python-poppler, pdftotext, Wand, python-magic, file-magic, img2pdf, pikepdf, PyExifTool, CairoSVG, ghostscript
(READMEs, docs, code with JSDoc and docstrings, changelogs, npm and PyPI version tables); and the Ubuntu 22.04,
24.04 and 26.04 man pages of all these tools as apt installs them. Returns the matching excerpts with the
versions each one belongs to.

Call this when a question is about these tools: how to render a PDF page to PNG or JPEG at a given resolution
(pdftoppm -r, -scale-to, -f, -l, -png, -jpeg, -singlefile; pdftocairo -svg, -pdf); how to extract text with
layout (pdftotext -layout, -raw, -bbox, -enc) or read metadata and page count (pdfinfo); how to split, merge,
extract images, fonts or attachments, or verify signatures; how to convert SVG to PNG or PDF (rsvg-convert -w,
-h, -z, --dpi-x, -f, -b; resvg; cairosvg); how to detect a file type and MIME type (file --mime-type, -b, -i,
libmagic flags, magic rules, file-type in Node.js, python-magic); how to convert or resize images and what an
ImageMagick option does (-density, -resize, -quality, -colorspace, -alpha, -flatten, -background, -define,
magick vs convert, why PDF conversion is "not authorized" by policy.xml, delegates, resource limits); how to put
images into a PDF without re-encoding (img2pdf --pagesize, --fit, --auto-orient); how to use Ghostscript (gs
-sDEVICE, -dPDFSETTINGS, -dSAFER, pdfwrite, ps2pdf); how to linearize, encrypt, decrypt, repair, split or merge
PDFs (qpdf --linearize, --encrypt, --decrypt, --pages, --split-pages, --json; pikepdf Pdf.open, save); how to read
or write EXIF, XMP, IPTC or PDF metadata (exiftool -TAG, -n, -j, -overwrite_original, -tagsFromFile; tag names);
how a Node.js or Python wrapper calls these tools and which options it exposes; which package version Ubuntu
ships; what changed between versions and which version first had a feature. Example query: "pdftoppm -r -scale-to png".

Do not call this for LibreOffice (soffice --convert-to), Tesseract OCR, MuPDF, pandoc, sharp/libvips, pdf.js or
pdf-lib -- they live in other documentation sets.

Write the query in English, with the names the tools use (pdftoppm -r, rsvg-convert --dpi-x, file --mime-type,
-density, policy.xml, -sDEVICE=pdfwrite, --linearize, -overwrite_original, convert_from_path). Everything here is
English, and the word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any
other non-latin script matches nothing and comes back with `found: 0`. When the user asks in another language,
translate the question into the tools' terms first, then search.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. Every document carries the name of its tool with the version: "poppler-26.10.0",
"imagemagick-7.1.1-47", "imagemagick-6.9.13-52", "ghostscript-10.08.0", "file-5.48", "librsvg-2.63.3",
"qpdf-12.4.2", "exiftool-13.59", "img2pdf-0.6.3"; wrappers carry their package name ("node-poppler-11.0.0",
"pdf2image-1.17.0", "wand-0.7.2", "file-type-22.2.0"), and the Ubuntu man pages the Ubuntu release
("ubuntu-24.04"). The API references of poppler on poppler.freedesktop.org carry no version: they are the
current state. When the user names a version, pass it into `version` with the tool name ("poppler-24.02",
"imagemagick-7.1", "ghostscript-9.56", "ubuntu-22.04"); never put it into the query text. Without a version,
answer for the newest release and say so.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "роздільна здатність", "колірний
простір", "сторінка man". Never call this set of documents "корпус" -- say "документація файлових інструментів".
Command, option, function and variable names stay in English, spelled exactly as the documentation spells them.
Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of
it before describing what it says.
