Search the documentation of the libraries used to test .NET applications, in English: the xUnit.net, NUnit
and bUnit test frameworks (with the xUnit.net and NUnit analyzers, the Visual Studio adapters, the NUnit
console and engine), the assertion libraries FluentAssertions and Shouldly, the mocking libraries Moq and
NSubstitute (with NSubstitute.Analyzers), AngleSharp and AngleSharp.Diffing (the HTML parser and comparer
bUnit's MarkupMatches is built on) and Respawn (database reset between integration tests). The set holds:
every page of xunit.net (v2 and v3 guides, configuration, every analyzer rule xUnit1000-xUnit3xxx, the release
notes of every stable release of the core v2 and v3, the analyzers and the Visual Studio adapter); every page
of docs.nunit.org (attributes, constraints, assertions, running tests, NUnit.Analyzers rules, adapter, engine,
release notes) and the legacy NUnit 2.2-2.6 documentation; bunit.dev at the last release of every minor line
1.0-2.11 with the code samples it inserts; fluentassertions.com at every stable release 4.19.3-8.11.0 with the
tips tables and its release notes; docs.shouldly.org at every stable release; nsubstitute.github.io at every
stable release 0.1-6.2; the Moq wiki (Quickstart, FAQ), README and changelog; the AngleSharp docs, README and
changelog at every release; the README of every library at every stable tag; the API reference from the XML
documentation of the NuGet packages for the newest release of every stable minor line (xunit.assert, the
xUnit.net extensibility and runner packages, xunit.v3.*, NUnit, bunit, AngleSharp, AngleSharp.Diffing,
FluentAssertions, Shouldly, Moq, NSubstitute); every NuGet package of these libraries with every stable
version, its date, dependencies and README; the source code and tests at the last release of every major
line, split into types and members; GitHub release notes where the site has none. Returns the matching
excerpts with the versions each one belongs to.

Call this when a question is about writing or running .NET tests with these libraries: facts and theories
(Fact, Theory, InlineData, MemberData, ClassData, TheoryData), fixtures and shared context (IClassFixture,
ICollectionFixture, CollectionDefinition, AssemblyFixture, IAsyncLifetime), TestContext, ITestOutputHelper,
parallelization, xunit.runner.json and testconfig.json, Microsoft Testing Platform, migrating from v2 to v3;
NUnit attributes (Test, TestCase, TestCaseSource, TestFixture, SetUp, OneTimeSetUp, Category, Parallelizable,
Values, Range, Retry, Timeout), Assert.That with constraints (Is.EqualTo, Has.Count, Does.Contain,
Throws.TypeOf), Assert.Multiple, ClassicAssert, NUnit 4 and 5 migration, the console runner and test selection
language; bUnit (BunitContext, Render, RenderComponent, Find, FindAll, MarkupMatches, WaitForAssertion,
JSInterop, fake NavigationManager, authorization); FluentAssertions (Should, BeEquivalentTo, AssertionScope,
ThrowAsync, WithMessage, Monitor, equivalency options); Shouldly (ShouldBe, ShouldThrow,
ShouldSatisfyAllConditions); Moq (Mock<T>, Setup, Returns, It.IsAny, It.Is, Verify, Times, Callback,
MockBehavior.Strict, SetupSequence, Protected); NSubstitute (Substitute.For, Returns, Arg.Any, Arg.Is,
Received, DidNotReceive, When/Do, Throws, ReturnsForAnyArgs); AngleSharp (HtmlParser, BrowsingContext,
QuerySelector) and AngleSharp.Diffing; Respawn (Respawner.CreateAsync, RespawnerOptions, ResetAsync,
TablesToIgnore); what an analyzer rule means and how to fix it; what a type or member does, its parameters,
return value and exceptions; which NuGet package and version to reference; what changed between versions.
Example query: "Assert.That Is.EqualTo Within tolerance".

Do not call this for other parts of .NET or other tools -- the C# language, the base class library,
ASP.NET Core, Blazor or EF Core beyond how a test library page uses them, MSTest, Playwright, Testcontainers,
Coverlet, the dotnet CLI as such, or JavaScript test frameworks -- they belong to their own documentation;
this set covers them only where a page of these libraries explains how to use them together.

Write the query in English, with the names the documentation uses (Fact, Theory, InlineData, MemberData,
IClassFixture, ICollectionFixture, IAsyncLifetime, ITestOutputHelper, TestContext, TestCase, TestCaseSource,
SetUp, OneTimeSetUp, Assert.That, Is.EqualTo, Assert.Multiple, BunitContext, MarkupMatches, Should,
BeEquivalentTo, AssertionScope, ShouldBe, Mock, Setup, Verify, It.IsAny, Substitute.For, Received, Arg.Is,
Respawner, HtmlParser, xUnit1004, NUnit2005, NS1001). Everything here is English, and the word index keeps only
latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing and comes back with `found: 0`. When the user asks in another language, translate the question into
the terms of the library first, then search. Name the library in the query when the question is about one
(NUnit, xUnit, Moq, NSubstitute): several libraries share words such as Assert, Setup or Returns.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "тест", "твердження" for an assertion, "замінник" or "мок", "фікстура",
"обмеження" for a constraint, "аналізатор", "правило". Never call this set of documents "корпус" -- say
"документація бібліотек тестування .NET". Type, member, attribute, package, rule and option names stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came back,
not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. Every document carries the name of its product with the version, because the
libraries number their releases independently: "xunit-2.9.3" (xUnit.net v2: xunit, xunit.core, xunit.assert,
the runners), "xunit-v3-3.2.2" (the xunit.v3 packages), "xunit-runner-visualstudio-3.1.5",
"xunit-analyzers-1.18.0", "nunit-4.3.2" (NUnit and NUnitLite; "nunit-2.6.4" is the legacy NUnit 2),
"nunit3testadapter-4.5.0", "nunit-analyzers-4.15.0", "nunit-console-3.22.0", "bunit-1.40.0",
"anglesharp-0.17.1", "anglesharp-diffing-1.0.0", "respawn-6.2.1", "fluentassertions-6.12.0", "shouldly-4.3.0",
"moq-4.20.72", "nsubstitute-5.3.0", "nsubstitute-analyzers-1.0.17". Pass a line with the name: "nunit-3.13",
"fluentassertions-6.12", "xunit-v3-3.2", or a major: "nunit-4", "moq-4"; never put a version into the query
text. The pages of xunit.net and docs.nunit.org exist only in their current state and carry the current
releases (xunit-2.9.3 and xunit-v3-4.0.2; nunit-5.0.0, nunit3testadapter-6.3.1, nunit-analyzers-4.15.0): when
the user names an older xUnit.net or NUnit version, search once with the version (API reference, packages,
release notes, code) and once without it (the guides). Without a version, answer for the most downloaded
release of the library and say so: xUnit.net v2 2.4.1 (v3: 3.2.2), NUnit 3.13.3, NUnit3TestAdapter 4.5.0,
bUnit 2.7.2 and 1.40.0 (downloaded about equally -- answer for both), FluentAssertions 6.12.0, Shouldly 4.3.0,
Moq 4.20.72, NSubstitute 5.3.0, AngleSharp 0.17.1, AngleSharp.Diffing 1.0.0, Respawn 6.2.1; when the newest
release differs from it, say how.
