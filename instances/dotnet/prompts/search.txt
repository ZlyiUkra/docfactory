Search the .NET documentation, in English: .NET (formerly .NET Core) 1.0-10.0 and its tools, the base class
library and Microsoft.Extensions.*, the C# language, F#, Visual Basic and .NET Framework. This is the only
documentation server for the C# language: the C# language reference and guide, the C# standard (ECMA-334), the
C# feature specifications and the Roslyn compiler documents live here and nowhere else. The set holds: every
page of learn.microsoft.com/dotnet as the site shows it now and as the dotnet/docs repository held it a week
after each release 1.0, 1.1, 2.0, 2.1, 2.2, 3.0, 3.1, 5.0, 6.0, 7.0, 8.0, 9.0 and 10.0 (with includes, code
samples and API names expanded) -- what's new in each release, the dotnet CLI (dotnet build, run, publish,
test, new, tool, workload, nuget), breaking changes per release, diagnostics, built-in metrics, logging,
tracing, deployment, containers, native AOT, trimming, the fundamentals (dependency injection, configuration,
options, hosting, HttpClient, networking, serialization with System.Text.Json, globalization, threading,
async), C#, F#, Visual Basic, .NET Standard, .NET Framework, architecture guides, AI, Orleans, Azure for .NET,
IoT and ML.NET; the C# standard (ECMA-334 editions 5, 6 and 7 and the drafts of 8 and 9), the C# 6
specification, the feature specifications of C# 7.0-14.0 (dotnet/csharplang), the Roslyn compiler docs
(Language Feature Status, compiler features, breaking changes of the C#, Visual Basic and Razor compilers per
.NET release) and the Visual Basic specification; the API reference of learn.microsoft.com/dotnet/api from
dotnet/dotnet-api-docs (every type and member with remarks and C# examples, "Applies to") and from the XML
documentation of the NuGet packages -- the shared framework (Microsoft.NETCore.App) of every line 2.0-10.0 and
every Microsoft.Extensions.* package in every stable minor line; the release metadata of every .NET release
1.0-10.0 (date, security fixes and CVEs, runtime, SDK, C# version, ASP.NET Core and Windows Desktop versions,
support phase and end of support) and the release notes of dotnet/core (known issues, supported OS, Linux
dependencies, API diffs); the design and contributor docs of dotnet/runtime (docs/) and dotnet/sdk
(documentation/). Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about .NET or C#: a C# language feature, keyword, operator, pattern, type rule or
compiler error and what the standard or a feature specification says about it; how to use a type or member of
the base class library or of Microsoft.Extensions.* (DI, configuration, logging, options, hosting, caching,
HttpClientFactory, resilience, AI), its parameters, return value, exceptions and examples; what a dotnet CLI
command or MSBuild property does; what changed in a release and which breaking changes it brought; which
metrics, event counters and diagnostics tools exist; how to deploy, trim, publish AOT or containerize an app;
which releases are supported, when support ends, which SDK and C# version ship with a runtime, which CVEs a
release fixed; how the runtime works inside (GC, JIT, type loader, hosting). Example query:
"HttpClient PooledConnectionLifetime".

Do not call this for ASP.NET Core, Blazor, SignalR or Razor Pages, Entity Framework, .NET MAUI, WinForms and
WPF beyond their API reference, or Aspire -- they belong to their own documentation; this set covers them only
where a .NET page or the API reference mentions them.

Write the query in English, with the names the documentation uses (HttpClient, IServiceCollection,
AddSingleton, IConfiguration, IOptions, ILogger, IHostedService, JsonSerializer, Span<T>, Task, ValueTask,
CancellationToken, record, init, required, pattern matching, nullable reference types, dotnet publish,
PublishAot, TargetFramework, Meter, ActivitySource). Everything here is English, and the word index keeps only
latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing and comes back with `found: 0`. When the user asks in another language, translate the question into
.NET terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "збірка", "простір імен", "тип", "член", "виняток", "випуск".
Never call this set of documents "корпус" -- say "документація .NET". Type, member, package, command and
option names stay in English, spelled exactly as the documentation spells them. Build the answer out of the
excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it before describing what
it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. The site pages and the API reference carry the .NET version: "10.0", "9.0", ...,
"1.0"; release documents carry the exact release ("8.0.5"). Pass "8.0" for the whole 8.0 line; a text that did
not change across versions carries every one of them. The packages of dotnet/extensions (Http.Resilience,
Compliance, Telemetry, AI ...) ship monthly minors: "8.1" ... "10.11". Microsoft.Extensions packages that
number their releases on their own carry their name: "azure-1.14", "configuration-azureappconfiguration-8.6",
"logging-applicationinsights-2.23", "ml-5.0", "caching-cosmos-1.8". The C# language carries "csharp-": the
standard editions "csharp-5", "csharp-6", "csharp-7" (and the drafts "csharp-8", "csharp-9"), the feature
specifications "csharp-7.0" ... "csharp-14.0"; "csharp-12" finds all of C# 12. The runtime and SDK repository
docs and the Roslyn docs carry no version: search them without one. When the user names a version, pass it
into `version`; never put it into the query text. Without a version, answer for the newest .NET (10.0) and
the newest C# (14) and say so.
