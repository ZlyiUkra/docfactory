# dukascopy-node — примірник фабрики docfactory

Цей примірник зібрав документацію бібліотеки dukascopy-node і віддає її через сервер MCP, щоб модель відповідала з текстів
бібліотеки, а не з пам'яті. Швейцарський банк Dukascopy безкоштовно публікує історію цін: кожну зміну ціни (тик) для валютних пар,
акцій, фондів, індексів, сировини, облігацій і криптовалют. dukascopy-node — це бібліотека для Node.js і програма командного рядка,
яка завантажує ці дані за вказаний період і повертає їх як масив, JSON чи файл CSV. Тики можна отримати як є або зібраними у
свічки OHLC: для кожного проміжку часу (секунда, хвилина, година, день, місяць) свічка каже ціну відкриття, найвищу, найнижчу і ціну
закриття.

## Скільки цього

Усього 1898 документів і 4384 фрагменти. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Однакові
розділи, що повторюються в кількох версіях README, пошук зливає й показує з переліком версій.

Замір `quality` на 09.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 9 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df dukascopy-node <крок>`.

**Чому посібники розбирає інший читач, ніж сторінки інструментів.** Сайт зібрано на Astro, а приклади коду оформлює Expressive
Code. Він кладе кожен рядок коду в окремий блок без переносу, і звичайний розбір склеював рядки: рядки CSV і виводу програми
зливалися в один. Читач `sitemap-starlight` ставить переноси назад. На сторінках інструментів коду немає, зате кожна з них має
однакову форму вибору таймфрейму й дат. Тому сторінка інструмента обрізається перед цією формою, і лишаються id, назва, група і
найраніші дати.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df dukascopy-node serve
```

Порт — `8963`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user dukascopy-node-docs http://127.0.0.1:8963/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `dukascopy-node-docs` з інструментами `search_docs` і `read_section`. Якщо
сервер позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/dukascopy-node-corpus-2026-11-09.tar.gz` (1898 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\dukascopy-node-corpus-2026-11-09.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/dukascopy-node/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/dukascopy-node-corpus-РРРР-ММ-ДД.tar.gz -C instances/dukascopy-node corpus raw
find instances/dukascopy-node/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/dukascopy-node/raw
gzip -9 -c instances/dukascopy-node/index/passages.json > instances/dukascopy-node/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/dukascopy-node-corpus-2026-11-09.tar.gz -C instances/dukascopy-node
./df dukascopy-node smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
