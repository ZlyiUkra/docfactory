# Оновлення корпусу dukascopy-node

Корпус живе нагорі: сайт dukascopy-node.app, реєстр npm і репозиторій `Leo4815162342/dukascopy-node` на GitHub. Нова версія
пакета не потребує правки `sources.json`: README нової версії, запис журналу змін і реліз підтягуються самі, а сайт і код беруться
такими, якими вони є в день оновлення.

Правило: **нічого не видаляється.** Ані `refresh`, ані `manifest` нічого не видаляють. Лише `vectors` прибирає точки своєї колекції,
чиїх фрагментів у корпусі вже немає.

**Спершу — повернути тексти.** Корпус примірника в архіві, а `check`, `refresh` і `manifest` читають файли. Тому перед роботою нижче
тексти розпаковують, а після неї виносять знову: обидві дії описано в
[README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df dukascopy-node refresh site-instruments   # окремим блоком: ~1540 сторінок
./df dukascopy-node refresh site-docs readme cli-readme changelog releases src npm
./df dukascopy-node manifest
./df dukascopy-node vectors
./df dukascopy-node smoke
# Ctrl+C у терміналі з serve, і знову: ./df dukascopy-node serve
```

Що треба зробити вручну після оновлення:

- **Версія сайту.** Поле `version` джерел `site-docs`, `site-instruments` і `src` — це версія, яку описує сайт у день знімка. Її
  видно на сайті і в `llms.txt` («Current version»). Нову версію записують у ці три поля.
- **Зниклі сторінки.** `refresh` не видаляє старих файлів. Якщо інструмент чи сторінку прибрали з сайту, їхній текст лишиться в
  корпусі, доки його не видалити вручну перед `manifest`.

Якщо `smoke` скаржиться на число фрагментів, корпус підріс: нове число записують в `expected_passages`, а в `expected_note` — коли й
чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу треба виконати `./df dukascopy-node quality --show`, переглянути запити зі знаком «-» і перевірити,
чи справді відповідь змінилася. Ціль розширюють лише тоді, коли знайдена сторінка справді відповідає на запит.
