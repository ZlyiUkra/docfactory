Search the documentation of dukascopy-node, the Node.js library and command-line tool that downloads free historical
and real-time market data (ticks and OHLC candles from 1 second to 1 month) for forex pairs, stocks, ETFs, indices,
commodities, bonds and crypto from the Dukascopy Bank data feed, and saves it as CSV or JSON. The corpus holds the site
dukascopy-node.app as of version 1.51.1 (installation, quick start, output formats, tick data, date formats and time
zones, real-time data with `getRealTimeRates`, the cache, batching and rate limits, errors and empty data, TypeScript,
debugging, the configuration, the CLI reference and the Node.js API reference of `getHistoricalRates`), the page of
every one of the 1499 instruments (its id, name, group and the earliest date with data for every timeframe) and the 40
instrument group pages, the README of every stable npm version from 1.0.0 to 1.51.1, the README of the old separate
package `dukascopy-cli`, the changelog, the GitHub release notes, the examples and the TypeScript source of the
library, and the npm registry history.

Use this tool for: how to call `getHistoricalRates` or the CLI and what every option does (`instrument`, `dates`,
`timeframe`, `priceType`, `format`, `volumes`, `utcOffset`, `ignoreFlats`, `batchSize`, `pauseBetweenBatchesMs`,
`useCache`, `retryCount`); what the output looks like in each format; which instrument id to use and since when the
feed has data for it; why a download comes back empty, slow or refused; what changed between versions. Write the query
in English with the name of the option, function or instrument id, such as `getHistoricalRates` or `eurusd`, or with
plain words for what is wanted. Give a version in the filter when the answer depends on it.

Do not use this tool for the Dukascopy trading platform itself, for other data providers, or for Node.js in general.
Returns the matching excerpts with the version each one applies to, the source address and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. 1.51.1 is the current version, and the site describes it. Search without `version`
first; when the user names the version they use, search that version, written as `1.50`, `1.46` and so on.
