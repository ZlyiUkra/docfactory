# ecmascript — примірник фабрики docfactory

Перший примірник фабрики: захищений MCP-сервер, що відповідає на питання про специфікацію ECMAScript. Пошук — з
практики модуля 5, чотири шари захисту — з модуля 6. Ця тека тримає самі дані домену; код спільний і лежить у
`../../server/` (сервер, агент, шари) та `../../common/` (пошук). Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Що в цій теці

- `corpus/` — база специфікацій ECMAScript: усі редакції ECMA-262 і ECMA-402 разом із живими чернетками, таблиці
  завершених пропозицій TC39, ECMA-404, 414 і вільні документи, на які спирається 402 (розділ «Редакції» нижче).
  Єдиний ресурс для пошуку й заливки у векторну базу; поруч `index.json` — його паспорт.
- `sources.json` — звідки цей корпус будується, і водночас білий список для оновлювача.
- `config.json` — назва домену, порт HTTP-сервера, колекція Qdrant, модель векторів, родини редакцій.
- `.env` — ключ Anthropic і моделі (лише для повного прогону агента).
- `.mcp.json` — запис HTTP-сервера для Claude Code.

## Редакції

**Редакція** — видання стандарту, яке Ecma ухвалює раз на рік: ECMAScript 2016 — це 7-ма редакція ECMA-262. Сервер
тримає їх усі, щоб відповідь могла сказати, з якої редакції щось є і як змінювалося.

| Документ | Редакції (мітка версії — рік) | Звідки |
|---|---|---|
| ECMA-262 | 1997 (ES1), 1998 (ES2), 1999 (ES3), 2009 (ES5) | PDF ecma-international.org |
| ECMA-262 | 2011 (ES5.1), 2015 (ES2015, вона ж ES6) … 2026 (ES2026, 17-та) | 262.ecma-international.org |
| ECMA-262 | 2027 — жива чернетка ES2027 | tc39.es/ecma262 |
| ECMA-402 | 2012 (1.0), 2015 (2-га) … 2026 (13-та), 2027 — чернетка | 402.ecma-international.org, tc39.es/ecma402 |
| TC39 | завершені пропозиції 262 і 402: пропозиція → рік редакції | github.com/tc39/proposals |

4-ту редакцію ECMA-262 покинули й не видали, тому її немає. Мітка версії — рік, а не номер редакції: номери 262 і 402
різні (2026 — це 17-та редакція 262 і 13-та 402), а рік у них спільний, і `version: "2016"` бере обидві.

Як це влаштовано. Редакції з 2011 року діляться на документи по одному на розділ (читач `clauses`), і ключем документа
є id розділу (`sec-array.prototype.includes`), а не номер: номери між редакціями зсуваються (22.1.3.11 у 2016,
23.1.3.16 у 2026), а id лишається. Тому однаковий текст кількох редакцій стає одним фрагментом з переліком цих
редакцій, а підпис і адресу він бере з найновішої. Найстаріший рік у переліку каже, відколи текст саме такий, — не
відколи існує сама можливість. На питання «з якої редакції» сервер відповідає таблицею завершених пропозицій (ES2016 і
новіші), вступом специфікації (там TC39 сам перелічує, що додала кожна редакція з ES2015) і пошуком з `version`
старших редакцій. Редакції 1997–2009 — по одному документу на PDF, зі своєю нумерацією розділів.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df ecmascript <крок>`.

find instances/ecmascript/corpus -maxdepth 1 -name '*.txt' -delete

архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

## Установка venv

Власний venv цьому примірнику не потрібен: `./df ecmascript …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/ecmascript/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

Ключ потрібен лише для повного прогону агента (спосіб А). Рукостискання, сервер під Claude Code і пошук ключа не
потребують.

## Спосіб А — власний захищений агент (усі чотири шари)

```
./df ecmascript tools                    # $0: під'єднання, перелік інструментів
./df ecmascript ask "How does Object.prototype.toString build the tag?"   # платно
```

Клієнт тут — наш код, тож працюють усі чотири шари: вхідний фільтр над запитом, правила перед кожним викликом
інструмента, список дозволених інструментів і вихідний фільтр разом із guardrail. Агент говорить із сервером по
stdio, піднімаючи його підпроцесом.

Вердикт guardrail — затвор: на «block» клієнтові показується відмова, а не відповідь із позначкою. Збій самого
guardrail (нерозібраний JSON, помилка виклику) — fail-open: відповідь іде, а причина збою лишається у звіті
прогону. Блокувати на збої означало б відправляти оператору й цілком легітимні відповіді — це свідомий вибір.

## Спосіб Б — сервер під Claude Code (HTTP)

З HTTP-транспортом сервер — окремий процес: його тримають запущеним, а Claude Code під'єднується до нього за
адресою. Тому підйом і інтеграція йдуть у такому порядку.

**1. Підняти сервер** (окремий термінал, з кореня фабрики `docfactory/`):

```
./df ecmascript serve                    # HTTP-сервер на порту з config.json (8760)
```

Лишіть його жити. Qdrant сервер знайде сам: якщо режим `vectors`, у фоні прогріє пошук за змістом, а поки не
прогрівся — відповідає по словах. Для самого під'єднання Docker не потрібен.

**2. Додати сервер у Claude Code** — одним зі способів:

- відкрити теку `instances/ecmascript/` як проєкт у Claude Code: він побачить `.mcp.json` цієї теки й запропонує
  сервер `ecma-spec` (адреса `http://127.0.0.1:8760/mcp`), який треба підтвердити;
- або командою: `claude mcp add --transport http --scope user ecma-spec http://127.0.0.1:8760/mcp`. Прапорець
  `--scope user` робить сервер видимим у всіх проєктах, а не лише в тій теці, з якої додали.

**3. Перевірити під'єднання.** У сесії Claude Code — команда `/mcp`: має бути `ecma-spec` і два інструменти
`search_spec`, `read_section`. Поза сесією той самий перелік дає `claude mcp list`.

**4. Користуватися.** Питайте про специфікацію ECMAScript звичайним чином — Claude Code сам покличе інструменти.
Запит усередину пишеться англійськими термінами специфікації (індекс англійський), а відповідь — мовою питання.

**Той самий сервер з іншого місця.** Клієнтів у сервера може бути скільки завгодно одночасно: друге вікно
VS Code, інша тека, Claude Desktop. Кожному він видає власну сесію, а корпус читають усі той самий. Другий раз
`serve` для цього запускати не треба й не можна — порт уже тримає перший процес. Сам клієнт при цьому нічого з
фабрики не потребує: ні venv, ні корпусу, ні ключа — лише адресу `http://127.0.0.1:8760/mcp`.

Чи побачить сервер нове вікно, вирішує не тека, а **scope** — місце, де лежить запис про сервер:

- **local** — типово, коли додають без прапорця: запис лягає в `~/.claude.json` під ключем тієї теки, з якої його
  додали, і з будь-якої іншої теки сервера не видно;
- **project** — це `.mcp.json` усередині теки примірника: працює лише тоді, коли Claude Code відкритий саме в ній,
  і перший раз питає підтвердження;
- **user** — верхній рівень `~/.claude.json`: видно з усіх тек і всіх вікон. Саме це потрібно для роботи з другого
  місця, і дає його прапорець `--scope user`:

```
claude mcp add --transport http --scope user ecma-spec http://127.0.0.1:8760/mcp
```

Після цього `/mcp` покаже `ecma-spec` у будь-якому вікні — за умови, що процес `serve` живий. Якщо сесія була
відкрита раніше за сервер, `/mcp` перепід'єднає; заново додавати запис не треба. У якому scope запис лежить зараз,
показує `claude mcp list`.

**Claude Desktop** бере ту саму адресу, доданою як сервер типу HTTP. Працює й тоді, коли Claude Desktop —
програма Windows, а `serve` живе у WSL: WSL2 прокидає порти, які слухає linux-сторона, на Windows-івський
`127.0.0.1`. Проброс живе, поки жива сама WSL-машина, — після `wsl --shutdown` він зникає разом з нею.

З іншого комп'ютера в мережі сервер недоступний, і це навмисно: він слухає `127.0.0.1`, а не `0.0.0.0`, і
автентифікації не має.

**5. Зупинити сервер.** У терміналі, де він живе, — Ctrl+C. Якщо термінал загублено, знайдіть процес за портом
і зупиніть його за номером:

```
ss -ltnp | grep 8760                     # покаже pid=NNNN процесу, що тримає порт
kill NNNN                                # м'яка зупинка: сервер закриває сесії й виходить
```

`kill -9` не потрібен — сервер виходить на TERM. А от зупиняти за іменем (`pkill -f spec_mcp`) не варто: під
шаблон потрапляють сервери інших примірників, а іноді й сама оболонка, з якої ви це запустили.

**Якщо щось не так.** `[Errno 98] address already in use` — порт уже зайнятий, майже завжди попереднім, забутим
`serve`; хто саме тримає порт, покаже `ss -ltnp | grep 8760`, і той процес треба зупинити. `/mcp` показує
`ecma-spec` як «failed / not connected» — майже завжди сервер не піднятий (крок 1) або порт інший; звірте адресу
`http://127.0.0.1:8760/mcp` з полем `port` у `config.json`.

Що саме тут захищає. Клієнтом стає Claude Code, а не наш агент, тож шари L1/L3/L4 тут **не** працюють — вони живуть
у клієнті. На сервері лишаються дві речі: вузький перелік інструментів (лише `search_spec` та `read_section`) і
санітар видачі. Санітар — це розтяжка на очевидні формулювання вшитих указівок, а не класифікатор: вказівку,
сформульовану іншими словами, він не впізнає, і жоден регулярний вираз не впізнав би. Натомість спрацювання гучне:
зачеплений фрагмент не підчищається, а вилучається з відповіді цілком — замість тексту клієнт дістає відмову з
номером розділу, а спрацювання пишеться в `out/calls.log`. Корпус тут чистий, тож у нормі розтяжка мовчить — це
запобіжник, а не гарантія.

## Пошук за змістом (необов'язковий)

Типово сервер шукає по словах (BM25), і цього досить. Пошук за змістом додає fastembed і Qdrant у Docker:

```
./df ecmascript vectors                  # підняти Qdrant і залити колекцію docs-ecmascript
./df ecmascript status                   # стан бази й розклад оновлення
```

Колекція в кожного домену своя (`docs-ecmascript`), тож примірники не змішуються. Базу оновлюють точково — стійкі
номери точок і сума тексту, тож перераховується лише змінене.

## Оновлення корпусу

Корпус — локальна копія специфікацій у `corpus/`; оригінали живуть на сайтах, перелічених у `sources.json`, і
час від часу змінюються. Оновлення — покроково:

```
./df ecmascript check                    # звірити копію з сайтами-джерелами; лише друкує різницю
./df ecmascript check --deep             # те саме, але звіряє й кожен розділ редакцій (довше)
./df ecmascript refresh <id…>            # завантажити змінені документи; без імен — увесь корпус наново
./df ecmascript manifest                 # перегенерувати паспорт — опис копії з контрольними сумами
./df ecmascript vectors                  # перерахувати відбитки зміненого тексту в Qdrant —
                                         #   лише якщо ввімкнено пошук за змістом
```

Після цього перезапустіть `./df ecmascript serve`: корпус сервер читає один раз, на старті, тож свіжу копію він
побачить лише після перезапуску. Покрокове проведення апдейту — з Qdrant і без нього, з особливими випадками
(зсув глав, сироти, чужа колекція) — у [../../UPDATE.md](../../UPDATE.md).

## Межа захисту, коротко

Спосіб А дає повний захист — усі чотири шари навколо агента. Спосіб Б дає серверну оборону (розтяжка санітара
плюс вузький перелік інструментів), а клієнтські шари — відповідальність Claude Code. Текст відповіді агент бере з файлів
корпусу, а не з payload бази, тож підміна тексту в Qdrant у відповідь не потрапляє.
