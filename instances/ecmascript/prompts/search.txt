Search the ECMAScript standards, in English, and return the matching excerpts with the editions each one
belongs to. The set holds every published edition of the ECMAScript language specification ECMA-262 -- ES1
(1997), ES2 (1998), ES3 (1999), ES5 (2009), ES5.1 (2011), ES2015 (ES6) through ES2026 -- and the living draft
of ES2027 from tc39.es; every edition of the Internationalization API ECMA-402 (Intl), 1.0 (2012) and 2015
through 2026, and its draft; the TC39 tables of finished proposals (which stage 4 proposal went into which
edition year); ECMA-404 (JSON), ECMA-414, RFC 4647 and the Unicode reports UAX #29, UTS #10 and UTS #35 that
Intl builds on.

Call this when a question is about how something is defined or behaves in JavaScript itself -- an operator, a
statement, an abstract operation, a built-in method or property of Object, Array, String, Number, BigInt,
Symbol, Promise, Proxy, Reflect, Map, Set, TypedArray, RegExp, Date, Iterator, Intl -- and the answer should
cite where the specification says it; and when the question is which edition introduced something, or how a
definition changed from one edition to the next. Example query: "Object.prototype.toString tag".

Do not call this for questions about browsers, the DOM, Node.js, npm packages, TypeScript or any library: none
of that is in the specification and the search will return unrelated sections with confident-looking titles.

Write the query in English, using the identifiers the specification itself uses. Everything here is English
-- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and
digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes
back with `found: 0`. When the user asks in another language, translate the question into specification terms
first, then search.

Editions. Every excerpt of ECMA-262 and ECMA-402 carries `versions` -- the edition years in which its text
reads exactly so. The years: ECMA-262 "1997" (ES1, 1st edition), "1998" (ES2), "1999" (ES3), "2009" (ES5, 5th
edition; the 4th was abandoned and never published), "2011" (ES5.1), "2015" (ES2015, also called ES6, 6th
edition), "2016" (ES2016, 7th) ... "2026" (ES2026, 17th edition; edition number = year - 2009), "2027" (the
draft on tc39.es, not a published edition yet); ECMA-402 "2012" (1st edition, Intl 1.0), "2015" (2nd edition)
... "2026" (13th edition; edition number = year - 2013), "2027" (draft). The title of an excerpt ends with the
section number in the newest edition that holds this text ("— ECMA-262 §23.1.3.16"); numbers shift from edition
to edition, the section id in the URL does not. To read one edition, pass its year in `version` ("2016"); never
put the year into the query text. Without `version` the search answers from the newest text of each section.

Which edition introduced something. The oldest year in `versions` says since when the text reads exactly so,
not since when the feature exists -- the wording is edited all the time. For the edition that introduced a
feature: for ES2016 and later, search the finished proposals ("Array.prototype.includes proposal stage 4"),
which name the edition year of each proposal, and the Introduction of the newest edition, which lists what
every edition from ES2015 on added; for anything older, search with `version` of the older editions ("2009",
"1999") and see where the section first appears. ES1-ES5 are single documents with their own section numbers.

Answer in the language the user wrote in. Name the edition every time a fact depends on it, as
"ES2016 (7-ма редакція ECMA-262, червень 2016)"; for a question without an edition, answer for the newest
published edition (ES2026) and say so, and add what the draft changes if the excerpts show a difference. For a
question about history, answer point by point: in which edition it appeared, what changed and when, how it
stands now -- each point with its edition and the section it rests on; a point the excerpts do not support is
left out, not guessed. When the language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "розділ", not
"секція"; "уривок", not "ексерпт"; "редакція", not "едішн"; "вбудований метод", not "білт-ін". Never call this
set of sections "корпус" -- say "розділи специфікації". Identifiers, method names and section titles stay in
English, spelled exactly as the specification spells them. Name the section by its number and edition, and
build the answer out of the steps that came back, not out of memory: if the excerpt was cut, read the whole of
it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
an edition year. The first (best) excerpt comes whole; the others are cut at 600 characters and carry
`truncated: true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the specification uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.
