# electron — примірник фабрики docfactory

Цей примірник зібрав документацію Electron і двох інструментів навколо нього та віддає її через сервер MCP, щоб модель відповідала з
текстів, а не з пам'яті. Electron дає змогу написати настільну програму для Windows, macOS і Linux на HTML, CSS і JavaScript. Усередині
кожної такої програми працює браузер Chromium, який малює вікна, і Node.js, який має доступ до файлів і системи. Головний процес
(main) керує вікнами й системою, а кожне вікно — це окремий процес відмальовування (renderer), який з міркувань безпеки не бачить Node.js
напряму. Два процеси обмінюються повідомленнями (IPC), а скрипт попереднього завантаження (preload) вирішує, які функції головного
процесу сторінка може викликати.

Два інструменти лежать поруч, бо без них програму на Electron не випускають:

- **electron-builder** збирає з програми інсталятор чи переносний файл (NSIS, portable, AppImage, dmg), підписує його сертифікатом і
  публікує оновлення, які програма потім сама завантажує через `electron-updater`;
- **electron-vite** збирає код головного процесу, preload і сторінок через Vite і під час розробки перезавантажує сторінку одразу після
  зміни коду (HMR).

## Скільки цього

Усього 4711 документів і 19 569 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Одна сторінка, що
змінювалася між версіями, лежить кількома документами, а однакові розділи пошук зливає й показує з переліком версій.

| Що | Лінії | Документів |
|---|---|---|
| тека `docs/` Electron: довідник API, посібники, безпека, швидкодія, несумісні зміни | 46 мажорів 0.37–45 | 2788 |
| нотатки релізів Electron на GitHub | усі стабільні теги | 1348 |
| документація electron-builder | 26 мажорів 1–26 | 291 |
| журнал змін electron-builder | стабільні версії | 141 |
| сайт electron-vite | поточна лінія 6 | 20 |
| журнал змін electron-vite | стабільні версії | 40 |
| реєстр npm: `electron`, `electron-builder`, `electron-vite` | усі версії | 83 |

Мітки версій мають вигляд `electron-45`, `electron-builder-26` і `electron-vite-6`. Префікс потрібен, щоб версії трьох інструментів не
збігалися між собою й з версіями інших бібліотек, коли сервери працюють разом.

**Де є прогалини, хоч ми й брали всі лінії.** Репозиторій документації electron-vite не має тегів, тож його сайт є лише в поточній лінії 6;
про зміни старіших ліній розповідає журнал змін. Тека документації electron-builder переїжджала: до лінії 22 вона звалася `docs/`, у 26 —
`pages/`, а сучасний сайт лежить у `website/`, тож одна сторінка може трапитися під трьома іменами. Сайт electronjs.org збирається з тієї
самої теки `docs/`, тому окремо його не брали.

Замір `quality` на 08.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне теж 10 із 10, коли пошук по словах і пошук за змістом працюють разом.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df electron <крок>`.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df electron serve
```

Порт — `8959`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user electron-docs http://127.0.0.1:8959/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `electron-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/electron-corpus-2026-11-08.tar.gz` (4711 текстів, паспорт і сховище сирого `raw/`; перед
видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows `C:\Distr\electron-corpus-2026-11-08.tar.gz`
(звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/electron/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/electron-corpus-РРРР-ММ-ДД.tar.gz -C instances/electron corpus raw
find instances/electron/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/electron/raw
gzip -9 -c instances/electron/index/passages.json > instances/electron/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/electron-corpus-2026-11-08.tar.gz -C instances/electron
./df electron smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
