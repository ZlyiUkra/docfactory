# Оновлення корпусу emberjs

Гайди, довідник API, гайд застарілого, гайди Ember CLI, блог, RFC і гайди WarpDrive беруться зі знімка: у `tags`
кожного з цих джерел стоїть один коміт («SHA → ""»), бо теги цих репозиторіїв або відсутні, або не означають версій
документації. Оновлення — новий SHA останнього коміту гілки на місці старого. Журнали змін, релізи GitHub і реєстр
npm читаються щоразу заново, і змінена відповідь не затирає збереженої — стара переїжджає в `raw/_old/<день>/`.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df emberjs check                        # чи змінилося щось нагорі за джерелом
./df emberjs refresh                      # повне перезавантаження (близько 4 годин, з них API — 3)
./df emberjs refresh changelog-ember changelog-warp-drive releases-ember releases-ember-cli releases-warp-drive npm-ember-source npm-ember-cli npm-ember-data
./df emberjs manifest
./df emberjs vectors
./df emberjs smoke
# Ctrl+C у терміналі з serve, і знову: ./df emberjs serve
```

Перерваний повний прогін продовжують командою `refresh <джерело, де зупинився>`, а потім `refresh --missing`.

**Новий випуск Ember.** Гайди нової мінорної з'являються в `ember-learn/guides-source` текою `guides/v7.3.0`, а
довідник — текою `json-docs/ember/7.3.0/` в `ember-learn/ember-api-docs-data`: досить замінити SHA в `tags` джерел
`guides`, `api-ember` і `api-ember-data` на свіжий SHA гілки `master` (`main`). Документи, чий текст не змінився,
зберігають імена: ім'я гайду — шлях у теці версії з хешем вмісту, ім'я запису API — сутність з хешем версії. Межі
версій названі в `prompts/search.txt` і `prompts/agent.txt` (зараз гайди «1.10–7.2»): нова мінорна — посунути їх, нова
мажорна — ще й `version_probe` у `checks.json`.

**Що перевірити після оновлення.**

- `./df emberjs check` після заміни SHA перелічить сироти — файли старого знімка, яких нагорі вже немає (сторінку
  перейменовано чи вилучено). Їх виносять з `corpus/` у теку поза репозиторієм, а не видаляють.
- Якщо `guides` пише «немає жодної теки версії за `folder_version`», гайди змінили імена тек: звірити вираз
  `folder_version` з деревом `guides/`.
- Якщо `api-ember` дає порожні документи, змінився формат JSON сайту api.emberjs.com: звірити один запис
  `classes/*.json` з полями `data.attributes`, які читає `engine/readers/emberapijson.py`.

Якщо `smoke` скаржиться на число фрагментів, корпус підріс. Нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df emberjs quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
