Search the documentation of Express, the web framework for Node.js, in English: the
expressjs.com site for Express 5.x and 4.x -- getting started (installing, hello world, the
generator, basic routing, static files, FAQ), the guides (routing, writing middleware, using
middleware, error handling, template engines, behind proxies, debugging, overriding the Express
API, developing template engines) and the API reference of express(), app, req, res and router;
the API reference of Express 3.x; the 2.x documentation from the old site; the pages shared by
all versions -- best practices for security and for performance, health checks and graceful
shutdown, security updates, database integration, migrating to Express 4 and to Express 5, the
glossary, and the pages of the official middleware (body-parser, cors, cookie-parser,
cookie-session, compression, errorhandler, method-override, morgan, multer, response-time,
serve-favicon, serve-index, serve-static, express-session, timeout, vhost); the Express blog
with release and security announcements; the History.md changelog of every version; the README
of every stable version; the GitHub release notes; and the npm registry list. Returns the
matching excerpts with the versions each one belongs to.

Call this when a question is about building an HTTP server or API with Express: app.get and
the other routing methods, express.Router, route parameters and path patterns, middleware
order and next(), req.params, req.query, req.body, res.json, res.status, res.send, res.redirect,
serving static files, parsing JSON and forms, file uploads, cookies and sessions, CORS, error
handling middleware, async handlers, template engines, trust proxy, security and performance in
production -- and above all when it is about versions: what changed between Express 4 and 5,
since which version an option exists, and how to migrate. Example query: "res.json status".

Do not call this for Node.js itself (http, streams, process), for other frameworks (Koa,
Fastify, NestJS -- NestJS has its own instance), for databases and ORMs, or for the web platform
itself: their documentation is not here, and the search will return Express excerpts that
merely mention them, with confident-looking titles.

`version` narrows the search to one major: "5" keeps Express 5.x, "4" keeps 4.x, "3" and "2" the
old lines. The pages shared by all versions carry the version "site", blog posts "blog", the
History.md changelog "changelog". Leave `version` empty to search everything. Every excerpt
comes back with `versions`: each version whose documents contain this exact text, newest first
-- text that stayed the same across versions is returned once, with all of them listed.

Which version to search first. Express 5 and Express 4 were downloaded almost equally in the
week the documentation was collected (52% and 48%), so when the user names no version, search
with "5" and with "4" and say where they differ -- async handlers and rejected promises, the
path syntax of path-to-regexp 8 (named wildcards, no inline regular expressions), removed
methods and signatures, req.query and req.body defaults. Search without `version` for history
and migrations; the migration guides and History.md name the version of every change.

Where the documentation lives. Site pages are named by their path (src-content-docs-en-5x-
guide-routing, src-content-api-5x-api-response-index, src-content-pages-en-guide-migrating-5,
src-content-pages-en-resources-middleware-cors); README documents, release notes and registry
documents are titled by package.

Write the query in English, with the names the documentation uses (app.use, app.get,
express.Router, router.param, req.params, req.query, req.body, res.json, res.status,
res.sendFile, res.cookie, express.json, express.urlencoded, express.static, error-handling
middleware, next(err), trust proxy, path-to-regexp). Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin
letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into Express terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Answer in the language the user wrote in. Every answer says which version it is for. When the
question is about a version change, a migration or compatibility, answer point by point: since
which version; what changed; what the migration requires; how it stands now -- each point with
the document it rests on; a point the excerpts do not support is left out, not guessed. When
that language is Ukrainian, write as a Ukrainian engineer writes, not as a translation from
English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "маршрут", "обробник", "проміжний обробник (middleware)", not "мідлвара";
"застарілий", not "депрекейтнутий". Never call this set of documents "корпус" -- say
"документація Express". Identifiers, option names and titles stay in English, spelled exactly
as the documentation spells them. Build the answer out of the excerpts that came back, not out
of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
