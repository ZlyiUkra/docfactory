# fabricjs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Fabric.js — бібліотеку, яка перетворює HTML5 canvas на полотно з
об'єктами, що їх користувач виділяє, тягає, масштабує й обертає мишею (`Canvas`, `Rect`, `Textbox`, `FabricImage`,
маркери керування, фільтри, збереження в JSON і SVG), — і про fabricjs-react, обгортку спільноти для React.
Документація — сайт fabricjs.com станом на 17.11.2026 (Fabric.js 7.4.0) з довідником API, старий сайт
fabric5.fabricjs.com (Fabric.js 5), README і реєстр npm п'яти пакетів, журнал змін і релізи GitHub; лише
англійською. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані
домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Браузер дає для малювання елемент `<canvas>` і його Canvas API: набір команд «проведи лінію», «залий прямокутник».
Намальоване стає просто пікселями: полотно не пам'ятає, де який прямокутник. Fabric.js тримає поверх полотна перелік
об'єктів і сама малює навколо вибраного об'єкта рамку з маркерами. Користувач тягне маркер — об'єкт змінює розмір чи
кут, і бібліотека перемальовує полотно. Тому Fabric.js беруть для редакторів: конструктор листівок, розмітка
зображень, підпис на документі. Друга її сильна сторона — SVG в обидва боки: вона читає файл SVG в об'єкти полотна
(`loadSVGFromString`) і записує полотно назад у SVG (`toSVG`). Сам Canvas API і сам SVG описано в примірнику `mdn`;
тут — лише те, що додає Fabric.js.

Між лініями 5 і 6 бібліотеку переписано на TypeScript, і код для них пишеться по-різному. У Fabric.js 5 усе лежить в
одному об'єкті `fabric` (`new fabric.Canvas(…)`, `fabric.Image.fromURL(url, callback)`). Від Fabric.js 6 класи
імпортуються за іменами (`import { Canvas, Rect } from 'fabric'`), три з них перейменовано (`fabric.Object` став
`FabricObject`, `fabric.Text` — `FabricText`, `fabric.Image` — `FabricImage`), а функції, що приймали зворотний
виклик, повертають `Promise`. Більшість прикладів у мережі написано для лінії 5 і старіших, тому відповідь мусить
знати, для якої версії вона.

**Що є що.** **Canvas** — полотно, з яким працює користувач: виділення, перетягування, події миші;
**StaticCanvas** — те саме полотно без взаємодії, лише малює (його ж беруть у Node.js); **FabricObject** — предок
усіх фігур із спільними властивостями (`left`, `top`, `fill`, `angle`, `scaleX`); **controls** — маркери на рамці
вибраного об'єкта, кожен зі своєю дією; **ActiveSelection** — тимчасова група з кількох вибраних об'єктів;
**Group** — постійна група, що рухається як одне ціле; **clipPath** — фігура, що обрізає інший об'єкт своїм
контуром; **object caching** — знімок об'єкта в окремому полотні, щоб не малювати його щоразу заново.

## Звідки документація

- **Посібник — з репозиторію, а не зі сторінок.** Сайт fabricjs.com збирає Astro Starlight із теки
  `packages/website` репозиторію `fabricjs/fabric.js`, і читач `ghdocs-history` бере її на коміті `ab604137` гілки
  `master` від 17.11.2026. У файлах `.mdx` лишаються підписи приміток і блоки коду такими, як їх написав автор.
  Адресу кожної з 37 сторінок на сайті задає поле `site` у `sources.json`; усі звірено з сайтмапом.
- **Один знімок, а не редакція на кожну версію.** Тека сайту є лише в гілці `master`: у тегах релізів її немає.
  Тому посібник не можна взяти «яким він був на 6.0» чи «на 7.1», і всі його сторінки несуть одну мітку `7.4.0` —
  останньої версії fabric на день знімка.
- **Довідник API 7 — готовий HTML.** Сторінки fabricjs.com/api плагін starlight-typedoc збирає з коду під час
  збирання сайту: у репозиторії їх немає. Читач `sitemap-starlight-typedoc` бере 467 адрес із сайтмапу й робить із
  кожною сторінкою дві речі. Перша: заголовки четвертого рівня й глибші («Parameters», «Returns», кожен параметр)
  стають рядками жирним, тож фрагмент пошуку — це цілий член класу, а не уривок із двох рядків. Друга: член, який
  клас успадкував від предка з власною сторінкою, з його сторінки прибирається, а наприкінці лишається розділ
  «Inherited members» з переліком імен і назвою предка. Члени `FabricObject` стоять на сайті дослівно на сторінках
  `Rect`, `Circle`, `Textbox` і ще двох десятків класів, і без цього та сама властивість займала б усю видачу під
  різними назвами. Член, чий предок сторінки не має, лишається: `Canvas` успадковує 146 членів від
  `SelectableCanvas`, якого в довіднику немає, і всі вони описані на сторінці `Canvas`.
- **Старий сайт.** fabric5.fabricjs.com — заморожена документація Fabric.js 5: довідник JSDoc (57 сторінок, читач
  `html-list`) і демонстрації (читач `html-pages`). Обидва шари несуть мітку `5.5.2` — останньої версії лінії 5.
- **Демонстрації нового сайту — кодом.** Сторінка демонстрації на fabricjs.com складається з кнопок і полотна, тексту
  на ній немає. Тому в корпусі лежить не сторінка, а код демонстрації з теки `demo`: читач `ghcode-history` дає
  документ на кожен файл.
- **README.** Реєстр npm віддає README лише найновішої версії, тому README кожної версії читається з репозиторію на
  коміті її публікації (`gitHead`), а де реєстр коміту не записав — з тегу `v{version}` чи `{version}`.
- **Версії інших пакетів з префіксом.** fabricjs-react, fabric-with-gestures, fabric-pure-browser і @types/fabric
  мають власну нумерацію, тому їхні документи несуть версію з префіксом (`fabricjs-react-2.2.0`). Без префікса
  фільтр «2» змішав би Fabric.js 2 з fabricjs-react 2.
- **Релізи з тегами без крапок.** Від 3.6.3 репозиторій називає теги трьома цифрами поспіль: `v740` — це 7.4.0.
  Читач `ghreleases-tag-version` виводить із такого тегу версію з крапками (поле `tag_version`); без цього нотатки
  до 7.4.0 несли б версію «740», і запит з версією «7» їх би не знайшов.
- **Журнал змін.** `CHANGELOG.md` пише заголовок версії як «## [7.4.0]»; читач `changelog-otel` дає документ на
  кожну версію, разом із записами передрелізів (36 записів на зразок 6.0.0-beta1): переписування на TypeScript
  описано саме в них.

## Межі, про які треба пам'ятати

- Посібник і довідник API нового сайту є лише для Fabric.js 7.4.0. Окремого довідника для лінії 6 немає: про неї
  відомо зі сторінки «Upgrading to Fabric 6.0», з README, журналу змін і релізів. API ліній 6 і 7 близькі, а що
  саме змінилося, каже сторінка «Upgrading to Fabric 7.0».
- Успадкованого члена класу в довіднику API 7 описано один раз, на сторінці предка: `Rect` → `FabricObject` →
  `InteractiveFabricObject` → `BaseFabricObject`. Якщо на сторінці класу члена немає, його ім'я і предок стоять у
  розділі «Inherited members» наприкінці цієї сторінки.
- З 44 демонстрацій старого сайту в корпусі 19: у решти 25 сторінка — це лише полотно, а код лежить у вбудованому
  скрипті, якого читач не бере. З 19 код у тексті мають дев'ять.
- Довідник API ліній 1–4 не входить: сайт для них не зберігся, є лише README, журнал змін і релізи.
- README немає в 97 версій fabric — це 1.4.3 і частина старіших: реєстр не записав для них ні коміту, ні тегу.
  Порожні в журналі змін розділи 6.0.0 і 1.0.0 документами не стали.
- fabricjs-react — пакет спільноти з README на одну сторінку; іншої документації в нього немає. Передрелізи README і
  релізів не беруться.
- Сам Canvas API браузера і SVG — у примірнику `mdn`; сам React — у примірнику `react`. Інші бібліотеки для полотна
  мають власні примірники: `konva`, `pixijs`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/fabricjs-corpus-2026-11-18.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\fabricjs-corpus-2026-11-18.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів
немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/fabricjs/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/fabricjs-corpus-РРРР-ММ-ДД.tar.gz -C instances/fabricjs corpus raw
find instances/fabricjs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/fabricjs/raw
gzip -9 -c instances/fabricjs/index/passages.json > instances/fabricjs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/fabricjs-corpus-2026-11-18.tar.gz -C instances/fabricjs
./df fabricjs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/fabricjs/index/passages.json.gz`,
далі `./df fabricjs vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df fabricjs …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/fabricjs/.env` (`cp .env.example .env`; для
кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df fabricjs sources --why    # перелік джерел і білий список
./df fabricjs refresh          # усе: близько 12 хвилин мережею (паузи 0,2 с)
./df fabricjs manifest         # оновити паспорт
./df fabricjs setup            # Qdrant чи пошук лише по словах
./df fabricjs vectors          # залити корпус у docs-fabricjs
./df fabricjs smoke            # перевірки
```

Найдовше йде довідник API: 467 сторінок, кожна близько мегабайта HTML. Порядок оновлення — у
[UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df fabricjs serve   # порт 8991
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8991/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user fabricjs-docs http://127.0.0.1:8991/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
