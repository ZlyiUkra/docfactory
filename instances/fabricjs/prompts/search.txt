`version` narrows the search to one release line: "7" keeps the site, the API reference and every fabric 7.x
document, "7.4" every 7.4.x, "6" the README, changelog and release notes of Fabric.js 6, "5" the Fabric.js 5 API
reference and demos together with the 5.x README, changelog and releases; leave it empty to search everything.
Other packages carry their own numbering with a prefix, so they never mix with the fabric lines:
"fabricjs-react-2", "fabric-with-gestures-4", "fabric-pure-browser-5", "types-fabric-5". Every excerpt comes
back with `versions`: each version whose documents contain this exact text, newest first, so the list itself
shows from which to which version the documentation said exactly this.

Write the query in English, with the names Fabric.js itself uses ("Canvas add Rect", "object:modified event",
"loadFromJSON", "clipPath", "FabricImage.fromURL filters", "Control actionHandler", "PencilBrush
isDrawingMode"), not in the user's own words. In Fabric.js 5 and earlier everything lives in the `fabric`
namespace: write "fabric.Canvas", "fabric.Image.fromURL". Everything here is English -- the excerpts, the word
index and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written
in Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When
the user asks in another language, translate the question into Fabric.js terms first, then search.

Answer in the language the user wrote in. When the question is about the history or support of a class, method
or option, answer point by point: since which version it exists; what changed in later versions; what prompted
the change, if the excerpts say so; and how it stands in the current version. Every point names the version and
the document it rests on; a point the excerpts do not support is left out, not guessed. When that language is
Ukrainian, write as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated:
true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Fabric.js 7 carries about 61% of the weekly downloads, Fabric.js 6 about 18%,
Fabric.js 5 about 14%. Fabric.js 6 rewrote the library in TypeScript: classes are imported by name (`import {
Canvas, Rect } from 'fabric'`) instead of the `fabric` namespace, loading became promise-based, and some classes
were renamed (fabric.Image is FabricImage, fabric.Object is FabricObject, fabric.Text is FabricText), so code
for 5 and for 6 or 7 is not interchangeable. Search with `version` "7" for a question about how to do
something; if the user names Fabric.js 5 or older, or the code uses the `fabric.` namespace and callbacks,
search "5". The API reference of line 6 was not kept separately: for Fabric.js 6 use line 7 together with the
guide "Upgrading to fabric 7.0" and say so. The "Old docs" articles of the site were written for lines 1 to 5
and say so on the page. Search without `version` when the question is about history or when the line gave
nothing. Every answer says which version it is for; when the user did not name one, answer for Fabric.js 7.4
and say so. In the API reference a member inherited from a parent class is described on the parent's page
(Canvas inherits from SelectableCanvas and StaticCanvas, shapes from FabricObject); the section "Inherited
members" of a page lists them with their origin.
