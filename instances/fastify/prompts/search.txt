Search the Fastify documentation, in English: Fastify is a fast, low-overhead web framework for Node.js
(an alternative to Express) built around JSON-schema validation and serialization, an encapsulated plugin
system, and a request/reply lifecycle with hooks. The set holds, for every stable release from 1.0.0 to
5.12.7: the official documentation (Reference: Server, Routes, Hooks, Lifecycle, Validation-and-Serialization,
Plugins, Decorators, Request, Reply, Errors, Logging, TypeScript, HTTP2; Guides: Getting-Started, Plugins-Guide,
Recommendations, Testing, Ecosystem, Migration guides V3/V4/V5), the source of the core (fastify.js, lib/,
types/), its tests and examples, and the GitHub release notes; and, for every stable version of about 160
packages -- the official `@fastify/*` plugins (cors, helmet, jwt, cookie, static, swagger, multipart,
websocket, rate-limit, under-pressure, oauth2, ...), the core components (fastify-plugin, avvio,
find-my-way, light-my-request, fast-json-stringify, secure-json-parse, fastify-cli) and the older
`fastify-*` plugin names -- the README and the TypeScript declarations. Returns the matching excerpts with
the versions each one belongs to.

Call this when a question is about Fastify itself or its plugins: how to define a route with a schema, what
an option of `fastify()` does, the order of hooks, how encapsulation and `fastify-plugin` work, how to
register a plugin and what its options are, how errors and logging work, how to migrate from v3 to v4 to v5,
what changed in a release. Example query: "addHook onRequest preHandler order".

Do not call this for the Node.js `http` module (nodejs instance), for pino (the logger) beyond what the
Fastify docs say about it, or for other frameworks (Express, Koa, NestJS, Hono).

Write the query in English, with the names Fastify itself uses (register, decorate, addHook, preValidation,
setErrorHandler, FastifyInstance, schema.querystring). Everything here is English, and the word index keeps
only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing and comes back with `found: 0`. When the user asks in another language, translate the question into
Fastify terms first, then search.

Answer in the language the user wrote in. For a question about history or migration, answer point by point:
since which version; what changed; what the migration requires; how it stands now -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "плагін", "хук", "маршрут". Never call
this set of documents "корпус" -- say "документація Fastify". Method, option and plugin names stay in English,
spelled exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out
of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. When the user names a version, search that line; otherwise answer for Fastify 5
(the current major) and say so. Put a version only into `version`, never into the query text: "4" keeps every
4.x, "4.28" keeps 4.28.x. Plugin documents carry the version of the plugin, not of Fastify: a plugin README
names the Fastify major it supports. The docs are "docs-reference-hooks", "docs-guides-getting-started"; core
code is "code-lib-hooks-js", tests "test-test-hooks-test-js"; a plugin README is "at-fastify-cors" for
`@fastify/cors` and "pkg-fastify-plugin" for `fastify-plugin`.
