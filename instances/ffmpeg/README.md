# ffmpeg — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про FFmpeg — набір програм командного рядка `ffmpeg`, `ffprobe` і
`ffplay` та бібліотек libav* для читання, перетворення, перепакування й аналізу відео та аудіо — за документацією
всіх гілок випусків від 0.6 до 9.0: посібниками з репозиторію на тегах випусків, журналом змін, сторінками ffmpeg.org
і обгортками npm. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі
дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

Що таке ffprobe, коротко: програма з набору FFmpeg, що відкриває медіафайл, нічого в ньому не змінюючи, і друкує, як
він улаштований — контейнер (MP4, MKV…), доріжки, кодеки, роздільність, тривалість, бітрейт, а на вимогу й пакети та
кадри — текстом, JSON, XML чи CSV. Її «брат» `ffmpeg` перетворює й перепаковує файли: наприклад,
`ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4` переносить службовий блок `moov` на початок файла, щоб
браузер міг почати відтворення й перемотування, не тягнучи спершу кінець файла.

## Скільки цього

Усього 37 гілок випусків, по найновішому сталому тегу кожної: 0.6.7, 0.7.17 … 8.1.3, 9.0.2. Журнал змін додає записи
окремих точкових випусків — 278 сталих версій від 0.3.3 до 9.0.2. Передрелізи й гілка розробки не беруться.

| Шар | Документів | Версій | Звідки |
|-----|-----------:|-------:|--------|
| Посібники: ffmpeg, ffprobe, ffplay, компоненти, бібліотеки, загальне, FAQ, розробникам | 887 | 37 гілок, 0.6.7–9.0.2 | тека `doc/` на тезі |
| Схема виводу ffprobe (`ffprobe.xsd`), розділ на кожен тип | 33 | 0.10.16–9.0.2 | тека `doc/` на тезі |
| Журнал змін, по документу на версію | 278 | 0.3.3–9.0.2 | `Changelog` на тезі гілки |
| Сторінки ffmpeg.org: новини, випуски, вразливості, ліцензія, про проєкт | 5 | без версії | ffmpeg.org |
| README обгорток: кожен неповторний текст один раз, з усіма версіями | 4 + 14 + 13 + 24 + 14 | 5 + 22 + 51 + 31 + 21 | репозиторій на `gitHead` / tarball |
| Реєстр npm обгорток: огляд і мажорні лінії | 4 + 3 + 4 + 6 + 2 | усі сталі | registry.npmjs.org |

Обгортки в порядку стовпців: `ffprobe-static`, `@ffprobe-installer/ffprobe`, `fluent-ffmpeg`, `ffmpeg-static`,
`@ffmpeg-installer/ffmpeg`.

Разом 1291 документ; фрагментів в індексі — 11668 (`expected_passages` у `checks.json`): сусідні версії посібників
здебільшого однакові, і однаковий розділ лягає в індекс один раз з усіма своїми версіями.

Замір `quality` на першому корпусі: по словах 3 із 10, за змістом 4, разом 5; десятка «як модель» — 10 із 10.
Перша десятка навмисне перефразована без жодного терміна FFmpeg («move the index of the file to the front…» замість
`movflags faststart`), і саме такі запити тут найслабші; запити назвами документації, як їх пише модель за описом
інструмента, знаходять усе. `max_per_doc` — 2: на замірі 0/1/2/3 це єдине значення, що дало більше (по словах 3
замість 2), не втративши жодного запиту «як модель».

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df ffmpeg <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| посібники й схема виводу ffprobe | тека `doc/` репозиторію `FFmpeg/FFmpeg` на останньому сталому тезі кожної гілки | `gh-texinfo`, новий |
| журнал змін | файл `Changelog` на тих самих тегах | `changelog-tags`, новий |
| новини, випуски, безпека, ліцензія, про проєкт | сторінки ffmpeg.org: `index`, `download`, `security`, `legal`, `about` | `html-pages` |
| README обгорток | репозиторій обгортки на коміті версії (`gitHead`), для `fluent-ffmpeg` — tarball версії | `npm-readme`, `npm-tarball-files` |
| реєстр npm обгорток | registry.npmjs.org, одне звернення на пакет | `npm-versions` |

**Чому з тегів, а не з сайту.** Сайт ffmpeg.org показує документацію лише гілки розробки, перебудовану щоночі, — без
вибору версії. Посібник кожного випуску є тільки в тезі, і лише у вигляді вихідного Texinfo (`doc/*.texi`): готових
HTML чи info в репозиторії немає. Читач `gh-texinfo` (`engine/readers/texinfo.py`) розкриває `@include`, макроси й
умовні блоки так, як їх розкриває HTML-збірка самого FFmpeg (`config-not-all`, усі бібліотеки ввімкнено), і робить з
розділів Texinfo заголовки, з таблиць опцій — пункти, з прикладів — блоки коду.

**Посібник** — файл теки `doc/` з `@settitle`: `ffmpeg`, `ffprobe`, `ffplay`, `ffserver` (до 3.4), `avconv` (лише 0.9),
`ffmpeg-utils`, `ffmpeg-scaler`, `ffmpeg-resampler`, `ffmpeg-codecs`, `ffmpeg-bitstream-filters`, `ffmpeg-formats`,
`ffmpeg-protocols`, `ffmpeg-devices`, `ffmpeg-filters`, сторінки бібліотек `libav*`, `general` (підтримувані формати й
кодеки), `faq`, `developer`, `git-howto`, `fate`, `platform`, `nut`, `mailing-list-faq`, `community`,
`drawvg-reference`. Перелік стоїть у полі `manuals` джерела `ffmpeg-docs`. Зведені `ffmpeg-all` і подібні не
беруться: вони складаються з тих самих частин. До 1.1 компонентів окремими посібниками ще не було — опції форматів і
кодеків стояли в посібниках `ffmpeg` та `libavfilter`.

**Версія** — номер тегу без «n»: `9.0.2`, `5.1.10`. Посібники гілки — це посібники її найновішого сталого випуску;
однакові розділи сусідніх версій зливаються в один фрагмент з усіма версіями. Журнал змін має запис на кожен
випуск, який записали журнали гілок.

Особливості корпусу:

- **Версія посібників — останній тег гілки.** Посібники гілки 5.1 — це посібники 5.1.10; між точковими випусками
  однієї гілки документація майже не змінюється, тож окремі точкові теги не беруться. Журнал змін, навпаки, має
  записи окремих точкових випусків.
- **Журнал змін старих гілок неповний.** У тегах `n0.7.17`, `n0.8.15` і `n1.1.16` файла `Changelog` немає, тож
  точкові 0.7.x, 0.8.x і 1.1.x записів не мають (мажорні 0.7, 0.8 і 1.1 — є, з журналів пізніших гілок). Гілки до 2.3
  записували точкові випуски вибірково, а в `n2.8.22` немає запису самого 2.8.22.
- **Склад посібників змінювався.** Компоненти окремими посібниками — з 1.1; до того опції форматів, кодеків і фільтри
  описував посібник `ffmpeg` (і `libavfilter`). `ffserver` — до 3.4 (з 4.0 його немає), `avconv` — лише 0.9,
  `drawvg-reference` — з 8.1.
- **Довгі таблиці поділено.** Таблиці підтримуваних форматів і кодеків у `general` — сотні рядків; читач ділить їх на
  шматки по 20 рядків, інакше фрагмент мав би 12 тисяч знаків, хвіст яких модель векторів не бачить.
- **Обгортки npm.** README `fluent-ffmpeg` береться з tarball кожної версії, бо реєстр записав коміт лише для 4 з
  51 версії. У `ffmpeg-static` пропущено 2.3.0 і 2.6.0: ні коміту в реєстрі, ні тегу, а tarball 2.x несе бінарники
  всіх платформ. Пакет `fluent-ffmpeg` більше не підтримується, але береться повністю.

## Межі, про які треба пам'ятати

Довідника C API (Doxygen, ffmpeg.org/doxygen), вікі спільноти (trac.ffmpeg.org), документації зовнішніх бібліотек
кодеків (x264, x265, libvpx, libaom) і пакетів операційних систем тут немає. Пакет Debian `ffmpeg` несе ті самі
man-сторінки, зібрані з тих самих `.texi`, тож окремо не береться: Debian 12 bookworm дає FFmpeg 5.1, Debian 13 trixie
— 7.1, Ubuntu 24.04 — 6.1, і ці гілки в корпусі є. Код бібліотек не входить — лише документація.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/ffmpeg-corpus-2026-10-10.tar.gz` (1291 текстів і паспорт). В історії git текстів немає
ніде. Архів лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/ffmpeg-corpus-2026-10-10.tar.gz -C instances/ffmpeg
./df ffmpeg smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/ffmpeg/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/ffmpeg-corpus-РРРР-ММ-ДД.tar.gz -C instances/ffmpeg corpus
find instances/ffmpeg/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/ffmpeg/index/passages.json > instances/ffmpeg/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/ffmpeg/index/passages.json.gz`,
далі `./df ffmpeg vectors` заллє колекцію Qdrant.

## Установка venv

```
cd instances/ffmpeg
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df ffmpeg sources --why        # перелік джерел і білий список
./df ffmpeg refresh ffmpeg-docs ffmpeg-changelog   # заморожені джерела — лише з іменами (близько 40 хвилин)
./df ffmpeg refresh              # решта: сайт і обгортки npm
./df ffmpeg manifest             # оновити паспорт
./df ffmpeg setup                # Qdrant чи пошук лише по словах
./df ffmpeg vectors              # залити корпус у docs-ffmpeg
./df ffmpeg smoke                # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df ffmpeg serve              # порт 8813
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8813/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user ffmpeg-docs http://127.0.0.1:8813/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `ffmpeg-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
