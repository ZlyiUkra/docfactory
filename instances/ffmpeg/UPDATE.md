# Оновлення корпусу ffmpeg

Версії FFmpeg оголошуються руками: посібники (`ffmpeg-docs`) і журнал змін (`ffmpeg-changelog`) читаються з тегів
репозиторію `FFmpeg/FFmpeg`, і перелік тегів стоїть у полі `versions` обох джерел. Тег не змінюється, тож обидва
джерела заморожені (`frozen: true`): `check` і `refresh` без імен їх не чіпають. Обгортки npm беруть версії з реєстру
npm самі. Сторінки ffmpeg.org — чинний стан сайту.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшов новий точковий випуск (9.0.3, 8.1.4 …)

Посібники беруться з найновішого сталого тегу гілки, тож тег гілки в обох джерелах замінюють новим: у
`ffmpeg-docs.versions` і `ffmpeg-changelog.versions` `n9.0.2` → `n9.0.3`. Старі файли тегу, що замінюється, не
видаляються самі: їх переносять у тимчасову теку поза корпусом і видаляють, коли новий набір звірено.

```
./df ffmpeg refresh ffmpeg-docs ffmpeg-changelog   # заморожені — лише з іменами
./df ffmpeg manifest
./df ffmpeg vectors
./df ffmpeg smoke
# Ctrl+C у терміналі з serve, і знову: ./df ffmpeg serve
```

## Вийшла нова гілка (9.1, 10.0 …)

Тег нової гілки дописують першим у `versions` обох джерел; решта — як вище. Після цього:

- у `prompts/search.txt` (абзац «Which version to search first») і `prompts/agent.txt` поточну гілку 9 замінити новою;
- у `checks.json`, у десятці `quality_model`, замінити `"9"` там, де питання про поточну поведінку;
- новий посібник у теці `doc/` (файл з `@settitle`, якого ще немає в полі `manuals`) — дописати в `manuals`, інакше він
  не візьметься. Перевірити: `@settitle` є лише в посібниках, частини (`filters.texi`, `muxers.texi`) його не мають.

## Обгортки npm і сайт

```
./df ffmpeg check                     # незаморожені: сайт і п'ять пакетів npm
./df ffmpeg refresh
./df ffmpeg manifest
./df ffmpeg vectors
./df ffmpeg smoke
```

`refresh` повний, не `--missing`: README, що не змінився, дописує нову версію в рядок `# версія:` наявного документа.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) потрібен для переліку тек `doc/` (37 звернень до API) і README обгорток: без
нього дерева ідуть годинними вікнами по 60 звернень. У `.env` не лишайте порожній рядок `GITHUB_TOKEN=` з
`.env.example`: читається перший збіг, і порожній затуляє справжній.

Формати читають два читачі, додані разом із примірником: `gh-texinfo` (посібники Texinfo) і `changelog-tags` (журнал
«version 7.1.5:»). Якщо FFmpeg змінить розмітку посібників, `refresh` запише документ із залишками команд «@…» —
перевірка: `grep -c '@[a-z]\+{' instances/ffmpeg/corpus/ffmpeg-docs--*.txt`.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df ffmpeg quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
