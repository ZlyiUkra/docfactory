Search the FFmpeg documentation -- every manual of the doc/ folder of the FFmpeg repository at
the newest stable tag of each release branch from 0.6 to 9.0, the XML schema of the ffprobe
output, the Changelog entry of every stable release, the ffmpeg.org news, download, security,
legal and about pages, and the README and npm registry history of the npm wrappers
(ffprobe-static, @ffprobe-installer/ffprobe, fluent-ffmpeg, ffmpeg-static,
@ffmpeg-installer/ffmpeg) -- and return the matching excerpts with the versions each one belongs
to. FFmpeg reads, converts, remuxes and inspects audio and video: the ffmpeg tool (inputs and
outputs, -i, -c copy, -map, -ss, -t, -f, stream specifiers, -filter_complex, encoding options),
the ffprobe tool (-show_format, -show_streams, -show_packets, -show_frames, -show_entries,
-select_streams, -count_frames, -print_format / -of with the default, compact, csv, flat, ini,
json and xml writers, exit codes, the XML schema of its output), the ffplay player, the
formats manual (every muxer and demuxer with its options: mov/mp4 movflags such as +faststart,
frag_keyframe, empty_moov; matroska, hls, dash, segment, tee, image2), the codecs, filters,
protocols, devices, bitstream filters, scaler, resampler and utilities manuals (expression
evaluation, time duration syntax, color names), the list of supported formats and codecs, the
FAQ, and the licensing and security pages.

Call this when a question is about FFmpeg itself -- one option of ffmpeg or ffprobe, the shape of
the ffprobe output, a muxer or demuxer and its flags, a codec, filter or protocol and its
options, an error a command prints, a licensing question -- and above all history and
compatibility: since which version an option, filter or format exists, what changed between
releases, which vulnerabilities a release fixed. Example query: "movflags faststart moov".

Do not call this for the C API of the libraries beyond what these manuals say (the Doxygen
reference is not here), for the external codec libraries (x264, x265, libvpx, libaom) beyond the
FFmpeg wrapper options, for operating system packages, or for other media tools (GStreamer,
HandBrake, MediaInfo): their documentation is not here, and the search will return FFmpeg
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "9" keeps every 9.x document, "5.1" keeps 5.1
and 5.1.x; leave it empty to search everything. Every excerpt comes back with `versions`: each
version whose documents contain this exact text, newest first -- text that stayed the same
across versions is returned once, with all of them listed, so the list itself shows from which
to which version the documentation said exactly this. The manuals are kept for the newest stable
release of each branch (5.1.10 stands for the 5.1 line); the Changelog has an entry for each
point release it recorded.

Write the query in English, with the names FFmpeg itself uses ("show_entries", "print_format",
"movflags", "faststart", "select_streams", "stream specifier", "-c copy", "libx264"), not in the
user's own words. Everything here is English -- the excerpts, the word index and the meaning
index alike -- and the word index keeps only latin letters and digits, so a query written in
Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with
`found: 0`. When the user asks in another language, translate the question into FFmpeg terms
first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists; what changed in later versions;
what prompted the change, if the excerpts say so; and how it stands in the current version. Every
point names the version and the document it rests on; a point the excerpts do not support is left
out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація FFmpeg". Identifiers, options and titles stay in English, spelled
exactly as the documentation spells them. Build the answer out of the excerpts that came back,
not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see below. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the
query had to appear in the text, so a query phrased in other words than the documentation uses
may miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase
had a chance.

Which version to search first. For a question about how to do something today, pass `version`
"9". When the user named a version, or the system it runs on fixes one (Debian 12 bookworm ships
FFmpeg 5.1, Debian 13 trixie ships 7.1, Ubuntu 24.04 ships 6.1), pass that line. Search without
`version` when the question is about history, or when the line gave nothing. Every answer says
which version it is for; when the user did not name one, answer for 9.0 and say so ("for FFmpeg
9.0"), and suggest checking the installed one with `ffmpeg -version`. When the excerpts behind a
statement come only from older versions, name those versions instead of presenting the text as
current.
