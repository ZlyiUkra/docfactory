# Оновлення корпусу flux

Сайт, специфікації й README беруться з закріплених комітів: джерело `flux-site` тримає в полі `tags` голову кожної
гілки `v2-N` репозиторію fluxcd/website, `flux2-docs` — коміти тегів 0.x репозиторію fluxcd/flux2, джерела
контролерів, Flagger, Flux Operator і terraform-provider-flux — коміт останнього тегу `vX.Y.Z` кожної мінорної. Журнали
змін контролерів і релізи GitHub беруться щоразу заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

**Нова версія.** Нова мінорна Flux — новий рядок нагорі `tags` джерела `flux-site`: голова нової гілки `v2-N`
(`git ls-remote --heads https://github.com/fluxcd/website`) і найновіший патч flux2 цієї мінорної; гілка, що
отримала правки, — замінити її коміт. Новий патч чи нова мінорна контролера чи супутнього проєкту — замінити коміт і
версію рядка або додати рядок нагорі `tags` його джерела; версії пишуться з префіксом (`source-controller-`,
`flagger-`, `flux-operator-`, `terraform-`). Коміт тегу дає `git ls-remote --tags https://github.com/fluxcd/<репозиторій>`
(рядок `^{}` — коміт анотованого тегу). Новий контролер — нова пара джерел за зразком наявних.

```
./df flux check                 # чи змінилося щось нагорі за джерелом
./df flux refresh               # повне перезавантаження
./df flux manifest
./df flux vectors
./df flux smoke
# Ctrl+C у терміналі з serve, і знову: ./df flux serve
```

Якщо вийшла нова мінорна Flux (на 26.10.2026 найновіша — 2.10.0) — у `prompts/search.txt` (абзац «Which version to
search first») і `prompts/agent.txt` замінити версію.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df flux quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
