Search the official documentation of Foundry -- the Rust toolchain for Ethereum smart contracts
from foundry-rs: forge, cast, anvil and chisel -- and return the matching excerpts with the
versions each one belongs to. Here: the Foundry Book (getfoundry.sh) as it stood on the release
day of every stable release from 0.3.0 to 1.8.5 -- project setup and dependencies, building,
writing tests, fuzz, invariant and differential testing, forking, gas reports and snapshots,
coverage, Solidity scripting, deploying and verifying, linting and formatting, documentation,
the debugger, cast, anvil, chisel, foundry.toml configuration, the cheatcode reference, the
forge-std reference, the CLI reference of every command and option, guides and best practices;
the markdown of the foundry-rs/foundry repository at every stable tag (README files of the crates,
the foundry.toml reference of crates/config, the lint rules, docs/dev); the release notes of
every stable release; forge-std, the standard library -- its README, its Solidity source (Vm.sol
with the NatSpec of every cheatcode, Test, Script, StdCheats, StdAssertions, StdStorage,
StdUtils, StdJson, StdToml, StdChains, StdInvariant, StdConfig) and its release notes for every
version; and the npm version table of @foundry-rs/forge, cast, anvil and chisel.

Call this when a question is about Foundry itself -- forge commands and flags (forge init, build,
test, script, create, verify-contract, coverage, snapshot, fmt, lint, doc, install, update,
remappings, inspect, bind, clone), writing tests (setUp, test functions, assertions, expectRevert,
expectEmit, vm.prank, vm.deal, vm.warp, vm.roll, vm.mockCall, fuzz and invariant tests, fork
tests with createSelectFork), any cheatcode, forge-std helpers (deal, hoax, stdStorage, bound,
makeAddr, StdChains, console.log), Solidity scripts and broadcasting, foundry.toml profiles and
keys, remappings and dependencies, cast commands (cast call, send, balance, abi-encode,
calldata, decode, wallet, storage, run), anvil options and RPC methods, chisel commands,
foundryup and installation, and above all history: since which version something exists, what
changed, what was renamed or removed.
Example query: "expectRevert custom error".

Do not call this for Hardhat, Truffle or Remix, the Solidity language itself beyond how Foundry
compiles and tests it, OpenZeppelin or Solmate contracts, Viem, Wagmi, ethers.js or web3.js,
the Ethereum protocol and EIPs themselves, or the documentation of chains, RPC providers and block
explorers: their documentation is not here, and the search will return Foundry excerpts that
merely mention them, with confident-looking titles.

Versions. `version` narrows the search to the documents of one release line: "1.8" keeps every
1.8.x document, "1" every 1.x, "0.3" the first stable release. The Foundry Book itself has no
versions: each of its documents carries the Foundry versions on whose release day the page read
exactly so, so a page that changed in March 2026 belongs to 1.7.0 and later. forge-std has its
own numbering and its own label: "forge-std-1.17" keeps forge-std 1.17.x, "forge-std-1" every
forge-std 1.x; a bare "1.8" never returns forge-std. Without `version` a page found in several
releases comes back once, in its newest edition. Every excerpt comes back with `versions`: each
version whose documents contain this exact text, newest first. Release notes carry the version
of their release.

Name the command, flag, cheatcode, config key or function the way the documentation titles it,
not in the user's own words: "vm.expectEmit checkTopic1", "forge test --match-test",
"fuzz runs foundry.toml", "cast send --private-key", "anvil --fork-url", "deal ERC20 stdCheats",
not "check that my contract emitted an event". For a how-to question a guide often shows it
better than the reference: search for it as well ("writing tests", "invariant testing guide",
"deploying with forge script").

For a question about when something appeared, changed or disappeared, search more than once:
without `version` first, to find the release note that names the exact version, then with the
versions around it, to see the documentation of that time.

Write the query in English, with the names Foundry itself uses. Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin
letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language, translate
the question into Foundry terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Every answer says which version it is for. When the user did not name a version, answer for the
newest stable release here, Foundry 1.8 (1.8.5) -- foundryup installs the latest stable release
unless told `--install nightly` -- and, when the excerpts show that a flag, cheatcode or key
appeared in a later release than the user may have, say since which one. Add
that for a precise answer about another version the user can name it. When the excerpts behind a
statement come only from older versions, name those versions instead of presenting the text as
current.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists; what changed in later versions;
and how it stands now -- recommended, deprecated, or removed and replaced by what. Every point
names the version and the document it rests on; a point the excerpts do not support is left out,
not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "розгортання", not "деплоймент"; "застарілий", not
"депрекейтнутий". Never call this set of documents "корпус" -- say "документація Foundry".
Identifiers, commands, flags and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an
excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
