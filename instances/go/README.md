# go — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про мову Go: специфікація, модель пам'яті, стандартна бібліотека й
команди інструментарію в кожній мінорній версії, сайт go.dev (документація, довідники, блог, «A Tour of Go»), доповіді
команди Go, вікі, проєктні документи пропозицій, gopls, а поруч — «Go by Example», «Learn Go with Tests», настанови
зі стилю Google і Uber, запитання до співбесіди й окремо виділена підготовка до сертифікації Ardan Labs. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Go — компільована мова зі статичною типізацією, збиранням сміття й легкими потоками — горутинами (goroutines), що
обмінюються даними каналами (channels). Мову описує одна специфікація (go.dev/ref/spec), а обіцянка сумісності Go 1
(go1compat) гарантує, що програма, написана під Go 1.0, збирається й новими версіями. Через це історія мови — це
історія доповнень: дженерики (type parameters) з 1.18, нова область видимості змінної циклу з 1.22, ітератори
`range over func` з 1.23, пакети `slices` і `maps` з 1.21. Питання «з якої версії» тут звичайне, тож специфікація,
стандартна бібліотека й команди лежать на кожну мінорну версію окремо.

Поруч стоїть локальний примірник `learning-go` ([README](../learning-go/README.md)): книжки «Learning Go» Джона
Боднера і «Go by Example» Інанца Гумуса, «100 Go Mistakes» і «Go 101». Їх тримають окремо, бо права на книжки не
дозволяють публікувати корпус.

RACE`). Пошук за змістом промахується на запитах своїми словами про `context.WithTimeout`, імена отримувачів,
обгорнуті помилки й детектор гонитви: його видача — сусідні теми (скасування запитів до бази, вибір отримувача,
місце `%w` у тексті помилки).

Чого немає:

- Пререлізів (`beta`, `rc`) і проміжних патчів: кожна мінорна — останнім патчем.
- Внутрішніх пакетів (`internal/`, `vendor/`) стандартної бібліотеки і підпакетів команд (`cmd/go/internal/…`).
- Сторінки `cmd/preprofile` у 1.23: pkg.go.dev не показує для неї розділу документації.
- Пакетів `golang.org/x/…` (errgroup, x/net, x/tools), сторонніх бібліотек і фреймворків (Gin, Echo, Chi, GORM, pgx,
  testify), вихідного коду Go.
- Сторінок-переадресацій блогу й вікі, сторінок `go.dev/doc/devel`, чорнових нотаток ще не випущеної 1.28.
- Книжок: вони в примірнику `learning-go`.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df go <крок>`.

**Стандартна бібліотека.** pkg.go.dev тримає документацію кожного випуску за адресою `<пакет>@goX.Y.Z`: оголошення,
коментарі, приклади й позначку «added in go1.21.0» біля кожної нової назви. Читач `pkgsite` з полем `versions` бере
перелік пакетів кожної версії зі сторінки `std@goX.Y.Z` і саму сторінку кожного пакета. Однаковий текст пакета в
кількох версіях стає одним документом із переліком цих версій (у назві файла — сума тексту, `std--context-1e02c7f1`).
Сторінку, на якій pkg.go.dev не показує розділу документації, читач пропускає вголос, а не обриває всю версію.

**Сайт go.dev** будується з репозиторію golang/website, і його сторінки — не чистий markdown. Читач
`ghdocs-history-godev` розгортає шаблонні вставки `{{code}}` і `{{play}}` (код береться з файла поруч за адресою чи
регулярним виразом, рядки `OMIT` викидаються), читає JSON-шапку сторінок `.html`, переводить формат present
(`.article`, `.slide` — Tour і доповіді) у markdown і пропускає сторінки-переадресації. Для Go by Example він
перетворює кожен приклад на текст: коментарі — прозою, код — блоком `go`, а вивід терміналу з файла `.sh` — окремим
блоком. Цитуються сторінки адресами go.dev (поле `site`), стандартна бібліотека — адресами pkg.go.dev.

## Підготовка до сертифікації

Офіційного сертифіката Go від Google чи команди Go немає. Іспит з Go проводить Ardan Labs, компанія Білла Кеннеді,
автора курсу «Ultimate Go» (з квітня 2025): 100 запитань з вибором відповіді за 90 хвилин, прохідний бал 80%, онлайн
з вебкамерою, $99 за спробу, сертифікат дійсний два роки. Запитання складено з навчальних матеріалів Ardan Labs.

Безкоштовна частина цих матеріалів — репозиторій ardanlabs/gotraining (Apache-2.0), матеріал класу Ultimate Go:
нотатки до кожної теми (механіка мови, семантика значень і вказівників, дизайн, конкурентність, тести, профілювання,
пакети) і код прикладів, де пояснення стоять у коментарях. Поруч — ardanlabs/service, сервіс-зразок курсу «Ultimate
Service»: шари `app`, `business`, `foundation`, опис архітектури для агентів і сам код. Обидва джерела виділено:

- id документів починаються з `cert-` (`cert-gotraining--…`, `cert-gotraining-code--…`, `cert-service--…`,
  `cert-service-code--…`);
- назви — з «Ardan Labs Ultimate Go (certification prep)» або «Ardan Labs Ultimate Service (certification prep)»,
  тож у видачі їх видно одразу;
- промпт каже моделі назвати такий уривок матеріалом сертифікації, а для підготовки до іспиту шукати словами курсу
  (value semantics, escape analysis, mechanical sympathy, data race, profiling) і відповідати спершу з курсу, потім з
  офіційної документації.

Прогалина: матеріал задуманий для класу з лектором, і контекст, який той дає вголос, у нотатках відсутній. Його
закривають офіційні тексти цього примірника й книжка «Learning Go» (примірник `learning-go`).

## Версії

Версію Go (`1.27.3`) несуть стандартна бібліотека, команди, тексти `doc/` (специфікація, модель пам'яті й решта) і
нотатки випусків сайту (`go1.22` — версія 1.22). Решта — поточна редакція без версії. Фільтр `version` приймає мінор
(`"1.22"`) або точну версію (`"1.22.12"`) і лишає у видачі лише документи з версією. Промпт відповідає для найновішої
Go 1.27.3, якщо користувач не назвав старішу, і в кожній відповіді про мову, бібліотеку чи команди каже, для якої
версії вона.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/go-corpus-2026-10-27-titles.tar.gz` (3901 текст, паспорт і сховище сирого
`raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\go-corpus-2026-10-27-titles.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/go/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/go-corpus-РРРР-ММ-ДД.tar.gz -C instances/go corpus raw
find instances/go/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/go/raw
gzip -9 -c instances/go/index/passages.json > instances/go/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/go-corpus-2026-10-27-titles.tar.gz -C instances/go
./df go smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/go/index/passages.json.gz`.
Далі `./df go vectors` заллє колекцію Qdrant: пів хвилини на відеокарті, кілька хвилин на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df go …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df go sources --why   # перелік джерел і білий список
./df go refresh         # завантажити все задеклароване (близько трьох годин: ~4 800 сторінок pkg.go.dev)
./df go manifest        # оновити паспорт
./df go setup           # Qdrant чи пошук лише по словах
./df go vectors         # залити корпус у docs-go
./df go smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df go serve          # порт 8913
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8913/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user go-docs http://127.0.0.1:8913/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `go-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
