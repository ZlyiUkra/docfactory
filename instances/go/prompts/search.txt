Search the documentation of the Go programming language: the language specification (go.dev/ref/spec), the Go memory
model (go.dev/ref/mem), the Go 1 compatibility promise, the assembler guide and the GODEBUG settings, each as it stood
in every minor release from Go 1.0 to Go 1.27 (the last patch of each: 1.0.3 ... 1.27.3); the reference of the whole
standard library from pkg.go.dev in every one of those 28 releases, one document per package (`fmt`, `errors`,
`context`, `sync`, `sync/atomic`, `net/http`, `encoding/json`, `database/sql`, `io`, `os`, `time`, `strings`,
`slices`, `maps`, `iter`, `log/slog`, `testing`, `embed`, `unique`, `weak` ...) with every constant, variable,
function, type and method, its declaration and its examples, and the note of the release that added it ("added in
go1.21.0"); the reference of the commands of the toolchain from Go 1.4 to Go 1.27 (`go` -- the whole of `go help`:
build, run, test, mod, work, get, install, vet, generate, env, the module and workspace modes, GOPROXY, GOFLAGS,
GOTOOLCHAIN, build constraints, test flags --, `gofmt`, `vet`, `cgo`, `compile`, `link`, `pprof`, `trace`, `cover`
and the others); the site go.dev -- Effective Go, the FAQ, the tutorials (getting started, modules, generics, fuzzing,
workspaces, database access, a RESTful web service with Gin), the Go Modules Reference and the go.mod reference,
developing and publishing modules, the database/sql guides, security (best practices, vulnerability management,
govulncheck, fuzzing), diagnostics, the GC guide, profile-guided optimization, toolchains, telemetry, and the release
notes of every release Go 1 to Go 1.27; the go.dev blog since 2009; A Tour of Go; the talks of the Go team (Go
Concurrency Patterns, Advanced Go Concurrency Patterns and more); the Go wiki (CodeReviewComments, CommonMistakes,
TableDrivenTests, SliceTricks, Modules, LoopvarExperiment ...); the design documents of Go proposals (generics, loop
variable scope, range over func, modules, context, error values ...); the documentation of gopls, the Go language
server. Next to the official texts: "Go by Example" (Mark McGranaghan, gobyexample.com), "Learn Go with Tests" (Chris
James), the Google Go Style Guide and the Uber Go Style Guide, and the Go Interview Guide (rixtrayker/golang-interview:
questions and answers for a Go developer interview). Returns the matching excerpts with the versions each one belongs
to.

Call this when a question is about Go itself: what the specification says about a construct (assignability,
conversions, method sets, type parameters and constraints, type inference, the `for` statement and `range`, `defer`,
`go`, `select`, `switch`, constants and iota, struct embedding, the zero value, package initialization), what the memory
model guarantees about goroutines, channels and `sync`; what a standard library function, type or method does, how
to call it and since which release it exists; what a `go` command or flag does; how modules, `go.mod`, `go.work`,
versions and the module proxy work; how to write, test, benchmark, fuzz, profile and secure Go code; idiomatic style
and review comments; what changed in a release; why the language was designed the way it is; how to prepare for a Go
interview.

Do not call this for third-party Go libraries and frameworks (Gin, Echo, Chi, Fiber, GORM, sqlx, pgx, testify,
gorilla/websocket, cobra, viper, zap, logrus, gRPC-Go), for the packages of golang.org/x (x/sync errgroup, x/net,
x/tools, x/crypto) beyond what the official pages say about them, for Go's own source code, or for other languages:
their documentation is not here, and the search will return excerpts that merely mention them, with confident-looking
titles. The book "Learning Go" by Jon Bodner is not here either: it has its own server.

`version` narrows the search to one release: two numbers keep a minor ("1.22" keeps every 1.22 document), three an
exact version ("1.22.12"); only the specification, the memory model and the other texts of doc/, the standard
library, the commands and the release notes carry versions, so a `version` leaves the site, the blog, the Tour, the
talks, the wiki, the proposals and the books out of the results. A text unchanged across releases carries all of
them. Every excerpt comes back with `versions`: each release whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("method set", "type parameters", "type
constraint", "comparable", "type inference", "zero value", "short variable declaration", "composite literal",
"slice expression", "append", "copy", "clear", "min", "max", "range over function", "iterator", "iter.Seq",
"goroutine", "channel", "select statement", "unbuffered channel", "happens before", "data race", "sync.WaitGroup",
"sync.Mutex", "sync.Once", "context.WithCancel", "context.WithTimeout", "errors.Is", "errors.As", "fmt.Errorf %w",
"panic", "recover", "defer", "embedding", "interface", "type assertion", "type switch", "init function",
"internal packages", "go.mod", "go.work", "GOPROXY", "minimal version selection", "go test -race", "t.Run",
"testing.B", "b.Loop", "fuzz test", "http.ServeMux", "http.Handler", "http.HandlerFunc", "log/slog",
"encoding/json struct tags", "database/sql", "sql.DB", "go:embed", "go vet", "gofmt"), not in the user's own words.
Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index keeps
only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing
at all and comes back with `found: 0`. When the user asks in another language, translate the question into the terms
of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer point by
point: since which release it exists; what changed in later releases; what prompted the change, if the excerpts say
so; and how it stands in the current release. Every point names the release and the document it rests on; a point the
excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer
writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "горутина", "канал", "зріз", "відображення" (map), "інтерфейс", "вбудовування". Never call this
set of documents "корпус" -- say "документація Go". Identifiers, keywords, package names and titles stay in English,
spelled exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out of
memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Go 1.27.3 is the newest release; Go 1.28 is not released yet and is not here. Search
without `version` first; when the user names their Go version, search that release ("1.21"). Every answer about the
language, the standard library or the commands says which release it is for.
