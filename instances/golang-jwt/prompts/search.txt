Search the documentation of golang-jwt (github.com/golang-jwt/jwt), the Go implementation of JSON Web Tokens: the site
golang-jwt.github.io/jwt (introduction, creating a token, parsing and validating, signing methods); the README,
MIGRATION_GUIDE, VERSION_HISTORY and SECURITY documents at every minor release 3.0 ... 5.3; the GitHub release notes;
and the package reference from pkg.go.dev for every minor release of v5 (5.0 ... 5.3) and v4 (4.0 ... 4.5) -- Token,
Claims, RegisteredClaims, MapClaims, NumericDate, ClaimStrings, New, NewWithClaims, SignedString, Parse,
ParseWithClaims, Parser, NewParser, ParserOption (WithValidMethods, WithLeeway, WithExpirationRequired, WithIssuer,
WithAudience, WithSubject, WithIssuedAt, WithJSONNumber, WithoutClaimsValidation), Keyfunc, the signing methods
(SigningMethodHS256, RS256, ES256, EdDSA, PS256, none), the errors (ErrTokenExpired, ErrTokenSignatureInvalid,
ErrTokenMalformed, ErrTokenNotValidYet) and ClaimsValidator -- with descriptions and examples. Returns the matching
excerpts with the versions each one belongs to.

Call this when a question is about JSON Web Tokens in Go with golang-jwt: creating and signing a token, choosing a
signing method and key type, parsing and validating a token, restricting the accepted algorithms, the expiration,
not-before and issued-at checks and clock skew (leeway), custom claims, audience and issuer checks, telling an expired
token from a forged one by its error, and migrating from v4 to v5.

Do not call this for the JWT and JOSE specifications themselves (RFC 7519, RFC 7515 -- the standards documentation),
for OAuth 2.0 or OpenID Connect, for other JWT libraries (lestrrat-go/jwx, go-jose), for password hashing or for other
languages: their documentation is not here, and the search will return excerpts that merely mention them, with
confident-looking titles.

`version` narrows the search to one release: one number keeps a major line ("5" or "4"), two a minor ("5.2"), three an
exact version ("5.2.3"). The site has no version: a `version` leaves it out. Every excerpt comes back with `versions`:
each release whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("NewWithClaims", "SignedString",
"RegisteredClaims", "MapClaims", "ParseWithClaims", "Keyfunc", "WithValidMethods", "WithLeeway",
"WithExpirationRequired", "WithAudience", "ErrTokenExpired", "ErrTokenSignatureInvalid", "SigningMethodHS256",
"SigningMethodRS256", "SigningMethodEdDSA", "ClaimsValidator", "NumericDate", "migration guide v5"), not in the user's
own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question into the
terms of the documentation first, then search.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "токен", "підпис", "ключ", "термін дії", "перевірка". Never call this set of documents "корпус" -- say
"документація golang-jwt". Identifiers and titles stay in English, spelled exactly as the documentation spells them.
Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it
before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. golang-jwt 5.3.1 is the newest release; v4 (4.5.2) is in existing code. Search without
`version` first; when the user's code imports github.com/golang-jwt/jwt/v4, search with version "4". Every answer says
which major version it is for.
