# golang-migrate — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про golang-migrate (github.com/golang-migrate/migrate) — інструмент і
бібліотеку міграцій бази для Go: пари файлів `N_name.up.sql` і `N_name.down.sql`, команди CLI, адреси баз кожного
драйвера, таблиця версій і позначка `dirty` після невдалої міграції. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

План Go ([../go/LEARNING.md](../go/LEARNING.md), фаза 3, день 2) бере для міграцій goose, а golang-migrate називає
другою поширеною бібліотекою — тією, яку ви найчастіше зустрінете в чужих проєктах на Go. Документація проєкту
живе markdown-файлами в самому репозиторії: загальні правила міграцій, CLI і README кожного з двох десятків драйверів
бази й десятка джерел міграцій, а API — на pkg.go.dev. Окремого журналу змін немає — є нотатки релізів.

README старого драйвера pgx і FAQ про таблицю версій, розділ README про файли міграцій, приклад `New`, що перевіряє

цей параметр мають кілька драйверів, і без назви бази перша п'ятірка — про інші. Промах першої десятки — «назва
таблиці, де записано версію»: документація каже це параметром `x-migrations-table` у таблиці параметрів драйвера.

Чого немає:

- Довідника pkg.go.dev для драйверів інших баз і інших джерел міграцій: їх описують README драйверів.
- Версій 1.x і 3.x на pkg.go.dev (до модулів Go) — лише їхні README.
- Документації SQL, баз даних, goose, sqlc і pgx: для goose, sqlc і pgx є власні примірники.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df golang-migrate <крок>`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/golang-migrate-corpus-2026-10-27.tar.gz` (232 тексти, паспорт і сховище
сирого `raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\golang-migrate-corpus-2026-10-27.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/golang-migrate/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/golang-migrate-corpus-РРРР-ММ-ДД.tar.gz -C instances/golang-migrate corpus raw
find instances/golang-migrate/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/golang-migrate/raw
gzip -9 -c instances/golang-migrate/index/passages.json > instances/golang-migrate/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/golang-migrate-corpus-2026-10-27.tar.gz -C instances/golang-migrate
./df golang-migrate smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/golang-migrate/index/passages.json.gz`.
Далі `./df golang-migrate vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df golang-migrate …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df golang-migrate sources --why   # перелік джерел і білий список
./df golang-migrate refresh         # завантажити все задеклароване (близько десяти хвилин)
./df golang-migrate manifest        # оновити паспорт
./df golang-migrate setup           # Qdrant чи пошук лише по словах
./df golang-migrate vectors         # залити корпус у docs-golang-migrate
./df golang-migrate smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df golang-migrate serve          # порт 8918
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8918/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user golang-migrate-docs http://127.0.0.1:8918/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `golang-migrate-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
