Search the documentation of golang-migrate (github.com/golang-migrate/migrate), the database migration tool and
library for Go: the README, GETTING_STARTED, MIGRATIONS and FAQ documents, the CLI README, and the README of every
database driver (postgres, pgx, mysql, sqlite3, sqlite, sqlserver, clickhouse, cockroachdb, mongodb, cassandra,
spanner, redshift and others) and every migration source (file, iofs, github, gitlab, s3, gcs, httpfs, go_bindata)
at every minor release 1.2 ... 4.20; the GitHub release notes of every stable release; and the package reference
from pkg.go.dev for every minor release 4.0 ... 4.20 -- package migrate (New, NewWithDatabaseInstance,
NewWithSourceInstance, Up, Down, Steps, Migrate, Force, Version, Drop, ErrNoChange, ErrDirty), the database and source
interfaces, the postgres and pgx/v5 drivers and the file and iofs sources. Returns the matching excerpts with the
versions each one belongs to.

Call this when a question is about database migrations with golang-migrate: the pair of files
NNN_name.up.sql and NNN_name.down.sql, sequential and timestamp versions, running migrations from the CLI or from Go
code, the database URL of each driver and its query parameters (x-migrations-table, sslmode, x-multi-statement), the
schema_migrations table and the dirty flag, fixing a failed migration with force, embedding migrations with iofs and
go:embed, locking, and what changed between releases.

Do not call this for SQL itself or the database servers (their own documentation), for goose, Atlas, dbmate or other
migration tools, for sqlc or pgx beyond what golang-migrate's pages say about them, or for other languages: their
documentation is not here, and the search will return excerpts that merely mention them, with confident-looking
titles.

`version` narrows the search to one release: one number keeps a major line ("4"), two a minor ("4.18"), three an exact
version ("4.18.3"). Every excerpt comes back with `versions`: each release whose documents contain this exact text,
newest first. Without `version` the newest text comes first.

Write the query in English, with the names the documentation itself uses ("up.sql", "down.sql", "migrate create",
"-seq", "-ext sql", "-dir", "migrate up", "migrate down", "migrate force", "migrate goto", "dirty database",
"ErrDirty", "ErrNoChange", "schema_migrations", "x-migrations-table", "x-multi-statement", "sslmode", "postgres://",
"pgx5://", "file://", "iofs", "go:embed", "NewWithDatabaseInstance", "WithInstance", "Steps", "Force", "Version"),
not in the user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike --
and the word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "міграція", "відкат", "драйвер", "рядок з'єднання". Never call this set of documents "корпус" -- say
"документація golang-migrate". Identifiers, commands and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. golang-migrate 4.20.1 is the newest release. Search without `version` first; when the
user names their version, search that release. Every answer says which release it is for.
