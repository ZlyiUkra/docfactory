# golang-x — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про три модулі golang.org/x — пакети проєкту Go поза стандартною
бібліотекою: `golang.org/x/crypto` (лише `argon2` і `bcrypt`), `golang.org/x/sync` (`errgroup`, `semaphore`,
`singleflight`, `syncmap`) і `golang.org/x/time` (`rate`). Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

План Go ([../go/LEARNING.md](../go/LEARNING.md)) бере з golang.org/x три речі, яких немає в стандартній бібліотеці:
хеш пароля Argon2id чи bcrypt (фаза 4, день 1), групу горутин зі спільною помилкою й межею паралельності `errgroup`
(фаза 0, день 15) і обмежувач частоти `rate` (фаза 4, день 11). Документація цих пакетів — лише коментарі коду на
pkg.go.dev, і в примірнику `go` їх немає: він тримає стандартну бібліотеку.

## Скільки цього

| Шар | Документів | Версій | Звідки |
|-----|-----------:|-------:|--------|
| x/crypto: argon2, bcrypt | 5 | 58 | pkg.go.dev, `golang.org/x/crypto@v0.N.0`, кожна мінорна 0.1–0.58 |
| x/sync: errgroup, semaphore, singleflight, syncmap | 19 | 24 | pkg.go.dev, кожна мінорна 0.1–0.24 |
| x/time: rate | 3 | 16 | pkg.go.dev, кожна мінорна 0.1–0.16 |

Документів набагато менше, ніж версій: ці пакети змінюються рідко, і однаковий текст пакета на кількох версіях — один
документ з усіма версіями (argon2 і bcrypt за 58 версій мали по два-три різні тексти).

Разом 27 записів паспорта. В індексі 120 фрагментів (`expected_passages` у `checks.json`) із 26 документів. Замір
`quality`: по словах 9 із 10, за змістом 10, разом 10, «як модель» 10 із 10. До запиту «запустити горутини разом і
зупинити всі на першій помилці» додано справжні відповіді — опис типу `Group` і методів `Go` та `Wait`.

Чого немає:

- Решти пакетів x/crypto (ssh, acme, nacl, chacha20poly1305 тощо) і решти модулів golang.org/x (x/net, x/tools, x/text,
  x/oauth2).
- Стандартної бібліотеки (`crypto/rand`, `sync`, `context`, `time`) — вона в примірнику `go`.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df golang-x <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| x/crypto | pkg.go.dev, `golang.org/x/crypto@v0.N.0` (корінь модуля — перелік пакетів), пакети `argon2` і `bcrypt`, 58 версій | `pkgsite` (`versions`) |
| x/sync | pkg.go.dev, `golang.org/x/sync@v0.N.0`, усі пакети, 24 версії | `pkgsite` (`versions`) |
| x/time | pkg.go.dev, `golang.org/x/time@v0.N.0`, пакет `rate`, 16 версій | `pkgsite` (`versions`) |

Корінь кожного модуля — не пакет, а перелік підпакетів (розділ Directories); документом він не стає, і з нього читач
бере сторінки пакетів тієї самої версії. Поле `exclude` джерела `crypto` лишає з кількох десятків пакетів лише
`argon2` і `bcrypt`. Цитуються сторінки pkg.go.dev з версією.

## Версії

Модулі мають кожен свою нумерацію 0.x: x/crypto 0.58.0, x/sync 0.24.0, x/time 0.16.0 — найновіші на 27.10.2026.
Фільтр `version` приймає мінор (`"0.58"`) або точну версію; та сама версія може належати двом модулям, тож промпт
просить називати пакет.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/golang-x-corpus-2026-10-27.tar.gz` (27 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\golang-x-corpus-2026-10-27.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/golang-x/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/golang-x-corpus-РРРР-ММ-ДД.tar.gz -C instances/golang-x corpus raw
find instances/golang-x/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/golang-x/raw
gzip -9 -c instances/golang-x/index/passages.json > instances/golang-x/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/golang-x-corpus-2026-10-27.tar.gz -C instances/golang-x
./df golang-x smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/golang-x/index/passages.json.gz`.
Далі `./df golang-x vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df golang-x …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df golang-x sources --why   # перелік джерел і білий список
./df golang-x refresh         # завантажити все задеклароване (близько п'ятнадцяти хвилин: ~330 сторінок pkg.go.dev)
./df golang-x manifest        # оновити паспорт
./df golang-x setup           # Qdrant чи пошук лише по словах
./df golang-x vectors         # залити корпус у docs-golang-x
./df golang-x smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df golang-x serve          # порт 8920
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8920/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user golang-x-docs http://127.0.0.1:8920/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `golang-x-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
