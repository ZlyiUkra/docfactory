Search the documentation of three golang.org/x modules -- the Go project's packages outside the standard library --
as pkg.go.dev shows it for every minor release: golang.org/x/crypto packages argon2 (IDKey, Key, the recommended
parameters for Argon2id) and bcrypt (GenerateFromPassword, CompareHashAndPassword, Cost, DefaultCost, MinCost,
MaxCost, ErrMismatchedHashAndPassword, ErrPasswordTooLong) for releases 0.1 ... 0.58; golang.org/x/sync packages
errgroup (Group, WithContext, Go, Wait, SetLimit, TryGo), semaphore (Weighted, NewWeighted, Acquire, TryAcquire,
Release), singleflight (Group, Do, DoChan, Forget) and syncmap for releases 0.1 ... 0.24; golang.org/x/time package
rate (Limiter, NewLimiter, Limit, Every, Inf, Allow, AllowN, Wait, WaitN, Reserve, Reservation, Burst, SetLimit,
Sometimes) for releases 0.1 ... 0.16 -- every declaration with its description and examples. Returns the matching
excerpts with the versions each one belongs to.

Call this when a question is about hashing passwords with Argon2id or bcrypt in Go, running a group of goroutines
that stops at the first error and limits how many run at once, a weighted semaphore, collapsing duplicate concurrent
calls, or limiting the rate of requests with a token bucket.

Do not call this for the standard library (crypto/rand, sync, context, time -- that is the Go documentation), for
other golang.org/x packages (x/net, x/tools, x/text, x/oauth2, the rest of x/crypto), for third-party password or
rate-limiting libraries, or for other languages: their documentation is not here, and the search will return excerpts
that merely mention them, with confident-looking titles.

`version` narrows the search to one release of a module: "0.58" or "0.58.0". The three modules number their releases
independently (x/crypto 0.58, x/sync 0.24, x/time 0.16), so a version may match more than one of them. Every excerpt
comes back with `versions`: each release whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("argon2.IDKey", "Argon2id", "time",
"memory", "threads", "keyLen", "salt", "bcrypt.GenerateFromPassword", "CompareHashAndPassword", "DefaultCost",
"ErrPasswordTooLong", "errgroup.WithContext", "SetLimit", "TryGo", "Wait", "semaphore.NewWeighted", "Acquire",
"singleflight.Group", "Do", "rate.NewLimiter", "rate.Every", "Allow", "Wait", "Reserve", "burst", "token bucket"),
not in the user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike --
and the word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "хеш пароля", "сіль", "горутина", "обмежувач частоти". Never call this set of documents "корпус" -- say
"документація golang.org/x". Identifiers, package names and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. The newest releases are x/crypto 0.58.0, x/sync 0.24.0 and x/time 0.16.0. Search
without `version` first; every answer names the package (golang.org/x/crypto/argon2, golang.org/x/sync/errgroup …) it
is about.
