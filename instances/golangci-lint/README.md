# golangci-lint — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про golangci-lint (golangci/golangci-lint) — швидкий запускач лінтерів
і форматерів Go: встановлення закріпленої версії локально й у CI, файл `.golangci.yml` версії 2, лінтери й форматери
та їхні налаштування, хибні спрацювання й `nolint`, винятки, лише нові проблеми для великих проєктів, плагіни, перехід
з v1. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену.
Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

У плані Go ([../go/LEARNING.md](../go/LEARNING.md)) golangci-lint з'являється у фазі 0 (день інструментів), стає
строгішим у фазі 5 (`gosec`, `bodyclose`, `noctx`, `errorlint`) і працює в CI фази 6 дією `golangci-lint-action`. У
2.0 формат конфігурації змінився повністю (лінтери й форматери окремо, `exclusions` замість `issues.exclude-*`), а
статті й чужі проєкти досі показують v1, тож сайт лежить на кожну мінорну 2.x, а журнал змін — обох ліній.

| Дані сайту | 5 | — | `docs/data` гілки main: перелік лінтерів і форматерів, пресети винятків, довідка CLI, опис файла конфігурації |
| Журнал змін v2 | 40 | 40 | `CHANGELOG.md` гілки main, по запису на випуск 2.x |
| Журнал змін v1 | 66 | 66 | `CHANGELOG-v1.md` гілки main, по запису на випуск 1.x |

Разом 156 записів паспорта. В індексі 387 фрагментів (`expected_passages` у `checks.json`) із 138 документів. Замір
`quality`: по словах 7 із 10, за змістом 9, разом 9, «як модель» 10 із 10. Цілі доповнено справжніми відповідями: FAQ
про `new-from-rev`, перелік форматерів і розділ посібника переходу про форматери, розділи посібника про налаштування
`errcheck`. Промах першої десятки — «який лінтер знаходить неперевірені помилки»: відповідь лежить у переліку
лінтерів, а він — один великий фрагмент JSON, і пошук своїми словами його не впізнає.

Чого немає:

- Еталонного файла `.golangci.reference.yml` з коментарями до кожного налаштування кожного лінтера: він більший за межу
  читача коду (40 КБ). Опис налаштувань лінтерів дає сторінка «Linters Settings» сайту там, де вона не згенерована з
  цього файла.
- Документації самих лінтерів (staticcheck, revive, gosec) і сайту v1 (інша збірка, Gatsby).
- `go vet` і gopls — вони в примірнику `go`.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df golangci-lint <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт | дерева 16 тегів golangci/golangci-lint (2.0.2–2.15.0): `docs/content` | `ghdocs-history` (`hugo`) |

Сайт зібрано Hugo; поле `hugo` розгортає вставки з теки `docs/content/includes` і знімає решту шорткодів (картки,
кнопки), лишаючи текст. Таблиці лінтерів сайт будує з `docs/data/linters_info.json` — тому ці дані лежать окремим
джерелом. Цитуються сторінки golangci-lint.run/docs/… (поле `site`).

## Версії

Сайт і журнали несуть версію golangci-lint (`2.15.0`); дані сайту — без версії. Фільтр `version` приймає мажор (`"2"`,
`"1"`), мінор (`"2.15"`) або точну версію. Промпт відповідає для 2.15.0 і нагадує, що v1-конфігурацію переводять
командою `golangci-lint migrate`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/golangci-lint-corpus-2026-10-27.tar.gz` (156 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\golangci-lint-corpus-2026-10-27.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/golangci-lint/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/golangci-lint-corpus-РРРР-ММ-ДД.tar.gz -C instances/golangci-lint corpus raw
find instances/golangci-lint/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/golangci-lint/raw
gzip -9 -c instances/golangci-lint/index/passages.json > instances/golangci-lint/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/golangci-lint-corpus-2026-10-27.tar.gz -C instances/golangci-lint
./df golangci-lint smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/golangci-lint/index/passages.json.gz`.
Далі `./df golangci-lint vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df golangci-lint …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df golangci-lint sources --why   # перелік джерел і білий список
./df golangci-lint refresh         # завантажити все задеклароване (дві-три хвилини)
./df golangci-lint manifest        # оновити паспорт
./df golangci-lint setup           # Qdrant чи пошук лише по словах
./df golangci-lint vectors         # залити корпус у docs-golangci-lint
./df golangci-lint smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df golangci-lint serve          # порт 8925
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8925/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user golangci-lint-docs http://127.0.0.1:8925/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `golangci-lint-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
