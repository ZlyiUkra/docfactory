pressly.github.io/goose -- installation, the documentation pages (SQL file annotations -- +goose Up, +goose Down,
+goose StatementBegin, +goose StatementEnd, +goose NO TRANSACTION, +goose ENVSUB ON; the CLI commands up, up-by-one,

environment variables GOOSE_DRIVER, GOOSE_DBSTRING, GOOSE_MIGRATION_DIR, GOOSE_TABLE) and its blog (embedded SQL

at every minor release 2.0 ... 3.29 (drivers and connection strings for postgres, mysql, sqlite3, clickhouse, mssql
and others, SQL and Go migrations, embedded migrations with go:embed, hybrid versioning); the changelog of every 3.x
release; the package reference from pkg.go.dev for every minor release 3.0 ... 3.29 (Up, UpTo, Down, DownTo, Status,
Version, Create, Fix, SetBaseFS, SetDialect, SetTableName, AddMigrationContext, NewProvider, ProviderOption,
WithAllowOutofOrder, WithVerbose, Dialect, database.Store, lock.NewPostgresSessionLocker); and the example code.
Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about database migrations with goose: writing a migration in SQL or in Go, statements
that must run outside a transaction, multi-statement blocks with $$, creating and naming migration files, applying,
rolling back and inspecting migrations from the CLI or from Go code, embedding migrations in the binary, the
migration version table, out-of-order and missing migrations, locking so that two instances do not migrate at once,
using goose with sqlc, and what changed between releases.

Do not call this for SQL itself or the database servers (PostgreSQL, MySQL -- their own documentation), for
golang-migrate, Atlas, dbmate or other migration tools, for sqlc or pgx beyond what goose's pages say about them, or
for other languages: their documentation is not here, and the search will return excerpts that merely mention them,
with confident-looking titles.

`version` narrows the search to one release: one number keeps a major line ("3"), two a minor ("3.24"), three an
exact version ("3.24.3"). The site and its blog have no version: a `version` leaves them out. Every excerpt comes back
with `versions`: each release whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("+goose Up", "+goose Down",
"StatementBegin", "NO TRANSACTION", "ENVSUB", "goose create", "goose up", "goose down", "goose status", "goose fix",
"hybrid versioning", "timestamp", "sequential", "SetBaseFS", "embed", "go:embed", "NewProvider", "Provider",
"WithAllowOutofOrder", "allow-missing", "goose_db_version", "SetTableName", "AddMigrationContext", "Go migrations",
"session locker", "GOOSE_DBSTRING", "GOOSE_MIGRATION_DIR", "pgx", "sqlc"), not in the user's own words. Everything here
is English -- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters
and digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes
back with `found: 0`. When the user asks in another language, translate the question into the terms of the
documentation first, then search.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "міграція", "відкат", "схема бази", "версія схеми". Never call this set of documents "корпус" -- say
"документація goose". Identifiers, commands and titles stay in English, spelled exactly as the documentation spells
them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of
it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. goose 3.29.0 (October 2026) is the newest release. Search without `version` first;
when the user names their goose version, search that release. Every answer about the library API says which release
it is for: the Provider API appeared in 3.16 and grew afterwards.
