# grafana — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Grafana — відкриту платформу дашбордів, візуалізації, сповіщень і
дослідження метрик, логів і трас (сайт grafana.com/docs/grafana, репозиторій grafana/grafana, реєстр npm). Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Grafana — те, чим дивляться на метрики, логи й траси: дашборди з панелями й змінними, джерела даних (Prometheus, Loki,
Tempo, бази SQL, хмарні моніторинги), перетворення даних, Grafana Alerting з правилами, точками контакту й політиками
сповіщень, провізіонування всього цього файлами, автентифікація й права. Налаштування розкидане між `grafana.ini`,
змінними оточення `GF_*`, файлами провізіонування й HTTP API, а сторінки документації за 2.x–13.x не раз переїжджали
— тож відповідь без версії тут особливо легко дати хибну.

Разом 14 311 записів паспорта, з них неповторних 8801; в індексі 8697 документів і 48 573 фрагменти
(`expected_passages` у `checks.json`): однаковий текст різних версій — один уривок із переліком версій. Замір
`quality`: по словах 4 із 10, за змістом 1, разом 4, «як модель» 10 із 10. Одну ціль доповнено справжньою відповіддю:
на запит «anonymous authentication auth.anonymous» відповідає й розділ `[auth.anonymous]` довідника налаштувань, і
розділ «Anonymous authentication» сторінки автентифікації 9.x–10.x, а не лише окрема сторінка анонімного доступу.

Чому документація береться з репозиторію. Сайт grafana.com/docs/grafana зібрано Hugo з теки `docs/sources`, і кожен
тег `vX.Y.Z` тримає документацію тієї версії; береться останній тег кожної мінорної, 2.0–13.2 (64 теги; у 1.x теки
документації в репозиторії ще не було). Знімок один на мажор, з тегами всіх його мінорних у полі `tags`: файл,
однаковий у кількох тегах, читач тягне один раз, — близько 14 300 завантажень, дві з половиною години. Сторінки 13.x
цитуються адресами grafana.com/docs/grafana/latest, старші — файлами на GitHub.

Чого немає. Пререлізи (beta, rc) і нічні збірки. Документація Prometheus, Loki, Tempo, Mimir, Pyroscope, Alloy, k6,
Grafana Cloud, plugin-tools (create-plugin) і бібліотеки Scenes — окремі проєкти з власними сайтами; спільні шматки
інших продуктів, які сторінки Grafana вставляють (`source="alloy"`), лежать поза білим списком і випадають. Код і
тести, журнал `CHANGELOG.md` (ті самі пункти, що й у релізах).

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df grafana <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| документація кожної мінорної | дерево тегу `vX.Y.Z`, тека `docs/sources`; знімок на мажор | `ghdocs-history-grafana` |
| README пакетів | `packages/*/README.md` на тезі v13.2.4 | `ghdocs-history` |
| релізи | GitHub Releases grafana/grafana, лише стабільні | `ghreleases-stable` |
| реєстр npm | 14 пакетів `@grafana/*`, що виходять із репозиторію (з ними й застарілі `toolkit`, `e2e`) | `npm-versions` |

Новий читач `ghdocs-history-grafana` — обгортка над `ghdocs-history`, як `ghdocs-history-toml`: сторінка в
репозиторії — не те, що бачить людина на сайті. Вставка `{{< docs/shared lookup="…" source="grafana" >}}` стає
шматком теки `docs/sources/shared` того самого тегу (без неї від сторінки лишався б заголовок без жодного рядка),
виноска `{{< admonition type="note" >}}` — підписом «Note:», вкладки, розгортки й питання — підписами зі своєю
назвою, блоки визначень посилань `docs/reference` знімаються цілком, решта вставок — лише самі дужки. Шапку TOML
документації 2.x–6.x обгортка перекладає в YAML, інакше назвою ставало б ім'я файла. Шматок тягнеться один раз на
хеш blob: хеші теки `shared` обгортка бере з дерева тегу, яке читач однаково завантажує. Опис реєстру п'яти пакетів
(`@grafana/data`, `ui`, `runtime`, `schema`, `e2e-selectors`) з тисячами канарних збірок важить понад 50 МБ, тож їх
тягнуть стиснутими (`gzip: true`).

## Версії

Сторінки несуть версії тегів, з яких узяті (`13.2.4, 13.1.8, 13.0.11`), релізи — версію релізу, README — 13.2.4;
фільтр `version` бере мажор (`"13"`), мінор (`"12.4"`) або точну версію (`"11.6.16"`). Найновіша стабільна — 13.2.4.
Та сама сторінка живе в десятках редакцій, тож промпт велить шукати спершу з `version` "13", а для старшої Grafana
користувача — ще й її лінію й казати, що змінилося відтоді. Завантажень, за якими можна було б зважити лінії, немає:
сам сервер у npm не виходить.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/grafana-corpus-2026-10-26.tar.gz` (14 311 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\grafana-corpus-2026-10-26.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/grafana/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/grafana-corpus-РРРР-ММ-ДД.tar.gz -C instances/grafana corpus raw
find instances/grafana/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/grafana/raw
gzip -9 -c instances/grafana/index/passages.json > instances/grafana/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/grafana-corpus-2026-10-26.tar.gz -C instances/grafana
./df grafana smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/grafana/index/passages.json.gz`,
далі `./df grafana vectors` заллє колекцію Qdrant (хвилина на відеокарті, кілька десятків хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df grafana …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df grafana sources --why   # перелік джерел і білий список
./df grafana refresh         # завантажити все задеклароване (близько двох з половиною годин)
./df grafana manifest        # оновити паспорт
./df grafana setup           # Qdrant чи пошук лише по словах
./df grafana vectors         # залити корпус у docs-grafana
./df grafana smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df grafana serve          # порт 8902
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8902/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user grafana-docs http://127.0.0.1:8902/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `grafana-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
