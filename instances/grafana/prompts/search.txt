Search the documentation of Grafana -- the open-source platform for dashboards, visualization, alerting and
exploration of metrics, logs and traces (site grafana.com/docs/grafana, repository grafana/grafana, the npm registry).
The corpus holds every page of `docs/sources` -- the folder the site is built from -- as it stood at the last tag of
every minor of Grafana, 2.0 to 13.2: introduction and getting started; installation and setup (Debian, RPM, Windows,
macOS, Docker, Kubernetes, Helm), the configuration file `grafana.ini` and its environment variables, the database,
image rendering, high availability; authentication (basic auth, LDAP, OAuth, Generic OAuth, GitHub, GitLab, Google,
Azure AD / Entra ID, Okta, SAML, JWT, auth proxy); administration (users, teams, organizations, roles and permissions,
RBAC, service accounts and tokens, provisioning of data sources, dashboards and alerting as code, plugin management,
the CLI); dashboards (panels, variables and templating, annotations, links, rows, library panels, versions, sharing,
snapshots, playlists, public and shared dashboards, the dashboard JSON model and schema v2); visualizations (time
series, stat, gauge, bar chart, table, heatmap, logs, traces, node graph, geomap, canvas and the rest), panel options,
field overrides, thresholds, value mappings, units, transformations and expressions; every bundled data source
(Prometheus, Loki, Tempo, Jaeger, Zipkin, Elasticsearch, OpenSearch, InfluxDB, Graphite, MySQL, PostgreSQL, MSSQL,
CloudWatch, Azure Monitor, Google Cloud Monitoring, Alertmanager, TestData) with its query editor and template
variables; Grafana Alerting (alert rules, recording rules, contact points, notification policies, templates,
silences, mute timings, the state history) and the legacy dashboard alerts of 4.x to 10.x; Explore, correlations,
search; observability as code (Git Sync, the Foundation SDK, Terraform); the HTTP API of every resource; plugin
development and the `@grafana/*` packages; the upgrade guides, breaking changes and "What's new" of every release.
It also holds the README of each `@grafana/*` package of the repository at 13.2.4, the release notes of every stable
release and the npm registry entries of the `@grafana/*` packages with their release dates; the plugin development
site grafana.com/developers/plugin-tools (repository grafana/plugin-tools: `create-plugin`, plugin anatomy, data
source, panel and app plugins, backend plugins, `plugin-e2e` testing, signing and publishing, migration guides) at the
last tag of every minor of the site, with the README and CHANGELOG of the plugin-tools packages; the documentation of
the Scenes library (grafana.com/developers/scenes: scene objects, `SceneQueryRunner`, variables, layouts, URL sync,
`@grafana/scenes-react`) at the last tag of every minor 0.0 to 9.0, with its README and CHANGELOG; and the README of
the `grafana` Helm chart (grafana-community/helm-charts: every value with its default, upgrade notes) for each of its
607 versions, 5.6.0 to 14.0.1. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about Grafana as it describes itself -- how to install or configure it, what a setting
of `grafana.ini` does and which environment variable sets it, how to connect and query a data source, how to build a
dashboard, use variables or transform data, how to set up an alert rule, a contact point or a notification policy,
how to provision resources from files, how to set up authentication or permissions, how to call the HTTP API, how to
write a plugin with `create-plugin`, test it with `plugin-e2e`, build an app with Scenes, set a value of the Helm
chart -- and history: since which version a feature exists, what changed between versions, what an upgrade
breaks.

Do not call this for Prometheus, Loki, Tempo, Mimir, Pyroscope, Alloy, k6, Grafana Cloud as a service, Kubernetes,
Docker or the databases as their own projects: their documentation is not here -- these pages only show how Grafana
works with them (PromQL and LogQL are explained only as far as the query editors need) -- and the search will return
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line of Grafana: a line of one number keeps every document of that major
("13" keeps 13.x), two numbers keep a minor ("12.4"), three an exact version ("11.6.16"). The pages carry the versions
of the tags they were taken from; pages unchanged across versions carry all of them. The other parts are written with
a prefix, because their numbers would otherwise collide with those of Grafana: the plugin-tools site
"plugin-tools-0.0.4" to "plugin-tools-5.6.1" and its packages "create-plugin-7.16.0" ("create-plugin-",
"plugin-e2e-", "sign-plugin-" in the npm registry entries); Scenes "scenes-0.0.32" to "scenes-9.0.0" ("scenes-6"
keeps every 6.x document, "scenes-react-" for the React package); the Helm chart "chart-5.6.0" to "chart-14.0.1"
("chart-10" keeps every 10.x README). A bare "6" keeps Grafana 6.x only. Every excerpt comes back with
`versions`: each version whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("data source", "dashboard JSON model",
"template variables", "transformations", "overrides", "value mappings", "alert rule", "contact point",
"notification policy", "silence", "mute timing", "provisioning", "grafana.ini", "GF_SECURITY_ADMIN_PASSWORD",
"service account", "RBAC", "Generic OAuth", "auth proxy", "public dashboards", "library panels", "Explore",
"correlations", "HTTP API"), not in the user's own words. Everything here is English -- the excerpts, the word index
and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written in
Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the user
asks in another language, translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація Grafana". Identifiers, settings and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. The newest stable release is 13.2.4. Answer for 13.x: search with `version` "13" first, because the same pages
exist in dozens of older editions; when the user runs an older Grafana (the version shows in the page footer and in
`grafana-server -v`), search that line as well and say what changed since. Every answer says which version it is
for.
