# helmet — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Helmet — пакет npm, який виставляє заголовки безпеки HTTP
(`Content-Security-Policy`, `Strict-Transport-Security` та інші) у застосунках Node.js, насамперед на Express, — за
документацією всіх його стабільних версій: сайтом helmetjs.github.io у стані на кожен реліз, README, типами й
журналом змін пакета та реєстром npm. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця
тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

README helmet вже є в примірнику express (як одна з супутніх бібліотек), але там воно одне з багатьох, а Helmet —
окремий предмет питань: що ввімкнено за замовчуванням у кожній мажорній лінії, які заголовки прибрано (`hpkp`,
`nocache`, `expect-ct`, `feature-policy`), як міняється `Content-Security-Policy` від 3.x до 8.x. Тут корпус повний і
самодостатній: сайт, README, типи, журнал змін і реєстр — усе по версіях, незалежно від express.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df helmet <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт | репозиторій `helmetjs/helmetjs.github.io`, гілка `main`; знімок — вершина гілки перед виходом наступної версії | `ghsite-dated` |
| README, `SECURITY.md`, `CONTRIBUTING.md` | tarball `registry.npmjs.org/helmet/-/helmet-X.tgz` | `npm-tarball-files` |
| типи | той самий tarball: головний файл і файл Content-Security-Policy | `npm-tarball-files` |
| журнал змін | `CHANGELOG.md` гілки main | `changelog-dated`, новий |
| реєстр npm | registry.npmjs.org, одне звернення | `npm-versions` |

Читач `changelog-dated` додано разом із цим примірником (`engine/readers/changelogdated.py`): журнал Helmet пише
версії як «## 8.3.0 - 2026-07-11», без дужок, яких чекають `changelog` і `changelog-keep`. Особливості корпусу:

- **Сайт має дві епохи.** До 02.06.2023 — Jekyll: окрема сторінка на кожен заголовок (`docs/csp/index.md`,
  `docs/hsts/index.md` …). Далі — Hugo: головна з довідником усіх заголовків (`content/_index.md`) і сторінки FAQ.
  Перший коміт репозиторію (серпень 2016) — лише ліцензія, тож для версій до 2.1.2 сайту в корпусі немає — лише README
  і журнал змін.
- **Сторінки без підзаголовків** (більшість Jekyll-сторінок і майже все FAQ) знаходяться пошуком, але в замірі
  `quality` на них посилатися не можна: ціль заміру мусить бути розділом із заголовком.
- **Типи є з 4.0.0.** У 4.x–6.0 типи кожного middleware лежать окремим файлом (`dist/middlewares/.../index.d.ts`,
  потім `dist/types/...`), у 6.1 і новіших — один `index.d.cts`; тому Content-Security-Policy 4.x–6.0 винесено
  окремим джерелом.
- **Вимога до Node (`engines`)** записана в документах реєстру npm: 3.x — Node 4, 4.x — 10, 5.x — 12, 6.x — 14,
  7.x — 16, 8.x — 18.
- **Документ — неповторний текст.** Версії, де файл не змінився, ділять один документ; у рядку `# версія:` стоять усі.

## Межі, про які треба пам'ятати

Документації Express, самих заголовків HTTP (MDN, специфікації) і Node.js тут немає, як і інших проміжних шарів
безпеки (cors, csurf, express-rate-limit). Код бібліотеки (`src/`) не входить — лише документація. Wiki в репозиторія
helmet порожня (лише рядок привітання), тож у корпус не входить.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/helmet-corpus-2026-10-09.tar.gz` (374 тексти і паспорт). В історії git
текстів немає ніде. Архів лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/helmet-corpus-2026-10-09.tar.gz -C instances/helmet
./df helmet smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/helmet/index/passages.json           # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/helmet-corpus-РРРР-ММ-ДД.tar.gz -C instances/helmet corpus
find instances/helmet/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/helmet/index/passages.json > instances/helmet/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/helmet/index/passages.json.gz`, далі
`./df helmet vectors` заллє колекцію Qdrant (близько хвилини).

## Установка venv

```
cd instances/helmet
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df helmet sources --why   # перелік джерел і білий список
./df helmet refresh         # завантажити все задеклароване (близько 25 хвилин)
./df helmet manifest        # оновити паспорт
./df helmet setup           # Qdrant чи пошук лише по словах
./df helmet vectors         # залити корпус у docs-helmet
./df helmet smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df helmet serve          # порт 8809
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8809/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user helmet-docs http://127.0.0.1:8809/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `helmet-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
