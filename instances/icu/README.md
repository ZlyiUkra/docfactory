# icu — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про ICU (International Components for Unicode) — бібліотеку, на якій
стоять `Intl` у Node.js і браузерах: рядки й Unicode, локалі, форматування чисел, дат і повідомлень, колація (сортування),
межі слів і речень, перетворення кодувань, транслітерація, календарі й часові пояси. Документація — посібник
користувача (як він був до ICU 65 і від 65.1 до 78.3), довідник C/C++ API (коментарі Doxygen публічних і внутрішніх
заголовків ICU4C кожного випуску 1.4.0–78.3) і дизайн-документи. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

Документація Node.js описує `Intl` зверху: `Intl.Collator`, `Intl.DateTimeFormat`. Чому порядок сортування залежить від
версії, що таке колація «ignorepunct», які календарі й часові пояси знає рушій, що робить `ucol_setStrength` —
відповідає ICU, а його версія в кожному релізі Node своя (які — у примірнику `nodejs`, документ кожної лінії).
Сайт ICU показує лише найновіший випуск; тут — кожен.

## Що в цій теці

- `corpus/` — паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа. Самих текстів тут немає:
  корпус в архіві.
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — токен GitHub і, для кроку `ask`, ключ Anthropic; `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики через `./df icu <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| посібник 65.1–78.3 | `docs/userguide` на тегах | `ghdocs-history` |
| довідник API, внутрішні заголовки | `source/**/unicode/*.h`, `source/**/*.h` на тегах | `ghcode-history` з `outline` |
| старий посібник, дизайн | `icu-docs`: `userguide/OO/*.sxw`, `design/*.html` | `gh-legacy-docs`, новий |

Особливості:

- **Довідник API — це заголовки.** Готового HTML кожного випуску немає (у `icu-docs` лежить лише найновіший). Коментарі
  Doxygen у заголовках і є довідник; поле `outline: true` у `ghcode-history` ділить файл на розділи за коментарем
  `/** … */`: заголовок розділу — ім'я функції, класу чи макроса, у тілі — коментар із `@stable ICU 2.0`, `@param`,
  `@return` і оголошення. Однакові розділи між випусками зливаються, і версії розділу показують, відколи він такий.
- **Імена документів.** Заголовки зведено до `api-<файл>-h` (`api-ucol-h`, `api-unistr-h`), внутрішні — до
  `int-<файл>-h`; до ICU 49 шлях був без `icu4c/` — це теж одне ім'я.
- **Старий посібник — файли `.sxw`.** Це OpenOffice Writer (zip із `content.xml`); читач `gh-legacy-docs` бере заголовки,
  абзаци, код (стиль `icu-source`), списки й таблиці. Підписаний версією 64.2 — станом на перенесення в репозиторій `icu`.
- **Дизайн-документи** не прив'язані до випуску: позначка версії «design».

## Межі, про які треба пам'ятати

- Посібник у git є лише з 65.1; для випусків 1.4–64 відповідь стоїть на заголовках і старому посібнику (він один, без
  історії).
- ICU 1.2.x–1.3.x не взято: публічних заголовків там ще немає. Реалізація (`.cpp`) не береться — лише заголовки.
- Java-класи ICU4J — лише в посібнику; довідника ICU4J тут немає.
- CLDR і Unicode Standard — окремі специфікації, тут їх нема; дизайн-документи містять лише технічні звіти UTC, які ICU
  реалізує (TR10, TR15, TR18, TR29).

## Родина Node: піднімати разом

Цей примірник — один зі складників Node.js, і питання до нього рідко приходять самі: «чому `dns.resolve` поводиться так» починається в API Node і закінчується в c-ares, «що значить `ERR_OSSL_…`» — в OpenSSL. Тому примірники родини Node піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує всі вісім серверів: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `nodejs` | `nodejs-docs` | 8796 | API Node.js, npm, розклад і склад релізів |
| `v8` | `v8-docs` | 8773 | рушій JavaScript |
| `libuv` | `libuv-docs` | 8838 | цикл подій, пул потоків, ввід-вивід |
| `openssl` | `openssl-docs` | 8839 | `crypto`, `tls`, сертифікати |
| `icu` | `icu-docs` | 8840 | `Intl`, нормалізація, часові пояси |
| `cares` | `cares-docs` | 8841 | `dns.resolve*` |
| `llhttp` | `llhttp-docs` | 8842 | парсер HTTP/1.x |
| `nghttp2` | `nghttp2-docs` | 8843 | `http2` |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус в архіві від самого початку: у `corpus/` лежить лише паспорт, а сервер підіймається з кешу фрагментів і
колекції Qdrant; відповіді ті самі до символа.

**Де тексти.** В архіві `~/archives/docfactory/icu-corpus-2026-10-15.tar.gz` (110 МБ, 8 300 текстів, паспорт і сховище
сирого `raw/`; перед видаленням розпакований окремо й звірений з диском — нуль розбіжностей). Лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
tar -czf ~/archives/docfactory/icu-corpus-РРРР-ММ-ДД.tar.gz -C instances/icu corpus raw
find instances/icu/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/icu/raw
gzip -9 -c instances/icu/index/passages.json > instances/icu/index/passages.json.gz
```

**Як повернути тексти** — перед будь-яким оновленням:

```
tar -xzf ~/archives/docfactory/icu-corpus-2026-10-15.tar.gz -C instances/icu
./df icu smoke
```

**Оновлення.** Новий тег дописують першим рядком у `tags` джерел `icu-api`, `icu-api-internal` (та `icu-userguide`).
Далі `./df icu refresh <id джерела>`, `manifest`, `vectors`, `smoke`, `quality`.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df icu …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/icu/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають. Для роботи сервера збирати нічого не
треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df icu sources --why   # перелік джерел і білий список
./df icu refresh         # завантажити все задеклароване (близько 70 хвилин)
./df icu manifest        # оновити паспорт
./df icu setup           # Qdrant чи пошук лише по словах
./df icu vectors         # залити корпус у docs-icu (близько 2 годин)
./df icu smoke           # перевірки
```

Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df icu serve          # порт 8840
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8840/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user icu-docs http://127.0.0.1:8840/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User).

**3. Перевірити.** `/mcp` — має бути `icu-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера.
