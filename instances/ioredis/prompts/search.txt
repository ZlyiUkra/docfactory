Search the ioredis documentation, in English: ioredis is the full-featured Redis client for Node.js --
standalone, Sentinel and Cluster connections, pipelining and auto-pipelining, transactions, pub/sub and sharded
pub/sub, streams, scan streams, Lua scripts through defineCommand, TLS, offline queue, reconnection, built-in
TypeScript types. The set holds, for every stable release from 1.0.0 to 6.0.0: the README (the guide:
connecting, options, events, pipelining, transactions, Lua scripting, Cluster, Sentinel, error handling,
TypeScript), the API reference API.md (versions 2 to 4), the changelog, the examples, the source code lib/
(classes Redis, Cluster, Pipeline, Command, ScanStream, the connectors, RedisOptions and ClusterOptions with
their JSDoc comments, RedisCommander with the signature of every command -- for 5.x and 6.x the API reference
is this code, from which the TypeDoc site is generated), the test suite of the last release of each minor
line, the GitHub release notes, the README and changelog of @ioredis/commands, and the community typings
@types/ioredis for ioredis 3 and 4. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about ioredis: how to connect (options, URL, Sentinel, Cluster, TLS), what an
option does and its default (maxRetriesPerRequest, retryStrategy, enableOfflineQueue, lazyConnect, keyPrefix,
enableAutoPipelining, reconnectOnError), how pipelines, transactions (multi/exec, WATCH), pub/sub, streams,
scan streams and Lua scripts (defineCommand) work, which events the client emits and in what order, how
reconnection and errors behave, what changed between versions (4 to 5 to 6), what a TypeScript type or
signature looks like. Example query: "retryStrategy".

Do not call this for the Redis server itself (commands, redis.conf, persistence, replication, Sentinel or
Cluster internals: the redis instance), for node-redis, for BullMQ or other queue libraries, or for frameworks
that wrap ioredis (NestJS, Fastify plugins) beyond what the ioredis documents say.

Write the query in English, with the names ioredis uses (retryStrategy, enableReadyCheck, Cluster,
defineCommand, scanStream, maxRetriesPerRequest, natMap). Everything here is English, and the word index keeps
only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing and comes back with `found: 0`. When the user asks in another language, translate the question into
ioredis terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "підключення", "опція", "подія".
Never call this set of documents "корпус" -- say "документація ioredis". Option, method, event and class
names stay in English, spelled exactly as the documentation spells them. Build the answer out of the excerpts
that came back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. When the user names a version, search that line; otherwise answer for the newest
release and say so. Put a version only into `version`, never into the query text: "5" keeps every 5.x, "4.28"
keeps 4.28.x, "5.4.1" one release. Every document carries the releases in which it was exactly so, so a
README excerpt marked 4.0.0-4.28.5 describes ioredis 4. The README is "readme", the API reference "api",
the changelog "changelog"; release notes are "ioredis-<tag>"; the source is named by its path under lib/.
