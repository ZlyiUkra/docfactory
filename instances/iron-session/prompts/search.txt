Search the iron-session documentation -- the README, MIGRATION.md, SECURITY.md and TypeScript
declarations of every stable version of the iron-session npm package (1.0, 2.0, 6.x, 7.x, 8.x,
9.x), of its predecessor next-iron-session (1.1-4.2) and of iron-webcrypto, the library that
seals the cookie; the changelogs, the GitHub release notes, the example apps of every tagged
release and the npm registry history -- and return the matching excerpts with the versions each
one belongs to. iron-session keeps a session in a signed and encrypted ("sealed") cookie: no
session store on the server, the data travels in the cookie itself. It works with Next.js (App
Router, Pages Router, Route Handlers, Server Actions, middleware and proxy), Express, Koa, Node's
http module, Bun and Deno.

Call this when a question is about iron-session itself -- getIronSession, session.save(),
session.destroy(), session.updateConfig(), the options (password, cookieName, ttl, cookieOptions:
secure, httpOnly, sameSite, maxAge, path, domain), password rotation with a map of passwords,
sealData and unsealData (magic links, signed invitations), typing the session data (SessionData,
IronSession), reading the session in Server Components, Server Actions, Route Handlers, API routes,
getServerSideProps and middleware; the old API of 6.x-7.x (withIronSessionApiRoute,
withIronSessionSsr, iron-session/next, iron-session/express, iron-session/edge, IronSessionOptions)
and of next-iron-session (withIronSession, ironSession, applySession); how to upgrade between
majors (next-iron-session 4 -> iron-session 6 -> 8 -> 9); what the cookie protects and what it
does not (SECURITY.md); the sealing format itself (iron-webcrypto: seal, unseal, defaults,
algorithms) -- and above all history and compatibility: since which version a function or option
exists, which defaults changed, which versions run on which Node.js (the `engines` field of each
version is written in the npm registry documents; 9.x needs Node 22.13+). Example query:
"getIronSession cookies Server Action".

Do not call this for Next.js itself, for authentication libraries (Auth.js, NextAuth, Better
Auth, Clerk, Lucia), for JWT and the jose library, for cookies and HTTP in general or for Node.js
and npm: their documentation is not here, and the search will return iron-session excerpts that
merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "8" keeps every 8.x document, "6.3" keeps
6.3.x; leave it empty to search everything. Every excerpt comes back with `versions`: each
version whose documents contain this exact text, newest first -- text that stayed the same
across versions is returned once, with all of them listed, so the list itself shows from which
to which version the documentation said exactly this. Three packages share this set and their
version numbers overlap: iron-session (1.0-9.x), next-iron-session (1.1-4.2) and iron-webcrypto
(0.x-2.x); the title of every excerpt names its package -- check it before citing a version.

Write the query in English, with the names iron-session itself uses ("getIronSession",
"cookieOptions", "sealData", "withIronSessionApiRoute", "ttl"), not in the user's own words.
Everything here is English -- the excerpts, the word index and the meaning index alike -- and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any
other non-latin script matches nothing at all and comes back with `found: 0`. When the user asks
in another language, translate the question into iron-session terms first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists; what changed in later versions;
what prompted the change, if the excerpts say so; and how it stands in the current version. Every
point names the version and the document it rests on; a point the excerpts do not support is left
out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація iron-session". Identifiers, option names and titles stay in English,
spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it
says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see below. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the
query had to appear in the text, so a query phrased in other words than the documentation uses
may miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase
had a chance.

Which version to search first. Two lines are in wide use: 8.x (the most downloaded, one function
getIronSession for everything) and 6.x (wrappers withIronSessionApiRoute and withIronSessionSsr
for the Pages Router); 9.x is the newest (ESM only, Node 22.13+). For a question about how to do
something, search with `version` "8"; when the 6.x way differs, search "6" as well and give both.
If the user names a version, or their code shows one (withIronSession -> next-iron-session,
withIronSessionApiRoute -> 6.x, getIronSession -> 8.x or 9.x), search that line. Search without
`version` when the question is about history, or when the line gave nothing. The API changed
with almost every major line, so an answer taken from the wrong line can be confidently wrong.
Every answer says which version it is for; when the user did not name one, answer for 8.x, add
how it is done in 6.x when that differs, and say so ("for iron-session 8.x; in 6.x ..."). When
the excerpts behind a statement come only from older versions, name those versions instead of
presenting the text as current.
