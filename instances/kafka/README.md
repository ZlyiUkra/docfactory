# kafka — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Apache Kafka — розподілену платформу потоків подій (сайт
kafka.apache.org, репозиторії apache/kafka-site і apache/kafka) — за документацією всіх мінорних версій: сайт кожної
версії від 0.7 до 4.4 з повними таблицями параметрів і схемами протоколу, оголошення релізів, сторінки завантажень і
вразливостей, README репозиторію на кожній мінорній. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Kafka — журнал подій, розподілений між брокерами: тема ділиться на розділи (partitions), кожен розділ копіюється на
кілька брокерів (репліки, ISR), продюсер дописує записи в кінець, консумери читають зі своєї позиції (offset) і
об'єднуються в групи. Поруч — Kafka Connect (конектори до інших систем) і Kafka Streams (бібліотека обробки потоків).
У плані NestJS (фулстек-родина) Kafka стоїть у «знати, що існує» серед транспортів мікросервісів поруч із RabbitMQ і
NATS.

Поведінка залежить від версії сильніше, ніж здається: у 3.0 змінилися типові `acks` і `enable.idempotence`, у 4.0
прибрано ZooKeeper (лише режим KRaft) і з'явився новий протокол груп консумерів (`group.protocol=consumer`, типовим
лишається `classic`), параметри з'являються й зникають у кожному випуску. Тут документація кожної мінорної версії, нотатки переходу (`upgrade`) і дата
кожного випуску зібрані в одному місці, з номером версії біля кожного уривка.

Разом 1911 документів; однаковий текст різних версій — один уривок, тож фрагментів в індексі 10 816
(`expected_passages` у `checks.json`). Замір `quality`: по словах 6 із 10, за змістом 7, разом 6, «як модель» 10 із 10.
Промахи першої десятки — питання без жодного слова документації: «keep only the latest value for every key» замість
log compaction, «let the broker decide which partitions each member reads» замість consumer rebalance protocol, «copy
topics from one data center to another» замість MirrorMaker і geo-replication; модель векторів bge-small цього розриву
не долає. Друга десятка — назвами документації, як шукає модель за промптом, — влучає всюди.

Чому сайт береться з репозиторію apache/kafka-site. З 2025 року сайт зібрано Hugo з markdown, і документація кожної
мінорної версії лежить у своїй теці (`07`, `081`, `0100`, `39`, `44`) на одному коміті гілки `markdown`; береться коміт
f0b9b2ace від 23.10.2026. Береться все, крім заглушок старих адрес (`documentation/…`) і порожніх сторінок розділів.
Версія 4.4 — найновіша: тег 4.4.0 є, сайт показує її як поточну, хоча сторінка завантажень ще називає останньою 4.3.1.

Чому README лише кореня apache/kafka. Документація в репозиторії (`docs/`) — те саме, з чого зібрано теку версії на
сайті; README — збирання з джерел, версії Java і Scala, запуск тестів. Береться остання латка кожної мінорної: у 0.7
стабільного тегу немає (лише `kafka-0.7.2-incubating-candidate-*`).

Чого немає. Javadoc API (на сайті — окремий HTML, кілька тисяч сторінок на версію), пропозицій KIP (вікі
cwiki.apache.org), нотаток релізів зі списками задач JIRA (`RELEASE_NOTES.html` на downloads.apache.org). Клієнтів поза
Apache Kafka — KafkaJS, librdkafka, Spring for Apache Kafka, транспорту NestJS — і продуктів Confluent. Maven Central,
звідки беруть Kafka як залежність, README не має, тож шару менеджера пакетів тут немає.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, `families` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df kafka <крок>`.

## Версії

Версія сторінки сайту — версія її теки: `0.7`, `0.8.0`…`0.11.0`, `1.0`…`4.4`; README несе тег (`4.3.2`). Фільтр
`version` бере мажор (`"3"`), мінор (`"3.9"`, `"0.10"`) або точну версію (`"0.10.2"`). Ті самі сторінки різних версій —
одна родина (`families` у `config.json`): розділ, що не змінився, займає у видачі одне місце й показує найновішу
версію, а перелік версій уривка сам каже, відколи й доки документація казала саме це.

Статистики завантажень за версіями Kafka не публікує (Maven Central чисел за версіями не дає), тож промпт відповідає
для лінії, яку підтримує проєкт: 4 (найновіша 4.4; сторінка завантажень на жовтень 2026 називає підтримуваними 4.3,
4.2 і 4.1). Коли питання про ZooKeeper чи старий кластер — ще й для 3.9, останньої версії з ZooKeeper.

## Родина Kafka: піднімати разом

Цей примірник — частина родини Kafka: сам Apache Kafka і три клієнти для Node.js. Питання про клієнта впирається в
поведінку брокера (`acks`, `min.insync.replicas`, ребаланс груп, транзакції), а питання про брокер часто звучить мовою
клієнта. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує всі чотири сервери:
підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `kafka` | `kafka-docs` | 8886 | сам Apache Kafka 0.7–4.4: брокери, KRaft, конфігурація, протокол, Connect, Streams |
| `kafkajs` | `kafkajs-docs` | 8887 | клієнт KafkaJS для Node.js (на ньому транспорт Kafka NestJS) |
| `confluent-kafka-javascript` | `confluent-kafka-javascript-docs` | 8888 | клієнт Confluent `@confluentinc/kafka-javascript` на librdkafka |
| `platformatic-kafka` | `platformatic-kafka-docs` | 8889 | клієнт `@platformatic/kafka` на чистому TypeScript |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/kafka-corpus-2026-10-25.tar.gz` (1911 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\kafka-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/kafka/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/kafka-corpus-РРРР-ММ-ДД.tar.gz -C instances/kafka corpus raw
find instances/kafka/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/kafka/raw
gzip -9 -c instances/kafka/index/passages.json > instances/kafka/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/kafka-corpus-2026-10-25.tar.gz -C instances/kafka
./df kafka smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/kafka/index/passages.json.gz`, далі
`./df kafka vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df kafka …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df kafka sources --why   # перелік джерел і білий список
./df kafka refresh         # завантажити все задеклароване (близько 30 хвилин)
./df kafka manifest        # оновити паспорт
./df kafka setup           # Qdrant чи пошук лише по словах
./df kafka vectors         # залити корпус у docs-kafka
./df kafka smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df kafka serve          # порт 8886
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8886/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user kafka-docs http://127.0.0.1:8886/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `kafka-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
