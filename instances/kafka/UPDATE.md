# Оновлення корпусу kafka

Сайт тут оголошено руками: кожна тека версії — окреме джерело в `sources.json`, і всі вони закріплені на одному коміті
гілки `markdown` репозиторію apache/kafka-site (f0b9b2ace від 23.10.2026). Теги README теж записано руками, в об'єкті
`tags` джерела `kafka-readme`. Сама собою нова версія сюди не потрапляє.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

1. Новий коміт сайту: `https://api.github.com/repos/apache/kafka-site/commits/markdown` дає SHA. У `url` і `within`
   усіх джерел `kafka-hugo` старий SHA замінюють новим — сторінки старих версій сайт теж правлять.
2. Нова мінорна (4.5) — нова тека `content/en/45`: джерело `kafka-4.5` дописують за зразком `kafka-4.4` (тека, `version`,
   `site`, `within`, назва), його id — у родину `kafka-site` поля `families` у `config.json`. Тека з'являється на сайті
   ще до випуску: брати її лише тоді, коли в apache/kafka є стабільний тег `4.5.0`.
3. Новий тег README: остання латка кожної мінорної — в об'єкт `tags` джерела `kafka-readme` (тег → версія); латка тієї
   самої мінорної заміняє стару. Перелік тегів — `https://api.github.com/repos/apache/kafka/tags`.

```
./df kafka check                 # чи змінилося щось нагорі за джерелом
./df kafka refresh               # повне перезавантаження, близько 30 хвилин
./df kafka manifest
./df kafka vectors
./df kafka smoke
# Ctrl+C у терміналі з serve, і знову: ./df kafka serve
```

`refresh` повний, не `--missing`: новий коміт сайту міняє й сторінки старих версій.

Якщо вийшла нова мажорна лінія (5.0):

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` замінити поточну лінію на нову і
  звірити перелік підтримуваних випусків зі сторінкою завантажень (`content/en/community/downloads.md`, розділ
  «Supported releases»): статистики завантажень за версіями Kafka не публікує, тож відповідь іде для підтримуваної
  лінії;
- у `checks.json`, у десятках `quality` і `quality_model`, звірити цілі там, де питання про поточну поведінку.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен: дерев тек сайту 37, тегів README 34, а без токена GitHub
дає 60 звернень на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df kafka quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
