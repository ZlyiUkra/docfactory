Search the Apache Kafka documentation -- the distributed event streaming platform: brokers and KRaft controllers,
topics and partitions, producers and consumers, Kafka Connect and Kafka Streams (site kafka.apache.org, repository
apache/kafka-site, and the README of repository apache/kafka). The corpus holds the documentation of every minor
version from 0.7 to 4.4, each taken from its own folder of the site (getting started, introduction and use cases,
the quickstart, the upgrade notes `getting-started/upgrade` with what changed in every release, the compatibility
pages, the migration from ZooKeeper to KRaft `zk2kraft`, the Producer, Consumer, Admin, Streams and Connect APIs,
configuration with the full generated tables of broker, topic, producer, consumer, admin, Connect, Streams and
MirrorMaker parameters -- every parameter with its type, default, valid values and importance --, design: the log,
replication, delivery semantics, idempotence and transactions, log compaction, quotas; the wire protocol with every
API key, request and response schema and error code; implementation; operations: basic operations with the CLI
tools, geo-replication with MirrorMaker 2, KRaft, monitoring with every JMX metric, tiered storage, multi-tenancy,
hardware and OS, the consumer rebalance protocol; security: SSL, SASL (GSSAPI, PLAIN, SCRAM, OAUTHBEARER),
authorization and ACLs; the Kafka Connect user and developer guides; the Kafka Streams concepts, architecture,
developer guide with the DSL and the Processor API, and its own upgrade guide); the release announcements of the site
blog from 3.5.0 to 4.3.1; the download page with the date of every release, the list of CVEs, the security policy;
and the README of the repository at the last patch of every minor from 0.8.0 to 4.4.0 (building from source, the
Java and Scala versions, running tests). Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about Apache Kafka as it describes itself -- what a configuration parameter does and its
default (`acks`, `enable.idempotence`, `retention.ms`, `min.insync.replicas`, `group.protocol`), how replication,
leader election and the ISR work, what exactly-once means and how transactions are used, how log compaction works,
how to run a cluster in KRaft mode, how to add or remove brokers and reassign partitions, which metric to watch, how
to configure SSL, SASL and ACLs, how to write a connector or a Streams application -- and above all history and
compatibility: since which version a parameter, feature or API exists, what changed between versions (the upgrade
notes of every version list notable changes, deprecations and removals; the blog lists the KIPs of a release), which
Java a version requires, and when every version came out.

Do not call this for Kafka clients and products outside Apache Kafka -- KafkaJS, node-rdkafka, librdkafka,
confluent-kafka for JavaScript, Python or Go, Spring for Apache Kafka, NestJS microservices, Confluent Platform and
Confluent Cloud, Schema Registry, ksqlDB, Strimzi, Debezium -- nor for ZooKeeper, Java or Docker themselves: their
documentation is not here, and the search will return excerpts that merely mention them, with confident-looking
titles.

`version` narrows the search to one release line. Kafka carries plain numbers: a line of one number keeps every
document of that major ("3" keeps 3.0 to 3.9), two numbers keep a minor ("3.9", or "0.10" for 0.10.0 to 0.10.2),
three an exact version ("0.10.2", "4.3.2"). The pages of the site carry the version of their folder ("4.1", "0.8.2");
the README carries the tag it was taken from ("4.3.2"). Leave `version` empty to search everything, including text
that carries no version. Every excerpt comes back with `versions`: each version whose documents contain this exact
text, newest first -- a page that stayed the same across versions is returned once, with all of them listed, so the
list itself shows from which to which version the documentation said exactly this.

Write the query in English, with the names the documentation itself uses ("acks", "enable.idempotence",
"transactional.id", "isolation.level", "min.insync.replicas", "unclean.leader.election.enable", "log.cleanup.policy",
"KRaft", "controller.quorum.voters", "kafka-reassign-partitions", "kafka-consumer-groups", "MirrorMaker",
"KStream", "KTable", "Processor API", "SinkConnector", "SASL/SCRAM", "OAUTHBEARER", "ACL"), not in the user's own
words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question into
the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the excerpts say
so; and how it stands in the current version. Every point names the version and the document it rests on; a point the
excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer
writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус" -- say
"документація Apache Kafka". Identifiers, parameter names and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Kafka publishes no download counts per version, so the line to answer for is the one
the project supports: 4.4 is the newest (tag 4.4.0), and the download page of October 2026 lists 4.3, 4.2 and 4.1 as
supported. The line 4 runs in KRaft mode only -- ZooKeeper was removed in 4.0 --, while 3.9 is the last version that
still runs with ZooKeeper and the bridge for migrating a cluster to KRaft. Answer how-to questions for 4: search
`version` "4" and say which 4.x the excerpt is for; when the question involves ZooKeeper or an older cluster, search
"3.9" as well and say where they differ (the pages `getting-started/upgrade` and `zk2kraft` list what changed).
Search without `version` when the question is about history, or when the line gave nothing. Every answer says which
version it is for; when the excerpts behind a statement come only from older versions, name those versions instead of
presenting the text as current.
