# kafkajs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про KafkaJS — клієнт Apache Kafka для Node.js на чистому JavaScript
(репозиторій tulios/kafkajs, сайт kafka.js.org, пакет kafkajs на npm) — за документацією всіх стабільних версій:
сторінки сайту з тегу кожної мінорної версії, README кожної версії, журнал змін та історія версій у реєстрі npm. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Примірник — другий у родині Kafka: сервер окремо (`kafka`), кожен клієнт Node окремо, як у родинах Redis і Mongo. Далі в
родині — `@confluentinc/kafka-javascript` і `@platformatic/kafka`.

KafkaJS — найпоширеніший клієнт Kafka для Node.js (близько 2,3 млн завантажень за тиждень до 25.10.2026): продюсер,
консумер у групі з `eachMessage` чи `eachBatch`, транзакції, адмін-клієнт, SSL і SASL, без рідних модулів. На ньому
працює транспорт Kafka мікросервісів NestJS, тож для плану NestJS (фулстек-родина) це клієнт, з яким зустрічаються
першим. Останній випуск — 2.2.4 від 27.02.2023; лінія 2.3.0-beta випуском не стала, і з того часу репозиторій випусків
не мав. Близько 92 % завантажень — саме 2.2.4.

Разом 196 документів; фрагментів в індексі — 709 (`expected_passages` у `checks.json`). Замір `quality`: по словах 2 із
10, за змістом 7, разом 6, «як модель» 10 із 10. Перша десятка своїми словами по словах майже не влучає — у питаннях

шукає модель за промптом, — влучає всюди.

Чому сайт береться з репозиторію. Сайт kafka.js.org (Docusaurus 1) зібрано з теки `docs/`, а версії сайту (з 1.10)
зберігають лише змінені сторінки; повний зміст кожної версії лежить у `docs/` на її тезі. Береться остання латка кожної
мінорної від 0.1 до 2.2. До появи `docs/` документацією був README — тому README кожної версії теж тут.

Чого немає. Документації самого Apache Kafka (вона — у примірнику `kafka`), librdkafka, інших клієнтів, NestJS і
Node.js. Коду клієнта, типів `types/index.d.ts` і прикладів `examples/`.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df kafkajs <крок>`.

## Версії

Версія — номер випуску; сторінки сайту мають версію тегу, з якого взято (остання латка мінорної). Фільтр `version` бере
мажор (`"1"`), мінор (`"1.16"`) або точну версію (`"2.2.4"`). На питання «як це зробити зараз» промпт велить шукати для
2.2. Сторінка, що не змінилася між версіями, — один документ з усіма ними, тож перелік версій уривка сам показує,
відколи й доки документація казала саме це.

## Родина Kafka: піднімати разом

Цей примірник — частина родини Kafka: сам Apache Kafka і три клієнти для Node.js. Питання про клієнта впирається в
поведінку брокера (`acks`, `min.insync.replicas`, ребаланс груп, транзакції), а питання про брокер часто звучить мовою
клієнта. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує всі чотири сервери:
підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `kafka` | `kafka-docs` | 8886 | сам Apache Kafka 0.7–4.4: брокери, KRaft, конфігурація, протокол, Connect, Streams |
| `kafkajs` | `kafkajs-docs` | 8887 | клієнт KafkaJS для Node.js (на ньому транспорт Kafka NestJS) |
| `confluent-kafka-javascript` | `confluent-kafka-javascript-docs` | 8888 | клієнт Confluent `@confluentinc/kafka-javascript` на librdkafka |
| `platformatic-kafka` | `platformatic-kafka-docs` | 8889 | клієнт `@platformatic/kafka` на чистому TypeScript |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/kafkajs-corpus-2026-10-25.tar.gz` (196 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\kafkajs-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/kafkajs/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/kafkajs-corpus-РРРР-ММ-ДД.tar.gz -C instances/kafkajs corpus raw
find instances/kafkajs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/kafkajs/raw
gzip -9 -c instances/kafkajs/index/passages.json > instances/kafkajs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/kafkajs-corpus-2026-10-25.tar.gz -C instances/kafkajs
./df kafkajs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/kafkajs/index/passages.json.gz`,
далі `./df kafkajs vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df kafkajs …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df kafkajs sources --why   # перелік джерел і білий список
./df kafkajs refresh         # завантажити все задеклароване (кілька хвилин)
./df kafkajs manifest        # оновити паспорт
./df kafkajs setup           # Qdrant чи пошук лише по словах
./df kafkajs vectors         # залити корпус у docs-kafkajs
./df kafkajs smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df kafkajs serve          # порт 8887
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8887/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user kafkajs-docs http://127.0.0.1:8887/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `kafkajs-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
