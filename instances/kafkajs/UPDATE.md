# Оновлення корпусу kafkajs

Перелік версій README і реєстру тут не оголошується руками: читачі беруть його з опису пакета в реєстрі npm
(`https://registry.npmjs.org/kafkajs`), журнал змін — з `CHANGELOG.md` на master, тож нова версія потрапляє туди сама.
Теги сайту записано в `sources.json` руками (ключ — коміт тегу).

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df kafkajs check                 # чи змінилося щось нагорі за джерелом
./df kafkajs refresh               # повне перезавантаження, кілька хвилин
./df kafkajs manifest
./df kafkajs vectors
./df kafkajs smoke
# Ctrl+C у терміналі з serve, і знову: ./df kafkajs serve
```

`refresh` повний, не `--missing`: у документі стоять усі версії, де текст був таким, тож нова версія змінює й старі
документи.

Нова мінорна версія (2.3) — ще й новий тег сайту: у джерелі `kafkajs-site` в об'єкт `tags` дописують коміт тегу
`v2.3.Z` з версією `2.3.Z`, а для нової латки тієї самої мінорної — замінюють коміт старої латки новим. Коміт тегу дає
`https://api.github.com/repos/tulios/kafkajs/git/refs/tags/v2.3.0`. Передрелізи (`-beta`) не беруться.

Якщо зміниться версія, яку завантажують найбільше, — у `prompts/search.txt` (абзац «Which version to search first») і
`prompts/agent.txt` замінити її, звіривши з `https://api.npmjs.org/versions/kafkajs/last-week`; на 25.10.2026 2.2.4 мала
близько 92 %.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен: дерев тегів сайту 28, а без токена GitHub дає 60 звернень
на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df kafkajs quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
