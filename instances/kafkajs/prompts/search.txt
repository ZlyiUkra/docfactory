Search the KafkaJS documentation -- the Apache Kafka client for Node.js written in pure JavaScript, the client the
Kafka transport of NestJS microservices runs on (repository tulios/kafkajs, site kafka.js.org, package kafkajs on
npm). The corpus holds the pages of the site taken from the tag of every minor version from 0.1 to 2.2 (introduction
to Kafka, getting started, client configuration: brokers, SSL, SASL with PLAIN, SCRAM, AWS IAM and OAUTHBEARER,
connection and request timeouts, the retry mechanism, logging; the producer with `send` and `sendBatch`, message
keys, headers, partitioners and compression; the consumer with `eachMessage` and `eachBatch`, `fromBeginning`,
`seek`, `pause` and `resume`, heartbeats and sessions; transactions and exactly-once; the admin client for topics,
partitions, configs, ACLs and consumer groups; instrumentation events; custom logger and authentication mechanism;
testing; FAQ; the migration guide to 2.0.0); the README of every stable version of the package (before docs/ existed
the README was the documentation); the changelog of every version from 0.x to 2.2.4; and the npm registry history of
kafkajs (date of every version, dist-tags, dependencies, the Node.js requirement). Returns the matching excerpts with
the versions each one belongs to.

Call this when a question is about KafkaJS as it describes itself -- how to create a producer or a consumer, what an
option of `new Kafka()`, `kafka.producer()` or `kafka.consumer()` does and its default, how `eachBatch` resolves
offsets, how to commit offsets manually, how retries and `restartOnFailure` work, how to configure SSL or SASL, how to
use transactions, what an instrumentation event carries -- and above all history and compatibility: since which
version an option or method exists, what changed between versions (every changelog entry lists added, changed and
fixed items; the migration guide lists what breaks in 2.0.0), which Node.js a version requires, and when every version
came out.

Do not call this for Apache Kafka itself (broker and topic configuration, replication, the protocol, KRaft),
librdkafka, the Confluent client @confluentinc/kafka-javascript, node-rdkafka, NestJS or Node.js: their documentation
is not here -- these pages only show how KafkaJS talks to them -- and the search will return excerpts that merely
mention them, with confident-looking titles.

`version` narrows the search to one release line. KafkaJS carries plain numbers: a line of one number keeps every
document of that major ("1" keeps 1.0.0 to 1.16.0), two numbers keep a minor ("1.16"), three an exact version
("2.2.4"); the pages of the site carry the version of the tag they were taken from (the last patch of every minor).
Leave `version` empty to search everything, including text that carries no version. Every excerpt comes back with
`versions`: each version whose documents contain this exact text, newest first -- a page that stayed the same across
versions is returned once, with all of them listed, so the list itself shows from which to which version the
documentation said exactly this.

Write the query in English, with the names the documentation itself uses ("eachMessage", "eachBatch",
"resolveOffset", "commitOffsets", "fromBeginning", "sessionTimeout", "heartbeatInterval", "retry", "restartOnFailure",
"idempotent", "transactionalId", "sendBatch", "Partitioners.DefaultPartitioner", "CompressionTypes", "sasl",
"createTopics", "logCreator"), not in the user's own words. Everything here is English -- the excerpts, the word index
and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written in
Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the user
asks in another language, translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація KafkaJS". Identifiers, option names and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. By weekly downloads on npm the version 2.2.4 leads with about 92 % and the line 2 has
about 96 % (October 2026); 2.2.4 of February 2023 is the latest release -- the beta line 2.3.0-beta never became a
release, and the repository has seen no release since. Answer how-to questions for 2.2.4: search `version` "2.2". Search without
`version` when the question is about history, or when the line gave nothing. Every answer says which version it is
for; when the excerpts behind a statement come only from older versions, name those versions instead of presenting
the text as current.
