# konva — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Konva — бібліотеку, яка малює на HTML5 canvas об'єктами (`Stage`,
`Layer`, фігури, події, перетягування, `Transformer`, фільтри, анімації) — і про react-konva, її обгортку для React.
Документація — сайт konvajs.org станом на 16.11.2026 (Konva 10.9.1), README кожної стабільної версії трьох пакетів,
журнал змін і релізи GitHub; лише англійською. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Браузер дає для малювання елемент `<canvas>` і його Canvas API: набір команд «проведи лінію», «залий прямокутник».
Намальоване стає просто пікселями: полотно не пам'ятає, де який прямокутник, тому не може сказати, по якій фігурі
клацнули, і не може пересунути одну фігуру, не перемалювавши все. Konva додає поверх полотна дерево об'єктів. Кожна
фігура — об'єкт із властивостями (`x`, `y`, `fill`), його можна слухати (`on('click')`), тягати мишею (`draggable`),
змінювати в розмірі рамкою (`Transformer`), і Konva сама перемальовує полотно, коли об'єкт змінився. Сам Canvas API
описано в примірнику `mdn`; тут — лише те, що додає Konva.

react-konva дозволяє описати те саме дерево компонентами React: `<Stage>`, `<Layer>`, `<Rect>`. Його мажорна версія
повторює мажорну версію React (react-konva 19 працює з React 19, react-konva 18 — з React 18), тому відповідь мусить
знати, для якої версії вона.

**Що є що.** **Stage** — корінь дерева, прив'язаний до елемента сторінки; **Layer** — шар, кожен шар малюється на
власному елементі `<canvas>`; **Group** — група фігур, що рухається як одне ціле; **Shape** — фігура (`Rect`,
`Circle`, `Line`, `Text`, `Image` та інші); **Transformer** — рамка з маркерами, якою користувач змінює розмір і кут
вибраної фігури; **Tween** — плавна зміна властивостей фігури за заданий час; **cache** — знімок фігури в окремому
полотні, щоб не малювати її щоразу заново.

## Звідки документація

- **Сайт — з репозиторію, а не зі сторінок.** Сайт konvajs.org збирає Docusaurus із репозиторію `konvajs/site`, і
  читач `ghdocs-history` бере теку `content` на коміті `dc0f3676` від 16.11.2026. Сайт віддає й готові
  markdown-двійники сторінок (`…/Arc.md`), але двійників немає в прикладів sandbox і в довідника API, і вони не
  підписують вкладки. У файлах `.mdx` вкладки названо (`<TabItem value="Vanilla">`), і поле `docusaurus_tabs` ставить
  перед кожним блоком коду підпис «Vanilla:», «React:» чи «Vue:». Без підписів у тексті стояли б три блоки коду
  поспіль, і не було б видно, котрий для чого.
- **Адреси сторінок.** Адресу сторінки на сайті задає поле `slug` у шапці файла, а не ім'я файла:
  `content/docs/styling/01-Fill.mdx` — це `konvajs.org/docs/styling/Fill.html`. Поле `site` у `sources.json` описує ці
  правила, тож у цитаті стоїть адреса сайту. Усі 313 адрес звірено з `sitemap.xml`.
- **Мітка версії сайту.** Репозиторій сайту тегів не ставить, і сайт описує лише поточну Konva. Тому всі його
  сторінки, разом із розділами React, Vue, Svelte й Angular, несуть мітку `10.9.1` — останньої версії konva на день
  знімка.
- **Код прикладів.** Сторінки розділу Svelte, три приклади sandbox і сторінка Complex Animations розділу React коду
  не містять: вони показують його вікном CodeSandbox із тек `svelte-demos` і `react-demos` того самого репозиторію.
  Читач `ghexamples` бере ці теки: одна тека прикладу — один документ, кожен файл коду — окремий розділ.
- **README.** Реєстр npm віддає README лише найновішої версії, тому README кожної версії читається з репозиторію на
  коміті її публікації (`gitHead`), а де реєстр коміту не записав — з тегу `v{version}`.
- **Версії react-konva з префіксом.** react-konva і react-konva-utils мають власну нумерацію, тому їхні документи
  несуть версію з префіксом (`react-konva-19.3.2`, `react-konva-utils-2.1.1`). Без префікса фільтр «10» змішав би
  Konva 10 з чужими лініями.
- **Журнал змін.** `CHANGELOG.md` Konva пише заголовок версії чотирма способами («## 10.9.1 (2026-10-31)»,
  «## 7.0.0 - 2020-06-23», «### 9.3.1 (…)», голе «## 4.0.1»); читач `changelog-otel` знає всі чотири й дає документ
  на кожну з 226 версій. Тим самим читачем поділено `RELEASE_NOTES.md` react-konva.

## Межі, про які треба пам'ятати

- Посібник, приклади й довідник API є лише для Konva 10.9.1. Про старіші версії відомо з README, журналу змін і
  релізів.
- README немає в п'яти версій, для яких реєстр не записав ні коміту, ні тегу: react-konva 0.4.0, 0.4.1, 0.4.2 і
  19.2.7, react-konva-utils 0.1.0.
- Релізи konva на GitHub починаються з 9.2.1; раніші версії описує журнал змін.
- Пакети `vue-konva`, `svelte-konva` і `ng2-konva` (README, реєстр, релізи) не входять: є лише сторінки сайту про
  них і код прикладів Svelte. Китайський переклад сайту не береться, передрелізи теж.
- Сам Canvas API браузера і SVG — у примірнику `mdn`; сам React — у примірнику `react`. Інші бібліотеки для полотна
  (Fabric.js, PixiJS, Paper.js) не входять.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/konva-corpus-2026-11-17.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\konva-corpus-2026-11-17.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів немає
ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/konva/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/konva-corpus-РРРР-ММ-ДД.tar.gz -C instances/konva corpus raw
find instances/konva/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/konva/raw
gzip -9 -c instances/konva/index/passages.json > instances/konva/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/konva-corpus-2026-11-17.tar.gz -C instances/konva
./df konva smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/konva/index/passages.json.gz`, далі
`./df konva vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df konva …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/konva/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df konva sources --why    # перелік джерел і білий список
./df konva refresh          # усе: близько 7 хвилин мережею (паузи 0,2 с)
./df konva manifest         # оновити паспорт
./df konva setup            # Qdrant чи пошук лише по словах
./df konva vectors          # залити корпус у docs-konva
./df konva smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df konva serve   # порт 8989
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8989/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user konva-docs http://127.0.0.1:8989/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `konva-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
