# kraken-spot — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про API споту біржі Kraken — як отримати ринкові дані (тікер, свічки,
книгу заявок, угоди), як під'єднатися до WebSocket v2 і підписатися на канал, як підписати запит REST, які є ордери,
ліміти й помилки і що в API змінилося. Джерело — офіційний сайт документації docs.kraken.com, лише англійською. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

Kraken — запасне джерело ринкових даних для модулів «список монет» і «живі ціни» в планах навчання React і NestJS
(основне — Binance, примірник `binance-spot`). Плани велять перейти на Kraken WS v2, якщо Binance недоступний з вашої
країни чи мережі, — а формат там інший: підписка окремим повідомленням, ціни числами JSON, книга заявок із
контрольною сумою CRC32. Ці правила, назви пар (`XBT` замість `BTC`, `wsname`, `altname`) і ліміти — у цій
документації; Kraken її міняє щотижня, і журнал змін каже, коли саме, — тож потрібен поточний текст, а не пам'ять
моделі.

**Що таке спот.** Спот — звичайна купівля й продаж монети за іншу монету з негайною поставкою, на противагу
ф'ючерсам (деривативам) і маржинальній торгівлі. **Ринкові дані** — публічна частина API: ціни, угоди, свічки, книга
заявок; ключ для них не потрібен. **Канал** (channel) — підписка WebSocket, якою біржа сама надсилає зміни: спершу
знімок (snapshot), далі оновлення (update).

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

| Гайди: огляд API, швидкий старт, вибір протоколу, ліміти, помилки, `cl_ord_id`, amend, L3, ключі й підпис REST, автентифікація WebSocket, контрольні суми книги, перепідключення | 26 | 247 |
| Журнал змін біржового API: 116 записів, 28.11.2018–06.10.2026 | 1 | 120 |

Разом 122 документи; фрагментів в індексі — 848 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук.

Замір `quality`: перша десятка (питання своїми словами) — по словах 8 із 10, за змістом 9, разом 8; друга, «як
модель» (назви ендпойнтів, каналів, полів і помилок, як велить промпт), — 10 із 10. Обидва промахи першої десятки —
питання без жодного слова документації («число, що мусить рости» замість `nonce`, «оновлення моїх ордерів» замість
`executions`). Поле `max_per_doc: 3` (не більше трьох фрагментів з документа у видачі) дало те саме «разом» і «як
модель», що й без нього, і на один більше за змістом: на 0, 1, 2 і 3 — «разом» 8, 8, 7 і 8, «як модель» 10, 9, 10 і 10.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (тут не потрібен: усе йде з docs.kraken.com);
  `.mcp.json` — запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df kraken-spot <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| REST, WebSocket v2, гайди, журнал змін | `https://docs.kraken.com/sitemap.xml`, текст — markdown-двійник кожної сторінки (`<адреса>.md`) | `sitemap-mintlify` |

Сайт зроблено на Mintlify, і кожна його сторінка віддає markdown за тією ж адресою з «.md». Білий список — поле
`within` кожного з чотирьох джерел: теки розділів сайту і поіменні адреси там, де в одній теці лежать і спот, і
деривативи (ринкові дані, субакаунти). Посилання у відповідях ведуть на сторінки docs.kraken.com.

Офіційного репозиторію з документацією в Kraken немає, офіційного пакета для JavaScript у npm теж: усі `kraken-*`
там сторонні. Офіційні SDK є лише для Go (`krakenfx/api-go`) і Rust (`krakenfx/kraken-api-sdk`), плюс консольна
утиліта `kraken-cli`; у примірник вони не беруться.

Особливості, які варто знати:

- **Сторінка ендпойнта REST — це OpenAPI.** Сайт показує на ній шматок специфікації одним блоком YAML: шапка
  специфікації (однакова на всіх сторінках) і схема з прикладами, подекуди на сто з гаком тисяч символів. Огорожу
  коду рушій на фрагменти не ріже, тож читач розбирає YAML і пише розділи `Request` (метод і повна адреса, чи
  потрібен ключ, параметри, поля тіла) і `Response` (поля відповіді списком з описами й переліками значень, короткі
  приклади JSON — до 1 500 символів). Розбирає PyYAML, що приходить разом із fastembed.
- **Поля WebSocket — компоненти MDX.** Ім'я поля, його тип і обов'язковість стоять в атрибутах
  `<ResponseField name="symbol" type="string[]" required>`; читач робить із них пункт списку «`symbol` (string[],
  required)», вкладені поля — з відступом.
- **Блок «Documentation Index»** на початку кожної сторінки вирізається: інакше це 122 однакові фрагменти без змісту.
- **Назви з префіксом.** Ендпойнт REST і метод WebSocket часто звуться однаково («Add Order»), тож документи REST
  звуться «Spot REST: …», а сторінки WebSocket — «WebSocket v2: …».
- **WebSocket v1 не береться.** Він підтримується як legacy, але канали звуться так само (ticker, book, trade), і
  пошук змішував би обидві версії. Про v1 лишаються згадки в гайдах і журналі змін.
- **Журнал змін — один документ** на весь біржовий API: спот, деривативи, FIX, affiliate. Фрагмент — запис дня
  («6 October 2026 — Spot REST v1»).

## Версії у відповіді

Версій у документації немає: вона описує API як він є зараз, а журнал змін — його історія за датами. Фільтр
`version` у цього примірника вимкнено. Коли ліміт чи поле могли змінитися, відповідь називає дату запису журналу.

## Межі, про які треба пам'ятати

Тут немає деривативів (ф'ючерсів), FIX, довідника WebSocket v1, інституційних API (custody, OTC, prime), Embed і Pay,
affiliate, SDK і `kraken-cli`. Сам протокол WebSocket і браузерний `WebSocket` — у примірниках `webstandards` і `mdn`;
Binance — у `binance-spot`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/kraken-spot-corpus-2026-10-11.tar.gz` (176 КБ, 122 тексти й паспорт;
перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде.
Архів лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/kraken-spot/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/kraken-spot-corpus-РРРР-ММ-ДД.tar.gz -C instances/kraken-spot corpus
find instances/kraken-spot/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/kraken-spot/index/passages.json > instances/kraken-spot/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/kraken-spot-corpus-РРРР-ММ-ДД.tar.gz -C instances/kraken-spot
./df kraken-spot smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/kraken-spot/index/passages.json.gz`,
далі `./df kraken-spot vectors` заллє колекцію Qdrant (кілька хвилин).

## Установка venv

```
cd instances/kraken-spot
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # якщо потрібен крок ask, впишіть ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

```
./df kraken-spot sources --why   # перелік джерел і білий список
./df kraken-spot refresh         # завантажити все задеклароване (~2 хвилини)
./df kraken-spot manifest        # оновити паспорт
./df kraken-spot setup           # Qdrant чи пошук лише по словах
./df kraken-spot vectors         # залити корпус у docs-kraken-spot (кілька хвилин)
./df kraken-spot smoke           # перевірки
```

**Нова сторінка на сайті** в уже взятій теці (новий канал WebSocket v2, новий гайд REST) з'явиться сама: перелік
береться з sitemap.xml. Новий ендпойнт ринкових даних чи субакаунтів — ні: ці дві теки взято поіменно, бо поруч
лежать деривативи; його адресу дописують у `within` джерела `rest`.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df kraken-spot serve       # порт 8824
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8824/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user kraken-spot-docs http://127.0.0.1:8824/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `kraken-spot-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію
Claude Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і
«Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
