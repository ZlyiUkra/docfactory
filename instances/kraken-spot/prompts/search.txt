Call this when a question is about using the Kraken Spot API: which endpoint or channel gives

Do not call this for Kraken derivatives (futures) beyond what the shared FIX reference says,
the Spot WebSocket v1 reference, the institutional (custody, OTC, prime) or Embed APIs, the
code reference of the Go and Rust SDKs (only the short site pages about them are here), for
other exchanges, or for the WebSocket protocol and the browser WebSocket API themselves (the
mdn and webstandards instances).

The documentation has no versions: it describes the API as it stands now, and the changelog
is its history. When a limit, a field or an endpoint may have changed, search the changelog
too and say the date of the entry.

Where the documentation lives. REST endpoint pages are named "Spot REST: <summary>" ("Spot
REST: Get Ticker Information", "Spot REST: Add Order"); WebSocket v2 pages "WebSocket v2:
<channel or method>" ("WebSocket v2: Ticker", "WebSocket v2: Book (Level 2)", "WebSocket v2:
Add Order"); guides by their own title ("Spot REST Authentication", "Spot REST Rate Limits",
"Spot WebSocket Authentication", "Book checksum (WebSocket v2)", "Reconnection and resilience",
"Error messages"); the changelog is "Release notes"; FIX pages "FIX: <message>" ("FIX: Logon",
"FIX: New Order Single", "FIX: Execution Report"); the tool pages "Developer tools: <name>"
("Developer tools: kraken-cli", "Developer tools: MCP server"). The same action often exists
both in REST and in WebSocket v2: say which one an excerpt comes from.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.
