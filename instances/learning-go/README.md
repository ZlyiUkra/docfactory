# learning-go — примірник фабрики docfactory

Захищений MCP-сервер для читання книжки «Learning Go: An Idiomatic Approach to Real-World Go Programming», 2nd Edition
— Jon Bodner; O'Reilly Media, 2024 — разом з офіційним кодом книжки й двома вільними для читання книжками про Go:
«100 Go Mistakes and How to Avoid Them» (Teiva Harsanyi; Manning, 2022) у викладі автора на 100go.co і «Go 101»
(Tapir Liu, go101.org), а також другий підручник — «Go by Example: Programmer's guide to idiomatic and testable code»
(Inanc Gumus; Manning Publications, 2025). Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає
самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

Книжка Боднера — основа плану вивчення Go: вона вчить не синтаксису, а ідіоматичного Go — як мова хоче, щоб на ній
писали (нульове значення, зрізи й відображення, затінення, замикання, `defer`, «accept interfaces, return structs»,
обгортання помилок, конкурентність через канали й `select`, контекст, тести). Кожна глава закінчується вправами, а
розв'язки лежать у репозиторіях книжки на GitHub. Сервер — довідка під час читання: «що каже книжка про затінення»,
«що питає вправа 3 глави 5», «як офіційний розв'язок робить вправу 2 глави 12». «100 Go Mistakes» — типові помилки
з поясненням, чому вони помилки (питання співбесід часто саме про них), «Go 101» — подробиці мови, яких немає в
специфікації простими словами (правила каналів, порядок обчислень, вартість копіювання значень). «Go by Example»
Гумуса — книжка-практикум: тестований пакет, покриття й оптимізація, програма командного рядка, впровадження
залежностей, HTTP-сервіс, структура проєкту, композиція й поліморфне сховище, з додатками про основи мови; її глави
ближчі до фулстек-проєкту, ніж глави Боднера. Сайт gobyexample.com (Mark McGranaghan) — інша річ, він у примірнику
[go](../go/README.md).

Специфікація мови, довідник стандартної бібліотеки й примітки до випусків — в окремому примірнику [go](../go/README.md)
(сервер `go-docs`).

## Корпус лише локально

Тексти «Learning Go» і «Go by Example» захищені авторським правом, «Go 101» — теж (автор лишає всі права:
читати на сайті вільно, перевидавати не можна), виклад «100 Go Mistakes» — під CC BY-NC-ND 4.0. Тому **корпус і
індекс у git не потрапляють** (`corpus/` і `index/` у `.gitignore`), у git лежать лише налаштування примірника. З тієї
ж причини промпт велить переказувати своїми словами, цитувати коротко й називати главу й розділ. Код книжки вільний
(MIT), але лежить у тому самому корпусі.

**Де тексти.** Корпус в архіві: `~/archives/docfactory/learning-go-corpus-2026-10-27-gbe.tar.gz` (549 текстів, паспорт і
сховище сирого `raw/` джерел з GitHub; перед видаленням текстів архів розпаковано окремо й звірено з диском) і копія на
Windows `C:\Distr\learning-go-corpus-2026-10-27-gbe.tar.gz` (звірено за SHA-256). Сервер підіймається з кешу фрагментів
`index/passages.json` (лише на цій машині) і колекції Qdrant. Обидві книжки читач бере з PDF у теці Downloads
користувача (`C:\Users\ne__r\Downloads\LearningGo,2ndEdition-JonBodner.pdf` і
`go_by_example_programmers_guide_to_idiomatic_and_testable_code.pdf`, з WSL — `/mnt/c/Users/ne__r/Downloads/…`): якщо
файл перенести, шлях треба замінити в полі `file` джерела `book` чи `gbe`.

**Як повернути тексти** — перед оновленням корпусу:

```
tar -xzf ~/archives/docfactory/learning-go-corpus-2026-10-27-gbe.tar.gz -C instances/learning-go
./df learning-go smoke
```

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
tar --sort=name -czf ~/archives/docfactory/learning-go-corpus-РРРР-ММ-ДД.tar.gz -C instances/learning-go corpus raw
find instances/learning-go/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/learning-go/raw
```

Тексти видаляють лише тоді, коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у
«Де тексти». `check`, `refresh` і `manifest` без текстів працювати не можуть; `smoke` пропускає їхні перевірки з
позначкою «корпус в архіві». **На іншій машині** кешу немає: тексти повертають з архіву, далі `./df learning-go
vectors`.

## Що в цій теці

- `corpus/` — паспорт `index.json` (тексти — в архіві, див. вище); у git не потрапляє.
- `index/` — кеш фрагментів, з якого підіймається сервер; у git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df learning-go <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| Learning Go | локальний PDF (поле `file`), закладки PDF — межі глав | `pdf-book` |
| Go by Example (Gumus) | локальний PDF, закладки — межі глав і додатків; імена документів з префіксом `gbe-` | `pdf-book` |
| код книжки | api.github.com, дерево гілки `main` кожного з 28 репозиторіїв learning-go-book-2e | `ghcode` |
| 100 Go Mistakes | тека `docs/` гілки master teivah/100-go-mistakes, крім перекладів | `ghdocs-history` |
| Go 101 | тека `pages/` гілки master go101/go101, файли `.html` | `ghdocs-history-html` |

Новий читач `pdf-book` (engine/readers/pdfbook.py). Простий витяг тексту з PDF губить межі коду й відступи, тому
читач бере кожен шматок тексту з його шрифтом, кеглем і місцем на сторінці й вирішує за шрифтом, що це: абзац,
заголовок, код чи колонтитул. Книжка O'Reilly набрана так: текст — Minion Pro 10,5 (у врізках 9,6), код — Ubuntu Mono
8,5, код у тексті — Ubuntu Mono 10, заголовки — Myriad Pro: 18,9 — розділ, 15,8 — підрозділ, 15,0 — назва врізки.
Ці кеглі записано в джерелі `book` (`headings`, `labels`, `code_max`), тож інша книжка того самого видавця потребує
лише інших чисел. Manning набирає інакше: текст — New Baskerville 10, код — Courier 8 (знак ширший: 0,6 кегля,
поле `code_char_width`), розділ «2.1» і підрозділ «2.1.1» — Franklin Gothic Demi Italic 12,5 і 10,5, а назва врізки —
Demi того самого кегля 10,5, тож у `headings` і `labels` після кегля стоїть ще вираз шрифту («10.5/DemiIt»).
Примітки на полях лістингу (Humanist 521, поле `aside_fonts`) стають рядком «Annotations:» під кодом, поруч з яким
стоять; написи на малюнках (Arial) випадають (`drop_fonts`), маркери списку Wingdings стають пунктами
(`bullet_fonts`), колонтитул угорі сторінки відсікає висота (`furniture_above`). Документи цієї книжки мають префікс
`gbe-` (`name_prefix`): обидві книжки мають «Preface» і «Chapter 1 …». Документ — глава, межі глав — закладки PDF; відступ рядка коду — відстань від лівого краю коду в
ширинах знака. Кожен пункт розділу «Exercises» стає підрозділом «Exercise N». Переноси слів («dupli-cate») і розриви
кернінгу («Y ou’re») читач лагодить за словником самої книжки, а справжні дефіси («compile-time») лишає.

Сторінки Go 101 загортають кожен абзац і пункт списку в `<div class="tmd-usual">`; поле `drop` знімає обгортки,
інакше маркер пункту відривався від свого тексту.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df learning-go …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`), а `pypdf` уже є в спільних наборах. Як збудувати середовище один раз — у кореневому
README, розділ «Спільне середовище».

## Збирання корпусу

```
./df learning-go sources --why   # перелік джерел і білий список
./df learning-go refresh         # книжки з PDF і все задеклароване на GitHub (кілька хвилин)
./df learning-go manifest        # оновити паспорт
./df learning-go setup           # Qdrant чи пошук лише по словах
./df learning-go vectors         # залити корпус у docs-learning-go
./df learning-go smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df learning-go serve          # порт 8914
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8914/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user learning-go-book http://127.0.0.1:8914/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `learning-go-book` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
