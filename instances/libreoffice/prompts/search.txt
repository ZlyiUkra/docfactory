Search the LibreOffice documentation, in English. LibreOffice is the office suite (Writer, Calc, Impress, Draw,
Math, Base) that also runs without a window as a document converter (soffice --headless --convert-to). The set
holds the whole LibreOffice Help as published on help.libreoffice.org, for the final release of every line
3.3-26.8 (Writer, Calc with every function, its syntax and examples, Impress, Draw, Math, Base, Basic and
ScriptForge, shared menus, dialogs and options, the guides -- starting with command line parameters, the file
conversion filter tables, the CSV, PDF and other filter options); the text `soffice --help` prints in every
line; the declaration of every import and export filter and file type (the filter name --convert-to and
--infilter take, its direction, file type, extensions and media type); the UNO API reference that
api.libreoffice.org is generated from (every interface, service, struct, enum, constant group and exception of
com.sun.star.*, one section per method, property or value with its description); the LibreOffice Developer's
Guide (UNO, connecting to the office, loading and storing documents, MediaDescriptor, text, spreadsheet and
drawing documents, Basic, extensions); the release notes of every line; the security advisories (one section
per CVE); and the conversion wrappers built on LibreOffice: libreoffice-convert and libreoffice-file-converter
on npm, unoserver and unoconv on PyPI -- README of every version, code, tests and changelogs. Returns the
matching excerpts with the versions each one belongs to.

Call this when a question is about LibreOffice: headless conversion (--headless, --convert-to, --outdir,
--infilter, --cat, --print-to-file, --convert-images-to, -env:UserInstallation for a separate user profile,
parallel conversions, the filter names writer_pdf_Export, calc8, MS Word 2007 XML, "Text - txt - csv
(StarCalc)" and their options), PDF export options, CSV import and export options, other command line
parameters (--accept, --invisible, --norestore, --safe-mode); what a menu command, dialog, option or
keyboard shortcut does in Writer, Calc, Impress, Draw, Math or Base; a Calc function; Basic and ScriptForge;
the UNO API (XComponentLoader.loadComponentFromURL, XStorable.storeToURL, MediaDescriptor properties
FilterName, FilterOptions, Hidden, the desktop, documents, cells, text); what changed in a version; which
security issue was fixed in which version; how unoserver, unoconvert, unoconv, libreoffice-convert or
libreoffice-file-converter call LibreOffice. Example query: "--convert-to pdf filter options".

Do not call this for Microsoft Office, Google Docs, OpenOffice.org or Collabora Online as such, or for
document formats in general (the ODF and OOXML standards themselves).

Write the query in English, with the names LibreOffice uses (--convert-to, -env:UserInstallation,
writer_pdf_Export, FilterOptions, storeToURL, VLOOKUP, Format - Cells). Everything here is English, and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing and comes back with `found: 0`. When the user asks in another language,
translate the question into LibreOffice terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page or section it rests on; a point the excerpts do not support is left out, not guessed.
When that language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian
word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "фільтр",
"параметр командного рядка", "профіль користувача". Never call this set of documents "корпус" -- say
"документація LibreOffice" or "довідка LibreOffice". Command line parameters, filter names, menu commands,
function, interface and method names stay in English, spelled exactly as the documentation spells them.
Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole
of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. LibreOffice documents carry the release line: "26.8", "26.2", "25.8", "24.2",
"7.6", "6.4", "3.3" (since 2024 the lines are numbered by year and month). The wrappers carry their name:
"libreoffice-convert-1.8.2", "libreoffice-file-converter-3.3.0", "unoserver-3.7", "unoconv-0.9.0". The
security advisories, the Developer's Guide and the 3.3 feature list carry no version. When the user names a
version, pass its line into `version` ("26.2", "7.6", "unoserver-3"); never put it into the query text.
Without a named version, answer for 26.8, the newest ("fresh") line, and say where 26.2, the line still
maintained for conservative users ("still"), differs.
