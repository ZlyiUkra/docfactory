# libuv — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про libuv — бібліотеку C, на якій стоїть цикл подій Node.js: цикл
(`uv_loop_t`, `uv_run`), handles і requests, потоки й мережа, файлова система, пул потоків, процеси, сигнали, таймери.
Документація — Sphinx-сайт docs.libuv.org кожної стабільної версії від 0.10.2 до 1.53.0, README, перелік підтримуваних
платформ, політика безпеки і ChangeLog кожного випуску. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Документація Node.js описує лише свій шар: `fs`, `net`, `child_process`. Чому виклики `fs` і `crypto` стають у чергу,
у якому порядку цикл проходить фази, що робить `UV_THREADPOOL_SIZE`, відповідає libuv. Він вбудований у Node, і версія
його в кожному релізі своя: Node 26 несе 1.52.1, Node 24 — від 1.50.0 до 1.52.1, Node 22 — від 1.48.0 до 1.51.0,
Node 20 — від 1.44.2 до 1.46.0 (точні відповідності — у примірнику `nodejs`, документ кожної лінії). Поточна версія
libuv — 1.53.0 (24.09.2026), у Node її ще немає. Сайт docs.libuv.org показує лише найновішу 1.x; тут — усі стабільні.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві.
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — токен GitHub і, для кроку `ask`, ключ Anthropic; `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики через `./df libuv <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| документація, README, платформи, безпека | дерева тегів `libuv/libuv`, `docs/src` і три файли кореня | `ghdocs-history` з `sphinx: true` |
| ChangeLog | `ChangeLog` гілки v1.x | `changelog-libuv`, новий |

Особливості:

- **Опис API — у директивах Sphinx.** Кожна функція й тип записані як `.. c:function:: int uv_run(…)` з описом у тілі.
  Спільний розбір Sphinx такі директиви викидав, і сторінка лишалась самим вступом. Розбір дістав їх як «Function:
  `сигнатура`» з описом, а `versionadded`, `versionchanged`, `deprecated` — рядком «Added in version X».
- **Журнал не markdown.** Заголовок запису — «2026.09.24, Version 1.53.0 (Stable), хеш»; читач `changelog-libuv`
  (модуль `changeloguv`) робить з нього документ на версію й лишає стан лінії (Stable, Maintenance).
- **Імена документів** — шлях у репозиторії: `docs-src-threadpool`, `docs-src-guide-networking`.

## Межі, про які треба пам'ятати

Документації Node.js (вона в `nodejs`), V8 (`v8`), OpenSSL, ICU й інших вбудованих бібліотек, а також обгорток libuv в
інших мовах (Luv, libuv-rs) тут немає. Приклади коду `docs/code` не беруться: вони підключені до сторінок директивою
`literalinclude`, яку розбір Sphinx не розкриває; коментарів у вихідному коді libuv теж немає.

## Архівний режим: сервер без корпусу

Корпус в архіві від самого початку: у `corpus/` лежить лише паспорт, а сервер підіймається з кешу фрагментів і
колекції Qdrant; відповіді ті самі до символа.

**Де тексти.** В архіві `~/archives/docfactory/libuv-corpus-2026-10-14.tar.gz` (5 МБ, 594 тексти, паспорт і сховище
сирого `raw/`; перед видаленням розпакований окремо й звірений з диском — нуль розбіжностей). Лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
tar -czf ~/archives/docfactory/libuv-corpus-РРРР-ММ-ДД.tar.gz -C instances/libuv corpus raw
find instances/libuv/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/libuv/raw
gzip -9 -c instances/libuv/index/passages.json > instances/libuv/index/passages.json.gz
```

і закомітити паспорт та `passages.json.gz`; видаляти тексти — лише після звірки архіву з диском.

**Як повернути тексти** — перед будь-яким оновленням:

```
tar -xzf ~/archives/docfactory/libuv-corpus-2026-10-14.tar.gz -C instances/libuv
./df libuv smoke
```

**Оновлення.** Новий тег дописують першим рядком у `tags` джерела `libuv-docs` («"v1.54.0": "1.54.0"»); ChangeLog
береться з гілки сам. Далі `./df libuv refresh`, `manifest`, `vectors`, `smoke`, `quality`.

## Установка venv

```
cd instances/libuv
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df libuv sources --why   # перелік джерел і білий список
./df libuv refresh         # завантажити все задеклароване (близько 10 хвилин)
./df libuv manifest        # оновити паспорт
./df libuv setup           # Qdrant чи пошук лише по словах
./df libuv vectors         # залити корпус у docs-libuv
./df libuv smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df libuv serve          # порт 8838
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8838/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user libuv-docs http://127.0.0.1:8838/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `libuv-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
