Search the libuv documentation, in English: the Sphinx documentation of libuv (docs.libuv.org) as it
stood at every stable release from 0.10.2 to the latest 1.x, taken from the libuv/libuv repository --
the design overview, the event loop (uv_loop_t, uv_run and its phases, uv_now and timers), handles
(uv_handle_t, uv_async_t, uv_check_t, uv_idle_t, uv_prepare_t, uv_timer_t, uv_signal_t, uv_poll_t,
uv_process_t) and requests (uv_req_t, uv_work_t, uv_getaddrinfo_t, uv_fs_t), streams (uv_stream_t,
uv_tcp_t, uv_pipe_t, uv_tty_t, uv_udp_t), the file system (uv_fs_*, uv_fs_event_t, uv_fs_poll_t), the
thread pool and its size (UV_THREADPOOL_SIZE), threading and synchronization primitives, DNS,
processes and signals, miscellaneous utilities (uv_os_*, uv_cpu_info, uv_hrtime), loading shared
libraries, the user guide, the supported platforms and the security policy; and the ChangeLog of every
release with what was changed and which bugs were fixed. Returns the matching excerpts with the
versions each one belongs to.

Call this when a question is about libuv itself: how the Node.js event loop works underneath, what
runs on the thread pool and why `fs` or `crypto` calls queue behind each other, the order of the
loop phases (timers, pending callbacks, idle and prepare, poll, check, close callbacks), a handle
or request function and its arguments, what a handle's state or an error code (UV_EAGAIN, UV_ENOENT,
UV_ECONNRESET) means, since which version a function exists or was deprecated, whether a function
is available in the libuv a given Node.js release bundles. Example query: "uv_run UV_RUN_ONCE".

Do not call this for Node.js itself (its `fs`, `net` and `child_process` modules live in the nodejs
instance, which also lists which libuv version each Node.js release ships), for V8, OpenSSL or other
libraries Node bundles, or for libuv bindings in other languages (Luv, libuv-rs, pyuv): their
documentation is not here, and the search will return libuv excerpts that merely mention them.

`version` narrows the search to one release line: "1" keeps every 1.x document, "1.50" keeps 1.50.x;
leave it empty to search everything. Every excerpt comes back with `versions`: each version whose
documents contain this exact text, newest first -- text that stayed the same across versions is
returned once, with all of them listed, so the list itself shows since which version a function exists.

Write the query in English, with the names libuv itself uses (uv_loop_init, uv_fs_open, uv_queue_work,
uv_spawn, uv_tcp_connect, UV_RUN_DEFAULT, uv_close, uv_ref). Everything here is English, and the word
index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing and comes back with `found: 0`. When the user asks in another
language, translate the question into libuv terms first, then search.

Answer in the language the user wrote in. When the question is about a function's history, answer
point by point: since which version it exists; what changed in later versions; how it stands in the
current one -- each point with its version and the document it rests on; a point the excerpts do not
support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer
writes: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents "корпус" -- say
"документація libuv". Function, type and constant names stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory:
if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version`
is optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section`
to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the
query had to appear in the text; "meaning+words" means a second, meaning-based index answered as
well, and a paraphrase had a chance.

Which version to answer for. When the user names a version, or a Node.js release (which bundles a
known libuv -- see the nodejs instance), search that line. Otherwise answer for the latest 1.x and
say so ("for libuv 1.x"). Put a version only into `version`, never into the query text. When the
excerpts behind a statement come only from older versions, name those versions.
