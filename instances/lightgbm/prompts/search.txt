Search the documentation of LightGBM, the gradient boosting library that grows decision trees leaf by leaf on histograms of the
features, and can also train a random forest with `boosting="rf"`. The corpus holds: the docs/ folder of the repository at the last
patch of every minor line 1-4.7 (the full parameter reference with aliases and defaults, parameter tuning, features, advanced topics,
GPU, distributed learning, the Python introduction, FAQ) with the READMEs of the examples; the Python API reference of the site
(`lightgbm.train`, `lightgbm.cv`, `Dataset`, `Booster`, `LGBMClassifier`, `LGBMRegressor`, `LGBMRanker`, callbacks such as
`early_stopping` and `log_evaluation`, plotting) for the lines 3.2-4.7; the PyPI records of every stable version; and the GitHub release
notes of every stable tag.

Use this tool for: training parameters, their aliases and defaults (`num_leaves`, `max_depth`, `learning_rate`, `min_data_in_leaf`,
`feature_fraction`, `bagging_fraction`, `bagging_freq`, `lambda_l1`, `max_bin`), `boosting="rf"` and other boosting types, the GPU and
CUDA versions (`device_type`), early stopping, categorical features, `Booster.predict` with `raw_score`, `pred_leaf` and `pred_contrib`,
saving models as text or JSON, feature importance, and what changed between versions. Write the query in English, with the name of the
parameter, class or page, such as `bagging_fraction` or `Booster.predict`. Give a version in the filter when the answer depends on it.

Do not use it for XGBoost, scikit-learn, NumPy or the Python language: other servers hold them. The Python API reference starts at
3.2, because the site publishes no older version. Returns the matching excerpts with the versions each one applies to, the source
address and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. LightGBM 4.7.0 is the newest release. Search without `version` first; when the user names
their LightGBM version, search that line, written as `lightgbm-4.7` or `lightgbm-3.3`. Every answer about a parameter says
which line it is for: parameters and their defaults changed between lines (for example `early_stopping_rounds` left
`train()` in 4.0 for the `early_stopping` callback).
