# lightweight-charts — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Lightweight Charts™ — безкоштовну бібліотеку фінансових графіків
від TradingView (пакет npm `lightweight-charts`): як створити графік і додати серію свічок, лінії чи гістограми, у
якому вигляді віддавати дані й час, як налаштувати шкали цін і часу, панелі, перехрестя, маркери, лінії цін, водяний
знак і форматування цін, як підписатися на рух миші й прокручування, як писати власні плагіни, як підключити графік у
React, Vue чи веб-компоненті і як він працює в обгортках для Android та iOS. Джерела — офіційний сайт
tradingview.github.io/lightweight-charts, репозиторій GitHub і реєстр npm, лише англійською. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

Факультатив «крипта» плану React малює графіки цін саме цією бібліотекою, а її API між мажорними версіями переписано:
у 5.0 серії додаються одним методом `addSeries`, маркери й водяний знак стали окремими плагінами, з'явилися панелі.
Більшість прикладів у мережі й у пам'яті моделі написано API 4.x, який у 5.x уже не працює. Тож потрібен текст
документації кожної версії, а не пам'ять моделі.

**Що таке серія.** Серія (series) — один набір даних на графіку з власним способом малювання: свічки
(`CandlestickSeries`), бари, лінія, область, гістограма, базова лінія або власна серія плагіна. **Шкала цін** (price
scale) — вертикальна вісь, **шкала часу** (time scale) — горизонтальна. **Панель** (pane) — окрема горизонтальна
смуга графіка зі своїми серіями й шкалою цін, напр. обсяги під свічками. **Примітив** (primitive) — плагін, що малює
поверх серії чи панелі: лінії тренду, позначки, підказки.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

відповіді, яких бракувало: властивість `autoSize` у `ChartOptionsImpl` і в `ChartOptions` 4.x, опцію `priceFormatter`
у `LocalizationOptions` 4.x і розділ уроку «Setting the price formatter», рецепт «Volume in its own pane» навички
`lightweight-charts`.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, зведення ключів сторінок різних версій
  (`slug_rewrite`, `families`) і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (дерева тегів, файли репозиторіїв, релізи);
  `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df lightweight-charts
<крок>`.

Сайт зібрано на Docusaurus. Markdown-двійники він віддає лише чинній версії; версійні копії й довідник API є тільки в
HTML. Довідник сайт генерує TypeDoc-ом із `typings.d.ts` кожної версії. Сайт починається з 3.8, тож для 1.0–3.7
документація береться з теки `docs/` репозиторію на тегах, а точні сигнатури — з `typings.d.ts` тих самих версій у
npm. Нотатки релізів GitHub не беруться: сторінка сайту «Release Notes» уже тримає кожну версію від 1.0.0. Посилання
у відповідях ведуть на tradingview.github.io, github.com і registry.npmjs.org.

Особливості, які варто знати:

- **Одна сторінка — один ключ у всіх версіях.** Версійні копії лежать за адресами `/docs/4.2/…`, чинна — `/docs/…`.
  Поле `slug_rewrite` у `config.json` зрізає номер версії з ключа сторінки, а `families` зводить усі джерела сайту в
  одну родину: та сама сторінка різних версій займає у видачі одне місце й показує найновішу редакцію.
- **Підрозділи довідника API.** TypeDoc ділить кожен метод і кожну опцію підзаголовками «Parameters», «Returns»,
  «Default Value», «Inherited from», а інтерфейс — ще й «Extends». Окремими розділами вони давали фрагменти з одного
  слова («`void`»), а значення за замовчуванням відривалося від опції. Поле `inline_titles` джерел сайту робить з них
  підписи всередині розділу члена: метод чи опція — один фрагмент з усім, що про нього сказано.
- **Короткі сторінки API.** Сторінка псевдоніма типу чи змінної справді куца: «`const` LineSeries:
  `SeriesDefinition`<`"Line"`>» — 48 символів. Спільна межа читача (120) відкидала б 32 такі сторінки на версію, серед
  них `LineSeries`, `Time`, `SeriesMarkerShape`. Поле `min_chars: 20` їх лишає.
- **Кінцівка сторінок 5.2.** Кожна markdown-сторінка закінчується однаковим блоком «Sitemap» з посиланнями на
  `llms.txt` і `docs_map.md`; читач його зрізає.
- **Каталог плагінів і README пакетів — той самий текст.** Сторінка каталогу на сайті показує README пакета, тож README
  десяти плагінів з каталогу з репозиторію не береться (поле `exclude` джерела `repo-plugins`); журнали змін і README
  плагінів, яких у каталозі ще немає (`anchored-text`, `scatter-series`, `preview-kit`), беруться.
- **Навички для асистентів коду.** Репозиторій тримає дві офіційні навички — `lightweight-charts` (як користуватися
  v5, типові пастки часу, шкал, маркерів) і `lightweight-charts-plugin-authoring` (як писати плагіни); на них
  посилається сторінка сайту «Build with AI». Вони в корпусі як документація.
- **Обгортки.** Документації, окрім README, в обгортках немає: їхній довідник API — сам код. Тож береться код
  бібліотеки й застосунку-прикладу на останньому тезі (`v5.2.1` Android, `v5.2.0` iOS), а README — з кожного сталого
  тегу.

## Версії у відповіді

Фільтр `version` бере лінію: `"5"` — усе 5.x, `"4.2"` — лінію 4.2, `"3"` — 3.x. Сайт тримає одну редакцію на мінорну
лінію (5.2, 5.1, 5.0, 4.2, 4.1, 4.0, 3.8); для 1.0–3.7 документи — тека `docs/`, типізації й README тієї версії. Уроки,
каталог плагінів і приклади описують чинну версію. Обгортки нумерують випуски за бібліотекою (Android 5.2.1 обгортає
`lightweight-charts` 5.2.1).

Без названої версії промпт велить відповідати для 5.2 — найпоширенішої за завантаженнями npm лінії (64% за тиждень на
12.10.2026; 4.2 і 5.1 — по 14%). Якщо код користувача написано API 4.x (`addLineSeries`, `setMarkers`, опція
`watermark`), відповідь іде для 4.2 і показує, як те саме пишеться в 5.x.

## Сховище сирого

Під час оновлення примірник тримає ще й сирі відповіді сайтів — у теці `raw/`, поза git (сховище ввімкнене за
замовчуванням). Правка читача тоді не вимагає нового завантаження: `./df lightweight-charts build` збирає тексти зі
сховища без мережі. Так цей примірник і доведено до кінця: обидві правки читачів застосовано до 1 373 сторінок без
жодного повторного звернення до сайту. Попередні версії сторінок не видаляються, а переїжджають у `raw/_old/<день>/`.
Між оновленнями сховище, як і тексти, лежить лише в архіві: серверу воно не потрібне. Устрій — у
[../../UPDATE.md](../../UPDATE.md), розділ про `refresh`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/lightweight-charts-corpus-2026-10-12.tar.gz` (34 МБ: 2 052 тексти,
паспорт і сховище сирого `raw/` — 2 108 відповідей, з них 22 МБ — tarball версій із npm; перед видаленням текстів
розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде. Архів лежить лише на
цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/lightweight-charts/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/lightweight-charts-corpus-РРРР-ММ-ДД.tar.gz -C instances/lightweight-charts corpus raw
find instances/lightweight-charts/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/lightweight-charts/raw
gzip -9 -c instances/lightweight-charts/index/passages.json > instances/lightweight-charts/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/lightweight-charts-corpus-РРРР-ММ-ДД.tar.gz -C instances/lightweight-charts
./df lightweight-charts smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k
instances/lightweight-charts/index/passages.json.gz`, далі `./df lightweight-charts vectors` заллє колекцію Qdrant
(близько 12 хвилин).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df lightweight-charts …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище». Свій `.env` примірник тримає в `instances/lightweight-charts/.env` (`cp .env.example .env`; для
кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

```
./df lightweight-charts sources --why   # перелік джерел і білий список
./df lightweight-charts refresh         # завантажити все задеклароване (~45 хвилин: 2 050 документів, пауза 1 с)
./df lightweight-charts build           # перезібрати тексти зі сховища сирого, без мережі (після правки читача)
./df lightweight-charts manifest        # оновити паспорт
./df lightweight-charts setup           # Qdrant чи пошук лише по словах
./df lightweight-charts vectors         # залити корпус у docs-lightweight-charts (~12 хвилин)
./df lightweight-charts smoke           # перевірки
```

Як оновлювати після нових версій — у [UPDATE.md](UPDATE.md).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df lightweight-charts serve       # порт 8826
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8826/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user lightweight-charts-docs http://127.0.0.1:8826/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт. Інший
шлях — запис `.mcp.json` цієї теки: Claude Code, відкритий у ній, побачить сервер сам.

**3. Перевірити.** `/mcp` — має бути `lightweight-charts-docs` і два інструменти `search_docs`, `read_section`. Якщо
сесію Claude Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і
«Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Якщо порт 8826 зайнятий, `serve` падає з «address already in use»: значить,
сервер уже піднято в іншому терміналі. Решта — scope запису — так само, як у
[README примірника nestjs](../nestjs/README.md#спосіб-б--сервер-під-claude-code-http).
