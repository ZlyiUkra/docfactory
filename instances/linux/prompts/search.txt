Search the documentation a Linux system administrator works from -- man pages of Ubuntu 22.04,
24.04 and 26.04, the Linux man-pages project, the kernel admin-guide, systemd, the GNU manuals
(bash, coreutils, grep, sed, findutils, tar), vim help, the Debian Handbook, Ubuntu Server and
Rocky Linux docs, and the LFCS exam program. Returns excerpts with the versions each belongs to.

The rules that matter most (each is explained in full further below):
- Write the query in English with the names the documentation uses (systemctl, sshd_config,
  lvcreate, /etc/fstab, ip route) and the command or tool in it; a non-latin query finds nothing.
- Every project numbers its own versions and the numbers overlap ("6.18" is a kernel and a
  man-pages release, "9.2" vim and coreutils): the title says whose document it is.
- For how a command works on a current system, pass `version` "26.04" or "24.04" (Ubuntu man
  pages, with the package version). Search without `version` for the GNU manuals, systemd,
  the kernel, history and the unversioned guides (Ubuntu Server, Rocky Linux).
- Every answer names the distribution or project and the version; say when an option exists
  only in newer releases, and when Ubuntu and RHEL-family (Rocky) commands differ.
- Do not call this for Docker, Kubernetes, cloud consoles or programming languages.
- Excerpts are cut at 600 characters: pass the `id` to `read_section` for the whole text.

In full:

Search the documentation of the Linux system -- every release kept: the man pages of Ubuntu
26.04 (resolute), 24.04 (noble) and 22.04 (jammy) -- several hundred commands and configuration
files an administrator uses (ip, ss, ssh, sshd_config, useradd, passwd, chmod, setfacl, find,
tar, rsync, systemctl, journalctl, crontab, lvcreate, mdadm, mkfs, mount, fstab, nft, ufw, apt,
dpkg, sudoers, chrony, netplan and so on), each with the package and its version; the Linux
man-pages project (sections 2, 4, 5 and 7: system calls, devices, file formats, overviews such
as namespaces, cgroups, capabilities, signal, proc), releases 2.00 to 6.19; the Linux kernel
admin-guide (sysctl, cgroup-v2, kernel parameters, /proc), lines 5.10 to 7.2; systemd (units,
services, timers, targets, journald, networkd, resolved, logind; every man page and the docs on
systemd.io), releases 183 to 262; the GNU manuals of bash, coreutils, grep, sed, findutils and
tar, every release; vim help, 7.0 to 9.2; the Debian Administrator's Handbook for Debian 6 to
13; the Ubuntu Server documentation; the Rocky Linux documentation (the RHEL family: dnf,
firewalld, SELinux); and the LFCS exam page of the Linux Foundation (domains with their weights).

Call this when a question is about administering a Linux machine -- the shell and its
expansions, files, permissions and ACLs, links, text processing (grep, sed, awk, sort, cut),
archives and compression, users, groups and sudo, PAM and password ageing, processes, signals,
priorities and limits, services and the boot (systemd units, targets, timers, journal), cron and
at, packages (apt, dpkg, dnf, rpm, snap), networking (ip, ss, routes, DNS, netplan,
NetworkManager, firewall with nftables, ufw or firewalld, SSH and its keys, port forwarding),
storage (partitions, LVM, RAID with mdadm, file systems, mount and fstab, swap, quotas, NFS),
time synchronisation, logs, kernel parameters and modules, SELinux and AppArmor, the vim editor
-- and about the LFCS exam: its domains and their weights.
Example query: "systemctl enable --now unit".

Do not call this for Docker or containers images, Kubernetes, cloud consoles, Ansible, or for
programming languages and their libraries: their documentation is not here, and the search
will return excerpts that merely mention them, with confident-looking titles.

Whose version. Every project numbers its own versions, and the numbers overlap: "6.18" is a
kernel line and a man-pages release; "9.2" is vim and coreutils; "13" is Debian. The title says
whose document it is: "Ubuntu man: ip(8) — …" (the man page of an Ubuntu release, with "Ubuntu
24.04 (noble), package …" in its first line), "man-pages: clone(2) — …", "Linux kernel: …",
"systemd: …", "systemd man: systemd.service", "GNU coreutils 9.12 manual", "GNU Bash 5.3 manual",
"Debian Handbook: …", "vim help: …", "Ubuntu Server: …", "Rocky Linux: …". Put the command or
the project in the query.

`version` narrows the search to one release line of whichever project: "24.04" keeps the Ubuntu
24.04 man pages; "262" keeps systemd 262; "6.12" keeps the kernel 6.12 admin-guide and man-pages
6.12; "5.2" keeps Bash 5.2. The Ubuntu Server and Rocky Linux guides and the LFCS page have no
version: a search with `version` never returns them. Leave `version` empty to search everything.
Every excerpt comes back with `versions`: each version whose documents contain this exact text,
newest first -- text that stayed the same across releases is returned once with all of them
listed, so the list itself shows from which to which release the documentation said exactly
this.

Which version to search first. For how a command behaves on a current machine, pass the Ubuntu
release -- "26.04", or the user's own ("24.04", "22.04") -- or the release of the project the
user named. LFCS takes place on a current Linux distribution that it does not name: answer for
current releases, and where Ubuntu and the RHEL family (Rocky Linux, dnf, firewalld, SELinux)
differ, say both. Search without `version` for the GNU manuals, for systemd and the kernel when
the user did not name a release, for history and for the unversioned guides.

For a question about when an option or a behaviour appeared, search more than once: the
neighbouring versions of the same page name the first release that has it.

Write the query in English, with the names the documentation uses (systemctl, journalctl -u,
sshd_config PermitRootLogin, /etc/sudoers, lvextend -r, mdadm --create, nft add rule, chmod
u+s). Everything here is English -- the excerpts, the word index and the meaning index alike --
and the word index keeps only latin letters and digits, so a query written in Ukrainian, Russian
or any other non-latin script matches nothing at all and comes back with `found: 0`. When the
user asks in another language, translate the question into Linux terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Every answer says which distribution or project and which version it is for. When the user did
not name one, answer for current releases and say so; when older releases differ, say how. When
the excerpts behind a statement come only from older versions, name those versions instead of
presenting the text as current.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian
engineer writes, not as a translation from English: plain technical prose, and the Ukrainian
word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never
call this set of documents "корпус" -- say "документація" or the project's name. Commands,
options, file paths and titles stay in English, spelled exactly as the documentation spells
them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
