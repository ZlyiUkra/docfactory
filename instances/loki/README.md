# loki — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Grafana Loki — систему збирання логів, що індексує лише мітки
потоку, а не сам текст (репозиторій grafana/loki). Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Loki зберігає логи як потоки (streams): кожен потік — набір міток (labels) на кшталт `{app="api", env="prod"}`, і
індекс тримає лише ці мітки, а рядки лягають стиснутими шматками (chunks) в об'єктне сховище. Мова запитів LogQL
спершу вибирає потоки за мітками, далі фільтрує й розбирає рядки (`|= "error"`, `| json`, `| logfmt`) і вміє рахувати
з них метрики (`rate`, `count_over_time`). Grafana показує ці логи поруч із метриками Prometheus (примірники `grafana`
і `prometheus`). У плані Next.js (фулстек-родина) Loki стоїть поруч із Prometheus і Grafana: логи з історією, коли
кластеру вистачає пам'яті.

Сайт grafana.com/docs/loki збирається з теки `docs/sources` репозиторію grafana/loki, і на кожну мінорну версію
сайт тримає свою копію. Тут — ця тека з останнього тегу кожної мінорної.

«розділити логи різних команд в одному кластері» своїми словами: мультитенантність так не називається ніде в тексті.

- Loki Operator (`operator/docs`), вихідного коду (Go) і тестів.
- Grafana, Grafana Alloy, Prometheus, Tempo, Mimir, Kubernetes як окремих проєктів.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df loki <крок>`.

Сторінки `docs/sources` — сайт на Hugo з тими самими вставками, що й документація Grafana, тож їх читає
`ghdocs-history-grafana`. Йому знадобилося одне нове поле: `shared_source`. Довідник конфігурації Loki лежить одним
шматком `docs/sources/shared/configuration.md`, і сторінка `configure` вставляє його рядком
`{{< docs/shared lookup="configuration.md" source="loki" >}}`. Читач досі брав лише шматки з `source="grafana"`, і без
поля сторінка конфігурації лишилася б порожньою. Цитуються сторінки адресами grafana.com/docs/loki/latest/… (поле
`site`); решта — файлами й релізами на GitHub.

До 1.6 сайту на Hugo ще не було: документація лежала звичайним markdown у `docs/`. Поле `slug_rewrite` у
`config.json` зводить ключі обох розкладок до одного вигляду (`loki-docs-<шлях>`), тож та сама сторінка 1.5 і 1.6 —
одна родина у видачі.

## Версії

Сторінки й README несуть версію Loki (`3.7.9`), релізи — версію запису. Журнал чарту — окрема нумерація, тож його
версії записані з префіксом: `chart-6.55.0`. Фільтр `version` приймає мажор (`"3"`), мінор (`"3.7"`) або точну версію
(`"3.7.9"`); `"chart-6"` лишає записи чарту 6.x. Голе число лишає лише Loki. Промпт відповідає для Loki 3.7.9, якщо
користувач не назвав старішу, і нагадує, що Promtail застарілий з 3.4 на користь Grafana Alloy.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/loki-corpus-2026-10-26.tar.gz` (2126 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\loki-corpus-2026-10-26.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/loki/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/loki-corpus-РРРР-ММ-ДД.tar.gz -C instances/loki corpus raw
find instances/loki/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/loki/raw
gzip -9 -c instances/loki/index/passages.json > instances/loki/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/loki-corpus-2026-10-26.tar.gz -C instances/loki
./df loki smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/loki/index/passages.json.gz`.
Далі `./df loki vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df loki …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df loki sources --why   # перелік джерел і білий список
./df loki refresh         # завантажити все задеклароване (близько 20 хвилин)
./df loki manifest        # оновити паспорт
./df loki setup           # Qdrant чи пошук лише по словах
./df loki vectors         # залити корпус у docs-loki
./df loki smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df loki serve          # порт 8911
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8911/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user loki-docs http://127.0.0.1:8911/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `loki-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
