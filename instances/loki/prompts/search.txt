Search the documentation of Grafana Loki -- the horizontally scalable, multi-tenant log aggregation system that
indexes only the labels of a log stream, not its text (repository grafana/loki). The corpus holds the `docs/sources`
folder that builds the site grafana.com/docs/loki, at the last tag of every minor, 1.6 to 3.7 -- getting started,
architecture and components (distributor, ingester, querier, query frontend, query scheduler, index gateway,
compactor, ruler, bloom planner and builder), deployment modes (monolithic, simple scalable, microservices),
installation (Helm, Docker, Tanka, local binaries) and the Helm chart values reference, upgrade notes between
versions, the full configuration reference (`limits_config`, `schema_config`, `storage_config`, `common`, `server`,
`ingester`, `querier`, `query_range`, `compactor`, `ruler`, `memberlist`, `runtime_config`, per-tenant overrides),
storage (TSDB, the older BoltDB shipper, object stores: S3, GCS, Azure, Swift, filesystem), labels and cardinality,
structured metadata, sending logs (Grafana Alloy, Promtail and its pipeline stages, the Docker logging driver,
Fluent Bit, Fluentd, Logstash, OpenTelemetry and the native OTLP endpoint, lambda-promtail, k6), LogQL (log queries,
stream selectors, line filters, parsers `json`, `logfmt`, `pattern`, `regexp`, `unpack`, label filters,
`line_format`, `label_format`, `drop`, `keep`, `decolorize`, metric queries, range and vector aggregations,
`unwrap`, template functions, query examples), alerting and recording rules, operations (retention and log deletion,
multi-tenancy, authentication, caching, query acceleration with blooms, autoscaling, scalability, zone-aware
replication, observability of Loki itself, rate limits and request validation errors, troubleshooting, Loki Canary,
query blocking, the overrides exporter), the HTTP API, `logcli`, the community pages and the release notes; the
plain `docs/` folder of 0.1 to 1.5; the repository README at every minor; the stable GitHub releases; the changelog
of the Helm chart `loki` kept in the Loki repository (production/helm/loki), one section per chart version 3.0 to
7.5 -- since 7.0 that chart serves Grafana Enterprise Logs only: in March 2026 the chart for OSS users moved to
grafana-community/helm-charts, forked at 6.55.0, and that repository's own README is not here (the upgrade guide to
it is). Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about Loki as it describes itself -- how to install and run it, choose a deployment
mode, write the configuration file, set up storage and a schema, choose labels, send logs with Alloy or Promtail or
OpenTelemetry, write a LogQL query (`{app="api"} |= "error"`, `| json`, `| logfmt`, `| pattern`, `| line_format`,
`rate`, `count_over_time`, `sum by`, `topk`, `quantile_over_time`, `unwrap`), write alerting and recording rules for
the ruler, set retention, delete logs, configure multi-tenancy and per-tenant limits, read a rate-limit or
cardinality error, call the HTTP API (`/loki/api/v1/push`, `/loki/api/v1/query_range`, `/loki/api/v1/tail`), use
`logcli`, install or upgrade the Helm chart -- and history: since which version a configuration field, a LogQL
feature or a behaviour exists and what changed between versions (the releases and upgrade notes list it).

Do not call this for Grafana, Grafana Alloy, Prometheus, Tempo, Mimir, Pyroscope, the Loki Operator, Kubernetes,
OpenTelemetry or Fluent Bit as their own projects: their documentation is not here -- these pages only show how Loki
is used with them -- and the search will return excerpts that merely mention them, with confident-looking titles.
The Go source code is not here either.

`version` narrows the search to one release line: a line of one number keeps every document of that major ("3"
keeps Loki 3.x), two numbers keep a minor ("3.7"), three an exact version ("3.7.9"); the Helm chart's changelog carries
the prefix "chart-" ("chart-6" keeps all of chart 6.x); a bare number keeps only Loki itself. Pages unchanged across
versions carry all of them. Every excerpt comes back with `versions`: each version whose documents contain this exact
text, newest first.

Write the query in English, with the names the documentation itself uses ("limits_config", "schema_config",
"retention_period", "compactor", "retention_enabled", "max_streams_per_user", "ingestion_rate_mb",
"structured metadata", "stream selector", "line filter", "label filter", "json parser", "logfmt", "pattern parser",
"line_format", "label_format", "unwrap", "count_over_time", "rate", "ruler", "recording rules", "pipeline stages",
"relabel_configs", "tsdb", "boltdb-shipper", "object storage", "simple scalable", "deployment modes",
"query frontend", "split_queries_by_interval", "auth_enabled", "X-Scope-OrgID", "otlp"), not in the user's own
words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question into
the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація Loki". Identifiers, parameters and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Loki 3.7.9 is the newest release; 6.55.0 was the last chart for OSS users from the
Loki repository, and its 7.x line (7.5.0 the newest) is for Grafana Enterprise Logs: search without `version` first; when the user names their version, search that line. Promtail is deprecated since
3.4 in favour of Grafana Alloy -- say so when the answer is about Promtail. Every answer says which version it is for.
