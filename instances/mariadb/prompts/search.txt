Search the documentation of MariaDB, the relational database server, and of the drivers that applications use to reach it. The documentation holds the MariaDB documentation
site as one current edition, taken from the repository `mariadb-docs`: the server with SQL statements, functions, data types, storage engines, replication and administration; the
release notes of every version; the connectors for Java, Node.js, C, C++, ODBC, Python and R2DBC; Galera Cluster, MaxScale, ColumnStore and the client tools. It also holds the GitHub
releases of `MariaDB/server`, the npm package `mariadb` with its README in every stable version, the Docker Hub tags and the page of the official `mariadb` image.

Use this tool for: MariaDB SQL syntax and functions, system variables, InnoDB and other storage engines, Galera, replication, `mariadb-dump` and `mariadb-backup`, connection settings
of a connector, what changed in a MariaDB version. Write the query in English with the exact name of the statement, function, variable or tool, such as "ALTER TABLE" or
"wsrep_sync_wait".

Do not use it for MySQL, which is a separate product with its own server: MariaDB behaves differently in many places, so never present a MySQL answer as a MariaDB one. It does not cover
MariaDB Cloud, GridGain or Exa. The site has one current edition and no copy per version: differences between versions appear only as notes in the text, as **Variant** blocks and in the
release notes. Returns the matching excerpts with the source address and the fetch date.

Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written in Ukrainian,
Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question into MariaDB terms first,
then search.

Answer in the language the user wrote in. When the answer depends on the version, name the version the excerpt gives. A point the excerpts do not support is left out, not guessed. Never
call this set of documents "корпус" -- say "документація MariaDB". Identifiers, command names, flags, keys and titles stay in English, spelled exactly as the documentation spells them.
Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional and narrows the search to one labelled line, which leaves out the site
because the site carries no version. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to
`read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear in the text, so a query phrased in other words than the
documentation uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase had a chance.
