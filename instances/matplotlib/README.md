# matplotlib — примірник фабрики docfactory

Цей примірник зібрав документацію бібліотеки Matplotlib і віддає її через сервер MCP, щоб модель відповідала з текстів
бібліотеки, а не з пам'яті. Matplotlib — це основна бібліотека Python для малювання графіків. Вона малює лінії, стовпчики,
точки, гістограми й багато іншого, а потім показує графік у вікні або зберігає його у файл PNG, SVG чи PDF. Інші бібліотеки
графіків, наприклад seaborn і mplfinance, малюють через Matplotlib, тому її поняття стануть у пригоді й там.

Два поняття Matplotlib треба знати з самого початку. `Figure` — це весь малюнок, тобто аркуш, на якому все розміщено. `Axes` —
це одна ділянка з графіком на цьому аркуші, з власними осями X і Y. Один `Figure` може мати кілька `Axes`, і функція
`plt.subplots` створює їх одним викликом.

Для торгового бота на ринку Форекс тут найважливіші такі речі:

- осі з датами. Ціна записана за часом, тож вісь X — це дати. Модуль `matplotlib.dates` і форматувальник `ConciseDateFormatter`
  роблять підписи дат короткими й такими, що не налазять один на одного;
- кілька графіків на одному аркуші (`subplots`, `subplot_mosaic`) і друга вісь Y (`twinx`). Так ціну й обсяг показують на одному
  малюнку, кожен у своєму масштабі;
- смуги й рівні: `fill_between` зафарбовує ділянку між двома лініями, наприклад між верхньою й нижньою межею каналу, а `axhline`
  проводить горизонтальну лінію на рівні ціни;
- збереження у файл без вікна. Бот працює на сервері, де немає екрана. Тому графік малюють через бекенд `Agg`, тобто модуль, що
  малює в пам'яті, і зберігають функцією `savefig`.

## Скільки цього

Усього 21 977 документів і 61 274 фрагменти. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Сторінка з
однаковим текстом у кількох лініях лежить одним документом із переліком цих ліній. Сторінка, що змінювалася, лежить кількома
документами, по одному на кожен варіант тексту.

| Що | Версії | Документів |
|---|---|---|
| сайт matplotlib.org: посібник користувача, довідник API зі сторінкою кожної функції `pyplot` і методу `Axes`, галерея прикладів, what's new і зміни API між версіями | увесь сайт кожної мінорної лінії 1.2–3.11, кожна на останньому патчі | 21 875 |
| нотатки релізів GitHub | усі стабільні теги | 75 |
| записи PyPI | усі стабільні версії та опис пакета | 27 |

Серед документів сайту 11 149 — сторінки довідника API, 8 889 — приклади галереї, 422 — what's new і зміни API, решта 1 415 —
посібник користувача та інші сторінки.

Мітка версії має вигляд `matplotlib-3.11`. Префікс потрібен, щоб версії Matplotlib не збігалися з версіями інших бібліотек, коли
сервери працюють разом.

**Де є прогалини, хоч ми й брали всі лінії.**

- Лінії 0.x–1.1 сайт не публікує. Про них є лише записи PyPI.
- Тека останнього патча лінії 3.9 (`3.9.4`) відповідає «404», тому лінія 3.9 взята з теки `3.9.3`.
- П'ять посилань сайту ведуть на сторінки, яких немає (відповідь «404»).
- 103 сторінки довідника не стали документами, бо в них немає нічого, крім назви.
- Сторінки міток `_tags/`, які лише перелічують приклади за темою, не взято: це перелік посилань, а не текст.

Замір `quality` на 14.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 2 із 10: довідник Matplotlib описує кожну функцію її власними словами («fill the area
between two curves»), а запит своїми словами («shade the region between two bands») має з ним мало спільного.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df matplotlib <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт документації | `matplotlib.org/<тека лінії>/` | `sphinx-html` |
| нотатки релізів | релізи GitHub `matplotlib/matplotlib` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/matplotlib/json` | `pypi-versions` |

**Як обходиться сайт.** Кожна лінія лежить на сайті своєю текою з номером останнього патча (`3.11.2`, `2.2.5`, `1.2.1`). Поле
`version_labels` перетворює назву теки на мітку версії (`3.11.2` → `3.11`). Мапи сайту немає, тому читач починає з `index.html`
теки й іде за посиланнями всередині неї. Нова лінія має близько 2 000 сторінок, лінії 1.x — 550–650. Разом це 30 343 сторінки.

**Поля читача для цього сайту.**

- `param_types: true`. Нова тема сайту ставить тип параметра в окремий елемент одразу за назвою, без пробілу. Без цього поля назва
  зливалася б з типом в одне слово («fmtstr»), і пошук за назвою параметра не знаходив би сторінки. З полем читач пише
  «fmt : str, optional», як це робить стара тема.
- `end` з рядком `<div class="footer"`. Стара тема 1.x–3.3 закінчує текст сторінки не тегом `<footer>`, а таким блоком.
- `skip_untitled: true`. Сторінка без заголовка `<h1>` не стає документом, але посилання з неї все одно йдуть в обхід.
- `exclude` з `/_tags/`: сторінки міток лише перелічують приклади, які й так є окремими документами.

**Як завантажували вперше.** Сайт працює через Cloudflare і відповідає швидко, тому його завантажили шістьма тимчасовими
джерелами по 3–4 лінії, які працювали паралельно. Кожне з них лише наповнювало сховище сирого кроком `list` і нічого не записувало
в корпус. Потім крок `build matplotlib-docs` зібрав тексти з цього сховища без мережі одним джерелом. Одне джерело потрібне для
того, щоб однакова сторінка кількох ліній стала одним документом, а не кількома. Так обхід зайняв 55 хвилин без жодної відмови
сервера.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df matplotlib serve
```

Порт — `8981`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user matplotlib-docs http://127.0.0.1:8981/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `matplotlib-docs` з інструментами `search_docs` і `read_section`. Якщо
сервер позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/matplotlib-corpus-2026-11-14.tar.gz` (21 977 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\matplotlib-corpus-2026-11-14.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/matplotlib/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/matplotlib-corpus-РРРР-ММ-ДД.tar.gz -C instances/matplotlib corpus raw
find instances/matplotlib/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/matplotlib/raw
gzip -9 -c instances/matplotlib/index/passages.json > instances/matplotlib/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/matplotlib-corpus-2026-11-14.tar.gz -C instances/matplotlib
./df matplotlib smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
