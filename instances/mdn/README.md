# mdn — примірник фабрики docfactory

Двадцять четвертий примірник фабрики: захищений MCP-сервер, що відповідає на питання про саму вебплатформу —
JavaScript, Web API, CSS, HTML, HTTP, доступність, безпеку й продуктивність вебу — за документацією MDN Web Docs
англійською. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані
домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

Плани навчання React, NestJS і Next.js спираються на мову й браузер не менше, ніж на самі бібліотеки: копіювання
об'єктів і замикання, `fetch` і `AbortController`, події, кеш HTTP, куки з `SameSite`, CORS, WebSocket, доступність.
Документація бібліотек усе це вважає відомим і не пояснює. До цього примірника такі посилання в планах стояли з
позначкою «поза корпусом» — тепер вони ведуть сюди. Карта того, яким фазам потрібен `mdn`, — у
[../../docs/learning-map.md](../../docs/learning-map.md).

MDN — один, безперервно оновлюваний текст: він описує платформу такою, як її зараз реалізують браузери, тож версій
у сторінок немає. Замість них кожна сторінка несе підсумок Baseline: чи можливість широко доступна, з якої дати й з
якої версії кожного з основних браузерів. Версії є лише в одному джерелі — `browser-compat-data`: це таблиця
сумісності браузерів, яку сайт дотягує окремо від тексту сторінки; тут узято найновіший стабільний випуск кожної
мажорної лінії пакета (2–8), чинна лінія — 8.

Разом 82 980 документів: 13 608 сторінок MDN і 69 372 документи browser-compat-data. Фрагментів в індексі — 186 174
(`expected_passages` у `checks.json`; до browser-compat-data було 115 196). Фрагменти — це шматки
документів між заголовками, по яких іде пошук. Це другий за розміром корпус фабрики після linux.

Замір `quality` на першому корпусі (05.10.2026): перша десятка (питання своїми словами) — по словах 5 із 10, за
змістом 4, разом 4; друга, «як модель» (назви API, заголовків і селекторів, як велить промпт), — 9 із 10. Промах
другої десятки — «IntersectionObserver API»: у першій п'ятірці сторінки конструктора й методів `IntersectionObserver`,
а не гайд `Intersection Observer API`. Переказ без назв слабкий: пошук за змістом охоче підіймає короткі розділи «See
also», де поруч стоять назви сусідніх сторінок. Тому промпт пошуку велить шукати назвами API англійською.

**Чого немає свідомо.** Mozilla/* (розширення браузера, нотатки випусків Firefox), службові сторінки самого MDN, блог,
інші мови. Дві однорядкові статті глосарія — `Nullish` і `decorating_box` — не пройшли спільну перевірку фабрики на
заглушку (тіло коротше порогу й без заголовка); визначення nullish повністю є на сторінках оператора `??` і `null`.

## Як влаштований документ

Текст — зібрана сторінка developer.mozilla.org, а не сирий markdown репозиторію mdn/content: у сирому тексті частина
сторінки — макроси KumaScript (`{{domxref}}`, `{{Compat}}`, `{{CSSSyntax}}`), які розгортаються лише під час
збирання сайту. Кожна сторінка віддається ще й як `index.json` — тіло, поділене на розділи з готовим HTML, плюс
специфікації й підсумок Baseline окремими полями. Читач `mdn-json` бере саме його.

- **Розділи прози** — як на сайті; навігація уроків Learn («Previous / Overview / Next») і підпис мови над блоком коду
  вирізано, мова переходить в огорожу коду.
- **Specifications** — назва й адреса кожної специфікації: адреса тут і є вміст, за нею звіряються.
- **Browser compatibility** — на сайті це таблиця, яку браузер дотягує окремо з browser-compat-data. У тексті сторінки
  замість неї підсумок Baseline: статус, дати, перша версія Chrome, Edge, Firefox і Safari (настільних і мобільних), а
  браузер без підтримки названо явно. Повна таблиця — окремі документи джерела `browser-compat-data` (розділ нижче);
  у сторінці лишається ключ browser-compat-data, за яким цей документ знаходять.
- **Ім'я документа** — розділ і шлях усередині нього: `web-api--abortcontroller`, `http--guides-cors`.

## browser-compat-data

Читач `npm-bcd` ([../../engine/readers/bcdnpm.py](../../engine/readers/bcdnpm.py)) бере опис пакета в реєстрі npm і з
кожної мажорної лінії — tarball найновішого стабільного випуску (2.0.7, 3.3.14, 4.2.1, 5.7.6, 6.1.5, 7.3.17, 8.1.6;
мінорні випуски всередині лінії пропущено). Ознак у лініях: 8 — 20 721, 7 — 19 752, 6 — 17 783, 5 — 17 065, 4 — 13 696,
3 — 13 276, 2 — 12 246 (у лінії 2 даних ще немає одним файлом `data.json`, і читач зводить файли ознак теками).

- **Документ** — одна ознака, неповторний текст: «Browser compatibility: api.structuredClone». У ньому адреса сторінки
  MDN і специфікації, статус (стандарт, застаріле, експериментальне) і для кожного рушія перша версія, що підтримує, з
  примітками, префіксами, прапорцями, видаленням і частковою підтримкою. Рушіїв до сімнадцяти: Chrome, Edge, Firefox,
  Safari, Opera, Samsung Internet, WebView, Node.js, Deno, Bun та інші.
- **Версії.** Однаковий у кількох лініях текст — один документ, у шапці якого всі ці лінії; змінений — окремий документ
  (усього їх 69 372). Суфікс-хеш в імені документа (`browser-compat-data--bcd-api-structuredclone-0128d838`) зрізає
  `slug_rewrite` у `config.json`, тож редакції однієї ознаки зливаються за версіями, як сторінки сусідніх версій в
  інших примірниках. Фільтр `version` пошуку діє лише на ці документи: інших сторінок MDN версії не мають.
- **Застереження.** Старі лінії несуть ознаки, яких чинна вже не має (наприклад, `api.structuredClone.worker_support`
  є лише в лінії 4). Без фільтра такий застарілий документ може опинитися у видачі вище чинного; для
  актуальних даних шукайте з `version` = `8`, про що сказано й в описі інструмента.
- **Webextensions.** Дані сумісності розширень браузера (2 078 ознак у лінії 8) тут є, а їхньої документації — ні.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — двадцять одне джерело: по одному на розділ MDN і `browser-compat-data`; водночас білий список для
  оновлювача (лише `developer.mozilla.org` і `registry.npmjs.org`).
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code; `.env` потрібен лише для кроку `ask` (ключ Anthropic).

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df mdn <крок>`.

Тут немає документації бібліотек і фреймворків (React, Next.js, NestJS, TypeScript — окремі примірники), Node.js і

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку, як у kubernetes, linux і vitest: у `corpus/` лежить лише паспорт
`index.json`, а сервер підіймається з кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до
символа — кеш тримає повний текст кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/mdn-corpus-2026-10-20.tar.gz` (39,5 МБ: 82 980 текстів, паспорт і
сховище сирого `raw/`; перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git
текстів немає ніде. Архів лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/mdn/index/passages.json                 # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/mdn-corpus-РРРР-ММ-ДД.tar.gz -C instances/mdn corpus raw
find instances/mdn/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/mdn/index/passages.json > instances/mdn/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/mdn-corpus-РРРР-ММ-ДД.tar.gz -C instances/mdn
./df mdn smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/mdn/index/passages.json.gz`, далі
`./df mdn vectors` заллє колекцію Qdrant (близько п'яти годин на процесорі цієї машини, на відеокарті — кілька хвилин).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df mdn …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/mdn/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

```
./df mdn sources --why   # перелік джерел і білий список
./df mdn refresh         # завантажити все задеклароване (~5 годин)
./df mdn refresh browser-compat-data   # лише таблиці сумісності (~10 с: сім tarball з реєстру npm)
./df mdn manifest        # оновити паспорт
./df mdn setup           # Qdrant чи пошук лише по словах
./df mdn vectors         # залити корпус у docs-mdn (~5 годин)
./df mdn smoke           # перевірки
```

`refresh` довший за 30 хвилин: із Claude Code його треба запускати окремим процесом (`setsid nohup …`), інакше
фонову задачу обірве оболонка. Обірваний `refresh` продовжується з `--missing`: уже записане він не тягне вдруге; з
`--missing` імена джерел звужують прогін (`./df mdn refresh --missing uri` — лише розділ Web/URI).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df mdn serve           # порт 8784
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8784/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user mdn-docs http://127.0.0.1:8784/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `mdn-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
