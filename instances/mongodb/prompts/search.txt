Search the MongoDB documentation, in English: MongoDB is the document database (BSON documents in collections,
the query language with its operators, aggregation pipelines, indexes, transactions, change streams,
replica sets, sharded clusters, security and authentication, storage engines, administration and
configuration). The set holds the Database Manual of every version from 2.2 to 9.0 -- every major, minor and
rapid release line (2.2, 2.4, 2.6, 3.0 ... 4.4, 5.0 ... 6.3, 7.0 ... 7.3, 8.0, 8.3, 9.0) as its documentation
stood when that line was current: CRUD tutorials with the examples for mongosh and for every driver language
(Node.js, Python, Java, C#, Go, PHP, Ruby, Scala, Kotlin, C, C++, Rust, Swift), the reference of every mongosh
method, database command, query, update and aggregation operator, server parameter, configuration file option
and `mongod`/`mongos` command-line option, the installation and upgrade procedures, release notes and
changelogs of every version, the compatibility changes between versions; the mongosh documentation (2.1 and
2.13: connecting, CRUD, scripts, configuration, logs, the shell's own methods) and the Database Tools
documentation (100.19: mongodump, mongorestore, mongoimport, mongoexport, bsondump, mongostat, mongotop,
mongofiles). Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about MongoDB itself: what a method, command or operator does, its syntax, fields
and return value, since which version it exists or how its behavior changed, what a configuration option or
server parameter means and its default, how indexes, transactions, replication, sharding, authentication or
storage behave, what changed between versions, how to install, upgrade or back up a deployment, how a mongosh
feature or a tool's flag works. Example query: "insertMany ordered".

Do not call this for a driver (the Node.js driver has its own instance, node-mongodb-docs), for Mongoose
(mongoose-docs), for Atlas, Compass, Ops Manager or Cloud Manager beyond what the manual says about them, or
for Mongoose/ODM questions.

Write the query in English, with the names MongoDB itself uses (db.collection.find, $lookup, $set, findAndModify,
readConcern, wiredTigerCacheSizeGB, mongod --replSet). Everything here is English, and the word index keeps only
latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing
and comes back with `found: 0`. When the user asks in another language, translate the question into MongoDB
terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "колекція", "документ", "індекс",
"репліка". Never call this set of documents "корпус" -- say "документація MongoDB". Names of methods, commands,
operators, options and parameters stay in English, spelled exactly as the documentation spells them. Build the
answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it before
describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. When the user names a version, search that line; otherwise answer for the newest
release line (9.0) and say so; when the user runs an older server, the manual of that line is here. Put a
version only into `version`, never into the query text: "7" keeps every 7.x line, "7.0" keeps that line. The
manual is marked by release line ("8.0"); mongosh and Database Tools carry their own numbering with a prefix
("mongosh-2.13", "database-tools-100.19") so that mongosh 2.x is never confused with MongoDB 2.x. A reference
page is named after its subject ("reference-method-db-collection-find", "reference-operator-aggregation-lookup",
"reference-configuration-options", "reference-program-mongod"); release notes are "release-notes-8-0" and the
compatibility changes "release-notes-8-0-compatibility". A tutorial page shows the same example once per
interface and language under its own heading ("mongosh", "Driver · Node.js"): quote the one the user works with.
