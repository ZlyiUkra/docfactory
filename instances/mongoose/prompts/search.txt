Search the Mongoose documentation, in English: Mongoose is the object-document mapper for MongoDB in Node.js --
schemas and schema types, models, documents, queries and query helpers, validation, middleware (hooks),
populate, virtuals, discriminators, subdocuments, timestamps, transactions, change streams, lean queries,
connections, plugins, TypeScript typings. The set holds the docs/ pages of every stable release from 5.13 to the
newest (as each release's documentation stood: guides, tutorials, TypeScript pages, FAQ, compatibility table,
the migration guides to 5, 6, 7, 8 and 9), the site snapshots of Mongoose 3.8 and 4 (including their API
reference), the source code lib/ with JSDoc (the API reference is generated from it), the TypeScript types
types/*.d.ts and the tests of every stable release, CHANGELOG.md with an entry for every version since 1.0.1,
the GitHub release notes, the npm registry (dates, dependencies) and the README of every version. Around
Mongoose: @nestjs/mongoose (NestJS module: MongooseModule, @Schema, @Prop, InjectModel), Typegoose (models as
TypeScript classes), mongodb-memory-server (an in-memory MongoDB for tests), connect-mongo (express-session
store) and the plugins mongoose-autopopulate, mongoose-lean-virtuals, mongoose-unique-validator,
mongoose-paginate-v2 -- their docs, code, release notes and npm history. Returns the matching excerpts with the
versions each one belongs to.

Call this when a question is about Mongoose or those packages: how to define a schema or a schema type option,
what a model or document method does, how populate, validation, middleware, virtuals, discriminators or
transactions work, how a query is cast, what changed between Mongoose versions and how to migrate, how to type
a model in TypeScript, how to set up Mongoose in NestJS, how to test with mongodb-memory-server. Example query:
"populate virtual ref localField".

Do not call this for the MongoDB server, mongosh or Database Tools (mongodb-docs), or for the raw Node.js
driver and bson (node-mongodb-docs) beyond what Mongoose says about them.

Write the query in English, with the names Mongoose uses (Schema, model, populate, findOneAndUpdate, pre('save'),
discriminator, lean, strictQuery, timestamps, HydratedDocument). Everything here is English, and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing and comes back with `found: 0`. When the user asks in another language, translate the question
into Mongoose terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "схема", "модель", "документ".
Never call this set of documents "корпус" -- say "документація Mongoose". Names of classes, methods and options
stay in English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that
came back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. When the user names a version, search that line; otherwise answer for both
lines in use -- 8.x and 9.x -- and say so when they differ. Put a version only into `version`, never into the
query text: "8" keeps every 8.x, "8.9" keeps that line. Mongoose documents are marked by release ("8.9.5"); the
other packages carry their own prefix ("nestjs-11.0.4", "typegoose-13.5.0", "memory-server-10.1.4",
"connect-mongo-5.1.0", "types-5.11.97") so that their numbers are never confused with Mongoose's. A docs page is
named after its file ("docs-populate", "docs-migrating-to-8", "docs-typescript-schemas"); a source file after its
path ("mongoose-lib-schema"); CHANGELOG entries by version ("mongoose-8.9.5").
