# motion — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Motion — бібліотеку анімацій для React, JavaScript і Vue, яка до
листопада 2024 року звалася Framer Motion, — за її офіційною документацією. Він знає кожну сторінку motion.dev у
теперішній редакції (документацію, Motion+, Motion UI, AI Kit, приклади й посібники, журнал помилок, статті), журнал
змін Motion від Framer Motion 0.3.0 (2019) до поточної 14.x, README й історію в реєстрі npm кожної стабільної версії
пакетів `framer-motion`, `motion`, `framer-motion-3d`, `motion-v` (Motion для Vue) і Motion One (`@motionone/*`), а
також попередника Framer Motion — бібліотеку Popmotion разом із Pose. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо стільки історії

Сайт motion.dev тримає лише одну редакцію — для поточного випуску, а в репозиторії документації немає зовсім. Тим
часом бібліотека тричі змінювала ім'я й склад:

- **Popmotion → Pose → Framer Motion.** Framer Motion виріс із Pose (`react-pose`), а та — з Popmotion; автор той
  самий, Matt Perry. Частина API прийшла звідти: `staggerChildren` описано вже в посібниках Pose.
- **Motion One.** Окрема бібліотека для чистого JS на Web Animations API виходила як `motion` 10.x і `@motionone/*`.
- **Злиття.** З 11.11.12 Framer Motion виходить і як `motion` (імпорт `motion/react`), а `framer-motion` лишився
  тією самою бібліотекою під старим ім'ям; Motion One влився в неї.

Тож на питання «як це було в моїй версії» чи «з якої версії є `layoutId`» сайт не відповідає. Відповідають журнал
змін, README тієї версії і запис реєстру npm — їх і зібрано, кожен документ несе свої версії.

коштує десятці «як модель» двох влучань, 2 і 3 нічого не змінюють — поле не ввімкнене.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df motion <крок>`.

Читач `sitemap-accept` додано разом із цим примірником (`engine/readers/sitemapaccept.py`), а спільна функція
завантаження дістала необов'язковий заголовок `Accept` — так само, як колись дістала стиснення для web.dev; без поля
запит той самий, що й був. Причина: двійник з «.md» на motion.dev є лише в документації, а сторінки прикладів, Motion
UI, журналу помилок і статей сервер віддає markdown-ом тільки на `Accept: text/markdown`.

Особливості, які варто знати:

- **Сайт — без версії.** Сторінки motion.dev описують поточний випуск (Motion 14.x, Motion для Vue 2.x, Motion UI 2.x)
  і версії не несуть, тож `expect_unversioned` у `checks.json` — `true`, а промпт велить питання «як зараз» шукати
  без `version`. Найпоширеніша ж за завантаженнями npm лінія — 12.x (61% `framer-motion`, 71% `motion` за тиждень
  до 11.10.2026), тож без названої версії промпт велить відповідати для 12.x: брати сторінку сайту й звіряти її з
  розділами 13.0 і 14.0 посібника з оновлення та журналом змін.
- **Motion+.** Платні сторінки беруться теж: їхній опис і API відкриті. Код прикладів Motion+ і продовження платних
  посібників сайт закриває; цю вставку читач замінює рядком «[Motion+ (paid): …]», а рекламні блоки, перелік схожих
  прикладів із картинками й JSON-LD вирізає (поле `drop` джерел сайту). Опис закритого прикладу береться з шапки
  сторінки (`lead_meta`), дата публікації прикладу й статті — з JSON-LD у назву (`date_jsonld`).
- **Номери версій перетинаються.** `framer-motion` і `motion` з 11.11.12 мають однакові номери — це та сама
  бібліотека; `motion` 10.x і `@motionone/*` 10.x — Motion One, інша бібліотека, ніж `framer-motion` 10.x; `motion-v`
  0.x–2.x — Motion для Vue, а не `framer-motion` 0.x–2.x; Popmotion має свої 0.x–11.x. Промпт велить разом із
  `version` називати в запиті пакет.
- **`motion` 0.x–6.0.0 не береться.** Версії 0.x–4.x належать іншому проєкту з тим самим ім'ям у npm, 6.0.0 —
  заглушка перед Motion One (`skip_versions`).
- **README без змісту не береться.** У `motion-dom` і `motion-utils` README немає, у `@motionone/*` це заглушки на
  три рядки («Full docs … at motion.dev»); у них лишаються записи реєстру npm. Документацію Motion One як сайт після
  злиття прибрано зовсім, тож її представляють README пакета `motion` 10.x, журнал змін motionone і реєстр npm.
- **Popmotion — з репозиторію.** popmotion.io відповідає 403 на автоматичні запити; ті самі сторінки лежать markdown-ом
  у теках `packages/*/docs` репозиторію (гілка master — останній стан сайту). Сайт описує API Popmotion 8.x і Pose;
  новіший API Popmotion 9–11 описано лише в README пакета. Пакет `pose` у npm належить іншому автору й не береться.
- **Журнал змін сайту — лише останні записи.** Сторінка `/changelog` віддає 33 найновіші записи Motion, Motion UI,
  AI Kit і Motion Studio, решту вона довантажує скриптом. Для самої бібліотеки повна історія — `CHANGELOG.md`.

## Межі, про які треба пам'ятати

GSAP, React Spring, CSS-анімацій без Motion, React, Vue чи Framer (редактора) тут немає — лише сторінки motion.dev,
що порівнюють Motion із ними. Старої документації Framer Motion на framer.com, сайту Motion One і старих редакцій
motion.dev немає ніде, крім README відповідних версій. Код прикладів і компонентів Motion+ закритий. Дві чернетки
блогу Popmotion (`blog/draft-*`) порожні — `refresh` рахує їх збоями, це очікувано. Порожній запис журналу змін Motion
0.8.8 так само не пишеться.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/motion-corpus-2026-10-11.tar.gz` (1,4 МБ, 2 413 текстів і паспорт;
перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде.
Архів лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/motion-corpus-2026-10-11.tar.gz -C instances/motion
./df motion smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/motion/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/motion-corpus-РРРР-ММ-ДД.tar.gz -C instances/motion corpus
find instances/motion/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/motion/index/passages.json > instances/motion/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/motion/index/passages.json.gz`, далі
`./df motion vectors` заллє колекцію Qdrant (~13 хвилин).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df motion …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/motion/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df motion sources --why   # перелік джерел і білий список
./df motion refresh         # завантажити все задеклароване (~1 год 15 хв)
./df motion manifest        # оновити паспорт
./df motion setup           # Qdrant чи пошук лише по словах
./df motion vectors         # залити корпус у docs-motion (~13 хвилин)
./df motion smoke           # перевірки
```

Сайт пишеться близько 30 хвилин (по 2–3 секунди на сторінку). Далі журнал надовго замовкає на джерелах `readme-*`:
щоб звести однакові README, читач спершу читає README кожної версії (875 у `framer-motion`, 408 у
`framer-motion-3d`, 272 у `motion`) і лише потім пише неповторні тексти.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df motion serve          # порт 8823
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8823/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user motion-docs http://127.0.0.1:8823/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `motion-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
