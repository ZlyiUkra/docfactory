# Оновлення корпусу motion

Дві різні роботи: звичайне оновлення, коли вийшли нові версії Motion чи змінився сайт, і збирання з нуля. Порядок
усередині кожної важливіший за самі команди.

Головне правило: **оновлювач тягне лише оголошене.** Перелік сторінок сайту він бере з sitemap.xml motion.dev, але
лише всередині полів `within` джерел; версії — з реєстру npm, README — з коміту кожної версії. Новий пакет сам у
корпус не потрапить, доки для нього не оголошено джерела.

Друге правило: **лише стабільні версії.** Поле `skip_versions` джерел `npm-*` і `readme-*` відкидає все з дефісом за
номером (`-alpha.1`, `-beta.4`, `-rc.6`); `releases-motion-vue` відкидає передрелізи сам.

Третє правило: **нова версія змінює й старі документи README.** Документ README — неповторний текст, а в рядку
`# версія:` стоять усі версії, де README був саме таким. Тож після нових версій джерело `readme-<пакет>`
перезаписується цілком (`refresh readme-motion`), а не докачується (`--missing`).

Четверте правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед будь-якою роботою нижче тексти розпаковують, а після неї — пакують і виносять
знову; обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## 1. Вийшли нові версії чи змінився сайт

**Крок 1. Завантажити.** Сайт, журнали змін, реєстр npm і README перечитуються цілком: сайт — одна редакція, і нові
сторінки з'являються в sitemap.xml самі.

```
./df motion sources --why
./df motion refresh
./df motion manifest
./df motion vectors
./df motion smoke
# Ctrl+C у терміналі з serve, і знову: ./df motion serve
```

Після одного-двох нових випусків досить `refresh site-docs site-examples site-ui site-troubleshooting site-magazine
site-changelog changelog-motion readme-motion readme-framer-motion npm-motion npm-framer-motion npm-motion-dom
npm-motion-utils`, для Vue — ще `readme-motion-v npm-motion-v releases-motion-vue changelog-motion-vue`.

**Крок 2. Якщо вийшла нова мажорна лінія**, у промптах замінити поточний випуск: `prompts/search.txt` (абзац
«Versions») і `prompts/agent.txt` називають «Motion 14.x» і «Motion для Vue 2.x».

**Крок 3. Новий пакет.** Якщо Motion випустив новий пакет у npm, додати для нього `npm-<пакет>` (читач
`npm-versions`, `name_prefix` — назва пакета, `skip_versions: "-"`) і, якщо в нього є README довший за заглушку,
`readme-<пакет>` (читач `npm-readme`, шаблон адреси README в полі `files`) за зразком сусідніх.

**Крок 4. Сайт змінив розмітку.** Якщо `refresh` пише «Сторінка не схожа на документ» чи в текстах прикладів
з'явилися рекламні блоки Motion+, треба поправити поле `drop` джерел `site-*`: це вирази, що вирізають навігацію,
закриті вставки Motion+, перелік схожих прикладів і JSON-LD.

Корпус не комітиться: після оновлення пишуть новий архів і знову виносять тексти (README, розділ «Архівний режим»),
а в git ідуть лише паспорт і кеш.

Якщо `smoke` скаржиться на число фрагментів — це наслідок того, що документація підросла. Нове число записують у
`checks.json` полем `expected_passages`, а в `expected_note` — коли й чому його знято.

## 2. Збирання з нуля

**Крок 1. Токен.** Покладіть `GITHUB_TOKEN=…` у `.env` цієї теки: без нього дерево репозиторію Popmotion і релізи
Motion для Vue ідуть годинними вікнами по 60 звернень.

**Крок 2. Усе одним прогоном**, окремим процесом:

```
PYTHONUNBUFFERED=1 setsid nohup ./df motion refresh > refresh.log 2>&1 < /dev/null &
```

Близько години з чвертю. Обірваний прогін продовжують `./df motion refresh --missing`: записане вдруге не тягнеться.

**Крок 3.** `manifest`, `vectors` (~13 хвилин), `smoke`, `quality`; далі — архів і винесення текстів.

Очікувані збої `refresh`: дві порожні чернетки блогу Popmotion (`popmotion-site-popmotion--…-blog-draft-*`) і
порожній запис 0.8.8 журналу змін Motion (`changelog-motion--motion-0.8.8`).
