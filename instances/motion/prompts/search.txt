Search the official documentation of Motion (formerly Framer Motion) -- the animation library for
React, JavaScript and Vue -- and return the matching excerpts with the versions each one belongs
to. Here: every page of motion.dev as it stands now -- the docs for Motion for React, JavaScript
and Vue, the Motion+ (paid) components, Motion UI, the AI Kit, the examples and tutorials, the
troubleshooting log of errors and warnings, the Magazine articles and the site changelog; and the
history of every stable release -- the CHANGELOG of Motion from Framer Motion 0.3.0 (2019) to the
current 14.x, the README and the npm registry record of every stable version of framer-motion,
motion, motion-dom, motion-utils, framer-motion-3d, motion-v (Motion for Vue) and Motion One
(@motionone/*, motion 10.x), the Motion One changelog, and the Motion for Vue changelog and GitHub
release notes.

Call this when a question is about Motion itself -- the motion component and its props (animate,
initial, exit, transition, variants, whileHover, whileTap, whileInView, whileDrag), gestures and
drag, AnimatePresence, layout animations (layout, layoutId, LayoutGroup), scroll animations
(useScroll, scroll, whileInView), motion values (useMotionValue, useTransform, useSpring,
useVelocity, motionValue), animate, useAnimate, stagger, springs and easing, timelines and
sequences, SVG and path drawing, animateView and view transitions, LazyMotion and bundle size,
reduced motion, MotionConfig, Reorder; Motion for JavaScript (animate, scroll, inView, hover,
press); Motion for Vue (motion-v); Motion+ components (AnimateNumber, Ticker, Carousel, Cursor,
splitText, Typewriter) and Motion UI; an error or warning Motion printed; upgrading from
framer-motion to motion and between major versions -- and above all when it is about history:
since which version something exists, what changed between versions, what was renamed or removed.
Example query: "AnimatePresence exit mode popLayout".

Do not call this for React, Vue, Next.js or the browser APIs themselves, for CSS animations and
transitions without Motion, for GSAP, React Spring, Popmotion or other animation libraries, or for
Framer the design tool: their documentation is not here, and the search will return Motion
excerpts that merely mention them, with confident-looking titles.

Versions. The pages of motion.dev carry no version: the site keeps one edition, describing the
current release (Motion 14.x for React and JavaScript, Motion for Vue 2.x), so a question about
how to do something today is searched without `version`. `version` narrows the search to the
documents of one release line -- registry records, READMEs, changelog entries and release notes:
"12" keeps every 12.x document, "12.23" keeps 12.23.x. Every excerpt comes back with `versions`:
each version whose documents contain this exact text, newest first. Version numbers of different
packages overlap: framer-motion and motion share numbers from 11.11.12 on (the same library under
two names); motion 10.x and @motionone/* 10.x are Motion One, a different library from
framer-motion 10.x; motion-v 0.x-2.x are Motion for Vue, not framer-motion 0.x-2.x. So name the
package or product in the query together with `version` ("framer-motion 10 layoutId", "Motion
One animate 10", "motion-v 1").

Name the component, hook, function or prop the way the documentation titles it, not in the
user's own words: "AnimatePresence", "useScroll", "layoutId", "whileInView", "useAnimate
stagger", "LazyMotion domAnimation", not "fade out an element when it is removed". Name the
platform for API pages ("react", "vue", "javascript"): the same API has a page for each. For a
how-to question an example often shows it better than the guide: search for the example as well
("example react scroll progress").

For a question about when something appeared, changed or disappeared, search more than once:
without `version` first, to find the changelog entry that names the exact version, then with the
versions around it, to see the READMEs and registry records of that time.

Write the query in English, with the names Motion itself uses (motion.div, AnimatePresence,
useMotionValue, motion/react). Everything here is English -- the excerpts, the word index and
the meaning index alike -- and the word index keeps only latin letters and digits, so a query
written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes back
with `found: 0`. When the user asks in another language, translate the question into Motion terms
first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Every answer says which version it is for. When the user did not name a version, answer for
Motion 12.x -- the line most installed from npm, for framer-motion and motion alike -- and for
Motion for Vue 2.x: take the motion.dev page, then check the 13.0 and 14.0 sections of the upgrade
guide ("upgrade guide 13.0 14.0") and the changelog, and say where 12.x differs from what the
page describes. Say so in the answer ("for Motion 12.x"), and add that for a precise answer about
another version the user can name it. When the excerpts behind a statement come only from older
versions, name those versions instead of presenting the text as current.
Pages marked "Motion+ (paid)" describe components that are not in the free motion package; say
so when the answer relies on one.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists; what changed in later versions;
and how it stands now -- recommended, deprecated, or removed and replaced by what. Every point
names the version and the document it rests on; a point the excerpts do not support is left out,
not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація Motion". Identifiers, API names and titles stay in English,
spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it
says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
