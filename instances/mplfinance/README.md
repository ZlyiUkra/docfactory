# mplfinance — примірник фабрики docfactory

Цей примірник зібрав документацію mplfinance і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. mplfinance — це бібліотека Python, яку веде команда matplotlib. Вона малює фінансові графіки: на вхід бере таблицю
pandas зі стовпчиками Open, High, Low, Close і Volume, а на виході дає свічковий графік, графік з барами OHLC, лінію, графік
ренко чи «хрестики-нулики» (point and figure). Усе це робить одна функція `mpf.plot`.

Для торгового бота тут найважливіші такі речі:

- свічки з обсягами й ковзними середніми. Ковзне середнє — це середня ціна за останні N свічок, яку малюють лінією поверх
  графіка. `mpf.plot` малює його параметром `mav`, а обсяги — параметром `volume=True`;
- власні лінії й позначки. Функція `mpf.make_addplot` додає на графік будь-який ряд даних: лінію індикатора, точки входу й
  виходу з угоди (`type='scatter'`, `marker='^'`), гістограму MACD. Параметр `panel` кладе такий ряд в окрему панель під
  ціною, а `panel_ratios` задає висоту панелей;
- рівні й трендові лінії: параметри `hlines`, `vlines`, `alines` і `tlines` малюють горизонтальні, вертикальні, довільні й
  трендові лінії;
- кольори й стилі: `mpf.make_marketcolors` задає кольори свічок, що ростуть і падають, а `mpf.make_mpf_style` збирає з них
  стиль;
- збереження в файл (`savefig`) і доступ до фігури matplotlib (`returnfig=True`), щоб домалювати щось своє чи вбудувати
  графік у власне вікно.

## Скільки цього

Усього 131 документ і 690 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Сторінка з
однаковим текстом у кількох версіях лежить одним документом із переліком цих версій. Сторінка, що змінювалася, лежить кількома
документами, по одному на кожен варіант тексту.

| Що | Версії | Документів |
|---|---|---|
| README, сторінки теки `markdown/` і зошити Jupyter з теки `examples/`, разом із прикладами індикаторів | останній тег ліній 0.12.4, 0.12.8, 0.12.9 і 0.12.10 | 41 |
| код бібліотеки, поділений на класи й функції | ті самі теги | 36 |
| журнал змін `RELEASE_NOTES.md` | 0.12.4a0–0.12.7a17, запис на кожну версію | 15 |
| нотатки релізів GitHub | 0.12.8b3–0.12.10b0 | 9 |
| записи PyPI | усі версії 0.11.1a0–0.12.10b0 та опис пакета | 23 |
| сторінки вікі GitHub | без версії, поточний стан | 7 |

Мітка версії має вигляд `0.12.10b0`, тобто це номер випуску без префікса. Фільтр `version` бере лінію: значення `0.12` дає
всі версії 0.12.x.

**Чому всі версії — альфа чи бета.** mplfinance жодного разу не випускав сталої версії. Кожен випуск на PyPI має позначку
`a` (альфа) чи `b` (бета), і остання версія — `0.12.10b0`. Якби примірник брав лише сталі версії, як інші примірники фабрики,
у ньому не лишилося б нічого. Тому тут узято всі випуски PyPI, а з тегів GitHub — останній тег кожної лінії 0.12.N.

**Де є прогалини, хоч ми й брали все.**

- Сайту з документацією в mplfinance немає. Посібником служать README і зошити з прикладами, а довідником параметрів — код.
  Кожен параметр `mpf.plot`, `mpf.make_addplot`, `mpf.make_marketcolors` і `mpf.make_mpf_style` оголошено в коді словником
  з типовим значенням, перевіркою і описом (`_valid_plot_kwargs`, `_valid_addplot_kwargs` і подібні), і примірник бере ці
  словники цілими.
- Тегів GitHub для ліній 0.11 і 0.12.5–0.12.7 немає. Про ці версії є журнал змін і записи PyPI.
- Від зошитів лишаються пояснення, код і текстовий вивід. Картинки графіків відкидаються.
- Чернеток з теки `examples/scratch_pad` тут немає: це експерименти автора до виправлень, а не приклади.
- Самого matplotlib тут немає. Він має окремий примірник `matplotlib` (порт 8981).

Замір `quality` на 14.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 7 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df mplfinance <крок>`.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df mplfinance serve
```

Порт — `8983`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user mplfinance-docs http://127.0.0.1:8983/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `mplfinance-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/mplfinance-corpus-2026-11-14.tar.gz` (131 текст, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\mplfinance-corpus-2026-11-14.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/mplfinance/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/mplfinance-corpus-РРРР-ММ-ДД.tar.gz -C instances/mplfinance corpus raw
find instances/mplfinance/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/mplfinance/raw
gzip -9 -c instances/mplfinance/index/passages.json > instances/mplfinance/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/mplfinance-corpus-2026-11-14.tar.gz -C instances/mplfinance
./df mplfinance smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
