# mupdf — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про MuPDF і PyMuPDF за їхньою документацією. MuPDF — бібліотека мовою C
від компанії Artifex: вона читає, малює, перетворює і змінює документи PDF, XPS, EPUB та інші. PyMuPDF — її прив'язка
до Python, тобто пакет, через який ту саму бібліотеку викликають із коду Python. Тут лежать документація обох,
заголовкові файли C з описом кожної функції, приклади коду, журнали змін і книжка розробника MuPDF.

## Навіщо MuPDF і PyMuPDF в одному примірнику

PyMuPDF — тонка обгортка: майже кожен його метод викликає одну-дві функції MuPDF, а номер версії PyMuPDF до лінії 1.28
повторював номер MuPDF усередині. Тому питання про одне часто впирається в інше. Чому `Page.get_text()` повертає текст
саме в такому порядку, пояснюють параметри структурованого тексту MuPDF. Що вміє `Document.save(garbage=4)`, описано і
в PyMuPDF, і в параметрах запису PDF бібліотеки MuPDF, і в команді `mutool clean`. В одному примірнику один пошук
бачить усі три місця.

| Що питають | Де відповідь у цьому примірнику |
|------------|----------------------------------|
| Як викликати функцію C і що означає кожен її параметр | заголовкові файли `include/mupdf/fitz/*.h` і `include/mupdf/pdf/*.h` |
| Як влаштовано C API: контекст, помилки, пам'ять, потоки | довідник C API в документації MuPDF і книжка «MuPDF Explored» |
| Які параметри має команда `mutool` | сторінка на кожну команду і сторінки man |
| Як зробити щось у Python: текст, таблиці, зображення, анотації, форми | документація PyMuPDF: сторінка на клас, рецепти, FAQ |
| Як перетворити PDF на Markdown для мовної моделі | розділи PyMuPDF4LLM і PyMuPDF Layout |
| З якої версії є метод і що змінив реліз | журнали змін обох бібліотек, релізи, історія PyPI |

**Що є що.** **Контекст** (`fz_context`) — об'єкт, який MuPDF отримує першим аргументом у кожній функції: у ньому
лежать стек помилок, розподілювач пам'яті й сховище розібраних ресурсів. **`fz_try` / `fz_catch`** — макроси, якими
MuPDF імітує винятки в мові C. **Заголовковий файл** — файл `.h` з оголошеннями функцій бібліотеки; у MuPDF над кожним
оголошенням стоїть коментар, що описує функцію. **`mutool`** — утиліта командного рядка MuPDF: малює сторінки,
перетворює, чистить і зливає файли. **Pixmap** — растрове зображення сторінки в пам'яті. **Структурований текст**
(stext) — текст сторінки, розкладений на блоки, рядки й символи з координатами. **Затирання** (redaction) — вилучення
тексту з файла так, щоб його не можна було відновити.

## Звідки документація

- **Довідник C API — із заголовкових файлів.** Сторінки документації MuPDF описують лише частину функцій. Повний опис
  стоїть у заголовкових файлах: над кожним оголошенням — коментар, що каже, що функція робить і що означає кожен
  параметр. Читач `ghcode-history-ch` ділить заголовок на групи оголошень, розділені порожнім рядком. Група з
  коментарем стає розділом, назва розділу — імена того, що група оголошує («fz_open_document()»,
  «fz_document_drop_fn», «struct fz_page»), коментар лягає звичайним текстом, а оголошення — блоком коду під ним.
- **Документація MuPDF — з репозиторію, у трьох макетах.** Від лінії 1.26 сайт mupdf.readthedocs.io збирається з теки
  `docs`, у лініях 1.22–1.25 — з теки `docs/src`, а до 1.21 документація лежала сторінками HTML. Узято всі три, кожен
  на останньому тегу своїх ліній. Поле `slug_rewrite` у `config.json` зводить імена тих самих сторінок у різних
  макетах до одного (сторінка команди `mutool draw` має три різні імена файла), щоб у видачі вона займала одне місце,
  а не три.
- **Довідник класів PyMuPDF розбирає власний читач.** У документації PyMuPDF сторінка описує клас, а кожен метод
  записано директивою Sphinx на відступі всередині `.. class:: Page`, а не заголовком. Спільний читач лишав би підпис
  методу звичайним рядком, і сторінка `Page` на 85 методів ділилася б на кілька розділів. Читач
  `ghdocs-history-pydomain` робить кожен метод розділом з назвою «Page.get_text()». Повний підпис з параметрами стоїть
  першим рядком розділу, а не в назві: підпис між версіями міняється, і в назві він дав би тому самому методові різних
  версій різні ключі.
- **Лінія PyMuPDF 1.19 — окремим джерелом.** У тезі 1.19.6 ті самі сторінки лежать файлами `.txt`, а не `.rst`.
- **Журнали змін — запис на версію.** Файли `CHANGES` (MuPDF), `changes.txt` (PyMuPDF) і `CHANGES.md` (PyMuPDF4LLM)
  поділено на документи за заголовком запису, і кожен документ несе свою версію.
- **Книжка — Robin Watts, MuPDF Explored, Artifex Software, редакція від 23.01.2023.** Її написав один із розробників
  MuPDF і виклав у відкритий доступ. Вона пояснює C API і внутрішню будову: контекст, помилки, пам'ять і сховище,
  інтерфейс документа й пристрою, списки показу, потоки, шрифти, будову інтерпретатора PDF. Документ — глава книжки;
  версії книжка не несе.
- **PyPI.** Реєстр PyPI дає історію версій кожного пакета з датами й вимогами до Python і README пакета.

## Межі, про які треба пам'ятати

- JavaScript API бібліотеки MuPDF (пакет npm `mupdf`, MuPDF.js, скрипти `mutool run`) сюди не входить: він лежить у
  примірнику `pdf-js` разом з іншими бібліотеками PDF для JavaScript. Сторінка команди `mutool run` тут є; у лініях до
  1.21 вона сама описує об'єкти JavaScript, а окремого довідника цих об'єктів з пізніших ліній тут немає. Для ліній
  MuPDF 1.22–1.25 цього довідника немає в жодному примірнику.
- Заголовок ділиться за коментарями й порожніми рядками. Функція без власного коментаря стоїть у розділі сусідньої
  групи; у назві розділу видно перші три імена групи, решта — лише в коді розділу.
- У книжці «MuPDF Explored» імена функцій у звичайному тексті записано без підкреслень («fz new context» замість
  «fz_new_context»): так їх зверстано в самому PDF. У блоках коду книжки імена цілі. Книжка описує MuPDF початку 2023
  року (лінії 1.21–1.22), тож частина функцій відтоді змінилася.
- Книжка не має версії, тому пошук із параметром `version` її не бачить.
- Текстові файли ліній 1.3–1.10 несуть назву файла («naming.txt») замість назви сторінки: заголовків у них немає.
- Документації PyMuPDF ліній 1.12–1.14 у репозиторії немає, а лінії до 1.9 лежали в іншій теці й не беруться. Для них
  є лише README з PyPI та історія версій.
- Сторінки документації ведуть на адреси `…/en/latest/…` сайтів mupdf.readthedocs.io і pymupdf.readthedocs.io, тобто
  на найновішу версію сторінки, а не на версію документа.
- Передрелізи не беруться. Теги MuPDF з літерою (`1.10a`, `1.9a`, `1.7a`) несуть мітку без літери: `mupdf-1.10`.
- Самого формату PDF (специфікація ISO 32000) тут немає. Утиліти poppler, Ghostscript і qpdf — у примірнику
  `doc-tools`. Інших бібліотек PDF для Python (pypdf, pdfplumber, ReportLab) немає ніде.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/mupdf-corpus-2026-11-21.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\mupdf-corpus-2026-11-21.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів немає
ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/mupdf/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/mupdf-corpus-РРРР-ММ-ДД.tar.gz -C instances/mupdf corpus raw
find instances/mupdf/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/mupdf/raw
gzip -9 -c instances/mupdf/index/passages.json > instances/mupdf/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/mupdf-corpus-2026-11-21.tar.gz -C instances/mupdf
./df mupdf smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/mupdf/index/passages.json.gz`, далі
`./df mupdf vectors` заллє колекцію Qdrant.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df mupdf …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Ключ для кроку `ask` і токен GitHub лежать у кореневому `.env`.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df mupdf sources --why    # перелік джерел і білий список
./df mupdf refresh          # усе: близько пів години мережею
./df mupdf manifest         # оновити паспорт
./df mupdf setup            # Qdrant чи пошук лише по словах
./df mupdf vectors          # залити корпус у docs-mupdf
./df mupdf smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df mupdf serve   # порт 8998
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8998/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user mupdf-docs http://127.0.0.1:8998/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `mupdf-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
