# Примірник mysql

Цей примірник шукає в документації MySQL. MySQL — це сервер реляційної бази даних: він зберігає дані в таблицях і виконує
запити мовою SQL. Застосунок звертається до сервера через драйвер, тобто бібліотеку для своєї мови програмування. Тому тут
лежать і довідник самого сервера, і документація драйверів.

MariaDB — окремий продукт, що колись відгалузився від MySQL. Її документація лежить у примірнику
[`mariadb`](../mariadb/README.md).

## Що всередині

| Що | Лінії чи версії | Звідки |

| Довідник MySQL | 26.10, 9.7, 8.4, 8.0 | Info-архіви, завантажені користувачем |
| Довідник MySQL | 5.7 | PDF, завантажений користувачем |
| Драйвери Connector/J, Connector/NET, Connector/Python, Connector/ODBC | поточні | PDF, завантажені користувачем |
| Коротка довідка `MySQL and PHP` | поточна | PDF на 8 сторінок; сам `mysqli` і `PDO` описано в примірнику `php` |
| Пакети npm `mysql2`, `mysql`, `@mysql/xdevapi` | усі стабільні | реєстр npm і README кожної версії |
| Документація і випуски `mysql2` | поточна | GitHub |
| Образ `mysql` | теги й сторінка образу | Docker Hub, `docker-library/docs` |

Усього 12 935 документів, із них пошук будує 29 275 фрагментів. Фрагмент — це невеликий шматок тексту, який знаходить пошук.

## Чого тут немає

- Окремих приміток до випусків кожної лінії MySQL. Про зміни говорять лише примітки всередині самого довідника.
- Лінії 26.7 і ліній, старших за 5.7.
- Окремого довідника кодів помилок, C API, Connector/C++ і офіційного довідника Connector/Node.js.

Запит `CREATE INDEX` спершу показує сторінку довідника 5.7. Це слабке місце: заголовки PDF мають інші імена, ніж сторінки
нових ліній, тому пошук не об'єднує їх як одну сторінку різних версій.

## Чому файли завантажує людина

Сайти `dev.mysql.com` і `downloads.mysql.com` відповідають кодом 403 на назву клієнта нашого завантажувача. Проєкт не обходить
цей фільтр підміною назви. Тому людина завантажує посібники браузером, а читачі `mysql-info` і `mysql-pdf` читають ці файли
без звернень до мережі. Імена вузлів Info збігаються зі сторінками сайту, тому посилання в довіднику ведуть на справжні адреси
на кшталт `refman/8.4/en/select.html`. У PDF такого збігу немає, і там посилання веде на зміст посібника.

## Корпус лише локально

Корпус — це завантажені тексти, а індекс — кеш фрагментів, з якого підіймається сервер. Умови Oracle прямо забороняють
публікувати чи поширювати цю документацію, але дозволяють особисте використання й перетворення формату без зміни змісту.
Тому **корпус та індекс у git не потрапляють** (`corpus/` і `index/` у `.gitignore`), у git лежать лише налаштування
примірника. Сервер працює лише на цій машині.

**Де тексти.** Вони лежать в архіві `~/archives/docfactory/mysql-corpus-2026-11-04.tar.gz` разом із паспортом і вихідними
файлами в `raw/local/`. Копія лежить на Windows: `C:\Distr\mysql-corpus-2026-11-04.tar.gz`. Архів звірено з диском файл за
файлом, а копію — за SHA-256. Сервер підіймається з кешу `index/passages.json` і колекції Qdrant, тому тексти йому не потрібні.

**Як повернути тексти** перед оновленням:

```
tar -xzf ~/archives/docfactory/mysql-corpus-2026-11-04.tar.gz -C instances/mysql
./df mysql smoke
```

**Якщо зникне кеш фрагментів.** Спершу поверніть тексти, а потім запустіть `./df mysql vectors`: кеш збереться заново.

Як оновлювати примірник, описано в [UPDATE.md](UPDATE.md).

## Як запустити

```
./df mysql serve
```

Сервер слухає порт `8952`. Перевірка: `./df mysql smoke` і `./df mysql quality`. Замір «як модель» дає 10 із 10, а запити
своїми словами — 7 із 10.
