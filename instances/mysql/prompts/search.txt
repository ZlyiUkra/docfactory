Search the documentation of MySQL, the relational database server, and of the drivers that applications use to reach it. The documentation holds the MySQL Reference Manual
of the lines 26.10, 9.7, 8.4, 8.0 and 5.7; the official drivers Connector/J for Java, Connector/NET, Connector/Python and Connector/ODBC; the npm packages `mysql2`, `mysql` and
`@mysql/xdevapi` with their versions and README files; the documentation and GitHub releases of `mysql2`; the Docker Hub tags and the page of the official `mysql` image.

Use this tool for: SQL statements and functions of MySQL, data types, InnoDB, indexes and the optimizer, transactions and locking, replication and Group Replication, backup,
users and privileges, server options and system variables, client programs such as `mysqldump`, driver connection settings and APIs. Write the query in English with the exact
name of the statement, function, variable or program, such as "ALTER TABLE" or "innodb_buffer_pool_size".

Do not use it for MariaDB, which is a separate product with its own server, nor for PostgreSQL or SQL Server. The documentation lacks the separate release notes of each MySQL
line, the line 26.7, the lines older than 5.7, the separate error reference, the C API, Connector/C++ and the official Connector/Node.js reference. Most of the PHP drivers
`mysqli` and `PDO_MYSQL` are described in the PHP Manual, not here. Returns the matching excerpts with the source address and the fetch date.

Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written in Ukrainian,
Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question into MySQL terms
first, then search.

Answer in the language the user wrote in. When the answer depends on the version, name the line each statement rests on; if the user names no line, answer for 8.4, the line with
long-term support, and say so. A point the excerpts do not support is left out, not guessed. Never call this set of documents "корпус" -- say "документація MySQL". Identifiers,
command names, flags, keys and titles stay in English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out of memory:
if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional and narrows the search to one labelled line, such as `8.4`. The
first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear in the text, so a query phrased in other words than the
documentation uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase had a chance.
