# nats-js — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про nats.js — офіційний клієнт NATS для JavaScript і TypeScript (Node.js,
Deno, Bun, браузери) в обох його лініях: пакет `nats` 2.x і модульні пакети `@nats-io/*` 3.x (репозиторії nats-io/nats.js
і nats-io/nats.deno, реєстр npm, довідник TypeDoc). Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Клієнт — те, чим код говорить із сервером NATS: `connect()` з опціями перепідключення й автентифікації, підписки
ітератором чи зворотним викликом, request/reply, заголовки, `drain()`, а для JetStream — менеджер потоків і консумерів,
`consume()`, `fetch()`, `next()`, підтвердження `ack()`, `nak()`, `term()`, Key-Value, Object Store і сервіси. На пакеті
`nats` 2.x стоїть транспорт NATS мікросервісів NestJS.

Між лініями API помітно змінився: у 3.0 клієнт розпався на окремі пакети (`@nats-io/nats-core`, `@nats-io/jetstream`,
`@nats-io/kv`, `@nats-io/obj`, `@nats-io/services`, `@nats-io/transport-node`), частину методів перейменовано чи
прибрано, і `migration.md` перелічує, що саме. Тут документація кожної лінії зібрана в одному місці, з номером версії
біля кожного уривка.

Примірник — другий і останній у родині NATS, після `nats` (сам сервер). Браузерний клієнт `nats.ws` не взято: його
репозиторій заархівовано, а WebSocket тепер у `@nats-io/nats-core` лінії 3.

Запити своїми словами слабкі, бо README пишуть назвами методів, а не описом задачі; модель же шукає назвами — і тут
влучає. Дві цілі доповнено справжніми відповідями з довідника API: опції перепідключення в `ConnectionOptions` і функція

Чому лінія 2 береться з nats.deno. Пакет `nats` 2.x для Node.js — тонка обгортка над спільним клієнтом nats-base-client,
який жив у репозиторії nats-io/nats.deno; мінорна nats.deno 1.N іде разом із пакетом `nats` 2.N, тож тег v1.N береться
з версією 2.N. Повний опис JetStream і сервісів другої лінії — саме там (`jetstream.md`, `services.md`); тегів 2.x у
репозиторії nats.js більше немає. Для кожної мінорної береться останній патч.

Чому довідник лише 3.4. TypeDoc на nats-io.github.io/nats.js зібрано з гілки `main`, тобто з поточної лінії; довідника
старших версій сайт не тримає. Імена документів довідника — шлях сторінки без назви пакета (`classes-bucket`,
`interfaces-connectionoptions`), бо так її адресує сам TypeDoc.

Чого немає. Самого сервера NATS (примірник `nats`), транспорту NATS у NestJS (у `nestjs`), клієнтів інших мов, коду й
тестів репозиторію. Пререлізи (`-0`, `-RC`) не беруться.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df nats-js <крок>`.

Версія документа — версія пакета (`2.29`, `3.4.0`); лінія 2 — пакет `nats`, лінія 3 — пакети `@nats-io/*`. Фільтр

## Родина NATS: піднімати разом

Цей примірник — частина родини NATS: сам сервер і клієнт для Node.js. Питання про клієнта впирається в поведінку сервера
(теми, черги-групи, підтвердження й повторна доставка JetStream, налаштування потоку), а питання про сервер — у те, як
його викликати з коду. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує обидва
сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `nats` | `nats-docs` | 8894 | сам NATS 2.11–2.15: core NATS, JetStream, KV, Object Store, кластери, безпека, конфігурація, релізи |
| `nats-js` | `nats-js-docs` | 8895 | клієнт nats.js: пакет `nats` 2.x (на ньому транспорт NATS NestJS) і пакети `@nats-io/*` 3.x |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/nats-js-corpus-2026-10-25.tar.gz` (585 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\nats-js-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/nats-js/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/nats-js-corpus-РРРР-ММ-ДД.tar.gz -C instances/nats-js corpus raw
find instances/nats-js/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/nats-js/raw
gzip -9 -c instances/nats-js/index/passages.json > instances/nats-js/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/nats-js-corpus-2026-10-25.tar.gz -C instances/nats-js
./df nats-js smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/nats-js/index/passages.json.gz`, далі
`./df nats-js vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df nats-js …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df nats-js sources --why   # перелік джерел і білий список
./df nats-js refresh         # завантажити все задеклароване (близько 6 хвилин)
./df nats-js manifest        # оновити паспорт
./df nats-js setup           # Qdrant чи пошук лише по словах
./df nats-js vectors         # залити корпус у docs-nats-js
./df nats-js smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df nats-js serve          # порт 8895
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8895/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user nats-js-docs http://127.0.0.1:8895/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `nats-js-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
