# Оновлення корпусу nats-js

Тут оголошено руками теги й коміти: README пакетів 3.x — з тегів v3.0.2–v3.4.0 nats-io/nats.js, документи лінії 2 — з
тегів v1.0.8–v1.29.3 nats-io/nats.deno, приклади docs.nats.io — з коміту e0e6eef34 гілки `main` nats.js. README пакета
`nats` з npm, реєстр, довідник TypeDoc і релізи беруться щоразу заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

1. Нова мінорна 3.x (тег `v3.5.0` у nats-io/nats.js): у поле `tags` джерела `njs-v3` дописують `"v3.5.0": "3.5.0"`; новий
   патч наявної мінорної заміняє її старий тег. Пререлізи (`v3.5.0-1`) не беруть.
2. У джерелах `njs-api-*` поле `version` — версія, з якої зібрано довідник на nats-io.github.io (на 25.10.2026 — 3.4.0).
3. Нові приклади docs.nats.io: SHA `https://api.github.com/repos/nats-io/nats.js/commits/main` — у `tags` джерела
   `njs-examples`.
4. Лінія 2 (пакет `nats`) нових мінорних не отримує; новий патч 2.29.x з'явиться в README з npm сам, а тег nats.deno
   v1.29.x — у `tags` джерела `njs-v2-base`.

```
./df nats-js check                 # чи змінилося щось нагорі за джерелом
./df nats-js refresh               # повне перезавантаження, близько 6 хвилин
./df nats-js manifest
./df nats-js vectors
./df nats-js smoke
# Ctrl+C у терміналі з serve, і знову: ./df nats-js serve
```

Якщо змінилося співвідношення завантажень ліній (на 25.10.2026 — `nats` 2.x і `@nats-io/*` 3.x поруч) — у
`prompts/search.txt` (абзац «Which version to search first») і `prompts/agent.txt` замінити лінії й числа; у
`checks.json`, у десятках `quality` і `quality_model`, звірити цілі там, де питання про поточну поведінку.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен: без нього GitHub дає 60 звернень на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df nats-js quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
