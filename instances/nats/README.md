# nats — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про NATS — систему обміну повідомленнями з відкритим кодом nats-server з
core NATS (публікація й підписка, request/reply, черги-групи) і JetStream (потоки, консумери, Key-Value, Object Store) —
за документацією сайту docs.nats.io всіх версій, які він тримає, старою документацією GitBook, архітектурними рішеннями
команди й нотатками кожного стабільного релізу сервера. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

NATS — сервер, через який клієнти обмінюються повідомленнями за темами (subjects) з шаблонами `*` і `>`: core NATS
доставляє «не більше одного разу» тим, хто підписаний зараз, а JetStream зберігає повідомлення в потоках (streams) і
віддає їх консумерам (consumers) з підтвердженнями й повторною доставкою. Поверх потоків збудовано Key-Value і Object
Store, а кластери, супер-кластери й leaf-вузли з'єднують сервери між собою. У плані NestJS (фулстек-родина) NATS стоїть у
«знати, що існує» серед транспортів мікросервісів поруч із Kafka і RabbitMQ — і він останній із трьох, кого там бракувало.

Поведінка між версіями змінювалася: JetStream заступив NATS Streaming, у 2.11 з'явився TTL окремого повідомлення, у
2.12 — атомарна пакетна публікація, лінії 2.11 і 2.12 сайт уже позначає як непідтримувані. Тут довідник кожної версії
сайту й нотатки кожного релізу зібрані в одному місці, з номером версії біля кожного уривка.

Примірник — перший у родині NATS: сервер окремо, клієнт Node окремо, як у родинах Redis, Mongo, Kafka і RabbitMQ. Далі
в родині — `nats-js` (пакет `nats` 2.x і пакети `@nats-io/*` 3.x). Окремого модуля NestJS для NATS не взято: транспорт
NATS є в самому `@nestjs/microservices`, тобто в примірнику `nestjs`.

Чому сайт береться з репозиторію. З серпня 2026 docs.nats.io збирає Docusaurus з репозиторію nats-io/nats.docs.v2:
довідник кожної версії лежить у теці `reference_versioned_docs/version-*` одного коміту гілки `main` (36e49e4b8 від

одна родина (`families` і `slug_rewrite` у `config.json`). Learn, Concepts і Tutorials версій не мають. Приклади коду
мовами клієнтів сайт вставляє під час збирання з репозиторіїв клієнтів, тож у тексті сторінок їх немає — приклади
JavaScript лежать у `nats-js`. Від них лишилися заглушки `<div class="nats-example" …>`, які займають кілька рядків:
49 штук на 18 сторінках Learn. Відповідей вони не псують, і прибрати їх варто разом із наступним оновленням.

Стара документація. До серпня 2026 той самий сайт збирав GitBook з репозиторію nats-io/nats.docs, тепер заархівованого.
Останній коміт (f115becf6 від 24.08.2026) береться цілим, без китайського перекладу: там налаштування сервера, `nsc` і
`nats` CLI, розробка з клієнтами з прикладами кожною мовою, NATS Streaming у розділі legacy. Версій вона не мала; адреса в
шапці документа — файл на GitHub, бо старі адреси сайту тепер ведуть на нову документацію.

Чого немає. Клієнтських бібліотек як окремих проєктів (nats.js — окремий примірник родини, nats.go, nats.py), транспорту
NATS у NestJS (він у `nestjs`), Kubernetes, Docker і самої мови Go. Пререлізи сервера (`-RC`, `-beta`) не беруться.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, `families`, `slug_rewrite` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df nats <крок>`.

## Версії

Версія сторінки довідника — версія сайту, з якого її взято (`2.11`…`2.15`); нотатки релізів несуть точну версію
(`2.14.8`). Фільтр `version` бере мажор (`"2"`), мінор (`"2.14"`) або точну версію (`"2.12.15"`). Статистики
завантажень за версіями сервера NATS не публікує, тож промпт відповідає для ліній, які проєкт латає: 2.15 (2.15.1 від
09.10.2026) і 2.14 (2.14.8 того ж дня); 2.12 і 2.11 сайт позначає як непідтримувані.

## Родина NATS: піднімати разом

Цей примірник — частина родини NATS: сам сервер і клієнт для Node.js. Питання про клієнта впирається в поведінку сервера
(теми, черги-групи, підтвердження й повторна доставка JetStream, налаштування потоку), а питання про сервер — у те, як
його викликати з коду. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує обидва
сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `nats` | `nats-docs` | 8894 | сам NATS 2.11–2.15: core NATS, JetStream, KV, Object Store, кластери, безпека, конфігурація, релізи |
| `nats-js` | `nats-js-docs` | 8895 | клієнт nats.js: пакет `nats` 2.x (на ньому транспорт NATS NestJS) і пакети `@nats-io/*` 3.x |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/nats-corpus-2026-10-25.tar.gz` (3449 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\nats-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/nats/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/nats-corpus-РРРР-ММ-ДД.tar.gz -C instances/nats corpus raw
find instances/nats/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/nats/raw
gzip -9 -c instances/nats/index/passages.json > instances/nats/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/nats-corpus-2026-10-25.tar.gz -C instances/nats
./df nats smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/nats/index/passages.json.gz`, далі
`./df nats vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df nats …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df nats sources --why   # перелік джерел і білий список
./df nats refresh         # завантажити все задеклароване (близько 35 хвилин)
./df nats manifest        # оновити паспорт
./df nats setup           # Qdrant чи пошук лише по словах
./df nats vectors         # залити корпус у docs-nats
./df nats smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df nats serve          # порт 8894
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8894/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user nats-docs http://127.0.0.1:8894/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `nats-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
