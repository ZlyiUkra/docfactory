# Оновлення корпусу nats

Тут усе оголошено руками: сайт закріплено на коміті гілки `main` nats-io/nats.docs.v2 (36e49e4b8 від 22.10.2026), стару
документацію — на останньому коміті заархівованого nats-io/nats.docs (f115becf6), ADR — на коміті
nats-io/nats-architecture-and-design (dc0b1c720). Релізи сервера беруться з GitHub Releases щоразу заново. Сама собою
нова версія сайту сюди не потрапляє.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

1. Новий коміт сайту: `https://api.github.com/repos/nats-io/nats.docs.v2/commits/main` дає SHA. У полі `tags` джерел
   `nats-ref-*`, `nats-learn`, `nats-concepts` і `nats-tutorials` старий SHA замінюють новим — сторінки старих версій
   сайт теж правлять.
2. Нова мінорна (2.16) з'являється в `reference_versions.json` сайту й текою `reference_versioned_docs/version-2.16`:
   джерело `nats-ref-2.16` дописують за зразком `nats-ref-2.15` (тека, вираз `site`), його id — у родину `nats-ref` поля
   `families` у `config.json`. Адреса найновішої версії на сайті — `/reference/…`, попередніх — `/reference/<версія>/…`,
   тож у джерелі `nats-ref-2.15` вираз `site` переписують на `/reference/2.15/…`. Тека `docs-reference/` — наступна, ще
   не випущена версія, її не беруть.
3. Нові ADR: SHA `https://api.github.com/repos/nats-io/nats-architecture-and-design/commits/main` — у `tags` джерела
   `nats-adr`.

```
./df nats check                 # чи змінилося щось нагорі за джерелом
./df nats refresh               # повне перезавантаження, близько 35 хвилин
./df nats manifest
./df nats vectors
./df nats smoke
# Ctrl+C у терміналі з serve, і знову: ./df nats serve
```

`refresh` повний, не `--missing`: новий коміт сайту міняє й сторінки старих версій.

Якщо змінилися лінії, які проєкт підтримує (на 25.10.2026 — 2.15 і 2.14), — у `prompts/search.txt` (абзац «Which
version to search first») і `prompts/agent.txt` замінити їх на нові; у `checks.json`, у десятках `quality` і
`quality_model`, звірити цілі там, де питання про поточну поведінку.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен: без нього GitHub дає 60 звернень на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df nats quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
