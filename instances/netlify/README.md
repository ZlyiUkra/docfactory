# netlify — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Netlify за його документацією: уся документація docs.netlify.com
(збирання й `netlify.toml`, розгортання, Deploy Previews, змінні оточення, Netlify Functions, Edge Functions, Netlify
Blobs, Netlify Database, кеш, Image CDN, переспрямування й `_redirects`, заголовки, домени, Forms, Identity, захист
доступу, моніторинг, фреймворки, розширення, AI Gateway, плани й ліміти), посібники developers.netlify.com, журнал
змін, блог і база знань www.netlify.com; довідник Netlify API з OpenAPI; довідник команд Netlify CLI на кожній
стабільній мінорній лінії; README і журнали змін `netlify-cli` та пакетів `@netlify/*`. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

Netlify — платформа, на якій можна розгорнути вебзастосунок (хостинг). Плани навчання називають її поряд із Vercel і
Cloudflare. Документація фреймворків (Astro, Next.js, Nuxt) описує лише адаптер, через який збірка потрапляє на
Netlify. Як працює сама платформа, у тих документаціях не написано: `netlify.toml`, `_redirects`, функції та їхні
ліміти, змінні оточення за контекстами розгортання, Forms, домени, ціни. Тут зібрано саму платформу.

  для користувача описано в документації.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df netlify <крок>`.

Читач `sitemap-accept-heading` спільний із примірником `vercel`. Для Netlify в нього додано кілька полів.
`title_strip` прибирає « | Netlify» з назв статей блогу. `date_from_url` бере дату з адреси запису журналу змін і
старої статті блогу й дописує її в назву. `md_url` і `title_html` потрібні для посібників: їхня сторінка не має
markdown-двійника за своєю адресою. Кнопка «Markdown» на сторінці посібника завантажує текст з
`/api/guides/<slug>/raw`, і читач бере його звідти. Так код прикладів зберігає переноси рядків, які в HTML злипалися
б. Назви в тому тексті немає, тож читач бере її з `<h1>` самої сторінки.

Поле `drop` прибирає примітку про llms.txt на початку кожної сторінки документації, а в блозі — усе від «Written by»:
автора, кнопки поширення й перелік схожих статей.

## Версії

Сайт версії не несе: його сторінки описують Netlify на день завантаження. Версію несуть довідник команд CLI, README і
журнали змін, і кожен пакет має свій префікс, щоб нумерації не змішувалися: CLI — `cli-` (`version: "cli-27"`
бере довідник команд, README і журнал змін 27.x), решта — за коротким іменем (`"functions-6"`, `"blobs-11"`,
`"edge-functions-4"`, `"nextjs-5"` для `@netlify/plugin-nextjs`, `"tanstack-start-1"` для
`@netlify/vite-plugin-tanstack-start`). Промпт шукає «як зробити» без версії, а версію передає лише для питань про
історію пакета.

Вибір версій такий: для кожного пакета взято останній патч кожної стабільної мінорної лінії. Список версій записано в
`skip_versions` джерела як вираз «усе, крім цих», а теги довідника CLI — у полі `tags`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/netlify-corpus-2026-11-24.tar.gz` (5 099 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\netlify-corpus-2026-11-24.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/netlify/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/netlify-corpus-РРРР-ММ-ДД.tar.gz -C instances/netlify corpus raw
find instances/netlify/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/netlify/raw
gzip -9 -c instances/netlify/index/passages.json > instances/netlify/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/netlify-corpus-2026-11-24.tar.gz -C instances/netlify
./df netlify smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/netlify/index/passages.json.gz`.
Далі `./df netlify vectors` заллє колекцію Qdrant: менше хвилини на відеокарті, довше на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df netlify …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df netlify sources --why   # перелік джерел і білий список
./df netlify refresh         # завантажити все задеклароване (близько 45 хвилин)
./df netlify manifest        # оновити паспорт
./df netlify setup           # Qdrant чи пошук лише по словах
./df netlify vectors         # залити корпус у docs-netlify
./df netlify smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df netlify serve          # порт 9003
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:9003/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user netlify-docs http://127.0.0.1:9003/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `netlify-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
