# Оновлення корпусу netlify

Сайти версій не мають: кожен `refresh` бере їхній поточний стан, і змінена сторінка не затирає збереженої — стара
відповідь переїжджає в `raw/_old/<день>/`. Журнали змін пакетів читаються з гілок main (у двох старих репозиторіях —
master).

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df netlify check                 # чи змінилося щось нагорі за джерелом
./df netlify refresh               # повне перезавантаження (близько 45 хвилин)
./df netlify refresh npm-netlify-cli cli-docs changelog-cli   # лише CLI
./df netlify manifest
./df netlify vectors
./df netlify smoke
# Ctrl+C у терміналі з serve, і знову: ./df netlify serve
```

Перерваний повний прогін продовжують командою `refresh <джерело, де зупинився>`, а потім `refresh --missing`.

**Нові мінорні лінії самі не додаються.** README беруться лише з версій, перелічених у `skip_versions` кожного джерела
`npm-…`, а довідник команд CLI — лише з тегів у полі `tags` джерела `cli-docs`. Обидва переліки складено на день
збирання: для кожного пакета — найбільший патч кожної пари «мажор.мінор». Щоб узяти нові лінії, переліки складають
заново за реєстром npm.

**Що перевірити після оновлення.**

- Сторінка, що зникла з sitemap, лишається в корпусі (нічого не видаляється). Щоб прибрати її, файл видаляють руками
  разом із записом паспорта — лише за рішенням людини.
- Якщо `refresh` пише «Замість markdown прийшов HTML», сторінка перестала віддавати markdown на `Accept`: звірити її
  (`curl -H 'Accept: text/markdown' <адреса>`). Так уже поводяться дев'ять шаблонів підказок.
- Якщо посібники developers.netlify.com дають 404, сайт змінив адресу `/api/guides/<slug>/raw`: знайти нову в скрипті
  кнопки «Markdown» на сторінці посібника й виправити `md_url` джерела `guides`.
- Якщо журнал змін дає мало записів, заголовки змінили вигляд: звірити вираз `heading` джерела з першими рядками
  `CHANGELOG.md`.
- Нова мажорна CLI (на 24.11.2026 найновіша — 27.20.1): замінити `"cli-27"` у `prompts/search.txt`,
  `prompts/agent.txt` і `version_probe` у `checks.json`.

Якщо `smoke` скаржиться на число фрагментів, корпус підріс. Нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df netlify quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
