Search the Netlify documentation and return the matching excerpts with the versions each one belongs to.
What is here: every page of docs.netlify.com as a current snapshot -- builds and `netlify.toml`, deploys, Deploy
Previews and branch deploys, environment variables, Netlify Functions (synchronous, background, scheduled, event
triggered), Edge Functions, Netlify Server, Netlify Blobs, Netlify Database, caching and the Cache API, Image CDN,
redirects, rewrites and proxies (`_redirects`), headers, domains and DNS, HTTPS, Forms, Identity, password protection,
traffic rules, rate limiting, WAF, monitoring and logs, framework setup guides, extensions and the SDK, AI Gateway,
Agent Runners, accounts, plans, pricing and limits -- with the developer guides of developers.netlify.com, the
changelog, the blog and the knowledge base of www.netlify.com; the Netlify API reference built from its OpenAPI file,
one document per resource; the Netlify CLI command reference (`netlify deploy`, `netlify dev`, `netlify env`,
`netlify functions`, `netlify blobs` and the rest) at the last release of every stable minor line from 3.0; the README
of the last release of every stable minor line of netlify-cli, @netlify/functions, @netlify/edge-functions,
@netlify/blobs, @netlify/images, @netlify/cache, @netlify/dev, @netlify/database, @netlify/ai, @netlify/identity,
@netlify/otel, @netlify/vite-plugin, @netlify/vite-plugin-tanstack-start, @netlify/nuxt, @netlify/plugin-nextjs (the
Next.js runtime), @netlify/angular-runtime, @netlify/api, @netlify/sdk, netlify-identity-widget and gotrue-js; and the
changelogs of all of them but the SDK.

Call this when a question is about Netlify: deploying a site from Git or the CLI, build settings and `netlify.toml`,
deploy contexts, Deploy Previews, environment variables and secrets, writing and configuring functions and edge
functions, storing data in Blobs or Netlify Database, redirects, rewrites, proxies and headers, domains, forms,
identity and access control, caching, framework support (Next.js, Astro, Nuxt, SvelteKit, TanStack Start, Angular),
limits and pricing, the REST API, and history: since which CLI version a command or flag exists, what changed in a
package release, when a feature was announced in the changelog.

Do not call this for other clouds or hosting platforms (AWS, Cloudflare, Vercel), for frameworks themselves (Next.js,
Astro, Nuxt, SvelteKit) beyond how they build and deploy on Netlify, for Node.js, Deno or Web API semantics in
general, or for JavaScript or TypeScript language questions: their documentation is not here, and the search will
return Netlify excerpts that merely mention them, with confident-looking titles.

The site carries no version: its pages describe Netlify as of the day they were fetched. `version` narrows the search
to one release line of a package. Every package carries a prefix, so the lines never mix: "cli-27" keeps the CLI
command reference, README and changelog entries of netlify-cli 27.x; the others are "functions-6",
"edge-functions-4", "blobs-11", "images-2", "cache-4", "dev-5", "database-2", "ai-1", "identity-2", "otel-7",
"vite-plugin-3", "tanstack-start-1", "nuxt-1", "nextjs-5", "angular-runtime-4", "api-15", "sdk-5",
"identity-widget-2", "gotrue-js-1". Leave it empty to search everything, the site included. Every excerpt comes back
with `versions`: each version whose documents contain this exact text, newest first, so the list itself shows from
which to which version a text said exactly this.

Write the query in English, with the names Netlify itself uses ("netlify deploy --prod", "netlify.toml",
"_redirects", "rewrites and proxies", "scheduled functions", "background functions", "Edge Functions declarations",
"getStore Netlify Blobs", "deploy contexts", "Deploy Previews", "password protection", "Netlify Forms"), not in the
user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin
script matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the
question into Netlify terms first, then search.

Answer in the language the user wrote in. When the question is about the history of a CLI command or option, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands now. Every point names the version and the document it rests on; a point the
excerpts do not support is left out, not guessed. Limits and prices are quoted as the page states them, as of the
date it was fetched. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a translation from
English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий",
not "депрекейтнутий". Never call this set of documents "корпус" -- say "документація Netlify". Identifiers, command
names, keys and titles stay in English, spelled exactly as the documentation spells them. Build the answer out of
the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it before describing what
it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` --
pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a
second, meaning-based index answered as well, and a paraphrase had a chance.
