# next-intl — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про next-intl — бібліотеку інтернаціоналізації (i18n) для Next.js:
повідомлення у форматі ICU (підстановки, множина, вибір за значенням, rich text), форматування дат, часу, чисел і
списків, маршрутизація за мовою з проміжним шаром (`middleware`, у Next.js 16 — `proxy`) і навігацією, App Router
(серверні й клієнтські компоненти) і Pages Router. Разом із ним — use-intl, ядро тієї самої бібліотеки без прив'язки
до Next.js, і два пакети 4.x з того самого репозиторію: icu-minify і next-intl-swc-plugin-extractor. Документація —
усіх стабільних версій. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає
самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Документація Next.js показує інтернаціоналізацію лише загально (маршрут `[lang]`, словники), а next-intl — окремий
шар зі своїм API, що помітно мінявся між мажорами: у 3.0 підтримка App Router вийшла з бети з новими API навігації,
у 3.18–3.22 з'явилися `defineRouting`, `createNavigation` і `requestLocale`, у 4.0 — сувора типізація мови й
аргументів ICU, кукі мови лише на час сесії, інша спадковість `NextIntlClientProvider`, обов'язкова мова з
`getRequestConfig`. Сайт next-intl.dev показує тільки найновішу версію; тут — усі стабільні поруч.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df next-intl <крок>`.

Читач `ghdocs-history-nextintl` додано разом із цим примірником (`engine/readers/ghnextintl.py`). Він бере сайт так
само, як `ghdocs-history`, але перед розбором доповнює й очищує текст сторінки:

- **Назва файла блоку коду** (```` ```tsx filename="src/i18n/request.ts" ````) стає рядком «File
  `src/i18n/request.ts`:» перед блоком. Саме з неї видно, куди класти код, а звичайний розбір лишає від рядка відкриття
  лише мову.
- **Вкладки** `<Tabs items={[…]}>` дістають підписи зі свого місця в `items`: «With i18n routing» / «Without i18n
  routing», «i18n/request.ts» / «Provider». Без них дві версії коду стояли б поруч без пояснення.
- **Питання розкривних блоків** (`<details>`/`<Details>` з `<summary>`) стають жирним рядком.
- **Банери відеокурсу й партнерів**, відео в блозі й коментарі JSX поза кодом знімаються.

Особливості корпусу:

- **До 1.2 документації в репозиторії немає**: уся документація тих версій — README.
- **Службові файли сайту** (його README, CHANGELOG, компоненти) і рекламна головна сторінка не беруться. Від
  головної лишалися б сирі властивості карток.
- **Нотатки релізів GitHub не беруться**: вони є лише з 3.15.1 і слово в слово повторюють журнал змін.
- **Документ — неповторний текст.** Версії, де файл не змінився, ділять один документ; у рядку `# версія:` стоять
  усі.

## Межі, про які треба пам'ятати

Документації Next.js (маршрутизація, `middleware`, `generateMetadata`), React, Intl API JavaScript (вона в
примірнику `mdn`), специфікації синтаксису ICU, i18next і react-intl тут немає. Код бібліотеки, тести, приклади
застосунків з `examples/` і типи з пакета не входять: сайт описує API повністю й показує код прикладів на сторінках.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/next-intl-corpus-2026-10-14.tar.gz` (1 121 текст, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде.
Архів лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/next-intl/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/next-intl-corpus-РРРР-ММ-ДД.tar.gz -C instances/next-intl corpus raw
find instances/next-intl/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/next-intl/raw
gzip -9 -c instances/next-intl/index/passages.json > instances/next-intl/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/next-intl-corpus-2026-10-14.tar.gz -C instances/next-intl
./df next-intl smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/next-intl/index/passages.json.gz`,
далі `./df next-intl vectors` заллє колекцію Qdrant (близько чотирьох хвилин).

## Установка venv

```
cd instances/next-intl
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df next-intl sources --why   # перелік джерел і білий список
./df next-intl refresh         # завантажити все задеклароване (близько 35 хвилин)
./df next-intl manifest        # оновити паспорт
./df next-intl setup           # Qdrant чи пошук лише по словах
./df next-intl vectors         # залити корпус у docs-next-intl
./df next-intl smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df next-intl serve          # порт 8837
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8837/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user next-intl-docs http://127.0.0.1:8837/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `next-intl-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
