# Оновлення корпусу next-safe-action

Сайт, README й журнали адаптерів беруться з закріплених комітів: джерело `nsa-repo` тримає в полі `tags` коміт
останнього тегу кожної мінорної (`vX.Y.Z`, з 8.x — `next-safe-action@X.Y.Z`). Релізи GitHub і реєстр npm беруться
щоразу заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

**Нова версія next-safe-action.** Новий патч наявної мінорної — замінити в полі `tags` джерела `nsa-repo` коміт і
версію її рядка; нова мінорна — новий рядок нагорі `tags` (від найновішого). Коміт тегу дає
`https://api.github.com/repos/next-safe-action/next-safe-action/git/ref/tags/next-safe-action@X.Y.Z` (для анотованого
тегу — ще один крок через `git/tags/<sha>`) або `git ls-remote --tags https://github.com/next-safe-action/next-safe-action`
(рядок `^{}` — коміт анотованого тегу). Нова тека чи пакет-адаптер — дописати в `folders` чи `files` того самого
джерела, а новий адаптер — ще й джерело `npm-…` за зразком наявних.

```
./df next-safe-action check                 # чи змінилося щось нагорі за джерелом
./df next-safe-action refresh               # повне перезавантаження, близько 6 хвилин
./df next-safe-action manifest
./df next-safe-action vectors
./df next-safe-action smoke
# Ctrl+C у терміналі з serve, і знову: ./df next-safe-action serve
```

Якщо змінилося співвідношення завантажень ліній (на 26.10.2026 лінія 8 — 80 %) чи найновіша версія в npm (8.7.3),
— у `prompts/search.txt` (абзац «Which version to search first») і `prompts/agent.txt` замінити лінії й числа.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df next-safe-action quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
