# next-themes — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про next-themes — пакет npm, який перемикає тему React-застосунку
(світлу, темну, системну чи будь-яку власну): ставить клас або атрибут `data-*` на елемент `html`, пам'ятає вибір у
`localStorage` і вставляє на сторінку маленький скрипт, щоб під час завантаження не блимала чужа тема. Працює з
Next.js App Router і Pages Router та з будь-яким застосунком React. Документація — усіх стабільних версій пакета. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Сайту документації в next-themes немає: усе, що є, — README (той самий текст на сторінках GitHub і npm), типи в
пакеті, нотатки релізів і приклади в репозиторії. Домашня сторінка репозиторію, next-themes-example.vercel.app, —
лише демо з перемикачами тем, тексту документації там немає. README мінявся з версіями: розділи про App Router, про
розбіжність гідратації, про Tailwind CSS і власний селектор, про Cloudflare Rocket Loader з'являлися поступово. Тут —
усі версії поруч, тож на питання «як це в моїй версії» є відповідь саме для неї.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df next-themes <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| README і типи | tarball `registry.npmjs.org/next-themes/-/next-themes-X.tgz` | `npm-tarball-files` |
| README 0.3.0 | тег v0.3.0 репозиторію `pacocoursey/next-themes` | `ghdocs-history` |
| нотатки релізів | API релізів `pacocoursey/next-themes` | `ghreleases` |
| приклади | теки `example/` і `examples/` репозиторію на кожній стабільній версії | `ghcode-history-ts` |
| реєстр npm | registry.npmjs.org, одне звернення | `npm-versions` |

Нових читачів примірник не потребував. Особливості корпусу:

- **README — з tarball**, а не з тегів: так є й версії без тегів (усі до 0.2.0 і 0.2.1), і текст точно той, що
  отримує `npm install`. README гілки main збігається з 0.4.6 байт у байт.
- **README 0.3.0 — з тегу**, бо пакет 0.3.0 вийшов без нього. Правило `slug_rewrite` у `config.json` дає йому той
  самий ключ, що й README з пакетів, тож однакові розділи зливаються в один фрагмент з усіма версіями.
- **Приклади версій без тегу** взято з останнього коміту main перед публікацією версії в npm (0.0.16 і 0.1.0 —
  той самий коміт); реєстр npm `gitHead` для next-themes не записав. До 0.0.10 приклад лежав у теці `example/`, далі —
  `examples/example/`; друге правило `slug_rewrite` зводить їх. Приклади поділено на розділи за оголошеннями
  (компонент, функція); конфіги Next.js, Tailwind і PostCSS відкинуто.
- **Лінія версії — два числа** (`version_line_depth: 2`): усі версії — 0.x, тож фільтр `version: "0.4"` бере 0.4.x, а
  `"0.3"` — 0.3.0.
- **Сумісність із React і Next.js** записана в документах реєстру npm полем peerDependencies: 0.0.16–0.1.x — `next
  >=11.1.1`, 0.2.x — будь-який `next`, 0.3.0 — без `next`, React 16.8–18, 0.4.x — React 16.8–19.
- **Документ — неповторний текст.** Версії, де файл не змінився, ділять один документ; у рядку `# версія:` стоять усі.

## Межі, про які треба пам'ятати

Документації Next.js, React, Tailwind CSS, CSS загалом і інших бібліотек тем та інтерфейсу (shadcn/ui, Radix, MUI)

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/next-themes-corpus-2026-10-13.tar.gz` (71 текст, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде.
Архів лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/next-themes/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/next-themes-corpus-РРРР-ММ-ДД.tar.gz -C instances/next-themes corpus raw
find instances/next-themes/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/next-themes/raw
gzip -9 -c instances/next-themes/index/passages.json > instances/next-themes/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/next-themes-corpus-2026-10-13.tar.gz -C instances/next-themes
./df next-themes smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/next-themes/index/passages.json.gz`,
далі `./df next-themes vectors` заллє колекцію Qdrant (близько хвилини).

## Установка venv

```
cd instances/next-themes
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df next-themes sources --why   # перелік джерел і білий список
./df next-themes refresh         # завантажити все задеклароване (близько 2 хвилин)
./df next-themes manifest        # оновити паспорт
./df next-themes setup           # Qdrant чи пошук лише по словах
./df next-themes vectors         # залити корпус у docs-next-themes
./df next-themes smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df next-themes serve          # порт 8835
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8835/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user next-themes-docs http://127.0.0.1:8835/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `next-themes-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
