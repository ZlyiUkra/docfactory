# Оновлення корпусу next-themes

Перелік версій README, типів і реєстру тут не оголошується руками: читачі пакета беруть його з опису пакета в реєстрі
npm (`https://registry.npmjs.org/next-themes`), тож нова версія потрапляє в корпус сама, коли вийде в npm. Нотатки
релізів беруться з API релізів `pacocoursey/next-themes`.

Руками оголошено лише версії прикладів: поле `tags` джерела `next-themes-examples`. Новий стабільний тег дописують
першим рядком, у вигляді `"v0.4.7": "0.4.7"`. Якщо версія вийде без тегу, ключем стає повний SHA останнього коміту
main перед її публікацією в npm. Якщо пакет нової версії вийде без README, як 0.3.0, її тег дописують і в поле `tags`
джерела `next-themes-readme-030`.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df next-themes check                 # чи змінилося щось нагорі за джерелом
./df next-themes refresh               # повне перезавантаження, близько 2 хвилин
./df next-themes manifest
./df next-themes vectors
./df next-themes smoke
# Ctrl+C у терміналі з serve, і знову: ./df next-themes serve
```

`refresh` повний, не `--missing`: у документі стоять усі версії, де текст був таким, тож нова версія змінює й старі
документи (README, що не змінився, дописує нову версію в рядок `# версія:`).

Якщо вийшла нова лінія (0.5 чи 1.0):

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` переглянути лінію за
  замовчуванням: вона — найпопулярніша за завантаженнями npm (на 13.10.2026 — 0.4.x, 80,5 %; друга — 0.3.0, 18,1 %),
  і де дві лінії близькі, відповідь дається для обох;
- у `checks.json`, у десятці `quality_model`, замінити `"0.4"` там, де питання про поточну поведінку, і звірити цілі.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) потрібен для дерев тегів і комітів (27 звернень) і релізів: без нього годинне
вікно в 60 звернень лишає надто мало запасу.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df next-themes quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
