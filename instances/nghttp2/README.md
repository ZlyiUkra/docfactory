# nghttp2 — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про nghttp2 — реалізацію HTTP/2 і HPACK на C, на якій стоїть модуль `http2`
Node.js: сесії (`nghttp2_session_*`), подання запитів і відповідей (`nghttp2_submit_*`), зворотні виклики, коди помилок
`NGHTTP2_ERR_*`, керування потоком, SETTINGS, динамічна таблиця HPACK, утиліти `nghttp`, `nghttpd`, `nghttpx` (проксі) і
`h2load` (навантаження). Документація — посібник програміста, туторіали, довідкові сторінки утиліт, публічний заголовок
з коментарями Doxygen, вихідний код бібліотеки й утиліт, тести, приклади й нотатки кожного випуску від 0.1.0 до 1.70.0. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій
фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Документація Node.js описує `http2` зверху. Чому сесія закрилась з `NGHTTP2_ERR_FLOW_CONTROL`, скільки потоків відкриває
сервер за замовчуванням, у якому випуску закрито «rapid reset» чи «CONTINUATION flood» — відповідає nghttp2, а його версія в
кожному випуску Node своя (які — у примірнику `nodejs`, документ кожної лінії).

## Що в цій теці

- `corpus/` — паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа. Самих текстів тут немає:
  корпус в архіві.
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — токен GitHub і, для кроку `ask`, ключ Anthropic; `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики через `./df nghttp2 <крок>`.

## Звідки документація

Один репозиторій `nghttp2/nghttp2`, 135 тегів `vX.Y.Z`. Читачі всі наявні: `ghdocs-history` (з `sphinx`), `ghcode-history`
(заголовки — з `outline`, розділ на коментар Doxygen), `ghreleases`. Нового коду не знадобилось.

Особливості:

- **Сторінки API зібрані з заголовка.** `doc/nghttp2.h.rst.in` — шаблон, у якому довідник збирає `mkapiref.py` із
  `nghttp2.h`; сам заголовок береться окремим джерелом (`nghttp2-api`) і є повним довідником C API.
- **Шаблони `.rst.in`.** Підстановки версії не обчислюються; у старих тегах поряд лежить `doc/sources/*.rst` — зібрана
  документація, тож однакові сторінки з'являються і як `doc-tutorial-client`, і як `doc-sources-tutorial-client`.
- **Утиліти — це C++ у `src`.** Конфігурація `nghttpx` читається з `shrpx_config.cc` і `shrpx.cc`: опції там описані
  поруч із кодом.

## Межі, про які треба пам'ятати

Документації модуля `http2` Node.js, HTTP/1.x (llhttp) і інших бібліотек HTTP/2 тут немає. `third-party/` (стороннє) і
`fuzz`-корпуси не беруться.

## Родина Node: піднімати разом

Цей примірник — один зі складників Node.js, і питання до нього рідко приходять самі: «чому `dns.resolve` поводиться так» починається в API Node і закінчується в c-ares, «що значить `ERR_OSSL_…`» — в OpenSSL. Тому примірники родини Node піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує всі вісім серверів: підключивши будь-який із них, Claude Code бачить решту.

## Архівний режим: сервер без корпусу

Корпус в архіві від самого початку: у `corpus/` лежить лише паспорт, а сервер підіймається з кешу фрагментів і
колекції Qdrant; відповіді ті самі до символа.

**Де тексти.** В архіві `~/archives/docfactory/nghttp2-corpus-2026-10-15.tar.gz` (80 МБ, 6 337 текстів, паспорт і сховище
сирого `raw/`; перед видаленням розпакований окремо й звірений з диском — нуль розбіжностей). Лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
tar -czf ~/archives/docfactory/nghttp2-corpus-РРРР-ММ-ДД.tar.gz -C instances/nghttp2 corpus raw
find instances/nghttp2/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/nghttp2/raw
gzip -9 -c instances/nghttp2/index/passages.json > instances/nghttp2/index/passages.json.gz
```

**Як повернути тексти** — перед будь-яким оновленням:

```
tar -xzf ~/archives/docfactory/nghttp2-corpus-2026-10-15.tar.gz -C instances/nghttp2
./df nghttp2 smoke
```

**Оновлення.** Новий тег дописують першим рядком у `tags` усіх шести джерел з тегами («"v1.70.1": "1.70.1"»). Далі
`./df nghttp2 refresh`, `manifest`, `vectors`, `smoke`, `quality`.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df nghttp2 …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/nghttp2/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають. Для роботи сервера збирати нічого не
треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df nghttp2 sources --why   # перелік джерел і білий список
./df nghttp2 refresh         # завантажити все задеклароване (близько 35 хвилин)
./df nghttp2 manifest        # оновити паспорт
./df nghttp2 setup           # Qdrant чи пошук лише по словах
./df nghttp2 vectors         # залити корпус у docs-nghttp2 (близько 35 хвилин)
./df nghttp2 smoke           # перевірки
```

Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df nghttp2 serve          # порт 8843
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8843/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user nghttp2-docs http://127.0.0.1:8843/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User).

**3. Перевірити.** `/mcp` — має бути `nghttp2-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера.
