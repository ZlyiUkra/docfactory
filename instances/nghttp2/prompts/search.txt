Search the nghttp2 documentation, in English: nghttp2 is the C implementation of HTTP/2 and HPACK that
Node.js uses for its `http2` module. The set holds, for every release from 0.1.0 to 1.70.0: the Sphinx
documentation (programmer's guide, client / server / HPACK tutorials, nghttpx and h2load how-tos, the manual
pages of the tools nghttp, nghttpd, nghttpx, h2load), the public header nghttp2.h with the Doxygen comments of
the whole C API (nghttp2_session_*, nghttp2_submit_*, nghttp2_option_*, nghttp2_hd_*, callbacks, error codes),
the library sources (lib), the tool sources (src), tests, examples, the Python binding and the GitHub release
notes. Returns the matching excerpts with the releases each one belongs to.

Call this when a question is about nghttp2 itself: what a function or callback does, an error code
(NGHTTP2_ERR_*), settings and flow control, HPACK dynamic table behaviour, the option flags, how nghttpx is
configured, since which release something exists or a vulnerability was fixed (CVE, rapid reset, CONTINUATION
flood). Example query: "nghttp2_session_callbacks_set_on_frame_recv_callback".

Do not call this for the Node.js `http2` module itself or for which nghttp2 a given Node.js release bundles
(the nodejs instance has them), for HTTP/1.x parsing (llhttp), or for other HTTP/2 libraries (hyper, h2).

Write the query in English, with the names nghttp2 itself uses (nghttp2_session, nghttp2_submit_request,
NGHTTP2_FLAG_END_STREAM, SETTINGS_MAX_CONCURRENT_STREAMS). Everything here is English, and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing and comes back with `found: 0`. When the user asks in another language, translate the
question into nghttp2 terms first, then search.

Answer in the language the user wrote in. For a question about history or a security fix, answer
point by point: since which release; what changed; which release fixed it; how it stands now -- each point
with the release and the file it rests on; a point the excerpts do not support is left out, not guessed. When
that language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word
wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of
documents "корпус" -- say "документація nghttp2". Function, type and macro names stay in English, spelled
exactly as the header spells them. Build the answer out of the excerpts that came back, not out of memory:
if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. When the user names a version, or a Node.js release (use the nodejs instance
to see which nghttp2 it bundles), search that line. Otherwise answer for the newest release and say so. Put
a version only into `version`, never into the query text: "1.60" keeps 1.60.x and "1" keeps every 1.x. The C API header is "api-lib-includes-nghttp2-nghttp2-h"; release
notes are "nghttp2-v1.70.0"; tool man pages are "doc-nghttpx-1".
