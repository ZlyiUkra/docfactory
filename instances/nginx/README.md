# nginx — примірник фабрики docfactory

Тридцять восьмий примірник фабрики: захищений MCP-сервер, що відповідає на питання про nginx. Тут документація
nginx.org — поточна (мітка «1.31») і знімки на мить випуску кожної стабільної гілки від 1.0 до 1.30, — журнали змін
кожного випуску від 0.1.0 до 1.31, NGINX Admin Guide, NGINX Ingress Controller (поточний і LTS) і NGINX Gateway Fabric
з docs.nginx.com та контролер ingress-nginx спільноти Kubernetes кожної мінорної версії від 0.34 до 1.15. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

nginx стоїть перед застосунком майже в кожному плані: зворотний проксі й TLS у плані Linux, сервіс у Docker Compose,
Ingress у Kubernetes, самостійне розгортання застосунків NestJS і Next.js, роздача зібраного SPA. Директиви міняються
з версіями: `ssl on` застаріла в 1.15.0 і зникла в 1.25.1, HTTP/2 з 1.25.1 вмикає окрема директива `http2` замість
параметра `listen … http2`, TLSv1 і TLSv1.1 з 1.27.3 вимкнено за замовчуванням. На сервері клієнта може стояти nginx
з дистрибутива п'ятирічної давнини, тож потрібна документація саме його гілки, а не лише поточна.

**Що таке F5 тут.** F5 — компанія, що 2019 року купила NGINX Inc. Сайт docs.nginx.com — її: там документація
комерційного NGINX Plus (вільний nginx плюс платні модулі: активні перевірки стану, API для зміни upstream на льоту,
JWT, дашборд) і власних продуктів для Kubernetes — NGINX Ingress Controller і NGINX Gateway Fabric. Вільний nginx
документує nginx.org. Контролер ingress-nginx — інший продукт: його писала спільнота Kubernetes, не F5, і з березня
2026 його закрито, репозиторій в архіві.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

Разом 2 181 документ; фрагментів в індексі — 11 390 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук. Документ — це одна редакція сторінки: сторінка, що не мінялася від 1.20
до 1.30, — один документ із шістьма версіями, а змінена — кілька. Однаковий текст розділу в різних редакціях
зливається в один фрагмент зі списком версій. Поточна документація nginx.org — 153 сторінки, знімок 1.20 — 130, 1.10 —
96, 1.0 — 12 (див. нижче, чому так мало).

Замір `quality`: перша десятка (питання своїми словами) — по словах 6 із 10, за змістом 7, разом 8; друга, «як модель»
(назви директив, параметрів і ресурсів, з версією, як велить промпт), — 10 із 10. Заміряно сітку `max_per_doc` 0–3 на
`fusion_depth` 0, 60, 120 і 200: «як модель» 10 із 10 дають лише варіанти без `max_per_doc`, і з них найкраще «разом»
(8) — без обох полів, так і стоїть. З `fusion_depth` 200 і `max_per_doc` 2 «разом» — 10 із 10, але запит
`VirtualServer VirtualServerRoute` з версією `nic` губить свою сторінку: обмеження лишає їй по два розділи в кожному
зі списків, що зливаються, а сторінки Policy, де VirtualServer згадано в кожному розділі, є в обох і стоять вище.

**Що пропускає пошук своїми словами.** «Тримати копії відповідей бекенду» (кешування) і «застосувати змінену
конфігурацію, не обриваючи з'єднань» (reload): ні по словах, ні за змістом. З назвами (`proxy_cache_path`,
`nginx -s reload`), як велить промпт, пошук знаходить потрібне.

**Сторінки без підзаголовків.** «WebSocket proxying» з nginx.org, «Basic usage» з ingress-nginx і кожен журнал змін —
суцільний текст без «##». Пошук їх знаходить (з фільтром «1.27.3» перший результат — журнал 1.27.3), але `quality`
рахує влучання лише в розділи із заголовком, тож цілями заміру вони бути не можуть.

**Повнота видачі.** На 20 пробних словах (`proxy`, `ssl`, `ingress`, `websocket`…) видача на 5 і на 10 результатів
повна.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження); `.mcp.json` — запис
  HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df nginx <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| nginx.org | `nginx/nginx.org`: `main` і 16 комітів на мить випуску 1.0.0, 1.2.0 … 1.30.0 | `ghdocs-history` |
| журнали змін | `nginx/nginx.org`, `CHANGES`, `CHANGES-1.30` … `CHANGES-1.0`, `CHANGES-0.8` … `0.5` | `nginx-changes` |
| docs.nginx.com | `nginx/documentation`, гілка `main`, чотири теки | `ghdocs-history` |
| ingress-nginx | `kubernetes/ingress-nginx`, теги `controller-v1.15.1` … `controller-v0.34.1` | `ghdocs-history` |

Білий список — `api.github.com` (дерева трьох репозиторіїв) і `raw.githubusercontent.com`: у кожного джерела — лише
його тека на його комітах і тегах, для docs.nginx.com ще теки `content/includes` і `layouts/shortcodes` та сирі файли
`nginx/kubernetes-ingress`, з яких сторінки NIC вставляють приклади. Посилання у відповідях ведуть на сторінку
nginx.org (`https://nginx.org/en/docs/http/ngx_http_proxy_module.html`), на журнал змін nginx.org, на сторінку
docs.nginx.com, а для ingress-nginx — на файл на GitHub на тезі версії: сайт проєкту показував лише останню.

Особливості, які варто знати:

- **nginx.org — не markdown.** Сайт збирається з XML власного словника: модуль, розділи, директиви з синтаксисом,
  значенням за замовчуванням, контекстом і версією появи. Поле `nginx_xml` читача `ghdocs-history` перетворює його в
  markdown так, як сторінку показує сайт: «### proxy_pass», рядки «Syntax:», «Default:», «Context:» і «This directive
  appeared in version …», приклади — блоками коду. Позначки версій біля параметрів («`delay` (1.15.7)») лишаються в
  тексті.
- **Знімки — коміти, не теги.** Сайт nginx.org тримає одну, поточну документацію, і тегів версій у репозиторії немає.
  Знімок гілки — останній коміт гілки `main` на мить випуску її першої версії (1.30.0, 1.28.0 …). Історію перенесено з
  Mercurial, і GitHub віддає коміти не за датою, тож коміт знято з повного ланцюга комітів, а не запитом «до дати».
  Історія в git починається 11.08.2011, через три місяці після 1.0.0, тож «1.0» — найраніший знімок; у ньому
  англійською лише 12 сторінок.
- **Мітка «1.31» — поточна документація**, тобто основна гілка на день завантаження, а не окремий знімок.
- **Журнал змін — документ на випуск.** Один файл `CHANGES` тримає всю основну гілку, а виправлення стабільних
  (1.30.1 … 1.30.5) є лише в журналі своєї гілки. Читач `nginx-changes` ділить файли на випуски («Changes with nginx
  1.27.3  26 Nov 2024»), кожен запис «*) Feature: …» стає пунктом; випуск, що є в кількох файлах, береться один раз.
- **Hugo на docs.nginx.com.** Сторінки вставляють спільні фрагменти (`{{< include "…" >}}`), приклади з GitHub
  (`{{< ghcode … >}}`), назви продуктів короткими кодами (`{{< product >}}`) і блоки-попередження. Поле `hugo` читача
  підставляє вставки й назви з файлів репозиторію, а попередження стають підписом «Note:», «Important:», «Warning:».
  Залишки `{{ … }}` у трьох документах NIC — це код шаблонів Go в прикладах, так і має бути.
- **NIC і NIC LTS — одна родина.** Сторінки гілки LTS лежать у `content/nic/lts/…`; поле `slug_rewrite` зводить їх
  до імен поточної (`nic-install-helm-index`), а `families` у `config.json` — до однієї родини, тож однаковий текст
  обох — один фрагмент із мітками «nic» і «nic-lts».
- **ingress-nginx — кожна мінорна, яка була.** Мінорних 0.36–0.39 і 0.50 проєкт не випускав, тож міток 29. Тека
  `docs/enhancements` (пропозиції змін, не документація) не береться. Блоки-попередження MkDocs («`!!! note`»)
  лишилися як є — текст під ними читається й шукається.

## Межі, про які треба пам'ятати

Тут немає документації nginx російською, njs поза nginx.org, сторонніх модулів (Lua, OpenResty, ModSecurity поза
сторінками docs.nginx.com), NGINX Unit, NGINX One, NGINX Instance Manager, F5 WAF як окремого продукту, старих версій
docs.nginx.com (сайт публікує лише поточну), історії NIC і NGF до поточного випуску, а також інших серверів і проксі
(Apache, Caddy, HAProxy, Traefik, Envoy). Сам Kubernetes — у примірнику `kubernetes`, Docker — у `docker`, тексти RFC
про TLS і HTTP — у `webstandards`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку, як у express: у `corpus/` лежить лише паспорт `index.json`, а сервер
підіймається з кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає
повний текст кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/nginx-corpus-2026-10-07.tar.gz` (3,7 МБ, 2 181 текст і паспорт;
перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде.
Архів лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/nginx/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/nginx-corpus-РРРР-ММ-ДД.tar.gz -C instances/nginx corpus
find instances/nginx/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/nginx/index/passages.json > instances/nginx/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/nginx-corpus-РРРР-ММ-ДД.tar.gz -C instances/nginx
./df nginx smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/nginx/index/passages.json.gz`, далі
`./df nginx vectors` заллє колекцію Qdrant (близько 50 хвилин).

## Установка venv

```
cd instances/nginx
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

```
./df nginx sources --why   # перелік джерел і білий список
./df nginx refresh         # завантажити все задеклароване (~45 хвилин)
./df nginx manifest        # оновити паспорт
./df nginx setup           # Qdrant чи пошук лише по словах
./df nginx vectors         # залити корпус у docs-nginx (~50 хвилин)
./df nginx smoke           # перевірки
```

Дерев комітів і тегів тут під п'ятдесят, а сторінки docs.nginx.com тягнуть вставки, тож без `GITHUB_TOKEN` у `.env`
анонімного ліміту GitHub API (60 звернень на годину) не вистачить. Тексти йдуть з raw.githubusercontent.com, що до
ліміту не рахується. Обірваний `refresh` продовжується з `--missing`.

**Нова стабільна гілка nginx** (1.32 навесні): знімок не з'являється сам. Знайти коміт гілки `main` репозиторію
`nginx/nginx.org` на мить випуску 1.32.0, дописати його в `tags` джерела `nginx-org` з міткою «1.32» і адресу в
`within`, мітку поточної (`main`) підняти до «1.33»; журнал `CHANGES-1.32` — у `files` джерела `nginx-changes`.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df nginx serve             # порт 8798
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8798/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user nginx-docs http://127.0.0.1:8798/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `nginx-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
