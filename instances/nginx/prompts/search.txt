Search the documentation of nginx, in English: the nginx.org documentation -- every module of http,
stream and mail with every directive (syntax, default value, context, the version it appeared
in), the njs scripting language, the beginner's guide, installing and building from source,
controlling nginx, debugging, how requests are processed, server names, load balancing, HTTPS
servers, the FAQ -- as it is now (nginx 1.31) and as it was at the release of every stable
branch from 1.0 to 1.30; the change logs (CHANGES) of every nginx release from 0.1.0 to 1.31, one
document per release; the NGINX Admin Guide of docs.nginx.com (HTTP and TCP/UDP load balancing,
reverse proxy, content caching, SSL termination, access control and rate limiting, monitoring,
high availability, dynamic modules, mail proxy, installing nginx and NGINX Plus, deployment
guides, NGINX Plus releases); the NGINX Ingress Controller of F5 (current and LTS) and NGINX
Gateway Fabric, both for Kubernetes; and the community ingress-nginx controller for Kubernetes,
every minor version from 0.34 to 1.15 (annotations, ConfigMap, TLS, authentication, examples).
Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about configuring or running nginx: server and location blocks,
proxy_pass and reverse proxying, upstream load balancing, TLS and certificates, HTTP/2 and
HTTP/3, caching, gzip, rewrites and redirects, rate and connection limits, access control,
logging, variables, timeouts and buffers, WebSocket proxying, serving static files, nginx in
Docker or as a Kubernetes ingress -- and when it is about which nginx version added, changed or
fixed something. Example query: "proxy_pass proxy_set_header Host upstream".

Do not call this for other web servers and proxies (Apache, Caddy, HAProxy, Traefik, Envoy have
no documentation here), for Kubernetes itself (the kubernetes instance covers it), for Docker
itself (the docker instance), or for TLS and HTTP as protocols (the webstandards instance has
the RFC texts): the search will return nginx excerpts that merely mention them, with
confident-looking titles.

`version` narrows the search. The nginx.org pages carry the nginx branch they describe: "1.31"
is the current documentation (mainline), "1.30", "1.28" ... "1.0" are snapshots taken at the
release of each stable branch -- a page that stayed the same across branches is one excerpt
with all of them. The change logs carry the exact release ("1.31.6", "1.30.5"), so "1.30"
finds the snapshot of 1.30 and every 1.30.x release note. docs.nginx.com carries "admin-guide",
"nic", "nic-lts" and "ngf"; ingress-nginx carries "ingress-nginx-1.15" ... "ingress-nginx-0.34"
("ingress-nginx-1" is every 1.x). Leave `version` empty to search everything. Every excerpt
comes back with `versions`: each version whose documents contain this exact text, newest first.

Which version to answer for. Unless the user names a version, answer from the current nginx.org
documentation ("1.31") and say since which version a directive or parameter exists -- the
"This directive appeared in version" line and the "(1.15.7)" marks after parameters say it.
Mention NGINX Plus only when it matters: a directive or parameter marked "available as part of
our commercial subscription" does not work in the free nginx, say so. When the user names an
older nginx (a server stuck on 1.14 or 1.18), filter by that branch and answer for it.

Where the documentation lives. nginx.org pages are named by their path (nginx-http-ngx-http-core-module,
nginx-http-ngx-http-proxy-module, nginx-http-ngx-http-upstream-module, nginx-http-ngx-http-ssl-module,
nginx-beginners-guide, nginx-http-request-processing, nginx-njs-reference); change logs by the release
(changes-1.31.6); docs.nginx.com pages by their path (nginx-admin-guide-load-balancer-http-load-balancer,
nic-configuration-ingress-resources-advanced-configuration-with-annotations, ngf-install-helm);
ingress-nginx pages by their path (ingress-nginx-user-guide-nginx-configuration-annotations).

Write the query in English, with the names the documentation uses (server, location, listen,
server_name, root, try_files, proxy_pass, proxy_set_header, proxy_buffering, upstream, least_conn,
keepalive, ssl_certificate, ssl_protocols, http2, http3, quic, gzip, expires, add_header,
return, rewrite, limit_req_zone, limit_conn, allow deny, auth_basic, access_log, log_format,
$remote_addr, $host, map, include, client_max_body_size, proxy_read_timeout, WebSocket Upgrade
Connection, nginx -t, nginx -s reload, Ingress annotations nginx.ingress.kubernetes.io). Everything
here is English -- the excerpts, the word index and the meaning index alike -- and the word
index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in
another language, translate the question into nginx terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Answer in the language the user wrote in. When the question is about a change between versions
or a migration, answer point by point: since which version; what changed; what the migration
requires; how it stands now -- each point with the document it rests on; a point the excerpts do
not support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian
engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word
wherever one exists -- "уривок", not "ексерпт"; "директива", "блок", "проксі", "балансування",
"сертифікат", "застарілий", not "депрекейтнутий". Never call this set of documents "корпус" --
say "документація nginx". Directive, parameter, variable and module names stay in English,
spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it
says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
