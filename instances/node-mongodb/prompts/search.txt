Search the documentation of the official MongoDB driver for Node.js, in English: the npm package `mongodb`
(MongoClient and connection strings, databases and collections, CRUD operations, cursors, aggregation,
indexes, transactions and sessions, change streams, bulk writes, GridFS, read and write concerns, connection
pool and monitoring, authentication mechanisms, TLS, in-use encryption, the TypeScript types) and the `bson`
library (BSON types, ObjectId, Decimal128, Long, Binary, UUID, EJSON). The set holds the driver documentation
site of every minor version from 3.6 to 7.7 (quick start, fundamentals, usage examples, upgrade and
compatibility pages, as each line's documentation stood), the driver's source code src/ with TSDoc (4.0–7.7)
and lib/ with JSDoc (0.x–3.7) and its integration and unit tests of every stable release, HISTORY.md and the
GitHub release notes of the driver and of bson, the npm registry (every version with dates and dependencies)
and the README of every version of mongodb, bson, mongodb-legacy, mongodb-client-encryption, @mongodb-js/zstd,
kerberos and @types/mongodb. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about the driver or bson: how to connect, what a method of MongoClient, Db,
Collection or a cursor does and which options it takes, how to run a transaction, watch a change stream, use
bulkWrite, handle errors and retries, configure the connection pool, which server versions a driver version
supports, what changed between versions, since which version an option exists, how a BSON type is represented
in JavaScript. Example query: "insertMany ordered false".

Do not call this for the server, mongosh or Database Tools (mongodb-docs), for Mongoose (mongoose-docs), or
for other drivers' languages.

Write the query in English, with the names the driver uses (MongoClient, insertMany, findOneAndUpdate,
aggregate, startSession, withTransaction, ObjectId, serverApi, maxPoolSize). Everything here is English, and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin
script matches nothing and comes back with `found: 0`. When the user asks in another language, translate the
question into the driver's terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "колекція", "документ", "курсор".
Never call this set of documents "корпус" -- say "документація драйвера". Names of classes, methods and options
stay in English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that
came back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. When the user names a version, search that line; otherwise answer for both lines
in use -- 6.x and 7.x -- and say so when they differ. Put a version only into `version`, never into the query
text: "6" keeps every 6.x, "6.17" keeps that line. The documentation site is marked by minor line ("6.17"),
the code, tests, HISTORY and npm by every release; bson and the other packages carry their own prefix
("bson-6.10.4", "types-4.0.7") so that their numbers are never confused with the driver's. A site page is named
after its path ("fundamentals-crud-write-operations-insert", "usage-examples-insertmany"); a source file after
its path ("mongodb-src-collection"); a test after its path; HISTORY entries by version.
