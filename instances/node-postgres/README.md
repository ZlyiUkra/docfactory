# node-postgres — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про node-postgres — пакет `pg` для роботи з PostgreSQL з Node.js — за
офіційною документацією всіх стабільних версій: сайтом node-postgres.com у стані на кожен реліз `pg` з 2019 року,
README кожної версії кожного пакета монорепозиторію й супутніх пакетів, журналом змін, сторінками вікі, типами
`@types/pg` з DefinitelyTyped і історією версій одинадцяти пакетів у реєстрі npm. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Що сюди входить і чому одним примірником

node-postgres — не один пакет, а набір: `pg` (клієнт і пул), `pg-pool` (сам пул), `pg-cursor` (курсори),
`pg-query-stream` (результат потоком), `pg-connection-string` (розбір рядка підключення), `pg-native` (біндинг до
libpq), `pg-protocol` (розбір протоколу) — усі в монорепозиторії `brianc/node-postgres`, а сайт описує їх разом. До
нього додано пакети, без яких робота з базою з Node.js рідко обходиться: `pg-types` (як типи PostgreSQL стають
значеннями JS), `pg-copy-streams` (потоки `COPY FROM/TO`), `pg-format` (форматування SQL з екрануванням, стороннього
автора) і `@types/pg` (власних типів `pg` не має). Розділити їх по примірниках означало б той самий пул і ті самі
типи в кількох серверах.

Лінія за замовчуванням — `pg` 8.x: на 09.10.2026 за тиждень 62,7 млн завантажень, з них на старші лінії — менше
0,3%. Супутні пакети нумеруються самі (`pg-pool` 3.x, `pg-cursor` 2.x, `pg-types` 2.x і 4.x), і їхні документи несуть
версію свого пакета. Сам сервер PostgreSQL — у примірнику `postgresql`.

Замір `quality` на першому корпусі: по словах 7 із 10, за змістом 9, разом 10; десятка «як модель» — 10 із 10. По
словах промахуються перекази без назв документації: «return a client to the pool» не містить `release`, «run several
statements inside a transaction» — `BEGIN` і `COMMIT`, «listen for notifications» — `LISTEN`; пошук за змістом усі
три знаходить. Пошук за змістом промахується на «bulk load rows from a csv file into a table»: README
`pg-copy-streams` він приносить, але приклад `COPY TO`, а не `COPY FROM`; пошук по словах ставить потрібний приклад
четвертим, і разом він на п'ятому місці.

Поле `max_per_doc` заміряно 0/1/2/3: перша десятка разом 10, 9, 9, 9, «як модель» — 10, 9, 10, 10; лишилося 0 —
редакції сторінки сайту різних років не займають місць одна в одної самі собою, бо різняться текстом.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, профіль домену й правила
  `slug_rewrite`, що зводять сторінки старого сайту до імен нового.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df node-postgres <крок>`.

Читач **`changelog-scoped`** додано разом із цим примірником (`engine/readers/changelogscoped.py`). node-postgres
веде один журнал на весь монорепозиторій: «## pg@8.23.0», «### pg-pool@3.0.0» і «### pg-cursor@2.0.0» стоять поруч, а
записи до монорепозиторію — «### v6.2.0» без пакета, бо тоді пакет був один (поле `package` джерела каже, що це
`pg`). Ім'я документа — «пакет-версія»: «pg-pool@3.0.0» і «pg@3.0.0» — різні записи.

Особливості, які варто знати:

- **Сайт жив у двох репозиторіях.** З липня 2019 до 10.10.2022 — окремий `brianc/node-postgres-docs` (тека
  `content/`, сторінки з номерами: `api/1-pool`), далі — `docs/pages/` монорепозиторію (`apis/pool`). Джерело
  `np-site` бере обидві епохи, а `slug_rewrite` у `config.json` зводить старі імена до нових, тож редакції тієї самої
  сторінки з обох репозиторіїв — один ключ. Знімок версії — вершина гілки перед виходом наступної версії тієї ж
  лінії, тож сайт описує `pg`, а не супутні пакети.
- **До липня 2019 сайту немає.** Тоді документацією була вікі GitHub; сторінок API там уже немає (лишилися FAQ і
  Extras), а історія вікі доступна лише через `git clone`, не звичайним завантаженням. Для `pg` 7.10 і старших у
  корпусі — README і журнал змін. Перші коміти `node-postgres-docs` (знімок 7.10.0) — заготовка теми сайту з текстом
  заповнювачем; вони виключені з джерела.
- **README переїжджали.** `pg-pool`, `pg-cursor`, `pg-query-stream`, `pg-native` до 2019–2020 жили в окремих
  репозиторіях `brianc/node-pg-*`, `pg-connection-string` — у `iceddev/pg-connection-string`; джерело README
  пробує спершу монорепозиторій, потім старий репозиторій. README немає для 48 версій різних пакетів, здебільшого
  найраніших: реєстр не записав, з якого коміту їх зібрано, а тегу немає, або на тому коміті README ще не було
  (перелік — у журналі `refresh`, рядки «без README»).
- **`@types/pg` — за датами.** Реєстр npm для пакетів `@types` не пише коміт; версія несе файл таким, яким він був у
  найновішому коміті DefinitelyTyped до її публікації (113 версій дали 85 текстів).
- **Вікі — без версії.** Дві сторінки вікі версії не мають, тож `expect_unversioned` у `checks.json` — `true`.

## Межі, про які треба пам'ятати

PostgreSQL (SQL, індекси, налаштування сервера) — у примірнику `postgresql`, Node.js — у `nodejs`. ORM і будівників
запитів на основі `pg` (Prisma, TypeORM, Knex, Drizzle, Sequelize) тут немає. Журнал змін `pg` пише лише мажорні й
мінорні релізи; про виправлення в патчах кажуть README і документи реєстру npm. Сайтів супутніх пакетів немає — лише
README.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/node-postgres-corpus-2026-10-09.tar.gz` (0,8 МБ, 587 текстів і
паспорт; перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів
немає ніде. Архів лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/node-postgres-corpus-2026-10-09.tar.gz -C instances/node-postgres
./df node-postgres smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/node-postgres/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/node-postgres-corpus-РРРР-ММ-ДД.tar.gz -C instances/node-postgres corpus
find instances/node-postgres/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/node-postgres/index/passages.json > instances/node-postgres/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k
instances/node-postgres/index/passages.json.gz`, далі `./df node-postgres vectors` заллє колекцію Qdrant (~4
хвилини).

## Установка venv

```
cd instances/node-postgres
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df node-postgres sources --why   # перелік джерел і білий список
./df node-postgres refresh         # завантажити все задеклароване (~35 хвилин)
./df node-postgres manifest        # оновити паспорт
./df node-postgres setup           # Qdrant чи пошук лише по словах
./df node-postgres vectors         # залити корпус у docs-node-postgres (~4 хвилини)
./df node-postgres smoke           # перевірки
```

Найдовше в `refresh` — README: кожна версія кожного пакета читається окремо, близько семисот звернень із паузою в
секунду. Перші хвилини журнал мовчить: читач сайту проходить коміти обох репозиторіїв і дерева знімків.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df node-postgres serve          # порт 8805
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8805/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user node-postgres-docs http://127.0.0.1:8805/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `node-postgres-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
