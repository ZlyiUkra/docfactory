# nodejs — примірник фабрики docfactory

Тридцять шостий примірник фабрики: захищений MCP-сервер, що відповідає на питання про Node.js і npm. Тут довідник API
Node.js усіх мажорів 10–26 (парних і непарних) з історією кожної функції, розклад ліній і склад кожного релізу,
Notable Changes кожної версії, посібники nodejs.org/learn, сторінки nodejs.org про кінець підтримки й безпекові релізи,
doc/contributing, undici, журнали змін npm 6–12,
документація CLI npm 12, 11, 10, 9, 8, 7 і 6 (команди, `package.json`, `package-lock.json`, `.npmrc`, scripts,
workspaces) і посібники docs.npmjs.com про реєстр, публікацію й безпеку пакетів. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

Node.js і npm стоять під кожним планом лінії 1: `package.json` і `npm ci` — у фазі 0 плану React, `fs`, потоки, event
loop і процеси — у фазі 0 планів NestJS і Next.js, і далі кожен бекенд-день спирається на рантайм. API Node міняється
з кожним мажором (`fs.rmdir` з `recursive` застарів, з'явилися `node:test`, `--env-file`, `require()` модулів ESM),
npm — так само (з npm 7 `peerDependencies` ставляться самі, lockfile змінив формат). Відповідь з пам'яті тут плутає
версії.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

Замір `quality` після оновлення 14.10.2026: сімнадцять питань, з них сім нових (розклад і кінець підтримки, що йде з

словах 10 із 17, за змістом 8, разом 11; «як модель» — 17 із 17 (`max_per_doc` 0, 1 і 3 дали 17, 13 і 17, тож лишилось 2).
Нижче — замір 07.10.2026, коли питань було десять: перша десятка (питання своїми словами) — по словах 4 із 10, за змістом 8, разом 8; друга, «як модель»
(назви модулів, функцій і команд, з версією, як велить промпт), — 10 із 10. Заміряно сітку `max_per_doc` 0–3 на
`fusion_depth` 0, 60, 120 і 200: найкраще 2 і 120, вони й стоять. До злиття сторінок npm пошук за змістом давав 6 із
10, «разом» — ті самі 8.

**Чому `fusion_depth` 120.** Пошук спершу бере кандидатів углиб — `k × 6`, тобто 30 на п'ять місць, — і лише потім
лишає обмежену кількість розділів з документа. Тут вісім мажорів Node: розділи `Buffer` різних мажорів, що трохи
різняться текстом, займали всі 30 місць, і на запит `buffer` пошук повертав один результат замість п'яти. З глибиною
120 видача повна на всіх пробних словах. Глибина ж задає довжину списків, які зливаються з двох способів пошуку, тож
`max_per_doc` 1 з нею давало «як модель» 7 із 10: розділи `configuration/workspaces` десятків команд npm є в обох
списках і витісняли саму сторінку `workspaces`. З 2 — 10 із 10.

**Що пропускає пошук своїми словами.** Питання «кілька пакетів в одному репозиторії» (workspaces): ні по словах, ні за
змістом. З назвою (`npm workspaces`), як велить промпт, пошук знаходить потрібне.

**Версія у відповіді.** Довідник API несе мажор Node («24», «12»); файл, однаковий у кількох мажорах, — один документ
з усіма. Посібники nodejs.org — «learn». Сторінки CLI npm — «npm-» і мажор npm («npm-11», «npm-6»): префікс не дає
сплутати npm 12 з Node 12. Посібники docs.npmjs.com — «docs». Без названої версії відповідь — для Node.js 24 (чинна
лінія Active LTS) і npm 11 (іде з Node 24 і має 44% завантажень npm за тиждень на 06.10.2026); з якої версії щось є чи
як змінилося — кажуть рядки «Added in» і «History» довідника.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження); `.mcp.json` — запис
  HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df nodejs <крок>`.

Білий список — три хости: `api.github.com`, `raw.githubusercontent.com` і `nodejs.org` (лише `dist/index.json`), і

nodejs.org/learn, npm — на docs.npmjs.com.

Особливості, які варто знати:

- **Історія API.** Довідник Node записує, з якої версії функція є, коли застаріла і що в ній мінялося, у прихованих
  блоках `<!-- YAML … -->`. Разом з іншими коментарями HTML вони зникали б, і примірник не знав би версій. Читач
  `ghdocs-history` дістав поле `yaml_history`: такі блоки стають видимим текстом «Added in: v0.1.29.» і «History:» зі
  списком змін за версіями. YAML розбирає PyYAML, що приходить разом із fastembed.
- **Адреса свого мажору.** У полі `site` читача тепер можна писати `{version}` — мітку найновішого тегу, де файл був
  саме таким: документ із Node 22 веде на `latest-v22.x`, а не на найновішу документацію.
- **Розклад — з офіційних файлів, не з правил.** Читач `node-releases` лише переписує дати з `schedule.json` (початок,
  Active LTS, Maintenance, End-of-life, кодове ім'я) і з `index.json` (дата, версії npm, V8, libuv, OpenSSL, прапорець
  безпекового релізу). Висновків на кшталт «непарні мажори не стають LTS» він не робить: розклад змінюється (Node 27
  уже має фазу Alpha). Документ лінії має версію-мажор («22», «0.12»), огляд всіх ліній — «releases».
- **Журнал змін без переліку комітів.** `changelog-node` бере заголовок релізу й усе до розділу `Commits`: Notable
  Changes, а в безпекових релізах — CVE і вражені лінії. Виправлення, що є лише в переліку комітів, тут немає.
- **Версії npm окремо від Node.** Журнали npm несуть «npm-11.0.0» (поле `version_prefix`), інакше `11.6.2` потрапляла
  б у лінію Node 11. Те саме — undici: «undici-8».
- **Склейка `all.md`** — уся документація одним файлом — не береться: вона повторила б кожен розділ.
- **Сайт npm адресує посібники плоско** — за останнім сегментом шляху (`docs.npmjs.com/about-audit-reports`), а CLI —
  з версією (`docs.npmjs.com/cli/v11/commands/npm-ci`). Юридичні правила, оплата й Enterprise не беруться.

## Межі, про які треба пам'ятати

Тут немає довідника API Node до 10 (розклад і перелік релізів 0.x і 4–9 є), переліку комітів у журналах змін,
вбудованих у Node бібліотек (libuv, OpenSSL, ICU, c-ares, llhttp, nghttp2 — їхні примірники ще попереду; V8 —
примірник `v8`), блогу nodejs.org поза розділами про безпеку, мажори й розклад, образів Docker `node`, інших
рантаймів (Deno, Bun) і менеджерів пакетів (pnpm, Yarn), а також фреймворків на Node — вони в своїх примірниках
(`express`, `nestjs`, `nextjs`, `socketio`).

## Екосистема: піднімати разом

Цей примірник **неповний сам по собі**: Node.js зібраний із компонентів, і кожен має власний примірник і власний сервер.
Питання, що йде нижче за API Node.js (чому цикл подій так упорядковує фази, що значить `ERR_OSSL_EVP_UNSUPPORTED`, як
`dns.resolve` ходить у c-ares, чим `http2` зобов'язаний nghttp2), належать їм. Тому `nodejs` завжди піднімають і додають у
Claude Code разом із ними:

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `nodejs` | `nodejs-docs` | 8796 | API Node.js, npm, розклад і склад релізів |
| `v8` | `v8-docs` | 8773 | рушій JavaScript |
| `libuv` | `libuv-docs` | 8838 | цикл подій, пул потоків, ввід-вивід |
| `openssl` | `openssl-docs` | 8839 | `crypto`, `tls`, сертифікати |
| `icu` | `icu-docs` | 8840 | `Intl`, нормалізація, часові пояси |
| `cares` | `cares-docs` | 8841 | `dns.resolve*` |
| `llhttp` | `llhttp-docs` | 8842 | парсер HTTP/1.x |
| `nghttp2` | `nghttp2-docs` | 8843 | `http2` |

Як це відмічено в самому примірнику: `.mcp.json` цієї теки перелічує всі вісім серверів; `prompts/loaded.txt` і
`prompts/search.txt` кажуть моделі, що набір неповний, які сервери його доповнюють і що казати, коли котрогось немає
(це бачить кожен клієнт, що підключився до `nodejs-docs`). Новий компонент екосистеми Node додають у всі три місця.
Те саме відмічено дзеркально в кожному складнику (розділ «Родина Node: піднімати разом», `.mcp.json` з усіма вісьмома
серверами, речення в `prompts/loaded.txt`), а перелік усіх родин — у розділі «Родини примірників» кореневого
[README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку, як у express: у `corpus/` лежить лише паспорт `index.json`, а сервер
підіймається з кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає
повний текст кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/nodejs-corpus-2026-10-14.tar.gz` (61 МБ, 2 784 тексти, паспорт і
сховище сирого `raw/`; перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде.
Архів лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/nodejs/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/nodejs-corpus-РРРР-ММ-ДД.tar.gz -C instances/nodejs corpus raw
find instances/nodejs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/nodejs/raw
gzip -9 -c instances/nodejs/index/passages.json > instances/nodejs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/nodejs-corpus-2026-10-14.tar.gz -C instances/nodejs
./df nodejs smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/nodejs/index/passages.json.gz`,
далі `./df nodejs vectors` заллє колекцію Qdrant (близько години і чверті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df nodejs …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/nodejs/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

```
./df nodejs sources --why   # перелік джерел і білий список
./df nodejs refresh         # завантажити все задеклароване (~30 хвилин)
./df nodejs manifest        # оновити паспорт
./df nodejs setup           # Qdrant чи пошук лише по словах
./df nodejs vectors         # залити корпус у docs-nodejs (~57 хвилин)
./df nodejs smoke           # перевірки
```

Без `GITHUB_TOKEN` у `.env` анонімного ліміту GitHub API (60 звернень на годину) вистачає: дерев тут лише 18, а тексти
йдуть з raw.githubusercontent.com, що до ліміту не рахується. Обірваний `refresh` продовжується з `--missing`.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df nodejs serve           # порт 8796
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8796/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user nodejs-docs http://127.0.0.1:8796/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `nodejs-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
