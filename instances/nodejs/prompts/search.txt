Search the documentation of Node.js and npm, in English: the Node.js API reference of the even
major versions 26, 24, 22, 20, 18, 16, 14 and 12 -- every module (fs and fs/promises, path,
stream, events, http, https, http2, net, dns, url, buffer, process, child_process,
worker_threads, cluster, os, crypto, zlib, readline, timers, util, async_hooks and
AsyncLocalStorage, diagnostics_channel, perf_hooks, vm, the test runner node:test, sqlite),
CommonJS and ECMAScript modules, packages and the "exports" field, the command-line options and
environment variables, globals, errors and their codes, deprecations, with the history of every
function (when it was added, deprecated or changed); the guides of nodejs.org/learn (getting
started, the event loop, timers and process.nextTick, blocking versus non-blocking, files, the
command line, modules, HTTP, TypeScript, the test runner, diagnostics and profiling, Node-API,
migrations); the npm CLI documentation of npm 12, 11, 10, 9, 8, 7 and 6 -- every command (npm
install, npm ci, npm run, npm exec and npx, npm publish, npm version, npm audit, npm outdated,
npm update, npm link, npm pack and the rest), package.json, package-lock.json and
npm-shrinkwrap.json, .npmrc, folders, scripts and lifecycle hooks, workspaces, config, the
registry, dependency selectors; and the guides of docs.npmjs.com (creating and publishing
packages, scoped packages, dist-tags, semantic versioning, audit reports, two-factor
authentication, access tokens, provenance and trusted publishing, organizations and teams).
Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about running JavaScript on the server or on the command line with
Node.js: reading and writing files, streams and backpressure, the event loop, timers, child
processes and worker threads, HTTP servers and clients, environment variables, modules and
package.json, errors, debugging -- and when it is about npm: installing, updating and auditing
dependencies, npm ci in CI, scripts, workspaces, semver ranges, publishing a package, the
lockfile. Example query: "fs.readFile encoding option".

Do not call this for frameworks built on Node.js (Express, NestJS, Next.js, socket.io have their
own instances), for TypeScript itself, for browser APIs (MDN has its own instance), for other
runtimes (Deno, Bun) or other package managers (pnpm, Yarn): their documentation is not here,
and the search will return Node.js excerpts that merely mention them, with confident-looking
titles.

`version` narrows the search. The Node.js API reference carries its major version ("24", "22",
"12"); one text that stayed the same across majors is one document with all of them. The
nodejs.org/learn guides carry "learn". The npm CLI pages carry "npm-" and the npm major
("npm-11", "npm-10", "npm-6") -- the prefix keeps them apart from the Node.js majors; the
docs.npmjs.com guides carry "docs". Leave `version` empty to search everything. Every excerpt
comes back with `versions`: each version whose documents contain this exact text, newest first
-- text that stayed the same across versions is returned once, with all of them listed.

Which version to answer for. Unless the user names a version, answer for Node.js 24 (the active
LTS line) and for npm 11 (the npm shipped with Node.js 24 and the most downloaded one). Mention
another version only when the user names it, or when the question is since which version
something exists or how it changed -- then the "Added in" and "History" lines of the API
reference say exactly that, version by version: quote them.

Where the documentation lives. API pages are named by their file (doc-api-fs,
doc-api-stream, doc-api-worker-threads, doc-api-esm, doc-api-packages, doc-api-cli,
doc-api-errors, doc-api-deprecations); guides by their path
(pages-asynchronous-work-event-loop-timers-and-nexttick); npm CLI pages by version and path
(content-cli-v11-commands-npm-ci, content-cli-v11-configuring-npm-package-json,
content-cli-v11-using-npm-scripts); npm guides by their path
(content-packages-and-modules-securing-your-code-about-audit-reports).

Write the query in English, with the names the documentation uses (fs.readFile,
fs.promises.readFile, fs.createReadStream, stream.pipeline, Readable, Writable, backpressure,
EventEmitter, process.nextTick, setImmediate, queueMicrotask, worker_threads Worker,
child_process.spawn, exec, http.createServer, AbortController, AsyncLocalStorage, node:test,
--watch, --env-file, process.env, require, import, "exports", "type": "module", ERR_REQUIRE_ESM,
DEP0005, npm ci, package-lock.json, devDependencies, peerDependencies, overrides, engines,
scripts prepare postinstall, npm run, npx, workspaces, npm audit fix, semver caret tilde,
.npmrc registry, npm publish --access public, dist-tag). Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin
letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into Node.js and npm terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Answer in the language the user wrote in. When the question is about a change between versions,
a deprecation or a migration, answer point by point: since which version; what changed; what
the migration requires; how it stands now -- each point with the document it rests on; a point
the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as
a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the
Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "потік", "подія", "залежність",
"пакет", "скрипт", "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація Node.js" or "документація npm". Module, function, option, command
and field names stay in English, spelled exactly as the documentation spells them. Build the
answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
