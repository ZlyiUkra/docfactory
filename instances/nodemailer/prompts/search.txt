Search the Nodemailer documentation -- the nodemailer.com site as it stood at every stable
release of the nodemailer npm package, the README, SECURITY.md, CONTRIBUTING.md, TypeScript
declarations, repository examples and changelog of every stable version, and the npm registry
history -- together with the same documents of the companion packages of the Nodemailer project:
mailparser (parses a raw message into headers, text, html and attachments), smtp-server (an SMTP
and LMTP server for receiving mail), and smtp-connection and mailcomposer as standalone packages
(the SMTP client and the message builder; their last releases date from 2017, mailcomposer is
marked unmaintained in the registry). Returns the matching excerpts with the versions each one
belongs to. Nodemailer
sends email from Node.js: createTransport() with the SMTP transport (host, port, secure,
requireTLS, auth, pool, proxy, tls, connection URLs), the sendmail, SES and stream transports,
JSON transport, message fields (from, to, cc, bcc, subject, text, html, attachments and cid
embedded images, alternatives, icalEvent calendar events, headers, list headers, envelope,
DSN, custom source), DKIM signing, OAuth2 and custom authentication, well-known services,
plugins (transporter.use), verify(), createTestAccount() and Ethereal, error codes, and the
extra modules MailComposer, mailparser, smtp-server and smtp-connection as the site describes
them.

Call this when a question is about Nodemailer itself -- the transporter and its options, one
message option, one error code, the way a transport behaves, a guide (Gmail, receiving mail,
testing with Ethereal, Deno) or an example -- and above all history and compatibility: since
which version an option or transport exists, which defaults changed between majors (0.x ->
1 -> 2 -> ... -> 10), and which versions run on which version of Node.js (the `engines` field
of each version is written in the npm registry documents: 0.x-2.x Node 0.6-0.10, 3.x-9.x
Node 6, 10.x Node 20). Example query: "engines node 20". Call it as well for the companion
packages: parsing incoming mail with simpleParser() or MailParser, running an SMTP server with
SMTPServer and its onAuth, onMailFrom, onRcptTo and onData handlers, and their history and Node
requirement (mailparser from 2.0.0 and smtp-server from 2.0.0 declare Node 6; smtp-server 1.x
declares Node 0.12).

Do not call this for Node.js itself, for SMTP or MIME standards, for the documentation of a mail
provider (Gmail, SES, SendGrid) beyond what the Nodemailer site says, or for other mail
libraries: their documentation is not here, and the search will return Nodemailer excerpts that
merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "10" keeps every 10.x document, "6.9" keeps
6.9.x; leave it empty to search everything. The line numbers belong to each package separately:
"3" means Nodemailer 3.x, but also mailparser 3.x and smtp-server 3.x, so for questions about a
companion package leave `version` empty and put the package name into the query. Every excerpt
comes back with `versions`: each
version whose documents contain this exact text, newest first -- text that stayed the same
across versions is returned once, with all of them listed, so the list itself shows from which
to which version the documentation said exactly this.

Write the query in English, with the names Nodemailer itself uses ("createTransport", "sendMail",
"requireTLS", "attachments", "dkim", "xoauth2", "pool"), not in the user's own words. Everything
here is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin
script matches nothing at all and comes back with `found: 0`. When the user asks in another
language, translate the question into Nodemailer terms first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists; what changed in later versions;
what prompted the change, if the excerpts say so; and how it stands in the current version. Every
point names the version and the document it rests on; a point the excerpts do not support is left
out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація Nodemailer". Identifiers, option names and titles stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts
that came back, not out of memory: if an excerpt was cut, read the whole of it before describing
what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see below. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the
query had to appear in the text, so a query phrased in other words than the documentation uses
may miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase
had a chance.

Which version to search first. For a question about how to do something today, pass `version`
"10"; if the user's project is bound to an older Node.js, remember that every line before 10
runs on Node 6 and later, so the line to name is the one the user's project has installed.
Search without `version` when the question is about history, or when the line gave nothing.
Every answer says which version it is for; when the user did not name one, answer for 10.x and
say so ("for Nodemailer 10.x"). When the excerpts behind a statement come only from older
versions, name those versions instead of presenting the text as current.
