# numpy — примірник фабрики docfactory

Цей примірник зібрав документацію бібліотеки NumPy і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. NumPy зберігає числа в багатовимірних масивах однакового типу і рахує над цілими масивами одразу, без циклу Python. На NumPy
стоять pandas, XGBoost, LightGBM і більшість інших бібліотек Python для обчислень.

## Скільки цього

Усього 31 404 документи і 46 713 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Одна сторінка, що
змінювалася між версіями, лежить кількома документами, а однакові розділи пошук зливає й показує з переліком версій.

| Що | Лінії | Документів |
|---|---|---|
| сайт numpy.org: посібник користувача, довідник API, C API, F2PY, нотатки релізів, посібник розробника | 17 ліній 1.16–2.5 | 20 044 |
| старий сайт docs.scipy.org: те саме для старих ліній | 13 ліній 1.3–1.15 | 11 339 |
| записи PyPI | усі стабільні версії | 21 |

Мітка версії має вигляд `numpy-2.5`. Префікс потрібен, щоб версії NumPy не збігалися з версіями інших бібліотек, коли сервери працюють
разом.

**Де є прогалини.** Сторінок, коротших за 20 символів, у корпусі немає. Це 79 сторінок: порожні сторінки-змісти і сторінки атрибутів
без опису, наприклад `numpy.dtype.str` у старих лініях. Лінії, старіші за 1.3, сайт не публікує.

Замір `quality` на 08.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 6 із 10. У `config.json` увімкнено `title_match`: розділ, чия назва-ідентифікатор
(`numpy.searchsorted`) дослівно стоїть у запиті, йде першим. Без цього запит `numpy.searchsorted` повертав десяток коротких сторінок
методів `ndarray.searchsorted`, `recarray.searchsorted` і подібних, а сторінки самої функції серед них не було.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df numpy <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт 1.16–2.5 | `numpy.org/doc/<лінія>/numpy-html.zip` | `sphinx-zip` |
| сайт 1.3–1.15 | `static.scipy.org/doc/numpy-<версія>/numpy-html*.zip` | `sphinx-zip` |
| записи PyPI | `pypi.org/pypi/numpy/json` | `pypi-versions` |

Для цього примірника написано читач `sphinx-zip`. NumPy публікує для кожної лінії весь сайт одним архівом HTML, і архів — одне звернення
замість близько 2 700 сторінок. Обхід сторінок numpy.org віддавав близько 20 сторінок на хвилину, тобто години на кожну лінію. Читач
розбирає сторінки так само, як `sphinx-html`, але ще виправляє три місця: тип параметра, що злипався з назвою («aarray_like»), сигнатуру
старої теми з двох `<code>` і нижній колонтитул старих тем із датою збирання, через який однакова сторінка двох версій ставала двома
документами. Джерела `numpy-docs` і `numpy-docs-old` — одна родина в полі `families`: однаковий розділ обох займає одне місце у видачі.

Нотатки релізів GitHub не беруться окремо: ті самі нотатки є на сайті кожної лінії, у розділі «Release notes».

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df numpy serve
```

Порт — `8956`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user numpy-docs http://127.0.0.1:8956/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `numpy-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/numpy-corpus-2026-11-08.tar.gz` (31 404 тексти, паспорт і сховище сирого `raw/`; перед
видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows `C:\Distr\numpy-corpus-2026-11-08.tar.gz`
(звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/numpy/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/numpy-corpus-РРРР-ММ-ДД.tar.gz -C instances/numpy corpus raw
find instances/numpy/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/numpy/raw
gzip -9 -c instances/numpy/index/passages.json > instances/numpy/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/numpy-corpus-2026-11-08.tar.gz -C instances/numpy
./df numpy smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
