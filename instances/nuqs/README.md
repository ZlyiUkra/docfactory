# nuqs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про nuqs — пакет npm, який тримає стан React у рядку адреси (query
string) з типами: `useQueryState` і `useQueryStates` працюють як `useState`, а значення живе в URL — фільтри, сортування,
сторінка переживають оновлення й копіювання посилання. Парсери, опції, кеш для серверних компонентів і адаптери для
Next.js (app і pages router), React SPA, Remix, React Router v6/v7/v8, TanStack Router і тестів. Документація — усіх
стабільних версій nuqs разом із попередником next-usequerystate. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

Документація Next.js згадує стан в адресі лише через `searchParams` і `useSearchParams`, а nuqs — окремий шар над ними
з власним API, що помітно змінився між 1.x і 2.x (адаптери замість прив'язки до Next.js, `nuqs/server` замість
`nuqs/parsers`, лише ESM). Сайт nuqs.dev показує тільки найновішу версію; тут — усі стабільні поруч.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df nuqs <крок>`.

| Що | Джерело | Читач |

| README обох пакетів | tarball `registry.npmjs.org/<пакет>/-/<пакет>-X.tgz` | `npm-tarball-files` |
| нотатки релізів | API релізів `47ng/nuqs` | `ghreleases` |
| реєстр npm | registry.npmjs.org, одне звернення на пакет | `npm-versions` |

Читач `ghdocs-history-nuqs` додано разом із цим примірником (`engine/readers/ghnuqs.py`). Він бере сайт так само, як
`ghdocs-history`, але перед розбором очищує текст MDX:

- **Сторінки пишуться для двох читачів**: `<HumanContent>` (з іконками й живими демо) і поруч `<LLMContent>` (те саме
  простим текстом для мовних моделей). З такої пари лишається текстова версія, інакше перелік адаптерів чи приклад
  стояв би на сторінці двічі.
- **`<FeatureSupportMatrix introducedInVersion='2.5.0' />`** стає реченням «Introduced in nuqs 2.5.0.» — саме з нього
  видно, з якої версії є можливість.
- **Розмітка підсвічування** (`` `useQueryState{:ts}` ``, `// [!code word:…]`), обгортки демо (`<Suspense
  fallback={…}>`) і багаторядкові імпорти компонентів на початку сторінки знімаються. Речення, що починається словом
  «import» (1.x: «import the parsers from `nuqs/parsers`…»), приєднується до свого абзацу, а не викидається як оператор.

Особливості корпусу:

- **Службові сторінки самого сайту** (`docs/internal/`, дизайн-система) не беруться.
- **До 1.15 сайту немає**: уся документація тих версій — README (обидва пакети).
- **Імена документів сайту** — шлях у репозиторії (`packages-docs-content-docs-adapters`): читач історії тегів кореня
  шляху не знімає.
- **Документ — неповторний текст.** Версії, де файл не змінився, ділять один документ; у рядку `# версія:` стоять усі.

## Межі, про які треба пам'ятати

Документації Next.js, React Router, Remix, TanStack Router, стандарту URL і `URLSearchParams` (вони в примірниках
`nextjs`, `react-router`, `tanstack-router`, `mdn`), zod та інших бібліотек схем тут немає. Код бібліотеки, тести,

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/nuqs-corpus-2026-10-13.tar.gz` (312 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде. Архів
лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/nuqs/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/nuqs-corpus-РРРР-ММ-ДД.tar.gz -C instances/nuqs corpus raw
find instances/nuqs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/nuqs/raw
gzip -9 -c instances/nuqs/index/passages.json > instances/nuqs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/nuqs-corpus-2026-10-13.tar.gz -C instances/nuqs
./df nuqs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/nuqs/index/passages.json.gz`, далі
`./df nuqs vectors` заллє колекцію Qdrant (близько двох хвилин).

## Установка venv

```
cd instances/nuqs
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df nuqs sources --why   # перелік джерел і білий список
./df nuqs refresh         # завантажити все задеклароване (близько 10 хвилин)
./df nuqs manifest        # оновити паспорт
./df nuqs setup           # Qdrant чи пошук лише по словах
./df nuqs vectors         # залити корпус у docs-nuqs
./df nuqs smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df nuqs serve          # порт 8836
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8836/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user nuqs-docs http://127.0.0.1:8836/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `nuqs-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
