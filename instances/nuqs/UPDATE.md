# Оновлення корпусу nuqs

Руками оголошено лише теги репозиторію `47ng/nuqs`: поле `tags` джерела `nuqs-site`. Новий стабільний тег дописують
першим рядком, у вигляді `"v2.11.0": "2.11.0"`. README обох пакетів і реєстр беруться з опису пакетів у реєстрі npm
(`https://registry.npmjs.org/nuqs`, `…/next-usequerystate`), нотатки релізів — з API релізів, тож нові версії там
з'являються самі.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df nuqs check                 # чи змінилося щось нагорі за джерелом
./df nuqs refresh               # повне перезавантаження, близько 10 хвилин
./df nuqs manifest
./df nuqs vectors
./df nuqs smoke
# Ctrl+C у терміналі з serve, і знову: ./df nuqs serve
```

`refresh` повний, не `--missing`: у документі стоять усі версії, де текст був таким, тож новий тег змінює й старі
документи.

Якщо сайт додасть новий компонент MDX, що несе текст (як `FeatureSupportMatrix`), чи змінить пару
`HumanContent`/`LLMContent`, — правка в `engine/readers/ghnuqs.py`, далі `./df nuqs build nuqs-site` без мережі.

Якщо вийшла нова мажорна лінія:

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` переглянути лінію за
  замовчуванням: вона — найпопулярніша за завантаженнями npm (на 13.10.2026 — 2.x, 98,5 %);
- у `checks.json`, у десятці `quality_model`, замінити `"2"` там, де питання про поточну поведінку, і звірити цілі.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) потрібен для дерев 69 тегів і сторінок релізів.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df nuqs quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
