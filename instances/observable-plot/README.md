# observable-plot — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Observable Plot — бібліотеку графіків на основі D3 від команди
Observable (`Plot.plot` і його опції, позначки, канали, шкали, перетворення, фасети, легенди, проєкції, взаємодії
`pointer` і `tip`). Документація — з тегу кожного релізу 0.6.6–0.6.17 і README кожної стабільної версії 0.1–0.6.17.
Джерела — репозиторій observablehq/plot, пакет і реєстр npm, зошити Observable про Plot; лише англійською. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Plot — інша бібліотека, ніж D3, хоч і від тієї ж команди: D3 дає будівельні блоки (шкали, фігури, виділення), а Plot —
готову граматику графіків, де діаграма розсіювання — один виклик `Plot.dot(data, {x, y}).plot()`. Довідник Plot
жив у різних місцях: до 0.6.5 — README пакета, поряд із ним — зошити Observable з поясненнями й прикладами
(`@observablehq/plot-marks`, `plot-scales`…), з 0.6.6 (травень 2023) — сайт observablehq.com/plot з теки `docs/`
репозиторію.

**Що є що.** **Позначка** (mark) — шар графіка, що малює дані геометрією (точки, лінії, стовпці, текст);
**канал** — властивість позначки, прив'язана до поля даних (`x`, `y`, `fill`, `r`); **перетворення** (transform) —
обробка даних перед позначкою (`binX` рахує частоти, `stackY` складає стовпці); **фасет** — розбиття графіка на
малі копії за категорією (`fx`, `fy`).

## Звідки документація

- **Сайт Plot** (VitePress) — читач `ghdocs-history-vue` з тегу кожного релізу 0.6.6–0.6.17. Мінорна лінія одна, тож
  береться кожен реліз, а не лише останній у лінії. Розбір розмітки той самий, що для vuejs.org і d3js.org:
  контейнери, `<script setup>` і живі графіки знімаються.
- **README** — `npm-readme` з тегу кожної стабільної версії. До 0.6.6 у README був увесь довідник, після — коротка
  заглушка, яку `min_chars` не пропускає.
- **Журнали змін.** Plot ділить журнал за роками. Кожен файл читає читач `changelog`, і кожен реліз стає окремим
  документом.
- **Зошити Observable** — читач `observable-collections` з полем `collections: "^plot"`. Беруться лише збірки Plot
  власника @observablehq: давня документація в зошитах, приклади, шпаргалки, курс, «Plot for matplotlib users». У
  `within` названо авторів @observablehq і @fil (Philippe Rivière, супровідник Plot). Зошити інших авторів у цих
  збірках не беруться.

## Межі, про які треба пам'ятати

## Родина D3: піднімати разом

Цей примірник — частина родини D3: сама бібліотека D3 і Observable Plot, бібліотека графіків тієї ж команди,
побудована на D3. Plot бере в D3 шкали, фігури, проєкції й формати, тож питання про графік Plot часто закінчується в
модулі D3 — і навпаки. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує обидва
сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `d3` | `d3-docs` | 8933 | D3 3.x–7.9: d3js.org, довідник 3.x, README 42 модулів на кожну версію, зошити Observable команди D3 |
| `observable-plot` | `observable-plot-docs` | 8934 | Observable Plot 0.1–0.6.17: сайт Plot з тегу кожного релізу 0.6, README, журнали, зошити про Plot |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
кореневому README.md, розділ «Родини примірників».

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/observable-plot-corpus-2026-10-29.tar.gz` (тексти, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\observable-plot-corpus-2026-10-29.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git
текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/observable-plot/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/observable-plot-corpus-РРРР-ММ-ДД.tar.gz -C instances/observable-plot corpus raw
find instances/observable-plot/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/observable-plot/raw
gzip -9 -c instances/observable-plot/index/passages.json > instances/observable-plot/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/observable-plot-corpus-2026-10-29.tar.gz -C instances/observable-plot
./df observable-plot smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати:
`gunzip -k instances/observable-plot/index/passages.json.gz`, далі `./df observable-plot vectors` заллє колекцію
Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df observable-plot …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище». Свій `.env` примірник тримає в `instances/observable-plot/.env` (`cp .env.example .env`; для
кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df observable-plot sources --why      # перелік джерел і білий список
./df observable-plot refresh            # усе: близько 4 хвилин мережею (паузи 0,1 с)
./df observable-plot manifest           # оновити паспорт
./df observable-plot setup              # Qdrant чи пошук лише по словах
./df observable-plot vectors            # залити корпус у docs-observable-plot
./df observable-plot smoke              # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df observable-plot serve     # порт 8934
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8934/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user observable-plot-docs http://127.0.0.1:8934/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `observable-plot-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
