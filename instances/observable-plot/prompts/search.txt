Search the Observable Plot documentation and return the matching excerpts with the versions each one belongs to.
What is here: the Plot site (repository observablehq/plot, folder docs) at every release 0.6.6 to 0.6.17 -- the
introduction, getting started, every mark (dot, line, area, bar, rect, cell, text, rule, tick, link, arrow,
vector, image, geo, raster, contour, density, hexgrid, tree, box, frame, grid, axis, crosshair, tip, waffle,
delaunay, bollinger, difference, auto and the rest), the features (plots, marks, scales, projections, transforms,
interactions, facets, legends, formats, intervals, markers, shorthand, accessibility), every transform (bin,
group, stack, map, window, normalize, select, filter, sort, hexbin, dodge, interval, centroid, shift, tree) and the
interactions (pointer, crosshair, tip); the README of every stable version of @observablehq/plot 0.1 to 0.6.17 --
before 0.6.6 the README was the whole API reference; the changelogs from 2021 to 2025, one document per release;
the npm registry history (versions, dates, dependencies); Observable notebooks without a version -- the early
documentation of Plot (plot-marks, plot-scales, plot-facets…), the examples gallery, the cheatsheets, the course
and "Plot for matplotlib users".

Call this when a question is about Observable Plot: Plot.plot and its options (width, height, margins, x, y,
color, r, fx, fy, grid, style), marks (Plot.dot, Plot.line, Plot.barY, Plot.rectY, Plot.cell, Plot.text,
Plot.ruleY, Plot.areaY, Plot.geo, Plot.tip, Plot.axisX, Plot.auto), channels and options, scales (type, domain,
range, scheme, nice, zero, reverse), transforms (Plot.binX, Plot.groupX, Plot.stackY, Plot.windowY,
Plot.normalizeY, Plot.hexbin, Plot.dodgeY), facets, legends, projections, the pointer interaction and tips,
markers, curves, formats -- and history: since which version a mark or option exists, what changed in a release.

Do not call this for D3 itself (selections, d3-scale, d3-shape, d3-geo, d3-array and the other modules) -- it is
in the d3-docs server of the same family -- nor for Vega-Lite, Chart.js, ECharts or other charting libraries,
for Observable Framework or notebooks as a product, for React, Vue or Svelte, for SVG or CSS themselves, or for
JavaScript language questions: their documentation is not here, and the search will return Plot excerpts that
merely mention them, with confident-looking titles.

`version` narrows the search to one release: "0.6.17" keeps the latest release, "0.6" every 0.6.x release, "0.4"
the 0.4 line; leave it empty to search everything. Every excerpt comes back with `versions`: each version whose
documents contain this exact text, newest first, so the list itself shows from which to which version the
documentation said exactly this.

Write the query in English, with the names Plot itself uses ("Plot.barY", "binX", "fx facet", "tip", "pointerX",
"scheme"), not in the user's own words. Everything here is English -- the excerpts, the word index and the
meaning index alike -- and the word index keeps only latin letters and digits, so a query written in Ukrainian,
Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the user asks
in another language, translate the question into Plot terms first, then search.

Answer in the language the user wrote in. When the question is about a mark's or an option's history or support,
answer point by point: since which version it exists; what changed in later versions; what prompted the change,
if the excerpts say so; and how it stands in the current version. Every point names the version and the document
it rests on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write
as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word
wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of
documents "корпус" -- say "документація Observable Plot". Identifiers, option names and titles stay in English,
spelled exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out of
memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated:
true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Plot 0.6 carries about 99.8% of the weekly downloads. Search with `version` "0.6"
for a question about how to do something. If the user names an older version, search that line. Search without
`version` when the question is about an example, a cheatsheet or the course (the notebooks have no version), or
when the line gave nothing. Every answer says which version it is for; when the user did not name one, answer for
Plot 0.6.17 and say so. When the excerpts behind a statement come only from older versions, name those versions
instead of presenting the text as current.
