# ollama — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Ollama — локальний запуск великих мовних моделей (і хмару Ollama)
з HTTP API на порту 11434, CLI, форматом Modelfile та офіційними клієнтами для JavaScript і Python. Документація —
сайт docs.ollama.com цілком (можливості, CLI, Modelfile, довжина контексту, Linux/macOS/Windows/Docker, підтримка GPU,
FAQ зі змінними сервера, інтеграції, довідник API з полями кожного ендпоінта, сумісність з OpenAI й Anthropic), а для
кожного стабільного випуску ollama/ollama v0.0.1–v0.40.6 — тека `docs/`, README, код Go `api/` і `envconfig/` з тестами
і нотатки релізів; для кожного стабільного випуску клієнтів ollama-js і ollama-python — код, тести, приклади, релізи,
README з npm і PyPI. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі
дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Ollama випускає нову версію щотижня-два, і API за цей час помітно змінився: `format` прийняв JSON-схему (0.5),
з'явилися `think`, `logprobs`, `/api/embed` замість `/api/embeddings`, хмарні моделі, сумісність з Anthropic; типова
довжина контексту `num_ctx` виросла з 2048 до 4096 (0.6.7). Сайт показує лише поточний стан, а на машинах живуть різні
версії. Тут
кожен випуск — окремою редакцією: відповідь «чи приймає `/api/chat` поле `think` у 0.6» береться з документації й коду
0.6, а не з пам'яті. Змінні середовища сервера (`OLLAMA_HOST`, `OLLAMA_KEEP_ALIVE`, `OLLAMA_CONTEXT_LENGTH`,
`OLLAMA_NUM_PARALLEL`…) описано і у FAQ, і в коді `envconfig/config.go` з типовими значеннями — тут є обидва.

## Що в цій теці

- `corpus/` — паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа. Самих текстів тут немає:
  корпус в архіві.
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`.
- `sources.json` — звідки корпус будується (12 джерел), і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, профіль домену, родина сайту й теки `docs/`.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — токен GitHub і, для кроку `ask`, ключ Anthropic; `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики через `./df ollama <крок>`.

## Звідки документація

| Що | Читач |
|----|-------|
| сайт docs.ollama.com | `sitemap-mintlify` (сторінки ендпоінтів розгорнуто з OpenAPI в поля запиту й відповіді) |
| тека `docs/`, README | `ghdocs-history` |
| код Go, код і тести ollama-python | `ghcode-history`, поле `outline` переліком мов (`["go"]`, `["python"]`) |
| код і тести ollama-js | `ghcode-history-ts` |
| нотатки релізів | `ghreleases-stable` |
| npm: таблиця версій і README | `npm-versions`, `npm-tarball-files` |
| PyPI: таблиця версій і опис | `pypi-versions` |

Новий код для ollama — лише поділ файлів Go й Python на розділи в `ghcode-history`. Раніше читач ділив JavaScript,
Solidity і заголовки C, а файл Go чи Python лягав одним фрагментом: `api/types.go` (44 тисячі символів — структура
`Options` з `num_ctx` і `num_predict`, запити й відповіді всіх ендпоінтів) і `ollama/_client.py` (41 тисяча) вектор
бачив би лише з імпортів. Тепер розділ — кожне оголошення верхнього рівня Go (функція, метод, тип, блок `var`/`const`
з переліком імен) разом з коментарем над ним, у Python — клас, функція, метод класу (перевантаження `@overload` —
один розділ). Поділ вмикається переліком мов, а не `outline: true`: `true` уже стоїть у джерелі redis, що бере `.py`,
і звірений примірник не змінився.

Особливості:

- **Сайт і тека `docs/` — одна родина.** З 0.13 сайт збирається з `docs/*.mdx` того самого репозиторію, тож чинна
  сторінка FAQ приходила двічі — з сайту (`faq`) і з теки (`docs-faq`) — і забирала два місця з п'яти. `slug_rewrite`
  `^docs-` → `` дає редакціям теки ключі сторінок сайту, `families` `{"docs": ["site", "docs"]}` згортає їх в одне
  місце видачі. Однакові тексти злилися (6 012 → 5 693 фрагменти); замір піднявся з 6 до 9, далі — `fusion_depth`.
- **Мітки версій.** Сервер — числом (`0.40.6`), клієнти — з назвою пакета (`ollama-js-0.6.4`, `ollama-python-0.6.3`):
  обидва клієнти мають власну нумерацію 0.x, і без мітки `version: "0.6"` змішав би Ollama 0.6 з ollama-js 0.6. Лінії
  мінорні (`version_line_depth: 2`): 0.0, 0.1, …, 0.40, ollama-js-0.6, ollama-python-0.5. Сторінки сайту версій не мають.
- **Імена документів.** Сайт і тека — шлях сторінки (`faq`, `api-chat`, `capabilities-thinking`, `api` — старий
  довідник `api.md`); README — `ollama-readme`; код — `api-types-go`, `envconfig-config-go`,
  `ollama-python-ollama-client-py`, `ollama-js-src-browser-ts`; релізи — `ollama-v0.40.5`, `ollama-js-v0.6.4`.
- **Старий довідник API.** `docs/api.md` (54 КБ, приклади кожного ендпоінта: завантаження й вивантаження моделі,
  JSON mode, опції, відтворювані відповіді) досі лежить у репозиторії з приміткою «API docs are moving to
  docs.ollama.com/api»; на сайті його немає, тут він є в усіх редакціях.
- **Запити `quality`** записано так, як їх ставить модель за промптом: назва з документації, далі опис
  («keep_alive: keep a model loaded in memory longer…»). Цілі — сторінки, які знаюча людина прийняла б як відповідь;
  крім очевидних, це розділ README «Customize a prompt» (Modelfile з `PARAMETER temperature` і `SYSTEM`) і метод
  `abort()` у коді ollama-js.

## Межі, про які треба пам'ятати

- Лише стабільні випуски: 439 передрелізних і службових тегів ollama/ollama (432 rc, 7 ci) не взято.
- Сторінки моделей на ollama.com/library (що вміє модель, її шаблон, ліцензія) — не документація Ollama, сюди не
  взято. Так само llama.cpp, на якому Ollama стоїть.
- Код Go — лише `api/` і `envconfig/`: сервер (`server/`, `llm/`, `ml/`) не взято. Тека `envconfig/` з'явилася в
  0.1.39; для старіших версій змінні середовища дає лише FAQ.
- `docs/openapi.yaml` окремо не взято: чинну специфікацію сайт розгортає в сторінки ендпоінтів, а для старих версій
  довідник — `api.md`.

## Архівний режим: сервер без корпусу

Корпус в архіві від самого початку: у `corpus/` лежить лише паспорт, а сервер підіймається з кешу фрагментів і
колекції Qdrant; відповіді ті самі до символа.

**Де тексти.** В архіві `~/archives/docfactory/ollama-corpus-2026-10-17.tar.gz` (22 МБ: 1 710 текстів, паспорт і
сховище сирого `raw/`; перед видаленням розпакований окремо й звірений з диском — нуль розбіжностей). Лише на цій
машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
tar -czf ~/archives/docfactory/ollama-corpus-РРРР-ММ-ДД.tar.gz -C instances/ollama corpus raw
find instances/ollama/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/ollama/raw
gzip -9 -c instances/ollama/index/passages.json > instances/ollama/index/passages.json.gz
```

**Як повернути тексти** — перед будь-яким оновленням:

```
tar -xzf ~/archives/docfactory/ollama-corpus-2026-10-17.tar.gz -C instances/ollama
./df ollama smoke
```

**Оновлення.** Новий випуск Ollama дописують першим рядком у `tags` джерел `docs`, `readme`, `code`
(«"v0.40.7": "0.40.7"»), випуск клієнта — у `js-code` («"v0.6.5": "ollama-js-0.6.5"») чи `py-code`; сайт, релізи,
npm і PyPI підхоплюються самі. Далі `./df ollama refresh`, `manifest`, `vectors`, `smoke`, `quality`.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df ollama …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/ollama/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають. Для роботи сервера збирати нічого не
треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df ollama sources --why   # перелік джерел і білий список
./df ollama refresh         # завантажити все задеклароване (близько 10 хвилин)
./df ollama manifest        # оновити паспорт
./df ollama setup           # Qdrant чи пошук лише по словах
./df ollama vectors         # залити корпус у docs-ollama (близько 12 хвилин)
./df ollama smoke           # перевірки
```

Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df ollama serve          # порт 8854
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8854/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user ollama-docs http://127.0.0.1:8854/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User).

**3. Перевірити.** `/mcp` — має бути `ollama-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера.
