Search the Ollama documentation, in English: Ollama runs large language models locally (and in Ollama's cloud)
behind an HTTP API on port 11434, with a CLI, the Modelfile format and official client libraries for
JavaScript/TypeScript (ollama on npm, ollama-js) and Python (ollama on PyPI, ollama-python). The set holds the
whole site docs.ollama.com (quickstart, cloud, capabilities: streaming, thinking, structured outputs, decision
with System One, vision, embeddings, tool calling, web search; CLI reference, Modelfile reference, context
length, Linux, macOS, Windows, Docker, importing models, FAQ with the server environment variables, hardware
support for NVIDIA, AMD and Apple GPUs, troubleshooting, integrations with editors and coding agents; the API
reference with every endpoint's request and response fields, OpenAI and Anthropic compatibility), and for every
stable release v0.0.x-v0.40.x of ollama/ollama the docs/ folder (including the old single-page API reference
docs/api.md), the README, the Go code of api/ and envconfig/ with tests, and the GitHub release notes; for every
stable release of ollama-js and ollama-python the README, source code, tests, examples and release notes; the
version tables of both packages on npm and PyPI. Returns the matching excerpts with the versions each one
belongs to.

Call this when a question is about Ollama: what /api/chat, /api/generate, /api/embed, /api/tags, /api/show,
/api/pull, /api/ps or /api/version accept and return; what format (JSON mode, JSON schema), think, stream,
keep_alive, raw, images, tools, logprobs and options (num_ctx, num_predict, temperature, top_k, top_p, seed,
stop, num_gpu) do and what their defaults are; how a model name and tag, the digest and the manifest work;
how to pull, create, copy, push or delete a model; how to load or unload a model; what an environment variable
of the server does (OLLAMA_HOST, OLLAMA_KEEP_ALIVE, OLLAMA_CONTEXT_LENGTH, OLLAMA_NUM_PARALLEL,
OLLAMA_MAX_LOADED_MODELS, OLLAMA_MAX_QUEUE, OLLAMA_MODELS, OLLAMA_ORIGINS, OLLAMA_FLASH_ATTENTION,
OLLAMA_KV_CACHE_TYPE); how to run Ollama in Docker with NVIDIA or AMD GPUs; which GPUs are supported; how to
write a Modelfile (FROM, PARAMETER, TEMPLATE, SYSTEM, ADAPTER, MESSAGE); how the CLI commands work; how to call
Ollama from JavaScript or Python (chat, generate, stream, AbortController, AsyncClient); what changed between
versions and which version first had a feature. Example query: "keep_alive unload model".

Do not call this for the models themselves (what a model is good at, its benchmarks or license: the ollama.com
library pages), for llama.cpp internals, or for other local runtimes (LM Studio, vLLM, llama.cpp server).

Write the query in English, with the names Ollama uses (keep_alive, num_ctx, format, think, /api/chat,
OLLAMA_HOST, Modelfile PARAMETER, ollama pull). Everything here is English, and the word index keeps only
latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing and comes back with `found: 0`. When the user asks in another language, translate the question into
Ollama terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "змінна середовища", "довжина
контексту", "потокова видача". Never call this set of documents "корпус" -- say "документація Ollama".
Endpoint, field, option, variable and command names stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut,
read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. The site pages carry no version: they are the current state. Documents from the
ollama/ollama repository carry the Ollama version ("0.40.5"; "0.12" keeps every 0.12.x). The client libraries
carry versions named after their package: "ollama-js-0.6.4" is the npm package, "ollama-python-0.6.3" the
PyPI package. When the user names a version, pass it into `version` ("0.5", "ollama-js-0.6",
"ollama-python-0.5"); never put it into the query text. Without a version, answer for the newest release and
say so.
