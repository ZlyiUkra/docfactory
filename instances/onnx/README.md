# onnx — примірник фабрики docfactory

Цей примірник зібрав документацію формату ONNX і інструментів навколо нього та віддає її через сервер MCP, щоб модель відповідала з
текстів, а не з пам'яті. ONNX (Open Neural Network Exchange) — це спільний формат файла для навченої моделі машинного навчання. Модель
навчають в одній бібліотеці (LightGBM, XGBoost, scikit-learn, PyTorch), зберігають у файл `.onnx`, а виконують в іншій програмі, яка
про ту бібліотеку нічого не знає. Модель у файлі — це граф операторів: кожен вузол графа виконує одну дію (додати, порівняти, пройти
ансамбль дерев), а набір операторів однієї редакції стандарту називають opset.

Примірник зібрано під проєкт торгового робота для валютних пар. Модель там навчають у Python, а торгує робот у MetaTrader 5, який
вміє виконувати файли ONNX (функції `OnnxCreate` і `OnnxRun` описано в примірнику `mql5`). Щоб модель на деревах потрапила в робот,
її треба перетворити на ONNX і перевірити, що перетворена модель дає ті самі ймовірності. Тут лежить усе для цього шляху:

- **onnx** — сам формат: поняття, версії opset і IR, сторінка на кожен оператор з усіма його редакціями. Серед них оператори ONNX-ML
  `TreeEnsembleClassifier`, `TreeEnsembleRegressor` і `ZipMap`, якими записується модель на деревах.
- **ONNX Runtime** — програма, що виконує файли ONNX: встановлення, сумісність версій opset, продуктивність, довідник Python API
  (`InferenceSession`, `SessionOptions`, провайдери).
- **skl2onnx** — перетворювач моделей scikit-learn; у ньому ж реєструють перетворювачі LightGBM і XGBoost, коли модель стоїть у
  конвеєрі, і вимикають `zipmap`, щоб ймовірності виходили масивом, а не переліком словників.
- **onnxmltools** — перетворювачі LightGBM, XGBoost та інших бібліотек (`convert_lightgbm`, `convert_xgboost`).

Мітки версій мають префікс бібліотеки: `onnx-1.23`, `onnxruntime-1.32`, `skl2onnx-1.20`, `onnxmltools-1.16`.

**Чому лише поточні версії сайтів.** Сайти onnx.ai і onnxruntime.ai публікують тільки поточну редакцію. Старші версії видно з
нотаток релізів і журналів змін: там записано, який opset увів кожен випуск ONNX і що змінилося в перетворювачах. Сторінка оператора
сама показує всі його редакції по opset.

**Чого не беру.** Сторінки сайту onnx.ai/onnx з порівнянням редакцій оператора рядок за рядком (`text_diff_*`) і копії великих файлів
`Operators.md` і `Changelog.md`: той самий зміст уже лежить на сторінках операторів. На сайті ONNX Runtime — сторінки про мобільні
застосунки, вебверсію, C#, Java, генеративні моделі й збирання з джерел: проєкт запускає модель із Python і в MetaTrader 5. Сайт
onnx.ai/onnxmltools — порожня оболонка без посилань на сторінки (перевірено 13.11.2026), тому приклади й опис функцій onnxmltools
взято з репозиторію.

**Чого ще немає.** Записів PyPI пакетів `onnx`, `onnxruntime`, `skl2onnx` і `onnxmltools`. Їх оголошено в `sources.json`, але
13.11.2026 pypi.org з WSL відповідав лише на половину запитів. Як їх дозбирати, описано в [UPDATE.md](UPDATE.md).

Замір `quality` на 13.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, запити своїми словами — 8 із
10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df onnx <крок>`.

`skl2onnx-`), і сторінки різних бібліотек не ділять один ключ розділу.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df onnx serve
```

Порт — `8977`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user onnx-docs http://127.0.0.1:8977/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `onnx-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/onnx-corpus-2026-11-13.tar.gz` (тексти, паспорт і сховище сирого `raw/`; перед
видаленням текстів архів звірено з диском) і в копії на диску Windows `C:\Distr\onnx-corpus-2026-11-13.tar.gz` (звірено за SHA-256).
В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/onnx/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/onnx-corpus-РРРР-ММ-ДД.tar.gz -C instances/onnx corpus raw
find instances/onnx/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/onnx/raw
gzip -9 -c instances/onnx/index/passages.json > instances/onnx/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів (і його копію в `C:\Distr`), а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/onnx-corpus-2026-11-13.tar.gz -C instances/onnx
./df onnx smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
