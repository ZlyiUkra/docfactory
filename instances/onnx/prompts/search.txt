Search the documentation of ONNX, the open format for trained machine learning models, and of the tools that convert a
model into it and run it. The corpus holds: the onnx.ai/onnx site of ONNX 1.23 (the concepts, the IR and versioning,
one page per operator with every version of it, including the ONNX-ML operators TreeEnsembleClassifier,
TreeEnsembleRegressor and ZipMap, and the Python API: helper, checker, shape inference, version converter); the GitHub
release notes of every ONNX release with the opset and IR version each one introduced; the onnxruntime.ai/docs site
(install, the Python start page, ONNX opset and platform compatibility, performance tuning, quantization, the CPU and
CUDA execution providers) and the ONNX Runtime Python API reference (InferenceSession, SessionOptions, RunOptions,
providers, IOBinding, model metadata); the release notes of every stable ONNX Runtime release; the onnx.ai/sklearn-onnx
site of skl2onnx (convert_sklearn and to_onnx, converter options such as zipmap, registering the LightGBM and XGBoost
converters inside a pipeline, comparing the converted predictions) and its change log; the onnxmltools examples and the
functions convert_lightgbm and convert_xgboost with their docstrings, its README and change log.

Use this tool for: converting a LightGBM, XGBoost or scikit-learn model to ONNX, choosing `target_opset`, getting
probabilities as an array (`zipmap=False`), declaring inputs (`FloatTensorType`), checking that the converted model gives
the same predictions, loading and running a model with `onnxruntime.InferenceSession`, which opset a given ONNX Runtime
version supports, and what an operator does in a given opset. Write the query in English with the name of the function,
class, option or operator, such as `convert_lightgbm`, `zipmap`, `InferenceSession` or `TreeEnsembleClassifier`. Give a
version in the filter when the answer depends on it.

Do not use it for running ONNX models inside MetaTrader 5 (OnnxCreate, OnnxRun belong to the MQL5 server), for PyTorch
export (`torch.onnx` belongs to the PyTorch server), or for LightGBM, XGBoost and scikit-learn themselves: other servers
hold them. Returns the matching excerpts with the versions each one applies to, the source address and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. The sites describe the current releases: ONNX 1.23 (`onnx-1.23`), ONNX Runtime 1.32
(`onnxruntime-1.32`), skl2onnx 1.20 (`skl2onnx-1.20`) and onnxmltools 1.16 (`onnxmltools-1.16`); older releases are
known through their release notes and change logs. Search without `version` first. Every answer says which library and
which version it is for: the opset a runtime accepts limits which model files it can load.
