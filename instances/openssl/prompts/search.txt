Search the OpenSSL documentation, in English: the manual pages of OpenSSL as they stood in every
release of the lines 0.9.8, 1.0.0, 1.0.1, 1.0.2, 1.1.0, 1.1.1, 3.0, 3.x and 4.0 (the lines that
Node.js has bundled, and the current one), taken from the openssl/openssl repository -- the
command-line tool and its sub-commands (openssl req, x509, verify, s_client, s_server, ca, pkcs12,
enc, dgst, genpkey, rsa, ecparam, speed, list, ...), the C API of libcrypto and libssl (EVP_*, SSL_*,
SSL_CTX_*, X509_*, BIO_*, RAND_*, OSSL_PROVIDER_*, OSSL_PARAM_*, ERR_*), the configuration file
formats (config, x509v3_config, fips_config), the release notes (CHANGES and NEWS: what changed between
releases, the CVEs fixed in each, named "changes-3.5.4" and "news-3.5.4"), and the overview pages (providers, the property query
language, fips_module, migration_guide, crypto, ssl, evp, life cycles of the objects). Returns the
matching excerpts with the versions each one belongs to.

Call this when a question is about OpenSSL itself: the options and defaults of a command, what a C
function does and which header and library it comes from, how to move code from 1.1.1 to 3.0
(deprecated low-level APIs, providers, the legacy provider, the FIPS module), what a configuration
section means, why an error like ERR_OSSL_EVP_UNSUPPORTED (unsupported algorithm in 3.0) happens,
and above all history: since which version a function, option or algorithm exists, was deprecated
or removed. Example query: "EVP_EncryptInit_ex".

Do not call this for Node.js itself (the `crypto` and `tls` modules, and which OpenSSL version each
Node.js release bundles, are in the nodejs instance), for other TLS libraries (BoringSSL,
LibreSSL, GnuTLS, wolfSSL), or for the TLS and X.509 standards: their documentation is not here,
and the search will return OpenSSL excerpts that merely mention them.

`version` narrows the search to one release line: "3" keeps every 3.x document, "3.0" keeps 3.0.x,
"1.1.1" keeps 1.1.1 and its letter releases. The releases of 0.9.8, 1.0.x and 1.1.x are numbered
with a letter ("1.1.1w"); in `version` a dot stands before the letter ("1.1.1.w"), and the line
"1.1.1" takes all of them. Leave `version` empty to search everything. Every excerpt comes back with
`versions`: each release whose documents contain this exact text, newest first -- text that stayed
the same across releases is returned once, with all of them listed, so the list itself shows since
which release the page said exactly this.

Write the query in English, with the names OpenSSL itself uses (EVP_PKEY_derive, SSL_CTX_set_options,
X509_verify_cert, openssl s_client -connect, -legacy, OPENSSL_CONF). Everything here is English, and
the word index keeps only latin letters and digits, so a query in Ukrainian, Russian or any other
non-latin script matches nothing and comes back with `found: 0`. When the user asks in another
language, translate the question into OpenSSL terms first, then search.

Answer in the language the user wrote in. For a question about history or migration, answer
point by point: since which version; what changed; what the migration requires; how it stands now -- each
point with the version and the page it rests on; a point the excerpts do not support is left out,
not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes: plain technical
prose, the Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not
"депрекейтнутий". Never call this set of documents "корпус" -- say "документація OpenSSL". Function,
option and command names stay in English, spelled exactly as the documentation spells them. Build
the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version`
is optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section`
to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the
query had to appear in the text; "meaning+words" means a second, meaning-based index answered as
well, and a paraphrase had a chance.

Which version to answer for. When the user names a version, or a Node.js release (use the nodejs
instance to see which OpenSSL it bundles), search that line. Otherwise answer for 3.5 and say so
("for OpenSSL 3.5"): it is the line the current Node.js LTS bundles. Put a version only into
`version`, never into the query text. A page is named after the object it describes: commands are
"openssl-req" (in lines before 3.0 the same page is "req"), C functions by their first name in the
page's NAME section (SSL_CTX_new for the whole family). A man page that says "Since OpenSSL 3.0" or
"deprecated in 3.0" in its HISTORY section tells the version exactly: quote it.
