Search the documentation of Optuna, the Python framework for automatic hyperparameter optimization: you write an
objective function that trains a model with parameters suggested by a `trial`, and Optuna searches for the parameters
that give the best score. The corpus holds the optuna.readthedocs.io site of every minor line 0.19-5.0 at its last
patch (installation, the tutorial with key features and recipes, the API reference with a page for every class and
function, the FAQ); the optuna-integration site of every minor line 3.2-5.0 (pruning callbacks for XGBoost and
LightGBM, `LightGBMTuner`, `OptunaSearchCV`, MLflow, Weights & Biases); the optuna-dashboard site of the stable version
0.21 (the web dashboard that plots the trials); the GitHub release notes and the PyPI records of all three packages.

Use this tool for: `optuna.create_study` (`direction`, `directions`, `storage`, `sampler`, `pruner`, `load_if_exists`),
`study.optimize` (`n_trials`, `timeout`, `n_jobs`, `callbacks`), `trial.suggest_float`, `suggest_int`,
`suggest_categorical` (`log`, `step`), samplers (`TPESampler`, `GPSampler`, `CmaEsSampler`, `NSGAIISampler`,
`RandomSampler`, `GridSampler`, `seed`), pruners (`MedianPruner`, `HyperbandPruner`, `SuccessiveHalvingPruner`,
`trial.report`, `trial.should_prune`), the pruning callbacks `XGBoostPruningCallback` and `LightGBMPruningCallback`,
multi-objective optimization, saving and resuming a study with an RDB storage, `optuna.visualization` plots,
`optuna.importance`, `optuna-dashboard` usage, and what changed between versions. Write the query in English, with the
name of the class, function or parameter, such as `TPESampler multivariate` or `XGBoostPruningCallback`. Give a version
in the filter when the answer depends on it: integrations moved from `optuna.integration` to the `optuna-integration`
package, and arguments were renamed and removed between lines.

Do not use it for XGBoost, LightGBM, scikit-learn or the Python language themselves: other servers hold them. Lines
0.0-0.18 are not here as a site, because Read the Docs publishes them no folder; they are covered only by the PyPI
records and the release notes. Returns the matching excerpts with the versions each one applies to, the source address
and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Optuna 5.0.0, optuna-integration 5.0.0 and optuna-dashboard 0.21.0 are the newest
releases. Search without `version` first; when the user names their version, search that line, written as
`optuna-5.0`, `optuna-3.6`, `optuna-integration-4.0` or `optuna-dashboard-0.21`. Every answer about a parameter says
which line it is for.
