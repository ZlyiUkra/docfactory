# oracle-cloud — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Oracle Cloud Infrastructure (OCI) — як завести обліковий запис і
що дає безкоштовний рівень, як створити машину Ampere A1 і під'єднатися до неї по ssh, як відкрити порт у мережі,
як налаштувати політики IAM, бюджет і сповіщення, як підняти кластер Kubernetes (OKE) і балансувальник, як
працювати з CLI, SDK і REST API. Джерело — офіційна документація docs.oracle.com/iaas, лише англійською, плюс
сторінка запитань Free Tier з www.oracle.com і SDK для TypeScript `oci-sdk`. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

На безкоштовній машині Oracle Cloud плани навчання React, NestJS і Next.js тримають продакшн усієї родини: кластер
k3s на Ampere A1, Traefik, сертифікати. Правила цієї машини — скільки OCPU й пам'яті безкоштовно, коли Oracle забирає
бездіяльну машину, що робити з помилкою «out of host capacity», як відкрити порти 80 і 443 у security list — Oracle
міняє, і стоять вони саме в цій документації. Тож потрібен поточний текст, а не пам'ять моделі.

**Що таке OCI.** Oracle Cloud Infrastructure — хмара Oracle: віртуальні машини, мережі, диски, сховище об'єктів,
керований Kubernetes. **Always Free** — ресурси, безкоштовні назавжди (на відміну від 30-денного Free Trial).
**Tenancy** — обліковий запис організації; **compartment** — тека ресурсів усередині нього, на яку вішаються
політики доступу. **Форма** (shape) — тип машини: скільки процесорів (OCPU) і пам'яті.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

жодного слова документації («пустити трафік з інтернету до сервера» замість `security list` і `ingress rule`,

фрагментів, де те саме загальне слово стоїть у сотнях сторінок. Поле `max_per_doc` (не більше N фрагментів з документа
у видачі) нічого не дає: на 2 і 3 «разом» лишається 5, «як модель» — 10. До цілей двох питань додано справжні
відповіді, яких бракувало: сторінку «Quick Create» кластера OKE і запитання FAQ «How do I convert my Oracle Cloud Free
Tier account to a paid account?».

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, сховище сирого (`raw_store`) і профіль
  домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (журнал змін і README `oci-sdk`); `.mcp.json` — запис
  HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df oracle-cloud <крок>`.

| Журнали змін сервісів | переліки `https://docs.oracle.com/en-us/iaas/releasenotes/services/<сервіс>/`, текст — кожна нотатка | `oci-releasenotes` |

Сайт згенеровано з DITA: markdown-двійників і sitemap.xml немає, а повний перелік сторінок — понад 18 тисяч — лежить
лише в дереві `toc.json`, з якого скрипт сайту малює ліве меню. Кожне з двадцяти джерел-розділів бере піддерево своєї
кореневої сторінки (поле `root`) і лише адреси з теки розділу (поле `within`). Посилання у відповідях ведуть на
docs.oracle.com, www.oracle.com, github.com і www.npmjs.com.

Особливості, які варто знати:

- **Вкладки Console / CLI / API.** Сторінки-завдання показують ті самі кроки трьома способами у вкладках. Підписи
  вкладок стоять окремим списком над панелями, тож читач ставить кожній панелі заголовок «Console», «CLI» чи «API»
  з підпису на тому самому місці. Без цього кроки консолі злипалися б із командами CLI в один розділ.
- **Гармошки.** Вкладені теми DITA сайт малює гармошкою: назва — посилання-перемикач, а не заголовок. Читач робить
  з неї підрозділ — так «Common Policies» розпадається на шістдесят політик, а «Always Free Resources» — на
  подробиці кожної форми.
- **Політики IAM — окремим джерелом.** Синтаксис і довідник політик лежать у дереві поза розділом IAM з доменами
  ідентичності, у гілці «IAM without Identity Domains»; їх бере джерело `iam-policies`.
- **Довідник PL/SQL SDK не береться.** У Developer Guide це 688 згенерованих сторінок (31 МБ) типів і процедур для
  всіх сервісів OCI, зокрема баз даних. Поле `exclude` джерела `developer` його відсікає.
- **Журнали змін.** Перелік сервісу — картки з описом, обрізаним на «...», тож береться кожна нотатка окремо; дата
  випуску дописується до назви («Release note: … (2026-10-08)»). Нотатка про кілька сервісів одразу береться раз.
  Сервісів сімнадцять: усі взяті розділи, консоль і загальні оголошення.
- **Таблиця версій `oci-sdk`.** SDK — від 79 до 172 пакетів сервісів, що виходять разом із ним, тож кожна версія
  перелічувала б їх усі з тим самим номером. Поле `lockstep_deps` згортає такий перелік в один рядок
  («79 dependencies moved with it to 2.0.1»); таблиця з 1,7 МБ стала 30 КБ.

## Версії у відповіді

Версій у документації сайту немає: вона описує OCI як він є зараз, а журнали змін — його історія з датами. Фільтр
`version` стосується лише `oci-sdk`: лінії 1 і 2. Коли ліміт, ціна чи правило могли змінитися, відповідь називає
дату нотатки.

## Межі, про які треба пам'ятати

Тут немає баз даних (Autonomous Database, MySQL HeatWave), AI й аналітики, Functions, API Gateway, Vault, Logging,

## Сховище сирого

Під час оновлення примірник тримає ще й сирі відповіді сайтів — у теці `raw/`, поза git (сховище ввімкнене за
замовчуванням; `"raw_store": true` у `config.json` лише каже це явно). Правка читача тоді не вимагає нового
завантаження: `./df oracle-cloud build` збирає тексти зі сховища без мережі. Попередні версії сторінок не видаляються, а переїжджають у `raw/_old/<день>/`. Між оновленнями
сховище, як і тексти, лежить лише в архіві: серверу воно не потрібне. Устрій — у [../../UPDATE.md](../../UPDATE.md),
розділ про `refresh`.

**Стан на 12.10.2026.** Сховище ввімкнено вже після першого повного завантаження, тож в архіві воно тримає лише 1 019
сторінок, перезавантажених після правки читача (вкладки й пункти списку), плюс дерево `toc.json`, переліки журналів
змін, реєстр npm і README `oci-sdk`: 1 322 файли, 9,9 МБ стиснутого. Решта сторінок ляже туди з наступним повним
`refresh`; доти `build` без імен на них відповідає збоєм «немає в сховищі», а наявні тексти лишає як є.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/oracle-cloud-corpus-2026-10-12.tar.gz` (12,7 МБ: 4 318 текстів,
паспорт і сховище сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском — нуль
розбіжностей). В історії git текстів немає ніде. Архів лежить лише на цій машині. Сховище `raw/` після звірки теж
видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/oracle-cloud/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/oracle-cloud-corpus-РРРР-ММ-ДД.tar.gz -C instances/oracle-cloud corpus raw
find instances/oracle-cloud/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/oracle-cloud/raw
gzip -9 -c instances/oracle-cloud/index/passages.json > instances/oracle-cloud/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/oracle-cloud-corpus-РРРР-ММ-ДД.tar.gz -C instances/oracle-cloud
./df oracle-cloud smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/oracle-cloud/index/passages.json.gz`,
далі `./df oracle-cloud vectors` заллє колекцію Qdrant (близько 40 хвилин).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df oracle-cloud …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/oracle-cloud/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

```
./df oracle-cloud sources --why   # перелік джерел і білий список
./df oracle-cloud refresh         # завантажити все задеклароване (~1 год 30 хв: 4 300 сторінок, пауза 1 с)
./df oracle-cloud build           # перезібрати тексти зі сховища сирого, без мережі (після правки читача)
./df oracle-cloud manifest        # оновити паспорт
./df oracle-cloud setup           # Qdrant чи пошук лише по словах
./df oracle-cloud vectors         # залити корпус у docs-oracle-cloud (~40 хвилин)
./df oracle-cloud smoke           # перевірки
```

**Нова сторінка на сайті** в уже взятому розділі з'явиться сама: перелік береться з дерева `toc.json`. Новий сервіс —
нове джерело в `sources.json` з полями `root` і `within`, а для його журналу змін — ім'я сервісу в полі `services`
джерела `release-notes`.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df oracle-cloud serve       # порт 8825
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8825/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user oracle-cloud-docs http://127.0.0.1:8825/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `oracle-cloud-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію
Claude Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і
«Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
