# orval — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про orval — генератор типізованих клієнтів TypeScript зі специфікації
OpenAPI (репозиторій orval-labs/orval, сайт orval.dev) — за документацією всіх його стабільних версій: сайт з тегу
кожної мінорної версії, README ранніх версій, нотатки релізів, приклади репозиторію та історія версій у реєстрі npm. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

orval читає документ OpenAPI (Swagger) — `input.target` у `orval.config.ts` — і пише код: функції запитів для axios чи
fetch, хуки TanStack Query для React, Vue, Svelte, Solid і Angular, хуки SWR, сервіси Angular, схеми Zod, обробники
MSW з даними Faker, сервери Hono і MCP. Що саме й куди — вирішують `output.client`, `output.mode` (один файл, поділ
за тегами), `override.mutator` (свій екземпляр axios чи функція fetch), `baseUrl`, `mock`. У плані NestJS (фулстек-
родина) це день, коли SPA перестає тримати ручні типи відповідей; у плані Next.js — шар даних поруч з окремим бекендом.

Версій багато, і змінюються вони часто: 292 стабільні випуски майже за сім років, лише лінія 8 — 45 мінорних. У 8.0
(14.01.2026) orval перейшов на ESM, типовим клієнтом став fetch замість axios, вилучено `override.coerceTypes`,
`override.useNativeEnums` і `input.validation`, схеми Zod названо в PascalCase, а `output.mock` дістав масив
`generators`. Сайт кожної мінорної версії, нотатки кожного релізу й вимоги до Node зібрано в одному місці, з номером
версії біля кожного уривка.

Чому сайт береться з репозиторію, а не з orval.dev. Сайт показує лише поточну версію, а зміст кожної версії лежить у
репозиторії на її тезі: у 3.x–8.0 — `docs/src/pages`, з 8.1 — `docs/content/docs` (Fumadocs, MDX). Береться остання
латка кожної мінорної версії від 3.0 до 8.44. Сторінка, що переїхала між теками, лишається тією самою сторінкою: поле
`slug_rewrite` у `config.json` зводить обидва шляхи до одного ключа (`orval-guides-react-query`). Китайський переклад
`docs/content/docs/zh` не береться.

Чому README лише 1.0–4.x. До появи сайту README і був документацією (6–9 КБ); з 5.0 це заглушка на 1 КБ із
посиланнями на orval.dev. README підпакетів `@orval/*` (core, axios, fetch, query, swr, zod, angular, hono, mock, mcp,
effect, solid-start) — такі самі заглушки, а їхні теми має сайт; вони не беруться.

Журнал змін. Репозиторій вів `CHANGELOG.md` до 3.x, далі — нотатки релізів GitHub (з 2.2.0). Зі старого журналу
береться лише 1.x–2.1: записи 2.2.0–3.2.3 повторюють релізи, а порожній запис 2.1.2 пропускає поле `skip`.

Чого немає. Документації OpenAPI, TanStack Query, SWR, Zod, MSW, Faker, Hono, Angular, axios і Effect: сторінки orval і
приклади лише показують код, який orval для них пише. Коду самого генератора.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, `slug_rewrite` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df orval <крок>`.

## Версії

Версія — номер випуску; сторінки сайту мають версію тегу, з якого взято (остання латка мінорної). Фільтр `version` бере
мажор (`"8"`), мінор (`"7.21"`) або точну версію (`"8.44.0"`). Без названої версії промпт велить шукати для лінії 8 — на
неї за тиждень до 24.10.2026 припадало близько 84 % завантажень (8.44.0 від 21.10.2026, Node 22.18+), на лінію 7
близько 15 %; де 7.x відрізняється (сторінка переходу на v8), модель згадує й її. Сторінка, що не змінилася між
версіями, — один документ з усіма ними, тож перелік версій уривка сам показує, відколи й доки документація казала саме
це.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/orval-corpus-2026-10-24.tar.gz` (751 текст, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\orval-corpus-2026-10-24.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/orval/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/orval-corpus-РРРР-ММ-ДД.tar.gz -C instances/orval corpus raw
find instances/orval/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/orval/raw
gzip -9 -c instances/orval/index/passages.json > instances/orval/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/orval-corpus-2026-10-24.tar.gz -C instances/orval
./df orval smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/orval/index/passages.json.gz`,
далі `./df orval vectors` заллє колекцію Qdrant (секунди на відеокарті, менше хвилини на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df orval …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df orval sources --why   # перелік джерел і білий список
./df orval refresh         # завантажити все задеклароване (близько години)
./df orval manifest        # оновити паспорт
./df orval setup           # Qdrant чи пошук лише по словах
./df orval vectors         # залити корпус у docs-orval
./df orval smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df orval serve          # порт 8883
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8883/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user orval-docs http://127.0.0.1:8883/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `orval-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
