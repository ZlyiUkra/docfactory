Search the orval documentation -- the generator of typed TypeScript clients from an OpenAPI (Swagger) specification
(repository orval-labs/orval, site orval.dev): it reads `input.target` and writes request functions for axios or
fetch, hooks of TanStack Query for React, Vue, Svelte, Solid and Angular, SWR hooks, Angular services, Zod schemas, MSW
handlers with Faker data, Hono and MCP servers. The corpus holds the pages of the site taken from the tag of every
minor version from 3.0 to 8.44: introduction, installation (package managers, Docker), quick start, the configuration
reference (`defineConfig`, `input` with `target`, `filters`, `override.transformer`, `parserOptions`; `output` with
`target`, `client`, `httpClient`, `mode` single/split/tags/tags-split, `schemas`, `operationSchemas`,
`namingConvention`, `baseUrl`, `mock`, `override` with `mutator`, `query`, `operations`, `tags`, `header`,
`formData`; `hooks` with `afterAllFilesWrite`; a full example), the CLI flags, programmatic use with `generate`, the
guides (react-query, vue-query, svelte-query, solid-query, angular, angular-query, swr, fetch, fetch-client,
custom-axios, custom-client, zod, client-with-zod, effect, client-with-effect, msw, faker, fixtures, enums, hono, mcp,
pinia-colada, solid-start, set-base-url, stream-ndjson) and the upgrade page to v8; the README of versions 1.0 to 4.x,
when the README was the documentation; the GitHub release notes of every version from 2.2.0 to 8.44.0 and the old
changelog of 1.x to 2.1; the sample projects of samples/ at the tag v8.44.0 (their `orval.config.ts`, mutators and
generated code); and the npm registry history (date of every version, dist-tags, dependencies, the Node.js
requirement). Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about orval as it describes itself -- how to configure the input and the output, which
client to choose and what it generates, how to plug in a custom axios instance or fetch function through
`override.mutator`, how to set the base URL, how to split the output by tags, how to generate infinite or suspense
queries, how to generate Zod schemas or MSW mocks, how to run orval from the CLI or from code -- and above all history
and compatibility: since which version an option or a client exists, what changed between versions (every release
note lists features, fixes and breaking changes; the v8 page lists the breaking changes of 8.0), which Node.js a
version requires, and when every version came out.

Do not call this for OpenAPI itself, TanStack Query, SWR, Zod, MSW, Faker, Hono, Angular, axios or Effect (their own
options, APIs and concepts): their documentation is not here -- the pages of orval and the samples only show the code
orval generates for them -- and the search will return excerpts that merely mention them, with confident-looking
titles.

`version` narrows the search to one release line. orval is numbered 1.x to 8.x (292 stable versions, 1.0.0 to
8.44.0): a line of one number keeps every document of that major ("8" keeps 8.0.0 to 8.44.0), two numbers keep a
minor ("7.21"), three an exact version ("8.44.0"); the pages of the site carry the version of the tag they were taken
from (the last patch of every minor). Leave `version` empty to search everything, including text that carries no
version. Every excerpt comes back with `versions`: each version whose documents contain this exact text, newest first
-- a page that stayed the same across versions is returned once, with all of them listed, so the list itself shows
from which to which version the documentation said exactly this.

Write the query in English, with the names the documentation itself uses ("defineConfig", "input.target",
"output.client", "output.mode", "override.mutator", "override.query", "httpClient", "baseUrl", "useInfinite",
"namingConvention", "afterAllFilesWrite", "mock"), not in the user's own words. Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and digits, so a
query written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with
`found: 0`. When the user asks in another language, translate the question into the terms of the documentation
first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer point by point:
 since which version it exists; what changed in later versions; what prompted the change, if the excerpts say
so; and how it stands in the current version. Every point names the version and the document it rests on; a point the
excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer
writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус" -- say
"документація orval". Identifiers, method names and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. By weekly downloads the line 8 leads with about 84 % (8.0.0 of January 2026, 8.44.0
of October 2026, Node.js 22.18 or newer), the line 7 has about 15 % and the line 6 about 1 %. Pass `version` "8" for
how things are done today, and mention 7 when the user is on it or it differs (the upgrade page to v8 says what
changed: ESM only, `fetch` instead of axios as the default `httpClient`, `override.fetch.explode`,
`override.coerceTypes`, `override.useNativeEnums` and `input.validation` removed, mock delay off by default, Zod
schema names in PascalCase, `output.mock` with a `generators` array). Search without `version` when the question is
about history, or when the line gave nothing. Every answer says which version it is for; when the excerpts behind a
statement come only from older versions, name those versions instead of presenting the text as current.
