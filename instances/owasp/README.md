# owasp — примірник фабрики docfactory

Тридцять п'ятий примірник фабрики: захищений MCP-сервер, що відповідає на питання про безпеку вебзастосунків і API
за документацією OWASP (Open Worldwide Application Security Project — відкрита спільнота, що пише стандарти й
посібники з безпеки застосунків). Тут усі шпаргалки OWASP Cheat Sheet Series з покажчиками й чернетками, OWASP Top 10
редакцій 2025, 2021, 2017 і 2013, API Security Top 10 редакцій 2023 і 2019, стандарт перевірки ASVS 5.0 і 4.0.3 та
Top 10 Proactive Controls редакцій 2024 і 2018 з архівними сторінками 2016 і 2014. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

Безпека стоїть у планах NestJS і Next.js: cookie й сесії, CSRF, SQL-ін'єкції, токени, WebSocket. Плани посилалися на
шпаргалки OWASP як на читання «поза корпусом». Відповідь з пам'яті тут небезпечна по-особливому: поради старіють
(MD5 і SHA-1 для паролів, `X-XSS-Protection`, JWT у `localStorage`), а Top 10 і ASVS між редакціями перенумеровують
категорії й вимоги — «A3» у 2017 і 2025 означає різне, «V3» в ASVS 4.0.3 і 5.0 теж.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

Разом 328 документів; фрагментів в індексі — 5 269 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук. Кожна редакція лежить у своїх файлах, тож однакові абзаци різних
редакцій не зливаються: на питання без названої редакції пошук може повернути той самий текст і з 2021, і з 2025.

Замір `quality` на першому корпусі: перша десятка (питання своїми словами) — по словах 8 із 10, за змістом 10, разом
10; друга, «як модель» (назви шпаргалок і категорій), — 10 із 10. `max_per_doc` заміряно з 0, 1, 2 і 3: найкраще 1,
воно й стоїть.

**Версія у відповіді.** Шпаргалки живуть однією редакцією і мають мітку «current», чернетки — «draft». Решта має мітку
своєї редакції: Top 10 — «2025», «2021», «2017», «2013»; API Security — «2023», «2019»; ASVS — «5.0», «4.0.3»;
Proactive Controls — «2024», «2018», «2016», «2014». Рік буває в кількох переліках, тож з фільтром версії перелік
треба називати й у запиті. Без названої редакції відповідь — за найновішою (Top 10 2025, API Security 2023, ASVS 5.0,
Proactive Controls 2024); старіші згадуються, коли їх назвав користувач або коли питання — як змінився перелік. Номер
вимоги ASVS іде лише разом із версією стандарту.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження); `.mcp.json` — запис
  HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df owasp <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| шпаргалки, Top 10 2017–2025, API Security, ASVS, Proactive Controls | markdown у репозиторіях OWASP на GitHub | `ghdocs-history` |
| Top 10 2013 | PDF у репозиторії `OWASP/Top10` | `pdf-paper` |

Білий список — два хости: `api.github.com` і `raw.githubusercontent.com`, і в кожного джерела — лише його тека
репозиторію. Самі сайти OWASP не читаються: вони збираються з тих самих репозиторіїв. Посилання у відповідях ведуть на
сайти — cheatsheetseries.owasp.org, owasp.org/Top10, owasp.org/API-Security, top10proactive.owasp.org; ASVS окремих
сторінок не має, чернетки на сайті не опубліковані, тож вони ведуть на GitHub.

Особливості, які варто знати:

- **Адреса сайту, а не репозиторію.** Читач `ghdocs-history` дістав необов'язкове поле `site` — вирази шляхів файлів і
  адреси сторінок сайту, на яких ці файли опубліковано. Текст і далі береться з GitHub, адреса лише цитується.
  Покажчик `IndexASVS4` на сайті не опубліковано, тож він веде на GitHub.
- **Top 10 2017 — з репозиторію `OWASP/Top10`, а не з копії сайту.** Копія сайту зверстана вставками Jekyll
  (`{% include risk_description.html %}`) без заголовків, і пошук не ділив би її на розділи. Markdown, з якого зібрано
  PDF 2017, має звичайні заголовки; адреси його файлів зіставлено зі сторінками сайту вручну. У п'яти іменах сайт
  кодує «&» і «'» двічі (`Logging%2526Monitoring`, `What%2527s_Next…`) — так вони й записані.
- **Top 10 2013 — лише PDF.** Буклет верстає одну тему на сторінку, а назву теми ставить у кутку, тож у витягнутому
  тексті вона опиняється наприкінці сторінки. Читач `pdf-paper` дістав поле `page_titles` — номер сторінки й назва:
  кожна названа сторінка стає розділом («2013-A1 – Injection»), підписи колонок таблиці ризику викидаються. Текст PDF
  розбирає `pypdf` — єдина залежність понад звичайний склад.
- **Картинки в заголовках.** Сторінки Top 10 2021 і 2025 ставлять іконку категорії просто в заголовок — після назви
  `A01:2025 Broken Access Control` іде картинка з атрибутами kramdown `{: style=…}`; вступ шпаргалок і вступ 2025
  починаються логотипом. Читач
  `ghdocs-history` тепер прибирає з назви картинки й атрибути kramdown, а рядки з самою картинкою — з тексту: інакше
  назвою документа ставала розмітка.
- **Дублі й службові файли.** Вступ 2021 лежить у двох файлах з однаковим текстом — один виключено; титулки, примітки
  й змісти Top 10 та API Security теж. Копія Proactive Controls 2024 в `docs/archive/2024` не береться — та сама
  редакція лежить у `docs/`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку, як у express: у `corpus/` лежить лише паспорт `index.json`, а сервер
підіймається з кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає
повний текст кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/owasp-corpus-2026-10-06.tar.gz` (1,2 МБ, 328 текстів і паспорт; перед
видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде. Архів
лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/owasp/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/owasp-corpus-РРРР-ММ-ДД.tar.gz -C instances/owasp corpus
find instances/owasp/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/owasp/index/passages.json > instances/owasp/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/owasp-corpus-РРРР-ММ-ДД.tar.gz -C instances/owasp
./df owasp smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/owasp/index/passages.json.gz`,
далі `./df owasp vectors` заллє колекцію Qdrant (близько 10 хвилин).

## Установка venv

```
cd instances/owasp
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

```
./df owasp sources --why   # перелік джерел і білий список
./df owasp refresh         # завантажити все задеклароване (~10 хвилин)
./df owasp manifest        # оновити паспорт
./df owasp setup           # Qdrant чи пошук лише по словах
./df owasp vectors         # залити корпус у docs-owasp (~10 хвилин)
./df owasp smoke           # перевірки
```

Без `GITHUB_TOKEN` у `.env` анонімного ліміту GitHub API (60 звернень на годину) вистачає: дерев тут лише 13, а
тексти йдуть з raw.githubusercontent.com, що до ліміту не рахується. Обірваний `refresh` продовжується з `--missing`.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df owasp serve           # порт 8795
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8795/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user owasp-docs http://127.0.0.1:8795/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `owasp-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
