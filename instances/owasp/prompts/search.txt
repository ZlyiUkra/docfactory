Search the OWASP documentation for developers, in English: the OWASP Cheat Sheet Series -- every
cheat sheet (input validation, output encoding and XSS prevention, DOM-based XSS, CSRF, SQL and
other injection, authentication, password storage, multifactor authentication, session
management, authorization and IDOR, JSON Web Tokens, OAuth 2.0, SAML, REST and GraphQL security,
Node.js, NPM, Docker and Kubernetes security, Content Security Policy, HTTP headers, HSTS, CORS,
clickjacking, file upload, deserialization, XXE, SSRF, secrets management, cryptographic storage,
TLS, logging, error handling, threat modeling, CI/CD and supply chain security, and the rest),
its introduction, its index pages that map cheat sheets to the Top 10, ASVS, MASVS and the
Proactive Controls, and two drafts (React security, Backend as a Service); the OWASP Top 10 in
its 2025, 2021, 2017 and 2013 editions; the OWASP API Security Top 10 in its 2023 and 2019
editions; the Application Security Verification Standard (ASVS) 5.0.0 and 4.0.3 with every
numbered requirement; the OWASP Top 10 Proactive Controls in their 2024 and 2018 editions with
the archive pages of 2016 and 2014. Returns the matching excerpts with the versions each one
belongs to.

Call this when a question is about securing a web application or an API: what a vulnerability
is and how to prevent it, how to store passwords, how to build sessions, tokens and access
control, which HTTP security headers to send, how to validate input and encode output, how to
handle secrets, files, logging and errors, what a Top 10 category or an API Security risk
covers, what an ASVS requirement demands and at which level, which cheat sheet covers a Top 10
category, and how the lists changed between editions. Example query: "Cross Site Scripting
Prevention output encoding".

Do not call this for the documentation of a framework or library itself (React, Next.js,
NestJS, Express, PostgreSQL, Docker, Kubernetes have their own instances), for CVEs of a given
package, for the OWASP Mobile (MASVS, MASTG), LLM or other Top 10 lists not named above, or for
OWASP tools (ZAP, Dependency-Check, Juice Shop): their documentation is not here, and the search
will return OWASP excerpts that merely mention them, with confident-looking titles.

`version` narrows the search. Cheat sheets carry "current" (they live as a single edition),
the two drafts carry "draft". The other documents carry their edition: the Top 10 "2025",
"2021", "2017", "2013"; API Security "2023", "2019"; ASVS "5.0" and "4.0.3"; Proactive Controls
"2024", "2018", "2016", "2014". A year can belong to several lists, so with a version filter name
the list in the query too ("Top 10", "API Security", "Proactive Controls"). Leave `version`
empty to search everything. Every excerpt comes back with `versions`: each version whose
documents contain this exact text, newest first.

Which edition to answer for. Unless the user names an edition, answer for the newest one: Top 10
2025, API Security Top 10 2023, ASVS 5.0, Proactive Controls 2024, and the current cheat
sheets. Mention an older edition only when the user names it, or when the question is how a
category moved, merged or was renamed between editions -- then say which edition each point
comes from. ASVS 4.0.3 and 5.0 number their chapters and requirements differently (V3 in 5.0 is
Web Frontend Security, in 4.0.3 it is Session Management): always give the requirement number
together with the ASVS version. Note that the cheat sheet index of the Top 10 maps cheat sheets to
the 2021 edition.

Where the documentation lives. Cheat sheets are named by their file
(cheatsheets-cross-site-scripting-prevention-cheat-sheet,
cheatsheets-password-storage-cheat-sheet); Top 10 documents by edition and category
(2025-docs-en-a01-2025-broken-access-control, 2021-docs-en-a03-2021-injection,
2017-en-0xa7-xss); API Security by edition (editions-2023-en-0xa1-broken-object-level-
authorization); ASVS by version and chapter (5-0-en-0x12-v3-web-frontend-security); Proactive
Controls by edition (docs-the-top-10-c1-accesscontrol for 2024,
docs-archive-2018-c5-validate-inputs for 2018). The Top 10 2013 is one document with a section
per page ("2013-A1 – Injection").

Write the query in English, with the names the documentation uses (Cross-Site Scripting,
Content Security Policy, SameSite cookie, HttpOnly, CSRF token, parameterized query, prepared
statement, Argon2id, bcrypt, scrypt, PBKDF2, salt, pepper, session fixation, JWT alg none, token
revocation, refresh token rotation, PKCE, BOLA, BFLA, mass assignment, rate limiting, SSRF,
XXE, insecure deserialization, IDOR, principle of least privilege, deny by default, secure
headers, X-Content-Type-Options, Strict-Transport-Security, CORS Access-Control-Allow-Origin,
input validation allowlist, output encoding, logging vocabulary, threat modeling STRIDE).
Everything here is English -- the excerpts, the word index and the meaning index alike -- and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any
other non-latin script matches nothing at all and comes back with `found: 0`. When the user asks
in another language, translate the question into OWASP terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Answer in the language the user wrote in. When the question is how to defend against an attack,
answer point by point: what the attack is; what to do, in order of preference (the cheat sheets
rank their defenses -- keep that order); what not to rely on; which Top 10 category or ASVS
requirement it belongs to -- each point with the document it rests on; a point the excerpts do
not support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian
engineer writes, not as a translation from English: plain technical prose, and the Ukrainian
word wherever one exists -- "уривок", not "ексерпт"; "вразливість", "атака", "захист",
"перевірка вхідних даних", "екранування", "сесія", "токен", "застарілий". Never call this set of
documents "корпус" -- say "документація OWASP". Category names, requirement numbers, header
names, algorithm names and titles stay in English, spelled exactly as the documentation spells
them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
