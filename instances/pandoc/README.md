# pandoc — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про pandoc та інструменти довкола нього за їхньою документацією. pandoc
— програма командного рядка, яка перетворює документ з одного формату розмітки на інший: Markdown на Word, HTML на
PDF, LaTeX на EPUB і так далі, усього кілька десятків форматів. Її написав Джон Макфарлейн мовою Haskell.

## Що тут зібрано і навіщо разом

Сам pandoc — це одна програма з одним великим посібником. Але працюють із ним рідко напряму: його викликають зі
скрипта, дописують до нього фільтри, запускають у контейнері чи в браузері. Тому поруч із посібником тут лежить
документація того, чим pandoc обгортають.

| Що питають | Де відповідь у цьому примірнику |
|------------|----------------------------------|
| Який параметр командного рядка що робить і які значення приймає | посібник користувача: розділ на кожен параметр |
| Які змінні розуміє шаблон формату | посібник (розділ на кожну змінну) і самі шаблони за замовчуванням |
| Як написати фільтр мовою Lua | довідник фільтрів Lua: розділ на кожну функцію і тип |
| Як викликати pandoc з Node.js або запустити в браузері | пакети npm: `pandoc-wasm`, `node-pandoc` та інші, тека `wasm` самого pandoc |
| Як написати фільтр мовою JavaScript | пакет npm `pandoc-filter` |
| Як пронумерувати рисунки й таблиці і послатися на них | pandoc-crossref |
| Як запустити pandoc у контейнері | сторінки образів Docker `pandoc/*` |
| Як викликати pandoc з Python або написати фільтр мовою Python | pypandoc, panflute, pandocfilters |
| З якої версії є параметр і як він називався раніше | журнал змін і посібники старих ліній |

**Що є що.** **Формат входу і формат виходу** — розмітка, яку pandoc читає і яку пише; їх задають параметри `-f` і
`-t`. **Розширення** — перемикач окремої можливості формату, який додають до імені формату знаком плюс чи мінус:
`markdown+pipe_tables-smart`. **Шаблон** — файл-заготовка цілого документа формату виходу з місцями для підстановки;
**змінна шаблону** — ім'я такого місця (`title`, `geometry`, `fontsize`). **Файл типових налаштувань** — файл YAML, у
якому записано ті самі параметри, що й у командному рядку; його передають параметром `--defaults`. **Фільтр** —
програма, яка змінює документ між читанням і записом: pandoc розбирає вхід у дерево елементів, фільтр це дерево
переробляє, pandoc записує результат. **Фільтр Lua** виконує сам pandoc, без сторонніх програм; **фільтр JSON** —
окрема програма будь-якою мовою, якій pandoc передає дерево у форматі JSON. **Рушій PDF** — стороння програма, якою
pandoc робить PDF: `xelatex`, `lualatex`, `typst`, `weasyprint` та інші.

`--embed-resources`. Лінія 3.0 дала рисункам власний блок `Figure`. Лінія 3.8 додала `--syntax-highlighting`, лінія
3.9 — збірку для WebAssembly.

## Звідки документація

- **Посібник — з репозиторію, і кожен параметр у ньому стає розділом.** У посібнику pandoc параметри командного рядка
  і змінні шаблонів записано не заголовками, а списком означень: рядок з іменем параметра, під ним опис. Заголовок має
  лише група, і під заголовком «General writer options» стоїть близько сотні параметрів. Читач
  `ghdocs-history-deflist` робить із кожного такого рядка розділ. Назва розділу — самі імена без значень
  («--toc-depth», «-f, -r, --from, --read»), а повний рядок зі значеннями лишається першим рядком тексту. У посібнику
  лінії 3.14 після цього 522 розділи замість 263.
- **Чому в назві розділу немає значень.** Запис параметра між версіями міняється: `--lof` у старій лінії,
  `--lof[=true|false]` у новій. Якби він стояв у назві, той самий параметр різних версій мав би різні ключі й займав
  би у видачі кілька місць.
- **До лінії 1.17 посібник лежав у файлі `README`.** Його взято окремим джерелом, а правило `slug_rewrite` у
  `config.json` зводить обидва імена до одного, щоб розділ старого й нового посібника вважався тією самою сторінкою.
- **Довідник фільтрів Lua — файл `doc/lua-filters.md`.** Заголовок функції в ньому — коротке ім'я зі службовою
  позначкою: «stringify {#pandoc.utils.stringify}». Читач знімає позначку і ставить у заголовок повне ім'я з неї:
  «pandoc.utils.stringify». Терміни списків означень у цьому файлі розділами не стають (поле `terms: false`), бо там
  ними записано параметри функцій.
- **Шаблони — файли теки `data/templates`.** Шаблон формату HTML починається з `<!DOCTYPE html>`, і читач коду приймав
  такий файл за сторінку помилки сервера. Поле `html_pages: "all"` каже йому, що це і є потрібний вміст.
- **README пакетів npm — з архіву самого пакета.** У старих версіях малих пакетів реєстр не записав ні коміту, ні
  тегу, тож надійне джерело README — лише архів версії (читач `npm-tarball-files`).
- **pypandoc і pandocfilters** не мають сайту документації: уся вона — README, який PyPI показує на сторінці пакета, і
  рядки документації в коді. Довідник API panflute теж лежить рядками документації в коді, тому взято файли
  `panflute/*.py`.

## Межі, про які треба пам'ятати

- У посібниках різних ліній той самий параметр може стояти в розділах із різними назвами: змінна `geometry` у лінії
  2.5 лежить під «Variables for LaTeX», а в лінії 3.14 — під «Variables», «Variables for LaTeX», «Layout». Тоді пошук
  без `version` показує її двічі.
- Розділом стає лише той рядок списку означень, що починається іменем у зворотних лапках і стоїть з першої колонки.
  Значення параметра, перелічені всередині його опису (`auto`, `none`, `preserve` у `--wrap`), лишаються в тексті
  розділу.
- pandoc-crossref узято однією версією, 0.3.26; старіші описує лише журнал змін.
- Сторінки образів Docker не мають версії, тому пошук із параметром `version` їх не бачить.
- Із пакетів npm узято ті, що викликають pandoc, збирають його для WebAssembly або пишуть для нього фільтри. Пакети,
  які лише читають чи пишуть розмітку в стилі pandoc без самого pandoc (`remark-deflist`, `markdown-it-attrs`), сюди
  не входять.
- Сторінки посібника ведуть на адреси сайту pandoc.org, тобто на найновішу версію сторінки, а не на версію документа.
- Передрелізи не беруться.
- Довідника бібліотеки pandoc мовою Haskell (Hackage), Quarto, R Markdown, специфікацій форматів (docx, EPUB, CSL) і
  самої мови Lua тут немає. LibreOffice — у примірнику `libreoffice`, утиліти poppler, Ghostscript і qpdf — у
  `doc-tools`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/pandoc-corpus-2026-11-21.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\pandoc-corpus-2026-11-21.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів немає
ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/pandoc/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/pandoc-corpus-РРРР-ММ-ДД.tar.gz -C instances/pandoc corpus raw
find instances/pandoc/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/pandoc/raw
gzip -9 -c instances/pandoc/index/passages.json > instances/pandoc/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/pandoc-corpus-2026-11-21.tar.gz -C instances/pandoc
./df pandoc smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/pandoc/index/passages.json.gz`, далі
`./df pandoc vectors` заллє колекцію Qdrant.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df pandoc …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Ключ для кроку `ask` і токен GitHub лежать у кореневому `.env`.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df pandoc sources --why    # перелік джерел і білий список
./df pandoc refresh          # усе: близько 12 хвилин мережею
./df pandoc refresh pandoc-docker   # заморожене джерело називають окремо
./df pandoc manifest         # оновити паспорт
./df pandoc setup            # Qdrant чи пошук лише по словах
./df pandoc vectors          # залити корпус у docs-pandoc
./df pandoc smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df pandoc serve   # порт 9000
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:9000/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user pandoc-docs http://127.0.0.1:9000/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `pandoc-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
