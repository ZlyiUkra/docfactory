# Оновлення корпусу pandoc

Історія npm (`npm-*`), README пакетів npm (`*-readme`) та історія PyPI (`pypi-*`) беруть версії з опису пакета в
реєстрі, тож новий реліз потрапляє туди сам. Релізи GitHub (`pandoc-releases`) читаються щоразу заново з API.
Передрелізи відсіюються.

Руками оголошено:

- **Посібник, тека `doc`, шаблони й код WebAssembly на тегах** (`pandoc-manual`, `pandoc-doc`, `pandoc-templates`,
  `pandoc-wasm-code`): поле `tags` — об'єкт «тег → мітка версії з префіксом», від найновішого, по одному тегу на
  лінію. Коли в лінії виходить новий патч, тег лінії заміняють новішим; коли виходить нова лінія, дописують рядок
  нагорі. У pandoc лінія — два числа (`3.14`), тег буває з двох, трьох чи чотирьох (`3.14`, `3.12.1`, `3.9.0.2`).
- **Журнал змін pandoc** (`pandoc-changelog`): файл `changelog.md` на тегу останнього релізу. Після нового релізу тег
  в адресі `url`, у `cite` і в полі `within` заміняють новим.
- **Старий посібник** (`pandoc-manual-readme`) оголошено на тегах закритих ліній 0.10–1.17, і міняти його не треба.
- **pandoc-crossref** (`crossref-docs`, `crossref-changelog`): один тег останнього релізу; після нового релізу
  заміняють тег і мітку версії.
- **pypandoc, panflute, pandocfilters** (`pypandoc-code`, `panflute-docs`, `panflute-code`, `panflute-changelog`,
  `pandocfilters-code`): теги ліній, як у pandoc.
- **Образи Docker** (`pandoc-docker`): репозиторій `pandoc/dockerfiles` на закріпленому коміті. Джерело позначено
  `frozen`, тож `refresh` без назви його не питає. Щоб оновити, хеш коміту заміняють новим і називають джерело в
  команді.
- **Новий пакет npm** — пара джерел `npm-tarball-files` і `npm-versions` за зразком наявних, з власним префіксом
  версії; пакет дописують у `prompts/search.txt`, `prompts/agent.txt` і в таблицю README.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описано в README, розділ «Архівний режим».

## Вийшла нова версія pandoc

```
./df pandoc refresh pandoc-manual pandoc-doc pandoc-templates pandoc-wasm-code pandoc-changelog pandoc-releases   # після правки tags і url
./df pandoc refresh --missing    # джерела, яких не названо, лише докачуються
./df pandoc manifest
./df pandoc vectors
./df pandoc smoke
# Ctrl+C у терміналі з serve, і знову: ./df pandoc serve
```

Названі джерела оновлюються повністю, не `--missing`: у документі стоять усі версії, де текст був таким, тож новий
реліз змінює й старі документи (шаблон, що не змінився, дописує нову версію в рядок `# версія:`).

Ім'я файла містить початок хеша його вмісту, тому змінений посібник лягає новим файлом поруч зі старим. Після заміни
тегу в `tags` файли, яких новий прогін не записав, переносять в окрему теку поза корпусом руками, перш ніж запускати
`manifest`: інакше в корпусі лишиться редакція патча, якого в `tags` уже немає.

Якщо вийшла нова лінія:

- у `prompts/search.txt` (абзаци про `version` і «Which version to search first») та `prompts/agent.txt` замінити
  номер і дату найновішої лінії; коли реліз перейменував параметр, дописати його до переліку перейменувань, звіривши
  із журналом змін;
- у таблиці «Пакети й версії» README оновити версію;
- у `checks.json`, у десятці `quality_model`, замінити мітку лінії й звірити цілі: назви розділів посібника між
  лініями зрідка міняються.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен для дерев репозиторіїв і сторінок релізів: без нього API
GitHub дає 60 звернень на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального
довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей): `./df pandoc quality --show`, порівняння обох
десяток з попереднім результатом, розбір промахів, правка промптів чи цілей. Головна мета — «як модель» 10 із 10.
