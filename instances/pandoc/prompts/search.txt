Search the documentation of pandoc and of the tools around it and return the matching excerpts with the versions each
one belongs to. pandoc is the command line program (and Haskell library) by John MacFarlane that converts documents
between markup formats: Markdown, HTML, LaTeX, Word docx, EPUB, reStructuredText, Org, Typst, PDF through an engine,
slides and dozens more.

What is here. pandoc: the User's Guide of every line 0.10-3.14 -- a section per command line option ("--toc-depth",
"-f, -r, --from, --read") and per template variable, the defaults files, templates and their syntax, the extensions
of every format, Pandoc's Markdown, citations, slide shows, EPUB metadata, syntax highlighting, custom readers and
writers; the doc folder of the lines 2.0-3.14 -- the Lua filters reference with a section per function and type of
the modules pandoc, pandoc.utils, pandoc.text, pandoc.path, pandoc.system, pandoc.layout, pandoc.template and the
rest, JSON filters, custom readers and writers in Lua, pandoc-server, EPUB, JATS, Org, XML, the Typst property output,
getting started, the FAQ, using the pandoc library, installing; the change log, one entry per release; the GitHub
release notes; the default templates of every output format (default.latex, default.html5, default.beamer,
default.revealjs, default.typst and the others) of the lines 2.0-3.14; the wasm folder of pandoc with the JavaScript
that drives the WebAssembly build. Node.js and JavaScript: the README of every version and the npm history of
pandoc-wasm (the official WebAssembly build of pandoc for browsers and Node.js), node-pandoc, pandoc-filter (JSON
filters in JavaScript and TypeScript), mermaid-filter, pandiff, pandoc (the 2012 wrapper), node-pandoc-promise,
simple-pandoc and pandoc-bin. pandoc-crossref 0.3.26: its documentation page, README and change log. The Docker
images pandoc/minimal, pandoc/core, pandoc/latex, pandoc/extra and pandoc/typst. Python: pypandoc (README of every
version, the code docstrings), panflute (the guide, the code docstrings of every element class and function, the
change log) and pandocfilters (README, the module, the example filters), each with its PyPI history.

Call this when a question is about converting documents with pandoc: which option does something and what its values
are; how to produce a PDF and which engine to use; how to write a defaults file or a template and which variables a
format understands; what an extension such as fenced_divs, pipe_tables or smart does; how Pandoc's Markdown writes
tables, footnotes, citations, attributes and divs; how to write a Lua filter, a JSON filter, a custom reader or
writer; how to number and reference figures with pandoc-crossref; how to run pandoc in Docker; how to call pandoc from
Node.js, from the browser through WebAssembly, or from Python -- and history: since which version an option, an
extension or a Lua function exists, what a release changed, what an old option is called now. Example query:
"--toc-depth --number-sections".

Do not call this for the formats themselves beyond what pandoc does with them (LaTeX packages, the docx file format,
the EPUB specification, CSL styles), for Quarto, R Markdown and Jupyter Book, for the Haskell API reference of the
pandoc library on Hackage, for the Lua language itself, or for other converters (LibreOffice is in the
libreoffice-docs server; poppler, Ghostscript and qpdf are in doc-tools-docs): their documentation is not here, and
the search will return excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line of one product. Each product carries its own numbering behind a
prefix: "pandoc-3.14", "pandoc-3.1", "pandoc-2.19", "pandoc-1.19", "pandoc-wasm-1", "node-pandoc-0.3",
"pandoc-filter-2", "pandoc-crossref-0.3", "pypandoc-1.17", "panflute-3", "pandocfilters-1.5". A longer value narrows
further ("pandoc-3.12.1"). Leave it empty to search every version at once. Every excerpt comes back with `versions`:
each version whose documents contain this exact text, newest first. The Docker image pages carry no version and are
found only by a search without `version`.

Which version to search first. When the user names no version, answer for the newest line, pandoc 3.14 (released on
12 November 2026), and say so. pandoc is installed from system packages and installers, not from a registry, so there
are no download figures by version, and Linux distributions often ship a line that is years old: when the user's
`pandoc --version` is known, search that line. Options that were renamed, with the release that did it -- check them
before an answer: 2.0 (October 2017) renamed `--latex-engine` to `--pdf-engine`, added Lua filters (`--lua-filter`)
and turned smart typography into the extension `+smart`; 2.8 added defaults files (`--defaults`, `-d`) and
`--shift-heading-level-by`, which replaced `--base-header-level`; 2.11 built citation processing in (`--citeproc`
instead of the external pandoc-citeproc filter); 2.11.2 added `--markdown-headings=atx|setext` in place of
`--atx-headers`; 2.19 added `--embed-resources`, which embeds resources without implying `--standalone`, and
pandoc-server; 3.0 gave figures their own Figure block, which changes what a filter sees; 3.1.2 accepts `typst` as a
PDF engine; 3.8 added `--syntax-highlighting`; 3.9 added the WebAssembly build.

How the text is laid out. Documents are named by source: pandoc-manual (the User's Guide; a section per option,
titled with the option names without their values, and per template variable), pandoc-doc (lua-filters, filters,
custom-readers, custom-writers, pandoc-server, epub, jats, org, getting-started, faqs, INSTALL), pandoc-changelog,
pandoc-release, pandoc-data-templates (one document per template file), pandoc-wasm, the README and npm documents of
each JavaScript package, pandoc-crossref, pandoc-docker, pypandoc, panflute, pandocfilters.

Write the query in English, with the names pandoc uses ("--pdf-engine xelatex", "--toc-depth", "--defaults file",
"--embed-resources --standalone", "--citeproc bibliography csl", "--reference-doc docx", "--lua-filter",
"pandoc.utils.stringify", "Pandoc Meta Blocks walk", "fenced_divs", "pipe_tables", "template variables geometry
fontsize", "pandoc-crossref figPrefix", "convert_file outputfile extra_args", "toJSONFilter walk"), not in the user's
own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word
index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question
into the terms of pandoc first, then search.

Answer in the language the user wrote in. When the question is about the history or support of an option, extension
or function, answer point by point: since which version it exists; what changed in later versions; what prompted the
change, if the excerpts say so; and how it stands in the current version. Every point names the product, the version
and the document it rests on; a point the excerpts do not support is left out, not guessed. When that language is
Ukrainian, write as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the
Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set
of documents "корпус" -- say "документація pandoc". Identifiers, option names and titles stay in English, spelled
exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if
an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
