# paperjs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Paper.js — бібліотеку векторної графіки поверх HTML5 canvas:
контури з сегментів і кривих Безьє (`Path`, `Segment`, `Curve`), геометрія (`Point`, `Size`, `Rectangle`), проєкт із
шарів і груп, булеві операції над контурами, інструменти миші, анімація, імпорт та експорт SVG і JSON, мова
PaperScript. Документація — сайт paperjs.org на релізах 0.12.18–0.17.0, довідник API з пакета npm для останньої
версії кожної лінії 0.10–0.17 і для 0.12.18, приклади репозиторію, README і реєстр npm, журнал змін і релізи GitHub;
лише англійською. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі
дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Елемент `<canvas>` браузера малює пікселі й одразу забуває, що саме намалював. Paper.js тримає над полотном дерево
об'єктів, як це роблять векторні редактори: проєкт складається з шарів, шар — з груп і елементів, а кожен контур —
із сегментів з точкою і двома ручками кривої. Змінив точку сегмента чи колір заливки — бібліотека сама перемалює
полотно. Її сильна сторона — математика кривих: перетин двох контурів, об'єднання й віднімання фігур, спрощення
намальованої від руки лінії до кількох плавних сегментів, точка на контурі за відстанню від початку. Тому Paper.js
беруть для редакторів кривих, генеративної графіки й інструментів малювання. Сам Canvas API описано в примірнику
`mdn`; тут — лише те, що додає Paper.js.

Код для Paper.js пишуть двома способами, і вони не взаємозамінні. **PaperScript** — це JavaScript, який бібліотека
сама виконує з тегу `<script type="text/paperscript">`. У ньому точки додаються оператором (`point1 + point2`), а
обробники `onMouseDown` і `onFrame` оголошуються просто функціями. У звичайному JavaScript операторів над точками
немає (`point1.add(point2)`), бібліотеку спершу прив'язують до полотна (`paper.setup(canvas)`), а обробники вішають
на об'єкти (`view.onFrame`, `tool.onMouseDown`). Більшість прикладів документації написано на PaperScript, тому
відповідь мусить казати, якою з двох мов написано приклад.

**Що є що.** **Project** — дерево всього намальованого; **Layer** і **Group** — елементи, що тримають інші;
**Item** — предок усього, що малюється, зі спільними властивостями (`position`, `fillColor`, `rotate()`);
**Path** — контур із сегментів; **Segment** — точка контуру з ручками `handleIn` і `handleOut`, що задають вигин;
**CompoundPath** — фігура з кількох контурів (літера «О» з отвором); **Tool** — набір обробників миші й клавіатури;
**View** — полотно, на якому показано проєкт, з обробником кадру `onFrame`; **Raster** — картинка як елемент проєкту.

## Звідки документація

- **Сайт — з репозиторію, а не зі сторінок.** Сайт paperjs.org зібрано системою woods (її репозиторій лежить у тій
  самій організації `paperjs`) з репозиторію `paperjs/paperjs.org`. Сторінка — це тека з файлом `tutorial.txt`,
  `page.txt` чи `example.txt`. Тегів у репозиторії немає, але кожен реліз `paper` має там коміт «Release version …», і
  примірник бере стан сайту на семи таких комітах. Мітка документа — версія `paper`, тож пошук у лінії 0.12 знаходить
  ті самі уроки, що й у 0.17. Назву сторінки дає ім'я її теки (поле `path_title`), адресу на сайті — поле `site` у
  `sources.json`; усі 46 адрес звірено з сайтом.
- **Читач `ghdocs-woods`.** Текст сторінки розмічено не markdown, а власними тегами: `<title>` — заголовок
  розділу, `<api Path.Circle(center,radius) />` — посилання на довідник, `<paperscript>` — приклад, що
  запускається на сторінці, `<note>`, `<page>`, `<url>`. Читач перетворює їх на заголовки, код у рядку, блоки
  коду й посилання markdown; без цього сторінка була б одним розділом без заголовків. Перелік комітів, імена й
  версії документів складає спільний читач `ghdocs-history`.
- **Довідник API — з пакета npm.** Проєкт збирає довідник власним шаблоном JSDoc і кладе його в пакет, у теку
  `dist/docs/classes`. Сайт показує довідник лише найновішої версії, а більшість користувачів працює з 0.12.18,
  тому читач `npm-tarball-classdocs` бере сторінки з пакета кожної названої версії. Член класу стає окремим
  розділом з підписом, як на сторінці (`Path.Circle(center, radius)`), а приклад PaperScript — блоком коду.
  Сторінка, чий текст є у 0.17.0, цитується адресою paperjs.org/reference; решта — адресою файла в пакеті на
  unpkg.com (сам unpkg не читається, це лише адреса для людини).
- **Успадковані члени зняті.** Сторінка `Path` дослівно повторює всі члени `Item` і `PathItem` — це понад половину
  її тексту, і так на двадцяти класах. Читач знімає ці розділи й лишає наприкінці розділ «Inherited members» з
  іменами предків. Кожен предок має власну сторінку в тому ж пакеті.
- **Приклади репозиторію — цілою сторінкою.** Приклад у теці `examples` — це файл HTML з вбудованим скриптом
  PaperScript. Читач `ghcode-history` бере його як код (поле `html_pages`); без цього поля файл, що починається з
  `<!DOCTYPE html>`, вважався б сторінкою помилки.
- **README.** Реєстр npm віддає README лише найновішої версії, тому README кожної версії читається з репозиторію
  на коміті її публікації (`gitHead`), а де реєстр коміту не записав — з тегу `v{version}`. README є в усіх 67
  стабільних версіях.
- **Журнал змін.** `CHANGELOG.md` пише заголовок версії у зворотних лапках («## `0.17.0`»), тому його розбирає
  читач `changelog-regex` з виразом заголовка в `sources.json`. Журнал починається з 0.10.0.

## Межі, про які треба пам'ятати

- Довідника API ліній 0.8 і 0.9 немає: у їхніх пакетах npm він відсутній. Про ці лінії відомо лише з README.
- Довідник узято з останньої версії кожної лінії і з 0.12.18, а не з кожної версії: що змінилося між 0.12.0 і
  0.12.18, кажуть журнал змін і релізи.
- Успадкованого члена класу описано один раз, на сторінці предка: `position`, `fillColor` чи `rotate()` для `Path`
  треба шукати на сторінці `Item`, а `unite()` чи `simplify()` — на сторінці `PathItem`.
- Дев'ять прикладів репозиторію не взято, бо файл більший за 40 000 байтів: це приклади з вбудованими даними
  картинки чи великого SVG (`Tiger.html`, `Raster.html`, `BlendModes.html`, `BooleanOperations.html`).
- Уроки сайту написано переважно на PaperScript; як те саме пишеться звичайним JavaScript, пояснює урок «Using
  JavaScript Directly».
- Редактор sketch.paperjs.org, сторінка завантажень і вітрина сайту не входять.
- Сам Canvas API браузера і SVG — у примірнику `mdn`. Інші бібліотеки для малювання мають власні примірники:
  `konva`, `pixijs`, `fabricjs`, `svgjs`, `d3`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/paperjs-corpus-2026-11-20.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\paperjs-corpus-2026-11-20.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів
немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/paperjs/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/paperjs-corpus-РРРР-ММ-ДД.tar.gz -C instances/paperjs corpus raw
find instances/paperjs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/paperjs/raw
gzip -9 -c instances/paperjs/index/passages.json > instances/paperjs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/paperjs-corpus-2026-11-20.tar.gz -C instances/paperjs
./df paperjs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/paperjs/index/passages.json.gz`,
далі `./df paperjs vectors` заллє колекцію Qdrant.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df paperjs …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/paperjs/.env` (`cp .env.example .env`; для
кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df paperjs sources --why    # перелік джерел і білий список
./df paperjs refresh          # усе: близько 5 хвилин мережею (паузи 0,2 с)
./df paperjs manifest         # оновити паспорт
./df paperjs setup            # Qdrant чи пошук лише по словах
./df paperjs vectors          # залити корпус у docs-paperjs
./df paperjs smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df paperjs serve   # порт 8993
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8993/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user paperjs-docs http://127.0.0.1:8993/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `paperjs-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
