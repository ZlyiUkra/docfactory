# Оновлення корпусу paperjs

README (`npm-readme-paper`) і реєстр (`npm-*`) беруть версії з опису пакетів у реєстрі npm, тож новий реліз `paper`
потрапляє туди сам. Журнал змін (`changelog`) і релізи GitHub (`releases`) читаються щоразу заново з гілки `develop`
і з API. Передрелізи README і релізів не беруться (`skip_versions: "-"` у README, `"stable": true` і `skip` у
релізах).

Руками оголошено:

- **Сайт** (`site`): поле `tags` тримає по рядку «SHA коміту → версія paper» на кожен знімок сайту. Тегів у
  репозиторії `paperjs/paperjs.org` немає, але кожен реліз має там коміт «Release version …»
  (`https://github.com/paperjs/paperjs.org/commits/main`). Для нової версії беруть SHA такого коміту й дописують
  рядок нагорі, бо `tags` оголошено від найновішого. Нова сторінка сайту потребує ще двох рядків: у `site` — «файл →
  адреса на paperjs.org», у `path_title` — нічого, якщо вона лежить у теці уроків чи прикладів (назву дає ім'я
  теки). Адресу звіряють із сайтом: без рядка в `site` цитата вестиме на файл у GitHub.
- **Довідник API** (`api`): поле `versions` — перелік версій `paper`, з пакета яких читається довідник, від
  найновішої. Нову версію дописують першою. Якщо вона відкриває нову лінію (скажімо, 0.18.0), попередня остання
  версія лишається в переліку як остання своєї лінії. Версію, що лише заміняє патч у тій самій лінії (0.17.1 після
  0.17.0), ставлять замість старої; виняток — 0.12.18, яку тримають окремо, поки вона має більшість завантажень.
- **Приклади репозиторію** (`examples`): поле `tags` — «тег → версія»; тримають тег найновішої версії і тег
  найпоширенішої.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df paperjs refresh site api examples npm-readme-paper npm-paper changelog releases   # після правки sources.json
./df paperjs refresh --missing    # джерела, яких не названо, лише докачуються
./df paperjs manifest
./df paperjs vectors
./df paperjs smoke
# Ctrl+C у терміналі з serve, і знову: ./df paperjs serve
```

Названі джерела оновлюються повністю, не `--missing`: у документі стоять усі версії, де текст був таким, тож новий
реліз змінює й старі документи (незмінна сторінка дописує нову версію в рядок `# версія:`).

Ім'я файла сторінки сайту й довідника містить початок хеша її тексту, тому змінена сторінка лягає новим файлом
поруч зі старим. Після заміни версії в переліку `versions` файли, яких новий прогін не записав, переносять в окрему
теку поза корпусом руками, перш ніж рахувати вектори: інакше пошук знаходив би сторінку версії, якої в переліку вже
немає. Сховище сирого `raw/` повертається з архіву разом із текстами, тож після правки читача тексти
перебудовуються без мережі: `./df paperjs build <id>`.

Якщо змінилася найпоширеніша версія (на 20.11.2026 — 0.12.18, близько 69 % завантажень; уся лінія 0.12 — понад
80 %):

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` переглянути лінію за
  замовчуванням;
- у `checks.json`, у десятці `quality_model`, замінити `"0.12"` і звірити цілі.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен для дерев репозиторію і сторінок релізів: без нього API
GitHub дає 60 звернень на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df paperjs quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
