# partysocket — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про PartySocket — клієнт WebSocket із перепідключенням для PartyKit і
PartyServer (пакет npm `partysocket`) — за офіційною документацією всіх стабільних версій, від 0.0.2 (серпень 2023) до
поточної 1.x: сторінки сайту docs.partykit.io про клієнт у стані на кожен реліз, README кожної версії, код і тести
пакета на кожну версію, журнал змін і історія пакета в реєстрі npm. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо код поруч зі сторінками

PartySocket — форк reconnecting-websocket (pladaria) з доданим клієнтом кімнат PartyKit і хуками React. Його
документація відстає від пакета: сторінку «PartySocket (Client API)» на сайті востаннє міняли 23.01.2024 (0.0.24),
README — у червні 2025 (у пакеті — з 1.1.5). Усе, що прийшло пізніше, описане лише в журналі змін і в коді: `basePath`
без `room` (1.1.12), фіксована базова затримка перепідключення 3 с замість випадкової (1.1.19), синхронна подія
`close`, `send()` з булевим результатом, `drainQueuedMessages()` і `transferEnqueuedMessages` у хуках (1.2.0),
`shouldReconnectOnClose` (1.3.0). Тож у корпусі поруч зі сторінками — сам код пакета й тести, поділені на класи,
методи, типи й окремі тести: кожен розділ несе версії, у яких він був саме таким, і відповідає на «як це працює в моїй
версії» точніше за сайт.

Лінію 1.x встановлюють найчастіше: за тиждень до 11.10.2026 — 2,78 млн завантажень із 3,24 млн (86 %), з них 1.3.0 —
1,35 млн; лінію 0.0.x — ще 0,45 млн. Тому лінія за замовчуванням у промптах — 1.x.

**Замір `quality`** на першому корпусі: по словах 9 із 10, за змістом 8, разом 9; десятка «як модель» — 10 із 10.
Перша десятка — переказ питання своїми словами, і промахи такі:

- **Друга party проєкту.** На «connect to a second server class of the same project» жоден спосіб не приносить
  розділу «Accessing parties via HTTP or WebSocket» (опція `party` клієнта): з посібника «Using multiple parties per
  project» приходить лише приклад зв'язку між parties на сервері, а решту місць займають «How PartyKit works» і
  довідник Party.Server, де слова «server», «project» і «connect» стоять частіше.
- **`updateProperties` за змістом.** На «move the client to another room without creating a new socket object» пошук
  за змістом приносить `PartySocket.reconnect()` і тести хука, а не сам метод; по словах і разом він є.

Дві цілі першої десятки доповнено тестами, бо знаюча людина прийняла б їх як відповідь: на «give up after a number of
attempts» — тест «stops retrying after maxRetries», на «stop reconnecting when the server closes the connection for
good» — тест «shouldReconnectOnClose: false stops reconnecting before close listeners run». Обидва називають опцію й
показують її в роботі.

Десятка «як модель» — запити назвами опцій, методів і хуків, як велить промпт, з `version "1"`. На першому замірі вона
дала 8 із 10: на голу назву опції (`maxRetries`, `maxEnqueuedMessages`) першими приходили тести, у назвах яких є ця
опція, — їх десятки в кількох файлах, — а таблиця значень за замовчуванням і константа `DEFAULT` опускалися нижче
п'ятого місця. Промпт тепер велить для значення опції додавати слово «default» («maxRetries default»): так першою
приходить константа `DEFAULT` з коду, а таблиці «Default values» сайту й README — у п'ятірці.

Поле `max_per_doc` заміряно 0/1/2/3 (до доповнення цілей тестами): перша десятка разом 6/9/6/6, «як модель»
10/10/10/10 — увімкнено 1. Без нього п'ятірку займали тести одного файла.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `requirements.txt` — склад пакетів примірника; працює спільне середовище з кореня (власний `.venv` — лише якщо
  бракує пакетів зі спільних наборів).

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df partysocket <крок>`.

Примірник додав читача `ghcode-history-ts` (`engine/readers/ghcodehistoryts.py`). Він бере файли коду з багатьох
тегів, як `ghcode-history` з примірника alpine, але ділить їх за будовою коду TypeScript: класи, методи й аксесори на
відступі в два пробіли, типи й інтерфейси верхнього рівня, тести `describe`/`it`/`test` (і з модифікаторами на кшталт
`describe.skipIf(…)`, і з назвою на наступному рядку). Коментар JSDoc над оголошенням іде в його розділ; текст
усередині шаблонних рядків межею розділу не стає; куций розділ приклеюється до попереднього. Поріг розміру файла —
100 000 символів: тести хуків React мають 52 тисячі.

Особливості, які варто знати:

- **Два репозиторії.** 0.0.2–1.1.0 і 1.1.2 вийшли з partykit/partykit, 1.1.1 і 1.1.3 і новіші — з cloudflare/partykit,
  куди пакет переїхав у березні 2025 (реєстр записав коміт gitHead кожної версії, тож README й код беруться з того
  репозиторію, де версія справді вийшла). Код обох оголошено однією родиною (`families` у `config.json`): та сама
  редакція методу з двох джерел займає у видачі одне місце.
- **Тегів бракує чотирьом версіям:** 0.0.4 у partykit/partykit і 1.1.4–1.1.6 у cloudflare/partykit. Для них ключ у
  `tags` — коміт gitHead з реєстру.
- **Тегів у сайту немає.** На кожну стабільну версію береться стан гілки `main` partykit/partykit на мить перед
  виходом наступної версії тієї ж лінії; для найновішої — сьогоднішній стан. Документація переїхала в цей репозиторій
  05.09.2023, тож версія 0.0.2 сайту не має — її документація в README.
- **Туторіал з курсорами переїхав** з `tutorial/` у `tutorials/`; поле `slug_rewrite` зводить обидва шляхи до одного
  ключа, і незмінні розділи двох шляхів зливаються.
- **Журнал змін — лише з cloudflare/partykit.** Записи з часів partykit/partykit перенесено туди разом із пакетом.
  Запис 1.1.2 («Update README.md») є лише в журналі старого репозиторію — його не взято. Релізи GitHub (теги
  `partysocket@…`) не беруться: changesets генерує їх із тих самих записів, а 1.1.4–1.1.7 релізів не мають зовсім.
- **Хостинг PartyKit закривається 23.10.2026** (сторінка «Migrate to PartyServer» у корпусі каже, як переїхати). Сам
  partysocket живе далі в cloudflare/partykit і працює з PartyServer і Agents SDK.

## Межі, про які треба пам'ятати

Socket.IO, пакета `ws`, браузерного WebSocket API загалом, Durable Objects і внутрішньої будови серверів PartyKit і
PartyServer тут немає — лише те, що про них показують сторінки поруч із клієнтом. Решта сайту docs.partykit.io (CLI,
конфігурація, сховище, розгортання) не береться: на тих сторінках клієнта немає. Бета-збірки не беруться ні в README,
ні в коді.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/partysocket-corpus-2026-10-11.tar.gz` (257 текстів і паспорт; перед
видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде. Архів
лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/partysocket-corpus-2026-10-11.tar.gz -C instances/partysocket
./df partysocket smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/partysocket/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/partysocket-corpus-РРРР-ММ-ДД.tar.gz -C instances/partysocket corpus
find instances/partysocket/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/partysocket/index/passages.json > instances/partysocket/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/partysocket/index/passages.json.gz`,
далі `./df partysocket vectors` заллє колекцію Qdrant (~3 хвилини).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df partysocket …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/partysocket/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df partysocket sources --why   # перелік джерел і білий список
./df partysocket refresh         # завантажити все задеклароване (~10 хвилин)
./df partysocket manifest        # оновити паспорт
./df partysocket setup           # Qdrant чи пошук лише по словах
./df partysocket vectors         # залити корпус у docs-partysocket (~3 хвилини)
./df partysocket smoke           # перевірки
```

Перші ~4 хвилини `refresh` журнал мовчить, а `corpus/` порожній: читач сайту проходить коміти partykit/partykit і
дерева знімків і лише потім починає писати файли. Без токена GitHub перелік ішов би годинними вікнами по 60
звернень.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df partysocket serve          # порт 8820
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8820/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user partysocket-docs http://127.0.0.1:8820/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `partysocket-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
