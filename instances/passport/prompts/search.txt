Search the Passport.js documentation -- the official site passportjs.org (concepts, the Username &
Password, Google, Email Magic Link and Auth0 tutorials, the normalized user profile), the README of
every stable version of the passport npm package (0.1 to 0.7) and of thirteen strategy packages:
passport-local (0.1-1.0), passport-jwt (0.1-4.0), passport-oauth2 (1.0-1.8), passport-google-oauth20
(1.0-2.0), passport-github2 (0.1.8-0.1.12), passport-facebook (0.1-3.0), passport-http-bearer
(0.1-1.0), passport-openidconnect (0.0-0.1), passport-saml (0.0-3.2), passport-azure-ad (0.0-4.3),
passport-twitter (0.1-1.0), passport-discord (0.1) and passport-strategy (1.0, the base class every
strategy extends); the changelogs, the jwt migration guides, the source code (lib/, src/) and the
tests (test/) of every tagged release of all fourteen packages, and the npm registry history -- and return the
matching excerpts with the versions each one belongs to. Passport is authentication middleware for
Node.js: an application declares strategies (a username and password, a JWT, OAuth 2.0 with Google
or Facebook), and passport.authenticate() runs one of them on a request; it works with Express and
Connect.

Call this when a question is about Passport itself -- passport.use, passport.initialize,
passport.authenticate and its options (session, failureRedirect, successRedirect, failureFlash,
failureMessage, keepSessionInfo, assignProperty, authInfo), passport.serializeUser and
passport.deserializeUser, req.login, req.logout (a callback is required since 0.6), req.isAuthenticated,
req.user, passport.session; the verify callback of a strategy and its done(err, user, info) contract;
the strategies of the fourteen packages -- LocalStrategy (usernameField, passwordField, passReqToCallback),
JwtStrategy (jwtFromRequest, secretOrKey, secretOrKeyProvider, issuer, audience, ignoreExpiration,
ExtractJwt.fromAuthHeaderAsBearerToken, fromExtractors), OAuth2Strategy (authorizationURL, tokenURL,
clientID, clientSecret, callbackURL, scope, state, pkce, store, customHeaders), the Google strategy
(profile, scope, accessType), the GitHub strategy (passport-github2: scope user:email, userAgent), the
Facebook strategy (profileFields, enableProof, graphAPIVersion), BearerStrategy (passport-http-bearer:
the token verify callback, scope, realm), the OpenID Connect strategy (issuer, authorizationURL,
tokenURL, userInfoURL), the SAML strategy (passport-saml: entryPoint, issuer, cert, callbackUrl, the
ADFS notes), the Azure AD strategies (passport-azure-ad: OIDCStrategy, BearerStrategy,
identityMetadata, clientID, validateIssuer), the Twitter strategy (consumerKey, consumerSecret) and the
Discord strategy (scope identify, guilds); how to write a custom strategy (Strategy base class, this.success,
this.fail, this.error, this.redirect, this.pass); the normalized profile; how the internals work
(the Authenticator class, SessionManager, the session strategy, the connect and http framework
adapters) -- and above all history and compatibility: since which version a function or option
exists, what changed between 0.5, 0.6 and 0.7 (session regeneration on login and logout, the
asynchronous req.logout), which versions run on which Node.js (the `engines` field of each version is
written in the npm registry documents). Example query: "req.logout callback session regeneration".

Do not call this for Express, express-session, cookie-session or Connect themselves, for NestJS and
@nestjs/passport, for strategies of other packages (passport-apple, passport-auth0, passport-steam and the rest of the
catalogue), for @node-saml/passport-saml (4.x and 5.x, the successor of passport-saml),
for OAuth 2.0, OpenID Connect or JWT as specifications, for Auth.js, Better Auth, jose or password
hashing (bcrypt, argon2): their documentation is not here, and the search will return Passport
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "0.7" keeps every 0.7.x document, "0.6" keeps
0.6.x; leave it empty to search everything. Every excerpt comes back with `versions`: each version
whose documents contain this exact text, newest first -- text that stayed the same across versions
is returned once, with all of them listed, so the list itself shows from which to which version the
documentation said exactly this. Fourteen packages share this set and their version numbers overlap:
passport (0.1-0.7), passport-local (0.1-1.0), passport-jwt (0.1-4.0), passport-oauth2 (1.0-1.8),
passport-google-oauth20 (1.0-2.0), passport-github2 (0.1), passport-facebook (0.1-3.0),
passport-http-bearer (0.1-1.0), passport-openidconnect (0.0-0.1), passport-saml (0.0-3.2),
passport-azure-ad (0.0-4.3), passport-twitter (0.1-1.0), passport-discord (0.1) and passport-strategy
(1.0); `version` filters by number only, so "0.7" also returns the old passport-saml 0.7.x documents
and "1.0" returns eight packages at once -- put the package name in the query, and check the title of
every excerpt, which names its package, before citing a version. The site passportjs.org is one snapshot, filed under 0.7.0; it has no older editions.

Write the query in English, with the names Passport itself uses ("passport.authenticate",
"serializeUser", "req.logout", "passReqToCallback", "secretOrKey", "ExtractJwt", "authorizationURL"),
not in the user's own words. Everything here is English -- the excerpts, the word index and the
meaning index alike -- and the word index keeps only latin letters and digits, so a query written in
Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with
`found: 0`. When the user asks in another language, translate the question into Passport terms first,
then search.

Answer in the language the user wrote in. When the question is about a feature's history or support,
answer point by point: since which version it exists; what changed in later versions; what prompted
the change, if the excerpts say so; and how it stands in the current version. Every point names the
version and the document it rests on; a point the excerpts do not support is left out, not guessed.
When that language is Ukrainian, write as a Ukrainian engineer writes, not as a translation from
English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents "корпус" -- say
"документація Passport". Identifiers, option names and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if
an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to
`read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query
had to appear in the text, so a query phrased in other words than the documentation uses may miss;
"meaning+words" means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. For passport itself 0.7.0 is the newest and carries about three
quarters of the weekly downloads; 0.6.0 about a sixth. Search with `version` "0.7" for a question
about how to do something, and when the 0.5 or 0.6 way differs (req.logout without a callback, no
session regeneration), search "0.6" or "0.5" as well and give both. For the strategies take the
newest line: passport-jwt 4.0, passport-oauth2 1.8, passport-local 1.0, passport-google-oauth20 2.0,
passport-facebook 3.0, passport-http-bearer 1.0, passport-openidconnect 0.1, passport-github2 0.1,
passport-saml 3.2, passport-azure-ad 4.3, passport-twitter 1.0, passport-discord 0.1.
If the user names a version, or their code shows one (req.logout() without a callback -> 0.5 or
older; keepSessionInfo -> 0.6 or newer), search that line. Search without `version` when the
question is about history, or when the line gave nothing. Every answer says which version it is for;
when the user did not name one, answer for passport 0.7 and say so ("for passport 0.7; in 0.5 and
older ..."). When the excerpts behind a statement come only from older versions, name those versions
instead of presenting the text as current.
