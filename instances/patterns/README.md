# patterns — примірник фабрики docfactory

Сімнадцятий примірник фабрики: захищений MCP-сервер, що відповідає на питання про патерни проєктування,
рефакторинг і принципи SOLID та GRASP: сайт [refactoring.guru](https://refactoring.guru/) (англійська версія),
[patterns.dev](https://www.patterns.dev/) (патерни JavaScript, React і Vue), оригінальні статті й блог Роберта
Мартіна, стаття Лісков і Вінг, статті Вікіпедії, глави трьох книг про GRASP і SOLID і дві книги цілком:
«Design Patterns in .NET» Тимура Ярошенка з кодом на C# і «Clean Code Cookbook» Максиміліано Контьєрі з рецептами
проти запахів коду (див. «Книги»). Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

Патерни важко засвоїти з книжки: розуміння приходить, коли застосовуєш їх у власному коді. Цей сервер — довідник під
рукою саме для цього: «який патерн тут підходить», «чим Strategy відрізняється від State», «який це запах коду і
якою технікою його прибрати», «чи не порушує цей клас SRP», «хто має створювати цей об'єкт (GRASP Creator)», «SSR
чи статичний рендеринг для цієї сторінки», з прикладом коду на TypeScript.

## Корпус лише локально

Текст refactoring.guru захищений авторським правом.
[Правила використання](https://refactoring.guru/content-usage-policy) дозволяють цитувати лише невелику частину
статті з посиланням на сторінку. Статті Мартіна, його блог і patterns.dev теж не мають вільної ліцензії (вільні лише
Вікіпедія — CC BY-SA — і репозиторій PatternsDev/skills — MIT), а книги платні. Тому **корпус у git не потрапляє**
(`corpus/` і `raw/` у `.gitignore`): у git лежать лише налаштування примірника, а `refresh` відтворює корпус з нуля
за ~20 хвилин. З тієї ж причини промпт велить переказувати своїми словами, цитувати коротко й давати адресу
сторінки.

**Резервна копія корпусу** — архів `patterns-corpus-2026-11-17.tar.gz`. Його оригінал лежить у
`~/archives/docfactory`, а копія під тим самим іменем — на диску Windows, поза WSL: `C:\Distr` (з WSL —
`/mnt/c/Distr/patterns-corpus-2026-11-17.tar.gz`). Усередині дві теки: `corpus/` з документами і `raw/` з файлами
двох книг, доданих цілком. `refresh` відтворює лише поточний стан сайтів і перечитує ці дві книги з їхніх файлів у
`raw/local/`, а глави книг Лармана й Мартіна (див. «Книги») — тільки з локальних копій тих книжок, тож точна копія
корпусу — лише в архіві. Відновлення, якщо корпусу немає, — з кореня `docfactory/`:

```
tar -xzf /mnt/c/Distr/patterns-corpus-2026-11-17.tar.gz -C instances/patterns
./df patterns smoke
```

Індекс (`index/`) збереться з корпусу сам при першому старті сервера; вектори лежать у Qdrant, а якщо їх там немає —
`./df patterns vectors`.

## Книги

Глави книг додано разово з локальних копій користувача: вони збагачують корпус першоджерелами GRASP і SOLID, яких
в інтернеті у вільному доступі немає. `refresh` їх не тягне й не чіпає — це не джерела `sources.json`, а файли
`corpus/book-*.txt`, видобуті скриптом [books.py](books.py) поза рушієм. Кожен документ — одна глава; назва
документа й рядок шапки `# джерело:` кажуть главу, книгу, автора й рік, тож відповідь посилається на них замість
адреси.

| Книга | Автор, рік | Глави |
|-------|-----------|-------|
| «Applying UML and Patterns: An Introduction to Object-Oriented Analysis and Design and Iterative Development», 3rd ed., Prentice Hall | Craig Larman, 2004 | 17 «GRASP: Designing Objects with Responsibilities», 18 «Object Design Examples with GRASP», 25 «GRASP: More Objects with Responsibilities», підрозділ 26.2 «Some GRASP Principles as a Generalization of Other Patterns» |

| «Clean Architecture: A Craftsman's Guide to Software Structure and Design», Prentice Hall | Robert C. Martin, 2017 | 7 SRP, 8 OCP, 9 LSP, 10 ISP, 11 DIP, 12 «Components», 13 «Component Cohesion», 14 «Component Coupling» |

Як видобуто: Larman — файл CHM, розпакований 7-Zip, текст із HTML розділів у порядку змісту; підписи рисунків і
врізки («Key Point») — звичайним текстом, а не заголовками. Книги Мартіна — PDF: межі глав зі змісту PDF, заголовки
— за шрифтом (у «Clean Architecture» вони набрані капітеллю, і шматки слів склеюються). Рисунки й діаграми в текст
не потрапляють, лише їхні підписи. Видання «Agile Software Development, Principles, Patterns, and Practices» 2002
року не взято: ті самі глави, що у виданні C#, з прикладами на Java і C++.

Повторити (на іншій машині, з тими самими файлами книг) — з кореня `docfactory/`:

```
.venvs/cpu/bin/python instances/patterns/books.py --books /mnt/c/Books/docfactory/patterns
./df patterns manifest
./df patterns vectors
```

Скрипт прив'язаний до цих видань і назв файлів. CHM Ларманa розпаковує віндовий 7-Zip (`--7z`, змовчання —
`C:\Program Files\7-Zip\7z.exe`) у `out/books/larman/`, і розпаковане там лишається. Наявну главу скрипт не
переписує без `--overwrite`; `--dry` лише показує, що вийде.

### Дві книги цілком

17.11.2026 додано дві книги з файлів користувача, обидві цілком. На відміну від глав вище, це звичайні джерела
`sources.json`. Файл книги лежить у `raw/local/` примірника, джерело називає шлях до нього полем `file`, і читач до
мережі не звертається. Обидва джерела заморожені (`frozen: true`), бо книжка не змінюється: `refresh` без імен їх
оминає, а `./df patterns refresh <id>` перечитує книгу з її файла.

| Книга | Автор, видавництво, рік | Що взято | Джерело, читач |
|-------|-------------------------|----------|----------------|
| «Design Patterns in .NET: Mastering design patterns to write dynamic and effective .NET Code» | Timur Yaroshenko, BPB Publications, 2024 | передмова й 11 глав: основи ООП у .NET, 22 класичні патерни (до кожного — проєкт прикладу й код), принципи SOLID, інверсія керування і контейнер залежностей .NET Core | `yaroshenko-dotnet`, `epub-local` |
| «Clean Code Cookbook: Recipes to Improve the Design and Quality of Your Code» | Maximiliano Contieri, O'Reilly Media, 2023 | передмова автора, 25 глав рецептів і словник термінів | `contieri-clean-code-cookbook`, `pdf-book` |

Як видобуто. У книзі Ярошенка глава — документ. Заголовки розділів і рядки коду в цьому EPUB набрано звичайними
абзацами з класами (`head1`, `head2`, `noindent1_code`), тому поле `classes` джерела каже читачеві, що з них
заголовок, а що код; назви глав виправляє поле `titles`, бо в розмітці номер глави зліплено з назвою. У книзі
Контьєрі глава — теж документ, рецепт («5.2 Declaring Variables to Be Variable») — розділ, а його частини Problem,
Solution, Discussion і Related Recipes — підрозділи. Межі розділів, код і колонтитули читач розрізняє за шрифтами
набору O'Reilly. Рисунки в текст не потрапляють, лише їхні підписи.

Мова коду. Увесь код книги Ярошенка написано на C#, і кожен його блок підписано мовою `csharp`. У «Clean Code
Cookbook» код рецептів написано різними мовами, найчастіше це JavaScript, PHP, Java і Python. Книга мову блоку не
підписує, тому блоки лежать без позначки мови, і вибір прикладу за мовою, названою в запиті, на них не діє. Промпт
велить моделі називати мову такого блоку лише тоді, коли її видно з самого коду.

Адреса в шапці документа. Для «Clean Code Cookbook» це сторінка книги у видавця,
`https://oreil.ly/clean-code-cookbook`. Для книги Ярошенка це репозиторій видавця з кодом книги,
`https://github.com/bpbpublications/Design-Patterns-in-.NET`: саме цю адресу називає сама книга.

Повторити на іншій машині: покласти обидва файли в `instances/patterns/raw/local/` під іменами з `sources.json` (вони
є в архіві, тека `raw/`) і виконати з кореня `docfactory/`:

```
./df patterns refresh yaroshenko-dotnet contieri-clean-code-cookbook
./df patterns manifest
./df patterns vectors
```

**Мова.** Лише англійська. Українська версія сайту повна, але спільний пошук фабрики англійський: індекс слів бере
лише латиницю, моделі векторів англійські, тож українські документи пошук не знаходив би. Переклад термінів, коли
він потрібен, береться з української версії сайту за тим самим шляхом під `https://refactoring.guru/uk/`.

**Приклади коду.** Основна мова — TypeScript: промпт велить додавати «typescript» до запиту про код, якщо
користувач не назвав іншу. Решта дев'ять мов — для загального відома. Приклади того самого патерна різними мовами
займають у видачі одне місце (`variant_pattern` у `config.json`, а десять джерел `examples-<мова>` оголошено однією
родиною полем `families`); мова, названа в запиті («python», «js», «c++»), вибирає свій приклад, а приклади інших мов
відсіюються (`variant_strict`). Для питань про C# і .NET промпт велить додавати до запиту «.NET» або «csharp»: тоді
поруч із прикладами refactoring.guru знаходиться книга Ярошенка.

## Що в цій теці

- `corpus/` — документи звичайними текстовими файлами; поруч `index.json` — паспорт: адреса, дата завантаження й
  сума тексту кожного документа. Лише локально, див. вище.
- `raw/local/` — файли двох книг, доданих цілком (EPUB і PDF). Лише локально, як і корпус.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`); `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df patterns <крок>`.

refactoring.guru — читач `sitemap-html` (`engine/readers/sitemaphtml.py`). Markdown-двійників і `llms.txt` сайт
не має, а меню — не повний перелік: техніки лежать у корені сайту поруч зі службовими сторінками. Повний перелік є
лише в `sitemap.xml`; текст — зібраний HTML від заголовка сторінки до кінця статті.

Особливості, які варто знати:

- **Білий список технік поіменний.** Сторінки технік лежать у корені сайту, тож тека `https://refactoring.guru/`
  відкрила б увесь сайт; поле `within` джерела `en-techniques` перелічує кожну з 66 сторінок.
- **Без реклами.** Сторінки книги (`/design-patterns/book`) і курсу (`/refactoring/course`) не взято; банер книги
  в кінці статей відрізається (поле `end`).
- **Мова коду — мітка блоку.** На сторінках технік код «До» і «Після» кількома мовами йде вкладками; кожен блок
  несе свою мову (`` ```typescript ``), тож їх видно окремо.
- **Приклади — лише англійською сторінкою:** код в українській версії той самий, різниться лише вступний абзац.
- **Статті Мартіна — з Internet Archive.** objectmentor.com більше не існує; адреса з `id_` віддає сам файл без
  обгортки архіву. Колонки 1996 року написано для The C++ Report, тож код у них — C++, і частина лістингів
  перемішана ще у верстці PDF. Текст береться з розкладкою сторінки: звичайне видобування розсипає курсив по рядках.
- **Liskov & Wing — скан.** Текст розпізнано з помилками («supert ype»), формули зіпсовані. Цифрова версія 1999 року
  (CMU-CS-99-156) має зламане кодування шрифтів, звіт 1993 року — скан без тексту; тож узято статтю 1994 року.
- **Вікіпедія — без меню й виносок:** текст від заголовка до розділу See also / References, врізки й навігаційні
  таблиці вирізаються (поле `drop`).
- **Документи без заголовків.** Частина статей patterns.dev і блогу не має жодного підзаголовка — такий документ
  лягає одним розділом без назви. Ціллю заміру `quality` він бути не може: `smoke` зараховує лише розділи з назвою.

## Межі, про які треба пам'ятати

Тут 22 класичні патерни (GoF), запахи коду й техніки за Фаулером, патерни JS/React/Vue з patterns.dev, SOLID і
GRASP, з главами книг Ларманa й Мартіна, і дві книги цілком: «Design Patterns in .NET» Ярошенка (патерни, SOLID і
впровадження залежностей з кодом на C#) і «Clean Code Cookbook» Контьєрі (рецепти проти запахів коду). Немає
архітектурних патернів (MVC, мікросервіси, CQRS), патернів інших фреймворків (NestJS, Angular, Redux), книг Gang of
Four і Фаулера, а з книг Ларманa й Мартіна — решти глав (зокрема архітектурних частин «Clean Architecture»). Код
рецептів «Clean Code Cookbook» написано різними мовами, і мову блоку там не підписано.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df patterns …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/patterns/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпусу в git немає, тож на новій машині (і після клонування) його треба зібрати. Глави книг Лармана й Мартіна
(див. «Книги») так не відтворюються — їх видобуває `books.py` з тих самих копій книг. Дві книги, додані цілком,
`refresh` читає з файлів у `raw/local/`, і без цих файлів їхні джерела дадуть помилку «не відкрив».

```
./df patterns sources --why   # перелік джерел і білий список
./df patterns refresh         # завантажити все задеклароване (~20 хвилин)
./df patterns manifest        # оновити паспорт
./df patterns setup           # Qdrant чи пошук лише по словах
./df patterns vectors         # залити корпус у docs-patterns (~5 хвилин)
./df patterns smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df patterns serve          # порт 8777
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8777/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user patterns-docs http://127.0.0.1:8777/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `patterns-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію
Claude Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і
«Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).

## На іншій машині

Інше вікно VS Code на тій самій машині нічого, крім кроків 1–3 вище, не потребує: сервер один, клієнтів скільки
завгодно. На іншій машині (теж WSL) бракує спільного середовища (`.venvs`), корпусу й векторів у Qdrant — їх немає в
git:

1. середовище — спільне, з кореня: розділ «Установка venv» вище;
2. корпус і пошук — за розділом «Збирання корпусу» (`setup --vectors` з Docker або `setup --no-vectors` без нього);
3. `./df patterns smoke`, `./df patterns serve` і кроки 2–3 розділу «Сервер під Claude Code».
