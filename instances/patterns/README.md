# patterns — примірник фабрики docfactory

Сімнадцятий примірник фабрики: захищений MCP-сервер, що відповідає на питання про патерни проєктування й
рефакторинг за сайтом [refactoring.guru](https://refactoring.guru/) (англійська версія). Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

Патерни важко засвоїти з книжки: розуміння приходить, коли застосовуєш їх у власному коді. Цей сервер — довідник під
рукою саме для цього: «який патерн тут підходить», «чим Strategy відрізняється від State», «який це запах коду і
якою технікою його прибрати», з прикладом коду на TypeScript.

## Корпус лише локально

Текст сайту захищений авторським правом. [Правила використання](https://refactoring.guru/content-usage-policy)
дозволяють цитувати лише невелику частину статті з посиланням на сторінку. Тому **корпус у git не потрапляє**
(`corpus/` у `.gitignore`): у git лежать лише налаштування примірника, а `refresh` відтворює корпус з нуля за кілька
хвилин. З тієї ж причини промпт велить переказувати своїми словами, цитувати коротко й давати адресу сторінки.

Разом 361 документ; фрагментів в індексі — 2 296 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук.

Замір `quality` на першому корпусі: перша десятка (питання своїми словами) — по словах 8 із 10, за змістом 9, разом
8; друга, «як модель» (назви патернів, запахів і технік, як велить промпт), — 10 із 10.

**Мова.** Лише англійська. Українська версія сайту повна, але спільний пошук фабрики англійський: індекс слів бере
лише латиницю, моделі векторів англійські, тож українські документи пошук не знаходив би. Переклад термінів, коли
він потрібен, береться з української версії сайту за тим самим шляхом під `https://refactoring.guru/uk/`.

**Приклади коду.** Основна мова — TypeScript: промпт велить додавати «typescript» до запиту про код, якщо
користувач не назвав іншу. Решта дев'ять мов — для загального відома. Приклади того самого патерна різними мовами
займають у видачі одне місце (`variant_pattern` у `config.json`); мова, названа в запиті («python», «js», «c++»),
вибирає свій приклад, а приклади інших мов відсіюються (`variant_strict`).

## Що в цій теці

- `corpus/` — документи звичайними текстовими файлами; поруч `index.json` — паспорт: адреса, дата завантаження й
  сума тексту кожного документа. Лише локально, див. вище.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`); `.mcp.json` — запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df patterns <крок>`.

## Звідки документація

Усе — з одного читача `sitemap-html` (новий, `engine/readers/sitemaphtml.py`). Markdown-двійників і `llms.txt` сайт
не має, а меню — не повний перелік: техніки лежать у корені сайту поруч зі службовими сторінками. Повний перелік є
лише в `sitemap.xml`; текст — зібраний HTML від заголовка сторінки до кінця статті.

Особливості, які варто знати:

- **Білий список технік поіменний.** Сторінки технік лежать у корені сайту, тож тека `https://refactoring.guru/`
  відкрила б увесь сайт; поле `within` джерела `en-techniques` перелічує кожну з 66 сторінок.
- **Без реклами.** Сторінки книги (`/design-patterns/book`) і курсу (`/refactoring/course`) не взято; банер книги
  в кінці статей відрізається (поле `end`).
- **Мова коду — мітка блоку.** На сторінках технік код «До» і «Після» кількома мовами йде вкладками; кожен блок
  несе свою мову (`` ```typescript ``), тож їх видно окремо.
- **Приклади — лише англійською сторінкою:** код в українській версії той самий, різниться лише вступний абзац.

## Установка venv

```
cd instances/patterns
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # якщо потрібен крок ask, впишіть ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпусу в git немає, тож на новій машині (і після клонування) його треба зібрати:

```
./df patterns sources --why   # перелік джерел і білий список
./df patterns refresh         # завантажити все задеклароване (~15 хвилин)
./df patterns manifest        # оновити паспорт
./df patterns setup           # Qdrant чи пошук лише по словах
./df patterns vectors         # залити корпус у docs-patterns (~2 хвилини)
./df patterns smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd /mnt/c/Projects/fwdays/docfactory
./df patterns serve          # порт 8777
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8777/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user patterns-docs http://127.0.0.1:8777/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `patterns-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію
Claude Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і
«Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).

## На іншій машині

Інше вікно VS Code на тій самій машині нічого, крім кроків 1–3 вище, не потребує: сервер один, клієнтів скільки
завгодно. На іншій машині (теж WSL) бракує venv примірника, корпусу й векторів у Qdrant — їх немає в git:

1. venv — за розділом «Установка venv» вище;
2. корпус і пошук — за розділом «Збирання корпусу» (`setup --vectors` з Docker або `setup --no-vectors` без нього);
3. `./df patterns smoke`, `./df patterns serve` і кроки 2–3 розділу «Сервер під Claude Code».
