# payload — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Payload — відкриту headless CMS і фреймворк застосунків на
TypeScript, що встановлюється просто в застосунок Next.js (сайт payloadcms.com/docs, репозиторій payloadcms/payload,
реєстр npm). Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані
домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Payload — CMS, у якій модель вмісту пишуть кодом: колекції й глобали з полями (`text`, `relationship`, `upload`,
`blocks`, `array`, `richText` на Lexical), контроль доступу функціями, хуки `beforeChange` і `afterRead`, а дані
читають через Local API (`payload.find`), REST чи GraphQL; з 3.0 адмін-панель і API живуть усередині застосунку
Next.js. У плані Next.js (фулстек-родина) Payload стоїть у «знати, що існує» поруч із Sanity і Contentful — на
випадок, коли вміст редагують не розробники.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df payload <крок>`.

## Версії

Сторінки несуть версії тегів, з яких узяті (`3.92.0, 3.91.0, …`), релізи — версію релізу, README і приклади — 3.92.0;
фільтр `version` бере мажор (`"3"`), мінор (`"3.92"`) або точну версію (`"2.32.3"`). За завантаженнями npm за тиждень до
25.10.2026 лінія 3 `payload` тримає 91 % (найновіша стабільна 3.92.0 від 22.10.2026), бета 4.0 — 8 %, лінія 2 — 1 %.
Та сама сторінка живе в десятках редакцій, тож промпт велить шукати спершу з `version` "3", а для коду на 2.x
(сервер Express, `payload.init`, збирач webpack чи Vite) — ще й "2" і казати, що змінилося в 3.0.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/payload-corpus-2026-10-25.tar.gz` (2955 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\payload-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/payload/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/payload-corpus-РРРР-ММ-ДД.tar.gz -C instances/payload corpus raw
find instances/payload/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/payload/raw
gzip -9 -c instances/payload/index/passages.json > instances/payload/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/payload-corpus-2026-10-25.tar.gz -C instances/payload
./df payload smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/payload/index/passages.json.gz`,
далі `./df payload vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df payload …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df payload sources --why   # перелік джерел і білий список
./df payload refresh         # завантажити все задеклароване (близько 40 хвилин)
./df payload manifest        # оновити паспорт
./df payload setup           # Qdrant чи пошук лише по словах
./df payload vectors         # залити корпус у docs-payload
./df payload smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df payload serve          # порт 8901
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8901/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user payload-docs http://127.0.0.1:8901/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `payload-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
