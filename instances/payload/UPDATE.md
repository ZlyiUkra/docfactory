# Оновлення корпусу payload

Документація береться з закріплених комітів: джерело `pl-docs-N` тримає в полі `tags` коміт останнього тегу кожної
мінорної мажору N, README і приклади — коміт тегу v3.92.0. Релізи й реєстр npm беруться щоразу заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

**Нова версія `payload`.** Новий патч наявної мінорної — замінити в полі `tags` джерела `pl-docs-3` коміт і версію цієї
мінорної; нова мінорна — дописати пару «коміт: версія» першою (найновіший тег іде першим: з нього читач бере адресу
файла). Коміт тегу дає `https://api.github.com/repos/payloadcms/payload/git/ref/tags/vX.Y.Z` і ще один крок через
`git/tags/<sha>`: теги анотовані. Для README і прикладів — замінити коміт в адресі дерева. Коли вийде стабільна 4.0 —
нове джерело `pl-docs-4` за зразком `pl-docs-3`.

```
./df payload check                 # чи змінилося щось нагорі за джерелом
./df payload refresh               # повне перезавантаження, близько 40 хвилин
./df payload manifest
./df payload vectors
./df payload smoke
# Ctrl+C у терміналі з serve, і знову: ./df payload serve
```

Якщо змінилося співвідношення завантажень ліній (на 25.10.2026 лінія 3 — 91 %), — у `prompts/search.txt` (абзац «Which
version to search first») і `prompts/agent.txt` замінити лінії й числа.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df payload quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
