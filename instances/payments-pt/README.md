# payments-pt — примірник фабрики docfactory

Цей примірник зібрав документацію чотирьох португальських постачальників онлайн-платежів і віддає її через сервер MCP, щоб
модель відповідала з їхніх текстів, а не з пам'яті. Постачальник платежів — це компанія, яка приймає гроші від покупця
через MB WAY, Multibanco, картку чи дебет і перераховує їх продавцеві. Тут є ifthenpay, Easypay, Eupago і SIBS.

## Навіщо окремий примірник

Примірник `stripe` описує одного постачальника. Коли Stripe клієнту не підходить, треба порівнювати, хто що приймає, скільки
це коштує і чи може приєднатися асоціація. Ці відповіді лежать на різних сайтах чотирьох компаній, тому один сервер шукає
по всіх одразу. Постачальники зібрані в один примірник за рішенням власника.

Примірник відповідає лише тим, що опубліковано. Ціна тут означає те, що сайт показував у день завантаження, тож перед
рішенням її треба підтвердити в постачальника.

Замір `quality` на 03.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай
питає саме так. Запити своїми словами знаходять потрібне лише 4 із 10.

Причина нижчого числа така. На питання про комісію чи повторні платежі відповідає багато сторінок чотирьох компаній, а
блоги й новини складають третину документів і часто випереджають довідку. Тому модель має писати в запиті назву постачальника
й назву сторінки, про що сказано в промпті. Блоги лишилися в корпусі, бо сторінки рішень посилаються на них за роз'ясненнями.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df payments-pt <крок>`.

Читач `html-query` новий. Він потрібен, бо ifthenpay віддає статті за адресами, що різняться лише рядком запиту, а назву
тримає не в `<h1>`. Сайт SIBS ще й відповідає 403 на запит без заголовка Accept.

**Що свідомо не взято.**

- Портал `developer.sibsapimarket.com`: це API PSD2 для ліцензованих сторонніх постачальників, а не для продавця.
- Іспанські й французькі редакції сайтів: вони лише повторюють англійську й португальську.
- Чотирнадцять коротких сторінок сайту SIBS і центру допомоги ifthenpay, де майже немає тексту, і заглушки документації SIBS.
- Три сторінки сайту SIBS, які сервер не віддає (403 і 404), і три README без заголовка.
- Шість репозиторіїв ifthenpay без README і порожній репозиторій Eupago.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. У окремому терміналі виконайте:

```
./df payments-pt serve
```

Порт — `8948`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user payments-pt-docs http://127.0.0.1:8948/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `payments-pt-docs` з інструментами `search_docs` і `read_section`. Якщо
сервер позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/payments-pt-corpus-2026-11-03.tar.gz` (1330 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\payments-pt-corpus-2026-11-03.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/payments-pt/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/payments-pt-corpus-РРРР-ММ-ДД.tar.gz -C instances/payments-pt corpus raw
find instances/payments-pt/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/payments-pt/raw
gzip -9 -c instances/payments-pt/index/passages.json > instances/payments-pt/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як
новий архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/payments-pt-corpus-2026-11-03.tar.gz -C instances/payments-pt
./df payments-pt smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки
`smoke`, яким потрібні тексти, пропускаються («корпус в архіві»).
