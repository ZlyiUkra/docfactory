# pdf-python — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про роботу з файлами PDF мовою Python за документацією бібліотек. У
Python немає однієї бібліотеки «для PDF»: одна читає й міняє готові файли, друга витягає текст і таблиці, третя
створює новий документ, четверта перетворює HTML. Тому тут в одному примірнику зібрано 24 пакети, і шукати можна від
задачі, а не від назви.

## Що тут зібрано і навіщо разом

| Задача | Бібліотеки в цьому примірнику |
|--------|-------------------------------|
| Об'єднати, поділити, повернути, зашифрувати наявний PDF | pypdf (і його стара назва PyPDF2), pikepdf, pdfrw, програма командного рядка pdfly |
| Витягти текст | pypdf, pdfplumber, pdfminer.six, pdftotext, pypdfium2 |
| Витягти таблиці | pdfplumber, Camelot, tabula-py |
| Створити PDF з коду | ReportLab, fpdf2, borb; svglib вставляє рисунок SVG у документ ReportLab |
| Перетворити HTML і CSS на PDF | WeasyPrint, xhtml2pdf, pdfkit |
| Перетворити сторінки на зображення | pypdfium2, pdf2image |
| Заповнити чи створити форму | PyPDFForm, pypdf |
| Підписати PDF і перевірити підпис | pyHanko |
| Перетворити PDF на Word, а зображення на PDF | pdf2docx, img2pdf |

**Що є що.** **Об'єкт PDF** — найменша одиниця файла: число, рядок, словник, потік; pypdf і pikepdf дають до них
прямий доступ. **Потік вмісту** — перелік команд малювання сторінки; саме з нього бібліотеки відновлюють текст.
**Аналіз макета** — крок, на якому окремі символи з координатами збираються в рядки й абзаци; у pdfminer.six ним керує
клас `LAParams`. **Canvas** — «полотно» ReportLab, на якому малюють командами з координатами. **PLATYPUS** — надбудова
ReportLab, яка сама розкладає абзаци й таблиці по сторінках. **Flowable** — елемент такого розкладання: абзац,
таблиця, рисунок. **AcroForm** — форма PDF з полями, які можна заповнити. **PAdES** — європейський стандарт цифрового
підпису PDF.

**Чого тут немає і де воно.** PyMuPDF і MuPDF — у примірнику `mupdf`. OCRmyPDF і Tesseract — у `tesseract`. Бібліотеки
PDF для JavaScript — у `pdf-js`. Утиліти poppler, Ghostscript і qpdf — у `doc-tools`.

**Яку версію вважати основною.** PyPI не дає надійної статистики за версіями пакета, тому промпт велить відповідати
для найновішої лінії названої бібліотеки і казати, для якої. Коли користувач бібліотеку не назвав, промпт велить
шукати без `version` і порівнювати знайдене.

**Що перейменовано.** Промпт називає зміни, на яких найчастіше помиляються, з релізом, що їх зробив; усі звірено із
журналами змін. PyPDF2 1.28 і 2.0 перейменували `PdfFileReader`, `PdfFileWriter` і `PdfFileMerger` на `PdfReader`,
`PdfWriter` і `PdfMerger`, а PyPDF2 3.0.0 прибрав старі назви. pypdf 3.1.0 від 23.12.2022 — це PyPDF2 3.0.0 під назвою
`pypdf`, і PyPDF2 відтоді не оновлюється. pypdf 5.0.0 прибрав `PdfMerger`. fpdf2 2.5.2 оголосив застарілим параметр
`ln` на користь `new_x` і `new_y`. Пакет `fpdf` — покинутий попередник `fpdf2`, і обидва імпортуються як `fpdf`.
WeasyPrint 53 замінив Cairo власним генератором PDF. ReportLab 4.0 зробив `rlPyCairo` типовим рушієм растрових
зображень.

сторінка чи файл коду, що не змінилися між п'ятьма лініями, лежать одним документом з усіма цими версіями. Фрагменти —
це шматки документа між заголовками, по яких іде пошук.

**Замір 21.11.2026.** «Як модель» (десять запитів назвами класів і параметрів, як їх ставить модель) — 10 з 10 з
першого заміру. Десятка своїми словами: по словах 8, за змістом 10, разом 10 з 10. Пошук по словах промахнувся двічі.
На запит «get the text out of a pdf page» слова запиту збіглися з кодом borb і з прикладами pdfly частіше, ніж зі
сторінкою pypdf. На запит «turn pdf pages into png images» вони збіглися з README пакетів img2pdf і pdfrw, які про
зворотну задачу. В обох випадках потрібні розділи знайшов пошук за змістом.

## Звідки документація

- **Сайт найновішої версії читається зібраним.** У більшості бібліотек довідник API не написано в теці документації:
  сторінка містить лише вказівку `automodule`, а текст Sphinx бере з рядків документації в коді, коли збирає сайт.
  Тому повний довідник є лише в готових сторінках сайту, і їх читає `sphinx-html`.
- **Старі лінії — з репозиторію.** Read the Docs зберігає старі версії не для всіх бібліотек. Де їх немає, сторінки
  посібника взято з теки документації на тегу лінії, а довідник цієї лінії — рядками документації з коду пакета на
  тому самому тегу.
- **Та сама сторінка із сайту і з репозиторію — один розділ.** Сторінка сайту називається `pikepdf-topics-pages`, а
  той самий файл у репозиторії — `pikepdf-docs-topics-pages`. Правила `slug_rewrite` у `config.json` зводять обидва
  імена до одного, а поле `families` каже, що ці джерела — версії одного сайту. Так зроблено для восьми бібліотек:
  pikepdf, pdfly, Camelot, tabula-py, pyHanko, WeasyPrint, pdfminer.six, xhtml2pdf.
- **Сайт fpdf2 і PyPDFForm зібрано з теки `docs` репозиторію** без змін, тому текст узято з неї на кожному тегу, а в
  шапці документа стоїть адреса сторінки сайту. Довідник API fpdf2 сайт будує з рядків документації, і вони взяті з
  коду.
- **Уся документація pdfplumber — файл README** на 42 тисячі символів; його взято на останньому тегу кожної лінії.
- **Посібник ReportLab** узято із сайту docs.reportlab.com: його розділи там лежать окремими сторінками. Сайт не має
  мапи, тому перелік сторінок — посилання з першого розділу посібника в межах відкритої частини сайту. Сторінки
  платних продуктів ReportLab (RML, PageCatcher, Diagra) не беруться.
- **Код ReportLab — із дзеркала.** Офіційне сховище ReportLab ведеться в Mercurial, а на GitHub є його дзеркало
  `MrBitBucket/reportlab-mirror`. Теги в дзеркалі закінчуються версією 3.5.0, тому кожну пізнішу версію взято комітом,
  останнім на дату її випуску в PyPI.
- **Версія pdfminer.six — дата випуску** (`20260107`), тож «лінія» тут — рік: узято останній випуск кожного року.

## Межі, про які треба пам'ятати

- Код узято не на кожній лінії великих бібліотек: для pypdf, pikepdf, pypdfium2 і PyPDFForm — останній тег кожної
  мажорної лінії, для WeasyPrint — дев'ять версій, для pyHanko — вісім ліній. Що мінялося між ними, каже журнал змін.
- Сторінки сайту docs.reportlab.com і посібник із прикладами borb не мають версії, тому пошук із параметром `version`
  їх не бачить.
- Релізів pyHanko на GitHub немає в примірнику: автор позначає їх усі попередніми, а читач релізів попередні відсіює.
  Журнал змін pyHanko є на його сайті.
- Код пакета img2pdf лежить на власному GitLab автора, і з нього нічого не взято: є лише README і версії з PyPI.
- Довідник API старих ліній pikepdf, Camelot, tabula-py і pyHanko — це код з рядками документації, а не оформлені
  сторінки.
- Запит про загальну задачу повертає розділи кількох бібліотек одразу. Це задумано, але модель мусить сама сказати,
  чим вони різняться.
- PyMuPDF, OCRmyPDF, бібліотек JavaScript, специфікації PDF і розбирачів документів на машинному навчанні (Docling,
  Marker, Unstructured) тут немає.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/pdf-python-corpus-2026-11-21.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\pdf-python-corpus-2026-11-21.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів
немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/pdf-python/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/pdf-python-corpus-РРРР-ММ-ДД.tar.gz -C instances/pdf-python corpus raw
find instances/pdf-python/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/pdf-python/raw
gzip -9 -c instances/pdf-python/index/passages.json > instances/pdf-python/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/pdf-python-corpus-2026-11-21.tar.gz -C instances/pdf-python
./df pdf-python smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/pdf-python/index/passages.json.gz`,
далі `./df pdf-python vectors` заллє колекцію Qdrant.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df pdf-python …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище». Ключ для кроку `ask` і токен GitHub лежать у кореневому `.env`.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df pdf-python sources --why    # перелік джерел і білий список
./df pdf-python refresh          # усе: близько 65 хвилин мережею
./df pdf-python refresh borb-examples   # заморожене джерело називають окремо
./df pdf-python manifest         # оновити паспорт
./df pdf-python setup            # Qdrant чи пошук лише по словах
./df pdf-python vectors          # залити корпус у docs-pdf-python
./df pdf-python smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df pdf-python serve   # порт 9001
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:9001/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user pdf-python-docs http://127.0.0.1:9001/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `pdf-python-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
