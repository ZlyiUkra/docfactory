# Оновлення корпусу pdf-python

Історія PyPI (`pypi-*`) бере версії з опису пакета в реєстрі, тож новий реліз потрапляє туди сам. Релізи GitHub
(`*-releases`) читаються щоразу заново з API. Передрелізи відсіюються.

Руками оголошено:

- **Сайти документації** (`*-site`): поле `versions` — теки версій на сайті, поле `version_labels` — який номер версії
  стоїть за текою `stable` чи `latest`. Коли виходить нова версія, у `version_labels` заміняють номер; якщо сайт
  зберігає й попередню версію окремою текою, її дописують у `versions`.
- **Теки документації, README і код на тегах** (`*-docs`, `*-readme`, `*-code`): поле `tags` — об'єкт «тег → мітка
  версії з префіксом», від найновішого, по одному тегу на лінію. Коли в лінії виходить новий патч, тег лінії заміняють
  новішим; коли виходить нова лінія, дописують рядок нагорі. У джерелах `*-docs` найновішої лінії немає навмисно: її
  сторінки дає сайт. Коли сайт переходить на нову лінію, попередню дописують у `*-docs`.
- **ReportLab** (`reportlab-code`, `reportlab-userguide-src`, `reportlab-changelog`): у `tags` стоять не теги, а хеші
  комітів дзеркала `MrBitBucket/reportlab-mirror`. Для нової версії беруть дату її випуску з PyPI і останній коміт
  дзеркала на цю дату: `https://api.github.com/repos/MrBitBucket/reportlab-mirror/commits?until=ДАТА&per_page=1`.
- **Журнали змін** (`*-changelog`): файл на тегу останнього релізу. Після нового релізу тег в адресі `url`, у `cite` і
  в полі `within` заміняють новим.
- **Посібник із прикладами borb** (`borb-examples`): репозиторій на закріпленому коміті. Джерело позначено `frozen`,
  тож `refresh` без назви його не питає. Щоб оновити, хеш коміту заміняють новим і називають джерело в команді.
- **Нова бібліотека** — набір джерел за зразком наявних (сайт, тека документації, код, журнал змін, релізи, PyPI) з
  власним префіксом версії; бібліотеку дописують у `prompts/search.txt`, `prompts/agent.txt`, `prompts/loaded.txt` і в
  таблиці README.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описано в README, розділ «Архівний режим».

## Вийшла нова версія бібліотеки

На прикладі pypdf:

```
./df pdf-python refresh pypdf-site pypdf-code pypdf-changelog pypdf-releases   # після правки versions, tags і url
./df pdf-python refresh --missing    # джерела, яких не названо, лише докачуються
./df pdf-python manifest
./df pdf-python vectors
./df pdf-python smoke
# Ctrl+C у терміналі з serve, і знову: ./df pdf-python serve
```

Названі джерела оновлюються повністю, не `--missing`: у документі стоять усі версії, де текст був таким, тож новий
реліз змінює й старі документи (файл коду, що не змінився, дописує нову версію в рядок `# версія:`).

Ім'я файла містить початок хеша його вмісту, тому змінена сторінка лягає новим файлом поруч зі старим. Після заміни
тегу в `tags` файли, яких новий прогін не записав, переносять в окрему теку поза корпусом руками, перш ніж запускати
`manifest`: інакше в корпусі лишиться редакція патча, якого в `tags` уже немає.

Якщо вийшла нова лінія:

- у `prompts/search.txt` (абзаци про `version` і «Which version to search first») та `prompts/agent.txt` замінити
  номер лінії; коли реліз перейменував клас чи параметр, дописати його до переліку змін, звіривши із журналом змін;
- у таблиці «Пакети й версії» README оновити версію і число завантажень;
- у `checks.json`, у десятці `quality_model`, замінити мітку лінії й звірити цілі: назви розділів між лініями зрідка
  міняються.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен для дерев репозиторіїв і сторінок релізів: без нього API
GitHub дає 60 звернень на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального
довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей): `./df pdf-python quality --show`, порівняння обох
десяток з попереднім результатом, розбір промахів, правка промптів чи цілей. Головна мета — «як модель» 10 із 10.
