# pgx — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про pgx (github.com/jackc/pgx) — драйвер і набір інструментів
PostgreSQL для Go: з'єднання й пул `pgxpool`, запити й розбір рядків у структури, типи PostgreSQL у Go (`pgtype`),
транзакції, пакети запитів, `COPY`, `LISTEN/NOTIFY`, трасування й драйвер для `database/sql`. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

У плані Go ([../go/LEARNING.md](../go/LEARNING.md), фаза 3) pgx — драйвер бази: пул з'єднань, запити руками й під
кодом, який генерує sqlc, транзакції, коди помилок PostgreSQL. Головна документація pgx — не сайт, а коментарі коду,
які показує pkg.go.dev: оголошення й опис кожного типу, функції й методу. Між лініями 4 і 5 API змінився відчутно
(у v4 `pgconn` і `pgtype` були окремими модулями, у v5 з'явилися `CollectRows` і `RowToStructByName`), а в чужому
коді трапляються обидві, тож довідник лежить на кожну мінорну версію обох ліній.

Документів менше, ніж сторінок: текст пакета, що не мінявся між мінорними, — один документ із переліком версій.

Разом 229 записів паспорта. В індексі 2658 фрагментів (`expected_passages` у `checks.json`) із 218 документів. Замір
`quality`: по словах 5 із 10, за змістом 7, разом 7, «як модель» 10 із 10. Цілі першої десятки доповнено справжніми
відповідями: опис `QueryRow` каже про `ErrNoRows`, оглядові розділи `Transactions`, `Copy Protocol` і `Listen and
Notify` пакета pgx (обох ліній) і розділ про кілька запитів за один обмін у `pgconn`. Промахи — запити своїми
словами про межу пулу, ім'я порушеного обмеження й журнал запитів з тривалістю: довідник API називає це `MaxConns`,
`PgError.ConstraintName` і `tracelog`, і пошук по словах їх не впізнає.

Чого немає:

- Вікі репозиторію (github.com/jackc/pgx/wiki): GitHub не віддає її через API дерев.
- Окремих модулів епохи v4 — `jackc/pgconn`, `jackc/pgtype`, `jackc/pgproto3`, `jackc/puddle` — і сторонніх бібліотек
  із розділу README «3rd Party Libraries».
- Пакетів `internal`, тестових допоміжних і програми-прикладу `pgproto3/example`.
- Документації PostgreSQL, `database/sql` загалом і sqlc (окремі примірники `postgresql`, `go`, `sqlc`).

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df pgx <крок>`.

## Версії

Довідник і README несуть версію pgx (`5.11.0`), журнали — версію запису. Фільтр `version` приймає мажор (`"5"`, `"4"`),
мінор (`"5.7"`) або точну версію (`"5.7.6"`). Промпт відповідає для v5, якщо користувач не назвав v4, і каже, для якої
версії відповідь.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/pgx-corpus-2026-10-27.tar.gz` (229 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\pgx-corpus-2026-10-27.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/pgx/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/pgx-corpus-РРРР-ММ-ДД.tar.gz -C instances/pgx corpus raw
find instances/pgx/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/pgx/raw
gzip -9 -c instances/pgx/index/passages.json > instances/pgx/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/pgx-corpus-2026-10-27.tar.gz -C instances/pgx
./df pgx smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/pgx/index/passages.json.gz`.
Далі `./df pgx vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df pgx …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df pgx sources --why   # перелік джерел і білий список
./df pgx refresh         # завантажити все задеклароване (близько двадцяти хвилин: ~400 сторінок pkg.go.dev)
./df pgx manifest        # оновити паспорт
./df pgx setup           # Qdrant чи пошук лише по словах
./df pgx vectors         # залити корпус у docs-pgx
./df pgx smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df pgx serve          # порт 8915
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8915/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user pgx-docs http://127.0.0.1:8915/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `pgx-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
