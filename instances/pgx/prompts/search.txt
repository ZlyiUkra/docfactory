Search the documentation of pgx (github.com/jackc/pgx), the PostgreSQL driver and toolkit for Go: the package
reference from pkg.go.dev for every minor release of pgx v5 (5.0 ... 5.11) and pgx v4 (4.0 ... 4.18) -- package pgx
(Conn, Rows, CollectRows, RowToStructByName, RowToStructByPos, Batch, SendBatch, CopyFrom, Tx, BeginFunc, NamedArgs,
QueryExecMode, ErrNoRows, QueryTracer), pgxpool (Pool, Config, ParseConfig, pool_max_conns, MaxConns, MinConns,
MaxConnLifetime, MaxConnIdleTime, HealthCheckPeriod, AfterConnect, BeforeAcquire, Stat), pgconn (PgConn, PgError,
Config, ParseConfig, connection strings and libpq environment variables, target_session_attrs), pgtype (Map, Text,
Int8, Numeric, Timestamptz, UUID, arrays, ranges, composite types, custom types, NULL handling), pgproto3, stdlib (the
database/sql driver), tracelog and multitracer -- with every declaration, its description and its examples; the README
of pgx and of pgconn and pgproto3 at every minor release 2.0 ... 5.11; the changelog of every release 4.0.0 ...
5.11.0; and the code of the example programs (chat with LISTEN/NOTIFY, todo, url_shortener). Returns the matching
excerpts with the versions each one belongs to.

Call this when a question is about using PostgreSQL from Go with pgx: connecting and the connection string, the
connection pool and its limits, querying a row or many rows and scanning them into structs, NULL values, the
PostgreSQL type mapping (numeric, timestamptz, jsonb, arrays, uuid), transactions, batches, COPY, LISTEN/NOTIFY,
prepared statements and the statement cache, PgBouncer and the simple protocol, error codes from PostgreSQL
(*pgconn.PgError, SQLSTATE 23505), query tracing and logging, using pgx through database/sql, and what changed
between releases or from v4 to v5.

Do not call this for PostgreSQL itself (SQL, indexes, server settings -- that is the PostgreSQL documentation), for
database/sql in general, for sqlc, goose, golang-migrate, GORM or other Go libraries, or for other languages: their
documentation is not here, and the search will return excerpts that merely mention them, with confident-looking
titles.

`version` narrows the search to one release: one number keeps a major line ("5" or "4"), two a minor ("5.7"), three
an exact version ("5.7.6"). Every excerpt comes back with `versions`: each release whose documents contain this exact
text, newest first. Without `version` the newest text comes first.

Write the query in English, with the names the documentation itself uses ("pgxpool.New", "pgxpool.Config",
"pool_max_conns", "CollectRows", "RowToStructByName", "pgx.ErrNoRows", "QueryRow Scan", "BeginFunc", "Tx Rollback",
"SendBatch", "CopyFrom", "pgconn.PgError", "ConnectConfig", "ParseConfig", "QueryExecModeSimpleProtocol",
"statement cache", "pgtype.Numeric", "pgtype.Text", "Timestamptz", "jsonb", "array", "NULL", "QueryTracer",
"tracelog", "stdlib.OpenDBFromPool", "LISTEN NOTIFY WaitForNotification", "AfterConnect", "RegisterType"), not in
the user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and
the word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin
script matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the
question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "пул з'єднань", "запит", "рядок", "транзакція". Never call this set of documents "корпус" -- say
"документація pgx". Identifiers, package names and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. pgx 5.11.0 (September 2026) is the newest release; pgx v4 (4.18.3) is no longer
developed but still common in existing code. Search without `version` first; when the user's code imports
github.com/jackc/pgx/v4, search with version "4". Every answer says which major version (and, when it matters, which
release) it is for.
