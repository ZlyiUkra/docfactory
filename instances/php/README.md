# php — примірник фабрики docfactory

Цей примірник зібрав документацію мови PHP і її менеджера пакетів Composer та віддає її через сервер MCP, щоб модель
відповідала з її тексту, а не з пам'яті.

## Скільки цього

Усього 13 152 документи й 85 309 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окрему відповідь.

| Що | Документів |
|---|---|
| посібник PHP англійською, знімок із php.net | 11 864 |
| RFC, тобто пропозиції змін до мови з обґрунтуванням і голосуванням, `wiki.php.net/rfc` | 960 |
| документація Composer, тека `doc/` | 281 |
| файли `UPGRADING` і `NEWS` у сирцях `php/php-src` | 39 |
| журнал змін Composer і посібник переходу на версію 2 | 2 |
| сторінки Packagist і запис про пакет `composer/composer` | 4 |
| сторінки php.net про підтримувані версії | 2 |

**Версії.** Посібник PHP існує лише в одній чинній редакції, тому документи посібника й RFC версії не мають. Про старі версії
посібник говорить у рядку на початку сторінки функції, у таблиці `Changelog` і в главах про перехід між версіями. Файли
`UPGRADING` і `NEWS` взято на останньому патчі кожної з 23 мінорних ліній від 4.0 до 8.5, їхня мітка — `8.5`. У старих лініях
деяких файлів немає: `UPGRADING` у сирцях з'явився пізніше за PHP 4. Документацію Composer взято так само на останньому патчі
кожної з 23 мінорних ліній від 1.0 до 2.11, її мітка — `composer-2.11`. Однакові тексти різних ліній об'єднано в один документ,
тому документів менше, ніж ліній помножити на файли.

Замір `quality` на 03.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а запити власними
словами 4 із 10. Тому модель має писати запит англійською й точними назвами, про це сказано в промпті.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів: у git лежить стиснений `passages.json.gz`, а розпакований `passages.json` лежить поруч і в git не
  потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df php <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| посібник | архів `php_manual_en.tar.gz` із php.net | `php-manual` |
| RFC | `wiki.php.net/rfc`, запит `do=export_xhtmlbody` | `dokuwiki` |
| `UPGRADING` і `NEWS` | `php/php-src` на GitHub | `php-text` |
| Composer | `composer/composer` на GitHub | `ghdocs-history` |
| реєстр | Packagist, `composer/composer` | `pkg-registry` |
| сторінки php.net і Packagist | перелічені адреси | `html-pages` |

Посібник береться одним архівом, який php.net публікує сам: це одне звернення замість обходу 12 тисяч адрес. В архіві немає
коментарів читачів, які є на сторінках сайту: вони не є офіційним текстом. Шість сторінок архіву порожні, вони вилучені полем
`exclude`. Сторінки однакової назви отримують уточнення: глава про перехід називається «Migrating to PHP 8.5: Backward
Incompatible Changes», а сторінка встановлення розширення — «curl: Installation».

Сюди не входять фреймворки й бібліотеки на PHP, а також образи Docker Hub.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі

```
./df php serve
```

Порт — `8951`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда

```
claude mcp add --transport http --scope user php-docs http://127.0.0.1:8951/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `php-docs` з інструментами `search_docs` і `read_section`. Якщо сервера
немає, перевірте, чи запущено `serve` і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів і векторів у
Qdrant.

**Де тексти.** В архіві `~/archives/docfactory/php-corpus-2026-11-03.tar.gz` (паспорт, тексти й сховище сирого `raw/`; перевірено
за диском) і в копії на диску Windows `C:\Distr\php-corpus-2026-11-03.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/php/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/php-corpus-РРРР-ММ-ДД.tar.gz -C instances/php corpus raw
find instances/php/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/php/raw
gzip -9 -c instances/php/index/passages.json > instances/php/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий
архів перевірено.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/php-corpus-2026-11-03.tar.gz -C instances/php
./df php smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke` і
`quality` працюють із кешу.
