Search the documentation of PHP, the programming language, and of Composer, its package manager. The corpus holds the PHP Manual of php.net in English as a snapshot: the
language reference, every function and class, installation, security and the migration guides between versions, with the changelog table of each function; the UPGRADING and NEWS
files of php-src at the last patch of every minor line 4.0-8.5; the RFCs of wiki.php.net, which explain why the language changed; the Composer documentation at the last patch of
every minor line 1.0-2.11 with its change log; the Packagist pages and record of `composer/composer`.

Use this tool for: PHP syntax and behaviour, a function or class by its exact name, what changed between PHP versions, why a feature was designed so, `composer.json`, Composer
commands and repositories, publishing a package. Write the query in English with the exact name of the function, class or feature, such as "array_map" or "readonly properties".

Do not use it for frameworks and libraries written in PHP, such as WordPress or Laravel: other servers hold some of them. The manual has only one current edition and carries no
version: it describes older versions only through its changelog tables and version notes, while php-src files carry labels such as `8.5` and Composer documents labels such as
`composer-2.11`. Returns the matching excerpts with the source address and the fetch date.

Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written in Ukrainian,
Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question into PHP terms first,
then search.

Answer in the language the user wrote in. When the question is about the history of a function or behaviour, answer point by point: since which version it exists; what changed
in later versions; what prompted the change, if an RFC says so; and how it stands now. Every point names the version and the document it rests on; a point the excerpts do not
support is left out, not guessed. Never call this set of documents "корпус" -- say "документація PHP". Identifiers, command names, flags, keys and titles stay in English, spelled
exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it before describing
what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional and narrows the search to one labelled line, `8.5` or
`composer-2.11`, which leaves out the manual and the RFCs because they carry no version. The first (best) excerpt comes whole; the others are cut at 600 characters and carry
`truncated: true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear in the text, so a query phrased in other words than the
documentation uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase had a chance.
