# pixijs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про PixiJS — бібліотеку швидкої двовимірної графіки в браузері, — про
Pixi React (пакет `@pixi/react`), про PixiJS 3D і про вісім пакетів-додатків. Документація — посібник PixiJS 8 з
останнього тегу кожної мінорної 8.10–8.23, довідник API 8.23.0 і останньої версії ліній 7, 6, 5 і 4, код офіційних
прикладів і підручників, README кожної стабільної версії, реєстр npm і релізи GitHub; лише англійською. Код спільний і
лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики
— у [../../README.md](../../README.md).

## Навіщо окремий примірник

Елемент `<canvas>` браузера вміє малювати двома способами. Перший — Canvas API: команди «проведи лінію», «намалюй
картинку», які виконує процесор. Другий — WebGL і WebGPU: малювання відеокартою, на порядки швидше, але писати під них
напряму означає писати шейдери й самому готувати буфери з координатами. PixiJS бере цю роботу на себе. Ви описуєте
сцену об'єктами — спрайт із картинкою, текст, фігура, — а PixiJS сам збирає їх у пакети й малює відеокартою тисячі
об'єктів за кадр. Тому його беруть для ігор, анімованих інтерфейсів і візуалізацій, де об'єктів багато й вони рухаються
щокадру. Сам Canvas API, WebGL і WebGPU описано в примірнику `mdn`; тут — лише PixiJS.

PixiJS 8 (березень 2024) глибоко змінив API: застосунок створюється асинхронно через `app.init()`, усе імпортується з
одного пакета `pixi.js`, малювання в `Graphics` переписано (`rect().fill()` замість `beginFill().drawRect()`), а
завантаження ресурсів іде через `Assets` замість `Loader`. Код для лінії 7 у лінії 8 не працює, і навпаки, а PixiJS 7 і
6 досі дають 22 % завантажень. Тому відповідь мусить знати, для якої версії вона, і тому примірник тримає довідник API
п'яти ліній.

**Що є що.** **Application** — обгортка, що створює рендерер, кореневий контейнер `stage`, полотно й лічильник кадрів;
**Container** — вузол сцени, що тримає дочірні об'єкти й передає їм своє положення, поворот і прозорість; **Sprite** —
об'єкт, що показує картинку; **Texture** — сама картинка в пам'яті відеокарти, яку можуть ділити багато спрайтів;
**Assets** — завантажувач ресурсів з кешем; **Graphics** — об'єкт для малювання фігур кодом; **Ticker** — лічильник
кадрів, що викликає ваші функції на кожному кадрі; **Filter** — візуальний ефект поверх об'єкта (розмиття, зміна
кольору).

## Звідки документація

- **Посібник PixiJS 8 — з основного репозиторію.** Сторінки посібника лежать поруч із кодом, у теках `__docs__`
  репозиторію `pixijs/pixijs`, і сайт збирає з них розділ `8.x/guides`. Читач `ghdocs-history` бере їх з останнього
  тегу кожної мінорної. Однаковий текст сусідніх тегів стає одним документом, а в рядку `# версія:` стоять усі версії,
  де він був саме таким. Поле `site` дає кожній сторінці адресу на pixijs.com; усі адреси звірено з `sitemap.xml`.
- **Довідник API 8.23 — новим читачем `llms-typedoc`.** Довідник зібрано TypeDoc, а markdown-двійники сторінок
  перелічує `llms.txt` сайту. TypeDoc ділить кожен член класу ще на «Parameters», «Returns», «Default», «Example»:
  268 сторінок несуть 28 850 таких підзаголовків, і поділ за ними дав би десятки тисяч уривків по два-три рядки.
  `heading_floor: 3` лишає фрагментом цілий член класу.
- **Успадковані члени не повторюються.** TypeDoc розгортає на сторінці кожного класу всі члени його предків: з 6 865
  членів довідника успадкованих 4 765, тобто `alpha` чи `position` контейнера стоять дослівно на сотні сторінок.
  `skip_inherited` лишає опис члена на сторінці класу, що його оголосив, а на сторінці нащадка — розділ «Inherited
  members» з переліком імен і тим, звідки кожен успадковано. Конструктор лишається завжди. Лишається й член, чий
  предок сторінки в корпусі не має: TypeDoc називає такого предка простим текстом (`PixiMixins` у PixiJS 3D) або
  посиланням на сторінку, якої перелік `llms.txt` не містить (`AccessibleOptions`, `ViewContainerOptions`,
  `CullingMixinConstructor`). Таких членів 638, серед них `accessible`, `cullArea` і `eventMode` у PixiJS 3D; до
  виправлення 18.11.2026 їхніх описів у корпусі не було зовсім. Зі сторінок нащадків прибрано 3 553 члени в
  довіднику PixiJS 8 і 1 600 у PixiJS 3D. У довідниках ліній 7 і 6 розділи «Inherited Properties» і «Inherited
  Methods» теж не беруться, і кожен їхній предок має власну сторінку. У лініях 5 і 4 таких розділів немає:
  успадковані члени стоять на сторінці класу разом із власними.
- **Довідники старих ліній — одна родина.** Довідники 7.4.3, 6.5.10, 5.3.12 і 4.8.9 мають однаковий шаблон сторінок,
  і читач `html-list` бере їх за переліком із бічного меню. У `config.json` вони оголошені родиною `api-old`, а
  `slug_rewrite` дає сторінці `PIXI.Sprite` усіх ліній один ключ. Завдяки цьому однаковий текст сусідніх ліній лежить
  в індексі один раз (так зникло 1 832 повтори), а в пошуку без версії клас займає одне місце й показує найновішу
  редакцію.
- **П'ять просторів імен лінії 5 — окремим джерелом.** `PIXI.mesh_`, `PIXI.ticker` та ще три відрізняються від класів
  `PIXI.Mesh`, `PIXI.Ticker_` лише регістром і підкресленням. В одному джерелі їхні документи мали б однакові імена, і
  сторінка простору імен затирала б сторінку класу.
- **Приклади й підручники — кодом.** Сторінка прикладу на сайті — це вікно редактора, а код лежить у репозиторії
  файлом. Читач `ghcode-history` бере ці файли: приклади PixiJS 8 з теки `examples/`, приклади PixiJS 7 і код кожного
  кроку підручників — з репозиторію сайту.
- **Версії з префіксом.** Усе, що не є самим `pixi.js`, має власну нумерацію, тому несе версію з префіксом:
  `react-8.0.5`, `3d-0.1.0`, `ui-2.4.1`, `sound-6.0.2`, `layout-3.2.1`, `devtools-2.0.1`, `tilemap-5.0.2`,
  `particle-emitter-5.0.10`, `gif-3.0.1`, `viewport-7.0.3`. Без префікса фільтр «7» змішав би PixiJS 7 з
  `pixi-viewport` 7.
- **Знімки без тегів.** Репозиторії сайту (`pixijs/pixijs.com`) і Pixi React тегів для документації не ставлять:
  узято коміти `27ec4c13` від 17.11.2026 і `30cf1f86` під мітками останніх на той день версій пакетів.

## Межі, про які треба пам'ятати

- Редакції посібника є з 8.10. До того посібник жив у репозиторії сайту без тегів, і його текстів для 8.0–8.9 не
  збереглося; про ці версії відомо з README і релізів.
- Довідник API є для 8.23.0 і для останньої версії кожної з ліній 7, 6, 5 і 4, а не для кожної мінорної. Для ліній
  1–3 довідника немає: лише README і реєстр.
- Опис успадкованого члена треба шукати на сторінці класу-предка (`Container`, `ViewContainer`).
- Приклади PixiJS 8 є з 8.17, коли тека `examples/` з'явилася в основному репозиторії.
- README немає у версії `@pixi/tilemap` 2.2.0 і в 112 старих версій `pixi-viewport`: реєстр не записав для них ні
  коміту, ні тегу.
- Довідники API додатків (сайти TypeDoc `@pixi/sound`, `@pixi/tilemap`, `@pixi/gif`, `@pixi/particle-emitter`,
  Storybook `@pixi/ui`) не входять: додатки описані README, релізами й, де є, текою документації.
- Не входять: передрелізи, сторонні плагіни (Spine та інші), сам Canvas API, WebGL і WebGPU (примірник `mdn`), сам
  React (примірник `react`), three.js (примірник `threejs`), Konva (примірник `konva`).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/pixijs-corpus-2026-11-18-inherited.tar.gz` (тексти, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\pixijs-corpus-2026-11-18-inherited.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git
текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/pixijs/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/pixijs-corpus-РРРР-ММ-ДД.tar.gz -C instances/pixijs corpus raw
find instances/pixijs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/pixijs/raw
gzip -9 -c instances/pixijs/index/passages.json > instances/pixijs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/pixijs-corpus-2026-11-18-inherited.tar.gz -C instances/pixijs
./df pixijs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/pixijs/index/passages.json.gz`, далі
`./df pixijs vectors` заллє колекцію Qdrant (близько пів хвилини на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df pixijs …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/pixijs/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df pixijs sources --why    # перелік джерел і білий список
./df pixijs refresh          # усе: близько 25 хвилин мережею, якщо джерела йдуть блоками
./df pixijs manifest         # оновити паспорт
./df pixijs setup            # Qdrant чи пошук лише по словах
./df pixijs vectors          # залити корпус у docs-pixijs
./df pixijs smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df pixijs serve   # порт 8990
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8990/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user pixijs-docs http://127.0.0.1:8990/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.
