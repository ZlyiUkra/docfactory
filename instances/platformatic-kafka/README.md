# platformatic-kafka — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про @platformatic/kafka — сучасний клієнт Apache Kafka для Node.js на
чистому TypeScript від Platformatic (репозиторій platformatic/kafka, пакет `@platformatic/kafka` на npm) — за
документацією всіх стабільних версій. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця
тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Примірник — четвертий у родині Kafka: сервер окремо (`kafka`), кожен клієнт Node окремо, як у родинах Redis і Mongo
(`kafkajs`, `confluent-kafka-javascript`, цей). Родину закрито: `node-rdkafka` (близько 31 тисячі завантажень за тиждень)
не береться — його заступив клієнт Confluent на тій самій librdkafka.

@platformatic/kafka — молодий клієнт (0.1.0 від 24.04.2025) без рідних модулів: продюсер, консумер, що повертає потік
повідомлень (`MessagesStream`), адмін-клієнт, транзакції, серіалізатори, метрики й канали діагностики Node.js, Confluent
Schema Registry. Близько 270 тисяч завантажень за тиждень до 25.10.2026: 2.11.0 — близько 34 %, 2.9.0 — 21 %, 2.14.0
(найновіша, від 07.10.2026) — 14 %, 2.2.3 — 14 %. Лінія 2 (з 05.05.2026) вимагає Node.js 22.22 чи 24.6 і новіших; лінія 1
лишилася під міткою `v-1.x` (1.35.0).

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df platformatic-kafka <крок>`.

## Версії

Версія — номер випуску; сторінки `docs/` мають версію тегу, з якого взято (остання латка мінорної). Фільтр `version`
бере мажор (`"1"`), мінор (`"2.11"`) або точну версію (`"2.12.1"`). На питання «як це зробити зараз» промпт велить
шукати для 2.11 (найбільше завантажень), а про нове — ще й для 2.14. Сторінка, що не змінилася між версіями, — один документ з усіма ними, тож перелік версій уривка сам показує,
відколи й доки документація казала саме це.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/platformatic-kafka-corpus-2026-10-25.tar.gz` (181 текст, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\platformatic-kafka-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/platformatic-kafka/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/platformatic-kafka-corpus-РРРР-ММ-ДД.tar.gz -C instances/platformatic-kafka corpus raw
find instances/platformatic-kafka/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/platformatic-kafka/raw
gzip -9 -c instances/platformatic-kafka/index/passages.json > instances/platformatic-kafka/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/platformatic-kafka-corpus-2026-10-25.tar.gz -C instances/platformatic-kafka
./df platformatic-kafka smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/platformatic-kafka/index/passages.json.gz`,
далі `./df platformatic-kafka vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df platformatic-kafka …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df platformatic-kafka sources --why   # перелік джерел і білий список
./df platformatic-kafka refresh         # завантажити все задеклароване (близько трьох хвилин)
./df platformatic-kafka manifest        # оновити паспорт
./df platformatic-kafka setup           # Qdrant чи пошук лише по словах
./df platformatic-kafka vectors         # залити корпус у docs-platformatic-kafka
./df platformatic-kafka smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df platformatic-kafka serve          # порт 8889
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8889/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user platformatic-kafka-docs http://127.0.0.1:8889/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `platformatic-kafka-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
