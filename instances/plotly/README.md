# plotly — примірник фабрики docfactory

Цей примірник зібрав документацію plotly.py і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. plotly.py — це бібліотека Python, яка малює інтерактивні графіки. Такий графік відкривається в браузері чи в зошиті
Jupyter, і його можна наближати мишею, рухати й читати значення, наводячи курсор на точку. Графік будують двома способами.
Plotly Express (`plotly.express`, зазвичай `px`) малює готовий графік однією функцією з таблиці pandas. graph_objects
(`plotly.graph_objects`, зазвичай `go`) складає фігуру з окремих рядів даних і дає керувати кожною властивістю.

Для торгового бота тут найважливіші такі речі:

- свічкові графіки й графіки OHLC: класи `go.Candlestick` і `go.Ohlc`, кольори свічок, що ростуть і падають, і повзунок
  діапазону під графіком, який вимикає `xaxis_rangeslider_visible=False`;
- вісь часу без проміжків: `rangebreaks` ховає вихідні, свята й нічні години, коли ринок закритий, і свічки стоять щільно;
- кілька панелей: `make_subplots` ставить обсяги чи індикатор під ціною (`shared_xaxes`, `row_heights`), а `secondary_y` дає
  другу вісь значень на тому самому графіку;
- лінії й позначки: `add_hline` і `add_vrect` малюють рівень ціни чи смугу часу, `add_trace` додає ковзні середні й точки угод,
  `hovertemplate` задає текст підказки під курсором;
- збереження: `write_html` записує інтерактивну сторінку, а `write_image` — картинку PNG чи SVG через пакет Kaleido.

## Скільки цього

Усього 2303 документи і 12 428 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Сторінка з
однаковим текстом у кількох лініях лежить одним документом із переліком цих ліній. Сторінка, що змінювалася, лежить кількома
документами, по одному на кожен варіант тексту.

| Що | Версії | Документів |
|---|---|---|
| посібник сайту plotly.com/python (тека `doc/python` репозиторію), README і посібник з переходу на нові версії | останній патч кожної мінорної лінії 4.4–7.1, 48 ліній | 1444 |
| довідник API plotly.com/python-api-reference: сторінка кожної функції Plotly Express і кожного класу graph_objects | 7.1 | 509 |
| журнал змін `CHANGELOG.md` | кожна стала версія 1.8–7.1 | 161 |
| нотатки релізів GitHub | усі сталі релізи, які GitHub публікує | 99 |
| записи PyPI | усі сталі версії та опис пакета | 92 |

Мітка версії має вигляд `plotly-7.1`. Префікс потрібен, щоб версії plotly не збігалися з версіями інших бібліотек, коли сервери
працюють разом.

**Де є прогалини, хоч ми й брали всі лінії.**

- Теки `doc/` до версії 4.4 у репозиторії не було. Про версії 1.x–4.3 є лише журнал змін і записи PyPI.
- Довідник API сайт публікує лише для поточної версії 7.1. Для старших ліній відповідь про властивість дає посібник тієї лінії
  і журнал змін.
- Дві сторінки довідника, `plotly.io.templates` і `plotly.io.renderers`, не взято: у них немає тексту, лише перелік об'єктів.
  Шаблони й способи показу описано в посібнику, на сторінках `templates` і `renderers`.
- Сторінки довідника API не мають підзаголовків, тож великий клас (наприклад `layout.XAxis`) лежить одним розділом, поділеним на
  багато фрагментів.
- Dash, plotly.js для JavaScript і Plotly для R та Julia тут немає.

Замір `quality` на 14.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 7 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df plotly <крок>`.

| Що | Джерело | Читач |
|----|---------|-------|

| довідник API | `plotly.com/python-api-reference/` | `sphinx-html` |
| журнал змін | `CHANGELOG.md` на тезі `v7.1.0` | `changelog-regex` |
| нотатки релізів | релізи GitHub `plotly/plotly.py` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/plotly/json` | `pypi-versions` |

**Як читається посібник.** Сайт plotly.com/python збирається з файлів markdown теки `doc/python`. Кожен файл починається шапкою
jupytext, де назва сторінки лежить у полі `jupyter.plotly.name`, а адреса — у полі `permalink`. Читач бере назву лише з поля
`title`, тому назви задано полем `path_title`: пара «шлях файла → назва», зібрана з шапок тегів 4.4.1, 4.14.3, 5.24.1 і 7.1.0.
Сторінка, якої на цих тегах не було, дістає назвою ім'я файла. Адресу сторінки на сайті дає поле `site`: здебільшого вона
збігається з ім'ям файла, а 15 сторінок з іншою адресою записано окремо. Сторінки-переадресації на Dash і на статтю про
застосунки машинного навчання не взято.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df plotly serve
```

Порт — `8984`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user plotly-docs http://127.0.0.1:8984/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `plotly-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/plotly-corpus-2026-11-14.tar.gz` (2303 тексти, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\plotly-corpus-2026-11-14.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/plotly/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/plotly-corpus-РРРР-ММ-ДД.tar.gz -C instances/plotly corpus raw
find instances/plotly/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/plotly/raw
gzip -9 -c instances/plotly/index/passages.json > instances/plotly/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/plotly-corpus-2026-11-14.tar.gz -C instances/plotly
./df plotly smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
