# prisma — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Prisma — ORM для TypeScript і Node.js (схема Prisma, Prisma Client,
Prisma Migrate, CLI `prisma`) для PostgreSQL, MySQL, MariaDB, SQLite, SQL Server, CockroachDB і MongoDB, разом із
платформою навколо нього (Prisma Postgres, Accelerate, Optimize, Studio, Console) і з документацією попереднього
продукту, Prisma 1. Джерела — сайт prisma.io/docs (репозиторій prisma/web, раніше prisma/docs), монорепозиторій
prisma/orm (раніше prisma/prisma), архівний репозиторій prisma/prisma1 і реєстр npm, лише англійською й лише стабільні
версії. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену.
Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

План NestJS будує шар даних на Prisma (понад сорок згадок), план Next.js — теж. Prisma змінюється швидко й ламає
сумісність на кожному мажорі: Prisma 5 прибрала `rejectOnNotFound` і зробила JSON-протокол типовим, Prisma 6 підняла
мінімальні версії Node і TypeScript, перейшла з `Buffer` на `Uint8Array` і прибрала `NotFoundError`, Prisma 7 — новий
генератор `prisma-client` без рушія на Rust і з обов'язковим шляхом `output`, адаптери драйверів, конфігурацію
`prisma.config.ts` замість `url` у схемі й прибрані middleware та метрики. Тож потрібен текст документації тієї
версії, з якою працюєш, а не пам'ять моделі.

**Що є що.** **ORM** — бібліотека, що описує дані моделями й складає з цього типізовані запити до бази. **Схема Prisma**
(`schema.prisma`) — файл власною мовою Prisma: джерело даних (`datasource`), генератор клієнта (`generator`), моделі з
полями й атрибутами (`@id`, `@unique`, `@default`, `@relation`). **Prisma Client** — клієнт запитів, який команда
`prisma generate` генерує зі схеми: `findMany`, `create`, `update`, `upsert`, `$transaction`, розширення `$extends`.
**Prisma Migrate** — міграції схеми: `prisma migrate dev` пише файли SQL і застосовує їх, `prisma migrate deploy`
застосовує їх у робочому середовищі, `prisma db push` змінює базу одразу, без файлів (для прототипів). **Адаптер
драйвера** — пакет `@prisma/adapter-*`, через який клієнт говорить із базою звичайним драйвером Node (pg, mysql2,
better-sqlite3…); з Prisma 7 це головний шлях. **Prisma Postgres** — керована база PostgreSQL від самої Prisma,
**Accelerate** — пул з'єднань і кеш запитів перед базою. **Prisma 1** — інший, старший продукт: сервер GraphQL поверх
бази з файлами `prisma.yml` і `datamodel.prisma`, у режимі підтримки відтоді, як вийшла Prisma 2.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

Разом 13 686 документів; фрагментів в індексі — 39 131 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук. Документ сторінки — неповторна редакція: сторінка разом із тим, що вона
вставляє, і в рядку `# версія:` стоять усі версії, де вона була саме такою. Однаковий текст різних версій лягає одним
фрагментом з усіма цими версіями.

Замір `quality`: перша десятка (питання своїми словами, без версії) — по словах 3 із 10, за змістом 4, разом 4; друга,
«як модель» (назви методів, команд і опцій, як велить промпт), — 10 із 10, з першого ж заміру. Своїми словами
(«undone if one fails» замість «rollback», «leave the field out» замість «omit») пошук часто приводить на старі
сторінки Gatsby й Docusaurus, яких на новому сайті вже немає: у них той самий зміст іншими словами. `max_per_doc`
заміряно на 1, 2 і 3: 1 дає на одне влучання більше пошукові за змістом, тож стоїть 1. `fusion_depth` 10 і 20 забирають
одне влучання «як модель», тож не ввімкнений.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, спільний ключ сторінок, що
  переїжджали між теками (`slug_rewrite`), `max_per_doc` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (дерева комітів і тегів, релізи); `.mcp.json` — запис
  HTTP-сервера для Claude Code.
- `requirements.txt` — склад пакетів примірника; працює спільне середовище з кореня (власний `.venv` — лише якщо
  бракує пакетів зі спільних наборів).

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df prisma <крок>`.

## Версії у відповіді

Фільтр `version` бере лінію Prisma: `"7"` — усе 7.x, `"6"` — усе 6.x, `"1"` — Prisma 1. Пакети з власною нумерацією
мають мітку: `"extension-accelerate-2"`, `"extension-read-replicas-0"`, `"extension-optimize-2"`, `"ppg-1"`,
`"studio-core-0"`; голе `"2"` їх не бере. Адаптери, `@prisma/config`, `@prisma/instrumentation` і плагіни sqlcommenter
виходять разом із Prisma й мають ту саму нумерацію. Без фільтра сторінка, що є в кількох версіях, показується один раз —
найновішою редакцією. Нотатки релізів мають версію свого випуску.

Без названої версії промпт велить відповідати для двох найпопулярніших стабільних ліній, бо вони близькі за
завантаженнями npm (тиждень до 13.10.2026, пакет `prisma`): Prisma 7 — 40 % (найбільше 7.10.0, 3,4 млн) і Prisma 6 —
38 % (6.19.3, 4,7 млн); де вони різняться — для обох. Prisma 5 має ще 18 %, кандидати 8.0.0 — 2 %, але це передрелізи,
і їхньої документації тут немає.

Тут немає Prisma ORM 8 (кандидатів 8.0.0-rc) і Prisma Next, блогу prisma.io/blog, Drizzle, TypeORM, Sequelize,

## Сховище сирого

Під час оновлення примірник тримає ще й сирі відповіді — у теці `raw/`, поза git (сховище ввімкнене за
замовчуванням). Правка читача тоді не вимагає нового завантаження: `./df prisma build` збирає тексти зі сховища без
мережі. Попередні версії файлів не видаляються, а переїжджають у `raw/_old/<день>/`. Між оновленнями сховище, як і
тексти, лежить лише в архіві: серверу воно не потрібне. Устрій — у [../../UPDATE.md](../../UPDATE.md), розділ про
`refresh`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/prisma-corpus-2026-10-13.tar.gz` (13 686 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде.
Архів лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/prisma/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/prisma-corpus-РРРР-ММ-ДД.tar.gz -C instances/prisma corpus raw
find instances/prisma/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/prisma/raw
gzip -9 -c instances/prisma/index/passages.json > instances/prisma/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/prisma-corpus-РРРР-ММ-ДД.tar.gz -C instances/prisma
./df prisma smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/prisma/index/passages.json.gz`, далі
`./df prisma vectors` заллє колекцію Qdrant (близько двох годин: 39 тисяч фрагментів на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df prisma …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/prisma/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

```
./df prisma sources --why   # перелік джерел і білий список
./df prisma refresh         # завантажити все задеклароване (~2 години: ~390 дерев, ~13 тисяч файлів, пауза 0,3 с)
./df prisma build           # перезібрати тексти зі сховища сирого, без мережі (після правки читача)
./df prisma manifest        # оновити паспорт
./df prisma setup           # Qdrant чи пошук лише по словах
./df prisma vectors         # залити корпус у docs-prisma (~2 години)
./df prisma smoke           # перевірки
```

Як оновлювати після нових версій — у [UPDATE.md](UPDATE.md).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df prisma serve       # порт 8831
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8831/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user prisma-docs http://127.0.0.1:8831/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт. Інший
шлях — запис `.mcp.json` цієї теки: Claude Code, відкритий у ній, побачить сервер сам.

**3. Перевірити.** `/mcp` — має бути `prisma-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Якщо порт 8831 зайнятий, `serve` падає з «address already in use»: значить,
сервер уже піднято в іншому терміналі. Решта — scope запису — так само, як у
[README примірника nestjs](../nestjs/README.md#спосіб-б--сервер-під-claude-code-http).
