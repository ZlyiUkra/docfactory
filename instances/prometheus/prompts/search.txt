Search the documentation of Prometheus -- the open-source monitoring system and time series database of the CNCF
(repository prometheus/prometheus) -- and of Alertmanager, its companion that deduplicates, groups, silences and
routes alerts (repository prometheus/alertmanager). The corpus holds the `docs/` folder of the Prometheus server at
the last tag of every minor, 1.8 to 3.15 -- getting started, installation, the configuration file (`scrape_config`,
every `*_sd_config` of service discovery, `relabel_config`, `remote_write`, `remote_read`, `tls_config`,
`alerting`), recording and alerting rules, template reference and examples, rule unit testing, PromQL (basics,
operators, functions, examples), the HTTP API, storage (TSDB, retention, remote storage), federation, feature flags,
the command-line flags of `prometheus` and `promtool`, migration to 3.0, native histograms, HTTPS and the web
configuration file; the `docs/` folder of Alertmanager at the last tag of every minor, 0.21 to 0.34 (versions written
"alertmanager-0.34.1") -- configuration (`route`, `receiver`, `inhibit_rule`, every integration such as
`email_config`, `slack_config`, `webhook_config`, `pagerduty_config`), clients, notification templates, the HTTP API,
high availability; the pages of the site prometheus.io itself (introduction, overview, FAQ, glossary, concepts:
data model, metric types, jobs and instances; best practices: naming, instrumentation, histograms and summaries,
alerting, recording rules, remote write; instrumenting: client libraries, exporters, exposition formats, pushing;
guides; tutorials; visualization; operating: security, integrations; the OpenMetrics and Remote-Write
specifications) and its blog, as of 24 October 2026; the stable GitHub releases of Prometheus and Alertmanager.
Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about Prometheus or Alertmanager as they describe themselves -- how to install and run
them, write the configuration file, discover and relabel targets, write a PromQL query (`rate`, `irate`,
`increase`, `histogram_quantile`, `sum by`, `offset`, `@`, subqueries), choose a metric type and name it, write
recording and alerting rules and test them with `promtool`, route, group, inhibit and silence alerts, template a
notification, call the HTTP API, size and retain storage, use remote write, federation, native histograms, the
OpenTelemetry (OTLP) receiver, migrate from 2.x to 3.0 -- and history: since which version a flag, a configuration
field, a PromQL function or a behaviour exists and what changed between versions (the releases list it).

Do not call this for Grafana, Kubernetes, the Prometheus Operator, kube-prometheus-stack and other Helm charts,
Thanos, Cortex, Mimir, Loki, OpenTelemetry, the client libraries themselves (Go, Java, Python, Node.js `prom-client`)
or the exporters (`node_exporter`, `blackbox_exporter`, `pushgateway`) as their own projects: their documentation is
not here -- these pages only show how Prometheus is used with them -- and the search will return excerpts that
merely mention them, with confident-looking titles. The Go source code is not here either.

`version` narrows the search to one release line: a line of one number keeps every document of that major ("3"
keeps Prometheus 3.x), two numbers keep a minor ("3.15"), three an exact version ("3.15.1"); Alertmanager carries the
prefix "alertmanager-" ("alertmanager-0" keeps all of it, "alertmanager-0.34" one minor), so a bare number keeps only
Prometheus and the site. Pages unchanged across versions carry all of them. Every excerpt comes back with
`versions`: each version whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("scrape_config", "relabel_configs",
"kubernetes_sd_config", "metric_relabel_configs", "remote_write", "evaluation_interval", "recording rules",
"alerting rules", "for", "keep_firing_for", "promtool test rules", "rate", "histogram_quantile", "native histograms",
"--storage.tsdb.retention.time", "--web.enable-lifecycle", "--enable-feature", "staleness", "honor_labels",
"route", "group_by", "group_wait", "repeat_interval", "inhibit_rules", "silences", "receivers"), not in the user's
own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word
index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the
question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація Prometheus". Identifiers, parameters and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Prometheus 3.15.1 is the newest release and 3.13 the current long-term support line;
Alertmanager 0.34.1 is the newest: search without `version` first; when the user names their version, search that
line; a question about Alertmanager is answered from the newest "alertmanager-0.34" unless the user names an older
one. Every answer says which version it is for.
