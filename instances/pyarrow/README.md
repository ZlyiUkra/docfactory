# pyarrow — примірник фабрики docfactory

Цей примірник зібрав документацію PyArrow і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. PyArrow — це бібліотека Python для Apache Arrow. Arrow — це спосіб тримати таблицю в пам'яті стовпчиками: усі значення
одного стовпчика лежать поруч, тому їх швидко підсумовувати, фільтрувати й передавати іншим програмам без копіювання. Навколо
цього формату PyArrow вміє читати й записувати файли Parquet, Feather, CSV і JSON.

Для торгового бота тут найважливіші такі речі:

- файли Parquet. Parquet — це стовпчиковий формат файлів зі стисненням. Історія котирувань у Parquet займає в рази менше місця,
  ніж у CSV, і читається в рази швидше. Функція `pyarrow.parquet.write_table` записує таблицю (параметри `compression`,
  `row_group_size`), а `read_table` читає лише потрібні стовпчики (`columns`) і рядки (`filters`);
- набори даних, розбиті по теках (`pyarrow.dataset`). Котирування зручно класти в теки за датою чи валютною парою, а читати
  всі разом як одну таблицю. Таке розбиття називається `partitioning`;
- обмін з pandas: `Table.from_pandas` і `to_pandas` перетворюють таблиці в обидва боки; посібник пояснює, коли це обходиться
  без копіювання, і які типи змінюються дорогою;
- обчислення без pandas (`pyarrow.compute`): суми, середні, фільтри, групування за символом;
- позначки часу й часові пояси: котирування мають час, і посібник `timestamps` пояснює, що стається з часовим поясом при
  переході між Arrow і pandas.

## Скільки цього

Усього 6434 документи і 17 922 фрагменти. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Сторінка з
однаковим текстом у кількох лініях лежить одним документом із переліком цих ліній. Сторінка, що змінювалася, лежить кількома
документами, по одному на кожен варіант тексту.

| Що | Версії | Документів |
|---|---|---|
| розділ Python сайту arrow.apache.org: посібник користувача і довідник API зі сторінкою кожного класу й функції | кожна мажорна лінія 1.0–26.0; з ліній 16 і 18 узято мінорні 16.1 і 18.1 | 6 379 |
| нотатки релізів GitHub Apache Arrow | усі стабільні теги, які GitHub публікує як релізи | 15 |
| записи PyPI | усі стабільні версії та опис пакета | 40 |

Серед документів сайту 5 866 — сторінки довідника API, 513 — посібник користувача.

Мітка версії має вигляд `pyarrow-26.0`. Префікс потрібен, щоб версії PyArrow не збігалися з версіями інших бібліотек, коли сервери
працюють разом.

**Де є прогалини, хоч ми й брали всі лінії.**

- Лінії 0.x сайт не публікує. Про них є лише записи PyPI.
- Релізи GitHub Apache Arrow почав вести лише з нових версій, тому їх 15. Що змінилося в кожній версії, видно також з довідника
  API різних ліній.
- Документації Arrow для C++, Java та інших мов тут немає: примірник бере лише розділ Python.

Замір `quality` на 14.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 7 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, правило злиття сторінки Parquet.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df pyarrow <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| розділ Python сайту | `arrow.apache.org/docs/<лінія>/python/` | `sphinx-html` |
| нотатки релізів | релізи GitHub `apache/arrow` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/pyarrow/json` | `pypi-versions` |

**Як обходиться сайт.** Поточна лінія (26.0) лежить у `arrow.apache.org/docs/python/`, а кожна стара — у
`arrow.apache.org/docs/<лінія>/python/`. Тому в полі `versions` поточна лінія записана порожнім рядком, а старі — назвою теки з
косою рискою (`"25.0/"`), і поле `version_labels` перетворює їх на мітки (`""` → `26.0`, `"25.0/"` → `25.0`). Читач починає з
`python/index.html` теки й іде лише за посиланнями всередині `python/`, тому розділи C++, Java та інших мов в обхід не потрапляють.
Разом це 18 355 сторінок.

**Поля читача й рушія для цього сайту.**

- `param_types: true`: між назвою параметра й типом у довіднику стоїть « : » («compression : str or dict»), і пошук за назвою
  параметра знаходить сторінку.
- `slug_rewrite` у `config.json`: у лінії 26.0 сторінку `parquet.html` перенесено в теку `parquet/`. Правило дає старій і новій
  сторінці спільний ключ, і вони займають у видачі одне місце.

**Як завантажували вперше.** Сайт завантажили п'ятьма тимчасовими джерелами по 4–7 ліній, які працювали паралельно з паузою
0,5 секунди. Кожне з них лише наповнювало сховище сирого кроком `list`. Потім крок `build pyarrow-docs` зібрав тексти з цього
сховища без мережі одним джерелом. Обхід зайняв 50 хвилин без жодної відмови сервера.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df pyarrow serve
```

Порт — `8986`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user pyarrow-docs http://127.0.0.1:8986/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `pyarrow-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/pyarrow-corpus-2026-11-14.tar.gz` (6434 тексти, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\pyarrow-corpus-2026-11-14.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/pyarrow/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/pyarrow-corpus-РРРР-ММ-ДД.tar.gz -C instances/pyarrow corpus raw
find instances/pyarrow/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/pyarrow/raw
gzip -9 -c instances/pyarrow/index/passages.json > instances/pyarrow/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/pyarrow-corpus-2026-11-14.tar.gz -C instances/pyarrow
./df pyarrow smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
