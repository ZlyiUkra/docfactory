# Оновлення корпусу pytest

Корпус живе нагорі: сайт docs.pytest.org, репозиторій GitHub `pytest-dev/pytest` і реєстр PyPI.

Правило: **нічого не видаляється.** Ані `refresh`, ані `manifest` нічого не видаляють. Лише `vectors` прибирає точки своєї колекції,
чиїх фрагментів у корпусі вже немає.

**Спершу — повернути тексти.** Корпус примірника в архіві, а `check`, `refresh` і `manifest` читають файли. Тому перед роботою нижче
тексти розпаковують, а після неї виносять знову: обидві дії описано в
[README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df pytest refresh <id джерела>   # лише те, що змінилося
./df pytest manifest
./df pytest vectors
./df pytest smoke
# Ctrl+C у терміналі з serve, і знову: ./df pytest serve
```

Що міняти, коли вийшов новий випуск:

- **Нова лінія (наприклад 9.3):** `stable` на сайті сам стане 9.3. У `version_labels` джерела `pytest-site` рядок `"stable"`
  змінити на `"9.3"`. Якщо Read the Docs опублікував гілку попередньої лінії (`9.2.x`), дописати її в `versions` другою з міткою
  `"9.2"`; якщо не опублікував — дописати тег останнього патча 9.2 у `tags` джерела `pytest-repo`. Перед цим перевірити, що
  `https://docs.pytest.org/en/9.2.x/index.html` відповідає «200» чи «404».
- **Новий патч наявної лінії:** гілки сайту оновлюються самі. Для ліній із репозиторію тег у `tags` замінити на новий.
- Релізи GitHub і PyPI підтягуються самі.
- Якщо сайт знову перекладе сторінки по теках, старі імена дописують у `slug_rewrite` у `config.json`.

**Read the Docs обмежує частоту запитів.** Пауза між зверненнями — одна секунда, і на сайт ходять не більше двох процесів одночасно:
шість процесів отримують «429» за кілька хвилин.

Якщо `smoke` скаржиться на число фрагментів, корпус підріс: нове число записують в `expected_passages`, а в `expected_note` — коли й
чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу треба виконати `./df pytest quality --show`, переглянути запити зі знаком «-» і перевірити, чи
справді відповідь змінилася. Ціль розширюють лише тоді, коли знайдена сторінка справді відповідає на запит.
