Search the documentation of pytest, the Python framework for writing and running tests. The corpus holds the
docs.pytest.org site of every line that Read the Docs publishes (4.6, 6.2, 7.0-9.0 and stable 9.2): getting started,
the how-to guides, the explanations, the API reference with every function, mark, fixture and hook, the list of
configuration options, the changelog and the deprecations; the doc/en folder of the repository at the last patch of
the lines the site does not publish (2.8-6.1 and 9.1), where the API reference is incomplete; the PyPI records of every
stable version; and the GitHub release notes.

Use this tool for: fixtures (`@pytest.fixture`, scope, `yield` teardown, `autouse`, `conftest.py`, overriding),
parametrization (`@pytest.mark.parametrize`, `pytest.param`, `ids`, indirect), checking exceptions and warnings
(`pytest.raises` with `match`, `pytest.warns`, `pytest.approx`), the built-in fixtures (`tmp_path`, `monkeypatch`,
`capsys`, `caplog`), marks (`skip`, `skipif`, `xfail`, custom marks and `--strict-markers`), selecting and running tests
(`-k`, `-m`, `-x`, `--lf`), configuration (`pytest.ini`, `pyproject.toml`, `addopts`, `testpaths`), writing plugins and
hooks, and what changed or was deprecated between versions. Write the query in English, with the name of the function,
fixture, mark, option or guide, such as `pytest.raises match` or `monkeypatch setenv`. Give a version in the filter when
the answer depends on it.

Do not use it for plugins such as pytest-asyncio, pytest-mock, pytest-cov or pytest-xdist, for `unittest.mock` or for
the Python language: they are not here. Returns the matching excerpts with the versions each one applies to, the source
address and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. pytest 9.2.0 is the newest release. Search without `version` first; when the user names
their pytest version, search that line, written as `pytest-9.2`, `pytest-8.4` or `pytest-7.4`. Every answer about an
option or a fixture says which line it is for.
