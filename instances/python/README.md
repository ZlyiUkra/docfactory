# python — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про мову Python за її документацією. Він знає документацію CPython
на кожну мінорну лінію 2.6–3.15, старий сайт docs.python.org для ліній 1.4–2.5, журнали змін, документи PEP, а ще
менеджери пакетів pip, uv і Poetry, посібник із пакування та документацію PyPI. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`, а тут лежать лише дані домену. Загальний устрій фабрики описано
в [../../README.md](../../README.md).

## Навіщо окремий примірник

Python потрібен у двох курсах лінійки навчання. У курсі Agent Harness Course власний агент пишеться на Python і лише
засобами стандартної бібліотеки. У курсі DevOps Core Course на Python написано вебсервіс, з якого починаються всі
лабораторні. Щоб відповідати на такі питання за документацією, сервер має знати саму мову, стандартну бібліотеку й
те, як поставити пакети.

**CPython** — це основна реалізація мови: саме її встановлюють із python.org, і саме в її репозиторії лежить
офіційна документація. **PEP** (Python Enhancement Proposal) — документ, у якому автори пропонують зміну мови й
пояснюють, навіщо вона потрібна. З PEP видно не лише що зроблено, а й чому.

Разом 16 852 записи паспорта. В індексі 117 603 фрагменти (`expected_passages` у `checks.json`). Замір `quality`
02.11.2026: по словах 4 із 10, за змістом 6, разом 6, «як модель» 10 із 10. Перша десятка нижча, бо запити в ній
написано своїми словами, а одну тему документація описує в багатьох місцях і редакціях. Друга десятка показує, як
працює сервер насправді: модель питає назвами з документації (`json.dumps`, `asyncio.TaskGroup`), як велить промпт.

**Кожна функція має власний розділ.** У файлах документації модуль названо один раз на початку сторінки, а функцію
записано коротко: `dumps`. Читач `_pydomain` дає кожному запису API заголовок із повним іменем: `json.dumps`,
`json.JSONEncoder.default`, `str.join`, `sys.path`. Завдяки цьому запит із назвою функції приводить до опису цієї
функції, а не до загального вступу сторінки.

Чого немає:

- Передрелізів: alpha, beta і rc не беруться, хоча журнали змін описують і їх.
- Ліній 0.9–1.3: окремої документації цих версій ми не перевіряли.
- Вихідного коду стандартної бібліотеки (`Lib/`): її описує документація.
- Сторонніх бібліотек (FastAPI, Flask, pytest): це окремі продукти.
- Таблиць параметрів на сторінках команд pip. Сайт pip генерує їх із коду під час збирання, у файлах репозиторію їх
  немає, тому розділ «Options» порожній. Самі можливості описано в тексті сторінок.
- Прикладів, що лежать окремими файлами (`.. literalinclude::`): читач бачить лише файл сторінки.
- 386 сторінок старого сайту. Перевірка відхилила їх як занадто короткі: у них лише назва або кілька слів, зазвичай
  заглушка майбутнього розділу.

У текстах uv лишилися рядки виносок `!!! note`, а в текстах Poetry — позначки `{{% note %}}`. Вони не заважають
пошуку, і їх можна прибрати під час наступного оновлення.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й контрольна сума кожного тексту.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`, а розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача: нічого поза ним не завантажується.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями до сайту.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента й текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df python <крок>`.

місце у видачі. Сайтові редакції 1.4–2.5 об'єднано полем `families` з тієї самої причини.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт, а серверу досить кешу фрагментів
(`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш зберігає текст кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/python-corpus-2026-11-02.tar.gz` (16 852 тексти й паспорт, сховище
сирого `raw/`, 158 МБ). Перед видаленням текстів архів розпаковано окремо й звірено з диском файл за файлом. Копія
лежить у `C:\Distr\python-corpus-2026-11-02.tar.gz` (звірено за SHA-256). В історії git текстів немає ніколи.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/python/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/python-corpus-РРРР-ММ-ДД.tar.gz -C instances/python corpus raw
find instances/python/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/python/raw
gzip -9 -c instances/python/index/passages.json > instances/python/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й `raw/` видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/python-corpus-2026-11-02.tar.gz -C instances/python
./df python smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють. Частину
перевірок `smoke` пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/python/index/passages.json.gz`.
Далі `./df python vectors` заллє колекцію Qdrant: кілька хвилин на відеокарті, довше на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df python …` бере спільне середовище фабрики (`.venvs/cpu` або
`.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними, описано в кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають. Для самого сервера збирати нічого не треба
— потрібен лише `vectors`, якщо колекції ще немає.

```
./df python sources --why   # перелік джерел і білий список
./df python refresh         # завантажити все задеклароване
./df python manifest        # оновити паспорт
./df python setup           # Qdrant чи пошук лише по словах
./df python vectors         # залити корпус у docs-python
./df python smoke           # перевірки
```

Повне завантаження одним процесом триває близько двох годин. Незалежні джерела можна завантажувати окремими
процесами: чотири блоки (`cpython`; `site-*`; `cpython-news` і `cpython-history`; решта) упоралися за 55 хвилин. Сам
`cpython` ділити на блоки за версіями не варто: тоді сторінка з однаковим текстом стала б кількома документами.

Порядок оновлення описано в [UPDATE.md](UPDATE.md).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df python serve          # порт 8944
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8944/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user python-docs http://127.0.0.1:8944/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер у цей файл. Перевірка:
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою, бо WSL пересилає порт.
