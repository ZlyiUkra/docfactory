# Оновлення корпусу python

Документація CPython, pip, uv і Poetry береться з тегів, тож уже записане не міняється: нова версія — це новий запис у
`tags` джерела, а не перезапис старого. PEP, посібник із пакування й документація PyPI закріплені на коміті: щоб їх
оновити, у `tags` замінюють коміт на новий. Реєстр PyPI читається щоразу заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `manifest` не видаляють файлів. `vectors` прибирає лише точки
власної колекції, чиїх фрагментів більше немає в корпусі.

**Спершу — повернути тексти.** Корпус примірника в архіві, а `refresh` і `manifest` працюють із файлами. Як розпакувати
й запакувати тексти, описано в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df python check                       # чи змінилося щось нагорі за джерелом
./df python refresh cpython --missing   # дозавантажити нове чи продовжити перерване
./df python refresh peps pypi-pip pypi-uv pypi-poetry
./df python manifest
./df python vectors
./df python smoke
./df python quality
# Ctrl+C у терміналі з serve, і знову: ./df python serve
```

**Новий патч чи нова мінорна Python.** У `tags` джерел `cpython` і `cpython-news` тег останнього патча лінії замінюють
новим (`v3.15.3` → `"3.15"`) або дописують нову лінію. Тег `cpython-history` міняють на найновіший.

**Нова мінорна pip, uv чи Poetry.** У `tags` відповідного джерела дописують тег із міткою `pip-<лінія>`, `uv-<лінія>`,
`poetry-<лінія>`. У джерелах `pip-news`, `uv-news`, `poetry-news` тег замінюють на найновіший.

**Нова основна лінія за завантаженнями.** Версію за замовчуванням (зараз 3.12) записано в `prompts/search.txt` і
`prompts/agent.txt`. Чинні частки дає `https://pypistats.org/api/packages/pip/python_minor`.

**Що перевірити після оновлення.**

- Сторінка pip чи Poetry, що переїхала в нову теку, потребує нового правила в `slug_rewrite` у `config.json`.
- Нова директива в документації CPython лишається в тексті рядком `.. назва::`. Її треба додати до
  `engine/readers/_pydomain.py`.

Якщо `smoke` скаржиться на число фрагментів, корпус підріс. Нове число записують в `expected_passages`, а в
`expected_note` — коли й чому його знято. Останній результат `quality` записують у README, розділ «Скільки цього».
