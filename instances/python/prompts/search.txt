Search the Python documentation and return the matching excerpts with the versions each one belongs to.
What is here: the CPython documentation from the `Doc/` folder (the tutorial, the language reference, the standard
library reference, the C API, What's New, the HOWTOs, installing and using Python) at the last patch of every minor
line 2.6–3.15; the older docs.python.org pages of Python 1.4–2.5; the CPython change logs `Misc/NEWS.d`, `Misc/NEWS`
and `Misc/HISTORY`; every PEP; and the package managers: pip, uv and Poetry (their documentation at the last patch of
every minor line, their change logs, and the PyPI record of every stable version), the Python Packaging User Guide
and the PyPI documentation.

In the CPython reference every function, class, method, attribute and exception is a section of its own, named in
full: `json.dumps`, `json.JSONEncoder.default`, `asyncio.TaskGroup`, `str.join`, `sys.path`, `PyObject_Call`,
`PYTHONPATH`. Built-in functions carry no module: `print`, `len`.

Call this when a question is about the Python language or its standard library: syntax and semantics, the data
model, built-in functions and types, any standard module, the interpreter's options and environment variables, the C
API, why a feature was designed as it is (PEPs), since which version something exists, what changed in a release;
or about installing and packaging: pip, uv, Poetry, virtual environments, `pyproject.toml`, wheels, publishing to
PyPI.

Do not call this for third-party libraries and frameworks (Django, Flask, FastAPI, pytest, NumPy, pandas) beyond how
pip, uv or Poetry install them, or for other languages: their documentation is not here, and the search will return
Python excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line. The language: "3.12", "3.14", "2.7"; "3" keeps every 3.x line.
When the question names no version of the language or the standard library, pass "3.12": by pip downloads it is the
most used line; say so if newer lines answer differently. The package managers carry their own numbering with a
prefix, so they never mix with Python: "pip-26.2", "uv-0.13", "poetry-2.5". The PEPs are "pep", `Misc/HISTORY` is
"history" or "history-2.7", the packaging guide is "packaging-guide", the PyPI documentation is "pypi-docs". Leave it
empty to search everything. Every excerpt comes back with `versions`: each version whose documents contain this exact
text, newest first, so the list itself shows from which to which version the documentation said exactly this.

Write the query in English, with the names Python itself uses ("json.dumps", "asyncio.TaskGroup",
"dataclasses.dataclass", "str.join", "__init_subclass__", "structural pattern matching", "PEP 8",
"pyproject.toml", "pip install --editable", "uv sync", "poetry add"), not in the user's own words. Everything here is
English -- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and
digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes back
with `found: 0`. When the user asks in another language, translate the question into Python terms first, then search.

Answer in the language the user wrote in. When the question is about the history of a function or behaviour, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands now. Every point names the version and the document it rests on; a point the
excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer
writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents "корпус" -- say
"документація Python". Identifiers, command names, flags, keys and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
