# rabbitmq — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про RabbitMQ — брокер повідомлень з відкритим кодом для AMQP 0-9-1, AMQP
1.0, MQTT, STOMP і потоків RabbitMQ Streams (сайт rabbitmq.com, репозиторії rabbitmq/rabbitmq-website і
rabbitmq/rabbitmq-server) — за документацією всіх версій, які зберіг сайт, і нотатками кожного релізу. Код спільний і
лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики —
у [../../README.md](../../README.md).

## Навіщо окремий примірник

RabbitMQ — брокер, що розносить повідомлення від продюсерів до черг через обмінники (exchanges) і прив'язки (bindings):
черги класичні, кворумні (реплікація на Raft) і потоки, підтвердження публікації й доставки, prefetch, dead lettering,
TTL, ліміти, політики, кластер, плагіни Shovel і Federation. У плані NestJS (фулстек-родина) RabbitMQ стоїть у «знати,
що існує» серед транспортів мікросервісів поруч із Kafka і NATS.

Поведінка між версіями помітно змінювалася: у 4.0 прибрано класичні дзеркальні черги, кворумні черги й потоки стали
реплікованими типами, Khepri заступив Mnesia як сховище метаданих, змінювалися типові ключі `rabbitmq.conf`. Тут
документація кожної версії сайту і нотатки кожного релізу зібрані в одному місці, з номером версії біля кожного уривка.

Примірник — перший у родині RabbitMQ: сервер окремо, кожен клієнт Node окремо, як у родинах Redis, Mongo і Kafka. Далі в
родині — `amqplib`, `amqp-connection-manager` і `@golevelup/nestjs-rabbitmq`.

Давніші гілки (`v3.6.x`) записано у власному XML старого сайту, і їх не взято. Та сама сторінка всіх версій — одна
родина (`families` і `slug_rewrite` у `config.json`).

Чого немає. Клієнтських бібліотек як окремих проєктів (amqplib, amqp-connection-manager, транспорт RabbitMQ у NestJS —
окремі примірники родини), туторіалів інших мов, специфікацій AMQP, Erlang, Kubernetes і Docker. Нотатки 5.0.0 —
чернетка ще не випущеної версії.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, `families`, `slug_rewrite` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df rabbitmq <крок>`.

## Версії

Версія сторінки сайту — версія сайту, з якого її взято (`3.11`…`4.4`); нотатки релізів несуть точну версію (`4.3.7`).
Фільтр `version` бере мажор (`"3"`), мінор (`"4.3"`) або точну версію (`"3.13.7"`). Статистики завантажень за версіями
RabbitMQ не публікує, тож промпт відповідає для лінії, яку проєкт латає: 4.4 (4.4.0 від 19.10.2026) і 4.3 (4.3.7 від
20.10.2026), а коли йдеться про старий кластер — ще й для 3.13.

## Родина RabbitMQ: піднімати разом

Цей примірник — частина родини RabbitMQ: сам брокер і три бібліотеки для Node.js. Питання про клієнта впирається в
поведінку брокера (підтвердження, prefetch, dead lettering, типи черг), а питання про модуль NestJS — у те, що роблять
під ним amqplib і amqp-connection-manager. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї
теки перелічує всі чотири сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `rabbitmq` | `rabbitmq-docs` | 8890 | сам RabbitMQ 3.11–4.4: типи черг, обмінники, підтвердження, кластер, `rabbitmq.conf`, нотатки релізів |
| `amqplib` | `amqplib-docs` | 8891 | клієнт amqplib для Node.js (на ньому транспорт RMQ NestJS) |
| `amqp-connection-manager` | `amqp-connection-manager-docs` | 8892 | перепідключення поверх amqplib, друга половина транспорту RMQ NestJS |
| `golevelup-nestjs-rabbitmq` | `golevelup-nestjs-rabbitmq-docs` | 8893 | модуль NestJS `@golevelup/nestjs-rabbitmq` з `@RabbitSubscribe` і `@RabbitRPC` |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/rabbitmq-corpus-2026-10-25.tar.gz` (1726 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\rabbitmq-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/rabbitmq/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/rabbitmq-corpus-РРРР-ММ-ДД.tar.gz -C instances/rabbitmq corpus raw
find instances/rabbitmq/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/rabbitmq/raw
gzip -9 -c instances/rabbitmq/index/passages.json > instances/rabbitmq/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/rabbitmq-corpus-2026-10-25.tar.gz -C instances/rabbitmq
./df rabbitmq smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/rabbitmq/index/passages.json.gz`, далі
`./df rabbitmq vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df rabbitmq …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df rabbitmq sources --why   # перелік джерел і білий список
./df rabbitmq refresh         # завантажити все задеклароване (близько 20 хвилин)
./df rabbitmq manifest        # оновити паспорт
./df rabbitmq setup           # Qdrant чи пошук лише по словах
./df rabbitmq vectors         # залити корпус у docs-rabbitmq
./df rabbitmq smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df rabbitmq serve          # порт 8890
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8890/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user rabbitmq-docs http://127.0.0.1:8890/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `rabbitmq-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
