# react-email — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про React Email — бібліотеку для верстки HTML-листів на React і
TypeScript від команди Resend (сайт react.email/docs, репозиторій resend/react-email, реєстр npm) — за документацією
кожної мінорної версії, пакетами й журналами змін. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Верстка листа — окреме ремесло: поштові клієнти не знають сучасного CSS, тож React Email дає компоненти (`Html`,
`Body`, `Container`, `Section`, `Row`, `Column`, `Text`, `Button`, `Img`, `Preview`, `Tailwind`…), які стають таблицями й
вбудованими стилями, функцію `render()` до HTML і простого тексту та CLI `email dev` з переглядом у браузері. У плані
Next.js (фулстек-родина) React Email стоїть у «знати, що існує» разом із Resend.

Між мажорами змінилося, звідки все імпортувати: до 5.x компоненти лежали в `@react-email/components` (або в окремих
пакетах на кожен компонент), а `render()` — у `@react-email/render`; у 6.0 усе це перейшло в сам пакет `react-email`, а
сервер перегляду `@react-email/preview-server` став `@react-email/ui`. Тут документація кожної мінорної зібрана в одному
місці, з номером версії біля кожного уривка.

Примірник — другий у родині Resend, після `resend`.

Журнали змін. Changesets пише заголовок кожної версії, навіть коли пакет лише підтягнуто за іншими, і такий запис
порожній. Читач `changelog-regex` тепер порожні записи пропускає — раніше кожен із них давав збій (тут таких було 79).
`@react-email/components` і `@react-email/tailwind` у 6.0 влилися в `react-email`, тож їхні журнали взято з останнього
тегу кожного (1.0.12 і 2.0.7).

Чого немає. README самого пакета `react-email`: 17 його версій мають тарбол понад 50 МБ (у пакет входив сервер
перегляду), а README на 1,7 КБ дублює сайт. Немає й самого Resend (окремий примірник родини), React, Tailwind CSS і
поштових сервісів як окремих проєктів, коду компонентів і тестів.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, `families`, `slug_rewrite` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df react-email <крок>`.

## Версії

Сторінка сайту несе версію випуску `react-email`, з тегу якого її взято (`6.11.3`, `5.2.10`); README й записи журналів —
версію свого пакета (`@react-email/components` 1.x, `@react-email/render` 2.x), тож фільтр лінії змішує пакети з
однаковим номером. Фільтр `version` бере мажор (`"6"`), мінор (`"6.11"`) або точну версію (`"5.2.10"`). За
завантаженнями npm за тиждень до 25.10.2026 лінія 6 `react-email` тримає 60 %, лінія 5 — 18 %, тож промпт відповідає
для 6.x, а коли код імпортує з `@react-email/components` — ще й для 5.x і каже, що змінює оновлення до 6.0.

## Родина Resend: піднімати разом

Цей примірник — частина родини Resend: сам сервіс надсилання з його SDK для Node.js і React Email, яким верстають
листи. Типовий шлях листа проходить обидва: шаблон на React Email, `render()` чи проп `react`, далі
`resend.emails.send()`. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує обидва
сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `resend` | `resend-docs` | 8896 | API Resend, дашборд, вебхуки, домени й доставлюваність, SDK `resend` для Node.js 0.1–6.34 |
| `react-email` | `react-email-docs` | 8897 | React Email 2.1–6.11: компоненти, `render()`, CLI і перегляд, інтеграції з поштовими сервісами |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/react-email-corpus-2026-10-25.tar.gz` (654 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\react-email-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/react-email/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/react-email-corpus-РРРР-ММ-ДД.tar.gz -C instances/react-email corpus raw
find instances/react-email/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/react-email/raw
gzip -9 -c instances/react-email/index/passages.json > instances/react-email/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/react-email-corpus-2026-10-25.tar.gz -C instances/react-email
./df react-email smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/react-email/index/passages.json.gz`, далі
`./df react-email vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df react-email …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df react-email sources --why   # перелік джерел і білий список
./df react-email refresh         # завантажити все задеклароване (близько 6 хвилин)
./df react-email manifest        # оновити паспорт
./df react-email setup           # Qdrant чи пошук лише по словах
./df react-email vectors         # залити корпус у docs-react-email
./df react-email smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df react-email serve          # порт 8897
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8897/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user react-email-docs http://127.0.0.1:8897/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `react-email-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
