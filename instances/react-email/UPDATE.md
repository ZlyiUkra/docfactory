# Оновлення корпусу react-email

Тут оголошено руками теги й коміти: сайт — з останнього тегу `react-email@*` кожної мінорної 2.1–6.11, журнали змін — з
коміту e0561e164 (тег react-email@6.11.3) і з останніх тегів `@react-email/components@1.0.12` та
`@react-email/tailwind@2.0.7`. README пакетів і реєстр npm беруться щоразу заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

1. Нова мінорна (тег `react-email@6.12.0` у resend/react-email): SHA коміту тегу дає перелік
   `https://api.github.com/repos/resend/react-email/tags` (поле `commit.sha`).
   Поточний запис поля `tags` джерела `re-docs-6.11` переносять у `re-docs-history` (з тією ж версією), а в
   `re-docs-6.11` ставлять новий SHA з новою версією; новий патч поточної мінорної просто заміняє її SHA.
2. Журнали змін: у `url`, `cite` і `within` джерел `re-changelog-react-email`, `-render`, `-editor`, `-ui`,
   `-create-email` SHA e0561e164 замінюють SHA нового тегу.

```
./df react-email check                 # чи змінилося щось нагорі за джерелом
./df react-email refresh               # повне перезавантаження, близько 6 хвилин
./df react-email manifest
./df react-email vectors
./df react-email smoke
# Ctrl+C у терміналі з serve, і знову: ./df react-email serve
```

Якщо змінилося співвідношення завантажень ліній (на 25.10.2026 лінія 6 — 60 %, лінія 5 — 18 %), — у
`prompts/search.txt` (абзац «Which version to search first») і `prompts/agent.txt` замінити лінії й числа; у
`checks.json`, у десятках `quality` і `quality_model`, звірити цілі там, де питання про поточну поведінку.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен: без нього GitHub дає 60 звернень на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df react-email quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
