Search the documentation of React Email -- the library for building HTML emails with React and TypeScript, made by
the Resend team (site react.email/docs, repository resend/react-email, the npm registry). The corpus holds the site as
it stood at the last release of every minor of the package `react-email` from 2.1 to 6.11 (getting started:
automatic, manual and monorepo setup, migrating from MJML, updating between majors; the components Html, Head, Body,
Container, Section, Row, Column, Text, Heading, Button, Link, Img, Hr, Preview, Font, Tailwind, Markdown, CodeBlock,
CodeInline with their props; the utility `render()` to HTML and plain text; the CLI `email dev`, `email build`,
`email start`, `email export` and the preview server; integrations for sending with Resend, Nodemailer, SendGrid,
Postmark, AWS SES, Mailgun and others; internationalization guides; the visual editor @react-email/editor; deployment
and contributing); the README of every stable version of `@react-email/components` and `@react-email/render`; the npm
registry of five packages with their versions and release dates; and the changelogs of `react-email`,
`@react-email/components`, `@react-email/render`, `@react-email/tailwind`, `@react-email/editor`, `@react-email/ui` and
`create-email`. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about React Email as it describes itself -- which component to use and which props it
takes, how `render()` turns a template into HTML or plain text and its options, how to preview emails locally with
`email dev`, how the Tailwind component works and what it cannot do, how to send a rendered email through a provider,
how to set up a project or a monorepo -- and history: since which version a component or option exists, what changed
between majors (in 6.0 the components and `render()` moved into the package `react-email` and the preview server
became `@react-email/ui`; the updating page and the changelogs list it).

Do not call this for Resend itself -- its API, SDK, domains and webhooks are the Resend documentation (resend-docs) --
nor for React, Tailwind CSS, Next.js, Nodemailer or the other email providers as their own projects: their
documentation is not here -- these pages only show how React Email is used with them -- and the search will return
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line. React Email carries plain numbers: a line of one number keeps every
document of that major ("6" keeps 6.x), two numbers keep a minor ("6.11"), three an exact version ("5.2.10"). The pages
of the site carry the version of the `react-email` release they were taken from ("6.11.3", "5.2.10"); the READMEs and
the changelog entries carry the version of their own package (`@react-email/components` is at 1.x, `@react-email/render`
at 2.x), so a line filter mixes the packages that share a number. Every excerpt comes back with `versions`: each version
whose documents contain this exact text, newest first -- a page that stayed the same across versions is returned once,
with all of them listed, so the list itself shows from which to which version the documentation said exactly this.

Write the query in English, with the names the documentation itself uses ("render", "toPlainText", "plainText",
"pretty", "Html", "Head", "Body", "Container", "Section", "Row", "Column", "Text", "Heading", "Button", "Link", "Img",
"Hr", "Preview", "Font", "Tailwind", "Markdown", "CodeBlock", "email dev", "email export", "preview server",
"integrations", "updating"), not in the user's own words. Everything here is English -- the excerpts, the word index
and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written in
Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the user
asks in another language, translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація React Email". Identifiers, props and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. By npm downloads in the week before 25 October 2026 the line 6 of `react-email` holds
60 % (6.11.3 is the newest), the line 5 -- 18 %; `@react-email/components` 1.x -- 66 %. Answer how-to questions for
6.x: search `version` "6.11" first; when the user's code imports from `@react-email/components` or
`@react-email/render`, it is on 5.x or older -- search "5.2" as well and say what the update to 6.0 changes. Search
without `version` when the question is about history, or when the line gave nothing. Every answer says which version
it is for.
