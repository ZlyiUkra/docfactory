# react-hook-form — примірник фабрики docfactory

Дев'ятий примірник фабрики: захищений MCP-сервер, що відповідає на питання про React Hook Form (RHF) за офіційною
документацією всіх його версій — від 0.0.12 (березень 2019) до поточної 7.x і бет 8.0, разом з кожним alpha, beta,
rc і next, — за TypeScript-сигнатурами публічного API, README кожної версії, журналом змін і нотатками релізів.
Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену.
Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо вся історія

RHF кілька разів міняв API з мажорною версією: `validationSchema` став `resolver` (v6), `ref={register}` —
`{...register('name')}` (v7), `errors` переїхав у `formState`, а v8 знову перекроює частину API. Проєкти на старих
версіях живуть роками, і питання звучить «як це було в моїй версії», «з якої версії є `useFormState`» і «на що
замінили». Відповідь дає лише документація саме тієї версії.

Складність у тому, що в сайту react-hook-form.com **немає версійних тегів**: документація живе в окремому
репозиторії, а текст до 2023 року лежав не в markdown, а прямо в коді сторінок React. Звідси нові читачі й
правило «знімок на кожну версію npm», описане нижче.

Разом 3 464 документи; фрагментів в індексі — 7 402 (`expected_passages` у `checks.json`). Фрагментів мало
відносно документів, бо незмінні розділи сотень редакцій зливаються в один (`revision_suffix`).

Замір `quality` на першому корпусі: перша десятка (питання своїми словами, без версії) — по словах 3 із 10, за
змістом 4, разом 4; друга, «як модель» (назвами API, з `version "7"`, як велить промпт), — 9 із 10. Цілі першої
десятки — не лише сучасні MDX-сторінки, а й ті самі розділи старих редакцій сайту (`website/src/Api`,
`components/ApiPage`, `data/en/api`, `data/V6/en/api`): для старої версії це правильна відповідь. Промахи:

- **Без версії видачу займають сусідні API.** На «очистити форму після відправки» перші місця беруть `<Form />` і
  опції `useForm`, на «чи змінив користувач щось» — `resetField` і журнал змін. Тому промпт велить на питання «як
  зараз» шукати з `version "7"`: друга десятка з ним влучає 9 разів.
- **Єдиний промах другої десятки** — «formState isDirty dirtyFields»: місця зайняли сторінки `resetField`, де ті
  самі слова стоять в опціях `keepDirty`. Правила промпту, яке б виправило це без підгонки під запит, немає.

**Версія у відповіді.** Кожна відповідь каже, для якої версії вона. Якщо користувач версії не назвав, модель
відповідає для лінії за замовчуванням 7.x, пише це прямо й пропонує назвати свою версію для точнішої відповіді;
текст, знайдений лише в старших версіях, подає з цими версіями, а не як поточний.

## Що в цій теці

- `corpus/` — документація звичайними текстовими файлами; поруч `index.json` — паспорт, тобто опис копії: адреса,
  дата завантаження й сума тексту кожного документа.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача. Теги для сигнатур лежать тут, у
  полі `tags` джерела `rhf-api`; версії для сайту й README приходять з реєстру npm.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df react-hook-form <крок>`.

Нові читачі додано разом із цим примірником, у `engine/readers/`; чинних не змінено.

Особливості, які варто знати:

- **Три епохи сайту.** До 20.05.2019 (версії 0.x–3.7) сайт — тека `website/` у репозиторії бібліотеки (Create React
  App). Далі — окремий репозиторій `react-hook-form/documentation`: до 2023 року Gatsby, де текст лежить у JSX
  сторінок і в об'єктах даних TSX (`src/data/en/api.tsx`), з 2023 — Next.js і MDX (`src/content/docs/…`). Назва
  документа — шлях файла без `src/`: `content/docs/useform/reset`, `data/en/api`, `components/ApiPage`.
- **Знімок на кожну версію npm.** Версійних тегів у сайту немає, тож на кожну з 1100 версій береться стан гілки
  `master` на мить перед наступним релізом тієї ж лінії: тоді документація й описувала цю версію, разом із
  правками, дописаними вже після її виходу. Для останньої версії лінії мить — наступний реліз пакета взагалі, для
  найновішої — сьогоднішній стан. Можлива похибка — на одну версію: опис можливості, залитий на сайт до її
  публікації, припишеться попередній версії.
- **Передрелізи — окрема лінія.** Усі alpha, beta, rc і next одного номера (`8.0.0-alpha.5`, `8.0.0-beta.4`) —
  одна лінія зі своїми знімками; версією документа стає власний номер передрелізу, тож фільтр `version: "8"` їх
  знаходить. Бети v8 виходять паралельно з 7.x, і сайт у `master` описує обидві лінії одразу: у знімків бет той
  самий текст, що й у свіжих 7.x.
- **Теки старих ліній.** Після виходу v7 документація v5 і v6 жила поруч у теках `V5/`, `v6/`. Такі теки належать
  лише своїй лінії: знімок версії 6.x бере тільки їх, решта знімків їх відкидає (`line_marker`).
- **Лише англійська.** Переклади 2019–2023 років (es, jp, kr, pt, ru, zh) відкинуто.
- **Текст із коду.** Для епохи Gatsby текст витягує простий сканер JSX/TSX (`engine/readers/_jsx.py`): слова
  сторінки на місці, розкладка — приблизна. Сторінки-компоненти тієї епохи часто несуть лише скелет із заголовків,
  бо текст вони брали з файлів даних; самі файли даних — окремі документи. Приклади коду (`codeExamples/`) теж
  окремі документи.
- **README — з репозиторію, а не з CDN.** Реєстр npm для кожної версії пише коміт, з якого її опубліковано
  (`gitHead`), і README береться з кореня репозиторію на цьому коміті. CDN із вмістом пакетів (jsDelivr, unpkg)
  білий список дозволити вузько не може, лише весь хост. У 9 версій (серед них 7.71.0, 6.5.1, 0.0.15) коміту
  публікації на GitHub немає — їхнього README в корпусі нема.
- **Журнал змін із повторами.** Три версії (6.12.0, 7.0.0-alpha.2, 7.0.0-rc.7) записано в `CHANGELOG.md` двічі;
  обидва записи лежать в одному документі версії, кожен зі своєю датою.
- **Resources — лише поточний стан.** Каталог чужих матеріалів з анотаціями сайту, без самих статей. Посилання з
  часом застарівають.
- **Редакції того самого файла зливаються (`revision_suffix`)**, як у `react-router`: ім'я документа несе хеш
  вмісту, і без поля незмінний розділ двох редакцій лишався б двома фрагментами.

## Межі, про які треба пам'ятати

`@hookform/resolvers`, `@hookform/devtools`, `@hookform/error-message` і Form Builder тут немає, як і документації
бібліотек, з якими RHF використовують (Zod, Yup, MUI). Alpha, beta, rc і next — не релізи: текст, що є лише в них,
міг так і не вийти, і промпт велить моделі казати про це прямо.

## Установка venv

```
cd instances/react-hook-form
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Якщо корпус уже лежить у `corpus/`, потрібен лише `vectors`, якщо колекції ще немає.

```
./df react-hook-form sources --why   # перелік джерел і білий список
./df react-hook-form refresh         # завантажити все задеклароване (~1 година 40 хвилин)
./df react-hook-form manifest        # оновити паспорт
./df react-hook-form setup           # Qdrant чи пошук лише по словах
./df react-hook-form vectors         # залити корпус у docs-react-hook-form (~25 хвилин)
./df react-hook-form smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd /mnt/c/Projects/fwdays/docfactory
./df react-hook-form serve          # порт 8768
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8768/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user react-hook-form-docs http://127.0.0.1:8768/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `react-hook-form-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).

## На іншій машині

Інше вікно VS Code на тій самій машині нічого, крім кроків 1–3 вище, не потребує: сервер один, клієнтів скільки
завгодно. На іншій машині (теж WSL) бракує трьох речей, яких немає в git: venv примірника, `.env` і векторів у
Qdrant.

**1. Код і корпус.** Корпус лежить у git, тож досить отримати репозиторій зі свіжими комітами (`git clone` або
`git pull` після того, як їх запушено) і перейти в його корінь.

**2. Venv примірника** — за розділом «Установка venv» вище. `.env` для пошуку не потрібен: токен GitHub треба лише
для `refresh`, ключ Anthropic — лише для `ask`.

**3. Спосіб пошуку.** Два варіанти:

```
./df react-hook-form setup --vectors      # з Qdrant: потрібен Docker; вектори рахуються ~25 хвилин
./df react-hook-form setup --no-vectors   # лише пошук по словах: без Docker, одразу
```

Без векторів сервер працює так само, лише перефразоване питання, що не має спільних слів із документацією, може не
знайтися. Перейти на вектори можна будь-коли тією самою командою з `--vectors`.

**4. Перевірка, сервер, клієнт.**

```
./df react-hook-form smoke          # усі перевірки мають бути ok
./df react-hook-form serve          # порт 8768, лишити жити
```

і далі — кроки 2–3 розділу «Сервер під Claude Code» на тій машині, де відкрито VS Code.
