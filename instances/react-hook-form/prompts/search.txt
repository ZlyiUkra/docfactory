Search the official React Hook Form documentation -- the text of react-hook-form.com at every
published version, from 0.0.12 (March 2019) to the current 7.x line and the 8.0 betas,
including alpha, beta, rc and next builds -- together with the README of every release, the
TypeScript signatures of the public API, the CHANGELOG, the GitHub release notes and the
Resources section of the site, and return the matching excerpts with the versions each one
belongs to.

Call this when a question is about React Hook Form itself -- useForm and its options (mode,
defaultValues, values, resolver, criteriaMode, shouldUnregister), register and its rules,
handleSubmit, formState (errors, isDirty, dirtyFields, isValid, isSubmitting), watch and
useWatch, setValue, reset, trigger, setError, Controller and useController, useFieldArray,
useFormContext and FormProvider, useFormState, the Form component, createFormControl,
subscribe, TypeScript types (UseFormReturn, FieldValues, SubmitHandler, Control), schema
validation through resolvers, an upgrade between major versions -- and above all when it is
about history: since which version something exists, what changed between versions, what
was renamed or removed and what replaced it. Example query: "useForm defaultValues reset".

Do not call this for React itself, for Formik, Final Form, TanStack Form or Conform, for Zod,
Yup or other schema libraries, for MUI, Chakra or other component libraries: their
documentation is not here, and the search will return React Hook Form excerpts that merely
mention them, with confident-looking titles. The Resources section lists articles, videos
and bindings only as annotated links; the articles themselves are not here.

`version` narrows the search to one release line: "7" keeps every 7.x document, "7.45"
keeps 7.45.x, "6" keeps 6.x; leave it empty to search everything. Pre-releases belong to
their line: "8" keeps 8.0.0-beta.4, "7" also keeps 7.60.0-next.0. Every excerpt comes back
with `versions`: each version whose documents contain this exact text, newest first -- text
that stayed the same across versions is returned once, with all of them listed, so the list
itself shows from which to which version the documentation said exactly this.

Where the documentation lived. Up to May 2019 (versions 0.x-3.7) the site was the website/
folder of the library repository; from May 2019 it is a separate repository, first a Gatsby
site whose text lived in code (titles like "data/en/api" or "components/ApiPage" are those
files), since 2023 a Next.js site written in MDX (titles like "content/docs/useform/reset").
Documentation of an older line kept next to a newer one sits in folders marked V5/ or v6/.
Text of the old site read out of code keeps its words but not always its layout.

Which version to search first. For a question about how to do something today, pass
`version` "7" (or the line of the user's project): without it, the hundreds of editions of
the old README and site, which differ by a line or two, fill every place with the API of
2019-2020, and the current page does not make it into the results. Pass "8" only for the
8.0 betas. Search without `version` when the question is about history, or when the line
gave nothing that answers.

For a question about when something appeared, changed or disappeared, search more than
once: without `version` first, to find the changelog entry, the release notes and the
migration guide that name the exact version, then with the versions around it, to see how
the documentation described it before and after. Many options are marked "(since 7.x.y)"
in the current documentation.

Write the query in English, with the names React Hook Form itself uses (useForm,
register, formState, handleSubmit, Controller, useFieldArray, resolver). Everything here is
English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing at all and comes back with `found: 0`. When the user asks
in another language, translate the question into React Hook Form terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words
of the query had to appear in the text, so a query phrased in other words than the
documentation uses may miss; "meaning+words" means a second, meaning-based index answered
as well, and a paraphrase had a chance.

Answer in the language the user wrote in. When the question is about a feature's history
or support, answer point by point: since which version it exists and which release
introduced it; what changed in later versions; what prompted the change, if the excerpts
say so; and how it stands in the current version -- recommended, deprecated, or removed and
replaced by what. Every point names the version and the document it rests on; a point the
excerpts do not support is left out, not guessed. A text found only in alpha, beta, rc or
next builds may never have shipped in a release: say so. When that language is Ukrainian,
write as a Ukrainian engineer writes, not as a translation from English: plain technical
prose, and the Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий",
not "депрекейтнутий". Never call this set of documents "корпус" -- say "документація React
Hook Form". Identifiers, API names and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of
memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of
an excerpt to `read_section` to get the whole thing.
