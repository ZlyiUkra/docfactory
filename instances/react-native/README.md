# react-native — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про React Native — фреймворк для нативних застосунків Android та iOS
на React — за офіційною документацією всіх стабільних версій, від 0.1 (березень 2015) до поточної 0.x: сайт
reactnative.dev у стані кожної мінорної версії, розділ Architecture, блог, сторінки про релізи, нотатки релізів на
GitHub, журнал змін і історія пакета в реєстрі npm. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

Expo — фреймворк і платформа поверх React Native — має власний примірник [`expo`](../expo/README.md).

## Навіщо вся історія

React Native досі в лінії 0.x, але за одинадцять років змінився до невпізнання. 0.60 (липень 2019) приніс
autolinking (нативні залежності підключаються самі) і AndroidX; 0.68 (березень 2022) дав увімкнути нову архітектуру
(рендерер Fabric, нативні модулі TurboModules, зв'язок JS і нативного коду через JSI); з 0.76 (жовтень 2024) вона
типова, а з 0.82 стара архітектура вже не вмикається. Цілі компоненти пішли з ядра в бібліотеки спільноти
(ListView, WebView, Picker, AsyncStorage), а спосіб писати власний нативний модуль мінявся тричі: Native Modules
через міст, Turbo Native Modules і Fabric Native Components з Codegen (генератором коду інтерфейсу).

Старі лінії досі встановлюють: за тиждень 0.86 завантажують ~40 % від усіх завантажень пакета, 0.81 — 16 % (її бере
Expo SDK 54), 0.85 — 10 %, 0.83 — 8 %, 0.87 (найновіша) — 5 %. Питання часто звучить «як це робилося в моїй версії» чи
«з якої версії є `X`», і відповідь дає лише документація саме тієї версії. Тож корпус — не одна редакція сайту, а вся
його історія, і кожен документ несе свої версії.

Перша десятка — переказ питання своїми словами, і промахи такі:

- **Власний нативний view.** На «show my own native platform widget inside the app screen» по словах першими стоять
  Toast-модуль і віджет «Today» із розширень застосунку; за змістом сторінка `native-components-android` лише п'ята,
  і злиття її опускає.
- **Клавіатура.** На «move the text field up so the on-screen keyboard does not cover it» жоден спосіб не приносить
  сторінки `KeyboardAvoidingView`. За змістом першим стоїть розділ `improvingux#manage-layout-when-keyboard-is-visible`,
  який якраз радить цей компонент, але в ціль він не входить.
- **Різний код для платформ.** На «run different code on iPhone and on Android phones» обидва способи беруть сторінки
  запуску на пристрої й симуляторі (слова «run», «iPhone», «Android»), а `platform-specific-code` не знаходить жоден.
- По словах ще два промахи — список, що «гальмує», і перехід в інший застосунок, — але за змістом ціль знаходиться,
  і злиття її втримує.

Десятка «як модель» — запити назвами компонентів, API й понять, як велить промпт, з `version "0.86"`, а один —
`ListView dataSource` з `version "0.44"`. На першому замірі вона дала 8 із 10: на «Turbo Native Modules Codegen»
першими стояли сторінка `turbo-native-modules-android` і `the-new-architecture-using-codegen`, а на
«PermissionsAndroid request» — приклад сторінки з тим самим викликом `PermissionsAndroid.request`. Знаюча людина
прийняла б їх як відповідь, і їх дописано в ціль.

Поле `max_per_doc` заміряно 0/1/2/3: перша десятка 7/7/7/7 разом, «як модель» 10/9/9/9 — поле не ввімкнене.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df react-native <крок>`.

Особливості, які варто знати:

- **Теки старих версій сайт прибирає.** На гілці лежать лише 0.77 і новіші; 0.60–0.72 сайт переніс на архівний сайт
  у серпні 2023-го, 0.73–0.76 — у серпні 2025-го. Читач бере кожну таку теку зі знімка перед комітом, що її видалив,
  тобто в останньому стані, з правками, дописаними вже після виходу версії. Архівний коміт 2023 року лишив у теці 0.69
  один файл (його прибрав наступний коміт), і знімок перед ним — не версія, а залишок; тоді читач робить крок назад.
- **0.5–0.59 — Docusaurus 1.** До переходу сайту на Docusaurus 2 (29.10.2020) тека версії тримала лише сторінки, що
  змінилися відтоді, як зрізали попередню версію, а решту сайт брав зі старших версій. Читач складає повний набір так
  само і лишає тільки сторінки з меню версії: тека 0.5 має 135 файлів, але частина з них описує компоненти пізніших
  версій (FlatList у меню сайту з'являється лише з 0.44), і меню 0.5 їх не показувало.
- **Документ — неповторний текст сторінки**, і він несе всі версії, де сторінка була саме такою: `FlatList` однаковий
  у 0.80–0.87 — один документ із вісьмома версіями.
- **Тека `docs/` не береться** — це документація ще не випущеної версії. Так само не беруться RC, nightly
  (`0.0.0-…`) і заглушка 1000.0.0 у реєстрі.
- **Репозиторії переїхали.** facebook/react-native і facebook/react-native-website тепер react/react-native і
  react/react-native-website; старі адреси API відповідають переадресацією, яку оновлювач поза білим списком не йде.
- **Журнал змін розбито на чотири файли** за лініями (0.5x, 0.6x, 0.7x і кореневий для 0.80+). Кореневий файл має
  й записи старших версій, але це лише відсилки «See CHANGELOG-0.Xx», і джерело `rn-changelog` їх пропускає: інакше
  відсилка займала б місце повного запису у видачі. Нотатки релізів до 0.77 — короткий анонс із посиланням на
  журнал, з 0.78 — увесь список змін.
- **Лише англійська.** Сайт перекладів не має.

## Межі, про які треба пам'ятати

Expo, React Navigation, Reanimated, Gesture Handler та інших бібліотек спільноти тут немає, як і React загалом — лише
те, що про них пише документація React Native; для Expo є примірник `expo`. Сайт 0.60–0.76 читається з репозиторію,
а не з архівних сайтів, тож посилання документів цих версій ведуть на GitHub. Код прикладів SnackPlayer лишається
блоками коду, а живих прикладів Snack (запуску в браузері) в тексті немає. Діаграми розділу Architecture — картинки,
і в тексті від них лишається лише підпис.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/react-native-corpus-2026-10-11.tar.gz` (3 503 тексти і паспорт; перед
видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде. Архів
лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/react-native-corpus-2026-10-11.tar.gz -C instances/react-native
./df react-native smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/react-native/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/react-native-corpus-РРРР-ММ-ДД.tar.gz -C instances/react-native corpus
find instances/react-native/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/react-native/index/passages.json > instances/react-native/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/react-native/index/passages.json.gz`,
далі `./df react-native vectors` заллє колекцію Qdrant.

## Установка venv

```
cd instances/react-native
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df react-native sources --why   # перелік джерел і білий список
./df react-native refresh         # завантажити все задеклароване (~1.5 години)
./df react-native manifest        # оновити паспорт
./df react-native setup           # Qdrant чи пошук лише по словах
./df react-native vectors         # залити корпус у docs-react-native
./df react-native smoke           # перевірки
```

Перші ~2 хвилини `refresh` журнал мовчить, а `corpus/` порожній: читач сайту проходить ~80 комітів і дерева знімків і
лише потім починає писати файли. Без токена GitHub перелік ішов би годинними вікнами по 60 звернень.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df react-native serve          # порт 8818
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8818/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user react-native-docs http://127.0.0.1:8818/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `react-native-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
