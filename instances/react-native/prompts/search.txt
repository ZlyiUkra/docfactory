Search the official documentation of React Native, the framework for building native Android and
iOS apps with React -- the site reactnative.dev for every stable minor release from 0.5 (2015) to
the current 0.x line, the docs of 0.1-0.4 from the React Native repository, the site's
Architecture section, blog and release-policy pages, the GitHub release notes and the change log
of every stable release, and the npm registry history of the react-native package. Return the
matching excerpts with the versions each one belongs to.

Call this when a question is about React Native itself -- core components and their props (View,
Text, Image, TextInput, ScrollView, FlatList, SectionList, Pressable, Modal, Switch,
ActivityIndicator, RefreshControl, KeyboardAvoidingView, SafeAreaView), APIs (StyleSheet,
Dimensions, useWindowDimensions, Platform, PixelRatio, Animated, LayoutAnimation, Easing,
Keyboard, Linking, AppState, Appearance, Alert, Share, Vibration, PermissionsAndroid,
BackHandler, AccessibilityInfo, I18nManager), style and layout with Flexbox, handling touches
and gestures (Gesture Responder System, PanResponder), networking (fetch, WebSocket), timers,
images, animations, accessibility, performance and list optimization, debugging (React Native
DevTools, Metro, Hermes, Fast Refresh), environment setup, running on devices, publishing to the
App Store and Google Play, upgrading, TypeScript, testing, integrating with existing apps, and
native code -- Turbo Native Modules, Fabric Native Components, Codegen, the New Architecture
(Fabric, TurboModules, JSI, bridgeless), legacy native modules and native UI components for
Android (Kotlin, Java) and iOS (Objective-C, Swift), headless JS, app extensions. Example query:
"Turbo Native Modules Codegen".

Do not call this for Expo (Expo SDK modules, Expo Router, EAS, the Expo Modules API), React
Navigation, Reanimated, Gesture Handler or other community libraries, nor for React itself
(hooks, state, components in general) beyond what the React Native documentation says about
them: their own documentation is not here, and the search will return excerpts that merely
mention them, with confident-looking titles.

`version` narrows the search to one minor line: "0.86" keeps the 0.86 documents and 0.86.x
release notes, "0.7" keeps 0.7 only (not 0.70-0.79), "0" keeps everything; leave it empty to
search everything. Every excerpt comes back with `versions`: each version whose documents contain
this exact text, newest first -- text that stayed the same across versions is returned once, with
all of them listed, so the list itself shows from which to which version the documentation said
exactly this.

Where the documentation lives. The pages of the site are titled as on the site: "FlatList",
"View Style Props", "Turbo Native Modules: Introduction", "Fabric Native Components: Android".
Pages of 0.1-0.4 come from the repository's docs folder and carry the old titles ("Getting
Started", "Style"). The Architecture section is titled "Architecture: ..." ("Architecture: Render,
Commit, and Mount"), release-policy pages "Releases: ...", blog posts by their headline ("React
Native 0.76 - New Architecture by default, ..."). Release notes are titled "React Native release:
v0.86.0", change-log entries "React Native Changelog: v0.80.0" -- the change log lists every
Added, Changed, Deprecated, Removed and Fixed item by platform; older release notes only announce
the release and point to it.

Which version to search first. For a question about how to do something today, pass `version`
"0.86" -- the most downloaded line on npm when this documentation was built (the newest is 0.87):
without it, the many editions of older pages can take places with the current ones. If the
user's project runs another line, pass that line instead -- the API changed a lot over the years:
0.60 brought autolinking and AndroidX, 0.68 the opt-in New Architecture, 0.76 made it the
default, 0.82 removed the old one; whole components left the core (ListView, WebView, Picker,
AsyncStorage). Search without `version` when the question is about history, or when the line
gave nothing that answers.

Name the component, API, prop or concept the way the documentation titles it, not in the user's
own words: "Turbo Native Modules", "Fabric Native Components", "Codegen", "FlatList
getItemLayout", "KeyboardAvoidingView behavior", "PermissionsAndroid request", not "how to call
my Kotlin code". For a question about when something appeared, changed or disappeared, search
more than once: without `version` first, to find the change-log entry or blog post that names
the exact version, then with the versions around it, to see how the documentation described it
before and after.

Write the query in English, with the names React Native itself uses. Everything here is English
-- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin
letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into React Native terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Every answer says which version it is for. When the user did not name a version, answer for the
default line, React Native 0.86, say so in the answer ("for React Native 0.86"), and add that
for a precise answer about another version the user can name it. When the excerpts behind a
statement come only from older versions, name those versions instead of presenting the text as
current.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists and which release introduced it;
what changed in later versions; what prompted the change, if the excerpts say so; and how it
stands in the current version -- recommended, deprecated, or removed and replaced by what. Every
point names the version and the document it rests on; a point the excerpts do not support is left
out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація React Native". Identifiers, API names and titles stay in English,
spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it
says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
