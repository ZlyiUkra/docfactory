Search the official React Router documentation -- every published version of it, from
0.x to the current line, including pre-releases, nightly and experimental builds, the
TypeDoc API reference, the changelogs and the release notes -- and return the matching
excerpts together with the versions each one belongs to.

Call this when a question is about React Router itself -- routes and route modules,
loaders and actions, navigation, Link and NavLink, the hooks (useNavigate,
useLoaderData, useFetcher, useParams...), data routers, framework mode and its Vite
plugin, server rendering, @react-router/dev, node, serve and the other packages, an
upgrade between major versions -- and above all when it is about history: since which
version something exists, what changed between versions, what was deprecated or
removed and what replaced it. Example query: "useNavigate relative path".

Do not call this for React itself (hooks like useState, components, react-dom), Remix
before its merge into React Router 7, Next.js, TanStack Router, Redux or any other
library: their documentation is not here, and the search will return React Router
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "7" keeps every 7.x document, "6.4"
keeps 6.4.x, "0.13" keeps 0.13.x; "experimental" and "nightly" keep the builds of those
kinds (their tags carry no meaningful number); leave it empty to search everything.
Pre-releases belong to their line: "7" also keeps 7.0.0-pre.1. Every excerpt comes back
with `versions`: each version whose documents contain this exact text, newest first --
text that stayed the same across versions is returned once, with all of them listed, so
the list itself shows from which to which version the documentation said exactly this.

For a question about when something appeared, changed or disappeared, search more than
once: without `version` first, to find the changelog entry, the release notes and the
upgrade guide that name the exact version, then with the versions around it, to see how
the documentation described it before and after.

Write the query in English, with the names React Router itself uses (createBrowserRouter,
useLoaderData, <Routes>, withRouter, browserHistory). Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only
latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing at all and comes back with `found: 0`. When the user
asks in another language, translate the question into React Router terms first, then
search.

The `search` field of the result says how the excerpts were found: "words" means the
words of the query had to appear in the text, so a query phrased in other words than
the documentation uses may miss; "meaning+words" means a second, meaning-based index
answered as well, and a paraphrase had a chance.

Answer in the language the user wrote in. When the question is about a feature's
history or support, answer point by point: since which version it exists and which
release introduced it; what changed in later versions; what prompted the change, if
the excerpts say so; and how it stands in the current version -- recommended,
deprecated, or removed and replaced by what. Every point names the version and the
document it rests on; a point the excerpts do not support is left out, not guessed. A
text found only in nightly or experimental builds never shipped in a release: say so.
When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one
exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this
set of documents "корпус" -- say "документація React Router". Identifiers, API names and
titles stay in English, spelled exactly as the documentation spells them. Build the
answer out of the excerpts that came back, not out of memory: if an excerpt was cut,
read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default
3; `version` is optional, see above. Excerpt text is cut at 600 characters -- pass the
`id` of an excerpt to `read_section` to get the whole thing.
