# react-three-fiber — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про React Three Fiber — React-рендерер для three.js (`Canvas`,
об'єкти three.js як JSX, хуки `useFrame`, `useThree`, `useLoader`, події, продуктивність, тестування) — і drei,
бібліотеку готових компонентів тієї ж команди pmndrs (контроли, камери, завантажувачі, `Environment`, `Html`, `Text`,
`Instances`). Документація — з останнього тегу кожної мінорної Fiber 1.0–9.8 і drei 10.0–10.7, README кожної стабільної
версії п'яти пакетів, релізи GitHub; лише англійською. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Fiber не має власного API three.js: `<mesh>` — це `THREE.Mesh`, а пропси — його властивості. Власне в Fiber — спосіб
описати сцену декларативно (`args`, `attach`, дефіси у вкладених властивостях), цикл кадрів (`useFrame`), події з
raycaster, `Suspense` для завантаження й правила продуктивності. Пакет двічі міняв ім'я й розкладку документації:
`react-three-fiber` 1.x–6.0 з довідником у `markdown/` і README, з 2021 року — `@react-three/fiber` у монорепозиторії, з
8.0 — тека `docs/` сайту docs.pmnd.rs. drei до 10.0 (2025) тримав увесь довідник у README, і для проєктів на drei 9.x
саме README тієї версії — єдина документація. Fiber 8 (React 18) досі дає 18 % завантажень, тож відповідь мусить
знати, до якої версії вона.

**Що є що.** **Canvas** — компонент, що створює сцену, камеру й рендерер three.js і рендерить дітей у них;
**useFrame** — хук, що виконує функцію на кожному кадрі; **args** — проп з аргументами конструктора класу three.js;
**attach** — куди прив'язати об'єкт у батьківському (`attach="material"`); **drei** — бібліотека компонентів поверх
Fiber (`<OrbitControls>`, `<Environment>`, `useGLTF`).

## Звідки документація

- **Документація Fiber з тегів.** Читач `ghdocs-history` бере `docs/` (MDX із шапкою `title`), `markdown/` і
  `packages/test-renderer/markdown` з останнього тегу кожної мінорної. Теги в репозиторії — `v9.8.2`, іноді голі
  `8.13.7`; де тегу немає зовсім (7.0, 8.0, 8.11, 9.2), стоїть SHA коміту публікації з реєстру npm (`gitHead`).
  Мінорна 8.4 не ввійшла: її `gitHead` у репозиторії немає, а тегу так само.
- **Документація drei** — тека `docs/` з drei 10.0; документи несуть ім'я з префіксом `drei-` (`name_prefix`), бо
  `docs/getting-started/introduction.mdx` є в обох репозиторіях, і без префікса обидві сторінки мали б один ключ.
  Версії drei і test-renderer несуть префікс (`drei-10.7.9`, `test-renderer-9.0.0`), інакше фільтр «9» змішав би
  drei 9.x із Fiber 9.
- **README.** Файл у репозиторії Fiber зветься `readme.md`, а не `README.md`, і лежить у `packages/fiber/`; `gitHead`
  у реєстрі `@react-three/fiber` часто вказує на коміт, якого в репозиторії немає, тож адреса README береться з тегу
  `v{version}`. README drei до 10.0 — увесь довідник бібліотеки (77 КБ у 9.0.0).
- **Релізи** — `ghreleases-stable` з тегами `v…`; drei випускає реліз на кожен коміт (semantic-release), тож їх 858.

## Родина three.js: піднімати разом

Цей примірник — частина родини three.js: сама бібліотека й React Three Fiber з drei. Кожен елемент JSX у Fiber
(`<mesh>`, `<meshStandardMaterial>`) — це клас three.js з його пропсами, тож питання про Fiber часто закінчується в
довіднику three.js — і навпаки, графік чи сцену на React пишуть через Fiber. Тому примірники родини піднімають у Claude
Code разом, а `.mcp.json` цієї теки перелічує обидва сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `threejs` | `threejs-docs` | 8935 | three.js r54–r186: довідник, доповнення, посібник, приклади, вікі, релізи |
| `react-three-fiber` | `react-three-fiber-docs` | 8936 | @react-three/fiber 1.0–9.8 і drei 1.5–10.7: документація, README, релізи, реєстр npm |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
кореневому README.md, розділ «Родини примірників».

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/react-three-fiber-corpus-2026-10-29.tar.gz` (тексти, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\react-three-fiber-corpus-2026-10-29.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git
текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/react-three-fiber/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/react-three-fiber-corpus-РРРР-ММ-ДД.tar.gz -C instances/react-three-fiber corpus raw
find instances/react-three-fiber/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/react-three-fiber/raw
gzip -9 -c instances/react-three-fiber/index/passages.json > instances/react-three-fiber/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/react-three-fiber-corpus-2026-10-29.tar.gz -C instances/react-three-fiber
./df react-three-fiber smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати:
`gunzip -k instances/react-three-fiber/index/passages.json.gz`, далі `./df react-three-fiber vectors` заллє колекцію
Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df react-three-fiber …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище». Свій `.env` примірник тримає в `instances/react-three-fiber/.env` (`cp .env.example .env`; для
кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df react-three-fiber sources --why    # перелік джерел і білий список
./df react-three-fiber refresh          # усе: близько 15 хвилин мережею (паузи 0,1 с)
./df react-three-fiber manifest         # оновити паспорт
./df react-three-fiber setup            # Qdrant чи пошук лише по словах
./df react-three-fiber vectors          # залити корпус у docs-react-three-fiber
./df react-three-fiber smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df react-three-fiber serve   # порт 8936
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8936/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user react-three-fiber-docs http://127.0.0.1:8936/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `react-three-fiber-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
