# Оновлення корпусу react-three-fiber

README (`npm-readme-*`) і реєстр (`npm-*`) беруть версії з опису пакетів у реєстрі npm, тож новий реліз Fiber чи drei
потрапляє туди сам, а релізи GitHub (`releases-*`) читаються з API щоразу заново. Передрелізи не беруться
(`skip_versions: "-"` у README, `ghreleases-stable` — без дефіса в номері).

Руками оголошено:

- **Документація Fiber** (`fiber-docs`): поле `tags` — останній тег кожної мінорної, найновіший першим
  (`"v9.8.2": "9.8.2"`). Де тегу в репозиторії немає, стоїть SHA коміту публікації (`gitHead` в описі версії в реєстрі
  npm). Нова мінорна — новий рядок на початку `tags`; новий латковий реліз тієї самої мінорної — заміна тегу в її
  рядку.
- **Документація drei** (`drei-docs`): так само, з версією під префіксом (`"v10.7.9": "drei-10.7.9"`). Тека `docs/` є з
  drei 10.0; старіші версії описує README (`npm-readme-drei`), який береться сам.
- **Новий пакет @react-three/\*** (наприклад, коли test-renderer чи eslint-plugin почнуть мати власну документацію) —
  нові джерела за зразком наявних, з префіксом версії.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df react-three-fiber refresh fiber-docs npm-readme-fiber npm-fiber releases-fiber   # або drei-docs і джерела drei
./df react-three-fiber refresh --missing    # джерела, яких не названо, лише докачуються
./df react-three-fiber manifest
./df react-three-fiber vectors
./df react-three-fiber smoke
# Ctrl+C у терміналі з serve, і знову: ./df react-three-fiber serve
```

Названі джерела оновлюються повністю, не `--missing`: у документі стоять усі версії, де текст був таким, тож новий
реліз змінює й старі документи (незмінна сторінка дописує нову версію в рядок `# версія:`). Документи редакцій, яких
у новому прогоні вже немає, лишаються в теці — їх переносять в окрему теку поза корпусом руками, перш ніж рахувати
вектори. Сховище сирого `raw/` повертається з архіву разом із текстами, тож після правки читача тексти
перебудовуються без мережі: `./df react-three-fiber build <id>`.

Якщо змінилися найпоширеніші лінії (на 29.10.2026 — Fiber 9.8, близько 82 % завантажень за мажором 9; drei 10.7):

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` переглянути лінії за
  замовчуванням;
- у `checks.json`, у десятці `quality_model`, замінити `"9.8"` і `"drei-10.7"` і звірити цілі.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) потрібен для дерев тегів і сторінок релізів (drei має близько тисячі релізів —
десять сторінок API).

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df react-three-fiber quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка
промпту, знову замір. Останній результат — у README, розділ «Скільки цього».
