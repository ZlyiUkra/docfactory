Search the React Three Fiber documentation and return the matching excerpts with the versions each one belongs to.
What is here: the documentation of @react-three/fiber (repository pmndrs/react-three-fiber, the site docs.pmnd.rs)
at the last release of every minor line -- in 8.x and 9.x the docs folder: getting started (introduction,
installation, your first scene, examples), the API (Canvas, objects, properties and events, hooks useThree,
useFrame, useLoader, useGraph, additional exports), advanced (scaling performance, pitfalls), tutorials (v8 and
v9 migration guides, events and interaction, loading models and textures, basic animations, using with React
Spring, TypeScript, testing), in 1.x–6.x the markdown folder (API, recipes, pitfalls) and the test renderer
docs; the documentation of drei (repository pmndrs/drei) 10.0 to 10.7 -- controls (OrbitControls,
CameraControls, PresentationControls…), cameras, gizmos, loaders (useGLTF, useTexture, Gltf), abstractions
(Text, Html, Billboard, Line, Image, Clone…), shaders, staging (Environment, Sky, Stage, ContactShadows,
Center, Bounds, Float…), performances (Instances, Merged, Detailed, Preload, BakeShadows…), portals, shapes,
misc -- and the README of drei 1.5 to 9.x, which was its whole reference before 10.0; the README of every stable
version and the npm registry history (versions, dates, peer dependencies) of @react-three/fiber,
react-three-fiber, @react-three/drei, drei and @react-three/test-renderer; the GitHub release notes of both
repositories.

Call this when a question is about React Three Fiber: Canvas and its props (camera, gl, shadows, dpr, frameloop,
events), declaring three.js objects as JSX (mesh, boxGeometry, meshStandardMaterial, the args prop, attach,
constructor arguments, setting nested properties with dashes), hooks (useThree, useFrame, useLoader, useGraph),
events and the raycaster (onClick, onPointerOver, stopPropagation), loading models with useLoader and GLTFLoader,
Suspense, performance (instancing, on-demand rendering, regress), extending with extend, portals (createPortal),
testing with @react-three/test-renderer, migrating between major versions -- and drei: its controls, cameras,
loaders, staging helpers, Text, Html, Environment, Instances -- and history: since which version a component or
hook exists, what changed in a release.

Do not call this for three.js itself (classes, geometries, materials, the WebGLRenderer, the three.js manual) --
it is in the threejs-docs server of the same family -- nor for React or React Native themselves, for
@react-three/rapier, @react-three/postprocessing, @react-three/xr, zustand, leva or other pmndrs libraries, or
for JavaScript or TypeScript language questions: their documentation is not here, and the search will return
Fiber excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "9.8" keeps every 9.8.x document of @react-three/fiber, "9"
every 9.x, "8.18" the last Fiber 8 line; leave it empty to search everything. drei and the test renderer carry
their own numbering with a prefix, so they never mix with Fiber: "drei-10.7", "drei-9", "test-renderer-9". Every
excerpt comes back with `versions`: each version whose documents contain this exact text, newest first, so the
list itself shows from which to which version the documentation said exactly this.

Write the query in English, with the names Fiber and drei themselves use ("useFrame", "Canvas frameloop",
"useLoader GLTFLoader", "OrbitControls", "Environment preset", "useGLTF"), not in the user's own words.
Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the
question into Fiber terms first, then search.

Answer in the language the user wrote in. When the question is about a hook's or component's history or
support, answer point by point: since which version it exists; what changed in later versions; what prompted
the change, if the excerpts say so; and how it stands in the current version. Every point names the version and
the document it rests on; a point the excerpts do not support is left out, not guessed. When that language is
Ukrainian, write as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and
the Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never
call this set of documents "корпус" -- say "документація React Three Fiber". Identifiers, prop names and titles
stay in English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated:
true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Fiber 9 carries about 82% of the weekly downloads (React 19), Fiber 8 about 18%
(React 18). Search with `version` "9.8" for a question about how to do something; if the user is on React 18 or
names Fiber 8, search "8.18". For drei search "drei-10.7"; for drei questions on older projects the README of
the matching drei version carries the reference. Search without `version` when the question is about history or
when the line gave nothing. Every answer says which version it is for; when the user did not name one, answer
for Fiber 9.8 and drei 10.7 and say so. When the excerpts behind a statement come only from older versions, name
those versions instead of presenting the text as current.
