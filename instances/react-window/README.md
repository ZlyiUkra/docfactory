# react-window — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про react-window за офіційною документацією всіх його стабільних
версій — від 1.0.0 (2018) до поточної 2.x, — разом із журналом змін і нотатками релізів, документацією супутніх
пакетів react-window-infinite-loader і react-virtualized-auto-sizer, типами `@types/react-window` з DefinitelyTyped і
історією версій чотирьох пакетів у реєстрі npm. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо обидві лінії

react-window має дві лінії з різним API. 1.x (2018–2024) — чотири компоненти `FixedSizeList`, `VariableSizeList`,
`FixedSizeGrid`, `VariableSizeGrid` з `itemCount`, `itemSize` і функцією-нащадком; 2.x (з серпня 2025) — бібліотеку
переписано: `List` і `Grid` з `rowComponent`, `rowCount`, `rowHeight`, `rowProps`, хук `useDynamicRowHeight` для рядків
невідомої висоти, власні типи замість DefinitelyTyped. При цьому 1.x досі має найбільше завантажень: на 09.10.2026 за
тиждень — 5,3 млн у лінії 1.x (з них 3,5 млн — 1.8.11) проти 1,1 млн у 2.x. Тож питання до документації звучить
«як це було в моїй версії» не рідше, ніж «як зараз», і корпус — обидві лінії, кожна версія, а промпт велить без
названої версії відповідати для обох.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача. Перелік версій лежить саме тут, у
  полях `tags` джерел `rw-readme`, `rw-site-v1` і `rw-site-v2`: оновлювач не питає в GitHub, які теги існують.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df react-window <крок>`.

| сайт 2.x | `src/routes.ts`, сторінки, приклади й довідка JSON на кожному тезі 2.x | `react-window-site-v2`, новий |
| журнали змін | `CHANGELOG.md` гілки за замовчуванням кожного з трьох репозиторіїв | `changelog-heading`, новий |
| нотатки релізів | GitHub API | `ghreleases` |

| реєстр npm | registry.npmjs.org, одне звернення на пакет | `npm-versions` |

Разом із примірником додано три модулі читачів:

- **`engine/readers/reactwindow.py`** — сайти обох ліній. Markdown у них немає: текст живе в коді сторінок React. У
  1.x довідник компонента — масиви `PROPS` і `METHODS` об'єктів `{ name: 'children', type: 'component', … }`, і
  кожен об'єкт стає розділом «## children» з типом і значенням за замовчуванням; код прикладів вставляється з модулів
  `website/src/code/`, назви сторінок прикладів беруться з меню сайту. У 2.x заголовок — атрибут
  `<Header title="…">`, код прикладів — з `src/routes/**/examples/` між позначками `// <begin>` і `// <end>`, а
  сторінки властивостей і імперативного API — з довідки JSON, яку сайт генерує з JSDoc (до 2.2.3 — формат
  react-docgen-typescript, з 2.2.4 — власний). Одиниця — сторінка разом з усім, що вона вставляє: однакова на
  кількох версіях — один документ з усіма цими версіями.
- **`engine/readers/changelogheading.py`** — журнал змін, де заголовок версії буває будь-якого рівня:
  react-window-infinite-loader пише версії «###», react-virtualized-auto-sizer — «##», але «# 2.0.0» серед них.
  `changelog-named` бачить лише «##», і запис 2.0.0 з інструкцією переходу ліг би в документ 2.0.1.
- **`engine/readers/dthistory.py`** — історія файла типів DefinitelyTyped. Тегів версій там немає, а реєстр npm для
  пакетів `@types` не пише `gitHead`; зате публікатор випускає версію одразу після злиття правки, тож версія несе
  файл таким, яким він був у найновішому коміті, не пізнішому за мить її публікації. Розділ документа — оголошення
  верхнього рівня (`interface ListProps`, `class FixedSizeList`) разом із коментарем JSDoc над ним.

Особливості, які варто знати:

- **Сайту 1.x більше немає.** react-window-v1.vercel.app віддає 404, а react-window.now.sh переадресовує на сайт 2.x,
  тож сторінки 1.x цитуються файлом у репозиторії на тезі. Сторінки 2.x, маршрут яких є на сайті зараз, цитуються на
  react-window.vercel.app; старі сторінки, яких там уже немає, — файлом у репозиторії.
- **Версії без тегу.** 1.2.3, 1.8.7 і 1.8.8 вийшли в npm без тегу в репозиторії; у полі `tags` вони стоять комітом
  `gitHead` з реєстру — GitHub віддає дерево й файли і за комітом.
- **Супутні пакети нумеруються самі.** react-window-infinite-loader 1.x–2.x і react-virtualized-auto-sizer 1.x–2.x
  мають власні версії; їхні документи несуть версію свого пакета. README трьох версій немає: для infinite-loader 1.0.7
  реєстр не записав коміт, а тегу немає; коміти auto-sizer 1.0.3 і 1.0.4 на GitHub не знаходяться (404).
- **`@types/react-window` — лише для 1.x.** 2.0.0 — заглушка («react-window provides its own type definitions»), тож
  джерело її не бере; документ реєстру npm про неї каже.
- **Редакції тієї самої сторінки зливаються (`revision_suffix`)**: ім'я документа несе хеш вмісту, і незмінний розділ
  двох редакцій лишається одним фрагментом.
- **Альф немає.** 2.0.0-alpha.* та інші передрелізи в документацію не взято; документи реєстру npm їх перелічують.

## Межі, про які треба пам'ятати

React, react-virtualized і TanStack Virtual тут немає (для TanStack Virtual є свій примірник `tanstack-virtual`).
Сайти супутніх пакетів не взято — лише README і журнали змін. README сторінок 2.x містить довідник у таблицях HTML;
у корпусі це рядки «назва — опис» без розмітки, а охайні розділи по властивостях дають сторінки `List: props` і
`Grid: props` сайту 2.x.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/react-window-corpus-2026-10-09.tar.gz` (0,2 МБ, 357 текстів і
паспорт; перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів
немає ніде. Архів лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/react-window-corpus-2026-10-09.tar.gz -C instances/react-window
./df react-window smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/react-window/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/react-window-corpus-РРРР-ММ-ДД.tar.gz -C instances/react-window corpus
find instances/react-window/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/react-window/index/passages.json > instances/react-window/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k
instances/react-window/index/passages.json.gz`, далі `./df react-window vectors` заллє колекцію Qdrant (~1 хвилина).

## Установка venv

```
cd instances/react-window
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df react-window sources --why   # перелік джерел і білий список
./df react-window refresh         # завантажити все задеклароване (~10 хвилин)
./df react-window manifest        # оновити паспорт
./df react-window setup           # Qdrant чи пошук лише по словах
./df react-window vectors         # залити корпус у docs-react-window (~1 хвилина)
./df react-window smoke           # перевірки
```

Перші хвилини `refresh` журнал мовчить: читачі сайтів проходять дерево кожної версії й читають сторінки, щоб знати,
що вони вставляють, і лише потім пишуть файли.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df react-window serve          # порт 8804
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8804/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user react-window-docs http://127.0.0.1:8804/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `react-window-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
