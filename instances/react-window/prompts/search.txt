Search the official react-window documentation -- every stable version of it, from 1.0.0 to the
current 2.x line -- together with its changelog and GitHub release notes, the README and changelog
of react-window-infinite-loader and react-virtualized-auto-sizer, the @types/react-window type
definitions from DefinitelyTyped and the npm registry history of all four packages, and return the
matching excerpts with the versions each one belongs to.

Call this when a question is about react-window itself -- the 1.x components FixedSizeList,
VariableSizeList, FixedSizeGrid and VariableSizeGrid and their props (itemCount, itemSize,
itemData, itemKey, overscanCount, useIsScrolling, onItemsRendered, outerElementType,
innerElementType, layout, direction) and methods (scrollTo, scrollToItem, resetAfterIndex);
areEqual and shouldComponentUpdate; the 2.x components List and Grid and their props (rowComponent,
rowCount, rowHeight, rowProps, cellComponent, columnCount, columnWidth, overscanCount,
defaultHeight, onRowsRendered, rowKey), the imperative API (listRef, gridRef, scrollToRow,
scrollToCell, useListRef, useGridRef) and the hooks (useDynamicRowHeight); variable and dynamic
row heights, scrolling to an item, sticky rows, RTL, ARIA roles, tabular data; InfiniteLoader and
useInfiniteLoader of react-window-infinite-loader; AutoSizer of react-virtualized-auto-sizer; the
TypeScript types of 1.x; an upgrade from 1.x to 2.x -- and above all when it is about history:
since which version something exists, what changed between versions, what was renamed or removed
and what replaced it. Example query: "VariableSizeList itemSize resetAfterIndex".

Do not call this for React itself, for react-virtualized, TanStack Virtual or other virtual list
libraries: their documentation is not here, and the search will return react-window excerpts
that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "1" keeps every 1.x document, "2" every 2.x,
"1.8" keeps 1.8.x; leave it empty to search everything. Every excerpt comes back with `versions`:
each version whose documents contain this exact text, newest first -- text that stayed the same
across versions is returned once, with all of them listed, so the list itself shows from which to
which version the documentation said exactly this. The companion packages number their releases on
their own (react-window-infinite-loader 1.x-2.x, react-virtualized-auto-sizer 1.x-2.x,
@types/react-window 1.x): their documents carry that package's own version, so a `version` filter
keeps them too when the number matches.

Where the documentation lived. The two lines have different APIs and different sites. In 1.x the
README holds installation, a short example and the FAQ, and the reference is the 1.x site: one page
per component, every prop and method a section with its type and default ("FixedSizeList",
"VariableSizeGrid", "areEqual"), and example pages titled "Example: …". That site is offline now,
so its pages are cited as files in the repository. In 2.x the README holds the full List and Grid
reference, and the site react-window.vercel.app has pages titled by section ("Lists: Dynamic row
heights", "Grids: …", "List: props", "List: imperative handle"). The TypeScript types of 1.x live
in DefinitelyTyped (document "@types/react-window: index.d.ts", one section per interface or
class); 2.x ships its own types.

Which version to search first. When the user names the version, or the project's code shows it
(FixedSizeList, itemSize, children render function: 1.x; List, rowComponent, rowHeight: 2.x),
pass that line. When neither does, search both lines -- "1" and "2" -- and answer for each: 1.x
(1.8.x) is still by far the most downloaded, 2.x is the current one, and the same task is solved
with different components in them. Search without `version` when the question is about history,
or when a line gave nothing that answers.

Name the component, prop or method the way the documentation titles it, not in the user's own
words: "VariableSizeList itemSize", "scrollToItem align", "useDynamicRowHeight", "List rowHeight",
"InfiniteLoader isItemLoaded", "AutoSizer", not "make rows of different height work". When the
question is how to do something, an example page often shows it better than the reference: search
for the example as well ("example variable size list", "dynamic row heights").

For a question about when something appeared, changed or disappeared, search more than once:
without `version` first, to find the changelog entry and the release notes that name the exact
version, then with the versions around it, to see how the documentation described it before and
after.

Write the query in English, with the names react-window itself uses. Everything here is English --
the excerpts, the word index and the meaning index alike -- and the word index keeps only latin
letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language, translate
the question into react-window terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of the
query had to appear in the text, so a query phrased in other words than the documentation uses may
miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase had a
chance.

Every answer says which version it is for. When the user did not name a version, answer for both
lines separately -- "in react-window 1.x …", "in react-window 2.x …" -- and add that for a precise
answer about another version the user can name it. When the excerpts behind a statement come only
from older versions, name those versions instead of presenting the text as current.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists and which release introduced it;
what changed in later versions; what prompted the change, if the excerpts say so; and how it
stands in the current version -- recommended, deprecated, or removed and replaced by what. Every
point names the version and the document it rests on; a point the excerpts do not support is left
out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація react-window". Identifiers, API names and titles stay in English,
spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it
says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
