# Лекція. День 1. Значення й посилання

Ця лекція пояснює, що насправді лежить у змінній і що означають слова «той самий об'єкт». Читання займе близько 40
хвилин. Програмувати під час читання не обов'язково: під кожним прикладом стоїть справжній вивід Node 24. Після лекції
теорія й практика дня на сторінці маршруту читатимуться значно легше.

**Після лекції ви зможете пояснити:**

- чому зміну об'єкта через одну змінну видно через іншу, а зі зміною числа так не буває;
- що саме порівнює оператор `===` і в яких двох випадках `Object.is` відповідає інакше;
- скільки рівнів копіюють три крапки і чому вкладений об'єкт лишається спільним;
- що вміє `structuredClone`, на чому він зупиняється з помилкою і чому для стану React він зазвичай не потрібен;
- чому React не оновлює екран, якщо змінити об'єкт стану й передати йому той самий об'єкт.

## Екран, який не оновився

Уявіть сторінку замовлення в інтернет-крамниці. У коді є об'єкт `order`, а на екрані написано «Статус: новий».
Покупець натискає кнопку «Оплатити», і запускається такий код:

```js
order.status = "оплачений";
setOrder(order);
```

Функція `setOrder` належить React: нею компонент повідомляє нове значення свого **стану**, тобто даних, які компонент
пам'ятає між оновленнями екрана. Докладно про це йдеться у фазі 1, а тут важливо інше. `console.log(order.status)`
друкує «оплачений», помилок немає, а на екрані й далі «новий».

React не читає поля об'єкта, щоб знайти зміни. Він ставить одне запитання: чи це той самий об'єкт, що був раніше? У
цьому коді відповідь «так», тому React вирішує, що оновлювати нічого. Щоб такі помилки перестали бути загадкою, треба
розібратися з трьома речами: що лежить у змінній, що означає «той самий» і як зробити справді новий об'єкт.

## Два види значень

JavaScript ділить усі значення на дві групи. Перша група — **прості значення**, або **примітиви**: числа, рядки,
`true` і `false`, `undefined`, `null`, великі цілі числа `BigInt` і символи `Symbol`. Друга група — **об'єкти**:
звичайні об'єкти у фігурних дужках, масиви, функції, дати.

Просте значення неможливо змінити. Можна лише записати в змінну інше значення:

```js
let price = 100;
let oldPrice = price;
price = 120;
console.log(price, oldPrice);

let word = "кіт";
word[0] = "Р";
console.log(word, word.toUpperCase(), word);
```

```text
120 100
кіт КІТ кіт
```

Подивимося на це рядок за рядком:

- `let oldPrice = price` записує в `oldPrice` число 100.
- `price = 120` записує в `price` інше число. Змінна `oldPrice` цього не помічає, тому друкується `120 100`.
- `word[0] = "Р"` намагається замінити літеру в рядку. Рядок змінити не можна, тому в звичайному режимі цей запис
  просто ігнорується.
- `word.toUpperCase()` не змінює `word`, а створює новий рядок `КІТ`.

Оскільки просте значення не змінюється, програма не може відрізнити дві копії числа від одного спільного числа. Тому
кажуть, що під час присвоєння просте значення копіюється.

Об'єкт поводиться інакше. Він складається з **полів**, які ще називають **властивостями**, і ці поля можна змінювати:

```js
const order = { status: "новий", total: 500 };
const sameOrder = order;
sameOrder.status = "оплачений";
console.log(order.status);
console.log(order === sameOrder);
```

```text
оплачений
true
```

Рядок `const sameOrder = order` не створює другого об'єкта. Об'єкт один, а змінних, через які до нього можна
дістатися, тепер дві. Тому запис через `sameOrder` видно через `order`.

Цю поведінку зручно описувати за допомогою аналогії. Об'єкт схожий на будинок, а змінна схожа на папірець, де записано
адресу цього будинку. Рядок `const sameOrder = order` переписує адресу на другий папірець, а будинок лишається один.
Той запис на папірці називають **посиланням**.

```text
змінні                 об'єкти

order      ---+
              +--->    #1 { status: "оплачений", total: 500 }
sameOrder  ---+
```

Позначка `#1` існує лише в цій лекції. Справжніх адрес пам'яті програма не бачить, і **специфікація ECMAScript**,
тобто документ, який описує поведінку JavaScript, про них теж не пише. Натомість вона каже, що кожен об'єкт має
**тотожність**: особливу характеристику, яка робить його рівним лише самому собі. У розділі [5.2.8
Identity](https://tc39.es/ecma262/#sec-identity) сказано, що посилання на таке значення передають із місця в місце, а
його зміну побачать усі, хто його тримає. Адреса — це зручна модель саме цієї поведінки.

Той самий розділ називає крайній випадок: символ `Symbol("a")` є примітивом, але теж має тотожність, тому два окремо
створені символи не рівні.

## Присвоїти змінній чи присвоїти полю

Новачки часто плутають дві різні дії, які записуються схожим знаком `=`:

| Запис | Що змінюється | Хто це побачить |
|-------|---------------|-----------------|
| `cart = нове` | лише сама змінна `cart`: тепер вона вказує на інше | ніхто, крім цієї змінної |
| `cart.count = 2` | поле об'єкта, на який вказує `cart` | кожен, хто тримає посилання на цей об'єкт |

Це добре видно в такому коді:

```js
const cart = { count: 1 };
cart.count = 2;
console.log(cart.count);

try {
  cart = { count: 3 };
} catch (e) {
  console.log(e.name + ": " + e.message);
}
```

```text
2
TypeError: Assignment to constant variable.
```

Слово `const` забороняє лише замінити вміст змінної. Воно не забороняє змінювати поля об'єкта, тому `cart.count = 2`
спрацювало, а `cart = { count: 3 }` кинуло помилку.

Те саме правило діє на виклик функції. Коли ви викликаєте функцію, значення аргумента копіюється в її параметр. Для
об'єкта таким значенням є посилання:

```js
function changeField(item) {
  item.price = item.price - 10;
}
function changeParameter(item) {
  item = { price: 0 };
}

const pen = { price: 50 };
changeField(pen);
console.log(pen.price);
changeParameter(pen);
console.log(pen.price);
```

```text
40
40
```

Функція `changeField` змінила поле того самого об'єкта, тому зовні ми бачимо 40. Функція `changeParameter` записала
новий об'єкт у свій параметр. Це присвоєння змінній, тому воно не вийшло за межі функції.

## Що порівнює `===`

Алгоритм оператора `===` описано в розділах [IsStrictlyEqual](https://tc39.es/ecma262/#sec-isstrictlyequal) і
[SameValueNonNumber](https://tc39.es/ecma262/#sec-samevaluenonnumber) специфікації. Своїми словами він працює так:

1. Якщо значення різних типів, відповідь `false`. Перетворення типів немає, тому `5 === "5"` дає `false`.
2. Якщо це числа, вони порівнюються за величиною. Є два особливі випадки: `NaN` не дорівнює нічому, навіть собі, а `0`
   і `-0` вважаються рівними. Значення `NaN` (скорочення від Not a Number, «не число») виникає, наприклад, після
   ділення нуля на нуль.
3. Якщо це рядки, вони рівні, коли мають однакову довжину й однакові символи на однакових місцях. `true`, `false`,
   `undefined`, `null` і `BigInt` теж порівнюються за значенням.
4. Усе інше, тобто об'єкти й символи, порівнюється за тотожністю. Значення рівні, лише якщо це одне й те саме
   значення.

Вміст об'єктів `===` не розглядає взагалі.

Функція `Object.is` робить те саме, але обробляє числа інакше: для неї `NaN` дорівнює `NaN`, а `0` не дорівнює `-0`.
Більше відмінностей немає. Ось результати, отримані запуском:

| Що порівнюємо | `===` | `Object.is` |
|---------------|-------|-------------|
| `5` і `5` | `true` | `true` |
| `5` і `"5"` | `false` | `false` |
| `NaN` і `NaN` | `false` | `true` |
| `0` і `-0` | `true` | `false` |
| `{}` і `{}` | `false` | `false` |
| `box` і `sameBox`, де `const sameBox = box` | `true` | `true` |
| `new Date(0)` і `new Date(0)` | `false` | `false` |
| `Symbol("a")` і `Symbol("a")` | `false` | `false` |

Кожен запис `{}` чи `new Date(0)` створює новий об'єкт, тому в цих випадках порівнюються два різні об'єкти.

Значення `-0` виникає, наприклад, як результат `0 * -1`, тому `Object.is(0 * -1, 0)` дає `false`.

Не всі методи порівнюють однаково. Метод `indexOf` порівнює через `===`, тому `[NaN].indexOf(NaN)` дає `-1`. Метод
`includes` вважає `NaN` рівним `NaN`, тому `[NaN].includes(NaN)` дає `true`.

Що робити, якщо потрібно порівняти саме вміст? Оператора для цього в мові немає. У Node для цього є функція
`isDeepStrictEqual` із модуля `node:util`. Поширений прийом із порівнянням через `JSON.stringify` ненадійний, бо він
залежить від порядку полів: `JSON.stringify({ a: 1, b: 2 }) === JSON.stringify({ b: 2, a: 1 })` дає `false`.

Перевірки практики цього дня написано через модуль `node:assert`. За [документацією
Node](https://nodejs.org/api/assert.html) `strictEqual` порівнює через `Object.is`, тобто питає «чи це той самий
об'єкт», а `deepStrictEqual` порівнює вміст усіх рівнів. Тому `assert.strictEqual` кидає `AssertionError` навіть для
двох однакових на вигляд об'єктів.

## Що роблять три крапки

**Розгортання** (англійською spread) — це запис `{ ...order }`. Він створює новий об'єкт і переписує в нього поля
старого. Простежимо за ним на замовленні, у якому є вкладений об'єкт і масив:

```js
const order = {
  id: 7,
  status: "новий",
  delivery: { street: "Соборна", house: 12 },
  items: ["чай"],
};
const copy = { ...order };
console.log(copy === order, copy.delivery === order.delivery, copy.items === order.items);

copy.status = "оплачений";
copy.delivery.house = 99;
copy.items.push("мед");
console.log(order.status, order.delivery.house, order.items);
console.log(copy.status, copy.delivery.house, copy.items);
```

```text
false true true
новий 99 [ 'чай', 'мед' ]
оплачений 99 [ 'чай', 'мед' ]
```

Таблиця показує, що відбувається на кожному кроці. Позначками `#1`–`#4` названо об'єкти.

| Рядок | Що відбувається | Стан після кроку |
|-------|-----------------|------------------|
| `const order = ...` | створено три об'єкти: замовлення `#1`, доставку `#2` і масив `#3` | `order` вказує на `#1`, поле `delivery` на `#2`, поле `items` на `#3` |
| `const copy = { ...order }` | створено об'єкт `#4`, у нього переписано чотири поля | `copy` вказує на `#4`, але його `delivery` знову вказує на `#2`, а `items` на `#3` |
| `copy.status = "оплачений"` | записано поле об'єкта `#4` | у `#1` статус лишається «новий» |
| `copy.delivery.house = 99` | за посиланням знайдено `#2`, і записано його поле | зміну видно і через `order`, і через `copy` |
| `copy.items.push("мед")` | за посиланням знайдено `#3`, і в нього додано елемент | зміну видно і через `order`, і через `copy` |

Правило просте. Розгортання копіює значення кожного поля верхнього рівня. Якщо у полі лежить посилання, копіюється
посилання, а об'єкт, на який воно вказує, не копіюється. Таку копію називають **поверхневою**.

Специфікація описує цю дію в розділі [CopyDataProperties](https://tc39.es/ecma262/#sec-copydataproperties).
Послідовність така: взяти список власних ключів об'єкта, пропустити неперелічувані поля, прочитати значення кожного
поля й записати його в новий об'єкт як звичайне поле. Власними називають ключі, які лежать у самому об'єкті.
Неперелічуваним називають поле, позначене так, щоб під час перебору об'єкта його не показували. Звідси випливає кілька
наслідків, які легко перевірити:

```js
console.log({ ...{ a: 1, b: 2 }, a: 9 });
console.log({ a: 9, ...{ a: 1, b: 2 } });
console.log({ ...null, ...undefined, ...5, ...true });

class Cart {
  constructor() {
    this.count = 2;
  }
  total() {
    return this.count * 10;
  }
}
const cart = new Cart();
const cartCopy = { ...cart };
console.log(cart.total(), cartCopy.count, typeof cartCopy.total, cartCopy instanceof Cart);
```

```text
{ a: 9, b: 2 }
{ a: 1, b: 2 }
{}
20 2 undefined false
```

- **Діє останній запис.** У першому рядку `a: 9` стоїть після розгортання й замінює значення. У другому рядку
  розгортання стоїть після `a: 9`, тому `a` знову дорівнює 1.
- **`null` і `undefined` не дають помилки.** Вони просто нічого не додають. Запис `[...null]` у масиві, навпаки, кидає
  `TypeError: null is not iterable`, бо розгортання в масив працює інакше: воно перебирає елементи за чергою, а не
  копіює поля.
- **Методи класу не копіюються.** Клас `Cart` зберігає метод `total` не в самому об'єкті, а в його прототипі, тобто в
  окремому об'єкті, де шукаються спільні методи. Власне поле лише одне, `count`, і копіюється лише воно. Копія стала
  звичайним об'єктом, тому `cartCopy.total` дорівнює `undefined`. Оператор `instanceof` питає, чи збудовано об'єкт за
  цим класом, і для копії відповідає `false`.

Масив копіюють схожим записом у квадратних дужках: `[0, ...[5, 6]]` дає `[ 0, 5, 6 ]`. Елементи-об'єкти при цьому теж
лишаються спільними.

Як тоді змінити поле на глибині кількох рівнів і не зачепити оригінал? Треба створити новий об'єкт на кожному рівні
шляху до цього поля. Ось крамниця, у якої потрібно змінити широту:

```js
const shop = {
  title: "Чайна",
  owner: { name: "Ліна" },
  contact: { phone: "044", geo: { lat: 50, lng: 30 } },
};
const next = {
  ...shop,
  contact: {
    ...shop.contact,
    geo: { ...shop.contact.geo, lat: 51 },
  },
};
console.log(next === shop, next.contact === shop.contact, next.contact.geo === shop.contact.geo);
console.log(next.owner === shop.owner);
console.log(shop.contact.geo.lat, next.contact.geo.lat);
```

```text
false false false
true
50 51
```

Шлях до поля `lat` проходить через три об'єкти: `shop`, `contact` і `geo`, тому створено три нові об'єкти. Об'єкт
`owner` не лежить на цьому шляху, тому він лишився спільним, і це правильно. Спільна частина безпечна, поки її ніхто
не змінює.

## `structuredClone`: копія всіх рівнів

Функція `structuredClone` робить **глибоку копію**, тобто копіює всі об'єкти на всіх рівнях. Вона працює у два етапи.
Спершу вона переводить значення в окремий запис, не пов'язаний із вихідними об'єктами. Цей етап називають
**серіалізацією**. Потім вона будує за цим записом нові об'єкти. Цей етап називають **десеріалізацією**. Алгоритм
описано в [розділі 2.7 стандарту
HTML](https://html.spec.whatwg.org/multipage/structured-data.html#safe-passing-of-structured-data).

Під час роботи функція веде перелік уже оброблених об'єктів. Завдяки цьому вона правильно обробляє об'єкт, що
посилається сам на себе, і зберігає спільні посилання всередині копії:

```js
const shared = { tag: "спільний" };
const source = {
  when: new Date(0),
  labels: new Set(["a"]),
  prices: new Map([["чай", 120]]),
  nothing: undefined,
  first: shared,
  second: shared,
};
source.self = source;

const clone = structuredClone(source);
console.log(clone.when instanceof Date, clone.labels instanceof Set, clone.prices.get("чай"));
console.log("nothing" in clone);
console.log(clone.first === clone.second, clone.first === shared);
console.log(clone.self === clone, clone.self === source);
```

```text
true true 120
true
true false
true false
```

Поля `first` і `second` у копії вказують на один об'єкт, як і в оригіналі, але це вже новий об'єкт, а не `shared`. З
посиланням на себе відбувається те саме: `clone.self` вказує на копію, а не на оригінал.

Функція копіює дані, а не все підряд. Таблиця підсумовує, що стається з різними значеннями. Усе, крім вузлів сторінки,
перевірено в Node. Вузли сторінки описано за [довідником
MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm), бо в Node їх немає.
У браузері ви побачите ту саму помилку `DataCloneError`.

| Що є в об'єкті | Що виходить у копії |
|----------------|---------------------|
| `Date`, `Map`, `Set`, масив, звичайний об'єкт, `undefined` | копія того самого типу |
| функція, зокрема метод об'єкта | помилка `DataCloneError` |
| значення-символ і вбудовані об'єкти `Promise`, `WeakMap`, `Proxy`, про які ви читатимете пізніше | помилка `DataCloneError` |
| вузол сторінки (DOM) | помилка `DataCloneError` |
| поле, чий ключ є символом | поле зникає без помилки |
| геттер, тобто поле, значення якого обчислює функція | звичайне поле зі значенням, яке геттер повернув |
| неперелічуване поле | поле зникає без помилки |
| об'єкт класу | звичайний об'єкт із власними полями, клас і методи зникають |
| заморожений об'єкт | звичайний об'єкт, який можна змінювати |

Текст помилки для функції в Node виглядає так: `DataCloneError: run() {} could not be cloned.`

Старий прийом `JSON.parse(JSON.stringify(x))` теж робить глибоку копію, але втрачає більше: дата стає рядком, поле зі
значенням `undefined` зникає, `NaN` стає `null`, `Set` стає порожнім об'єктом, а об'єкт із посиланням на себе дає
`TypeError`.

Глибока копія зручна, але для оновлення даних вона часто шкодить. Порівняємо два способи змінити один товар у каталозі
з 1000 товарів:

```js
const catalog = {
  items: Array.from({ length: 1000 }, (_, i) => ({ id: i, hot: false })),
};

const spreadUpdate = {
  ...catalog,
  items: catalog.items.map((it) => (it.id === 5 ? { ...it, hot: true } : it)),
};
const cloneUpdate = structuredClone(catalog);
cloneUpdate.items[5].hot = true;

const sameAs = (next) => next.items.filter((it, i) => it === catalog.items[i]).length;
console.log(sameAs(spreadUpdate), sameAs(cloneUpdate));
```

```text
999 0
```

Перший спосіб зберіг тотожність 999 незмінених товарів, а другий не зберіг жодної. Якщо програма визначає зміни
порівнянням посилань, то після другого способу вона вважатиме зміненими всі 1000 товарів, хоча насправді змінився
один.

## Типові хибні уявлення

**«`const` робить об'єкт незмінним».** Слово `const` забороняє лише присвоїти змінній інше значення. Поля об'єкта
можна змінювати, тому `const` нічого не гарантує щодо вмісту.

**«Три крапки роблять копію, отже, копія незалежна».** Незалежний лише верхній рівень. Запис у вкладений об'єкт
потрапляє в той самий об'єкт, який бачить оригінал.

**«Об'єкти передаються у функцію за посиланням, отже, функція може замінити змінну того, хто її викликав».** Функція
отримує копію посилання. Вона може змінити поля об'єкта, але присвоєння параметру не змінює змінну зовні, що й
показала `changeParameter`.

**«`Object.is` кращий за `===`, тому його варто писати скрізь».** Він відрізняється лише для `NaN` і `-0`. MDN у
[посібнику про
порівняння](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Equality_comparisons_and_sameness) радить у
звичайному коді лишатися з `===`.

**«`structuredClone` усе вирішує, краще завжди клонувати».** Він кидає помилку на функціях, не зберігає класи й дає
нову тотожність навіть тому, що не змінювалося.

## Як це проявиться в React

Документація React про функцію, яка змінює стан, каже, що React порівнює нове значення з поточним через `Object.is`.
Якщо значення збігаються, React пропускає оновлення компонента та його дочірніх компонентів ([useState, розділ про
застереження](https://react.dev/reference/react/useState#setstate-caveats)). Перевірмо це на замовленні зі вступу.
Компонент показує `order.status`, а ми виконуємо чотири дії одну за одною, кожну як окреме оновлення:

```js
order.status = "оплачений";
setOrder(order);

setTick(1);

setOrder({ ...order, status: "відправлений" });

setOrder({ ...order });
```

Функція `setTick` змінює інший, не пов'язаний стан компонента. Ось що показав запуск у React 19.3:

| Дія | Скільки разів React викликав компонент | Що на екрані |
|-----|-------------------------------------|--------------|
| перший показ | 1 | новий |
| змінили поле, передали той самий об'єкт | 1 | новий |
| змінили інший стан | 2 | оплачений |
| передали новий об'єкт із новим статусом | 3 | відправлений |
| передали новий об'єкт із тим самим вмістом | 4 | відправлений |

Кожен результат випливає з того, що ви вже знаєте:

- **Той самий об'єкт.** Посилання не змінилося, тому `Object.is` дає `true`, і React нічого не робить. Дані вже
  змінено, а екран ні.
- **Зміна іншого стану.** Це найнеприємніша частина помилки. Оновлення, спричинене чимось іншим, раптом показує зміну,
  зроблену раніше. Тому така помилка виглядає випадковою.
- **Новий об'єкт із новим статусом.** Посилання нове, тому React оновлює компонент. Це правильний спосіб.
- **Новий об'єкт із тим самим вмістом.** Посилання нове, тому React оновлює компонент ще раз, хоча на екрані нічого не
  змінюється. React не порівнює вміст, тому однаковий вміст теж не зупиняє оновлення.

Документація також попереджає, що інколи React викликає компонент ще раз, перш ніж пропустити оновлення, тому
лічильник викликів може зрости, але екран при цьому не зміниться. Правило `Object.is` пояснює й числові випадки:
перехід від `NaN` до `NaN` не оновлює компонент, а перехід від `0` до `-0` оновлює.

`Object.is` працює в React і в інших місцях:

- **Залежності ефекту.** Ефект — це код, який React запускає після оновлення екрана, а залежності — значення, від яких
  цей код залежить. React порівнює кожну залежність `useEffect` з попередньою через `Object.is`
  ([useEffect](https://react.dev/reference/react/useEffect#parameters)). Об'єкт, створений під час показу компонента,
  щоразу новий, тому ефект із такою залежністю запускається після кожного оновлення. У нашому запуску другий показ
  компонента запустив ефект удруге.
- **`memo`.** Обгортка `memo` пропускає повторний виклик компонента, якщо кожен його вхідний параметр (props) не
  змінився за `Object.is` ([memo](https://react.dev/reference/react/memo)). Тому незмінені об'єкти варто лишати тими
  самими. У запуску зі списком із трьох рядків оновлення одного елемента через `map` викликало лише один рядок, а
  `structuredClone` усього списку викликав усі три.

Звідси правило документації React: стан вважають призначеним лише для читання й замінюють новим об'єктом ([Updating
Objects in State](https://react.dev/learn/updating-objects-in-state)). Є важливе уточнення. Змінювати об'єкт, який ви
щойно створили й ще нікому не передали, цілком нормально, бо ніхто інший його не тримає.

## Перевірте себе

Спершу дайте відповідь самі, уголос або письмово, і лише потім розгортайте пояснення.

**1. Що надрукує цей код і чому?**

```js
let a = { n: 1 };
let b = a;
b = { n: 2 };
console.log(a.n);
```

<details><summary>Відповідь</summary>

Надрукує `1`. Рядок `b = { n: 2 }` змінює лише змінну `b`: вона починає вказувати на новий об'єкт. Об'єкт, на який
вказує `a`, ніхто не змінював.

</details>

**2. Масив `xs` містить два елементи. Яка довжина масиву після виклику кожної функції?**

```js
function reset(list) { list = []; }
function clear(list) { list.length = 0; }
```

<details><summary>Відповідь</summary>

Після `reset(xs)` довжина лишається 2, бо функція присвоїла новий масив своєму параметру. Після `clear(xs)` довжина
стає 0, бо функція змінила поле самого масиву, який їй передали.

</details>

**3. Скільки нових об'єктів створює цей запис і які поля лишаються спільними з `shop`?**

```js
const next = { ...shop, owner: { ...shop.owner, name: "Ія" } };
```

<details><summary>Відповідь</summary>

Два нових об'єкти: новий зовнішній і новий `owner`. Усі інші поля верхнього рівня скопійовано як є, тому, наприклад,
`next.contact === shop.contact` дає `true`.

</details>

**4. Що станеться під час виклику `structuredClone({ id: 1, onClick() {} })` і як зробити копію такого об'єкта?**

<details><summary>Відповідь</summary>

Виклик кине `DataCloneError`, бо функцію не можна скопіювати. Якщо вкладених даних немає, досить розгортання `{ ...obj
}`: воно скопіює посилання на функцію, і копія користуватиметься тією самою функцією.

</details>

**5. Компонент зберігає `order` у стані. Що побачить користувач у кожному випадку: а) `order.total = 900;
setOrder(order)`; б) `setOrder({ ...order, total: 900 })`; в) `setOrder({ ...order })`?**

<details><summary>Відповідь</summary>

а) Екран не оновиться, бо посилання те саме. Нове значення з'явиться лише тоді, коли компонент оновиться з іншої
причини. б) Екран покаже 900, бо посилання нове. в) Компонент оновиться ще раз, бо посилання нове, але на екрані
нічого не зміниться, бо вміст той самий.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| просте значення, примітив | число, рядок, логічне значення, `undefined`, `null`, `BigInt` чи `Symbol`; його не можна змінити |
| посилання | те, що лежить у змінній чи полі замість самого об'єкта; вказує, який це об'єкт |
| тотожність (identity) | характеристика, завдяки якій об'єкт рівний лише самому собі |
| мутація | зміна вмісту наявного об'єкта чи масиву |
| розгортання (spread) | запис `...`, який переписує поля чи елементи в новий об'єкт або масив |
| поверхнева копія | новий об'єкт, у якому вкладені об'єкти лишаються спільними з оригіналом |
| глибока копія | копія всіх об'єктів на всіх рівнях |
