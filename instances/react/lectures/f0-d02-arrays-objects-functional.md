# Лекція. День 2. Масиви й об'єкти функційно

Лекція дня 1 показала, що React помічає лише нове посилання. Ця лекція пояснює, як отримати нове посилання на
практиці: які методи масиву створюють новий результат, які змінюють наявний масив і як перевірити, що ваш код нічого
не змінює. **Методом** називають функцію, яка лежить у полі об'єкта. Метод викликають через крапку після значення,
наприклад `list.sort()`, і він працює саме з тим значенням, яке стоїть перед крапкою. Читання займе близько 40 хвилин.
Під кожним прикладом стоїть справжній вивід Node 24.

**Після лекції ви зможете пояснити:**

- як за назвою методу визначити, чи він змінює масив, і що він повертає;
- що таке функція порівняння в `sort` і чому `[10, 9, 1]` без неї сортується неправильно;
- чому `filter` і `find` не дають нових об'єктів і чим це небезпечно;
- що саме забороняє `Object.freeze` і чому заборонена зміна інколи не дає помилки;
- чому `items.sort()` у стані React дає помилку, якої не видно.

## Кнопка, яка нічого не сортує

Уявіть каталог товарів. Товари лежать у стані React, тобто в даних, які React пам'ятає між оновленнями екрана. Про
стан ішлося в лекції дня 1. Кнопка «Спершу дешевші» запускає такий код:

```js
products.sort((a, b) => a.price - b.price);
setProducts(products);
```

Функція `setProducts` повідомляє React новий стан. Метод `sort` справді відсортував товари, але зробив це в тому
самому масиві й повернув його ж. React порівняв старе й нове значення, побачив той самий масив і нічого не оновив.
Екран лишився старим, а дані вже змінилися. Заодно зник і початковий порядок товарів.

Слово **функційно** в назві дня означає такий стиль коду: функція отримує дані й повертає новий результат, а отримане
лишає незмінним. Будь-яку зміну наявного об'єкта чи масиву називають **мутацією**. Щоб писати без мутацій, треба
знати, які методи мутують, а які ні.

## Масив — це теж об'єкт

Масив є об'єктом, у якого поля названо номерами, а окреме поле `length` зберігає довжину. Код нижче перевіряє це
трьома вбудованими засобами. Оператор `typeof` повертає рядок із назвою типу значення. Функція `Array.isArray`
відповідає, чи є значення масивом. Функція `Object.keys` повертає масив назв полів об'єкта:

```js
const sizes = ["S", "M"];
console.log(typeof sizes, Array.isArray(sizes));
console.log(Object.keys(sizes), sizes.length, sizes["1"]);
```

```text
object true
[ '0', '1' ] 2 M
```

Отже, `typeof` називає масив об'єктом, а назви його полів є рядками `'0'` і `'1'`. Запис `sizes["1"]` читає поле з
назвою `"1"` і дає другий елемент `M`.

Звідси два наслідки. Масив передається посиланням, як і будь-який об'єкт, тому метод, що змінює масив, зачіпає всіх,
хто його тримає. І `===` для масивів теж перевіряє, чи це той самий масив, а не чи однакові в них елементи.

## Два види методів

Перевіримо, що повертає кожен метод, викликаний на масиві `[3, 1, 2]`. Функція `run` у коді нижче для кожного виклику
створює цей масив заново, щоб один виклик не впливав на наступний. Вона друкує назву виклику, потім те, що метод
повернув, і наприкінці те, яким став масив. Коли метод повертає той самий масив, а не новий, вона друкує слова «той
самий масив».

Код записано стрілковими функціями, які пояснював день 1: ліворуч від стрілки `=>` стоять параметри, а праворуч стоїть
тіло. **Тілом** функції називають код, який виконується під час її виклику. Якщо тіло взято у фігурні дужки, як у
`run`, функція повертає значення лише через `return`. Якщо праворуч від стрілки стоїть один вираз без фігурних дужок,
функція повертає значення цього виразу без слова `return`. Тому функція `(a) => a.push(9)` повертає те, що повернув
виклик `a.push(9)`. Саме таку функцію `run` отримує другим аргументом і викликає її з новим масивом.

Слова «той самий масив» вибирає умовний оператор `умова ? перше : друге`, який пояснював день 1.

```js
const run = (label, call) => {
  const list = [3, 1, 2]; // Щоразу новий масив
  const result = call(list); // Викликаємо метод
  // Порівняння result === list перевіряє, чи метод повернув той самий масив
  console.log(label, "->", result === list ? "той самий масив" : result, "->", list);
};

run("push(9)", (a) => a.push(9));
run("pop()", (a) => a.pop());
run("shift()", (a) => a.shift());
run("unshift(9)", (a) => a.unshift(9));
run("splice(0, 1)", (a) => a.splice(0, 1));
run("sort()", (a) => a.sort());
run("reverse()", (a) => a.reverse());
run("fill(0)", (a) => a.fill(0));
run("copyWithin(0, 1)", (a) => a.copyWithin(0, 1));
```

```text
push(9) -> 4 -> [ 3, 1, 2, 9 ]
pop() -> 2 -> [ 3, 1 ]
shift() -> 3 -> [ 1, 2 ]
unshift(9) -> 4 -> [ 9, 3, 1, 2 ]
splice(0, 1) -> [ 3 ] -> [ 1, 2 ]
sort() -> той самий масив -> [ 1, 2, 3 ]
reverse() -> той самий масив -> [ 2, 1, 3 ]
fill(0) -> той самий масив -> [ 0, 0, 0 ]
copyWithin(0, 1) -> той самий масив -> [ 1, 2, 2 ]
```

У кожному рядку виводу останнє значення відрізняється від початкового `[3, 1, 2]`. Ось той самий результат у таблиці:

| Виклик | Що повернув | Яким став масив |
|--------|-------------|-----------------|
| `push(9)` | `4`, нова довжина | `[3, 1, 2, 9]` |
| `pop()` | `2`, вилучений елемент | `[3, 1]` |
| `shift()` | `3`, вилучений елемент | `[1, 2]` |
| `unshift(9)` | `4`, нова довжина | `[9, 3, 1, 2]` |
| `splice(0, 1)` | `[3]`, масив вилучених елементів | `[1, 2]` |
| `sort()` | той самий масив | `[1, 2, 3]` |
| `reverse()` | той самий масив | `[2, 1, 3]` |
| `fill(0)` | той самий масив | `[0, 0, 0]` |
| `copyWithin(0, 1)` | той самий масив | `[1, 2, 2]` |

Ці дев'ять методів **мутують**: вони змінюють масив, на якому їх викликали. Наступні методи масив не змінюють.
Перевіримо їх тією самою функцією `run`:

```js
run("map(x => x * 2)", (a) => a.map((x) => x * 2));
run("filter(x => x > 1)", (a) => a.filter((x) => x > 1));
run("slice(1)", (a) => a.slice(1));
run("concat([9])", (a) => a.concat([9]));
run("toSorted()", (a) => a.toSorted());
run("toReversed()", (a) => a.toReversed());
run("toSpliced(0, 1)", (a) => a.toSpliced(0, 1));
run("with(0, 9)", (a) => a.with(0, 9));
run("find(x => x > 1)", (a) => a.find((x) => x > 1));
run("some(x => x > 2)", (a) => a.some((x) => x > 2));
run("reduce((s, x) => s + x, 0)", (a) => a.reduce((s, x) => s + x, 0));
```

```text
map(x => x * 2) -> [ 6, 2, 4 ] -> [ 3, 1, 2 ]
filter(x => x > 1) -> [ 3, 2 ] -> [ 3, 1, 2 ]
slice(1) -> [ 1, 2 ] -> [ 3, 1, 2 ]
concat([9]) -> [ 3, 1, 2, 9 ] -> [ 3, 1, 2 ]
toSorted() -> [ 1, 2, 3 ] -> [ 3, 1, 2 ]
toReversed() -> [ 2, 1, 3 ] -> [ 3, 1, 2 ]
toSpliced(0, 1) -> [ 1, 2 ] -> [ 3, 1, 2 ]
with(0, 9) -> [ 9, 1, 2 ] -> [ 3, 1, 2 ]
find(x => x > 1) -> 3 -> [ 3, 1, 2 ]
some(x => x > 2) -> true -> [ 3, 1, 2 ]
reduce((s, x) => s + x, 0) -> 6 -> [ 3, 1, 2 ]
```

Тепер у кожному рядку останнє значення лишилося `[3, 1, 2]`, і слів «той самий масив» немає жодного разу. У таблиці це
виглядає так:

| Виклик | Що повернув | Яким став масив |
|--------|-------------|-----------------|
| `map(x => x * 2)` | новий `[6, 2, 4]` | `[3, 1, 2]` |
| `filter(x => x > 1)` | новий `[3, 2]` | `[3, 1, 2]` |
| `slice(1)` | новий `[1, 2]` | `[3, 1, 2]` |
| `concat([9])` | новий `[3, 1, 2, 9]` | `[3, 1, 2]` |
| `toSorted()` | новий `[1, 2, 3]` | `[3, 1, 2]` |
| `toReversed()` | новий `[2, 1, 3]` | `[3, 1, 2]` |
| `toSpliced(0, 1)` | новий `[1, 2]` | `[3, 1, 2]` |
| `with(0, 9)` | новий `[9, 1, 2]` | `[3, 1, 2]` |
| `find(x => x > 1)` | наявний елемент `3` | `[3, 1, 2]` |
| `some(x => x > 2)` | `true` | `[3, 1, 2]` |
| `reduce((s, x) => s + x, 0)` | `6` | `[3, 1, 2]` |

Методи, які спершу створюють новий масив, а потім заповнюють його, MDN називає **копіювальними** (англійською copying
methods). З нашого списку це `map`, `filter`, `slice`, `concat`, `toSorted`, `toReversed`, `toSpliced` і `with`.
Методи `find`, `some` і `reduce` масиву теж не змінюють, але повертають не масив, а одне значення.

Зверніть увагу на дві пастки першої таблиці. Метод `push` повертає довжину, а не масив, тому `const next = [1,
2].push(3)` записує в `next` число 3. Методи `sort` і `reverse` повертають масив, тому результат виглядає як новий,
хоча це той самий масив.

Методи `toSorted`, `toReversed`, `toSpliced` і `with` створено саме як незмінні пари до мутуючих. **Незмінною парою**
тут називаємо метод, який дає той самий результат, що й мутуючий метод, але кладе цей результат у новий масив, а
масив, на якому його викликали, не змінює. Для `push` роль пари виконує `concat`, для `pop` запис `slice(0, -1)`, для
`shift` запис `slice(1)`, а для `unshift` запис `toSpliced(0, 0, значення)`. Ці пари перелічено в таблиці [довідника
MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array#copying_methods_and_mutating_methods).
Для `fill` і `copyWithin` готової пари немає, тому спершу роблять копію, а потім змінюють її.

## Методи з функцією: `filter`, `find`, `some`, `map`

Багато методів приймають функцію й викликають її для елементів по черзі. Функція, яку передають іншій функції,
називається **зворотним викликом** (англійською callback). Вона отримує три аргументи: елемент, його номер і сам
масив. Від того, що вона повертає, залежить результат методу.

Працюватимемо з невеликим каталогом. У кожного товару поле `sku` зберігає код товару, поле `name` зберігає назву, поле
`price` зберігає ціну, а поле `qty` зберігає кількість на складі:

```js
const products = [
  { sku: "A1", name: "Чай", price: 120, qty: 3 },
  { sku: "B2", name: "Кава", price: 300, qty: 0 },
  { sku: "C3", name: "Мед", price: 180, qty: 2 },
  { sku: "D4", name: "Цукор", price: 40, qty: 10 },
];

const inStock = products.filter((p) => p.qty > 0);
console.log(inStock.length, products.length, inStock === products, inStock[0] === products[0]);

const found = products.find((p) => p.sku === "C3");
console.log(found === products[2], products.find((p) => p.sku === "Z9"));

console.log(products.some((p) => p.qty === 0), products.every((p) => p.qty > 0));

const repriced = products.map((p) =>
  p.sku === "C3" ? { ...p, price: 200 } : p,
);
console.log(products[2].price, repriced[2].price);
console.log(repriced[0] === products[0], repriced[2] === products[2]);
console.log(repriced.filter((p, i) => p === products[i]).length);
```

```text
3 4 false true
true undefined
true false
180 200
true false
3
```

Розберемо це рядок за рядком:

- **`filter`** лишає елементи, для яких функція повернула істинне значення, і кладе їх у новий масив. **Істинним**
  (англійською truthy) називають значення, яке в умові діє як `true`. Хибних значень лише кілька, серед них `false`,
  `0`, порожній рядок, `null`, `undefined` і `NaN`. Усі інші значення істинні, зокрема будь-який об'єкт. Масив новий
  (`false` у порівнянні), але об'єкти ті самі (`true` у порівнянні першого елемента).
- **`find`** повертає перший знайдений елемент або `undefined`, якщо такого немає. Він не створює копії: `found` і
  `products[2]` є одним об'єктом. Тому запис `found.price = 1` змінив би й каталог.
- **`some`** відповідає, чи підходить хоча б один елемент, а **`every`** відповідає, чи підходять усі. Обидва
  зупиняються, щойно відповідь стала відомою. `find` теж зупиняється на першому збігу.
- **`map`** будує новий масив із результатів функції. Умовний оператор `?` повертає новий об'єкт для одного товару, а
  для решти повертає наявний об'єкт. Тому в результаті лише один об'єкт новий, а три лишилися спільними з `products`.

Це головний прийом роботи зі списками в React: новий масив, новий об'єкт для зміненого елемента, а незмінені елементи
лишаються тими самими. Чому це корисно, ви побачите наприкінці лекції.

Є дві типові помилки. Перша стосується фігурних дужок у стрілковій функції:

```js
const bad = [{ name: "Чай" }].map((p) => { name: p.name });
const good = [{ name: "Чай" }].map((p) => ({ name: p.name }));
console.log(bad, good);
```

```text
[ undefined ] [ { name: 'Чай' } ]
```

Фігурні дужки одразу після стрілки означають тіло функції, а не об'єкт. У такому тілі немає `return`, тому функція
повертає `undefined`. Щоб повернути об'єкт, його беруть у круглі дужки. Друга помилка: метод `forEach` виконує дію для
кожного елемента й завжди повертає `undefined`, тому будувати новий масив через нього не вийде.

## `reduce`: згорнути масив в одне значення

Метод `reduce` проходить масив і накопичує результат. Функція отримує **накопичувач**, тобто результат попередніх
кроків, і поточний елемент. Те, що вона повертає, стає накопичувачем для наступного кроку. Другий аргумент `reduce`
задає початкове значення накопичувача. Порахуймо вартість усіх товарів на складі:

```js
const stockValue = products.reduce((sum, p) => sum + p.price * p.qty, 0);
console.log(stockValue);
```

```text
1120
```

| Крок | `sum` на вході | Товар | Обчислення | Що повертає функція |
|------|----------------|-------|------------|---------------------|
| перший | 0 | Чай | 0 + 120 × 3 | 360 |
| другий | 360 | Кава | 360 + 300 × 0 | 360 |
| третій | 360 | Мед | 360 + 180 × 2 | 720 |
| четвертий | 720 | Цукор | 720 + 40 × 10 | 1120 |

Початкове значення не варто пропускати. Без нього накопичувачем стає перший елемент, а обхід починається з другого.
Ось що стається без початкового значення на каталозі `products` і на порожньому масиві.

Код нижче перехоплює помилки конструкцією `try { ... } catch (e) { ... }`, яку пояснював день 1. Там же пояснено, що
означає «кидає помилку» і що лежить у полях `e.name` та `e.message`:

```js
// Без другого аргументу накопичувачем стає весь перший об'єкт каталогу
console.log(products.reduce((s, p) => s + p.price));

try {
  // У порожньому масиві немає першого елемента, який міг би стати накопичувачем
  [].reduce((s, x) => s + x);
} catch (e) {
  console.log(e.name + ": " + e.message);
}

// З другим аргументом порожній масив просто повертає це значення
console.log([].reduce((s, x) => s + x, 0));
```

```text
[object Object]30018040
TypeError: Reduce of empty array with no initial value
0
```

Перший рядок виводу є текстом, а не числом, бо до першого об'єкта почали додавати числа. Оператор `+` спершу
перетворює об'єкт на просте значення, і тут об'єкт став рядком `[object Object]`. Коли з одного боку `+` стоїть рядок,
оператор склеює обидва боки як текст, тому ціни 300, 180 і 40 дописалися в кінець цього рядка. Другий рядок показує,
що на порожньому масиві виклик без початкового значення кидає помилку. Третій рядок показує, що з початковим значенням
той самий виклик повертає це значення. Тому другий аргумент `reduce` краще писати завжди.

## Сортування і функція порівняння

Обидва методи сортування, `sort` і `toSorted`, працюють однаково, а відрізняються лише тим, де лежить результат. Без
аргументу вони перетворюють елементи на рядки й порівнюють рядки. Тому числа сортуються неочікувано:

```js
console.log([10, 9, 1].toSorted());
console.log([10, 9, 1].toSorted((a, b) => a - b));
```

```text
[ 1, 10, 9 ]
[ 1, 9, 10 ]
```

Коли числа стали рядками, `"10"` стоїть перед `"9"`. Рядки порівнюються символ за символом за числовими кодами, і MDN
уточнює, що це коди UTF-16. Перші символи тут `1` і `9`, а код символу `1` менший за код символу `9`, тому весь рядок
`"10"` вважається меншим. Щоб сортувати за величиною, передають **функцію порівняння**. Вона отримує два елементи й
повертає число:

| Що повертає функція | Що це означає |
|---------------------|---------------|
| від'ємне число | `a` стоїть перед `b` |
| додатне число | `a` стоїть після `b` |
| нуль або `NaN` | порядок цих двох елементів не змінюється |

Запис `a.price - b.price` дає від'ємне число, коли `a` дешевший, тому дешевші йдуть першими. Запис `b.price - a.price`
сортує навпаки.

Функція має повертати саме число зі знаком. Ось два поширені способи помилитися:

```js
const items = [
  { name: "Чай", price: 120 },
  { name: "Кава", price: 300 },
  { name: "Мед", price: 180 },
];
const names = (list) => list.map((p) => p.name);

console.log(names(items.toSorted((a, b) => a.name - b.name)));
console.log([3, 1, 2].toSorted((a, b) => a > b));
console.log(names(items.toSorted((a, b) => a.name.localeCompare(b.name, "uk"))));
```

```text
[ 'Чай', 'Кава', 'Мед' ]
[ 3, 1, 2 ]
[ 'Кава', 'Мед', 'Чай' ]
```

У першому рядку відняти рядок від рядка неможливо, виходить `NaN`, і порядок не змінюється. У другому рядку функція
повертає `true` або `false`, які перетворюються на 1 і 0. Від'ємного значення вона ніколи не повертає, тому результат
ненадійний. **Рушієм** називають програму, яка виконує JavaScript у браузері чи в Node. За словами MDN, різні рушії
дають тут різний порядок, а Node 24 лишив масив незміненим. Для текстів існує метод `localeCompare`, який повертає
число зі знаком і враховує правила мови. Другий аргумент `"uk"` у третьому рядку коду просить порівнювати за правилами
української мови.

Сортування **стабільне**: елементи, які функція вважає рівними, зберігають взаємний порядок. Елементи зі значенням
`undefined` завжди стають у кінець.

## Незмінні пари докладніше

Метод `with(номер, значення)` повертає новий масив із заміненим елементом. Від'ємний номер рахується від кінця, а
номер поза межами масиву кидає помилку `RangeError`. Цю помилку JavaScript кидає, коли значення виходить за дозволені
межі. Метод `toSpliced(початок, скільки, ...нові)` працює як `splice`, але не змінює масив і повертає результат, а не
вилучені елементи. Три крапки перед словом `нові` означають, що після другого аргументу можна передати скільки
завгодно нових елементів:

```js
const nums = [1, 2, 3];
console.log(nums.with(-1, 9), nums.toSpliced(1, 1), nums.toSpliced(1, 0, 7, 8), nums);
try {
  nums.with(3, 9);
} catch (e) {
  console.log(e.name + ": " + e.message);
}
```

```text
[ 1, 2, 9 ] [ 1, 3 ] [ 1, 7, 8, 2, 3 ] [ 1, 2, 3 ]
RangeError: Invalid index : 3
```

Ці методи працюють у всіх основних браузерах із липня 2023 року й у Node з версії 20. У старому коді замість них ви
побачите `[...list].sort()`: спершу копія, потім сортування копії. Це теж правильний запис.

## Об'єкти без мутацій

Для об'єктів працює розгортання з лекції дня 1. Ось три типові дії:

```js
const settings = { theme: "light", size: 14, note: "чернетка" };

const dark = { ...settings, theme: "dark" };
console.log(settings.theme, dark.theme);

const field = "size";
console.log({ ...settings, [field]: 16 });

const { note, ...withoutNote } = settings;
console.log(withoutNote, "note" in settings);
```

```text
light dark
{ theme: 'light', size: 16, note: 'чернетка' }
{ theme: 'light', size: 14 } true
```

Перша дія замінює поле. Друга робить те саме, коли назву поля зберігає змінна: квадратні дужки в записі об'єкта
означають «обчисли назву». Третя дія прибирає поле. Запис `const { note, ...withoutNote } = settings` називають
**деструктуризацією** (англійською destructuring): він розкладає об'єкт на окремі змінні. Змінна `note` отримує
значення поля `settings.note`, а запис `...withoutNote` збирає всі інші поля в новий об'єкт `withoutNote`. Оператор
`in` відповідає, чи є поле з такою назвою в об'єкті або в його прототипі. Вивід `true` показує, що в `settings` поле
`note` лишилося, тоді як `delete settings.note` змінило б сам об'єкт.

Щоб перетворити всі поля, об'єкт переводять у масив пар і назад. Функція `Object.entries` повертає масив пар `[назва,
значення]`, метод `map` будує з них нові пари, а функція `Object.fromEntries` збирає з пар новий об'єкт. Вираз
`Object.fromEntries(Object.entries({ чай: 120 }).map(([n, p]) => [n, p * 2]))` дає `{ 'чай': 240 }`, а вихідний об'єкт
не змінюється. Запис `([n, p])` у параметрі стрілкової функції теж є деструктуризацією, тільки масиву: він кладе
перший елемент пари в змінну `n`, а другий у змінну `p`.

## `Object.freeze`: як перевірити, що нічого не змінюється

Як упевнитися, що функція нічого не мутує? Можна заборонити мутації й подивитися, чи щось зламається. Функція
`Object.freeze` робить три речі з об'єктом: забороняє додавати поля, забороняє видаляти поля й забороняє змінювати
значення наявних. Вона повертає той самий об'єкт, а не копію. Таку заборону називають **заморожуванням**, а об'єкт
після неї називають замороженим.

**Заморожування торкається лише одного рівня.** Об'єкти всередині лишаються звичайними. У коді нижче функція
`Object.isFrozen` відповідає, чи заморожено об'єкт. Рядок `"use strict"` на початку вмикає суворий режим, про який
ідеться трохи нижче:

```js
"use strict";
const shelf = Object.freeze([{ title: "Кобзар", copies: 2 }]);

shelf[0].copies = 5;
console.log(shelf[0].copies, Object.isFrozen(shelf), Object.isFrozen(shelf[0]));

Object.freeze(shelf[0]);
try {
  shelf[0].copies = 7;
} catch (e) {
  console.log(e.name + ": " + e.message);
}

const mapped = shelf.map((b) => b);
console.log(Object.isFrozen(mapped), Object.isFrozen(mapped[0]));
```

```text
5 true false
TypeError: Cannot assign to read only property 'copies' of object '#<Object>'
false true
```

Масив заморожено, а об'єкт у ньому ні, тому перший запис пройшов. Коли заморозили ще й об'єкт, запис кинув
`TypeError`. Новий масив від `map` не заморожений, бо заморожування не передається результату, а елемент у ньому той
самий заморожений об'єкт.

**Заборонена зміна не завжди дає помилку.** Це залежить від того, як саме вона зроблена, і від режиму. Звичайний
JavaScript деякі помилкові дії мовчки пропускає, бо мову колись задумали простою для початківців. Окремий режим
виконання перетворює такі мовчазні помилки на справжні, щоб їх було видно й можна було одразу виправити. Цей режим
називають **суворим режимом** (англійською strict mode). На сторінці дня трапляється й назва «строгий режим», це те
саме. Суворий режим вмикає рядок `"use strict"`, якщо він стоїть першим у файлі чи функції.

Порівняємо обидва режими на масиві `Object.freeze([3, 1, 2])`. Для цього потрібен файл, який не є модулем. **Модулем**
у цій лекції називаємо модуль ECMAScript: файл у стандартному форматі, який бере код з інших файлів записом `import` і
віддає свій код записом `export`. Модулі завжди виконуються в суворому режимі, про це йдеться нижче. Node має й
старіший власний формат файлів, CommonJS, у якому файли обмінюються кодом через функцію `require`. Файл із розширенням
`.cjs` Node завжди читає як CommonJS, тому модулем ECMAScript такий файл не є, і суворий режим у ньому вмикає лише
рядок `"use strict"`. Збережіть код у файлі `plain.cjs` і запустіть командою `node plain.cjs`. Потім скопіюйте його у
файл `strict.cjs`, допишіть першим рядком `"use strict";` і запустіть копію.

```js
const attempt = (label, action) => {
  const a = Object.freeze([3, 1, 2]); // Щоразу новий заморожений масив
  try {
    const result = action(a);
    console.log(label, "-> повернуто", result, "| масив", a);
  } catch (e) {
    console.log(label, "->", e.name + ": " + e.message);
  }
};

attempt("a[0] = 9", (a) => { a[0] = 9; });
attempt("a.length = 0", (a) => { a.length = 0; });
attempt("delete a[0]", (a) => delete a[0]);
attempt("a.push(9)", (a) => a.push(9));
attempt("a.sort()", (a) => a.sort());
attempt("a.map(...)", (a) => a.map((x) => x * 2));
attempt("a.filter(...)", (a) => a.filter((x) => x > 1));
attempt("a.toSorted()", (a) => a.toSorted());
attempt("a.slice()", (a) => a.slice());
attempt("[...a]", (a) => [...a]);
attempt("a.with(0, 9)", (a) => a.with(0, 9));
```

Без суворого режиму, файл `plain.cjs`:

```text
a[0] = 9 -> повернуто undefined | масив [ 3, 1, 2 ]
a.length = 0 -> повернуто undefined | масив [ 3, 1, 2 ]
delete a[0] -> повернуто false | масив [ 3, 1, 2 ]
a.push(9) -> TypeError: Cannot add property 3, object is not extensible
a.sort() -> TypeError: Cannot assign to read only property '0' of object '[object Array]'
a.map(...) -> повернуто [ 6, 2, 4 ] | масив [ 3, 1, 2 ]
a.filter(...) -> повернуто [ 3, 2 ] | масив [ 3, 1, 2 ]
a.toSorted() -> повернуто [ 1, 2, 3 ] | масив [ 3, 1, 2 ]
a.slice() -> повернуто [ 3, 1, 2 ] | масив [ 3, 1, 2 ]
[...a] -> повернуто [ 3, 1, 2 ] | масив [ 3, 1, 2 ]
a.with(0, 9) -> повернуто [ 9, 1, 2 ] | масив [ 3, 1, 2 ]
```

У суворому режимі, файл `strict.cjs`:

```text
a[0] = 9 -> TypeError: Cannot assign to read only property '0' of object '[object Array]'
a.length = 0 -> TypeError: Cannot assign to read only property 'length' of object '[object Array]'
delete a[0] -> TypeError: Cannot delete property '0' of [object Array]
a.push(9) -> TypeError: Cannot add property 3, object is not extensible
a.sort() -> TypeError: Cannot assign to read only property '0' of object '[object Array]'
a.map(...) -> повернуто [ 6, 2, 4 ] | масив [ 3, 1, 2 ]
a.filter(...) -> повернуто [ 3, 2 ] | масив [ 3, 1, 2 ]
a.toSorted() -> повернуто [ 1, 2, 3 ] | масив [ 3, 1, 2 ]
a.slice() -> повернуто [ 3, 1, 2 ] | масив [ 3, 1, 2 ]
[...a] -> повернуто [ 3, 1, 2 ] | масив [ 3, 1, 2 ]
a.with(0, 9) -> повернуто [ 9, 1, 2 ] | масив [ 3, 1, 2 ]
```

Рядок із написом `повернуто` означає, що помилки не було, а масив наприкінці рядка показує, що він не змінився. Рядок
із `TypeError` означає, що дія кинула помилку. Обидва виводи зведено в таблицю:

| Дія | Без суворого режиму | У суворому режимі |
|-----|--------------------|-------------------|
| `a[0] = 9` | нічого не змінюється, помилки немає | `TypeError: Cannot assign to read only property '0'...` |
| `a.length = 0` | нічого не змінюється, помилки немає | `TypeError: Cannot assign to read only property 'length'...` |
| `delete a[0]` | повертає `false`, помилки немає | `TypeError: Cannot delete property '0'...` |
| `a.push(9)` | `TypeError: Cannot add property 3...` | така сама помилка |
| `a.sort()` | `TypeError: Cannot assign to read only property '0'...` | така сама помилка |
| `a.map(...)`, `a.filter(...)`, `a.toSorted()`, `a.slice()`, `[...a]`, `a.with(0, 9)` | працюють, масив не змінюється | працюють, масив не змінюється |

Причина такої різниці записана в специфікації мови. Присвоєння кидає помилку лише в суворому коді
([PutValue](https://tc39.es/ecma262/#sec-putvalue)), а мутуючі методи завжди вимагають, щоб запис вдався
([Array.prototype.push](https://tc39.es/ecma262/#sec-array.prototype.push)). Розбір читання показує ці алгоритми
докладно. Висновок для практики такий: без суворого режиму присвоєння в заморожений об'єкт мовчить, тому перевірка
через заморожування працює лише в суворому режимі.

Де суворий режим уже ввімкнено без жодного рядка? Модулі ECMAScript завжди суворі. У Node модулем є файл `.mjs`, файл
у пакеті з `"type": "module"` і файл `.js`, у якому є `import` чи `export`. **Пакетом** Node називає теку з файлом
`package.json`, який описує проєкт. Поле `"type": "module"` у цьому файлі каже Node читати всі файли `.js` пакета як
модулі. Модулями є й файли проєкту на React із Vite. **Vite** — це інструмент збирання, тобто програма, яка з файлів
проєкту готує сторінку для браузера. З ним ви працюватимете з дня 11 цієї фази.

Рядок `"use strict"`, поставлений не першим, не діє. У цьому файлі `.cjs` він стоїть другим:

```js
const a = Object.freeze([3, 1, 2]);
"use strict"; // Перед цим рядком уже є код, тому режим не вмикається
a[0] = 9; // Помилки немає, бо режим не суворий
console.log(a);
```

```text
[ 3, 1, 2 ]
```

Присвоєння знову промовчало, а масив не змінився. Отже, цей рядок діє лише тоді, коли стоїть першим.

Є два крайні випадки. Перший стосується трьох вбудованих видів об'єктів. `Map` зберігає пари «ключ — значення», і
ключем у ньому може бути будь-яке значення. `Set` зберігає набір неповторних значень. `Date` зберігає одну мить часу.
`Object.freeze` цим об'єктам не заважає, бо їхні дані лежать не в полях: `map.set(...)` на замороженому `Map` працює.
Другий випадок стосується масиву з одного елемента: він теж може не виявити мутацію. За алгоритмом специфікації `sort`
мав би кинути помилку, а Node 24 для такого масиву помилки не кинув.

```js
"use strict";
const prices = Object.freeze(new Map());
prices.set("Чай", 120);
const tags = Object.freeze(new Set());
tags.add("новинка");
const day = Object.freeze(new Date(0));
day.setFullYear(2000);
console.log(prices.get("Чай"), tags.has("новинка"), day.getFullYear());

console.log(Object.freeze([1]).sort()); // Один елемент

try {
  Object.freeze([2, 1]).sort(); // Два елементи
} catch (e) {
  console.log(e.name + ": " + e.message);
}
```

```text
120 true 2000
[ 1 ]
TypeError: Cannot assign to read only property '0' of object '[object Array]'
```

Перший рядок виводу показує, що всі три заморожені об'єкти прийняли нові дані. Другий рядок показує, що `sort` на
масиві з одного елемента не кинув помилки. Третій рядок показує, що на масиві з двох елементів помилка є. Тому
перевіряйте на даних із кількох елементів.

## Покроковий приклад: ланцюжок перетворень

Методи, що повертають масив, можна викликати один за одним. Покажемо товари в наявності від дешевших до дорожчих, із
вартістю кожного й загальною сумою:

```js
const inStock = products.filter((p) => p.qty > 0);
const cheapFirst = inStock.toSorted((a, b) => a.price - b.price);
const priced = cheapFirst.map((p) => ({ ...p, value: p.price * p.qty }));
const total = priced.reduce((sum, p) => sum + p.value, 0);

console.log(inStock.map((p) => p.sku));
console.log(cheapFirst.map((p) => p.sku));
console.log(priced.map((p) => p.value));
console.log(total);
console.log(products.map((p) => p.sku));
console.log(cheapFirst[0] === products[3], priced[0] === products[3]);
```

```text
[ 'A1', 'C3', 'D4' ]
[ 'D4', 'A1', 'C3' ]
[ 400, 360, 360 ]
1120
[ 'A1', 'B2', 'C3', 'D4' ]
true false
```

| Крок | Метод | Що стало | Чи нові масив і об'єкти |
|------|-------|----------|-------------------------|
| відібрати | `filter` | три товари з чотирьох, Кави немає | масив новий, об'єкти ті самі |
| відсортувати | `toSorted` | Цукор, Чай, Мед | масив новий, об'єкти ті самі |
| дописати вартість | `map` з розгортанням | 400, 360, 360 | масив новий, об'єкти нові |
| підсумувати | `reduce` | 1120 | одне число |

Масив `products` після всього цього лишився в початковому порядку. Останнє порівняння показує різницю між кроками:
після `toSorted` об'єкт Цукру той самий, а після `map` з розгортанням він новий.

Є й ціна. Запис `reduce`, який на кожному кроці робить `[...acc, x]`, копіює весь накопичений масив щоразу. Лічильник
у цьому коді додає розмір кожної такої копії для масиву з 1000 чисел. Виклик `Array.from({ length: 1000 }, (_, i) =>
i)` створює масив із 1000 місць. Функція в другому аргументі для кожного місця отримує два параметри, значення місця й
номер місця, а те, що вона повертає, лягає в масив. Значення місць тут порожні, тому перший параметр названо
підкресленням `_`: це звичайне ім'я для параметра, який не потрібен. Функція повертає номер `i`, тому в масиві лежать
числа від 0 до 999:

```js
const source = Array.from({ length: 1000 }, (_, i) => i);
let copied = 0;
const result = source.reduce((acc, x) => {
  copied += acc.length; // Запис [...acc, x] нижче копіює всі елементи acc
  return [...acc, x];
}, []);
console.log(result.length, copied);
```

```text
1000 499500
```

Перше число є довжиною результату. Друге число показує, що для 1000 елементів було скопійовано 499 500 елементів: нуль
на першому кроці, один на другому і так далі до 999 на останньому. MDN попереджає про це **квадратичне зростання**:
кількість скопійованих елементів росте як квадрат довжини масиву, тому вдвічі довший масив дає приблизно вчетверо
більше копіювання. Для такого завдання досить `map` чи `filter`.

## Типові хибні уявлення

**«`sort` повертає масив, отже, створює новий».** Він повертає той самий масив. Новий масив дає `toSorted` або копія
перед сортуванням.

**«`filter` і `map` роблять повну копію даних».** Обидва створюють лише новий масив. Без розгортання у функції об'єкти
всередині лишаються тими самими, тому зміна знайденого об'єкта зачіпає оригінал.

**«`find` повертає копію».** Він повертає сам елемент. `found.price = 1` є мутацією даних, навіть якщо масив ви не
чіпали.

**«`Object.freeze` заморожує все всередині».** Він заморожує лише те, що йому дали. Для масиву об'єктів треба
заморозити і масив, і кожен об'єкт.

**«Немає помилки, отже, зміна вдалась».** Без суворого режиму присвоєння в заморожений об'єкт мовчить. Перевіряйте
результат, а не відсутність помилки.

**«`Object.assign` створює новий об'єкт».** Він копіює поля з решти аргументів у перший аргумент і повертає цей перший
аргумент. Новий об'єкт буде лише в записі `Object.assign({}, a)`.

## Як це проявиться в React

React ви почнете вивчати у фазі 1, тому спершу кілька слів, без яких цей розділ не прочитати. **Компонент** React — це
функція, яка повертає опис частини сторінки, наприклад кнопки чи списку. Опис записують у вигляді, схожому на HTML, і
такий запис називають **JSX**. У фігурних дужках усередині JSX стоїть звичайний вираз JavaScript, і React показує на
екрані його значення. Функція `useState` створює стан компонента й повертає масив із двох елементів: поточне значення
стану й функцію, яка записує нове значення. Коли нове значення записано, React викликає компонент знову й оновлює
екран.

Документація [Updating Arrays in State](https://react.dev/learn/updating-arrays-in-state) рекомендує для кожної дії
брати метод, що повертає новий масив:

| Дія | Уникати | Брати |
|-----|---------|-------|
| додати | `push`, `unshift` | `concat`, запис `[...arr]` |
| прибрати | `pop`, `shift`, `splice` | `filter`, `slice` |
| замінити | `splice`, `arr[i] = ...` | `map` |
| упорядкувати | `reverse`, `sort` | спершу скопіювати масив |

Таблиця не згадує нових пар, але для упорядкування підходять і `toSorted` та `toReversed`. Наступний дослід запущено в
React 19.3, де компонент показує масив чисел. Код лежить у файлі, ім'я якого закінчується на `.test.tsx`. Такий файл
запускає Vitest, програма для виконання тестів, а бібліотека Testing Library показує компонент в імітації браузера й
натискає його кнопки. Команда `npx vitest run --disable-console-intercept` запускає файл. Vitest друкує ще й власний
короткий підсумок, а нижче показано лише рядки, надруковані через `console.log`.

У коді трапляються ще кілька записів. Розширення `.tsx` означає, що файл написано мовою **TypeScript** і в ньому є
JSX. TypeScript — це JavaScript із позначками типів, за якими можна перевірити, чи правильно код поводиться з даними.
Наприклад, запис `name: string` у функції `click` позначає, що параметр `name` має бути рядком. Метод `join(",")`
склеює елементи масиву в один рядок через кому. Функцію в атрибуті `onClick` React викликає, коли користувач клацає
кнопку, і таку функцію називають **обробником клацання**. Порожні теги `<>` і `</>` лише об'єднують кілька елементів в
один, бо компонент повертає одне значення. Вираз `document.querySelector("p")` знаходить на сторінці перший абзац
`<p>`, а поле `textContent` дає його текст. Запис `?.` потрібен на випадок, коли абзацу немає: тоді вираз дає
`undefined` замість помилки.

```tsx
// @vitest-environment jsdom
// Цей коментар просить Vitest створити імітацію браузера, бо без документа компонент показати ніде.
import { useState } from "react";
import { fireEvent, render, screen } from "@testing-library/react";
import { test } from "vitest";

function Numbers() {
  const [items, setItems] = useState([3, 1, 2]);
  return (
    <>
      <p>{items.join(",")}</p>
      <button onClick={() => setItems(items.sort())}>sort</button>
      <button onClick={() => setItems(items.toReversed())}>toReversed</button>
      <button onClick={() => { items.push(9); setItems(items); }}>push</button>
      {/* Ця кнопка друкує масив зі стану й текст, який зараз стоїть на екрані */}
      <button onClick={() => console.log("масив:", items, "екран:", document.querySelector("p")?.textContent)}>
        показати
      </button>
    </>
  );
}

test("масив і екран", () => {
  render(<Numbers />);
  const click = (name: string) => fireEvent.click(screen.getByText(name));
  click("показати"); // Перший показ
  click("sort");
  click("показати");
  click("toReversed");
  click("показати");
  click("push");
  click("показати");
});
```

```text
масив: [ 3, 1, 2 ] екран: 3,1,2
масив: [ 1, 2, 3 ] екран: 3,1,2
масив: [ 3, 2, 1 ] екран: 3,2,1
масив: [ 3, 2, 1, 9 ] екран: 3,2,1
```

Чотири рядки виводу відповідають чотирьом рядкам таблиці:

| Дія | Що в масиві | Що на екрані |
|-----|-------------|--------------|
| перший показ | `[3, 1, 2]` | 3,1,2 |
| `setItems(items.sort())` | `[1, 2, 3]` | 3,1,2 |
| `setItems(items.toReversed())` | новий `[3, 2, 1]` | 3,2,1 |
| `items.push(9); setItems(items)` | `[3, 2, 1, 9]` | 3,2,1 |

Після `sort` і `push` дані вже інші, а екран ні, бо посилання те саме.

Друга причина лишати незмінені елементи тими самими стосується швидкості. Один компонент може показувати інший і
передавати йому дані атрибутами JSX, наприклад `<Row product={p} />`. Ці дані називають **вхідними параметрами**
компонента, англійською props. Функція `memo` з лекції дня 1 приймає компонент і повертає його версію, яку React не
викликає повторно, якщо вхідні параметри не змінилися за `Object.is`. У тесті нижче кожен рядок списку показує
компонент `Row`, переданий у `memo`. Атрибут `key` дає кожному рядку постійне ім'я, за яким React упізнає цей рядок
між оновленнями. Запис `type Product = ...` мовою TypeScript описує, які поля має товар. Цей тест рахує, скільки разів
React викликав кожен рядок списку з трьох товарів:

```tsx
// @vitest-environment jsdom
import { memo, useState } from "react";
import { fireEvent, render, screen } from "@testing-library/react";
import { test } from "vitest";

type Product = { sku: string; name: string; price: number };

const START: Product[] = [
  { sku: "A1", name: "Чай", price: 120 },
  { sku: "B2", name: "Кава", price: 300 },
  { sku: "C3", name: "Мед", price: 180 },
];
const calls: Record<string, number> = { A1: 0, B2: 0, C3: 0 }; // Лічильники викликів рядків

// memo не викликає Row, якщо product є тим самим об'єктом, що й минулого разу
const Row = memo(function Row({ product }: { product: Product }) {
  calls[product.sku] += 1;
  return <li>{product.name}: {product.price}</li>;
});

function List() {
  const [list, setList] = useState(START);
  return (
    <>
      <ul>{list.map((p) => <Row key={p.sku} product={p} />)}</ul>
      <button onClick={() => setList(list.map((p) => (p.sku === "B2" ? { ...p, price: 350 } : p)))}>map</button>
      <button onClick={() => setList(structuredClone(list))}>clone</button>
    </>
  );
}

test("лічильники рядків", () => {
  render(<List />);
  console.log("перший показ:", calls);
  fireEvent.click(screen.getByText("map"));
  console.log("після map:", calls);
  fireEvent.click(screen.getByText("clone"));
  console.log("після structuredClone:", calls);
});
```

```text
перший показ: { A1: 1, B2: 1, C3: 1 }
після map: { A1: 1, B2: 2, C3: 1 }
після structuredClone: { A1: 2, B2: 3, C3: 2 }
```

Перший рядок виводу показує, що кожен рядок спершу показано один раз. Оновлення одного товару через `map` із
розгортанням викликало лише цей рядок, тому лічильники стали 1, 2, 1. Заміна всього списку через `structuredClone`
викликала всі три рядки, бо всі об'єкти стали новими, тому кожен лічильник виріс ще на одиницю.

Документація також формулює межу правила: змінювати можна лише те, що ви щойно створили. Тому `const next =
[...items]; next.sort(); setItems(next)` є правильним кодом, бо `sort` тут змінює нову копію, яку ще ніхто не тримає.

## Перевірте себе

Спершу дайте відповідь самі, уголос або письмово, і лише потім розгортайте пояснення.

**1. Що надрукує цей код? Зверніть увагу на обидві частини виводу.**

```js
const prices = [30, 4, 100];
const sorted = prices.sort();
console.log(prices === sorted, prices);
```

<details><summary>Відповідь</summary>

`true [ 100, 30, 4 ]`. Метод `sort` повернув той самий масив, тому порівняння дає `true`. Без функції порівняння він
порівнює елементи як рядки, тому `"100"` стоїть першим.

</details>

**2. Що потрапить у стан після `setItems(items.push(5))`?**

<details><summary>Відповідь</summary>

Число, бо `push` повертає нову довжину масиву. Стан перестане бути масивом, а виклики `items.map` далі кинуть помилку.
Крім того, старий масив мутовано.

</details>

**3. Ви знайшли товар через `find` і записали `found.qty = 0`. Чому це мутація стану і як зробити правильно?**

<details><summary>Відповідь</summary>

`find` повертає сам елемент, тому запис змінює об'єкт усередині стану. Правильно побудувати новий масив через `map`,
де для потрібного товару повертається новий об'єкт із розгортанням, а для решти наявний.

</details>

**4. Чому `users.toSorted((a, b) => a.name - b.name)` не змінює порядок?**

<details><summary>Відповідь</summary>

Віднімання рядків дає `NaN`, а `NaN` вважається нулем, тобто «порядок цих двох не змінювати». Для рядків потрібен
`localeCompare` або явне порівняння, яке повертає число зі знаком.

</details>

**5. Масив `a` заморожено. Файл не в суворому режимі. Що станеться під час `a[0] = 1`, `a.push(1)` і `a.map((x) =>
x)`?**

<details><summary>Відповідь</summary>

Присвоєння буде проігноровано без помилки. `push` кине `TypeError`, бо вимагає, щоб запис вдався. `map` спрацює й
поверне новий незаморожений масив.

</details>

**6. Після `const list = Object.freeze([{ n: 1 }])` у суворому режимі виконується `list[0].n = 2`. Що станеться?**

<details><summary>Відповідь</summary>

Запис пройде, і `n` стане 2, бо заморожено лише масив. Об'єкт усередині лишається звичайним, поки його не заморозять
окремо.

</details>

## Словничок лекції

| Слово | Що означає |
|-------|------------|
| метод | функція, яка лежить у полі об'єкта й викликається через крапку після цього об'єкта |
| мутація | зміна наявного об'єкта чи масиву |
| мутуючий метод | метод, який змінює масив, на якому його викликали |
| копіювальний метод | метод, який повертає новий масив, а старий лишає незмінним |
| незмінна пара | метод, який дає той самий результат, що й мутуючий метод, але в новому масиві |
| тіло функції | код, який виконується під час виклику функції |
| істинне значення (truthy) | значення, яке в умові діє як `true` |
| рушій | програма, яка виконує JavaScript у браузері чи в Node |
| деструктуризація (destructuring) | запис, який розкладає об'єкт чи масив на окремі змінні |
| зворотний виклик (callback) | функція, яку передають іншому коду, щоб той її викликав |
| накопичувач | значення, яке `reduce` передає від кроку до кроку |
| функція порівняння | функція, яка отримує два елементи й числом каже, який стоїть раніше |
| стабільне сортування | сортування, де рівні елементи зберігають взаємний порядок |
| заморожування | заборона додавати, видаляти й змінювати поля одного об'єкта |
| суворий режим (strict mode) | режим, у якому заборонені дії кидають помилку, а не мовчать |
| модуль | файл у стандартному форматі ECMAScript, який бере код з інших файлів через `import` і віддає свій через `export` |
| пакет | тека з файлом `package.json`, який описує проєкт |
| Vite | інструмент збирання, який із файлів проєкту готує сторінку для браузера |
| квадратичне зростання | зростання, за якого вдвічі більші дані потребують учетверо більше роботи |
| компонент | функція React, яка повертає опис частини сторінки |
| JSX | запис, схожий на HTML, яким компонент описує частину сторінки |
| TypeScript | JavaScript із позначками типів, за якими перевіряють, чи правильно код поводиться з даними |
| обробник клацання | функція, яку React викликає, коли користувач клацає елемент |
| вхідні параметри (props) | дані, які один компонент передає іншому атрибутами JSX |
