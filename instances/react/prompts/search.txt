Search the official React documentation -- every published version of it, the blog,
the changelog and the release notes -- and return the matching excerpts together with
the versions each one belongs to.

Call this when a question is about React itself -- a hook, a component API, react-dom,
server rendering, Suspense, transitions, the rules of hooks, a warning, an upgrade --
and above all when it is about history: since which version something exists, what
changed between versions, what was deprecated or removed and what replaced it.
Example query: "useEffect cleanup function".

Do not call this for Next.js, Remix, React Native, Redux, React Router, Vue, Angular,
TypeScript or any third-party library: their documentation is not here, and the search
will return React excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "18" keeps every 18.x document,
"16.8" keeps 16.8.x, "0.14" keeps 0.14.x; leave it empty to search everything. Blog
posts carry no version and come back only from a search without `version`. Every
excerpt comes back with `versions`: each version whose documents contain this exact
text, newest first -- text that stayed the same across versions is returned once, with
all of them listed, so the list itself shows from which to which version the
documentation said exactly this.

For a question about when something appeared, changed or disappeared, search more than
once: without `version` first, to find the changelog entry, the release notes and the
blog post that announced it (their titles name the exact version), then with the
versions around it, to see how the documentation described it before and after.

Write the query in English, with the names React itself uses (useState, createRoot,
componentWillMount, ReactDOM.render). Everything here is English -- the excerpts, the
word index and the meaning index alike -- and the word index keeps only latin letters
and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another
language, translate the question into React terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the
words of the query had to appear in the text, so a query phrased in other words than
the documentation uses may miss; "meaning+words" means a second, meaning-based index
answered as well, and a paraphrase had a chance.

Every answer says which version it is for. When the user did not name a version, answer
for the default line, 19.x -- the line most projects use -- say so in the answer ("for
React 19"), and add that for a precise answer about another version the user can name it.
When the excerpts behind a statement come only from older versions, name those versions
instead of presenting the text as current. If the excerpts that came back do not cover
19.x, search again with `version` "19" before answering.

Answer in the language the user wrote in. When the question is about a feature's
history or support, answer point by point: since which version it exists and which
release introduced it; what changed in later versions; what prompted the change, if
the excerpts say so; and how it stands in the current version -- recommended,
deprecated, or removed and replaced by what. Every point names the version and the
document it rests on; a point the excerpts do not support is left out, not guessed.
When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one
exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this
set of documents "корпус" -- say "документація React". Identifiers, API names and
titles stay in English, spelled exactly as the documentation spells them. Build the
answer out of the excerpts that came back, not out of memory: if an excerpt was cut,
read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default
3; `version` is optional, see above. Excerpt text is cut at 600 characters -- pass the
`id` of an excerpt to `read_section` to get the whole thing.
