## `Array`

**Де читати:** [сторінка MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array).
MDN — це довідник із вебтехнологій, який пишуть розробники браузерів і спільнота.

**Що там є.** Це велика довідкова сторінка про все, що стосується масивів. Спершу йде опис, далі перелік усіх методів
зі стислими поясненнями, а потім довгий список прикладів. Цю сторінку не треба читати цілком. Для цього дня важливий
її опис.

**Якщо часу мало,** прочитайте вступ до `Description`, `Copying methods and mutating methods` і `Iterative methods`.

### `Description`

Вступ називає чотири властивості масиву в JavaScript:

- **Масив можна змінювати за розміром, і в ньому можуть лежати значення різних типів.** Якщо це небажано, існують
  типізовані масиви, тобто масиви чисел одного фіксованого типу.
- **Масив не є асоціативним.** Елементи читають за цілими невід'ємними номерами, а не за довільними рядками.
  Асоціативним називають масив, де ключем може бути будь-який рядок.
- **Нумерація починається з нуля.** Останній елемент має номер `length - 1`.
- **Копіювання завжди поверхневе.** Сторінка підкреслює, що всі стандартні вбудовані операції копіювання будь-яких
  об'єктів дають поверхневу копію. Саме цю думку ви бачили в лекції дня 1.

### `Array indices`

Розділ пояснює, що елемент масиву є звичайним полем об'єкта, а номер є назвою цього поля. Тому `arr.0` є синтаксичною
помилкою, бо назва після крапки не може починатися з цифри, а `arr[0]` працює. Запис `arr[2]` перетворює номер на
рядок `"2"`.

Є важлива тонкість. Рядок `"02"` не є номером елемента. Запис `arr["02"]` створює звичайне поле, яке методи масиву не
бачать. Те саме стосується запису `arr.note`:

```js
const arr = [1, 2];
arr["02"] = "рядок";
arr.note = "поле";
console.log(arr.length, Object.keys(arr));
console.log(arr.map((x) => x));
```

```text
2 [ '0', '1', '02', 'note' ]
[ 1, 2 ]
```

Довжина лишилася 2, а `map` не побачив додаткових полів.

### `Relationship between length and numerical properties`

Поле `length` пов'язане з номерами елементів у два боки:

- Якщо записати елемент за номером поза межами масиву, `length` зростає. Між старими елементами й новим лишаються
  **порожні місця** (англійською empty slots), у яких немає навіть `undefined`.
- Якщо зменшити `length`, елементи з більшими номерами видаляються.

```js
const sizes = ["S", "M"];
sizes[3] = "XL";
console.log(sizes, sizes.length, 2 in sizes, sizes[2]);
sizes.length = 1;
console.log(sizes);
```

```text
[ 'S', 'M', <1 empty item>, 'XL' ] 4 false undefined
[ 'S' ]
```

Запис `<1 empty item>` у виводі Node означає порожнє місце. Читання такого місця дає `undefined`, але оператор `in`
показує, що поля там немає. Запис `sizes.length = 1` є мутацією, хоча ніякого методу не викликано, тому на
замороженому масиві в суворому режимі він дає помилку.

### `Array methods and empty slots`

Масив із порожніми місцями називають **розрідженим**. Старі й нові методи обробляють порожні місця по-різному, і цей
розділ перелічує обидві групи:

- Старі методи, наприклад `forEach`, `map`, `filter`, `reduce`, `every`, `some`, не викликають функцію для порожніх
  місць. Методи копіювання, наприклад `concat`, `slice`, `map`, зберігають порожні місця в результаті.
- Нові методи, наприклад `find`, `includes`, `toSorted`, `toReversed`, `toSpliced`, `with`, вважають порожнє місце
  значенням `undefined`.

Ось різниця в запуску:

| Виклик | Результат |
|--------|-----------|
| `[1, , 3].map((x) => x * 2)` | `[ 2, <1 empty item>, 6 ]` |
| `[1, , 3].with(0, 9)` | `[ 9, undefined, 3 ]` |
| `[1, , 3].toReversed()` | `[ 3, undefined, 1 ]` |
| `[3, , 1].sort()` | `[ 1, 3, <1 empty item> ]` |
| `[3, , 1].toSorted()` | `[ 1, 3, undefined ]` |

У коді React розріджені масиви майже не трапляються, бо дані зазвичай приходять цілими. Запис `new Array(3).map(...)`
є винятком, який ви можете зустріти: функція не викличеться жодного разу, бо всі місця порожні.

### `Copying methods and mutating methods`

Це головний розділ для цього дня. Він ділить методи на дві групи.

**Копіювальні методи** спершу створюють новий масив, а потім заповнюють його. Копія завжди поверхнева, бо метод не
заходить усередину елементів. Сторінка описує це так:

- якщо елемент є об'єктом, у новий масив копіюється посилання на нього, тому зміну об'єкта видно через обидва масиви;
- якщо елемент є рядком, числом чи логічним значенням, копіюється саме значення.

**Мутуючі методи** змінюють масив, на якому їх викликали. Їхній результат залежить від методу: це або той самий масив,
або нова довжина. Для цього в лекції є таблиця результатів.

Сторінка також ділить копіювальні методи за тим, яким конструктором вони створюють результат:

| Методи | Звідки беруть конструктор | Що це означає |
|--------|---------------------------|---------------|
| `concat`, `filter`, `flat`, `flatMap`, `map`, `slice`, а також `splice` для масиву вилучених | через `this.constructor[Symbol.species]` | підклас масиву отримає результат свого класу |
| `toReversed`, `toSorted`, `toSpliced`, `with` | завжди звичайний `Array` | результат завжди звичайний масив |

**Конструктор** — це функція, яка створює об'єкт, а `Symbol.species` — поле, через яке підклас вибирає тип результату.
Це стосується лише класів, успадкованих від `Array`. У коді React таких майже немає, тому цю різницю можна поки не
запам'ятовувати.

Далі йде найважливіша таблиця сторінки. Вона називає для кожного мутуючого методу незмінну заміну:

| Мутуючий метод | Незмінна заміна |
|----------------|-----------------|
| `copyWithin()` | заміни одним методом немає |
| `fill()` | заміни одним методом немає |
| `pop()` | `slice(0, -1)` |
| `push(v1, v2)` | `concat([v1, v2])` |
| `reverse()` | `toReversed()` |
| `shift()` | `slice(1)` |
| `sort()` | `toSorted()` |
| `splice()` | `toSpliced()` |
| `unshift(v1, v2)` | `toSpliced(0, 0, v1, v2)` |

Після таблиці сторінка показує простий загальний прийом для будь-якого мутуючого методу: спершу зробити копію через
`arr.slice()` або `[...arr]`, а вже потім викликати метод на копії.

### `Iterative methods`

**Ітеративними** сторінка називає методи, які приймають функцію й викликають її для елементів по черзі: `every`,
`filter`, `find`, `findIndex`, `findLast`, `findLastIndex`, `flatMap`, `forEach`, `map`, `some`.

Функція отримує три аргументи: `element`, тобто поточний елемент, `index`, тобто його номер, і `array`, тобто сам
масив, на якому викликано метод. Сторінка уточнює, що цей `array` не є масивом, який зараз будується: з функції до
результату `map` дістатися неможливо.

Другий аргумент таких методів, `thisArg`, задає значення `this` усередині функції. Для стрілкової функції він нічого
не змінює, бо вона не має власного `this`. У сучасному коді його майже не пишуть.

Сторінка наводить спрощену схему роботи таких методів і робить кілька висновків. Перекажемо їх:

- Довжина запам'ятовується до початку циклу, тому додані елементи не обробляються.
- Вміст не запам'ятовується, тому зміну ще не оброблених елементів функція побачить.
- `every`, `find`, `findIndex`, `findLast`, `findLastIndex` і `some` зупиняються, щойно відповідь стала відомою.
- `reduceRight`, `findLast` і `findLastIndex` рухаються від кінця до початку.
- `find`, `findIndex`, `findLast` і `findLastIndex` не перевіряють, чи елемент справді є, тому порожні місця для них
  виглядають як `undefined`.

Окремо сказано про два методи, схожі на ітеративні, але не такі:

- **`reduce` і `reduceRight`.** Вони мають інші аргументи: функція отримує ще й накопичувач, а `thisArg` немає.
- **`sort`.** Він змінює масив, не приймає `thisArg` і може викликати функцію кілька разів для одного елемента.

Важливе речення цього розділу: усі ітеративні методи є копіювальними, тобто самі масив не змінюють. Але функція, яку
ви їм передали, може це зробити. Про це йдеться в останньому прикладі сторінки.

### `Generic array methods`

**Загальними** (generic) методи названо тому, що вони не потребують справжнього масиву. Вони читають лише `length` і
елементи за номерами, тому працюють з будь-яким об'єктом, у якого це є:

```js
console.log(Array.prototype.join.call({ 0: "a", 1: "b", length: 2 }, "+"));
console.log(Array.prototype.map.call("ой", (c) => c + c));
```

```text
a+b
[ 'оо', 'йй' ]
```

Запис `.call` викликає функцію, підставляючи перший аргумент як `this`. Об'єкт, що має `length` і елементи за
номерами, називають **схожим на масив** (`Array-like objects`). Сторінка наводить приклади таких об'єктів: `NodeList`
і `HTMLCollection` у DOM та `arguments` у функціях. Вони мають номери й довжину, але не мають методів масиву, тому у
браузерному коді їх часто спершу перетворюють через `Array.from` чи `[...список]`.

Підрозділ `Normalization of the length property` пояснює, що `length` перетворюється на ціле число від 0 до `2^53 -
1`, а `NaN` стає нулем. Для цього дня він необов'язковий.

### `Constructor`, `Static methods` і `Instance methods`

Ці три розділи є покажчиком. Для цього дня корисні такі записи:

| Запис | Що робить |
|-------|-----------|
| `Array.from(x, fn)` | створює масив зі схожого на масив або ітерованого значення, може одразу перетворити елементи |
| `Array.isArray(x)` | перевіряє, чи `x` є масивом, бо `typeof` дає `"object"` |
| `at(-1)` | читає елемент, де від'ємний номер рахується від кінця |
| `includes`, `indexOf`, `lastIndexOf` | шукають значення, а не умову; різницю в порівнянні `NaN` розглянуто в лекції дня 1 |
| `flat`, `flatMap` | вкладені масиви стають плоскими: `[1, [2, [3]]].flat()` дає `[ 1, 2, [ 3 ] ]`, а `[1, 2].flatMap((x) => [x, x])` дає `[ 1, 1, 2, 2 ]` |
| `findLast` | як `find`, але шукає від кінця |

Конструктор `Array(n)` створює масив із порожніми місцями, а `Array.of` створює масив із переданих значень.

Коротко про приклади, які варто прочитати:

- **`Copy an array`.** Сторінка повторює, що всі три способи дають поверхневу копію, і для глибокої копії називає
  `JSON.stringify` з `JSON.parse` або `structuredClone`.
- **`Creating a two-dimensional array`.** Двовимірний масив є масивом масивів, тому на ньому особливо добре видно
  поверхневість. Цей приклад сторінки показує шахову дошку. Наша перевірка показує типову пастку з таким масивом:

```js
const grid = Array(2).fill([]);
grid[0].push("x");
console.log(grid, grid[0] === grid[1]);

const grid2 = Array.from({ length: 2 }, () => []);
grid2[0].push("x");
console.log(grid2);
```

```text
[ [ 'x' ], [ 'x' ] ] true
[ [ 'x' ], [] ]
```

Метод `fill` кладе в усі місця посилання на один масив, а `Array.from` із функцією створює новий масив для кожного
місця.

### `Mutating initial array in iterative methods`

Цей приклад показує, що станеться, якщо функція змінить масив під час обходу. Сторінка формулює правило так:
обробляються лише номери від 0 до початкової довжини, а значення читається в той момент, коли до нього дійшла черга.
Звідси такі наслідки:

- елементи, додані за межі початкової довжини, не обробляються;
- вже оброблені елементи не обробляються вдруге;
- зміну ще не обробленого елемента функція побачить;
- видалені елементи не обробляються.

```js
const queue = [1, 2, 3];
queue.forEach((x, i) => {
  if (i === 0) queue.shift();
  console.log(x);
});

const grow = [1, 2];
console.log(grow.map((x) => { grow.push(9); return x * 2; }), grow);
```

```text
1
3
[ 2, 4 ] [ 1, 2, 9, 9 ]
```

У першому випадку `shift` посунув елементи, тому двійка опинилася на номері 0, який уже оброблено, і її пропущено. У
другому випадку `map` обробив лише два початкові елементи, хоча масив виріс. Сторінка прямо застерігає, що такий код
важко зрозуміти, тому його варто уникати. У React функція всередині `map` узагалі не має змінювати дані.

### Навіщо це в React

## `Object.freeze()`

**Де читати:** [сторінка
MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/freeze).

**Що там є.** Сторінка описує найсильнішу заборону змін, яку дає мова: що саме вона забороняє, що лишається дозволеним
і чому заморожування торкається лише одного рівня.

**Якщо часу мало,** прочитайте `Description` і приклади `Freezing arrays` та `Deep freezing`.

### `Syntax`

`Object.freeze(obj)` отримує об'єкт і повертає **той самий** об'єкт. Копії не створюється, тому `Object.freeze(x) ===
x` завжди дає `true`. Якщо передати просте значення, функція поверне його як є. Наприклад, `Object.freeze(5)` дає `5`.

### `Description`

Сторінка пояснює заморожування через **дескриптор поля**. Кожне поле об'єкта має кілька позначок, які й утворюють
дескриптор:

| Позначка | Що означає |
|----------|-----------|
| `writable` | значення поля можна замінити |
| `enumerable` | поле показується під час перебору |
| `configurable` | поле можна видалити або змінити його позначки |

Заморожування робить дві дії: забороняє додавати нові поля й ставить усім наявним полям `configurable: false`, а
звичайним полям ще й `writable: false`. Це легко побачити:

```js
const fr = Object.freeze({ a: 1 });
console.log(Object.getOwnPropertyDescriptor(fr, "a"));
```

```text
{ value: 1, writable: false, enumerable: true, configurable: false }
```

Далі розділ описує особливі випадки:

- **Як проявляється заборона.** Спроба змінити заморожений об'єкт або нічого не робить мовчки, або кидає `TypeError`.
  Сторінка застерігає, що помилка виникає найчастіше в суворому режимі, але не лише в ньому. Метод `push` з лекції є
  саме таким випадком.
- **Геттери й сетери працюють далі.** **Геттер** — це поле, значення якого обчислює функція, а **сетер** — поле, запис
  у яке викликає функцію. Заморожування не заважає їм працювати. Запуск показав, що запис через сетер у замороженому
  об'єкті спрацював, а значення змінилося.
- **Вкладені об'єкти не заморожуються.** Це головне застереження, і воно ж пояснює дві дії в завданні цього дня.
- **Масив можна заморозити**, бо масив є об'єктом. Після цього його елементи не можна змінювати, додавати й видаляти.
- **Приватні поля класу не захищені**, бо вони не є полями в цьому сенсі й дескрипторів не мають. У нашому запуску
  лічильник із приватним полем у замороженому об'єкті рахував далі.
- **Типізований масив чи `DataView` з елементами** дає `TypeError: Cannot freeze array buffer views with elements`, бо
  це вікна в байти пам'яті.

Останнє речення розділу порівнює заморожування з `Object.seal`: `seal` не дає додавати й видаляти поля, але дозволяє
замінювати значення. Ось три рівні заборони в запуску без суворого режиму, де для кожного об'єкта `{ a: 1 }` виконано
запис у `a`, додавання поля `b` і видалення `a`:

| Функція | Що лишилося від `{ a: 1 }` | Значення змінюється? | Поля додаються? | Поля видаляються? |
|---------|----------------------------|----------------------|-----------------|-------------------|
| `Object.preventExtensions` | `{}` | так | ні | так |
| `Object.seal` | `{ a: 2 }` | так | ні | ні |
| `Object.freeze` | `{ a: 1 }` | ні | ні | ні |

### `Examples`

- **`Freezing objects`.** Цей приклад показує кожен вид заборони: присвоєння, додавання, видалення, зміну через
  `Object.defineProperty` і заміну прототипу. Поза суворим режимом перші види заборон лишаються непомітними, а у
  функції з `"use strict"` вони кидають `TypeError`. Методи `Object.defineProperty` і `Object.setPrototypeOf` кидають
  помилку в будь-якому режимі. Наш запуск це підтвердив для `defineProperty`: `TypeError: Cannot redefine property:
  price`.
- **`Freezing arrays`.** Присвоєння елементу мовчить, а `push` кидає помилку. Лекція показує ту саму різницю в
  таблиці.
- **`Deep freezing`.** Спершу приклад показує, що вкладений об'єкт можна змінити. Далі він наводить рекурсивну
  функцію, яка обходить усі поля й заморожує все, що знайшла. Сторінка попереджає про дві проблеми: функція
  зациклиться на об'єкті, що посилається сам на себе, і може заморозити те, чого не треба, наприклад `window`. Для
  цього вона пропонує запам'ятовувати вже оброблені об'єкти через `WeakSet`, тобто спеціальний набір об'єктів.

У цьому розділі є й термінологія: об'єкт називають **незмінним** (immutable), якщо його власні поля зафіксовані, а
**константним** (constant), якщо зафіксовано все дерево об'єктів, на які він посилається. Звичайне заморожування дає
лише перше.

### `See also`

Розділ веде до `Object.isFrozen`, `Object.isSealed`, `Object.isExtensible`, `Object.preventExtensions` і
`Object.seal`. Функція `Object.isFrozen` корисна для перевірки, але має крайній випадок: `Object.isFrozen(5)` дає
`true`, а незаморожений об'єкт без полів, який не можна розширювати, теж вважається замороженим. Звичайний порожній
масив `[]` дає `false`, бо його можна розширювати.

### Навіщо це в React

У виробничому коді стан зазвичай не заморожують, бо перевірка лише заважала б. Заморожування є інструментом перевірки:
під час розробки чи в тесті воно перетворює тиху мутацію на помилку. Сам React у режимі розробки заморожує елементи,
які створює: запуск показав `Object.isFrozen(createElement("div", { a: 1 }))` рівним `true`, і так само для його
`props`. Тому в режимі розробки спроба змінити `props` у компоненті зазвичай закінчується помилкою, і причину ви вже
знаєте.

## Як читати алгоритми ECMAScript

План дня не вимагає читати специфікацію, але її розділи названо в джерелах теорії дня. Тому ось як прочитати ті самі
правила в [ECMA-262](https://tc39.es/ecma262/). Специфікація не пояснює, а записує кроки, які мають дати певний
результат. Читати її варто так: знайти потрібну операцію за назвою, виконати кроки на конкретному значенні й
записувати, що відбувається.

| Запис | Що означає |
|-------|-----------|
| `Let x be ...` | завести змінну алгоритму |
| `Perform ...` | виконати дію, результат не потрібен |
| `Return ...` | завершити й видати результат |
| `?` перед викликом | якщо виклик дав помилку, передати її далі |
| `!` перед викликом | автори стверджують, що помилки тут бути не може |
| `[[Set]]`, `[[OwnPropertyKeys]]` | внутрішній метод об'єкта, якого немає в JavaScript за цим іменем |
| `𝔽(k)` | ціле число `k`, перетворене на число JavaScript |

Докладніше про ці записи йдеться в розборі читання дня 1. Номери розділів змінюються від видання до видання, тому
шукайте операцію за назвою.

### `Object.freeze ( obj )`, розділ 20.1.2.6

Алгоритм має чотири кроки. Якщо `obj` не об'єкт, повернути його. Викликати `SetIntegrityLevel(obj, frozen)`. Якщо вона
повернула `false`, кинути `TypeError`. Повернути `obj`. Звідси випливають і поведінка з простими значеннями, і той
самий об'єкт у результаті.

### `SetIntegrityLevel ( obj, level )`, розділ 7.3.15

Ця операція спершу викликає `[[PreventExtensions]]`, що забороняє додавати поля. Потім вона бере всі власні ключі
через `[[OwnPropertyKeys]]`. Для кожного ключа вона читає опис поля й ставить нові позначки: для звичайного поля
`[[Configurable]]: false` і `[[Writable]]: false`, для геттера чи сетера лише `[[Configurable]]: false`. Жодного
кроку, який заходить усередину значень, в алгоритмі немає, тому заморожування торкається лише одного рівня. Геттери й
сетери лишаються робочими, бо `[[Writable]]` до них не застосовується.

### Чому `a[0] = 9` мовчить, а `a.push(9)` кидає помилку

Обидва шляхи ведуть до внутрішнього методу `[[Set]]`, який на замороженому об'єкті повертає `false`. Різниця лише в
тому, хто вирішує, що робити з цим `false`.

| Запис | Де вирішується | Що там написано |
|-------|---------------|-----------------|
| `a[0] = 9` | [6.2.5.6 PutValue](https://tc39.es/ecma262/#sec-putvalue) | кинути `TypeError`, лише якщо результат `false` і посилання має позначку `[[Strict]]`, тобто код суворий |
| `a.push(9)` | [23.1.3.23 push](https://tc39.es/ecma262/#sec-array.prototype.push), [7.3.4 Set](https://tc39.es/ecma262/#sec-set-o-p-v-throw) | метод викликає `Set(obj, ключ, значення, true)`; останній параметр `throw` наказує кидати помилку за будь-якого режиму |

**Покроково для `Object.freeze([3, 1, 2]).push(9)`:**

| Крок алгоритму `push` | Значення | Результат |
|-----------------------|----------|-----------|
| `Let length be ? LengthOfArrayLike(obj)` | `length` = 3 | продовжуємо |
| `Let argCount be ...` | `argCount` = 1 | продовжуємо |
| `Perform ? Set(obj, "3", 9, true)` | `[[Set]]` повертає `false`, бо масив не можна розширювати | `throw` дорівнює `true`, тому `TypeError` |

Node повідомляє саме про цей крок: `TypeError: Cannot add property 3, object is not extensible`.

### `Array.prototype.sort ( comparator )`, розділ 23.1.3.30, і `toSorted`, розділ 23.1.3.34

Обидва алгоритми майже збігаються, і саме це корисно побачити:

| Етап | `sort` | `toSorted` |
|------|--------|-----------|
| перевірити функцію порівняння | так | так |
| куди писати | у той самий об'єкт `obj` | спершу `ArrayCreate(length)` створює новий масив |
| зібрати елементи | `SortIndexedProperties(..., skip-holes)`, порожні місця пропускаються | `SortIndexedProperties(..., read-through-holes)`, порожні місця читаються як `undefined` |
| записати результат | `Set(obj, номер, значення, true)`, що кидає помилку на замороженому масиві | `CreateDataPropertyOrThrow(array, ...)` у новий масив |
| що повернути | `obj`, тобто той самий масив | `array`, тобто новий масив |

Останній рядок `sort` і є причиною пастки цього дня: крок `Return obj` повертає те саме посилання.

Обидва методи порівнюють елементи через [CompareArrayElements](https://tc39.es/ecma262/#sec-comparearrayelements). Її
кроки пояснюють усе, що ви бачили в лекції. Значення `undefined` стає наприкінці ще до виклику вашої функції. Якщо
функція порівняння передана, її результат перетворюється на число, і `NaN` стає нулем. Без функції обидва значення
перетворюються на рядки й порівнюються як рядки, тому `10` стоїть перед `9`.

Є один випадок, де рушій поводиться не так, як написано. За кроками `sort` масив `Object.freeze([1])` теж мав би дати
помилку, бо `Set` виконується і для єдиного елемента. Node 24 повернув масив без помилки, а `Object.freeze([1,
2]).sort()` помилку кинув, хоча цей масив уже відсортований. Тому не покладайтеся на перевірку на даних із одного
елемента.

### `Array.prototype.reduce`, розділ 23.1.3.24

Примітка цього розділу описує все, що лекція каже про початкове значення. Якщо його передано, першим накопичувачем є
воно, а поточним елементом є перший елемент. Якщо ні, накопичувачем є перший елемент, а поточним другий. На порожньому
масиві без початкового значення алгоритм кидає `TypeError`. Функція отримує чотири аргументи: накопичувач, поточне
значення, номер і сам масив.

## Запитання до читання

**1. Які два види результату можуть повертати мутуючі методи, за словами сторінки `Array`?**

<details><summary>Відповідь</summary>

Або посилання на той самий масив, як `sort` і `reverse`, або нову довжину, як `push` і `unshift`. Лекція додає, що
`pop`, `shift` і `splice` повертають вилучені елементи.

</details>

**2. Чому `arr["02"] = 1` не змінює `arr.length`, а `arr["2"] = 1` змінює, якщо довжина масиву була 2?**

<details><summary>Відповідь</summary>

`"2"` є правильним номером елемента, тому поле стає елементом, і довжина зростає до 3. `"02"` не є номером, тому це
звичайне поле об'єкта, яке методи масиву ігнорують.

</details>

**3. Чому `Array(2).fill([])` дає масив, у якого елементи пов'язані?**

<details><summary>Відповідь</summary>

Вираз `[]` обчислюється один раз, і `fill` кладе в обидва місця посилання на той самий масив. Функція в `Array.from({
length: 2 }, () => [])` викликається для кожного місця окремо, тому створює різні масиви.

</details>

**4. Чим описи полів замороженого об'єкта відрізняються від звичайних?**

<details><summary>Відповідь</summary>

Звичайне поле має `writable: true` і `configurable: true`. Заморожене поле має в обох позначках `false`. Значення
`enumerable` не змінюється, тому заморожене поле перебирається як раніше.

</details>

**5. Де в алгоритмі видно, що `Object.freeze` не заморожує вкладені об'єкти?**

<details><summary>Відповідь</summary>

`SetIntegrityLevel` проходить лише власні ключі переданого об'єкта й змінює позначки цих полів. Значень полів він не
читає як об'єкти й не викликає себе для них.

</details>

**6. Якими двома кроками алгоритм `toSorted` відрізняється від `sort` так, що заморожений масив не заважає?**

<details><summary>Відповідь</summary>

`toSorted` створює новий масив через `ArrayCreate` і записує в нього через `CreateDataPropertyOrThrow`. До вихідного
масиву він лише читає, а `sort` пише у вихідний масив через `Set` із `throw = true`.

</details>
