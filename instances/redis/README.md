# redis — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Redis — сервер структур даних у пам'яті: команди й типи даних,
`redis.conf` і `sentinel.conf`, збереження на диск (RDB, AOF), реплікація, Sentinel, Cluster, ACL, транзакції, Lua і
Functions, потоки, витіснення, клієнтське кешування, протокол RESP. Документація — офіційна, кожної мінорної лінії від
1.3 до 8.10 у тому вигляді, якою вона була на день виходу наступної лінії: сайт redis.io, конфігураційні файли й нотатки
усіх 269 стабільних випусків, код `src/` і тести першого та останнього випуску кожної лінії. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

redis.io показує лише поточну версію, а на проді живуть 6.2, 7.0, 7.2 і 7.4 одночасно; розділ HISTORY сторінки команди
каже, з якої версії є аргумент, але не те, як сторінка виглядала тоді. Тут кожна лінія — окремим знімком, а
`redis.conf` — кожного випуску: відповідь «який default у `maxmemory-policy` в 6.2» береться з файла 6.2, а не з пам'яті.
Клієнти (ioredis, node-redis) і BullMQ — окремі примірники.

## Що в цій теці

- `corpus/` — паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа. Самих текстів тут немає:
  корпус в архіві.
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`.
- `sources.json` — звідки корпус будується (6 джерел), і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — токен GitHub і, для кроку `ask`, ключ Anthropic; `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики через `./df redis <крок>`.

## Звідки документація

| Що | Читач |
|----|-------|
| обидва сайти | `ghsite-milestones` (знімок гілки на дату кожної лінії; версії — з `milestones` джерела) |
| код, тести, конфіги | `ghcode-history` (код — з `outline`) |
| нотатки випусків | `ghreleases` (пре-релізи відкинуто за `skip`) |

Нового коду для Redis не знадобилось.

Особливості:

- **Один ключ для обох сайтів.** У `redis/docs` сторінки лежать під `content/`, у `redis-doc` — у корені; `slug_rewrite`
  знімає `content-`, тож `commands/xadd.md` обох репозиторіїв — один ключ `commands-xadd`, і редакції різних ліній
  згортаються в одну відповідь (обидва джерела — одна родина `site` у `config.json`). Решта розділів у сайтів названа
  по-різному (`topics-persistence` і `docs-management-persistence` проти `operate-oss-and-stack-management-persistence`) —
  їх видно поруч як різні сторінки.
- **Мітки версій.** Знімок сайту несе лінію і рік («7.4, 2026»); фільтр `version: "7.4"` лишає сайт 7.4 і всі 7.4.x
  тегів коду, `"2023"` — усе, що лежало на сайті в 2023 році. Перелік ліній у відповіді сервера — мінорний
  (`version_line_depth: 2`): 1.3, 2.0, …, 8.10.
- **Імена документів.** Сайт: `commands-xadd`, `topics-sentinel`, `develop-data-types-streams`,
  `operate-oss-and-stack-management-persistence`. Конфіги: `conf-redis-conf`, `conf-sentinel-conf`,
  `conf-00-releasenotes` (один ключ на всі 269 випусків, версія розрізняє). Код: `src-src-t-stream-c`, тести:
  `test-tests-unit-type-stream-tcl`. Нотатки GitHub: `redis-7.2.0`.
- **Нотатки до 5.0.10** живуть лише у `00-RELEASENOTES` тега (GitHub Releases тоді не заводили).
- **Весь redis.io.** Сайт 7.4+ тримає й Redis Enterprise Software (`operate-rs-*`), Cloud (`operate-rc-*`), Kubernetes,
  RedisInsight, RDI (`integrate-*`), RedisVL (`develop-ai-*`) — узято як є, бо такий сайт. Для питань про OSS варто
  називати `redis.conf`, «open source» чи команду: інакше пошук по словах приносить сторінки Enterprise.

## Межі, про які треба пам'ятати

- Лише стабільні випуски: rc, alpha, beta, milestone-теги і Releases не взято.
- Клієнтських бібліотек тут немає: сторінки `develop-clients-*` сайту — це лише вступ до кожного клієнта. ioredis,
  node-redis і BullMQ — окремі примірники.
- Для лінії 1.3 знімка сайту немає (репозиторій `redis-doc` молодший за вихід 2.0); від 1.3 є лише `redis.conf` і
  README тега 1.3.6.
- Сторінки Enterprise і Cloud присутні, але відповіді за замовчуванням — для open source; про це сказано в промптах.

## Архівний режим: сервер без корпусу

Корпус в архіві від самого початку: у `corpus/` лежить лише паспорт, а сервер підіймається з кешу фрагментів і
колекції Qdrant; відповіді ті самі до символа.

**Де тексти.** В архіві `~/archives/docfactory/redis-corpus-2026-10-15.tar.gz` (170 МБ: 19 678 текстів, паспорт і
сховище сирого `raw/`; перед видаленням розпакований окремо й звірений з диском — нуль розбіжностей). Лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
tar -czf ~/archives/docfactory/redis-corpus-РРРР-ММ-ДД.tar.gz -C instances/redis corpus raw
find instances/redis/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/redis/raw
gzip -9 -c instances/redis/index/passages.json > instances/redis/index/passages.json.gz
```

**Як повернути тексти** — перед будь-яким оновленням:

```
tar -xzf ~/archives/docfactory/redis-corpus-2026-10-15.tar.gz -C instances/redis
./df redis smoke
```

**Оновлення.** Нова мінорна лінія — новий рядок у `milestones` джерела `redis-docs-site` («"8.12": "РРРР-ММ-ДД"», дата
виходу) і теги в `redis-conf` (кожен випуск), `redis-src` і `redis-tests` (перший і останній випуск лінії). Далі
`./df redis refresh`, `manifest`, `vectors`, `smoke`, `quality`. `./df redis list` довго (складає перелік усіх знімків):
краще одразу `refresh`.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають. Для роботи сервера збирати нічого не
треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df redis sources --why     # перелік джерел і білий список
./df redis refresh           # завантажити все задеклароване (близько 1 год 20 хв)
./df redis manifest          # оновити паспорт
./df redis setup             # Qdrant чи пошук лише по словах
./df redis vectors           # залити корпус у docs-redis (близько 4 годин: 97 тисяч фрагментів)
./df redis smoke             # перевірки
```

Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df redis serve            # порт 8845
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8845/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user redis-docs http://127.0.0.1:8845/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User).

**3. Перевірити.** `/mcp` — має бути `redis-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера.
