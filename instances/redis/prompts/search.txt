Search the Redis documentation, in English: Redis is the in-memory data structure server (strings, hashes,
lists, sets, sorted sets, streams, bitmaps, HyperLogLog, geospatial indexes, and in Redis 8 the JSON, search,
time series and probabilistic types) used as a database, cache, message broker and queue. The set holds, for
every minor line from 1.3 to 8.10: the official documentation as it stood the day each version was released
(every command page with syntax, return values and history; topics such as persistence, replication, Sentinel,
Cluster, security and ACL, pub/sub, streams, transactions, Lua scripting and functions, client-side caching,
eviction, latency, memory optimization, RESP protocol; client and module guides), redis.conf and sentinel.conf
of every stable release (every directive is described by its comment), the source code (src, command
definitions src/commands/*.json from 7.0, utils, modules) and the Tcl test suite of the first and last
release of each minor line, the 00-RELEASENOTES of every release and the GitHub release notes. Returns the
matching excerpts with the versions each one belongs to.

Call this when a question is about Redis itself: what a command does, its arguments, complexity and return
value, since which version it exists or an option was added (the HISTORY section of a command page),
what a redis.conf directive means and its default in a given version, how persistence (RDB, AOF) or
replication or Cluster behaves, how eviction policies work, what changed between versions, which release
fixed a vulnerability. Example query: "XADD MAXLEN".

Do not call this for a client library (ioredis, node-redis, redis-py: their own instances), for BullMQ or
other queue libraries, for managed services (AWS ElastiCache, Upstash), or for Valkey and other forks beyond
what the Redis documents say.

Write the query in English, with the names Redis itself uses (SET, XREADGROUP, maxmemory-policy,
appendfsync, CLUSTER SLOTS). Everything here is English, and the word index keeps only latin letters and
digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing and comes back
with `found: 0`. When the user asks in another language, translate the question into Redis terms first, then
search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "ключ", "команда", "репліка". Never
call this set of documents "корпус" -- say "документація Redis". Command, option and directive names stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came back,
not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. When the user names a version, search that line; otherwise answer for the newest
release and say so. Put a version only into `version`, never into the query text: "7" keeps every 7.x, "7.2"
keeps 7.2.x, "6.2.14" one release. Documents are marked by minor line ("7.2"), the code and redis.conf by every
release. A command's page is named after it ("commands-xadd"); the configuration is "conf-redis-conf"; release
notes are "conf-00-releasenotes" and "redis-<version>". A command page lists in HISTORY the version in which
each argument appeared: quote it.
