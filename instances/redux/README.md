# redux — примірник фабрики docfactory

Шістнадцятий примірник фабрики: захищений MCP-сервер, що відповідає на питання про Redux і бібліотеки поруч із ним —
Redux Toolkit з RTK Query, React Redux, Reselect, Immer, redux-thunk, redux-saga, redux-persist і Redux DevTools — за
офіційною документацією всіх їхніх версій, README кожної опублікованої версії пакетів, нотатками релізів і реєстром
версій npm. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані
домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

Redux за десять років змінив спосіб писати код двічі. Спершу були «ручні» reducer-и з `switch`, константи типів
дій, `createStore` і `connect`; потім Redux Toolkit (`configureStore`, `createSlice`, `createAsyncThunk`) і хуки React
Redux (`useSelector`, `useDispatch`); тепер ще й RTK Query для запитів до сервера. Проєкти живуть на всіх трьох
етапах, і відповідь «як це зробити» залежить від того, на якому з них проєкт і яких версій пакети в ньому стоять.

Тому тут документація кожної версії, а не лише поточна: один і той самий текст, що не змінювався між версіями,
лежить один раз із переліком усіх версій, де він був таким. А для питань «що з чим сумісне» (Toolkit 2 і React
Redux 9, React 18 чи 19, TypeScript) — реєстр npm з peer-залежностями кожної версії.

найпопулярнішої лінії за завантаженнями npm, а де поширені дві — для обох. На питання про ручні reducer-и чи
`createStore` відповідь додає, як те саме робить Toolkit: так радить сама документація.

### Проміжні збірки в реєстрі

У реєстрі npm трапляються версії, які релізами не є: збірки з хешем коміту чи номером pull request у номері
(`1.2.0-pr.123`, `0.3.1-8de0114`) і `0.0.0-…`. Це збірки для перевірки змін до релізу; README таких версій не
береться, але в реєстрі вони лишаються — якщо така версія трапиться в lock-файлі, документ реєстру покаже її дату й
мітку. Передрелізи (`-alpha`, `-beta`, `-rc`) — інша річ: це версії на шляху до релізу, вони беруться всюди.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження); `.mcp.json` — запис
  HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df redux <крок>`.

- **React Redux** тримає копії документації старих версій у `website/versioned_docs`; їх не взято: той самий текст
  уже є на тегах своєї версії, а з тегу новішої він отримав би неправильну мітку.
- **Теги монорепозиторіїв.** У redux-toolkit беруться лише теги релізів `@reduxjs/toolkit`, у redux-saga — лише

- **DevTools без історії версій:** поточна документація — знімок `main` з міткою 4.0 (лінія

- **Кілька версій без README:** перші 0.x і окремі передрелізи — ні коміту публікації, ні тегу для них немає. Також

- **Релізи без версії.** Нотатки релізів інших пакетів монорепозиторіїв (`@rtk-query/codegen-openapi@…`,

## Архівний режим: сервер без корпусу

Текстів у `corpus/` немає: примірник працює з кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді
при цьому ті самі до символа — кеш тримає повний текст кожного фрагмента, а не лише його адресу.

**Де тексти.** В архіві `~/archives/docfactory/redux-corpus-2026-10-09.tar.gz` (9,2 МБ, 3 368 текстів і паспорт;
перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей) і в історії git: останній коміт із
текстами — той, що перед «Корпус redux в архів». Архів лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/redux-corpus-2026-10-09.tar.gz -C instances/redux
./df redux smoke
```

Після розпакування `git status` покаже 3 368 «нових» файлів: у git вони більше не ведуться, і комітити їх назад не
треба — досить оновити корпус, перепакувати архів і знову винести тексти.

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/redux/index/passages.json                  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/redux-corpus-РРРР-ММ-ДД.tar.gz -C instances/redux corpus
find instances/redux/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/redux/index/passages.json > instances/redux/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш спершу розпаковують — розділ «На іншій машині» нижче.

## Установка venv

```
cd instances/redux
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df redux sources --why   # перелік джерел і білий список
./df redux refresh         # завантажити все задеклароване (~1,5 години)
./df redux manifest        # оновити паспорт
./df redux setup           # Qdrant чи пошук лише по словах
./df redux vectors         # залити корпус у docs-redux (~30 хвилин)
./df redux smoke           # перевірки
```

`refresh` і `vectors` довші за 30 хвилин: із Claude Code їх треба запускати окремим процесом (`setsid nohup …`),
інакше фонову задачу обірве оболонка. Обірваний `refresh` продовжується з `--missing`: уже записане він не тягне
вдруге. Імена джерел без `--missing` прогін не звужують.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df redux serve          # порт 8776
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8776/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user redux-docs http://127.0.0.1:8776/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `redux-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію
Claude Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і
«Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).

## На іншій машині

Інше вікно VS Code на тій самій машині нічого, крім кроків 1–3 вище, не потребує: сервер один, клієнтів скільки
завгодно. На іншій машині (теж WSL) бракує трьох речей, яких немає в git: venv примірника, `.env` і векторів у
Qdrant.

**1. Код і кеш.** Отримати репозиторій зі свіжими комітами (`git clone` або `git pull` після того, як їх запушено),
перейти в його корінь і розпакувати кеш фрагментів — текстів корпусу в репозиторії немає, сервер підіймається з нього:

```
gunzip -k instances/redux/index/passages.json.gz
```

**2. Venv примірника** — за розділом «Установка venv» вище. `.env` для пошуку не потрібен: токен GitHub треба лише
для `refresh`, ключ Anthropic — лише для `ask`.

**3. Спосіб пошуку.** Два варіанти:

```
./df redux setup --vectors      # з Qdrant: потрібен Docker
./df redux setup --no-vectors   # лише пошук по словах: без Docker, одразу
```

**4. Перевірка, сервер, клієнт.**

```
./df redux smoke          # усі перевірки мають бути ok
./df redux serve          # порт 8776, лишити жити
```

і далі — кроки 2–3 розділу «Сервер під Claude Code» на тій машині, де відкрито VS Code.
