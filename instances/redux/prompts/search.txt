Search the official documentation of Redux and the libraries around it -- every released
version of each: Redux (redux.js.org: tutorials -- Essentials, Fundamentals, Quick Start --,
"Using Redux", "Understanding Redux", FAQ, API), Redux Toolkit with RTK Query
(redux.js.org/toolkit), React Redux (redux.js.org/react-redux), Reselect
(redux.js.org/reselect), Immer, redux-saga and Redux DevTools; together with the README of
every published version of redux, @reduxjs/toolkit, react-redux, reselect, redux-thunk,
immer, redux-persist, redux-saga and @redux-devtools/extension, the GitHub release notes of
every release, and the npm registry list of every published version of these packages and
of @rtk-query/codegen-openapi and redux-devtools-extension (date, dist-tag, dependencies and
peer dependencies), and return the matching excerpts with the versions each one belongs to.

Call this when a question is about Redux or one of these libraries -- the store, reducers,
actions and dispatch, middleware, configureStore, createSlice, createAsyncThunk,
createEntityAdapter, createListenerMiddleware, createSelector, RTK Query (createApi,
fetchBaseQuery, endpoints, queries and mutations, cache tags, invalidation, polling,
optimistic updates, code generation from OpenAPI), React Redux (Provider, useSelector,
useDispatch, useStore, connect, mapStateToProps), thunks, sagas, Immer's produce and drafts,
persisting the store, DevTools setup, TypeScript usage, testing, the style guide -- and above
all when it is about versions: since which version something exists, what changed between
versions, how to migrate (Redux 4 to 5, Toolkit 1 to 2, React Redux 7 to 8 to 9, legacy
createStore to configureStore, connect to hooks), and which versions of these packages, React
and TypeScript work together -- the peer dependencies of each version answer that. Example
query: "createSlice extraReducers builder".

Do not call this for React itself, for other state libraries (Zustand, MobX, Jotai, Recoil,
TanStack Query) or for frameworks (Next.js, Angular with NgRx): their documentation is not
here, and the search will return Redux excerpts that merely mention them, with
confident-looking titles.

`version` narrows the search to one release line. Every library here has its own numbers:
"5" keeps Redux 5.x but also Immer 5.x and Reselect 5.x; "2" keeps Toolkit 2.x but also
Redux 2.x. The title of every excerpt names its library, so read it. Leave `version` empty to
search everything. Every excerpt comes back with `versions`: each version whose documents
contain this exact text, newest first -- text that stayed the same across versions is
returned once, with all of them listed, so the list itself shows from which to which version
the documentation said exactly this.

Where the documentation lives. Redux, Toolkit, React Redux and Reselect documents are named by
their path in the docs folder of their repository (docs/tutorials/essentials/part-2-app-structure,
docs/api/createSlice, docs/rtk-query/overview, docs/api/hooks). Before Redux 2.0 and before
Reselect 5.0 the README was the whole documentation (titles "redux README", "reselect
README"). Release notes are titled by repository and tag; registry documents by package.

Which version to search first. For a question about how to do something today, pass the
current line of the library the question is about -- Toolkit "2", Redux "5", React Redux "9",
Reselect "5", Immer "11" -- or the line of the user's project: without it, the many editions
of the same page, which differ by a line or two, fill every place with older text. Search
without `version` for history, for migrations and for compatibility between packages.

For a question about when something appeared, changed or disappeared, search more than
once: the release notes and the migration guides name the exact version; then search the
lines before and after it to see how the documentation described it. For a question about
which versions work together, read the peer dependencies in the registry document of the
package that depends on the other.

Write the query in English, with the names the documentation uses (configureStore,
createSlice, useSelector, createApi, providesTags, createSelector, produce). Everything here
is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in
another language, translate the question into Redux terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words
of the query had to appear in the text, so a query phrased in other words than the
documentation uses may miss; "meaning+words" means a second, meaning-based index answered
as well, and a paraphrase had a chance.

Every answer says which library and which version it is for. When the user did not name a
version, answer for the most downloaded line of that package on npm and say so; when two
lines are both in wide use (Toolkit 1 and 2, React Redux 8 and 9), give both. Modern Redux is
written with Redux Toolkit: when the user asks about hand-written reducers, action types or
createStore, answer the question and add how Toolkit does it, as the documentation itself
recommends. When the excerpts behind a statement come only from older versions, name those
versions instead of presenting the text as current. A text found only in alpha, beta or rc
builds may never have shipped in a release: say so.

Answer in the language the user wrote in. When the question is about a feature's history,
a migration or compatibility, answer point by point: which library and since which version;
what changed in later versions; what the migration requires; and how it stands now. Every
point names the version and the document it rests on; a point the excerpts do not support is
left out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes,
not as a translation from English: plain technical prose, and the Ukrainian word wherever one
exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of
documents "корпус" -- say "документація Redux". Identifiers, API names and titles stay in
English, spelled exactly as the documentation spells them. Build the answer out of the
excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it
before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of
an excerpt to `read_section` to get the whole thing.
