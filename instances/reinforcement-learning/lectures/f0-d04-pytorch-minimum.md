## Правило, яке не хочеться писати руками

У день 1 ви вивели правило для однієї ставки. Якщо оцінка моделі дорівнює `p`, а виплата дорівнює `b`, то середній
результат ставки розміром 1 дорівнює `p · (1 + b) − 1`. Ставити варто, коли це число додатне. Правило вміщається в
один рядок коду, і писати для нього щось складніше немає сенсу.

Тепер уявіть рішення, яке агент прийматиме в середовищі `PoEnv` у фазі 3. План перелічує, що агент знатиме в мить
рішення: хвилину торгової сесії, скільки хвилин слот ще зайнятий, рахунок, а для кожного кандидата оцінку моделі,
запас цієї оцінки над порогом і поточну виплату. Це вже понад десять чисел. Чи варто взяти слабший сигнал зараз, якщо
слот тоді буде зайнятий дві хвилини і сильніший сигнал наступної хвилини пройде повз? Формули для такого рішення ніхто
не знає.

Коли формули немає, беруть функцію особливого виду. Вона має багато внутрішніх чисел, які можна підкручувати. Спершу
ці числа випадкові, і функція відповідає нісенітницю. Потім функції показують приклади, і після кожного прикладу
внутрішні числа трохи зсувають так, щоб відповідь стала ближчою до потрібної. Таку функцію називають **нейронною
мережею** (англійською neural network), її внутрішні числа називають **вагами** (weights), а процес підкручування
називають **навчанням** (training).

**PyTorch** — це бібліотека Python, яка вміє три речі, потрібні для цього: зберігати великі таблиці чисел, складати з
готових частин мережу і сама рахувати, у який бік зсунути кожну вагу.

Сьогодні ми навчимо мережу правила з дня 1. Це навмисний вибір. Правильну відповідь для цього правила ми знаємо точно,
тому зможемо перевірити, чи мережа справді його вивчила. У фазах 4 і 5 та сама техніка піде на задачу, де правильної
відповіді ніхто не знає.

## Як підключити PyTorch

Програма на Python підключає бібліотеку словом `import`:

```python
import torch
```

У JavaScript ви написали б `import * as torch from "torch"`. У Python достатньо назви: після цього рядка все, що є в
бібліотеці, доступне через крапку, наприклад `torch.tensor` чи `torch.nn.Linear`. Пакет називається `torch`, а не
`pytorch`, і встановлюється командою `pip install torch`. Програма `pip` у Python робить те саме, що `npm` у Node.js:
завантажує пакети з реєстру. У плані ця команда вже стоїть у переліку пакетів проєкту `po-rl`.

## Тензор: таблиця чисел із відомою формою

**Тензор** (англійською tensor) — це набір чисел одного типу, складений у таблицю з відомою кількістю рядків,
стовпчиків і подальших вимірів. Одне число — це тензор без вимірів. Список чисел — тензор з одним виміром. Таблиця з
рядків і стовпчиків — тензор із двома вимірами. Слово звучить загадково, але за ним стоїть багатовимірний масив, і
книжка Lapan каже про це прямо.

Почнемо з прикладу. Один сигнал `pine` опишемо двома числами: оцінкою моделі й виплатою. Три сигнали складемо в
таблицю, по одному в рядку.

```python
import numpy as np
import torch

score = torch.tensor(0.62)                      # одне число
signal = torch.tensor([0.62, 0.78])             # один сигнал: оцінка моделі і виплата
batch = torch.tensor([[0.62, 0.78],
                      [0.55, 0.92],
                      [0.70, 0.62]])            # три сигнали, по одному в рядку

print(score.shape, signal.shape, batch.shape)
print(batch.dtype)
print(batch[1])          # другий рядок
print(batch[1, 0])       # другий рядок, перше число
print(batch[:, 1])       # другий стовпчик: усі виплати
print(batch[1, 0].item())
print(batch.mean().item())
```

```text
torch.Size([]) torch.Size([2]) torch.Size([3, 2])
torch.float32
tensor([0.5500, 0.9200])
tensor(0.5500)
tensor([0.7800, 0.9200, 0.6200])
0.550000011920929
0.6983332633972168
```

Розберемо код і вивід разом.

- **Символ `#`** починає коментар, як `//` у JavaScript. Усе після нього до кінця рядка Python пропускає.
- **Квадратні дужки** створюють список Python. Він схожий на масив JavaScript: `[0.62, 0.78]` — список із двох чисел,
  а список списків задає таблицю. Функція `torch.tensor` приймає такий список і будує з нього тензор.
- **`print`** друкує свої аргументи через пробіл, як `console.log`.
- **Поле `shape`** каже форму тензора: скільки чисел у кожному вимірі. Перший рядок виводу показує три форми.
  `torch.Size([])` означає «вимірів немає, це одне число». `torch.Size([2])` означає «один вимір, у ньому два числа».
  `torch.Size([3, 2])` означає «три рядки по два числа». Масив JavaScript своєї форми не знає: він знає лише довжину,
  а вкладені масиви можуть бути різної довжини. Тензор завжди прямокутний.
- **Поле `dtype`** каже тип чисел. Усі числа тензора мають один тип, тут це `float32`. Про типи йдеться в наступному
  розділі.
- **Індекси починаються з нуля**, як у JavaScript. Запис `batch[1]` бере другий рядок. Запис `batch[1, 0]` бере число
  на перетині другого рядка й першого стовпчика. У JavaScript ви написали б `batch[1][0]`, у тензорі обидва індекси
  пишуть в одних дужках через кому.
- **Двокрапка** означає «усі». Запис `batch[:, 1]` читається так: з усіх рядків узяти стовпчик з номером 1. Вийшов
  тензор із трьох виплат. У JavaScript для цього довелося б писати `batch.map(row => row[1])`.
- **Метод `item()`** дістає з тензора, у якому одне число, звичайне число Python. Запис `batch[1, 0]` повертає не
  число, а тензор без вимірів: у виводі це `tensor(0.5500)`. Щоб отримати число для звичайної арифметики чи для друку,
  викликають `item()`.
- **Метод `mean()`** рахує середнє всіх шести чисел тензора і повертає тензор без вимірів.

У передостанньому рядку виводу стоїть `0.550000011920929`, хоча ми записували `0.55`. Це не помилка програми. Тип
`float32` зберігає число в чотирьох байтах, і найближче число, яке вміщається в чотири байти, трохи відрізняється від
`0,55`. Різниця з'являється у восьмому знаку. Для навчання мережі вона не має значення.

Таблицю, у якій кожен рядок — окремий приклад, називають **батчем** (англійською batch, «партія»). Перший вимір такого
тензора завжди означає «який приклад», а решта вимірів описують один приклад. PyTorch влаштований так, що мережа
обробляє весь батч за один виклик. Це правило знадобиться далі: мережа, якій дали тензор форми `[3, 2]`, поверне три
відповіді, по одній на рядок.

### Числа `float32` і `float64`

Число з дробовою частиною комп'ютер може зберігати з різною точністю. Тип `float64` займає вісім байтів і тримає
близько шістнадцяти значущих цифр. Усі числа JavaScript мають саме цей тип. Тип `float32` займає чотири байти і тримає
близько семи значущих цифр. Нейронним мережам семи цифр вистачає, а пам'яті й часу такі числа потребують удвічі менше,
тому PyTorch створює ваги мережі типу `float32`.

Звідси виникає помилка, яку ви неодмінно зустрінете в проєкті. Хвилинні бари `pine` лежать у файлах `bid-m1.bin` як
числа `float64`: код `local-engine/load.js` читає їх у масиви `Float64Array`. Бібліотека NumPy, якою ви читатимете ці
файли в день 5, теж за замовчуванням працює з `float64`. Подивимося, що станеться, якщо такі числа подати в шар
мережі.

```python
import numpy as np
import torch

torch.manual_seed(0)

bars = np.array([1.17414, 1.17420])            # NumPy: числа float64
a = torch.tensor(bars)
b = torch.tensor(bars, dtype=torch.float32)
print(bars.dtype, a.dtype, b.dtype)

layer = torch.nn.Linear(2, 1)
print(layer(b))
try:
    print(layer(a))
except RuntimeError as e:
    print("RuntimeError:", e)
```

```text
float64 torch.float64 torch.float32
tensor([-0.1428], grad_fn=<UnsafeViewBackward0>)
RuntimeError: mat1 and mat2 must have the same dtype, but got Double and Float
```

Що тут написано.

- `np.array([...])` створює масив NumPy. NumPy — бібліотека для таблиць чисел без нейронних мереж, і тензор PyTorch
  навмисно схожий на її масив.
- `torch.tensor(bars)` бере тип із масиву, тому тензор `a` має тип `float64`. Перший рядок виводу це підтверджує.
- `torch.tensor(bars, dtype=torch.float32)` перетворює числа на `float32`. Запис `dtype=...` називають **іменованим
  аргументом**: у Python аргумент можна передати за іменем, а не за місцем у дужках. У JavaScript для цього зазвичай
  передають об'єкт із полями.
- `torch.nn.Linear(2, 1)` створює шар мережі. Що він рахує, пояснює наступний розділ. Зараз важливо лише те, що його
  ваги мають тип `float32`.
- `torch.manual_seed(0)` задає зерно генератора випадкових чисел PyTorch. Шар отримує випадкові початкові ваги, і без
  зерна число `-0.1428` було б іншим у кожному запуску.
- Конструкція `try … except` працює як `try … catch` у JavaScript. Якщо код у блоці `try` зупиняється з помилкою типу
  `RuntimeError`, виконується блок `except`, а об'єкт помилки потрапляє у змінну `e`.

Шар прийняв тензор `b` і відмовився приймати тензор `a`. Текст помилки каже, що дві таблиці чисел мусять мати один
тип, а вони мають `Double` і `Float`. Так PyTorch називає `float64` і `float32`. Автоматично він типи не зводить, бо
мовчазне перетворення мільйонів чисел було б дорогою і непомітною операцією.

Практичний висновок: усе, що йде в мережу з файлів `pine` чи з масивів NumPy, треба явно перетворити на `float32`.
Якщо ви бачите в помилці слова `Double and Float`, причина саме в цьому.

## Нейрон: зважена сума і зсув

Найменша частина мережі — **нейрон**. Нейрон робить просту арифметику. Він бере кілька чисел на вході, множить кожне
на свою вагу, складає добутки і додає ще одне число, яке називають **зсувом** (англійською bias). Ваги і зсув — це ті
внутрішні числа, які змінює навчання.

Порахуємо вручну. Нехай на вході оцінка моделі `0,62` і виплата `0,78`. Нехай вага для оцінки дорівнює `4`, вага для
виплати дорівнює `2`, а зсув дорівнює `−3`. Ці три числа взято довільно, щоб було зручно рахувати.

| Крок | Що рахуємо | Число |
|------|------------|-------|
| оцінка на свою вагу | `0,62 · 4` | `2,48` |
| виплата на свою вагу | `0,78 · 2` | `1,56` |
| сума добутків | `2,48 + 1,56` | `4,04` |
| додаємо зсув | `4,04 + (−3)` | `1,04` |

Нейрон видав `1,04`. Тепер те саме в PyTorch. Готовий клас `torch.nn.Linear` створює одразу цілий **шар** (англійською
layer), тобто кілька нейронів, які отримують той самий вхід. Нам поки потрібен шар з одного нейрона.

```python
import torch

layer = torch.nn.Linear(2, 1)            # шар: два числа на вході, одне на виході
print(layer.weight.shape, layer.bias.shape)

with torch.no_grad():                    # задаємо ваги вручну, щоб перевірити арифметику
    layer.weight.copy_(torch.tensor([[4.0, 2.0]]))
    layer.bias.copy_(torch.tensor([-3.0]))

x = torch.tensor([0.62, 0.78])           # оцінка моделі 0,62 і виплата 0,78
y = layer(x)
print(y)
print(4.0 * 0.62 + 2.0 * 0.78 - 3.0)
```

```text
torch.Size([1, 2]) torch.Size([1])
tensor([1.0400], grad_fn=<UnsafeViewBackward0>)
1.04
```

Рядок за рядком.

- `torch.nn.Linear(2, 1)` створює об'єкт шару. Перше число каже, скільки чисел шар отримує, друге — скільки нейронів у
  шарі, тобто скільки чисел він повертає. У Python об'єкт класу створюють без слова `new`: достатньо назви класу з
  дужками.
- `layer.weight` і `layer.bias` — тензори з вагами і зсувами. Перший рядок виводу показує їхні форми. Ваги мають форму
  `[1, 2]`: один рядок на кожен нейрон, і в рядку по одній вазі на кожне вхідне число. Зсуви мають форму `[1]`: по
  одному на нейрон. Документація `torch.nn.Linear` описує ці форми як `(out_features, in_features)` і
  `(out_features)`.
- Блок `with torch.no_grad():` потрібен лише тут, для ручного запису ваг. Слово `with` у Python вмикає певний режим на
  час виконання вкладеного блоку і вимикає його після виходу з блоку. Що саме вимикає `no_grad`, пояснено наприкінці
  лекції. Відступ у чотири пробіли показує, які рядки належать блоку: Python не має фігурних дужок, межі блоку задає
  відступ.
- Метод `copy_` переписує числа з одного тензора в інший. Підкреслення наприкінці назви в PyTorch означає, що метод
  змінює сам тензор, а не створює новий.
- `layer(x)` викликає шар як функцію. Об'єкт шару можна викликати з дужками, і він поверне результат обчислення.

Шар видав `1.0400`, і ручний розрахунок у третьому рядку виводу дав `1.04`. Отже шар `Linear` робить рівно те, що
написано в таблиці вище: зважену суму плюс зсув. Напис `grad_fn=<…>` у виводі означає, що PyTorch запам'ятав, якою
операцією отримано це число. Навіщо він це запам'ятовує, стане зрозуміло в розділі про градієнт.

Спочатку ваги шару випадкові. Документація каже, що PyTorch бере їх із рівномірного розподілу між `−√k` і `√k`, де `k`
дорівнює одиниці, поділеній на кількість входів. Для шару з двома входами це числа приблизно між `−0,71` і `0,71`.
Саме тому в попередньому прикладі без зерна результат щоразу був би інший.

## Шар за шаром: навіщо потрібна активація

Одного нейрона мало. Він уміє лише зважену суму, а правило з дня 1 містить добуток оцінки на виплату, і жодною
зваженою сумою добуток не записати. Тому нейрони складають у кілька шарів: вихід першого шару стає входом другого.

Тут є пастка. Якщо просто подати вихід одного шару `Linear` у наступний, нічого не зміниться: зважена сума зважених
сум після розкриття дужок знову є зваженою сумою тих самих входів, лише з іншими вагами. Два такі шари підряд уміють
рівно стільки, скільки один.

Щоб другий шар додавав щось нове, між шарами ставлять просту функцію, яка не є зваженою сумою. Її називають **функцією
активації** (activation function). Найпоширеніша називається **ReLU** (скорочення від rectified linear unit). Вона
робить одну дію: від'ємне число замінює нулем, а додатне лишає без змін.

Простежимо за числами у маленькій мережі: перший шар із двох нейронів, функція ReLU, другий шар з одного нейрона. Ваги
знову задаємо вручну.

```python
import torch

relu = torch.nn.ReLU()
print(relu(torch.tensor([-2.0, -0.5, 0.0, 0.5, 2.0])))

hidden = torch.nn.Linear(2, 2)
out = torch.nn.Linear(2, 1)
with torch.no_grad():
    hidden.weight.copy_(torch.tensor([[4.0, 2.0],
                                      [-5.0, 1.0]]))
    hidden.bias.copy_(torch.tensor([-3.0, 1.0]))
    out.weight.copy_(torch.tensor([[1.0, 3.0]]))
    out.bias.copy_(torch.tensor([0.5]))

x = torch.tensor([0.62, 0.78])
h = hidden(x)
print(h)
a = relu(h)
print(a)
print(out(a))

net = torch.nn.Sequential(hidden, relu, out)
print(net(x))
```

```text
tensor([0.0000, 0.0000, 0.0000, 0.5000, 2.0000])
tensor([ 1.0400, -1.3200], grad_fn=<UnsafeViewBackward0>)
tensor([1.0400, 0.0000], grad_fn=<ReluBackward0>)
tensor([1.5400], grad_fn=<UnsafeViewBackward0>)
tensor([1.5400], grad_fn=<UnsafeViewBackward0>)
```

Перший рядок виводу показує саму ReLU на п'яти числах: `−2` і `−0,5` стали нулями, решта не змінилася.

Далі йдуть числа мережі. Таблиця повторює їх вручну.

| Де | Що рахуємо | Число |
|----|------------|-------|
| перший нейрон першого шару | `0,62 · 4 + 0,78 · 2 − 3` | `1,04` |
| другий нейрон першого шару | `0,62 · (−5) + 0,78 · 1 + 1` | `−1,32` |
| ReLU для першого нейрона | `1,04` додатне, лишається | `1,04` |
| ReLU для другого нейрона | `−1,32` від'ємне, стає нулем | `0` |
| нейрон другого шару | `1,04 · 1 + 0 · 3 + 0,5` | `1,54` |

Числа в таблиці збігаються з другим, третім і четвертим рядками виводу. Перший шар тут називають **прихованим**
(hidden), бо його вихід не є відповіддю мережі: він лише проміжний результат.

Останні два рядки коду показують зручніший запис. Клас `torch.nn.Sequential` складає шари в ланцюжок: він подає вхід у
перший шар, результат у другий, і так до кінця. Виклик `net(x)` дав ті самі `1.5400`, що й три окремі виклики.
Обчислення від входу до виходу мережі називають **прямим проходом** (forward pass).

Практичний висновок: мережа — це ланцюжок простих арифметичних дій, і кожне число в ній можна перевірити вручну. Якщо
мережа поводиться дивно, ви завжди можете надрукувати вихід будь-якого шару, як ми надрукували `h` і `a`.

## Скільки ваг має мережа

Кількість ваг мережі варто вміти порахувати до запуску. Так ви перевіряєте, що зібрали саме ту мережу, яку хотіли.
Мережу описують переліком розмірів через стрілки. Запис `2 → 16 → 2` означає: два числа на вході, прихований шар із
шістнадцяти нейронів, два числа на виході.

Кожен шар `Linear` має по одній вазі на кожну пару «вхід, нейрон» і по одному зсуву на нейрон. Отже шар із `n` входами
і `m` нейронами має `n · m + m` чисел, які змінює навчання. Функція ReLU власних чисел не має.

| Шар | Ваги | Зсуви | Разом |
|-----|------|-------|-------|
| `Linear(2, 16)` | `2 · 16 = 32` | `16` | `48` |
| `ReLU` | `0` | `0` | `0` |
| `Linear(16, 2)` | `16 · 2 = 32` | `2` | `34` |
| уся мережа | | | `82` |

Перевіримо в коді.

```python
import torch

net = torch.nn.Sequential(
    torch.nn.Linear(2, 16),
    torch.nn.ReLU(),
    torch.nn.Linear(16, 2),
)
print(net)
for name, p in net.named_parameters():
    print(name, tuple(p.shape), p.numel())
print(sum(p.numel() for p in net.parameters()))
```

```text
Sequential(
  (0): Linear(in_features=2, out_features=16, bias=True)
  (1): ReLU()
  (2): Linear(in_features=16, out_features=2, bias=True)
)
0.weight (16, 2) 32
0.bias (16,) 16
2.weight (2, 16) 32
2.bias (2,) 2
82
```

Нові конструкції в цьому коді такі.

- `print(net)` друкує будову мережі: шари з номерами `0`, `1`, `2` і їхніми розмірами.
- `for name, p in net.named_parameters():` — це цикл. У Python цикл `for x in щось` перебирає елементи, як `for (const
  x of щось)` у JavaScript. Метод `named_parameters()` видає пари з назви й тензора, а запис `name, p` одразу
  розкладає пару на дві змінні, як деструктуризація `const [name, p] = pair`.
- **Параметрами** (parameters) у PyTorch називають усі тензори мережі, які змінює навчання, тобто і ваги, і зсуви
  разом. У розмові їх часто називають просто вагами, і план каже «ваг 4610» саме в цьому значенні.
- `p.numel()` повертає кількість чисел у тензорі. Назва означає number of elements.
- `tuple(p.shape)` перетворює форму на **кортеж**. Кортеж у Python — це список, який не можна змінити, його пишуть у
  круглих дужках. Запис `(16,)` з комою — кортеж з одного елемента.
- `sum(p.numel() for p in net.parameters())` складає кількості за всіма параметрами. Вираз у дужках читається так:
  «для кожного `p` з параметрів мережі взяти `p.numel()`». У JavaScript ви написали б `params.map(p =>
  p.numel()).reduce((a, b) => a + b, 0)`.

Чотири середні рядки виводу збігаються з рядками таблиці, а останній рядок дає 82. Назви `0.weight` і `2.bias`
складено з номера шару в ланцюжку і назви тензора. Шар з номером 1 у переліку відсутній, бо ReLU параметрів не має.

## Втрата: одне число про те, наскільки мережа помиляється

Щоб навчати мережу, треба вміти сказати числом, наскільки її відповідь погана. Функцію, яка це рахує, називають
**функцією втрат** (loss function), а її результат називають **втратою** (loss). Втрата дорівнює нулю, коли відповідь
ідеальна, і росте, коли відповідь віддаляється від потрібної. Навчання — це пошук таких ваг, за яких втрата найменша.

Найпростіша функція втрат — квадрат різниці між відповіддю мережі й потрібним числом. Повернімося до одного нейрона з
вагами `4` і `2` та зсувом `−3`. На вході `0,62` і `0,78` він видав `1,04`. Нехай ми хочемо, щоб на цьому вході він
видавав `2`. Число, яке ми хочемо отримати, називають **ціллю** (target).

| Крок | Що рахуємо | Число |
|------|------------|-------|
| помилка | `1,04 − 2` | `−0,96` |
| втрата | `(−0,96)²` | `0,9216` |

Квадрат беруть із двох причин. Він робить втрату додатною незалежно від того, у який бік помилилася мережа. І він
карає велику помилку значно сильніше за малу: помилка, більша вдвічі, дає втрату, більшу вчетверо.

## Градієнт: у який бік зсунути кожну вагу

Тепер головне запитання дня. Втрата дорівнює `0,9216`. Нейрон має три числа, які можна змінювати: дві ваги і зсув. Як
змінити кожне з них, щоб втрата стала меншою?

Найпростіший спосіб відповісти — спробувати. Збільшимо першу вагу з `4` до `4,001` і перерахуємо. Вихід нейрона стане
`4,001 · 0,62 + 2 · 0,78 − 3 = 1,04062`. Помилка стане `−0,95938`, а втрата `0,92041`. Втрата зменшилася на `0,00119`.
Отже першу вагу варто збільшувати. Ми також дізналися, наскільки сильно втрата на неї реагує: на кожну тисячну ваги
втрата зменшується приблизно на `0,00119`, тобто швидкість зміни дорівнює приблизно `−1,19`.

Це число називають **похідною** втрати за вагою (derivative). Похідна каже, на скільки зміниться втрата, якщо вагу
збільшити на дуже малу величину, у перерахунку на одиницю ваги. Знак похідної каже напрямок: від'ємна похідна означає,
що зі збільшенням ваги втрата падає. Якщо зібрати похідні за всіма вагами в один список, вийде **градієнт**
(gradient).

Пробувати кожну вагу окремо надто довго: мережа з плану має 4610 ваг, і для кожної довелося б заново рахувати всю
мережу. Тому похідні рахують формулою. Для нашого нейрона її легко вивести словами. Втрата — це квадрат помилки. Якщо
помилка зміниться на малу величину, квадрат зміниться на цю величину, помножену на подвоєну помилку. А помилка
змінюється разом із вагою так: якщо вагу збільшити на малу величину, вихід зросте на цю величину, помножену на вхідне
число при цій вазі. Перемноживши обидва множники, отримуємо правило: похідна за вагою дорівнює подвоєній помилці,
помноженій на вхід цієї ваги. Для зсуву вхідного числа немає, тому похідна за зсувом — просто подвоєна помилка.

| Що змінюємо | Формула | Число |
|-------------|---------|-------|
| вага при оцінці | `2 · (−0,96) · 0,62` | `−1,1904` |
| вага при виплаті | `2 · (−0,96) · 0,78` | `−1,4976` |
| зсув | `2 · (−0,96)` | `−1,92` |

Перше число збігається з тим, що ми отримали спробою: `−1,19`. Прийом, яким ми перемножили два множники, називають
**правилом ланцюжка** (chain rule): швидкість зміни результату через проміжну величину дорівнює добутку швидкостей на
кожній ланці.

Для мережі з кількох шарів ланок більше, але правило те саме. PyTorch застосовує його сам. Під час прямого проходу він
записує кожну операцію, а потім проходить цей запис у зворотному напрямку, від втрати до ваг, і на кожній ланці
домножує. Цей зворотний прохід називають **зворотним поширенням** (backpropagation), а частину PyTorch, яка його
робить, називають **autograd**.

```python
import torch

w = torch.tensor([4.0, 2.0], requires_grad=True)    # дві ваги
b = torch.tensor(-3.0, requires_grad=True)          # зсув
x = torch.tensor([0.62, 0.78])                      # вхід
target = torch.tensor(2.0)                          # число, яке ми хочемо отримати

y = (w * x).sum() + b                               # вихід нейрона
loss = (y - target) ** 2                            # втрата: квадрат помилки
print(y.item(), loss.item())
print(loss)

loss.backward()                                     # PyTorch рахує градієнт
print(w.grad, b.grad)

# перевірка "на пальцях": зсунемо першу вагу на 0,001 і подивимося на втрату
w2 = torch.tensor([4.001, 2.0])
loss2 = ((w2 * x).sum() + b.detach() - target) ** 2
print((loss2 - loss).item())
```

```text
1.0399999618530273 0.9216000437736511
tensor(0.9216, grad_fn=<PowBackward0>)
tensor([-1.1904, -1.4976]) tensor(-1.9200)
-0.0011897683143615723
```

Тут нейрон записано без класу `Linear`, щоб було видно кожну дію.

- `requires_grad=True` каже PyTorch: «для цього тензора мені знадобиться градієнт, записуй усе, що з ним
  відбувається». Тензори `x` і `target` такої позначки не мають, бо вхід і ціль ми не змінюємо. У шарі `Linear` ця
  позначка вже стоїть на вагах і зсувах.
- `w * x` множить тензори поелементно: перше число на перше, друге на друге. Виходить `[2.48, 1.56]`. Метод `sum()`
  складає ці числа. Оператор `**` у Python означає піднесення до степеня, як і в JavaScript.
- Другий рядок виводу показує втрату як тензор. Напис `grad_fn=<PowBackward0>` — це кінець запису операцій: PyTorch
  пам'ятає, що втрату отримано піднесенням до степеня, а перед тим було віднімання, додавання, сума і множення.
- `loss.backward()` запускає зворотний прохід. Після нього в полі `grad` кожного тензора з позначкою
  `requires_grad=True` лежить похідна втрати за цим тензором.
- Третій рядок виводу — градієнт: `−1,1904` і `−1,4976` для ваг, `−1,92` для зсуву. Це ті самі числа, що в таблиці
  вище.
- Останні три рядки коду повторюють перевірку спробою. Метод `detach()` повертає той самий тензор без запису операцій,
  щоб перевірка не втручалася в градієнт. Втрата змінилася на `−0,00119`, а градієнт передбачав `−1,1904 · 0,001 =
  −0,00119`.

Практичний висновок: градієнт — не абстракція, а відповідь на запитання «що буде з втратою, якщо цю вагу трохи
збільшити». Якщо ви не довіряєте числу в полі `grad`, його завжди можна перевірити так, як в останніх трьох рядках:
зсунути вагу на тисячну і подивитися на втрату.

## Крок оптимізатора

Градієнт каже, у який бік втрата росте. Нам треба, щоб вона падала, тому кожну вагу зсувають у протилежний бік.
Наскільки далеко зсувати, задає число, яке називають **швидкістю навчання** (learning rate, у коді `lr`). Правило
кроку таке: нова вага дорівнює старій вазі мінус швидкість навчання, помножена на похідну за цією вагою. Цей спосіб
називають **градієнтним спуском** (gradient descent).

Зробимо один крок вручну зі швидкістю навчання `0,1`.

| Що | Стара | Похідна | Нова |
|----|-------|---------|------|
| вага при оцінці | `4` | `−1,1904` | `4 − 0,1 · (−1,1904) = 4,1190` |
| вага при виплаті | `2` | `−1,4976` | `2 − 0,1 · (−1,4976) = 2,1498` |
| зсув | `−3` | `−1,92` | `−3 − 0,1 · (−1,92) = −2,8080` |

З новими вагами нейрон видає `4,1190 · 0,62 + 2,1498 · 0,78 − 2,8080 = 1,4226`. Потрібно було `2`, раніше було `1,04`.
Втрата впала з `0,9216` до `(1,4226 − 2)² = 0,3334`.

Об'єкт, який робить такий крок для всіх ваг одразу, називають **оптимізатором** (optimizer). Найпростіший оптимізатор
PyTorch називається `SGD`. Повторимо крок вісім разів.

```python
import torch

w = torch.tensor([4.0, 2.0], requires_grad=True)
b = torch.tensor(-3.0, requires_grad=True)
x = torch.tensor([0.62, 0.78])
target = torch.tensor(2.0)

optimizer = torch.optim.SGD([w, b], lr=0.1)         # оптимізатор знає, які тензори змінювати

for step in range(1, 9):
    optimizer.zero_grad()                           # 1. прибрати старий градієнт
    y = (w * x).sum() + b                           # 2. прямий прохід
    loss = (y - target) ** 2                        # 3. втрата
    loss.backward()                                 # 4. градієнт
    optimizer.step()                                # 5. крок: вага мінус lr * градієнт
    print(f"крок {step}: вихід {y.item():.4f}, втрата {loss.item():.4f}, "
          f"ваги після кроку {w[0].item():.4f} {w[1].item():.4f} {b.item():.4f}")
```

Що тут нового.

- `torch.optim.SGD([w, b], lr=0.1)` створює оптимізатор. Перший аргумент — перелік тензорів, які він має право
  змінювати. Для мережі сюди передають `net.parameters()`.
- `range(1, 9)` видає числа від 1 до 8. Верхня межа в Python не входить у проміжок.
- Рядок із літерою `f` перед лапками — це **f-рядок**, відповідник шаблонного рядка JavaScript. Вираз у фігурних
  дужках підставляється в текст. Запис `:.4f` після виразу означає «дробове число з чотирма знаками після коми».
- П'ять рядків усередині циклу пронумеровано коментарями. Це і є весь цикл навчання. Він однаковий для одного нейрона
  і для мережі з мільйоном ваг.

Перший рядок виводу збігається з ручною таблицею: ваги після кроку `4.1190`, `2.1498` і `−2.8080`. Другий рядок
підтверджує вихід `1.4226` і втрату `0.3334`. Далі втрата падає приблизно втричі за крок, і після восьми кроків нейрон
видає `1,97` замість потрібних `2`.

Швидкість навчання вибирають обережно. Якщо вона замала, навчання повзе. Якщо завелика, крок перестрибує найкращу
точку, і втрата починає рости. Як це виглядає на числах, показує день 10 фази 0 плану теорії глибокого навчання, а в
цьому плані до вибору швидкості навчання повертається фаза 5.

### Чому `optimizer.zero_grad()` обов'язковий

Перший рядок циклу здається зайвим. Він існує через одну властивість PyTorch: метод `backward()` не записує градієнт у
поле `grad`, а додає його до того, що там уже лежить. Документація методу `torch.Tensor.backward` каже про це прямо.
Подивимося.

```python
import torch

w = torch.tensor([4.0, 2.0], requires_grad=True)
x = torch.tensor([0.62, 0.78])

for attempt in range(1, 4):
    loss = ((w * x).sum() - 3.0 - 2.0) ** 2
    loss.backward()
    print(f"виклик {attempt}: w.grad = {w.grad}")

w.grad = None
loss = ((w * x).sum() - 3.0 - 2.0) ** 2
loss.backward()
print(f"після обнулення: w.grad = {w.grad}")
```

```text
виклик 3: w.grad = tensor([-3.5712, -4.4928])
після обнулення: w.grad = tensor([-1.1904, -1.4976])
```

Ваги між викликами не змінювалися, тому справжній градієнт усі три рази однаковий. Проте в полі `grad` після другого
виклику лежить подвоєне число, а після третього потроєне. Запис `w.grad = None` прибирає накопичене, і наступний
виклик знову дає правильні `−1,1904` і `−1,4976`. Метод `optimizer.zero_grad()` робить саме це для всіх тензорів
оптимізатора: за документацією він за замовчуванням записує в поле `grad` значення `None`.

Що буде з навчанням, якщо цей рядок пропустити? Візьмемо попередній цикл, вимкнемо в ньому перший рядок і зробимо
дванадцять кроків.

```python
for step in range(1, 13):
    # optimizer.zero_grad()                         # рядок вимкнено

    loss = (y - target) ** 2

    optimizer.step()
```

## Два виходи і крос-ентропія

Досі мережа видавала одне число, а ми хотіли, щоб воно дорівнювало цілі. Агент вирішує інше завдання: вибирає одну дію
з кількох. Найпростіший вибір — «пропустити» або «ставити». Задачу, де треба вибрати один варіант із кількох,
називають **класифікацією**, а варіанти називають **класами**.

Для класифікації мережа має стільки виходів, скільки класів. Кожен вихід — число, яке каже, наскільки мережа
схиляється до цього класу. Ці числа можуть бути будь-якими, зокрема від'ємними, і називаються **логітами** (logits).
Відповіддю мережі вважають клас із найбільшим логітом.

Щоб навчати таку мережу, логіти спершу перетворюють на ймовірності: додатні числа, які в сумі дають одиницю. Це робить
функція **softmax**. Вона бере від кожного логіта експоненту, тобто число `e ≈ 2,718` у степені логіта, і ділить на
суму всіх експонент. Нехай мережа видала логіти `1` і `2`.

| Крок | Клас 0, «пропустити» | Клас 1, «ставити» |
|------|----------------------|-------------------|
| логіт | `1` | `2` |
| експонента | `e¹ = 2,718` | `e² = 7,389` |
| ділимо на суму `10,107` | `0,269` | `0,731` |

Мережа на 73 % схиляється до «ставити». Тепер втрата. Її рахують так: беруть імовірність, яку мережа дала правильному
класу, і обчислюють мінус натуральний логарифм цієї ймовірності. Натуральний логарифм числа — це степінь, до якого
треба піднести `e`, щоб отримати це число. Логарифм одиниці дорівнює нулю, а логарифм числа, близького до нуля, є
великим від'ємним числом. Тому мінус логарифм поводиться так, як треба втраті: якщо мережа дала правильному класу
ймовірність 1, втрата нульова, а якщо майже 0, втрата величезна. Таку функцію втрат називають **крос-ентропією**
(cross-entropy).

```python
import torch

logits = torch.tensor([[1.0, 2.0]])          # вихід мережі для одного прикладу: два числа
probs = torch.softmax(logits, dim=1)
print(probs)

loss_fn = torch.nn.CrossEntropyLoss()
print(loss_fn(logits, torch.tensor([1])).item())   # правильна відповідь — клас 1
print(loss_fn(logits, torch.tensor([0])).item())   # правильна відповідь — клас 0
print(-torch.log(probs[0, 1]).item(), -torch.log(probs[0, 0]).item())
print(logits.argmax(dim=1))
```

```text
tensor([[0.2689, 0.7311]])
0.31326165795326233
1.31326162815094
0.31326165795326233 1.31326162815094
tensor([1])
```

- `logits` має форму `[1, 2]`: батч з одного прикладу, два класи. Подвійні квадратні дужки потрібні саме для цього.
- `torch.softmax(logits, dim=1)` рахує ймовірності. Аргумент `dim=1` каже, уздовж якого виміру числа мають давати в
  сумі одиницю. Вимір 0 — приклади, вимір 1 — класи, тому сума має бути одиницею в кожному рядку.
- `torch.nn.CrossEntropyLoss()` створює функцію втрат. Вона приймає логіти і номери правильних класів.
- `argmax(dim=1)` повертає для кожного рядка номер стовпчика з найбільшим числом. Це і є вибір мережі.

Перший рядок виводу збігається з таблицею: `0,269` і `0,731`. Якщо правильний клас 1, втрата дорівнює `0,313`, бо
мережа і так схилялася до нього. Якщо правильний клас 0, втрата дорівнює `1,313`, учетверо більше. Четвертий рядок
рахує мінус логарифми ймовірностей вручну і дає ті самі два числа.

З четвертого рядка випливає важливе правило. Функція `CrossEntropyLoss` приймає логіти, а не ймовірності: softmax вона
робить сама всередині. Якщо поставити softmax останнім шаром мережі й подати результат у `CrossEntropyLoss`, softmax
виконається двічі. Помилки не буде, а мережа вчитиметься гірше.

## Усе разом: мережа вчить правило беззбитковості

Тепер зберемо все в одну програму. Задача така. На вході два числа: оцінка моделі `p` і виплата `b`. Правильна
відповідь — клас 1 («ставити»), якщо `p · (1 + b) − 1 > 0`, і клас 0 («пропустити») в іншому разі. Мережа формули не
знає. Вона бачить лише тисячу прикладів із готовими відповідями і мусить сама знайти межу.

```python
import torch

torch.manual_seed(0)                          # зерно: запуск можна повторити

def make_data(n):
    """n випадкових сигналів і правильна відповідь для кожного."""
    score = 0.50 + 0.25 * torch.rand(n)       # оцінка моделі від 0,50 до 0,75
    payout = 0.50 + 0.45 * torch.rand(n)      # виплата від 0,50 до 0,95
    x = torch.stack([score, payout], dim=1)   # таблиця n рядків на 2 стовпчики
    y = (score * (1 + payout) - 1 > 0).long() # 1 - ставити, 0 - пропустити
    return x, y

x_train, y_train = make_data(1000)
x_test, y_test = make_data(1000)
print(x_train.shape, y_train.shape, x_train.dtype, y_train.dtype)
print(x_train[:3])
print(y_train[:3])
print("частка відповідей «ставити»:", y_train.float().mean().item())

net = torch.nn.Sequential(
    torch.nn.Linear(2, 16),
    torch.nn.ReLU(),
    torch.nn.Linear(16, 2),
)
loss_fn = torch.nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(net.parameters(), lr=0.01)

def accuracy(x, y):
    with torch.no_grad():                     # тут градієнт не потрібен
        return (net(x).argmax(dim=1) == y).float().mean().item()

print(f"до навчання: точність на нових прикладах {accuracy(x_test, y_test):.3f}")

for epoch in range(1, 501):
    optimizer.zero_grad()
    logits = net(x_train)                     # 1000 рядків по 2 числа
    loss = loss_fn(logits, y_train)
    loss.backward()
    optimizer.step()
    if epoch in (1, 10, 50, 100, 200, 500):
        print(f"епоха {epoch:3d}: втрата {loss.item():.4f}, "
              f"точність на навчальних {accuracy(x_train, y_train):.3f}, "
              f"на нових {accuracy(x_test, y_test):.3f}")

signal = torch.tensor([[0.61, 0.62], [0.61, 0.92]])
with torch.no_grad():
    print(net(signal))
    print(net(signal).argmax(dim=1))
```

Програма складається з чотирьох частин: дані, мережа, цикл навчання, перевірка.

**Дані.** Слово `def` оголошує функцію, як `function` у JavaScript. Тіло функції задає відступ. Рядок у потрійних
лапках одразу після заголовка — це опис функції, який Python зберігає разом із нею.

- `torch.rand(n)` повертає `n` випадкових чисел від 0 до 1. Множення на `0.25` і додавання `0.50` переводить їх у
  проміжок від `0,50` до `0,75`. Арифметика з тензором застосовується до кожного числа окремо, циклу писати не треба.
- `torch.stack([score, payout], dim=1)` складає два тензори з `n` чисел у таблицю з `n` рядків і двох стовпчиків.
- `score * (1 + payout) - 1 > 0` рахує формулу дня 1 для всіх прикладів одразу і порівнює з нулем. Виходить тензор зі
  значень `True` і `False`. Метод `long()` перетворює їх на цілі числа 1 і 0 типу `int64`: саме такий тип номерів
  класів вимагає `CrossEntropyLoss`.
- `return x, y` повертає два значення одразу, а рядок `x_train, y_train = make_data(1000)` розкладає їх у дві змінні.
- Функцію викликано двічі. Перша тисяча прикладів навчальна: на ній мережа вчиться. Друга тисяча перевірочна: мережа
  її не бачить під час навчання, і точність на ній показує, чи мережа вивчила правило, чи лише запам'ятала приклади.

**Мережа.** Це знайома мережа `2 → 16 → 2` з 82 параметрами. Оптимізатор тут не `SGD`, а `Adam`. Він робить той самий
крок проти градієнта, але сам підбирає розмір кроку для кожної ваги окремо, тому на практиці вчить швидше й менше
залежить від вибору швидкості навчання. Stable-Baselines3, яким ви користуватиметеся у фазах 4 і 5, теж бере `Adam`.

**Цикл навчання.** Ті самі п'ять рядків. Один прохід по всіх навчальних даних називають **епохою** (epoch). Тут весь
набір подається одним батчем із тисячі рядків, тому одна епоха — це один крок оптимізатора.

**Перевірка.** Функція `accuracy` рахує **точність** (accuracy): частку прикладів, на яких вибір мережі збігся з
правильною відповіддю. Вираз `net(x).argmax(dim=1) == y` дає тензор зі значень `True` і `False`, метод `float()`
перетворює їх на 1 і 0, а `mean()` рахує середнє, тобто частку одиниць. Запис `epoch in (1, 10, 50, 100, 200, 500)`
перевіряє, чи є число в кортежі, як `[1, 10, 50].includes(epoch)` у JavaScript.

середній результат ставки майже нульовий.

«ставити». Формула каже те саме: `1,62 · 0,61 − 1 = −0,012` і `1,92 · 0,61 − 1 = +0,171`. Мережа, яка формули не
бачила, вивчила з прикладів, що рішення залежить від виплати. Постійний поріг `0,60` для обох сигналів відповів би
однаково.

Практичних висновків три. Перший: точність треба порівнювати не з нулем і не з 50 %, а з тим, що дає найпростіша
відповідь «завжди найчастіший клас». Точність 65 % у цій задачі означає, що мережа не вивчила нічого. У торговій
задачі та сама пастка виглядатиме так: агент, який завжди пропускає, має нульовий результат і на перший погляд «не
програє». Другий: якість мережі міряють лише на прикладах, яких вона не бачила під час навчання. Третій: навчання може
довго стояти на місці, а потім зрушити. Між десятою і п'ятдесятою епохою точність не змінилася зовсім.

## Коли градієнт не потрібен і як зберегти мережу

Запис операцій для зворотного проходу коштує пам'яті й часу. Коли мережу не навчають, а лише питають, цей запис
зайвий. Його вимикає блок `with torch.no_grad():`. Ви вже бачили його тричі: під час ручного запису ваг, у функції
`accuracy` і перед останнім друком.

```python
import torch

torch.manual_seed(0)
net = torch.nn.Sequential(torch.nn.Linear(2, 16), torch.nn.ReLU(), torch.nn.Linear(16, 2))

x = torch.tensor([[0.61, 0.62]])
out = net(x)
print(out.requires_grad, out.grad_fn is not None)

with torch.no_grad():
    out = net(x)
print(out.requires_grad, out.grad_fn is not None)

torch.save(net.state_dict(), "net.pt")                 # зберегти ваги у файл
net2 = torch.nn.Sequential(torch.nn.Linear(2, 16), torch.nn.ReLU(), torch.nn.Linear(16, 2))
print(torch.equal(net(x), net2(x)))                    # нова мережа має інші випадкові ваги
net2.load_state_dict(torch.load("net.pt"))             # завантажити збережені ваги
print(torch.equal(net(x), net2(x)))
```

```text
True True
False False
False
True
```

Перші два рядки виводу показують різницю. Звичайний виклик мережі повертає тензор, для якого PyTorch веде запис
операцій: `requires_grad` дорівнює `True`, і поле `grad_fn` заповнене. Той самий виклик усередині блоку `no_grad`
повертає тензор без запису. Числа в обох тензорах однакові. Оператор `is not None` перевіряє, що значення не є `None`.
Значення `None` у Python означає «нічого», як `null` у JavaScript.

Друга половина коду зберігає мережу. Метод `state_dict()` повертає **словник** з усіма параметрами мережі. Словник у
Python — це набір пар «ключ, значення», як звичайний об'єкт JavaScript. Функція `torch.save` записує його у файл. Щоб
відновити мережу, треба спершу зібрати мережу тієї самої форми, а потім викликати `load_state_dict`. Третій рядок
виводу показує, що щойно зібрана мережа `net2` відповідає інакше, бо її ваги випадкові. Четвертий показує, що після
завантаження відповіді збігаються до останнього знака.

Практичний висновок: у файлі лежать лише числа, а не будова мережі. Якщо зібрати мережу іншої форми й завантажити в
неї чужі ваги, PyTorch зупиниться з помилкою. У фазі 4 Stable-Baselines3 зберігає і будову, і ваги одним викликом, але
всередині робить те саме.

## Як це піде в проєкт

У фазах 4 і 5 агент — це мережа такого самого виду, як сьогоднішня. Змінюються лише три речі: що входить, що виходить
і звідки береться ціль.

**Вхід.** Сьогодні мережа отримувала два числа: оцінку й виплату. Агент отримуватиме стан середовища `PoEnv`. План у
дні 1 фази 3 перелічує його склад: хвилина сесії, скільки хвилин слот ще зайнятий, рахунок, а для кожного кандидата
оцінка моделі `pine`, запас оцінки над порогом і поточна виплата. Якщо кандидатів, наприклад, три, це `3 + 3 · 3 = 12`
чисел. Точний перелік ви запишете самі у файлі `po-rl/ENV.md` у той день. Для мережі це означає одне: перший шар
матиме стільки входів, скільки чисел у стані.

**Вихід.** Сьогодні виходів було два. В агента їх буде стільки, скільки дій: «пропустити» і «взяти кандидата `k`» для
кожного кандидата. Для трьох кандидатів це чотири виходи.


дорівнює справжній імовірності виграшу, а в житті це треба перевіряти. Перевірка відбувається у фазі 3 і далі.

## Типові хибні уявлення

**«Нейронна мережа — це щось на зразок мозку, і зрозуміти її числа неможливо».** Мережа з лекції — це множення,
додавання і заміна від'ємних чисел нулем. Кожне проміжне число ми порахували вручну, і воно збіглося з виводом
PyTorch.

**«Більше шарів `Linear` підряд дають розумнішу мережу».** Без функції активації між ними кілька шарів `Linear`
рахують те саме, що один: зважена сума зважених сум є зваженою сумою. Нове з'являється лише тоді, коли між шарами
стоїть ReLU чи інша активація.

**«Втрата падає, отже мережа вчиться правильного».** Між першою і п'ятдесятою епохою втрата впала з `0,77` до `0,59`,
а мережа весь цей час відповідала «ставити» на все підряд. Втрату треба дивитися разом із точністю на нових прикладах
і разом із тим, що дає найпростіша відповідь.

**«Точність 65 % краща за монетку, отже щось вивчено».** У задачі, де один клас трапляється у 65 % прикладів, точність
65 % дає відповідь без жодного розуміння. Порівнювати треба з часткою найчастішого класу.

**«Градієнт каже, якою має бути вага».** Градієнт каже лише напрямок і крутизну в поточній точці: що буде з втратою,
якщо вагу зовсім трохи збільшити. Наскільки далеко йти, вирішує швидкість навчання, і після кроку градієнт треба
рахувати заново.

**«`zero_grad()` — формальність, без якої все одно працює».** Без цього рядка градієнти складаються від кроку до
кроку, і втрата в нашому прикладі гойдалася між `0,00` і `0,99` без кінця. Програма при цьому не повідомляє про жодну
помилку.

**«Останнім шаром класифікатора має бути softmax».** Функція `CrossEntropyLoss` робить softmax сама. Мережа має
повертати логіти. Softmax викликають окремо лише тоді, коли потрібні самі ймовірності, наприклад щоб вибрати дію
випадково у фазі 5.

**«Числа з NumPy можна одразу подавати в мережу».** NumPy за замовчуванням дає `float64`, а ваги мережі мають тип
`float32`. PyTorch зупиняється з помилкою `mat1 and mat2 must have the same dtype`.

## Перевірте себе

**1. Мережа має форму `12 → 64 → 64 → 4`. Скільки в неї параметрів?**

<details><summary>Відповідь</summary>

Перший шар: `12 · 64 + 64 = 832`. Другий шар: `64 · 64 + 64 = 4160`. Третій шар: `64 · 4 + 4 = 260`. Разом `832 + 4160
+ 260 = 5252`. Функції ReLU між шарами параметрів не мають.

</details>

**2. Нейрон має ваги `1` і `−2` та зсув `0,5`. На вході `3` і `1`. Ціль дорівнює `0`. Чому дорівнює втрата як квадрат
помилки і чому дорівнює похідна втрати за першою вагою?**

<details><summary>Відповідь</summary>

Вихід: `3 · 1 + 1 · (−2) + 0,5 = 1,5`. Помилка: `1,5 − 0 = 1,5`. Втрата: `1,5² = 2,25`. Похідна за першою вагою
дорівнює подвоєній помилці, помноженій на вхід цієї ваги: `2 · 1,5 · 3 = 9`. Похідна додатна, тому, щоб зменшити
втрату, першу вагу треба зменшувати.

</details>

**3. У попередньому запитанні швидкість навчання дорівнює `0,01`. Якою стане перша вага після одного кроку
градієнтного спуску?**

<details><summary>Відповідь</summary>

Нова вага дорівнює старій мінус швидкість навчання, помножена на похідну: `1 − 0,01 · 9 = 0,91`.

</details>

**4. Чому мережу з лекції не можна оцінювати за точністю на тих самих тисячі прикладах, на яких вона вчилася?**

<details><summary>Відповідь</summary>

Мережа з достатньою кількістю параметрів може запам'ятати відповіді на окремі приклади, не вивчивши правила. На
навчальних прикладах така мережа матиме високу точність, а на нових помилятиметься. Лише приклади, яких мережа не
бачила під час навчання, показують, чи вона вивчила саме правило. У торговій задачі це правило суворіше: перевірочні
приклади мають бути ще й пізнішими в часі, і цьому присвячено день 5 фази 3.

</details>

**5. Після ста епох навчання точність класифікатора «ставити чи пропустити» дорівнює 70 %. Відомо, що відповідь
«пропустити» правильна в 70 % прикладів. Що це означає?**

<details><summary>Відповідь</summary>

Найімовірніше, мережа завжди відповідає «пропустити» і нічого не вивчила про зв'язок входу з відповіддю. Точність 70 %
у цій задачі дає стала відповідь без жодної мережі. Щоб перевірити, треба порахувати, як часто мережа обирає кожен
клас: якщо клас «ставити» вона не обирає ніколи, здогад правильний.

</details>

**6. Програма навчання не падає, але втрата то падає майже до нуля, то знову росте, і так без кінця. Назвіть дві
можливі причини з лекції.**

<details><summary>Відповідь</summary>

Перша причина: у циклі пропущено `optimizer.zero_grad()`. Градієнти складаються від кроку до кроку, і оптимізатор
проскакує найкращу точку за інерцією. Друга причина: завелика швидкість навчання, через яку кожен крок перестрибує
найкращу точку. Починати перевірку варто з першої, бо вона трапляється частіше і перевіряється одним поглядом на код.

</details>

**7. Ви прочитали бари `pine` у масив NumPy, зробили з нього тензор через `torch.tensor(...)` і подали в мережу.
PyTorch зупинився з помилкою `mat1 and mat2 must have the same dtype, but got Double and Float`. Що сталося і як це
виправити?**

<details><summary>Відповідь</summary>

Бари `pine` зберігаються як `float64`, і NumPy зберіг цей тип. Функція `torch.tensor` узяла тип із масиву, тому тензор
має тип `float64`, який PyTorch називає `Double`. Ваги мережі мають тип `float32`, який він називає `Float`. Треба
перетворити вхід: `torch.tensor(масив, dtype=torch.float32)`.

</details>

## Словничок лекції

- **Тензор (tensor).** Набір чисел одного типу, складений у таблицю з відомою формою. Має поля `shape` і `dtype`.
- **Форма (shape).** Перелік розмірів тензора за кожним виміром: `[3, 2]` означає три рядки по два числа.
- **Батч (batch).** Тензор, у якому перший вимір означає «який приклад». Мережа обробляє весь батч одним викликом.
- **`float32` і `float64`.** Два типи дробових чисел: у чотирьох і у восьми байтах. Ваги PyTorch мають тип `float32`.
- **Нейрон.** Зважена сума вхідних чисел плюс зсув.
- **Вага (weight) і зсув (bias).** Числа нейрона, які змінює навчання. Разом їх називають параметрами.
- **Шар (layer).** Кілька нейронів з одним входом. У PyTorch це клас `torch.nn.Linear`.
- **Функція активації.** Проста функція між шарами, яка не є зваженою сумою. ReLU замінює від'ємні числа нулем.
- **Прямий прохід (forward pass).** Обчислення від входу мережі до її виходу.
- **Функція втрат (loss function) і втрата (loss).** Функція, яка одним числом каже, наскільки відповідь мережі далека
  від потрібної, і саме це число.
- **Ціль (target).** Відповідь, яку ми хочемо отримати від мережі на цьому прикладі.
- **Похідна (derivative).** На скільки зміниться втрата, якщо вагу збільшити на дуже малу величину, у перерахунку на
  одиницю ваги.
- **Градієнт (gradient).** Похідні втрати за всіма вагами, зібрані разом.
- **Правило ланцюжка (chain rule).** Швидкість зміни результату через проміжну величину дорівнює добутку швидкостей на
  кожній ланці.
- **Зворотне поширення (backpropagation).** Обчислення градієнта проходом від втрати назад до ваг. У PyTorch його
  запускає `loss.backward()`.
- **Швидкість навчання (learning rate).** Число, яке задає розмір кроку проти градієнта.
- **Оптимізатор (optimizer).** Об'єкт, який змінює ваги за їхнім градієнтом. У лекції це `SGD` і `Adam`.
- **Епоха (epoch).** Один прохід навчання по всіх навчальних прикладах.
- **Логіти (logits).** Числа на виході класифікатора до перетворення на ймовірності.
- **Softmax.** Функція, яка перетворює логіти на ймовірності із сумою одиниця.
- **Крос-ентропія (cross-entropy).** Функція втрат для класифікації: мінус логарифм імовірності, яку мережа дала
  правильному класу.
- **Точність (accuracy).** Частка прикладів, на яких вибір мережі збігся з правильною відповіддю.
