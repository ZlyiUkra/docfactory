### `Tossing a Biased Coin`: чесна монета і випадкові ставки

Правила гри в книжці такі. Агент ставить на орла або на решку. Ставка безкоштовна. Якщо агент угадав, він отримує 1
долар, якщо ні, не отримує нічого. Мета агента — якомога більша сума винагород. Зверніть увагу на відмінність від
бінарного опціону: тут програш нічого не коштує. До цієї відмінності розбір повернеться наприкінці розділу.

Перший приклад — точка відліку: монета чесна, агент ставить навмання.

```python
import numpy as np
from numpy.random import default_rng
rng = default_rng(seed=100)

ssp = [1, 0]
asp = [1, 0]

def epoch():
    tr = 0
    for _ in range(100):
        a = rng.choice(asp)
        s = rng.choice(ssp)
        if a == s:
            tr += 1
    return tr

rl = np.array([epoch() for _ in range(250)])
print(rl[:10])
print(rl.mean())
```

```text
[56 47 48 55 55 51 54 43 55 40]
49.968
```

Рядок за рядком.

- `from numpy.random import default_rng` бере з модуля `numpy.random` одну функцію і дає змогу викликати її без
  префікса. У JavaScript це `import { default_rng } from "..."`. Лекція викликала ту саму функцію як
  `np.random.default_rng`. Обидва записи рівноцінні.
- `rng = default_rng(seed=100)` створює генератор випадкових чисел із зерном 100. Завдяки зерну ваш запуск надрукує
  ті самі числа, що й книжка.
- `ssp = [1, 0]` — список можливих результатів кидка: 1 означає орла, 0 — решку. Назва `ssp` скорочує state space,
  **простір станів**: перелік усього, що може статися в середовищі.
- `asp = [1, 0]` — список можливих ставок: 1 означає ставку на орла, 0 — на решку. Назва `asp` скорочує action
  space, **простір дій**: перелік усього, що може зробити агент.
- `def epoch():` оголошує функцію без параметрів. Вона грає одну серію зі ста ставок і повертає, скільки з них
  виграло. Слово epoch у машинному навчанні означає один повний прохід.
- `tr = 0` — лічильник. Назва скорочує total reward, сума винагород.
- `for _ in range(100):` повторює тіло циклу сто разів. Ім'я `_` — звичайна змінна. За домовленістю Python так
  називають змінну, значення якої не потрібне: тут важливо лише повторити дію сто разів.
- `a = rng.choice(asp)` вибирає навмання один елемент списку `asp`. Це випадкова ставка.
- `s = rng.choice(ssp)` так само вибирає результат кидка. Усі елементи списку мають однакові шанси, тому орел і
  решка випадають порівну.
- `if a == s: tr += 1` додає одиницю, якщо ставка збіглася з результатом. Це й є винагорода в 1 долар.
- `[epoch() for _ in range(250)]` — **спискове включення**, англійською list comprehension. Воно будує список,
  викликаючи `epoch()` 250 разів. У JavaScript це `Array.from({ length: 250 }, () => epoch())`.
- `np.array(...)` перетворює список на масив NumPy, щоб потім порахувати середнє методом `mean()`. Назва `rl`
  означає список винагород.
- `rl[:10]` — **зріз**, англійською slice: перші десять елементів. У JavaScript це `rl.slice(0, 10)`.

Перший рядок виводу показує суми перших десяти серій: 56, 47, 48 і так далі. Вони гуляють навколо 50. Другий рядок —
середнє за 250 серій, `49.968`. Це збігається з числом у книжці. Агент, який ставить навмання на чесну монету,
вгадує половину кидків.

Практичний висновок для вашого проєкту вже знайомий із лекції: навіть коли шанси точно 50 %, окрема серія зі ста
ставок дає і 40, і 56 виграшів.

### `Tossing a Biased Coin`: монета зі зміщенням і ті самі випадкові ставки

Тепер орел випадає у 80 % кидків. Книжка змінює лише один рядок: `ssp = [1, 1, 1, 1, 0]`. У списку чотири одиниці
й один нуль, тому `rng.choice(ssp)` повертає 1 у чотирьох випадках із п'яти. Функцію `epoch` книжка наводить ще раз
без змін.

```python
import numpy as np
from numpy.random import default_rng
rng = default_rng(seed=100)

ssp = [1, 1, 1, 1, 0]
asp = [1, 0]

def epoch():
    tr = 0
    for _ in range(100):
        a = rng.choice(asp)
        s = rng.choice(ssp)
        if a == s:
            tr += 1
    return tr

rl = np.array([epoch() for _ in range(250)])
print(rl[:10])
print(rl.mean())
```

```text
[50 53 47 45 54 48 47 51 68 52]
50.296
```

Числа тут інші, ніж у книжці, де надруковано `[53 56 40 55 53 49 43 45 50 51]` і середнє `49.924`. Причина проста: у
книжці це продовження того самого блокнота, і генератор уже видав частину своєї послідовності в першому прикладі. У
нашому файлі генератор створено заново. Якщо запустити обидва приклади один за одним в одному файлі, вийдуть числа
книжки. Ми це перевірили.

Головне у виводі — середнє близько 50. Монета дуже несправедлива, а агент заробляє стільки ж, скільки на чесній.
Книжка пояснює це арифметикою: агент у половині випадків ставить на орла й тоді вгадує з імовірністю 0,8, а в
половині ставить на решку й вгадує з імовірністю 0,2. Разом це `0,8 · 0,5 + 0,2 · 0,5 = 0,5`.

Автор робить із цього висновок: без навчання агент не може скористатися зміщенням.

**Навіщо це в `po-rl`.** Це перша з базових стратегій, з якими ви порівнюватимете агента: випадкова. У фазі 3, дні 4,
ви запустите її на історії `pine`. Якщо навчений агент не кращий за випадкового, він нічого не навчився.

### `Tossing a Biased Coin`: агент запам'ятовує результати

Третій приклад дає агентові пам'ять. Агент записує кожен побачений результат і ставить, вибираючи навмання з усього
записаного.

```python
import numpy as np
from numpy.random import default_rng
rng = default_rng(seed=100)

ssp = [1, 1, 1, 1, 0]

def epoch(n):
    tr = 0
    asp = [0, 1]
    for _ in range(n):
        a = rng.choice(asp)
        s = rng.choice(ssp)
        if a == s:
            tr += 1
        asp.append(s)
    return tr

rl = np.array([epoch(100) for _ in range(250)])
print(rl[:10])
print(rl.mean())
```

```text
[63 65 80 65 65 67 60 74 55 81]
66.544
```

Що змінилося в коді.

- `def epoch(n):` тепер має параметр `n`, довжину серії.
- `asp = [0, 1]` перенесено всередину функції. На початку кожної серії агент нічого не знає, і в списку по одній
  ставці кожного виду.
- `asp.append(s)` дописує побачений результат у кінець списку. Метод `append` робить те саме, що `push` у
  JavaScript. Рядок стоїть на одному рівні з `if`, а не всередині нього, тому виконується після кожного кидка, хоч би
  чим він закінчився.

Простежимо, що відбувається зі списком `asp`. Після першого кидка, якщо випав орел, список дорівнює `[0, 1, 1]`, і
шанс наступної ставки на орла вже два з трьох. Після ста кидків у списку близько 80 одиниць і 20 нулів. Агент не
рахує ймовірностей: вони самі відбиваються у складі списку, з якого він вибирає.

Середнє `66.544` помітно вище за 50. У книжці надруковано `66.78`, і різниця знову пояснюється місцем у послідовності
генератора. Автор порівнює результат з очікуваним значенням цієї стратегії: `(0,8² + 0,2²) · 100 = 68`. Звідки
формула: коли список уже відбиває справжні шанси, агент ставить на орла з імовірністю 0,8 і тоді вгадує з імовірністю
0,8, а на решку ставить з імовірністю 0,2 і вгадує з імовірністю 0,2. Разом `0,8 · 0,8 + 0,2 · 0,2 = 0,68`.

Цю стратегію називають **зіставленням імовірностей**, англійською probability matching: агент обирає варіант так
часто, як часто той вигравав. Автор зауважує, що так поводяться люди в дослідах і навіть тварини.

### `Tossing a Biased Coin`: агент ставить на найчастіше

Четвертий приклад змінює один крок: агент не вибирає навмання з побаченого, а завжди ставить на той результат, який
досі випадав найчастіше.

```python
import numpy as np
from numpy.random import default_rng
from collections import Counter
rng = default_rng(seed=100)

ssp = [1, 1, 1, 1, 0]

def epoch(n):
    tr = 0
    asp = [0, 1]
    for _ in range(n):
        c = Counter(asp)
        a = c.most_common()[0][0]
        s = rng.choice(ssp)
        if a == s:
            tr += 1
        asp.append(s)
    return tr

rl = np.array([epoch(100) for _ in range(250)])
print(rl[:10])
print(rl.mean())
print(Counter([0, 1, 1, 1, 0, 1]).most_common())
```

```text
[74 83 81 74 80 81 75 79 84 77]
79.156
[(1, 4), (0, 2)]
```

- `from collections import Counter` бере з модуля `collections`, що входить до Python, клас `Counter`. **Клас** —
  це шаблон для створення об'єктів, як `class` у JavaScript. Слова `new` у Python немає: об'єкт створює звичайний
  виклик `Counter(asp)`.
- `Counter(asp)` рахує, скільки разів кожне значення трапляється у списку.
- `c.most_common()` повертає список пар «значення, кількість», упорядкований від найчастішого. Останній рядок
  виводу показує це на маленькому списку: значення 1 трапилося 4 рази, значення 0 — 2 рази, тому результат `[(1, 4),
  (0, 2)]`.
- `[0][0]` бере перший елемент першої пари, тобто найчастіше значення. Нумерація елементів, як і в JavaScript,
  починається з нуля.

Останній рядок коду з маленьким списком додано для розбору, у книжці його немає.

Середнє `79.156`, у книжці `78.50` в тексті, а якщо запустити її блокнот підряд, виходить `78.828`. Усі три числа
близькі до найбільшого можливого. Найкраще, що можна зробити з такою монетою, — завжди ставити на орла й вигравати 80
разів зі ста. Агент цього не знав і дійшов до цього сам за кілька перших кидків.

Порівняйте три стратегії на одній монеті:

| Стратегія | Як агент обирає ставку | Виграшів зі ста в середньому |
|-----------|------------------------|-------------------------------|
| випадкова | навмання | близько 50 |
| зіставлення ймовірностей | навмання з побачених результатів | близько 68 |
| найчастіший результат | те, що досі випадало найчастіше | близько 80 |

Після прикладів книжка наводить врізку `Probability Matching`. У ній переказано дослідження Koehler і James 2014
року за участю 1557 студентів: зіставлення ймовірностей було або найпоширенішою стратегією, або другою після
найкращої, а найкращу частіше обирали учасники з вищими оцінками тестів і більшою кількістю курсів статистики. Автор
підсумовує, що людям потрібні навчання й досвід, щоб подолати поведінку, яка здається природною. У виносках пояснено
слова utility maximization — вибір варіанта, що дає найбільшу користь, — і зроблено застереження, що такі досліди
проводять переважно на студентах.

**Навіщо це в `po-rl`.** Тут закладено дві думки, до яких план повернеться.

Перша думка: стратегія «завжди брати те, що досі було найкращим» у цьому прикладі перемагає, бо монета не змінюється
і варіантів лише два. У фазі 1, дні 1, ви побачите, що з кількома варіантами й малою різницею між ними така стратегія
може назавжди застрягнути на гіршому варіанті, якщо кращому на початку не пощастило. План називає таку стратегію
жадібною.

Друга думка стосується людини за торговим терміналом. Зіставлення ймовірностей — це звичка «розкладати» ставки
приблизно так, як розкладаються виграші. Якщо одна пара виграє у 62 % випадків, а інша у 58 %, інтуїція радить
ставити на обидві, трохи частіше на першу. Арифметика цього розділу каже інше.

### `Rolling a Biased Die`

Другий приклад повторює ті самі три стратегії на кубику. Четвірка випадає вп'ятеро частіше за кожне інше число:
`ssp = [1, 2, 3, 4, 4, 4, 4, 4, 5, 6]`. У списку десять елементів, п'ять із них четвірки, тому шанс четвірки 0,5, а
шанс кожного іншого числа 0,1. Простір дій — шість чисел: `asp = [1, 2, 3, 4, 5, 6]`. Серія тепер із 600 ставок, і
за вгадане число агент отримує 1 долар.

Код відрізняється від прикладів із монетою лише цими списками й числом 600, тому тут наведено тільки результати
нашого запуску всього блокнота підряд. Вони збігаються з надрукованими в книжці.

| Стратегія | Перші суми серій | Середнє за 250 серій | З чим порівнює автор |
|-----------|------------------|----------------------|----------------------|
| випадкова | 92, 96, 106, 99 | 101,22 | близько 100: шанс угадати одне число з шести — одна шоста |
| зіставлення ймовірностей | 182, 174, 162, 157 | 176,296 | `(0,5² + 0,1² · 5) · 600 = 180` |
| найчастіший результат | 305, 288, 312, 306 | 297,204 | найбільше можливе: 300, тобто половина з 600 |

Формула в другому рядку влаштована так само, як для монети. Агент ставить на четвірку з імовірністю 0,5 і тоді вгадує
з імовірністю 0,5. На кожне з п'яти інших чисел він ставить з імовірністю 0,1 і вгадує з імовірністю 0,1. Разом `0,25
+ 5 · 0,01 = 0,30`, а на 600 ставок це 180.

Автор підкреслює, що зіставлення ймовірностей збільшило суму винагород більш ніж на 75 % проти випадкових ставок, а
стратегія найчастішого результату майже досягла найбільшого можливого.

**Навіщо це в `po-rl`.** Кубик ближчий до вашої задачі, ніж монета: варіантів багато, і лише один помітно кращий.
Валютні пари у фазі 1 — це такий самий набір варіантів, тільки різниця між ними не 50 % проти 10 %, а 62 % проти 58
%. Чим менша різниця, тим довше треба збирати результати, щоб її помітити.

### `Bayesian Updating`

Останній підрозділ пояснює, чому підрахунок побачених результатів — не просто зручний прийом, а обґрунтований спосіб
оцінити шанси. Математики тут більше, ніж у решті розділу. Якщо формули зараз заважають, прочитайте лише підсумок
наприкінці цього підрозділу розбору.

| Що написано | Що це означає |
|-------------|---------------|
| Граючи, агент оновлює свої оцінки ймовірностей | Кожен новий кидок уточнює те, що агент знає про монету |
| Це можна розуміти як баєсове оновлення ймовірностей | **Баєсове оновлення**, англійською Bayesian updating, — правило, як змінювати впевненість у чомусь після нового спостереження. Названо за Томасом Баєсом, який описав його у XVIII столітті |
| Імовірність орла позначено `α`, імовірність решки `1 − α` | `α` (альфа) — це невідоме зміщення монети. У лекції те саме число позначено `p` |
| Кидки вважаються IID | IID скорочує independent and identically distributed: кожен кидок не залежить від попередніх і має ті самі шанси |
| У досліді орел випав `f_h` разів, решка `f_t` разів | Це два лічильники. Літера `f` означає frequency, частоту; `h` — heads, орел; `t` — tails, решка |
| `B` — біноміальний коефіцієнт | Число способів розставити `f_h` орлів серед усіх кидків. Наприклад, 8 орлів серед 10 кидків можна розставити 45 способами |
| `P(E | α) = B · α^f_h · (1 − α)^f_t` | Імовірність побачити саме такий результат досліду `E`, якщо зміщення монети дорівнює `α`. Запис `P(E | α)` читають «імовірність `E` за умови `α`» |

Розберемо останню формулу на числах. Нехай із 10 кидків орел випав 8 разів. Порахуємо, наскільки ймовірний такий
результат для різних монет.

| Припущення про монету `α` | Обчислення | Імовірність побачити 8 орлів із 10 |
|---------------------------|------------|-------------------------------------|
| 0,5 | `45 · 0,5⁸ · 0,5²` | 0,044 |
| 0,7 | `45 · 0,7⁸ · 0,3²` | 0,233 |
| 0,8 | `45 · 0,8⁸ · 0,2²` | 0,302 |
| 0,9 | `45 · 0,9⁸ · 0,1²` | 0,194 |

Чесна монета дає 8 орлів із 10 лише в 4 випадках зі ста. Монета зі зміщенням 0,8 дає такий результат у 30 випадках
зі ста, і це найбільше число в таблиці.

Саме так книжка шукає оцінку. Метод називається **оцінкою найбільшої правдоподібності**, англійською maximum
likelihood estimation, скорочено MLE: з усіх можливих значень `α` береться те, за якого побачений результат
найімовірніший. Книжка записує це так: `α_MLE = argmax P(E | α)`. Запис `argmax` означає «те значення `α`, за якого
вираз найбільший».

Далі книжка робить два кроки. Спершу вона замінює ймовірність її логарифмом. Логарифм перетворює добуток на суму, а
найбільшого значення досягає в тій самій точці, тому шукати стає простіше: `ln B + f_h · ln α + f_t · ln(1 − α)`.
Потім вона бере **похідну** цього виразу за `α` і прирівнює її до нуля. Похідна показує, як швидко змінюється вираз,
коли трохи змінити `α`. У найвищій точці вираз уже не росте й ще не спадає, тому похідна там дорівнює нулю. Виходить
рівняння `f_h / α − f_t / (1 − α) = 0`.

На цьому рівнянні текст розділу в корпусі обривається: наступна сторінка книжки до нього не потрапила. Розв'язати
рівняння нескладно, і ми доводимо обчислення до кінця самі:

```
f_h / α = f_t / (1 − α)
f_h · (1 − α) = f_t · α
f_h = α · (f_h + f_t)
α = f_h / (f_h + f_t)
```

**Підсумок підрозділу.** Найкраща оцінка шансів орла — це кількість орлів, поділена на кількість усіх кидків. Для 8
орлів із 10 це `8 / 10 = 0,8`, що збігається з найбільшим числом у таблиці вище. Формули лише підтвердили те, що
агент із прикладів робив без формул: рахував, що як часто випадає.

Подивимося, як ця оцінка поводиться зі зростанням кількості кидків. Цього прикладу в книжці немає.

```python
import numpy as np

rng = np.random.default_rng(seed=100)
tosses = rng.choice([1, 1, 1, 1, 0], size=1000)     # тисяча кидків, орел у 80 %

for n in (10, 100, 1000):
    heads = tosses[:n].sum()                        # скільки орлів серед перших n кидків
    print(f"кидків {n:4d}, орлів {heads:3d}, оцінка {heads / n:.3f}")
```

```text
кидків   10, орлів   8, оцінка 0.800
кидків  100, орлів  76, оцінка 0.760
кидків 1000, орлів 803, оцінка 0.803
```

- `rng.choice(список, size=1000)` повертає одразу масив із тисячі випадкових виборів.
- `tosses[:n].sum()` бере перші `n` кидків і складає їх. Орел записано одиницею, тому сума дорівнює кількості орлів.

Після 10 кидків оцінка випадково влучила рівно у 0,8. Після 100 кидків вона дорівнює 0,76, тобто помиляється на
чотири пункти. Після 1000 кидків вона 0,803. Оцінка наближається до справжнього значення, але повільно й не рівно.

**Навіщо це в `po-rl`.** Частка виграшів моделі — це та сама оцінка `f_h / (f_h + f_t)`, де орел — виграна ставка. У
журналі налаштувань `pine` є два такі виміри: 69,2 % на 610 угодах і 57,5 % на 40 угодах. Приклад вище показує, що на
сотні спроб оцінка легко помиляється на чотири пункти. Наскільки саме можна помилитися при заданій кількості угод,
рахує день 3 цієї фази.

### Чим ставки з книжки відрізняються від бінарного опціону

У книжці ставка безкоштовна: вгадав — отримав 1 долар, не вгадав — нічого не втратив. Тому навіть випадковий агент
там заробляє 50 доларів зі ста ставок. У бінарному опціоні програш забирає ставку. Перепишемо приклад із монетою так,
щоб гроші рахувалися, як у лекції: виграш `+0,70`, програш `−1`. Цього прикладу в книжці немає.

```python
import numpy as np
from collections import Counter

rng = np.random.default_rng(seed=100)
ssp = [1, 1, 1, 1, 0]           # орел випадає у 80 % кидків

def epoch(n, learn):
    money = 0.0
    seen = [0, 1]
    for _ in range(n):
        if learn:
            a = Counter(seen).most_common()[0][0]   # найчастіший із побачених результатів
        else:
            a = rng.choice([1, 0])                  # випадкова ставка
        s = rng.choice(ssp)
        money += 0.70 if a == s else -1.0
        seen.append(s)
    return money

for learn in (False, True):
    totals = np.array([epoch(100, learn) for _ in range(250)])
    print(f"вчиться: {learn}, середній підсумок ста ставок: {totals.mean():+.2f}")
```

```text
вчиться: False, середній підсумок ста ставок: -14.50
вчиться: True, середній підсумок ста ставок: +34.27
```

- Параметр `learn` перемикає стратегію: `True` означає ставити на найчастіший побачений результат, `False` — ставити
  навмання.
- `if learn: ... else: ...` — звичайне розгалуження. Слово `else` стоїть на тому самому рівні відступу, що й `if`, і
  після нього теж двокрапка.
- `0.70 if a == s else -1.0` — умовний вираз. У JavaScript це `a === s ? 0.70 : -1.0`. У Python порядок інший:
  спершу значення для випадку «так», потім умова, потім значення для випадку «ні».

Випадковий агент тепер не заробляє 50, а втрачає в середньому `14,50` за сто ставок. Це збігається з формулою
лекції: при `p = 0,5` і виплаті 70 % середній результат ставки `1,7 · 0,5 − 1 = −0,15`, а на сто ставок `−15`. Агент,
який вчиться, заробляє `+34,27`. Найкраще можливе тут — завжди ставити на орла: `1,7 · 0,8 − 1 = +0,36` на ставку,
тобто `+36` на сто ставок.

Практичний висновок: у книжці бездіяльна стратегія коштує лише недоотриманого прибутку, а в бінарних опціонах вона
коштує грошей. Тому у вашій задачі з'являється дія, якої в прикладах книжки немає: пропустити ставку.

### Гіпотеза винагороди

| Що написано | Що це означає |
|-------------|---------------|
| Мету агента в RL записують через особливий сигнал, який середовище передає агентові | Цей сигнал називається **винагородою**, англійською reward |
| На кожному кроці винагорода — просте число, `R_t ∈ ℝ` | `R_t` — винагорода на кроці з номером `t`. Запис `∈ ℝ` означає «належить до дійсних чисел», тобто це будь-яке число: ціле, дробове, від'ємне |
| Мета агента — якомога більша сума винагород | Не найбільша винагорода зараз, а найбільша сума за довгий час. Автори називають її cumulative reward, накопиченою винагородою |
| Reward hypothesis | **Гіпотеза винагороди**: усе, що ми називаємо метою, можна описати як прагнення якомога більшого очікуваного значення суми одного числового сигналу |
| Використання сигналу винагороди для запису мети — одна з найхарактерніших рис RL | Саме цим RL відрізняється від навчання з учителем, де моделі показують правильні відповіді |

Слово expected у формулюванні гіпотези — це те саме очікуване значення, яке ви рахували в лекції. Агент не може
збільшити суму винагород у кожній окремій серії, бо в серії багато випадку. Він може збільшити її в середньому.

Слово hypothesis автори вжили навмисно. Вони не доводять, що кожну мету можна записати одним числом. Вони кажуть, що
на практиці цього щоразу вистачало.

**Навіщо це в `po-rl`.** Для торгівлі гіпотеза виконується майже без зусиль: мета й так є числом, зміною рахунку.
Це одна з причин, чому торгові задачі здаються зручними для RL. Труднощі там в іншому, і про них фази 3 і 7.

### Приклади винагород

Автори показують на прикладах, як мету перекладають у числа.

| Задача | Винагорода в книжці | Що вона заохочує |
|--------|---------------------|------------------|
| робот вчиться ходити | на кожному кроці число, пропорційне пройденому вперед | рухатися вперед якомога швидше |
| робот шукає вихід із лабіринту | `−1` за кожен крок до виходу | вийти якомога швидше, бо кожен зайвий крок коштує |
| робот збирає порожні бляшанки | здебільшого `0`, і `+1` за кожну бляшанку | збирати якомога більше |
| той самий робот | від'ємна винагорода, коли він на щось наштовхнувся або на нього накричали | уникати зіткнень |
| гра в шашки чи шахи | `+1` за перемогу, `−1` за поразку, `0` за нічию і за всі позиції до кінця гри | перемагати |

У тексті з PDF знак мінус перед одиницею загубився: написано «the reward is often 1 for every time step» і «+1 for
winning, 1 for losing». У книжці там `−1`. Без мінуса приклад із лабіринтом втрачає сенс, бо додатна винагорода за
кожен крок заохочувала б блукати довше.

Приклад із лабіринтом вартий окремої уваги. Агент там не отримує нічого приємного, навіть коли знайшов вихід. Він
лише перестає втрачати. Цього досить, щоб він шукав найкоротший шлях.

Порівняйте з вашою задачею:

| Задача | Винагорода | Що вона заохочує |
|--------|------------|------------------|
| агент торгових рішень `po-rl` | `+ставка · виплата` за виграну ставку, `−ставка` за програну, `0` за пропуск | збільшувати рахунок |

Ваша винагорода найбільше схожа на шашки з тією відмінністю, що виграш і програш мають різний розмір, а «нічия» в
`pine` рахується програшем.

### Винагорода каже, чого досягти, а не як

Останній абзац розділу в корпусі лежить на початку документа `Returns and Episodes`.

| Що написано | Що це означає |
|-------------|---------------|
| Агент завжди вчиться збільшувати свою винагороду | Він не знає, чого ми хотіли. Він знає лише число |
| Щоб агент зробив щось для нас, винагороди треба задати так, щоб, збільшуючи їх, він досягав і нашої мети | Відповідальність за мету лежить на тому, хто пише функцію винагороди |
| Сигнал винагороди — не місце, щоб передавати агентові знання про те, як досягти мети | Підказки на кшталт «за це плюс, бо це зазвичай корисно» шкодять |
| Шаховий агент має отримувати винагороду лише за перемогу, а не за проміжні цілі: взяті фігури чи контроль центру | Проміжна ціль, англійською subgoal, — те, що зазвичай веде до мети, але не є нею |
| Якщо винагороджувати проміжні цілі, агент може знайти спосіб досягати їх без справжньої мети | Наприклад, брати фігури суперника ціною програної партії |
| Сигнал винагороди — це спосіб сказати агентові, чого ви хочете досягти, а не як | Підсумкове речення розділу |

Перекладемо шаховий приклад на торгівлю.

| Спокуслива проміжна ціль | Що агент навчиться робити замість заробітку |
|--------------------------|----------------------------------------------|
| винагорода за кожну виграну ставку, незалежно від виплати | ставити там, де виграти легше, навіть якщо виплата не покриває програшів |
| винагорода за пропуск слабкого сигналу | пропускати все й збирати винагороду за обережність |
| винагорода за малу кількість угод | не торгувати взагалі |
| штраф за кожен збитковий день | уникати днів із багатьма ставками, навіть коли ставки вигідні |

План повторює це застереження у фазі 3, дні 1, у рядку «Пастка»: винагорода — це гроші, і більше нічого.

У цьому абзаці є дві виноски, 5 і 6, але їхнього тексту в корпусі немає. У фазі 3, дні 1, план просить прочитати
розділ `Designing Reward Signals` тієї самої книжки, де автори розбирають цю тему докладно.

**Навіщо це в `po-rl`.** Розділ дає правило, за яким ви перевірятимете кожну свою функцію винагороди: чи дорівнює
сума винагород за сесію зміні рахунку за сесію. Якщо так, агент вчиться того, що вам потрібно. Якщо у функції
з'явився доданок, якого на рахунку немає, агент вчиться чогось іншого.

## Запитання до читання

**1. Чому випадкові ставки на монету, яка у 80 % випадків падає орлом, дають ті самі 50 % вгаданих, що й на чесну
монету?**

<details><summary>Відповідь</summary>

Агент у половині випадків ставить на орла й тоді вгадує з імовірністю 0,8, а в половині ставить на решку й вгадує з
імовірністю 0,2. Разом `0,8 · 0,5 + 0,2 · 0,5 = 0,5`. Зміщення монети допомагає одній ставці рівно настільки,
наскільки шкодить іншій. Скористатися зміщенням може лише агент, який ставить на орла частіше, ніж на решку.

</details>

**2. Орел випадає з імовірністю 0,7. Скільки ставок зі ста в середньому вгадує агент, який зіставляє ймовірності, і
скільки агент, який завжди ставить на найчастіший результат?**

<details><summary>Відповідь</summary>

Зіставлення ймовірностей дає `0,7² + 0,3² = 0,49 + 0,09 = 0,58`, тобто 58 ставок зі ста. Ставка на найчастіший
результат дає 70 зі ста, бо агент завжди ставить на орла.

</details>

**3. Що робить рядок `a = Counter(asp).most_common()[0][0]`?**

<details><summary>Відповідь</summary>

`Counter(asp)` рахує, скільки разів кожне значення трапляється у списку `asp`. Метод `most_common()` повертає список
пар «значення, кількість» від найчастішого. Перший індекс `[0]` бере першу пару, другий `[0]` бере з неї значення.
У змінній `a` опиняється результат, який досі випадав найчастіше.

</details>

**4. З 40 кидків орел випав 23 рази. Яка оцінка найбільшої правдоподібності для ймовірності орла? Чи можна на неї
покладатися?**

<details><summary>Відповідь</summary>

Оцінка дорівнює `23 / 40 = 0,575`. Покладатися на неї рано: у прикладі розбору оцінка після ста кидків помилялася на
чотири пункти, а тут кидків лише сорок. Це ті самі числа, що у другому вимірі з журналу налаштувань `pine`: 40 угод,
57,5 % виграшів.

</details>

**5. У прикладі з лабіринтом агент отримує `−1` за кожен крок і нічого за вихід. Чому він усе одно вчиться
виходити?**

<details><summary>Відповідь</summary>

Агент збільшує суму винагород. Поки він у лабіринті, сума зменшується на одиницю щокроку. Найбільша можлива сума —
та, де кроків найменше, тобто найкоротший шлях до виходу. Окрема винагорода за вихід не потрібна.

</details>

**6. Чому в бінарних опціонах випадковий агент втрачає гроші, а в прикладах Hilpisch заробляє?**

<details><summary>Відповідь</summary>

У книжці ставка безкоштовна: програш дає нуль, виграш дає 1 долар, тому кожна стратегія має невід'ємний результат. У
бінарному опціоні програш забирає ставку, а виграш додає лише її частину. При ймовірності виграшу 0,5 і виплаті 70 %
середній результат ставки дорівнює `1,7 · 0,5 − 1 = −0,15`.

</details>

**7. Хтось пропонує додати до винагороди агента `+0,1` за кожну хвилину, коли він пропустив сигнал із низькою
оцінкою моделі. Що на це каже розділ `Goals and Rewards`?**

<details><summary>Відповідь</summary>

Це винагорода за проміжну ціль, як винагорода за взяті фігури в шахах. Агент може збирати її, не досягаючи справжньої
мети: пропускати все й отримувати `+0,1` щохвилини. Сума винагород перестане дорівнювати зміні рахунку. Пропуск має
давати нуль, бо на рахунку він нічого не змінює.

</details>
