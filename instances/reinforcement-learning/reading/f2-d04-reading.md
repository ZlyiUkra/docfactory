### Рамка алгоритму: `First-visit MC prediction`

Рамка на сервері розсипалася найсильніше. Ось вона, записана заново:

```text
вхід: політика π, яку треба оцінити
початок: V(s) — довільні числа для всіх станів s
         Returns(s) — порожній список для всіх станів s
повторювати без кінця (для кожного епізоду):
    зіграти епізод за політикою π:  S_0, A_0, R_1, S_1, A_1, R_2, …, S_{T−1}, A_{T−1}, R_T
    G ← 0
    для кожного кроку епізоду з кінця, t = T−1, T−2, …, 0:
        G ← γ · G + R_{t+1}
        якщо S_t не трапляється серед S_0, S_1, …, S_{t−1}:
            додати G до Returns(S_t)
            V(S_t) ← середнє зі списку Returns(S_t)
```

| Рядок рамки | Що він робить | Де це в лекції дня |
|-------------|---------------|---------------------|
| зіграти епізод | записує стани, дії й винагороди до завершального кроку `T` | функція `walk` |
| `G ← 0` | повернення після кінця епізоду дорівнює нулю | `g = 0.0` |
| цикл з кінця | іде від останнього кроку до нульового | `reversed(...)` |
| `G ← γ · G + R_{t+1}` | повернення від кроку `t` через повернення від наступного кроку; на сервері `γ` зникла | `g = reward + 1.0 * g` |
| «якщо `S_t` не трапляється серед ранніх» | перевірка першого відвідування: крок беруть, лише якщо раніше в епізоді цього стану не було | множина `seen` |
| додати до списку й усереднити | оцінка — середнє всіх зібраних повернень стану | список `found[state]`, потім покрокове середнє |

Про рамку варто знати три речі. Перша: перевірку «серед ранніх» роблять, ідучи з кінця, тому для кожного кроку треба
переглядати початок епізоду; у коді зручніше спершу порахувати всі повернення, а потім пройти епізод з початку й
запам'ятовувати вже бачені стани. Друга: для кожного відвідування без перевірки вийшла б та сама рамка, і автори
кажуть це прямо. Третя: рамка зберігає списки; вправа 5.4, яка стоїть у розділі 5.3, просить замінити їх середнім і
лічильником, як у розділі 2.4 про бандита. Лекція дня зробила це в розділі про покрокове середнє.

### Чому оцінки збігаються

| Що написано | Що це означає |
|-------------|---------------|
| обидва методи збігаються до `v_π(s)`, коли кількість відвідувань, або перших відвідувань, прямує до нескінченності | оцінка стає точною лише в границі |
| для першого відвідування це легко побачити: кожне повернення — незалежна, однаково розподілена оцінка `v_π(s)` зі скінченною дисперсією | повернення з різних епізодів одне на одне не впливають |
| за законом великих чисел послідовність середніх збігається до очікуваного значення | як частка виграшів до ймовірності |
| кожне середнє саме є незміщеною оцінкою, а стандартне відхилення його помилки зменшується як `1/√n`, де `n` — кількість усереднених повернень | формула стандартної похибки з лекції «Наскільки можна вірити частці виграшів» |
| з кожним відвідуванням складніше, але його оцінки теж збігаються до `v_π(s)` | автори посилаються на статтю Singh і Sutton 1996 року |

**Незнайомі слова.** Independent, identically distributed — «незалежні й однаково розподілені»: кожне число взято з
того самого розподілу й не залежить від решти. Unbiased — «незміщений». Variance — «дисперсія»: квадрат стандартного
відхилення. Converge quadratically — так автори кажуть про швидкість, з якою помилка зменшується; для практики досить
знати, що вона падає як `1/√n`.

```python
def total(hard, ace):
    """Сума руки. hard — сума, у якій кожен туз рахується як 1; ace — чи є в руці туз."""
    return hard + 10 if ace and hard + 10 <= 21 else hard          # придатний туз рахується як 11

@lru_cache(maxsize=None)
def dealer(hard, ace, cards):
    """Чим закінчить дилер: словник {(сума або 0 за перебору, чи це natural): імовірність}."""
    now = total(hard, ace)
    if now >= 17:                                                  # дилер зупиняється на 17 і більше
        return {(now if now <= 21 else 0, cards == 2 and now == 21): 1.0}
    ends = {}
    for card, prob in CARDS.items():                               # інакше бере карту: перебираємо всі
        for end, p in dealer(hard + card, ace or card == 1, cards + 1).items():
            ends[end] = ends.get(end, 0.0) + prob * p
    return ends

@lru_cache(maxsize=None)
def value(hard, ace, cards, shown):
    """Точна цінність руки гравця за політики «зупинятися на 20 і 21»; shown — відкрита карта дилера."""
    now = total(hard, ace)
    if now > 21:
        return -1.0                                                # перебір
    if now < 20:                                                   # політика бере карту: середнє за всіма картами
        return sum(prob * value(hard + card, ace or card == 1, cards + 1, shown) for card, prob in CARDS.items())
    natural, result = cards == 2 and now == 21, 0.0
    for (end, dealer_natural), prob in dealer(shown, shown == 1, 1).items():
        win = 1 if natural and not dealer_natural else (now > end) - (now < end)   # правило sab=True
        result += prob * win
    return result

if __name__ == "__main__":
    for ace, title in ((False, "без придатного туза"), (True, "з придатним тузом")):
        print(f"{title}; стовпчики — відкрита карта дилера: туз, 2, …, 10")
        for player in range(12, 22):
            hard = player - 10 if ace else player                  # три карти й більше: рука не є natural
            print(f"  {player}  " + " ".join(f"{value(hard, ace, 3, shown):+.2f}" for shown in range(1, 11)))
    print(f"natural проти дев'ятки дилера: {value(11, True, 2, 9):+.3f};  проти туза: {value(11, True, 2, 1):+.3f}")
```

- Словник `CARDS` — це вся модель: з якою ймовірністю з колоди приходить кожен номінал. Десятка, валет, дама й король
  дають 10, тому їхня ймовірність учетверо більша.
- Руку записано двома числами: `hard` — сума, у якій кожен туз рахується як одиниця, і `ace` — чи є туз. Функція
  `total` додає 10, якщо туз придатний.
- `@lru_cache(maxsize=None)` перед функцією велить Python запам'ятовувати її результати: удруге для тих самих
  аргументів функція не рахується, а відповідь береться з пам'яті. Без цього рядка програма рахувала б ту саму руку
  мільйони разів. У JavaScript таке запам'ятовування пишуть вручну через `Map`.
- Функція `dealer` викликає сама себе: якщо дилер ще не дійшов до 17, вона перебирає всі карти, для кожної питає в
  себе, чим закінчиться нова рука, і складає ймовірності. Це рекурсія, і вона закінчується, бо сума руки лише росте.
- Функція `value` робить те саме для гравця. Якщо сума менша за 20, політика бере карту, і цінність — середнє за всіма
  картами. Якщо 20 чи 21, гравець зупиняється, і цінність — сума за всіма фіналами дилера. Вираз `(now > end) - (now <
  end)` дає `+1`, `0` або `−1`: у Python `True` і `False` у арифметиці поводяться як 1 і 0.
- Аргумент `cards` потрібен лише для того, щоб відрізнити natural: 21 саме з двох карт.

Друга програма відповідає на запитання, наскільки добре оцінки Монте-Карло наближають ці числа після десяти тисяч і

можна лише після того, як практику зроблено. Числа нижче — з мого запуску.

```python
from experiments.f2_d4_blackjack import evaluate, stick_on_20      # ваші функції з практики дня
from r1_exact import value

def exact(state):
    """Точна цінність стану-спостереження; для руки з трьох і більше карт, тобто не natural."""
    player, shown, ace = state
    return value(player - 10 if ace else player, bool(ace), 3, shown)

for episodes in (10_000, 500_000):                                 # дві кількості з малюнка 5.1 книжки
    V, N = evaluate(stick_on_20, episodes, 1)
    print(f"після {episodes} епізодів")
    for ace, title in ((0, "без придатного туза"), (1, "з придатним тузом ")):
        states = [s for s in V if s[2] == ace and 12 <= s[0] <= 20]      # дев'яносто станів: суми від 12 до 20
        errors = sorted(abs(V[s] - exact(s)) for s in states)
        visits = sorted(N[s] for s in states)
        print(f"  {title}: станів {len(states)}, відвідувань на стан від {visits[0]} до {visits[-1]}")
        middle = errors[len(errors) // 2]
        print(f"      помилка оцінки: у половини станів до {middle:.3f}, найбільша {errors[-1]:.3f}")
```

- Рядок `from experiments.f2_d4_blackjack import ...` бере функції з вашого файла досліду; файл `r1_exact.py` з
  попередньою програмою має лежати в корені проєкту поруч.
- Функція `exact` переводить спостереження назад у руку: якщо туз придатний, сума містить зайві 10, і їх треба
  відняти.
- Список `errors` — відстані між оцінкою й точною цінністю для кожного стану, упорядковані за зростанням; елемент із
  середини списку — це помилка, меншу за яку має половина станів.

Вивід підтверджує обидва твердження книжки, і тепер із числами. Після десяти тисяч епізодів стани без придатного туза
мають від 77 до 616 відвідувань, і половина з них оцінена з помилкою до `0,045`. Стани з придатним тузом мають від 2
до 82 відвідувань; половина з них помиляється більше ніж на `0,165`, а найгірша оцінка відстоїть від істини на `1,23`:
це стан, де з двох відвідувань вийшло два виграші за точної цінності близько `−0,2`. Саме це автори називають «менш
певні й менш рівні».

Після п'ятисот тисяч епізодів найбільша помилка серед станів без придатного туза дорівнює `0,026`. Слова «наближена
дуже добре» для них справедливі. Серед станів із придатним тузом найрідкісніший має 190 відвідувань, і найбільша
помилка там `0,171`. Навіть пів мільйона епізодів не рятує рідкісний стан: це пастка дня на прикладі з книжки.

Стани із сумою 21 і придатним тузом програма пропускає, і ось чому. Спостереження `(21, 9, 1)` приховує дві різні
руки. Перша — natural, туз і десятка: проти дев'ятки дилера вона виграє завжди, цінність `+1,000`. Друга — 21 з трьох
і більше карт, наприклад туз, чотири й шість: її цінність `+0,94`. Оцінка Монте-Карло для цього спостереження —
середнє обох, зважене тим, як часто трапляється кожна, і за точним розрахунком воно дорівнює `+0,987`. Тобто три числа
спостереження тут не є повним станом: минуле, а саме кількість карт, додає відомості. Метод Монте-Карло від цього не
ламається, бо усереднює справжні повернення й нічого не припускає про властивість Маркова.

**Вправа 5.2** питає, чи змінилися б результати, якби взяти кожне відвідування замість першого. У блекджеку стан не
може повторитися в межах епізоду: сума гравця з кожною картою росте, а якщо туз перестає бути придатним, змінюється
третє число спостереження. Тому обидва методи дають ті самі числа.

### Рамка алгоритму: `Monte Carlo ES`

```text
початок: π(s) — довільна дія для кожного стану s
         Q(s, a) — довільні числа; Returns(s, a) — порожні списки
повторювати без кінця (для кожного епізоду):
    вибрати навмання стартовий стан S_0 і стартову дію A_0 так, щоб кожна пара мала ймовірність більше нуля
    зіграти епізод від S_0, A_0, далі за політикою π
    G ← 0
    для кожного кроку епізоду з кінця, t = T−1, T−2, …, 0:
        G ← γ · G + R_{t+1}
        якщо пара S_t, A_t не трапляється серед ранніх пар епізоду:
            додати G до Returns(S_t, A_t)
            Q(S_t, A_t) ← середнє зі списку Returns(S_t, A_t)
            π(S_t) ← дія a з найбільшим Q(S_t, a)
```

Від рамки розділу 5.1 ця відрізняється трьома місцями: епізод починається з випадкової пари, ключем є пара, а не стан,
і після кожного оновлення оцінки політика в цьому стані стає жадібною. Букви ES у назві — Exploring Starts.

| Що написано після рамки | Що це означає |
|--------------------------|---------------|
| вправа 5.4: рамка неефективна, бо тримає списки й щоразу рахує середнє; опишіть, як замінити їх середнім і лічильником | покрокове середнє з лекції дня |
| усі повернення для пари накопичуються й усереднюються незалежно від того, яка політика діяла, коли їх спостерігали | у середнє потрапляють і повернення старих, гірших політик; у прикладі лекції тому `Q(free, взяти)` вийшло `0,0505` за точного `0,0481` |
| алгоритм не може зійтися до неоптимальної політики: тоді функція цінності зійшлася б до її цінностей, а це змінило б політику | нерухомою може бути лише оптимальна пара |
| збіжність до цієї нерухомої точки здається неминучою, але формально не доведена; автори називають це одним із найфундаментальніших відкритих питань галузі | простота алгоритму оманлива |

| Що написано | Що це означає |
|-------------|---------------|
| єдиний загальний спосіб гарантувати, що всі дії вибиратимуться нескінченно часто, — щоб агент і далі їх вибирав | дослідження не можна вимкнути |
| методи за політикою (on-policy) оцінюють або покращують ту політику, якою приймають рішення; методи поза політикою (off-policy) — іншу, ніж та, що породила дані | другі відкладено до дня 6 |
| у методах за політикою політика зазвичай м'яка: `π(a\|s) > 0` для всіх станів і дій | кожна дія можлива |
| ε-жадібна політика: нежадібні дії дістають найменшу ймовірність `ε / \|A(s)\|`, а жадібна — решту, `1 − ε + ε / \|A(s)\|` | для двох дій і `ε = 0,1`: `0,05` і `0,95`; на сервері `ε` виглядає як лапка |
| ε-жадібні політики — приклад ε-м'яких: `π(a\|s) ≥ ε / \|A(s)\|` | серед ε-м'яких вони найближчі до жадібних |
| без дослідницьких стартів не можна просто зробити політику жадібною: це зупинило б дослідження нежадібних дій | тому політику рухають лише до ε-жадібної |
| узагальнена ітерація за політиками й не вимагає доводити політику до жадібної, лише рухати в той бік | цього досить для покращення |

Рамка алгоритму `On-policy first-visit MC control (for ε-soft policies)` відрізняється від попередньої двома місцями.
Епізод починається звичайно, без випадкової стартової пари. А останній рядок замість «`π(S_t)` ← жадібна дія» записує
ймовірності:

```text
A* ← дія a з найбільшим Q(S_t, a); якщо таких кілька, будь-яка з них
для кожної дії a стану S_t:
    π(a | S_t) ← 1 − ε + ε / |A(S_t)|,  якщо a = A*
    π(a | S_t) ← ε / |A(S_t)|,          якщо a ≠ A*
```

У лекції дня ці два рядки — функція `eps_greedy`.

Решту розділу займає доведення, і з нього варто взяти дві думки.

| Що написано | Що це означає |
|-------------|---------------|
| формула (5.2): для будь-якої ε-м'якої політики `π` будь-яка ε-жадібна щодо `q_π` політика не гірша за `π` | теорема про покращення політики працює й тут |
| уявімо нове середовище, таке саме, як старе, але вимогу ε-м'якості «перенесено всередину»: з імовірністю `ε` середовище саме замінює дію агента на випадкову | найкраща звичайна політика в новому середовищі — це найкраща ε-м'яка в старому |
| покращення зупиняється лише тоді, коли знайдено найкращу серед ε-м'яких політик | не найкращу взагалі |
| останнє речення, на сервері вже в наступному документі: тепер ми досягаємо лише найкращої політики серед ε-м'яких, зате позбулися припущення дослідницьких стартів | ціна дослідження |

Число до цієї таблиці є в лекції дня. На торговій хвилині найкраща політика бере сигнал завжди й має `Q(free, взяти) =
0,05`. Найкраща ε-м'яка політика з `ε = 0,1` бере його в `95 %` випадків, і за неї та сама дія варта `0,0481`. Різниця
`0,0019` — це те, що агент платить за дослідження в цій задачі.

### `The random walk environment`

Задача, на якій Моралес показує всі методи глави, — випадкове блукання. П'ять незавершальних станів стоять у ряд, по
краях два завершальні. З кожного стану агент із рівними ймовірностями переходить ліворуч або праворуч, хоч би яку дію
вибрав. Винагорода `+1` приходить лише за вихід праворуч. Епізод починається в середньому стані.

Автор пропонує два способи думати про цю задачу: або середовище не слухає агента, або середовище слухняне, а оцінюють
політику, що вибирає напрямок навмання. Для оцінювання різниці немає. Справжні цінності п'яти станів зліва направо
дорівнюють `1/6`, `2/6`, `3/6`, `4/6`, `5/6`: це ймовірність вийти праворуч раніше, ніж ліворуч. Для середнього стану
Моралес називає число `0,5`.

### Код: `generate_trajectory` і `mc_prediction`

Код Моралеса написано для старої бібліотеки Gym і старого NumPy. Запустити його сьогодні як є не вийде, і корисно
знати, де саме він зупиниться.

| Що в коді Моралеса | Як це в Gymnasium 1.4 і NumPy 2.5 |
|--------------------|------------------------------------|
| `state = env.reset()` | `reset` повертає пару: `obs, info = env.reset()` |
| `next_state, reward, done, _ = env.step(action)` | `step` повертає п'ять значень; `done` розділено на `terminated` і `truncated` |
| `np.array(trajectory, np.object)` | назву `np.object` з NumPy прибрано; я перевірив у NumPy 2.5.4: звертання до неї дає `AttributeError`. Писати треба `object` |
| `for e in tqdm(range(n_episodes))` | `tqdm` — окремий пакет, що малює смугу поступу; у вашому віртуальному середовищі його немає, і цикл працює без нього |

Функція `generate_trajectory` грає епізод і повертає масив кортежів досвіду. Вона робить те саме, що `env_episode` у
практиці дня, з однією відмінністю: якщо епізод не закінчився за `max_steps` кроків, вона викидає його й починає
новий. Для методу Монте-Карло це чесний хід: обірваний епізод не має справжнього повернення.

Функція `mc_prediction` у двох частинах робить таке.

| Рядок | Що він робить |
|-------|---------------|
| `discounts = np.logspace(0, max_steps, num=max_steps, base=gamma, endpoint=False)` | рахує наперед усі множники `γ⁰`, `γ¹`, …; `np.logspace` дає степені числа `base` |
| `alphas = decay_schedule(...)` | рахує наперед крок навчання для кожного епізоду: від `0,5` він спадає до `0,01` |
| `V = np.zeros(nS)` | оцінки цінності починаються з нулів; стани — номери, тому таблиця — масив |
| `visited = np.zeros(nS, dtype=np.bool)` | позначки «стан уже траплявся в цьому епізоді» |
| `if visited[state] and first_visit: continue` | перевірка першого відвідування; з `first_visit=False` та сама функція робить кожне відвідування |
| `G = np.sum(discounts[:n_steps] * trajectory[t:, 2])` | повернення від кроку `t`: винагороди до кінця, помножені на множники знецінення |
| `V[state] = V[state] + alphas[e] * (G - V[state])` | оновлення оцінки |

Останній рядок — те місце, де код розходиться з рамкою Sutton і Barto і з практикою дня. У рамці й у вас крок дорівнює
`1 / N(s)`, і оцінка є точним середнім усіх повернень. У Моралеса крок `alphas[e]` залежить від номера епізоду, а не
від лічильника стану, і не опускається нижче за `0,01`. Це загальна форма оновлення з лекції «Наскільки можна вірити
частці виграшів»: нова оцінка дорівнює старій плюс крок, помножений на різницю між ціллю й старою оцінкою. Сам автор
пояснює вибір так: сталий крок допомагає в середовищах, що змінюються, а спадний він узяв, щоб показати збіжність; до
нуля крок не доходить, тому повної збіжності немає.

Що це дає на практиці, показує коротка програма на його ж задачі.

```python
import numpy as np

def walk(rng):
    """Епізод випадкового блукання Моралеса: стани 1–5, старт у стані 3, кроки ліворуч і праворуч навпіл.

    Повертає відвідані стани й повернення епізоду: 1, якщо агент вийшов праворуч (у стан 6), і 0, якщо ліворуч.
    """
    state, visited = 3, []
    while 0 < state < 6:
        visited.append(state)
        state += 1 if rng.random() < 0.5 else -1
    return visited, float(state == 6)

def estimate(step, episodes, rng):
    """Оцінка V(3) методом «перше відвідування»; step(n) — крок оновлення для n-го повернення стану."""
    v = 0.0
    for n in range(1, episodes + 1):
        _, g = walk(rng)                      # стан 3 — стартовий, тож він є в кожному епізоді
        v += step(n) * (g - v)
    return v

for title, step in (("крок 1/n (середнє)", lambda n: 1 / n), ("сталий крок 0.5", lambda n: 0.5),
                    ("сталий крок 0.01", lambda n: 0.01)):
    values = [estimate(step, 500, np.random.default_rng(seed)) for seed in range(40)]
    print(f"{title:20s} V(3) після 500 епізодів на 40 зернах: від {min(values):.3f} до {max(values):.3f}, "
          f"розкид {np.std(values):.3f}; точна цінність 0.500")
```

- Функція `walk` грає епізод блукання. `float(state == 6)` перетворює `True` на `1.0` і `False` на `0.0`.
- Функція `estimate` приймає аргументом функцію `step`: вона каже, яким кроком оновлювати оцінку для повернення з
  номером `n`. Так один цикл робить і середнє, і сталий крок.

```text
крок 1/n (середнє)   V(3) після 500 епізодів на 40 зернах: від 0.448 до 0.534, розкид 0.019; точна цінність 0.500
сталий крок 0.5      V(3) після 500 епізодів на 40 зернах: від 0.004 до 0.986, розкид 0.304; точна цінність 0.500
сталий крок 0.01     V(3) після 500 епізодів на 40 зернах: від 0.440 до 0.622, розкид 0.035; точна цінність 0.500
```

З кроком `1/n` сорок оцінок після п'ятисот епізодів лежать між `0,45` і `0,53`. Зі сталим кроком `0,5` вони лежать між
`0,004` і `0,986`: кожне нове повернення, нуль або одиниця, перетягує оцінку наполовину до себе, і вона ніколи не
заспокоюється. Зі сталим кроком `0,01` розкид удвічі більший, ніж у середнього. Саме це видно на графіках Моралеса,
які на сервері не збереглися: за його словами, оцінки першого відвідування дуже шумні й стрибають довкола справжніх
значень. Частина цього шуму належить методу, частина — кроку, який не зменшується до нуля.

**Навіщо це в проєкті `po-rl`.** Вибір між кроком `1/n` і сталим кроком ви вже робили в дні 4 фази 1. Для оцінювання
сталої політики в сталому світі беріть `1/n`. Сталий крок знадобиться з дня 5, де ціль оновлення сама змінюється під
час навчання.

У коді є конструкція, яку варто розібрати, бо вона стосується пастки дня. Таблицю цінностей підручник створює рядком
`defaultdict(lambda: np.zeros(env.action_space.n))`. `defaultdict` — словник, який для ключа, якого ще немає, сам
створює значення; тут це масив із двох нулів, по одному на дію. Стан, якого агент іще не бачив, одразу має цінності
«нуль і нуль». Для алгоритму це зручно, але таблиця після цього не відрізняє стан, оцінений у нуль, від стану, якого
ніхто не відвідував. У практиці дня поруч зі словником оцінок лежить словник лічильників саме для того, щоб цю різницю
було видно.

Одне застереження наперед. Підручник оцінює стан як найбільшу з цінностей двох його дій. Такі числа описують політику,
яку агент знайшов сам, а не політику плану, тому порівнювати його малюнки із сьогоднішньою таблицею не можна: у вас
суми до 19 мають цінність близько `−0,6`, бо політика плану на них бере карту, а навчений агент на 19 зупиняється.

## Що взяти собі

- Метод Монте-Карло оцінює цінність прямо з означення: середнє повернень після відвідувань стану. Йому потрібні лише
  епізоди, зіграні до кінця.
- Перше відвідування дає з епізоду одне незалежне число на стан; кожне відвідування дає більше чисел, але залежних.
  Обидва збігаються; формулі похибки можна вірити лише в першому.
- Оцінка незміщена, і її похибка падає як `1/√n` від кількості відвідувань саме цього стану, а не від загальної
  кількості епізодів. У блекджеку після п'ятисот тисяч епізодів найрідкісніший стан із придатним тузом має 190
  відвідувань і помилку `0,17`.
- Без моделі оцінюють `q`, а не `v`: жадібну політику з `q` видно без таблиці переходів.
- Щоб оцінити всі дії, їх треба робити. Дослідницькі старти годяться для симулятора; для справжньої взаємодії
  лишається ε-м'яка політика, і тоді знайдена політика найкраща лише серед ε-м'яких.
- У формулах на сервері бракує `γ`: рядок рамки — це `G ← γG + R_{t+1}`.
- Код Моралеса не запускається в нинішніх версіях без правок, і крок оновлення в ньому не `1/N`, а розклад, що спадає
  до `0,01`.
- `gym.make("Blackjack-v1")` створює середовище з `sab=True`, хоча сторінка документації показує `sab=False`.

## Запитання до читання

**1. На сервері в рамці алгоритму стоїть рядок `G  G + Rt+1`. Що там було в книжці і що цей рядок робить?**

<details><summary>Відповідь</summary>

`G ← γG + R_{t+1}`. Зі тексту зникли стрілка присвоєння й літера `γ`. Рядок стоїть у циклі, що йде з кінця епізоду:
повернення від кроку `t` дорівнює винагороді після нього плюс знецінене повернення від наступного кроку.

</details>

**2. Чому Sutton і Barto кажуть, що збіжність методу «перше відвідування» побачити легко, а з кожним відвідуванням
складніше?**

<details><summary>Відповідь</summary>

За першого відвідування кожен епізод дає стану одне повернення, а епізоди незалежні. Тому повернення незалежні й
однаково розподілені, і закон великих чисел застосовний прямо. За кожного відвідування кілька повернень походять з
одного епізоду й залежать одне від одного, тож просте міркування не годиться, хоча збіжність є.

</details>

**3. У прикладі 5.1 автори пишуть, що оцінки для станів із придатним тузом менш певні. Якими числами це підтверджує
перерахунок?**

<details><summary>Відповідь</summary>

Після десяти тисяч епізодів стани без придатного туза мають від 77 до 616 відвідувань, і половина з них оцінена з
помилкою до `0,045`. Стани з придатним тузом мають від 2 до 82 відвідувань, половина помиляється більше ніж на
`0,165`, а найгірша оцінка — на `1,23`. Причина одна: придатний туз трапляється рідко, а похибка оцінки залежить від
кількості відвідувань саме цього стану.

</details>

**4. Чому в блекджеку методи «перше відвідування» і «кожне відвідування» дають однакові оцінки?**

<details><summary>Відповідь</summary>

Стан не може повторитися в межах епізоду. Сума гравця з кожною картою росте; виняток — мить, коли туз перестає бути
придатним, але тоді змінюється третє число спостереження. Тому кожен стан відвідано щонайбільше раз, і перше
відвідування — єдине.

</details>

**5. Чому без моделі середовища оцінюють цінності дій, а не цінності станів?**

<details><summary>Відповідь</summary>

Щоб вибрати дію за цінностями станів, треба подивитися на крок уперед: знати, у які стани веде кожна дія і з якими
ймовірностями. Це модель. Цінність дії вже містить відповідь: жадібна політика бере дію з найбільшим `q(s, a)`, і
нічого більше знати не треба.

</details>

**6. Що втрачає алгоритм, коли дослідницькі старти замінено ε-жадібною політикою?**

<details><summary>Відповідь</summary>

Він знаходить найкращу політику лише серед ε-м'яких, тобто таких, що кожну дію роблять з імовірністю не менше `ε`,
поділеного на кількість дій. На торговій хвилині з `ε = 0,1` це `Q(free, взяти) = 0,0481` замість `0,05`. Натомість
епізоди не треба починати з довільної пари зі стану й дії, чого на ринку зробити не можна.

</details>

**7. Чим оновлення в коді Моралеса відрізняється від оновлення в рамці Sutton і Barto і до чого це призводить?**

<details><summary>Відповідь</summary>

У рамці оцінка — середнє всіх повернень стану, тобто крок дорівнює `1/N(s)`. У Моралеса крок береться з розкладу за
номером епізоду: спадає від `0,5` до `0,01` і далі не зменшується. Оцінка тоді не є середнім: останні повернення
важать більше, і вона не заспокоюється до кінця. На випадковому блуканні зі сталим кроком `0,01` розкид оцінки після
п'ятисот епізодів удвічі більший, ніж у середнього.

</details>

**8. Сторінка `Blackjack` показує виклик із `sab=False`, а `gym.make("Blackjack-v1")` створює середовище з `sab=True`.
Як це перевірити і на що це впливає?**

<details><summary>Відповідь</summary>

Перевірити можна рядком `gym.make("Blackjack-v1").spec.kwargs`: він показує `{'sab': True, 'natural': False}`. Впливає
це лише на руку natural, 21 з перших двох карт: із `sab=True` гравець із нею виграє, якщо дилер не має natural, навіть
коли дилер добрав до 21; із `sab=False` у такому разі нічия.

</details>
