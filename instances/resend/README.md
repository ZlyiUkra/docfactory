# resend — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Resend — API надсилання листів для розробників — і його SDK для
Node.js, пакет npm `resend` (сайт resend.com/docs, репозиторій resend/resend-node, реєстр npm). Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

Resend — сервіс, через який застосунок надсилає листи: `resend.emails.send()` з полями `from`, `to`, `subject`,
`html` чи `react`, пакетне й відкладене надсилання, ключі ідемпотентності, вкладення, домени з записами SPF, DKIM і
DMARC, вебхуки з подіями доставки, контакти й розсилки. У плані Next.js (фулстек-родина) Resend стоїть у «знати, що
існує» разом із React Email.

Примірник — перший у родині Resend, поруч із `react-email`. Сервіс і SDK тут разом, бо сайт описує їх разом: довідник
API показує кожен виклик через SDK для Node.js, а README пакета короткий.

Разом 559 документів, з них неповторних 556, фрагментів в індексі 3045 (`expected_passages` у `checks.json`). README з
npm лише 15: однаковий текст сусідніх версій записується один раз. Замір `quality`: по словах 7 із 10, за змістом 7,
разом 7, «як модель» 10 із 10. Один запит «як модель» переписано назвами документації: про типи подій вебхуків модель
шукає назвами подій (`email.delivered`, `email.bounced`), і тоді влучає в сторінку Event Types.

Чому сайт береться з самого сайту. Репозиторію документації Resend не публікує; сайт зібрано на Mintlify, і кожна
сторінка з карти сайту має markdown-двійник за тією ж адресою з `.md`. Його читає `sitemap-mintlify`: знімає банер
«Documentation Index», розгортає компоненти, поля запиту й відповіді. Сторінка ендпойнта повторює той самий виклик
одинадцятьма мовами, і поле `drop_code` цього джерела відкидає вісім із них (PHP, Python, Ruby, Go, Rust, Java, .NET,
Elixir) — лишаються Node.js, cURL, CLI і відповіді. Кількох прикладів PHP на сторінках дашборду це не стосується: там
блок без заголовка мови.

Чого немає. React Email (окремий примірник родини), Next.js, Node.js, Nodemailer і поштових сервісів як окремих
проєктів, SDK інших мов, коду й тестів resend-node. Пререлізи SDK (`-canary`) не беруться.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df resend <крок>`.

## Версії

Сторінки сайту версії не мають: API — один живий сервіс. Версію несуть README, реєстр і релізи пакета `resend`
(`6.34.1`); фільтр `version` бере мажор (`"6"`), мінор (`"6.34"`) або точну версію (`"4.8.0"`). За завантаженнями npm за
тиждень до 25.10.2026 лінія 6 тримає 81 %, лінія 4 — 15 %, тож промпт відповідає для 6.x, а для старшої лінії каже,
що змінилося.

## Родина Resend: піднімати разом

Цей примірник — частина родини Resend: сам сервіс надсилання з його SDK для Node.js і React Email, яким верстають
листи. Типовий шлях листа проходить обидва: шаблон на React Email, `render()` чи проп `react`, далі
`resend.emails.send()`. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує обидва
сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `resend` | `resend-docs` | 8896 | API Resend, дашборд, вебхуки, домени й доставлюваність, SDK `resend` для Node.js 0.1–6.34 |
| `react-email` | `react-email-docs` | 8897 | React Email 2.1–6.11: компоненти, `render()`, CLI і перегляд, інтеграції з поштовими сервісами |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
розділі «Родини примірників» кореневого [README](../../README.md).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/resend-corpus-2026-10-25.tar.gz` (559 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\resend-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/resend/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/resend-corpus-РРРР-ММ-ДД.tar.gz -C instances/resend corpus raw
find instances/resend/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/resend/raw
gzip -9 -c instances/resend/index/passages.json > instances/resend/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/resend-corpus-2026-10-25.tar.gz -C instances/resend
./df resend smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/resend/index/passages.json.gz`, далі
`./df resend vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df resend …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df resend sources --why   # перелік джерел і білий список
./df resend refresh         # завантажити все задеклароване (близько 6 хвилин)
./df resend manifest        # оновити паспорт
./df resend setup           # Qdrant чи пошук лише по словах
./df resend vectors         # залити корпус у docs-resend
./df resend smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df resend serve          # порт 8896
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8896/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user resend-docs http://127.0.0.1:8896/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `resend-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
