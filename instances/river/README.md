# river — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про River (github.com/riverqueue/river) — чергу задач для Go на
PostgreSQL: задачі й обробники, вставка в тій самій транзакції, що й дані (`InsertTx`), повтори, унікальні,
заплановані й періодичні задачі, черги, чемна зупинка, міграції, тестування й River UI. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

У плані Go ([../go/LEARNING.md](../go/LEARNING.md), фаза 6, день 6) вебхук після публікації запису ставиться в чергу
River тією самою транзакцією, що й публікація: або обидва, або нічого — те, чого не дає черга в Redis (BullMQ у плані
NestJS). Документація River — сайт riverqueue.com/docs, сирців якого у відкритому доступі немає, README з
`docs/` у репозиторії, журнал змін і API на pkg.go.dev.

Чого немає:

- Сторінок клієнтів інших мов (Java, Python, Ruby, TypeScript) і самих цих клієнтів.
- Довідника pkg.go.dev раніше 0.31 (мінорних 0.x понад п'ятдесят) — зміни раніших видно в журналі.
- Окремих модулів драйверів (`riverpgxv5`, `riverdatabasesql`), `rivertype`, River UI як проєкту.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df river <крок>`.

## Версії

README, журнал і довідник несуть версію River (`0.50.0`); сайт — поточна редакція без версії. Фільтр `version`
приймає мінор (`"0.50"`) або точну версію і лишає сайт поза видачею. Промпт відповідає для 0.50.0 і прямо каже, коли
можливість належить платній River Pro.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/river-corpus-2026-10-27.tar.gz` (201 текст, паспорт і сховище сирого
`raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\river-corpus-2026-10-27.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/river/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/river-corpus-РРРР-ММ-ДД.tar.gz -C instances/river corpus raw
find instances/river/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/river/raw
gzip -9 -c instances/river/index/passages.json > instances/river/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/river-corpus-2026-10-27.tar.gz -C instances/river
./df river smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/river/index/passages.json.gz`.
Далі `./df river vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df river …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df river sources --why   # перелік джерел і білий список
./df river refresh         # завантажити все задеклароване (близько десяти хвилин)
./df river manifest        # оновити паспорт
./df river setup           # Qdrant чи пошук лише по словах
./df river vectors         # залити корпус у docs-river
./df river smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df river serve          # порт 8924
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8924/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user river-docs http://127.0.0.1:8924/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `river-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
