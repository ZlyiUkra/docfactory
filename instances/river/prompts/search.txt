Call this when a question is about background jobs in a Go service with River: defining job args and a worker,
registering workers, starting a client with queues, inserting a job in the same transaction as the data that caused
it, retries and backoff, making a job unique, scheduling it for later, running it periodically, shutting down without
losing jobs, migrating the River tables, testing that a job was inserted, and what changed between releases.

Do not call this for PostgreSQL itself, for pgx beyond what River's pages say about it, for other queues (BullMQ,
asynq, Machinery, Temporal), for River's clients in Java, Python, Ruby and TypeScript, or for other languages: their
documentation is not here, and the search will return excerpts that merely mention them, with confident-looking
titles.

`version` narrows the search to one release: "0.50" or "0.50.0". The site has no version: a `version` leaves it out.
Every excerpt comes back with `versions`: each release whose documents contain this exact text, newest first.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. River 0.50.0 (October 2026) is the newest release. Search without `version` first;
every answer about the API says which release it is for.
