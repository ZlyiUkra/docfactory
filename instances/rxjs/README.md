# rxjs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про RxJS — бібліотеку для складання асинхронних програм і подій з
послідовностей Observable: значення приходять у часі, а оператори (`map`, `switchMap`, `debounceTime`…) перетворюють і
поєднують потоки. Документація — всіх стабільних версій пакета rxjs (5.0–7.8: 70 версій у 22 мінорних лініях).
Джерела — офіційні сайти rxjs.dev і v6.rxjs.dev, README і журнал змін, документація з тегів репозиторію
ReactiveX/rxjs, його код і тести та реєстр npm, лише англійською й лише стабільні версії. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

RxJS мовчки лежить під багатьма іншими бібліотеками: Observable повертають і приймають, наприклад, перехоплювачі
NestJS та HTTP-клієнт Angular, але документація цих бібліотек не пояснює, що таке `switchMap` і чим він відрізняється
від `mergeMap`. Це лежить у документації RxJS і в його коді. До того ж бібліотека за десять років змінила форму: 5.5
додав оператори-функції для `pipe`, 6.0 (24.04.2018) змінив спосіб імпорту й випустив `rxjs-compat` для поступового
переходу, а в лінії 7 (7.0 — 29.04.2021) застарілими стали аргументи `resultSelector` і метод `toPromise()`; з 7.2
оператори імпортуються з кореня `rxjs`, а `rxjs/operators` стало застарілим. Код, що працює на 5 чи 6, ламається чи
лякає застарілими викликами на 7, тож відповідь мусить знати версію.

**Що є що.** **Observable** — «ліниве» джерело кількох значень у часі: нічого не відбувається, доки хтось не
підпишеться. **Observer** — об'єкт із трьома функціями (`next`, `error`, `complete`), що слухає Observable.
**Subscription** — запущене виконання, яке можна скасувати. **Subject** — одночасно Observable і Observer: єдиний
спосіб розіслати одне значення багатьом підписникам (`BehaviorSubject` пам'ятає останнє значення, `ReplaySubject` —
кілька). **Оператор** — функція, що перетворює один Observable на інший (`map`, `filter`, `mergeMap`). **Планувальник**
(scheduler) — вирішує, коли й де виконується робота: одразу, в мікрозадачі чи на кадр анімації. **Marble testing** —
тести потоків, де час і значення креслять символами, замість чекати по-справжньому.

Разом 5196 документів; фрагментів в індексі — 23 924 (`expected_passages` у `checks.json`). Фрагменти — це шматки
документів між заголовками, по яких іде пошук. Документ — неповторна редакція файла, і в рядку `# версія:` стоять
усі версії, де він був саме таким; однаковий текст різних версій лягає одним фрагментом з усіма цими версіями. 86 %
фрагментів — код і тести.

Замір `quality`: перша десятка (питання своїми словами, без версії) — по словах 1 із 10, за змістом 5, разом 4; друга,
«як модель» (назви RxJS, як велить промпт, з `version`), — 10 із 10. Чотири запити «як модель» після першого заміру
переписано назвами документації («rxjs-compat update guide v5 to v6», «importing instructions operators exported from
rxjs v7.2», «retry resubscribe on error», «resultSelector arguments deprecated», для останнього додано й `version`
7.8): у першій редакції вони складалися з голих назв функцій і поверталися до коду та тестів (`rxjs-code-spec-…`), які
повторюють ті самі назви. Так запит і писатиме модель за промптом; цілі не змінювалися. Шість запитів першої десятки
зливання не знаходить: про `switchMap`, про пізніх підписників `BehaviorSubject`, про перехід зі стилю прототипу на
`pipe` (його знаходить пошук за змістом, але злиття губить), про шлях імпорту операторів, про випуск, що прибрав
аргумент `resultSelector`, і про залежність лінії 7 від допоміжної бібліотеки: слів питання в відповідних сторінках
немає, а назви функцій стоять у сотнях фрагментів коду й тестів. `max_per_doc` не заміряно: «як модель» дав 10 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується (7 джерел), і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, `slug_rewrite` і `families`
  (сторінки сайтів і теги — одна родина) та профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df rxjs <крок>`.

Особливості корпусу:

- **Сайти — односторінкові застосунки Angular.** HTML, який віддає rxjs.dev, — порожня оболонка на вісім кілобайтів, а
  мапи сайту немає. Текст кожної сторінки лежить готовим JSON (`id`, `title`, `contents` — HTML статті), перелік —
  це бічне меню плюс список довідника API. Для цього додано читача `aio-json` (`../../engine/readers/aiojson.py`): він
  переписує власний елемент `<code-example>` у блок коду, знімає кнопки «правити», якорі заголовків і зміст сторінки, а
  заголовки «Parameters», «Returns», «Throws» робить підписами всередині розділу (`inline_titles`), щоб кожне
  перевантаження оператора лишалося одним фрагментом з сигнатурою. Сторінки `team`, `operator-decision-tree` і
  `api` (список, який малює браузер) не беруться: у JSON від них лишається лише оболонка.
- **Сайт — один знімок на лінію.** rxjs.dev записано під 7.8.2, v6.rxjs.dev — під 6.6.7 (версії з `__versionInfo`
  сайту); старіших редакцій сторінок сайт не має, зате документація з тегів (`doc/`, `docs_app/content`) і код є для
  кожної версії. Живого сайту 5.x немає (reactivex.io/rxjs/ віддає 404): для 5.x є README, `doc/`, журнал і код.
- **Одна сторінка — одна родина.** Сторінка сайту й той самий файл з тегу (`docs_app/content/guide/observable.md`)
  дають одне ім'я після `slug_rewrite`, а `families` зводить їх в одне місце видачі. `doc/` (5.x — 6.5) має інші
  імена, ніж `docs_app/content` (`rxjs-doc-observable` проти `guide-observable`), і з ними не зводиться: у тегах
  6.3–6.5 обидві теки лежать поруч.
- **У двох тегах `docs_app/content` — документація самого Angular.** У 6.2.1 і 6.2.2 там лежить сотня сторінок Angular
  (архітектура, форми, впровадження залежностей); до RxJS вони не мають стосунку, тож `exclude` у `rxjs-gh-docs`
  пропускає лише відомі сторінки RxJS.
- **Журнал змін неповний.** `CHANGELOG.md` не має записів про 5.5.7–5.5.12, 6.5.4, 6.5.5, 6.6.0–6.6.4, 6.6.6 і 6.6.7 —
  їх лише реєстр npm і код. Записи про передрелізи (`7.0.0-beta.*` тощо) не беруться.
- **Код і тести поділено на розділи** за оголошеннями й викликами `describe`/`it`: назва тесту стає назвою розділу, тож
  перелік тестів читається як перелік поведінок. Код 5.x лежить у `src/operator/` і `src/observable/`; з 6.0 основа
  переїхала в `src/internal/`.
- **Вимоги до Node і TypeScript** записані в документах реєстру npm (`engines`, `peerDependencies`).
- **Документ — неповторний текст.** Версії, де файл не змінився, ділять один документ; у рядку `# версія:` стоять усі.

## Межі, про які треба пам'ятати

Документації Angular, NgRx, redux-observable, `rxjs-compat`, `rxjs-tslint`, `eslint-plugin-rxjs`, RxJS 8 і 9 (є лише
передрелізи), інших мов ReactiveX (RxJava та ін.) і пропозиції Observable в TC39 тут немає. Типи `@types/*` не входять.
Код — лише на тегах: коміти гілки master після 7.8.2 без тегу в корпус не потрапляють (master зараз веде 9.0).
Інтерактивне «дерево вибору оператора» (`operator-decision-tree`) на сайті — застосунок, у корпусі його немає.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/rxjs-corpus-2026-10-20.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде. Архів
лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/rxjs/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/rxjs-corpus-РРРР-ММ-ДД.tar.gz -C instances/rxjs corpus raw
find instances/rxjs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/rxjs/raw
gzip -9 -c instances/rxjs/index/passages.json > instances/rxjs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/rxjs-corpus-2026-10-20.tar.gz -C instances/rxjs
./df rxjs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/rxjs/index/passages.json.gz`, далі
`./df rxjs vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df rxjs …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/rxjs/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df rxjs sources --why   # перелік джерел і білий список
./df rxjs refresh         # завантажити все задеклароване (сайти — близько 8 хвилин; код і документи з тегів швидше
                          # брати з клону: tools/seed_git_store.py, потім ./df rxjs build)
./df rxjs manifest        # оновити паспорт
./df rxjs setup           # Qdrant чи пошук лише по словах
./df rxjs vectors         # залити корпус у docs-rxjs
./df rxjs smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df rxjs serve          # порт 8872
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8872/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user rxjs-docs http://127.0.0.1:8872/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `rxjs-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
