# Оновлення корпусу rxjs

Перелік версій npm тут не оголошується руками: читачі `rxjs-readme` і `rxjs-npm` беруться за описом пакета в реєстрі
(`https://registry.npmjs.org/rxjs`), тож нова версія потрапляє в README й реєстр сама, коли вийде в npm. Передрелізи
(`-alpha`, `-beta`, `-rc`; зараз `next` → 9.0.0-beta.1) не беруться: у `rxjs-readme` і `rxjs-npm` стоїть
`skip_versions: "-"`.

Руками оголошено лише:

- **Теги репозиторію** — поле `tags` джерел `rxjs-gh-docs` і `rxjs-code`. Новий стабільний тег дописують першим рядком у
  обидва, у вигляді `"7.9.0": "7.9.0"` (теги ReactiveX/rxjs без префікса `v`). Версії без тегу в git на 20.10.2026
  немає; а тег 6.6.5, який у git є, у npm не публікувався, тому його не оголошено.
- **Журнал змін** — `rxjs-changelog` читає `CHANGELOG.md` з тегу 7.8.2: гілка master стала монорепозиторієм без цього
  файла. Коли вийде новіша стабільна версія, у джерелі міняють тег у `url`, `cite` і `within` на найновіший — журнал у
  тезі кожного випуску містить усю історію. Якщо новий випуск журнал не веде, лишають 7.8.2.
- **Знімки сайтів** — `rxjs-site` (rxjs.dev) записано під 7.8.2, `rxjs-site-6` (v6.rxjs.dev) — під 6.6.7; номер
  береться з `__versionInfo.raw` у `https://<сайт>/generated/navigation.json`. Коли rxjs.dev перейде на нову версію,
  читач `aio-json` сам перепише сторінки на `refresh`, а поле `version` джерела міняють руками на нове `raw`. Якщо
  старий знімок хочеться зберегти поруч (як `rxjs-site-6` біля `rxjs-site`), старе джерело залишають під його версією,
  а новому дають новий `id` й дописують його в родину `rxjs-docs` у `config.json` (кроки — у [UPDATE.md
  кореня](../../UPDATE.md), «Нове джерело-версія сайту»).

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df rxjs check                 # чи змінилося щось нагорі за джерелом
./df rxjs refresh               # повне перезавантаження: сайти — близько 8 хвилин, теги — див. нижче
./df rxjs manifest
./df rxjs vectors
./df rxjs smoke
# Ctrl+C у терміналі з serve, і знову: ./df rxjs serve
```

`refresh` повний, не `--missing`: у документі стоять усі версії, де текст був таким, тож нова версія змінює й старі
документи (README, що не змінився, дописує нову версію в рядок `# версія:`).

**Код і документи з тегів швидше брати з клону**, а не мережею по одному файлу (4 тисячі файлів):

```
git clone --bare --filter=blob:none https://github.com/ReactiveX/rxjs.git <шлях>/rxjs.git
.venvs/gpu/bin/python tools/seed_git_store.py --instance rxjs --clone ReactiveX/rxjs=<шлях>/rxjs.git
./df rxjs list                          # дерева тегів через API
./df rxjs build rxjs-gh-docs rxjs-code  # тексти зі сховища, без мережі, секунди
```

Якщо вийшла нова лінія RxJS (7.9, 8.0):

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` переглянути лінію за
  замовчуванням: вона — найпоширеніша за завантаженнями npm (на 20.10.2026 — 7.8, 81 %; друга — 6.6, 14 %), і де дві
  лінії близькі, відповідь дається для обох;
- у `checks.json`, у десятці `quality_model`, замінити `"7.8"` там, де питання про поточну поведінку, і звірити цілі;
- у `config.json` лінії версій складаються з двох чисел (`version_line_depth: 2`); для 8.x це лишається чинним.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) потрібен для дерев тегів (близько двохсот звернень) і журналу змін: без нього
вистачає годинного вікна в 60 звернень лише впритул.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df rxjs quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
