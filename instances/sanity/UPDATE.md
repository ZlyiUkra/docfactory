# Оновлення корпусу sanity

Сайт www.sanity.io/docs, довідник API reference.sanity.io, README дев'яти пакетів, реєстр npm і релізи семи
репозиторіїв беруться щоразу заново: закріплених комітів тут немає, і `refresh` сам бачить нові сторінки й версії.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df sanity check                 # чи змінилося щось нагорі за джерелом
./df sanity refresh               # повне перезавантаження, близько 80 хвилин
./df sanity manifest
./df sanity vectors
./df sanity smoke
# Ctrl+C у терміналі з serve, і знову: ./df sanity serve
```

`refresh` повний, не `--missing`: сайт і довідник правлять на місці, і стара сторінка лишилася б старою. Довгий прогін
запускають відокремлено (`setsid nohup … &`), щоб він пережив обрив сесії.

Якщо `sanity-readme` чи інше джерело README пише «без README N версій» з новими версіями — пакет міг переїхати в
інший репозиторій або змінити ім'я тегу; шаблон нової адреси дописують у поле `files` джерела (так додано
`@sanity/cli@{version}` і `@sanity/visual-editing@{version}`). Якщо опис ще одного пакета в реєстрі переріс 50 МБ
(«збій: більше за 50000000 байтів»), — його джерелам `npm-readme` і `npm-versions` дописують `"gzip": true`.

Якщо змінилося співвідношення завантажень ліній (на 25.10.2026 `sanity` 6 — 52 %, 5 — 24 %), — у `prompts/search.txt`
(абзац «Which version to search first») і `prompts/agent.txt` замінити лінії й числа.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df sanity quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього». Якщо сторінки типів схеми знову тонуть під довідником
API — перший важіль `fusion_depth` у `config.json` (зараз 20).
