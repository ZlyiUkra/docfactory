# scipy — примірник фабрики docfactory

Цей примірник зібрав документацію SciPy і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. SciPy — це бібліотека Python для наукових обчислень поверх NumPy. NumPy дає масиви й прості операції з ними, а SciPy
додає готові методи: статистичні розподіли й тести, пошук мінімуму функції, фільтри сигналів, інтерполяцію, інтегрування.

Для торгового бота тут найважливіші такі речі:

- статистика прибутковості (`scipy.stats`). Функції `skew`, `kurtosis` і `describe` описують розподіл прибутків числами.
  Тести `jarque_bera`, `shapiro`, `normaltest` і `kstest` перевіряють, чи схожий розподіл на нормальний; на ринку він зазвичай
  має «важкі хвости», тобто великі рухи трапляються частіше, ніж обіцяє нормальний розподіл. Розподіл Стьюдента `t` з методом
  `fit` описує такі хвости;
- кореляції й порівняння: `pearsonr`, `spearmanr` і `kendalltau` міряють зв'язок двох рядів, `ttest_ind` порівнює середні двох
  вибірок;
- оптимізація параметрів (`scipy.optimize`). `minimize` шукає мінімум функції з обмеженнями (наприклад, ваги портфеля, що в сумі
  дають одиницю), `differential_evolution` шукає глобальний мінімум без похідних, `curve_fit` і `least_squares` підганяють
  криву під точки, `brentq` знаходить корінь рівняння;
- обробка сигналів (`scipy.signal`): `savgol_filter` згладжує ряд поліномом, `butter` і `filtfilt` фільтрують без зсуву в часі,
  `find_peaks` знаходить локальні вершини.

## Скільки цього

Усього 48 946 документів і 71 285 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат.
Сторінка з однаковим текстом у кількох лініях лежить одним документом із переліком цих ліній. Сторінка, що змінювалася, лежить
кількома документами, по одному на кожен варіант тексту.

| Що | Версії | Документів |
|---|---|---|
| увесь сайт docs.scipy.org: посібник користувача, довідник API зі сторінкою кожної функції й класу, нотатки випусків | останній патч кожної мінорної лінії 0.7–1.18, 32 лінії | 48 866 |
| нотатки релізів GitHub | усі сталі релізи, які GitHub публікує | 64 |
| записи PyPI | усі сталі версії та опис пакета | 16 |

Мітка версії має вигляд `scipy-1.18`. Префікс потрібен, щоб версії SciPy не збігалися з версіями інших бібліотек, коли сервери
працюють разом.

**Де є прогалини, хоч ми й брали всі лінії.**

- 298 сторінок атрибутів (`scipy.stats.Binomial.n`, `scipy.sparse.dia_array.ndim`) не взято: у них менше 20 символів тексту.
- Самого NumPy тут немає. Він має окремий примірник `numpy` (порт 8956).

Замір `quality` на 14.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 4 із 10: довідник API великий, і запит без назви функції часто знаходить сусідню
функцію чи сторінку посібника.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, правило злиття сторінок довідника.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df scipy <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт кожної лінії | архів `scipy-html-<версія>.zip` на `static.scipy.org` | `sphinx-zip` |
| нотатки релізів | релізи GitHub `scipy/scipy` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/scipy/json` | `pypi-versions` |

**Чому архіви, а не обхід сайту.** docs.scipy.org публікує для кожної версії увесь сайт одним архівом HTML. Обхід сайту — тисячі
звернень на версію, а архів — одне. Сторінка docs.scipy.org переадресовує архів на static.scipy.org, тож у білому списку стоїть
саме він. Адреса для людей у шапці документа — сторінка docs.scipy.org тієї версії. Архіви важать до 77 МБ, тому стелю однієї
відповіді `MAX_BYTES` у `engine/net.py` 14.11.2026 піднято з 50 до 100 МБ.

**Правило злиття сторінок.** Довідник API старих ліній лежить у теці `generated/`, а нових — у `reference/generated/`. Поле
`slug_rewrite` у `config.json` дає обом спільний ключ, і та сама функція різних ліній займає у видачі одне місце.

Завантаження всього примірника зайняло близько 20 хвилин, з них архіви — 1,2 ГБ.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df scipy serve
```

Порт — `8987`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user scipy-docs http://127.0.0.1:8987/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `scipy-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/scipy-corpus-2026-11-14.tar.gz` (48 946 текстів, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\scipy-corpus-2026-11-14.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/scipy/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/scipy-corpus-РРРР-ММ-ДД.tar.gz -C instances/scipy corpus raw
find instances/scipy/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/scipy/raw
gzip -9 -c instances/scipy/index/passages.json > instances/scipy/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/scipy-corpus-2026-11-14.tar.gz -C instances/scipy
./df scipy smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
