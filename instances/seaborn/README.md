# seaborn — примірник фабрики docfactory

Цей примірник зібрав документацію seaborn і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. seaborn — це бібліотека Python, яка малює статистичні графіки поверх matplotlib. Вона бере таблицю pandas, сама
рахує те, що треба показати (розподіл, середнє з довірчим інтервалом, лінію регресії), і малює це однією функцією. Самі
графіки — звичайні фігури matplotlib, тож їх можна доналаштувати засобами matplotlib.

Для торгового бота тут найважливіші такі речі:

- розподіл прибутковості. Функції `histplot` і `kdeplot` показують, як часто трапляються прибутки й збитки певного розміру:
  перша — стовпчиками гістограми, друга — гладкою кривою густини. `displot` робить те саме з окремими панелями для кожної групи;
- кореляції між валютними парами. Функція `heatmap` малює матрицю кольоровими клітинками, а параметр `annot=True` пише в
  кожну клітинку її число; `clustermap` ще й групує схожі рядки;
- порівняння груп: `boxplot` і `violinplot` показують розкид значень, наприклад прибутку угод за стратегіями чи сесіями;
- багато малих графіків: `FacetGrid`, `relplot` і `pairplot` малюють сітку графіків, по одному на кожну категорію чи пару
  стовпчиків;
- оформлення: `set_theme` і `color_palette` задають стиль і кольори для всіх графіків одразу.

## Скільки цього

Усього 837 документів і 1998 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Сторінка з
однаковим текстом у кількох версіях лежить одним документом із переліком цих версій. Сторінка, що змінювалася, лежить кількома
документами, по одному на кожен варіант тексту.

| Що | Версії | Документів |
|---|---|---|
| сайт seaborn.pydata.org: вступ, підручник, довідник API зі сторінкою кожної функції й класу, галерея прикладів, «Що нового» кожної версії від 0.2 | 0.13, поточна версія в корені сайту | 247 |
| той самий сайт з теки `archive/` | 0.12, 0.11, 0.10 і 0.9 | 550 |
| нотатки релізів GitHub | усі релізи, які GitHub публікує | 25 |
| записи PyPI | усі сталі версії 0.1–0.13.2 та опис пакета | 15 |

Мітка версії має вигляд `seaborn-0.13`. Префікс потрібен, щоб версії seaborn не збігалися з версіями інших бібліотек, коли сервери
працюють разом.

**Де є прогалини, хоч ми й брали всі версії.**

- Сайт зберігає в архіві лише лінії 0.9–0.12. Про старші версії 0.2–0.8 є сторінки «Що нового», релізи й записи PyPI.
- Сторінка довідника API не має підзаголовків, тож опис функції лежить одним розділом, поділеним на кілька фрагментів.
- Самого matplotlib тут немає. Він має окремий примірник `matplotlib` (порт 8981).

Замір `quality` на 14.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 9 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, родина джерел сайту.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df seaborn <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт поточної версії | `seaborn.pydata.org/` | `sphinx-html` |
| сайт старих версій | `seaborn.pydata.org/archive/<лінія>/` | `sphinx-html` |
| нотатки релізів | релізи GitHub `mwaskom/seaborn` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/seaborn/json` | `pypi-versions` |

**Чому сайт — два джерела.** Поточна версія лежить у корені сайту, а теки старих версій — усередині нього, у `archive/`. Обхід
кореня зайшов би й в архів, тому джерело `seaborn-docs` виключає адреси `archive/` полем `exclude`, а архів обходить окреме джерело
`seaborn-archive`. Поле `families` у `config.json` зводить обидва джерела в одну родину: та сама сторінка різних версій займає у
видачі одне місце.

**Поля читача для цього сайту.**

- `param_types: true`: між назвою параметра й типом у довіднику стоїть « : » («annot : bool or rectangular dataset»), і пошук
  за назвою параметра знаходить сторінку.
- `min_chars: 25`: сторінка методу (`FacetGrid.set`, `objects.Mark`) часто має один рядок опису, коротший за звичну межу в 120
  символів, і без поля такі сторінки не потрапили б у корпус.

Завантаження всього примірника зайняло 9 хвилин.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df seaborn serve
```

Порт — `8982`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user seaborn-docs http://127.0.0.1:8982/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `seaborn-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/seaborn-corpus-2026-11-14.tar.gz` (837 текстів, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\seaborn-corpus-2026-11-14.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/seaborn/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/seaborn-corpus-РРРР-ММ-ДД.tar.gz -C instances/seaborn corpus raw
find instances/seaborn/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/seaborn/raw
gzip -9 -c instances/seaborn/index/passages.json > instances/seaborn/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/seaborn-corpus-2026-11-14.tar.gz -C instances/seaborn
./df seaborn smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
