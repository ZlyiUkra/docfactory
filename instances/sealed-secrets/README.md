# sealed-secrets — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Sealed Secrets: контролер Kubernetes і утиліту `kubeseal` від
Bitnami (репозиторій bitnami/sealed-secrets, раніше bitnami-labs/sealed-secrets). Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

Звичайний `Secret` Kubernetes лише закодований base64, тож класти його в Git не можна. Sealed Secrets розв'язує це
асиметричним шифруванням. `kubeseal` шифрує `Secret` відкритим ключем контролера в ресурс `SealedSecret`, і такий
ресурс можна комітити. Розшифрувати його може лише контролер у кластері, бо закритий ключ є тільки в нього. З
`SealedSecret` контролер створює звичайний `Secret`. Тому Sealed Secrets і ставлять поруч із GitOps-контролерами
(примірники `argocd` і `flux`). У плані Next.js (фулстек-родина) Sealed Secrets стоїть у розділі «знати, що існує»:
секрети розшифровує контролер у кластері.

Супутніх проєктів не взято. Bitnami-чарт із `bitnami/charts` — друга збірка того самого контролера, а офіційний
Helm-чарт лежить у самому репозиторії, тож він тут є. Не взято й `sealed-secrets-web` (159 зірок проти 9,3 тис. в
основного репозиторію), і pkg.go.dev (там лише API Go).

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df sealed-secrets <крок>`.

## Версії

Сторінки README, `docs/` і сайту несуть версію контролера й `kubeseal` (`0.41.2`); журнал змін і релізи — версію
запису. Номери чарта (1.x, 2.x) — окрема нумерація, тож вони записані з префіксом: `chart-2.22.0`. Фільтр `version`
приймає мажор (`"0"`), мінор (`"0.41"`) або точну версію (`"0.41.2"`). Голе число лишає лише контролер; `"chart-2"`
лишає лінію чарта. Промпт відповідає для найновіших версій (контролер 0.41.2, чарт 2.22.0), якщо користувач не назвав
старішу.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/sealed-secrets-corpus-2026-10-26.tar.gz` (314 текстів, паспорт і
сховище сирого `raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\sealed-secrets-corpus-2026-10-26.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/sealed-secrets/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/sealed-secrets-corpus-РРРР-ММ-ДД.tar.gz -C instances/sealed-secrets corpus raw
find instances/sealed-secrets/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/sealed-secrets/raw
gzip -9 -c instances/sealed-secrets/index/passages.json > instances/sealed-secrets/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/sealed-secrets-corpus-2026-10-26.tar.gz -C instances/sealed-secrets
./df sealed-secrets smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/sealed-secrets/index/passages.json.gz`.
Далі `./df sealed-secrets vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df sealed-secrets …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df sealed-secrets sources --why   # перелік джерел і білий список
./df sealed-secrets refresh         # завантажити все задеклароване (близько 3 хвилин)
./df sealed-secrets manifest        # оновити паспорт
./df sealed-secrets setup           # Qdrant чи пошук лише по словах
./df sealed-secrets vectors         # залити корпус у docs-sealed-secrets
./df sealed-secrets smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df sealed-secrets serve          # порт 8909
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8909/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user sealed-secrets-docs http://127.0.0.1:8909/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `sealed-secrets-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
