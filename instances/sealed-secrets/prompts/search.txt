Search the documentation of Sealed Secrets -- the Kubernetes controller and the `kubeseal` command-line tool from
Bitnami (repository bitnami/sealed-secrets, formerly bitnami-labs/sealed-secrets) that encrypt a Secret into a
SealedSecret safe to keep in Git, which only the controller running in the cluster can decrypt. The corpus holds the
README of the repository -- the main documentation: overview, installation (controller, `kubeseal`, Helm, Homebrew,
Kustomize), usage, scopes, the annotations, `kubeseal` flags, secret rotation and sealing key renewal, early key
renewal, user secret rotation, re-encryption, backup and disaster recovery, offline sealing, multiple controllers,
the FAQ -- and the `docs/` folder (GKE private clusters, bring your own certificates, the developer notes on the
controller, `kubeseal` and the cryptography, configuration templates), the README of the Prometheus mixin, all of
them at the last tag of every minor, 0.1 to 0.41; the pages of the site sealed-secrets.netlify.app (getting started,
installation, cryptography, validation, FAQ) at the last tag of every minor that has the site, 0.18 to 0.41; the
README of the official Helm chart (`helm/sealed-secrets`, every value of values.yaml) at the last tag of every minor
of the chart, 1.13 to 2.22 (versions written "chart-2.22.0"); the release notes (RELEASE-NOTES.md, one section per
version) and the stable GitHub releases of the controller and `kubeseal`. Returns the matching excerpts with the
versions each one belongs to.

Call this when a question is about Sealed Secrets as it describes itself -- how to install the controller and
`kubeseal`, fetch the public certificate, seal a Secret, choose a scope (strict, namespace-wide, cluster-wide), keep
labels and annotations through `spec.template`, update or merge a single value (`--merge-into`, `--raw`), rotate or
bring your own sealing keys, back up the keys and restore them, decrypt in an emergency (`--recovery-unseal`),
re-encrypt with the newest key, validate a SealedSecret, run several controllers, configure the Helm chart, read
the metrics -- and history: since which version a flag, annotation, Helm value or behaviour exists and what changed
between versions (the release notes and the releases list it).

Do not call this for Kubernetes, Helm, Kustomize, Argo CD, Flux, SOPS, External Secrets or HashiCorp Vault as their
own projects: their documentation is not here -- these pages only show how Sealed Secrets is used with them -- and
the search will return excerpts that merely mention them, with confident-looking titles. The Go source code is not
here either, nor the Bitnami-packaged chart from bitnami/charts.

`version` narrows the search to one release line: a line of one number keeps every document of that major ("0"
keeps the controller and `kubeseal` 0.x), two numbers keep a minor ("0.41"), three an exact version ("0.41.2"); the
Helm chart carries the prefix "chart-" ("chart-2" keeps the chart 2.x, "chart-2.22" one minor of it), so a bare number
keeps only the controller, `kubeseal` and the site. Pages unchanged across versions carry all of them. Every excerpt
comes back with `versions`: each version whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("SealedSecret", "kubeseal",
"--fetch-cert", "--cert", "--scope", "strict", "namespace-wide", "cluster-wide",
"sealedsecrets.bitnami.com/namespace-wide", "sealedsecrets.bitnami.com/managed", "spec.template", "--raw",
"--merge-into", "--re-encrypt", "--recovery-unseal", "--validate", "--key-renew-period", "--key-cutoff-time",
"sealing key", "bring your own certificates", "--controller-name", "--controller-namespace", "keyrenewperiod",
"secretName", "update-status"), not in the user's own words. Everything here is English -- the excerpts, the word
index and the meaning index alike -- and the word index keeps only latin letters and digits, so a query written in
Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the user
asks in another language, translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація Sealed Secrets". Identifiers, parameters and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Sealed Secrets is still 0.x and only its newest release is maintained (0.41.2 is the
newest, the chart 2.22.0): search without `version` first; when the user names their version, search that line; a
question about a Helm value is answered from the newest chart ("chart-2") unless the user names an older one. Every
answer says which version it is for.
