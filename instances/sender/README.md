# sender — примірник фабрики docfactory

Цей примірник зібрав документацію Sender.net і віддає її через сервер MCP, щоб модель відповідала за текстом документації,
а не з пам'яті. Sender.net — це сервіс email- і SMS-розсилок. Програми працюють із ним через REST API: це звичайні запити
HTTP на адресу `https://api.sender.net/v2/`.

## Навіщо окремий примірник

Перед імпортом підписників і синхронізацією треба знати дві речі. Довідка API каже, які запити існують і що вони
приймають. Центр допомоги каже, як працюють поля, групи, імпорт і перенесення з інших сервісів. Ці знання лежать на двох
різних сайтах, а ліміти запитів описано лише в центрі допомоги. Примірник шукає по всьому одразу.

## Скільки цього

Усього 1464 документи і 21 478 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окрему відповідь.

| Що | Документів |
|----|-----------|
| довідка API, api.sender.net | 74 |
| центр допомоги, sender.net/help | 339 |
| сторінки продукту sender.net | 396 |
| блог sender.net | 409 |
| галерея шаблонів листів | 109 |
| llms.txt сайту, короткий опис компанії й тарифів | 1 |
| сторінка плагіна на wordpress.org | 1 |
| знімок OpenAPI від 21.04.2021 з веб-архіву | 2 |
| пакет Node.js: README, реєстр, GUIDE, приклади, код і тести | 41 |
| пакет PHP: реєстр, README, GUIDE, код і тести | 46 |
| код модуля PrestaShop і плагіна WordPress | 46 |

Замір `quality` на 02.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, бо модель
зазвичай питає саме так. Запити своїми словами знаходять потрібне 6 із 10: пошук по словах дає 2, пошук за змістом дає 6.

Причина нижчого числа така. Блог і сторінки продукту складають дві третини документів і говорять звичайною мовою, тож на
запит без термінів вони часто випереджають довідку API. Наприклад, «mailing list» трапляється в блозі 32 рази, а в довідці
API жодного разу, бо там це називається `groups`. Тому модель має шукати назвами кінцевих точок і полів, і так сказано в її
промпті. Блог лишився в корпусі, бо примірник навмисно зібрано якнайширшим.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df sender <крок>`.

**Новий читач `sitemap-starlight`.** Обидва сайти Sender.net зібрано на Astro Starlight, і спільний розбір псував на них
три речі. Рядки прикладів коду злипалися, бо сайт кладе кожен рядок в окремий блок. Адреси пошти Cloudflare заміняв на
«[email protected]». Під кожним заголовком з'являвся зайвий рядок «Section titled». Читач виправляє це все, а ще не
губить головну сторінку довідки.

**Що не взято.** Не взято пакети зі схожими назвами, які не належать Sender.net: npm `sender`, `sender-forms`,
`nagoc-sender-mcp`, PyPI `sender`, `sender-net`. Не взято інші репозиторії `sendernet`: форки чужих бібліотек
(`amqp`, `phpClickHouse`, `smtpd`, `laravel-cloudflare-zero-trust-middleware`) і `format-wordpress`, який описує
форматування статей блогу. На сайті не взято сторінки авторів, службові сторінки, `quiz` і `request-demo`. Статтю
`blog/postmark-alternatives` сайт перенаправляє на чужий домен, тому білий список її не пропустив.

## Версії

Sender.net не публікує версій своєї документації й журналу змін API. Чинна версія API одна, `v2`. Адреса `/v1/` відповідає
кодом 410, тобто «більше не існує». Тому сторінки сайтів не мають версії, і фільтр `version` для них лишають порожнім.

Версію мають лише пакети, і в кожного вона досі одна:

| Пакет | Версія | Фільтр `version` |
|-------|--------|------------------|
| `@sender-net/sender-transactional-nodejs` | 0.0.1, з гілки `master`, бо тегів у репозиторії немає | `"0"` |
| `sendernet/sender-transactional-php` | 1.0.0, тег `v1.0.0` | `"php-1"` |

**Історичний знімок.** Єдину стару редакцію опису API знайдено у веб-архіві: файл OpenAPI від 21.04.2021, 119 шляхів `v2`.
Там є шляхи, яких чинна довідка не описує, наприклад `/v2/subscribers/file_import` і `/v2/subscribers/mailchimp_import`.
Такі шляхи можуть бути внутрішніми або вже не діяти, тому промпт велить називати їх лише із застереженням. Покажчик
цього документа дозволяє побачити їх усі, а перевіряти чинність треба за довідкою.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/sender-corpus-2026-11-02-openapi.tar.gz` (1464 тексти, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\sender-corpus-2026-11-02-openapi.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/sender/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/sender-corpus-РРРР-ММ-ДД.tar.gz -C instances/sender corpus raw
find instances/sender/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/sender/raw
gzip -9 -c instances/sender/index/passages.json > instances/sender/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як
новий архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/sender-corpus-2026-11-02-openapi.tar.gz -C instances/sender
./df sender smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки
`smoke`, яким потрібні тексти, пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/sender/index/passages.json.gz`. Далі
`./df sender vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df sender …` бере спільне середовище (`.venvs/cpu` або `.venvs/gpu`). Як його
збудувати один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ вище). Для самого сервера збирати нічого
не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df sender sources --why   # перелік джерел і білий список
./df sender refresh         # завантажити все задеклароване (близько 15 хвилин)
./df sender manifest        # оновити паспорт
./df sender setup           # Qdrant чи пошук лише по словах
./df sender vectors         # залити корпус у docs-sender
./df sender smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df sender serve          # порт 8945
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8945/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user sender-docs http://127.0.0.1:8945/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування, тому у вікні на боці Windows команду треба виконати в PowerShell.
Сам сервер з Windows доступний за тією ж адресою.

**3. Перевірити.** `/mcp` має показати `sender-docs` і два інструменти, `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» і невдале під'єднання — описана в
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
