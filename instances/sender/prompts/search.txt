One document set is historical: the OpenAPI snapshot of 2021-04-21 from the Internet Archive lists paths of v2 that the
current reference does not document (file_import, start_import, mailchimp_import and others). Say that such a path comes
from the 2021 snapshot and that it may be internal or gone; never present it as the current API.

Do not call this for Mailchimp, GetResponse, Shopify, WooCommerce, PrestaShop, WordPress, Zapier or SMTP as their own
projects: their documentation is not here -- these pages only show how Sender is used with them -- and the search will
return excerpts that merely mention them, with confident-looking titles. Marketing advice in the blog and the product
pages is the vendor's own view: for what the API really does, the API reference decides. Unofficial packages with a
similar name (npm `sender`, `sender-forms`, PyPI `sender-net`) are not here.

`version` narrows the search to one release line of a library: "0.0" keeps the Node.js package, "php-1.0" keeps the PHP
package. The pages of the sites carry no version -- the API is one live service, v2, and v1 no longer answers -- so leave
`version` empty for anything about the API, the help center or the product. Every excerpt comes back with `versions`:
each version whose documents contain this exact text, newest first.

Answer in the language of the question, keep identifiers and titles in English, and answer a question about history or
support point by point, naming the version and the document for each point.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
