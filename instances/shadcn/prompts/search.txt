shadcn/ui is a set of components copied into your project; most of them wrap Radix Primitives, and
from 3.x each component also exists on Base UI and on React Aria. The shadcn page says how to
install and use a component and shows examples; the props, events, `data-*` attributes and keyboard
behaviour of the parts underneath (`open`, `onOpenChange`, `asChild`, `data-state`) are on the page
of the same component in the primitives library -- Radix, Base UI or React Aria. A question about
controlling or customising a shadcn component usually needs both.

Call this when a question is about shadcn/ui, Radix, Base UI or React Aria: adding a component (`npx
shadcn add`), `components.json`, theming with CSS variables, Tailwind CSS v4 vs v3 setup, dark mode,
forms with React Hook Form and zod, data tables, sidebars, charts, the registry, props and events of
the primitives, controlled vs uncontrolled state, `asChild` (Radix) and `render` (Base UI), portals,
focus management, animation with `data-state` or `data-starting-style`, accessibility and keyboard
navigation, React Aria hooks and render props, Radix Themes components and tokens, Radix Colors
scales. Example query: "Dialog onOpenChange controlled open state".

Do not call this for other component libraries (Material UI, Chakra, Mantine, Headless UI, Ark UI,
React Spectrum's own Spectrum components have no documentation here), for Tailwind CSS itself (the
tailwind instance), for React Hook Form or zod themselves (their own instances), or for React itself
(the react instance): the search will return excerpts that merely mention them, with
confident-looking titles.

`version` narrows the search. shadcn/ui pages carry the minor release of the CLI they were published
with: "shadcn-4.21" ... "shadcn-2.6" for the current site (ui.shadcn.com, Tailwind CSS v4), and
"shadcn-tw3-3.8" ... "shadcn-tw3-0.1" for the site for Tailwind CSS v3, which up to 2.5 was the
whole documentation. A major takes every minor of it: "shadcn-4" is every 4.x, "shadcn-tw3-3" every
3.x of the Tailwind v3 site, "shadcn-tw3-0" every 0.x. Radix Primitives pages carry "radix-ui-1.7"
... "radix-ui-1.1" (the single `radix-ui` package, 2025 on) and, for the years when every component
was a package of its own, the component and its version: "radix-dialog-1.1.2", "radix-dialog-0.1.7"
("radix-dialog-1" is every 1.x of the Dialog package). Radix Themes carry "radix-themes-3.3" ...
"radix-themes-1.0", Radix Colors "radix-colors-3.0" ... "radix-colors-0.1". Base UI carries
"base-ui-1.8" ... "base-ui-1.0" ("base-ui-1" is every one). React Aria Components carry "rac-1.21"
(the current site, hooks pages included) ... "rac-1.0", the react-aria hooks from the repository
"react-aria-3.50" ... "react-aria-3.0" (hooks up to 3.47, the general pages up to 3.50). Leave
`version` empty to search everything. Every excerpt comes back with `versions`: each version whose
documents contain this exact text, newest first.

Which version to answer for. Unless the user names a version, answer from the current sites
("shadcn-4.21", "radix-ui-1.7", "base-ui-1.8", "rac-1.21"). When the project uses Tailwind CSS v3 or
an old CLI, filter by the major of its CLI on the Tailwind v3 site ("shadcn-tw3-3", "shadcn-tw3-2",
"shadcn-tw3-0"); when it imports `@radix-ui/react-dialog` and the like (one package per component),
filter by that component and its major ("radix-dialog-1"). Say which primitives library a shadcn
page is for when it matters: components/radix, components/base (Base UI) and components/aria (React
Aria) are three pages with different props. Prop tables of React Aria are only on the current site
("rac-1.21"); older React Aria pages have the text and the examples.

the Radix variant, shadcn-components-base-dialog, shadcn-components-aria-dialog,
shadcn-installation-next, shadcn-theming, shadcn-forms-react-hook-form, shadcn-cli,
shadcn-registry-index; shadcn-tw3-components-dialog on the Tailwind v3 site); Radix pages by the

rac-combobox, rac-examples-account-menu, rac-releases-v1-21-0, react-aria-usebutton,
react-aria-getting-started).

chance.
