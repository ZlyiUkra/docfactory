# shap — примірник фабрики docfactory

Цей примірник зібрав документацію бібліотеки SHAP і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не
з пам'яті. SHAP (SHapley Additive exPlanations) — бібліотека для Python, яка пояснює прогноз моделі машинного навчання. Для
кожного окремого прогнозу вона рахує, наскільки кожна ознака підняла або опустила результат порівняно із середнім прогнозом
моделі. Ці числа називають значеннями SHAP. Вони походять зі значень Шеплі з теорії ігор: там так ділять виграш між гравцями
за внеском кожного. Сума значень SHAP усіх ознак разом із середнім прогнозом дорівнює самому прогнозу, тому пояснення завжди
сходиться до числа, яке дала модель.

Для моделей-дерев XGBoost, LightGBM і scikit-learn у SHAP є окремий пояснювач `TreeExplainer`. Він рахує значення SHAP точно і
швидко, бо проходить самими деревами, а не перебирає комбінації ознак. Графіки показують пояснення: `waterfall` — один прогноз
ознака за ознакою, `beeswarm` і `bar` — які ознаки важать найбільше на всьому наборі даних, `scatter` — як внесок однієї ознаки
залежить від її значення.

## Скільки цього

Усього 219 документів і 1575 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат.

| Що | Версії | Документів |
|---|---|---|
| сайт shap.readthedocs.io: вступ, тематичні огляди, приклади-ноутбуки (табличні дані, дерева, текст, зображення, геноміка), приклади API, довідник API зі сторінкою кожного пояснювача, графіка, маски й допоміжної функції | стабільна версія 0.54 | 161 |
| нотатки релізів GitHub | усі стабільні теги 0.19.1–0.54.1 | 38 |
| записи PyPI з README | усі стабільні версії | 20 |

Мітка версії має вигляд `shap-0.54`. Префікс потрібен, щоб версії SHAP не збігалися з версіями інших бібліотек, коли сервери
працюють разом.

**Де є прогалини.**

- Read the Docs публікує лише останню стабільну версію сайту і гілку розробки, а старіших тек немає. Тому довідник API і
  ноутбуки описують версію 0.54. Про старіші версії примірник знає лише з нотаток релізів і README у записах PyPI.
- Сторінку `release_notes` сайту не взято. На ній той самий текст, що в релізах GitHub, але релізи лежать окремими документами, і
  кожен має свою мітку версії, тож фільтр за версією знаходить саме його.
- У ноутбуках збережено текстовий вивід коду, а картинки графіків — ні: розбір HTML залишає лише текст.

Замір `quality` на 09.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 5 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df shap <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт документації | `shap.readthedocs.io/en/stable/` | `sphinx-html` |
| нотатки релізів | релізи GitHub `shap/shap` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/shap/json` | `pypi-versions` |

Сайт розміщено на Read the Docs. Коли програма звертається до нього частіше ніж раз на секунду, сайт відповідає «429 Too Many
Requests». Тому в `config.json` стоїть `pause_sec: 1.0`. Сайт невеликий, близько 200 сторінок, і обхід триває кілька хвилин.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df shap serve
```

Порт — `8966`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user shap-docs http://127.0.0.1:8966/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `shap-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/shap-corpus-2026-11-09.tar.gz` (219 текстів, паспорт і сховище сирого `raw/`; перед
видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows `C:\Distr\shap-corpus-2026-11-09.tar.gz`
(звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/shap/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/shap-corpus-РРРР-ММ-ДД.tar.gz -C instances/shap corpus raw
find instances/shap/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/shap/raw
gzip -9 -c instances/shap/index/passages.json > instances/shap/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/shap-corpus-2026-11-09.tar.gz -C instances/shap
./df shap smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
