# snapsvg — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Snap.svg — бібліотеку для роботи з SVG у сучасних браузерах:
малювання фігур і контурів (`Snap()`, `Paper.circle`, `Paper.path`), атрибути й трансформації, анімація
(`Element.animate`, функції плавності `mina`), події й перетягування, фільтри, маски, градієнти і робота з готовим
файлом SVG (`Snap.load`, `Snap.select`). Документація — довідник API на кожному тегу 0.1.0–0.5.1, сторінки сайту
snapsvg.io, код демонстрацій і покрокового уроку, README, журнал змін і три пакети npm; лише англійською. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

SVG — це малюнок, який браузер тримає деревом елементів, і кожен елемент можна змінювати з JavaScript. Snap.svg
написав Дмитро Барановський, автор старішої бібліотеки Raphaël. Raphaël підтримував браузери аж до Internet
Explorer 6 і тому вмів лише те, що вміли вони всі. Snap.svg розрахована на сучасні браузери й дає маски, обрізання,
візерунки, повні градієнти й групи. Друга її особливість — робота з готовим SVG: малюнок, зроблений в Illustrator чи
Inkscape, завантажується (`Snap.load`), у ньому знаходять потрібні частини селектором CSS (`select`) і анімують
їх. Сам формат SVG і DOM браузера описано в примірнику `mdn`; тут — лише те, що додає Snap.svg.

Бібліотека давно не оновлюється: останній реліз 0.5.1 вийшов у лютому 2017 року. Нею досі користуються, тому
довідник потрібен, але нових можливостей у ній не з'являється, і відповідь мусить казати, що вона для 0.5.1.

**Що є що.** **Snap()** — функція, що створює поверхню малювання або загортає наявний елемент `<svg>`;
**Paper** — поверхня малювання, її методи створюють елементи (`Paper.circle`, `Paper.g`); це не бібліотека
Paper.js; **Element** — будь-який елемент малюнка з методами `attr`, `animate`, `transform`, `click`, `drag`;
**Fragment** — шматок розмітки SVG, ще не вставлений у сторінку (його повертають `Snap.load` і `Snap.parse`);
**Set** — набір елементів, з яким працюють як з одним; **mina** — функції плавності анімації (`mina.bounce`,
`mina.elastic`); **Matrix** — матриця трансформації.

## Звідки документація

- **Довідник — з репозиторію, з кожного тегу.** Snap.svg збирає довідник інструментом dr.js із коментарів у коді
  й кладе в репозиторій одним файлом `doc/reference.html` (на тегу `v0.1.0` — `dist/reference.html`). Сайт
  snapsvg.io/docs показує довідник лише версії 0.5.1 і відповідає тільки за `http`, тому цитата веде на файл у
  GitHub на відповідному тегу.
- **Читач `ghdocs-history-drjs`.** Сторінка довідника — це меню на шістсот посилань і двісті блоків
  `<article id="Element.attr">`. Читач бере лише блоки: назва методу з шапки блока стає заголовком, а підписи
  всередині («Parameters», «Usage») — рядками жирним, тож фрагмент пошуку — цілий метод. Рівень заголовка методу
  в різних версіях різний (`<h4>` у 0.1.0, `<h3>` у 0.3.0, `<h2>` у 0.5.1), і спільний читач HTML поділив би кожну
  версію по-своєму.
- **Сайт — з його репозиторію.** Сторінки snapsvg.io збирає Jekyll з `adobe-webplatform/snapsvg-site`; останній
  коміт там — 06.02.2017, день релізу 0.5.1, звідси мітка. Узято три сторінки з текстом. «Getting Started» і
  «Demos» на сайті — лише рамки, у яких відкривається демонстрація з основного репозиторію.
- **Покроковий урок — кодом.** Урок зі сторінки snapsvg.io/start — це файли `demos/tutorial/1.html` … `4.html`:
  код кроку з коментарями, що пояснюють кожну дію. Читач `ghcode-history` бере їх як код (поле `html_pages`).
  Так само взято інші демонстрації; чужі бібліотеки в їхніх теках (jQuery, Backbone, RequireJS) не беруться.
- **README — з тегів.** Версій 0.2.0 і 0.4.1 у npm немає, тому README читається з репозиторію на кожному з семи
  тегів; різних текстів серед них чотири.
- **Журнал змін.** `history.md` пише заголовок версії як «#0.5.1», без пробілу; його розбирає читач
  `changelog-regex` з виразом заголовка в `sources.json`.

## Межі, про які треба пам'ятати

- Нових версій немає з лютого 2017 року. Усе, що тут описано, стосується 0.5.1 і старіших.
- Довідник — єдиний докладний опис API. Посібника з розділами, як у новіших бібліотек, Snap.svg не має: є
  покроковий урок із чотирьох кроків і демонстрації.
- Цитата довідника веде на файл HTML у GitHub, де його видно кодом. Читати зручніше на snapsvg.io/docs, але там
  лише версія 0.5.1 і лише `http`.
- Демонстрація «animated-game» представлена трьома своїми скриптами: її сторінка більша за 40 000 байтів і не
  береться.
- Сторонні плагіни Snap.svg не входять.
- Сам формат SVG і DOM браузера — у примірнику `mdn`. Інші бібліотеки для малювання мають власні примірники:
  `svgjs`, `paperjs`, `konva`, `pixijs`, `fabricjs`, `d3`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/snapsvg-corpus-2026-11-20.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\snapsvg-corpus-2026-11-20.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів
немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/snapsvg/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/snapsvg-corpus-РРРР-ММ-ДД.tar.gz -C instances/snapsvg corpus raw
find instances/snapsvg/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/snapsvg/raw
gzip -9 -c instances/snapsvg/index/passages.json > instances/snapsvg/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/snapsvg-corpus-2026-11-20.tar.gz -C instances/snapsvg
./df snapsvg smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/snapsvg/index/passages.json.gz`,
далі `./df snapsvg vectors` заллє колекцію Qdrant.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df snapsvg …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/snapsvg/.env` (`cp .env.example .env`; для
кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df snapsvg sources --why    # перелік джерел і білий список
./df snapsvg refresh          # усе: близько хвилини мережею (паузи 0,2 с)
./df snapsvg manifest         # оновити паспорт
./df snapsvg setup            # Qdrant чи пошук лише по словах
./df snapsvg vectors          # залити корпус у docs-snapsvg
./df snapsvg smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df snapsvg serve   # порт 8994
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8994/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user snapsvg-docs http://127.0.0.1:8994/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `snapsvg-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
