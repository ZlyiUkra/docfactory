Search the Snap.svg documentation and return the matching excerpts with the versions each one belongs to.
What is here: the API reference of Snap.svg at every tag 0.1.0 to 0.5.1, one section per method and property --
Snap (Snap(), Snap.select, Snap.selectAll, Snap.load, Snap.parse, Snap.fragment, Snap.ajax, Snap.animate,
Snap.matrix, Snap.color, Snap.rgb, Snap.hsb, Snap.format, the angle and distance helpers), Paper (circle, rect,
ellipse, line, path, polyline, polygon, text, image, g, group, svg, mask, ptrn, use, symbol, gradient, filter,
toString, toDataURL), Element (attr, animate, stop, transform, select, selectAll, add, append, prepend, before,
after, insertBefore, insertAfter, remove, clone, use, toDefs, pattern, marker, data, getBBox, addClass,
removeClass, toggleClass, hasClass, the event handlers click, dblclick, mousedown, mousemove, mouseover,
mouseout, mouseup, touchstart, touchmove, touchend, hover, drag and their un… counterparts, getTotalLength,
getPointAtLength, getSubpath), Fragment, Set, Matrix, the easing functions of mina, Snap.path (bounding boxes,
intersections, toAbsolute, toRelative, toCubic, map) and Snap.filter (blur, shadow, grayscale, sepia, saturate,
hueRotate, invert, brightness, contrast); the pages of the site snapsvg.io (the home page with the feature
overview, "Why Snap", "Support"); the code of the demos of the repository, including the four steps of the
"Getting Started" tutorial, the clock, the animated map, the pattern, the mascot, the coffee infographic, the
game and the display ad; the README of the repository at every tag; the changelog (history.md); and the
related packages: the README and registry history of snapsvg-cjs, the community CommonJS build for webpack and
other bundlers, and the registry history of snapsvg and of @types/snapsvg.

Call this when a question is about Snap.svg: creating a drawing surface with Snap(), drawing shapes, paths and
text, groups, gradients, patterns, masks and clipping, filters, setting attributes, transforms and matrices,
animating attributes with easing, events and dragging, selecting elements with CSS selectors, loading and
parsing an external SVG file and working with its parts, sets, path math -- and history: since which version a
method exists, what a release changed.

Do not call this for the SVG format or the browser DOM themselves (SVG elements and attributes, SVGElement,
CSS) -- they are in the mdn-docs server -- nor for SVG.js (the svgjs-docs server), Paper.js (the paperjs-docs
server), Konva, PixiJS, Fabric.js, D3 (their own servers), Raphaël, other drawing libraries, or JavaScript
language questions: their documentation is not here, and the search will return Snap.svg excerpts that merely
mention them, with confident-looking titles. In Snap.svg "Paper" is the drawing surface, not the Paper.js
library.

`version` narrows the search to one release line. Snap.svg has no 1.0, so a line is two numbers: "0.5" keeps
the reference, README and changelog of 0.5.0 and 0.5.1 together with the site and the demos, "0.4" those of
0.4.0 and 0.4.1, "0.5.1" one exact version; leave it empty to search everything. The related packages carry a
prefix so they never mix with snapsvg: "snapsvg-cjs-0.0", "types-snapsvg-0.5". Every excerpt comes back with
`versions`: each version whose documents contain this exact text, newest first, so the list itself shows from
which to which version the documentation said exactly this.

Write the query in English, with the names Snap.svg itself uses ("Paper.circle", "Element.attr fill stroke",
"Element.animate duration easing", "Snap.load Fragment", "Element.drag", "Snap.select", "Paper.filter
Snap.filter.blur", "mina.bounce", "Element.transform"), not in the user's own words. Everything here is English
-- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and
digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes
back with `found: 0`. When the user asks in another language, translate the question into Snap.svg terms first,
then search.

Answer in the language the user wrote in. When the question is about the history or support of a method or
option, answer point by point: since which version it exists; what changed in later versions; what prompted the
change, if the excerpts say so; and how it stands in the current version. Every point names the version and
the document it rests on; a point the excerpts do not support is left out, not guessed. When that language is
Ukrainian, write as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and
the Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never
call this set of documents "корпус" -- say "документація Snap.svg". Identifiers, option names and titles stay
in English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated:
true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Version 0.5.1 came out in February 2017 and is the last release; in the week to
18 November 2026 it carried about 93% of the downloads of snapsvg, 0.4.0 about 6%. Search with `version` "0.5"
for a question about how to do something and say the answer is for Snap.svg 0.5.1; if the user names an older
version, search its line. Search without `version` when the question is about history or when the line gave
nothing. The reference names a method by the object it belongs to: methods of the drawing surface are
"Paper.…" (Paper.circle), methods of an element "Element.…" (Element.attr), library-level helpers "Snap.…";
group elements, masks and patterns share the Paper methods. When the user asks how to use Snap.svg with a
bundler, the snapsvg package is published in AMD format and the snapsvg-cjs package repackages it as CommonJS;
look at the snapsvg-cjs README and say that it is a community package.
