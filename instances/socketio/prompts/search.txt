Call this when a question is about real-time features built with Socket.IO: io.on("connection"),
socket.emit and socket.on, acknowledgements and emitWithAck, timeouts, namespaces, rooms,
socket.join, io.to, socket.broadcast, io.use and socket.handshake.auth, reconnection and
connection state recovery, transports and upgrades, CORS, sticky sessions, adapters and
running several servers, the Admin UI, using Socket.IO with Express, NestJS, Next.js or React
-- and above all when it is about versions: what changed between 2, 3 and 4, since which
version an option exists, and how to migrate. Example query: "socket.join rooms".

Do not call this for Node.js itself (http, net, cluster), for the raw WebSocket browser API or
the ws package, for Redis, PostgreSQL or MongoDB themselves, for NestJS (it has its own
instance, the @nestjs/websockets chapters are there) or for other real-time libraries: their
documentation is not here, and the search will return Socket.IO excerpts that merely mention
them, with confident-looking titles.

`version` narrows the search to one major: "4" keeps Socket.IO 4.x, "3" and "2" the old lines.
The changelog pages and package changelogs carry the version "changelog", blog posts "blog",
the protocol specifications "protocol"; README documents of a package carry the versions of
that package (the adapters and the Admin UI have their own numbering). Leave `version` empty to
search everything. Every excerpt comes back with `versions`: each version whose documents
contain this exact text, newest first -- text that stayed the same across versions is
returned once, with all of them listed.

Which version to search first. Socket.IO 4 took 92% of the downloads of the socket.io package
in the week the documentation was collected, so when the user names no version, search with
"4" and answer for Socket.IO 4. Bring up 3 or 2 only when the user names them. Search without
`version` for history and migrations; the migration guides and the changelogs name the
version of every change.

Where the documentation lives. Site pages are named by their path
(docs-categories-04-events-rooms, docs-server-api, src-pages-how-to-use-with-jwt,
versioned-docs-version-3-x-…); README documents, changelogs, release notes and registry
documents are titled by package.

Write the query in English, with the names the documentation uses (io.on, socket.emit,
socket.on, emitWithAck, socket.timeout, socket.join, socket.leave, io.to, io.in,
socket.broadcast, io.of, io.use, socket.handshake, socket.data, fetchSockets,
serverSideEmit, connectionStateRecovery, createAdapter, transports, upgrade, pingInterval,
pingTimeout, maxHttpBufferSize, cors, path, sticky sessions). Everything here is English --
the excerpts, the word index and the meaning index alike -- and the word index keeps only
latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin
script matches nothing at all and comes back with `found: 0`. When the user asks in another
language, translate the question into Socket.IO terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Answer in the language the user wrote in. Every answer says which version it is for. When the
question is about a version change, a migration or compatibility, answer point by point: since
which version; what changed; what the migration requires; how it stands now -- each point with
the document it rests on; a point the excerpts do not support is left out, not guessed. When
that language is Ukrainian, write as a Ukrainian engineer writes, not as a translation from
English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "подія", "кімната", "простір імен", "підтвердження", not "аквнолідж"; "застарілий",
not "депрекейтнутий". Never call this set of documents "корпус" -- say "документація
Socket.IO". Identifiers, option names and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of
memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
