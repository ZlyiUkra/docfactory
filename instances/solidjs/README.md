# solidjs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про SolidJS — бібліотеку інтерфейсів на дрібнозернистій реактивності
(сигнали, ефекти, мемо, сховища, компоненти, керування потоком, ресурси, рендеринг на сервері), а також про Solid
Router, SolidStart, Solid Meta і Solid Primitives. Документація — на кожен стабільний реліз: сайт docs.solidjs.com на
релізи solid-js 1.8–1.9 і на релізи Router, Start і Meta, давня документація solidjs.com 1.0–1.8, і єдиний
нестабільний шар — реліз-кандидат Solid 2.0 (2.0.0-rc.19) з позначкою в кожному документі. Джерела — репозиторії
solidjs/solid-docs, solidjs/solid-docs-legacy, solidjs/solid, solid-router, solid-start, solid-meta,
solidjs-community/solid-primitives, пакети й реєстр npm; лише англійською. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

Solid змінювався швидше, ніж його документація встигала переїжджати. До липня 2021 року довідник API лежав у теці
`documentation/` самої бібліотеки, потім — у репозиторії сайту solidjs.com (нині solid-docs-legacy, заморожений
01.06.2024), а з 2024 року основною стала docs.solidjs.com, що за два роки двічі переклала теки. Router і Start мають
власну нумерацію (Router 0.4–1.0, Start 0.4–2.1), а Start 1 і Start 2 описано поруч, у теках `v1/` і `v2/` того самого
сайту. Тегів у репозиторії сайту немає зовсім. Тож відповідь мусить знати версію, а версії мусять бути всі.

**Що є що.** **Сигнал** — значення, що сповіщає залежних про зміну (`createSignal`); **мемо** — закешоване похідне
значення (`createMemo`); **ефект** — код, що перезапускається за зміною сигналів (`createEffect`). **Сховище** —
вкладений реактивний стан (`createStore`, `produce`, `reconcile`). **Ресурс** — асинхронні дані зі станом завантаження
(`createResource`, `Suspense`). **Solid Router** — маршрутизатор, **SolidStart** — метафреймворк (файлові маршрути,
серверні функції `"use server"`), **Solid Meta** — теги `<head>`. **Solid Primitives** — 85 пакетів спільноти
`@solid-primitives/*` (сховище, таймери, події, спостерігачі, медіа тощо). **Реліз-кандидат** — збірка перед
стабільним випуском, не стабільна версія.

## Звідки документація

- **Сайт без тегів.** Читач `ghsite-dated` бере знімок репозиторію сайту на мить перед наступним релізом пакета з
  реєстру npm: так кожна версія дістає текст, який описував саме її, з правками, дописаними вже після виходу. Розділи
  Router, Start і Meta знімаються на релізи своїх пакетів читачем `ghsite-dated-prefixed`
  (`engine/readers/ghdatedprefix.py`), який ставить перед версією префікс пакета (`router-0.15.4`, `start-2.1.0`,
  `meta-0.29.4`): інакше фільтр «1» змішав би solid-js 1.x, Router 1.0 і Start 1.x. Теки `v1/` і `v2/` (поле
  `line_marker`) належать лише своїй лінії: тека `v2/` у main навесні 2026 року — документація 2.0, і знімки 1.9 її не
  беруть.
- **Перекладені теки.** Сайт тричі міняв розкладку (`(0)concepts/…` з номерами впорядкування, `reference/solid-router/`
  проти `solid-router/reference/`, `solid-start/v1/` і `v2/`); `slug_rewrite` у `config.json` зводить імена тієї самої
  сторінки до одного ключа, щоб її редакції зливалися.
- **Реліз-кандидат 2.0.** Гілка `v2-rebuild` (активна, `update-v2-docs` застаріла) на день збирання, з версією
  2.0.0-rc.19. Поле `redact` у `config.json` ставить на початку кожного такого документа рядок «Solid 2.0 release
  candidate (2.0.0-rc.19), not a stable release. Реліз-кандидат 2.0, не стабільна.» Інших передрелізів тут немає.
- **Журнали.** Кореневий `CHANGELOG.md` Solid — довгі нотатки мінорних 0.x–1.8 (`changelog-dated`); журнали Changesets
  `packages/solid`, Router, Start (гілки main і 1.x), Meta і кожного пакета Primitives — читачем
  `changelog-named-prefixed`, який ставить префікс пакета і відсіює записи передрелізів.
- **npm.** Реєстр восьми пакетів (solid-js, `@solidjs/router`, `@solidjs/start`, старий `solid-start` 0.1–0.3,
  `@solidjs/meta`, `@solidjs/testing-library`, `vite-plugin-solid`, `babel-preset-solid`) і 85 пакетів
  `@solid-primitives/*`; README кожної стабільної версії — з репозиторію на коміті, з якого версію опубліковано, або на
  тезі релізу.

## Межі, про які треба пам'ятати

- Сайт docs.solidjs.com став основним на початку 2024 року; для solid-js 1.0–1.8 основна документація — давня
  solidjs.com. Знімки 1.8, зроблені до появи `src/routes/`, нової документації не мають.
- Давня документація — англійська частина solid-docs-legacy (`langs/en/`); переклади не беруться.
- Пакет `@solid-primitives/match` журналу змін не має.
- Передрелізів (крім реліз-кандидата 2.0), Kobalte, Solid UI, TanStack та інших сторонніх бібліотек тут немає.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/solidjs-corpus-2026-10-28.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\solidjs-corpus-2026-10-28.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів
немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/solidjs/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/solidjs-corpus-РРРР-ММ-ДД.tar.gz -C instances/solidjs corpus raw
find instances/solidjs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/solidjs/raw
gzip -9 -c instances/solidjs/index/passages.json > instances/solidjs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/solidjs-corpus-2026-10-28.tar.gz -C instances/solidjs
./df solidjs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/solidjs/index/passages.json.gz`, далі
`./df solidjs vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df solidjs …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/solidjs/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df solidjs sources --why   # перелік джерел і білий список
./df solidjs refresh         # усе задеклароване: близько 40 хвилин мережею (паузи 0,1 с)
./df solidjs manifest        # оновити паспорт
./df solidjs setup           # Qdrant чи пошук лише по словах
./df solidjs vectors         # залити корпус у docs-solidjs
./df solidjs smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df solidjs serve          # порт 8928
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8928/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user solidjs-docs http://127.0.0.1:8928/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `solidjs-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
