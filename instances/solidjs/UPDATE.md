# Оновлення корпусу solidjs

Перелік версій тут не оголошується руками: знімки сайту (`docs-*`, читачі `ghsite-dated` і `ghsite-dated-prefixed`),
README (`npm-readme-*`) і реєстр (`npm-*`) беруть версії з опису пакета в реєстрі npm, тож новий реліз потрапляє туди
сам, а журнали змін і релізи GitHub читаються з гілок і API щоразу заново. Передрелізи не беруться (`only` у знімках,
`skip_versions: "-"` у README і журналах); виняток — реліз-кандидат Solid 2.0, джерело `docs-v2-rc`.

Руками оголошено:

- **Реліз-кандидат 2.0** — `docs-v2-rc`: поле `only` називає один номер (`^2\.0\.0-rc\.19$`), а `redact` у
  `config.json` — той самий номер у позначці. Новий RC — новий номер в обох місцях. Коли вийде стабільна 2.0.0:
  `docs-v2-rc` прибрати (його файли перенести в окрему теку, не видаляти), а в `docs-core` розширити `only` до
  `^(1\.(8|9)|2\.\d+)\.\d+$` і звірити гілку: 2.0 може переїхати в main.
- **Давня документація** (`docs-legacy`, 1.0–1.8) заморожена разом із solid-docs-legacy.
- **Новий пакет Primitives** — три джерела за зразком наявних (`npm-readme-solid-primitives-<ім'я>`,
  `npm-solid-primitives-<ім'я>`, `changelog-primitives-<ім'я>`) з префіксом версії `primitives-<ім'я>-`.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df solidjs refresh docs-core docs-router docs-start docs-meta npm-solid-js   # і решту npm-*, що змінилися
./df solidjs refresh --missing    # джерела, яких не названо, лише докачуються
./df solidjs manifest
./df solidjs vectors
./df solidjs smoke
# Ctrl+C у терміналі з serve, і знову: ./df solidjs serve
```

Названі джерела оновлюються повністю, не `--missing`: у документі стоять усі версії, де текст був таким, тож новий
реліз змінює й старі документи (незмінна сторінка дописує нову версію в рядок `# версія:`). Документи редакцій, яких
у новому прогоні вже немає, лишаються в теці — їх переносять в окрему теку поза корпусом руками, перш ніж рахувати
вектори. Повний `refresh` — близько 40 хвилин мережею; сховище сирого `raw/` повертається з архіву разом із текстами,
тож після правки читача тексти перебудовуються без мережі: `./df solidjs build <id>`.

Якщо змінилася найпоширеніша лінія (на 28.10.2026 — 1.9, понад 95 % завантажень solid-js):

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` переглянути лінію за
  замовчуванням;
- у `checks.json`, у десятці `quality_model`, замінити `"1.9"` там, де питання про поточну поведінку, і звірити цілі.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) потрібен для дерев знімків (кілька сотень звернень на повний прогін).

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df solidjs quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
