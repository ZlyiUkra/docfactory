Search the SolidJS documentation -- the Solid core library, Solid Router, SolidStart, Solid Meta and Solid
Primitives -- and return the matching excerpts with the versions each one belongs to. What is here: the site
docs.solidjs.com (repository solidjs/solid-docs) as it stood at every stable release: the core concepts,
guides, configuration and API reference at every solid-js release 1.8 to 1.9, the Solid Router section at every
@solidjs/router release, the SolidStart section at every @solidjs/start release, the Solid Meta section at every
@solidjs/meta release; the old solidjs.com documentation (the API page, the guides and the lessons of the
tutorial) at every stable solid-js release 1.0 to 1.8; the documentation of the Solid 2.0 release candidate
(2.0.0-rc.19, branch v2-rebuild) -- the only non-stable part, every excerpt of it carries a notice saying so;
the changelogs of solid (the long notes of every minor 0.x to 1.8 and the patch notes 1.6.3 to 1.9.x),
@solidjs/router, @solidjs/start (1.x and 2.x) and @solidjs/meta, and the GitHub release notes of solid and
solid-start; the README of every stable version and the npm registry history (versions, dates, dist-tags, peer
dependencies, exports) of solid-js, @solidjs/router, @solidjs/start, solid-start (0.1 to 0.3), @solidjs/meta,
@solidjs/testing-library, vite-plugin-solid and babel-preset-solid; and Solid Primitives
(solidjs-community/solid-primitives): for every @solid-primitives package the README of every stable version,
its changelog and its registry history.

Call this when a question is about Solid itself: signals and fine-grained reactivity (createSignal,
createEffect, createMemo, createComputed, createRenderEffect, batch, untrack, on, createRoot, ownership and
disposal), stores (createStore, produce, reconcile, unwrap, createMutable), components and props (splitProps,
mergeProps, children), control flow (Show, For, Index, Switch, Match, Dynamic, Portal, ErrorBoundary), lifecycle
(onMount, onCleanup), context, refs and directives (use:), JSX and the compiler (babel-preset-solid, dom
expressions), resources and async (createResource, Suspense, SuspenseList, useTransition, lazy), server
rendering and hydration (renderToString, renderToStream, hydrate, isServer), Solid Router (Router, Route, A,
useNavigate, useParams, useSearchParams, query, cache, action, createAsync, preload), SolidStart (file routes,
"use server" functions, API routes, middleware, sessions, app.config.ts, deployment presets, Vinxi and Vite),
Solid Meta (MetaProvider, Title, Meta, Link), testing (@solidjs/testing-library), vite-plugin-solid options,
and any Solid Primitives package (storage, scheduled, event-listener, resize-observer, intersection-observer,
media, keyboard, i18n, websocket, workers and the rest) -- and history: since which version an API exists,
what changed in a release, how to migrate between versions.

Do not call this for React, Vue, Svelte or other frameworks, for TanStack, Kobalte, Solid UI or other
third-party libraries, for TypeScript or JavaScript language questions, or for prereleases other than the Solid
2.0 release candidate: their documentation is not here, and the search will return Solid excerpts that merely
mention them, with confident-looking titles.

`version` narrows the search to one release line: "1.9" keeps every 1.9.x document of solid-js, "1" every 1.x,
"2.0.0-rc.19" the Solid 2.0 release candidate; leave it empty to search everything. The other packages carry
their own numbering with a prefix, so they never mix with solid-js: "router-0.15", "start-1", "meta-0.29",
"testing-library-0.8", "vite-plugin-solid-2", "babel-preset-solid-1.9", "primitives-storage-4". Every excerpt
comes back with `versions`: each version whose documents contain this exact text, newest first, so the list
itself shows from which to which version the documentation said exactly this.

Write the query in English, with the names Solid itself uses ("createResource", "createStore", "Suspense",
"useSearchParams", "createAsync", "use server", "makePersisted"), not in the user's own words. Everything here is
English -- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin
letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing at
all and comes back with `found: 0`. When the user asks in another language, translate the question into Solid
terms first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if
the excerpts say so; and how it stands in the current version. Every point names the version and the document
it rests on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian,
write as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the
Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call
this set of documents "корпус" -- say "документація SolidJS". Identifiers, option names and titles stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional, see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry
`truncated: true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. solid-js 1.9 carries over 95% of the weekly downloads; 1.8 and older a fraction
of a percent; the 2.0 release candidate about 3%. Search with `version` "1.9" for a question about how to do
something. If the user names a version, or asks about Solid 2.0, search that line; every answer drawn from the
2.0 documentation says that 2.0 is a release candidate, not a stable release. Search without `version` when the
question is about history, about Router, Start, Meta or a primitive (their versions carry a prefix), or when the
line gave nothing. Every answer says which version it is for; when the user did not name one, answer for Solid
1.9 and say so. When the excerpts behind a statement come only from older versions, name those versions instead
of presenting the text as current.
