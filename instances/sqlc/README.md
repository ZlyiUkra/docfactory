# sqlc — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про sqlc (sqlc-dev/sqlc) — генератор типізованого коду Go із запитів
SQL: ви пишете схему й запити, sqlc перевіряє їх і генерує функції та структури Go. Код спільний і лежить у
`../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

У плані Go ([../go/LEARNING.md](../go/LEARNING.md), фаза 3) SQL пишуть руками, а код доступу до бази генерує sqlc:
запит із коментарем `-- name: GetPost :one` стає методом `GetPost(ctx, id)` з готовою структурою результату, а
помилка в імені колонки — помилкою генерації, а не продакшну. Документація sqlc — це конфігурація `sqlc.yaml`,
анотації запитів, макроси (`sqlc.arg`, `sqlc.narg`, `sqlc.slice`, `sqlc.embed`) і відповідність типів бази типам Go;
її ключі додавалися й змінювалися від версії до версії, тож вона лежить на кожну мінорну окремо.

Документів менше, ніж файлів на всіх тегах: текст, що не мінявся між мінорними, — один документ із переліком версій.

Разом 367 записів паспорта. В індексі 1064 фрагменти (`expected_passages` у `checks.json`) із 323 документів. Замір
`quality`: по словах 8 із 10, за змістом 10, разом 10, «як модель» 10 із 10. Два запити першої десятки
переформульовано ближче до того, як питає користувач («optional query parameter that can be null…», «verify queries
against the schema in a CI pipeline…»); до запиту `emit_pointers_for_null_types` додано ціль — розділ Version 1
довідника конфігурації, де цей ключ описано.

Чого немає:

- Згенерованого коду Go прикладів: що генерує кожна анотація, показує документація.
- Плагінів інших мов (sqlc-gen-kotlin, sqlc-gen-python) як окремих проєктів — лише сторінки переходу на них.
- Сервісу sqlc Cloud поза тим, що про нього кажуть сторінки `push`, `verify`, `managed databases`.
- Документації PostgreSQL, MySQL, SQLite, pgx, goose і golang-migrate: для pgx, goose і golang-migrate є власні
  примірники.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df sqlc <крок>`.

## Версії

Документація й README несуть версію sqlc (`1.31.1`), журнал — версію запису, приклади — без версії. Фільтр
`version` приймає мажор (`"1"`), мінор (`"1.27"`) або точну версію (`"1.27.0"`). Промпт відповідає для найновішої
sqlc 1.31.1, якщо користувач не назвав старішу, і для ключів конфігурації каже, з якої вони версії.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/sqlc-corpus-2026-10-27.tar.gz` (367 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\sqlc-corpus-2026-10-27.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/sqlc/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/sqlc-corpus-РРРР-ММ-ДД.tar.gz -C instances/sqlc corpus raw
find instances/sqlc/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/sqlc/raw
gzip -9 -c instances/sqlc/index/passages.json > instances/sqlc/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/sqlc-corpus-2026-10-27.tar.gz -C instances/sqlc
./df sqlc smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/sqlc/index/passages.json.gz`.
Далі `./df sqlc vectors` заллє колекцію Qdrant: секунди на відеокарті, хвилина на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df sqlc …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне
середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df sqlc sources --why   # перелік джерел і білий список
./df sqlc refresh         # завантажити все задеклароване (кілька хвилин)
./df sqlc manifest        # оновити паспорт
./df sqlc setup           # Qdrant чи пошук лише по словах
./df sqlc vectors         # залити корпус у docs-sqlc
./df sqlc smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df sqlc serve          # порт 8916
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8916/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user sqlc-docs http://127.0.0.1:8916/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `sqlc-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
