Search the documentation of sqlc (sqlc-dev/sqlc), the tool that generates type-safe Go code from SQL: the site
docs.sqlc.dev as it stood at every minor release 0.1 ... 1.31 -- the tutorials (getting started with PostgreSQL,
MySQL, SQLite), the how-to guides (select, insert, update, delete, transactions, prepared queries, named parameters,
embedding structs with sqlc.embed, overrides of Go types and struct field names, renaming, DDL and migrations from
goose, golang-migrate, dbmate, sql-migrate and Atlas, generate, vet, verify, push, CI/CD), the reference (the
sqlc.yaml / sqlc.json configuration version 2 -- sql, engine, schema, queries, gen.go with package, out,
sql_package pgx/v5, emit_json_tags, emit_interface, emit_pointers_for_null_types, overrides -- the CLI, the query
annotations :one, :many, :exec, :execrows, :execresult, :execlastid, :copyfrom, :batchexec, :batchmany, :batchone,
the macros sqlc.arg, sqlc.narg, sqlc.slice, sqlc.embed, the data types and how PostgreSQL types map to Go,
environment variables, language support), the guide "Using Go and pgx", plugins; the README at every release; the
changelog of every release; and the example projects (schemas, queries and sqlc configuration of authors, batch,
booktest, jets, ondeck). Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about sqlc: how to configure it, how to annotate a query, which Go code it generates for
a query or a column type, how NULL columns become Go types, how to use it with pgx v5 or database/sql, how it reads a
schema from migration files, how to write optional filters and IN lists, how to run queries in a transaction, how to
check queries in CI (vet, verify), and what changed between releases.

Do not call this for PostgreSQL, MySQL or SQLite themselves (SQL syntax, indexes -- the database documentation), for
pgx beyond what sqlc's pages say about it, for goose or golang-migrate beyond their mention, for ORMs (GORM, ent) or
for other languages' code generators beyond the list of plugins: their documentation is not here, and the search will
return excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release: two numbers keep a minor ("1.27"), three an exact version ("1.27.0");
"1" keeps every 1.x release. Every excerpt comes back with `versions`: each release whose documents contain this exact
text, newest first. Without `version` the newest text comes first.

Write the query in English, with the names the documentation itself uses ("sqlc.yaml", "version 2", "sql_package
pgx/v5", "emit_json_tags", "emit_pointers_for_null_types", "overrides", "db_type", "go_type", "column", "rename",
"query annotations", ":one", ":many", ":exec", ":execrows", ":copyfrom", ":batchexec", "sqlc.arg", "sqlc.narg",
"sqlc.slice", "sqlc.embed", "named parameters", "transactions WithTx", "prepared queries", "nullable", "pgtype",
"goose", "golang-migrate", "schema", "queries", "sqlc generate", "sqlc vet", "sqlc verify", "sqlc compile"), not in the
user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question
into the terms of the documentation first, then search.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "запит", "схема", "згенерований код", "налаштування". Never call this set of documents "корпус" -- say
"документація sqlc". Identifiers, configuration keys and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. sqlc 1.31.1 is the newest release. Search without `version` first; when the user names
their sqlc version, search that release. Every answer about configuration keys says which release it is for: keys
were added and renamed between releases.
