# stable-baselines3 — примірник фабрики docfactory

Цей примірник зібрав документацію Stable-Baselines3 і двох пакетів, що йдуть із нею в парі, та віддає її через сервер MCP, щоб
модель відповідала з текстів бібліотек, а не з пам'яті.

Stable-Baselines3 (скорочено SB3) — бібліотека для Python на PyTorch з готовими алгоритмами навчання з підкріпленням. Користувач
дає їй середовище у форматі Gymnasium і назву алгоритму, наприклад `PPO("MlpPolicy", env)`. Метод `learn` навчає агента задану
кількість кроків, метод `predict` повертає дію для спостереження, методи `save` і `load` зберігають і відновлюють модель. У самій
бібліотеці сім алгоритмів: A2C, DDPG, DQN, HER, PPO, SAC і TD3. Навколо них є спільні інструменти: векторні середовища, які
запускають кілька копій середовища одразу (`DummyVecEnv`, `SubprocVecEnv`), нормування спостережень і винагород (`VecNormalize`),
колбеки, що оцінюють і зберігають модель під час навчання (`EvalCallback`, `CheckpointCallback`), і перевірка власного середовища
(`check_env`).

- **sb3-contrib** містить експериментальні алгоритми, яких немає в основній бібліотеці: `MaskablePPO` (забороняє агентові дії,
  недопустимі в поточному стані), `RecurrentPPO` (політика з пам'яттю LSTM), `QRDQN`, `TQC`, `TRPO`, `ARS`, `CrossQ`.
- **RL Baselines3 Zoo** — набір сценаріїв навколо SB3: навчання однією командою, оцінка, підбір гіперпараметрів через Optuna і
  файли з уже підібраними гіперпараметрами для відомих середовищ.

## Скільки цього

Усього 686 документів і 3 845 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Сторінка з
однаковим текстом у кількох лініях лежить одним документом із переліком цих ліній.

| Що | Версії | Документів |
|---|---|---|
| сайт stable-baselines3.readthedocs.io: посібник, сторінка кожного алгоритму, спільні модулі, журнал змін | 17 мінорних ліній 0.11–2.9 | 420 |
| сайт sb3-contrib.readthedocs.io: сторінка кожного експериментального алгоритму, приклади | 16 мінорних ліній 1.0–2.9 | 122 |
| сайт rl-baselines3-zoo.readthedocs.io: навчання, оцінка, підбір гіперпараметрів, налаштування | 11 мінорних ліній 1.8–2.9 | 45 |
| нотатки релізів GitHub трьох репозиторіїв | усі стабільні теги | 25 + 23 + 23 |
| записи PyPI трьох пакетів з README | усі стабільні версії | 13 + 10 + 5 |

Мітки версій мають вигляд `sb3-2.9`, `sb3-contrib-2.9` і `rl-zoo-2.9`. Префікси потрібні, щоб номери трьох пакетів не змішувалися
між собою й з версіями інших бібліотек.

**Де є прогалини, хоч ми й брали всі лінії.**

- Read the Docs має не кожну лінію. Для Stable-Baselines3 немає тек ліній 0.6–0.10, 1.1–1.3; для sb3-contrib — 0.10–0.11 і
  1.1–1.3; для RL Zoo — усього до 1.8. Про ці лінії є тільки записи PyPI і нотатки релізів.
- Береться останній патч лінії, який сайт публікує: `v2.9.2`, `v2.7.1`, `v2.4.1`, `v2.3.2` тощо.
- Сторінки `_modules/` (вихідний код, на який ведуть посилання «[source]») не взято: це код, а не документація.
- SBX (версія SB3 на Jax) має в корпусі лише сторінку-огляд із сайту SB3.

Замір `quality` на 12.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає
саме так. Запити своїми словами знаходять потрібне 9 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df stable-baselines3 <крок>`.

| Що | Джерело | Читач |

| сайт Stable-Baselines3 | `stable-baselines3.readthedocs.io/en/v*/` | `sphinx-html` |
| сайт sb3-contrib | `sb3-contrib.readthedocs.io/en/v*/` | `sphinx-html` |
| сайт RL Baselines3 Zoo | `rl-baselines3-zoo.readthedocs.io/en/v*/` | `sphinx-html` |
| нотатки релізів | релізи GitHub `DLR-RM/stable-baselines3`, `Stable-Baselines-Team/stable-baselines3-contrib`, `DLR-RM/rl-baselines3-zoo` | `ghreleases-pattern` |
| записи PyPI | `pypi.org/pypi/<пакет>/json` | `pypi-versions` |

**Чому обхід довгий.** Read the Docs відмовляє відповіддю «429», коли запитів забагато. Тому три сайти обходить один процес із
паузою в секунду. Перше збирання 44 тек версій тривало близько пів години.

**Чому одне місце на родину документів.** У `config.json` стоїть `"max_per_doc": 1`: одна сторінка з усіма її версіями займає у
видачі одне місце. Без цього на запит назвою алгоритму перші місця забирали журнал змін і нотатки релізів, а сторінка самого
алгоритму до видачі не доходила.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df stable-baselines3 serve
```

Порт — `8973`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user stable-baselines3-docs http://127.0.0.1:8973/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `stable-baselines3-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Родина «Навчання з підкріпленням»: піднімати разом

Цей примірник — частина родини «Навчання з підкріпленням»: теорія і три бібліотеки, якими її застосовують. Питання про те, чому
агент не вчиться, починається в документації алгоритму Stable-Baselines3, а закінчується в теорії або в описі середовища
Gymnasium. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки перелічує всі чотири сервери:
підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `reinforcement-learning` | `reinforcement-learning-docs` | 8971 | теорія: книжки, курси й статті про навчання з підкріпленням і бандитів, торгове середовище, навчання на записаній історії |
| `gymnasium` | `gymnasium-docs` | 8972 | Gymnasium 0.26–1.4: інтерфейс середовища, простори, обгортки, векторні середовища |
| `stable-baselines3` | `stable-baselines3-docs` | 8973 | Stable-Baselines3 0.11–2.9, sb3-contrib і RL Zoo: готові алгоритми, колбеки, векторні середовища |
| `d3rlpy` | `d3rlpy-docs` | 8974 | d3rlpy 0.2–2.8: навчання на записаній історії без живого середовища (CQL, IQL, Decision Transformer) |

Усі чотири одним терміналом:

```
cd ~/Projects/docfactory && tools/up.sh reinforcement-learning gymnasium stable-baselines3 d3rlpy
```

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
кореневому README.md, розділ «Родини примірників».

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/stable-baselines3-corpus-2026-11-12.tar.gz` (686 текстів, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\stable-baselines3-corpus-2026-11-12.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/stable-baselines3/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/stable-baselines3-corpus-РРРР-ММ-ДД.tar.gz -C instances/stable-baselines3 corpus raw
find instances/stable-baselines3/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/stable-baselines3/raw
gzip -9 -c instances/stable-baselines3/index/passages.json > instances/stable-baselines3/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/stable-baselines3-corpus-2026-11-12.tar.gz -C instances/stable-baselines3
./df stable-baselines3 smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
