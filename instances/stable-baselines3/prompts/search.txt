Search the documentation of Stable-Baselines3 (SB3), the PyTorch library of ready reinforcement learning algorithms, with
its companion packages sb3-contrib (experimental algorithms) and RL Baselines3 Zoo (training scripts and tuned
hyperparameters). The corpus holds the stable-baselines3.readthedocs.io site of every minor line 0.11-2.9 (the user
guide, a page for every algorithm, the common modules, the changelog), the sb3-contrib site 1.0-2.9, the RL Zoo site
1.8-2.9, the GitHub release notes and the PyPI records of all three packages.

Use this tool for: the algorithms `PPO`, `A2C`, `DQN`, `SAC`, `TD3`, `DDPG`, `HER` and their parameters
(`learning_rate`, `n_steps`, `batch_size`, `gamma`, `gae_lambda`, `clip_range`, `ent_coef`, `buffer_size`,
`exploration_fraction`, `policy_kwargs`), `model.learn` (`total_timesteps`, `callback`, `reset_num_timesteps`),
`predict` (`deterministic`), `save` and `load`, custom policies and feature extractors (`net_arch`,
`BaseFeaturesExtractor`), callbacks (`EvalCallback`, `CheckpointCallback`, `StopTrainingOnRewardThreshold`), vectorized
environments (`make_vec_env`, `DummyVecEnv`, `SubprocVecEnv`, `VecNormalize`, `VecFrameStack`), `check_env`, `Monitor`,
`evaluate_policy`, TensorBoard logging, exporting a policy to ONNX, the tips for training and for custom environments;
from sb3-contrib: `MaskablePPO` (invalid action masking), `RecurrentPPO` (LSTM), `QRDQN`, `TQC`, `TRPO`, `ARS`,
`CrossQ`; from RL Zoo: `train.py`, the hyperparameter YAML files, tuning with Optuna. Write the query in English, with
the name of the class, function or parameter, such as `PPO clip_range` or `VecNormalize`. Give a version in the filter
when the answer depends on it: SB3 2.0 moved from Gym to Gymnasium.

Do not use it for the Gymnasium API itself, for the theory of reinforcement learning or for PyTorch: other servers hold
them. The lines 0.6-0.10 and several lines between 1.0 and 1.4 have no site folder and are covered only by the PyPI
records and the release notes. Returns the matching excerpts with the versions each one applies to, the source address
and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
