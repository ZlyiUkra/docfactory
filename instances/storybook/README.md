# storybook — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Storybook — майстерню для розробки, документування й тестування
UI-компонентів окремо від застосунку — за офіційною документацією останньої мінорної кожної мажорної версії: 6.5, 7.6,
8.6, 9.1 і поточної 10.x. Сторінки документації з прикладами коду всіх фреймворків, README кожної лінії, рецепти
інтеграцій сайту storybook.js.org, посібник з переходу між версіями, журнали змін, релізи латок і історія пакета
`storybook` у реєстрі npm. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає
самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо сторінки з репозиторію, а не з сайту

Сайт storybook.js.org віддає markdown-двійник кожної сторінки (адреса з «.md»), але цей двійник губить код: JSX у
прикладах він зрізає як розмітку. У прикладі декоратора з нього зникають усі `import` і рядок `<Story />` — тобто
саме те, заради чого приклад написано. До того ж сайт тримає лише три останні лінії (8, 9, 10): документації 6.5 і
7.6 там уже немає, стара адреса перекидає на поточну версію.

Тому сторінки беруться з теки `docs/` репозиторію storybookjs/storybook, з гілок випусків. Приклади коду лежать там
окремими файлами `docs/_snippets/<ім'я>.md`, і сторінка лише посилається на них тегом `<CodeSnippets path="…" />`.
Новий читач `storybook-docs` (`engine/readers/sbdocs.py`) вставляє кожен приклад на місце тега:

- **кожен фреймворк** — React, Vue, Angular, Svelte, Web Components, Solid, Preact, HTML, Ember і спільні для всіх;
- **TypeScript**; JavaScript лишається лише там, де варіанта TypeScript немає;
- **кожна вкладка** — CSF 3, CSF Next, Svelte CSF — і **кожен менеджер пакетів** — npm, yarn, pnpm.

Перед кожним прикладом стоїть підпис з іменем файла й атрибутами: «`Button.stories.ts|tsx` (react, TS, CSF 3):».
Без нього двадцять однакових на вигляд прикладів сторінки не казали б, до якого фреймворку кожен. Текст, який сайт
показує лише для деяких фреймворків (`<If renderer="…">`), береться весь, з підписом «Only for react:» чи «Not for
angular:». Чернетки (`draft: true`) і сторінки розділів, що мають лише назву, не беруться.

Лінію 10.x встановлюють найчастіше. За тиждень до 11.10.2026 розподіл завантажень `@storybook/react` такий:

| Лінія | Частка |
|-------|-------:|
| 10 | 70 % |
| 8 | 18 % |
| 9 | 6,4 % |
| 7 | 2,9 % |
| 6 | 2,2 % |

Пакета `storybook`: лінія 10 — 72,5 %, лінія 8 — 18,4 %. Тому лінія за замовчуванням у промптах — 10.x.

Разом 1 119 документів; фрагментів в індексі — 9 309 (`expected_passages` у `checks.json`). Однаковий текст сторінки
кількох версій лежить одним фрагментом з переліком усіх версій.

**Замір `quality`** на першому корпусі: по словах 7 із 10, за змістом 9, разом 9; десятка «як модель» — 10 із 10.

Перша десятка — переказ питання своїми словами. Промах один: на «show a dropdown to pick a prop value in the controls
panel» жоден спосіб не приносить таблиці типів контролів (`essentials-controls`, «Annotation») чи
`argTypes.control`. Приходять сусідні розділи сторінки Controls: «Dealing with complex values» і параметр
`expanded`. По словах бракує ще двох влучань: на «click a button and type into a field…» приходять сторінки
end-to-end тестів, на «replace an imported module…» — питання FAQ про TanStack React і конфіг Webpack.

Десятка «як модель» — запити назвами API, як велить промпт, з `version "10"` (питання про історію й рецепт — без
версії). На першому замірі вона дала 8 із 10, через формулювання запитів, а не через корпус:

- «autodocs tags» приносило сторінку Tags, а не Autodocs; запит «autodocs» приносить Autodocs першою;
- голе «addon-vitest» приносило приклади конфігу аддона, а не розділ «Usage» (CLI, CI); запит «Vitest addon run
  tests CLI CI» його приносить.

Поле `max_per_doc` заміряно 0/1/2/3. Перша десятка разом — 9/8/9/9, «як модель» — 8/8/8/8 (на запитах до
виправлення). Поле не ввімкнено.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, перейменування сторінок, що
  переїхали, і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df storybook <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сторінки документації п'яти ліній і README.md кожної гілки | дерева гілок через GitHub API, текст — `raw.githubusercontent.com` | `storybook-docs` |
| рецепти | sitemap.xml розділу `/recipes` і HTML кожної сторінки | `sitemap-html` |
| посібник з переходу | `MIGRATION.md` гілки `main` | `storybook-migration` |
| журнали змін | `CHANGELOG.md` і `CHANGELOG.v6.md` гілки `main` | `changelog-v` |
| релізи латок | релізи GitHub, лише перелічені в полі `skip` | `ghreleases` |
| реєстр npm | registry.npmjs.org, одне звернення | `npm-versions` |

Примірник додав два читачі в `engine/readers/sbdocs.py`:

- **`storybook-docs`** — сторінки MDX з прикладами на місці, як описано вище. Поле `refs` задає «гілка → версія»,
  поле `site` — шаблон адреси сторінки на сайті для гілок, які сайт ще віддає.
- **`storybook-migration`** — MIGRATION.md, одна секція «## From version A to B» — один документ з версією B. Зміст
  на початку файла (тисяча рядків посилань на всі секції) не береться: інакше він дав би десятки фрагментів-змістів,
  що відгукуються на будь-яку назву API.

Особливості, які варто знати:

- **Адреси.** Сторінки 8.6, 9.1 і 10.x ведуть на сайт (`storybook.js.org/docs/8/…`, `/docs/9/…`, `/docs/10/…`).
  Сторінки 6.5 і 7.6 ведуть на файл на GitHub: на сайті їх уже немає.
- **Сторінки, що переїхали.** Між версіями частина сторінок змінила шлях: `writing-tests/test-runner` →
  `writing-tests/integrations/test-runner`, `writing-tests/test-addon` → `writing-tests/integrations/vitest-addon`,
  `writing-docs/doc-blocks/*` → `api/doc-blocks/*`, `migration-guide` → `releases/migration-guide` та інші, десять
  правил. Поле `slug_rewrite` у `config.json` зводить старий шлях до нового ключа, і незмінні розділи зливаються.
- **Рецепти — без версії.** Сайт їх не версіонує; частина написана ще для 7.x, і рецепт так і каже
  («Storybook >=7.0»). Порожній `<div>` перед текстом заголовка (якір прокрутки сайту) вирізається полем `drop`:
  інакше номер і назва кроку відривалися від «##». MSW окремим рецептом сайт не має — його покриває сторінка
  документації «Mocking network requests».
- **Латки без журналу.** Журнали змін закінчуються на 7.6.20, 8.6.14 і 9.1.16. Латки березня 2026 (перевірка запитів
  dev-сервера) записано лише в релізах GitHub, і їх узято звідти. У 7.6.22 релізу немає — вона є лише в реєстрі npm.
- **Передрелізи не беруться** — ні з журналів (alpha, beta, rc 7.0 там злиті з записом 7.0.0), ні з реєстру. Пакет
  `storybook` до 7.0 був лише обгорткою CLI; версії 0.x, 1.x і 5.x реєстр показує, але вони не беруться.

## Межі, про які треба пам'ятати

Chromatic як продукт, блог Storybook, каталог сторонніх аддонів, туторіали storybook.js.org/tutorials і внутрішня
будова Vite, Webpack, Vitest, Playwright, Jest чи MSW тут не беруться. Документацію MSW, Vitest, Playwright і Testing
Library мають окремі примірники `msw`, `vitest`, `playwright`, `testing-library`. Мінорні лінії між останніми (6.0–6.4,
7.0–7.5, 8.0–8.5, 9.0, 10.0–10.5) окремих знімків документації не мають: що змінювалося в них, кажуть журнали змін і
MIGRATION.md.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/storybook-corpus-2026-10-11.tar.gz` (1 119 текстів і паспорт; перед
видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде. Архів
лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/storybook-corpus-2026-10-11.tar.gz -C instances/storybook
./df storybook smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/storybook/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/storybook-corpus-РРРР-ММ-ДД.tar.gz -C instances/storybook corpus
find instances/storybook/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/storybook/index/passages.json > instances/storybook/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/storybook/index/passages.json.gz`,
далі `./df storybook vectors` заллє колекцію Qdrant (~20 хвилин).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df storybook …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/storybook/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df storybook sources --why   # перелік джерел і білий список
./df storybook refresh         # завантажити все задеклароване (~30 хвилин)
./df storybook manifest        # оновити паспорт
./df storybook setup           # Qdrant чи пошук лише по словах
./df storybook vectors         # залити корпус у docs-storybook (~20 хвилин)
./df storybook smoke           # перевірки
```

Перші ~5 хвилин `refresh` журнал мовчить, а `corpus/` порожній. За цей час читач проходить дерева п'яти гілок і
читає кожну сторінку, щоб відкинути чернетки.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df storybook serve          # порт 8821
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8821/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user storybook-docs http://127.0.0.1:8821/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `storybook-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
