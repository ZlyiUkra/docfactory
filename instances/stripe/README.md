# stripe — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Stripe — прийом платежів, підписки, рахунки, податки, Connect,
виплати й гроші в коді. Документація — сайт docs.stripe.com цілком англійською: посібники з усіма варіантами
інтеграцій (Checkout, Elements, мобільні iOS і Android, Direct API) і прикладами сервера сімома мовами, довідник API,
журнал змін API, довідник Stripe.js; повна специфікація OpenAPI (v1 і v2) — кожен ресурс і кожен об'єкт з типами
полів; для кожного стабільного випуску SDK Node.js, Stripe.js, React Stripe.js, React Native і Connect.js — README і
MIGRATING з репозиторію, для SDK Python, Go, Ruby, Java, .NET, PHP, CLI, iOS і Android — те саме з останнього тегу
кожної мінорної лінії; нотатки релізів усіх п'ятнадцяти репозиторіїв; код найновіших JS-SDK; таблиці версій з npm,
PyPI, RubyGems, Packagist, NuGet, Maven і CocoaPods. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Примірник зібрано під фінансові розрахунки в наших програмах: суми в найменших одиницях валюти, валюти без дробової
частини, мінімальні суми платежу, пропорційні нарахування підписок, заокруглення податку, комісії й курси в
`balance_transaction`, часткові повернення, графік виплат. Тому десять питань заміру — саме про гроші. Stripe
міняє API щомісяця (версії на зразок `2025-03-31.basil`, `2026-09-30.endive`), а SDK мають власну нумерацію:
stripe-node дійшов до 23.0, stripe-go — до 87.0. Сайт показує лише поточний стан, а в проєктах живуть різні версії
SDK і API — тут кожна версія API має свої записи журналу змін, а кожен випуск SDK — свою редакцію README, нотатки
релізу і рядок у таблиці версій реєстру.

## Що в цій теці

- `corpus/` — паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа. Самих текстів тут немає:
  корпус в архіві.
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`.
- `sources.json` — звідки корпус будується (56 джерел), і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — токен GitHub і, для кроку `ask`, ключ Anthropic; `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики через `./df stripe <крок>`.

Новий код для stripe — чотири читачі:

- **`stripe-md`** бере сторінки з sitemap.xml, текст — з markdown-двійника сторінки (та сама адреса з «.md»). Код
  сервера на сторінці Stripe показує мовою, яку вибрав читач, а двійник віддає одну мову за запитом `?lang=`. Тому
  сторінку з серверним кодом читач бере сім разів (`node`, `python`, `go`, `ruby`, `java`, `dotnet`, `cli`) і зводить
  в один документ: текст основної мови (Node.js) один раз, а під кожним розділом — блоки коду інших мов з підписом
  («Python:»). Розділи, яких в основній мові немає (установка пакета Python), стають на своє місце. Сторінка, що є
  лише переліком варіантів («This article has multiple variants»), заміняється самими варіантами: кожен — окремий
  документ з назвою «Build a subscriptions integration (Checkout: Stripe-hosted page)». Записи журналу змін
  дістають версію API з адреси: `/changelog/basil/2025-03-31/…` → `api-2025-03-31.basil`.
- **`openapi-stripe`** — документ на кожен ресурс API (шлях до першої змінної частини: `/v1/charges`,
  `/v2/core/accounts`) з розділом на операцію (параметри, поля тіла форми з вкладеними на один рівень, що повертає) і
  документ на кожну схему — «Object: balance_transaction (OpenAPI)»: опис, усі поля з типами, nullable і повними
  переліками значень enum, розгортувані поля. Спільний читач `openapi` групує операції за тегами, а Stripe тегів не
  ставить.
- **`ghraw-history`** — кілька відомих файлів (README, MIGRATING, CONTRIBUTING) з кожного тегу напряму через
  raw.githubusercontent.com. Дерев тегів через API не бере: стабільних тегів у SDK Stripe понад шість тисяч, а
  година API з токеном — п'ять тисяч звернень, і дерева stripe-ios та stripe-java GitHub ще й обрізає. Однаковий
  вміст на кількох тегах — один документ з усіма їхніми версіями.
- **`pkg-registry`** — таблиця версій пакета з реєстрів інших мов: огляд (найновіша стабільна, скільки версій у
  кожній мажорній лінії) і розділ на мажорну лінію з датою кожної версії й вимогами (Ruby, PHP і розширення,
  цільові платформи .NET).

Особливості:

- **Мітки версій.** Кожен SDK має власну нумерацію, тож версія несе його назву: `node-23.0.0`, `stripe-js-10.1.0`,
  `react-stripe-js-7.0.0`, `react-native-0.82.0`, `connect-js-3.4.6`, `react-connect-js-3.4.4`, `python-16.0.0`,
  `go-87.0.0`, `ruby-20.0.0`, `java-34.0.0`, `dotnet-53.0.0`, `php-22.0.0`, `cli-1.54.0`, `ios-26.14.0`,
  `android-23.23.0`. Версія API — `api-2026-09-30.endive` в OpenAPI, а в журналі змін — версія самого запису, від
  `api-2011-06-21` до `api-2026-08-26.dahlia`. Лінії мінорні (`version_line_depth: 2`): `node-23.0`. Посібники
  сайту версій не мають.
- **Скільки тегів.** JS-стек — кожен стабільний тег (stripe-node 0.0.2–23.0.0, 595 тегів). Інші SDK — останній тег
  кожної мінорної лінії: stripe-go має 705 таких ліній, stripe-java — 601, stripe-dotnet — 607. README stripe-java
  дав 599 документів: у кожному стоїть номер версії, тож вміст різний на кожній лінії.
- **Сайтмап несе частину сторінок двічі** — звичайною адресою і з «.md» (359 сторінок, серед них `/cli/…`): читач
  зводить їх в одну сторінку.
- **Довідник Stripe.js** має ще й сторінку `/js`, що містить увесь довідник на одній сторінці (1 086 фрагментів); її
  залишено як є.
- **Імена документів.** Сайт — шлях сторінки, варіант — шлях плюс значення параметрів
  (`billing-subscriptions-build-subscriptions-checkout-stripe-hosted`); журнал змін —
  `changelog-basil-2025-03-31-deprecate-subscription-current-period-start-and-end`; OpenAPI —
  `openapi-v1-charges`, `object-balance-transaction`; репозиторії — з назвою репозиторію (`stripe-node-readme`).
- **Запити `quality`** записано так, як їх ставить модель за промптом: назва з документації, далі опис. Трьом
  запитам додано справжні відповіді, яких не було в першій чернетці цілей: сторінку об'єкта довідника API
  (`api-balance-transactions-object`), параметри створення повернення (`api-refunds-create#parameters`) і запис
  журналу змін basil цілком, бо весь він про одну зміну.

## Межі, про які треба пам'ятати

- Сайт — англійською. Переклади сайту не взято.
- Код на сторінках сайту — сімома мовами: Node.js, Python, Go, Ruby, Java, .NET і Stripe CLI. PHP і curl не взято:
  PHP дають README, релізи й Packagist, curl — довідник API. Нативний код iOS і Android приходить варіантами
  сторінок («Mobile: iOS»), а не параметром мови.
- Код — лише JS-SDK найновіших тегів, без тестів. Код SDK інших мов не взято: методи дають довідник API й OpenAPI.
- Лише стабільні випуски: альфи, беты, rc і передрелізи з дефісом у номері не взято, у таблицях реєстрів їх лише
  пораховано.
- Не взято: документацію Dokka stripe-android, довідники stripe.dev, pkg.go.dev (теги й релізи stripe-go дають те
  саме), блог stripe.com. У Maven дат випуску немає — лише перелік версій.
- Варіант Checkout «Stripe-hosted page» сторінки build-subscriptions майже порожній на боці Stripe: вступ і заголовок.

## Архівний режим: сервер без корпусу

Корпус в архіві від самого початку: у `corpus/` лежить лише паспорт, а сервер підіймається з кешу фрагментів і
колекції Qdrant; відповіді ті самі до символа.

**Де тексти.** В архіві `~/archives/docfactory/stripe-corpus-2026-10-18.tar.gz` (106 МБ: 14 499 текстів, паспорт і
сховище сирого `raw/`; перед видаленням розпакований окремо й звірений з диском — нуль розбіжностей). Лише на цій
машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
tar -czf ~/archives/docfactory/stripe-corpus-РРРР-ММ-ДД.tar.gz -C instances/stripe corpus raw
find instances/stripe/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/stripe/raw
gzip -9 -c instances/stripe/index/passages.json > instances/stripe/index/passages.json.gz
```

**Як повернути тексти** — перед будь-яким оновленням:

```
tar -xzf ~/archives/docfactory/stripe-corpus-2026-10-18.tar.gz -C instances/stripe
./df stripe smoke
```

**Оновлення.** Новий випуск SDK дописують першим рядком у `tags` його джерела сторінок («"v23.1.0": "node-23.1.0"»
у `node-docs`), а для JS-SDK переносять на новий тег і код (`node-code` та інші `-code`). Сайт, довідник API,
журнал змін, OpenAPI, релізи й реєстри підхоплюються самі. Далі `./df stripe refresh`, `manifest`, `vectors`,
`smoke`, `quality`. Оновлення сайту — це повний перепрохід усіх сторінок кожною мовою (близько 2 годин), а вектори
змінених сторінок рахуються заново.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають. Для роботи сервера збирати нічого не
треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df stripe sources --why   # перелік джерел і білий список
./df stripe refresh         # завантажити все задеклароване (близько 3 годин)
./df stripe manifest        # оновити паспорт
./df stripe setup           # Qdrant чи пошук лише по словах
./df stripe vectors         # залити корпус у docs-stripe (близько 4,5 години)
./df stripe smoke           # перевірки
```

Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df stripe serve          # порт 8863
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8863/mcp`. Якщо порт зайнятий,
сервер скаже про це й вийде: значить, `serve` цього примірника вже десь запущений; хто тримає порт, покаже
`ss -ltnp | grep 8863`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user stripe-docs http://127.0.0.1:8863/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User).

**3. Перевірити.** `/mcp` — має бути `stripe-docs` і два інструменти `search_docs`, `read_section`. Якщо
`/mcp` показує `failed`, сервер не запущено або запущено з іншим портом.

Зупинка — Ctrl+C у терміналі сервера.
