Search the Stripe documentation, in English: the whole site docs.stripe.com and the official SDKs. The set holds the
guides (payments and the Payment Intents API, Checkout, Elements and the Payment Element, payment methods, mobile
payments on iOS, Android and React Native, Billing and subscriptions, Invoicing, Connect for platforms and
marketplaces, Tax, Revenue Recognition, Radar, Terminal, Issuing, Treasury, currencies and amounts in the smallest
currency unit, fees, refunds, disputes, payouts, balances, reports, webhooks and events, testing and sandboxes,
the Stripe CLI, Stripe Apps), with server code in Node.js, Python, Go, Ruby, Java, .NET and the Stripe CLI side by
side and every integration variant (Checkout, Elements, iOS, Android, React Native) as its own page; the API
reference (every endpoint and object of API v1 and v2 with parameters, returns and examples); the API changelog
with every change of every dated API version; the Stripe.js reference; the OpenAPI specification (one document per
resource and per object schema with exact types, nullable fields and enum values); for every stable release the
README of stripe-node, @stripe/stripe-js, @stripe/react-stripe-js, @stripe/stripe-react-native, Connect.js, and of
the Python, Go, Ruby, Java, .NET, PHP, CLI, iOS and Android SDKs, with their GitHub release notes; the source code
and types of the newest JavaScript SDKs; version tables from npm, PyPI, RubyGems, Packagist, NuGet, Maven Central
and CocoaPods. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about Stripe: how to create a PaymentIntent, Checkout Session, Customer, Subscription,
Invoice, Price, Product, Refund, Payout or Transfer; what a parameter or object field means and what values it
takes (amount, currency, capture_method, payment_method_types, automatic_payment_methods, setup_future_usage,
proration_behavior, billing_cycle_anchor, application_fee_amount, transfer_data, metadata, idempotency key);
how amounts work in the smallest currency unit and which currencies are zero-decimal; what fees, taxes and
rounding apply; how webhooks, event types and signature verification work; how to handle declines, errors and
3D Secure; how stripe.confirmPayment, Elements and the React and React Native components work; what changed in an
API version and how to upgrade; what an SDK version requires and what changed between SDK versions. Example query:
"PaymentIntent capture_method manual".

Do not call this for other payment providers (PayPal, Adyen, Braintree, LiqPay), for accounting or tax law itself,
or for the Stripe Dashboard account settings of a particular business.

Write the query in English, with the names Stripe uses (PaymentIntent, checkout.sessions.create, payment_intent.succeeded,
application_fee_amount, Stripe-Version, stripe.confirmPayment). Everything here is English, and the word index keeps
only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing and comes back with `found: 0`. When the user asks in another language, translate the question into
Stripe terms first, then search. Name the language when the code matters ("in Python", "in Go", ".NET").

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its version
and the page it rests on; a point the excerpts do not support is left out, not guessed. When that language is
Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "найменша одиниця валюти", "повернення коштів",
"підписка". Never call this set of documents "корпус" -- say "документація Stripe". Object, field, parameter,
method and event names stay in English, spelled exactly as the documentation spells them. Build the answer out of
the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it before describing what
it says. Amounts, fees, limits and currency rules change: quote them from the excerpt, never from memory.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional.
Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase had a
chance.

Which version to answer for. The site pages, the API reference and Stripe.js carry no version: they are the
current state. The API changelog and the OpenAPI specification carry the dated API version ("api-2025-03-31.basil";
older ones without a name, "api-2020-08-27"). SDK documents carry versions named after their SDK: "node-23.0.0",
"stripe-js-10.1.0", "react-stripe-js-7.0.0", "react-native-0.82.0", "python-16.0.0", "go-84.4.0", "ruby-…",
"java-…", "dotnet-…", "php-…", "cli-…", "ios-…", "android-…". When the user names a version, pass its line into
`version` ("node-23.0", "python-16.0"); never put it into the query text. Without a version, answer for the current
site and the newest SDK release and say so.
