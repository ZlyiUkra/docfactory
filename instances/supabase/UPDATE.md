# Оновлення корпусу supabase

Дві різні роботи: звичайне оновлення і збирання примірника з нуля. Версійних ліній, знімків і заморожених джерел
тут немає — Supabase тримає одну, поточну документацію, — тож і правил про порядок знімків, як у `nestjs` чи
`astro`, теж немає.

Головне правило: **нічого не видаляється.** Якщо сторінка зникла з сайтмапу, її файл лишається в `corpus/` з тією
датою, коли його завантажено. Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі. Чи прибрати
застарілу сторінку — рішення людини, а не кроку.

## 1. Звичайне оновлення

Раз на кілька тижнів, або коли Supabase оголосив щось помітне.

```
./df supabase check                    # що нагорі змінилося за паспортом
./df supabase refresh                  # перечитати все задеклароване (~35 хвилин)
./df supabase manifest                 # оновити паспорт
./df supabase vectors                  # дорахувати лише змінені фрагменти
./df supabase smoke                    # звірити, що нічого не поїхало
```

Лише нові сторінки, наявних не чіпаючи: `./df supabase refresh --missing guides`. Лише налаштування:
`./df supabase refresh config-toml selfhost-auth selfhost-storage selfhost-realtime selfhost-analytics
selfhost-functions auth-readme`.

Після `refresh` число фрагментів зазвичай змінюється, і `smoke` про це скаже. Тоді треба оновити
`expected_passages` у `checks.json` і в полі `expected_note` записати, коли й чому число знято.

## Що робити, коли щось не так

- **`sitemap-md` каже «не знайдено жодної дозволеної сторінки».** Сайт переніс гайди з `/docs/guides/` або змінив
  формат сайтмапу. Звірити `within` джерела `guides` з адресами в `https://supabase.com/docs/sitemap.xml`.
- **Сторінка гайду «не схожа на документ» або «замість markdown прийшов HTML».** Сторінку перенесли й `.md` веде на
  оболонку сайту, або вона стала заглушкою. Документ не записується, наявний лишається як був — так і задумано.
- **`config-spec` каже «не схоже на configspec» чи 404.** Supabase перейменував або переніс YAML у
  `apps/docs/spec/`. Знайти новий файл у репозиторії й виправити `url` у `sources.json`.
- **Збій `guides--docs-guides-getting-started-features`: редирект поза оголошенням.** Очікуваний і постійний: гайд
  переадресовує на `supabase.com/features`, а цей зміст бере джерело `features`. Нічого робити не треба.
- **У `llms.txt` з'явилася нова мова SDK.** Додати джерело `ref-<мова>` за зразком наявних: читач `mdfile`, `url` —
  `https://supabase.com/llms/<мова>.txt`, `page` — `https://supabase.com/docs/reference/<мова>/introduction`.
