Administration APIs requiring elevated access.

## POST /invite

Invite a user by email.

Sends an invitation email which contains a link that allows the user to sign-in.

Security: APIKeyAuth

Request body (application/json):

- `email` `string`, required
- `data` `object`

Responses:

- `200`: An invitation has been sent to the user.
- `400`: HTTP Bad Request response. Can occur if the passed in JSON cannot be unmarshalled properly or when CAPTCHA verification was not successful. In certain cases can also occur when features are disabled on the server (e.g. sign ups). It may also mean that the operation failed due to some constraint not being met (such a user already exists for example).
- `422`: User already exists and has confirmed their address.

## POST /admin/generate_link

Generate a link to send in an email message.

Security: APIKeyAuth, AdminAuth

Request body (application/json):

- `type` `string, one of magiclink, signup, recovery, email_change_current, email_change_new`, required
- `email` `string`, required
- `new_email` `string`
- `password` `string`
- `data` `object`
- `redirect_to` `string`

Responses:

- `200`: User profile and generated link information.
- `400`: HTTP Bad Request response. Can occur if the passed in JSON cannot be unmarshalled properly or when CAPTCHA verification was not successful. In certain cases can also occur when features are disabled on the server (e.g. sign ups). It may also mean that the operation failed due to some constraint not being met (such a user already exists for example).
- `401`: HTTP Unauthorized response.
- `403`: HTTP Forbidden response.
- `404`: There is no such user.
- `422`: Has multiple meanings: - User already exists - Provided password does not meet minimum criteria - Secure email change not enabled

## POST /admin/oauth/clients

Register OAuth client (admin)

Manually register a new OAuth client (admin endpoint). Only available when OAuth server is enabled.

Security: APIKeyAuth, AdminAuth

Request body (application/json):

- `client_name` `string`, required: Human-readable name of the client application
- `client_uri` `string`: URL of the client application's homepage
- `logo_uri` `string`: URL of the client application's logo
- `redirect_uris` `array of string`, required: Array of redirect URIs used by the client (maximum 10)
- `client_type` `string, one of public, confidential`: Type of the client. Optional. If not provided, will be inferred from token_endpoint_auth_method or defaults to 'confidential'. Public clients are used for applications that cannot securely store credentials (e.g., SPAs, mobile apps). Confidential clients can securely store credentials (e.g., server-side applications).
- `token_endpoint_auth_method` `string, one of none, client_secret_basic, client_secret_post`: Authentication method for the token endpoint. Optional. 'none' is for public clients, 'client_secret_basic' and 'client_secret_post' are for confidential clients. If provided, must be consistent with client_type. If not provided, will be inferred from client_type.
- `grant_types` `array of string, one of authorization_code, refresh_token`: OAuth grant types the client will use (defaults to both if not specified)
- `response_types` `array of string, one of code`: OAuth response types the client can use
- `scope` `string`: Space-separated list of scope values

Responses:

- `201`: OAuth client created
- `400`: HTTP Bad Request response. Can occur if the passed in JSON cannot be unmarshalled properly or when CAPTCHA verification was not successful. In certain cases can also occur when features are disabled on the server (e.g. sign ups). It may also mean that the operation failed due to some constraint not being met (such a user already exists for example).
- `401`: HTTP Unauthorized response.
- `403`: HTTP Forbidden response.

## POST /admin/custom-providers

Create a new custom OIDC/OAuth provider

Creates a new custom OAuth 2.0 or OIDC provider configuration. Required fields differ based on provider_type. Only available when custom OIDC/OAuth providers are enabled. For OIDC providers, the server fetches and validates the OpenID Connect discovery document from the issuer's well-known endpoint (or the provided discovery_url) at creation time. This ensures the issuer is reachable and correctly configured before the provider is stored.

Security: APIKeyAuth, AdminAuth

Request body (application/json):

- `provider_type` `string, one of oauth2, oidc`, required: Type of OAuth provider
- `identifier` `string`, required: Unique identifier (will be prefixed with 'custom:' automatically). Cannot use reserved provider names.
- `name` `string`, required: Human-readable display name
- `client_id` `string`, required: OAuth client ID from the provider
- `client_secret` `string`, required: OAuth client secret (will be encrypted at rest)
- `acceptable_client_ids` `array of string`: Additional acceptable client IDs for token validation
- `scopes` `array of string`: OAuth scopes to request (OIDC providers will automatically include 'openid')
- `pkce_enabled` `boolean`: Enable PKCE (Proof Key for Code Exchange)
- `attribute_mapping` `object`: Map provider claims to user attributes (cannot map to protected system fields)
- `custom_claims_allowlist` `array of string`: Raw IdP claim keys to copy verbatim into the user's custom_claims (e.g. groups, org_id). For OIDC providers these are read from the ID token claims (falling back to the userinfo response when no ID token is returned); for OAuth2 providers they are read from the userinfo response. Empty preserves no non-standard claims.
- `authorization_params` `object`: Additional authorization request parameters as string key-value pairs (cannot override reserved OAuth parameters)
- `enabled` `boolean`: Whether the provider is enabled
- `email_optional` `boolean`: Whether email is optional for users from this provider
- `issuer` `string`: OIDC issuer URL (required for provider_type: oidc)
- `discovery_url` `string`: OIDC discovery URL (optional for OIDC, defaults to {issuer}/.well-known/openid-configuration)
- `skip_nonce_check` `boolean`: Skip nonce validation for OIDC (not recommended for production)
- `authorization_url` `string`: OAuth 2.0 authorization endpoint (required for provider_type: oauth2)
- `token_url` `string`: OAuth 2.0 token endpoint (required for provider_type: oauth2)
- `userinfo_url` `string`: OAuth 2.0 userinfo endpoint (required for provider_type: oauth2)
- `jwks_uri` `string`: JWKS URI for token validation (optional for OAuth2)

Responses:

- `201`: Custom OIDC/OAuth provider created successfully
- `400`: Bad request - validation failed, provider exists, or quota exceeded
- `401`: HTTP Unauthorized response.
- `403`: HTTP Forbidden response.

## PUT /admin/custom-providers/{identifier}

Update custom OIDC/OAuth provider

Updates an existing custom OIDC/OAuth provider. All fields are optional. Only provided fields will be updated. Only available when custom OIDC/OAuth providers are enabled. When `issuer` or `discovery_url` is changed on an OIDC provider, the server re-fetches and validates the discovery document before persisting.

Security: APIKeyAuth, AdminAuth

Parameters:

- `identifier` (path, required) `string`: Provider identifier (must start with 'custom:' prefix)

Request body (application/json):

- `name` `string`: Human-readable display name
- `client_id` `string`: OAuth client ID
- `client_secret` `string`: OAuth client secret (only provide if changing, will be encrypted)
- `acceptable_client_ids` `array of string`: Additional acceptable client IDs
- `scopes` `array of string`: OAuth scopes to request
- `pkce_enabled` `boolean`: Enable PKCE
- `attribute_mapping` `object`: Map provider claims to user attributes
- `custom_claims_allowlist` `array of string`: Raw IdP claim keys to copy verbatim into the user's custom_claims (e.g. groups, org_id). For OIDC providers these are read from the ID token claims (falling back to the userinfo response when no ID token is returned); for OAuth2 providers they are read from the userinfo response. Empty preserves no non-standard claims.
- `authorization_params` `object`: Additional authorization request parameters as string key-value pairs
- `enabled` `boolean`: Whether the provider is enabled
- `email_optional` `boolean`: Whether email is optional
- `issuer` `string`: OIDC issuer URL (for OIDC providers)
- `discovery_url` `string`: OIDC discovery URL (for OIDC providers)
- `skip_nonce_check` `boolean`: Skip nonce validation for OIDC
- `authorization_url` `string`: OAuth 2.0 authorization endpoint (for OAuth2 providers)
- `token_url` `string`: OAuth 2.0 token endpoint (for OAuth2 providers)
- `userinfo_url` `string`: OAuth 2.0 userinfo endpoint (for OAuth2 providers)
- `jwks_uri` `string`: JWKS URI for token validation (for OAuth2 providers)

Responses:

- `200`: Custom OIDC/OAuth provider updated successfully
- `400`: Invalid identifier, validation failed, or OIDC discovery validation failed
- `401`: HTTP Unauthorized response.
- `403`: HTTP Forbidden response.
- `404`: Provider not found
