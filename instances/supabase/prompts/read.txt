Return the full text of one excerpt of the Supabase documentation by its identifier,
together with the document it belongs to, the URL it was taken from and the date the
text was fetched from that URL -- so a quotation can be checked against the source even
a year later.

Call this after `search_docs` when the excerpt you need came back cut at 600
characters, or when the exact wording matters -- a configuration key, an environment
variable, a policy in SQL, a client call or a CLI command quoted half-way is how a wrong
answer starts. Configuration especially: key names, their nesting in `config.toml`,
defaults and which setting must be switched on together with which are the part a
summary gets wrong.

Do not guess identifiers: they are not URLs, not page names and cannot be assembled by
hand. Every identifier this tool accepts comes from the `id` field of a `search_docs`
result.

The text comes back in English, as the documentation is written. Answer the user in
their own language, and follow the same rules as for `search_docs`: keep identifiers,
keys and titles in English, use Ukrainian words for Ukrainian prose, and name the
document you read.
