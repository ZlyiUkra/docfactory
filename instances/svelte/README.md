# svelte — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Svelte — компілятор інтерфейсів (руни й реактивність, синтаксис
шаблонів, прив'язки, події, переходи й анімації, дії, сховища, контекст, спеціальні елементи, стилі, компілятор і
рантайм), а також про CLI `sv`, `@sveltejs/vite-plugin-svelte` і `svelte-check`. Документація — з тегу кожної
стабільної мінорної версії 3.0–5.57 і на кожен реліз 1.x–2.x. Джерела — репозиторії sveltejs/svelte,
sveltejs/v2.svelte.dev, sveltejs/svelte.dev, sveltejs/cli, sveltejs/vite-plugin-svelte, sveltejs/language-tools,
пакети й реєстр npm; лише англійською. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Svelte тричі міняв саму модель компонентів: Svelte 3 (2019) зробив реактивність частиною мови (`let`, `$:`),
Svelte 5 (2024) замінив її рунами (`$state`, `$derived`, `$effect`, `$props`), слоти — сніпетами, `on:click` —
атрибутами `onclick`. Документація змінювалася разом із ним: у 3.x — кілька великих сторінок у `site/content/docs`, у
4.x — `documentation/docs`, у 5.x — десятки сторінок із власною розкладкою, а підручник Svelte 5 переїхав у репозиторій
сайту svelte.dev. Код Svelte 4 досі пишуть (12 % завантажень), тож відповідь мусить знати, до якої версії вона.

**Що є що.** **Руна** — вбудований у компілятор символ із `$` (`$state`, `$derived`), що робить змінну реактивною;
**сніпет** — шматок розмітки, який передають і рендерять (`{#snippet}`, `{@render}`); **дія** (action) — функція, що
отримує DOM-елемент (`use:`). **sv** — офіційний CLI (`sv create`, `sv add`, `sv migrate`); **vite-plugin-svelte** —
плагін компіляції для Vite; **svelte-check** — перевірка типів і діагностика з командного рядка.

## Звідки документація

- **Сайт з тегів.** Документація Svelte живе в репозиторії самого компілятора, тож читач `ghdocs-history` бере її з
  останнього тегу кожної мінорної (`v3.x.y`, далі `svelte@4.x.y` і `svelte@5.x.y`). Підручник і FAQ беруться тієї ж
  версії; блог — лише зі svelte.dev, де він зібраний увесь.
- **Ключі сторінок.** Сайт тримає номери впорядкування в іменах тек і файлів (`03-template-syntax/09-const.md`) і
  міняє їх між версіями; `slug_rewrite` у `config.json` прибирає номери й зводить `site/content/` 3.x до
  `documentation/`, щоб редакції тієї самої сторінки різних версій зливалися.
- **Svelte 1.x–2.x** — репозиторій v2.svelte.dev без тегів, читач `ghsite-dated` (знімок на мить перед наступним
  релізом), `families` збирає його з документацією 3.x–5.x в одну родину джерел.
- **svelte.dev сьогодні** — один знімок без версії: підручник Svelte 5 (частини «Basic Svelte» і «Advanced Svelte»),
  блог з 2016 року, приклади й розділ AI. Порожні сторінки-змісти (`index.md` лише з назвою) не пишуться.
- **sv, vite-plugin-svelte, svelte-check** мають власну нумерацію: версії їхніх документів несуть префікс
  (`sv-1.1.1`, `vite-plugin-svelte-7.3.1`, `svelte-check-4.7.7`), інакше фільтр «5» змішав би їх зі Svelte 5.
- **Журнали.** Журнали Changesets svelte (`CHANGELOG.md` з 5.0 і `CHANGELOG-pre-5.md` до неї), sv і
  vite-plugin-svelte — читачем `changelog-named-prefixed` без передрелізів; svelte-check журналу не має — беруться його
  релізи GitHub.

## Межі, про які треба пам'ятати

- Документації 0.x у репозиторіях немає; посібник 1.x–2.x — лише сторінки `content/guide`.
- Розділ AI svelte.dev частково згенерований (підказки MCP-сервера) і дає кілька дуже довгих фрагментів.
- SvelteKit, адаптери й Sapper тут не входять; передрелізи (`5.0.0-next`) теж.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/svelte-corpus-2026-10-29.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\svelte-corpus-2026-10-29.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів немає
ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/svelte/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/svelte-corpus-РРРР-ММ-ДД.tar.gz -C instances/svelte corpus raw
find instances/svelte/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/svelte/raw
gzip -9 -c instances/svelte/index/passages.json > instances/svelte/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/svelte-corpus-2026-10-29.tar.gz -C instances/svelte
./df svelte smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/svelte/index/passages.json.gz`, далі
`./df svelte vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df svelte …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/svelte/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df svelte sources --why               # перелік джерел і білий список
./df svelte refresh                     # усе незакріплене: близько 30 хвилин мережею (паузи 0,1 с)
./df svelte refresh svelte-dev language-tools-docs   # закріплені джерела — лише названими
./df svelte manifest                    # оновити паспорт
./df svelte setup                       # Qdrant чи пошук лише по словах
./df svelte vectors                     # залити корпус у docs-svelte
./df svelte smoke                       # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df svelte serve              # порт 8931
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8931/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user svelte-docs http://127.0.0.1:8931/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `svelte-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
