Search the Svelte documentation and return the matching excerpts with the versions each one belongs to. What is
here: the documentation of Svelte (svelte.dev, repository sveltejs/svelte) at the last release of every minor
line 3.0 to 5.57 -- in Svelte 5 the runes ($state, $derived, $effect, $props, $bindable), template syntax,
special elements, styling, the runtime and the reference of compiler errors and warnings, in Svelte 3 and 4 the
docs pages, the FAQ and the tutorial of that version; the Svelte 1.x and 2.x guide (v2.svelte.dev) at every
stable release; from svelte.dev today, without a version: the Svelte 5 tutorial (Basic and Advanced Svelte), the
whole blog since 2016, the examples and the AI section (MCP server, llms.txt); the documentation of the sv CLI
(sv create, sv add, add-ons, sv migrate) and of @sveltejs/vite-plugin-svelte at the last release of every
minor line, and the language tools notes on preprocessors and TypeScript; the changelogs of svelte (all of it,
before and after 5.0), sv and vite-plugin-svelte and the release notes of svelte-check; the README of every
stable version and the npm registry history (versions, dates, dist-tags, peer dependencies, exports) of svelte,
sv, @sveltejs/vite-plugin-svelte and svelte-check.

Call this when a question is about Svelte itself: runes and reactivity ($state, $state.raw, $derived, $effect,
$effect.pre, $props, $bindable, $inspect, $host), .svelte and .svelte.js files, template syntax ({#if}, {#each},
{#await}, {#key}, {#snippet} and {@render}, {@html}, {@attach}, {@const}), bindings (bind:), event handlers,
transitions and animations (transition:, in:, out:, animate:), actions (use:), stores, context (setContext,
getContext), lifecycle (onMount, onDestroy, tick), special elements (svelte:window, svelte:head, svelte:element,
svelte:boundary), scoped styles and class:, the compiler (compile, preprocess, options), the client and server
runtime (mount, hydrate, render), custom elements, TypeScript, testing, Svelte 4 to 5 migration and the legacy
syntax (export let, $:, on:, slots, createEventDispatcher); the sv CLI, vite-plugin-svelte options and
svelte-check -- and history: since which version a feature exists, what changed in a release, how to migrate.

Do not call this for SvelteKit (routing, load functions, form actions, hooks, adapters, $app modules) -- it is
in the sveltekit-docs server of the same family -- nor for Sapper, React, Vue, Angular, Solid or other
frameworks, for Vite itself, for third-party Svelte libraries, or for TypeScript or JavaScript language
questions: their documentation is not here, and the search will return Svelte excerpts that merely mention
them, with confident-looking titles.

`version` narrows the search to one release line: "5.57" keeps every 5.57.x document of svelte, "5" every 5.x,
"4.2" the last Svelte 4 line; leave it empty to search everything. The other packages carry their own numbering
with a prefix, so they never mix with svelte: "sv-1.1", "vite-plugin-svelte-7", "svelte-check-4". Every excerpt
comes back with `versions`: each version whose documents contain this exact text, newest first, so the list
itself shows from which to which version the documentation said exactly this.

Write the query in English, with the names Svelte itself uses ("$derived", "{#snippet}", "bind:this",
"svelte:boundary", "createEventDispatcher"), not in the user's own words. Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and digits,
so a query written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes back
with `found: 0`. When the user asks in another language, translate the question into Svelte terms first, then
search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it
rests on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write
as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word
wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of
documents "корпус" -- say "документація Svelte". Identifiers, option names and titles stay in English, spelled
exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out of
memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated:
true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Svelte 5 carries about 85% of the weekly downloads (5.57 alone 40%), Svelte 4
(4.2) about 12%, Svelte 3 about 3%. Search with `version` "5.57" for a question about how to do something. If
the user names a version or writes Svelte 4 code (export let, $:, on:click, slots), search that line. Search
without `version` when the question is about history, about sv, vite-plugin-svelte or svelte-check (their
versions carry a prefix), about the tutorial or the blog (no version), or when the line gave nothing. Every
answer says which version it is for; when the user did not name one, answer for Svelte 5.57 and say so. When
the excerpts behind a statement come only from older versions, name those versions instead of presenting the
text as current.
