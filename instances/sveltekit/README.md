# sveltekit — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про SvelteKit — фреймворк застосунків на Svelte (маршрути й файли
`+page`/`+layout`/`+server`, функції `load`, form actions, параметри сторінок, хуки, помилки й переадресації, модулі
`$app` і `$env`, адаптери й розгортання), а також про адаптери, `@sveltejs/package`, `@sveltejs/enhanced-img` і
попередника SvelteKit — Sapper. Документація — з тегу кожної стабільної мінорної версії 1.0–3.1. Джерела —
репозиторії sveltejs/kit, sveltejs/svelte.dev і sveltejs/sapper, пакети й реєстр npm; лише англійською. Код спільний і
лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій
фабрики — у [../../README.md](../../README.md). Сам Svelte, CLI `sv`, vite-plugin-svelte і svelte-check — у примірнику
[`svelte`](../svelte/README.md) тієї самої родини Svelte.

## Навіщо окремий примірник

SvelteKit має власну нумерацію (1.0 у грудні 2022, 2.0 у грудні 2023, 3.0 у жовтні 2026) і власний обсяг: понад сто
мінорних версій, сім адаптерів, кожен зі своїми версіями. З нумерацією Svelte вона не збігається (SvelteKit 2 працює
і з Svelte 4, і з Svelte 5), тож у примірнику `svelte` вона змішалася б із версіями компілятора. Половина довідника —
сторінки модулів `$app/*`, `$env/*`, `@sveltejs/kit` — у репозиторії лише заглушки: текст генерується з типів.

**Що є що.** **Маршрут** — тека в `src/routes` з файлами `+page.svelte` (сторінка), `+page.js`/`+page.server.js`
(функція **`load`**, що готує дані) і `+layout.*` (обгортка); **form action** — серверний обробник форми в
`+page.server.js`; **хук** — функція в `hooks.server.js`, що бачить кожен запит (`handle`); **адаптер** — пакет, що
перетворює збірку на застосунок для конкретної платформи (Node, статичний хостинг, Vercel, Netlify, Cloudflare, Bun).
**Sapper** — попередник SvelteKit (0.x, 2018–2021), архівований.

## Звідки документація

- **Документація з тегів.** Читач `ghdocs-history` бере `documentation/docs` і `documentation/faq` репозиторію kit з
  останнього тегу `@sveltejs/kit@` кожної мінорної; `slug_rewrite` прибирає номери впорядкування з ключів сторінок.
- **Довідник модулів.** Сторінки `98-reference` і `99-legacy-reference` у репозиторії kit — заглушки; сайт генерує
  їхній текст з типів і з червня 2024 року кладе готовим у репозиторій svelte.dev (коміти «Sync kit docs»). Звідти їх
  бере `ghsite-dated` на мить перед кожним наступним релізом Kit; ключі сторінок ті самі, що в заглушок, а `families`
  збирає обидва джерела. Для версій до червня 2024 є лише заглушки.
- **Адаптери й пакети** мають власну нумерацію: версії їхніх документів несуть префікс (`adapter-node-5.4.0`,
  `package-2.5.0`, `enhanced-img-0.9.0`, `sapper-0.29.3`), інакше фільтр «2» змішав би їх із SvelteKit 2.
- **Журнали.** Журнали Changesets Kit, адаптерів, package, enhanced-img і журнал Sapper — читачем
  `changelog-named-prefixed` без передрелізів.

## Родина Svelte: піднімати разом

Цей примірник — частина родини Svelte: сам компілятор з CLI `sv` і SvelteKit, фреймворк застосунків на ньому. Сторінка
SvelteKit — це компонент Svelte (`+page.svelte`), а питання про `load` чи form actions часто закінчується в рунах і
синтаксисі шаблонів — і навпаки. Тому примірники родини піднімають у Claude Code разом, а `.mcp.json` цієї теки
перелічує обидва сервери: підключивши будь-який із них, Claude Code бачить решту.

| Примірник | Сервер | Порт | Що |
|-----------|--------|-----:|----|
| `svelte` | `svelte-docs` | 8931 | Svelte 1.x–5.57 (svelte.dev з тегу кожної мінорної), підручник, блог, CLI `sv`, vite-plugin-svelte, svelte-check |
| `sveltekit` | `sveltekit-docs` | 8932 | SvelteKit 1.0–3.1, довідник модулів, адаптери, `@sveltejs/package`, `@sveltejs/enhanced-img`, Sapper |

`prompts/loaded.txt` каже моделі, що цей набір — частина родини, і які сервери її доповнюють. Повний перелік родин — у
кореневому README.md, розділ «Родини примірників».

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/sveltekit-corpus-2026-10-29.tar.gz` (тексти, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\sveltekit-corpus-2026-10-29.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git
текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/sveltekit/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/sveltekit-corpus-РРРР-ММ-ДД.tar.gz -C instances/sveltekit corpus raw
find instances/sveltekit/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/sveltekit/raw
gzip -9 -c instances/sveltekit/index/passages.json > instances/sveltekit/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/sveltekit-corpus-2026-10-29.tar.gz -C instances/sveltekit
./df sveltekit smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/sveltekit/index/passages.json.gz`,
далі `./df sveltekit vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df sveltekit …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище». Свій `.env` примірник тримає в `instances/sveltekit/.env` (`cp .env.example .env`; для кроку
`ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df sveltekit sources --why               # перелік джерел і білий список
./df sveltekit refresh                     # усе незакріплене: близько 20 хвилин мережею (паузи 0,1 с)
./df sveltekit refresh svelte-dev-tutorial          # закріплене джерела — лише названими
./df sveltekit manifest                    # оновити паспорт
./df sveltekit setup                       # Qdrant чи пошук лише по словах
./df sveltekit vectors                     # залити корпус у docs-svelte
./df sveltekit smoke                       # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df sveltekit serve              # порт 8932
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8932/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user sveltekit-docs http://127.0.0.1:8932/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `sveltekit-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
