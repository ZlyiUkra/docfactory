# svg — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про сам формат SVG (Scalable Vector Graphics) за текстами його
специфікацій. Тут лежать SVG 2 у двох виданнях, SVG 1.1, модулі, куди SVG 2 виніс фільтри, маски, накладання,
перетворення й анімацію, чернетки робочої групи SVG і дві специфікації доступності. Усе лише англійською. Код спільний
і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій
фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

SVG — це мова, якою описують двовимірний векторний малюнок: фігури, контури, текст, заливку й обведення. Що саме
означає кожен елемент і атрибут, визначає **специфікація** — документ консорціуму W3C, за яким пишуть браузери й
редактори. Посібник (наприклад, на MDN) пояснює, як користуватися форматом. Специфікація відповідає на інше питання:
що формат вимагає. Вона каже, як саме рахується дуга еліпса в контурі, який елемент отримує клацання миші, коли фігури
перекриваються, і чим `viewBox` відрізняється від розміру малюнка.

Специфікація SVG існує в кількох виданнях одразу, і вони кажуть різне. Тому сервер мусить знати, з якого видання взято
кожен уривок.

| Видання | Що це | Мітка для пошуку |
|---------|-------|------------------|
| SVG 1.1 (друге видання) | остання повна рекомендація W3C, від 16.08.2011; описує ще й фільтри, маски, анімацію і шрифти SVG | `1.1` |
| SVG 2, знімок на w3.org | кандидат у рекомендації W3C, знімок від 06.10.2026; за ним браузери втілюють сучасні можливості | `2` |
| SVG 2, чернетка редакторів | той самий текст із правками, внесеними після знімка | `2.draft` |

SVG 2 не повторює всього, що було в SVG 1.1. За додатком «Changes from SVG 1.1» з нього прибрано розділи Filters,
Clipping and Masking, Animation, Fonts і Color: їхній зміст або перенесено в інші специфікації, або визнано
застарілим. Тому поруч із SVG 2 лежать модулі, що описують ці теми тепер. Без них питання про `feGaussianBlur`,
`clipPath`, `mask` чи `animateTransform` у поколінні SVG 2 лишилося б без відповіді.

**Що є що.** **Рекомендація** (Recommendation) — завершений стандарт W3C. **Кандидат у рекомендації** (Candidate
Recommendation) — текст, який робоча група вважає готовим і перевіряє втіленнями в браузерах. **Робоча чернетка**
(Working Draft) — опублікований проміжний стан. **Чернетка редакторів** (Editor's Draft) — поточний робочий текст,
який міняється будь-якого дня і ще не пройшов публікації. **Модуль** — окрема специфікація однієї теми (фільтри,
маски), спільна для SVG і CSS.

дата збирання сайту, а не останньої правки тексту. Тому «зібрана 20.11.2026» не означає, що текст змінився того дня.

опубліковану від дев'яти до дванадцяти років тому. Її не взято: чернетка редакторів — це робочий текст тієї самої
специфікації в сьогоднішньому стані. Ці п'ять специфікацій і SVG Native описують пропозиції, а не чинні правила, і
сервер каже про це у відповіді.

| лише `2.draft` | 571 | текст, який чернетка змінила чи додала, і специфікації, що існують лише чернеткою |
| лише `1.1` | 1 234 | текст SVG 1.1 |
| усі три мітки | 14 | фрагменти, які SVG 2 зберіг із SVG 1.1 дослівно |

**Замір 20.11.2026.** «Як модель» (десять запитів назвами елементів, атрибутів і властивостей, як їх ставить модель) —
10 з 10 з першого заміру. Десятка своїми словами: по словах 5, за змістом 8, разом 7 з 10. Питання своїми словами
важкі з тієї ж причини, що й у будь-якій специфікації: користувач описує бажаний вигляд («плавний перехід від кольору
до кольору»), а специфікація називає елемент (`linearGradient`).

## Звідки документація

- **Багатосторінкові видання SVG читає власний читач.** SVG 1.1, знімок SVG 2 і чернетка редакторів SVG 2 видані
  однаково: сторінка на кожен розділ, назва розділу в заголовку першого рівня. Читач `svg-chapters`
  (`engine/readers/svgspec.py`) бере зі змісту видання перелік сторінок і робить з кожної документ. Спільний читач
  `whatwg-html` для цього не годиться: він назвав би документ першим підрозділом («9.1. Introduction»), а не розділом
  («Paths»), і не записав би видання в шапку.
- **Специфікації однією сторінкою читає `spec-html-edition`.** Це той самий розбір, що й у `spec-html` примірника
  `webstandards`, з міткою видання в шапці документа. Він розуміє три способи верстки: Bikeshed (модулі CSS, SVG
  Native), ReSpec (SVG Strokes, SVG-AAM, Graphics Module) і власний інструмент робочої групи SVG (Animations, Markers,
  Paths, Integration).
- **Номери розділів лишилися тільки в назві документа.** Документ зветься «SVG 2: 9 Paths», а заголовки всередині
  нього номерів не мають: «Path data», а не «9.3 Path data». Причина в тому, що нумерація у виданнях різна. «Paths» —
  розділ 8 у SVG 1.1 і розділ 9 у SVG 2. У CSS Transforms властивість `transform` описує розділ 4 публікації і розділ
  3 чернетки. Пошук упізнає той самий розділ у різних виданнях за іменем документа і шляхом заголовків. З номером у
  заголовку один розділ трьох видань зайняв би три місця у видачі з трьох.
- **Формули записано текстом.** Перетворення координат, обчислення дуги еліпса й матриці фільтрів у специфікаціях
  записані розміткою MathML. Спільний розбір HTML її відкидає, і від розділу про перерахунок параметрів дуги лишилися
  б слова без формул. Читач перетворює формулу на рядок: `x_1` — нижній індекс, `r_x^2` — степінь, `(a) / (b)` — дріб,
  `sqrt(...)` — корінь, а матриця чи вектор — таблиця у квадратних дужках із рядками через «;».
- **Знімок і чернетку SVG 2 зведено до одного запису.** Чернетку редакторів зібрано іншим інструментом (Bikeshed), ніж
  знімок. Вона бере назви елементів у позначки коду і ставить друкарський апостроф там, де знімок пише прямий. Читач
  знімає позначки коду в рядку й пише апостроф прямим в обох виданнях. Без цього незмінений абзац різнився б самими
  лапками і не зливався б в один фрагмент.
- **Чернетка редакторів SVG 2 — на `w3c.github.io`.** На неї посилається титульна сторінка знімка. Копія на
  `svgwg.org` у день збирання була датована 14.09.2025, тобто старіша за сам знімок, тому її не взято.
- **Модулі взято у двох виданнях.** Публікації модулів на w3.org старі: Filter Effects — 2018 року, CSS Transforms —
  2019-го. Чернетки редакторів на `drafts.csswg.org` несуть пізніші правки. Обидва видання модуля оголошено однією
  родиною в `config.json`, тож однаковий розділ займає у видачі одне місце.
- **Чого з видань не взято.** Односторінкове видання, перелік літератури й покажчики елементів та інтерфейсів (у них
  самі назви) не беруться. Не беруться й додатки з IDL усіх інтерфейсів, текст DTD і прив'язки DOM до Java та
  ECMAScript у SVG 1.1: це механічний повтор того, що вже стоїть у розділах.

## Межі, про які треба пам'ятати

- Без названого видання пошук показує найновіше з тих, де розділ знайдено. Щоб отримати текст SVG 1.1, пошуку
  передають `version` зі значенням `1.1`.
- Мітка `2` охоплює і публікації, і чернетки: `2.draft` є її частиною. Окремо «лише публікації» вибрати не можна. Чи
  текст є в публікації, видно з переліку видань уривка.
- Специфікація не каже, який браузер що підтримує і з якої версії. Це знає примірник `mdn`.
- SVG 2 — кандидат у рекомендації, а не рекомендація. Частину його можливостей браузери не втілили, і з тексту
  специфікації цього не видно.
- Цитата веде на розділ верхнього рівня, а не на підрозділ: якорів підрозділів у адресі немає.
- Кілька формул джерело записало неохайно, і в тексті це лишилося як є: наприклад, `(- x_1)'` замість `-x_1'` у
  формулі кута дуги.
- SVG Tiny 1.2, SVG 1.0, перше видання SVG 1.1 і старіші знімки SVG 2 не беруться.
- З модулів CSS узято п'ять, прямо пов'язаних із SVG. CSS Color, CSS Images, CSS Shapes, Web Animations і Geometry
  Interfaces сюди не входять. Graphics Accessibility API Mappings, на яку посилається SVG-AAM, теж не входить.
- Бібліотеки, що малюють SVG, мають власні примірники: `svgjs`, `snapsvg`, `paperjs`, `d3`. Зменшення файлів SVG —
  `svgo`. HTML, DOM і WAI-ARIA — `webstandards`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/svg-corpus-2026-11-20.tar.gz` (тексти, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском), копія — `C:\Distr\svg-corpus-2026-11-20.tar.gz`
(`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/svg/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/svg-corpus-РРРР-ММ-ДД.tar.gz -C instances/svg corpus raw
find instances/svg/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/svg/raw
gzip -9 -c instances/svg/index/passages.json > instances/svg/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/svg-corpus-2026-11-20.tar.gz -C instances/svg
./df svg smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/svg/index/passages.json.gz`, далі
`./df svg vectors` заллє колекцію Qdrant.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df svg …` бере спільне середовище з кореня репозиторію (`.venvs/cpu` або
`.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/svg/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`). Токен GitHub цьому примірнику не потрібен: жодне джерело не читається з GitHub API.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df svg sources --why    # перелік джерел і білий список
./df svg refresh          # усе: кілька хвилин мережею (пауза 1 с між сторінками одного сайту)
./df svg manifest         # оновити паспорт
./df svg setup            # Qdrant чи пошук лише по словах
./df svg vectors          # залити корпус у docs-svg
./df svg smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df svg serve   # порт 8996
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8996/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user svg-docs http://127.0.0.1:8996/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `svg-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
