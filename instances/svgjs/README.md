# svgjs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про SVG.js — легку бібліотеку, яка створює й змінює малюнки SVG у
браузері з JavaScript (`SVG()`, `rect()`, `path()`, `text()`, градієнти, маски, `animate()`, події), — і про її
офіційні додатки: перетягування, малювання мишею, фільтри, панорамування й масштаб, виділення з маркерами, зміну
розміру, перетворення фігур, а також svgdom, що дає SVG.js працювати в Node.js без браузера. Документація — сайт
svgjs.dev у лініях 3.2, 3.1, 3.0 і 2.7 станом на 20.11.2026, README і реєстр npm двох пакетів ядра й одинадцяти
пакетів додатків, журнали змін і релізи GitHub; лише англійською. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

SVG — це формат малюнка, який браузер тримає не пікселями, а деревом елементів: `<rect>`, `<circle>`, `<path>`,
`<text>`. Кожен елемент лишається окремим вузлом сторінки, тож його можна знайти, змінити й підписати на клік, як
звичайний елемент HTML. Писати таке дерево руками через DOM браузера довго: кожен елемент треба створити функцією
`document.createElementNS` із простором імен SVG і кожен атрибут поставити окремим викликом. SVG.js загортає ці
виклики в ланцюжок методів: `draw.rect(100, 100).move(20, 20).fill('#f06')` створює прямокутник, ставить його на
місце й фарбує одним рядком. Вона ж плавно анімує атрибути (`animate()`), читає й записує розмітку SVG (`svg()`)
і не має залежностей. Сам формат SVG і DOM браузера описано в примірнику `mdn`; тут — лише те, що додає SVG.js.

Між лініями 2 і 3 бібліотеку переписано, і код для них пишеться по-різному. SVG.js 3 поділено на модулі ES, головний
клас малюнка `SVG.Doc` перейменовано на `SVG.Svg`, а метод `doc()` — на `root()`. Групу `SVG.Set` прибрано на
користь `SVG.List`, модуль анімації переписано навколо `SVG.Runner` і `SVG.Timeline`, і `transform()` працює
інакше. Пакет теж змінив назву: SVG.js 2 ставиться як `svg.js`, SVG.js 3 — як `@svgdotjs/svg.js`. Обидва пакети
досі завантажують приблизно однаково, тому відповідь мусить знати, для якої лінії вона.

**Що є що.** **SVG()** — функція, що створює малюнок або загортає наявний елемент сторінки в об'єкт SVG.js;
**контейнер** — елемент, що тримає інші (`SVG.Svg`, група `SVG.G`, `SVG.Defs` для визначень, що самі не малюються);
**фігура** — елемент, що малюється (`SVG.Rect`, `SVG.Circle`, `SVG.Path`, `SVG.Text`); **Runner** — одна анімація
одного елемента, яку можна зупинити, перемотати й повторити; **Timeline** — розклад, що тримає раннери й рухає їх
у часі; **додаток (plugin)** — окремий пакет, що дописує в класи SVG.js нові методи (`draggable()`, `panZoom()`).

## Звідки документація

- **Сайт — з репозиторію, а не зі сторінок.** Сайт svgjs.dev зібрано системою керування вмістом Kirby з
  репозиторію `svgdotjs/svgdotjs.github.io`. Кожна лінія документації лежить у своїй гілці (`source-3.2`,
  `source-3.1`, `source-3.0`, `source-2.7`), і примірник бере останній коміт кожної гілки на 20.11.2026. Сторінка
  сайту — це тека з файлом `default.txt`. Мітка документа — лінія (`3.2`), а не номер релізу, бо сайт тримає одну
  сторінку на лінію: svgjs.dev/docs/3.2/… Адресу сторінки на сайті читач складає з шляху теки (поле `site` у
  `sources.json`), і для кожної лінії її звірено з сайтом.
- **Читач `ghdocs-kirby`.** Файл Kirby — це поля, розділені рядком `----`: `Title: Other Elements`, `Text:` і далі
  markdown, а наприкінці `Description:`. Без перетворення рядок `----` під `Title:` markdown прочитав би як
  підкреслення заголовка, і назвою сторінки ставало б «Title: Other Elements». Читач бере з файла лише поле
  `Text`, а `Title` ставить назвою, коли текст не починається заголовком. Посилання розмітки Kirby
  `(link: /plugins/svg-draw-js/ text: svg.draw.js)` він перетворює на звичайне посилання markdown. Файли
  `anchor.txt` (лише назва якоря) і сторінка 404 не беруться. Усе інше — перелік гілок, імена й версії
  документів — робить спільний читач `ghdocs-history`.
- **README.** Реєстр npm віддає README лише найновішої версії, тому README кожної версії читається з репозиторію на
  коміті її публікації (`gitHead`), а де реєстр коміту не записав — з тегу `{version}` чи `v{version}`. README є в
  усіх 220 стабільних версіях двадцяти пакетів.
- **Журнал змін.** `CHANGELOG.md` SVG.js пише заголовок версії як «## [3.2.8]», `changelog.md` svgdom — як
  «## 0.1.29 - 2026-09-09»; обидва розбирає читач `changelog-otel`, по документу на версію. Журнал svgdom
  почато лише з 0.1.25.
- **Релізи.** Для кожного репозиторію з релізами — своє джерело `ghreleases`: SVG.js (39), filter (11), panzoom
  (10), draggable (6), topath і topoly (по 5), select (3), resize (2), draw, pathmorphing і svgdom (по 1).
  Передрелізи не беруться.

## Межі, про які треба пам'ятати

- Сайт є для ліній 3.2, 3.1, 3.0 і 2.7; ліній 1.x і 2.0–2.6 на ньому немає, про них відомо з README, журналу змін і
  релізів.
- Сторінки додатків на сайті короткі — назва й посилання на репозиторій. Справжній опис додатка — у його README.
- Сайт перелічує більше додатків, ніж зібрано тут (svg.connectable.js, svg.math.js, svg.shapes.js, ngx-svg та
  інші): для них у корпусі є лише сторінка-посилання на сайті, а README цих пакетів не входить.
- Фільтр версії додатка йде за номером додатка, а не ядра: `pathmorphing-0` бере обидві лінії, бо стара назва має
  0.1.x, а нова — 0.2.0.
- Сам формат SVG і DOM браузера — у примірнику `mdn`; сам React — у примірнику `react`. Бібліотеки для полотна
  мають власні примірники: `konva`, `pixijs`, `fabricjs`; D3 — `d3`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/svgjs-corpus-2026-11-20.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\svgjs-corpus-2026-11-20.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів
немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/svgjs/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/svgjs-corpus-РРРР-ММ-ДД.tar.gz -C instances/svgjs corpus raw
find instances/svgjs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/svgjs/raw
gzip -9 -c instances/svgjs/index/passages.json > instances/svgjs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Новий архів копіюють у `C:\Distr` і звіряють за SHA-256 (`tools/mirror-archives.sh --apply`),
і лише тоді видаляють попередній з обох місць, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/svgjs-corpus-2026-11-20.tar.gz -C instances/svgjs
./df svgjs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/svgjs/index/passages.json.gz`,
далі `./df svgjs vectors` заллє колекцію Qdrant.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df svgjs …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/svgjs/.env` (`cp .env.example .env`; для
кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df svgjs sources --why    # перелік джерел і білий список
./df svgjs refresh          # усе: кілька хвилин мережею (паузи 0,2 с)
./df svgjs manifest         # оновити паспорт
./df svgjs setup            # Qdrant чи пошук лише по словах
./df svgjs vectors          # залити корпус у docs-svgjs
./df svgjs smoke            # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df svgjs serve   # порт 8992
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8992/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user svgjs-docs http://127.0.0.1:8992/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `svgjs-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
