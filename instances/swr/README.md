# swr — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про SWR — бібліотеку хуків React для отримання даних від Vercel — за
офіційною документацією всіх стабільних версій, від 0.1.2 (жовтень 2019) до поточної 2.x: сайт swr.vercel.app у стані
на кожен реліз, README кожної версії, нотатки релізів, приклади застосунків трьох ліній і історія пакета в реєстрі
npm. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену.
Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо вся історія

SWR двічі ламав API. 1.0 (серпень 2021) переніс `useSWRInfinite` у `swr/infinite`, перейменував `initialData` на
`fallbackData`, прибрав типовий fetcher і замість спільного кешу дав провайдери кешу та middleware. 2.0 (грудень 2022)
додав `useSWRMutation`, `isLoading`, `keepPreviousData` і `preload`, а fetcher перестав приймати кілька аргументів.
Лінії 0.x і 1.x досі встановлюють (за тиждень 2.x завантажують ~18 млн разів, 1.x — ~230 тисяч, 0.x — ~60 тисяч), і
питання часто звучить «як це було в моїй версії» чи «з якої версії є `keepPreviousData`». Відповідь дає лише
документація саме тієї версії, тож корпус — не одна редакція сайту, а вся його історія, і кожен документ несе свої
версії.

На сайті 26 сторінок, і найбільше редакцій мають `docs/pagination` (19), `docs/mutation` (18) і `docs/with-nextjs`
(17).

**Замір `quality`** на першому корпусі: по словах 6 із 10, за змістом 9, разом 7; десятка «як модель» — 10 із 10.
Перша десятка — переказ питання своїми словами, і промахи такі:

- **Підписки на 2.1.** На «receive live updates from a websocket and keep them in the cache» жоден спосіб не приносить
  сторінки `docs/subscription` і прикладу `subscription`: запит не має слова «subscription», а сторінки про мутації
  й кеш мають «cache» і «update» частіше.
- **Відкладений запит.** На «call the API only when the user presses a button» по словах першими стоять prefetching і
  пагінація; `useSWRMutation` знаходить лише пошук за змістом.
- **Умовний запит.** На «only send the request once the user id is available» по словах ідуть мутації, аргументи й
  Next.js — сторінки, де часто стоять «user» і «request», а `docs/conditional-fetching` знаходить лише пошук за
  змістом.
- **Злиття двох способів** в обох останніх випадках ставить вище знахідки по словах, і «разом» (7) нижче, ніж «за
  змістом» (9).

Десятка «як модель» — запити назвами хуків і опцій, як велить промпт, з `version "2"`, а один — `initialData` з
`version "0"`. На першому замірі він дав 9 із 10: першим стояв приклад SSR з README 0.x, де `initialData` якраз і
показано в роботі, а розділ опцій — довгий перелік усіх опцій — опускався нижче п'ятого місця. Приклад SSR і сторінку
`docs/with-nextjs` доби 0.x дописано в ціль: знаюча людина прийняла б їх як відповідь.

Поле `max_per_doc` заміряно 0/1/2/3: перша десятка 7/7/7/7 разом, «як модель» 10/9/10/10 — поле не ввімкнене.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df swr <крок>`.

Нових читачів примірник не додав. Разом із ним спільний розбір markdown навчився зрізати якір заголовка Fumadocs
(«## Options [#options]»): сайт пише його з травня 2023, і без цього якір потрапляв у назву розділу.

Особливості, які варто знати:

- **Тегів у сайту немає.** На кожну стабільну версію береться стан гілки `main` на мить перед виходом наступної
  версії тієї ж лінії; для найновішої — сьогоднішній стан. Документ — неповторна пара «шлях, вміст», і він несе всі
  версії, де сторінка була саме такою.
- **Три розкладки сайту.** 22.05–30.06.2020 — одна сторінка `docs/index.md` (у корпусі — версія 0.2.2); 30.06.2020–
  10.12.2025 — сайт на Nextra, `pages/` (з 26.02.2021 англійські файли мають суфікс `.en-US`); з 10.12.2025 —
  `content/`. Поле `slug_rewrite` зводить усі три до одного імені сторінки (`docs-mutation`, `docs-advanced-cache`,
  `blog-swr-v2`), і незмінний розділ різних епох зливається в один фрагмент.
- **До травня 2020 сайту не було.** Документацією 0.1.x–0.2.x був README репозиторію vercel/swr, і він лишався
  найповнішим довідником усієї лінії 0.x (API, опції, приклади, SSR, мутації). З 1.0 README короткий і веде на сайт.
- **Лише англійська.** Сім перекладів сайту (китайська, іспанська, японська, корейська, російська, португальська,
  французька) не беруться.
- **Чого з сайту не взято.** Сторінки `examples/` — лише рамка CodeSandbox; код тих самих прикладів дають джерела
  `swr-examples-*`. Сторінка `change-log` складала останні релізи з GitHub API під час збирання сайту, і в її файлі
  лише код; релізи дає `swr-releases`.
- **Приклади — на останньому релізі кожної лінії**: 0.5.7 (тегу немає, коміт — gitHead з реєстру), 1.3.0 і v2.5.1.
  Три джерела оголошено однією родиною (`families` у `config.json`), тож однаковий приклад різних ліній займає у
  видачі одне місце.
- **Теги репозиторію двох видів.** 0.x, 1.x і 2.0.0 — без «v», з 2.0.1 — з «v». Для 2.0.0–2.1.3 реєстр не записав
  коміту, і README береться з тегу.
- **CHANGELOG немає.** Журнал змін SWR — це нотатки релізів на GitHub.

## Межі, про які треба пам'ятати

TanStack Query, Apollo, RTK Query й інших бібліотек отримання даних тут немає, як і React чи Next.js загалом — лише те,
що про них пише документація SWR. Бети й RC (97 версій, зокрема 2.6.0-beta.0) не беруться: ні знімки сайту, ні
README, ні нотатки релізів. Блог сайту — два дописи, про 1.0 і про 2.0. Діаграми сторінки «Understanding SWR» —
картинки, і в тексті від них лишається лише підпис.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/swr-corpus-2026-10-10.tar.gz` (430 текстів і паспорт; перед видаленням
розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає ніде. Архів лежить лише на
цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/swr-corpus-2026-10-10.tar.gz -C instances/swr
./df swr smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/swr/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/swr-corpus-РРРР-ММ-ДД.tar.gz -C instances/swr corpus
find instances/swr/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/swr/index/passages.json > instances/swr/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/swr/index/passages.json.gz`, далі
`./df swr vectors` заллє колекцію Qdrant (~3 хвилини).

## Установка venv

```
cd instances/swr
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df swr sources --why   # перелік джерел і білий список
./df swr refresh         # завантажити все задеклароване (~15 хвилин)
./df swr manifest        # оновити паспорт
./df swr setup           # Qdrant чи пошук лише по словах
./df swr vectors         # залити корпус у docs-swr (~3 хвилини)
./df swr smoke           # перевірки
```

Перші ~4 хвилини `refresh` журнал мовчить, а `corpus/` порожній: читач сайту проходить ~440 комітів і дерева знімків і
лише потім починає писати файли. Без токена GitHub перелік ішов би годинними вікнами по 60 звернень.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df swr serve          # порт 8817
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8817/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user swr-docs http://127.0.0.1:8817/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `swr-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
