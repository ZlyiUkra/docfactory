# ta-indicators — примірник фабрики docfactory

Цей примірник зібрав документацію бібліотек технічних індикаторів для Python і віддає її через сервер MCP, щоб модель відповідала з
текстів бібліотек, а не з пам'яті. Технічний індикатор — це число, яке рахують з історії цін: наприклад, середня ціна за останні 14
свічок або сила останніх зростань проти останніх падінь (RSI). Такі числа стають ознаками для моделі машинного навчання і правилами
для торгового робота.

Примірник зібрано під проєкт торгового робота для валютних пар. Там індикатори рахуватимуть двічі: у Python, коли модель навчається,
і в MetaTrader, коли робот торгує. Одна й та сама назва індикатора не гарантує однакових чисел: бібліотеки по-різному згладжують
середні й по-різному рахують перші свічки. Щоб звірити формули, тут лежать точні описи трьох бібліотек:

- **TA-Lib** — бібліотека мовою C з обгорткою для Python (`talib`). Її сайт ta-lib.org має окрему сторінку на кожну функцію: формулу,
  примітки про те, скільки перших значень ненадійні, входи, виходи й параметри з допустимими значеннями.
- **pandas-ta-classic** — підтримуваний спільнотою форк бібліотеки pandas-ta. Сам репозиторій pandas-ta з GitHub видалено. Опис
  кожного індикатора (джерела, розрахунок, аргументи) записано в рядку документації його функції, тому код і є головною документацією.
- **ta** (bukosabino) — бібліотека на pandas з класами на кшталт `RSIIndicator`; її сайт теж збирається з рядків документації коду.

Формули вбудованих індикаторів MetaTrader (iRSI, iATR) лежать в інших примірниках: `mql5` (довідка терміналу MetaTrader 5) і `mql4`.

## Скільки цього

змінювався між версіями, лежить кількома документами, а однакові фрагменти пошук зливає й показує з переліком версій.

версії різних бібліотек не збігалися між собою.

**Чого ще немає.** Записів PyPI чотирьох пакетів (`TA-Lib`, `pandas-ta-classic`, оригінальний `pandas-ta`, `ta`). Їх оголошено в
`sources.json`, але 13.11.2026 pypi.org з WSL відповідав лише на половину запитів, і перелік версій не складався. Як їх дозбирати,
описано в [UPDATE.md](UPDATE.md).

**Де є прогалини.** Сайт ta-lib.org існує лише з TA-Lib 0.8.1, тож сторінок функцій для старших ліній немає. Сторінка `stream.md`
обгортки для Python є лише в гілці master, у жодному випуску її немає.

Замір `quality` на 13.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 5 із 10. Код pandas-ta-classic кожної з шести ліній лежить окремою редакцією, тому в
`config.json` стоїть `max_per_doc: 2`: один файл займає щонайбільше два місця видачі.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df ta-indicators <крок>`.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df ta-indicators serve
```

Порт — `8976`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user ta-indicators-docs http://127.0.0.1:8976/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `ta-indicators-docs` з інструментами `search_docs` і `read_section`. Якщо
сервер позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/ta-indicators-corpus-2026-11-13.tar.gz` (тексти, паспорт і сховище сирого `raw/`;
перед видаленням текстів архів звірено з диском) і в копії на диску Windows `C:\Distr\ta-indicators-corpus-2026-11-13.tar.gz`
(звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/ta-indicators/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/ta-indicators-corpus-РРРР-ММ-ДД.tar.gz -C instances/ta-indicators corpus raw
find instances/ta-indicators/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/ta-indicators/raw
gzip -9 -c instances/ta-indicators/index/passages.json > instances/ta-indicators/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів (і його копію в `C:\Distr`), а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/ta-indicators-corpus-2026-11-13.tar.gz -C instances/ta-indicators
./df ta-indicators smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
