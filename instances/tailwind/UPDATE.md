# Оновлення корпусу tailwind

Дві різні роботи: звичайне оновлення (вийшов реліз Tailwind чи пакета поруч, змінилася сторінка документації) і
нова мажорна версія Tailwind. Порядок усередині кожної важливіший за самі команди.

Головне правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.
Сторінка, що зникла з сайту, чи версія, прибрана з реєстру, лишається в `corpus/`; прибрати — рішення людини.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед будь-якою роботою нижче тексти розпаковують, а після неї — пакують і виносять
знову; обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## 1. Звичайне оновлення

```
./df tailwind sources --why
./df tailwind refresh             # усі джерела (~50 хвилин, переважно README пакетів)
./df tailwind manifest
./df tailwind vectors
./df tailwind smoke
# Ctrl+C у терміналі з serve, і знову: ./df tailwind serve
```

Живе тут майже все: сайти v4 і v3 іноді правлять, журнал змін і реєстр npm ростуть з кожним релізом, у README
пакетів додаються нові версії. Сайти v2, v1 і гілка `v0` — архіви, але `refresh` проходить і їх: сторінка, що не
змінилася, лишається як є.

Щоб довантажити лише нове джерело, — `./df tailwind refresh --missing <id…>`: без `--missing` імена джерел
не звужують прогін.

Корпус не комітиться: після оновлення пишуть новий архів і знову виносять тексти (README, розділ «Архівний режим»),
а в git ідуть лише паспорт і кеш.

Якщо `smoke` скаржиться на число фрагментів — це наслідок того, що корпус підріс. Нове число записують у
`checks.json` полем `expected_passages`, а в `expected_note` — коли й чому його знято.

## 2. Новий пакет поруч із Tailwind

**Реєстр версій** — джерело `npm-versions` за зразком `npm-daisyui`: одна адреса реєстру.

**README** — лише якщо README пакета є документацією, а не посиланням на сайт. Дивитися треба README в
опублікованих пакетах старих ліній, а не на GitHub сьогодні: у flowbite-react на GitHub 21 байт, а в пакеті —
12 КБ. Джерело `npm-readme` за зразком `readme-daisyui`: шляхи README в репозиторії (монорепозиторій з часом
переносить його в `packages/…`), шаблон тегу релізу (`v{version}`, `пакет@v{version}`), `skip_versions` для
insiders, development-, нічних збірок і збірок з хешем коміту.

Потім `refresh --missing <нові id>`, `manifest`, `vectors`, `smoke`, як у розділі 1, і рядок у таблиці пакетів
README.

## 3. Нова мажорна версія Tailwind

Скажімо, v5 на tailwindcss.com, а v4 переїхала на v4.tailwindcss.com.

**Крок 1. Джерело нової версії** — `tw-v5` за зразком `tw-v4`: `url` — сторінка встановлення, `index` — сторінка
посібників під фреймворки, `pages` — вкладки посібників, що живуть окремими адресами (їх видно в модулях
`framework-guides/*.tsx` репозиторію сайту: масив `tabs`), `version` — номер нової лінії.

**Крок 2. Стара версія на новій адресі.** У `tw-v4` замінити домен в `url`, `index`, `pages` і `within`.
Документи v4 отримають нові імена файлів, а старі лишаться поруч (нічого не видаляється): старі файли `tw-v4--*`
прибрати руками, коли нові записано.

**Крок 3. Промпти й перевірки.** У `prompts/search.txt` і `prompts/agent.txt` поточна лінія `"4"` стає `"5"`, а
«спосіб v3» — способом попередньої лінії; у `checks.json` — `quality_model`.

**Крок 4.** `refresh --missing <нові id>` для нового джерела, повний `refresh` для перенесеного, `manifest`,
`vectors`, `smoke`, як у розділі 1.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df tailwind quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Що це означає тут:

- **Поточна лінія — v4.** `prompts/search.txt` (абзац «Which version to search first») і `prompts/agent.txt`
  велять на питання «як зараз» шукати з `version "4"`, а для проєкту зі старим Tailwind — з його лінією.
- **Правила промпту, що вже є:** запит — назвами класів, директив і пакетів англійською; без версії — сумісність
  пакетів та історія; кожна відповідь каже версію, а де v3 інакше — дає і спосіб v3; номери в реєстрі й README —
  свого пакета.
- **Останній результат:** у README, абзац «Замір `quality`».
