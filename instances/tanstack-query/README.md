# tanstack-query — примірник фабрики docfactory

Восьмий примірник фабрики: захищений MCP-сервер, що відповідає на питання про TanStack Query (до v4 — React Query)
за офіційною документацією всіх його версій — від 0.x (2019) до поточної 5.x, разом з кожним alpha, beta й release
candidate, — за довідником API кожного фреймворку, прикладами, журналами змін пакетів і нотатками релізів. Код
спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо вся історія

TanStack Query міняв API з кожною мажорною версією: `cacheTime` став `gcTime`, `isLoading` — `isPending`,
`keepPreviousData` — `placeholderData`, пакет `react-query` — `@tanstack/react-query`, а один об'єкт параметрів
замінив три позиційні аргументи. Проєкти на старих версіях живуть роками, і питання до документації часто звучить
«як це було в моїй версії», «з якої версії є `useSuspenseQuery`» і «на що замінили». Відповідь дає лише документація
саме тієї версії, тож корпус — не одна редакція сайту, а вся історія репозиторію, і кожен документ несе свої версії.

показують межу корпусу з усією історією:

- **README v0–v1 займає видачу.** До v2 уся документація була одним README з розділом на кожну тему, і в корпусі
  десятки його редакцій, що різняться парою рядків і тому не зливаються. На «invalidate after mutation» усі п'ять
  місць — розділи того README: відповідь правильна, але для версії 2020 року.
- **Довідник API семи фреймворків.** Сторінки на кшталт `createBaseQueryOptions` в Angular мають інші імена, ніж
  у React, тож згортання варіантів їх не об'єднує, і вони відтісняють гайди.
- **Частина промахів — сам замір:** на «query keys» пошук приносить потрібний гайд, але у варіанті Lit, бо запит
  фреймворку не називає, а ціль названо для React.

## Що в цій теці

- `corpus/` — документація звичайними текстовими файлами; поруч `index.json` — паспорт, тобто опис копії: адреса,
  дата завантаження й сума тексту кожного документа.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача. Перелік усіх 1313 тегів лежить
  саме тут, у полі `tags` джерела `tq-docs`: оновлювач не питає в GitHub, які теги існують.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df tanstack-query <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| документація всіх версій | дерево кожного тегу через GitHub API, текст — `raw.githubusercontent.com` | `ghdocs-history` |
| приклади | тека `examples/` на тезі | `ghexamples`, новий |
| журнали змін пакетів | `packages/*/CHANGELOG.md` гілки main | `changelog-v` |
| нотатки релізів | GitHub API, відбір за префіксом тегу | `ghreleases-tagged` |
| блог | `src/blog/*.md` репозиторію tanstack.com | `mdfile` |

Читач `ghexamples` додано разом із цим примірником (`engine/readers/ghexamples.py`). З чинних змінено `mdfile`: назву
він тепер бере з поля `title:` шапки YAML, коли воно там є (записи блогу починаються картинкою чи одразу
підрозділом); для supabase, де шапки немає, документи ті самі дослівно.

Особливості, які варто знати:

- **Сайт — не першоджерело.** tanstack.com/query будує сторінки з теки `docs/` репозиторію, разом із довідником API
  (`docs/framework/*/reference`, згенерований і закомічений). Тож текст береться прямо з тегу.
- **Де лежала документація.** 0.x–1.x — увесь кореневий `README.md`; 2.x–3.x — `docs/` (частина ще в
  `docs/src/pages/`); 4.x і ранні 5.x — `docs/react/…`, `docs/vue/…`; пізніші 5.x — `docs/framework/<фреймворк>/…`.
- **Теги.** До v5.90.3 репозиторій ставив спільні теги `vX.Y.Z`. Далі — лише теги окремих пакетів, і версією
  документації служать теги `@tanstack/query-core@X.Y.Z`, бо документація одна на всі пакети. Пізні патчі лінії 4
  (4.41.1, 4.43.0, 4.44.0) теж є лише як теги `query-core`.
- **Версії пакетів розходяться.** Журнали змін і релізи адаптерів несуть версію свого пакета: svelte-query вже на
  лінії 6.x, у solid-query є release candidate 6.0. Фільтр `version: "6"` знайде саме їх.
- **Варіанти фреймворків займають одне місце (`variant_pattern`).** Сторінка, що є для React, Vue, Angular, Solid,
  Svelte, Preact і Lit, у видачі займає одне місце, а якщо запит називає фреймворк — місце дістається його варіанту.
  Вираз розпізнає обидві форми шляхів: `docs/framework/react/…` і старішу `docs/react/…`.
- **Довідник інших фреймворків не заходить у видачу (`variant_strict`).** Довідник API кожного фреймворку має свої
  імена сторінок (`injectQuery` в Angular, `createQuery` у Solid), тож згортанню вони не піддаються. Коли запит
  називає фреймворк, сторінки інших фреймворків, що не мають його копії, відсіюються ще до відбору місць. Стара
  назва «React Query» теж називає React.
- **Редакції того самого файла зливаються (`revision_suffix`)**, як у `react-router`: ім'я документа несе хеш
  вмісту, і без поля незмінний розділ двох редакцій лишався б двома фрагментами.
- **Приклади — лише на останньому тезі кожної лінії.** Історія прикладів за тегами дала б тисячі майже однакових
  тек; `package.json` у кожному прикладі каже, на якій версії він написаний.
- **Порожні версії журналів змін.** 98 версій у `CHANGELOG.md` пакетів записані без тексту (пакет вийшов разом з
  іншими без змін). Документами вони не стали, а `refresh` рахує їх збоями.
- **Зведені релізи `release-РРРР-ММ-ДД-…` не беруться:** це підсумки дня з тими самими пакетними релізами, а
  версією документа стала б дата.

## Межі, про які треба пам'ятати

TanStack Router, Start, Table, Form і DB тут немає — лише два записи блогу про DB поверх Query. Немає й сторінки
Community Resources: сайт малює її з даних, markdown-тексту в неї немає. Alpha, beta й rc — не релізи: текст, що є
лише в них, міг так і не вийти, і промпт велить моделі казати про це прямо.

## Установка venv

```
cd instances/tanstack-query
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Якщо корпус уже лежить у `corpus/`, потрібен лише `vectors`, якщо колекції ще немає.

```
./df tanstack-query sources --why   # перелік джерел і білий список
./df tanstack-query refresh         # завантажити все задеклароване (~4 години)
./df tanstack-query manifest        # оновити паспорт
./df tanstack-query setup           # Qdrant чи пошук лише по словах
./df tanstack-query vectors         # залити корпус у docs-tanstack-query (~1 година)
./df tanstack-query smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd /mnt/c/Projects/fwdays/docfactory
./df tanstack-query serve          # порт 8767
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8767/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user tanstack-query-docs http://127.0.0.1:8767/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `tanstack-query-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
