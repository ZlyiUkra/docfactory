Search the official documentation of TanStack Router and TanStack Start -- every stable version
of it, from 1.0 to the current 1.x line -- and of their predecessor React Location (1.0 to 3.7),
together with the example apps, the changelogs of all @tanstack/* router and start packages, the
GitHub release notes, the TanStack blog posts about Router and Start and the npm registry history
of every package, current and retired, and return the matching excerpts with the versions each
one belongs to.

Call this when a question is about TanStack Router or TanStack Start themselves -- creating a
router (createRouter, RouterProvider), file-based and code-based routing (createFileRoute,
createRootRoute, createRoute, route trees, the router plugin and generator, virtual file routes),
path and search params (validateSearch, useSearch, useParams, search middlewares, the zod,
valibot and arktype adapters), navigation (Link, useNavigate, redirect, navigation blocking,
route masking, preloading), data loading (loader, beforeLoad, loaderDeps, deferred data, router
context, pending and error components, notFound), code splitting, scroll restoration, SSR and
streaming, the devtools, the ESLint plugin; in TanStack Start -- server functions
(createServerFn), server routes, middleware, hosting and deployment, static prerendering, React
Server Components, authentication, environment variables; the adapters for React, Solid and Vue;
React Location 1.x-3.x and the move to TanStack Router -- and above all when it is about history:
since which version something exists, what changed between versions, what was renamed or removed
and what replaced it. Example query: "createFileRoute loader beforeLoad".

Do not call this for React, Solid, Vue or Vite themselves, for React Router or Remix, for
Next.js, for TanStack Query, Table, Form or Virtual or the rest of TanStack: their documentation
is not here, and the search will return TanStack Router excerpts that merely mention them, with
confident-looking titles.

`version` narrows the search to one release line: "1" keeps every 1.x document, "1.120" keeps
1.120.x; leave it empty to search everything. Only stable releases are here. Every excerpt comes
back with `versions`: each version whose documents contain this exact text, newest first -- text
that stayed the same across versions is returned once, with all of them listed, so the list itself
shows from which to which version the documentation said exactly this. Versions of the
documentation after 1.166.7 are the versions of @tanstack/react-router; the other packages number
their releases on their own from 1.166.8 on (@tanstack/react-start is at 1.168.x while
@tanstack/react-router is at 1.170.x), and changelog and release entries of a package carry that
package's own version. React Location versions are 1.0.0-3.7.4: lines 2 and 3 are React Location
only, and React Location 1.0.0-1.1.2 shares the numbers of Router 1.0.0-1.1.2, so name React
Location in the query when that is what you look for.

Where the documentation lived. In 1.0 the pages were docs/guide/*.md; then
docs/framework/react/guide and docs/framework/react/api/router (the API reference, one page per
function, hook, component and type), with TanStack Start in docs/framework/react/start; then
docs/router/framework/{react,solid}/... and docs/start/framework/{react,solid}/...; today the
router pages are docs/router/{guide,api,routing,how-to,installation}/... for all frameworks and
Start keeps docs/start/framework/{react,solid}/guide. Start pages are titled "TanStack Start: ..."
(with the framework in brackets), React Location pages "React Location: ...". Example apps are
documents titled "Example: react/basic-file-based" with their package.json and source files.

Which version to search first. For a question about how to do something today, pass `version`
"1" and name the framework and the product in the query ("server function start react",
"search params solid router"): without it, React Location 3.x pages with the same words
(useMatch, useSearch, Link) can take places with an API that predates TanStack Router. Search
without `version` when the question is about history or about React Location, or when the line
gave nothing that answers.

Name the function, hook, option or component the way the documentation titles it, not in the
user's own words: "beforeLoad redirect", "validateSearch", "loaderDeps", "createServerFn
validator", "notFoundComponent", not "send the user to login if not signed in". When the question
is how to do something, an example app often shows it better than the guide: search for the
example as well ("example react authenticated-routes", "example react start-basic").

For a question about when something appeared, changed or disappeared, search more than once:
without `version` first, to find the changelog entry and the release notes that name the exact
version, then with the versions around it, to see how the documentation described it before and
after.

Write the query in English, with the names TanStack Router itself uses (createFileRoute,
useLoaderData, createServerFn, routeTree.gen.ts). Everything here is English -- the excerpts, the
word index and the meaning index alike -- and the word index keeps only latin letters and digits,
so a query written in Ukrainian, Russian or any other non-latin script matches nothing at all and
comes back with `found: 0`. When the user asks in another language, translate the question into
TanStack Router terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Every answer says which version it is for. When the user did not name a version, answer for the
current line, 1.x, as the newest documents describe it, say so in the answer ("for TanStack
Router 1.x"), and add that for a precise answer about another version the user can name it. When
the excerpts behind a statement come only from older versions, name those versions instead of
presenting the text as current.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists and which release introduced it;
what changed in later versions; what prompted the change, if the excerpts say so; and how it
stands in the current version -- recommended, deprecated, or removed and replaced by what. Every
point names the version and the document it rests on; a point the excerpts do not support is
left out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists
-- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація TanStack Router". Identifiers, API names and titles stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts
that came back, not out of memory: if an excerpt was cut, read the whole of it before describing
what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
