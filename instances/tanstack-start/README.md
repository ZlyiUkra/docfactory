# tanstack-start — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про TanStack Start за його документацією: серверні функції
(`createServerFn`), `createMiddleware`, серверні маршрути, SSR, вибірковий SSR, статичне попереднє рендерення, режим SPA,
змінні оточення, автентифікація, розгортання. Тут сайт tanstack.com/start на день знімка, документація з репозиторію на
кожну сталу мінорну 1.49–1.169, README пакетів від 1.31, приклади, журнали змін і нотатки релізів, реєстр npm. Код
спільний — у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний опис фабрики
— у [../../README.md](../../README.md).

## Навіщо окремий примірник

Мажорна версія в Start одна, 1.x, але API всередині неї мінявся не раз: «API routes» стали «server routes», конфігурація
пішла з `app.config.ts` у плагін Vite, пакет `@tanstack/start` розпався на `react-start` і `solid-start`. Відповідь без
версії тут часто неправильна, тож мінорні зібрано всі, а не лише поточну.

Start є і в примірнику [`tanstack-router`](../tanstack-router/README.md), станом на 11.10.2026 і впереміш із Router. Цей
примірник окремий: Start без сторінок Router і свіжіший. Під час наступного оновлення `tanstack-router` Start звідти
вилучається.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й контрольна сума кожного тексту. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснутий `passages.json.gz`, а розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише для
  завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df tanstack-start <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт | `tanstack.com/start/latest/llms.txt` | `llms` |
| документація всіх мінорних | дерево кожного тегу через GitHub API, текст — `raw.githubusercontent.com` | `ghdocs-history` |
| приклади | дерево тегу `@tanstack/react-start@1.169.4` | `ghexamples` з полем `only` |
| README | реєстр npm і `packages/<пакет>/README.md` на тегу версії | `npm-readme` |
| журнали змін | `packages/<пакет>/CHANGELOG.md` | `changelog-named` |
| релізи | GitHub API релізів, без передрелізів | `ghreleases-stable` |
| npm | `registry.npmjs.org/@tanstack/<пакет>`, без передрелізів | `npm-versions` |

**Сайт і репозиторій.** Сайт показує лише `latest`, а старі версії є тільки в репозиторії: сайт будує сторінки з теки
`docs/`. Переїзди сторінок (`docs/framework/react/start/…`, далі `docs/start/framework/{react,solid}/…` і нарешті `guide/`)
зводить поле `slug_rewrite`, а поле `families` робить сайт і репозиторій редакціями однієї сторінки.

**Теги.** До `v1.166.7` теги спільні на весь репозиторій, далі кожен пакет має свої. Тому мінорні 1.166–1.169 узято за
тегами `@tanstack/react-start@…`. Документація одна на всі пакети, а React-адаптер найпопулярніший (41 млн завантажень за
місяць проти 296 тисяч у Solid).

**React і Solid.** Більшість сторінок Solid повторює сторінки React. Поле `variant_pattern` дає двом копіям одне місце у
видачі, а якщо запит називає фреймворк, місце дістається його копії. Запит без назви фреймворку може повернути будь-яку з
них, тож промпти наказують моделі називати фреймворк, а без нього відповідати для React.

**Приклади.** Читач бере лише теки `start-*`: приклади Router лишаються в `tanstack-router`. Сторінки прикладів на сайті
markdown-двійника не мають, тому до джерела сайту вони не входять.

## Версії

`version: "1"` бере всю лінію 1.x, `"1.120"` — лише 1.120.x. Кожну мінорну представляє її останній випуск. Без версії
пошук іде по всьому, і це правильний вибір для питань про історію. У версій документації після 1.166.7 ті самі номери,
що й в `@tanstack/react-start`; журнали й релізи решти пакетів мають власні.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт; сервер працює з кешу фрагментів
(`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символу: кеш тримає повний текст кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/tanstack-start-corpus-2026-11-02.tar.gz` (4 306 текстів, паспорт і сховище
сирого `raw/`); перед видаленням текстів архів розпаковано окремо й звірено з паспортом. Копія —
`C:\Distr\tanstack-start-corpus-2026-11-02.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/tanstack-start/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/tanstack-start-corpus-РРРР-ММ-ДД.tar.gz -C instances/tanstack-start corpus raw
find instances/tanstack-start/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/tanstack-start/raw
gzip -9 -c instances/tanstack-start/index/passages.json > instances/tanstack-start/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сире видаляють лише тоді, коли
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у цей розділ.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається і сховище сирого:

```
tar -xzf ~/archives/docfactory/tanstack-start-corpus-2026-11-02.tar.gz -C instances/tanstack-start
./df tanstack-start smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони марні. Частину перевірки
`smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/tanstack-start/index/passages.json.gz`.
Далі `./df tanstack-start vectors` заллє колекцію Qdrant: менше хвилини на відеокарті.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df tanstack-start …` бере спільне середовище (`.venvs/cpu` або `.venvs/gpu`).
Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ вище). Для самого сервера збирати нічого
не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df tanstack-start sources --why   # перелік джерел і білий список
./df tanstack-start refresh         # завантажити все задеклароване (близько 35 хвилин)
./df tanstack-start manifest        # оновити паспорт
./df tanstack-start setup           # Qdrant чи пошук лише по словах
./df tanstack-start vectors         # залити корпус у docs-tanstack-start
./df tanstack-start smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу сервер треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df tanstack-start serve          # порт 8941
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8941/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно Claude Code:

```
claude mcp add --transport http --scope user tanstack-start-docs http://127.0.0.1:8941/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер через `/mcp` (тип HTTP, рівень
User). Сам сервер з Windows доступний за тією ж адресою.

**3. Перевірити.** `/mcp` має показати `tanstack-start-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
