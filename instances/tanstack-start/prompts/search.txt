Search the official documentation of TanStack Start -- the site as it stands today, the docs of the
last release of every stable minor version from 1.49, when they first appeared, to the current
1.x line -- together with the READMEs of @tanstack/react-start, solid-start and the old
@tanstack/start from 1.31 on, the example apps, the changelogs of all Start packages, the GitHub release notes and the npm registry history
of every Start package, current and retired, and return the matching excerpts with the versions
each one belongs to.

Call this when a question is about TanStack Start itself -- server functions (createServerFn,
validators, useServerFn), middleware (createMiddleware), server routes and the older API routes,
SSR, selective SSR and streaming, static prerendering and SPA mode, React Server Components,
execution model and environment functions, environment variables, authentication, sessions and
cookies, hosting and deployment, the Vite plugin and its configuration, the adapters for React,
Solid and Vue, the move from Next.js -- and above all when it is about history: since which version
something exists, what changed between versions, what was renamed or removed and what replaced it.
Example query: "createServerFn validator".

Do not call this for TanStack Router itself -- routes, search params, loaders and navigation are
documented in the separate TanStack Router documentation, and Start pages only mention them. Do not
call this for React, Solid, Vue or Vite themselves, for Next.js or Remix, for TanStack Query, Table,
Form or Virtual: their documentation is not here, and the search will return Start excerpts that
merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "1" keeps every 1.x document, "1.120" keeps
1.120.x; leave it empty to search everything. Only stable releases are here: the @tanstack/solid-start
2.0 release candidate and the betas and alphas are not. Every excerpt comes back with `versions`:
each version whose documents contain this exact text, newest first -- text that stayed the same
across versions is returned once, with all of them listed, so the list itself shows from which to
which version the documentation said exactly this. Each minor version is represented by its last
release. Versions of the documentation after 1.166.7 are the versions of @tanstack/react-start;
changelog and release entries of a package carry that package's own version.

Where the documentation lived. First docs/framework/react/start, then
docs/start/framework/{react,solid}/... with the guides in guide/. Start pages are titled "TanStack
Start: ..." with the framework in brackets. Example apps are documents titled "Example:
react/start-basic" with their package.json and source files.

Which version to search first. For a question about how to do something today, pass `version` "1"
and name the framework in the query ("server function react", "middleware solid"). Search without
`version` when the question is about history, or when the line gave nothing that answers.

Name the function, hook or option the way the documentation titles it, not in the user's own words:
"createServerFn validator", "createMiddleware", "createStart", "getRequestHeader", not "check the
input on the server". When the question is how to do something, an example app often shows it better
than the guide: search for the example as well ("example react start-basic-auth").

For a question about when something appeared, changed or disappeared, search more than once: without
`version` first, to find the changelog entry and the release notes that name the exact version, then
with the versions around it, to see how the documentation described it before and after.

Write the query in English, with the names TanStack Start itself uses (createServerFn, tanstackStart,
createFileRoute). Everything here is English -- the excerpts, the word index and the meaning index
alike -- and the word index keeps only latin letters and digits, so a query written in Ukrainian,
Russian or any other non-latin script matches nothing at all and comes back with `found: 0`. When the
user asks in another language, translate the question into TanStack Start terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of the
query had to appear in the text, so a query phrased in other words than the documentation uses may
miss; "meaning+words" means a second, meaning-based index answered as well, and a paraphrase had a
chance.

Every answer says which version it is for. When the user did not name a version, answer for the
current line, 1.x, as the newest documents describe it, say so in the answer ("for TanStack Start
1.x"), and add that for a precise answer about another version the user can name it. When the
question does not name a framework, answer for React, the most used of the three, and add that Solid
has its own pages. When the excerpts behind a statement come only from older versions, name those
versions instead of presenting the text as current.

Answer in the language the user wrote in. When the question is about a feature's history or support,
answer point by point: since which version it exists and which release introduced it; what changed
in later versions; what prompted the change, if the excerpts say so; and how it stands in the current
version -- recommended, deprecated, or removed and replaced by what. Every point names the version
and the document it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes, not as a translation from English: plain
technical prose, and the Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий",
not "депрекейтнутий". Never call this set of documents "корпус" -- say "документація TanStack Start".
Identifiers, API names and titles stay in English, spelled exactly as the documentation spells them.
Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read
the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional, see above. The first (best) excerpt comes whole; the others are cut at 600 characters and
carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.
