# tanstack-virtual — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про TanStack Virtual (до v3 — react-virtual) за офіційною
документацією всіх його версій — від react-virtual 1.0 (2020) до поточної 3.x, разом з кожним alpha й beta лінії 3, —
за прикладами кожної лінії, журналами змін і нотатками релізів пакетів, записами блогу TanStack і історією версій
пакетів у реєстрі npm. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає
самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо вся історія

TanStack Virtual міняв API разом із назвою: react-virtual 1.x–2.x — один хук `useVirtual` лише для React, з v3 —
ядро без фреймворку (`@tanstack/virtual-core`, клас `Virtualizer`) і адаптер на кожен фреймворк: `useVirtualizer` у
React, `injectVirtualizer` в Angular, `createVirtualizer` у Solid і Svelte. Старий пакет `react-virtual` 2.x досі має
~600 тисяч завантажень на тиждень, і питання до документації часто звучить «як це було в моїй версії», «з якої версії
є `lanes`» і «на що замінили». Відповідь дає лише документація саме тієї версії, тож корпус — не одна редакція сайту,
а вся історія репозиторію, і кожен документ несе свої версії.

Разом 947 документів; фрагментів в індексі — 2 115 (`expected_passages` у `checks.json`).

Документації небагато: на кожному тезі 10–13 файлів, і 201 тег дав лише 148 різних текстів — найбільше редакцій у
сторінки `Virtualizer` (41) і кореневого README (31).

Замір `quality` на першому корпусі: по словах 4 із 10, за змістом 3, разом 4; десятка «як модель» — 10 із 10. Перша
десятка — переказ питання своїми словами, і промахи тут здебільшого не порожні:

- **Запит не називає фреймворку, а ціль названо для React.** На «load more rows when the user scrolls near the
  bottom» пошук приносить приклад infinite-scroll для Angular, на «virtualize columns in a horizontal list» — приклади
  колонок Svelte і Vue. Приклади кожного фреймворку мають різні імена файлів, тож згортання варіантів їх не об'єднує.
- **Сторінка Marko — довгий посібник.** `docs/framework/marko/marko-virtual.md` розписує вікно, колонки, сітку,
  змінні розміри й SSR окремими розділами і на переказ без назв опцій часто стоїть першою.
- **Журнали змін і релізи пакета повторюють одне одного.** Нотатка релізу `@tanstack/virtual-core@3.13.14` дослівно
  та сама, що запис журналу змін, і обидві займають місце у видачі.

Десятка «як модель» — запити назвами опцій, як велить промпт. На першому замірі вона дала 8 із 10: на
«useVirtual options» з `version "2"` видача ставила першим розділ `useVirtual` (опції — його підрозділ), а запит
«lanes masonry» тягнув записи журналів змін, де є обидва слова. Ціль першого — тепер увесь розділ `useVirtual`,
другий запит — «lanes», як опцію названо в документації.

Поле `max_per_doc` заміряно 0/1/2/3: «як модель» 8, 5, 8, 8 (до правки двох цілей), перша десятка разом 4, 3, 4, 4 —
лишилося 2, як у tanstack-query. `fusion_depth` 30 і 60 опускали «разом» до 3 і 2 — поле не ввімкнене.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача. Перелік усіх 201 тегу
  документації лежить саме тут, у полі `tags` джерела `tv-docs`: оновлювач не питає в GitHub, які теги існують.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df tanstack-virtual <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| документація всіх версій | дерево кожного тегу через GitHub API, текст — `raw.githubusercontent.com` | `ghdocs-history` |
| приклади | тека `examples/` на тезі | `ghexamples` |
| журнали змін пакетів | `packages/*/CHANGELOG.md` гілки main | `changelog-named`, новий |
| нотатки релізів | GitHub API, відбір за префіксом тегу | `ghreleases-tagged` |
| реєстр npm | registry.npmjs.org, одне звернення на пакет | `npm-versions` |
| блог | `src/blog/*.md` репозиторію tanstack.com | `mdfile` |

Читач `changelog-named` додано разом із цим примірником (`engine/readers/changelognamed.py`). Він не пише нового
розбору: під загальним ім'ям реєструє той, що вже є в `sentry-changelog`, — журнал, поділений на версії, з префіксом
пакета в імені документа. Changesets пише журнал кожному пакету, і номери в них ті самі: запис «Updated dependencies
… @tanstack/virtual-core@3.13.12» стоїть дослівно в журналах react-, lit- й angular-virtual. `changelog-v` назвав би
всі три документи «3.13.12», і скан спільних ключів знайшов 44 такі збіги — однаковий запис трьох журналів злився б в
один фрагмент. З префіксом збігів нуль.

Особливості, які варто знати:

- **Сайт — не першоджерело.** tanstack.com/virtual будує сторінки з теки `docs/` репозиторію. Тож текст береться
  прямо з тегу, а адреса в шапці документа — blob на GitHub.
- **Де лежала документація.** 1.x–2.x — кореневий `README.md` і кілька сторінок сайту react-virtual
  (`docs/src/pages/docs/api.md` з хуком `useVirtual`, сторінки прикладів); 3.0 — `docs/guide/`, `docs/api/` і
  `docs/adapters/<фреймворк>-virtual.md`; пізніші 3.x — `docs/introduction.md`, `docs/api/` і
  `docs/framework/<фреймворк>/<фреймворк>-virtual.md`. Поле `slug_rewrite` зводить переїзди до одного імені: сторінка
  адаптера, вступ і встановлення кожної епохи — редакції тієї самої сторінки, і незмінний розділ зливається в один
  фрагмент.
- **Теги.** До v3.13.2 репозиторій ставив спільні теги `vX.Y.Z` (164, з них 73 alpha й beta лінії 3). Далі — лише теги
  окремих пакетів, і версією документації служать 37 тегів `@tanstack/virtual-core@X.Y.Z`: документація одна на всі
  пакети, а ядро — спільний знаменник адаптерів.
- **Версії пакетів розходяться.** З 3.13.3 кожен пакет нумерується сам: ядро вже на 3.17.x, `@tanstack/react-virtual`
  — на 3.14.x, `@tanstack/angular-virtual` пройшов лінії 4, 5 і 6. Журнали змін і релізи адаптерів несуть версію свого
  пакета; від якої версії ядра залежить кожен реліз адаптера, видно в документах реєстру npm цього адаптера.
- **Редакції того самого файла зливаються (`revision_suffix`)**, як у `tanstack-query`: ім'я документа несе хеш
  вмісту, і без поля незмінний розділ двох редакцій лишався б двома фрагментами.
- **Приклади — лише на останньому тезі кожної лінії** (v1.1.0, v2.10.4, `virtual-core@3.17.11`); `package.json` у
  кожному прикладі каже, на якій версії він написаний.
- **Блог — без версії.** Два записи блогу TanStack версії не мають, тож `expect_unversioned` у `checks.json` — `true`.

## Межі, про які треба пам'ятати

TanStack Query, Table, Router і решти TanStack тут немає, як і react-window чи react-virtualized. Приклади Marko
лежать без коду: читач прикладів бере `.ts`, `.tsx`, `.vue`, `.svelte` і подібні файли, а `.marko` серед них немає,
тож від 19 прикладів Marko в корпусі лише `package.json`; сама сторінка Marko-адаптера — повна. Сторінки прикладів
сайту react-virtual 2.x (`docs/src/pages/examples/*.md`) — лише рамка CodeSandbox без тексту; код тих самих прикладів
є в `tv-examples-v2`. Alpha й beta — не релізи: текст, що є лише в них, міг так і не вийти, і промпт велить моделі
казати про це прямо.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/tanstack-virtual-corpus-2026-10-09.tar.gz` (0,5 МБ, 947 текстів і
паспорт; перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів
немає ніде. Архів лежить лише на цій машині.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/tanstack-virtual-corpus-2026-10-09.tar.gz -C instances/tanstack-virtual
./df tanstack-virtual smoke
```

**Як знову винести** — після оновлення, коли `vectors` і `smoke` пройшли (вони ж збирають свіжий кеш):

```
ls -l instances/tanstack-virtual/index/passages.json       # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/tanstack-virtual-corpus-РРРР-ММ-ДД.tar.gz -C instances/tanstack-virtual corpus
find instances/tanstack-virtual/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/tanstack-virtual/index/passages.json > instances/tanstack-virtual/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти» і «Як повернути тексти».

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»): звірка індексу з документами і звірка паспорта з файлами.

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k
instances/tanstack-virtual/index/passages.json.gz`, далі `./df tanstack-virtual vectors` заллє колекцію Qdrant (~3
хвилини).

## Установка venv

```
cd instances/tanstack-virtual
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df tanstack-virtual sources --why   # перелік джерел і білий список
./df tanstack-virtual refresh         # завантажити все задеклароване (~16 хвилин)
./df tanstack-virtual manifest        # оновити паспорт
./df tanstack-virtual setup           # Qdrant чи пошук лише по словах
./df tanstack-virtual vectors         # залити корпус у docs-tanstack-virtual (~3 хвилини)
./df tanstack-virtual smoke           # перевірки
```

Перші ~5 хвилин `refresh` журнал мовчить, а `corpus/` порожній: читач проходить дерево кожного з 201 тегу і лише потім
починає писати файли. Без токена GitHub перелік тегів ішов би годинними вікнами по 60 звернень.

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df tanstack-virtual serve          # порт 8803
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8803/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user tanstack-virtual-docs http://127.0.0.1:8803/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `tanstack-virtual-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
