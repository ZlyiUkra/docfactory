Search the official TanStack Virtual documentation (react-virtual before v3) -- every published
version of it, from 1.0 to the current 3.x line, including the alpha and beta builds of 3.0 --
together with the example apps of every major line, the changelogs of all @tanstack/*-virtual
packages, the GitHub release notes, the TanStack blog posts about Virtual and the npm registry
history of every package, and return the matching excerpts with the versions each one belongs to.

Call this when a question is about TanStack Virtual itself -- the Virtualizer class and its
options (count, getScrollElement, estimateSize, overscan, horizontal, lanes, gap, paddingStart,
scrollMargin, initialRect, measureElement, rangeExtractor, getItemKey), VirtualItem,
scrollToIndex and scrollToOffset, getVirtualItems, getTotalSize, dynamic and variable sizes,
sticky items, infinite scroll, window virtualization (useWindowVirtualizer), grids and tables,
the adapters for React, Vue, Solid, Svelte, Lit, Angular and Marko, the old useVirtual hook of
react-virtual 1.x-2.x, an upgrade between major versions -- and above all when it is about
history: since which version something exists, what changed between versions, what was renamed
or removed and what replaced it. Example query: "useVirtualizer estimateSize measureElement".

Do not call this for React, Vue or the other frameworks themselves, for react-window,
react-virtualized or other virtual list libraries, for TanStack Query, Table, Router or the
rest of TanStack: their documentation is not here, and the search will return TanStack Virtual
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "3" keeps every 3.x document, "2.10" keeps
2.10.x, "3.13" keeps 3.13.x; leave it empty to search everything. Pre-releases belong to their
line: "3" also keeps 3.0.0-beta.12. Every excerpt comes back with `versions`: each version
whose documents contain this exact text, newest first -- text that stayed the same across
versions is returned once, with all of them listed, so the list itself shows from which to which
version the documentation said exactly this. Versions of the documentation after 3.13.2 are the
versions of @tanstack/virtual-core; the adapters number their releases on their own from 3.13.3
on (@tanstack/react-virtual is at 3.14.x while the core is at 3.17.x, @tanstack/angular-virtual
is on its own 4.x-6.x lines), and changelog and release entries of an adapter carry that
package's own version. Which core version an adapter release depends on is written in the npm
registry documents of that adapter.

Where the documentation lived. In 1.x and 2.x the package was react-virtual with one hook,
useVirtual; its documentation was the README of the repository and a few pages of its site
(docs/src/pages/docs/api.md and the example pages). From 3.0 the core is framework-agnostic
(@tanstack/virtual-core, the Virtualizer class) and every framework has an adapter package with
its own short page (docs/framework/react/react-virtual.md, earlier docs/adapters/...); the API
pages (Virtualizer, VirtualItem) are shared by all frameworks. Example apps are documents titled
"Example: react/dynamic" with their package.json and source files.

Which version to search first. For a question about how to do something today, pass `version`
"3" and name the framework of the project in the query ("scrollToIndex react"): without it, the
many editions of the old react-virtual README and API page, which differ by a line or two, can
take places with the useVirtual API of 2020-2022. If the user's project still runs react-virtual
2.x, pass "2" instead. Search without `version` when the question is about history, or when the
line gave nothing that answers.

Name the option or method the way the documentation titles it, not in the user's own words:
"estimateSize", "measureElement dynamic", "overscan", "useWindowVirtualizer", not "make rows of
different height work". When the question is how to do something, an example app often shows it
better than the API page: search for the example as well ("example react dynamic",
"example react infinite-scroll").

For a question about when something appeared, changed or disappeared, search more than once:
without `version` first, to find the changelog entry and the release notes that name the exact
version, then with the versions around it, to see how the documentation described it before and
after.

Write the query in English, with the names TanStack Virtual itself uses (useVirtualizer,
getVirtualItems, estimateSize, measureElement, scrollToIndex). Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin
letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into TanStack Virtual terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Every answer says which version it is for. When the user did not name a version, answer for the
default line, 3.x -- the line almost every project uses -- say so in the answer ("for TanStack
Virtual 3.x"), and add that for a precise answer about another version the user can name it.
When the excerpts behind a statement come only from older versions, name those versions instead
of presenting the text as current.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists and which release introduced it;
what changed in later versions; what prompted the change, if the excerpts say so; and how it
stands in the current version -- recommended, deprecated, or removed and replaced by what. Every
point names the version and the document it rests on; a point the excerpts do not support is
left out, not guessed. A text found only in alpha or beta builds may never have shipped in a
release: say so. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of documents
"корпус" -- say "документація TanStack Virtual". Identifiers, API names and titles stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts
that came back, not out of memory: if an excerpt was cut, read the whole of it before describing
what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
