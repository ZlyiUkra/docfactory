# telegram-bot — примірник фабрики docfactory

Цей примірник зібрав документацію Telegram Bot API і віддає її через сервер MCP, щоб модель відповідала з текстів Telegram, а не з
пам'яті. Бот у Telegram — це обліковий запис, яким керує програма. Програма шле звичайні HTTP-запити на `api.telegram.org`: щоб
надіслати повідомлення, вона викликає `sendMessage`, а щоб дізнатися про нові повідомлення, або сама питає `getUpdates`, або просить
Telegram викликати її адресу (webhook).

## Скільки цього

Усього 606 документів і 1320 фрагментів. Фрагмент — це шматок документа, який пошук повертає як окремий результат.

| Що | Документів |
|---|---|
| довідник Bot API: окрема сторінка на кожен метод | 185 |
| довідник Bot API: окрема сторінка на кожен тип | 400 |
| індекс Bot API, форматування, журнал змін усіх версій (зараз Bot API 10.3), можливості ботів, урок, Serverless, FAQ, webhook, Mini Apps, платежі й Telegram Stars, inline-режим, ігри, приклади | 20 |
| README власного сервера Bot API (`tdlib/telegram-bot-api`) | 1 |

Це знімок розділу ботів сайту core.telegram.org на 09.11.2026. Версій як окремих тек сайт не має: він завжди описує чинний Bot API.
Тому історію шукають у журналі змін Bot API: там для кожної версії перелічено, які методи й поля вона додала.

**Чого тут немає.** Telegram API, яким працюють повноцінні застосунки від імені людини (протокол MTProto, бібліотека TDLib), сюди не
входить: це інший вхід у Telegram, і боти ним не користуються. Сторонніх бібліотек для ботів (python-telegram-bot, aiogram, Telegraf,
grammY) теж немає. Тексти решти сайту core.telegram.org (MTProto, TDLib, Passport, Gateway) завантажено разом із цими й збережено в
архіві `telegram-corpus-2026-11-09.tar.gz`, тож окремий примірник для них можна зібрати без нового завантаження.

Замір `quality` на 09.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 8 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df telegram-bot <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| розділ ботів | markdown-версії сторінок `core.telegram.org/bots…` | `mdcrawl` |
| власний сервер Bot API | `README.md` гілки master `tdlib/telegram-bot-api` | `ghdocs-history` |

**Як знаходяться сторінки.** Сайт віддає markdown-версію майже кожної сторінки за тією самою адресою з `.md` в кінці, але повного
переліку сторінок немає. Тому читач `mdcrawl` починає з кількох вхідних сторінок і йде за посиланнями всередині них. Поле `within`
пускає обхід лише на `/bots.md` і адреси, що починаються з `/bots/`.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df telegram-bot serve
```

Порт — `8964`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user telegram-bot-docs http://127.0.0.1:8964/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `telegram-bot-docs` з інструментами `search_docs` і `read_section`. Якщо
сервер позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/telegram-bot-corpus-2026-11-09.tar.gz` (606 текстів, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\telegram-bot-corpus-2026-11-09.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/telegram-bot/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/telegram-bot-corpus-РРРР-ММ-ДД.tar.gz -C instances/telegram-bot corpus raw
find instances/telegram-bot/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/telegram-bot/raw
gzip -9 -c instances/telegram-bot/index/passages.json > instances/telegram-bot/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/telegram-bot-corpus-2026-11-09.tar.gz -C instances/telegram-bot
./df telegram-bot smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
