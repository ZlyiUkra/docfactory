# telegram — примірник фабрики docfactory

Цей примірник зібрав документацію розробника Telegram і віддає її через сервер MCP, щоб модель відповідала з текстів Telegram, а не з
пам'яті. Telegram дає програмам два різні входи. Перший — Bot API: бот — це обліковий запис, яким керує програма, і вона шле звичайні
HTTP-запити на `api.telegram.org` (`sendMessage`, `getUpdates`). Другий — Telegram API, яким працюють повноцінні застосунки від імені
людини: він ходить власним протоколом MTProto, а щоб не писати цей протокол самому, беруть бібліотеку TDLib. Тут лежить документація
обох входів.

## Скільки цього

Усього 3797 документів і 17 821 фрагмент. Фрагмент — це шматок документа, який пошук повертає як окремий результат.

| Що | Документів |

| довідник Bot API: окрема сторінка на кожен метод | 185 |
| довідник Bot API: окрема сторінка на кожен тип | 400 |
| решта розділу ботів: індекс Bot API, форматування, журнал змін усіх версій (зараз Bot API 10.3), можливості ботів, урок, Serverless, FAQ, webhook, Mini Apps, платежі й Telegram Stars, inline-режим, ігри, приклади | 20 |
| Telegram API: посібники за темами (`/api/…`) і зміни за шарами схеми (зараз шар 225) | 129 |
| схема Telegram API: сторінка кожного методу, конструктора й типу | 785 + 1610 + 616 |
| протокол MTProto, мова схем TL, TDLib, Telegram Passport, Gateway API, віджети, теми, стікери, CDN | 46 |
| GitHub: README, журнал змін і приклади TDLib, README власного сервера Bot API | 4 |

Це знімок сайту core.telegram.org на 09.11.2026. Версій як окремих тек сайт не має: він завжди описує чинний Bot API і чинний шар
схеми. Тому історію шукають у журналі змін Bot API і на сторінці шарів (`/api/layers`).

**Де є прогалини.** Довідник класів TDLib (`/tdlib/docs/`) згенеровано Doxygen, і markdown-версії він не має, тож його тут немає.
Ті самі класи описано в журналі змін і README TDLib лише частково. Сторонніх бібліотек для ботів (python-telegram-bot, aiogram,
Telegraf, grammY) тут теж немає.

Замір `quality` на 09.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 7 із 10.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df telegram <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| розділ ботів | markdown-версії сторінок `core.telegram.org/bots…` | `mdcrawl` |
| решта сайту | markdown-версії сторінок `/api`, `/method`, `/constructor`, `/type`, `/mtproto`, `/tdlib` та інших | `mdcrawl` |
| TDLib | `README.md`, `CHANGELOG.md`, `example/README.md` гілки master `tdlib/td` | `ghdocs-history` |
| власний сервер Bot API | `README.md` гілки master `tdlib/telegram-bot-api` | `ghdocs-history` |

**Як знаходяться сторінки.** Сайт віддає markdown-версію майже кожної сторінки за тією самою адресою з `.md` в кінці, але повного
переліку сторінок немає. Тому читач `mdcrawl` починає з кількох вхідних сторінок і йде за посиланнями всередині них. Поле `within`
обмежує, куди обхід може піти: розділ ботів і решта сайту — два окремі джерела, щоб їх можна було оновлювати окремо.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df telegram serve
```

Порт — `8964`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user telegram-docs http://127.0.0.1:8964/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `telegram-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/telegram-corpus-2026-11-09.tar.gz` (3797 текстів, паспорт і сховище сирого `raw/`;
перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\telegram-corpus-2026-11-09.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/telegram/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/telegram-corpus-РРРР-ММ-ДД.tar.gz -C instances/telegram corpus raw
find instances/telegram/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/telegram/raw
gzip -9 -c instances/telegram/index/passages.json > instances/telegram/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/telegram-corpus-2026-11-09.tar.gz -C instances/telegram
./df telegram smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
