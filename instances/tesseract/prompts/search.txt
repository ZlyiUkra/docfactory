Search the Tesseract OCR documentation, in English: Tesseract is the open-source OCR engine that recognizes text
in images, with a command-line program (tesseract), a C++ API (TessBaseAPI) and a C API, trained language
models (tessdata, tessdata_best, tessdata_fast: eng, ukr, rus, deu and over a hundred more, plus script models)
and LSTM training tools; around it, OCRmyPDF adds a searchable text layer to scanned PDFs (Tesseract with
Ghostscript and pikepdf), tesseract.js runs Tesseract compiled to WebAssembly in the browser and Node,
pytesseract and tesserocr call it from Python, node-tesseract-ocr calls the CLI from Node. The set holds the
whole site tesseract-ocr.github.io/tessdoc (installation and compiling, command-line usage, improving the
quality of the output, input formats, data files and the list of languages and scripts, training Tesseract
3.x, 4.x and 5.x, fine-tuning, VGSL network specs, C++ API examples, FAQ, common errors, Docker, OpenCL), and
for every stable release of tesseract-ocr/tesseract (1.03-5.5.x, man pages from 3.00) the man pages (tesseract
with every option and
config parameter, lstmtraining, lstmeval, combine_tessdata, combine_lang_model, text2image,
unicharset_extractor, wordlist2dawg, unicharset, unicharambigs), the README, the public API headers
(baseapi.h, capi.h, publictypes.h, renderer.h, the result iterators), the ChangeLog and the GitHub release
notes; the tesstrain README, Makefile and scripts; the READMEs and config files (hocr, pdf, alto, tsv, txt,
lstm.train, makebox, digits) of the tessdata repositories; for every stable release of OCRmyPDF its whole
documentation site (ocrmypdf.readthedocs.io), README, Python API and command-line arguments, and release
notes; for tesseract.js its docs/ folder, typings, constants, examples and release notes; for pytesseract and
tesserocr their module code; the README and version tables of all wrappers on npm and PyPI. Returns the
matching excerpts with the versions each one belongs to.

Call this when a question is about Tesseract or these wrappers: what a page segmentation mode (--psm) or OCR
engine mode (--oem) does; how to pass languages (-l ukr+eng), a whitelist or blacklist of characters, a
config variable (-c, tessedit_char_whitelist, preserve_interword_spaces, user_defined_dpi); how to get hOCR,
ALTO, PAGE, TSV, PDF or text output; where tessdata lives (TESSDATA_PREFIX, --tessdata-dir) and which model
set to choose; how to improve accuracy (rescaling, binarization, DPI, borders, deskew, noise); how to train or
fine-tune a model for a language, and what lstmtraining, text2image or combine_tessdata accept; how to use
TessBaseAPI (Init, SetImage, GetUTF8Text, GetIterator, SetVariable, MeanTextConf) or the C API; how OCRmyPDF
options work (--language, --deskew, --clean, --force-ocr, --skip-text, --redo-ocr, --mode, --output-type pdfa,
--optimize, --jobs, --sidecar) and its exit codes, plugins and Python API; how tesseract.js workers, schedulers,
recognize(), detect() and setParameters() work and where it loads its core and language files from; what
pytesseract image_to_string, image_to_data, image_to_boxes, image_to_osd do; how tesserocr PyTessBaseAPI works;
what changed between versions and which version first had a feature. Example query: "psm single line".

Do not call this for other OCR engines or cloud OCR services (ABBYY, Google Vision, AWS Textract, EasyOCR,
PaddleOCR), for image libraries themselves (Leptonica, OpenCV, Pillow, ImageMagick), or for PDF tools outside
OCRmyPDF (Ghostscript, qpdf, pikepdf, poppler have their own documentation).

Write the query in English, with the names the documentation uses (--psm, --oem, tessedit_char_whitelist,
TESSDATA_PREFIX, TessBaseAPI SetImage, lstmtraining --continue_from, ocrmypdf --skip-text, createWorker,
image_to_data). Everything here is English, and the word index keeps only latin letters and digits, so a query
written in Ukrainian, Russian or any other non-latin script matches nothing and comes back with `found: 0`.
When the user asks in another language, translate the question into Tesseract terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "розпізнавання", not "ріконгнішн"; "мовна модель", "режим сегментації
сторінки", "текстовий шар", "навчання". Never call this set of documents "корпус" -- say "документація
Tesseract". Option, parameter, function and variable names stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an
excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. The site pages carry no version: they are the current state. Documents from the
tesseract-ocr/tesseract repository carry the Tesseract version ("5.5.3"; "5.5" keeps every 5.5.x, "3.05" every
3.05.xx). The wrappers carry versions named after their package: "ocrmypdf-17.13.0", "tesseract.js-7.0.0",
"tesseract.js-core-6.1.2", "pytesseract-0.3.13", "tesserocr-2.11.0", "node-tesseract-ocr-2.2.1". When the user
names a version, pass it into `version` ("5.5", "4.1", "ocrmypdf-16", "tesseract.js-5"); never put it into the
query text. Without a version, answer for the newest release and say so.
