Search the documentation of testcontainers-go (github.com/testcontainers/testcontainers-go), the Go library that runs
throwaway Docker containers from tests: the site golang.testcontainers.org at every minor release 0.0 ... 0.44 --
quickstart, system requirements, the features (creating a container, wait strategies, networking, Docker Compose,
reusing containers, the Ryuk reaper and garbage collection, configuration through properties and environment
variables, files and mounts, logs, best practices) and the postgres, redis and compose modules; the pkg.go.dev
reference of the core package for every minor release (Run, GenericContainer, ContainerRequest, ContainerCustomizer,
CleanupContainer, TerminateContainer, Container, wait.ForLog, wait.ForListeningPort, wait.ForSQL, network.New) and of
the postgres module for 0.20 ... 0.44 (Run, WithDatabase, WithUsername, WithPassword, WithInitScripts,
BasicWaitStrategies, ConnectionString, MustConnectionString, Snapshot, Restore, WithSQLDriver); and the GitHub release
notes. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about running a real database or another service in a Docker container from Go tests:
starting PostgreSQL for integration tests, waiting until it is ready, getting the connection string, running
migrations or init scripts, resetting the database between tests with snapshots, sharing one container across a
package with TestMain, cleaning up containers, running in CI, Docker requirements and environment variables, and what
changed between releases.

Do not call this for Docker itself, for PostgreSQL itself, for Go testing in general (that is the Go documentation),
for testcontainers in other languages (Java, Node, .NET, Python), or for other modules of testcontainers-go beyond
postgres, redis and compose: their documentation is not here, and the search will return excerpts that merely mention
them, with confident-looking titles.

`version` narrows the search to one release: "0.44" or "0.44.0". Every excerpt comes back with `versions`: each release
whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("postgres.Run", "testcontainers.Run",
"GenericContainer", "ContainerRequest", "CleanupContainer", "TerminateContainer", "wait.ForLog", "WithOccurrence",
"wait.ForListeningPort", "BasicWaitStrategies", "ConnectionString", "WithInitScripts", "Snapshot", "Restore",
"TestMain", "Ryuk", "TESTCONTAINERS_RYUK_DISABLED", "reuse", "network.New", "compose", "DOCKER_HOST"), not in the
user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question
into the terms of the documentation first, then search.

Answer in the language the user wrote in. When that language is Ukrainian, write as a Ukrainian engineer writes, not
as a translation from English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not
"ексерпт"; "контейнер", "тест", "очікування", "знімок". Never call this set of documents "корпус" -- say
"документація testcontainers-go". Identifiers and titles stay in English, spelled exactly as the documentation spells
them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of
it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. testcontainers-go 0.44.0 is the newest release; the module API changed in 0.32
(postgres.Run instead of RunContainer, testcontainers.Run, CleanupContainer). Search without `version` first; every
answer says which release it is for.
