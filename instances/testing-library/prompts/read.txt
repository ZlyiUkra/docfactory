Return the full text of one excerpt of the Testing Library documentation (the site
testing-library.com with every framework wrapper, the eslint plugin rules, and for the React
line the README of each version, the release notes and the npm registry lists) by its
identifier, together with the document it belongs to, the URL it was taken from and the date
the text was fetched from that URL -- so a quotation can be checked against the source even
a year later.

Call this after `search_docs` when the excerpt you need came back cut at 600 characters, or
when the exact wording matters -- a query option, the order of query priority, an
act(...) warning, a matcher signature or a peer dependency range quoted half-way is how a
wrong answer starts.

Do not guess identifiers: they are not URLs, not function names and cannot be assembled by
hand. Every identifier this tool accepts comes from the `id` field of a `search_docs`
result.

The text comes back in English, as the documentation is written. Answer the user in their
own language, and follow the same rules as for `search_docs`: name the framework, the package
and the version, keep identifiers and titles in English, use Ukrainian words for Ukrainian
prose, and name the document you read.
