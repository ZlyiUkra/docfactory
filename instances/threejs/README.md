# threejs — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про three.js — бібліотеку 3D-графіки для браузера (сцена, камери,
рендерери WebGL і WebGPU, геометрії, матеріали, текстури, світло й тіні, завантажувачі моделей, анімація, raycasting,
контроли, постобробка, WebXR, TSL). Документація — сайт threejs.org з тегу кожного релізу r54–r186 (2013–2026),
офіційні приклади з кодом, вікі, README і реєстр npm пакета `three`, нотатки релізів; лише англійською. Код спільний і
лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій
фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

three.js випускає реліз щомісяця й нумерує його не семантично, а порядково: r186 — це 186-й реліз, на npm він
`0.186.x`. Між релізами ламається API, і Migration Guide вікі веде перелік змін із r41: `Geometry` зникла в r125,
приклади переїхали з `examples/js` у модулі `examples/jsm` у r148, з r167 з'явився `WebGPURenderer`, а довідник сайту в
r181 переписано з рукописного HTML на сторінки, згенеровані з JSDoc. Код на three.js живе роками (r170 досі дає 14 %
завантажень), тож відповідь мусить знати, до якого релізу вона.

**Що є що.** **Реліз rNNN** — випуск three.js, одночасно мінорна версія npm `0.NNN`; **довідник** (docs) — сторінка на
кожен клас із конструктором, властивостями й методами; **доповнення** (addons, колись `examples/jsm`) — контроли,
завантажувачі, постобробка поза ядром, у довіднику вони теж є; **посібник** (manual) — статті «Fundamentals»,
«Cameras», «Shadows» тощо; **TSL** — Three.js Shading Language, спосіб писати шейдери на JavaScript для WebGPU.

## Звідки документація

- **Сайт з тегів.** threejs.org — це теки `docs/` і `manual/` самого репозиторію, і довідник там завжди писали HTML.
  Читач `ghdocs-history-three` (`engine/readers/ghthree.py`) бере сторінки з тегу кожного релізу й розбирає три
  розмітки: дужкову r54–r180 (`[page:Vector3 v]`, `[method:this add]( [param:Vector3 v] )` → `.add( v : Vector3 ) :
  this`), сторінки з JSDoc із r181 (таблиця параметрів стає рядками «**ім'я** — опис») і статті посібника. Переклади
  (zh, ko, fr, it, ar, ja, ru, pt-br, zh-CN) не беруться.
- **Ключі сторінок.** Та сама сторінка за 13 років мала шлях `docs/api/math/Vector3.html`, `docs/api/en/math/Vector3.html`
  і `docs/pages/Vector3.html`; `slug_rewrite` у `config.json` зводить усі до `docs-pages-vector3`, а посібник — до
  `manual-pages-…`, щоб редакції різних релізів зливалися.
- **Версія — назва релізу.** Документи сайту й релізи несуть версію `r186`, як її пише three.js; README і реєстр npm —
  номер npm `0.186.1`. Фільтр `version: "r186"` бере сайт і реліз, `"0.186"` — README і реєстр.
- **Приклади** — лише останній реліз: 607 сторінок на кожен із 133 тегів роздули б корпус, а сайт показує код саме
  останнього. Документ прикладу — назва, підпис і весь код `<script type="module">` огорожею.
- **Вікі** — по сторінці на джерело читачем `ghwiki-page`; Migration Guide — найбільша (90 КБ).

## Межі, про які треба пам'ятати

- Довідника до r54 немає; Migration Guide веде зміни з r41.
- Приклади — лише r186; `llms-full.txt` сайту не взято: це той самий довідник одним файлом.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/threejs-corpus-2026-10-29.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\threejs-corpus-2026-10-29.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів немає
ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/threejs/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/threejs-corpus-РРРР-ММ-ДД.tar.gz -C instances/threejs corpus raw
find instances/threejs/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/threejs/raw
gzip -9 -c instances/threejs/index/passages.json > instances/threejs/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/threejs-corpus-2026-10-29.tar.gz -C instances/threejs
./df threejs smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/threejs/index/passages.json.gz`, далі
`./df threejs vectors` заллє колекцію Qdrant (близько хвилини на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df threejs …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/threejs/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df threejs sources --why              # перелік джерел і білий список
./df threejs refresh                    # усе: близько 80 хвилин мережею (паузи 0,1 с; дерева 133 тегів — 9 хв)
./df threejs manifest                   # оновити паспорт
./df threejs setup                      # Qdrant чи пошук лише по словах
./df threejs vectors                    # залити корпус у docs-threejs
./df threejs smoke                      # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df threejs serve             # порт 8935
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8935/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user threejs-docs http://127.0.0.1:8935/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `threejs-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
