# Оновлення корпусу threejs

README (`npm-readme-three`) і реєстр (`npm-three`) беруть версії з опису пакета в реєстрі npm, тож новий реліз three
потрапляє туди сам; релізи GitHub (`releases`) і сторінки вікі (`wiki-*`) читаються щоразу заново. Передрелізи не
беруться (`skip_versions: "-"` у README; теги релізів — лише `rNNN`).

Руками оголошено:

- **Сайт threejs.org** (`docs`): поле `tags` — тег кожного релізу, найновіший першим (`"r186": "r186"`). Версія
  документа — назва релізу, як її пише сам three.js (`r186`), а не номер npm (`0.186`). Новий реліз — новий рядок на
  початку `tags`. Якщо сайт знову перекладе теки (як у r96, r140, r181), — розширити `folders` і `exclude` у джерелі
  та правила `slug_rewrite` у `config.json`, щоб редакції тієї самої сторінки зливалися.
- **Приклади** (`examples`): лише останній реліз, поле `tags` з одним рядком. Новий реліз — замінити тег; документи
  попереднього релізу лишаються в теці — їх переносять в окрему теку поза корпусом руками, якщо не хочуть тримати
  обидві редакції.
- **Вікі** (`wiki-*`): по джерелу на сторінку. Нова сторінка вікі — нове джерело за зразком наявних.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df threejs refresh docs examples npm-readme-three npm-three releases
./df threejs refresh --missing    # джерела, яких не названо, лише докачуються
./df threejs manifest
./df threejs vectors
./df threejs smoke
# Ctrl+C у терміналі з serve, і знову: ./df threejs serve
```

Названі джерела оновлюються повністю, не `--missing`: у документі стоять усі версії, де текст був таким, тож новий
реліз змінює й старі документи (незмінна сторінка дописує нову версію в рядок `# версія:`). Документи редакцій, яких
у новому прогоні вже немає, лишаються в теці — їх переносять в окрему теку поза корпусом руками, перш ніж рахувати
вектори. Сховище сирого `raw/` повертається з архіву разом із текстами, тож після правки читача тексти
перебудовуються без мережі: `./df threejs build <id>`.

Якщо змінився найпоширеніший реліз (на 29.10.2026 — r186, близько 28 % завантажень; r170 — 14 %):

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` переглянути реліз за
  замовчуванням;
- у `checks.json`, у десятці `quality_model`, замінити `"r186"` і звірити цілі.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) потрібен для дерев 133 тегів і сторінок релізів.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df threejs quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
