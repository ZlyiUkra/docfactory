Search the three.js documentation and return the matching excerpts with the versions each one belongs to.
What is here: threejs.org (repository mrdoob/three.js) at every release r54 (2013) to r186 (2026) -- the API
reference of every class (Scene, Object3D, PerspectiveCamera, WebGLRenderer, WebGPURenderer, Mesh, the
geometries, the materials, the lights, the textures, the loaders, the math classes Vector3, Matrix4, Quaternion,
Euler, the animation system, audio, constants), the reference of the add-ons (OrbitControls and the other
controls, GLTFLoader and the other loaders, the post-processing passes, the exporters, the helpers, TSL nodes),
and the manual (fundamentals, responsive design, primitives, scenegraph, materials, textures, lights, cameras,
shadows, fog, render targets, custom geometry, picking, post-processing, optimization, WebXR, WebGPU, TSL);
the official examples of r186 (examples/*.html), without a version, each with its caption and full source code;
the wiki: the Migration Guide (what changed between every pair of releases since r41), Three.js Shading
Language, the editor manual, the JSON Object/Scene, Geometry, Material and Texture formats 4, build
instructions; the README of every stable version 0.54 to 0.186 and the npm registry history (versions, dates,
dist-tags) of the three package; the GitHub release notes of every release.

Call this when a question is about three.js: creating a scene, camera and renderer, the render loop, Object3D
transforms (position, rotation, quaternion, scale, lookAt), the scene graph (add, remove, traverse, Group),
geometries (BufferGeometry, BufferAttribute, BoxGeometry, PlaneGeometry, SphereGeometry, custom geometry),
materials (MeshStandardMaterial, MeshPhysicalMaterial, MeshBasicMaterial, ShaderMaterial, NodeMaterial),
textures and TextureLoader, lights and shadows, cameras and controls, loading models (GLTFLoader, DRACOLoader,
FBXLoader, OBJLoader), animation (AnimationMixer, AnimationClip, KeyframeTrack), raycasting and picking,
InstancedMesh, render targets and post-processing (EffectComposer), WebXR, WebGPURenderer and TSL,
disposing resources, the Migration Guide -- and history: since which release a class or option exists, what
changed in a release, how to migrate between releases.

Do not call this for React Three Fiber, drei, A-Frame, Babylon.js or other engines and wrappers, for WebGL,
WebGPU, GLSL or WGSL themselves, for Blender or glTF as formats, or for JavaScript language questions: their
documentation is not here, and the search will return three.js excerpts that merely mention them, with
confident-looking titles.

`version` narrows the search to one release: "r186" keeps the documents of that release; leave it empty to
search everything. Releases are named as three.js names them, rNNN, one per npm minor (r186 is npm 0.186);
the README and registry documents carry the npm number ("0.186"). Every excerpt comes back with `versions`:
each release whose documents contain this exact text, newest first, so the list itself shows from which to
which release the documentation said exactly this.

Write the query in English, with the names three.js itself uses ("PerspectiveCamera", "OrbitControls",
"MeshStandardMaterial", "GLTFLoader", "AnimationMixer", "InstancedMesh"), not in the user's own words.
Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the
question into three.js terms first, then search.

Answer in the language the user wrote in. When the question is about a class's or option's history or support,
answer point by point: since which release it exists; what changed in later releases; what prompted the change,
if the excerpts say so; and how it stands in the current release. Every point names the release and the
document it rests on; a point the excerpts do not support is left out, not guessed. When that language is
Ukrainian, write as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and
the Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never
call this set of documents "корпус" -- say "документація three.js". Identifiers, option names and titles stay
in English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated:
true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. r186 carries about 28% of the weekly downloads, r170 about 14%, r185 about 10%,
r180 about 8%. Search with `version` "r186" for a question about how to do something. If the user names a
release or writes code of an older API (THREE.Geometry, Face3, the global THREE script tag, examples/js), search
that release or the Migration Guide. Search without `version` when the question is about history, the examples
or the wiki (no version), or when the release gave nothing. Every answer says which release it is for; when the
user did not name one, answer for r186 and say so. When the excerpts behind a statement come only from older
releases, name those releases instead of presenting the text as current.
