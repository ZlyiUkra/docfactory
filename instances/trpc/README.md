# trpc — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про tRPC — бібліотеку типобезпечних API на TypeScript без схем і
генерації коду (сайт trpc.io, репозиторій trpc/trpc, реєстр npm). Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

tRPC з'єднує сервер і клієнт на TypeScript без опису схеми: на сервері роутер (`initTRPC`, `router`) складають із
процедур (`publicProcedure.input(…).query(…)`, `mutation`, `subscription`), контекст (`createContext`) і middleware
дають кожній процедурі користувача й з'єднання з базою, а клієнт (`createTRPCClient` з посиланнями `httpBatchLink`,
`httpSubscriptionLink`, `splitLink`) чи інтеграція з TanStack React Query бачать типи вводу й виводу кожної процедури
напряму з типу роутера. У плані Next.js (фулстек-родина) tRPC — типізовані виклики сервера поверх дій.

Разом 1603 записи паспорта; в індексі 1394 документи й 5037 фрагментів (`expected_passages` у `checks.json`):
однаковий текст різних версій — один уривок із переліком версій. Замір `quality`: по словах 3 із 10, за змістом 5,
разом 5, «як модель» 10 із 10. Своїми словами нижче, бо перша десятка питає побутовими словами («об'єднати кілька
запитів в один»), а сторінки говорять назвами функцій і посилань.

Чому сайт береться з репозиторію. Сайт trpc.io зібрано Docusaurus з теки `www/` монорепозиторію, і кожен тег `vX.Y.Z`
тримає сайт тієї версії; береться останній тег кожної мінорної (131 тег 0.7–11.21; тека `www/docs` — з 3.3, раніше
був лише README). Одне джерело з усіма тегами: однаковий файл різних тегів тягнеться й лежить один раз, а в його
версії лягають усі теги, де він був таким. Сторінки цитуються файлами на GitHub: адреси trpc.io задає поле `slug`
шапки сторінки, і вирахувати їх зі шляху не можна.

Теги `v11.20.0` і `v11.21.0` (27–28.09.2026) є в репозиторії, але в npm не вийшли: на 26.10.2026 найновіша в npm —
11.19.0.

Чого немає. Довідник typedoc сайту (trpc.io/docs/typedoc) збирається з коду під час побудови сайту й у репозиторії не
лежить. Теки `www/versioned_docs` не беруться окремо: це ті самі сторінки v9 і v10, що вже є з тегів цих ліній. Код і
тести пакетів, Next.js, React, TanStack Query, Zod, Express і Fastify як окремі проєкти. Пререлізи (`-rc`, `-alpha`,
`-canary`) не беруться; виняток — `@trpc/openapi`, у якого стабільних версій ще немає.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df trpc <крок>`.

## Версії

Сторінки сайту, README й навички несуть версію тегу, з якого взяті (`11.21.0`), релізи — версію релізу, реєстр — версію
пакета; фільтр `version` бере мажор (`"11"`), мінор (`"10.45"`) або точну версію (`"9.27.4"`). За завантаженнями
`@trpc/server` у npm за тиждень до 26.10.2026 лінія 11 тримає 90 %, лінія 10 — 8 %, лінія 9 — 2 %, тож промпт відповідає
для 11.x, а для коду на v10 чи v9 (`createTRPCProxyClient`, `trpc.router().query(…)`) каже, що змінилося.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/trpc-corpus-2026-10-26.tar.gz` (1603 тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\trpc-corpus-2026-10-26.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/trpc/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/trpc-corpus-РРРР-ММ-ДД.tar.gz -C instances/trpc corpus raw
find instances/trpc/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/trpc/raw
gzip -9 -c instances/trpc/index/passages.json > instances/trpc/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/trpc-corpus-2026-10-26.tar.gz -C instances/trpc
./df trpc smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/trpc/index/passages.json.gz`,
далі `./df trpc vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df trpc …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df trpc sources --why   # перелік джерел і білий список
./df trpc refresh         # завантажити все задеклароване (близько 20 хвилин)
./df trpc manifest        # оновити паспорт
./df trpc setup           # Qdrant чи пошук лише по словах
./df trpc vectors         # залити корпус у docs-trpc
./df trpc smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df trpc serve          # порт 8903
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8903/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user trpc-docs http://127.0.0.1:8903/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `trpc-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
