Search the documentation of tRPC -- the library for end-to-end typesafe APIs in TypeScript without schemas or code
generation (site trpc.io, repository trpc/trpc, the npm registry). The corpus holds every page of the site as it stood
at the last tag of every minor of tRPC, 3.3 to 11.21: the introduction and the quickstart; the server -- `initTRPC`,
routers and merging routers, procedures (`publicProcedure`, `query`, `mutation`, `subscription`), the context
(`createContext`), middlewares, input and output validators (Zod, Valibot, ArkType and others), error handling with
`TRPCError` and error formatting, data transformers (`superjson`), metadata, server-side calls
(`createCallerFactory`), authorization, the adapters (standalone, Express, Fastify, Fetch, Next.js, AWS Lambda),
subscriptions over SSE and WebSockets (`tracked`), caching and non-JSON content types (FormData, files); the client --
the vanilla client (`createTRPCClient`), the links (`httpBatchLink`, `httpBatchStreamLink`, `httpSubscriptionLink`,
`wsLink`, `splitLink`, `loggerLink`), the TanStack React Query integration (`createTRPCContext`, `useTRPC`,
`queryOptions`, `mutationOptions`), the classic React Query integration (`createTRPCReact`, `useQuery`, `useMutation`,
`useUtils`), Next.js with the App Router and the Pages Router (`createTRPCNext`, SSR, SSG, `createServerSideHelpers`);
the migration guides (v9 to v10, v10 to v11), the FAQ and the blog. It also holds the README of the repository and of
every package at the same tags (tRPC 0.7 to 3.2 had no site, only these), the agent skills shipped in the packages
(`packages/*/skills`), the GitHub releases, the npm registry entry of `@trpc/server`, `client`, `react-query`, `next`,
`tanstack-react-query`, `openapi`, `upgrade` and the old `@trpc/react` with release dates, and the examples folder of
the repository at 11.21.0. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about tRPC as it describes itself -- how to define a router and procedures, how to
validate input, how to build the context and protect procedures with a middleware, how to throw and format errors, how
to mount tRPC in Express, Fastify, Next.js or a fetch runtime, how to set up the client and its links, how to use tRPC
with TanStack React Query or in the Next.js App Router, how to call a procedure on the server, how to stream or
subscribe -- and history: since which version a function or option exists, what changed between versions (v9 to v10
and v10 to v11 above all: the migration guides and the releases list it).

Do not call this for Next.js, React, TanStack Query, Zod, Express or Fastify as their own projects: their documentation
is not here -- these pages only show how tRPC is used with them -- and the search will return excerpts that merely
mention them, with confident-looking titles. The typedoc API reference of the site is not here either.

`version` narrows the search to one release line of tRPC: a line of one number keeps every document of that major
("11" keeps 11.x), two numbers keep a minor ("10.45"), three an exact version ("9.27.4"). The site pages carry the
version of the tag they were taken from; pages unchanged across versions carry all of them. Every excerpt comes back
with `versions`: each version whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("initTRPC", "router", "publicProcedure",
"procedure", "query", "mutation", "subscription", "input", "output", "middleware", "createContext", "TRPCError",
"errorFormatter", "transformer", "superjson", "createCallerFactory", "createTRPCClient", "httpBatchLink",
"httpBatchStreamLink", "httpSubscriptionLink", "wsLink", "splitLink", "createTRPCContext", "useTRPC", "queryOptions",
"createTRPCReact", "useUtils", "createTRPCNext", "createServerSideHelpers", "inferRouterOutputs", "tracked"), not in
the user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script
matches nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question
into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація tRPC". Identifiers, parameters and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. By npm downloads of `@trpc/server` in the week before 26 October 2026 the line 11 holds
90 % (11.19.0 of 16 September 2026 is the newest in npm; the tags 11.20.0 and 11.21.0 are in the repository but were
not published to npm), the line 10 -- 8 %, the line 9 -- 2 %. Answer for 11.x: search without `version` first, then
with "11" if older pages crowd the results; when the user's code is on v10 (`createTRPCProxyClient`,
`createTRPCReact` with `useContext`) or v9 (`trpc.router().query(...)`, `createReactQueryHooks`), search that line as
well and say what changed. Every answer says which version it is for.
