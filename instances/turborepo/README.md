# turborepo — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Turborepo — систему збирання монорепозиторіїв JavaScript і
TypeScript від Vercel (сайт turborepo.dev, колишні turbo.build і turborepo.com; репозиторій vercel/turborepo; реєстр npm).
Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Монорепозиторій тримає кілька застосунків і спільні пакети поруч, і кожна команда `build`, `lint` чи `test` мусить
іти в правильному порядку й не перезапускати те, що не змінилося. Turborepo бере задачі з `package.json`, будує граф
пакетів і задач з `turbo.json` (`tasks`, `dependsOn`, `outputs`, `inputs`), кешує результат кожної задачі за хешем
вводу — локально й через Remote Caching — і запускає лише потрібне (`--filter`, `--affected`). У плані Next.js
(фулстек-родина) — у розділі «знати, що існує»: кілька застосунків в одному репозиторії.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df turborepo <крок>`.

## Версії

Сторінки сайту, блог, навичка й README несуть версію тегу, з якого взяті (`2.11.10`), релізи — версію релізу, реєстр —
версію пакета; фільтр `version` бере мажор (`"2"`), мінор (`"1.13"`) або точну версію (`"2.11.10"`). За завантаженнями
`turbo` у npm за тиждень до 26.10.2026 лінія 2 тримає 98 %, лінія 1 — 2 %, тож промпт відповідає для 2.x, а для
`turbo.json` з `pipeline` замість `tasks` (1.x) каже, що змінилося.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/turborepo-corpus-2026-10-26.tar.gz` (1812 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\turborepo-corpus-2026-10-26.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/turborepo/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/turborepo-corpus-РРРР-ММ-ДД.tar.gz -C instances/turborepo corpus raw
find instances/turborepo/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/turborepo/raw
gzip -9 -c instances/turborepo/index/passages.json > instances/turborepo/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/turborepo-corpus-2026-10-26.tar.gz -C instances/turborepo
./df turborepo smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/turborepo/index/passages.json.gz`,
далі `./df turborepo vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df turborepo …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df turborepo sources --why   # перелік джерел і білий список
./df turborepo refresh         # завантажити все задеклароване (близько 25 хвилин)
./df turborepo manifest        # оновити паспорт
./df turborepo setup           # Qdrant чи пошук лише по словах
./df turborepo vectors         # залити корпус у docs-turborepo
./df turborepo smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df turborepo serve          # порт 8906
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8906/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user turborepo-docs http://127.0.0.1:8906/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `turborepo-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
