# Оновлення корпусу turborepo

Сайт, блог, навичка й README беруться з закріплених комітів: джерело `turbo-repo` тримає в полі `tags` коміт
останнього тегу `vX.Y.Z` кожної мінорної, приклади — коміт тегу 2.11.10. Релізи GitHub і реєстр npm беруться щоразу
заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

**Нова версія Turborepo.** Новий патч наявної мінорної — замінити в полі `tags` джерела `turbo-repo` коміт і версію її
рядка; нова мінорна — новий рядок нагорі `tags` (від найновішого). Коміт тегу дає
`https://api.github.com/repos/vercel/turborepo/git/ref/tags/vX.Y.Z` (для анотованого тегу — ще один крок через
`git/tags/<sha>`) або `git ls-remote --tags https://github.com/vercel/turborepo` (рядок `^{}` — коміт анотованого тегу).
У джерелі `turbo-examples` — замінити коміт в адресі й поле `version`. Якщо сайт знову переїде в іншу теку — дописати її
в `folders` і в перший вираз `slug_rewrite` у `config.json`.

```
./df turborepo check                 # чи змінилося щось нагорі за джерелом
./df turborepo refresh               # повне перезавантаження, близько 25 хвилин
./df turborepo manifest
./df turborepo vectors
./df turborepo smoke
# Ctrl+C у терміналі з serve, і знову: ./df turborepo serve
```

Якщо змінилося співвідношення завантажень ліній (на 26.10.2026 лінія 2 — 98 %) чи найновіша версія в npm (2.11.10),
— у `prompts/search.txt` (абзац «Which version to search first») і `prompts/agent.txt` замінити лінії й числа.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df turborepo quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
