Call this when a question is about Turborepo as it describes itself -- how to lay out a monorepo, how to declare a
task and its dependencies in `turbo.json`, why a task misses the cache or what goes into its hash, how to pass
environment variables to tasks, how to filter packages or run only affected ones, how to set up Remote Caching, how

Do not call this for Turbopack, Next.js, pnpm, npm, Yarn, Bun, Docker or the CI services as their own projects: their
documentation is not here -- these pages only show how Turborepo is used with them -- and the search will return
excerpts that merely mention them, with confident-looking titles. The Rust source code of `turbo` is not here either.

`version` narrows the search to one release line of Turborepo: a line of one number keeps every document of that
major ("2" keeps 2.x), two numbers keep a minor ("1.13"), three an exact version ("2.11.10"). The site pages carry the
version of the tag they were taken from; pages unchanged across versions carry all of them. Every excerpt comes back
with `versions`: each version whose documents contain this exact text, newest first.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
