Call this when a question is about UploadThing as it describes itself -- how to define a file route and restrict
types and sizes, how to authenticate an upload in `middleware` and pass metadata to `onUploadComplete`, how to mount
the route handler (`createRouteHandler`) in Next.js or another framework, how to render and style `UploadButton` and
`UploadDropzone`, how to upload or delete files from the server with `UTApi`, which environment variable holds the
token (`UPLOADTHING_TOKEN`), what an error code means -- and history: since which version a function or option exists,
what changed between versions (v6 to v7 above all: the changelogs and the migration guide list it).

Do not call this for Next.js, React, Nuxt, Express or Fastify as their own projects, nor for S3 or other storage
services: their documentation is not here -- these pages only show how UploadThing is used with them -- and the
search will return excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line of `uploadthing`: a line of one number keeps every document of that
major ("7" keeps 7.x), two numbers keep a minor ("7.7"), three an exact version ("6.13.3"). The site pages carry the
version of the tag they were taken from; pages unchanged across versions carry all of them. Every excerpt comes back
with `versions`: each version whose documents contain this exact text, newest first.

Write the query in English, with the names the documentation itself uses ("file route", "createUploadthing",
"middleware", "onUploadComplete", "createRouteHandler", "UploadButton", "UploadDropzone", "useUploadThing",
"generateReactHelpers", "UTApi", "uploadFiles", "deleteFiles", "ufsUrl", "customId", "UPLOADTHING_TOKEN",
"UploadThingError", "appearance", "regions", "ACL", "awaitServerData"), not in the user's own words. Everything here
is English -- the excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters
and digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes
back with `found: 0`. When the user asks in another language, translate the question into the terms of the
documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it rests
on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус"
-- say "документація UploadThing". Identifiers, parameters and titles stay in English, spelled exactly as the
documentation spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was
cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
