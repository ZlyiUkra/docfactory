# QStash: Retry a Message Now
# джерело: https://upstash.com/docs/qstash/api-reference/messages/retry-a-message-now
# отримано: 2026-10-16

> Deliver a delayed message, or a message waiting for its next retry, immediately

`POST /v2/messages/{messageId}/retry`

This endpoint skips the remaining wait of a waiting message and delivers it right away. It works for:

- **Delayed messages**, published with `Upstash-Delay` or `Upstash-Not-Before`, including sleeping workflow steps.
- **Retrying messages**, whose last delivery failed and which are waiting out the retry delay before the next attempt.

Retrying now does not add an extra attempt. It moves the already scheduled retry forward, so the retry count and the remaining retries stay the same.

You can find messages waiting for a retry by listing the logs with `state=RETRY`.

With the TypeScript SDK, use `client.messages.runNow("<MESSAGE_ID>")`.

See Run a Delayed Message Now for more details.

Note:
Messages published to a queue can not be rescheduled to retry now. The request returns `400` for them.

## Request

`POST https://qstash-{region}.upstash.io/v2/messages/{messageId}/retry`

Authentication: `bearerAuth`, `bearerAuthQuery` headers.

**Parameters**

- `messageId` (path, string, required)
  The identifier of the message to deliver now.

## Response

**200** — The message is rescheduled for immediate delivery.

**400** — The message id is invalid, or the message belongs to a queue.

- `error` (string, required)
  Error message

**404** — Message not found, or the message is not waiting for a delay or a retry.

- `error` (string, required)
  Error message
