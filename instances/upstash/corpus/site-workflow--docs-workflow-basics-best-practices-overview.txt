# Workflow: Best practices
# джерело: https://upstash.com/docs/workflow/basics/best-practices/overview
# отримано: 2026-10-16

Keep the rules below in mind to avoid unexpected behavior and failures.

To learn more about how the internal of Upstash Workflow works, see how Workflow works.

**Execute business logic in context.run**

Your endpoint runs many times per workflow run. Only code inside a step runs exactly once.

**Return results from context.run**

Variables assigned inside a step are lost on the next call. Return the value instead.

**Avoid non-deterministic code outside context.run**

Database reads, time checks, and randomness must produce the same result on every call.

**Ensure idempotency in context.run**

Steps can be retried. Running one twice must have the same effect as running it once.

**Keep workflows within hard limits**

A workflow run can have at most 1,000 steps and a 100 MB context.

**Don't nest context methods**

Never call `context.run`, `context.sleep`, or `context.call` inside another `context.run`.

**Include at least one step**

A workflow without any `context.run` fails with `Failed to authenticate Workflow request.`

**Avoid Promise.any**

`Promise.all` works for parallel steps, but `Promise.any` isn't supported.
