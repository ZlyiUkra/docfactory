Search the Upstash documentation, in English: Upstash is the serverless data platform billed per request --
Upstash Redis (a Redis-compatible database reachable over TCP and over an HTTP REST API, for serverless and
edge runtimes) with its clients @upstash/redis for TypeScript and upstash-redis for Python, the rate limiter
@upstash/ratelimit and upstash-ratelimit, QStash (HTTP message queue and scheduler: publish, schedules, URL
groups, queues, DLQ, signatures), Workflow (durable serverless functions on QStash: serve, context.run, sleep,
call, waitForEvent, invoke, agents), Vector (vector database: upsert, query, namespaces, hybrid indexes),
Search, Realtime (Redis Streams subscriptions for React), Blob (file storage), Box (sandboxes for AI coding
agents), the retired Kafka, Context7 (docs for AI agents: MCP server, SDK, ctx7 CLI), the Upstash CLI, the MCP
servers, the Terraform and Pulumi providers and the Developer API. The set holds the whole site
upstash.com/docs (Redis command reference of 334 commands, SDK pages per method, guides, quickstarts,
integrations, troubleshooting, pricing, Developer API endpoints; the Kafka section as it stood in May 2025),
the blog (400 posts, 2021-2026) and glossary, and for every stable release of every official SDK and tool
(TypeScript, Python, Go, PHP) the README, CHANGELOG, source code, tests, example READMEs, skills and GitHub
release notes; the version tables and README of every @upstash package on npm and of the Upstash projects on
PyPI; the official examples. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about Upstash: how to connect to Upstash Redis from Next.js, Vercel, Cloudflare
Workers or Node (Redis.fromEnv, REST token, pipeline, multi, auto-pipelining, JSON, scripting, Search, Vector
commands), what a Redis command does and what Upstash supports, how to rate limit with sliding window, token
bucket or fixed window and what ephemeral cache, analytics and timeouts do, how to publish, schedule, retry,
deduplicate or verify QStash messages, how to write and deploy a Workflow (serve, steps, parallelism,
waitForEvent, failure function, Hono, Express, Next.js), how to upsert and query vectors, how Search indexes
and queries work, how Realtime channels and events work, how Blob uploads work, how to create and use a Box,
what the Developer API or Terraform resource for a database looks like, what changed between versions of a
package, which version first had a method, what a blog post explains. Example query: "Ratelimit slidingWindow".

Do not call this for the Redis server itself (redis.conf, persistence, Cluster, Sentinel: the redis instance),
for the clients ioredis and node-redis (their own instances), for BullMQ (the bullmq instance), or for other
cloud providers' managed Redis (ElastiCache, Azure Cache, Redis Cloud).

Write the query in English, with the names Upstash uses (Redis.fromEnv, pipeline, Ratelimit.slidingWindow,
publishJSON, context.run, waitForEvent, upsert, namespace, createBox). Everything here is English, and the
word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing and comes back with `found: 0`. When the user asks in another language,
translate the question into Upstash terms first, then search.

Answer in the language the user wrote in. For a question about history or a change between versions, answer
point by point: since which version; what changed; how it stands in the newest one -- each point with its
version and the page it rests on; a point the excerpts do not support is left out, not guessed. When that
language is Ukrainian, write as a Ukrainian engineer writes: plain technical prose, the Ukrainian word wherever
one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий"; "черга", "обмеження частоти",
"безсерверний". Never call this set of documents "корпус" -- say "документація Upstash". Command, method,
option and package names stay in English, spelled exactly as the documentation spells them. Build the answer
out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it before
describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the
whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had
to appear in the text; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Which version to answer for. The site pages, the blog, the examples and the skills carry no version: they are
the current state. SDK documents carry versions named after their package: "redis-1.39.0" is @upstash/redis
1.39.0, "ratelimit-2.2.0", "qstash-2.12.0", "workflow-1.4.0", "vector-1.2.3", "upstash-redis-1.8.0" is the
Python client, "qstash-py-3.4.0" the Python QStash SDK, "box-cli-0.3.5", "context7-mcp-4.4.2",
"terraform-2.1.0". When the user names a version, pass it as "<package>-<version>" into `version`
("redis-1.39" keeps every 1.39.x of @upstash/redis, "qstash-2" every 2.x); never put it into the query text.
Without a version, answer for the newest release and say so. Documents are named by source and path:
"docs-redis-commands-string-get", "docs-workflow-basics-serve", "docs-qstash-howto-publishing",
"blog-data-blog-2024-05-21-...", "redis-js-readme", "redis-js-packages-redis-src-pkg-ts",
"ratelimit-js-src-ratelimit-ts", "qstash-js-releases ...", "redis-readme-markdown-...", "upstash-redis-line-1".
