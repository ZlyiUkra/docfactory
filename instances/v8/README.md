# v8 — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про рушій JavaScript і WebAssembly V8 за його офіційним сайтом v8.dev —
документацією, блогом і поясненнями можливостей — в усіх редакціях сайту від V8 7.0 (жовтень 2018) до поточної
15.4. Поруч — неофіційні навчальні нотатки й код `danbev/learning-v8`: як V8 влаштований усередині, показано на
вихідному коді й тестах C++ API. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека
тримає самі дані домену.
Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо історія

V8 не має документації на кожну версію: v8.dev завжди описує рушій таким, яким він є зараз. Але рушій змінюється
швидко, і порада з оптимізації коду залежить від того, які компілятори стоять у конвеєрі. У 2017 році це були
Full-codegen і Crankshaft, з 2017 — Ignition і TurboFan, у 2021 додався Sparkplug, у 2023 — Maglev. Допис блогу
описує V8 на мить свого написання, а сторінка docs за роки переписується. Тому корпус тримає сайт у кожній редакції,
а кожна редакція знає, до яких версій V8 і яких років вона належала: видно, що сайт казав тоді і що каже тепер.

Разом 1 026 документів. З сайту — 946: кожен — неповторна редакція одного файла (приблизно 260 файлів у 84 знімках).
З learning-v8 — 80: один файл — один документ, лише поточний стан гілки `master`. Фрагментів в індексі — 3 437
(`expected_passages` у `checks.json`). Фрагменти — це шматки документів між заголовками, по яких іде
пошук; незмінні розділи різних редакцій зливаються в один (`revision_suffix`).

Замір `quality` після додавання learning-v8 (30.09.2026): перша десятка (питання своїми словами, без назв V8) — по
словах 6 із 10, за змістом 6, разом 6; друга, «як модель» (назвами, як велить промпт), — 9 із 10. На першому корпусі
було 6, 6, 7 і 9. Промахи:

- **Своїми словами без назв.** «Ярус компілятора між базовим і найвищим оптимізувальним» не знаходить допис про
  Maglev, «профілювальник Linux» — сторінку `linux-perf`, «що тримає об'єкти живими» — сторінку про витоки пам'яті:
  слова питання й документації не перетинаються. Тому промпт велить писати запит назвами V8; з ними перші два
  влучають.
- **Запуск файла власною оболонкою рушія** втратив влучання «разом»: пошук за змістом тепер ставить вище README
  прикладу rusty-v8 («Run») і розділ «v8 shell startup» нотаток, і `src-docs-d8` лишився п'ятим за змістом, а в
  злиття не пройшов. Нотатки справді про те саме; запит назвою («d8 shell») сторінку d8 знаходить першою.
- **Єдиний промах другої десятки** — «memory leaks heap snapshot»: сторінка «Investigating memory leaks» говорить про
  `%DebugTrackRetainingPath` і retaining path, а не про heap snapshot, тож місця зайняв допис про прискорення знімків
  купи. Запит не переписано під видачу: це була б підгонка заміру.

## Що в цій теці

- `corpus/` — документація звичайними текстовими файлами; поруч `index.json` — паспорт, тобто опис копії: адреса,
  дата завантаження й сума тексту кожного документа.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача. Дати версій V8 лежать тут, у
  полі `milestones` джерела `v8-site`.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (лише для завантаження корпусу); `.mcp.json` —
  запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df v8 <крок>`.

## Звідки документація

Сайт v8.dev зібрано з markdown репозиторію `v8/v8.dev`: кожна сторінка сайту внизу веде туди посиланням «Edit this
page on GitHub». Нотатки й код — з репозиторію `danbev/learning-v8`. Білий список — лише ці два репозиторії: дерева
й перелік комітів через GitHub API, текст — `raw.githubusercontent.com/v8/v8.dev/` і
`raw.githubusercontent.com/danbev/learning-v8/`.

| Що | Джерело | Читач |
|----|---------|-------|
| docs, blog, features усіх редакцій | гілка `main` репозиторію `v8/v8.dev` на кожну версію V8 | `ghsite-milestones` |
| нотатки learning-v8 | `README.md` і `notes/*.md` гілки `master` | `ghdocs-heading` |
| код learning-v8 | решта файлів гілки `master` | `ghcode`, новий |

Читач `ghsite-milestones` новий, його додав цей примірник. Наявний `ghsite-dated` бере дати версій з реєстру npm, а V8
на npm немає. Чим новий відрізняється:

- **Дати версій — у самому джерелі.** Версія V8 прямо відповідає версії Chrome: V8 12.4 — це Chrome 124 (сторінка
  `docs/version-numbers`). Дата версії — день стабільного виходу Chrome з офіційного розкладу
  `chromiumdash.appspot.com`, вписаний у поле `milestones` руками. Сам оновлювач до chromiumdash не звертається.
- **Знімок і мітки.** Знімок версії — стан гілки на мить виходу наступної версії: до того сайт і описував цю
  версію. Для найновішої — сьогоднішній стан. Кожен знімок дає дві мітки: версію (`12.4`) і рік своєї миті
  (`2024`). V8 8.2 немає: Chrome 82 не виходив.
- **Пост про реліз несе лише свою версію.** `v8-release-99.md` — це `9.9` і рік допису (`2022`), а не всі знімки, в
  яких він лежав. Інакше фільтр `9.9` віддав би пости 4.5–9.8 так само, як 9.9.

Особливості, які варто знати:

- **Історія починається 26.09.2018** — з першого коміту репозиторію. Дописи блогу 2015–2018 років туди перенесено
  зі старого блогу, тож вони є, але їхні редакції до вересня 2018 — ні.
- **Назва документа — шлях файла з хешем вмісту**: `src-docs-d8-29b38eba`, `src-blog-maglev-…`.
- **Лише англійська.**
- **learning-v8 — неофіційне.** Це особисті нотатки одного інженера (Daniel Bevenius), писані 2016–2024 років на
  тодішньому вихідному коді V8: назви класів, шляхи файлів і кроки збирання могли з того часу змінитися. Міток версій
  нотатки й код не мають, тож фільтр `version` їх не бачить; промпт велить казати, що відповідь спирається на них, і
  ставити v8.dev першим, коли відповідають обидва. Ліцензії в репозиторії немає.
- **Читач `ghcode` новий**, його додав цей примірник. Наявний `ghexamples` бере лише приклади JavaScript із власним
  `package.json`, а тут код — C++, Torque, Rust, Makefile, команди lldb. Один файл — один документ із блоком коду,
  назва — «learning-v8: шлях». Службові файли (`.gitignore`, `.github/FUNDING.yml`, `Cargo.lock`) теж узято: усе
  з репозиторію. README прикладу rusty-v8 іде цим же читачем, бо ім'я `readme` вже зайняте кореневим README нотаток.
- **Сторінку v8.github.io/tools не взято**: це вебзастосунки (Turbolizer, System Analyzer, Profview), а не
  документація; як ними користуватися, пояснюють `docs` (`profile`, `trace`, `rcs`, `linux-perf`) і блог.

## Межі, про які треба пам'ятати

Тут немає самої мови JavaScript (для неї — примірник `ecmascript`), Node.js, Chromium, Blink, вихідного коду V8 і
довідника його C++ API — лише те, що про них кажуть v8.dev і нотатки learning-v8 (вони цитують шматки вихідного коду
й показують кілька класів API в тестах, але довідником не є). Допис блогу описує V8 на мить написання: порада 2017
року може вже не діяти, і промпт велить моделі називати дату, на яку спирається відповідь.

## Установка venv

```
cd instances/v8
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # впишіть GITHUB_TOKEN і, якщо потрібен крок ask, ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

Якщо корпус уже лежить у `corpus/`, потрібен лише `vectors`, якщо колекції ще немає.

```
./df v8 sources --why   # перелік джерел і білий список
./df v8 refresh         # завантажити все задеклароване (~35 хвилин)
./df v8 manifest        # оновити паспорт
./df v8 setup           # Qdrant чи пошук лише по словах
./df v8 vectors         # залити корпус у docs-v8 (~10 хвилин)
./df v8 smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df v8 serve          # порт 8773
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8773/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user v8-docs http://127.0.0.1:8773/mcp
```

Або відкрити теку `instances/v8/` як проєкт: Claude Code побачить `.mcp.json` цієї теки й запропонує сервер.

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `v8-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію
Claude Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і
«Reconnect».

Зупинка — Ctrl+C у терміналі сервера. `[Errno 98] address already in use` при `serve` означає, що порт 8773 уже
тримає інший процес, майже завжди попередній забутий `serve`: `ss -ltnp | grep 8773` покаже його `pid`. Решта —
scope запису — так само, як у [README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).

## На іншій машині

Інше вікно VS Code на тій самій машині нічого, крім кроків 1–3 вище, не потребує: сервер один, клієнтів скільки
завгодно. На іншій машині (теж WSL) бракує трьох речей, яких немає в git: venv примірника, `.env` і векторів у
Qdrant.

**1. Код і корпус.** Корпус лежить у git, тож досить отримати репозиторій зі свіжими комітами і перейти в його
корінь.

**2. Venv примірника** — за розділом «Установка venv» вище. `.env` для пошуку не потрібен: токен GitHub треба лише
для `refresh`, ключ Anthropic — лише для `ask`.

**3. Спосіб пошуку.**

```
./df v8 setup --vectors      # з Qdrant: потрібен Docker; вектори рахуються ~10 хвилин
./df v8 setup --no-vectors   # лише пошук по словах: без Docker, одразу
```

**4. Перевірка, сервер, клієнт.**

```
./df v8 smoke          # усі перевірки мають бути ok
./df v8 serve          # порт 8773, лишити жити
```

і далі — кроки 2–3 розділу «Сервер під Claude Code» на тій машині, де відкрито VS Code.
