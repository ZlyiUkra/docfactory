When dealing with internationalization APIs, it’s common to pass strings representing locale IDs to the various `Intl` constructors, such as `'en'` for English. The new `Intl.Locale` API offers a more powerful mechanism to deal with such locales.

It enables easily extracting locale-specific preferences such as not only the language, but also the calendar, the numbering system, the hour cycle, the region, and so on.

```js
const locale = new Intl.Locale('es-419-u-hc-h12', {
  calendar: 'gregory'
});
locale.language;
// → 'es'
locale.calendar;
// → 'gregory'
locale.hourCycle;
// → 'h12'
locale.region;
// → '419'
locale.toString();
// → 'es-419-u-ca-gregory-hc-h12'
```
