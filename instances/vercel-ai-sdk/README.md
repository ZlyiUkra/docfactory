# vercel-ai-sdk — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про AI SDK від Vercel — набір TypeScript для застосунків і агентів на
мовних моделях (сайт ai-sdk.dev, репозиторій vercel/ai, реєстр npm) — за документацією кожної мінорної версії,
пакетами й журналами змін. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає
самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

AI SDK дає єдиний інтерфейс до моделей різних провайдерів: `generateText` і `streamText` для тексту, `Output` (раніше
`generateObject`) для структурованої відповіді за схемою, інструменти (`tool` з `inputSchema` і `execute`) з кількома
кроками поспіль (`stopWhen`), агентів (`ToolLoopAgent`), клієнт MCP, вектори (`embed`, `embedMany`), а для інтерфейсу —
хуки `useChat`, `useCompletion`, `useObject` для React, Vue, Svelte й Angular. У плані Next.js (фулстек-родина) Vercel
AI SDK стоїть у «знати, що існує»: ним зроблено чат і генерацію тексту в 58 шаблонах галереї.

Між мажорами API змінювався сильно: у 5.0 `maxSteps` став `stopWhen`, `parameters` інструмента — `inputSchema`,
`CoreMessage` — `ModelMessage`, `useChat` отримав транспорти й `sendMessage` замість `append` і `handleSubmit`; у 6.0
з'явилися агенти й `Output` у `generateText`. Тут документація кожної мінорної зібрана в одному місці, з номером версії
біля кожного уривка, тож видно, що саме казав сайт для коду конкретної версії.

Разом 25 369 документів; однаковий текст різних версій — один уривок, тож фрагментів в індексі 47 870
(`expected_passages` у `checks.json`). Замір `quality`: по словах 2 із 10, за змістом 2, разом 2, «як модель» 10 із 10.
Десятка своїми словами низька, бо дві третини фрагментів — записи журналів змін, і запит без назв API тоне серед них;
модель же шукає назвами (`stopWhen`, `embedMany`, `createMCPClient`), і там влучає кожен запит. Один запит «як модель»
переписано: «tool description inputSchema execute» замість переліку з `generateText`, як питала б модель про сам
інструмент.

Чому сайт береться з репозиторію. Сайт ai-sdk.dev зібрано з теки `content` репозиторію (до 3.1 — `docs/pages/docs`,
сайт на Next.js), і він показує лише поточну версію; старі мажори живуть на окремих піддоменах (v4, v5, v6.ai-sdk.dev),
а точна редакція кожної мінорної — лише на тегах `ai@*`. Береться останній тег кожної мінорної: 7.0.153 з адресою
живого сайту, решта — з адресою файла на GitHub. Та сама сторінка всіх версій — одна родина (`families` у
`config.json`). Імена файлів сайту несуть номер порядку (`04-ai-sdk-ui/02-chatbot.mdx`), і між версіями номери
зсуваються, тож `slug_rewrite` знімає їх із ключа сторінки: інакше сторінка 4.x і 7.x не зливалися б.

Довідник API. Параметри й поля результату кожної функції записано не текстом, а масивом `<PropertiesTable content={[…]}
/>` з вкладеними типами. Читач `ghdocs-history` (поле `jsx_props`) тепер розбирає і його: без цього сторінка
`generateText` лишалася б порожньою.

README. Береться остання версія кожної мінорної кожного пакета (371 тарбол), а не кожна версія: у `ai` їх 1 146, у
всіх 89 пакетах — 21 486. README пакетів `@ai-sdk/provider` і `@ai-sdk/provider-utils` деяких версій — лише заголовок,
ці 4 документи не записано.

Журнали змін. Після виходу нового мажору попередній живе на окремій гілці (`release-v5.0`, `release-v6.0`), і його
патчі в журнал гілки `main` не потрапляють. Тому журнал кожного пакета взято з останнього тегу кожного мажору, і з
кожного файла — лише записи свого мажору (поле `skip`): так кожна версія є рівно один раз. Журнал `ai` 2.x лежав у
`packages/core`.

Пакети. 83 нинішні з теки `packages/` і 5 знятих з підтримки (`@ai-sdk/lmnt`, `solid`, `swarm`, `ui-utils`, `vercel`),
що лишилися в npm і тегах.

Чого немає. Власних API провайдерів (OpenAI, Anthropic, Google), React, Next.js, Vue, Svelte, Zod і платформи Vercel
як окремих проєктів, коду пакетів і тестів, прикладів з теки `examples/`.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, `families`, `slug_rewrite` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df vercel-ai-sdk <крок>`.

## Версії

Сторінка сайту й документи пакета `ai` несуть версію випуску `ai` (`7.0.153`, `6.0.315`); пакети `@ai-sdk/*` — свою,
з іменем пакета попереду (`openai-3.0.12`, `react-2.0.5`, поле `version_prefix`), щоб фільтр лінії не змішував їх із
`ai`. Фільтр `version` бере мажор (`"7"`, `"openai-3"`), мінор (`"4.3"`) або точну версію. Провайдери й
`@ai-sdk/provider` мають мажор на три менший за `ai`: `@ai-sdk/openai` 4.x виходить разом з `ai` 7, 3.x — з `ai` 6.
За завантаженнями npm за тиждень до 25.10.2026 лінія 7 `ai` тримає 44 %, лінія 6 — 42 %, лінія 5 — 10 %: дві перші
майже рівні, тож промпт відповідає для обох, а коли код показує старішу версію (`maxSteps`, `parameters`) — ще й для
неї і каже, що змінює оновлення.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/vercel-ai-sdk-corpus-2026-10-25.tar.gz` (25 369 текстів, паспорт і
сховище сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на Windows-диску
`C:\Distr\vercel-ai-sdk-corpus-2026-10-25.tar.gz` (звірено за SHA-256). В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/vercel-ai-sdk/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/vercel-ai-sdk-corpus-РРРР-ММ-ДД.tar.gz -C instances/vercel-ai-sdk corpus raw
find instances/vercel-ai-sdk/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/vercel-ai-sdk/raw
gzip -9 -c instances/vercel-ai-sdk/index/passages.json > instances/vercel-ai-sdk/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/vercel-ai-sdk-corpus-2026-10-25.tar.gz -C instances/vercel-ai-sdk
./df vercel-ai-sdk smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/vercel-ai-sdk/index/passages.json.gz`,
далі `./df vercel-ai-sdk vectors` заллє колекцію Qdrant (секунди на відеокарті, кілька хвилин на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df vercel-ai-sdk …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df vercel-ai-sdk sources --why   # перелік джерел і білий список
./df vercel-ai-sdk refresh         # завантажити все задеклароване (близько 40 хвилин)
./df vercel-ai-sdk manifest        # оновити паспорт
./df vercel-ai-sdk setup           # Qdrant чи пошук лише по словах
./df vercel-ai-sdk vectors         # залити корпус у docs-vercel-ai-sdk
./df vercel-ai-sdk smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df vercel-ai-sdk serve          # порт 8898
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8898/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user vercel-ai-sdk-docs http://127.0.0.1:8898/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `vercel-ai-sdk-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
