# Оновлення корпусу vercel-ai-sdk

Тут оголошено руками теги й коміти: сайт — з останнього тегу `ai@*` кожної мінорної 2.1–7.0, журнали змін — з
останнього тегу кожного мажору кожного пакета, README — з останньої версії кожної мінорної (вираз `skip_versions`
джерел `vas-readme-*`). Реєстр npm береться щоразу заново.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

Тегів у vercel/ai десятки тисяч (кожен пакет — свій тег на кожен випуск), тож SHA беруть одним переліком:

```
git ls-remote --tags https://github.com/vercel/ai > tags.txt
```

1. Нова мінорна `ai` (тег `ai@7.1.0`): поточний запис поля `tags` джерела `vas-docs-7.0` переносять у `vas-docs-history`
   (з тією ж версією), а в `vas-docs-7.0` ставлять SHA нового тегу з новою версією; новий патч поточної мінорної просто
   заміняє її SHA. Новий мажор — так само, і ще новий тег-рядок для журналів (пункт 2).
2. Журнали змін: в `url`, `cite` і `within` джерел `vas-changelog-<пакет>-<мажор>` поточного мажору SHA замінюють SHA
   останнього тегу пакета; для нового мажору додають джерело з полем `skip` `-|^(?!<мажор>\.)`.
3. README: у `skip_versions` джерела `vas-readme-<пакет>` версію останнього патча мінорної замінюють новою, а нову
   мінорну дописують до переліку.
4. Новий пакет `@ai-sdk/*`: три джерела за зразком сусідніх — `vas-readme-`, `vas-changelog-`, `vas-npm-` з
   `version_prefix` «ім'я-».

```
./df vercel-ai-sdk check                 # чи змінилося щось нагорі за джерелом
./df vercel-ai-sdk refresh               # повне перезавантаження, близько 40 хвилин
./df vercel-ai-sdk manifest
./df vercel-ai-sdk vectors
./df vercel-ai-sdk smoke
# Ctrl+C у терміналі з serve, і знову: ./df vercel-ai-sdk serve
```

Якщо змінилося співвідношення завантажень ліній (на 25.10.2026 лінія 7 — 44 %, лінія 6 — 42 %, лінія 5 — 10 %), — у
`prompts/search.txt` (абзац «Which version to search first») і `prompts/agent.txt` замінити лінії й числа; у
`checks.json`, у десятках `quality` і `quality_model`, звірити цілі там, де питання про поточну поведінку.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у кореневому `.env`) потрібен: без нього GitHub дає 60 звернень на годину.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df vercel-ai-sdk quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
