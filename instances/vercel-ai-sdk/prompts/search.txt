Search the documentation of the AI SDK by Vercel -- the TypeScript toolkit for building applications and agents on
large language models (site ai-sdk.dev, repository vercel/ai, the npm registry). The corpus holds the site as it stood
at the last release of every minor of the package `ai` from 2.1 to 7.0 (foundations and getting started; AI SDK Core:
`generateText`, `streamText`, structured output with `Output` and `generateObject`/`streamObject`, tool calling and
multi-step loops with `stopWhen`, agents and `Agent`/`ToolLoopAgent`, MCP clients, embeddings, image, speech and
transcription, middleware, provider management and the registry, telemetry, error handling, testing; AI SDK UI:
`useChat`, `useCompletion`, `useObject`, transports, message persistence and resumable streams, `UIMessage` and the
stream protocol; AI SDK RSC; the API reference of every function with its parameters and result fields; the migration
guides between majors; troubleshooting; the cookbook for Next.js, Node.js and RSC; the providers: OpenAI, Anthropic,
Google, Vertex, Azure, Amazon Bedrock, Mistral, Groq, xAI, DeepSeek, the AI Gateway, OpenAI-compatible and community
providers, LangChain and LlamaIndex adapters, observability integrations); the README of the last release of every
minor of `ai` and of 88 packages `@ai-sdk/*` (providers, the UI packages for React, Vue, Svelte, Angular and Solid,
`rsc`, `provider`, `provider-utils`, `gateway`, `mcp`, `otel`, `devtools`, `codemod`, the `harness-*`, `tool-*` and
`sandbox-*` packages); the changelogs of all 89 packages with every stable release; and the npm registry of each with
its versions and release dates. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about the AI SDK as it describes itself -- which function to use and which parameters it
takes, what `generateText` or `streamText` returns, how to define a tool with `inputSchema` and run several steps, how
to stream structured output, how `useChat` sends and receives messages and how to persist them, how to set up a
provider and its model options, how to test with mock models -- and history: since which version a function or option
exists, what was renamed between majors (`maxSteps` → `stopWhen`, `parameters` → `inputSchema`, `CoreMessage` →
`ModelMessage`, `ai/rsc` → `@ai-sdk/rsc`; the migration guides and the changelogs list it).

Do not call this for the model providers' own APIs (the OpenAI, Anthropic or Google APIs as such), for React, Next.js,
Vue, Svelte, Zod or LangChain as their own projects, or for the Vercel platform beyond what these pages say: their
documentation is not here -- these pages only show how the AI SDK is used with them -- and the search will return
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line. The pages of the site, and the README, changelog and registry of
the package `ai`, carry the plain version of the `ai` release ("7.0.153", "6.0.315"): a line of one number keeps every
document of that major ("6" keeps 6.x), two numbers keep a minor ("4.3"). The packages `@ai-sdk/*` carry the name of
the package before their own number ("openai-3.0.12", "react-2.0.5", "provider-utils-4.0.3"): "openai-3" keeps the 3.x
line of `@ai-sdk/openai`. The providers and `@ai-sdk/provider` ship one major below `ai` by three: `@ai-sdk/openai` 4.x
goes with `ai` 7, 3.x with `ai` 6, 2.x with `ai` 5, 1.x with `ai` 4. Every excerpt comes back with `versions`: each
version whose documents contain this exact text, newest first -- a page that stayed the same across versions is
returned once, with all of them listed, so the list itself shows from which to which version the documentation said
exactly this.

Write the query in English, with the names the documentation itself uses ("generateText", "streamText", "Output",
"generateObject", "tool", "inputSchema", "stopWhen", "stepCountIs", "prepareStep", "ToolLoopAgent", "useChat",
"sendMessage", "DefaultChatTransport", "UIMessage", "toUIMessageStreamResponse", "convertToModelMessages",
"createMCPClient", "embedMany", "wrapLanguageModel", "providerOptions", "MockLanguageModelV3", "migration guide"),
not in the user's own words. Everything here is English -- the excerpts, the word index and the meaning index alike
-- and the word index keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other
non-latin script matches nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into the terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the excerpts
say so; and how it stands in the current version. Every point names the version and the document it rests on; a
point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian
engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever one exists
-- "уривок", not "ексерпт"; "потік", "інструмент", "застарілий". Never call this set of documents "корпус" -- say
"документація AI SDK". Identifiers, parameters and titles stay in English, spelled exactly as the documentation spells
them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of
it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` -- pass
the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. By npm downloads in the week before 25 October 2026 the line 7 of `ai` holds 44 %
(7.0.153 is the newest) and the line 6 -- 42 % (6.0.315); 5.x keeps 10 %. The two leading lines are close, so answer
how-to questions for both: search `version` "7" and "6", and when the two differ, give both answers and say which
version each one is for. When the user's code shows a version (`maxSteps`, `parameters`, `CoreMessage` point to 4.x;
`append` and `handleSubmit` of `useChat` to 4.x or older), search that line as well and say what the update changes.
Search without `version` when the question is about history, or when the line gave nothing. Every answer says which
version it is for.
