# vercel — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Vercel за його документацією: уся документація vercel.com/docs
(розгортання, проєкти й середовища, змінні оточення, домени, Vercel Functions і Fluid compute, Routing Middleware, CDN
і кеш, ISR, Blob, Global Config (колишній Edge Config), Cron Jobs, Queues, Sandbox, Firewall і BotID, Deployment
Protection, Observability, мікрофронтенди, Flags, `vercel.json` і `vercel.ts`, кожна команда CLI, довідник REST API,
коди помилок, плани й ліміти), довідка vercel.com/kb, журнал змін, блог і курси Vercel Academy; README CLI `vercel` і 18
пакетів `@vercel/*`, їхні журнали змін і релізи. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

Vercel — платформа, на якій можна розгорнути вебзастосунок (хостинг). Плани навчання називають її поряд із Netlify і
Cloudflare. Документація фреймворків (Next.js, Astro, SvelteKit) описує лише адаптер, через який збірка потрапляє на
Vercel. Як працює сама платформа, у тих документаціях не написано: ліміти функцій, `vercel.json`, змінні оточення,
домени, захист preview-розгортань, ціни. Тут зібрано саму платформу. AI SDK має окремий примірник `vercel-ai-sdk`, і
тут його немає.

- `@vercel/node` та інших будівельників (builders) платформи: їхні README порожні, а суть описано в документації.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа. Самих
  текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого підіймається сервер. У git лежить стиснений `passages.json.gz`; розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки будується корпус. Він же білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише
  для завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df vercel <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| сайт | `vercel.com/crawled-sitemap.xml` (на неї переадресовує `sitemap.xml`); markdown сторінки сайт віддає на `Accept: text/markdown` | `sitemap-accept-heading` |
| коди помилок | ті самі сторінки `/docs/errors/…`, але markdown лише за адресою з `.md` (на `Accept` вони віддають HTML) | `sitemap-accept-heading` з `md_suffix` |
| README | tarball реєстру npm останнього патча кожної стабільної мінорної лінії; `@vercel/sdk` — raw.githubusercontent.com на коміті публікації | `npm-tarball-files`, `npm-readme` |
| журнали змін | `packages/<пакет>/CHANGELOG.md` гілки main репозиторіїв vercel/vercel, vercel/storage, vercel/sandbox, vercel/flags, vercel/microfrontends | `changelog-regex` |
| релізи | GitHub API, стабільні релізи з тегами `v…` | `ghreleases-stable` |

Читач `sitemap-accept-heading` написано для цього примірника. Він бере назву сторінки з шапки YAML, а якщо поля `title`
там немає, то з першого заголовка «# …». Так влаштовані статті довідки, записи журналу змін і блогу. Дату з рядка
«**Published:** …» він дописує в назву, щоб відповідь на «коли це з'явилося» було видно вже у видачі.

Вибір версій зроблено так: для кожного пакета взято останній патч кожної стабільної мінорної лінії. Список версій
записано в `skip_versions` як вираз «усе, крім цих». Його складено за реєстром npm: для кожного пакета взято
найбільший патч кожної пари «мажор.мінор».

Поле `drop` вирізає службові вставки, однакові на сотнях сторінок. Це підказка «Search the docs from your terminal» з
командами CLI, посилання на мапу сайту, рядок зворотного зв'язку в кінці кожної сторінки, блок `<agent-instructions>` в
уроках Academy, перелік «Reference Architecture / Build with prompts» у довідці та рядок «More updates / More posts» у
журналі змін і блозі.

## Версії

Сайт версії не несе: його сторінки описують Vercel на день завантаження. Версію несуть README, журнали змін і релізи
пакетів, і кожен пакет має свій префікс, щоб нумерації не змішувалися: CLI — `cli-` (`version: "cli-66"`), решта — за
коротким іменем пакета (`"functions-3"`, `"blob-2"`, `"sdk-1"`, `"flags-4"` тощо). Старе ім'я Flags SDK `@vercel/flags`
має префікс `legacy-flags-`. Префікс не може починатися з «v»: сервер відкидає її як позначку версії («v66» → «66»), тож
`vercel-66` перетворився б на `ercel-66`. Промпт шукає «як зробити» без версії, а версію передає лише для питань про
історію пакета.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку. У `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant. Відповіді ті самі до символа, бо кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/vercel-corpus-2026-11-24.tar.gz` (7 016 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів архів розпаковано окремо й звірено з диском) і в копії на Windows
`C:\Distr\vercel-corpus-2026-11-24.tar.gz` (звірено за SHA-256). Сховище сирого важить близько 0,7 ГБ: це tarball
пакетів npm. В історії git текстів немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/vercel/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/vercel-corpus-РРРР-ММ-ДД.tar.gz -C instances/vercel corpus raw
find instances/vercel/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/vercel/raw
gzip -9 -c instances/vercel/index/passages.json > instances/vercel/index/passages.json.gz
```

Після цього закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Тексти й сховище видаляють лише тоді,
коли архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із текстами повертається сховище сирого:

```
tar -xzf ~/archives/docfactory/vercel-corpus-2026-11-24.tar.gz -C instances/vercel
./df vercel smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Їхні
перевірки `smoke` чесно пропускає з позначкою «корпус в архіві».

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/vercel/index/passages.json.gz`.
Далі `./df vercel vectors` заллє колекцію Qdrant: близько хвилини на відеокарті, довше на процесорі.

## Установка venv

Власний venv цьому примірнику не потрібен: `./df vercel …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як збудувати його один раз і як `df` обирає між ними — у кореневому README, розділ
«Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df vercel sources --why   # перелік джерел і білий список
./df vercel refresh         # завантажити все задеклароване (близько півтори години: 5 575 сторінок сайту)
./df vercel manifest        # оновити паспорт
./df vercel setup           # Qdrant чи пошук лише по словах
./df vercel vectors         # залити корпус у docs-vercel
./df vercel smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити його працювати:

```
cd ~/Projects/docfactory
./df vercel serve          # порт 9002
```

Сервер готовий, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:9002/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user vercel-docs http://127.0.0.1:9002/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування. Вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell або додати сервер кнопкою «Add server» у вікні
`/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` має показати `vercel-docs` і два інструменти: `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта (scope запису, «address already in use») — так само, як у [README
примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
