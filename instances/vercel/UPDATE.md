# Оновлення корпусу vercel

Сайт версій не має: кожен `refresh` бере його поточний стан, і змінена сторінка не затирає збереженої — стара відповідь
переїжджає в `raw/_old/<день>/`. Журнали змін пакетів читаються з гілок main, релізи — з GitHub API.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

```
./df vercel check                 # чи змінилося щось нагорі за джерелом
./df vercel refresh               # повне перезавантаження (близько півтори години)
./df vercel refresh npm-vercel changelog-vercel   # лише CLI
./df vercel manifest
./df vercel vectors
./df vercel smoke
# Ctrl+C у терміналі з serve, і знову: ./df vercel serve
```

Перерваний повний прогін продовжують командою `refresh <джерело, де зупинився>`, а потім `refresh --missing`.

**Нові мінорні лінії пакетів самі не додаються.** README беруться лише з версій, перелічених у `skip_versions` кожного
джерела `npm-…` (останній патч кожної стабільної мінорної лінії на день збирання). Щоб узяти нові лінії, перелік треба
скласти заново за реєстром npm: для кожного пакета — найбільший патч кожної пари «мажор.мінор».

**Що перевірити після оновлення.**

- Сторінка, що зникла з sitemap, лишається в корпусі (нічого не видаляється). Щоб прибрати її, файл видаляють руками
  разом із записом паспорта — лише за рішенням людини.
- Якщо `refresh` пише «Замість markdown прийшов HTML», сторінка перестала віддавати markdown на `Accept`. Звірити її
  адресу з `.md` (`curl <адреса>.md`) і, якщо там markdown, перенести такі сторінки в джерело з `md_suffix`, як
  `docs-errors`.
- Якщо `sitemap.xml` переадресовує вже не на `crawled-sitemap.xml`, `refresh` скаже «редирект на адресу поза
  оголошенням»: виправити `url` джерел сайту.
- Нова мажорна CLI (на 24.11.2026 найновіша — 66.6.0): замінити `"cli-66"` у `prompts/search.txt`, `prompts/agent.txt`
  і `version_probe` у `checks.json`.

Якщо `smoke` скаржиться на число фрагментів, корпус підріс. Нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df vercel quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту, знову
замір. Останній результат — у README, розділ «Скільки цього».
