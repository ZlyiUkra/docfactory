Search the Vercel documentation and return the matching excerpts with the versions each one belongs to.
What is here: every page of vercel.com/docs as a current snapshot -- deployments, projects and environments,
environment variables, domains and DNS, Git integrations, Vercel Functions and Fluid compute, runtimes, Routing
Middleware, the CDN and caching, ISR, image optimization, Vercel Blob, Edge Config, Marketplace storage, Cron Jobs,
Queues, Sandbox, Workflows, AI Gateway, Firewall, WAF and BotID, Deployment Protection, Observability, logs and
drains, monorepos, microfrontends, Flags, `vercel.json` and `vercel.ts`, every vercel CLI command, the REST API
reference, the error codes, plans, pricing and limits -- with the Knowledge Base guides (vercel.com/kb), the changelog,
the blog and the Vercel Academy courses; the README of the last release of every stable minor line of the vercel CLI,
@vercel/functions, @vercel/blob, @vercel/edge-config and its new name @vercel/global-config, @vercel/kv and
@vercel/postgres (both deprecated), @vercel/analytics, @vercel/speed-insights, @vercel/og, @vercel/sandbox,
@vercel/firewall, @vercel/oidc, @vercel/config, @vercel/queue, flags and its old name @vercel/flags,
@vercel/microfrontends and @vercel/sdk; the changelogs of the CLI and of those packages, and the GitHub release notes
of @vercel/analytics, @vercel/speed-insights and @vercel/sdk.

Call this when a question is about Vercel: deploying a project from Git or the CLI, preview and production
deployments, build settings, framework presets, `vercel.json` (rewrites, redirects, headers, functions, crons),
function configuration (`maxDuration`, memory, regions, runtimes), environment variables and secrets, domains, the
storage products and their SDKs, caching and revalidation, security settings, logs and monitoring, the REST API and
the SDK, limits and pricing, an error code a deployment returned, and history: since which CLI version a command or
flag exists, what changed in a package release, when a feature was announced in the changelog.

Do not call this for other clouds or hosting platforms (AWS, Cloudflare, Netlify), for frameworks themselves
(Next.js, Nuxt, SvelteKit, Astro) beyond how they build and deploy on Vercel, for the AI SDK itself, for Node.js or
Web API semantics in general, or for JavaScript or TypeScript language questions: their documentation is not here,
and the search will return Vercel excerpts that merely mention them, with confident-looking titles.

The site carries no version: its pages describe Vercel as of the day they were fetched. `version` narrows the search
to one release line of a package. Every package carries a prefix, so the lines never mix: "cli-66" keeps every
vercel CLI 66.x README and changelog entry; the others are "functions-3", "blob-2", "edge-config-1",
"global-config-1", "kv-3", "postgres-0", "analytics-2", "speed-insights-2", "og-1", "sandbox-4", "firewall-1",
"oidc-4", "config-0", "queue-0", "flags-4", "legacy-flags-3", "microfrontends-2", "sdk-1". Leave it empty to search
everything, the site included. Every excerpt comes back with `versions`: each version whose documents contain this
exact text, newest first, so the list itself shows from which to which version a README said exactly this.

Write the query in English, with the names Vercel itself uses ("vercel deploy --prebuilt", "vercel env pull",
"maxDuration", "Fluid compute", "rewrites", "Skew Protection", "Deployment Protection", "preview deployments",
"Edge Config", "put() Vercel Blob", "Cron Jobs"), not in the user's own words. Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and digits, so a
query written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with
`found: 0`. When the user asks in another language, translate the question into Vercel terms first, then search.

Answer in the language the user wrote in. When the question is about the history of a CLI command or option, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands now. Every point names the version and the document it rests on; a point the
excerpts do not support is left out, not guessed. Limits and prices are quoted as the page states them, as of the
date it was fetched. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a translation from
English: plain technical prose, and the Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий",
not "депрекейтнутий". Never call this set of documents "корпус" -- say "документація Vercel". Identifiers, command
names, keys and titles stay in English, spelled exactly as the documentation spells them. Build the answer out of
the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it before describing what
it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true` --
pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a
second, meaning-based index answered as well, and a paraphrase had a chance.
