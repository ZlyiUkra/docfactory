# viem — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Viem — бібліотеку TypeScript від wevm для роботи з Ethereum: як
створити клієнт і транспорт, прочитати баланс, блок, транзакцію чи журнали подій, прочитати смартконтракт, перевірити
виклик симуляцією й записати в нього, надіслати транзакцію й дочекатися її квитанції, підписати повідомлення чи
типізовані дані, перевести одиниці (ether, gwei, wei), закодувати й розкодувати ABI, знайти адресу за іменем ENS,
працювати з L2 (OP Stack, ZKsync), смарт-акаунтами й EIP-7702. Джерела — репозиторій wevm/viem на GitHub (з нього
збирається сайт viem.sh) і реєстр npm, лише англійською. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

Факультатив «крипта» планів React і Next.js стоїть на Wagmi, а Wagmi — на Viem: дії Wagmi лише обгортають дії Viem,
а клієнти, транспорти, ланцюги, одиниці й ABI застосунок бере з Viem напряму. API Viem між версіями мінявся: у 0.2
прибрано `getAccount`, у 1.0 — `ethersWalletToAccount` і змінено `decodeEventLog`, у 2.0 `getContract` бере
`client: { public, wallet }`, частину точок входу прибрано, а `isAddress` і `getAddress` перевіряють контрольну суму.
Мінорні версії 2.x щомісяця додають дії й параметри. Тож потрібен текст документації кожної версії, а не пам'ять
моделі.

**Що є що.** **Клієнт** (client) — об'єкт, через який застосунок звертається до мережі: **публічний** (`createPublicClient`)
читає ланцюг, **гаманцевий** (`createWalletClient`) підписує й надсилає, **тестовий** (`createTestClient`) керує
локальним вузлом (Anvil, Hardhat). **Транспорт** (transport) — як клієнт говорить із вузлом: `http`, `webSocket`,
`fallback` (кілька вузлів по черзі), `custom` (провайдер гаманця EIP-1193). **Дія** (action) — одна операція клієнта:
`getBalance`, `sendTransaction`, `readContract`. **Акаунт** (account) — хто підписує: локальний (ключ у застосунку,
`privateKeyToAccount`) чи JSON-RPC (ключ у гаманці). **Ланцюг** (chain) — мережа Ethereum чи сумісна з нею (mainnet,
Sepolia, Base, Optimism) з ідентифікатором `chainId`. **Утиліти** (utilities) — чисті функції без мережі: `parseEther`,
`formatUnits`, `keccak256`, `encodeFunctionData`. **Смарт-акаунт** і **user operation** — гаманець-контракт стандарту
ERC-4337 і його «транзакція», яку надсилає bundler (розділ Account Abstraction). **Tempo** — окремий блокчейн для
платежів; Viem має для нього власний набір дій (`viem/tempo`).

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

вставляє, і в рядку `# версія:` стоять усі версії, де вона була саме такою. Однаковий текст різних версій лягає одним
фрагментом з усіма цими версіями, тож 349 редакцій сайту 1.x додають лише 144 фрагменти: решта тексту та сама, що в
2.x.

Замір `quality`: перша десятка (питання своїми словами, без версії) — по словах 8 із 10, за змістом 7, разом 10;
друга, «як модель» (назви дій, утиліт і параметрів, з версією, як велить промпт), — 10 із 10 з першого заміру. До
цілі питання «перевірити, що виклик контракту пройде, перш ніж надсилати його гаманцю» (`simulateContract`) додано
справжню відповідь, якої бракувало: вступ сторінки `writeContract`, що прямо радить спершу викликати
`simulateContract`. Поле `max_per_doc` 1 опускає «як модель» до 8 із 10, 2 і 3 нічого не міняють; `fusion_depth` 10
теж нічого не дає, тож обидва не ввімкнені.

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, спільний ключ сторінок двох розкладок
  сайту (`slug_rewrite`), родини джерел сайту й прикладів (`families`) і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (дерева тегів, файли репозиторію); `.mcp.json` — запис
  HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df viem <крок>`.

Сайт viem.sh збирається з теки `site/` репозиторію, тож текст береться звідти, а в шапці документа стоїть адреса
сторінки сайту: viem.sh для 2.x, v1.viem.sh (з «.html» у кінці) для 1.x. Окремого сайту 0.x немає — там адреса файла
на GitHub. Окремого довідника API (TypeDoc) у Viem немає: сторінки дій і утиліт сайту і є довідник. Релізи GitHub
повторюють журнал змін слово в слово, тож не беруться; README пакета — логотип, перелік можливостей і спонсори, теж не
береться. Посилання у відповідях ведуть на viem.sh, v1.viem.sh, github.com і registry.npmjs.org.

Особливості, які варто знати:

- **Сторінка Vocs у репозиторії — MDX зі вставками.** Код налаштування клієнта лежить окремими файлами й вставляється в
  блок коду рядком `// [!include ~/snippets/publicClient.ts]` (з областю `:setup`), спільні шматки параметрів дій
  Tempo — імпортом `.mdx` і рядком `<WriteParameters />`. Поле `vocs` читача `ghdocs-history` (модуль `_vocs`) усе це
  розкриває, тож у корпусі сторінка така, як на сайті. Контейнери `:::tip` і `:::warning[…]` стають підписами,
  вкладки `:::code-group` — блоками коду з підписом файла, картки меню `<Card>` — пунктами списку.
- **Службове twoslash знімається.** Блоки коду сайту перевіряються компілятором TypeScript: рядок `// @twoslash-cache:`
  — кеш підказок типів на кілька кілобайтів, рядки до `// ---cut---` сайт ховає, `// @noErrors` і `// ^?` — службові.
  У корпусі лишається те, що бачить читач; вивід `// @log: …` стає коментарем. Рядки на кшталт `// ^? const selector:
  "0xa9059cbb"` — тип, який автор вписав сам, — лишаються.
- **Редакція — без кешу twoslash.** Кеш перегенеровується разом із типами, і незмінна для читача сторінка давала б нову
  редакцію ледь не з кожним випуском. Тому ім'я документа будується з тексту сторінки без кешу разом із вставленими
  файлами.
- **Дві розкладки сайту.** До 2.0.6 сторінки лежали в `site/docs/…`, з 2.0.10 — у `site/pages/docs/…`. Поле
  `slug_rewrite` у `config.json` дає їм спільний ключ, тож та сама сторінка різних ліній зливається, а не займає два
  місця у видачі.
- **Розділи сайту в назві.** Сторінки розділів OP Stack, ZKsync, Account Abstraction, Experimental, Circle USDC, Tempo
  і Tokens мають ту саму назву, що й основні (`getBalance` є і в основній документації, і в Tempo, і в Tokens), тож
  назва документа несе розділ: «OP Stack: depositTransaction», «Tempo: `token.transfer`», «Tokens: getBalance».
- **Версії без тегу.** 1.6.5, 1.10.10, 1.17.0 і 2.7.6 вийшли без тегу в репозиторії; вони беруться з коміту випуску
  (поле `gitHead` у реєстрі npm, для 1.10.10 — коміт «chore: changelog gen» за хвилину до публікації). 2.27.1 реєстр
  позначає «mistaken publish», 0.0.0 (2022) — порожня заглушка імені; обидві не беруться. 1.6.5, 1.6.6 і 1.10.10
  позначено «Deprecated», але це стабільні випуски, і вони беруться.
- **Подвійний запис журналу.** У журналі змін двічі стоїть заголовок 0.0.1-alpha.26; документ один, і в ньому другий
  запис (`estimateContractGas`, `retryCount`). Перший — перейменування `encodeBytes`/`encodeHex`/`encodeRlp` на
  `toBytes`/`toHex`/`toRlp` — з альфи ще до 0.1 і в корпус не потрапив.

## Версії у відповіді

Фільтр `version` бере лінію: `"2"` — усе 2.x, `"2.21"` — лінію 2.21, `"1"` і `"0"` — старі лінії. Без фільтра
сторінка, що є в кількох лініях, показується один раз — найновішою редакцією; родина `site` у `config.json` зводить
усі чотири джерела сайту, родина `examples` — приклади трьох ліній. Записи журналу мають версію свого запису.

Без названої версії промпт велить відповідати для viem 2 — її ставлять 99% тижневих завантажень npm (12.10.2026; серед
окремих версій найчастіша 2.23.2 — 19%, далі 2.36.0 і 2.57.3), поточна 2.57 — і казати, з якої мінорної 2.x
з'явилися дія чи параметр, якщо видача це показує.

Тут немає Wagmi (хуки React поверх Viem — примірник `wagmi`), ethers.js і web3.js як таких (є лише сторінка про перехід

## Сховище сирого

Під час оновлення примірник тримає ще й сирі відповіді — у теці `raw/`, поза git (сховище ввімкнене за
замовчуванням). Правка читача тоді не вимагає нового завантаження: `./df viem build` збирає тексти зі сховища без
мережі. Попередні версії файлів не видаляються, а переїжджають у `raw/_old/<день>/`. Між оновленнями сховище, як і
тексти, лежить лише в архіві: серверу воно не потрібне. Устрій — у [../../UPDATE.md](../../UPDATE.md), розділ про
`refresh`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/viem-corpus-2026-10-12.tar.gz` (4 057 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде.
Архів лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/viem/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/viem-corpus-РРРР-ММ-ДД.tar.gz -C instances/viem corpus raw
find instances/viem/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/viem/raw
gzip -9 -c instances/viem/index/passages.json > instances/viem/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/viem-corpus-РРРР-ММ-ДД.tar.gz -C instances/viem
./df viem smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/viem/index/passages.json.gz`, далі
`./df viem vectors` заллє колекцію Qdrant (близько 30 хвилин).

## Установка venv

```
cd instances/viem
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # ANTHROPIC_API_KEY — для кроку ask; GITHUB_TOKEN — для репозиторію
cd ../..
```

## Збирання корпусу

```
./df viem sources --why   # перелік джерел і білий список
./df viem refresh         # завантажити все задеклароване (~45 хвилин: 628 тегів, ~3 100 файлів, пауза 0,3 с)
./df viem build           # перезібрати тексти зі сховища сирого, без мережі (після правки читача)
./df viem manifest        # оновити паспорт
./df viem setup           # Qdrant чи пошук лише по словах
./df viem vectors         # залити корпус у docs-viem (~30 хвилин)
./df viem smoke           # перевірки
```

Як оновлювати після нових версій — у [UPDATE.md](UPDATE.md).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df viem serve       # порт 8828
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8828/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user viem-docs http://127.0.0.1:8828/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт. Інший
шлях — запис `.mcp.json` цієї теки: Claude Code, відкритий у ній, побачить сервер сам.

**3. Перевірити.** `/mcp` — має бути `viem-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Якщо порт 8828 зайнятий, `serve` падає з «address already in use»: значить,
сервер уже піднято в іншому терміналі. Решта — scope запису — так само, як у
[README примірника nestjs](../nestjs/README.md#спосіб-б--сервер-під-claude-code-http).
