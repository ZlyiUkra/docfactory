# vue — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Vue.js — прогресивний фреймворк інтерфейсів (реактивність,
компоненти, однофайлові компоненти й `<script setup>`, шаблони й директиви, композиційні функції, вбудовані
компоненти, рендеринг на сервері), а також про офіційні бібліотеки екосистеми: Vue Router, Pinia, Vuex і Vue Test
Utils. Документація — на кожен стабільний реліз: сайт vuejs.org на релізи vue 3.0–3.5, v2.vuejs.org на релізи 2.0–2.7,
давній vuejs.org на релізи 0.7–1.0; документація Router, Pinia, Vuex і Test Utils — з тегу кожної мінорної версії.
Єдиний нестабільний шар — журнал змін передрелізу Vue 3.6 (альфа, бета, реліз-кандидат) з позначкою в назві кожного
документа. Джерела — репозиторії vuejs/docs, vuejs/v2.vuejs.org, vuejs/core, vuejs/vue, vuejs/router,
vuejs/vue-router, vuejs/pinia, vuejs/vuex, vuejs/test-utils, vuejs/vue-test-utils, vuejs/v3-migration-guide,
vuejs/blog, vuejs/rfcs, пакети й реєстр npm; лише англійською. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо окремий примірник

Vue пережив три різні документації. Давній vuejs.org (Hexo, 2014–2016) описував 0.x і 1.0; з виходом 2.0 його
документація переїхала в теку `src/v2/` того самого репозиторію, а з лютого 2022 року основною стала нова vuejs.org
(VitePress) для Vue 3, де одна сторінка тримає два тексти — для Options API і для Composition API. Router, Pinia, Vuex
і Test Utils мають власну нумерацію (Router 0.5–5.4, Pinia 2.0–4.1, Vuex 0.3–4.1, Test Utils 1.0–2.5) і власні сайти.
Тегів у репозиторіях сайтів vuejs.org немає зовсім. Тож відповідь мусить знати версію й стиль API, а версії мусять
бути всі.

**Що є що.** **Ref** — реактивна обгортка значення (`ref()`); **reactive** — реактивний об'єкт-проксі; **computed** —
закешоване похідне значення; **watcher** — код, що перезапускається за зміною реактивних даних (`watch`,
`watchEffect`). **SFC** (однофайловий компонент) — файл `.vue` з шаблоном, скриптом і стилями; **`<script setup>`** —
стислий запис Composition API в SFC (`defineProps`, `defineEmits`, `defineModel`). **Options API** — компонент
об'єктом опцій (`data`, `methods`, `computed`); **Composition API** — функціями всередині `setup`. **Композиційна
функція** (composable) — функція, що інкапсулює стан і логіку на Composition API. **Vue Router** — маршрутизатор,
**Pinia** — сховище стану (наступник **Vuex**), **Vue Test Utils** — бібліотека тестування компонентів. **Vapor Mode**
— новий режим компіляції Vue 3.6 без віртуального DOM. **Реліз-кандидат** — збірка перед стабільним випуском, не
стабільна версія.

## Звідки документація

- **Сайт без тегів.** Читач `ghsite-dated-vue` (`engine/readers/ghvue.py`, обгортка над `ghsite-dated`) бере знімок
  репозиторію сайту на мить перед наступним релізом vue з реєстру npm: так кожна версія дістає текст, який описував
  саме її. Три джерела — три сайти: `docs-v3` (vuejs/docs, лише 3.x), `docs-v2` (v2.vuejs.org, лише 2.x) і `docs-v1`
  (той самий репозиторій, лише 0.x–1.0). Гілку `docs-v1` закріплено на коміті c7cefd24 — останньому стані master перед
  злиттям гілки 2.0 (30.09.2016): інакше 1.0.28, чий знімок припадає на мить виходу 2.0.0, дістав би вже документацію
  2.0. Теки `_guide_old` і `_api_old` (документація 0.12 поруч із 1.0) не беруться.
- **Розмітка Vue.** Той самий модуль перед звичайним розбором дає блокам `<div class="options-api">` і
  `<div class="composition-api">` підпис «Options API:» чи «Composition API:», а заголовкам у них — стиль у дужках
  (інакше розділ «Declaring Reactive State» був би двічі з тим самим ключем); позначки версій у заголовку
  (`<sup class="vt-badge" data-text="3.4+" />`) стають рядком під ним; контейнери VitePress і VuePress — підписами
  «Tip: …»; обгортки Hexo давнього сайту знімаються разом із живими демо; шапка `badges` посібника переходу стає
  рядком «Badges: breaking.».
- **Router, Pinia, Vuex, Test Utils** — читач `ghdocs-history-vue` (обгортка над `ghdocs-history`) з тегу кожної
  мінорної, переклади не беруться. Версія документа несе префікс пакета (`router-4.6.4`, `pinia-3.0.4`,
  `vuex-4.1.0`, `test-utils-2.4.11`), README, реєстр і журнали — той самий префікс: інакше фільтр «4» змішав би Router
  4.x, Pinia 4.x і Vuex 4.x.
- **Перекладені теки.** `slug_rewrite` у `config.json` зводить імена тієї самої сторінки до одного ключа: `source/` і

  `docs/`. `families` збирають сайти Vue 1–3, обидва репозиторії Router і обидва Test Utils у родини: редакції однієї
  сторінки займають у видачі одне місце, а фільтр версії бере потрібну.
- **Передреліз 3.6.** Документації Vue 3.6 у vuejs/docs ще немає; є журнал гілки `minor` vuejs/core з усіма записами

  окремим джерелом лише із записами 3.6.0-*, і назва кожного документа каже «Vue 3.6 pre-release changelog (alpha,
  beta, release candidate; NOT a stable release)». Інших передрелізів тут немає.
- **Журнали.** Conventional-changelog `vuejs/core` (`CHANGELOG.md` для 3.5 і `changelogs/CHANGELOG-3.0…3.4.md`),
  Vue 2, Router 4–5 і vue-router 3, Pinia, Vuex, Language Tools — читачем `changelog-conventional` без передрелізів.
  Релізи GitHub vuejs/core — лише посилання на журнал, тож не беруться; релізи Vue 2 несуть справжні нотатки.
- **npm.** Реєстр і README кожної стабільної версії дев'яти пакетів: vue, vue-router, pinia, vuex, `@vue/test-utils`,
  create-vue, vue-tsc, `@vitejs/plugin-vue`, eslint-plugin-vue; README — з репозиторію на коміті, з якого версію

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/vue-corpus-2026-10-29.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\vue-corpus-2026-10-29.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів немає
ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/vue/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/vue-corpus-РРРР-ММ-ДД.tar.gz -C instances/vue corpus raw
find instances/vue/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/vue/raw
gzip -9 -c instances/vue/index/passages.json > instances/vue/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/vue-corpus-2026-10-29.tar.gz -C instances/vue
./df vue smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/vue/index/passages.json.gz`, далі
`./df vue vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df vue …` бере спільне середовище з кореня репозиторію (`.venvs/cpu`
або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ «Спільне
середовище». Свій `.env` примірник тримає в `instances/vue/.env` (`cp .env.example .env`; для кроку `ask` потрібен
`ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df vue sources --why               # перелік джерел і білий список
./df vue refresh                     # усе незакріплене: близько 50 хвилин мережею (паузи 0,1 с)
./df vue refresh v3-migration blog blog-legacy rfcs   # закріплені джерела — лише названими
./df vue manifest                    # оновити паспорт
./df vue setup                       # Qdrant чи пошук лише по словах
./df vue vectors                     # залити корпус у docs-vue
./df vue smoke                       # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df vue serve              # порт 8929
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8929/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user vue-docs http://127.0.0.1:8929/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `vue-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
