# Оновлення корпусу vue

Перелік версій vue тут не оголошується руками: знімки сайту (`docs-v1`, `docs-v2`, `docs-v3`, читач
`ghsite-dated-vue`), README (`npm-readme-*`) і реєстр (`npm-*`) беруть версії з опису пакета в реєстрі npm, тож новий
реліз vue потрапляє туди сам, а журнали змін і релізи GitHub читаються з гілок і API щоразу заново. Передрелізи не
беруться (`only` у знімках, `skip_versions: "-"` у README, `skip: "-"` у журналах); виняток — журнал передрелізу 3.6,
джерело `changelog-vue-3.6-prerelease`.

Руками оголошено:

- **Документація Router, Pinia, Vuex і Test Utils** (`router-docs-v4`, `router-docs-v3`, `pinia-docs`, `vuex-docs`,
  `test-utils-docs-v2`, `test-utils-docs-v1`): поле `tags` — останній тег кожної мінорної, найновіший першим, з
  версією, що несе префікс пакета (`"v5.4.0": "router-5.4.0"`). Нова мінорна — новий рядок на початку `tags`; новий
  латковий реліз тієї самої мінорної — заміна тегу в її рядку.
- **Передреліз 3.6** — `changelog-vue-3.6-prerelease` бере з гілки `minor` vuejs/core лише записи 3.6.0-*. Коли вийде
  стабільна 3.6.0: джерело прибрати (його файли перенести в окрему теку, не видаляти), бо записи 3.6 з'являться в
  журналі гілки `main`, а `only` у `docs-v3` уже бере будь-яку 3.x.
- **Нова розкладка сайту.** Якщо vuejs/docs перенесе теки, розширити `include` у `docs-v3` і додати правило в
  `slug_rewrite`, щоб редакції тієї самої сторінки зливалися (див. README, «Звідки документація»).
- **Закріплені джерела** (`v3-migration`, `blog`, `blog-legacy`, `rfcs`) стоять на коміті й оновлюються лише заміною
  SHA в адресі й `within` та названим `refresh`.
- **Давній сайт** (`docs-v1`, гілка на коміті c7cefd24) і Vue 2 (`docs-v2`) не змінюються: 1.0 і 2.7 більше не
  виходять.

Правило: **нічого не видаляється.** Ані `refresh`, ані `vectors`, ані `manifest` нічого не стирають самі.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед роботою нижче тексти розпаковують, а після неї — пакують і виносять знову;
обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## Вийшла нова версія

```
./df vue refresh docs-v3 npm-readme-vue npm-vue changelog-vue   # і решту джерел пакета, що змінився
./df vue refresh --missing    # джерела, яких не названо, лише докачуються
./df vue manifest
./df vue vectors
./df vue smoke
# Ctrl+C у терміналі з serve, і знову: ./df vue serve
```

Названі джерела оновлюються повністю, не `--missing`: у документі стоять усі версії, де текст був таким, тож новий
реліз змінює й старі документи (незмінна сторінка дописує нову версію в рядок `# версія:`). Документи редакцій, яких
у новому прогоні вже немає, лишаються в теці — їх переносять в окрему теку поза корпусом руками, перш ніж рахувати
вектори. Повний `refresh` — близько 50 хвилин мережею; сховище сирого `raw/` повертається з архіву разом із текстами,
тож після правки читача тексти перебудовуються без мережі: `./df vue build <id>`.

Якщо змінилася найпоширеніша лінія (на 29.10.2026 — 3.5, близько 85 % завантажень vue):

- у `prompts/search.txt` (абзац «Which version to search first») та `prompts/agent.txt` переглянути лінію за
  замовчуванням і лінії інших пакетів (vue-router 4.6, pinia 3.0, vuex 4.1, `@vue/test-utils` 2.4);
- у `checks.json`, у десятці `quality_model`, замінити `"3.5"` там, де питання про поточну поведінку, і звірити цілі.

Якщо `smoke` скаржиться на число фрагментів — корпус підріс; нове число записують у `checks.json` полем
`expected_passages`, а в `expected_note` — коли й чому його знято.

Токен GitHub (`GITHUB_TOKEN` у `.env`) потрібен для історії комітів і дерев знімків (кілька сотень звернень на повний
прогін).

## Уточнення відповідей після оновлення

Після кожного оновлення корпусу — цикл із [кроку 7 загального довідника](../../UPDATE.md#крок-7--відновити-уточнення-відповідей):
`./df vue quality --show`, порівняння обох десяток з попереднім результатом, розбір промахів, правка промпту,
знову замір. Останній результат — у README, розділ «Скільки цього».
