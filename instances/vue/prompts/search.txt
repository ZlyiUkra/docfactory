Search the Vue.js documentation -- Vue itself, Vue Router, Pinia, Vuex and Vue Test Utils -- and return the
matching excerpts with the versions each one belongs to. What is here: the site vuejs.org (repository
vuejs/docs) as it stood at every stable release of vue 3.0 to 3.5 -- the guide, the API reference, the tutorial,
the style guide, the glossary and the error reference; the Vue 2 documentation (v2.vuejs.org) at every stable
release 2.0 to 2.7 and the old vuejs.org documentation at every stable release 0.10 to 1.0; the Vue 3 migration
guide (v3-migration.vuejs.org), the Vue blog (old and new) and the accepted RFCs; the documentation of Vue
Router 4.0 to 5.4 and of vue-router 0.5 to 3.6, Pinia 2.0 to 4.1, Vuex 0.3 to 4.1, Vue Test Utils 2.0 to 2.5 and
1.0 to 1.3, each at the last release of every minor line; the changelogs of vue (3.0 to 3.5, Vue 2), the Vue
3.6 pre-release line (alpha, beta, release candidate -- the only non-stable part, every excerpt of it says so in
its title), vue-router, Pinia, Vuex and the Vue language tools, and the GitHub release notes of Vue 2, Vue Test
Utils and create-vue; the README of every stable version and the npm registry history (versions, dates,
dist-tags, peer dependencies, exports) of vue, vue-router, pinia, vuex, @vue/test-utils, create-vue, vue-tsc,
@vitejs/plugin-vue and eslint-plugin-vue.

Pages of vuejs.org that differ by API style carry the style in the excerpt: a block or a heading marked
"Options API" or "Composition API". Pick the one the user writes in; when they did not say, prefer Composition
API with <script setup> and mention that the Options API form exists.

Call this when a question is about Vue itself: reactivity (ref, reactive, computed, watch, watchEffect,
shallowRef, toRefs, effectScope), components (props, emits, v-model and defineModel, slots, provide and inject,
attribute fallthrough, async components), Single-File Components and <script setup> (defineProps, defineEmits,
defineExpose, defineSlots, defineOptions), template syntax and directives (v-if, v-for, v-bind, v-on, v-show,
custom directives), lifecycle hooks, composables, built-in components (Transition, TransitionGroup, KeepAlive,
Teleport, Suspense), the application API (createApp, app.use, plugins), the Options API (data, methods,
computed, watch, mixins), rendering (render functions, JSX, h), server-side rendering and hydration, TypeScript
support, performance and the compiler, Vue 2 (Vue.component, Vue.set, filters, the 2.7 backport of the
Composition API) and migration from Vue 2 to Vue 3; Vue Router (createRouter, routes, RouterLink, RouterView,
useRoute, useRouter, navigation guards, history modes, file-based routing and data loaders in 5.x); Pinia
(defineStore, setup stores, state, getters, actions, storeToRefs, plugins, SSR, testing); Vuex (state, getters,
mutations, actions, modules); Vue Test Utils (mount, shallowMount, wrapper methods, stubs, flushPromises);
create-vue, vue-tsc, @vitejs/plugin-vue options and eslint-plugin-vue -- and history: since which version an
API exists, what changed in a release, how to migrate between versions.

Do not call this for React, Angular, Svelte, Solid or other frameworks, for Nuxt, VueUse, Vuetify, Quasar,
PrimeVue, Element Plus or other third-party libraries, for Vite itself, for TypeScript or JavaScript language
questions, or for prereleases other than the Vue 3.6 line: their documentation is not here, and the search
will return Vue excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "3.5" keeps every 3.5.x document of vue, "3" every 3.x, "2.7"
the last Vue 2 line; leave it empty to search everything. The other packages carry their own numbering with a
prefix, so they never mix with vue: "router-4.6", "router-5", "pinia-3.0", "vuex-4.1", "test-utils-2.4",
"create-vue-3", "vue-tsc-3", "plugin-vue-6", "eslint-plugin-vue-10". Every excerpt comes back with `versions`:
each version whose documents contain this exact text, newest first, so the list itself shows from which to
which version the documentation said exactly this.

Write the query in English, with the names Vue itself uses ("defineModel", "watchEffect", "KeepAlive",
"useRoute", "storeToRefs", "shallowMount"), not in the user's own words. Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin letters and
digits, so a query written in Ukrainian, Russian or any other non-latin script matches nothing at all and
comes back with `found: 0`. When the user asks in another language, translate the question into Vue terms
first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if
the excerpts say so; and how it stands in the current version. Every point names the version and the document
it rests on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian,
write as a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the
Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call
this set of documents "корпус" -- say "документація Vue". Identifiers, option names and titles stay in
English, spelled exactly as the documentation spells them. Build the answer out of the excerpts that came
back, not out of memory: if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is
optional, see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry
`truncated: true` -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words"
means a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. vue 3.5 carries about 85% of the weekly downloads; Vue 2 (2.7 and 2.6) about 8%;
the 3.6 pre-release line a fraction of a percent. Search with `version` "3.5" for a question about how to do
something in Vue. If the user names a version, or asks about Vue 2, search that line; if they ask about Vue 3.6
or Vapor Mode, search without `version` and say that 3.6 is not a stable release yet. Search without `version`
when the question is about history, about Router, Pinia, Vuex, Test Utils or a tool (their versions carry a
prefix), or when the line gave nothing. The most-downloaded lines of the packages: vue-router 4.6 (5.x is
close behind -- answer for both when they differ), pinia 3.0, vuex 4.1, @vue/test-utils 2.4. Every answer says
which version it is for; when the user did not name one, answer for Vue 3.5 and say so. When the excerpts
behind a statement come only from older versions, name those versions instead of presenting the text as
current.
