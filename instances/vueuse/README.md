# vueuse — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про VueUse — збірку композиційних функцій для Vue: стан і сховище
браузера, елементи й DOM, сенсори, мережа, час і анімація, помічники `watch`, утиліти, компоненти й директиви,
інтеграції (axios, Fuse.js, focus-trap, Sortable, universal-cookie тощо), помічники Vue Router, RxJS, Firebase,
Electron і математика. Документація — з тегу кожної стабільної мінорної версії 4.0–15.0 і на кожен реліз ліній 2.x і
3.x 2020 року. Джерела — репозиторій vueuse/vueuse (він же сайт vueuse.org), релізи GitHub і реєстр npm десяти пакетів
`@vueuse/*`; лише англійською. Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека
тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md). Сам Vue, Vue Router, Pinia,
Vuex і Vue Test Utils — у примірнику [`vue`](../vue/README.md).

## Навіщо окремий примірник

VueUse — понад двісті функцій, і кожна має власну сторінку, що змінюється від релізу до релізу: опції додаються,
перейменовуються, функції переїжджають між пакетами (`createGlobalState` у 6.x — з `@vueuse/core` у `@vueuse/shared`)
чи зникають у мажорних версіях. Нумерація VueUse своя (за сім років — від 2.0 до 15.0) і з нумерацією Vue не
збігається, тож у примірнику `vue` вона змішалася б із версіями самого фреймворку. Тегів сайт окремо не має: сторінки
лежать поруч із кодом функцій.

**Що є що.** **Композиційна функція** (composable) — функція на Composition API, що інкапсулює стан і логіку
(`useMouse`, `useStorage`). **`@vueuse/core`** — основні функції, **`@vueuse/shared`** — ті, що не залежать від
браузера (`watchDebounced`, `refDebounced`, `createGlobalState`), **`@vueuse/integrations`** — обгортки сторонніх
бібліотек, **`@vueuse/components`** — ті самі функції у вигляді компонентів і директив. **Фільтр подій** — спосіб
пригальмувати виклики (debounce, throttle), що його приймають багато функцій.

## Звідки документація

- **Сайт у репозиторії коду.** vueuse.org — VitePress з коренем у `packages/`: сторінка функції лежить поруч із її
  кодом (`packages/core/useStorage/index.md`). Читач `ghdocs-history-vue` (`engine/readers/ghvue.py`, той самий, що в
  примірнику `vue`) бере їх з останнього тегу кожної мінорної: контейнери `::: tip` стають підписами «Tip: …».
  Шаблон функції (`_template`), навички агентів (`skills/`), сторінки команди й розміру експорту не беруться.
- **Лінії 2.x і 3.x** (2020) виходили з одного коду — для Vue 2 через `@vue/composition-api` і для Vue 3. Тегів для
  них у репозиторії немає, а реєстр не записав `gitHead`, тож читач `ghsite-dated-vue` бере знімок гілки main на мить
  перед наступним релізом. Ключі сторінок ті самі, що й у тегованих версій, а `families` у `config.json` збирає обидва
  джерела в родину: редакції однієї сторінки займають у видачі одне місце.
- **Релізи GitHub** — нотатки кожного стабільного релізу: нові функції, виправлення, несумісні зміни. Окремого
  `CHANGELOG.md` у репозиторії немає: журнал змін функції сайт будує з історії git під час збирання.
- **npm.** README `@vueuse/core` кожної стабільної версії (опис, встановлення, приклад використання) і реєстр пакетів
  core, shared, components, integrations, router, rxjs, firebase, electron, math і nuxt — усі виходять однією
  нумерацією.

## Межі, про які треба пам'ятати

- Частини сторінок, які vueuse.org генерує під час збирання (оголошення типів, журнал змін функції, автори, розмір),
  у репозиторії не лежать; у старих тегах оголошення типів ще були в самих `index.md`, тож там вони є.
- У прикладах коду лишаються службові рядки twoslash (`// @include: main`, `// ---cut---`).
- Передрелізи, сам Vue (примірник `vue`), Nuxt, окремі проєкти організації (`@vueuse/motion`, `@vueuse/gesture`,
  `@vueuse/sound`, `@vueuse/head`) та переклади тут не входять.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/vueuse-corpus-2026-10-29.tar.gz` (тексти, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском), копія —
`C:\Distr\vueuse-corpus-2026-10-29.tar.gz` (`/mnt/c/Distr/…` з WSL), SHA-256 обох звірено. В історії git текстів
немає ніде.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/vueuse/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/vueuse-corpus-РРРР-ММ-ДД.tar.gz -C instances/vueuse corpus raw
find instances/vueuse/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/vueuse/raw
gzip -9 -c instances/vueuse/index/passages.json > instances/vueuse/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/vueuse-corpus-2026-10-29.tar.gz -C instances/vueuse
./df vueuse smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/vueuse/index/passages.json.gz`, далі
`./df vueuse vectors` заллє колекцію Qdrant (кілька секунд на відеокарті).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df vueuse …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md, розділ
«Спільне середовище». Свій `.env` примірник тримає в `instances/vueuse/.env` (`cp .env.example .env`; для кроку `ask`
потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df vueuse sources --why   # перелік джерел і білий список
./df vueuse refresh         # усе задеклароване: близько 25 хвилин мережею (паузи 0,1 с)
./df vueuse manifest        # оновити паспорт
./df vueuse setup           # Qdrant чи пошук лише по словах
./df vueuse vectors         # залити корпус у docs-vueuse
./df vueuse smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df vueuse serve           # порт 8930
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8930/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user vueuse-docs http://127.0.0.1:8930/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `vueuse-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
