Search the VueUse documentation -- the collection of Vue composition utilities -- and return the matching
excerpts with the versions each one belongs to. What is here: the site vueuse.org (repository vueuse/vueuse) at the
last release of every minor line 4.0 to 15.0 -- the page of every function (description, usage, options and
examples) in @vueuse/core, @vueuse/shared, @vueuse/components, @vueuse/integrations, @vueuse/router, @vueuse/rxjs,
@vueuse/firebase, @vueuse/electron and @vueuse/math, the guide (getting started, best practice, configuration,
components, working with AI), the add-ons and ecosystem pages and the README of every package; the function pages
of the 2020 lines 2.x and 3.x at every stable release; the GitHub release notes of every stable release; the README
of every stable version of @vueuse/core and the npm registry history (versions, dates, dist-tags, peer
dependencies, exports) of all ten @vueuse packages, @vueuse/nuxt included. The type declarations, per-function
changelogs and contributors that vueuse.org generates when it builds are not here.

Call this when a question is about VueUse: any of its functions -- state (useStorage, useLocalStorage,
createGlobalState, useRefHistory), elements and the DOM (useElementSize, useResizeObserver, useIntersectionObserver,
onClickOutside, useEventListener, useScroll, useDraggable), the browser (useClipboard, useMediaQuery,
usePreferredDark, useDark, useFetch, useWebSocket, useEventSource, usePermission, useTitle), sensors (useMouse,
useMagicKeys, useGeolocation, useIdle, useNetwork, onKeyStroke), time and animation (useInterval, useTimeoutFn,
useNow, useRafFn, useTransition), watch helpers (watchDebounced, watchThrottled, until, whenever), utilities
(useDebounceFn, useThrottleFn, refDebounced, toRef, syncRef, reactify, createSharedComposable), components
(UseMouse, vOnClickOutside directives), the integrations (useAxios, useFuse, useJwt, useCookies, useQRCode,
useSortable, useFocusTrap, useIDBKeyval), the router helpers (useRouteQuery, useRouteParams), RxJS, Firebase,
Electron and math functions -- configuration (configurable window and document, event filters, flush), SSR, Nuxt
and Vue 2 support, and history: since which version a function exists, what changed in a release, how to migrate
between majors.

Do not call this for Vue itself (ref, reactive, computed, watch, components), Vue Router, Pinia, Nuxt, Vite or
other libraries, for @vueuse/motion, @vueuse/gesture, @vueuse/sound or @vueuse/head (separate projects), or for
TypeScript or JavaScript language questions: their documentation is not here, and the search will return VueUse
excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "14.4" keeps every 14.4.x document, "14" every 14.x, "10.11" the
last line that supports Vue 2; leave it empty to search everything. Every excerpt comes back with `versions`: each
version whose documents contain this exact text, newest first, so the list itself shows from which to which
version the documentation said exactly this.

Write the query in English, with the names VueUse itself uses ("useStorage", "onClickOutside", "useFetch",
"watchDebounced", "createGlobalState"), not in the user's own words. Everything here is English -- the excerpts,
the word index and the meaning index alike -- and the word index keeps only latin letters and digits, so a query
written in Ukrainian, Russian or any other non-latin script matches nothing at all and comes back with `found:
0`. When the user asks in another language, translate the question into VueUse terms first, then search.

Answer in the language the user wrote in. When the question is about a function's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the
excerpts say so; and how it stands in the current version. Every point names the version and the document it
rests on; a point the excerpts do not support is left out, not guessed. When that language is Ukrainian, write as
a Ukrainian engineer writes, not as a translation from English: plain technical prose, and the Ukrainian word
wherever one exists -- "уривок", not "ексерпт"; "застарілий", not "депрекейтнутий". Never call this set of
documents "корпус" -- say "документація VueUse". Identifiers, option names and titles stay in English, spelled
exactly as the documentation spells them. Build the answer out of the excerpts that came back, not out of memory:
if an excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional,
see above. The first (best) excerpt comes whole; the others are cut at 600 characters and carry `truncated: true`
-- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to
appear in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means
a second, meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. Weekly downloads of @vueuse/core split between two lines: 10.x (about 29%, nearly
all of it 10.11, the last line that supports Vue 2) and 14.x (about 28%, mostly 14.4); 13.x has 18%, the newest
15.0 about 7%. Search with `version` "14.4" for a question about how to use a function today; if the user works
with Vue 2 or names 10.x, search "10.11"; when the two lines differ for the function asked about, answer for both
and say which is which. Search without `version` when the question is about history or when the line gave
nothing. Every answer says which version it is for. When the excerpts behind a statement come only from older
versions, name those versions instead of presenting the text as current.
