# wagmi — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про Wagmi — бібліотеку від wevm для фронтенду застосунків на Ethereum:
як підключити гаманець, перемкнути мережу, прочитати баланс, блок чи транзакцію, прочитати смартконтракт і записати в
нього, надіслати транзакцію й дочекатися її квитанції, підписати повідомлення, налаштувати кеш TanStack Query і
рендеринг на сервері, згенерувати типізовані хуки з ABI контрактів. Джерела — репозиторій wevm/wagmi на GitHub (з нього
збирається сайт wagmi.sh) і реєстр npm, лише англійською. Код спільний і лежить у `../../engine/`, `../../server/` та
`../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у [../../README.md](../../README.md).

## Навіщо

Факультатив «крипта» планів React і Next.js підключає гаманець саме через Wagmi 3, а API бібліотеки між мажорними
версіями переписано: у 1.0 ethers.js замінено на viem, у 2.0 запити перейшли на TanStack Query й половина хуків
дістала нові імена, у 3.0 `useAccount` став `useConnection`, а SDK гаманців застосунок ставить сам. Більшість прикладів
у мережі й у пам'яті моделі написано для 1.x і 2.x. Тож потрібен текст документації кожної версії, а не пам'ять
моделі.

**Що є що.** **Гаманець** (wallet) — розширення браузера чи застосунок (MetaMask, Coinbase Wallet), що тримає ключі й
підписує транзакції. **З'єднувач** (connector) — модуль Wagmi, що вміє говорити з одним видом гаманців: `injected`
(будь-яке розширення браузера), `metaMask`, `walletConnect`, `coinbaseWallet`, `baseAccount`, `safe`. **Транспорт**
(transport) — як застосунок звертається до вузла мережі: `http`, `webSocket`, `fallback`. **Ланцюг** (chain) — мережа
Ethereum чи сумісна з нею (mainnet, Sepolia, Base) з ідентифікатором `chainId`. Одна дія має кілька облич: **хук**
React (`useBalance`), **composable** Vue (`useBalance` з `@wagmi/vue`), **primitive** Solid (`useBalance` з
`@wagmi/solid`) і **дія** без фреймворку (`getBalance` з `@wagmi/core`). **Tempo** — окремий блокчейн для платежів
від Stripe і Paradigm; Wagmi 3 має для нього власні хуки й дії (`wagmi/tempo`).

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

вставляє, і в рядку `# версія:` стоять усі версії, де вона була саме такою. Однаковий текст різних версій лягає одним
фрагментом з усіма цими версіями, тож 939 редакцій сайту 2.x додають лише 1 130 фрагментів: решта тексту та сама, що в
3.x.

Замір `quality`: перша десятка (питання своїми словами, без версії) — по словах 5 із 10, за змістом 7, разом 9; друга,
«як модель» (назви хуків, параметрів і з'єднувачів, з версією, як велить промпт), — 10 із 10. Промах першої десятки —
«перевірити, що виклик контракту пройде, перш ніж просити гаманець підписати» без жодного слова документації
(`useSimulateContract`). Поля `max_per_doc` (1, 2, 3) і `fusion_depth` (10) нічого не покращують, тож не ввімкнені. До
цілей двох питань додано справжні відповіді, яких бракувало: приклад і посібник «Sign Message» 0.x–1.x та хук
`useEnsLookup` 0.x (попередник `useEnsName`).

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, родина джерел сайту (`families`) і
  профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (дерева тегів, файли репозиторію); `.mcp.json` — запис
  HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df wagmi <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| Сайт 2.x і 3.x | тека `site/` (VitePress) на тезі кожної стабільної версії | `ghdocs-history` з полем `vitepress` |
| Сайт 1.x і документація 0.x | тека `docs/pages` (Nextra, MDX) на тезі кожної стабільної версії | `ghdocs-history` |
| Журнали змін | `packages/<пакет>/CHANGELOG.md` гілки `main`; для 0.12.14–0.12.19 — гілки `0.12.x` | `changelog-named` |
| Таблиці версій | реєстр npm, сім пакетів | `npm-versions` |

Сайт wagmi.sh збирається з теки `site/` репозиторію, тож текст береться звідти, а в шапці документа стоїть адреса
сторінки сайту: wagmi.sh для 3.x, 2.x.wagmi.sh для 2.x, 1.x.wagmi.sh для 1.x. Сайту 0.x більше немає — там адреса
файла на GitHub. Markdown-копії сторінок (`.md`, `llms.txt`) сайт віддає лише останній редакції кожної лінії, а
потрібна кожна версія. Релізи GitHub повторюють журнали змін слово в слово, тож не беруться; README пакетів у npm —
логотип і посилання, теж не беруться. Посилання у відповідях ведуть на wagmi.sh, 2.x.wagmi.sh, 1.x.wagmi.sh,
github.com і registry.npmjs.org.

Особливості, які варто знати:

- **Сторінка 2.x–3.x у репозиторії — каркас.** Опції TanStack Query, поля результату, файл конфігу прикладу, текст
  сторінок з'єднувачів лежать окремими файлами й вставляються рядками `<!--@include: @shared/…-->` і
  `<<< @/snippets/…`, а типи й версії — змінними `{{TData}}`, `{{viemVersion}}` з блоку `<script setup>` сторінки й
  полів `package.json` пакетів. Поле `vitepress` читача `ghdocs-history` (модуль `_vitepress`) усе це розкриває, тож
  у корпусі сторінка така, як на сайті: `pnpm add @metamask/connect-evm@^2.1.0`, а не порожнє місце. Контейнери
  `::: tip` стають підписами «Tip:», вкладки `::: code-group` — блоками коду з підписом файла.
- **Редакція враховує вставлене.** Сторінка хука між версіями часто не міняється, а спільний файл опцій — міняється.
  Тому ім'я документа будується з вмісту сторінки, вставлених файлів і підставлених значень, інакше сторінка 2.5
  показувала б опції 2.19. Із `package.json` береться лише підставлене поле, а не цілий файл: він міняється з кожним
  випуском.
- **Повтор файла конфігу.** Сайт ставить вкладку `config.ts` біля кожного прикладу сторінки; у тексті вона лишається
  один раз на сторінку, щоб однаковий код не топив розділи.
- **Версії без тегу.** 14 стабільних версій вийшли без тегу в репозиторії; 13 з них беруться з коміту випуску
  («chore: version packages»), зокрема 0.12.14–0.12.19 з гілки `0.12.x`. Версію 2.0.0 реєстр позначає «alpha
  version, do not use», вона не береться.
- **Переклади.** Документація 0.x має 31 сторінку китайською; корпус англійський, вони не беруться.
- **Тексти, яких сайт не підставляє.** `{{TPageParam}}` у переліку опцій безкінечних запитів лишається як є: значення
  на сторінках не задано й на сайті.

## Версії у відповіді

Фільтр `version` бере лінію: `"3"` — усе 3.x, `"2"` — 2.x, `"2.19"` — лінію 2.19, `"1"` і `"0"` — старі лінії.
Без фільтра сторінка, що є в кількох лініях, показується один раз — найновішою редакцією; родина `site` у
`config.json` зводить усі чотири джерела сайту. Записи журналів мають версію свого запису.

Без названої версії промпт велить відповідати для wagmi 2 — найпоширенішої за завантаженнями npm лінії (73% за
тиждень на 12.10.2026, з них 57% — 2.19.5; 3.x — 24%) і показувати, як те саме пишеться у wagmi 3, де це інакше.

Якщо питання не називає фреймворку, відповідь іде для React з окремим рядком про те, що те саме є у Vue, Solid,
`@wagmi/core` чи Tempo, і як воно там зветься. Назва документа несе фреймворк: «React: useBalance», «Vue: useBalance»,
«Core: getBalance», «Solid: useBalance», «Tempo: …», «CLI: …».

## Межі, про які треба пам'ятати

Тут немає viem (низькорівнева бібліотека, на якій стоїть Wagmi; сторінки Wagmi лише посилаються на її дії), ethers.js,
RainbowKit, ConnectKit, Reown AppKit, SDK MetaMask і WalletConnect, Solidity, Foundry і Hardhat як таких, документації
мережі Tempo поза хуками Wagmi, передрелізів (canary). TanStack Query як такий — у примірнику `tanstack-query`, React —
у `react`.

## Сховище сирого

Під час оновлення примірник тримає ще й сирі відповіді — у теці `raw/`, поза git (сховище ввімкнене за
замовчуванням). Правка читача тоді не вимагає нового завантаження: `./df wagmi build` збирає тексти зі сховища без
мережі. Попередні версії файлів не видаляються, а переїжджають у `raw/_old/<день>/`. Між оновленнями сховище, як і
тексти, лежить лише в архіві: серверу воно не потрібне. Устрій — у [../../UPDATE.md](../../UPDATE.md), розділ про
`refresh`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/wagmi-corpus-2026-10-12.tar.gz` (4 965 текстів, паспорт і сховище
сирого `raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде.
Архів лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/wagmi/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/wagmi-corpus-РРРР-ММ-ДД.tar.gz -C instances/wagmi corpus raw
find instances/wagmi/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/wagmi/raw
gzip -9 -c instances/wagmi/index/passages.json > instances/wagmi/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/wagmi-corpus-РРРР-ММ-ДД.tar.gz -C instances/wagmi
./df wagmi smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/wagmi/index/passages.json.gz`, далі
`./df wagmi vectors` заллє колекцію Qdrant (близько 40 хвилин).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df wagmi …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище». Свій `.env` примірник тримає в `instances/wagmi/.env` (`cp .env.example .env`;
для кроку `ask` потрібен `ANTHROPIC_API_KEY`); `GITHUB_TOKEN`, якого немає в цьому `.env`, береться з кореневого.

## Збирання корпусу

```
./df wagmi sources --why   # перелік джерел і білий список
./df wagmi refresh         # завантажити все задеклароване (~45 хвилин: 420 тегів, ~5 000 файлів, пауза 0,3 с)
./df wagmi build           # перезібрати тексти зі сховища сирого, без мережі (після правки читача)
./df wagmi manifest        # оновити паспорт
./df wagmi setup           # Qdrant чи пошук лише по словах
./df wagmi vectors         # залити корпус у docs-wagmi (~40 хвилин)
./df wagmi smoke           # перевірки
```

Як оновлювати після нових версій — у [UPDATE.md](UPDATE.md).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df wagmi serve       # порт 8827
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8827/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user wagmi-docs http://127.0.0.1:8827/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт. Інший
шлях — запис `.mcp.json` цієї теки: Claude Code, відкритий у ній, побачить сервер сам.

**3. Перевірити.** `/mcp` — має бути `wagmi-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Якщо порт 8827 зайнятий, `serve` падає з «address already in use»: значить,
сервер уже піднято в іншому терміналі. Решта — scope запису — так само, як у
[README примірника nestjs](../nestjs/README.md#спосіб-б--сервер-під-claude-code-http).
