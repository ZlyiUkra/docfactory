# Оновлення корпусу wagmi

Дві різні роботи: звичайне оновлення, коли вийшли нові версії Wagmi, і збирання з нуля. Порядок усередині кожної
важливіший за самі команди.

Головне правило: **оновлювач тягне лише оголошене.** Дерева й файли репозиторію — лише тих тегів і комітів, що
перелічені в полі `tags` джерел `docs-*`, і лише в межах `within`; журнали змін — лише з адрес джерел `changelog-*`;
версії — з реєстру npm. Нова версія сама в документацію не потрапить, доки її тег не дописано в `tags`.

Друге правило: **лише стабільні версії.** У `tags` — тільки стабільні випуски пакета `wagmi`, без canary; поле
`skip_versions` джерел `npm-*` відкидає все з дефісом за номером.

Третє правило: **нова версія змінює й старі документи.** Документ сторінки — неповторна редакція, а в рядку
`# версія:` стоять усі версії, де вона була саме такою. Тож після нових тегів джерело `docs-3` перезаписується цілком
(`refresh docs-3`), а не докачується (`--missing`).

Четверте правило: **нічого не видаляється.** Ані `refresh`, ані `build`, ані `manifest` нічого не стирають самі;
`vectors` прибирає лише точки власної колекції, чиїх фрагментів у корпусі вже немає.

**Спершу — повернути тексти.** Корпус примірника в архіві: у `corpus/` лежить лише паспорт, а `check`, `refresh` і
`manifest` працюють із файлами. Перед будь-якою роботою нижче тексти й сховище сирого розпаковують, а після неї —
пакують і виносять знову; обидві дії описані в [README, розділ «Архівний режим»](README.md#архівний-режим-сервер-без-корпусу).

## 1. Вийшли нові версії

**Крок 1. Дописати теги.** Нові стабільні версії — у реєстрі npm (`https://registry.npmjs.org/wagmi`, поле `versions`
без дефіса). Для кожної — тег `wagmi@<версія>` на початок поля `tags` джерела `docs-3` (від найновішого):
`"wagmi@3.8.0": "3.8.0"`. Якщо тегу в репозиторії немає (так буває з changesets), береться коміт випуску «chore:
version packages», де `packages/react/package.json` дістав цю версію: `git log -S'"version": "3.8.0"' --
packages/react/package.json` у клоні репозиторію, повний SHA — ключем замість тегу.

**Крок 2. Нова мажорна лінія (напр. 4.0).** Сайт переносить попередню лінію на свій піддомен (так 2.x переїхала на
2.x.wagmi.sh). Тоді:

- додати джерело `docs-4` за зразком `docs-3` (адреса `wagmi.sh` у полі `site`), а `docs-3` перевести на
  `https://3.x.wagmi.sh/` — перевірити, що адреса справді відповідає;
- дописати `docs-4` у родину `site` поля `families` у `config.json`;
- у промптах оновити лінії й версію за замовчуванням: `prompts/search.txt` (абзаци «Versions», про зміни API між
  версіями й про версію за замовчуванням), `prompts/agent.txt`, `prompts/loaded.txt`; версію за замовчуванням брати з
  тижневих завантажень npm (`https://api.npmjs.org/versions/wagmi/last-week`).

**Крок 3. Завантажити.**

```
./df wagmi sources --why
./df wagmi refresh docs-3 changelog-wagmi changelog-wagmi-core changelog-wagmi-connectors changelog-wagmi-vue \
    changelog-wagmi-solid changelog-wagmi-cli changelog-create-wagmi npm-wagmi npm-wagmi-core npm-wagmi-connectors \
    npm-wagmi-vue npm-wagmi-solid npm-wagmi-cli npm-create-wagmi
./df wagmi manifest
./df wagmi vectors
./df wagmi smoke
# Ctrl+C у терміналі з serve, і знову: ./df wagmi serve
```

Названий `refresh` інших джерел не чіпає зовсім. Джерела `docs-2`, `docs-1`, `docs-0` і журнали гілки `0.12.x`
застиглі: ці лінії більше не виходять.

**Крок 4. Сайт змінив розмітку.** Якщо в тексті з'явилися службові рядки VitePress (`:::`, `<<<`, `{{…}}`, рядки
скрипта), правиться модуль `engine/readers/_vitepress.py`. Правка читача не вимагає нового завантаження:
`./df wagmi build docs-3` збирає тексти зі сховища сирого.

Корпус не комітиться: після оновлення пишуть новий архів і знову виносять тексти й сховище (README, розділ «Архівний
режим»), а в git ідуть лише паспорт і кеш. Старий архів видаляють, коли новий звірено з диском.

Якщо `smoke` скаржиться на число фрагментів — це наслідок того, що документація підросла. Нове число записують у
`checks.json` полем `expected_passages`, а в `expected_note` — коли й чому його знято.

## 2. Збирання з нуля

**Крок 1. Токен.** Покладіть `GITHUB_TOKEN=…` у `.env` цієї теки: без нього 420 дерев тегів ішли б годинними вікнами
по 60 звернень.

**Крок 2. Усе одним прогоном**, окремим процесом:

```
PYTHONUNBUFFERED=1 setsid nohup ./df wagmi refresh > refresh.log 2>&1 < /dev/null &
```

Близько 45 хвилин: дерево кожного тегу через API GitHub і кожен неповторний файл (сторінка, вставка, `package.json`)
один раз із raw.githubusercontent.com, з паузою 0,3 с. Обірваний прогін продовжують `./df wagmi refresh <джерело, де
зупинився>`, далі `refresh --missing`.

**Крок 3.** `manifest`, `vectors` (~40 хвилин), `smoke`, `quality`; далі — архів і винесення текстів.

Очікуваних збоїв `refresh` немає.
