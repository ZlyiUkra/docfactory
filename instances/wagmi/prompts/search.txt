Search the official documentation of Wagmi -- wevm's reactive library for Ethereum apps: React
hooks (npm package wagmi), Vue composables (@wagmi/vue), Solid primitives (@wagmi/solid),
framework-free actions (@wagmi/core), wallet connectors (@wagmi/connectors), the code generator
(@wagmi/cli) and the project starter (create-wagmi) -- and return the matching excerpts with the
versions each one belongs to. Here: the documentation site of every stable release -- 3.x (current,
wagmi.sh), 2.x (2.x.wagmi.sh), 1.x (1.x.wagmi.sh) and 0.x (repository only) -- with the guides,
the configuration (createConfig, chains, connectors, transports, storage), every hook, composable,
primitive and action, the connectors and transports, the CLI with its commands and plugins
(Foundry, Hardhat, Etherscan, React, actions), the migration guides, the developer pages, and the
Tempo hooks and actions (wagmi/tempo); the changelog of every package (wagmi, @wagmi/core,
@wagmi/connectors, @wagmi/vue, @wagmi/solid, @wagmi/cli, create-wagmi), every version from the
first; and the npm version tables of these packages with dates, dist-tags and dependencies.

Call this when a question is about Wagmi itself -- connecting a wallet (useConnect,
useConnection, useDisconnect, injected, metaMask, walletConnect, coinbaseWallet, baseAccount,
safe), chains and switching them (useSwitchChain, useChainId), reading balances, blocks and
transactions (useBalance, useBlockNumber, useTransaction, useWaitForTransactionReceipt), reading
and writing contracts (useReadContract, useReadContracts, useWriteContract,
useSimulateContract, useWatchContractEvent), sending transactions (useSendTransaction), signing
(useSignMessage, useSignTypedData), ENS (useEnsName, useEnsAddress), gas (useEstimateGas),
TanStack Query integration (query keys, invalidation, SSR and hydration, cookieStorage),
TypeScript (ABI and typed data inference), error types, the CLI (wagmi generate, the foundry
plugin), and above all history: since which version something exists, what changed, what was
renamed or removed (the 1.0, 2.0 and 3.0 migrations).
Example query: "useReadContract query enabled".

Do not call this for viem itself (publicClient, walletClient, parseEther, the viem actions that
Wagmi wraps), ethers.js, TanStack Query itself, RainbowKit, ConnectKit or Reown AppKit,
Solidity, Foundry or Hardhat themselves, the MetaMask or WalletConnect SDKs, or the Tempo chain
beyond Wagmi's own Tempo hooks: their documentation is not here, and the search will return
Wagmi excerpts that merely mention them, with confident-looking titles. Wagmi pages often say
"this is a wrapper around viem's …" -- that sentence is all that is here about viem.

Frameworks. The same hook exists for several frameworks: titles carry the framework -- "React:
useBalance", "Vue: useBalance" (composable), "Solid: useBalance" (primitive), "Core: getBalance"
(action, no framework), "CLI: foundry", "Tempo: token.useGetBalance". Name the framework in the
query when the user names one ("vue useBalance", "core getBalance"). When the user names none,
answer for React (wagmi) and add one line saying that the same exists in the other tools and how it
is called there -- the Vue composable, the Solid primitive, the @wagmi/core action or the Tempo
hook -- when the excerpts show such a counterpart.

Versions. `version` narrows the search to the documents of one release line: "3" keeps every 3.x
document, "2" keeps 2.x, "2.19" keeps 2.19.x, "1" and "0" the old lines. Each document keeps one
text of a page with every version where the page read exactly so. Without `version` a page found
in several lines comes back once, in its newest edition -- so for an answer about wagmi 2 pass
"2". Every excerpt comes back with `versions`: each version whose documents contain this exact
text, newest first. Changelog excerpts carry the version of their entry.

The API changed between major versions, and the same task is written differently: 3.0 renamed
useAccount, useAccountEffect and useSwitchAccount to useConnection, useConnectionEffect and
useSwitchConnection and made the connectors' SDKs (MetaMask, WalletConnect, Coinbase, Safe…)
separate dependencies the app installs itself; 2.0 moved data fetching onto TanStack Query (the
`query` parameter, WagmiProvider inside QueryClientProvider) and renamed many hooks
(useContractRead became useReadContract, useNetwork became useAccount().chain,
useWaitForTransaction became useWaitForTransactionReceipt); 1.0 replaced ethers.js with viem.
When the user's code shows which API they use, search that version.

Name the hook, action, parameter or type the way the documentation titles it, not in the user's
own words: "useWriteContract", "createConfig ssr", "cookieStorage", "useWaitForTransactionReceipt
confirmations", "injected target", not "make the button wait until the transfer is done". For a
how-to question a guide often shows it better than the reference: search for it as well
("guide connect wallet", "guide send transaction", "guide ssr").

For a question about when something appeared, changed or disappeared, search more than once:
without `version` first, to find the changelog entry or migration guide that names the exact
version, then with the versions around it, to see the documentation of that time.

Write the query in English, with the names Wagmi itself uses. Everything here is English -- the
excerpts, the word index and the meaning index alike -- and the word index keeps only latin
letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language, translate
the question into Wagmi terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words of
the query had to appear in the text, so a query phrased in other words than the documentation
uses may miss; "meaning+words" means a second, meaning-based index answered as well, and a
paraphrase had a chance.

Every answer says which version it is for. When the user did not name a version, answer for
wagmi 2 -- the line most installed from npm (about three quarters of weekly downloads, most of
them 2.19.5) -- and, because 3.x is the current release, add how the same is written in 3.x when
it differs; say so in the answer ("for wagmi 2.19; in wagmi 3 …"). Add that for a precise answer
about another version the user can name it. When the excerpts behind a statement come only from
older versions, name those versions instead of presenting the text as current.

Answer in the language the user wrote in. When the question is about a feature's history or
support, answer point by point: since which version it exists; what changed in later versions;
and how it stands now -- recommended, deprecated, or removed and replaced by what. Every point
names the version and the document it rests on; a point the excerpts do not support is left out,
not guessed. When that language is Ukrainian, write as a Ukrainian engineer writes, not as a
translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "гаманець", not "воллет"; "застарілий", not "депрекейтнутий". Never
call this set of documents "корпус" -- say "документація Wagmi". Identifiers, API names and
titles stay in English, spelled exactly as the documentation spells them. Build the answer out of
the excerpts that came back, not out of memory: if an excerpt was cut, read the whole of it
before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of an
excerpt to `read_section` to get the whole thing.
