# WebAssembly spec issue #354: Convert a general wast to wasm?
# джерело: https://github.com/WebAssembly/spec/issues/354
# отримано: 2026-09-30

Issue #354, opened by kripken on 2016-10-03, closed (completed) on 2016-10-10.

Doing `wasm a.wast -o a.wasm` works if the wast validates under the spec interpreter, but if not then not (and e.g. a real-world wast from emscripten would import a bunch of things that the spec interpreter is not aware of). I also tried with `-u` for unchecked but it still hits link failures. Is that intentional? It seems like it would be useful if the reference implementation could convert a general wast to wasm, for comparison purposes.

## Comment by rossberg, 2016-10-11

Ah, that actually _is_ a bug. A crash error should never occur unless you run an invalid module with `-u`. And you should never need `-u` for conversion.

The crash was due to the fact that validation still tried to check order and boundedness of segment definitions, even though with the new import/export semantics that's is no longer possible in general, as @binji observed. I created #358 to eliminate these checks from static validation.
