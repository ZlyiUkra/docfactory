# WebAssembly spec issue #461: Invalid grammar for func_sig
# джерело: https://github.com/WebAssembly/spec/issues/461
# отримано: 2026-09-30

Issue #461, opened by cretz on 2017-04-14, closed (completed) on 2017-04-19.

On the interpreter README that has the sexpr syntax, `func_sig` says it can be a type reference OR a param/result set. However https://github.com/WebAssembly/spec/blob/6a01dab6d29b7c2b5dfd3bb3879bbd6ab76fd5dc/test/core/func_ptrs.wast#L18 says otherwise.

## Comment by binji, 2017-04-15

Good catch. You probably have already seen this, but the yacc-like syntax here is quite helpful for resolving these things:

```
...
LPAR FUNC bind_var_opt inline_export type_use func_fields RPAR
...
```

This makes it clear that the `type_use` (e.g. `(type 3)`) must come before the `func_fields` (e.g. `(param i32)`).
