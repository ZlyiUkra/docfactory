# WebAssembly spec issue #506: [interpreter] Unable to compile wast.js generated binary in current browsers
# джерело: https://github.com/WebAssembly/spec/issues/506
# отримано: 2026-09-30

Issue #506, opened by thelonious on 2017-06-13, closed (completed) on 2017-06-29.

I'm currently unable to create a new module from the binary generated by wast.js. I've verified this in  the following browsers:

- Brave 0.16.9
- Safari Technology Preview (Safari 11.0, WebKit 12604.1.23.0.4)
- Chrome 59.0.3071.86
- Firefox 53.0.3
- Opera 45.0.2552.888

For reference, I'm using this modified version of the sample code from the interpreter README.md

```
let source = '(module (func (export "f") (param i32 i32) (result i32) (i32.add (get_local 0) (get_local 1))))';
let binary = WebAssemblyText.encode(source);
let module = new WebAssembly.Module(binary);
let instance = new WebAssembly.Instance(module);

console.log("result = %d", instance.exports.f(3, 4));
```

All of the listed browsers complain about the version number. It is `0x0d` and should be `0x01`.

For testing purposes and out of curiosity, I changed wast.js, line 16902 to `u32(1)`. I was then able to run the test code in all browsers without issue. Of course, I could not convert the binary back to an s-expr since the expected version number had been changed.

I would file a pull request for this, but I don't know how the wast.js file is generated. I'm not sure what source file(s) would need to be changed. This also assumes there is no difference between the version 13 and version 1 file formats.
