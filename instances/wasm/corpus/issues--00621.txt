# WebAssembly spec issue #621: Wrong behavior of truncate for inexact float literals?
# джерело: https://github.com/WebAssembly/spec/issues/621
# отримано: 2026-09-30

Issue #621, opened by yblein on 2017-12-10, closed (completed) on 2017-12-10.

The following test looks suspicious:
https://github.com/WebAssembly/spec/blob/fb7e7e1e381ffc283c923a87fdfea5ebbd213737/test/core/conversions.wast#L70

The spec says that floats are rounded to nearest, therefore the inexact literal `f32.const 2147483648.0` should be rounded to the exact value `f32.const 2147483600.0` during parsing. And since `2147483600` is representable as a `i32`, I don't see why this test should cause a trap.

## Comment by yblein, 2017-12-10

Actually it seems that I'm mistaken, `2147483648.0` is representable as a `f32`.
