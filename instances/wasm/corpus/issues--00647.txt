# WebAssembly spec issue #647: Clarify signed/unsigned interpretation for ToJSValue with i32 arguments
# джерело: https://github.com/WebAssembly/spec/issues/647
# отримано: 2026-09-30

Issue #647, opened by maurobringolf on 2018-01-17, closed (completed) on 2018-02-19.

This is more of a question than an issue:
When calling an exported wasm function from JavaScript that returns an `i32`, is it guaranteed to be interpreted as signed i32 two's complement integer?

Is this specified somewhere? The only thing I could find was the **ToJSValue** algorithm which says:

> If w is of the form 𝗂𝟥𝟤.𝖼𝗈𝗇𝗌𝗍 i32, return the Number value for i32.

https://webassembly.github.io/spec/js-api/index.html#tojsvalue

If I understand it correctly, `i32` is not inherently signed or unsigned in general (depends on instruction, `i32.div_u` and `i32.div_s` for example. So maybe the sign interpretation of **ToJSValue** could be stated more clearly?

cc @ColinEberhardt @xtuc

## Comment by rossberg, 2018-01-17

In the Wasm abstract syntax, i32 is represented by its unsigned interpretation (see here). So this implies an unsigned conversion. However, I agree that this is not very obvious, and that we should include a note to this effect with ToJSValue (and perhaps link i32 to its definition).

## Comment by gahaas, 2018-01-17

In https://github.com/WebAssembly/design/blob/master/JS.md#tojsvalue it is clearly stated that i32 is interpreted as a signed integer.

## Comment by rossberg, 2018-01-17

@gahaas, indeed, so the current wording in the API spec is in fact incorrect. It needs to apply the signed function.
