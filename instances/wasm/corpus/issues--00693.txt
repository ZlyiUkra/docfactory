## Comment by rossberg, 2018-02-15

The ellipses here and elsewhere are simply a placeholder for whatever (well-bracketed) sequence of tokens is there, and that is transported to the RHS unchanged. That may include stuff that requires more expansion (like additional import/export clauses).

However, the key point to note is that a program only is well-formed if it ultimately expands into a token sequence that is well-formed according to the kernel grammar. In this case (and some others) that necessarily implies that any `memory` declaration must end in a memtype, because otherwise it could not be expanded into something well-formed. You can use that invariant to multiply out all expansions into a full grammar. For example, the reference interpreter implements the text format through an LR(1) grammar, including memory definitions.
