## Comment by eholk, 2018-04-10

Some comments based on my review:

The algorithmic sub-steps (such as here) look strange to me with the gray sidebar. Can we indent them instead? The gray bar makes me think they are block quotes or some other kind of notes. I like the way this one is formatted much better.

When talking about memory sizes, should we use a variable like `page_size` instead of writing out 64 Ki? example

The pseudo code in the Validation Algorithm section should use a code font. The PDF version seems to, but it's a normal sans-serif variable width font in the bikeshed version.

In the Name Section description, it says "the name section is a custom sections" when it should say "the name section is a custom section."

In Soundness, it says "every function invocation always evaluates to a result of the right type (if it does not trap)." This should mention the possibility of nontermination too. WebAssembly does not guarantee all programs terminate.

Similarly, I found it odd that host functions are also assumed to terminate, but since the execution of host functions is outside the theory this seems okay since it only specifies the conditions that must hold upon returning from a host function.

In the rule for Frames, the prose says t* is prepended to the locals variable, but the notation reads more like appending or replacing to me. Similarly in the label rule.

There is a broken reference in the note under Store Extension.

The Theorems section mentions resulttype in a couple of places, but it seems like this should instead be a reference to result type.
