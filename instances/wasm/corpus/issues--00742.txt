# WebAssembly spec issue #742: `div_s` execution semantics invalid?
# джерело: https://github.com/WebAssembly/spec/issues/742
# отримано: 2026-09-30

Issue #742, opened by ehildenb on 2018-03-06, closed (completed) on 2018-03-06.

The `div_s` execution semantics seem to lead to invalid behaviour (file https://github.com/WebAssembly/spec/blob/master/document/core/exec/numerics.rst).

Take for example, that `i = 32`, `i_1 = (2 ^ 31) + 15`, and `i_2 = 7`.
The following script (which can be piped into command-line calculator `bc`) demonstrates that we are asked to calculate `signed^{-1}` of a number that is not in the range of `signed` (and thus not in the domain of `signed^{-1}`, since `signed` is bijective).

bc-script.txt

I think the issue is in the last line, inside the call to `signed^{-1}`, the *unsigned* values `i_1` and `i_2` appear, where perhaps the *signed* values `j_1` and `j_2` should appear.
