# WebAssembly spec issue #806: Does WebAssembly.compileStreaming allow a Response as parameter?
# джерело: https://github.com/WebAssembly/spec/issues/806
# отримано: 2026-09-30

Issue #806, opened by gahaas on 2018-05-16, closed (completed) on 2018-05-22.

The spec defines the signature of `WebAssembly.compileStreaming` as `Promise<Module> compileStreaming(Promise<Response> source);`. In my understanding this means that the parameter has to be a `Promise`, it cannot be a `Response` directly. The not below the signature of `WebAssembly.compileStreaming`, however, says

> This algorithm accepts a Response object, or a promise for one ...

The design repo agrees with the note.

I think the spec and the note should match, so should the spec be updated or the note?

## Comment by lukewagner, 2018-05-16

You're right that the intended behavior is to accept `Response` objects and I think this is handled automatically for us by the definition of Web IDL `Promise` argument types (see also) which specify that a given JS argument value `v` is first `Promise.resolve`d.

## Comment by littledan, 2018-05-17

Yes, seems like the note should be changed.

Edit: Not sure what I was thinking here, @lukewagner explained above why the note was correct.

## Comment by gahaas, 2018-05-22

Thanks!

I was wondering what should happen if there is a `Response` object with a `then` function which does not return the `Response` object itself. However, I think the spec clearly says what should happen. I guess it is not possible to use `WebAssembly.compileStreaming` on such a `Response` object.

## Comment by littledan, 2018-06-24

@gahaas Yes, I agree with your analysis. Basically, Promises mean that, across the JS universe, the method named "then" should only be used for Promise-related purposes.
