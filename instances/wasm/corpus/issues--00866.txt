# WebAssembly spec issue #866: The branching analogy in the control instructions subsection of the "Structure" section could use a little more context.
# джерело: https://github.com/WebAssembly/spec/issues/866
# отримано: 2026-09-30

Issue #866, opened by dead-claudia on 2018-08-27, closed (completed) on 2019-01-25. Labels: editorial.

In this section, it has an analogy about how the control flow operators work:

> This enforces *structured control flow*. Intuitively, a branch targeting a 𝖻𝗅𝗈𝖼𝗄 or 𝗂𝖿 behaves like a 𝖻𝗋𝖾𝖺𝗄 statement, while a branch targeting a 𝗅𝗈𝗈𝗉 behaves like a 𝖼𝗈𝗇𝗍𝗂𝗇𝗎𝖾 statement.

I feel that the `break` analogy could use a little more context, so it's clearer you're referring to C-like languages, something like this (emphasis mine):

> This enforces *structured control flow*. Intuitively, a branch targeting a 𝖻𝗅𝗈𝖼𝗄 or 𝗂𝖿 behaves like a 𝖻𝗋𝖾𝖺𝗄 statement **in most C-like languages**, while a branch targeting a 𝗅𝗈𝗈𝗉 behaves like a 𝖼𝗈𝗇𝗍𝗂𝗇𝗎𝖾 statement.

This could help someone who's not reading as closely (like what I did earlier today) and doesn't make the initial implicit connection. There are several languages that lack at least some of these, including Rust (which only has `break`), OCaml (which uses exceptions and `return` within iterators instead), and Haskell (which uses recursive calls and direct iteration instead).
