# WebAssembly spec issue #878: Is TableDescriptor's TableKind really an enum?
# джерело: https://github.com/WebAssembly/spec/issues/878
# отримано: 2026-09-30

Issue #878, opened by lars-t-hansen on 2018-09-17, closed (completed) on 2018-10-15.

The background here is a bug that was filed against Firefox.  The TableDescriptor's TableKind (ie the value of the "element" property of the descriptor) is typed as a WebIDL "enum", which means that it shall first be converted to string by ToString and then checked against one of the known string enumeration values.  This strikes me as not necessarily forward-compatible, as we may wish in the future to have strongly typed tables where the value of the element property is itself some kind of type descriptor or reference into the module's type table to express (ref T) or complex function types.

The reftypes proposal already suggests adding "anyref" and "nullref" types, though these are expressible in the enumeration.  At the very end of the proposal, though, it also speculates about some unification of table types and value types.  See here.

If we go for an "enum" solution here a future expansion may break existing content as the ToString operation cannot be applied blindly to a type that expresses eg a reference into the module's type table.

A lighter-weight solution would be to recognize the string "anyfunc" but to reject every other type at this time.  Don't know what this would look like in WebIDL, but it feels less restrictive.
