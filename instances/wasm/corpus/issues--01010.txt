# WebAssembly spec issue #1010: [spec] name section: duplicate subsections allowed
# джерело: https://github.com/WebAssembly/spec/issues/1010
# отримано: 2026-09-30

Issue #1010, opened by nomeata on 2019-05-06, closed (completed) on 2019-05-07.

The current spec for the `name` section seems to allow multiple subsections within the same `name` section.

This seems to be an oversight, given that the spec is clear that there is at most one `name` section, and that within each name map, keys have to be unique, so it seems odd that one would be allowed to have, say, multiple module name subsections, or multiple function name subsections with non-disjoint keys.

I suggest to add the sentence “Each kind of subsection should appear at most once” or something similar to that end to the spec. Or, if duplicate subsections are intended, clarify their semantics (first wins, or last wins, and how to merge name maps).
