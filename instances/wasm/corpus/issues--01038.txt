# WebAssembly spec issue #1038: How to reconcile imported table with table section?
# джерело: https://github.com/WebAssembly/spec/issues/1038
# отримано: 2026-09-30

Issue #1038, opened by RyanLamansky on 2019-06-30, closed (completed) on 2019-06-30.

If an assembly requests a table import, but also has a table section internally, is this an error condition or are they combined in some way?

## Comment by rossberg, 2019-06-30

It works the same way as with functions or globals: the imported tables come first in the index space, then the internal definitions.

## Comment by RyanLamansky, 2019-06-30

But with 0 being the only legal table index, does that mean the extra table is inaccessible?

## Comment by rossberg, 2019-06-30

Sorry, I misinterpreted your question, and thought you were talking about the multi table extension.

But nevertheless, the answer is yes: in the MVP, there is simply a check that 0 is the maximum resulting table index.

## Comment by RyanLamansky, 2019-06-30

Thanks; I'm not deeply involved in the spec development so it didn't (initially) occur to me that multiple tables may be supported in upcoming releases, thus making my question unclear 🙄

So, for the MVP runtime I'm building, I'll accept multiple function tables but only the first will be usable.
