# WebAssembly spec issue #1060: When should resources be exhausted?
# джерело: https://github.com/WebAssembly/spec/issues/1060
# отримано: 2026-09-30

Issue #1060, opened by hjorthjort on 2019-08-28, closed (completed) on 2019-08-29.

The core tests (for example `fac.wast`) test for resource exhaustion with `assert_exhaustion`.

I can't find any mention of an absolute number that the call stack can't exceed in the spec or elsewhere. What's the intended behavior of `assert_exhaustion` -- that a program may either fail or return with a resource exhaustion error?

## Comment by sunfishcode, 2019-08-29

There is no specific number specified. The purpose of `assert_exhaustion` tests is only to ensure that implementations have a limit. Implementations are not permitted to perform implicit tail-call optimization of recursive functions in a way that would allow them to recurse infinitely without trapping.

The `assert_exhaustion` test in `fac.wast` may be overzealous, because in theory an implementation could have a stack large enough to do that computation while still being finite. The test in call.wast is a better example; see this comment.
