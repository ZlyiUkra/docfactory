# WebAssembly spec issue #1068: Documentation for name custom section is wrong
# джерело: https://github.com/WebAssembly/spec/issues/1068
# отримано: 2026-09-30

Issue #1068, opened by kg on 2019-09-13, closed (completed) on 2019-09-13.

The documentation for the name custom section is wrong (http://webassembly.github.io/spec/core/appendix/custom.html#name-section). It says the map assigns function names to function indices, but the indices are not function indices. From looking at the table, it appears to begin with the names of all the imports, and possibly follow with the names of all the exports? So offsetting the indices by some unknown value is required to actually map names to functions.

## Comment by kg, 2019-09-13

It looks like the indices in the function name map are ```len(from imports where kind == Function) + func_index```

## Comment by tlively, 2019-09-13

This is working as intended. The function index space always starts with the imported functions followed by the functions in the function/code sections, which allows code to refer to imported and defined functions uniformly.

This should be consistent throughout the documentation, and if there are any exceptions those would be bugs.

## Comment by kg, 2019-09-13

That makes sense, but where is that specified? I can't find this specified anywhere on the website and it doesn't make any sense for funcidx to not be a 0-based index into the function section.

## Comment by tlively, 2019-09-13

See https://webassembly.github.io/spec/core/syntax/modules.html#indices.

> The index space for functions, tables, memories and globals includes respective imports declared in the same module. The indices of these imports precede the indices of other definitions in the same index space.
