# WebAssembly spec issue #1072: [spec] validation rule for function is inaccurate
# джерело: https://github.com/WebAssembly/spec/issues/1072
# отримано: 2026-09-30

Issue #1072, opened by Huxpro on 2019-09-16, closed (completed) on 2022-08-04.

The formalization of Validation - Module - Function is incorrect, or at least inconsistent with the prose spec and reference interpreter.

In the premise of the validation rule, the `expr` is checked against the context of the original `C` with new locals, labels, and return elements **prepended** to each field, according to the Validation - Convention.

While the prose, stated that `locals`, `labels` and `return` are **set** to be the new element.
Also the reference interpreter, state an OCaml record functional update that replaces the field content:

```ocaml
let check_func (c : context) (f : func) =
  let {ftype; locals; body} = f.it in
  let FuncType (ins, out) = type_ c ftype in
  let c' = {c with locals = ins @ locals; results = out; labels = [out]} in
  check_block c' body out f.at
```

This situation, is different from other cases, e.g. `if`, where the original field content is con-ed:

```ocaml
  | If (ts, es1, es2) ->
    check_arity (List.length ts) e.at;
    check_block {c with labels = ts :: c.labels} es1 ts e.at;
    check_block {c with labels = ts :: c.labels} es2 ts e.at;
    [I32Type] --> ts
```

Although at least for the current version of web assembly, function declarations may only occur from the top level of modules, plus we do not have nested functions nor nested modules, we may safely assert these 3 fields (local, labels, return) would always be empty during the precondition of validating functions. Nonetheless, I'd argue having a distinguishment and being consistent and more accurate could be nicer (for all purposes including reading, in-paper formalization, mechanized formalization, proofs...)

I'd propose changing it to either following the record update from Structure - Convention

```
C, with locals = ... with labels = ... with return =
```

or extening the `with` notation with an OCaml-like batch-able update:

```
C, with locals = ...; labels = ...; return =
```

At very least, the `return` field is an optional `resulttype` that should not be **prepended** in any way. An alternative would be declaring the overloads of the `C, field A*` notation for option, but I guess that would be even more confusing.  A tentative PR of only this change is here https://github.com/WebAssembly/spec/pull/1070.
