# WebAssembly spec issue #1078: [question] about incompleteness and stack-polymorphic
# джерело: https://github.com/WebAssembly/spec/issues/1078
# отримано: 2026-09-30

Issue #1078, opened by Huxpro on 2019-09-26, closed (completed) on 2019-09-26.

This question is merely a question, out of curiosity. Say,

```wat
(func $stkpoly (param) (result i32)
  i32.const 1
  block (result i32)
    i32.const 10
    i32.const 100
    br 0
    i32.add  ;; vs. i64.add
  end
  i32.add
```

Using `i64.add` here is indeed, _safe_, but could not type check.

This reminds me of type checking `if e i32 i64` where `e` is undecidable so we have to lose the completeness and perform a safe approximation...is this also the case here?

My first intuition is like, do we need to care about instructions after the `br`? To me the type safety of the stack's been ensured by "keeping only as many `valtype` as the arity of `blocktype` and unwinding anything else"?

My second thought is that "okay I am not sure how to write the typing rule for the content of `block` (or other structurals) then...how do you know there is a `br` if you don't get there"? ...so maybe unconstraining this is indeed as hard as the halting problem?

## Comment by rossberg, 2019-09-26

See the design rationale for some explanation. A simple typing algorithm is sketched in the Appendix of the spec.

## Comment by Huxpro, 2019-09-26

@rossberg Ah. I think "Allowing but not type-checking unreachable code would break decomposability and requires the spec to provide a syntactic definition of reachability" answered my question perfectly. Thanks!
