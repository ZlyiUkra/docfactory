# WebAssembly spec issue #1110: [js‑api] Should methods be made non‑enumerable to match other ECMAScript built‑ins?
# джерело: https://github.com/WebAssembly/spec/issues/1110
# отримано: 2026-09-30

Issue #1110, opened by ExE-Boss on 2019-12-11, closed (completed) on 2022-08-04.

Currently WebAssembly is specified using WebIDL, which makes all methods enumerable, which contrasts with ECMAScript classes and built‑ins, which only have enumerable data properties.

Since WebAssembly is meant to be an ECMAScript platform feature, I find it surprising that its methods are enumerable.

<https://github.com/heycam/webidl/pull/825> provides the `[NonEnumerableMethods]` extended attribute, which makes methods non‑enumerable by default, which matches what ECMAScript does.
