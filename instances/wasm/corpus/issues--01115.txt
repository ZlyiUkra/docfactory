# WebAssembly spec issue #1115: Security feature: Signed modules
# джерело: https://github.com/WebAssembly/spec/issues/1115
# отримано: 2026-09-30

Issue #1115, opened by abdulla-tuychi on 2020-01-08, closed (completed) on 2022-08-04.

According to the report below half of the modules are used for malicious purposes.
https://www.zdnet.com/article/half-of-the-websites-using-webassembly-use-it-for-malicious-purposes/

Signatures are required to make modules safer. Browsers should check and warn users when the modules are not signed.

## Comment by RyanLamansky, 2020-01-08

I expect this will get as much traction as requiring signed JavaScript files, and there are far more websites that use JavaScript maliciously than WebAssembly.

## Comment by Pauan, 2020-01-09

To clarify, Wasm cannot do anything that JS itself can't do. So all of the malicious Wasm exploits can also be done in JS (or ASM.js). The only thing that Wasm does is *be really fast*.

In the future Wasm may get more capabilities, but the security of those new capabilities will be taken very seriously.

## Comment by rossberg, 2020-01-09

> In the future Wasm may get more capabilities,

Unfortunate use of words. ;)  It is very important design constraint that Wasm does not have any "capabilities" in the technical, security-related sense of the word. This won't change with any future features. All it can do is compute.

## Comment by Pauan, 2020-01-09
