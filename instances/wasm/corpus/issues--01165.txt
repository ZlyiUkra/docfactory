# WebAssembly spec issue #1165: Why do we use KaTeX for 1-page HTML but MathJax for multi-page?
# джерело: https://github.com/WebAssembly/spec/issues/1165
# отримано: 2026-09-30

Issue #1165, opened by ngzhian on 2020-03-28, closed (completed) on 2022-08-04.

Can we use KaTeX for both?

## Comment by binji, 2020-03-28

The WG discussed this recently. The main reason we use KaTeX currently is to avoid having JS in the spec document. But to do so, we introduce a lot of complexity into the doc process. We think we can instead use the multi-page document (with MathJax) as a basis for the official TR document, and remove the single-page document. Then we can use the PDF as a JS-free version of the same document.

## Comment by ngzhian, 2020-03-30

Got it. Another question: will it be a good idea to KaTeX-fy our multipage html docs? If we do that, build times are longer, but pages will load/be interactive faster!

## Comment by binji, 2020-03-30

I think that would be nice, but if we do so, I'd like it to be incorporated in a more principled way, like having a Sphinx extension to do it (like the upstream MathJax one). Another concern is that KaTeX is not as fully-featured as MathJax, so we've often had to work-around limitations by replacing certain Latex constructs with near-equivalents (IIRC the python script does this in a few places). We may want to push upstream KaTeX to do this work before we do more work on our end.

I should also mention that part of the reason for this proposed change is to reduce the amount of work we'd have to do to produce a wasm spec document, so I'm a little hesitant to make more work for ourselves here :)

## Comment by rossberg, 2020-03-30

What @binji said. Our KaTeX support mostly is a gross and brittle hack to create a single static doc. Various aspects of the resulting type setting are suboptimal, including wrong fonts, spacing, alignment etc.

## Comment by rossberg, 2022-08-04

Closing, since we now use MathJax for the W3C draft as well.
