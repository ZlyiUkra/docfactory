# WebAssembly spec issue #1189: [spec] Validation: block vs loop
# джерело: https://github.com/WebAssembly/spec/issues/1189
# отримано: 2026-09-30

Issue #1189, opened by philipahlberg on 2020-05-02, closed (completed) on 2020-05-04.

In the validation judgement for block, `[t2*]` (the output type of the block) is prepended to the `labels` vector in the context, while in the judgement for loop, it's `[t1*]` (the input type of the loop). Is this intended?

## Comment by conrad-watt, 2020-05-02

It is intended. The purpose of prepending the type to the `labels` vector is to ensure that a `br` instruction targetting that label has that type as its input type.

Targetting block with a br causes execution to jump to the end of the block, and so the stack must have the block's output type at the point the br is executed (the input type of the br must be the output type of the block).

Targetting loop with a br causes execution to jump to the _start_ of the loop body, so the stack must have the loop's _input_ type at the point the br is executed (the input type of the br must be the _input_ type of the loop, to match the start of the loop body).
