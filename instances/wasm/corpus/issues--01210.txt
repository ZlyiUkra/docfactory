# WebAssembly spec issue #1210: Inconsistency between table limit validation and possible encodings
# джерело: https://github.com/WebAssembly/spec/issues/1210
# отримано: 2026-09-30

Issue #1210, opened by eqrion on 2020-06-12, closed (completed) on 2020-06-15.

Unsure if this an issue, but it seemed odd to me.

1. Limits are defined as valid within an inclusive range
2. Table limits use the range [`[0, 2^32]`](https://webassembly.github.io/spec/core/valid/types.html#table-types)
3. Limit binary encoding and text parsing use `u32` for an effective range of [`[0, 2^32 - 1]`](https://webassembly.github.io/spec/core/text/values.html#integers)

This implies that there's a valid module that cannot be encoded or decoded. This isn't an issue in practice, as the web embedding limits prevent tables of this size.

I'm curious if this was intentional, or has a future use? If not, it may make sense to lower the table limit validation to [0, 2^32-1].

(This isn't an issue for memory limits because they are restricted to [0, 2^16].)
