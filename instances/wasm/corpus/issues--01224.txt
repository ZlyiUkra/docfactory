# WebAssembly spec issue #1224: Truncating slightly less than INT32_MIN?
# джерело: https://github.com/WebAssembly/spec/issues/1224
# отримано: 2026-09-30

Issue #1224, opened by kripken on 2020-07-21, closed (completed) on 2020-07-23.

```wat
(module
 (func (export "trunc")
  (drop
   (i32.trunc_f64_s
    (f64.const -2147483648.1)
   )
  )
 )
)
(assert_trap (invoke "trunc") "integer overflow")
```
This behaves differently in different VMs: The spec interpreter, JavaScriptCore, wabt and binaryen trap (that is, the testcase passes as it throws an error when doing the truncation), while V8 and SpiderMonkey do not trap.

To run it: `d8 aa.js -- aa.wasm` etc., or run the above wast file in something that can run spec testcases.

## Comment by binji, 2020-07-21

Hm, this looks like it should not trap to me, according to the spec. The definition of truncation is to drop the fractional parts: https://webassembly.github.io/spec/core/exec/numerics.html#aux-trunc

And the truncation instruction itself is defined here as `cvtop`: https://webassembly.github.io/spec/core/exec/instructions.html#t-2-mathsf-xref-syntax-instructions-syntax-cvtop-mathit-cvtop-mathsf-t-1-mathsf-xref-syntax-instructions-syntax-sx-mathit-sx

Which forwards to this numeric function: https://webassembly.github.io/spec/core/exec/numerics.html#xref-exec-numerics-op-trunc-s-mathrm-trunc-mathsf-s-m-n-z

In particular, truncation is defined if -2N - 1 < trunc(q) < 2N-1. For i32 this means the range is -2147483649 < trunc(q) < 2147483647.

So -2147483648.1 should be truncated to -2147483648, which should be valid.

