# WebAssembly spec issue #1229: About the maximum memory size limit
# джерело: https://github.com/WebAssembly/spec/issues/1229
# отримано: 2026-09-30

Issue #1229, opened by gahaas on 2020-07-29, closed (completed) on 2020-07-29.

Hi,

There is a core spec test that requires that the memory size of a module is at most 65536 pages. I know that this limit makes sense, but it's nowhere written. It is only written in the js-api spec, where it is defined as a dynamic limit. The difference between a core spec limit and a dynamic limit is that exceeding the core spec causes a validation error, whereas the dynamic limit only causes an error at instantiation or at runtime.

I think it would be best to add the limit to the core spec, and remove the dynamic limit from the js-api, as it would not be needed anymore. Wdyt?

Cheers, Andreas
