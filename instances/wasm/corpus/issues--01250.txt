# WebAssembly spec issue #1250: [test] Missing test cases that partially-oob stores do not store partial data
# джерело: https://github.com/WebAssembly/spec/issues/1250
# отримано: 2026-09-30

Issue #1250, opened by lars-t-hansen on 2020-09-25, closed (completed) on 2021-10-27.

Recently I ran across a bug in our ARM64 implementation where it turns out we perform partial stores of data at the end of wasm memory when an unaligned (but not hinted as such) store overlaps the end of the memory.  The ARMv8 ARM states that an unaligned store may either trap, *or* it may store byte-at-a-time into memory and trap when it gets to an inaccessible address, depending on the write mode and the setting of system flags.  Vector stores are always byte-at-a-time; other stores are not, but SCTLR.A=0 makes them so if they are not aligned.  (This is explicit in the semantics for aarch64; for aarch32 it's buried a little deeper but seems to also be the case.)  A naive use of STR to store data under these circumstances will store some bytes at the end of memory before trapping, if the store is unaligned and overlaps the end of memory.  Wasm semantics forbid this: an OOB trap must happen before any data are written.  Android on the Pixel (at least the Pixel we use for testing) has SCTLR.A==0, I would expect this to be the case for Android generally.

We appear to have no test cases for this part of the semantics.
