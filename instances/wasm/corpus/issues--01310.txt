# WebAssembly spec issue #1310: Incorrect condition for text encoding of call_indirect
# джерело: https://github.com/WebAssembly/spec/issues/1310
# отримано: 2026-09-30

Issue #1310, opened by SpecLad on 2021-04-10, closed (completed) on 2021-04-21.

In section 6.5.2 the encoding for `call_indirect` is given as follows:

> `‘call_indirect’`  _x_:`tableidx`  _y_,_I′_:`typeuse`_I_​​ ⇒​ `call_indirect` _x_ _y_ ​(if _I′_={})

With a note saying:

> The side condition stating that the identifier context I′ must be empty in the rule for `call_indirect` enforces that no identifier can be bound in any `param` declaration appearing in the type annotation.

However, according to the definition of `typeuse`, it will always produce a context whose **locals** component contains the same amount of elements as the number of parameters in the referenced function type. Therefore, the only way I' can be empty (i.e. { **locals** ϵ }) is if the function type has no parameters. I assume no such restriction is meant to be impled by the encoding rule.

It seems to be like the condition should actually be "if _I′_={ **locals** (ϵ)\* }", which permits all function types, but not parameter identifiers.
