# WebAssembly spec issue #1313: Identifiers can seemingly be replaced with fresh identifiers
# джерело: https://github.com/WebAssembly/spec/issues/1313
# отримано: 2026-09-30

Issue #1313, opened by SpecLad on 2021-04-17, closed (completed) on 2021-05-10.

In 6.6.5.1, the condition on the rewrite rule is (if `id`′ = `id`? !​= ϵ ∨ `id`′ fresh), which suggests that as long as `id`′ is a fresh identifier, the rule can be applied. So even if the declaration already has an identifier, that identifier can be replaced with a fresh one.

That seems wrong and unintentional, as it would break any references to the original identifier. The right side of the condition should probably be changed to something like (`id`′ fresh ∧ `id`? = ϵ).

Same thing applies to the many similar rewrite rules for other types of declarations.

## Comment by rossberg, 2021-04-21

Ah yes, you are right, the right side needs to negate the left to be accurate. Please see #1315 for a fix, I reformulated the condition slightly to make it more symmetric.
