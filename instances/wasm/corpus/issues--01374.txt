# WebAssembly spec issue #1374: Validation algorithm in append doesn't handle unreachable `br_table` correctly
# джерело: https://github.com/WebAssembly/spec/issues/1374
# отримано: 2026-09-30

Issue #1374, opened by alexcrichton on 2021-10-13, closed (completed) on 2021-10-13.

With the merging of the reference types and bulk memory proposals the validation algorithm provided in the appendix has been updated, notably around `br_table` I believe to handle possible subtyping. Specifically the algorithm currently states that to validate `br_table` it suffices to do:

```
    case (br_table n* m)
      pop_val(I32)
      error_if(ctrls.size() < m)
      let arity = label_types(ctrls[m]).size()
      foreach (n in n*)
        error_if(ctrls.size() < n)
        error_if(label_types(ctrls[n]).size() =/= arity)
        push_vals(pop_vals(label_types(ctrls[n])))
      pop_vals(label_types(ctrls[m]))
      unreachable()
```

After implementing this, however, it fails the spec test case added for this algorithmic adjustment, notably:

```wasm
(module
  (func (export "meet-bottom")
    (block (result f64)
      (block (result f32)
        (unreachable)
        (br_table 0 1 1 (i32.const 1))
      )
      (drop)
      (f64.const 0)
    )
    (drop)
  )
)
```

I believe the reason for this is that the `push_vals(pop_vals(...))` for each label means that, when the `br_table` is `unreachable`, `pop_vals` will return the values of the label type that you're jumping to. This means that `push_vals` will push the precise types of the label itself, meaning that if the next label has differnet types (such as in the test case above), this handling of `br_table` produces an error when it should actually accept the code.
