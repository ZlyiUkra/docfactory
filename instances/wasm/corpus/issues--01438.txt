## Comment by tlively, 2022-03-30

The `81 80 80 80 00` is a 5-byte LEB128 encoding of 1. Some producers like clang/wasm-ld will use a 5-byte encoding for function indices to allow the linker to patch in arbitrary indices into those locations once it has assigned indices to all functions in the program. If clang only used one byte there but the linker then happened to assign that called function to a large index, the linker would have to move more bytes around to make room for the larger index, which is something linkers typically try to avoid.

## Comment by sbc100, 2022-03-30

Running the binary through `wasm-opt` will remove this padding.    You can also pass `--compress-relocations` to the linker (`-Wl,--compress-relocations` if run via clang), but be aware that this compression will invalidate the DWARF debug information.
