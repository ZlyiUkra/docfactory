# WebAssembly spec issue #1503: [Text] Parentheses optional around global init?
# джерело: https://github.com/WebAssembly/spec/issues/1503
# отримано: 2026-09-30

Issue #1503, opened by tlively on 2022-07-11, closed (completed) on 2022-07-11.

The text format for globals uses `e:expr` for the initializer and `expr` is defined as `(in:instr)*`, which does not include any literal parens, so it seems that this would be valid:

```
(global $foo i32 i32.const 0)
```

And that this would be the same but using the folded form of the instruction:

```
(global $foo i32 (i32.const 0))
```

But I've only ever seen the latter format, so I want to verify that I'm reading this correctly and that it is intentional that the parentheses here are optional.

## Comment by rossberg, 2022-07-11

I don't remember if this was intentional. It probably came about because the global grammar predates the "flat" unparenthesised instruction format, and we may or may not have noticed the implication on globals when we introduced it. FWIW, the interpreter allows the unparenthesised form.

One could argue that this is consistent with func, given that a global is like a function without parameters.

One could similarly argue that a global initialiser is more like an element expression, in which case `( instr )` should just be shorthand for some `(init instr*)`, and the latter form would be required if there is more than one instruction. But that would require introducing the `init` keyword.

## Comment by redianthus, 2022-07-11

FYI I tried with my own interpreter and it also allows the unparenthesised form.
