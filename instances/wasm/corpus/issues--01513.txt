i'm trying to implement a runtime in C.
because `funcref` values can be freely produced by instances (either with elements or `ref.func`)

You'll definitely need to do reference counting, but `funcref` can't form cycles with other `funcref` values, so you shouldn't need a full GC.

## Comment by rossberg, 2022-08-02

No, that's correct. It has been the case since Wasm 1.0 that you can create a cycle between module instances by initialising table entries in one with functions from another (and with Wasm 2.0, also through globals instead of table). If an engine wants to reliably reclaim instances dynamically, then it has to implement some memory management policy that can detect such cycles. Since all the respective data structures are under control of the engine, that may be somewhat simpler than a typical, fine-grained GC.

I don't remember if we had any specific discussion of this, but perhaps the assumption was that most non-Web, AOT-style stand-alone engines are more "static", and not interested in reclaiming modules until the program terminates. That may not actually be true. In any case, the problem seems unavoidable.

(FWIW, engines like V8 have fairly sophisticated approaches involving weak pointers and stuff like that to deal with the cycles between e.g. instances and their functions, IIRC. I am not sure to what extent they actually rely on the global GC for this.)
