# WebAssembly spec issue #1854: wasm-core-2 Spec 5.5.12. Element Section decoding funcref/func types do not match elem.wast or 3.0 Spec
# джерело: https://github.com/WebAssembly/spec/issues/1854
# отримано: 2026-09-30

Issue #1854, opened by kelnishi on 2024-12-09, closed (completed) on 2024-12-09.

When decoding an element section according to 5.5.12. Element Section, the segment type is incorrectly listed as _func_ `(ref func)` for case 4. This is covered under **elem.wast** and should be  `(ref null func)` like in the 3.0 draft spec. Posted versions of the core 2.0 spec also have a similar discrepancy where both decode case 0 and case 4 are listed as _funcref_ `(ref null func)`. According to **elem.wast** testing, the types of case 0 and case 4 differ and should be `(ref func)` and `(ref null func)`, respectively.

## Comment by rossberg, 2024-12-09

The GC proposal has been merged into the main repo's Wasm 3.0 branch, so the gc repo generally isn't updated with upstream changes anymore. It is correct in the Wasm 3.0 draft.

## Comment by rossberg, 2024-12-09

As for the 2.0 spec, that is correct as is, since non-nullable references do not exist in 2.0 yet. The change in 3.0 (and according tests) is a backwards-compatible refinement.
