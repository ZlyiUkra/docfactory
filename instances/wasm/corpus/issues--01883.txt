# WebAssembly spec issue #1883: [spec] Issues related to the helper functions `pack` and `unpack`
# джерело: https://github.com/WebAssembly/spec/issues/1883
# отримано: 2026-09-30

Issue #1883, opened by ShinWonho on 2025-03-10, closed (completed) on 2025-03-11.

I noticed that there are two issues related to `pack` and `unpack` helper functions.

### Duplicate definitions for `unpack`

The below `unpack` is defined in syntax/convention, which unpacks storage types into value types.

However, there is another `unpack` defined in execution/convention, which unpacks field value into value.

Both are used during execution (e.g. `struct.new_default` for the former and `struct.get` for the latter).
It might be distinguishable by its usage, but I'd like to conform whether this is intentional.

### Incorrect argument for `pack` and `unpack`

`pack` and two `unpack`s all take storage type as an argument.
However, they take field type as an argument.

The meaning could be inferred easily, but I'd like to conform whether this is intentional.

## Comment by rossberg, 2025-03-10

Yes, the overloading of the function name was intentional. However, what's missing from the doc is the text or definition that lifts them to field types.
