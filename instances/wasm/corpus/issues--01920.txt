# WebAssembly spec issue #1920: Validation reference algorithm `push_ctrl` mistakenly pushes parameters too
# джерело: https://github.com/WebAssembly/spec/issues/1920
# отримано: 2026-09-30

Issue #1920, opened by Swiftb0y on 2025-06-14, closed (completed) on 2025-06-16.

The validation algorithm from the appendix contains a (afaict superflous) `push_vals(in)`:

https://github.com/WebAssembly/spec/blob/abc8d16dcb4b36f818af9ee2fa9b1bf0b50503cb/document/core/appendix/algorithm.rst?plain=1#L112-L115

This does not match the prose description following:

https://github.com/WebAssembly/spec/blob/abc8d16dcb4b36f818af9ee2fa9b1bf0b50503cb/document/core/appendix/algorithm.rst?plain=1#L132-L133

Based on my personal understanding this would mean that during execution the functions parameters are already on the stack. This also conflicts with the reduction of invoke:
https://github.com/WebAssembly/spec/blob/abc8d16dcb4b36f818af9ee2fa9b1bf0b50503cb/document/core/exec/instructions.rst?plain=1#L2973-L3011

Am I correct in the assessment that the `push_vals(in)` in the reference algorithm is simply incorrect and should be removed? Thank you.

## Comment by rossberg, 2025-06-16

The control frames appearing in the pseudo code represent blocks, not function calls. As such, the block's parameters (if any) are pushed to the stack when entering a block. That is consistent with the execution rules for blocks, which do push their operands.

(Admittedly, the pushing of block parameters was somewhat implicit in the current wording, by making the values part of the block instruction sequence to be entered, which is not quite in line with the conventions used elsewhere in the prose. I just pushed a change that makes them more explicit.)

Thank you. I've looked at my implementation again and mistakenly used `push_ctrl` in the validation of functions. This is the source of the confusion. Sorry for the noise.
