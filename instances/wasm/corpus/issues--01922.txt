Ah, yes, the CDDL autolink syntax was added in version 5.2.0, released at the end of May.  If you're not using cddl and have conflicting usage of that syntax, you can turn that autolink syntax off with `Markup Shorthands: cddl off`.

## Comment by tabatkins, 2025-06-23

Actually the answer is yes to both of those questions.

* You can turn off any inline link shorthands you don't want with the `Markup Shorthands` metadata (as I suggested above for the cddl category specifically, but there are a bunch more categories you can turn off if you don't want them; I suspect you can remove nearly all of them for wasm)
* There are two ways to mark an element as "opaque" so it won't process any of the markup shorthands: `Opaque Elements` to list custom element names that shouldn't process anything in their contents, or adding the `bs-opaque` boolean attribute (which, I now realize, isn't documented, sorry about that...) to an element for a one-off skip of their contents. `pre`/`xmp`/`script`/`style` are all opaque by default in HTML. And then you can opt a particular shorthand back in to being processed within an opaque element by wrapping it in an `<l>` element.

The only inline thing beyond basic HTML you *can't* turn off is Markdown code spans (`` `foo` ``). That's kinda a chicken-and-egg thing, since they can contain markup themselves which would change the document's meaning, up to potentially changing what metadata is recognized.

## Comment by tabatkins, 2025-06-24

Heh, the *intention* is that it only be used for HTML custom elements (aka author-defined tag names with a dash in them), but yes, it works with any tag name at all. If you set `Opaque Elements: div, span` it will turn off autolink processing within the contents of any div or span in the document.
