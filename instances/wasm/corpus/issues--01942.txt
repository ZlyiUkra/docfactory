# WebAssembly spec issue #1942: Why catch can't refer to try_table's label
# джерело: https://github.com/WebAssembly/spec/issues/1942
# отримано: 2026-09-30

Issue #1942, opened by 4y8 on 2025-06-25, closed (completed) on 2025-06-25.

This might not be the right place to ask. I apologise in advance for the inconvenience if this is not the case.

In the verification rule of `try_table`, the catch clauses do not have access to the label of `try_table`. The following kind of code is then impossible:
```wasm
(try_table $l
   (catch $x $l)
   ...)
```
However, it can be done by enclosing the try_table in a block (at the cost on an extra instruction):
```wasm
(block $l
   (try_table
      (catch $x $l)
      ...))
```
Is there any particular reason for this choice ? The first form seemed quite natural to me as I tried to write code using `try_table` by hand.

## Comment by rossberg, 2025-06-25

Yeah, this is a frequent question. See WebAssembly/exception-handling#345 for a recent answer. I would phrase it somewhat differently by saying that the handler list is part of the block delimiter, not the block body, so the block label is not in scope yet. That way, block bodies are treated uniformly for all blockish instructions.
