# WebAssembly spec issue #1966: [gc proposal] A typo in the `heaptype` production in the Binary Format / Types section
# джерело: https://github.com/WebAssembly/spec/issues/1966
# отримано: 2026-09-30

Issue #1966, opened by ast-hugger on 2025-09-11, closed (completed) on 2025-09-14.

This is an apparent typo in the GC Proposal repo, but the repo is now archived so I'm reporting it here.

The last alternative of the `heaptype` production in https://webassembly.github.io/gc/core/binary/types.html#binary-heaptype says `x:s33`. That is probably meant to be `s32`.

## Comment by tlively, 2025-09-11

No, this is intentionally an `s33`. This allows it to encode the full range of unsigned 32-bit type indices as well as the negative numbers used to identify abstract heap types. If it were an `s32` it would not be able to encode type indices greater than or equal to 2^31 and if it were a `u32` it would not be able to encode abstract heap types.
