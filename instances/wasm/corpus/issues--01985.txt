# WebAssembly spec issue #1985: Incorrect definition of blocktype
# джерело: https://github.com/WebAssembly/spec/issues/1985
# отримано: 2026-09-30

Issue #1985, opened by tlively on 2025-09-25, closed (completed) on 2025-09-25.

In the Wasm 3.0 spec, `blocktype` is defined as being an optional `valtype` or a `funcidx`(!). The second option should be a `typeidx` (or `typeuse`, for consistency with the text format). How did this get through all the SpecTec validation and the meta-interpreter?

## Comment by rossberg, 2025-09-25

Oops, thanks! Fixed now.

It went unnoticed because both funcidx and typeidx are just synonyms for u32, so semantically it didn't matter. The type system doesn't help in this case, as it's just misleading naming.
