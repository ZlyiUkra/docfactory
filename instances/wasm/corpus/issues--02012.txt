# WebAssembly spec issue #2012: [test] incorrect assertion in `align.wast` (`wg-2.0`)

# отримано: 2026-09-30

Issue #2012, opened by agis on 2025-10-13, closed (not_planned) on 2025-10-16.

Hello! I'm writing a decoder and while running this repository's test against it to validate spec conformance, I noticed a failure in the following test case:

https://github.com/WebAssembly/spec/blob/fffc6e12fa454e475455a7b58d3b5dc343980c10/test/core/align.wast#L890-L907

If I understand correctly, validating the alignment for `i32.load` instructions is part of the Validation step (Section 3.3.7), not the Decoding step. Therefore, shouldn't this actually be `assert_invalid` as opposed to `assert_malformed`?

I noticed that in `main` this is changed to be `assert_invalid` indeed, but I'm unsure if the reason is what I described above. However, since I'm initially targeting v2.0, I'm executing against the `wg-2.0` branch.

P.S. I could submit a fix if my understanding is correct.

## Comment by rossberg, 2025-10-14

Yeah, the distinction between decoding time and validation time used to be a bit fuzzy with respect to alignment, and the reference interpreter implemented it slightly differently from the written spec. This has been rectified in 3.0.

I don't think it's worth fixing in the 2.0 branch at this point (it's essentially archived), and it that would require changing the interpreter as well. In general, the distinction between invalid and malformed is a detail that most Wasm implementations can ignore anyway.
