# WebAssembly spec issue #2046: [test] Incorrect assertions in `memory_init.9.wasm`/`memory_init.4.wasm`
# джерело: https://github.com/WebAssembly/spec/issues/2046
# отримано: 2026-09-30

Issue #2046, opened by agis on 2025-12-20, closed (completed) on 2025-12-21.

Hello! I'm writing a decoder for v2 of the spec and I'm running into an inconsistency when trying to execute the suite, to ensure conformance.

In the `wg-2.0` branch, there are two modules that contain instructions in their Code section, that specify a Data Index. However, those modules do not contain a Data Count section, which is required by the spec (if I understand correctly).

Quoting the spec, Section 5.5.16 (emphasis mine):

> [...] Similarly, the optional data count must match the length of the data segment vector. Furthermore, **it must be present
if any data index occurs in the code section**.

The modules in question are:

```
$ hexdump -C memory_init.9.wasm
00000000  00 61 73 6d 01 00 00 00  01 04 01 60 00 00 03 02  |.asm.......`....|
00000010  01 00 07 08 01 04 74 65  73 74 00 00 0a 0f 01 0d  |......test......|
00000020  00 41 d2 09 41 01 41 01  fc 08 01 00 0b           |.A..A.A......|
0000002d

$ hexdump -C memory_init.4.wasm
00000000  00 61 73 6d 01 00 00 00  01 04 01 60 00 00 03 02  |.asm.......`....|
00000010  01 00 07 08 01 04 74 65  73 74 00 00 0a 07 01 05  |......test......|
00000020  00 fc 09 00 0b                                    |.....|
00000025
```

and the corresponding assertions:

```shell
# memory_init.json:139
{"type": "assert_invalid", "line": 227, "filename": "memory_init.9.wasm", "text": "unknown memory 0", "module_type": "binary"}

# memory_init.json:131
{"type": "assert_invalid", "line": 190, "filename": "memory_init.4.wasm", "text": "unknown data segment", "module_type": "binary"},
```

Aren't these modules be malformed rather than invalid, according to the spec? I checked the `main` branch as well and the corresponding assertions are unchanged.

However, both of these modules are accepted by `wasm-tools`, which makes me wonder whether I'm misunderstanding something or these tests are indeed wrong.

```
$ wasm-tools print /home/agis/dev/wadec/tests/fixtures/spec/memory_init.4.wasm

$ wasm-tools print /home/agis/dev/wadec/tests/fixtures/spec/memory_init.9.wasm
```

Thanks in advance!

## Comment by keithw, 2025-12-20

See https://github.com/WebAssembly/wabt/issues/2629#issuecomment-3240285461 and https://github.com/WebAssembly/testsuite/issues/132 . I think you are getting tripped up by some spec deviance in WABT's wasm2json (which is writing out this invalid module without the DataCount section) and then again in BA's wasm-tools (which has chosen to deal with DataCount at validation time; see https://github.com/bytecodealliance/wasm-tools/blob/main/src/bin/wasm-tools/wast.rs#L233-L242).

The actual test (https://github.com/WebAssembly/spec/blob/wg-2.0/test/core/memory_init.wast) doesn't have any binary examples or malformed modules.

FWIW the reference interpreter (the one in this repo) is probably the one to test against if you want the gold standard in this area.
