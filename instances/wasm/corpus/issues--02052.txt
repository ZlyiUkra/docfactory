# WebAssembly spec issue #2052: [js-api] `WebAssembly.Exception.getArg()`: missing tag parameter?
# джерело: https://github.com/WebAssembly/spec/issues/2052
# отримано: 2026-09-30

Issue #2052, opened by woess on 2026-01-15, closed (completed) on 2026-02-06.

In the current js-api (v2) spec draft, the `getArg` method on `WebAssembly.Exception` is defined as`getArg(unsigned long index)`, not requiring a tag:
https://github.com/WebAssembly/spec/blob/1d3e26f709cabeff385a7eda1cd35c983aea6f4b/document/js-api/index.bs#L1686
https://github.com/WebAssembly/spec/blob/1d3e26f709cabeff385a7eda1cd35c983aea6f4b/document/js-api/index.bs#L1754-L1765

This does not align with the description in Exceptions.md and current browser implementations that expect a `Tag` argument:
https://github.com/WebAssembly/spec/blob/1d3e26f709cabeff385a7eda1cd35c983aea6f4b/proposals/exception-handling/Exceptions.md?plain=1#L279
https://github.com/WebAssembly/spec/blob/1d3e26f709cabeff385a7eda1cd35c983aea6f4b/proposals/exception-handling/Exceptions.md?plain=1#L236-L237

It's not entirely clear to me if this is a spec bug or an intentional change that has not been adopted in implementations yet. Either way, one of the two documents needs to be fixed.

## Comment by eqrion, 2026-02-04

This is definitely a spec bug, the implementations are correct here.
