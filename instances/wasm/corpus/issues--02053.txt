# WebAssembly spec issue #2053: Spec says immediate of i32.const should be u32, but it should be s32?
# джерело: https://github.com/WebAssembly/spec/issues/2053
# отримано: 2026-09-30

Issue #2053, opened by ragnarelofs on 2026-01-16, closed (completed) on 2026-01-16.

The spec says i32.const is written in binary as "0x41 n:u32". Shouldn't it say "0x41 n:s32" to specify that the immediate value should be written in _signed_ leb128 encoding? In practice, this is what Chrome seems to expect and it obviously makes sense so you can say "i32.const -1" and not lose the sign in the encoding. I might be reading the spec wrong.

Spec
  i32.const
  u32

## Comment by rossberg, 2026-01-16

You are right, this was a bug. It should in fact be i32 (all numbers are internally represented as unsigned, and the rule for i32 performs the necessary inverse two's complement reinterpretation).

Should be fixed now (allow some time for the fix to propagate).
