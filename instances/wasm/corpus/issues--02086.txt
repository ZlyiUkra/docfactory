## Comment by rossberg, 2026-02-17

Ah, no.

1. `(ref.extern 𝑖)` in the wast format is not meant to represent a bare address 𝑖. It merely is an abstract external reference with some "payload" 𝑖 to identify it. So even for 𝑖 = 0 (or whatever bit pattern a host uses) it has no overlap with null pointers. How it is represented, is up to the host and must not affect Wasm's semantics.
2.  OTOH, external null references are deterministically recognised as such and must be handled correctly by reference instructions checking for null. They must also be mapped correctly by `extern.convert_any`/`any.convert_extern`.

Generally, Wasm avoids implementation-dependent behaviour like the plague (because it is a plague), including wrt references.

## Comment by rossberg, 2026-02-17

The ref.extern pseudo instruction models acquiring a proper foreign pointer, e.g., as produced by a host-side allocation or by taking the static address of something. As such it shouldn't produce null. The only other constraint is that it can be mapped back to 𝑖. There are various ways to implement these two requirements, depending on your engine and its API for external/foreign pointers. Performing an actual allocation is one obvious possibility.

FWIW, this is not specific to this one test either. If your implementation of ref.extern doesn't model that minimal semantics correctly, then I'm sure multiple other tests will fail as well.
