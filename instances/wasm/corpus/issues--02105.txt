# WebAssembly spec issue #2105: Inconsistency & Missing rules in semantics of spectec il
# джерело: https://github.com/WebAssembly/spec/issues/2105
# отримано: 2026-09-30

Issue #2105, opened by jihongmin63 on 2026-03-10, closed (completed) on 2026-03-10.

While reading the semantics of the IL, I encountered a few points that I may be misunderstanding. I would appreciate any clarification.

**1. Reduction rules for seemingly ill-typed expressions**

In the semantics of the IL, there appear to be reduction rules for expressions that seem ill-typed.
For example, the typing rules include:
```
rule Ok_exp/MEM:
  E |- MEM e_1 e_2 : BOOL
  -- Ok_exp: E |- e_1 : t_1
  -- Ok_exp: E |- e_2 : ITER t_1 STAR

rule Ok_exp/OPT:
  E |- OPT e? : ITER t QUEST
  -- (Ok_exp: E |- e : t)?
  -- Ok_typ: E |- t : OK
```

There are also the following reduction rules:
```
rule Step_exp/MEM-OPT-true:
  S |- MEM e_1 (OPT (e_2)) ~> BOOL true
  -- if e_1 = e_2

rule Step_exp/MEM-OPT-false:
  S |- MEM val_1 (OPT val_2?) ~> BOOL false
  -- (if val_1 =/= val_2)?
```
However, according to the typing rules, even if `e_1` and `e_2` are well-typed, the expression `MEM e_1 (OPT (e_2))` appears to be ill-typed.
I noticed similar patterns in other parts of the specification as well:
- `Ok_exp/ITER` vs. `Step_exp/ITER-QUEST`
- `Ok_prem/ITER` vs. `Step_prems/ITER-QUEST`

In addition, since there is a `LIFT` construct that converts `t?` into `t*`, I expected such rules to operate through LIFT rather than directly using OPT.

As I am very new to SpecTec IL, I may simply be misunderstanding the intended interpretation. I would greatly appreciate any clarification on how these rules should be understood.

**2. Missing reduction rules for Step_exp/COMP?**

I also noticed that there do not appear to be reduction rules corresponding to Step_exp/COMP.
If there is a particular reason why these rules are omitted, I would be interested to learn the rationale!

## Comment by rossberg, 2026-03-10

Good catches!

The MEM-OPT reductions make no sense, no idea how they got there.

COMP is something I forgot to clean up. At some point I decided that CAT and COMP are too similar to justify having both (the former is a special case of the latter). So I generalised the reduction of CAT to be the same as COMP would have been, but forgot to adjust its typing rule (and to remove COMP from the AST).

I just pushed changes fixing both issues, please have a look.
