# WebAssembly spec issue #2128: Rendering of `ref.null` values in .wast drops heaptype
# джерело: https://github.com/WebAssembly/spec/issues/2128
# отримано: 2026-09-30

Issue #2128, opened by titzer on 2026-03-29, closed (completed) on 2026-03-30.

It looks like https://github.com/WebAssembly/spec/commit/228e9109e2f6e7a23bec92f590eb8dc83a7963e3 accidentally dropped the heap type when rendering `ref.null` values in spec tests.

E.g.

```
% interpreter/wasm test/core/table_grow.wast -o /tmp/t.bin.wast
```

## Comment by rossberg, 2026-03-30

Oops, yes, sorry, I hadn't realised that this was implying a breaking change to the conversion. The wast format now allows the type to be omitted in script commands. It is no longer generated, because after a fix to the spec in that PR, that information is no longer available on null values.

Do you depend on this annotation? In theory, I could introduce a few hacks to keep the information around in selected cases like this one, but it wouldn't exactly be pretty.

## Comment by titzer, 2026-03-30

With unboxed continuations, `(ref.null cont)` and `(ref.null extern|any)` have different value representations, so it's necessary for proper invocations and comparisons of null values in tests.
