# WebAssembly spec issue #2155: Structured cloning of WebAssembly.Memory is not defined
# джерело: https://github.com/WebAssembly/spec/issues/2155
# отримано: 2026-09-30

Issue #2155, opened by annevk on 2026-05-04, open.

At least Gecko and WebKit support serializing & deserializing `WebAssembly.Memory` objects. Yet https://webassembly.github.io/spec/web-api/#serialization only covers `WebAssembly.Module`.

I also couldn't find test coverage for this on WPT.

## Comment by eqrion, 2026-05-07

Just to clarify, this is only serializing/deserializing shared `WebAssembly.Memory` right? I don't think Gecko supports doing that for unshared memories. You could make a copy of the underlying ArrayBuffer if you want, but it's not transferable.

Technically the threads proposal hasn't merged yet, and so shared memory isn't defined here yet. I looked upstream though and it is missing a definition for this in the specification there.
