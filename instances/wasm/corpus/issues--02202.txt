# WebAssembly spec issue #2202: [spec] Slight imprecision in module function body validation
# джерело: https://github.com/WebAssembly/spec/issues/2202
# отримано: 2026-09-30

Issue #2202, opened by raoxiaojia on 2026-06-25, closed (completed) on 2026-06-25.

The module's function body validation rule tries to type its body under a new context with the function's locals/labels/return appended to the current context: https://github.com/WebAssembly/spec/blob/24a7a71a4ac6f277233a5e2a69da6806a1dbc045/specification/wasm-3.0/2.4-validation.modules.spectec#L56-L62

From a metatheory pov, it seems that an overwrite is more correct, as functions can't access outer locals or `br` out of the function itself in anyway, and I'm not sure if concatenation of `return` has any meaning in the spectec syntax. Strictly speaking this is not a bug currently, because all the use sites of `Func_ok` has C.locals/labels/return being empty (I think), but an unaware edit in the future could break that.

The reference interpreter correctly use the overwritten context instead of the concatenated one. https://github.com/WebAssembly/spec/blob/24a7a71a4ac6f277233a5e2a69da6806a1dbc045/interpreter/valid/valid.ml#L1018-L1029

(The suggested change is quite small and I'm happy to do a quick fix for it, but I didn't want to prematurely open one in case the current concatenation form is preferred).

## Comment by rossberg, 2026-06-25

That was intentional. Wasm functions don't nest, and this won't ever change, so this is the most concise and natural way of writing it. (Not available in OCaml, though.)

Concatenation on options is specified as partial. It is defined as long as at least one side is empty, which is the case here.
