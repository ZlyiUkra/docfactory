# webdev — примірник фабрики docfactory

Сороковий примірник фабрики: захищений MCP-сервер, що відповідає на питання про те, як робити сайти швидкими,
доступними й надійними. Тут web.dev — сайт команди Chrome у Google: курси Learn, статті й блог, — і бібліотека
`web-vitals`, якою міряють метрики швидкості в браузерах справжніх відвідувачів: README кожного стабільного випуску
від 0.1.0 до 6.2.3, журнал змін і настанови з переходу на v4, v5 і v6. Код спільний і лежить у `../../engine/`,
`../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний устрій фабрики — у
[../../README.md](../../README.md).

## Навіщо

Метрики швидкості сторінки стоять у кількох планах навчання: React (фази 2 і 5 — INP, LCP, CLS і бібліотека
`web-vitals`), Next.js (журнал вимірів, `useReportWebVitals`), Astro (день метрик). Що вважати добрим значенням,
вирішує не браузер і не фреймворк, а web.dev: там опубліковано пороги «добре / треба покращити / погано» для кожної
метрики (INP — до 200 мс добре, понад 500 мс погано, на 75-му процентилі відвідувачів) і те, як їх обрано. Метрики
міняються: FID 2024 року замінено на INP, а бібліотека `web-vitals` у 5.0 прибрала `onFID`, у 4.0 перейменувала поля
атрибуції, — тож потрібні і сайт, і README тієї версії бібліотеки, що стоїть у проєкті.

Курси Learn (CSS, JavaScript, HTML, Accessibility, Forms, Images, Performance, PWA, Design, Testing, Privacy, AI) і
статті про зображення, шрифти, кешування, service worker, доступність і форми — це той самий сайт, і вони потрібні
поруч: найчастіша порада щодо LCP — про зображення, щодо INP — про довгі задачі JavaScript.

**Що таке метрики тут.** LCP (Largest Contentful Paint) — коли з'явився найбільший видимий елемент; INP (Interaction
to Next Paint) — як швидко сторінка відповідає на клік чи натискання; CLS (Cumulative Layout Shift) — наскільки
стрибає вміст під час завантаження. Разом це Core Web Vitals. FCP і TTFB — допоміжні: перший намальований вміст і
перший байт відповіді сервера.

У яких фазах і днях планів навчання він потрібен — див. [../../docs/learning-map.md](../../docs/learning-map.md).

## Що в цій теці

- `corpus/` — лише паспорт `index.json`: адреса, дата завантаження й сума тексту кожного документа (тексти — в архіві,
  див. нижче).
- `index/passages.json.gz` — стиснений кеш фрагментів, з якого підіймається сервер.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.env` — ключ Anthropic (лише для кроку `ask`) і токен GitHub (тут не потрібен: усе йде з web.dev, реєстру npm і
  raw.githubusercontent.com); `.mcp.json` — запис HTTP-сервера для Claude Code.
- `.venv/` — власний venv примірника; `requirements.txt` — його склад.

Кроки нижче, окрім установки venv, запускаються з кореня фабрики (`docfactory/`) через `./df webdev <крок>`.

Особливості, які варто знати:

- **Markdown від самого сайту.** web.dev стоїть на Google DevSite, і той віддає кожну сторінку markdown-ом за адресою
  з «.md.txt» (`https://web.dev/articles/inp.md.txt`). Репозиторій сайту `GoogleChrome/web.dev` у березні 2024 року
  переведено в архів, тож брати тексти з нього не можна — сайт відтоді живе далі.
- **Назва — з HTML.** Статті й записи блогу в markdown починаються блоком авторів, глави курсів — одразу текстом;
  назви там немає. Читач бере її з `<title>` HTML-сторінки — друге звернення на кожну сторінку. У сторінки-змісту
  курсу назва є в markdown («# Learn CSS»), і нею підписано кожну главу: «Learn CSS: Box Model». Записи блогу
  підписано «Blog: …» з датою публікації.
- **Перелік — лише сайтмап.** Сторінки «Articles» і «Blog» складають перелік скриптом, у markdown вони порожні.
  Сайтмап сервер віддає тільки стиснутим (інакше — 500), а розпакованим він важить 78 і 81 МБ: кожна адреса там
  повторена двадцятьма мовами. Для цього мережевий модуль фабрики вміє просити стиснення — поле вмикає лише цей
  читач. Переклади (`?hl=de`) не беруться.
- **Що вирізається з тексту.** Рядки авторів (фото, ім'я й посилання на профілі), банер підписки на розсилку, кнопки
  згортання на сторінці-змісті курсу, тести наприкінці статей («Test your knowledge») і глав курсів («Check your
  understanding»): запитання, варіанти й «Correct!» / «Try again!» там злиті в суцільні рядки й шуму в пошуку дають
  більше, ніж змісту. Окремі сторінки тестів курсів (`learn/quizzes`) не беруться з тієї ж причини. Рядок
  «Published: …, Last updated: …» лишається: дата каже, чи порада ще чинна.
- **Код — з відступом.** Приклади в главах курсів сайт віддає не блоками «```», а відступом у чотири пробіли; у тексті
  вони так і лишаються.
- **23 адреси сайтмапа — не сторінки.** Службові шматки прикладів (`…/assets/body`, `…/assets/supporting-popup`) і
  сторінки, яких уже немає (404). Кожен `refresh` показує їх як збої — так і має бути.
- **Windows Defender і стаття про злам.** Стаття `fix-the-japanese-keyword-hack` містить приклади коду зламаних сайтів,
  і Defender за замовчуванням видаляє її файл із корпусу. На цій машині для неї додано виняток; на іншій її текст
  може зникнути з `corpus/` одразу після запису.
- **README `web-vitals` — лише стабільні випуски.** Бети, rc і експериментальні збірки (`soft-navs`, `debug`, `types` —
  54 штуки) не беруться. Випуску 3.2.0 не існує: автори пропустили номер, і в журналі змін про це окремий запис.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/webdev-corpus-2026-10-08.tar.gz` (4,1 МБ, 1 407 текстів і
паспорт; перед видаленням розпакований окремо й звірений із диском — нуль розбіжностей). В історії git текстів немає
ніде. Архів лежить лише на цій машині.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/webdev/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/webdev-corpus-РРРР-ММ-ДД.tar.gz -C instances/webdev corpus
find instances/webdev/corpus -maxdepth 1 -name '*.txt' -delete
gzip -9 -c instances/webdev/index/passages.json > instances/webdev/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти — лише після того, як архів
звірено з диском.

**Як повернути тексти** — перед будь-яким оновленням корпусу:

```
tar -xzf ~/archives/docfactory/webdev-corpus-РРРР-ММ-ДД.tar.gz -C instances/webdev
./df webdev smoke
```

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/webdev/index/passages.json.gz`, далі
`./df webdev vectors` заллє колекцію Qdrant (близько 35 хвилин).

## Установка venv

```
cd instances/webdev
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # якщо потрібен крок ask, впишіть ANTHROPIC_API_KEY
cd ../..
```

## Збирання корпусу

```
./df webdev sources --why   # перелік джерел і білий список
./df webdev refresh         # завантажити все задеклароване (~75 хвилин)
./df webdev manifest        # оновити паспорт
./df webdev setup           # Qdrant чи пошук лише по словах
./df webdev vectors         # залити корпус у docs-webdev (~35 хвилин)
./df webdev smoke           # перевірки
```

Сторінок web.dev близько 1 335, і на кожну без назви в markdown — два звернення з паузою в секунду, звідси година з
чвертю. Обірваний `refresh` продовжується з `--missing`.

**Новий випуск `web-vitals`** з'являється сам: README береться з реєстру npm на кожен випуск, журнал змін — з `main`.
Нова настанова з переходу (`docs/upgrading-to-v7.md`) — окреме джерело `mdfile` за зразком `web-vitals-upgrading-v6`.
**Нова частина сайтмапа web.dev** (`sitemap_2_of_3.xml`): перелік відмовить з назвою адреси поза білим списком —
дописати її у `within` джерела `webdev`.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df webdev serve             # порт 8800
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8800/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user webdev-docs http://127.0.0.1:8800/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server» у
вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `webdev-docs` і два інструменти `search_docs`, `read_section`. Якщо сесію Claude
Code відкрито раніше, ніж піднято сервер, вона покаже його як недоступний: у `/mcp` виберіть сервер і «Reconnect».

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
