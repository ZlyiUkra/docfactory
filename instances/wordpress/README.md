# wordpress — примірник фабрики docfactory

Цей примірник зібрав документацію WordPress і віддає її через сервер MCP, щоб модель відповідала за текстом документації, а
не з пам'яті. WordPress — це система керування вмістом сайту, написана мовою PHP. До неї належать REST API (запити HTTP, якими
програма читає й змінює вміст сайту), редактор блоків Gutenberg і WP-CLI (керування сайтом із командного рядка).

## Навіщо окремий примірник

Щоб вивезти вміст сайту й замінити форму, треба знати кілька речей водночас: як працюють REST API й WP-CLI, у якому форматі
WordPress експортує вміст, які функції й хуки є в ядрі та як влаштовані плагіни форм. Ці відомості лежать на десятку різних
сайтів і в репозиторіях. Примірник шукає по них одразу.

Хук — це точка в коді WordPress, де плагін може виконати власну функцію. Наприклад, `rest_api_init` спрацьовує, коли запускається
REST API.

Замір `quality` на 03.11.2026 дав такі числа. Запити точними назвами з документації знаходять потрібне 10 із 10, бо модель
зазвичай питає саме так. Запити звичайними словами знаходять потрібне 4 із 10: пошук по словах дає 4, пошук за змістом дає 3.

Причина нижчого числа така. Корпус дуже великий, а більшість фрагментів довідника описує вузькі функції й методи, тож на
загальний запит вони часто випереджають потрібну сторінку посібника. Тому модель має шукати точними іменами, і так сказано в її
промпті. Перша редакція цих десяти запитів дала 0 із 10, бо вони навмисно уникали всіх слів документації. Запити переписано
ближче до звичайної мови, тому числа 0 і 4 не можна порівнювати як покращення пошуку.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df wordpress <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| довідник коду, Learn WordPress | сторінки сайту, перелік адрес із REST API | `wp-rest-html` |
| посібники, документація, нотатки, блог, сайти плагінів форм | REST API сайтів | `wp-rest` |
| каталог плагінів | api.wordpress.org | `wp-plugin-info` |
| Gutenberg, WP-CLI | теги на GitHub | `ghdocs-history`, `ghdocs`, `ghreleases` |
| вимоги кожної лінії, код Importer | `WordPress/WordPress`, `WordPress/wordpress-importer` | `ghcode` |
| `readme.html` кожної лінії | `WordPress/WordPress` | `html-list` |
| npm, Packagist, Docker Hub | реєстри | `npm-versions`, `pkg-registry`, `dockerhub-tags` |

**Новий читач `wprest`.** REST API сайту на WordPress віддає сто записів за один запит, тому тисячі сторінок посібників
приходять за десятки звернень. Довідник коду там віддає лише назву, бо сигнатуру, параметри й журнал змін будує сторінка сайту,
тому його текст береться зі сторінок. Це займає близько п'яти годин, і саме цей крок найдовший.

**Що не взято.** Вихідний код ядра кожної лінії не взято: це сотні мегабайтів на лінію, а описи функцій і хуків із цього коду вже
є в довіднику. Сторінки `wporg_explanations` не взято окремо, бо їхній текст уже стоїть на сторінках довідника в розділі
«More Information».

**Чого не вдалося взяти.**

- `codex.wordpress.org`, стара документація, закрита перевіркою браузера й відповідає кодом 403.
- Docker Hub анонімно віддає лише 1000 найновіших із 5962 тегів образу `wordpress`.
- `contactform7.com`, `formidableforms.com` і сайт Forminator не віддають REST API. Про ці плагіни є лише запис у каталозі.
- 62 сторінки відкинуто як закороткі, здебільшого службові сторінки Gravity Forms.

## Версії

Звичайне число у фільтрі `version` позначає сам WordPress: `"6.8"` бере сторінку цієї версії, її нотатки для розробників і вимоги.
Інший проєкт позначає префікс, бо інакше номер пакета npm `6.8.0` плутався б із WordPress 6.8:

| Проєкт | Приклад `version` |
|--------|-------------------|
| WordPress | `"6.8"` |
| Gutenberg | `"gutenberg-22.0"` |
| один пакет npm | `"npm-block-editor-15"` |
| WP-CLI | `"cli-2.7"` |
| Packagist | `"composer-6.8"` |
| WordPress Coding Standards | `"wpcs-3"` |

Довідник коду й посібники версії не мають: вони описують лише чинний стан. Журнал змін на сторінці довідника називає версії, у яких
функція змінювалася, а старого коду там немає. Чинна лінія — 7.1 (7.1.4).

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/wordpress-corpus-2026-11-03.tar.gz` (29 106 текстів, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows
`C:\Distr\wordpress-corpus-2026-11-03.tar.gz` (звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/wordpress/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/wordpress-corpus-РРРР-ММ-ДД.tar.gz -C instances/wordpress corpus raw
find instances/wordpress/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/wordpress/raw
gzip -9 -c instances/wordpress/index/passages.json > instances/wordpress/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як
новий архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/wordpress-corpus-2026-11-03.tar.gz -C instances/wordpress
./df wordpress smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки
`smoke`, яким потрібні тексти, пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/wordpress/index/passages.json.gz`. Далі
`./df wordpress vectors` заллє колекцію Qdrant (кілька хвилин на відеокарті, довше на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df wordpress …` бере спільне середовище (`.venvs/cpu` або `.venvs/gpu`). Як його
збудувати один раз і як `df` обирає між ними — у кореневому README, розділ «Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ вище). Для самого сервера збирати нічого
не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df wordpress sources --why   # перелік джерел і білий список
./df wordpress refresh         # завантажити все задеклароване (близько 7 годин)
./df wordpress manifest        # оновити паспорт
./df wordpress setup           # Qdrant чи пошук лише по словах
./df wordpress vectors         # залити корпус у docs-wordpress
./df wordpress smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md).

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df wordpress serve          # порт 8946
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8946/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user wordpress-docs http://127.0.0.1:8946/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування, тому у вікні на боці Windows команду треба виконати в PowerShell.
Сам сервер з Windows доступний за тією ж адресою.

**3. Перевірити.** `/mcp` має показати `wordpress-docs` і два інструменти, `search_docs` і `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» і невдале під'єднання — описана в
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
