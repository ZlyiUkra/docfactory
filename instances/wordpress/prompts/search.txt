Search the documentation of WordPress -- the PHP content management system, its REST API, its block editor Gutenberg and
its command line tool WP-CLI. The corpus holds the whole Code Reference of developer.wordpress.org (every function, class,
method and hook with its signature, parameters, return value, source code, changelog and user notes); the Plugin, Theme,
Block Editor, REST API, Common APIs, Coding Standards, Advanced Administration, Secure Custom Fields and Playground
handbooks; the user documentation of wordpress.org with the page of every WordPress version; the developer notes and field
guides of make.wordpress.org/core and the Core Contributor Handbook; the Developer Blog; Learn WordPress (lessons, courses,
tutorials, lesson plans); the docs/ of Gutenberg at the last release of every minor, its release notes, the README and
changelog of every @wordpress/* package with its npm registry entry; the WP-CLI handbook and every command at each tag; the
Packagist entries of roots/wordpress, johnpbloch/wordpress, composer/installers, wp-cli and wpcs; readme.html and the PHP and
MySQL requirements of every WordPress line 1.5 to 7.1 (wp-includes/version.php); the WordPress Importer plugin with its code
for the WXR export format; the directory entries of form, import, export and backup plugins; the documentation of WPForms,
Gravity Forms and Ninja Forms; and the Docker image. Returns the matching excerpts with the versions each one belongs to.

Call this when a question is about WordPress as it describes itself -- what a function or hook does and since which version
it exists, how to build a plugin, theme or block, how the REST API routes and authentication work (application passwords,
cookies, nonces), how to export and import content (Tools > Export, WXR, `wp export`, `wp import`, the WordPress Importer),
how to read or write posts, users and media through the REST API or WP-CLI, how to get a form's entries out of a form
plugin and what its hooks are, which PHP and MySQL a WordPress version requires, what changed in a release.

Query by the exact name the documentation uses: `register_rest_route`, `rest_api_init`, `WP_Query`, `wp_insert_post`, `wp post
list`, `@wordpress/scripts`, `block.json`, `gform_after_submission`, "application passwords".

Do not call this for PHP, MySQL, Apache, nginx, React or Composer as their own projects: their documentation is not here, and
the search will return excerpts that merely mention them, with confident-looking titles. Only the free plugins listed above
and the three form plugin sites are here; any other plugin or theme is not. The Code Reference shows only the current
state of each function: its changelog names the versions in which it changed, but the old source code is not kept.

`version` narrows the search to one release line, and the prefix says what the number belongs to. A plain number is
WordPress itself: "6.8" keeps the page of that version, its developer notes and its requirements. "gutenberg-22.0" keeps
Gutenberg, "npm-block-editor-15" keeps one npm package, "cli-2.7" keeps WP-CLI, "composer-6.8" keeps the Packagist entries.
Leave `version` empty for the Code Reference and the handbooks, which describe the current state only. Every excerpt comes
back with `versions`: each version whose documents contain this exact text, newest first. When a question names no version,
answer for the current line, 7.1, and say which version the answer is for.

Answer in the language of the question, keep identifiers and titles in English, and answer a question about history or
support point by point, naming the version and the document for each point.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.
