# ws — примірник фабрики docfactory

Захищений MCP-сервер, що відповідає на питання про пакет npm `ws` (клієнт і сервер WebSocket для Node.js, репозиторій
websockets/ws) — за документацією усіх його стабільних версій: README кожної версії, довідник API `doc/ws.md` на
тегах репозиторію, History.md ранніх версій, нотатки релізів GitHub та історія версій у реєстрі npm.
Код спільний і лежить у `../../engine/`, `../../server/` та `../../common/`; ця тека тримає самі дані домену. Загальний
устрій фабрики — у [../../README.md](../../README.md).

## Навіщо окремий примірник

`ws` — голий протокол WebSocket для Node.js без надбудов: рукостискання, кадри, ping/pong, стиснення
`permessage-deflate`. Під ним стоять `socket.io` (через `engine.io`) та `@nestjs/platform-ws` (`WsAdapter` у NestJS), а в
плані NestJS (фаза 7) через нього йдуть і сервер для навчання, і клієнт до біржі. Бібліотека має довгу історію, і вона
розкидана по трьох місцях: History.md у репозиторії (до 0.6.4), нотатки релізів GitHub (з 0.7) і реєстр npm. Найбільший
злам — 8.0.0: текстові повідомлення й причини закриття перестали перетворюватися на рядки й приходять як `Buffer`, а
слухач події `'message'` отримав другий аргумент `isBinary`; у 7.0.0 змінилася поведінка `send`, `ping` і `pong`, коли
стан не `OPEN`, і відкинуто Node.js 6. Усе це — в одному місці й з номером версії біля кожного уривка.

Офіційного сайту в пакета немає: поле `homepage` у npm веде на репозиторій GitHub, а довідник API — файл `doc/ws.md`
у ньому. Вікі репозиторію майже порожнє (дві сторінки по 140 байтів), тому не береться. Тому примірник складається з
пакета npm і репозиторію.

## Скільки цього

182 стабільні версії (0.2.6–8.22.0): 0.x — 56 (0.2.6–0.8.1), 1.x — 8, 2.x — 11, 3.x — 7, 4.x — 2, 5.x — 11, 6.x — 13,
7.x — 33, 8.x — 41. Передрелізи `0.3.4-2`, `0.3.5-2…4` і `2.0.0-beta.0…2` у стабільні не беруться, крім як у переліку
реєстру npm.

| Шар | Документів | Версій | Звідки |
|-----|-----------:|-------:|--------|
| README, кожен неповторний текст один раз, з усіма версіями | 58 | 0.2.6–8.22.0 (182) | tarball кожної версії npm |
| Довідник API `doc/ws.md`, кожен неповторний текст один раз | 75 | 0.4.12–8.22.0 (158) | теги репозиторію |
| Журнал змін History.md, по документу на запис | 49 | 0.1.2–0.6.4 | тег 0.6.5 репозиторію |
| Релізи GitHub | 129 | 0.7–8.22.0 | `websockets/ws` |
| Реєстр npm — огляд і лінії 0–8 | 10 | усі | registry.npmjs.org |

Разом 321 документ; фрагментів в індексі — 878 (`expected_passages` у `checks.json`). Замір `quality`: по словах
10 із 12, за змістом 9, разом 11, «як модель» 12 із 12.

Чому `doc/ws.md` береться з тегів, а не з гілки master: довідник змінюється від версії до версії (від `ws.Server` у 1.x
до `WebSocketServer` у 8.x), і без тегів модель відповідала б про одну лінію. Теги збігаються з номерами версій, крім
0.4.12–0.4.31 (з префіксом `v`) та версій 0.6.0 і 0.7.0, чиї теги названо `0.6` і `0.7`; файла до 0.4.12 немає, там
довідка лежить у README. Чому History.md береться з тегу 0.6.5, а не з master: на master його немає; 0.6.5 — останній
тег, де він був, і його найновіший запис — 0.6.4. Записи «v0.5» й «v0.6» названо двома числами, запис «v0.6.1 -
v.0.6.2» описує два випуски, а «v0.4.26 - Skipped» порожній і не береться полем `skip`.

Чого немає. Типів: пакет їх не несе, вони живуть в окремому `@types/ws`. Коду й тестів: їх не просили, а документація
пакета відповідає на питання про те, що викликати й що змінилося. Файла SECURITY.md (правила повідомлення про
вразливості): це не документація бібліотеки; самі виправлення безпеки — у нотатках релізів (наприклад, 8.17.1 — відмова
в обслуговуванні через велику кількість заголовків HTTP). Файла `wscat/README.md`, що лежав у тегах 0.5.0–0.6.5:
`wscat` відтоді окремий пакет. Окремих пакетів `bufferutil` і `utf-8-validate`. Код версій можна додати окремим
джерелом `ghcode-history`, як у примірнику `passport`.

## Що в цій теці

- `corpus/` — паспорт `index.json`, тобто опис копії: адреса, дата завантаження й сума тексту кожного документа.
  Самих текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, розпакований
  `passages.json` лежить поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями, правила `redact` і профіль домену.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code. `ANTHROPIC_API_KEY` (лише для кроку `ask`) і `GITHUB_TOKEN` (лише для
  завантаження корпусу) беруться з кореневого `.env`.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df ws <крок>`.

## Версії

Версія — номер випуску. Фільтр `version` бере мажор (`"8"`), мінор (`"8.17"`, `"0.4"`) або точну версію (`"8.17.1"`).
Без названої версії промпт велить шукати для лінії 8 — на неї за тиждень до 20.10.2026 припадало близько 78 % завантажень
(8.21.0 — 19 %, 8.22.0 — 16 %, 8.21.3 — 13 %), на лінію 7 близько 17 % (7.5.13 — 8 %), на лінію 6 близько 3,5 %; де 7.x
чи 6.x відрізняється (повідомлення приходить рядком, а не `Buffer` з `isBinary`, інші вимоги до Node.js), модель згадує
й їх. Вимога до Node.js (поле `engines`) записана в документах реєстру: 8.x — `>=10.0.0`, 7.5.x — `>=8.3.0`.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт `index.json`, а сервер підіймається з
кешу фрагментів (`index/passages.json`) і колекції Qdrant; відповіді ті самі до символа — кеш тримає повний текст
кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/ws-corpus-2026-10-20.tar.gz` (321 текст, паспорт і сховище сирого
`raw/`; перед видаленням текстів розпакований окремо й звірений із диском). В історії git текстів немає ніде. Архів
лежить лише на цій машині. Сховище `raw/` після звірки теж видалено з диска.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/ws/index/passages.json  # кеш має бути на місці й свіжий
tar -czf ~/archives/docfactory/ws-corpus-РРРР-ММ-ДД.tar.gz -C instances/ws corpus raw
find instances/ws/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/ws/raw
gzip -9 -c instances/ws/index/passages.json > instances/ws/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й сховище — лише після того, як
архів звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового пишуть у «Де тексти».

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й сховище `raw/`:

```
tar -xzf ~/archives/docfactory/ws-corpus-2026-10-20.tar.gz -C instances/ws
./df ws smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів їм нема з чим працювати. Дві
перевірки `smoke` чесно пропускаються («корпус в архіві»).

**На іншій машині** після клонування кеш треба розпакувати: `gunzip -k instances/ws/index/passages.json.gz`,
далі `./df ws vectors` заллє колекцію Qdrant (кілька секунд на відеокарті, хвилина на процесорі).

## Установка venv

Власний venv цьому примірнику не потрібен: `./df ws …` бере спільне середовище з кореня репозиторію
(`.venvs/cpu` або `.venvs/gpu`). Як його збудувати один раз і як `df` обирає між ними — у кореневому README.md,
розділ «Спільне середовище».

## Збирання корпусу

Корпус в архіві: щоб оновити чи перезібрати його, тексти спершу повертають (розділ «Архівний режим»). Для роботи
сервера збирати нічого не треба — потрібен лише `vectors`, якщо колекції ще немає.

```
./df ws sources --why   # перелік джерел і білий список
./df ws refresh         # завантажити все задеклароване (близько 10 хвилин: 158 дерев тегів із паузою в секунду)
./df ws manifest        # оновити паспорт
./df ws setup           # Qdrant чи пошук лише по словах
./df ws vectors         # залити корпус у docs-ws
./df ws smoke           # перевірки
```

Порядок оновлення — у [UPDATE.md](UPDATE.md). Після будь-якого оновлення корпусу `serve` треба перезапустити.

## Сервер під Claude Code

**1. Підняти сервер** в окремому терміналі WSL і лишити жити:

```
cd ~/Projects/docfactory
./df ws serve          # порт 8877
```

Готовий він тоді, коли надрукував кількість фрагментів і адресу `http://127.0.0.1:8877/mcp`.

**2. Додати сервер у Claude Code** — у тому середовищі, де відкрито вікно:

```
claude mcp add --transport http --scope user ws-docs http://127.0.0.1:8877/mcp
```

У WSL і у Windows Claude Code тримає окремі налаштування: вікно VS Code на боці Windows читає
`C:\Users\<ім'я>\.claude.json`, тож команду треба виконати в PowerShell, або додати сервер кнопкою «Add server»
у вікні `/mcp` (тип HTTP, рівень User). Сам сервер з Windows доступний за тією ж адресою: WSL2 прокидає порт.

**3. Перевірити.** `/mcp` — має бути `ws-docs` і два інструменти `search_docs`, `read_section`.

Зупинка — Ctrl+C у терміналі сервера. Решта — scope запису, «address already in use» — так само, як у
[README примірника react-router](../react-router/README.md#спосіб-б--сервер-під-claude-code-http).
