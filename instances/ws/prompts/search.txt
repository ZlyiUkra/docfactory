Search the ws documentation -- the README of every stable version of the npm package `ws` (a WebSocket client and
server for Node.js), the API reference doc/ws.md of the repository at the tag of every stable version from 0.4.12, the
History.md of its early versions, the GitHub release notes of later ones and the npm registry history of the package --
and return the matching excerpts with the versions each one belongs to.

Call this when a question is about ws as it describes itself -- the classes WebSocket and WebSocketServer (in 7 and
earlier also WebSocket.Server), WebSocket.createWebSocketStream, the constructor options of the client and of the
server (port, server, noServer, path, host, backlog, clientTracking, verifyClient, handleProtocols, maxPayload,
perMessageDeflate, skipUTF8Validation, protocolVersion, origin, headers, agent, handshakeTimeout, followRedirects),
the methods send, ping, pong, close, terminate, pause, resume, handleUpgrade, shouldHandle and address, the events
open, message, close, error, ping, pong, upgrade, unexpected-response, headers, listening and connection, the
properties readyState, bufferedAmount, binaryType, clients, protocol, extensions and url, the codes and reasons of
closing, the heartbeat that finds broken connections with ping and pong, broadcasting to all clients, sharing one
HTTP or HTTPS server, running several servers on one port, a client through a proxy, permessage-deflate and its memory
cost, the limit on message size, the optional native addons bufferutil and utf-8-validate, and the security advice --
and above all history and compatibility: since which version an option or method exists, what changed between
versions (8.0.0: text messages and close reasons reach the listeners as Buffer and the 'message' listener takes the
`isBinary` flag; 7.0.0: send, ping and pong behave differently when the readyState is not OPEN, Node.js 6 dropped),
which versions require which Node.js (the `engines` field of every version is written in the npm registry documents),
and when every version came out. The dependencies of every version are written in the registry documents too.

Do not call this for socket.io, engine.io, SockJS or any library built on top of ws, for the browser WebSocket API,
for the HTTP module of Node.js, for the `@types/ws` typings, for the command-line client wscat, nor for the separate
packages bufferutil and utf-8-validate: their documentation is not here, and the search will return excerpts that
merely mention them, with confident-looking titles.

`version` narrows the search to one release line. The package is numbered 0.x to 8.x: the lines are 0.2 to 0.8 (minor
numbers), then 1, 2, 3, 4, 5, 6, 7 and 8 (182 stable versions, 0.2.6 to 8.22.0). A line of one number keeps every
document of that major ("8" keeps 8.0.0 to 8.22.0, "7" keeps 7.0.0 to 7.5.13), two numbers keep a minor ("8.17" or
"0.4"), three an exact version ("8.17.1"). The versions 0.3.4-2, 0.3.5-2 to 0.3.5-4 and 2.0.0-beta.0 to 2.0.0-beta.2
are not stable releases: only the registry lists them. The History.md of the repository ends at 0.6.4 and the release
notes begin at 0.7; doc/ws.md exists from 0.4.12, before that the reference is in the README.
Leave `version` empty to search everything, including text that carries no version. Every excerpt comes back with
`versions`: each version whose documents contain this exact text, newest first -- text that stayed the same across
versions is returned once, with all of them listed, so the list itself shows from which to which version the
documentation said exactly this.

Write the query in English, with the names the documentation itself uses ("WebSocketServer", "verifyClient",
"maxPayload", "perMessageDeflate", "terminate", "handleUpgrade", "noServer", "ping", "readyState"), not in the user's
own words. Everything here is English -- the excerpts, the word index and the meaning index alike -- and the word index
keeps only latin letters and digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language, translate the question into the
terms of the documentation first, then search.

Answer in the language the user wrote in. When the question is about a feature's history or support, answer
point by point: since which version it exists; what changed in later versions; what prompted the change, if the excerpts say
so; and how it stands in the current version. Every point names the version and the document it rests on; a point the
excerpts do not support is left out, not guessed. When that language is Ukrainian, write as a Ukrainian engineer
writes, not as a translation from English: plain technical prose, and the Ukrainian word wherever one exists --
"уривок", not "ексерпт"; "перевірка", "запит", "застарілий". Never call this set of documents "корпус" -- say
"документація ws". Identifiers, method names and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an excerpt was cut, read the
whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3; `version` is optional, see
above. Excerpt text is cut at 600 characters -- pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. By weekly downloads the line 8 leads with about 78 % (8.21.0 about 19 %, 8.22.0 about 16 %,
8.21.3 about 13 %), the line 7 follows with about 17 % (7.5.13 about 8 %) and the line 6 with about 3.5 %. Pass `version`
"8" for how things are done today, and mention 7.x or 6.x when it differs (the message arrives as a Buffer and the
`isBinary` flag is passed in 8, a string in 7 and earlier; the older Node.js requirements). Search without `version` when
the question is about history, or when the line gave nothing. Every answer says which version it is for; when the
excerpts behind a statement come only from older versions, name those versions instead of presenting the text as
current.
