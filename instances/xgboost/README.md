# xgboost — примірник фабрики docfactory

Цей примірник зібрав документацію бібліотеки XGBoost і віддає її через сервер MCP, щоб модель відповідала з текстів бібліотеки, а не з
пам'яті. XGBoost навчає ансамблі дерев рішень. Ансамбль — це багато дерев, чиї відповіді складаються в одну. Найчастіше XGBoost будує
дерева по черзі, і кожне наступне виправляє помилки попередніх; цей спосіб називають градієнтним бустингом. Той самий XGBoost уміє
будувати й випадковий ліс: тоді за один раунд росте кілька незалежних дерев, і їхні відповіді усереднюються (параметр
`num_parallel_tree`).

## Скільки цього

Усього 774 документи і 4631 фрагмент. Фрагмент — це шматок документа, який пошук повертає як окремий результат. Одна сторінка, що
змінювалася між версіями, лежить кількома документами, а однакові розділи пошук зливає й показує з переліком версій.

| Що | Лінії | Документів |
|---|---|---|
| тека `doc/` репозиторію: посібники, параметри, GPU, формат моделі, навчальні статті, R і JVM, нотатки релізів 2.1+ | 25 ліній 0.40–3.4 | 520 |
| довідник Python API і приклади Python із сайту | 20 ліній 0.72–3.4 | 145 |
| нотатки релізів GitHub | усі стабільні теги | 63 |
| журнал змін `NEWS.md` | записи 0.1–2.0.0 | 35 |
| записи PyPI | усі стабільні версії | 11 |

Мітка версії має вигляд `xgboost-3.4`. Префікс потрібен, щоб версії XGBoost не збігалися з версіями інших бібліотек, коли сервери
працюють разом.

**Де є прогалини, хоч ми й брали всі лінії.** Деяких текстів уже ніде не публікують.

- Сайт Read the Docs публікує теки лише від 0.72, тож довідник Python API для старіших ліній відсутній. Цей довідник створюється з
  коду, і в репозиторії його тексту немає.
- Теги 0.32 і старіші не мають теки `doc/`, тож про ці лінії є лише записи `NEWS.md`.

Замір `quality` на 08.11.2026 дав такі числа. Запити назвами з документації знаходять потрібне 10 із 10, а модель зазвичай питає саме
так. Запити своїми словами знаходять потрібне 5 із 10. Сторінка довідника Python API має лише кілька великих розділів, і кожна з 20
версій лежить окремою редакцією. Без обмеження ця сторінка займала дев'ять перших місць видачі, тому в `config.json` стоїть
`max_per_doc: 2`: одна сторінка займає щонайбільше два місця.

## Що в цій теці

- `corpus/` — паспорт `index.json`; текстів тут немає: корпус в архіві (розділ «Архівний режим» нижче).
- `index/` — кеш фрагментів, з якого сервер підіймається: у git — стиснений `passages.json.gz`, а розпакований `passages.json` лежить
  поруч і в git не потрапляє.
- `sources.json` — звідки корпус будується, і водночас білий список для оновлювача.
- `config.json` — порт, колекція Qdrant, модель векторів, пауза між зверненнями.
- `prompts/` — описи інструментів для моделі, системний промпт власного агента, текст відмови.
- `checks.json` — чим `smoke` і `quality` перевіряють саме цей корпус.
- `.mcp.json` — запис HTTP-сервера для Claude Code.

Кроки нижче запускаються з кореня фабрики (`docfactory/`) через `./df xgboost <крок>`.

## Звідки документація

| Що | Джерело | Читач |
|----|---------|-------|
| тексти документації | `doc/` у тегах `dmlc/xgboost` | `ghdocs-history` |
| довідник Python API і приклади | `xgboost.readthedocs.io/en/*/python/` | `sphinx-html` |
| нотатки релізів | релізи GitHub `dmlc/xgboost` | `ghreleases-pattern` |
| журнал змін | `NEWS.md` у тегу `v3.4.2` | `changelog-regex` |
| записи PyPI | `pypi.org/pypi/xgboost/json` | `pypi-versions` |

Read the Docs називає теки версій `release_3.3.0` і `stable`, а мітка версії мусить бути номером. Тому читач `sphinx-html` отримав
необов'язкове поле `version_labels`, яке перекладає назву теки в номер. Тека `stable` — це 3.4.2.

## Як підняти сервер

Сервер працює у спільному середовищі фабрики, власного `.venv` примірник не має. В окремому терміналі виконайте:

```
./df xgboost serve
```

Порт — `8954`. Якщо порт зайнято, `serve` скаже про це й зупиниться: швидше за все, цей сервер уже запущено в іншому терміналі.

Під'єднати сервер до Claude Code можна двома способами. Перший — файл `.mcp.json` цієї теки. Другий — команда:

```
claude mcp add --transport http --scope user xgboost-docs http://127.0.0.1:8954/mcp
```

Команда для Claude Code у Windows, коли сервер працює у WSL, та сама: WSL віддає порт на `127.0.0.1` Windows.

У сесії Claude Code команда `/mcp` має показати сервер `xgboost-docs` з інструментами `search_docs` і `read_section`. Якщо сервер
позначено як недоступний, перевірте, чи працює `serve`, і чи запущено контейнер Qdrant.

## Архівний режим: сервер без корпусу

Корпус примірника в архіві від самого початку: у `corpus/` лежить лише паспорт. Серверу вистачає кешу фрагментів
(`index/passages.json`) і колекції Qdrant; відповіді ті самі до символу, бо адреса й дата лежать у кеші кожного фрагмента.

**Де тексти.** В архіві `~/archives/docfactory/xgboost-corpus-2026-11-08.tar.gz` (774 тексти, паспорт і сховище сирого `raw/`; перед
видаленням текстів розпакований окремо й звірений із диском) і в копії на диску Windows `C:\Distr\xgboost-corpus-2026-11-08.tar.gz`
(звірено за SHA-256). В історії git текстів немає.

**Як винести знову** — після оновлення, коли `vectors` і `smoke` пройшли:

```
ls -l instances/xgboost/index/passages.json  # кеш має бути на місці й свіжий
tar --sort=name -czf ~/archives/docfactory/xgboost-corpus-РРРР-ММ-ДД.tar.gz -C instances/xgboost corpus raw
find instances/xgboost/corpus -maxdepth 1 -name '*.txt' -delete
rm -rf instances/xgboost/raw
gzip -9 -c instances/xgboost/index/passages.json > instances/xgboost/index/passages.json.gz
```

і закомітити паспорт `corpus/index.json` та `index/passages.json.gz`. Видаляти тексти й `raw/` можна лише після того, як новий архів
звірено з диском. Тоді ж видаляють попередній архів, а ім'я нового записують сюди.

**Як повернути тексти** — перед будь-яким оновленням корпусу; разом із ними повертається й `raw/`:

```
tar -xzf ~/archives/docfactory/xgboost-corpus-2026-11-08.tar.gz -C instances/xgboost
./df xgboost smoke
```

**Що перестає працювати.** `check`, `refresh` і `manifest` читають файли, і без текстів вони не працюють; перевірки `smoke`, яким
потрібні тексти, пропускаються («корпус в архіві»).
