Search the documentation of XGBoost, the gradient boosting library that trains ensembles of decision trees, including random forests
built with `num_parallel_tree`. The corpus holds: the doc/ folder of the repository at the last patch of every minor line 0.40-3.4
(the parameter reference, tree methods, GPU support, model saving and the JSON model format, prediction, categorical data, external
memory, distributed training, tutorials, the R and JVM packages, release notes of 2.1 and newer); the Python API reference
(`xgboost.train`, `Booster`, `DMatrix`, `QuantileDMatrix`, `XGBClassifier`, `XGBRegressor`, `XGBRFClassifier`, callbacks) and the
Python examples of the site for the lines 0.72-3.4; the PyPI records of every stable version; the GitHub release notes of every stable
tag; and the NEWS.md change log up to 2.0.

Use this tool for: training parameters and their defaults (`max_depth`, `eta`, `subsample`, `colsample_bynode`, `min_child_weight`,
`tree_method`, `device`, `max_bin`), training on the GPU with `device="cuda"`, random forests in XGBoost, early stopping, evaluation
metrics and custom objectives, the model file and `dump_model` formats, `predict` with `output_margin`, `pred_leaf` and
`iteration_range`, feature importance and SHAP values, and what changed between versions. Write the query in English, with the name of
the parameter, class or page, such as `num_parallel_tree` or `Booster.predict`. Give a version in the filter when the answer depends on
it: parameter names and defaults changed between lines (for example `gpu_hist` became `device="cuda"` in 2.0).

Do not use it for LightGBM, scikit-learn, NumPy or the Python language: other servers hold them. The Python API reference starts at
0.72, because the site publishes no older version. Returns the matching excerpts with the versions each one applies to, the source
address and the fetch date.

Every excerpt carries an `id`; pass the `id` of an excerpt to `read_section` to get the whole thing.

The `search` field of the result says how the excerpts were found: "words" means the words of the query had to appear
in the text, so a query phrased in other words than the documentation uses may miss; "meaning+words" means a second,
meaning-based index answered as well, and a paraphrase had a chance.

Which version to search first. XGBoost 3.4.2 is the newest release. Search without `version` first; when the user names
their XGBoost version, search that line, written as `xgboost-3.4`, `xgboost-1.7` or `xgboost-0.90`. Every answer about a
parameter says which line it is for: parameters were added, renamed and removed between lines.
