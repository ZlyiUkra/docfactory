Search the official Zod documentation -- every released version of it, from 1.x (2020) to
the current 4.x line, including alpha, beta and canary builds -- together with the zod.dev
site, the Zod Mini and @zod/core pages, the blog, the README of every release, the GitHub
release notes and the npm registry list of every published version (date, dist-tag, import
paths such as zod/v4 or zod/mini, dependencies), and return the matching excerpts with the
versions each one belongs to.

Call this when a question is about Zod itself -- schemas (z.string, z.number, z.object,
z.array, z.union, z.discriminatedUnion, z.enum, z.record, z.tuple), parsing (parse,
safeParse, parseAsync), type inference (z.infer, z.input, z.output), refinements and
transforms (refine, superRefine, transform, pipe, preprocess, coerce), optional and default
values, errors (ZodError, issues, error maps, formatting and customization), codecs, JSON
Schema, metadata and registries, Zod Mini, an upgrade from v3 to v4 -- and above all when it
is about history: since which version something exists, what changed between versions, what
was renamed or removed and what replaced it. Example query: "z.object strict passthrough".

Do not call this for TypeScript itself, for Yup, Joi, Valibot, ArkType or io-ts, for tRPC,
react-hook-form or other libraries that use Zod: their documentation is not here, and the
search will return Zod excerpts that merely mention them, with confident-looking titles.

`version` narrows the search to one release line: "4" keeps every 4.x document, "3.22"
keeps 3.22.x, "1" keeps 1.x; leave it empty to search everything. Pre-releases belong to
their line: "4" also keeps 4.0.0-beta and the 4.x canary builds, "2" keeps the 2.0.0 alpha
and beta builds -- the whole 2.x line, which never had a stable release. Every excerpt
comes back with `versions`: each version whose documents contain this exact text, newest
first -- text that stayed the same across versions is returned once, with all of them
listed, so the list itself shows from which to which version the documentation said exactly
this.

Where the documentation lived. Up to 3.24 the whole documentation was the README of the
package (titles "Zod README …"), with ERROR_HANDLING.md and MIGRATION.md beside it. From
3.25 it is the zod.dev site (titles from packages/docs/content): 3.25.x already shipped Zod 4
under the import path "zod/v4" while the package root stayed on the v3 API, so v4 pages carry
3.25.x versions too; from 4.0 "zod" itself is v4 and the v3 docs live in packages/docs-v3.

Which version to search first. For a question about how to do something today, pass
`version` "4" (or the line of the user's project): without it, the hundreds of editions of
the v3 README, which differ by a line or two, fill every place with the API of 2021-2024.
Search without `version` when the question is about history, or when the line gave nothing
that answers.

For a question about when something appeared, changed or disappeared, search more than
once: without `version` first, to find the release notes and the migration guide that name
the exact version, then with the versions around it, to see how the documentation described
it before and after.

Write the query in English, with the names Zod itself uses (z.object, safeParse,
superRefine, z.infer, ZodError, error map). Everything here is English -- the excerpts, the
word index and the meaning index alike -- and the word index keeps only latin letters and
digits, so a query written in Ukrainian, Russian or any other non-latin script matches
nothing at all and comes back with `found: 0`. When the user asks in another language,
translate the question into Zod terms first, then search.

The `search` field of the result says how the excerpts were found: "words" means the words
of the query had to appear in the text, so a query phrased in other words than the
documentation uses may miss; "meaning+words" means a second, meaning-based index answered
as well, and a paraphrase had a chance.

Every answer says which version it is for. When the user did not name a version, answer
for the default line, 4.x -- the line most projects use -- say so in the answer ("for Zod
4.x"), and add that for a precise answer about another version the user can name it. When
the excerpts behind a statement come only from older versions, name those versions instead
of presenting the text as current. Line 3 is still widely used (about 40% of downloads):
when the answer differs between 3 and 4, give both and ask which one the project is on.

Answer in the language the user wrote in. When the question is about a feature's history
or support, answer point by point: since which version it exists and which release
introduced it; what changed in later versions; what prompted the change, if the excerpts
say so; and how it stands in the current version -- recommended, deprecated, or removed and
replaced by what. Every point names the version and the document it rests on; a point the
excerpts do not support is left out, not guessed. A text found only in alpha, beta or canary
builds may never have shipped in a release: say so. When that language is Ukrainian, write as a
Ukrainian engineer writes, not as a translation from English: plain technical prose, and the
Ukrainian word wherever one exists -- "уривок", not "ексерпт"; "застарілий", not
"депрекейтнутий". Never call this set of documents "корпус" -- say "документація Zod".
Identifiers, API names and titles stay in English, spelled exactly as the documentation
spells them. Build the answer out of the excerpts that came back, not out of memory: if an
excerpt was cut, read the whole of it before describing what it says.

Arguments: `query` is free text; `k` is how many excerpts to return, 1 to 10, default 3;
`version` is optional, see above. Excerpt text is cut at 600 characters -- pass the `id` of
an excerpt to `read_section` to get the whole thing.
