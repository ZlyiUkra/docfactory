# Розпізнавання сторінок PDF для спільного середовища збірки для відеокарти (.venvs/gpu): другий крок збірки.
# Потрібне лише читачеві cncfcurriculum (примірник kubernetes, кроки refresh і build); решта примірників
# без нього працює як працювала.
#
# Ставиться ПІСЛЯ requirements/gpu.txt і ОБОВ'ЯЗКОВО з --no-deps, з кореня docfactory/:
#
#   .venvs/gpu/bin/python -m pip install --no-deps -r requirements/gpu-ocr.txt
#
# Чому --no-deps. rapidocr-onnxruntime оголошує залежність від звичайного onnxruntime, а той у одному venv
# з onnxruntime-gpu пише в ту саму теку onnxruntime/ і затирає файли збірки для відеокарти. Але
# onnxruntime-gpu — це той самий модуль onnxruntime, і CPUExecutionProvider у ньому лишається, а
# розпізнаванню потрібен саме він. Тому rapidocr-onnxruntime ставиться без залежностей, а чого йому
# справді бракує в gpu.txt — перелічено нижче й закріплено тими самими версіями, що в .venvs/cpu
# (numpy, Pillow і PyYAML у gpu.txt уже є й не чіпаються).
#
# Наслідок: `pip check` у цьому venv скаржиться на один формальний рядок — «rapidocr-onnxruntime 1.2.3
# requires onnxruntime, which is not installed». Так і має бути: модуль onnxruntime стоїть, його дає
# onnxruntime-gpu, просто під іншою назвою пакета. Інших зауважень у `pip check` бути не повинно.
# Перевірено 19.10.2026 на Python 3.14.6: розпізнавання сторінки-картинки дає той самий текст, що й
# на .venvs/cpu, вектори на CUDA рахуються як раніше.

rapidocr-onnxruntime==1.2.3
